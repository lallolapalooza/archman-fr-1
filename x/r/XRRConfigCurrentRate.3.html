La structure XRRScreenSize contient une taille racine possible en pixels et en millimètres.

Un événement XRRScreenChangeNotifyEvent est envoyé à un client qui a demandé une notification chaque fois que la configuration de l'écran change. Un client peut effectuer cette requête en appelant XRRSelectInput, en passant l'affichage, la fenêtre racine et le masque RRScreenChangeNotifyMask.

XRRScreenConfiguration est un type de données opaque contenant les informations de configuration d'un écran.

Horodatages

Les horodatages sont inclus et doivent être utilisés pour s'assurer que le client joue avec un jeu complet : l'écran peut changer de propriétés à la volée et cela garantit que sa connaissance de la configuration est à jour. Ceci afin d'aider les problèmes lorsque les écrans peuvent devenir connectables à chaud à l'avenir.

DESCRIPTION

Xrandr est une bibliothèque simple conçue pour interagir avec l'extension X de redimensionnement et de rotation. Cela permet aux clients de changer la taille et la rotation de la fenêtre racine d'un écran, ainsi que la possibilité de refléter l'écran sur l'un ou l'autre axe (si pris en charge par l'implémentation). La rotation et la réflexion peuvent être implémentées par logiciel et entraîner des performances plus lentes si la rotation et la réflexion sont implémentées de cette manière (comme le sont toutes les implémentations en octobre 2002).

La bibliothèque Xrandr effectue une mise en cache minimale pour éviter les allers-retours afin de fournir aux clients des informations fréquemment utilisées. Voir « L'extension X de redimensionnement et de rotation » pour une description détaillée ; notez également que le changement de profondeur, tel que décrit dans le document, n'est pas implémenté et peut (ou peut-être pas) jamais être implémenté, car la mémoire d'affichage augmente rapidement et les toolkits commencent déjà à prendre en charge la migration, atténuant ainsi le besoin de changement de profondeur. Si cela est implémenté à l'avenir, nous prévoyons de le faire via une extension rétrocompatible avec la bibliothèque/le protocole actuel ; les fonctionnalités décrites ici devraient continuer à fonctionner.

La rotation et la réflexion, et leur interaction, peuvent être déroutantes. Dans Randr, le système de coordonnées est tourné dans le sens inverse des aiguilles d'une montre par rapport à l'orientation normale. La réflexion se fait le long du système de coordonnées du système de fenêtrage, et non des axes X et Y physiques de l'écran, de sorte que la rotation et la réflexion n'interagissent pas. L'autre façon de considérer la réflexion est de la traiter comme spécifiée dans l'orientation « normale », avant la rotation.

L'événement XRRScreenChangeNotify est envoyé aux clients qui demandent à être informés chaque fois que la configuration de la fenêtre racine change. Les changements de configuration peuvent inclure la résolution, la taille physique, l'ordre des sous-pixels (voir XRender(3)), et la rotation. Notez que les changements de l'un ou de tous ces éléments peuvent survenir en raison d'événements externes (contrôle utilisateur dans le serveur X, connexion/déconnexion d'un moniteur/écran plat différent) et ne sont pas uniquement le résultat d'une requête de protocole/bibliothèque au serveur X.

De plus, pour éliminer une condition de concurrence potentielle, cet événement peut être généré immédiatement lors de la sélection de la notification si l'écran a changé depuis que le client de Xrandr s'est connecté au serveur X, afin de permettre un changement de résolution d'écran fiable lorsqu'un utilisateur peut se connecter et changer la configuration pendant que plusieurs clients démarrent.

Notification Xlib

Les clients doivent rappeler Xlib en utilisant XRRUpdateConfiguration lorsque des événements de notification de changement de configuration de l'écran sont générés (ou que des changements de configuration de la fenêtre racine se produisent, pour mettre à jour la vue Xlib de la résolution, de la taille, de la rotation, de la réflexion ou de l'ordre des sous-pixels. Généralement, les toolkits effectueront cette opération pour le compte des applications ; nous ne voulions pas modifier les données de structure d'affichage derrière le dos des toolkits, car dans les clients multithreadés, diverses conditions de concurrence pourraient survenir. Les toolkits devraient fournir aux clients un mécanisme de notification de changement d'écran, bien sûr.

DATATYPES

The RandR extension defines several structures and types:

XRRScreenResources
Contains information about the screen, including the possible rotations and reflections, the default screen size, and the list of supported sizes and refresh rates.
XRRScreenSize
Represents a screen size, with fields for the size identifier, width, and height.
XRRScreenRate
Represents a screen refresh rate, with fields for the number of rates and a pointer to the list of supported rates.
XRRScreenConfiguration
Contains the current screen configuration, including the current size, the list of supported sizes and rates, and the current refresh rate.
XRRScreenChangeNotifyEvent
An event structure used to notify clients of screen configuration changes.

DESCRIPTION

The X Resize and Rotate (RandR) extension provides a mechanism for clients to query and modify the screen size, rotation, and reflection. It also allows clients to query and set the refresh rate.

FUNCTIONS

There are two classes of interfaces: those which can be safely called even if RandR is not implemented on a screen (to make common idioms not dependent on the server having support), and those which will return errors if the extension is not present.

XRRRotations returns both the possible set of rotations/reflections supported (as a bitmask) as the value of the function, along with the current rotation/reflection of the screen.

XRRSizes returns the size and a pointer to the current sizes supported by the specified screen. The first size specified is the default size of the server. If RandR is not supported, it returns 0 for the number of sizes.

XRRRates returns a pointer to the rates supported by the specified size. If RandR is not supported, it returns 0 for the number of rates.

XRRTimes returns the time last reported by the server along with the timestamp the last configuration changed. If the configuration has changed since the client last updated its view of the server time, requests to change the configuration will fail until the client has an up to date timestamp.

XRRRootToScreen returns the screen number given a root window (for example, from an XRRScreenChangeNotifyEvent).

The rest of the functions will fail if applied to screens not implementing the RandR extension. XRRSetScreenConfig sets the screen size and rotation and reflection to the desired values on the screen specified by window, or returns a BadValue error. size_index specifies which size configuration is to be used, rotation specifies which rotation or reflection is to be used (or a BadValue error is returned). The timestamp is used by the server to make sure the client has up to date configuration information. Status is returned to indicate success or failure; a client must refresh its configuration information if it fails and try the call again (by calling XRRGetScreenInfo).

XRRSetScreenConfigAndRate is like XRRSetScreenConfig but also sets the refresh rate. If specified rate is not supported a BadValue error is returned.

XRRConfigRotations, XRRConfigSizes, XRRConfigCurrentConfiguration, XRRConfigTimes, XRRConfigRates, and XRRConfigCurrentRate are used to get specific configuration information out of a screen configuration.

XRRGetScreenInfo returns a screen configuration for later use; the information is private to the library. Call XRRFreeScreenConfigInfo to free this information when you are finished with it. It forces a round trip to the server.

Other functions include: XRRQueryExtension which returns the event and error base codes, XRRQueryVersion , which returns the current version of the extension (this information is cached by the library).

RESTRICTIONS

Xrandr will remain upward compatible after the current 1.0 release.
