TYPES DE DONNÉES

Rotations/Réflexions

Peut être l'une des valeurs suivantes :

#define RR_Rotate_0             1
#define RR_Rotate_90            2
#define RR_Rotate_180           4
#define RR_Rotate_270           8
/∗ nouveau dans le protocole 1.0, pour permettre la réflexion de l'écran */
/∗ la réflexion est appliquée après la rotation */
#define RR_Reflect_X            16
#define RR_Reflect_Y            32
typedef struct {
    int	width, height;
    int	mwidth, mheight;
} XRRScreenSize;
typedef struct {
    int type;				/∗ base d'événements */
    unsigned long serial;	/∗ # de la dernière requête traitée par le serveur */
    Bool send_event;		/∗ vrai si cela provenait d'une requête SendEvent */
    Display *display;		/∗ Affichage à partir duquel l'événement a été lu */
    Window window;			/∗ fenêtre qui a sélectionné cet événement */
    Window root;			/∗ fenêtre racine pour l'écran modifié */
    Time timestamp;			/∗ quand le changement d'écran s'est produit */
    Time config_timestamp;	/∗ quand le dernier changement de configuration */
    SizeID size_index;
    SubpixelOrder subpixel_order;
    Rotation rotation;
    int width;
    int height;
    int mwidth;
    int mheight;
} XRRScreenChangeNotifyEvent;
La structure XRRScreenSize contient une taille racine possible en pixels et en millimètres.

Un événement XRRScreenChangeNotifyEvent est envoyé à un client qui a demandé une notification chaque fois que la configuration de l'écran est modifiée. Un client peut effectuer cette demande en appelant XRRSelectInput, en passant l'affichage, la fenêtre racine et le masque RRScreenChangeNotifyMask.

XRRScreenConfiguration est un type de données opaque contenant les informations de configuration d'un écran.

Horodatages

Les horodatages sont inclus et doivent être utilisés pour s'assurer que le client joue avec un jeu complet : l'écran peut changer de propriétés à la volée et cela garantit que sa connaissance de la configuration est à jour. Ceci est pour aider les problèmes lorsque les écrans peuvent devenir enfichables à chaud à l'avenir.

DESCRIPTION

Xrandr est une bibliothèque simple conçue pour interfacer l'extension X de redimensionnement et de rotation. Cela permet aux clients de changer la taille et la rotation de la fenêtre racine d'un écran, ainsi que la possibilité de refléter l'écran sur l'un ou l'autre axe (si pris en charge par l'implémentation). La rotation et la réflexion peuvent être implémentées par logiciel et peuvent entraîner des performances plus lentes si la rotation et la réflexion sont implémentées de cette manière (comme le sont toutes les implémentations en octobre 2002).

La bibliothèque Xrandr effectue une mise en cache minimale pour éviter les allers-retours afin de fournir aux clients des informations fréquemment utilisées. Voir « L'extension X de redimensionnement et de rotation » pour une description détaillée ; notez également que le changement de profondeur, tel que décrit dans le document, n'est pas implémenté et peut (ou non) jamais être implémenté, car la mémoire d'affichage croît rapidement et les boîtes à outils commencent déjà à prendre en charge la migration, atténuant le besoin de changement de profondeur. S'il est implémenté à l'avenir, nous prévoyons de le faire via une extension compatible ascendante de la bibliothèque/protocole actuel ; les fonctionnalités décrites ici devraient continuer à fonctionner.

La rotation et la réflexion et la manière dont elles interagissent peuvent être déroutantes. Dans Randr, le système de coordonnées est tourné dans le sens inverse des aiguilles d'une montre par rapport à l'orientation normale. La réflexion se fait le long du système de coordonnées du système de fenêtrage, et non des axes X et Y physiques de l'écran, de sorte que la rotation et la réflexion n'interagissent pas. L'autre façon d'envisager la réflexion est de la traiter comme spécifié dans l'orientation « normale », avant la rotation.

L'événement XRRScreenChangeNotify est envoyé aux clients qui demandent à être informés chaque fois que la configuration de la fenêtre racine change. Les changements de configuration peuvent inclure la résolution, la taille physique, l'ordre des sous-pixels (voir XRender(3)) et la rotation. Notez que les changements de l'un ou de tous ces éléments peuvent survenir en raison d'événements externes (contrôle utilisateur dans le serveur X, connexion/déconnexion d'un moniteur/écran plat différent) et ne sont pas seulement le résultat d'une demande de protocole/bibliothèque au serveur X.

De plus, pour éliminer une condition de concurrence potentielle, cet événement peut être généré immédiatement après la sélection de la notification si l'écran a changé depuis que le client Xrandr s'est connecté au serveur X, afin de permettre un changement de résolution d'écran fiable lorsqu'un ou plusieurs clients démarrent et que l'utilisateur peut changer la configuration.

Notification Xlib

Les clients doivent rappeler Xlib en utilisant XRRUpdateConfiguration lorsque des événements de notification de changement de configuration de l'écran sont générés (ou lorsque des changements de configuration de la fenêtre racine se produisent, pour mettre à jour la vue de Xlib sur la résolution, la taille, la rotation, la réflexion ou l'ordre des sous-pixels. Généralement, les boîtes à outils effectueront cette opération pour le compte des applications ; nous ne voulions pas modifier les données de structure d'affichage derrière le dos des boîtes à outils, car dans les clients multithreadés, diverses conditions de concurrence pourraient survenir. Les boîtes à outils devraient fournir aux clients un mécanisme de notification de changement d'écran, bien sûr.

ARGUMENTS

See XRRSetScreenConfig(3) for details.

DATATYPES

See XRRSetScreenConfig(3) for details.

DESCRIPTION

There are two classes of interfaces: those which can be safely called even if RandR is not implemented on a screen (to make common idioms not dependent on the server having support), and those which will return errors if the extension is not present.

XRRRotations returns both the possible set of rotations/reflections supported (as a bitmask) as the value of the function, along with the current rotation/reflection of the screen.

XRRSizes returns the size and a pointer to the current sizes supported by the specified screen. The first size specified is the default size of the server. If RandR is not supported, it returns 0 for the number of sizes.

XRRRates returns a pointer to the rates supported by the specified size. If RandR is not supported, it returns 0 for the number of rates.

XRRTimes returns the time last reported by the server along with the timestamp the last configuration changed. If the configuration has changed since the client last updated its view of the server time, requests to change the configuration will fail until the client has an up to date timestamp.

XRRRootToScreen returns the screen number given a root window (for example, from an XRRScreenChangeNotifyEvent).

The rest of the functions will fail if applied to screens not implementing the RandR extension. XRRSetScreenConfig sets the screen size and rotation and reflection to the desired values on the screen specified by draw, or returns a BadValue error. size_index specifies which size configuration is to be used, rotation specifies which rotation or reflection is to be used (or a BadValue error is returned). The timestamp is used by the server to make sure the client has up to date configuration information. Status is returned to indicate success or failure; a client must refresh its configuration information if it fails and try the call again (by calling XRRGetScreenInfo).

XRRSetScreenConfigAndRate is like XRRSetScreenConfig but also sets the refresh rate. If specified rate is not supported a BadValue error is returned.

XRRConfigRotations, XRRConfigSizes, XRRConfigCurrentConfiguration, XRRConfigTimes, XRRConfigRates, and XRRConfigCurrentRate are used to get specific configuration information out of a screen configuration.

XRRGetScreenInfo returns a screen configuration for later use; the information is private to the library. Call XRRFreeScreenConfigInfo to free this information when you are finished with it. It forces a round trip to the server.

Other functions include: XRRQueryExtension which returns the event and error base codes, XRRQueryVersion , which returns the current version of the extension (this information is cached by the library).

RESTRICTIONS

Xrandr will remain upward compatible after the current 1.0 release.

DESCRIPTION

Il existe deux classes d'interfaces : celles qui peuvent être appelées en toute sécurité même si RandR n'est pas implémenté sur un écran (pour rendre les idiomes courants indépendants du support du serveur), et celles qui retourneront des erreurs si l'extension n'est pas présente.

XRRRotations retourne à la fois l'ensemble possible de rotations/réflexions supportées (sous forme de masque de bits) comme valeur de la fonction, ainsi que la rotation/réflexion actuelle de l'écran.

XRRSizes retourne la taille et un pointeur vers les tailles actuelles supportées par l'écran spécifié. La première taille spécifiée est la taille par défaut du serveur. Si RandR n'est pas supporté, il retourne 0 pour le nombre de tailles.

XRRRates retourne un pointeur vers les fréquences supportées par la taille spécifiée. Si RandR n'est pas supporté, il retourne 0 pour le nombre de fréquences.

XRRTimes retourne le temps rapporté pour la dernière fois par le serveur ainsi que l'horodatage du dernier changement de configuration. Si la configuration a changé depuis que le client a mis à jour sa vue du temps du serveur, les requêtes pour changer la configuration échoueront jusqu'à ce que le client ait un horodatage à jour.

XRRRootToScreen retourne le numéro de l'écran étant donné une fenêtre racine (par exemple, depuis un XRRScreenChangeNotifyEvent).

Le reste des fonctions échouera si elles sont appliquées à des écrans qui n'implémentent pas l'extension RandR. XRRSetScreenConfig définit la taille, la rotation et la réflexion de l'écran aux valeurs désirées sur l'écran spécifié par draw, ou retourne une erreur BadValue. size_index spécifie quelle configuration de taille doit être utilisée, rotation spécifie quelle rotation ou réflexion doit être utilisée (ou une erreur BadValue est retournée). L'timestamp est utilisé par le serveur pour s'assurer que le client dispose d'informations de configuration à jour. Le statut est retourné pour indiquer le succès ou l'échec ; un client doit rafraîchir ses informations de configuration si elles échouent et réessayer l'appel (en appelant XRRGetScreenInfo).

XRRSetScreenConfigAndRate est similaire à XRRSetScreenConfig mais définit également le taux de rafraîchissement. Si le taux spécifié n'est pas supporté, une erreur BadValue est retournée.

XRRConfigRotations, XRRConfigSizes, XRRConfigCurrentConfiguration, XRRConfigTimes, XRRConfigRates, et XRRConfigCurrentRate sont utilisés pour extraire des informations de configuration spécifiques d'une configuration d'écran.

XRRGetScreenInfo retourne une configuration d'écran pour une utilisation ultérieure ; les informations sont privées à la bibliothèque. Appelez XRRFreeScreenConfigInfo pour libérer ces informations lorsque vous avez terminé. Cela force un aller-retour vers le serveur.

Les autres fonctions incluent : XRRQueryExtension qui retourne les codes de base des événements et des erreurs, XRRQueryVersion, qui retourne la version actuelle de l'extension (cette information est mise en cache par la bibliothèque).
