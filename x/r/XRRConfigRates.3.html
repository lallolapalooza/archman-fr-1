TYPES DE DONNÉES

Rotations/Reflets

Peut être l'un des suivants :

#define RR_Rotate_0             1
#define RR_Rotate_90            2
#define RR_Rotate_180           4
#define RR_Rotate_270           8
/∗ nouveau dans le protocole 1.0, pour permettre le reflet de l'écran */
/∗ le reflet est appliqué après la rotation */
#define RR_Reflect_X            16
#define RR_Reflect_Y            32
typedef struct {
    int	width, height;
    int	mwidth, mheight;
} XRRScreenSize;
typedef struct {
    int type;				/∗ base d'événement */
    unsigned long serial;	/∗ # de la dernière requête traitée par le serveur */
    Bool send_event;		/∗ vrai si ceci provient d'une requête SendEvent */
    Display *display;		/∗ affichage à partir duquel l'événement a été lu */
    Window window;			/∗ fenêtre qui a sélectionné cet événement */
    Window root;			/∗ fenêtre racine pour l'écran modifié */
    Time timestamp;			/∗ quand le changement d'écran s'est produit */
    Time config_timestamp;	/∗ quand le dernier changement de configuration */
    SizeID size_index;
    SubpixelOrder subpixel_order;
    Rotation rotation;
    int width;
    int height;
    int mwidth;
    int mheight;
} XRRScreenChangeNotifyEvent;
La structure XRRScreenSize contient une taille racine possible en pixels et en millimètres.

Un événement XRRScreenChangeNotifyEvent est envoyé à un client qui a demandé à être notifié chaque fois que la configuration de l'écran est modifiée. Un client peut effectuer cette requête en appelant XRRSelectInput, en passant l'affichage, la fenêtre racine et le masque RRScreenChangeNotifyMask.

XRRScreenConfiguration est un type de données opaque contenant les informations de configuration d'un écran.

Horodatages

Les horodatages sont inclus et doivent être utilisés pour s'assurer que le client joue avec toutes ses cartes : l'écran peut changer de propriétés à la volée et cela garantit que sa connaissance de la configuration est à jour. Ceci afin de résoudre les problèmes lorsque les écrans peuvent devenir remplaçables à chaud à l'avenir.

DESCRIPTION

Xrandr est une bibliothèque simple conçue pour interagir avec l'extension X de redimensionnement et de rotation. Cela permet aux clients de changer la taille et la rotation de la fenêtre racine d'un écran, ainsi que la possibilité de refléter l'écran sur l'un ou l'autre axe (si pris en charge par l'implémentation). La rotation et le reflet peuvent être implémentés par logiciel et peuvent entraîner des performances plus lentes si la rotation et le reflet sont implémentés de cette manière (comme toutes les implémentations en octobre 2002).

La bibliothèque Xrandr effectue un minimum de mise en cache pour éviter les allers-retours afin de fournir aux clients des informations fréquemment utilisées. Voir "The X Resize and Rotate Extension" pour une description détaillée ; notez également que le changement de profondeur, tel que décrit dans le document, n'est pas implémenté, et peut-être jamais implémenté, car la mémoire d'affichage croît rapidement et les toolkits commencent déjà à prendre en charge la migration, atténuant ainsi le besoin de changer de profondeur. Si elle est implémentée à l'avenir, nous prévoyons de le faire via une extension rétrocompatible avec la bibliothèque/le protocole actuel ; les fonctionnalités décrites ici devraient continuer à fonctionner.

La rotation et le reflet, et la manière dont ils interagissent, peuvent prêter à confusion. Dans Randr, le système de coordonnées est tourné dans le sens inverse des aiguilles d'une montre par rapport à l'orientation normale. Le reflet se fait le long du système de coordonnées du système de fenêtrage, et non selon les axes X et Y physiques de l'écran, de sorte que la rotation et le reflet n'interagissent pas. L'autre façon de considérer le reflet est de le traiter comme spécifié dans l'orientation "normale", avant la rotation.

L'événement XRRScreenChangeNotify est envoyé aux clients qui demandent à être informés chaque fois que la configuration de la fenêtre racine change. Les changements de configuration peuvent inclure la résolution, la taille physique, l'ordre des sous-pixels (voir XRender(3)) et la rotation. Notez que des changements à l'un ou à tous ces éléments peuvent se produire en raison d'événements externes (contrôle utilisateur dans le serveur X, branchement d'un moniteur/écran plat différent) et ne sont pas seulement le résultat d'une demande de protocole/bibliothèque au serveur X.

De plus, pour éliminer une condition de concurrence potentielle, cet événement peut être généré immédiatement lors de la sélection pour la notification si l'écran a changé depuis que le client de Xrandr s'est connecté au serveur X, afin de permettre un changement de résolution d'écran fiable lorsqu'un utilisateur peut se connecter et modifier la configuration pendant que un ou plusieurs clients démarrent.

Notification Xlib

Les clients doivent rappeler Xlib en utilisant XRRUpdateConfiguration lorsque des événements de notification de changement de configuration de l'écran sont générés (ou que des changements de configuration de la fenêtre racine se produisent, pour mettre à jour la vue de Xlib sur la résolution, la taille, la rotation, le reflet ou l'ordre des sous-pixels. En général, les toolkits effectueront cette opération pour le compte des applications ; nous ne voulions pas modifier les données de structure d'affichage derrière le dos des toolkits, car dans les clients multithreadés, diverses conditions de concurrence pourraient survenir. Les toolkits devraient fournir aux clients un mécanisme de notification de changement d'écran, bien sûr.

DATATYPES

Les types de données utilisés sont définis dans <X11/extensions/Xrandr.h>.

Rotation_t : masque de bits représentant les rotations et réflexions possibles.

RRMode : représente un mode d'affichage, incluant la taille et le taux de rafraîchissement.

XRRScreenResources : structure contenant les ressources de l'écran, y compris les tailles, rotations et taux de rafraîchissement supportés.

Time : type représentant un horodatage.

DESCRIPTION

Il existe deux classes d'interfaces : celles qui peuvent être appelées en toute sécurité même si RandR n'est pas implémenté sur un écran (pour que les idiomes courants ne dépendent pas du support du serveur), et celles qui renverront des erreurs si l'extension n'est pas présente.

XRRRotations retourne à la fois l'ensemble des rotations/réflexions possibles supportées (sous forme de masque de bits) comme valeur de la fonction, ainsi que la rotation/réflexion actuelle de l'écran.

XRRSizes retourne la taille et un pointeur vers les tailles actuelles supportées par l'écran spécifié. La première taille spécifiée est la taille par défaut du serveur. Si RandR n'est pas supporté, il retourne 0 pour le nombre de tailles.

XRRRates retourne un pointeur vers les taux supportés par la taille spécifiée. Si RandR n'est pas supporté, il retourne 0 pour le nombre de taux.

XRRTimes retourne le temps rapporté en dernier par le serveur ainsi que l'horodatage du dernier changement de configuration. Si la configuration a changé depuis que le client a mis à jour sa vue de l'heure du serveur, les requêtes pour changer la configuration échoueront jusqu'à ce que le client ait un horodatage à jour.

XRRRootToScreen retourne le numéro de l'écran étant donné une fenêtre racine (par exemple, depuis un XRRScreenChangeNotifyEvent).

Le reste des fonctions échouera si elles sont appliquées à des écrans n'implémentant pas l'extension RandR.

FONCTIONS

XRRSetScreenConfig définit la taille de l'écran et la rotation et la réflexion aux valeurs souhaitées sur l'écran spécifié par draw, ou retourne une erreur BadValue. size_index spécifie quelle configuration de taille doit être utilisée, rotation spécifie quelle rotation ou réflexion doit être utilisée (ou une erreur BadValue est retournée). Le timestamp est utilisé par le serveur pour s'assurer que le client dispose d'informations de configuration à jour. Le statut est retourné pour indiquer le succès ou l'échec ; un client doit rafraîchir ses informations de configuration si l'appel échoue et réessayer (en appelant XRRGetScreenInfo).

XRRSetScreenConfigAndRate est similaire à XRRSetScreenConfig mais définit également le taux de rafraîchissement. Si le taux spécifié n'est pas supporté, une erreur BadValue est retournée.

XRRConfigRotations, XRRConfigSizes, XRRConfigCurrentConfiguration, XRRConfigTimes, XRRConfigRates, et XRRConfigCurrentRate sont utilisés pour extraire des informations de configuration spécifiques d'une configuration d'écran.

XRRGetScreenInfo retourne une configuration d'écran pour une utilisation ultérieure ; les informations sont privées à la bibliothèque. Appelez XRRFreeScreenConfigInfo pour libérer ces informations lorsque vous avez terminé. Cela force un aller-retour vers le serveur.

Les autres fonctions incluent : XRRQueryExtension qui retourne les codes de base des événements et des erreurs, XRRQueryVersion , qui retourne la version actuelle de l'extension (cette information est mise en cache par la bibliothèque).

RESTRICTIONS

Xrandr restera compatible avec les versions antérieures après la version actuelle 1.0.
