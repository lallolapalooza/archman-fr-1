XrmGetFileDatabase(3) FONCTIONS XLIB XrmGetFileDatabase(3)

NOM

XrmGetFileDatabase, XrmPutFileDatabase, XrmGetStringDatabase, XrmLocaleOfDatabase, XrmGetDatabase, XrmSetDatabase, XrmDestroyDatabase - récupérer et stocker des bases de données de ressources

SYNTAXE

#include <X11/Xresource.h>

XrmDatabase XrmGetFileDatabase(char *filename);

void XrmPutFileDatabase(XrmDatabase database, _Xconst char *stored_db);

XrmDatabase XrmGetStringDatabase(_Xconst char *data);

const char *XrmLocaleOfDatabase(XrmDatabase database);

XrmDatabase XrmGetDatabase(Display *display);

void XrmSetDatabase(Display *display, XrmDatabase database);

void XrmDestroyDatabase(XrmDatabase database);

ARGUMENTS

filename
Spécifie le nom du fichier de la base de données de ressources.
database
Spécifie la base de données qui doit être utilisée.
stored_db
Spécifie le nom du fichier pour la base de données stockée.
data
Spécifie le contenu de la base de données à l'aide d'une chaîne.
database
Spécifie la base de données de ressources.
display
Spécifie la connexion au serveur X.

DESCRIPTION

La fonction XrmGetFileDatabase ouvre le fichier spécifié, crée une nouvelle base de données de ressources et la charge avec les spécifications lues à partir du fichier spécifié. Le fichier spécifié doit contenir une séquence d'entrées au format valide ResourceLine (voir la section 15.1) ; la base de données résultant de la lecture d'un fichier de syntaxe incorrecte est dépendante de l'implémentation. Le fichier est analysé dans la locale actuelle, et la base de données est créée dans la locale actuelle. Si elle ne parvient pas à ouvrir le fichier spécifié, XrmGetFileDatabase renvoie NULL.

La fonction XrmPutFileDatabase stocke une copie de la base de données spécifiée dans le fichier spécifié. Le texte est écrit dans le fichier sous forme d'une séquence d'entrées au format valide ResourceLine (voir la section 15.1). Le fichier est écrit dans la locale de la base de données. Les entrées contenant des noms de ressources qui ne sont pas dans l'encodage de caractères portable hôte ou contenant des valeurs qui ne sont pas dans l'encodage de la locale de la base de données, sont écrites de manière dépendante de l'implémentation. L'ordre dans lequel les entrées sont écrites est dépendant de l'implémentation. Les entrées dont les types de représentation autres que “String” sont ignorées.

La fonction XrmGetStringDatabase crée une nouvelle base de données et stocke les ressources spécifiées dans la chaîne terminée par un caractère nul spécifiée. XrmGetStringDatabase est similaire à XrmGetFileDatabase, sauf qu'elle lit les informations à partir d'une chaîne au lieu d'un fichier. La chaîne doit contenir une séquence d'entrées au format valide ResourceLine (voir la section 15.1) terminée par un caractère nul ; la base de données résultant de l'utilisation d'une chaîne de syntaxe incorrecte est dépendante de l'implémentation. La chaîne est analysée dans la locale actuelle, et la base de données est créée dans la locale actuelle.

Si database est NULL, XrmDestroyDatabase retourne immédiatement.

La fonction XrmLocaleOfDatabase renvoie le nom de la locale liée à la base de données spécifiée, sous forme de chaîne terminée par un caractère nul. La chaîne de nom de locale renvoyée appartient à Xlib et ne doit pas être modifiée ni libérée par le client. Xlib n'est pas autorisé à libérer la chaîne tant que la base de données n'est pas détruite. Jusqu'à ce que la chaîne soit libérée, elle ne sera pas modifiée par Xlib.

La fonction XrmGetDatabase renvoie la base de données associée à l'affichage spécifié. Elle renvoie NULL si une base de données n'a pas encore été définie.

La fonction XrmSetDatabase associe la base de données de ressources spécifiée (ou NULL) à l'affichage spécifié. La base de données précédemment associée à l'affichage (le cas échéant) n'est pas détruite. Un client ou une boîte à outils peut trouver cette fonction pratique pour conserver une base de données une fois qu'elle est construite.

SYNTAXE FICHIER

La syntaxe d'un fichier de ressources est une séquence de lignes de ressources terminées par des caractères de nouvelle ligne ou la fin du fichier. La syntaxe d'une ligne de ressource individuelle est la suivante :

ResourceLine	=	Comment | IncludeFile | ResourceSpec | <ligne vide>
Comment	=	"!" {<tout caractère sauf nul ou nouvelle ligne>}
IncludeFile	=	"#" WhiteSpace "include" WhiteSpace FileName WhiteSpace
FileName	=	<nom de fichier valide pour le système d'exploitation>
ResourceSpec	=	WhiteSpace ResourceName WhiteSpace ":" WhiteSpace Value
ResourceName	=	[Binding] {Component Binding} ComponentName
Binding	=	"." | "*"
WhiteSpace	=	{<espace> | <tabulation horizontale>}
Component	=	"?" | ComponentName
ComponentName	=	NameChar {NameChar}
NameChar	=	"a"-"z" | "A"-"Z" | "0"-"9" | "_" | "-"
Value	=	{<tout caractère sauf nul ou nouvelle ligne non échappée>}

Les éléments séparés par une barre verticale (|) sont des alternatives. Les accolades ({...}) indiquent zéro ou plusieurs répétitions des éléments inclus. Les crochets ([...]) indiquent que l'élément inclus est optionnel. Les guillemets ("...") sont utilisés autour des caractères littéraux.

Les lignes IncludeFile sont interprétées en remplaçant la ligne par le contenu du fichier spécifié. Le mot “include” doit être en minuscules. Le nom du fichier est interprété par rapport au répertoire du fichier dans lequel la ligne apparaît (par exemple, si le nom du fichier ne contient aucun répertoire ou contient une spécification de répertoire relative).

Si un ResourceName contient une séquence contiguë de deux caractères Binding ou plus, la séquence sera remplacée par un seul caractère “.” si la séquence ne contient que des caractères “.” ; sinon, la séquence sera remplacée par un seul caractère “*”.

Une base de données de ressources ne contient jamais plus d'une entrée pour un ResourceName donné. Si un fichier de ressources contient plusieurs lignes avec le même ResourceName, la dernière ligne du fichier est utilisée.

Tout caractère d'espacement avant ou après le nom ou le deux-points dans un ResourceSpec est ignoré. Pour permettre à un Value de commencer par un espacement, la séquence de deux caractères “\espace” (antislash suivi d'un espace) est reconnue et remplacée par un caractère d'espace, et la séquence de deux caractères “\tab” (antislash suivi d'une tabulation horizontale) est reconnue et remplacée par une tabulation horizontale. Pour permettre à un Value de contenir des caractères de nouvelle ligne, la séquence de deux caractères “\n” est reconnue et remplacée par un caractère de nouvelle ligne. Pour permettre à un Value d'être réparti sur plusieurs lignes dans un fichier texte, la séquence de deux caractères “\newline” (antislash suivi d'une nouvelle ligne) est reconnue et supprimée de la valeur. Pour permettre à une Valeur de contenir des codes de caractères arbitraires, la séquence de quatre caractères “\nnn”, où chaque n est un chiffre dans la plage de “0”-“7”, est reconnue et remplacée par un seul octet contenant la valeur octale spécifiée par la séquence. Enfin, la séquence de deux caractères “\\” est reconnue et remplacée par un seul antislash.
