ARGUMENTS

display
Spécifie la connexion au serveur X.
screen
Spécifie quel écran.
draw
Spécifie l'écran.
rotation
Spécifie les rotations ou reflets possibles de l'écran.
current_rotation
Spécifie les rotations et le reflet actuels de l'écran.
timestamp
Spécifie l'horodatage du serveur.
config_timestamp
Spécifie l'horodatage de la dernière configuration (re) de l'écran.
config
Spécifie la configuration de l'écran utilisée.
sizes
Spécifie le tableau des tailles prises en charge.
rate
Spécifie le taux de rafraîchissement en Hz.

TYPES DE DONNÉES

Rotations/Reflets

Peut être l'une des valeurs suivantes :

#define RR_Rotate_0             1
#define RR_Rotate_90            2
#define RR_Rotate_180           4
#define RR_Rotate_270           8
/∗ nouveau dans le protocole 1.0, pour permettre le reflet de l'écran */
/∗ le reflet est appliqué après la rotation */
#define RR_Reflect_X            16
#define RR_Reflect_Y            32
typedef struct {
    int	width, height;
    int	mwidth, mheight;
} XRRScreenSize;
typedef struct {
    int type;				/∗ base d'événement */
    unsigned long serial;	/∗ # de la dernière requête traitée par le serveur */
    Bool send_event;		/∗ vrai si ceci provient d'une requête SendEvent */
    Display *display;		/∗ Display à partir duquel l'événement a été lu */
    Window window;			/∗ fenêtre qui a sélectionné cet événement */
    Window root;			/∗ fenêtre racine pour l'écran modifié */
    Time timestamp;			/∗ quand le changement d'écran s'est produit */
    Time config_timestamp;	/∗ quand le dernier changement de configuration */
    SizeID size_index;
    SubpixelOrder subpixel_order;
    Rotation rotation;
    int width;
    int height;
    int mwidth;
    int mheight;
} XRRScreenChangeNotifyEvent;
La structure XRRScreenSize contient une taille racine possible en pixels et en millimètres.

Un événement XRRScreenChangeNotifyEvent est envoyé à un client qui a demandé une notification chaque fois que la configuration de l'écran est modifiée. Un client peut effectuer cette demande en appelant XRRSelectInput, en passant l'affichage, la fenêtre racine et le masque RRScreenChangeNotifyMask.

XRRScreenConfiguration est un type de données opaque contenant les informations de configuration d'un écran.

Horodatages

Les horodatages sont inclus et doivent être utilisés pour s'assurer que le client est à jour : l'écran peut changer de propriétés à la volée et cela garantit que ses connaissances de la configuration sont à jour. Ceci est pour aider aux problèmes lorsque les écrans peuvent devenir enfichables à chaud à l'avenir.

DESCRIPTION

Xrandr est une bibliothèque simple conçue pour interagir avec l'extension X Resize and Rotate. Elle permet aux clients de modifier la taille et la rotation de la fenêtre racine d'un écran, ainsi que la capacité de refléter l'écran selon l'un ou l'autre axe (si pris en charge par l'implémentation). La rotation et le reflet peuvent être implémentés par logiciel et peuvent entraîner une performance plus lente si la rotation et le reflet sont implémentés de cette manière (comme le sont toutes les implémentations en octobre 2002).

La bibliothèque Xrandr effectue une mise en cache minimale pour éviter les allers-retours afin de fournir aux clients des informations fréquemment utilisées. Voir "The X Resize and Rotate Extension" pour une description détaillée ; notez également que la commutation de profondeur, telle que décrite dans le document, n'est pas implémentée, et ne le sera peut-être jamais, car la mémoire d'affichage augmente rapidement, et les toolkits prennent déjà en charge la migration, atténuant le besoin de commutation de profondeur. Si elle est implémentée à l'avenir, nous prévoyons de le faire via une extension compatible ascendante de la bibliothèque/protocole actuel ; la fonctionnalité décrite ici devrait continuer à fonctionner.

La rotation et le reflet et la façon dont ils interagissent peuvent être confus. Dans Randr, le système de coordonnées est tourné dans le sens inverse des aiguilles d'une montre par rapport à l'orientation normale. Le reflet se fait le long du système de coordonnées du système de fenêtrage, et non des axes X et Y physiques de l'écran, de sorte que la rotation et le reflet n'interagissent pas. L'autre façon de considérer le reflet est de le traiter comme spécifié dans l'orientation "normale", avant la rotation.

L'événement XRRScreenChangeNotify est envoyé aux clients qui demandent à être informés chaque fois que la configuration de la fenêtre racine change. Les changements de configuration peuvent inclure la résolution, la taille physique, l'ordre des sous-pixels (voir XRender(3)) et la rotation. Notez que les changements de tout ou partie de ces éléments peuvent survenir en raison d'événements externes (contrôle utilisateur dans le serveur X, connexion/déconnexion d'un moniteur/écran plat différent) et ne sont pas uniquement le résultat d'une requête de protocole/bibliothèque au serveur X.

De plus, pour éliminer une condition de concurrence potentielle, cet événement peut être généré immédiatement lors de la sélection de la notification si l'écran a changé depuis que le client de Xrandr s'est connecté au serveur X, afin de permettre un changement de résolution d'écran fiable lorsqu'un utilisateur peut se connecter et modifier la configuration pendant qu'un ou plusieurs clients démarrent.

Notification Xlib

Les clients doivent rappeler Xlib en utilisant XRRUpdateConfiguration lorsque des événements de notification de changement de configuration d'écran sont générés (ou que des changements de configuration de fenêtre racine se produisent, pour mettre à jour la vue Xlib de la résolution, de la taille, de la rotation, du reflet ou de l'ordre des sous-pixels. Généralement, les toolkits effectueront cette opération pour le compte des applications ; nous ne voulions pas modifier les données de structure d'affichage derrière le dos des toolkits, car dans les clients multithread, diverses conditions de concurrence pourraient survenir. Les toolkits devraient fournir aux clients un mécanisme de notification des changements d'écran, bien sûr.

XRRQueryVersion(3) — X Version 11

NAME

XRRQueryVersion, XRRQueryExtension, XRRRotations, XRRSizes, XRRRates, XRRTimes, XRRRootToScreen, XRRGetScreenInfo, XRRFreeScreenConfigInfo, XRRSetScreenConfig, XRRSetScreenConfigAndRate, XRRConfigRotations, XRRConfigSizes, XRRConfigCurrentConfiguration, XRRConfigTimes, XRRConfigRates, XRRConfigCurrentRate — RandR extension library interface

int *XRRRates (Display *dpy, Window root, SizeID size, int *nrates_return);

Time XRRTimes (Display *dpy, Window root, Time *last_config_time_return);

Window XRRRootToScreen (Display *dpy, Window root);

int XRRSetScreenConfig (Display *dpy, Window root, Rotation rotation, int size_index, int rate, Time timestamp);

int XRRSetScreenConfigAndRate (Display *dpy, Window root, Rotation rotation, int size_index, int rate, Time timestamp);

SizeID XRRConfigSizes (XRRScreenConfiguration *config);

ARGUMENTS

The argument descriptions below are identical to the ones specified in the RandR extension specification.

DATATYPES

RandR defines the following data types:

Rotation
This is a bitmask, specifying which rotations or reflections are supported. Possible values are RR_Rotate_0, RR_Rotate_90, RR_Rotate_180, RR_Rotate_270, RR_Reflect_X, RR_Reflect_Y.
Time
Timestamp of the last configuration change.
SizeID
An index into the list of supported screen sizes.
XRRScreenConfiguration
A structure holding screen configuration information. This structure is opaque to the application and should only be manipulated via the library functions.
XRRScreenSize
A structure describing a supported screen size. It contains width, height, and the screen’s mm_width and mm_height.

DESCRIPTION

There are two classes of interfaces: those which can be safely called even if RandR is not implemented on a screen (to make common idioms not dependent on the server having support), and those which will return errors if the extension is not present.

XRRRotations returns both the possible set of rotations/reflections supported (as a bitmask) as the value of the function, along with the current rotation/reflection of the screen.

XRRSizes returns the size and a pointer to the current sizes supported by the specified screen. The first size specified is the default size of the server. If RandR is not supported, it returns 0 for the number of sizes.

XRRRates returns a pointer to the rates supported by the specified size. If RandR is not supported, it returns 0 for the number of rates.

XRRTimes returns the time last reported by the server along with the timestamp the last configuration changed. If the configuration has changed since the client last updated its view of the server time, requests to change the configuration will fail until the client has an up to date timestamp.

XRRRootToScreen returns the screen number given a root window (for example, from an XRRScreenChangeNotifyEvent).

The rest of the functions will fail if applied to screens not implementing the RandR extension. XRRSetScreenConfig sets the screen size and rotation and reflection to the desired values on the screen specified by draw, or returns a BadValue error. size_index specifies which size configuration is to be used, rotation specifies which rotation or reflection is to be used (or a BadValue error is returned). The timestamp is used by the server to make sure the client has up to date configuration information. Status is returned to indicate success or failure; a client must refresh its configuration information if it fails and try the call again (by calling XRRGetScreenInfo).

XRRSetScreenConfigAndRate is like XRRSetScreenConfig but also sets the refresh rate. If specified rate is not supported a BadValue error is returned.

XRRConfigRotations, XRRConfigSizes, XRRConfigCurrentConfiguration, XRRConfigTimes, XRRConfigRates, and XRRConfigCurrentRate are used to get specific configuration information out of a screen configuration.

XRRGetScreenInfo returns a screen configuration for later use; the information is private to the library. Call XRRFreeScreenConfigInfo to free this information when you are finished with it. It forces a round trip to the server.

Other functions include: XRRQueryExtension which returns the event and error base codes, XRRQueryVersion , which returns the current version of the extension (this information is cached by the library).

RESTRICTIONS

Xrandr will remain upward compatible after the current 1.0 release.
