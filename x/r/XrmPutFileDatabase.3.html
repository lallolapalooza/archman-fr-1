XrmGetFileDatabase(3) FONCTIONS XLIB XrmGetFileDatabase(3)

NOM

XrmGetFileDatabase, XrmPutFileDatabase, XrmGetStringDatabase, XrmLocaleOfDatabase, XrmGetDatabase, XrmSetDatabase, XrmDestroyDatabase - récupérer et stocker des bases de données de ressources

SYNTAXE

#include <X11/Xresource.h>

XrmDatabase XrmGetFileDatabase(char *nom_fichier);

void XrmPutFileDatabase(XrmDatabase base_de_donnees, _Xconst char *db_stockee);

XrmDatabase XrmGetStringDatabase(_Xconst char *donnees);

const char *XrmLocaleOfDatabase(XrmDatabase base_de_donnees);

XrmDatabase XrmGetDatabase(Display *affichage);

void XrmSetDatabase(Display *affichage, XrmDatabase base_de_donnees);

void XrmDestroyDatabase(XrmDatabase base_de_donnees);

ARGUMENTS

nom_fichier
Spécifie le nom du fichier de la base de données de ressources.
base_de_donnees
Spécifie la base de données qui doit être utilisée.
db_stockee
Spécifie le nom du fichier pour la base de données stockée.
donnees
Spécifie le contenu de la base de données à l'aide d'une chaîne de caractères.
base_de_donnees
Spécifie la base de données de ressources.
affichage
Spécifie la connexion au serveur X.

DESCRIPTION

La fonction XrmGetFileDatabase ouvre le fichier spécifié, crée une nouvelle base de données de ressources et la charge avec les spécifications lues à partir du fichier spécifié. Le fichier spécifié doit contenir une séquence d'entrées au format ResourceLine valide (voir la section 15.1) ; la base de données résultant de la lecture d'un fichier de syntaxe incorrecte dépend de l'implémentation. Le fichier est analysé dans la locale actuelle, et la base de données est créée dans la locale actuelle. Si elle ne peut pas ouvrir le fichier spécifié, XrmGetFileDatabase renvoie NULL.

La fonction XrmPutFileDatabase stocke une copie de la base de données spécifiée dans le fichier spécifié. Le texte est écrit dans le fichier sous forme d'une séquence d'entrées au format ResourceLine valide (voir la section 15.1). Le fichier est écrit dans la locale de la base de données. Les entrées contenant des noms de ressources qui ne sont pas dans l'encodage de caractères portable hôte (Host Portable Character Encoding) ou contenant des valeurs qui ne sont pas dans l'encodage de la locale de la base de données, sont écrites d'une manière dépendante de l'implémentation. L'ordre dans lequel les entrées sont écrites dépend de l'implémentation. Les entrées avec des types de représentation autres que "String" sont ignorées.

La fonction XrmGetStringDatabase crée une nouvelle base de données et stocke les ressources spécifiées dans la chaîne terminée par un caractère nul. XrmGetStringDatabase est similaire à XrmGetFileDatabase sauf qu'elle lit les informations à partir d'une chaîne au lieu d'un fichier. La chaîne doit contenir une séquence d'entrées au format ResourceLine valide (voir la section 15.1) terminée par un caractère nul ; la base de données résultant de l'utilisation d'une chaîne de syntaxe incorrecte dépend de l'implémentation. La chaîne est analysée dans la locale actuelle, et la base de données est créée dans la locale actuelle.

Si base_de_donnees est NULL, XrmDestroyDatabase retourne immédiatement.

La fonction XrmLocaleOfDatabase renvoie le nom de la locale liée à la base de données spécifiée, sous forme de chaîne terminée par un caractère nul. La chaîne de nom de locale renvoyée appartient à Xlib et ne doit pas être modifiée ou libérée par le client. Xlib n'est pas autorisé à libérer la chaîne tant que la base de données n'est pas détruite. Tant que la chaîne n'est pas libérée, elle ne sera pas modifiée par Xlib.

La fonction XrmGetDatabase renvoie la base de données associée à l'affichage spécifié. Elle renvoie NULL si une base de données n'a pas encore été définie.

La fonction XrmSetDatabase associe la base de données de ressources spécifiée (ou NULL) à l'affichage spécifié. La base de données précédemment associée à l'affichage (le cas échéant) n'est pas détruite. Un client ou une boîte à outils peut trouver cette fonction pratique pour conserver une base de données une fois qu'elle est construite.

SYNTAXE DES FICHIERS

La syntaxe d'un fichier de ressources est une séquence de lignes de ressources terminées par des caractères de nouvelle ligne ou la fin du fichier. La syntaxe d'une ligne de ressource individuelle est :

ResourceLine	=	Commentaire | FichierInclus | SpecResource | <ligne vide>
Commentaire	=	"!" {<tout caractère sauf nul ou nouvelle ligne>}
FichierInclus	=	"#" EspaceBlanc "include" EspaceBlanc NomFichier EspaceBlanc
NomFichier	=	<nom de fichier valide pour le système d'exploitation>
SpecResource	=	EspaceBlanc NomResource EspaceBlanc ":" EspaceBlanc Valeur
NomResource	=	[Liaison] {Composant Liaison} NomComposant
Liaison	=	"." | "*"
EspaceBlanc	=	{<espace> | <tabulation horizontale>}
Composant	=	"?" | NomComposant
NomComposant	=	CharNom {CharNom}
CharNom	=	"a"-"z" | "A"-"Z" | "0"-"9" | "_" | "-"
Valeur	=	{<tout caractère sauf nul ou nouvelle ligne non échappée>}

Les éléments séparés par une barre verticale (|) sont des alternatives. Les accolades ({...}) indiquent zéro ou plusieurs répétitions des éléments inclus. Les crochets ([...]) indiquent que l'élément inclus est optionnel. Les guillemets ("...") sont utilisés autour des caractères littéraux.

Les lignes FichierInclus sont interprétées en remplaçant la ligne par le contenu du fichier spécifié. Le mot « include » doit être en minuscules. Le nom du fichier est interprété par rapport au répertoire du fichier dans lequel la ligne se trouve (par exemple, si le nom du fichier ne contient aucun répertoire ou contient une spécification de répertoire relative).

Si un NomResource contient une séquence contiguë de deux caractères de Liaison ou plus, la séquence sera remplacée par un seul caractère « . » si la séquence ne contient que des caractères « . » ; sinon, la séquence sera remplacée par un seul caractère « * ».

Une base de données de ressources ne contient jamais plus d'une entrée pour un NomResource donné. Si un fichier de ressources contient plusieurs lignes avec le même NomResource, la dernière ligne du fichier est utilisée.

Tous les caractères d'espacement avant ou après le nom ou le deux-points dans une SpecResource sont ignorés. Pour permettre à une Valeur de commencer par un espace blanc, la séquence de deux caractères « \espace » (barre oblique inverse suivie d'un espace) est reconnue et remplacée par un caractère espace, et la séquence de deux caractères « \tabulation » (barre oblique inverse suivie d'une tabulation horizontale) est reconnue et remplacée par un caractère de tabulation horizontale. Pour permettre à une Valeur de contenir des caractères de nouvelle ligne incorporés, la séquence de deux caractères « \n » est reconnue et remplacée par un caractère de nouvelle ligne. Pour permettre à une Valeur d'être divisée sur plusieurs lignes dans un fichier texte, la séquence de deux caractères « \nouvelle ligne » (barre oblique inverse suivie d'une nouvelle ligne) est reconnue et supprimée de la valeur. Pour permettre à une Valeur de contenir des codes de caractères arbitraires, la séquence de quatre caractères « \nnn », où chaque n est un chiffre décimal dans la plage « 0 »-« 7 », est reconnue et remplacée par un seul octet contenant la valeur octale spécifiée par la séquence. Enfin, la séquence de deux caractères « \\ » est reconnue et remplacée par une seule barre oblique inverse.
