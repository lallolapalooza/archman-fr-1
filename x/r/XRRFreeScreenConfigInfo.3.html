Xrandr - Extension X de redimensionnement, rotation et réflexion.

TYPES DE DONNÉES

Rotations/Réflexions

Peut être l'une des valeurs suivantes :

#define RR_Rotate_0             1
#define RR_Rotate_90            2
#define RR_Rotate_180           4
#define RR_Rotate_270           8
/∗ nouveau dans le protocole 1.0, pour permettre la réflexion de l'écran */
/∗ la réflexion est appliquée après la rotation */
#define RR_Reflect_X            16
#define RR_Reflect_Y            32
typedef struct {
    int	width, height;
    int	mwidth, mheight;
} XRRScreenSize;
typedef struct {
    int type;				/∗ base d'événement */
    unsigned long serial;	/∗ # de la dernière requête traitée par le serveur */
    Bool send_event;		/∗ vrai si ceci provient d'une requête SendEvent */
    Display *display;		/∗ Affichage à partir duquel l'événement a été lu */
    Window window;			/∗ fenêtre qui a sélectionné cet événement */
    Window root;			/∗ Fenêtre racine pour l'écran modifié */
    Time timestamp;			/∗ quand le changement d'écran s'est produit */
    Time config_timestamp;	/∗ quand le dernier changement de configuration */
    SizeID size_index;
    SubpixelOrder subpixel_order;
    Rotation rotation;
    int width;
    int height;
    int mwidth;
    int mheight;
} XRRScreenChangeNotifyEvent;
La structure XRRScreenSize contient une taille racine possible en pixels et en millimètres.

Un événement XRRScreenChangeNotifyEvent est envoyé à un client qui a demandé une notification chaque fois que la configuration de l'écran est modifiée. Un client peut effectuer cette requête en appelant XRRSelectInput, en passant l'affichage, la fenêtre racine et le masque RRScreenChangeNotifyMask.

XRRScreenConfiguration est un type de données opaque contenant les informations de configuration d'un écran.

Horodatages

Les horodatages sont inclus et doivent être utilisés pour s'assurer que le client joue avec toutes les cartes : l'écran peut changer de propriétés à la volée et cela garantit que sa connaissance de la configuration est à jour. Ceci est pour aider avec les problèmes lorsque les écrans peuvent devenir plug-and-play à l'avenir.

DESCRIPTION

Xrandr est une bibliothèque simple conçue pour interfacer l'extension X de redimensionnement et de rotation. Cela permet aux clients de changer la taille et la rotation de la fenêtre racine d'un écran, ainsi que la capacité de refléter l'écran sur l'un ou l'autre axe (si supporté par l'implémentation). La rotation et la réflexion peuvent être implémentées par logiciel et peuvent entraîner des performances plus lentes si la rotation et la réflexion sont implémentées de cette manière (comme le sont toutes les implémentations en octobre 2002).

La bibliothèque Xrandr effectue une mise en cache minimale pour éviter les allers-retours afin de fournir aux clients des informations fréquemment utilisées. Voir "The X Resize and Rotate Extension" pour une description détaillée ; notez également que la commutation de profondeur, telle que décrite dans le document, n'est pas implémentée et pourrait (ou pourrait ne jamais) être implémentée, car la mémoire d'affichage augmente rapidement et les toolkits commencent déjà à supporter la migration, atténuant le besoin de commutation de profondeur. Si elle est implémentée à l'avenir, nous nous attendons à le faire via une extension compatible ascendante à la bibliothèque/protocole actuel ; les fonctionnalités décrites ici devraient continuer à fonctionner.

La rotation et la réflexion et la manière dont elles interagissent peuvent être déroutantes. Dans Randr, le système de coordonnées est tourné dans le sens inverse des aiguilles d'une montre par rapport à l'orientation normale. La réflexion se fait le long du système de coordonnées du système de fenêtrage, pas des axes X et Y physiques de l'écran, de sorte que la rotation et la réflexion n'interagissent pas. L'autre façon de considérer la réflexion est de la traiter comme spécifiée dans l'orientation "normale", avant la rotation.

L'événement XRRScreenChangeNotify est envoyé aux clients qui demandent à être informés chaque fois que la configuration de la fenêtre racine change. Les changements de configuration peuvent inclure la résolution, la taille physique, l'ordre des sous-pixels (voir XRender(3)) et la rotation. Notez que des changements à l'un ou à tous ces éléments peuvent survenir en raison d'événements externes (contrôle utilisateur dans le serveur X, connexion/déconnexion d'un autre moniteur/écran plat) et ne résultent pas seulement d'une requête de protocole/bibliothèque au serveur X.

De plus, pour éliminer une condition de concurrence potentielle, cet événement peut être généré immédiatement lors de la sélection pour notification si l'écran a changé depuis que le client de Xrandr s'est connecté au serveur X, afin de permettre un changement de résolution d'écran fiable lorsqu'un utilisateur peut se connecter et modifier la configuration pendant qu'un ou plusieurs clients démarrer.

Notification Xlib

Les clients doivent rappeler Xlib en utilisant XRRUpdateConfiguration lorsque les événements de notification de changement de configuration de l'écran sont générés (ou que des changements de configuration de fenêtre racine se produisent, pour mettre à jour la vue de Xlib sur la résolution, la taille, la rotation, la réflexion ou l'ordre des sous-pixels. En général, les toolkits effectueront cette opération au nom des applications ; nous ne voulions pas modifier les données de structure d'affichage derrière le dos des toolkits, car dans les clients multithreads, diverses conditions de concurrence pourraient survenir. Les toolkits devraient fournir aux clients un mécanisme de notification de changement d'écran, bien sûr.

FONCTION S

Les fonctions suivantes sont fournies par la bibliothèque Xrandr.

XRRQueryExtension()
Interroge le serveur pour savoir si l'extension RandR est disponible et récupère les numéros de base des événements et des erreurs.
XRRQueryVersion()
Interroge le serveur pour connaître la version du protocole RandR supportée.
XRRGetScreenInfo()
Récupère les informations de configuration actuelles pour un écran donné. Renvoie un pointeur vers une structure opaque XRRScreenConfiguration.
XRRFreeScreenConfigInfo()
Libère la mémoire allouée par XRRGetScreenInfo.
XRRSetScreenConfig()
Définit la configuration de l'écran. Cela inclut la taille, la rotation et le taux de rafraîchissement.
XRRSetScreenConfigAndRate()
Identique à XRRSetScreenConfig mais permet également de spécifier le taux de rafraîchissement.
XRRConfigRotations()
Récupère les rotations possibles pour l'écran actuel et la rotation actuelle.
XRRConfigTimes()
Récupère les horodatages associés à la configuration actuelle de l'écran.
XRRConfigSizes()
Récupère les tailles possibles pour l'écran actuel.
XRRConfigRates()
Récupère les taux de rafraîchissement possibles pour une taille d'écran donnée.
XRRConfigCurrentConfiguration()
Récupère la configuration actuelle de l'écran (taille et rotation).
XRRConfigCurrentRate()
Récupère le taux de rafraîchissement actuel de l'écran.
XRRRootToScreen()
Convertit une fenêtre racine en numéro d'écran.
XRRSelectInput()
Permet à un client de recevoir des notifications de changement de configuration de l'écran.
XRRUpdateConfiguration()
Met à jour l'état interne de Xlib suite à un événement de changement de configuration de l'écran.
XRRRotations()
Récupère les rotations possibles et la rotation actuelle pour un écran donné (version sans cache).
XRRSizes()
Récupère les tailles possibles pour un écran donné (version sans cache).
XRRRates()
Récupère les taux de rafraîchissement possibles pour une taille d'écran donnée sur un écran donné (version sans cache).
XRRTimes()
Récupère les horodatages associés à la configuration d'un écran donné (version sans cache).

FONCTIONS

Il existe deux classes d'interfaces : celles qui peuvent être appelées en toute sécurité même si RandR n'est pas implémenté sur un écran (pour rendre les idiomes courants indépendants du support du serveur), et celles qui retourneront des erreurs si l'extension n'est pas présente.

XRRRotations retourne à la fois l'ensemble des rotations/réflexions possibles prises en charge (sous forme de masque de bits) comme valeur de la fonction, ainsi que la rotation/réflexion actuelle de l'écran.

XRRSizes retourne la taille et un pointeur vers les tailles actuelles prises en charge par l'écran spécifié. La première taille spécifiée est la taille par défaut du serveur. Si RandR n'est pas pris en charge, elle retourne 0 pour le nombre de tailles.

XRRRates retourne un pointeur vers les fréquences prises en charge par la taille spécifiée. Si RandR n'est pas pris en charge, elle retourne 0 pour le nombre de fréquences.

XRRTimes retourne l'heure dernièrement rapportée par le serveur ainsi que l'horodatage du dernier changement de configuration. Si la configuration a changé depuis que le client a mis à jour sa vue de l'heure du serveur, les requêtes de changement de configuration échoueront jusqu'à ce que le client ait un horodatage à jour.

XRRRootToScreen retourne le numéro de l'écran étant donné une fenêtre racine (par exemple, depuis un événement XRRScreenChangeNotifyEvent).

Le reste des fonctions échoueront si elles sont appliquées à des écrans qui n'implémentent pas l'extension RandR. XRRSetScreenConfig définit la taille de l'écran ainsi que la rotation et la réflexion aux valeurs désirées sur l'écran spécifié par draw, ou retourne une erreur BadValue. size_index spécifie quelle configuration de taille doit être utilisée, rotation spécifie quelle rotation ou réflexion doit être utilisée (sinon une erreur BadValue est retournée). L'horodatage timestamp est utilisé par le serveur pour s'assurer que le client dispose d'informations de configuration à jour. Le statut est retourné pour indiquer le succès ou l'échec ; un client doit actualiser ses informations de configuration si elle échoue et réessayer l'appel (en appelant XRRGetScreenInfo).

XRRSetScreenConfigAndRate est similaire à XRRSetScreenConfig mais définit également le taux de rafraîchissement. Si le taux spécifié n'est pas pris en charge, une erreur BadValue est retournée.

XRRConfigRotations, XRRConfigSizes, XRRConfigCurrentConfiguration, XRRConfigTimes, XRRConfigRates, et XRRConfigCurrentRate sont utilisés pour extraire des informations de configuration spécifiques d'une configuration d'écran.

XRRGetScreenInfo retourne une configuration d'écran pour une utilisation ultérieure ; les informations sont privées à la bibliothèque. Appelez XRRFreeScreenConfigInfo pour libérer ces informations lorsque vous avez terminé. Cela force un aller-retour vers le serveur.

D'autres fonctions incluent : XRRQueryExtension qui retourne les codes de base des événements et des erreurs, XRRQueryVersion, qui retourne la version actuelle de l'extension (cette information est mise en cache par la bibliothèque).

RESTRICTIONS

Xrandr restera compatible ascendante après la version actuelle 1.0.
