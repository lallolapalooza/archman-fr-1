NOM


Xrandr - Extension X de redimensionnement, rotation et réflexion.

SYNTAXE

ARGUMENTS

display
Spécifie la connexion au serveur X.
screen
Spécifie quel écran.
draw
Spécifie l'écran.
rotation
Spécifie les rotations ou réflexions possibles de l'écran.
current_rotation
Spécifie les rotations et réflexions actuelles de l'écran.
timestamp
Spécifie l'horodatage du serveur.
config_timestamp
Spécifie l'horodatage de la dernière (re)configuration de l'écran.
config
Spécifie la configuration de l'écran utilisée.
sizes
Spécifie le tableau des tailles supportées.
rate
Spécifie le taux de rafraîchissement en Hz.

TYPES DE DONNÉES

Rotations/Réflexions

Peut être l'une des suivantes :

#define RR_Rotate_0             1
#define RR_Rotate_90            2
#define RR_Rotate_180           4
#define RR_Rotate_270           8
/∗ nouvelle version 1.0 du protocole, pour permettre la réflexion de l'écran */
/∗ la réflexion est appliquée après la rotation */
#define RR_Reflect_X            16
#define RR_Reflect_Y            32
typedef struct {
    int	width, height;
    int	mwidth, mheight;
} XRRScreenSize;
typedef struct {
    int type;				/∗ base d'événement */
    unsigned long serial;	/∗ # de la dernière requête traitée par le serveur */
    Bool send_event;		/∗ vrai si cela provient d'une requête SendEvent */
    Display *display;		/∗ Display à partir duquel l'événement a été lu */
    Window window;			/∗ fenêtre qui a sélectionné cet événement */
    Window root;			/∗ Fenêtre racine pour l'écran modifié */
    Time timestamp;			/∗ quand le changement d'écran s'est produit */
    Time config_timestamp;	/∗ quand la dernière modification de configuration */
    SizeID size_index;
    SubpixelOrder subpixel_order;
    Rotation rotation;
    int width;
    int height;
    int mwidth;
    int mheight;
} XRRScreenChangeNotifyEvent;
La structure XRRScreenSize contient une taille racine possible en pixels et en millimètres.

Un événement XRRScreenChangeNotifyEvent est envoyé à un client qui a demandé une notification chaque fois que la configuration de l'écran est modifiée. Un client peut effectuer cette requête en appelant XRRSelectInput, en passant le display, la fenêtre racine, et le masque RRScreenChangeNotifyMask.

XRRScreenConfiguration est un type de données opaque contenant les informations de configuration d'un écran.

Horodatages

Les horodatages sont inclus et doivent être utilisés pour s'assurer que le client dispose des informations les plus récentes : l'écran peut changer de propriétés à la volée et cela garantit que sa connaissance de la configuration est à jour. Ceci est conçu pour aider aux problèmes lorsque les écrans pourraient devenir connectables à chaud à l'avenir.

DESCRIPTION

Xrandr est une bibliothèque simple conçue pour interagir avec l'extension X de redimensionnement et de rotation. Cela permet aux clients de changer la taille et la rotation de la fenêtre racine d'un écran, ainsi que la capacité de refléter l'écran sur l'un ou l'autre axe (si supporté par l'implémentation). La rotation et la réflexion peuvent être implémentées par logiciel et entraîner des performances plus lentes si la rotation et la réflexion sont implémentées de cette manière (comme c'est le cas pour toutes les implémentations en octobre 2002).

La bibliothèque Xrandr effectue une mise en cache minimale pour éviter les allers-retours afin de fournir aux clients des informations fréquemment utilisées. Voir « The X Resize and Rotate Extension » pour une description détaillée ; notez également que le changement de profondeur, tel que décrit dans le document, n'est pas implémenté, et ne le sera peut-être jamais, car la mémoire d'affichage augmente rapidement et les toolkits commencent déjà à supporter la migration, ce qui atténue le besoin de changement de profondeur. Si cela est implémenté à l'avenir, nous prévoyons de le faire via une extension compatible ascendante de la bibliothèque/protocole actuel ; les fonctionnalités décrites ici devraient continuer à fonctionner.

La rotation et la réflexion et leur interaction peuvent être déroutantes. Dans Randr, le système de coordonnées est tourné dans le sens inverse des aiguilles d'une montre par rapport à l'orientation normale. La réflexion se fait le long du système de coordonnées du système de fenêtrage, et non sur les axes X et Y physiques de l'écran, de sorte que la rotation et la réflexion n'interagissent pas. L'autre façon d'envisager la réflexion est de la traiter comme spécifié dans l'orientation « normale », avant la rotation.

L'événement XRRScreenChangeNotify est envoyé aux clients qui demandent à être informés chaque fois que la configuration de la fenêtre racine change. Les changements de configuration peuvent inclure la résolution, la taille physique, l'ordre des sous-pixels (voir XRender(3)), et la rotation. Notez que les changements de l'un ou de tous ces éléments peuvent survenir en raison d'événements externes (contrôle utilisateur dans le serveur X, connexion/déconnexion d'un moniteur différent/écran plat) et ne sont pas uniquement le résultat d'une requête de protocole/bibliothèque au serveur X.

De plus, pour éliminer une condition de concurrence potentielle, cet événement peut être généré immédiatement lors de la sélection de la notification si l'écran a changé depuis que le client de Xrandr s'est connecté au serveur X, afin de permettre un changement fiable de la résolution de l'écran lorsqu'un utilisateur peut se connecter et modifier la configuration pendant que plusieurs clients démarrent.

Notification Xlib

Les clients doivent rappeler Xlib en utilisant XRRUpdateConfiguration lorsque les événements de notification de changement de configuration de l'écran sont générés (ou que des changements de configuration de la fenêtre racine se produisent, pour mettre à jour la vue de Xlib de la résolution, de la taille, de la rotation, de la réflexion ou de l'ordre des sous-pixels. Généralement, les toolkits effectueront cette opération pour le compte des applications ; nous ne voulions pas modifier les données de la structure d'affichage à l'insu des toolkits, car dans les clients multithreadés, diverses conditions de concurrence pourraient survenir. Les toolkits devraient fournir aux clients un mécanisme de notification de changement d'écran, bien sûr.

FONCTIONS

Il existe deux classes d'interfaces : celles qui peuvent être appelées en toute sécurité même si RandR n'est pas implémenté sur un écran (pour que les idiomes courants ne dépendent pas du support du serveur), et celles qui renverront des erreurs si l'extension n'est pas présente.

XRRRotations renvoie à la fois l'ensemble possible de rotations/réflexions prises en charge (sous forme de masque de bits) comme valeur de la fonction, ainsi que la rotation/réflexion actuelle de l'écran.

XRRSizes renvoie la taille et un pointeur vers les tailles actuelles prises en charge par l'écran spécifié. La première taille spécifiée est la taille par défaut du serveur. Si RandR n'est pas pris en charge, elle renvoie 0 pour le nombre de tailles.

XRRRates renvoie un pointeur vers les fréquences prises en charge par la taille spécifiée. Si RandR n'est pas pris en charge, elle renvoie 0 pour le nombre de fréquences.

XRRTimes renvoie l'heure signalée pour la dernière fois par le serveur ainsi que l'horodatage du dernier changement de configuration. Si la configuration a changé depuis que le client a mis à jour sa vue du temps serveur, les requêtes pour changer la configuration échoueront jusqu'à ce que le client dispose d'un horodatage à jour.

XRRRootToScreen renvoie le numéro de l'écran étant donné une fenêtre racine (par exemple, à partir d'un événement XRRScreenChangeNotifyEvent).

Le reste des fonctions échouera si elles sont appliquées à des écrans qui n'implémentent pas l'extension RandR. XRRSetScreenConfig définit la taille, la rotation et la réflexion de l'écran aux valeurs souhaitées sur l'écran spécifié par draw, ou renvoie une erreur BadValue. size_index spécifie quelle configuration de taille doit être utilisée, rotation spécifie quelle rotation ou réflexion doit être utilisée (ou une erreur BadValue est retournée). L'horodatage est utilisé par le serveur pour s'assurer que le client dispose d'informations de configuration à jour. Le statut est renvoyé pour indiquer le succès ou l'échec ; un client doit actualiser ses informations de configuration si cela échoue et réessayer l'appel (en appelant XRRGetScreenInfo).

XRRSetScreenConfigAndRate est similaire à XRRSetScreenConfig mais définit également le taux de rafraîchissement. Si le taux spécifié n'est pas pris en charge, une erreur BadValue est retournée.

XRRConfigRotations, XRRConfigSizes, XRRConfigCurrentConfiguration, XRRConfigTimes, XRRConfigRates, et XRRConfigCurrentRate sont utilisés pour extraire des informations de configuration spécifiques d'une configuration d'écran.

XRRGetScreenInfo renvoie une configuration d'écran pour une utilisation ultérieure ; les informations sont privées à la bibliothèque. Appelez XRRFreeScreenConfigInfo pour libérer ces informations lorsque vous avez terminé. Cela force un aller-retour vers le serveur.

Les autres fonctions incluent : XRRQueryExtension qui renvoie les codes de base d'événement et d'erreur, XRRQueryVersion, qui renvoie la version actuelle de l'extension (cette information est mise en cache par la bibliothèque).

RESTRICTIONS

Xrandr restera rétrocompatible après la version actuelle 1.0.
