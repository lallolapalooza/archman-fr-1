XrmGetFileDatabase(3) FONCTIONS XLIB XrmGetFileDatabase(3)

NOM

XrmGetFileDatabase, XrmPutFileDatabase, XrmGetStringDatabase, XrmLocaleOfDatabase, XrmGetDatabase, XrmSetDatabase, XrmDestroyDatabase - récupérer et stocker des bases de données de ressources

SYNTAXE

#include <X11/Xresource.h>

XrmDatabase XrmGetFileDatabase(char *filename);

void XrmPutFileDatabase(XrmDatabase database, _Xconst char *stored_db);

XrmDatabase XrmGetStringDatabase(_Xconst char *data);

const char *XrmLocaleOfDatabase(XrmDatabase database);

XrmDatabase XrmGetDatabase(Display *display);

void XrmSetDatabase(Display *display, XrmDatabase database);

void XrmDestroyDatabase(XrmDatabase database);

ARGUMENTS

filename
Spécifie le nom du fichier de la base de données de ressources.
database
Spécifie la base de données à utiliser.
stored_db
Spécifie le nom du fichier pour la base de données stockée.
data
Spécifie le contenu de la base de données à l'aide d'une chaîne de caractères.
database
Spécifie la base de données de ressources.
display
Spécifie la connexion au serveur X.

DESCRIPTION

La fonction XrmGetFileDatabase ouvre le fichier spécifié, crée une nouvelle base de données de ressources et la charge avec les spécifications lues à partir du fichier spécifié. Le fichier spécifié doit contenir une séquence d'entrées au format valide ResourceLine (voir section 15.1) ; la base de données résultant de la lecture d'un fichier avec une syntaxe incorrecte est dépendante de l'implémentation. Le fichier est analysé dans la locale actuelle, et la base de données est créée dans la locale actuelle. Si elle ne parvient pas à ouvrir le fichier spécifié, XrmGetFileDatabase retourne NULL.

La fonction XrmPutFileDatabase stocke une copie de la base de données spécifiée dans le fichier spécifié. Le texte est écrit dans le fichier sous forme d'une séquence d'entrées au format valide ResourceLine (voir section 15.1). Le fichier est écrit dans la locale de la base de données. Les entrées contenant des noms de ressources qui ne sont pas dans l'encodage de caractères portable de l'hôte ou contenant des valeurs qui ne sont pas dans l'encodage de la locale de la base de données, sont écrites d'une manière dépendante de l'implémentation. L'ordre dans lequel les entrées sont écrites est dépendant de l'implémentation. Les entrées avec des types de représentation autres que “String” sont ignorées.

La fonction XrmGetStringDatabase crée une nouvelle base de données et stocke les ressources spécifiées dans la chaîne terminée par un caractère nul. XrmGetStringDatabase est similaire à XrmGetFileDatabase, sauf qu'elle lit les informations à partir d'une chaîne au lieu d'un fichier. La chaîne doit contenir une séquence d'entrées au format valide ResourceLine (voir section 15.1) terminée par un caractère nul ; la base de données résultant de l'utilisation d'une chaîne avec une syntaxe incorrecte est dépendante de l'implémentation. La chaîne est analysée dans la locale actuelle, et la base de données est créée dans la locale actuelle.

Si database est NULL, XrmDestroyDatabase retourne immédiatement.

La fonction XrmLocaleOfDatabase retourne le nom de la locale liée à la base de données spécifiée, sous forme d'une chaîne terminée par un caractère nul. La chaîne de nom de locale retournée est la propriété de Xlib et ne doit pas être modifiée ou libérée par le client. Xlib n'est pas autorisé à libérer la chaîne tant que la base de données n'est pas détruite. Jusqu'à ce que la chaîne soit libérée, elle ne sera pas modifiée par Xlib.

La fonction XrmGetDatabase retourne la base de données associée à l'affichage spécifié. Elle retourne NULL si une base de données n'a pas encore été définie.

La fonction XrmSetDatabase associe la base de données de ressources spécifiée (ou NULL) à l'affichage spécifié. La base de données précédemment associée à l'affichage (le cas échéant) n'est pas détruite. Un client ou une boîte à outils peut trouver cette fonction pratique pour conserver une base de données une fois qu'elle est construite.

SYNTAXE DE FICHIER

La syntaxe d'un fichier de ressources est une séquence de lignes de ressources terminées par des caractères de nouvelle ligne ou la fin du fichier. La syntaxe d'une ligne de ressource individuelle est :

ResourceLine	=	Comment | IncludeFile | ResourceSpec | <ligne vide>
Comment	=	"!" {<tout caractère sauf nul ou nouvelle ligne>}
IncludeFile	=	"#" WhiteSpace "include" WhiteSpace FileName WhiteSpace
FileName	=	<nom de fichier valide pour le système d'exploitation>
ResourceSpec	=	WhiteSpace ResourceName WhiteSpace ":" WhiteSpace Value
ResourceName	=	[Binding] {Component Binding} ComponentName
Binding	=	"." | "*"
WhiteSpace	=	{<espace> | <tabulation horizontale>}
Component	=	"?" | ComponentName
ComponentName	=	NameChar {NameChar}
NameChar	=	"a"-"z" | "A"-"Z" | "0"-"9" | "_" | "-"
Value	=	{<tout caractère sauf nul ou nouvelle ligne non échappée>}

Les éléments séparés par une barre verticale (|) sont des alternatives. Les accolades ({...}) indiquent zéro ou plusieurs répétitions des éléments entre parenthèses. Les crochets ([...]) indiquent que l'élément entre parenthèses est facultatif. Les guillemets ("...") sont utilisés autour des caractères littéraux.

Les lignes IncludeFile sont interprétées en remplaçant la ligne par le contenu du fichier spécifié. Le mot “include” doit être en minuscules. Le nom du fichier est interprété par rapport au répertoire du fichier dans lequel la ligne se trouve (par exemple, si le nom du fichier ne contient pas de répertoire ou contient une spécification de répertoire relative).

Si un ResourceName contient une séquence contiguë de deux caractères Binding ou plus, la séquence sera remplacée par un seul caractère “.” si la séquence ne contient que des caractères “.” ; sinon, la séquence sera remplacée par un seul caractère “*”.

Une base de données de ressources ne contient jamais plus d'une entrée pour un ResourceName donné. Si un fichier de ressources contient plusieurs lignes avec le même ResourceName, la dernière ligne du fichier est utilisée.

Tous les caractères d'espacement avant ou après le nom ou le deux-points dans un ResourceSpec sont ignorés. Pour permettre à une Value de commencer par un espace, la séquence de deux caractères “\espace” (antislash suivi d'un espace) est reconnue et remplacée par un caractère espace, et la séquence de deux caractères “\tab” (antislash suivi d'une tabulation horizontale) est reconnue et remplacée par un caractère de tabulation horizontale. Pour permettre à une Value de contenir des caractères de nouvelle ligne, la séquence de deux caractères “\n” est reconnue et remplacée par un caractère de nouvelle ligne. Pour permettre à une Value d'être répartie sur plusieurs lignes dans un fichier texte, la séquence de deux caractères “\newline” (antislash suivi d'une nouvelle ligne) est reconnue et supprimée de la valeur. Pour permettre à une Value de contenir des codes de caractères arbitraires, la séquence de quatre caractères “\nnn”, où chaque n est un chiffre compris entre “0” et “7”, est reconnue et remplacée par un seul octet contenant la valeur octale spécifiée par la séquence. Enfin, la séquence de deux caractères “\\” est reconnue et remplacée par un seul antislash.

XrmGetStringDatabase(3)

NAME

XrmGetStringDatabase — build a representation of a resource database from a string

SYNTAX

XrmDatabase XrmGetStringDatabase ( String representation );

ARGUMENTS

representation
Specifies a pointer to a null-terminated string containing the resource database representation.

DESCRIPTION

The XrmGetStringDatabase function builds and returns a representation of a resource database from the null-terminated string specified by representation.

The string must contain a valid resource database representation. The database representation is a set of resource specifications, one per line, terminated by a null character.

The format of the resource database representation is described in X(1).

The database returned by XrmGetStringDatabase is not mutable. If you need a mutable database, use XrmGetFileDatabase to read a file and then use XrmMergeDatabases to merge it into a mutable database.

FILE SYNTAX

The format of the resource database representation is as follows:

Each line contains a resource specification. Lines starting with an exclamation mark (!) or a hash mark (#) are comments and are ignored.

A resource specification consists of one or more component names separated by periods (.), optionally followed by an asterisk (*) or other separator. The component names are identifiers that correspond to the widgets in the application hierarchy.

For example:


    Emacs.geometry:   80x24+10+5
    Emacs*scrollBar.width: 15
    Emacs*Text*font:    -adobe-courier-medium-r-normal--12-120-75-75-m-70-iso10646-1
    *background:      white

The asterisk (*) is a wildcard character that matches any sequence of component names. It is equivalent to using a period (.) followed by a wildcard specification.

The format of the resource database representation is described in detail in the X(1) manual page.

XrmGetStringDatabase(3)

NOM

XrmGetStringDatabase — construire une représentation d'une base de données de ressources à partir d'une chaîne de caractères

SYNTAXE

XrmDatabase XrmGetStringDatabase ( String representation );

ARGUMENTS

representation
Spécifie un pointeur vers une chaîne de caractères terminée par un caractère nul contenant la représentation de la base de données de ressources.

DESCRIPTION

La fonction XrmGetStringDatabase construit et retourne une représentation d'une base de données de ressources à partir de la chaîne de caractères terminée par un caractère nul spécifiée par representation.

La chaîne doit contenir une représentation valide de base de données de ressources. La représentation de la base de données est un ensemble de spécifications de ressources, une par ligne, terminées par un caractère nul.

Le format de la représentation de la base de données de ressources est décrit dans X(1).

La base de données retournée par XrmGetStringDatabase n'est pas modifiable. Si vous avez besoin d'une base de données modifiable, utilisez XrmGetFileDatabase pour lire un fichier, puis utilisez XrmMergeDatabases pour la fusionner dans une base de données modifiable.

SYNTAXE DE FICHIER

Le format de la représentation de la base de données de ressources est le suivant :

Chaque ligne contient une spécification de ressource. Les lignes commençant par un point d'exclamation (!) ou un dièse (#) sont des commentaires et sont ignorées.

Une spécification de ressource se compose d'un ou plusieurs noms de composants séparés par des points (.), éventuellement suivis d'un astérisque (*) ou d'un autre séparateur. Les noms de composants sont des identifiants qui correspondent aux widgets dans la hiérarchie de l'application.

Par exemple :


    Emacs.geometry:   80x24+10+5
    Emacs*scrollBar.width: 15
    Emacs*Text*font:    -adobe-courier-medium-r-normal--12-120-75-75-m-70-iso10646-1
    *background:      white

L'astérisque (*) est un caractère générique qui correspond à toute séquence de noms de composants. Il est équivalent à utiliser un point (.) suivi d'une spécification générique.

Le format de la représentation de la base de données de ressources est décrit en détail dans la page de manuel X(1).
