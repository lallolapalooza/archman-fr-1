TYPES DE DONNÉES

Rotations/Réflexions

Peut être l'une des suivantes :

#define RR_Rotate_0             1
#define RR_Rotate_90            2
#define RR_Rotate_180           4
#define RR_Rotate_270           8
/∗ nouveau dans le protocole 1.0, pour permettre la réflexion de l'écran */
/∗ la réflexion est appliquée après la rotation */
#define RR_Reflect_X            16
#define RR_Reflect_Y            32
typedef struct {
    int	width, height;
    int	mwidth, mheight;
} XRRScreenSize;
typedef struct {
    int type;				/∗ base d'événement */
    unsigned long serial;	/∗ # de la dernière requête traitée par le serveur */
    Bool send_event;		/∗ vrai si cela provient d'une requête SendEvent */
    Display *display;		/∗ Affichage à partir duquel l'événement a été lu */
    Window window;			/∗ fenêtre qui a sélectionné cet événement */
    Window root;			/∗ Fenêtre racine pour l'écran modifié */
    Time timestamp;			/∗ moment où le changement d'écran s'est produit */
    Time config_timestamp;	/∗ moment de la dernière modification de configuration */
    SizeID size_index;
    SubpixelOrder subpixel_order;
    Rotation rotation;
    int width;
    int height;
    int mwidth;
    int mheight;
} XRRScreenChangeNotifyEvent;
La structure XRRScreenSize contient une taille racine possible en pixels et en millimètres.

Un événement XRRScreenChangeNotifyEvent est envoyé à un client qui a demandé à être informé chaque fois que la configuration de l'écran est modifiée. Un client peut effectuer cette requête en appelant XRRSelectInput, en passant l'affichage, la fenêtre racine et le masque RRScreenChangeNotifyMask.

XRRScreenConfiguration est un type de données opaque contenant les informations de configuration d'un écran.

Horodatages

Les horodatages sont inclus et doivent être utilisés pour garantir que le client joue avec toutes ses cartes : l'écran peut changer de propriétés à la volée et cela garantit que sa connaissance de la configuration est à jour. Ceci afin d'aider les problèmes lorsque les écrans pourraient devenir échangeables à chaud à l'avenir.

DESCRIPTION

Xrandr est une bibliothèque simple conçue pour interagir avec l'extension X pour redimensionner et faire pivoter. Cela permet aux clients de modifier la taille et la rotation de la fenêtre racine d'un écran, ainsi que la capacité de refléter l'écran autour de l'un ou l'autre axe (si supporté par l'implémentation). La rotation et la réflexion peuvent être implémentées par logiciel et peuvent entraîner des performances plus lentes si la rotation et la réflexion sont implémentées de cette manière (comme le sont toutes les implémentations en octobre 2002).

La bibliothèque Xrandr effectue une mise en cache minimale pour éviter les allers-retours afin de fournir aux clients des informations fréquemment utilisées. Voir "L'extension X pour redimensionner et faire pivoter" pour une description détaillée ; notez également que le changement de profondeur, tel que décrit dans le document, n'est pas implémenté, et pourrait (ou pourrait ne pas) jamais être implémenté, car la mémoire d'affichage augmente rapidement et les toolkits commencent déjà à supporter la migration, atténuant le besoin de changement de profondeur. Si cela est implémenté à l'avenir, nous nous attendons à le faire via une extension compatible ascendante de la bibliothèque/protocole actuel ; les fonctionnalités décrites ici devraient continuer à fonctionner.

La rotation et la réflexion et la manière dont elles interagissent peuvent être confuses. Dans Randr, le système de coordonnées est tourné dans le sens antihoraire par rapport à l'orientation normale. La réflexion se fait le long du système de coordonnées de la fenêtre, et non des axes X et Y physiques de l'écran, de sorte que la rotation et la réflexion n'interagissent pas. L'autre façon d'envisager la réflexion est de la traiter comme spécifié dans l'orientation "normale", avant la rotation.

L'événement XRRScreenChangeNotify est envoyé aux clients qui demandent à être informés chaque fois que la configuration de la fenêtre racine change. Les changements de configuration peuvent inclure la résolution, la taille physique, l'ordre des sous-pixels (voir XRender(3)), et la rotation. Notez que les changements de l'un ou de tous ces éléments pourraient se produire en raison d'événements externes (contrôle utilisateur dans le serveur X, un moniteur différent/ un écran plat branché à chaud) et ne sont pas seulement le résultat d'une requête de protocole/bibliothèque au serveur X.

De plus, pour éliminer une condition de concurrence potentielle, cet événement peut être généré immédiatement lors de la sélection pour la notification si l'écran a changé depuis que le client de Xrandr s'est connecté au serveur X, afin de permettre un changement de résolution d'écran fiable lorsqu'un utilisateur peut se connecter et changer la configuration pendant qu'un ou plusieurs clients démarrent.

Notification Xlib

Les clients doivent rappeler dans Xlib en utilisant XRRUpdateConfiguration lorsque les événements de notification de changement de configuration d'écran sont générés (ou lorsque des changements de configuration de la fenêtre racine se produisent, pour mettre à jour la vue Xlib de la résolution, de la taille, de la rotation, de la réflexion ou de l'ordre des sous-pixels. En général, les toolkits effectueront cette opération au nom des applications ; nous ne voulions pas changer les données de structure d'affichage derrière le dos des toolkits, car dans les clients multithreadés, diverses conditions de concurrence pourraient survenir. Les toolkits devraient fournir aux clients un mécanisme de notification de changement d'écran, bien sûr.

DATATYPES

La structure XRRScreenConfiguration est opaque et doit être manipulée uniquement par les fonctions XRRGetScreenInfo, XRRFreeScreenConfigInfo, et les fonctions XRRConfig.

Les constantes Rotation sont définies comme suit :

#define RR_Rotate_0     (1 << 0)
#define RR_Rotate_90    (1 << 1)
#define RR_Rotate_180   (1 << 2)
#define RR_Rotate_270   (1 << 3)
#define RR_Reflect_X    (1 << 4)
#define RR_Reflect_Y    (1 << 5)

Ces valeurs peuvent être combinées en utilisant l'opérateur OU logique.

DESCRIPTION

Il existe deux classes d'interfaces : celles qui peuvent être appelées en toute sécurité même si RandR n'est pas implémenté sur un écran (pour que les idiomes courants ne dépendent pas du support du serveur), et celles qui renverront des erreurs si l'extension n'est pas présente.

XRRRotations renvoie à la fois l'ensemble des rotations/réflexions supportées (sous forme de masque de bits) comme valeur de la fonction, ainsi que la rotation/réflexion actuelle de l'écran.

XRRSizes renvoie la taille et un pointeur vers les tailles actuelles supportées par l'écran spécifié. La première taille spécifiée est la taille par défaut du serveur. Si RandR n'est pas supporté, il renvoie 0 pour le nombre de tailles.

XRRRates renvoie un pointeur vers les fréquences supportées par la taille spécifiée. Si RandR n'est pas supporté, il renvoie 0 pour le nombre de fréquences.

XRRTimes renvoie l'heure rapportée pour la dernière fois par le serveur ainsi que le timestamp du dernier changement de configuration. Si la configuration a changé depuis que le client a mis à jour sa vue de l'heure du serveur, les requêtes pour changer la configuration échoueront jusqu'à ce que le client ait un timestamp à jour.

XRRRootToScreen renvoie le numéro de l'écran étant donné une fenêtre racine (par exemple, à partir d'un événement XRRScreenChangeNotifyEvent).

Le reste des fonctions échouera si elles sont appliquées à des écrans ne mettant pas en œuvre l'extension RandR. XRRSetScreenConfig définit la taille et la rotation/réflexion de l'écran aux valeurs souhaitées sur l'écran spécifié par win, ou renvoie une erreur BadValue. size_index spécifie quelle configuration de taille doit être utilisée, rotation spécifie quelle rotation ou réflexion doit être utilisée (ou une erreur BadValue est renvoyée). Le timestamp est utilisé par le serveur pour s'assurer que le client dispose d'informations de configuration à jour. Le statut est renvoyé pour indiquer le succès ou l'échec ; un client doit rafraîchir ses informations de configuration si cela échoue et réessayer l'appel (en appelant XRRGetScreenInfo).

XRRSetScreenConfigAndRate est comme XRRSetScreenConfig mais définit également la fréquence de rafraîchissement. Si la fréquence spécifiée n'est pas supportée, une erreur BadValue est renvoyée.

XRRConfigRotations, XRRConfigSizes, XRRConfigCurrentConfiguration, XRRConfigTimes, XRRConfigRates, et XRRConfigCurrentRate sont utilisées pour extraire des informations de configuration spécifiques d'une configuration d'écran.

XRRGetScreenInfo renvoie une configuration d'écran pour une utilisation ultérieure ; les informations sont privées à la bibliothèque. Appelez XRRFreeScreenConfigInfo pour libérer ces informations lorsque vous avez terminé. Cela force un aller-retour vers le serveur.

Les autres fonctions incluent : XRRQueryExtension qui renvoie les codes de base des événements et des erreurs, XRRQueryVersion, qui renvoie la version actuelle de l'extension (cette information est mise en cache par la bibliothèque).

RESTRICTIONS

Xrandr restera compatible avec les versions antérieures après la sortie actuelle 1.0.
