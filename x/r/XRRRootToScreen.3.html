XRANDR(3) Manuel des fonctions de bibliothèque XRANDR(3)

NOM


Xrandr - Extension X pour le redimensionnement, la rotation et la réflexion.

ARGUMENTS

display
Spécifie la connexion au serveur X.
screen
Spécifie quel écran.
draw
Spécifie l'écran.
rotation
Spécifie les rotations ou réflexions possibles de l'écran.
current_rotation
Spécifie les rotations et réflexions actuelles de l'écran.
timestamp
Spécifie l'horodatage du serveur.
config_timestamp
Spécifie l'horodatage de la dernière (re)configuration de l'écran.
config
Spécifie la configuration d'écran utilisée.
sizes
Spécifie le tableau des tailles prises en charge.
rate
Spécifie le taux de rafraîchissement en Hz.

TYPES DE DONNÉES

Rotations/Réflexions

Peut être l'un des suivants :

#define RR_Rotate_0             1
#define RR_Rotate_90            2
#define RR_Rotate_180           4
#define RR_Rotate_270           8
/∗ nouveau dans le protocole 1.0, pour permettre la réflexion de l'écran */
/∗ la réflexion est appliquée après la rotation */
#define RR_Reflect_X            16
#define RR_Reflect_Y            32
typedef struct {
    int	width, height;
    int	mwidth, mheight;
} XRRScreenSize;
typedef struct {
    int type;				/∗ base d'événements */
    unsigned long serial;	/∗ # de la dernière requête traitée par le serveur */
    Bool send_event;		/∗ vrai si cela provient d'une requête SendEvent */
    Display *display;		/∗ Affichage à partir duquel l'événement a été lu */
    Window window;			/∗ fenêtre qui a sélectionné cet événement */
    Window root;			/∗ Fenêtre racine pour l'écran modifié */
    Time timestamp;			/∗ quand le changement d'écran s'est produit */
    Time config_timestamp;	/∗ quand le dernier changement de configuration */
    SizeID size_index;
    SubpixelOrder subpixel_order;
    Rotation rotation;
    int width;
    int height;
    int mwidth;
    int mheight;
} XRRScreenChangeNotifyEvent;
La structure XRRScreenSize contient une taille racine possible en pixels et en millimètres.

Un événement XRRScreenChangeNotifyEvent est envoyé à un client qui a demandé une notification chaque fois que la configuration de l'écran est modifiée. Un client peut effectuer cette demande en appelant XRRSelectInput, en passant l'affichage, la fenêtre racine et le masque RRScreenChangeNotifyMask.

XRRScreenConfiguration est un type de données opaque contenant les informations de configuration d'un écran.

Horodatages

Les horodatages sont inclus et doivent être utilisés pour s'assurer que le client joue avec toutes ses cartes : l'écran peut changer de propriétés à la volée et cela garantit que ses connaissances de la configuration sont à jour. Ceci est pour aider les problèmes lorsque les écrans peuvent devenir "hot-pluggable" à l'avenir.

DESCRIPTION

Xrandr est une bibliothèque simple conçue pour interagir avec l'extension X Resize and Rotate. Cela permet aux clients de changer la taille et la rotation de la fenêtre racine d'un écran, ainsi que la capacité de refléter l'écran sur l'un ou l'autre axe (si pris en charge par l'implémentation). La rotation et la réflexion peuvent être implémentées par logiciel et peuvent entraîner des performances plus lentes si la rotation et la réflexion sont implémentées de cette manière (comme le sont toutes les implémentations en octobre 2002).

La bibliothèque Xrandr effectue une mise en cache minimale pour éviter les allers-retours afin de fournir aux clients des informations fréquemment utilisées. Voir "The X Resize and Rotate Extension" pour une description détaillée ; notez également que le changement de profondeur, tel que décrit dans le document, n'est pas implémenté, et peut (ou peut ne pas) jamais être implémenté, car la mémoire d'affichage augmente rapidement et les toolkits commencent déjà à prendre en charge la migration, atténuant le besoin de changement de profondeur. S'il est implémenté à l'avenir, nous prévoyons de le faire via une extension compatible ascendante à la bibliothèque/protocole actuel ; les fonctionnalités décrites ici devraient continuer à fonctionner.

La rotation et la réflexion, ainsi que leur interaction, peuvent être déroutantes. Dans Randr, le système de coordonnées est tourné dans le sens inverse des aiguilles d'une montre par rapport à l'orientation normale. La réflexion se fait le long du système de coordonnées du système de fenêtrage, et non des axes X et Y de l'écran physique, de sorte que la rotation et la réflexion n'interagissent pas. L'autre façon d'envisager la réflexion est de la traiter comme spécifiée dans l'orientation "normale", avant la rotation.

L'événement XRRScreenChangeNotify est envoyé aux clients qui demandent à être informés chaque fois que la configuration de la fenêtre racine change. Les changements de configuration peuvent inclure la résolution, la taille physique, l'ordre des sous-pixels (voir XRender(3)) et la rotation. Notez que les modifications de l'un ou de tous ces éléments peuvent survenir en raison d'événements externes (contrôle utilisateur dans le serveur X, connexion/déconnexion d'un moniteur/écran plat différent) et ne résultent pas uniquement d'une demande de protocole/bibliothèque au serveur X.

De plus, pour éliminer une condition de concurrence potentielle, cet événement peut être généré immédiatement lors de la sélection de la notification si l'écran a changé depuis que le client de Xrandr s'est connecté au serveur X, afin de permettre un changement fiable de résolution d'écran lorsque l'utilisateur peut se connecter et modifier la configuration pendant qu'un ou plusieurs clients démarrent.

Notification Xlib

Les clients doivent rappeler Xlib en utilisant XRRUpdateConfiguration lorsque des événements de notification de changement de configuration de l'écran sont générés (ou que des modifications de configuration de la fenêtre racine se produisent, pour mettre à jour la vue de Xlib de la résolution, de la taille, de la rotation, de la réflexion ou de l'ordre des sous-pixels. Généralement, les toolkits effectueront cette opération pour le compte des applications ; nous ne voulions pas changer les données de structure d'affichage derrière le dos des toolkits, car dans les clients multithreadés, diverses conditions de concurrence pourraient survenir. Les toolkits devraient fournir aux clients un mécanisme de notification de changement d'écran, bien sûr.

XRRRootToScreen(3)

NAME

XRRRootToScreen, XRRRotations, XRRSizes, XRRRates, XRRTimes, XRRQueryExtension, XRRQueryVersion, XRRGetScreenInfo, XRRFreeScreenConfigInfo, XRRSetScreenConfig, XRRSetScreenConfigAndRate, XRRConfigRotations, XRRConfigSizes, XRRConfigCurrentConfiguration, XRRConfigTimes, XRRConfigRates, XRRConfigCurrentRate - RandR extension utility functions

SYNTAX

#include <X11/extensions/Xrandr.h>

boolean XRRQueryExtension (int *event_base_return, int *error_base_return);
boolean XRRQueryVersion (Display *dpy, int *major_version_return, int *minor_version_return);
Rotation XRRRotations (Display *dpy, RRCrtc crtc, Rotation *current_rotation);
XRRScreenSize *XRRSizes (Display *dpy, RRCrtc crtc, int *nsize);
short *XRRRates (Display *dpy, RRCrtc crtc, SizeID size, short *current_rate);
unsigned long XRRTimes (Display *dpy, RRCrtc crtc, Time *timestamp);
int XRRRootToScreen (Display *dpy, RROutput output);
Status XRRSetScreenConfig (Display *dpy, RRCrtc crtc, RROutput output, int size_index, Rotation rotation, Time timestamp);
Status XRRSetScreenConfigAndRate (Display *dpy, RRCrtc crtc, RROutput output, int size_index, Rotation rotation, short rate, Time timestamp);
XRRScreenConfiguration *XRRGetScreenInfo (Display *dpy, Window win);
void XRRFreeScreenConfigInfo (XRRScreenConfiguration *config);
Rotation XRRConfigRotations (XRRScreenConfiguration *config, Rotation *current_rotation);
XRRScreenSize *XRRConfigSizes (XRRScreenConfiguration *config, int *nsize);
SizeID XRRConfigCurrentConfiguration (XRRScreenConfiguration *config, Rotation *current_rotation);
unsigned long XRRConfigTimes (XRRScreenConfiguration *config, Time *timestamp);
short *XRRConfigRates (XRRScreenConfiguration *config, int *nrates);
short XRRConfigCurrentRate (XRRScreenConfiguration *config);

ARGUMENTS

All functions except XRRRootToScreen take a dpy argument, the X display structure.

XRRRotations, XRRSizes, XRRRates, XRRTimes, XRRSetScreenConfig, XRRSetScreenConfigAndRate, and XRRGetScreenInfo also take a crtc or win argument, which is the CRTC or root window associated with the screen. (Note: CRTC is the core way to interact with RandR for screen configuration.)

XRRSetScreenConfig and XRRSetScreenConfigAndRate also take a size_index argument, which specifies which size configuration is to be used.

XRRSetScreenConfig and XRRSetScreenConfigAndRate also take a rotation argument, which specifies which rotation or reflection is to be used.

XRRSetScreenConfigAndRate also takes a rate argument, which specifies the desired refresh rate.

XRRGetScreenInfo returns a pointer to an XRRScreenConfiguration structure, which is then used by the `XRRConfig*` functions.

XRRFreeScreenConfigInfo takes the pointer returned by XRRGetScreenInfo.

XRRRootToScreen takes a output argument, which is the output identifier from an event.

All configuration setting functions require a timestamp. This is used by the server to ensure that the client has up to date configuration information.

DATATYPES

Rotation
A bitmask indicating rotation and reflection. Possible values are RR_Rotate_0, RR_Rotate_90, RR_Rotate_180, RR_Rotate_270, RR_Reflect_X, RR_Reflect_Y.
SizeID
An index into the array of supported sizes returned by XRRSizes or XRRConfigSizes.
XRRScreenSize
Structure containing screen width and height in pixels and millimeters.

int width_in_pixels
int height_in_pixels
int width_in_millimeters
int height_in_millimeters

XRRScreenConfiguration
An opaque structure used by the RandR library to store screen configuration information.

DESCRIPTION

There are two classes of interfaces: those which can be safely called even if RandR is not implemented on a screen (to make common idioms not dependent on the server having support), and those which will return errors if the extension is not present.

XRRRotations returns both the possible set of rotations/reflections supported (as a bitmask) as the value of the function, along with the current rotation/reflection of the screen.

XRRSizes returns the size and a pointer to the current sizes supported by the specified screen. The first size specified is the default size of the server. If RandR is not supported, it returns 0 for the number of sizes.

XRRRates returns a pointer to the rates supported by the specified size. If RandR is not supported, it returns 0 for the number of rates.

XRRTimes returns the time last reported by the server along with the timestamp the last configuration changed. If the configuration has changed since the client last updated its view of the server time, requests to change the configuration will fail until the client has an up to date timestamp.

XRRRootToScreen returns the screen number given a root window (for example, from an XRRScreenChangeNotifyEvent).

The rest of the functions will fail if applied to screens not implementing the RandR extension. XRRSetScreenConfig sets the screen size and rotation and reflection to the desired values on the screen specified by draw, or returns a BadValue error. size_index specifies which size configuration is to be used, rotation specifies which rotation or reflection is to be used (or a BadValue error is returned). The timestamp is used by the server to make sure the client has up to date configuration information. Status is returned to indicate success or failure; a client must refresh its configuration information if it fails and try the call again (by calling XRRGetScreenInfo).

XRRSetScreenConfigAndRate is like XRRSetScreenConfig but also sets the refresh rate. If specified rate is not supported a BadValue error is returned.

XRRConfigRotations, XRRConfigSizes, XRRConfigCurrentConfiguration, XRRConfigTimes, XRRConfigRates, and XRRConfigCurrentRate are used to get specific configuration information out of a screen configuration.

XRRGetScreenInfo returns a screen configuration for later use; the information is private to the library. Call XRRFreeScreenConfigInfo to free this information when you are finished with it. It forces a round trip to the server.

Other functions include: XRRQueryExtension which returns the event and error base codes, XRRQueryVersion , which returns the current version of the extension (this information is cached by the library).

RESTRICTIONS

Xrandr will remain upward compatible after the current 1.0 release.
