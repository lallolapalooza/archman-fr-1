NOM


Xrandr - Extension X pour le redimensionnement, la rotation et la réflexion.

ARGUMENTS

display
Spécifie la connexion au serveur X.
screen
Spécifie l'écran.
draw
Spécifie l'écran.
rotation
Spécifie les rotations ou réflexions possibles de l'écran.
current_rotation
Spécifie les rotations et réflexions actuelles de l'écran.
timestamp
Spécifie l'horodatage du serveur.
config_timestamp
Spécifie l'horodatage du dernier (re)paramétrage de l'écran.
config
Spécifie la configuration de l'écran utilisée.
sizes
Spécifie le tableau des tailles prises en charge.
rate
Spécifie le taux de rafraîchissement en Hz.

TYPES DE DONNÉES

Rotations/Réflexions

Peut être l'un des éléments suivants :

#define RR_Rotate_0             1
#define RR_Rotate_90            2
#define RR_Rotate_180           4
#define RR_Rotate_270           8
/∗ nouveau dans le protocole 1.0, pour permettre la réflexion de l'écran */
/∗ la réflexion est appliquée après la rotation */
#define RR_Reflect_X            16
#define RR_Reflect_Y            32
typedef struct {
    int	width, height;
    int	mwidth, mheight;
} XRRScreenSize;
typedef struct {
    int type;				/∗ base d'événement */
    unsigned long serial;	/∗ # de la dernière requête traitée par le serveur */
    Bool send_event;		/∗ vrai si cela provient d'une requête SendEvent */
    Display *display;		/∗ Affichage à partir duquel l'événement a été lu */
    Window window;			/∗ fenêtre qui a sélectionné cet événement */
    Window root;			/∗ Fenêtre racine pour l'écran modifié */
    Time timestamp;			/∗ moment où le changement d'écran s'est produit */
    Time config_timestamp;	/∗ moment du dernier changement de configuration */
    SizeID size_index;
    SubpixelOrder subpixel_order;
    Rotation rotation;
    int width;
    int height;
    int mwidth;
    int mheight;
} XRRScreenChangeNotifyEvent;
La structure XRRScreenSize contient une taille racine possible en pixels et en millimètres.

Un XRRScreenChangeNotifyEvent est envoyé à un client qui a demandé une notification à chaque fois que la configuration de l'écran est modifiée. Un client peut effectuer cette requête en appelant XRRSelectInput, en passant l'affichage, la fenêtre racine et le masque RRScreenChangeNotifyMask.

XRRScreenConfiguration est un type de données opaque contenant les informations de configuration d'un écran.

Horodatages

Les horodatages sont inclus et doivent être utilisés pour s'assurer que le client est à jour : l'écran peut changer de propriétés à la volée et cela garantit que sa connaissance de la configuration est à jour. Ceci afin d'éviter les problèmes lorsque les écrans peuvent devenir connectables à chaud à l'avenir.

DESCRIPTION

Xrandr est une bibliothèque simple conçue pour interagir avec l'extension X de redimensionnement et de rotation. Celle-ci permet aux clients de modifier la taille et la rotation de la fenêtre racine d'un écran, ainsi que de réfléchir l'écran sur l'un ou l'autre axe (si pris en charge par l'implémentation). La rotation et la réflexion peuvent être implémentées par logiciel et peuvent entraîner des performances plus lentes si la rotation et la réflexion sont implémentées de cette manière (comme toutes les implémentations en octobre 2002).

La bibliothèque Xrandr effectue une mise en cache minimale pour éviter les allers-retours afin de fournir aux clients des informations fréquemment utilisées. Voir "The X Resize and Rotate Extension" pour une description détaillée ; notez également que le changement de profondeur, tel que décrit dans le document, n'est pas implémenté, et peut-être ne le sera jamais, car la mémoire d'affichage augmente rapidement et les boîtes à outils commencent déjà à prendre en charge la migration, atténuant ainsi le besoin de changer de profondeur. Si elle est implémentée à l'avenir, nous prévoyons de le faire via une extension compatible ascendante de la bibliothèque/protocole actuel ; les fonctionnalités décrites ici devraient continuer à fonctionner.

La rotation, la réflexion et leurs interactions peuvent être déroutantes. Dans Randr, le système de coordonnées est tourné dans le sens inverse des aiguilles d'une montre par rapport à l'orientation normale. La réflexion se fait le long du système de coordonnées du système de fenêtrage, et non le long des axes X et Y de l'écran physique, de sorte que la rotation et la réflexion n'interagissent pas. L'autre façon d'envisager la réflexion est de la considérer comme spécifiée dans l'orientation "normale", avant la rotation.

L'événement XRRScreenChangeNotify est envoyé aux clients qui demandent à être informés chaque fois que la configuration de la fenêtre racine change. Les changements de configuration peuvent inclure la résolution, la taille physique, l'ordre des sous-pixels (voir XRender(3)) et la rotation. Notez que les changements de l'un ou de tous ces éléments peuvent survenir en raison d'événements externes (contrôle utilisateur dans le serveur X, connexion/déconnexion d'un moniteur différent/écran plat) et ne sont pas seulement le résultat d'une demande de protocole/bibliothèque au serveur X.

De plus, pour éliminer une condition de concurrence potentielle, cet événement peut être généré immédiatement lors de la sélection de la notification si l'écran a changé depuis que le client Xrandr s'est connecté au serveur X, afin de permettre un changement fiable de la résolution de l'écran lorsqu'un utilisateur peut se connecter et modifier la configuration pendant que plusieurs clients démarrent.

Notification Xlib

Les clients doivent rappeler Xlib en utilisant XRRUpdateConfiguration lorsque des événements de notification de changement de configuration de l'écran sont générés (ou lorsque des changements de configuration de la fenêtre racine se produisent, pour mettre à jour la vue de Xlib sur la résolution, la taille, la rotation, la réflexion ou l'ordre des sous-pixels. Généralement, les boîtes à outils effectueront cette opération au nom des applications ; nous ne voulions pas modifier les données de la structure d'affichage à l'insu des boîtes à outils, car dans les clients multithreadés, diverses conditions de concurrence pourraient survenir. Les boîtes à outils devraient fournir aux clients un mécanisme de notification des changements d'écran, bien sûr.

FONCTIONS

XRRQueryExtension

Interroge le serveur X pour savoir si l'extension Xrandr est prise en charge. Si elle est prise en charge, elle renvoie l'octet de base des événements et des erreurs pour cette extension.

Renvoie `True` si l'extension est prise en charge, `False` sinon.

XRRQueryVersion

Interroge la version du protocole Xrandr prise en charge par le serveur.

Les numéros de version majeurs et mineurs sont renvoyés dans les pointeurs correspondants.

Renvoie `Status` (succès ou échec).

XRRGetScreenInfo

Récupère les informations de configuration actuelles pour un écran donné.

Il renvoie un pointeur vers une structure `XRRScreenConfiguration` qui contient des informations telles que les tailles disponibles, les taux de rafraîchissement, la rotation actuelle, etc.

Utilisez `XRRFreeScreenConfigInfo` pour libérer la mémoire allouée à cette structure lorsque vous n'en avez plus besoin.

XRRFreeScreenConfigInfo

Libère la mémoire associée à une structure `XRRScreenConfiguration`.

XRRSetScreenConfig

Définit la configuration de l'écran, y compris la taille et la rotation.

Le `size_index` fait référence à l'un des `XRRScreenSize` retournés par `XRRGetScreenInfo`.

Le `rotation` spécifie la rotation souhaitée (par exemple, `RR_Rotate_0`, `RR_Rotate_90`).

Le `timestamp` doit être le dernier horodatage de configuration connu pour éviter les conflits.

Renvoie `Status` (succès ou échec).

XRRSetScreenConfigAndRate

Similaire à `XRRSetScreenConfig`, mais permet également de spécifier le taux de rafraîchissement souhaité (`rate`).

Renvoie `Status` (succès ou échec).

XRRConfigRotations

Récupère les rotations et réflexions possibles pour la configuration d'écran actuelle.

Le `current_rotation` est rempli avec la rotation actuellement active.

Renvoie une combinaison des drapeaux de rotation possibles.

XRRConfigTimes

Récupère les horodatages associés à la configuration actuelle de l'écran.

Le `config_timestamp` est rempli avec l'horodatage de la dernière modification de configuration.

Renvoie l'horodatage du serveur.

XRRConfigSizes

Récupère les tailles d'écran (`XRRScreenSize`) disponibles pour la configuration actuelle.

Le `nsizes` est rempli avec le nombre de tailles disponibles.

Renvoie un tableau de structures `XRRScreenSize`.

XRRConfigRates

Récupère les taux de rafraîchissement disponibles pour une taille d'écran donnée (`size_index`).

Le `nrates` est rempli avec le nombre de taux disponibles.

Renvoie un tableau de taux de rafraîchissement courts.

XRRConfigCurrentConfiguration

Récupère la configuration actuelle de l'écran, y compris la taille et la rotation.

Le `rotation` est rempli avec la rotation actuelle.

Renvoie l'ID de la taille actuelle (`SizeID`).

XRRConfigCurrentRate

Récupère le taux de rafraîchissement actuel de l'écran.

Renvoie le taux de rafraîchissement actuel.

XRRRootToScreen

Détermine le numéro d'écran associé à une fenêtre racine donnée.

Utile pour mapper une fenêtre à un écran spécifique.

Renvoie le numéro de l'écran ou -1 en cas d'erreur.

XRRSelectInput

Indique au serveur X de générer des événements `RRScreenChangeNotify` pour la fenêtre spécifiée.

Le masque `mask` doit inclure `RRScreenChangeNotifyMask`.

XRRUpdateConfiguration

Traite un événement X (généralement `RRScreenChangeNotify` ou `ConfigureNotify` sur la fenêtre racine) et met à jour la structure de données interne de Xlib concernant la configuration de l'écran.

Il est important d'appeler cette fonction lorsqu'un tel événement est reçu pour maintenir la cohérence.

Renvoie 1 si l'événement a été traité, 0 sinon.

XRRRotations

Fonction de sécurité pour récupérer les rotations possibles et la rotation actuelle pour un écran donné, même si l'extension RandR n'est pas implémentée.

Le `current_rotation` est rempli avec la rotation actuellement active.

Renvoie une combinaison des drapeaux de rotation possibles.

XRRSizes

Fonction de sécurité pour récupérer les tailles d'écran disponibles pour un écran donné, même si l'extension RandR n'est pas implémentée.

Le `nsizes` est rempli avec le nombre de tailles disponibles.

Renvoie un tableau de structures `XRRScreenSize`.

XRRRates

Fonction de sécurité pour récupérer les taux de rafraîchissement disponibles pour une taille d'écran donnée, même si l'extension RandR n'est pas implémentée.

Le `nrates` est rempli avec le nombre de taux disponibles.

Renvoie un tableau de taux de rafraîchissement courts.

XRRTimes

Fonction de sécurité pour récupérer l'horodatage de configuration actuel pour un écran donné, même si l'extension RandR n'est pas implémentée.

Le `config_timestamp` est rempli avec l'horodatage de la dernière modification de configuration.

Renvoie l'horodatage du serveur.

Xrandr — Extension for screen resizing and rotation

ARGUMENTS

dpy
Specifies the connection to the X server.
window
Specifies the root window of the screen to query.
resources
Specifies the screen resources structure returned by XRRGetScreenResources.
rotation
Specifies the desired rotation/reflection.
size_index
Specifies the desired screen size configuration.
rate
Specifies the desired refresh rate.
timestamp
Specifies the timestamp of the last configuration change.

DESCRIPTION

The RandR extension provides an interface for querying and modifying screen sizes, rotations, and refresh rates. There are two classes of interfaces: those which can be safely called even if RandR is not implemented on a screen (to make common idioms not dependent on the server having support), and those which will return errors if the extension is not present.

XRRRotations returns both the possible set of rotations/reflections supported (as a bitmask) as the value of the function, along with the current rotation/reflection of the screen.

XRRSizes returns the size and a pointer to the current sizes supported by the specified screen. The first size specified is the default size of the server. If RandR is not supported, it returns 0 for the number of sizes.

XRRRates returns a pointer to the rates supported by the specified size. If RandR is not supported, it returns 0 for the number of rates.

XRRTimes returns the time last reported by the server along with the timestamp the last configuration changed. If the configuration has changed since the client last updated its view of the server time, requests to change the configuration will fail until the client has an up to date timestamp.

XRRRootToScreen returns the screen number given a root window (for example, from an XRRScreenChangeNotifyEvent).

The rest of the functions will fail if applied to screens not implementing the RandR extension. XRRSetScreenConfig sets the screen size and rotation and reflection to the desired values on the screen specified by window, or returns a BadValue error. size_index specifies which size configuration is to be used, rotation specifies which rotation or reflection is to be used (or a BadValue error is returned). The timestamp is used by the server to make sure the client has up to date configuration information. Status is returned to indicate success or failure; a client must refresh its configuration information if it fails and try the call again (by calling XRRGetScreenInfo).

XRRSetScreenConfigAndRate is like XRRSetScreenConfig but also sets the refresh rate. If specified rate is not supported a BadValue error is returned.

XRRConfigRotations, XRRConfigSizes, XRRConfigCurrentConfiguration, XRRConfigTimes, XRRConfigRates, and XRRConfigCurrentRate are used to get specific configuration information out of a screen configuration.

XRRGetScreenResources returns a screen configuration for later use; the information is private to the library. Call XRRFreeScreenResources to free this information when you are finished with it. It forces a round trip to the server.

Other functions include: XRRQueryExtension which returns the event and error base codes, XRRQueryVersion , which returns the current version of the extension (this information is cached by the library).

RESTRICTIONS

Xrandr will remain upward compatible after the current 1.0 release.
