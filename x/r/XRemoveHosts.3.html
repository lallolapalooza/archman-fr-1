XRemoveHosts(3)

Paquet: libx11

Licences: MIT AND X11

XAddHost(3) FONCTIONS XLIB XAddHost(3)

NOM

XAddHost, XAddHosts, XListHosts, XRemoveHost, XRemoveHosts, XSetAccessControl, XEnableAccessControl, XDisableAccessControl, XHostAddress, XServerInterpretedAddress - contrôler l'accès aux hôtes et la structure de contrôle des hôtes

SYNTAXE

int XAddHost(Display *display, XHostAddress *host);

int XAddHosts(Display *display, XHostAddress *hosts, int num_hosts);

XHostAddress *XListHosts(Display *display, int *nhosts_return, Bool *state_return);

int XRemoveHost(Display *display, XHostAddress *host);

int XRemoveHosts(Display *display, XHostAddress *hosts, int num_hosts);

int XSetAccessControl(Display *display, int mode);

int XEnableAccessControl(Display *display);

int XDisableAccessControl(Display *display);

ARGUMENTS

display
Spécifie la connexion au serveur X.
host
Spécifie l'hôte qui doit être ajouté ou supprimé.
hosts
Spécifie chaque hôte qui doit être ajouté ou supprimé.
mode
Spécifie le mode. Vous pouvez passer EnableAccess ou DisableAccess.
nhosts_return
Retourne le nombre d'hôtes actuellement dans la liste de contrôle d'accès.
num_hosts
Spécifie le nombre d'hôtes.
state_return
Retourne l'état du contrôle d'accès.

DESCRIPTION

La fonction XAddHost ajoute l'hôte spécifié à la liste de contrôle d'accès pour cet affichage. Le serveur doit être sur le même hôte que le client émettant la commande, sinon une erreur BadAccess en résultera.

XAddHost peut générer des erreurs BadAccess et BadValue.

La fonction XAddHosts ajoute chaque hôte spécifié à la liste de contrôle d'accès pour cet affichage. Le serveur doit être sur le même hôte que le client émettant la commande, sinon une erreur BadAccess en résultera.

XAddHosts peut générer des erreurs BadAccess et BadValue.

La fonction XListHosts retourne la liste de contrôle d'accès actuelle ainsi que si l'utilisation de la liste lors de l'établissement de la connexion était activée ou désactivée. XListHosts permet à un programme de savoir quelles machines peuvent établir des connexions. Elle retourne également un pointeur vers une liste de structures d'hôtes qui ont été allouées par la fonction. Lorsque ce n'est plus nécessaire, cette mémoire doit être libérée en appelant XFree.

La fonction XRemoveHost supprime l'hôte spécifié de la liste de contrôle d'accès pour cet affichage. Le serveur doit être sur le même hôte que le processus client, sinon une erreur BadAccess en résultera. Si vous supprimez votre machine de la liste d'accès, vous ne pourrez plus vous connecter à ce serveur, et cette opération ne pourra pas être inversée à moins de réinitialiser le serveur.

XRemoveHost peut générer des erreurs BadAccess et BadValue.

La fonction XRemoveHosts supprime chaque hôte spécifié de la liste de contrôle d'accès pour cet affichage. Le serveur X doit être sur le même hôte que le processus client, sinon une erreur BadAccess en résultera. Si vous supprimez votre machine de la liste d'accès, vous ne pourrez plus vous connecter à ce serveur, et cette opération ne pourra pas être inversée à moins de réinitialiser le serveur.

XRemoveHosts peut générer des erreurs BadAccess et BadValue.

La fonction XSetAccessControl active ou désactive l'utilisation de la liste de contrôle d'accès lors de chaque établissement de connexion.

XSetAccessControl peut générer des erreurs BadAccess et BadValue.

La fonction XEnableAccessControl active l'utilisation de la liste de contrôle d'accès lors de chaque établissement de connexion.

XEnableAccessControl peut générer une erreur BadAccess.

La fonction XDisableAccessControl désactive l'utilisation de la liste de contrôle d'accès lors de chaque établissement de connexion.

XDisableAccessControl peut générer une erreur BadAccess.

STRUCTURES

La structure XHostAddress contient :

typedef struct {
        int family;     /* par exemple FamilyInternet */
        int length;     /* longueur de l'adresse, en octets */
        char *address;  /* pointeur vers l'emplacement de l'adresse */
} XHostAddress;

Le membre family spécifie quelle famille d'adresses de protocole utiliser (par exemple, TCP/IP ou DECnet) et peut être FamilyInternet, FamilyInternet6, FamilyServerInterpreted, FamilyDECnet, ou FamilyChaos. Le membre length spécifie la longueur de l'adresse en octets. Le membre address spécifie un pointeur vers l'adresse.

Pour la famille ServerInterpreted, la longueur est ignorée et le membre address est un pointeur vers une structure XServerInterpretedAddress qui contient :

typedef struct {
        int typelength;         /* longueur de la chaîne de type, en octets */
        int valuelength;        /* longueur de la chaîne de valeur, en octets */
        char *type;             /* pointeur vers l'emplacement de la chaîne de type */
        char *value;            /* pointeur vers l'emplacement de l'adresse */
} XServerInterpretedAddress;

Les membres type et value pointent vers des chaînes représentant le type et la valeur de l'entrée interprétée par le serveur. Ces chaînes peuvent ne pas être terminées par NULL, donc il faut être prudent lors de leur accès. Les membres typelength et valuelength spécifient la longueur en octets des chaînes de type et de valeur.

DIAGNOSTICS

BadAccess
Un client a tenté de modifier la liste de contrôle d'accès depuis un hôte autre que l'hôte local (ou autrement autorisé).
BadValue
Une valeur numérique se situe en dehors de la plage de valeurs acceptées par la requête. Sauf si une plage spécifique est indiquée pour un argument, la plage complète définie par le type de l'argument est acceptée. Tout argument défini comme un ensemble d'alternatives peut générer cette erreur.
