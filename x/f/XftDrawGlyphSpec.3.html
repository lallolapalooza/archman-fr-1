NOM

Xft - bibliothèque d'interface X FreeType

SYNTAXE

#include <X11/Xft/Xft.h>

DESCRIPTION

Xft est une bibliothèque simple qui dessine du texte et des graphiques :

  • en utilisant les informations fournies par la bibliothèque Fontconfig,
  • Xft convertit les glyphes de police en utilisant le moteur de rendu FreeType, et
  • affiche les données de police converties en utilisant l'extension X Rendering Extension.

Cette page de manuel ne fait qu'effleurer la surface de cette bibliothèque.

CONSTANTES

XFT_MAJOR
est le numéro de version majeure de Xft.
XFT_MINOR
est le numéro de version mineure de Xft.
XFT_REVISION
est le numéro de révision de Xft.
XFT_VERSION
est XFT_MAJOR multiplié par 10000 (dix mille), plus XFT_MINOR multiplié par 100, plus XFT_REVISION.
XftVersion
est un alias pour XFT_VERSION.

L'exemple suivant illustre comment les constantes de version de Xft pourraient être utilisées : 

    #if (XFT_VERSION >= 20107)
    (void) puts("Version 2.1.7 ou ultérieure de la bibliothèque Xft est en"
                " cours d'utilisation.");
    #else
    (void) printf("Version insuffisante de Xft (%d.%d.%d) installée ;"
                  " besoin d'au moins la version 2.1.7.\n", XFT_MAJOR,
                  XFT_MINOR,
                  XFT_REVISION);
    #endif

TYPES DE DONNÉES

Les types de données Xft suivent une convention de nommage, préfixant tous les noms par « Xft »

De Xlib...

Les types de données Xlib ne suivent pas une convention de nommage. Ils sont documentés dans Xlib - C Language Interface.

Xft utilise ces noms : Bool, Colormap, Display, Drawable, Pixmap, Region, Visual, et XRectangle.

Certains types de données sont particulièrement pertinents pour Xft :

Drawable
Déclaré dans <X11/X.h>, il s'agit d'un ID de ressource X, par exemple une fenêtre associée à un écran. Les fenêtres et les pixmaps peuvent être utilisés comme sources et destinations dans les opérations graphiques. Ces fenêtres et pixmaps sont collectivement appelés drawables. Cependant, une fenêtre InputOnly ne peut pas être utilisée comme source ou destination dans une opération graphique.
Region
Déclaré dans <X11/Xutil.h> et <X11/Xregion.h>, une Region est un ensemble arbitraire de pixels que Xlib peut manipuler. En interne, une Region est représentée par l'union d'un nombre arbitraire de rectangles. Xlib maintient un rectangle qui lui indique l'étendue de cette union.
Visual
Déclaré dans <X11/Xutil.h>, cette structure contient des informations sur le mappage de couleurs possible.

De XRender...

Les types de données de l'extension X Render sont inspirés de Xlib, mais manquent de la documentation correspondante. Référez-vous au fichier d'en-tête pour plus de détails :

<X11/extensions/Xrender.h>

ou lisez le code source (qui fournit un aperçu de libXrender).

Xft utilise ces noms : Picture, XGlyphInfo, XRenderColor.

De Fontconfig...

Les types de données Fontconfig suivent une convention de nommage, préfixant tous les noms par « Fc », qui sont documentés dans Fontconfig Developers Reference.

Xft utilise ces noms Fontconfig : FcBool, FcChar8, FcChar16, FcChar32, FcCharSet, FcEndian, FcFontSet, FcPattern, et FcResult.

De FreeType 2...

Les types de données FreeType 2 suivent une convention de nommage, préfixant tous les noms par « FT_ », qui sont documentés dans FreeType API Reference.

Xft utilise ces noms : FT_Face, FT_Library, et FT_UInt.

FreeType 2 utilise FT_UInt (un entier non signé) pour représenter les glyphes.

XftFont


typedef struct _XftFont {
	int	 ascent;
	int	 descent;
	int	 height;
	int	 max_advance_width;
	FcCharSet	*charset;
	FcPattern	*pattern;
} XftFont;

Un XftFont est la structure de données principale qui intéresse les programmeurs utilisant Xft ; il contient des métriques générales de police et des pointeurs vers l'ensemble de caractères et le modèle Fontconfig associés à la police.

Les XftFonts sont remplis par XftFontOpen(), XftFontOpenName(), XftFontOpenXlfd(), XftFontOpenInfo(), ou XftFontOpenPattern(). XftFontCopy() est utilisé pour dupliquer les XftFonts, et XftFontClose() est utilisé pour marquer un XftFont comme inutilisé. Les XftFonts sont alloués en interne, comptés par référence, et libérés par Xft ; le programmeur n'a normalement pas besoin d'allouer ou de libérer de l'espace mémoire pour eux.

XftDrawGlyphs(), la famille XftDrawString*(), XftDrawCharSpec(), et XftDrawGlyphSpec() utilisent les XftFonts pour rendre du texte dans un objet XftDraw, qui peut correspondre soit à un dessinable X de base, soit à un dessinable de l'extension X Rendering Extension.

XftGlyphExtents() et la famille XftTextExtents*() sont utilisés pour déterminer les étendues (dimensions maximales) d'un XftFont.

La couverture des glyphes ou des caractères d'un XftFont peut être déterminée avec XftFontCheckGlyph() ou XftCharExists(). XftCharIndex() renvoie l'indice de caractère spécifique à XftFont correspondant à un point de code Unicode donné.

XftGlyphRender(), XftGlyphSpecRender(), XftCharSpecRender(), et la famille XftTextRender*() utilisent les XftFonts pour dessiner dans des structures Picture de l'extension X Rendering.

Note : XftDrawGlyphs(), la famille XftDrawString*(), XftDrawCharSpec(), et XftDrawGlyphSpec() fournissent un moyen de rendre les polices qui est indépendant de la disponibilité de l'extension X Rendering sur le serveur X.

XftFontInfo

est un objet opaque qui stocke des informations sur une police. Les structures XftFontInfo sont créées avec XftFontInfoCreate(), libérées avec XftFontInfoDestroy(), et comparées avec XftFontInfoEqual(). Les objets XftFontInfo sont alloués et libérés en interne par Xft ; le programmeur n'a normalement pas besoin d'allouer ou de libérer de l'espace mémoire pour eux.

Chaque structure XftFontInfo en cours d'utilisation est associée à un identifiant unique, qui peut être récupéré avec XftFontInfoHash(). Un XftFont peut être ouvert sur la base des données XftFontInfo avec XftFontOpenInfo().

XftColor


typedef struct _XftColor {
	unsigned long	 pixel;
	XRenderColor	 color;
} XftColor;

Un objet XftColor permet de rendre du texte et d'autres éléments dans une couleur particulière (ou la meilleure approximation offerte par le visuel X utilisé).

XftColorAllocName() et XftColorAllocValue() demandent une allocation de couleur au serveur X (si nécessaire) et initialisent les membres de XftColor. XftColorFree() demande au serveur X de libérer la couleur actuellement allouée pour un XftColor.

DESCRIPTION

XftDraw

est un objet opaque qui contient des informations utilisées pour le rendu sur un X drawable en utilisant soit le protocole de base, soit l'extension X Rendering.

Les objets XftDraw sont créés avec l'une des fonctions XftDrawCreate() (qui associe un XftDraw à un X drawable existant), XftDrawCreateBitmap(), ou XftDrawCreateAlpha(), et détruits avec XftDrawDestroy(). Le X drawable associé à un XftDraw peut être modifié avec XftDrawChange(). Les objets XftDraw sont alloués et libérés en interne par Xft; le programmeur n'a pas besoin de gérer l'allocation ou la libération de mémoire pour eux en temps normal.

Les propriétés X Display, Drawable, Colormap, et Visual d'un XftDraw peuvent être interrogées avec XftDrawDisplay(), XftDrawDrawable(), XftDrawColormap(), et XftDrawVisual(), respectivement.

Plusieurs fonctions utilisent les objets XftDraw: XftDrawCharFontSpec(), XftDrawCharSpec(), XftDrawGlyphFontSpec(), XftDrawGlyphSpec(), XftDrawGlyphs(), XftDrawRect(), XftDrawSetClip(), XftDrawSetClipRectangles(), XftDrawSetSubwindowMode(), et la famille XftDrawString*().

L'extension X Rendering Picture associée à un XftDraw est retournée par XftDrawPicture(), et XftDrawSrcPicture(). Elle est utilisée par XftCharFontSpecRender(), XftCharSpecRender(), XftGlyphFontSpecRender(), XftGlyphRender(), XftGlyphSpecRender(), et la famille XftTextRender*().

FONCTIONS

Initialisation

Une application typique utilisant Xft n'initialise pas explicitement la bibliothèque. Cela est généralement fait comme effet secondaire de l'ouverture d'une police.

Lorsque Xft s'initialise, il collecte des informations sur l'affichage et stocke certaines de ces informations dans un modèle Fontconfig (essentiellement une collection de propriétés avec des valeurs typées). L'application appelante peut modifier ce modèle pour changer le comportement de la bibliothèque.

Toutes les informations collectées ne sont pas stockées dans un modèle. Le reste est stocké dans des structures de données internes. Xft met une partie de celles-ci à disposition de l'application via des fonctions.

Bool XftDefaultHasRender (
	Display	*dpy);

Obtient des informations sur l'affichage dpy si ce n'est pas déjà fait, et renvoie vrai si Xft a constaté que l'affichage supporte l'extension X Render, et s'il est capable de trouver un XRenderPictFormat approprié (le type de données de X Render analogue au Visual de Xlib) sur l'affichage.

Bool XftDefaultSet (
	Display	*dpy,
	FcPattern	*defaults);

Obtient des informations sur l'affichage dpy si ce n'est pas déjà fait, et définit le modèle Fontconfig contenant les propriétés par défaut que Xft utilisera pour cet affichage.

Xft utilise ces propriétés initialement pour obtenir ces limites :
XFT_MAX_GLYPH_MEMORY
(maxglyphmemory). C'est la quantité maximale de mémoire de glyphes pour toutes les polices utilisées par Xft (défaut : 4*1024*1024).
XFT_MAX_UNREF_FONTS
(maxunreffonts). C'est le nombre maximum de polices non référencées (défaut : 16).
XFT_TRACK_MEM_USAGE
(trackmemusage). Lorsque vrai, Xft suit l'utilisation de la mémoire des glyphes pour améliorer les performances lors de la décision de ce qu'il faut décharger lorsque la quantité maximale de mémoire des glyphes est atteinte (défaut : faux).
Xft utilise également ces propriétés par défaut dans XftDefaultSubstitute().
void XftDefaultSubstitute (
	Display	*dpy,
	int	 screen,
	FcPattern	*pattern);

Xft remplit les propriétés manquantes dans le pattern fourni en utilisant les propriétés par défaut pour l'affichage spécifié dpy, par exemple celles définies dans XftDefaultSet().

Les applications Xft typiques utilisent cette fonction pour aider Fontconfig à choisir une police appropriée. Ces propriétés sont substituées avant l'appel de FcDefaultSubstitute():
FC_ANTIALIAS
Vrai si FreeType doit utiliser l'anti-aliasing (défaut: Faux). (défaut: Vrai).
FC_AUTOHINT
Vrai si FreeType doit utiliser l'auto-hinting (défaut: Faux).
FC_DPI
Points par pouce utilisés pour la résolution (défaut : calculé à partir de la hauteur de l'affichage).
FC_EMBOLDEN
Vrai si FT_GlyphSlot_Embolden() doit être utilisé pour épaissir une police (défaut: Faux).
FC_HINTING
Vrai si le hinting doit être utilisé lors du remplissage des propriétés pour ouvrir une police (défaut: Vrai).
FC_HINT_STYLE
Style de hinting utilisé lors du remplissage des propriétés pour ouvrir une police (défaut : FC_HINT_FULL).
FC_LCD_FILTER
Paramètre passé à FT_Library_SetLcdFilter() lors du chargement des glyphes (défaut: FC_LCD_DEFAULT).
FC_MINSPACE
Espace minimum utilisé lors du remplissage des propriétés pour ouvrir une police (défaut: Faux).
FC_RGBA
Valeur RGBA utilisée lors du remplissage des propriétés pour ouvrir une police (défaut : calculé en appelant XRenderQuerySubpixelOrder()).
FC_SCALE
Échelle utilisée dans Fontconfig (défaut : 1.0).
XFT_MAX_GLYPH_MEMORY
Mémoire maximale pour une seule police (défaut : 1024*1024).
XFT_RENDER
Vrai si l'affichage supporte l'extension X Render (défaut : résultat de XftDefaultHasRender()).
FcBool XftInit (
	_Xconst char	*config);

Initialise la bibliothèque Fontconfig (appelant FcInit()).

Le paramètre config n'est pas utilisé.
Xft ne désinitialise pas la bibliothèque Fontconfig une fois terminée.
FcBool XftInitFtLibrary (void);

    
Initialise la bibliothèque FreeType (appelant
        FT_Init_FreeType() pour créer un objet bibliothèque) si elle n'a pas déjà été initialisée. Ceci est nécessaire avant d'utiliser la bibliothèque FreeType pour lire les données de police à partir d'un fichier.

  





  

  
Xft appelle XftInitFtLibrary() en interne via
      XftFontInfoCreate() et XftFontOpenPattern().

  

  
Xft ne détruit pas l'objet bibliothèque (par exemple, en utilisant
      FT_Done_FreeType()) une fois terminé.

Ouverture et Correspondance des Polices



  
XftFont *XftFontOpen (

  

    
	Display	*dpy,
	int	 screen,
	...);


    
XftFontOpen prend une liste de triplets de type champ,
        champ, type, valeur (terminée par un NULL), fait correspondre ce modèle aux polices disponibles, et ouvre la police correspondante, en la dimensionnant correctement pour l'écran numéro screen sur l'affichage dpy. Retourne la police correspondante, ou NULL si aucune correspondance n'est trouvée.

  




Exemple :
  




    font = XftFontOpen (dpy, screen,
                        XFT_FAMILY, XftTypeString, "charter",
                        XFT_SIZE, XftTypeDouble, 12.0,
                        NULL);




  

  
Ceci ouvre la police "charter" en 12 points. La taille en points est automatiquement convertie en la taille en pixels correcte en fonction de la résolution du moniteur.





  
XftFont *XftFontOpenName (

  

    
	Display	*dpy,
	int	 screen,
	_Xconst char	*name);


    
XftFontOpenName se comporte comme

  



XftFontOpen,
        sauf qu'il prend une chaîne de modèle Fontconfig (qui est passée à la
        fonction FcNameParse() de la bibliothèque Fontconfig).

	Display	*dpy,

	_Xconst char	*xlfd)


    
XftFontOpenXlfd se comporte comme XftFontOpen,
        sauf qu'il prend une chaîne contenant une description de police logique X

Également utilisé en interne par les fonctions XftFontOpen*,

FcPattern *XftXlfdParse (

  

    
	_Xconst char	*xlfd_orig,
	Bool	ignore_scalable,
	Bool	complete);


    
XftXlfdParse analyse le paramètre xlfd_orig
        conformément au document Conventions de description de police logique X,
        mais ignore certains champs : setwidth_name,
        add_style_name, spacing et average_width.

  




  

  
XftXlfdParse crée un modèle Fontconfig, définit la propriété
      XFT_XLFD à la valeur xlfd_orig et mappe les informations collectées
      aux propriétés Fontconfig. Les champs vides ou “*” sont ignorés :







  
FC_FOUNDRY

  
à partir de foundry.

  
FC_FAMILY

  
à partir de family.

  
FC_WEIGHT

  
weight_name, avec une valeur par défaut FC_WEIGHT_MEDIUM.

  
FC_SLANT

  
à partir de slant, avec une valeur par défaut FC_SLANT_ROMAN.

  
FC_SIZE

  
à partir de point_size.

  
FC_PIXEL_SIZE

  
à partir de pixel_size. Si point_size était défini, ainsi que
      resolution_x et resolution_y, alors la valeur est mise à l'échelle
      pour convertir la hauteur de la police en points.

Gestion des XftColor



  
Bool XftColorAllocName (

  

    
	Display	*dpy,
	_Xconst Visual	*visual,
	Colormap	 cmap,
	_Xconst char	*name,
	XftColor	*result);


    
Utilise XAllocNamedColor() pour rechercher la couleur nommée
        name pour l'écran associé à la palette de couleurs cmap.

  






    
  
  • Si XAllocNamedColor() retourne une valeur non nulle, XftColorAllocName()
      remplit le champ de pixel XftColor résultant avec la couleur la plus proche
      prise en charge par l'écran, ainsi que les champs rouge, vert et bleu exacts de la
      base de données, et retourne True.
    • 
  
  • Si XAllocNamedColor() retourne zéro, XftColorAllocName()
      retourne False et ne met pas à jour le XftColor référencé par
      result.
    • 






  

  
Le paramètre visual n'est pas utilisé.





  
Bool XftColorAllocValue (

  

    
	Display	*dpy,
	Visual	*visual,
	Colormap	 cmap,
	_Xconst XRenderColor	*color,
	XftColor	*result);


    
Alloue une valeur de couleur :

  






    
  
  • Si la classe de visual est TrueColor, XftColorAllocValue()
      définit le champ pixel dans le XftColor référencé par result
      en utilisant les champs rouge, vert et bleu du paramètre color.
    • 
  
  • Si la classe de visual n'est pas TrueColor, XftColorAllocValue()
      appelle XAllocColor() pour allouer une entrée dans la palette de couleurs
      cmap. qui retourne la valeur de pixel de la couleur la plus proche des
      éléments RVB spécifiés supportés par le matériel.
    • 




  

  
Si XAllocColor() réussit, XftColorAllocValue() stocke cette
      valeur de pixel dans le XRenderColor référencé par result et
      retourne True.

  

  
Si XAllocColor() échoue, XftColorAllocValue() retourne False
      et ne modifie pas le résultat.







  
void XftColorFree (

  

    
	Display	*dpy,
	Visual	*visual,

Si la classe de visual n'est pas TrueColor, Xft appelle

	int	 len);


    
Dessine une liste de glyphes associés à des polices à des

        XftGlyphFontSpec de taille len via le paramètre
        glyphs. Tous les glyphes sont dessinés en utilisant la couleur

Pour chaque entrée du tableau glyphs :






    
  
  • Si la police associée utilise l'extension X Render, alors Xft utilise
      XftGlyphFontSpecRender() pour dessiner le glyphe, en utilisant une
      Picture obtenue en appelant XftDrawSrcPicture () avec les

void XftGlyphFontSpecRender (

  

    
	Display	*dpy,
	int	 op,
	Picture	 src,
	Picture	 dst,
	int	 srcx,
	int	 srcy,
	_Xconst XftGlyphFontSpec	*glyphs,
	int	 nglyphs);


    
Cela implique plusieurs étapes :

  






    
  
  • Premièrement, Xft s'assure que le tableau glyphs est complet
      en utilisant XftFontCheckGlyph() et en chargeant les glyphes
      manquants avec XftFontLoadGlyphs().
    • 
  
  • Ensuite, Xft examine les glyphes pour trouver la valeur Unicode
      maximale. Cela détermine la taille de l'encodage, c'est-à-dire la
      largeur.
    • 
  
  • Ensuite, pour chaque glyphe, Xft vérifie si sa valeur Unicode est
      gérée par la police correspondante. Sinon, la valeur est définie sur zéro
      (0), pour l'ignorer. Pendant ce processus, Xft se souvient également
      de la première police utilisée et calcule la position à laquelle chaque
      glyphe sera dessiné.
    • 
  
  • Xft construit ensuite un tableau équivalent de glyphes dans le format
      attendu par la bibliothèque X Render.
    • 
  
  • Enfin, XftGlyphFontSpecRender() utilise l'extension X Render pour
      dessiner les glyphes, avec la fonction XRenderCompositeText*()
      appropriée en fonction de la largeur, et rejette les données
      temporaires.
    • 




  

  
Les paramètres op, dst, src, srcx et
      srcy sont utilisés comme décrit dans la documentation de la
      bibliothèque X Render.

DESCRIPTION


The Xft library is a thin library which is built on top of
    FreeType 2 and the X Render extension. It is used for rendering fonts using
    FreeType 2 and the X Render extension.


Xft uses Fontconfig for font matching, font handling and
    font-characterization. Xft also uses the X Render extension for
    drawing the fonts.


The library uses the fontconfig library to determine which fonts
    to use. The functions XftFontOpen() and XftFontOpenXlfd()
    return an XftFont structure. This structure contains the font
    information needed for rendering, including the FreeType 2 face and the
    X Render extension glyph-set.

DEBUGGING


The XFT_DEBUG environment variable can be set to control
    debugging output. The variable should be set to an integer value, where each
    bit corresponds to a different debugging option:



  
1

  
Print information about font opening.

  
2

  
Print verbose information about font matching and opening.

  
4

  
Print details about the XRenderPictFormat used.

  
8

  
Print the string being drawn by XftDrawString8().

  
16

  
Print information about matched font IDs.

  
32

  
Print details about the glyphs being drawn.

  
64

  
Print an ASCII-art representation of the glyphs.

  
128

  
Print details about memory cache management.

  
256

  
Print details about glyph cache memory management.

  
512

  
Print a report on memory usage.

  
1024

  
Print details about extended glyph cache memory management.
