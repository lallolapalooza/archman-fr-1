NOM

Xft - Bibliothèque d'interface X FreeType

SYNTAXE

#include <X11/Xft/Xft.h>

DESCRIPTION

Xft est une bibliothèque simple qui dessine du texte et des graphiques :

  • en utilisant les informations fournies par la bibliothèque Fontconfig,
  • Xft convertit les glyphes de polices à l'aide du rasterizer FreeType, et
  • affiche les données de police converties à l'aide de l'extension X Rendering Extension.

Cette page de manuel effleure à peine cette bibliothèque.

CONSTANTES

XFT_MAJOR
est le numéro de version majeure de Xft.
XFT_MINOR
est le numéro de version mineure de Xft.
XFT_REVISION
est le numéro de révision de Xft.
XFT_VERSION
est XFT_MAJOR multiplié par 10000 (dix mille), plus XFT_MINOR multiplié par 100, plus XFT_REVISION.
XftVersion
est un alias pour XFT_VERSION.

L'exemple suivant illustre comment les constantes de version de Xft pourraient être utilisées : 

    #if (XFT_VERSION >= 20107)
    (void) puts("Version 2.1.7 ou ultérieure de la bibliothèque Xft est en"
                " cours d'utilisation.");
    #else
    (void) printf("Version insuffisante de Xft (%d.%d.%d) installée ;
                  " besoin d'au moins la version 2.1.7.\n", XFT_MAJOR,
                  XFT_MINOR,
                  XFT_REVISION);
    #endif

TYPES DE DONNÉES

Les types de données Xft suivent une convention de nommage, préfixant tous les noms par « Xft »

Depuis Xlib...

Les types de données Xlib ne suivent pas de convention de nommage. Ils sont documentés dans Xlib - Interface en langage C.

Xft utilise ces noms : Bool, Colormap, Display, Drawable, Pixmap, Region, Visual, et XRectangle.

Certains types de données sont particulièrement pertinents pour Xft :

Drawable
Déclaré dans <X11/X.h>, il s'agit d'un ID de ressource X, par exemple, une fenêtre associée à un écran. Les fenêtres et les pixmaps peuvent être utilisés comme sources et destinations dans les opérations graphiques. Ces fenêtres et pixmaps sont collectivement connus sous le nom de drawables. Cependant, une fenêtre InputOnly ne peut pas être utilisée comme source ou destination dans une opération graphique.
Region
Déclaré dans <X11/Xutil.h> et <X11/Xregion.h>, une Region est un ensemble arbitraire d'emplacements de pixels que Xlib peut manipuler. Internelement, une Region est représentée par l'union d'un nombre arbitraire de rectangles. Xlib maintient un rectangle qui indique l'étendue de cette union.
Visual
Déclaré dans <X11/Xutil.h>, cette structure contient des informations sur le mappage couleur possible.

Depuis XRender...

Les types de données de l'extension X Render Extension s'inspirent de Xlib, mais manquent de la documentation correspondante. Référez-vous au fichier d'en-tête pour les détails :

<X11/extensions/Xrender.h>

ou lisez le code source (qui fournit un aperçu de libXrender).

Xft utilise ces noms : Picture, XGlyphInfo, XRenderColor.

Depuis Fontconfig...

Les types de données Fontconfig suivent une convention de nommage, préfixant tous les noms par « Fc », qui sont documentés dans le Référentiel des développeurs Fontconfig.

Xft utilise ces noms Fontconfig : FcBool, FcChar8, FcChar16, FcChar32, FcCharSet, FcEndian, FcFontSet, FcPattern, et FcResult.

Depuis FreeType 2...

Les types de données FreeType 2 suivent une convention de nommage, préfixant tous les noms par « FT_ », qui sont documentés dans le Référentiel de l'API FreeType.

Xft utilise ces noms : FT_Face, FT_Library, et FT_UInt.

FreeType 2 utilise FT_UInt (un entier non signé) pour représenter les glyphes.

XftFont


typedef struct _XftFont {
	int	 ascent;
	int	 descent;
	int	 height;
	int	 max_advance_width;
	FcCharSet	*charset;
	FcPattern	*pattern;
} XftFont;

Un XftFont est la structure de données principale qui intéresse les programmeurs utilisant Xft ; elle contient des métriques générales de police et des pointeurs vers l'ensemble de caractères et le modèle Fontconfig associés à la police.

Les XftFont sont peuplés par XftFontOpen(), XftFontOpenName(), XftFontOpenXlfd(), XftFontOpenInfo(), ou XftFontOpenPattern(). XftFontCopy() est utilisé pour dupliquer les XftFont, et XftFontClose() est utilisé pour marquer un XftFont comme non utilisé. Les XftFont sont alloués en interne, comptés par référence et libérés par Xft ; le programmeur n'a généralement pas besoin d'allouer ou de libérer de la mémoire pour eux.

XftDrawGlyphs(), la famille XftDrawString*(), XftDrawCharSpec(), et XftDrawGlyphSpec() utilisent les XftFont pour rendre du texte à un objet XftDraw, qui peut correspondre à un dessin central X ou à un dessin de l'extension X Rendering Extension.

XftGlyphExtents() et la famille XftTextExtents*() sont utilisés pour déterminer les étendues (dimensions maximales) d'un XftFont.

La couverture des glyphes ou des caractères d'un XftFont peut être déterminée avec XftFontCheckGlyph() ou XftCharExists(). XftCharIndex() renvoie l'index de caractère spécifique à XftFont correspondant à un point de code Unicode donné.

XftGlyphRender(), XftGlyphSpecRender(), XftCharSpecRender(), et la famille XftTextRender*() utilisent les XftFont pour dessiner dans des structures Picture de l'extension X Rendering Extension.

Note : XftDrawGlyphs(), la famille XftDrawString*(), XftDrawCharSpec(), et XftDrawGlyphSpec() fournissent un moyen de rendre les polices qui est indépendant de la disponibilité de l'extension X Rendering Extension sur le serveur X.

XftFontInfo

est un objet opaque qui stocke des informations sur une police. Les structures XftFontInfo sont créées avec XftFontInfoCreate(), libérées avec XftFontInfoDestroy(), et comparées avec XftFontInfoEqual(). Les objets XftFontInfo sont alloués et libérés en interne par Xft ; le programmeur n'a généralement pas besoin d'allouer ou de libérer de la mémoire pour eux.

Chaque structure XftFontInfo en cours d'utilisation est associée à un identifiant unique, qui peut être récupéré avec XftFontInfoHash(). Un XftFont peut être ouvert sur la base des données XftFontInfo avec XftFontOpenInfo().

XftColor


typedef struct _XftColor {
	unsigned long	 pixel;
	XRenderColor	 color;
} XftColor;

Un objet XftColor permet de rendre du texte et d'autres éléments dans une couleur particulière (ou la meilleure approximation offerte par le visual X utilisé).

XftColorAllocName() et XftColorAllocValue() demandent une allocation de couleur au serveur X (si nécessaire) et initialisent les membres de XftColor. XftColorFree() demande au serveur X de libérer la couleur actuellement allouée pour un XftColor.

Une fois qu'un XftColor a été initialisé, XftDrawSrcPicture(), XftDrawGlyphs(), la famille XftDrawString*(), XftDrawCharSpec(), XftDrawCharFontSpec(), XftDrawGlyphSpec(), XftDrawGlyphFontSpec(), et XftDrawRect() peuvent être utilisés pour dessiner divers objets en l'utilisant.

XftDraw

est un objet opaque qui contient des informations utilisées pour le rendu sur un X drawable à l'aide du protocole principal ou de l'extension X Rendering.

Les objets XftDraw sont créés avec l'une des fonctions XftDrawCreate() (qui associe un XftDraw à un X drawable existant), XftDrawCreateBitmap() ou XftDrawCreateAlpha(), et détruits avec XftDrawDestroy(). Le X drawable associé à un XftDraw peut être modifié avec XftDrawChange(). Les objets XftDraw sont alloués et libérés en interne par Xft ; le programmeur n'a généralement pas besoin d'allouer ou de libérer de la mémoire pour eux.

Les propriétés X Display, Drawable, Colormap et Visual d'un XftDraw peuvent être interrogées avec XftDrawDisplay(), XftDrawDrawable(), XftDrawColormap() et XftDrawVisual() respectivement.

Plusieurs fonctions utilisent des objets XftDraw : XftDrawCharFontSpec(), XftDrawCharSpec(), XftDrawGlyphFontSpec(), XftDrawGlyphSpec(), XftDrawGlyphs(), XftDrawRect(), XftDrawSetClip(), XftDrawSetClipRectangles(), XftDrawSetSubwindowMode() et la famille XftDrawString*().

L'extension X Rendering Picture associée à un XftDraw est retournée par XftDrawPicture() et XftDrawSrcPicture(). Elle est utilisée par XftCharFontSpecRender(), XftCharSpecRender(), XftGlyphFontSpecRender(), XftGlyphRender(), XftGlyphSpecRender() et la famille XftTextRender*().

FONCTIONS

Initialisation

Une application typique utilisant Xft n'initialise pas explicitement la bibliothèque. Cela est généralement fait comme effet secondaire de l'ouverture d'une police.

Lorsque Xft s'initialise, il collecte des informations sur l'affichage et stocke certaines de ces informations dans un modèle Fontconfig (essentiellement une collection de propriétés avec des valeurs typées). L'application appelante peut modifier ce modèle pour changer le comportement de la bibliothèque.

Toutes les informations collectées ne sont pas stockées dans un modèle. Le reste est stocké dans des structures de données internes. Xft met une partie de ces informations à la disposition de l'application via des fonctions.

Bool XftDefaultHasRender (
	Display	*dpy);

Obtient des informations sur l'affichage dpy si ce n'est pas déjà fait, et retourne true si Xft a déterminé que l'affichage prend en charge l'extension X Render, et s'il est capable de trouver un XRenderPictFormat approprié (le type de données de X Render qui est analogue au Visual de Xlib) sur l'affichage.

Bool XftDefaultSet (
	Display	*dpy,
	FcPattern	*defaults);

Obtient des informations sur l'affichage dpy si ce n'est pas déjà fait, et définit le modèle Fontconfig contenant les propriétés par défaut que Xft utilisera pour cet affichage.

Xft utilise ces propriétés initialement pour obtenir les limites suivantes :
XFT_MAX_GLYPH_MEMORY
(maxglyphmemory). C'est la quantité maximale de mémoire de glyphes pour toutes les polices utilisées par Xft (par défaut : 4*1024*1024).
XFT_MAX_UNREF_FONTS
(maxunreffonts). C'est le nombre maximum de polices non référencées (par défaut : 16).
XFT_TRACK_MEM_USAGE
(trackmemusage). Lorsque vrai, Xft suit l'utilisation de la mémoire des glyphes pour améliorer les performances lors de la décision de ce qu'il faut décharger lorsque la quantité maximale de mémoire des glyphes est atteinte (par défaut : false).
Xft utilise également ces propriétés par défaut dans XftDefaultSubstitute().
void XftDefaultSubstitute (
	Display	*dpy,
	int	 screen,
	FcPattern	*pattern);

Xft remplit les propriétés manquantes dans le pattern fourni en utilisant les propriétés par défaut pour l'affichage spécifié dpy, par exemple, celles définies dans XftDefaultSet().

Les applications Xft typiques utilisent cette fonction pour aider Fontconfig à choisir une police appropriée. Ces propriétés sont substituées avant d'appeler FcDefaultSubstitute():
FC_ANTIALIAS
Vrai si FreeType doit utiliser l'anti-crénelage (par défaut : False). (par défaut : True).
FC_AUTOHINT
Vrai si FreeType doit utiliser l'autohinting (par défaut : False).
FC_DPI
Points/pouce utilisés pour la résolution (par défaut : calculé à partir de la hauteur de l'affichage).
FC_EMBOLDEN
Vrai si FT_GlyphSlot_Embolden() doit être utilisé pour épaissir une police (par défaut : False).
FC_HINTING
Vrai si le hinting doit être utilisé lors du remplissage des propriétés pour ouvrir une police (par défaut : True).
FC_HINT_STYLE
Style de hinting utilisé lors du remplissage des propriétés pour ouvrir une police (par défaut : FC_HINT_FULL).
FC_LCD_FILTER
Paramètre passé à FT_Library_SetLcdFilter() lors du chargement des glyphes (par défaut : FC_LCD_DEFAULT).
FC_MINSPACE
Espace minimum utilisé lors du remplissage des propriétés pour ouvrir une police (par défaut : False).
FC_RGBA
Valeur RGBA utilisée lors du remplissage des propriétés pour ouvrir une police (par défaut : calculée en appelant XRenderQuerySubpixelOrder()).
FC_SCALE
Facteur d'échelle utilisé dans Fontconfig (par défaut : 1.0).
XFT_MAX_GLYPH_MEMORY
Mémoire maximale pour une police (par défaut : 1024*1024).
XFT_RENDER
Vrai si l'affichage prend en charge l'extension X Render (par défaut : résultat de XftDefaultHasRender()).
FcBool XftInit (
	_Xconst char	*config);

Initialise la bibliothèque Fontconfig (en appelant FcInit()).

Le paramètre config n'est pas utilisé.
Xft ne désinitialise pas la bibliothèque Fontconfig lorsqu'elle est terminée.
FcBool XftInitFtLibrary (void);

    
Initialise la bibliothèque FreeType (en appelant
        FT_Init_FreeType() pour créer un objet de bibliothèque) si elle n'a
        pas déjà été initialisée. Ceci est nécessaire avant d'utiliser la
        bibliothèque FreeType pour lire des données de police à partir d'un
        fichier.

  





  

  
Xft appelle XftInitFtLibrary() en interne via
      XftFontInfoCreate() et XftFontOpenPattern().

  

  
Xft ne supprime pas l'objet de la bibliothèque (par exemple, en utilisant
      FT_Done_FreeType()) lorsqu'il a terminé.

Ouverture   et Correspondance des Polices



  
XftFont *XftFontOpen (

  

    
	Display	*dpy,
	int	 screen,
	...);


    
XftFontOpen prend une liste de triplets d'éléments de modèle
        de la forme champ, type, valeur (terminée par un
        NULL), fait correspondre ce modèle aux polices disponibles, et ouvre la
        police correspondante, en la dimensionnant correctement pour le numéro
        d'écran screen sur l'affichage dpy. Retourne la police
        correspondante, ou NULL si aucune correspondance n'est trouvée.

  




Exemple :
  




    font = XftFontOpen (dpy, screen,
                        XFT_FAMILY, XftTypeString, "charter",
                        XFT_SIZE, XftTypeDouble, 12.0,
                        NULL);




  

  
Ceci ouvre la police “charter” à 12 points. La taille en points
      est automatiquement convertie en la taille correcte en pixels en fonction
      de la résolution de l'écran.





  
XftFont *XftFontOpenName (

  

    
	Display	*dpy,
	int	 screen,
	_Xconst char	*name);


    
XftFontOpenName se comporte comme X
ftFontOpen,
        sauf qu'il prend une chaîne de modèle Fontconfig (qui est transmise à la
        fonction FcNameParse() de la bibliothèque Fontconfig).

  

  
XftFont *XftFontOpenXlfd (

  

    
	Display	*dpy,
	int	 screen,
	_Xconst char	*xlfd)


    
XftFontOpenXlfd se comporte comme XftFontOpen,
        sauf qu'il prend une chaîne contenant une description de police logique X
        (XLFD) et utilise la fonction XftXlfdParse().

  

  
FcPattern *XftFontMatch (

  

    
	Display	*dpy,
	int	 screen,
	_Xconst FcPattern	*pattern,
	FcResult	*result);


    
Également utilisé en interne par les fonctions
        XftFontOpen*, XftFontMatch peut également être utilisé
        directement pour déterminer le modèle de police Fontconfig résultant
        d'une demande d'ouverture de police Xft.

  

  
FcPattern *XftXlfdParse (

  

    
	_Xconst char	*xlfd_orig,
	Bool	ignore_scalable,
	Bool	complete);


    
XftXlfdParse analyse le paramètre xlfd_orig
        conformément au document X Logical Font Description Conventions,
        mais ignore certains champs : setwidth_name,
        add_style_name, spacing et average_width.

  





  

  
XftXlfdParse crée un modèle Fontconfig, définit la propriété
      XFT_XLFD sur la valeur xlfd_orig et mappe les informations
      collectées aux propriétés Fontconfig. Les champs vides ou “*” sont
      ignorés :







  
FC_FOUNDRY

  
provenant de foundry.

  
FC_FAMILY

  
provenant de family.

  
FC_WEIGHT

  
weight_name, par défaut FC_WEIGHT_MEDIUM.

  
FC_SLANT

  
provenant de slant, par défaut FC_SLANT_ROMAN.

  
FC_SIZE

  
provenant de point_size.

  
FC_PIXEL_SIZE

  
provenant de pixel_size. Si point_size a été défini, ainsi que
      resolution_x et resolution_y, alors la valeur est mise à
      l'échelle pour convertir la hauteur de la police en points.

Gestion   des XftColor



  
Bool XftColorAllocName (

  

    
	Display	*dpy,
	_Xconst Visual	*visual,
	Colormap	 cmap,
	_Xconst char	*name,
	XftColor	*result);


    
Utilise XAllocNamedColor() pour rechercher la couleur nommée
        name pour l'écran associé à la palette de couleurs
        cmap.

  






    
  
  • Si XAllocNamedColor() retourne une valeur non nulle,
      XftColorAllocName() remplit le champ pixel XftColor résultant
      avec la couleur la plus proche prise en charge par l'écran, ainsi que les
      champs rouge, vert et bleu exacts de la base de données, et retourne True.
    • 
  
  • Si XAllocNamedColor() retourne zéro, XftColorAllocName()
      retourne False et ne met pas à jour le XftColor référencé par
      result.
    • 






  

  
Le paramètre visual n'est pas utilisé.





  
Bool XftColorAllocValue (

  

    
	Display	*dpy,
	Visual	*visual,
	Colormap	 cmap,
	_Xconst XRenderColor	*color,
	XftColor	*result);


    
Alloue une valeur de couleur :

  






    
  
  • Si la classe visual est TrueColor, XftColorAllocValue()
      définit le champ pixel dans le XftColor référencé par
      result en utilisant les champs rouge, vert et bleu du paramètre
      color.
    • 
  
  • Si la classe visual n'est pas TrueColor, XftColorAllocValue()
      appelle XAllocColor() pour allouer une entrée dans la palette de
      couleurs cmap. qui retourne la valeur pixel de la couleur la plus
      proche des éléments RVB spécifiés pris en charge par le matériel.
    • 




  

  
Si XAllocColor() réussit, XftColorAllocValue() stocke cette
      valeur pixel dans le XRenderColor référencé par result et
      retourne True.

  

  
Si XAllocColor() échoue, XftColorAllocValue() retourne
      False et ne modifie pas le résultat.







  
void XftColorFree (

  

    
	Display	*dpy,
	Visual	*visual,

Si la classe visual n'est pas TrueColor, Xft appelle
        XFreeColors() pour libérer l'entrée de la palette de couleurs
        cmap dont la valeur pixel dans le paramètre color a été

Bool XftDrawSetClip (

  

    
	XftDraw	*draw,
	Region	 r);


    
Configure le découpage pour le paramètre XftDraw
        donné draw en commençant par une Region :

  






    
  
  • Si le paramètre Region r n'est pas nul, Xft crée une
      nouvelle Region (pour copier le paramètre),
    • 
  
  • Xft détruit toute région de découpage existante.
    • 
  
  • Xft définit le type de découpage pour le paramètre draw à
      XftClipTypeRegion si le paramètre r n'était pas nul. Sinon,
      il définit le type de découpage à XftClipTypeNone.
    • 
  
  • Enfin, Xft met à jour le découpage pour les objets existants, met
      à jour le masque de découpage pour son objet Picture X Render et
      définit le masque de découpage dans le contexte graphique (GC) associé au
      paramètre XftDraw.
    • 






  

  
XftDrawSetClip() renvoie True si aucun changement n'était
      nécessaire, ou si l'opération a réussi. Il renvoie False s'il n'a
      pas pu créer la nouvelle Region().

Définit le mode de sous-fenêtre pour le paramètre XftDraw

void XftDrawGlyphFontSpec (

  

    
	XftDraw	*draw,
	_Xconst XftColor	*color,
	_Xconst XftGlyphFontSpec	*glyphs,
	int	 len);


    
Dessine une liste de glyphes associés à des polices à des
        coordonnées spécifiées, passés sous forme d'un tableau de structures
        XftGlyphFontSpec de taille len via le paramètre
        glyphs. Tous les glyphes sont dessinés en utilisant la couleur
        spécifiée dans le paramètre color.

  





  

  
Pour chaque entrée dans le tableau glyphs :






    
  
  • Si la police associée utilise l'extension X Render, alors Xft utilise
      XftGlyphFontSpecRender() pour dessiner le glyphe, en utilisant une
      Picture obtenue en appelant XftDrawSrcPicture() avec les
      paramètres draw et color.
    • 
  
  • Sinon, Xft fournit une fonctionnalité analogue en utilisant Xlib.
    • 






  
void XftGlyphFontSpecRender (

  

    
	Display	*dpy,
	int	 op,
	Picture	 src,
	Picture	 dst,
	int	 srcx,
	int	 srcy,
	_Xconst XftGlyphFontSpec	*glyphs,
	int	 nglyphs);


    
Cela implique plusieurs étapes :

  






    
  
  • Premièrement, Xft s'assure que le tableau glyphs est complet
      en utilisant XftFontCheckGlyph() et en chargeant les glyphes
      manquants avec XftFontLoadGlyphs().
    • 
  
  • Ensuite, Xft examine les glyphes pour trouver la valeur Unicode
      maximale. Cela détermine la taille de l'encodage, c'est-à-dire la
      largeur.
    • 
  
  • Ensuite, pour chaque glyphe, Xft vérifie si sa valeur Unicode est
      prise en charge par la police correspondante. Sinon, la valeur est définie
      à zéro (0), pour l'ignorer. Tout en faisant cela, Xft se souvient
      également quelle a été la première police utilisée, et calcule la position
      à laquelle chaque glyphe sera dessiné.
    • 
  
  • Xft construit ensuite un tableau équivalent de glyphes dans le format
      attendu par la bibliothèque X Render.
    • 
  
  • Enfin, XftGlyphFontSpecRender() utilise l'extension X Render pour
      dessiner les glyphes, avec la fonction appropriée XRenderCompositeText*()
      selon la largeur, et écarte les données temporaires.
    • 




  

  
Les paramètres op, dst, src, srcx, et
      srcy sont utilisés comme décrit dans la documentation de la
      bibliothèque X Render.

NAME


XftFontClose, XftFontOpen, XftFontOpenInfo, XftFontOpen padrões - ouvrir et fermer les polices Xft






SYNOPSIS


#include <X11/Xft/Xft.h>

XftFont *XftFontOpen (
    Display *dpy,
    int  screen,
    ...
);

XftFont *XftFontOpenInfo (
    Display *dpy,
    int  screen,
    FcPattern *pat
);

XftFont *XftFontOpen padrões (
    Display *dpy,
    int  screen,
    FcPattern *pat
);

void XftFontClose (
    Display *dpy,
    XftFont *font
);






DESCRIPTION


Ces fonctions ouvrent et ferment les polices Xft. La fonction
    principale est XftFontOpen(), qui prend un certain nombre d'arguments
    de correspondance de polices suivis de l'argument NULL. Les valeurs
    pour la correspondance de polices sont des paires de chaînes de caractères
    du type :



  
XftFontOpen (dpy, screen,
      Xft FontWeight, weight,
      XftFont Slant, slant,
      XftFontاد, ad,
      XftFontاد, ad,
      ...,
      NULL);
  




Les autres fonctions sont des wrappers pour des opérations plus
    spécifiques :



  
XftFontOpenInfo()

  
Utilise le motif de police donné pour trouver et ouvrir une police.

  
XftFontOpen()

  
Utilise le motif de police donné pour trouver et ouvrir une police.

  
XftFontClose()

  
Ferme la police et libère toutes les ressources associées.




Les fonctions XftFontOpen() et XftFontOpenInfo()
    sont similaires. La principale différence est que XftFontOpen()
    n'attend pas un motif de police explicite, mais prend ses valeurs à partir
    des arguments de ligne de commande qui lui sont transmis. Ces deux fonctions
    utilisent FcFontOpen() pour trouver une police qui correspond aux
    critères spécifiés.


La structure XftFont contient des informations sur la
    police ouverte, y compris des métriques et des glyphes.


XftFontClose() doit être appelé pour chaque police ouverte
    par XftFontOpen() ou des fonctions similaires afin d'éviter les fuites
    de mémoire.

DEBUGGING


La variable d'environnement XFT_DEBUG peut être utilisée pour
    contrôler le niveau de débogage des messages imprimés par Xft. La valeur est
    un masque de bits où chaque bit active un niveau de débogage différent :



  
1

  
Ouverture de polices

  
2

  
Correspondance et ouverture de polices supplémentaires (verbeux)

  
4

  
Détails sur XRenderPictFormat utilisé

  
8

  
Chaîne dessinée par XftDrawString8()

  
16

  
IDs de polices correspondants

  
32

  
Informations utiles sur les glyphes dessinés

  
64

  
Représentation ASCII des glyphes

  
128

  
Gestion du cache de mémoire

  
256

  
Gestion de la mémoire des glyphes en cache

  
512

  
Rapport d'utilisation de la mémoire

  
1024

  
Gestion étendue de la mémoire des glyphes en cache

#include <X11/Xft/XftCompat.h>






Types de données Xft 1.x



  
XftPattern

  
Un ensemble de noms avec des listes de valeurs associées ; chaque nom fait
      référence à une propriété d'une police. Les XftPatterns sont utilisés
      comme entrées pour le code de correspondance ainsi que pour contenir des
      informations sur des polices spécifiques.

  
XftFontSet

  
Contient une liste de XftPatterns. En interne, Xft utilise cette
      structure de données pour contenir des ensembles de polices. Externe-ment,
      Xft renvoie les résultats de la liste des polices dans ce format.

  
XftObjectSet

  
Contient un ensemble de noms et est utilisé pour spécifier quels champs
      des polices sont placés dans la liste des motifs renvoyés lors de la liste
      des polices.
