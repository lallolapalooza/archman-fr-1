NOM

Xft - Bibliothèque d'interface X FreeType

SYNOPSIS

#include <X11/Xft/Xft.h>

DESCRIPTION

Xft est une bibliothèque simple qui dessine du texte et des graphiques :

  • en utilisant les informations fournies par la bibliothèque Fontconfig,
  • Xft convertit les glyphes de polices en utilisant le rasteriseur FreeType, et
  • affiche les données de polices converties en utilisant l'extension de rendu X.

Cette page de manuel ne fait qu'effleurer la surface de cette bibliothèque.

CONSTANTES

XFT_MAJOR
est le numéro de version majeure de Xft.
XFT_MINOR
est le numéro de version mineure de Xft.
XFT_REVISION
est le numéro de révision de Xft.
XFT_VERSION
est XFT_MAJOR multiplié par 10000 (dix mille), plus XFT_MINOR multiplié par 100, plus XFT_REVISION.
XftVersion
est un alias pour XFT_VERSION.

L'exemple suivant illustre comment les constantes de version de Xft pourraient être utilisées : 

    #if (XFT_VERSION >= 20107)
    (void) puts("Version 2.1.7 ou ultérieure de la bibliothèque Xft est en"
                " cours d'utilisation.");
    #else
    (void) printf("Version insuffisante de Xft (%d.%d.%d) installée ;"
                  " besoin d'au moins la version 2.1.7.\n", XFT_MAJOR,
                  XFT_MINOR,
                  XFT_REVISION);
    #endif

TYPES DE DONNEES

Les types de données Xft suivent une convention de nommage, préfixant tous les noms par “Xft”

Depuis Xlib...

Les types de données Xlib ne suivent pas de convention de nommage. Ils sont documentés dans Xlib - C Language Interface.

Xft utilise ces noms : Bool, Colormap, Display, Drawable, Pixmap, Region, Visual, et XRectangle.

Certains types de données sont particulièrement pertinents pour Xft :

Drawable
Déclaré dans <X11/X.h>, c'est un ID de ressource X, par exemple une fenêtre associée à un écran. Les fenêtres et les pixmaps peuvent être utilisées comme sources et destinations dans les opérations graphiques. Ces fenêtres et pixmaps sont collectivement connues sous le nom de drawables. Cependant, une fenêtre InputOnly ne peut pas être utilisée comme source ou destination dans une opération graphique.
Region
Déclaré dans <X11/Xutil.h> et <X11/Xregion.h>, une Region est un ensemble arbitraire d'emplacements de pixels que Xlib peut manipuler. Interne, une Region est représentée par l'union d'un nombre arbitraire de rectangles. Xlib maintient un rectangle qui lui indique l'étendue de cette union.
Visual
Déclaré dans <X11/Xutil.h>, cette structure contient des informations sur le mappage de couleur possible.

Depuis XRender...

Les types de données de la bibliothèque X Render Extension sont inspirés de Xlib, mais manquent de la documentation correspondante. Référez-vous au fichier d'en-tête pour les détails :

<X11/extensions/Xrender.h>

ou lisez le code source (qui fournit un aperçu de libXrender).

Xft utilise ces noms : Picture, XGlyphInfo, XRenderColor.

Depuis Fontconfig...

Les types de données Fontconfig suivent une convention de nommage, préfixant tous les noms par “Fc” qui sont documentés dans le Fontconfig Developers Reference.

Xft utilise ces noms Fontconfig : FcBool, FcChar8, FcChar16, FcChar32, FcCharSet, FcEndian, FcFontSet, FcPattern, et FcResult.

Depuis FreeType 2...

Les types de données FreeType 2 suivent une convention de nommage, préfixant tous les noms par “FT_” qui sont documentés dans le FreeType API Reference.

Xft utilise ces noms : FT_Face, FT_Library, et FT_UInt.

FreeType 2 utilise FT_UInt (un entier non signé) pour représenter des glyphes.

XftFont


typedef struct _XftFont {
	int	 ascent;
	int	 descent;
	int	 height;
	int	 max_advance_width;
	FcCharSet	*charset;
	FcPattern	*pattern;
} XftFont;

Un XftFont est la principale structure de données d'intérêt pour les programmeurs utilisant Xft ; il contient des métriques de police générales et des pointeurs vers le jeu de caractères Fontconfig et le modèle associés à la police.

Les XftFonts sont peuplés par XftFontOpen(), XftFontOpenName(), XftFontOpenXlfd(), XftFontOpenInfo(), ou XftFontOpenPattern(). XftFontCopy() est utilisé pour dupliquer les XftFonts, et XftFontClose() est utilisé pour marquer un XftFont comme non utilisé. Les XftFonts sont alloués, comptés par référence et libérés en interne par Xft ; le programmeur n'a généralement pas besoin d'allouer ou de libérer de la mémoire pour eux.

XftDrawGlyphs(), la famille XftDrawString*(), XftDrawCharSpec(), et XftDrawGlyphSpec() utilisent les XftFonts pour rendre le texte à un objet XftDraw, qui peut correspondre à un drawable X classique ou à un drawable X Rendering Extension.

XftGlyphExtents() et la famille XftTextExtents*() sont utilisés pour déterminer les étendues (dimensions maximales) d'un XftFont.

La couverture des glyphes ou caractères d'un XftFont peut être déterminée avec XftFontCheckGlyph() ou XftCharExists(). XftCharIndex() retourne l'index de caractère spécifique au XftFont correspondant à un point de code Unicode donné.

XftGlyphRender(), XftGlyphSpecRender(), XftCharSpecRender(), et la famille XftTextRender*() utilisent les XftFonts pour dessiner dans les structures Picture de X Rendering Extension.

Remarque : XftDrawGlyphs(), la famille XftDrawString*(), XftDrawCharSpec(), et XftDrawGlyphSpec() fournissent un moyen de rendu des polices qui est indépendant de la disponibilité de l'extension X Rendering sur le serveur X.

XftFontInfo

est un objet opaque qui stocke des informations sur une police. Les structures XftFontInfo sont créées avec XftFontInfoCreate(), libérées avec XftFontInfoDestroy(), et comparées avec XftFontInfoEqual(). Les objets XftFontInfo sont alloués et libérés en interne par Xft ; le programmeur n'a généralement pas besoin d'allouer ou de libérer de la mémoire pour eux.

Chaque structure XftFontInfo en cours d'utilisation est associée à un identifiant unique, qui peut être récupéré avec XftFontInfoHash(). Un XftFont peut être ouvert sur la base des données XftFontInfo avec XftFontOpenInfo().

typedef struct _XftColor {

XftDraw

est un objet opaque qui contient les informations utilisées pour rendre sur un drawable X en utilisant soit le protocole de base, soit l'extension X Rendering.

Les objets XftDraw sont créés avec XftDrawCreate() (qui associe un XftDraw à un drawable X existant), XftDrawCreateBitmap() ou XftDrawCreateAlpha(), et détruits avec XftDrawDestroy(). Le drawable X associé à un XftDraw peut être modifié avec XftDrawChange(). Les objets XftDraw sont alloués et libérés interne par Xft ; le programmeur n'a généralement pas besoin d'allouer ou de libérer de la mémoire pour eux.

Les propriétés Display, Drawable, Colormap et Visual d'un XftDraw peuvent être interrogées avec XftDrawDisplay(), XftDrawDrawable(), XftDrawColormap() et XftDrawVisual(), respectivement.

Plusieurs fonctions utilisent des objets XftDraw : XftDrawCharFontSpec(), XftDrawCharSpec(), XftDrawGlyphFontSpec(), XftDrawGlyphSpec(), XftDrawGlyphs(), XftDrawRect(), XftDrawSetClip(), XftDrawSetClipRectangles(), XftDrawSetSubwindowMode(), et la famille XftDrawString*().

L'extension X Rendering Picture associée à un XftDraw est retournée par XftDrawPicture() et XftDrawSrcPicture(). Elle est utilisée par XftCharFontSpecRender(), XftCharSpecRender(), XftGlyphFontSpecRender(), XftGlyphRender(), XftGlyphSpecRender(), et la famille XftTextRender*().

FONCTIONS

Initialisation

Une application typique utilisant Xft n'initialise pas explicitement la bibliothèque. Ceci est généralement fait comme effet secondaire de l'ouverture d'une police.

Lors de l'initialisation de Xft, il collecte des informations sur l'affichage, et stocke certaines de ces informations dans un modèle Fontconfig (essentiellement une collection de propriétés avec des valeurs typées). L'application appelante peut modifier ce modèle pour changer le comportement de la bibliothèque.

Toutes les informations collectées ne sont pas stockées dans un modèle. Le reste est stocké dans des structures de données internes. Xft rend certaines de ces informations disponibles à l'application via des fonctions.

Bool XftDefaultHasRender (
	Display	*dpy);

Obtient des informations sur l'affichage dpy si ce n'est pas déjà fait, et retourne true si Xft a constaté que l'affichage supporte l'extension X Render, et s'il est capable de trouver un XRenderPictFormat approprié (type de données de X Render analogue au Visual de Xlib) sur l'affichage.

Bool XftDefaultSet (
	Display	*dpy,
	FcPattern	*defaults);

Obtient des informations sur l'affichage dpy si ce n'est pas déjà fait, et définit le modèle Fontconfig contenant les propriétés par défaut que Xft utilisera pour cet affichage.

Xft utilise ces propriétés initialement pour obtenir les limites suivantes :
XFT_MAX_GLYPH_MEMORY
(maxglyphmemory). C'est la quantité maximale de mémoire de glyphes pour toutes les polices utilisées par Xft (par défaut : 4*1024*1024).
XFT_MAX_UNREF_FONTS
(maxunreffonts). C'est le nombre maximum de polices non référencées (par défaut : 16).
XFT_TRACK_MEM_USAGE
(trackmemusage). Si vrai, Xft suit l'utilisation de la mémoire des glyphes pour améliorer les performances lors de la décision de ce qu'il faut décharger lorsque la quantité maximale de mémoire de glyphes est atteinte (par défaut : false).
Xft utilise également ces propriétés par défaut dans XftDefaultSubstitute().
void XftDefaultSubstitute (
	Display	*dpy,
	int	 screen,
	FcPattern	*pattern);

Xft remplit les propriétés manquantes dans le pattern donné en utilisant les propriétés par défaut pour l'affichage spécifié dpy, par exemple, telles que définies dans XftDefaultSet().

Les applications Xft typiques utilisent cette fonction pour aider Fontconfig à choisir une police appropriée. Ces propriétés sont substituées avant d'appeler FcDefaultSubstitute() :
FC_ANTIALIAS
True si FreeType doit utiliser l'anti-aliasing (par défaut : False). (par défaut : True).
FC_AUTOHINT
True si FreeType doit utiliser l'auto-hinting (par défaut : False).
FC_DPI
Points par pouce utilisés pour la résolution (par défaut : calculé à partir de la hauteur de l'affichage).
FC_EMBOLDEN
True si FT_GlyphSlot_Embolden() doit être utilisé pour mettre en gras une police (par défaut : False).
FC_HINTING
True si l'hinting doit être utilisé lors du remplissage des propriétés pour ouvrir une police (par défaut : True).
FC_HINT_STYLE
Style d'hinting utilisé lors du remplissage des propriétés pour ouvrir une police (par défaut : FC_HINT_FULL).
FC_LCD_FILTER
Paramètre passé à FT_Library_SetLcdFilter() lors du chargement des glyphes (par défaut : FC_LCD_DEFAULT).
FC_MINSPACE
Espace minimum utilisé lors du remplissage des propriétés pour ouvrir une police (par défaut : False).
FC_RGBA
Valeur RGBA utilisée lors du remplissage des propriétés pour ouvrir une police (par défaut : calculée en appelant XRenderQuerySubpixelOrder()).
FC_SCALE
Échelle utilisée dans Fontconfig (par défaut : 1.0).
XFT_MAX_GLYPH_MEMORY
Mémoire maximale pour une police (par défaut : 1024*1024).
XFT_RENDER
True si l'affichage supporte l'extension X Render (par défaut : résultat de XftDefaultHasRender()).
FcBool XftInit (
	_Xconst char	*config);

Initialise la bibliothèque Fontconfig (en appelant FcInit()).

Le paramètre config est inutilisé.

Ouverture et Correspondance des Polices



  
XftFont *XftFontOpen (

  

    
	Display	*dpy,
	int	 screen,
	...);


    
XftFontOpen prend une liste de triplets champ, type,
        valeur (terminée par NULL), fait correspondre ce modèle aux polices
        disponibles, et ouvre la police correspondante, en la dimensionnant
        correctement pour le numéro d'écran screen sur l'affichage
        dpy. Retourne la police correspondante, ou NULL si aucune
        correspondance n'est trouvée.

  




Exemple :
  




    font = XftFontOpen (dpy, screen,
                        XFT_FAMILY, XftTypeString, "charter",
                        XFT_SIZE, XftTypeDouble, 12.0,
                        NULL);




  

  
Ceci ouvre la police “charter” à 12 points. La taille en
      points est automatiquement convertie en la taille en pixels correcte en
      fonction de la résolution du moniteur.

FcPattern *XftXlfdParse (

  

    
	_Xconst char	*xlfd_orig,
	Bool	ignore_scalable,
	Bool	complete);


    
XftXlfdParse analyse le paramètre xlfd_orig
        conformément au document X Logical Font Description Conventions,
        mais ignore certains champs : setwidth_name,
        add_style_name, spacing et average_width.

  




  

  
XftXlfdParse crée un motif Fontconfig, définit la propriété
      XFT_XLFD avec la valeur xlfd_orig, et mappe les informations
      collectées aux propriétés Fontconfig. Les champs vides ou contenant "“*”"
      sont ignorés :







  
FC_FOUNDRY

  
provenant de foundry.

provenant de family.

  
FC_WEIGHT

  
weight_name, avec une valeur par défaut FC_WEIGHT_MEDIUM.

provenant de slant, avec une valeur par défaut FC_SLANT_ROMAN.

  
FC_SIZE

  
provenant de point_size.

  
FC_PIXEL_SIZE

  
provenant de pixel_size. Si point_size a été défini, ainsi que
      resolution_x et resolution_y, alors la valeur est mise à
      l'échelle pour convertir la hauteur de la police en points.

Gestion   de XftColor



  
Bool XftColorAllocName (

  

    
	Display	*dpy,
	_Xconst Visual	*visual,
	Colormap	 cmap,
	_Xconst char	*name,
	XftColor	*result);


    
Utilise XAllocNamedColor() pour rechercher la couleur nommée
        name pour l'écran associé à la palette de couleurs cmap.

  






    
  
  • Si XAllocNamedColor() retourne une valeur non nulle,
      XftColorAllocName() remplit le champ pixel XftColor résultant
      avec la couleur la plus proche prise en charge par l'écran, ainsi que les
      champs rouge, vert et bleu exacts de la base de données, et retourne
      True.
    • 
  
  • Si XAllocNamedColor() retourne zéro, XftColorAllocName()
      retourne False et ne met pas à jour le XftColor référencé par
      result.
    • 






  

  
Le paramètre visual n'est pas utilisé.





  
Bool XftColorAllocValue (

  

    
	Display	*dpy,
	Visual	*visual,
	Colormap	 cmap,
	_Xconst XRenderColor	*color,
	XftColor	*result);


    
Alloue une valeur de couleur :

  






    
  
  • Si la classe de visual est TrueColor, XftColorAllocValue()
      définit le champ pixel dans le XftColor référencé par
      result en utilisant les champs rouge, vert et bleu du paramètre
      color.
    • 
  
  • Si la classe de visual n'est pas TrueColor, XftColorAllocValue()
      appelle XAllocColor() pour allouer une entrée dans la palette de
      couleurs cmap, qui retourne la valeur de pixel de la couleur la plus
      proche des éléments RVB spécifiés pris en charge par le matériel.
    • 




  

  
Si XAllocColor() réussit, XftColorAllocValue() stocke cette
      valeur de pixel dans le XRenderColor référencé par result et
      retourne True.

  

  
Si XAllocColor() échoue, XftColorAllocValue() retourne False
      et ne modifie pas le résultat.

Bool XftDrawSetClip (

  

    
	XftDraw	*draw,
	Region	 r);


    
Configure le découpage pour le paramètre XftDraw donné
        draw en commençant par une Region :

  






    
  
  • Si le paramètre Region r n'est pas nul, Xft crée une
      nouvelle Region (pour copier le paramètre),
    • 
  
  • Xft détruit toute région de découpage existante.
    • 
  
  • Xft définit le clip_type pour le paramètre draw à
      XftClipTypeRegion si le paramètre r n'était pas nul. Sinon,
      il définit le clip_type à XftClipTypeNone.
    • 
  
  • Enfin, Xft met à jour le découpage pour les objets existants, met à
      jour le clip_mask pour son objet Picture X Render et définit le
      masque de découpage dans le contexte graphique (GC) associé au paramètre
      XftDraw.
    • 






  

  
XftDrawSetClip() retourne True si aucun changement n'était
      nécessaire, ou si l'opération a réussi. Il retourne False s'il n'a
      pas pu créer la nouvelle Region().

void XftDrawSetSubwindowMode (

  

    
	XftDraw	*draw,
	int	 mode);


    
Définit le mode sous-fenêtre pour le paramètre XftDraw donné
        draw. Le mode peut être soit ClipByChildren (par défaut),
        soit IncludeInferiors :

      sous-fenêtre pour tout contexte graphique (GC) associé en utilisant
      XSetSubwindowMode() ainsi que pour une Picture X Render en
      utilisant XRenderChangePicture().

void XftDrawGlyphFontSpec (

  

    
	XftDraw	*draw,
	_Xconst XftColor	*color,
	_Xconst XftGlyphFontSpec	*glyphs,

Dessine une liste de glyphes associés à des polices à des
        coordonnées spécifiées, passés sous forme d'un tableau de structures
        XftGlyphFontSpec de longueur len via le paramètre
        glyphs. Tous les glyphes sont dessinés en utilisant la couleur
        spécifiée dans le paramètre color.

  





  

  
Pour chaque entrée du tableau glyphs :






    
  
  • Si la police associée utilise l'extension X Render, alors Xft utilise
      XftGlyphFontSpecRender() pour dessiner le glyphe, en utilisant une
      Picture obtenue en appelant XftDrawSrcPicture () avec les
      paramètres draw et color.
    •

    • 






  
void XftGlyphFontSpecRender (

  

    
	Display	*dpy,
	int	 op,
	Picture	 src,
	Picture	 dst,
	int	 srcx,
	int	 srcy,
	_Xconst XftGlyphFontSpec	*glyphs,
	int	 nglyphs);


    
Cela implique plusieurs étapes :

  






    
  
  • Premièrement, Xft s'assure que le tableau glyphs est complet en
      utilisant XftFontCheckGlyph() et en chargeant les glyphes manquants
      avec XftFontLoadGlyphs().
    • 
  
  • Ensuite, Xft examine les glyphes pour trouver la valeur Unicode
      maximale. Cela détermine la taille d'encodage, c'est-à-dire la largeur.
    • 
  
  • Ensuite, pour chaque glyphe, Xft vérifie si sa valeur Unicode est
      prise en charge par la police correspondante. Sinon, la valeur est définie
      à zéro (0), pour l'ignorer. Pendant ce temps, Xft se souvient également
      de la première police utilisée, et calcule la position à laquelle chaque
      glyphe sera dessiné.
    • 
  
  • Xft construit ensuite un tableau équivalent de glyphes dans le format
      attendu par la bibliothèque X Render.
    • 
  
  • Enfin, XftGlyphFontSpecRender() utilise l'extension X Render pour
      dessiner les glyphes, avec la fonction appropriée XRenderCompositeText*()
      selon la largeur, et écarte les données temporaires.
    • 




  

  
Les paramètres op, dst, src, srcx et srcy
      sont utilisés comme décrit dans la documentation de la bibliothèque X Render.

FT_Face XftLockFace (

  

    
	XftFont	*pub);


    
Si aucune « face » FreeType 2 (représentation en mémoire
        d'une police donnée dans un style donné) n'a été créée pour la police
        pub, en crée une en utilisant FT_New_Face(). Les verrous
        de face sont un compteur de référence utilisé par Xft pour
        s'assurer qu'une seule face est créée et qu'elle est conservée jusqu'à ce
        que la police ne soit plus utilisée.

  





  

  
Le verrouillage de face est utilisé directement dans XftCharIndex()
      et XftFontLoadGlyphs(), qui à leur tour sont utilisés dans de
      nombreuses fonctions de Xft.

  

  
Le verrouillage de face a été introduit dans la version 1 (octobre 2002).
      Quelques applications, comme Gdk/Gimp, dépendaient de ces fonctions. Dans
      la version 2.1.9 (juin 2006), le verrouillage de face a été conservé en tant
      que partie de l'API publique lorsque des configurations améliorées de
      bibliothèques partagées ont permis de masquer les symboles privés.

DEBUGAGE


Xft lit la variable d'environnement XFT_DEBUG et
    la convertit en un entier. Chaque bit de la valeur résultante indique à
    Xft d'imprimer des informations de débogage sur la sortie standard
    :



  
1

  
ouverture de police

  
2

  
correspondance et ouverture de police supplémentaires (verbeux)

  
4

  
affiche les détails sur le XRenderPictFormat qui sera utilisé.

  
8

  
affiche la chaîne que XftDrawString8() dessinera.

  
16

  
affiche les identifiants de police qui correspondent.

  
32

  
affiche des informations utiles sur les glyphes qui seront dessinés

  
64

  
affiche une représentation en art ASCII des glyphes.

  
128

  
affiche les détails sur la gestion du cache mémoire

  
256

  
affiche les détails sur la gestion de la mémoire cache des glyphes

  
512

  
affiche un rapport sur l'utilisation de la mémoire

  
1024

  
affiche les détails sur la gestion étendue de la mémoire cache des
      glyphes








COMPATIBILITE


À partir de la version 2 (mai 2002), Xft est devenu
    relativement stable. On s'attend à ce qu'il conserve la compatibilité source
    et binaire dans les futures versions.


Xft fournit une interface de compatibilité avec sa version
    principale précédente, Xft 1.x, décrite ci-dessous.




Fichier   d'en-tête Xft 1.x


#include <X11/Xft/XftCompat.h>






Types   de données Xft 1.x



  
XftPattern

  
contient un ensemble de noms avec des listes de valeurs associées ; chaque
      nom fait référence à une propriété d'une police. Les XftPatterns
      sont utilisés comme entrées pour le code de correspondance ainsi que pour
      contenir des informations sur des polices spécifiques.

  
XftFontSet

  
contient une liste de XftPatterns. Interne à Xft, il utilise
      cette structure de données pour contenir des ensembles de polices.
      Externellement, Xft retourne les résultats de la liste des polices
      dans ce format.

  
XftObjectSet

  
contient un ensemble de noms et est utilisé pour spécifier quels champs de
      polices sont placés dans la liste des modèles retournés lors de la liste des
      polices.
