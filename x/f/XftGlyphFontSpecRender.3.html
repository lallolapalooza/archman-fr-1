NOM

Xft - Bibliothèque d'interface X FreeType

SYNTAXE

#include <X11/Xft/Xft.h>

DESCRIPTION

Xft est une bibliothèque simple qui dessine du texte et des graphiques :

  • en utilisant les informations fournies par la bibliothèque Fontconfig,
  • Xft convertit les glyphes de polices à l'aide du moteur de rendu FreeType, et
  • affiche les données de polices converties à l'aide de l'extension de rendu X.

Cette page de manuel ne fait qu'effleurer la surface de cette bibliothèque.

CONSTANTES

XFT_MAJOR
est le numéro de version majeure de Xft.
XFT_MINOR
est le numéro de version mineure de Xft.
XFT_REVISION
est le numéro de révision de Xft.
XFT_VERSION
est XFT_MAJOR multiplié par 10000 (dix mille), plus XFT_MINOR multiplié par 100, plus XFT_REVISION.
XftVersion
est un alias pour XFT_VERSION.

L'exemple suivant illustre comment les constantes de version de Xft pourraient être utilisées : 

    #if (XFT_VERSION >= 20107)
    (void) puts("Version 2.1.7 ou ultérieure de la bibliothèque Xft est en"
                " cours d'utilisation.");
    #else
    (void) printf("Version insuffisante de Xft (%d.%d.%d) installée ;"
                  " besoin d'au moins la version 2.1.7.\n", XFT_MAJOR,
                  XFT_MINOR,
                  XFT_REVISION);
    #endif

TYPES DE DONNÉES

Les types de données Xft suivent une convention de nommage, en préfixant tous les noms par “Xft”

Depuis Xlib...

Les types de données Xlib ne suivent pas de convention de nommage. Ils sont documentés dans Xlib - Interface en langage C.

Xft utilise ces noms : Bool, Colormap, Display, Drawable, Pixmap, Region, Visual, et XRectangle.

Certains types de données sont particulièrement pertinents pour Xft :

Drawable
Déclaré dans <X11/X.h>, il s'agit d'un ID de ressource X, par exemple une fenêtre associée à un affichage. Les fenêtres et les pixmaps peuvent être utilisés comme sources et destinations dans les opérations graphiques. Ces fenêtres et pixmaps sont collectivement appelés drawables. Cependant, une fenêtre InputOnly ne peut pas être utilisée comme source ou destination dans une opération graphique.
Region
Déclaré dans <X11/Xutil.h> et <X11/Xregion.h>, une Region est un ensemble arbitraire d'emplacements de pixels que Xlib peut manipuler. Internement, une Region est représentée par l'union d'un nombre arbitraire de rectangles. Xlib maintient un rectangle qui lui indique l'étendue de cette union.
Visual
Déclaré dans <X11/Xutil.h>, cette structure contient des informations sur la cartographie des couleurs possible.

Depuis XRender...

Les types de données de l'extension de rendu X sont inspirés de Xlib, mais manquent de la documentation correspondante. Référez-vous au fichier d'en-tête pour les détails :

<X11/extensions/Xrender.h>

ou lisez le code source (qui fournit un aperçu de libXrender).

Xft utilise ces noms : Picture, XGlyphInfo, XRenderColor.

Depuis Fontconfig...

Les types de données Fontconfig suivent une convention de nommage, en préfixant tous les noms par “Fc” qui sont documentés dans le Référence du développeur Fontconfig.

Xft utilise ces noms Fontconfig : FcBool, FcChar8, FcChar16, FcChar32, FcCharSet, FcEndian, FcFontSet, FcPattern, et FcResult.

Depuis FreeType 2...

Les types de données FreeType 2 suivent une convention de nommage, en préfixant tous les noms par “FT_” qui sont documentés dans le Référence de l'API FreeType.

Xft utilise ces noms : FT_Face, FT_Library, et FT_UInt.

FreeType 2 utilise FT_UInt (un entier non signé) pour représenter des glyphes.

XftFont


typedef struct _XftFont {
	int	 ascent;
	int	 descent;
	int	 height;
	int	 max_advance_width;
	FcCharSet	*charset;
	FcPattern	*pattern;
} XftFont;

Un XftFont est la structure de données principale d'intérêt pour les programmeurs utilisant Xft ; il contient des métriques de police générales et des pointeurs vers le jeu de caractères Fontconfig et le modèle associés à la police.

Les XftFont sont peuplés par l'une des fonctions XftFontOpen(), XftFontOpenName(), XftFontOpenXlfd(), XftFontOpenInfo(), ou XftFontOpenPattern(). XftFontCopy() est utilisé pour dupliquer les XftFont, et XftFontClose() est utilisé pour marquer un XftFont comme non utilisé. Les XftFont sont alloués en interne, comptés par référence, et libérés par Xft ; le programmeur n'a généralement pas besoin d'allouer ou de libérer de la mémoire pour eux.

XftDrawGlyphs(), la famille XftDrawString*(), XftDrawCharSpec(), et XftDrawGlyphSpec() utilisent les XftFont pour rendre le texte à un objet XftDraw, qui peut correspondre soit à un drawable X de base, soit à un drawable de l'extension de rendu X.

XftGlyphExtents() et la famille XftTextExtents*() sont utilisés pour déterminer les étendues (dimensions maximales) d'un XftFont.

La couverture des glyphes ou des caractères d'un XftFont peut être déterminée avec XftFontCheckGlyph() ou XftCharExists(). XftCharIndex() renvoie l'indice de caractère spécifique à XftFont correspondant à un point de code Unicode donné.

XftGlyphRender(), XftGlyphSpecRender(), XftCharSpecRender(), et la famille XftTextRender*() utilisent les XftFont pour dessiner dans des structures Picture de l'extension de rendu X.

Remarque : XftDrawGlyphs(), la famille XftDrawString*(), XftDrawCharSpec(), et XftDrawGlyphSpec() fournissent un moyen de rendre les polices indépendant de la disponibilité de l'extension de rendu X sur le serveur X.

XftFontInfo

est un objet opaque qui stocke des informations sur une police. Les structures XftFontInfo sont créées avec XftFontInfoCreate(), libérées avec XftFontInfoDestroy(), et comparées avec XftFontInfoEqual(). Les objets XftFontInfo sont alloués et libérés en interne par Xft ; le programmeur n'a généralement pas besoin d'allouer ou de libérer de la mémoire pour eux.

Chaque structure XftFontInfo en cours d'utilisation est associée à un identifiant unique, qui peut être récupéré avec XftFontInfoHash(). Un XftFont peut être ouvert sur la base des données XftFontInfo avec XftFontOpenInfo().

XftColor


typedef struct _XftColor {
	unsigned long	 pixel;
	XRenderColor	 color;
} XftColor;

Un objet XftColor permet de rendre du texte et d'autres éléments dans une couleur particulière (ou la meilleure approximation offerte par le visual X utilisé).

XftColorAllocName() et XftColorAllocValue() demandent une allocation de couleur au serveur X (si nécessaire) et initialisent les membres de XftColor. XftColorFree() demande au serveur X de libérer la couleur actuellement allouée pour un XftColor.

Une fois qu'un XftColor a été initialisé, XftDrawSrcPicture(), XftDrawGlyphs(), la famille XftDrawString*(), XftDrawCharSpec(), XftDrawCharFontSpec(), XftDrawGlyphSpec(), XftDrawGlyphFontSpec(), et XftDrawRect() peuvent être utilisés pour dessiner divers objets.

XftDraw

est un objet opaque qui contient les informations utilisées pour le rendu sur un objet drawable X à l'aide du protocole de base ou de l'extension X Rendering.

Les objets XftDraw sont créés avec l'une des fonctions XftDrawCreate() (qui associe un XftDraw à un objet drawable X existant), XftDrawCreateBitmap(), ou XftDrawCreateAlpha(), et détruits avec XftDrawDestroy(). L'objet drawable X associé à un XftDraw peut être modifié avec XftDrawChange(). Les objets XftDraw sont alloués et libérés en interne par Xft ; le programmeur n'a généralement pas besoin d'allouer ou de libérer de la mémoire pour eux.

Les propriétés Display, Drawable, Colormap et Visual de X d'un XftDraw peuvent être interrogées respectivement avec XftDrawDisplay(), XftDrawDrawable(), XftDrawColormap() et XftDrawVisual().

Plusieurs fonctions utilisent des objets XftDraw : XftDrawCharFontSpec(), XftDrawCharSpec(), XftDrawGlyphFontSpec(), XftDrawGlyphSpec(), XftDrawGlyphs(), XftDrawRect(), XftDrawSetClip(), XftDrawSetClipRectangles(), XftDrawSetSubwindowMode(), et la famille XftDrawString*().

L'extension X Rendering Picture associée à un XftDraw est retournée par XftDrawPicture() et XftDrawSrcPicture(). Elle est utilisée par XftCharFontSpecRender(), XftCharSpecRender(), XftGlyphFontSpecRender(), XftGlyphRender(), XftGlyphSpecRender(), et la famille XftTextRender*().

FONCTIONS

Initialisation

Une application typique utilisant Xft n'initialise pas explicitement la bibliothèque. Cela se fait généralement lors de l'ouverture d'une police.

Lorsque Xft s'initialise, il collecte des informations sur l'affichage et stocke certaines de ces informations dans un modèle Fontconfig (essentiellement une collection de propriétés avec des valeurs typées). L'application appelante peut modifier ce modèle pour changer le comportement de la bibliothèque.

Toutes les informations collectées ne sont pas stockées dans un modèle. Le reste est stocké dans des structures de données internes. Xft met une partie de ces informations à disposition de l'application via des fonctions.

Bool XftDefaultHasRender (
	Display	*dpy);

Obtient les informations sur l'affichage dpy si cela n'a pas déjà été fait, et retourne true si Xft a constaté que l'affichage prend en charge l'extension X Render, et s'il a pu trouver un XRenderPictFormat approprié (type de données de X Render analogue au Visual de Xlib) sur l'affichage.

Bool XftDefaultSet (
	Display	*dpy,
	FcPattern	*defaults);

Obtient les informations sur l'affichage dpy si cela n'a pas déjà été fait, et définit le modèle Fontconfig contenant les propriétés par défaut que Xft utilisera pour cet affichage.

Xft utilise ces propriétés initialement pour obtenir les limites suivantes :
XFT_MAX_GLYPH_MEMORY
(maxglyphmemory). Il s'agit de la quantité maximale de mémoire de glyphes pour toutes les polices utilisées par Xft (défaut : 4*1024*1024).
XFT_MAX_UNREF_FONTS
(maxunreffonts). C'est le nombre maximum de polices non référencées (défaut : 16).
XFT_TRACK_MEM_USAGE
(trackmemusage). Lorsque cette valeur est vraie, Xft suit l'utilisation de la mémoire des glyphes pour améliorer les performances lors de la décision de ce qu'il faut décharger lorsque la quantité maximale de mémoire des glyphes est atteinte (défaut : faux).
Xft utilise également ces propriétés par défaut dans XftDefaultSubstitute().
void XftDefaultSubstitute (
	Display	*dpy,
	int	 screen,
	FcPattern	*pattern);

Xft complète les propriétés manquantes dans le pattern donné en utilisant les propriétés par défaut pour l'affichage spécifié dpy, par exemple tel que défini dans XftDefaultSet().

Les applications Xft typiques utilisent cette fonction pour aider Fontconfig à choisir une police appropriée. Ces propriétés sont substituées avant d'appeler FcDefaultSubstitute() :
FC_ANTIALIAS
Vrai si FreeType doit utiliser l'anti-crénelage (défaut : Faux). (défaut : Vrai).
FC_AUTOHINT
Vrai si FreeType doit utiliser l'auto-hinting (défaut : Faux).
FC_DPI
Points par pouce utilisés pour la résolution (défaut : calculé à partir de la hauteur de l'écran).
FC_EMBOLDEN
Vrai si FT_GlyphSlot_Embolden() doit être utilisé pour épaissir une police (défaut : Faux).
FC_HINTING
Vrai si l'hinting doit être utilisé lors du remplissage des propriétés pour ouvrir une police (défaut : Vrai).
FC_HINT_STYLE
Style d'hinting utilisé lors du remplissage des propriétés pour ouvrir une police (défaut : FC_HINT_FULL).
FC_LCD_FILTER
Paramètre passé à FT_Library_SetLcdFilter() lors du chargement des glyphes (défaut : FC_LCD_DEFAULT).
FC_MINSPACE
Valeur d'espace minimale utilisée lors du remplissage des propriétés pour ouvrir une police (défaut : Faux).
FC_RGBA
Valeur RGBA utilisée lors du remplissage des propriétés pour ouvrir une police (défaut : calculée en appelant XRenderQuerySubpixelOrder()).
FC_SCALE
Échelle utilisée dans Fontconfig (défaut : 1.0).
XFT_MAX_GLYPH_MEMORY
Mémoire maximale pour une seule police (défaut : 1024*1024).
XFT_RENDER
Vrai si l'affichage prend en charge l'extension X Render (défaut : résultat de XftDefaultHasRender()).
FcBool XftInit (
	_Xconst char	*config);

Initialise la bibliothèque Fontconfig (en appelant FcInit()).

Le paramètre config n'est pas utilisé.
Xft ne désinitialise pas la bibliothèque Fontconfig une fois terminée.
FcBool XftInitFtLibrary (void);

    
Initialise la bibliothèque FreeType (en appelant FT_Init_FreeType() pour créer un objet bibliothèque) si elle n'a pas déjà été initialisée. Ceci est nécessaire avant d'utiliser la bibliothèque FreeType pour lire les données de polices à partir d'un fichier.

  





  

  
Xft appelle XftInitFtLibrary() en interne via XftFontInfoCreate() et XftFontOpenPattern().

  

  
Xft ne supprime pas l'objet bibliothèque (par exemple, en utilisant FT_Done_FreeType()) une fois terminé.

Ouverture et Correspondance des Polices



  
XftFont *XftFontOpen (

  

    
	Display	*dpy,
	int	 screen,
	...);


    
XftFontOpen prend une liste de triplets d'éléments de modèle de la forme champ, type, valeur (terminée par NULL), fait correspondre ce modèle aux polices disponibles, et ouvre la police correspondante, en la dimensionnant correctement pour l'écran numéro screen sur l'affichage dpy. Retourne la police correspondante, ou NULL si aucune correspondance n'est trouvée.

  




Exemple :
  




    font = XftFontOpen (dpy, screen,
                        XFT_FAMILY, XftTypeString, "charter",
                        XFT_SIZE, XftTypeDouble, 12.0,
                        NULL);




  

  
Ceci ouvre la police “charter” à 12 points. La taille en points est automatiquement convertie en la taille en pixels correcte en fonction de la résolution du moniteur.

es comme le fait XftFontOpen,
        sauf qu'elle prend une chaîne de caractères de motif Fontconfig (qui est transmise à

FcPattern *XftXlfdParse (

  

    
	_Xconst char	*xlfd_orig,
	Bool	ignore_scalable,
	Bool	complete);


    
XftXlfdParse analyse le paramètre xlfd_orig
        conformément au document X Logical Font Description Conventions,
        mais ignore certains champs : setwidth_name,
        add_style_name, spacing et average_width.

  




  

  
XftXlfdParse crée un motif Fontconfig, définit la propriété
      XFT_XLFD à la valeur xlfd_orig, et mappe les informations collectées
      aux propriétés Fontconfig. Les champs vides ou “*” sont ignorés :







  
FC_FOUNDRY

  
provenant de foundry.

  
FC_FAMILY

  
provenant de family.

  
FC_WEIGHT

  
weight_name, avec une valeur par défaut de FC_WEIGHT_MEDIUM.

  
FC_SLANT

  
provenant de slant, avec une valeur par défaut de FC_SLANT_ROMAN.

  
FC_SIZE

  
provenant de point_size.

  
FC_PIXEL_SIZE

  
provenant de pixel_size. Si point_size a été défini, ainsi que
      resolution_x et resolution_y, alors la valeur est mise à l'échelle
      pour convertir la hauteur de la police en points.

Gestion   de XftColor



  
Bool XftColorAllocName (

  

    
	Display	*dpy,
	_Xconst Visual	*visual,
	Colormap	 cmap,
	_Xconst char	*name,
	XftColor	*result);


    
Utilise XAllocNamedColor() pour rechercher la couleur nommée
        name pour l'écran associé à la colormap cmap.

  






    
  
  • Si XAllocNamedColor() retourne une valeur non nulle,
      XftColorAllocName() remplit le champ pixel XftColor résultant
      avec la couleur la plus proche prise en charge par l'écran, ainsi que les
      champs rouge, vert et bleu exacts de la base de données, et retourne True.
    • 
  
  • Si XAllocNamedColor() retourne zéro, XftColorAllocName()
      retourne False, et ne met pas à jour le XftColor référencé par
      result.
    • 






  

  
Le paramètre visual n'est pas utilisé.





  
Bool XftColorAllocValue (

  

    
	Display	*dpy,
	Visual	*visual,
	Colormap	 cmap,
	_Xconst XRenderColor	*color,
	XftColor	*result);


    
Alloue une valeur de couleur :

  






    
  
  • Si la classe visual est TrueColor, XftColorAllocValue() définit
      le champ pixel dans le XftColor référencé par result
      en utilisant les champs rouge, vert et bleu du paramètre color.
    • 
  
  • Si la classe visual n'est pas TrueColor, XftColorAllocValue()
      appelle XAllocColor() pour allouer une entrée dans la colormap
      cmap. qui retourne la valeur de pixel de la couleur la plus proche des
      éléments RVB spécifiés pris en charge par le matériel.
    • 




  

  
Si XAllocColor() réussit, XftColorAllocValue() stocke cette
      valeur de pixel dans le XRenderColor référencé par result et
      retourne True.

  

  
Si XAllocColor() échoue, XftColorAllocValue() retourne False
      et ne modifie pas le résultat.

XftDraw *XftDrawCreate (

  

    
	Display	*dpy,
	Drawable	 drawable,
	Visual	*visual,
	Colormap	 colormap);


    
XftDrawCreate crée une structure qui peut être utilisée pour

void XftDrawGlyphFontSpec (

  

    
	XftDraw	*draw,
	_Xconst XftColor	*color,
	_Xconst XftGlyphFontSpec	*glyphs,
	int	 len);


    
Dessine une liste de glyphes associés à des polices à des
        coordonnées spécifiées, passée sous forme de tableau de len
        structures XftGlyphFontSpec via le paramètre glyphs. Tous
        les glyphes sont dessinés en utilisant la couleur spécifiée dans le
        paramètre color.

  





  

  
Pour chaque entrée dans le tableau glyphs :






    
  
  • Si la police associée utilise l'extension X Render, alors Xft utilise
      XftGlyphFontSpecRender() pour dessiner le glyphe, en utilisant un
      Picture obtenu en appelant XftDrawSrcPicture () avec les
      paramètres draw et color.
    •

    • 






  
void XftGlyphFontSpecRender (

  

    
	Display	*dpy,
	int	 op,
	Picture	 src,
	Picture	 dst,
	int	 srcx,
	int	 srcy,
	_Xconst XftGlyphFontSpec	*glyphs,
	int	 nglyphs);


    
Cela implique plusieurs étapes :

  






    
  
  • Tout d'abord, Xft s'assure que le tableau glyphs est complet
      en utilisant XftFontCheckGlyph() et en chargeant les glyphes manquants
      avec XftFontLoadGlyphs().
    • 
  
  • Ensuite, Xft examine les glyphes pour trouver la valeur Unicode
      maximale. Cela détermine la taille de l'encodage, c'est-à-dire la
      largeur.
    • 
  
  • Ensuite, pour chaque glyphe, Xft vérifie si sa valeur Unicode est
      prise en charge par la police correspondante. Sinon, la valeur est mise à
      zéro (0), pour l'ignorer. Pendant ce temps, Xft se souvient quelle
      était la première police utilisée, et calcule la position à laquelle chaque
      glyphe sera dessiné.
    • 
  
  • Xft construit ensuite un tableau équivalent de glyphes dans le format
      attendu par la bibliothèque X Render.
    • 
  
  • Enfin, XftGlyphFontSpecRender() utilise l'extension X Render pour
      dessiner les glyphes, avec la fonction XRenderCompositeText*() appropriée
      selon la largeur, et écarte les données temporaires.
    • 




  

  
Les paramètres op, dst, src, srcx, et
      srcy sont utilisés comme décrit dans la documentation de la
      bibliothèque X Render.

NAME


XftGlyphFontSpecRender - render glyphs using Xft






SYNOPSIS


#include <X11/Xft/Xft.h>

typedef struct _XftFont XftFont;
typedef struct _XftPattern XftPattern;

void
XftFontLoadGlyphs(Display *dpy, XftFont *pub, FcBool need_bitmaps,
    const FT_UInt *glyphs, int nglyph);

void
XftFontUnloadGlyphs(Display *dpy, XftFont *pub, const FT_UInt *glyphs,
    int nglyph);







DESCRIPTION


The XftFontLoadGlyphs() function loads glyphs
    into the given font structure. The glyphs argument
    is an array of glyph indices (Unicode values) to load, and nglyph
    is the number of glyphs in the array. The need_bitmaps
    argument specifies whether bitmaps are needed for the glyphs. The dpy
    argument is the display connection.


The XftFontUnloadGlyphs() function unloads
    glyphs from the given font structure. The glyphs
    argument is an array of glyph indices (Unicode values) to unload, and
    nglyph is the number of glyphs in the array. The dpy
    argument is the display connection.


These functions are used internally by Xft to manage glyphs and their
    associated rendering data.

void XftFontLoadGlyphs (

  

    
	Display	*dpy,
	XftFont	*pub,
	FcBool	 need_bitmaps,
	_Xconst FT_UInt	*glyphs,
	int	 nglyph);


    
Using FT_Load_Glyph(), load nglyphs for the
        glyph indices (Unicode values) listed in the array glyphs from
        the given font pub.

  





  

  
Loading a glyph entails more than just reading data into memory.
      Xft uses the Fontconfig pattern associated with the display
      dpy (e.g., via XftDefaultSet()) to determine whether to use
      a bounding box, clip the glyphs into those bounds, scale the glyphs,
      compute font metrics, and add it to the X Render extension using
      XRenderAddGlyphs().

        indices (Unicode values) are listed in the array glyphs for the

FT_Face XftLockFace (

  

    
	XftFont	*pub);


    
If no FreeType 2 “face” (in-memory
        representation of a given typeface in a given style) has been created
        for the pub font, create one using FT_New_Face().
        Face-locks are a reference count used by Xft to ensure that only
        one face is created, and that it is retained until the font is no longer
        used.

  





  

  
Face-locking is used directly in XftCharIndex() and
      XftFontLoadGlyphs(), which in turn are used in many functions of
      Xft.

  

  
Face-locking was introduced in version 1 (October 2002). A few
      applications, such as Gdk/Gimp relied upon these functions. In version
      2.1.9 (June 2006), face-locking was retained as part of the public API
      when improved shared-library configurations provided for hiding private
      symbols.

DEBUGGING


Xft reads the environment variable XFT_DEBUG and
    converts that to an integer. Each bit in the resulting value tells
    Xft to print debugging information to the standard output:



  
1

  
font-opening

  
2

  
additional font-matching and opening (verbose)

  
4

  
shows details about the XRenderPictFormat which will be used.

  
8

  
shows the string which XftDrawString8() will draw.

  
16

  
shows which font-ids are matched.

  
32

  
shows useful information about the glyphs which will be drawn

  
64

  
shows an ASCII-art representation of the glyphs.

  
128

  
shows details about the memory-cache management

  
256

  
shows details about managing glyph cached-memory

  
512

  
shows a report on memory-usage

  
1024

  
shows details on extended management of glyph cached-memory

      code as well as holding information about specific fonts.
