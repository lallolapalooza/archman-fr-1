XCreateGC(3) FONCTIONS XLIB XCreateGC(3)

NOM

XCreateGC, XCopyGC, XChangeGC, XGetGCValues, XFreeGC, XGContextFromGC, XGCValues - créer ou libérer des contextes graphiques et la structure du contexte graphique

SYNTAXE

GC XCreateGC(Display *display, Drawable d, unsigned long valuemask, XGCValues *values);

int XCopyGC(Display *display, GC src, unsigned long valuemask, GC dest);

int XChangeGC(Display *display, GC gc, unsigned long valuemask, XGCValues *values);

Status XGetGCValues(Display *display, GC gc, unsigned long valuemask, XGCValues *values_return);

int XFreeGC(Display *display, GC gc);

GContext XGContextFromGC(GC gc);

ARGUMENTS

d
Spécifie le dessinable.
dest
Spécifie le GC de destination.
display
Spécifie la connexion au serveur X.
gc
Spécifie le GC.
src
Spécifie les composants du GC source.
valuemask
Spécifie quels composants dans le GC doivent être définis, copiés, modifiés ou retournés. Cet argument est le OU inclusif bit à bit de zéro ou plusieurs des bits de masque de composant GC valides.
values
Spécifie les valeurs comme indiqué par le valuemask.
values_return
Retourne les valeurs du GC dans la structure XGCValues spécifiée.

DESCRIPTION

La fonction XCreateGC crée un contexte graphique et retourne un GC. Le GC peut être utilisé avec n'importe quel dessinable de destination ayant la même racine et la même profondeur que le dessinable spécifié. L'utilisation avec d'autres dessinables entraîne une erreur BadMatch.

XCreateGC peut générer des erreurs BadAlloc, BadDrawable, BadFont, BadMatch, BadPixmap et BadValue.

La fonction XCopyGC copie les composants spécifiés de la GC source vers la GC de destination. Les GC source et destination doivent avoir la même racine et la même profondeur, sinon une erreur BadMatch se produit. Le valuemask spécifie quel composant copier, comme pour XCreateGC.

XCopyGC peut générer des erreurs BadAlloc, BadGC et BadMatch.

La fonction XChangeGC modifie les composants spécifiés par valuemask pour le GC spécifié. L'argument values contient les valeurs à définir. Les valeurs et les restrictions sont les mêmes que pour XCreateGC. La modification du masque de découpage remplace toute requête précédente XSetClipRectangles sur le contexte. La modification du décalage de tirets ou de la liste de tirets remplace toute requête précédente XSetDashes sur le contexte. L'ordre dans lequel les composants sont vérifiés et modifiés est dépendant du serveur. Si une erreur est générée, un sous-ensemble des composants peut avoir été modifié.

XChangeGC peut générer des erreurs BadAlloc, BadFont, BadGC, BadMatch, BadPixmap et BadValue.

La fonction XGetGCValues retourne les composants spécifiés par valuemask pour le GC spécifié. Si le valuemask contient un ensemble valide de bits de masque GC (GCFunction, GCPlaneMask, GCForeground, GCBackground, GCLineWidth, GCLineStyle, GCCapStyle, GCJoinStyle, GCFillStyle, GCFillRule, GCTile, GCStipple, GCTileStipXOrigin, GCTileStipYOrigin, GCFont, GCSubwindowMode, GCGraphicsExposures, GCClipXOrigin, GCClipYOrigin, GCDashOffset, ou GCArcMode) et qu'aucune erreur ne se produit, XGetGCValues définit les composants demandés dans values_return et retourne un statut non nul. Sinon, il retourne un statut nul. Notez que le masque de découpage et la liste de tirets (représentés par les bits GCClipMask et GCDashList, respectivement, dans le valuemask) ne peuvent pas être demandés. Notez également qu'un identifiant de ressource invalide (avec un ou plusieurs des trois bits les plus significatifs mis à 1) sera retourné pour GCFont, GCTile et GCStipple si le composant n'a jamais été explicitement défini par le client.

La fonction XFreeGC détruit le GC spécifié ainsi que tout le stockage associé.

XFreeGC peut générer une erreur BadGC.

De nombreuses opérations graphiques dépendent soit des valeurs de pixels, soit des plans d'un GC. L'attribut des plans est de type `long` et spécifie quels plans de la destination doivent être modifiés, un bit par plan. Un écran monochrome n'a qu'un seul plan et sera le bit le moins significatif du mot. Au fur et à mesure que des plans sont ajoutés au matériel d'affichage, ils occuperont des bits plus significatifs dans le masque de plans.

Dans les opérations graphiques, étant donné un pixel source et un pixel destination, le résultat est calculé bit par bit sur les bits correspondants des pixels. C'est-à-dire qu'une opération booléenne est effectuée dans chaque plan de bits. Le `plane_mask` restreint l'opération à un sous-ensemble de plans. Une constante macro `AllPlanes` peut être utilisée pour faire référence à tous les plans de l'écran simultanément. Le résultat est calculé par ce qui suit :

((src FUNC dst) ET plane-mask) OU (dst ET (NON plane-mask))

Aucune vérification de plage n'est effectuée sur les valeurs de `foreground`, `background` ou `plane_mask`. Elles sont simplement tronquées au nombre approprié de bits. La largeur de ligne est mesurée en pixels et peut soit être supérieure ou égale à un (ligne large), soit être la valeur spéciale zéro (ligne fine).

Les lignes larges sont dessinées centrées sur le chemin décrit par la requête graphique. Sauf indication contraire de `join_style` ou `cap_style`, la boîte englobante d'une ligne large avec les points d'extrémité [x1, y1], [x2, y2] et la largeur w est un rectangle avec les sommets aux coordonnées réelles suivantes :

[x1-(w*sn/2), y1+(w*cs/2)], [x1+(w*sn/2), y1-(w*cs/2)],
[x2-(w*sn/2), y2+(w*cs/2)], [x2+(w*sn/2), y2-(w*cs/2)]

Ici, `sn` est le sinus de l'angle de la ligne, et `cs` est le cosinus de l'angle de la ligne. Un pixel fait partie de la ligne et est donc dessiné si le centre du pixel est entièrement à l'intérieur de la boîte englobante (qui est vue comme ayant des bords infiniment fins). Si le centre du pixel est exactement sur la boîte englobante, il fait partie de la ligne si et seulement si l'intérieur est immédiatement à sa droite (direction d'augmentation de x). Les pixels dont les centres sont sur un bord horizontal sont un cas spécial et font partie de la ligne si et seulement si l'intérieur ou la frontière est immédiatement en dessous (direction d'augmentation de y) et si l'intérieur ou la frontière est immédiatement à droite (direction d'augmentation de x).

Les lignes fines (largeur de ligne zéro) sont des lignes d'un pixel de large dessinées à l'aide d'un algorithme indéterminé et dépendant du périphérique. Il n'y a que deux contraintes sur cet algorithme.

1.
Si une ligne est dessinée sans découpage de [x1,y1] à [x2,y2] et si une autre ligne est dessinée sans découpage de [x1+dx,y1+dy] à [x2+dx,y2+dy], un point [x,y] est touché par le dessin de la première ligne si et seulement si le point [x+dx,y+dy] est touché par le dessin de la seconde ligne.
2.
L'ensemble effectif de points constituant une ligne ne peut pas être affecté par le découpage. C'est-à-dire qu'un point est touché dans une ligne découpée si et seulement si le point se trouve à l'intérieur de la région de découpage et que le point serait touché par la ligne lorsqu'elle est dessinée sans découpage.

Une ligne large dessinée de [x1,y1] à [x2,y2] dessine toujours les mêmes pixels qu'une ligne large dessinée de [x2,y2] à [x1,y1], sans compter `cap_style` et `join_style`. Il est recommandé que cette propriété soit vraie pour les lignes fines, mais ce n'est pas obligatoire. Une largeur de ligne de zéro peut différer d'une largeur de ligne de un dans la manière dont les pixels sont dessinés. Cela permet d'utiliser le matériel de dessin de ligne de nombreux fabricants, qui peut fonctionner beaucoup plus rapidement que les lignes larges spécifiées plus précisément.

En général, dessiner une ligne fine sera plus rapide que de dessiner une ligne large de largeur un. Cependant, en raison de leurs algorithmes de dessin différents, les lignes fines peuvent ne pas bien se mélanger esthétiquement avec les lignes larges. S'il est souhaitable d'obtenir des résultats précis et uniformes sur tous les affichages, un client doit toujours utiliser une largeur de ligne de un plutôt qu'une largeur de ligne de zéro.

Le `line_style` définit quelles sections d'une ligne sont dessinées :

LineSolid Le chemin complet de la ligne est dessiné.
LineDoubleDash Le chemin complet de la ligne est dessiné, mais les tirets pairs sont remplis différemment des tirets impairs (voir `fill_style`) avec un style `CapButt` utilisé là où les tirets pairs et impairs se rencontrent.
LineOnOffDash Seuls les tirets pairs sont dessinés, et `cap_style` s'applique à toutes les extrémités internes des tirets individuels, sauf `CapNotLast` est traité comme `CapButt`.

Le `cap_style` définit comment les points d'extrémité d'un chemin sont dessinés :

CapNotLast Ceci est équivalent à `CapButt`, sauf que pour une largeur de ligne de zéro, le point d'extrémité final n'est pas dessiné.
CapButt La ligne est carrée à l'extrémité (perpendiculaire à la pente de la ligne) sans projection au-delà.
CapRound La ligne a un arc de cercle dont le diamètre est égal à la largeur de la ligne, centré sur le point d'extrémité. (Ceci est équivalent à `CapButt` pour une largeur de ligne de zéro).
CapProjecting La ligne est carrée à l'extrémité, mais le chemin continue au-delà du point d'extrémité sur une distance égale à la moitié de la largeur de la ligne. (Ceci est équivalent à `CapButt` pour une largeur de ligne de zéro).

Le `join_style` définit comment les coins sont dessinés pour les lignes larges :

JoinMiter Les bords extérieurs de deux lignes s'étendent pour se rencontrer sous un angle. Cependant, si l'angle est inférieur à 11 degrés, un style `JoinBevel` est utilisé à la place.
JoinRound Le coin est un arc de cercle dont le diamètre est égal à la largeur de la ligne, centré sur le point de jonction.
JoinBevel Le coin a des styles de point d'extrémité `CapButt` avec l'encoche triangulaire remplie.

Pour une ligne avec des points d'extrémité coïncidents (x1=x2, y1=y2), lorsque `cap_style` est appliqué aux deux points d'extrémité, la sémantique dépend de la largeur de ligne et du `cap_style` :

CapNotLast fine Les résultats dépendent du périphérique, mais l'effet souhaité est que rien ne soit dessiné.
CapButt fine Les résultats dépendent du périphérique, mais l'effet souhaité est qu'un seul pixel soit dessiné.
CapRound fine Les résultats sont les mêmes que pour `CapButt` / `fine`.
CapProjecting fine Les résultats sont les mêmes que pour `CapButt` / `fine`.
CapButt large Rien n'est dessiné.
CapRound large Le chemin fermé est un cercle, centré sur le point d'extrémité, et avec un diamètre égal à la largeur de la ligne.
CapProjecting large Le chemin fermé est un carré, aligné avec les axes de coordonnées, centré sur le point d'extrémité, et avec des côtés égaux à la largeur de la ligne.

Pour une ligne avec des points d'extrémité coïncidents (x1=x2, y1=y2), lorsque `join_style` est appliqué à un ou aux deux points d'extrémité, l'effet est comme si la ligne était retirée du chemin global. Cependant, si le chemin total consiste en un seul point joint à lui-même ou est réduit à un tel point, l'effet est le même que lorsque `cap_style` est appliqué aux deux points d'extrémité.

Le motif/tampon représente un plan bidimensionnel infini, avec le motif/tampon répliqué dans toutes les dimensions. Lorsque ce plan est superposé au dessin pour être utilisé dans une opération graphique, le coin supérieur gauche d'une instance du motif/tampon se trouve aux coordonnées du dessin spécifiées par l'origine du motif/tampon. Les origines du motif et du découpage sont interprétées par rapport à l'origine de tout dessin de destination spécifié dans une requête graphique. Le pixmap de motif doit avoir la même racine et la même profondeur que le GC, sinon une erreur `BadMatch` se produit. Le pixmap de tampon doit avoir la profondeur un et doit avoir la même racine que le GC, sinon une erreur `BadMatch` se produit. Pour les opérations de tampon où `fill_style` est `FillStippled` mais pas `FillOpaqueStippled`, le motif de tampon est répliqué sur un seul plan et agit comme un masque de découpage supplémentaire à faire avec un ET (`AND`) avec le masque de découpage (`clip_mask`). Bien que certaines tailles puissent être plus rapides à utiliser que d'autres, n'importe quelle taille de pixmap peut être utilisée pour le pavage ou le tamponnage.

Le `fill_style` définit le contenu de la source pour les requêtes de ligne, de texte et de remplissage. Pour toutes les requêtes de texte et de remplissage (par exemple, `XDrawText`, `XDrawText16`, `XFillRectangle`, `XFillPolygon`, et `XFillArc`); pour les requêtes de ligne avec `line_style` `LineSolid` (par exemple, `XDrawLine`, `XDrawSegments`, `XDrawRectangle`, `XDrawArc`); et pour les tirets pairs des requêtes de ligne avec `line_style` `LineOnOffDash` ou `LineDoubleDash`, les règles suivantes s'appliquent :

FillSolid Premier plan
FillTiled Motif
FillOpaqueStippled Un motif de la même largeur et hauteur que le tampon, mais avec l'arrière-plan partout où le tampon a un zéro et avec le premier plan partout où le tampon a un un
FillStippled Premier plan masqué par le tampon
XFreeGC(3) — X Version 11

NAME

XFreeGC — free a graphics context

SYNTAX

void XFreeGC ( Display *display , GC gc );

ARGUMENTS

display Specifies the connection to the X server.

gc Specifies the GC that is to be freed.

DESCRIPTION

The XFreeGC function frees the specified graphics context (GC) and releases any associated resources. After this call, the GC is no longer valid. All other GCs that share the same components, such as font or tile, are unaffected.

When drawing lines with line-style LineDoubleDash, the odd dashes are controlled by the fill-style in the following manner:

FillSolid Background
FillTiled Same as for even dashes
FillOpaqueStippled Same as for even dashes
FillStippled Background masked by stipple

Storing a pixmap in a GC might or might not result in a copy being made. If the pixmap is later used as the destination for a graphics request, the change might or might not be reflected in the GC. If the pixmap is used simultaneously in a graphics request both as a destination and as a tile or stipple, the results are undefined.

For optimum performance, you should draw as much as possible with the same GC (without changing its components). The costs of changing GC components relative to using different GCs depend on the display hardware and the server implementation. It is quite likely that some amount of GC information will be cached in display hardware and that such hardware can only cache a small number of GCs.

The dashes value is actually a simplified form of the more general patterns that can be set with XSetDashes. Specifying a value of N is equivalent to specifying the two-element list [N, N] in XSetDashes. The value must be nonzero, or a BadValue error results.

The clip-mask restricts writes to the destination drawable. If the clip-mask is set to a pixmap, it must have depth one and have the same root as the GC, or a BadMatch error results. If clip-mask is set to None, the pixels are always drawn regardless of the clip origin. The clip-mask also can be set by calling the XSetClipRectangles or XSetRegion functions. Only pixels where the clip-mask has a bit set to 1 are drawn. Pixels are not drawn outside the area covered by the clip-mask or where the clip-mask has a bit set to 0. The clip-mask affects all graphics requests. The clip-mask does not clip sources. The clip-mask origin is interpreted relative to the origin of whatever destination drawable is specified in a graphics request.

You can set the subwindow-mode to ClipByChildren or IncludeInferiors. For ClipByChildren, both source and destination windows are additionally clipped by all viewable InputOutput children. For IncludeInferiors, neither source nor destination window is clipped by inferiors. This will result in including subwindow contents in the source and drawing through subwindow boundaries of the destination. The use of IncludeInferiors on a window of one depth with mapped inferiors of differing depth is not illegal, but the semantics are undefined by the core protocol.

The fill-rule defines what pixels are inside (drawn) for paths given in XFillPolygon requests and can be set to EvenOddRule or WindingRule. For EvenOddRule, a point is inside if an infinite ray with the point as origin crosses the path an odd number of times. For WindingRule, a point is inside if an infinite ray with the point as origin crosses an unequal number of clockwise and counterclockwise directed path segments. A clockwise directed path segment is one that crosses the ray from left to right as observed from the point. A counterclockwise segment is one that crosses the ray from right to left as observed from the point. The case where a directed line segment is coincident with the ray is uninteresting because you can simply choose a different ray that is not coincident with a segment.

For both EvenOddRule and WindingRule, a point is infinitely small, and the path is an infinitely thin line. A pixel is inside if the center point of the pixel is inside and the center point is not on the boundary. If the center point is on the boundary, the pixel is inside if and only if the polygon interior is immediately to its right (x increasing direction). Pixels with centers on a horizontal edge are a special case and are inside if and only if the polygon interior is immediately below (y increasing direction).

The arc-mode controls filling in the XFillArcs function and can be set to ArcPieSlice or ArcChord. For ArcPieSlice, the arcs are pie-slice filled. For ArcChord, the arcs are chord filled.

The graphics-exposure flag controls GraphicsExpose event generation for XCopyArea and XCopyPlane requests (and any similar requests defined by extensions).

DIAGNOSTICS

BadAlloc
The server failed to allocate the requested resource or server memory.
BadDrawable
A value for a Drawable argument does not name a defined Window or Pixmap.
BadFont
A value for a Font or GContext argument does not name a defined Font.
BadGC
A value for a GContext argument does not name a defined GContext.
BadMatch
An InputOnly window is used as a Drawable.
BadMatch
Some argument or pair of arguments has the correct type and range but fails to match in some other way required by the request.
BadPixmap
A value for a Pixmap argument does not name a defined Pixmap.
BadValue
Some numeric value falls outside the range of values accepted by the request. Unless a specific range is specified for an argument, the full range defined by the argument's type is accepted. Any argument defined as a set of alternatives can generate this error.
