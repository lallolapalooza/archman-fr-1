NOM

Xft - Bibliothèque d'interface X FreeType

SYNTAXE

#include <X11/Xft/Xft.h>

DESCRIPTION

Xft est une bibliothèque simple qui dessine du texte et des graphiques :

  • en utilisant les informations fournies par la bibliothèque Fontconfig,
  • Xft convertit les glyphes de polices en utilisant le rasterizer FreeType, et
  • affiche les données de police converties en utilisant l'extension X Rendering Extension.

Cette page de manuel ne fait qu'effleurer la surface de cette bibliothèque.

CONSTANTES

XFT_MAJOR
est le numéro de version majeure de Xft.
XFT_MINOR
est le numéro de version mineure de Xft.
XFT_REVISION
est le numéro de révision de Xft.
XFT_VERSION
est XFT_MAJOR multiplié par 10000 (dix mille), plus XFT_MINOR multiplié par 100, plus XFT_REVISION.
XftVersion
est un alias pour XFT_VERSION.

L'exemple suivant illustre comment les constantes de version de Xft pourraient être utilisées : 

    #if (XFT_VERSION >= 20107)
    (void) puts("Version 2.1.7 ou ultérieure de la bibliothèque Xft est en"
                " cours d'utilisation.");
    #else
    (void) printf("Version insuffisante de Xft (%d.%d.%d) installée ;"
                  " besoin d'au moins la version 2.1.7.\n", XFT_MAJOR,
                  XFT_MINOR,
                  XFT_REVISION);
    #endif

TYPES DE DONNÉES

Les types de données Xft suivent une convention de nommage, en préférant tous les noms par "Xft"

Depuis Xlib...

Les types de données Xlib ne suivent pas de convention de nommage. Ils sont documentés dans Xlib - C Language Interface.

Xft utilise ces noms : Bool, Colormap, Display, Drawable, Pixmap, Region, Visual, et XRectangle.

Certains types de données sont particulièrement pertinents pour Xft :

Drawable
Déclaré dans <X11/X.h>, il s'agit d'un identifiant de ressource X, par exemple, une fenêtre associée à un affichage. Les fenêtres et les pixmaps peuvent être utilisés comme sources et destinations dans les opérations graphiques. Ces fenêtres et pixmaps sont collectivement appelés des "drawables". Cependant, une fenêtre InputOnly ne peut pas être utilisée comme source ou destination dans une opération graphique.
Region
Déclaré dans <X11/Xutil.h> et <X11/Xregion.h>, une Region est un ensemble arbitraire d'emplacements de pixels que Xlib peut manipuler. En interne, une Region est représentée par l'union d'un nombre arbitraire de rectangles. Xlib maintient un rectangle qui lui indique l'étendue de cette union.
Visual
Déclaré dans <X11/Xutil.h>, cette structure contient des informations sur le mappage des couleurs possible.

Depuis XRender...

Les types de données de la bibliothèque X Render Extension sont inspirés de Xlib, mais manquent de la documentation correspondante. Se référer au fichier d'en-tête pour les détails :

<X11/extensions/Xrender.h>

ou lire le code source (qui fournit un aperçu de libXrender).

Xft utilise ces noms : Picture, XGlyphInfo, XRenderColor.

Depuis Fontconfig...

Les types de données Fontconfig suivent une convention de nommage, préférant tous les noms par "Fc", qui sont documentés dans le Fontconfig Developers Reference.

Xft utilise ces noms Fontconfig : FcBool, FcChar8, FcChar16, FcChar32, FcCharSet, FcEndian, FcFontSet, FcPattern, et FcResult.

Depuis FreeType 2...

Les types de données FreeType 2 suivent une convention de nommage, préférant tous les noms par "FT_", qui sont documentés dans le FreeType API Reference.

Xft utilise ces noms : FT_Face, FT_Library, et FT_UInt.

FreeType 2 utilise FT_UInt (un entier non signé) pour représenter les glyphes.

XftFont


typedef struct _XftFont {
	int	 ascent;
	int	 descent;
	int	 height;
	int	 max_advance_width;
	FcCharSet	*charset;
	FcPattern	*pattern;
} XftFont;

Un XftFont est la principale structure de données d'intérêt pour les programmeurs utilisant Xft ; il contient des métriques de police générales et des pointeurs vers l'ensemble de caractères Fontconfig et le modèle associé à la police.

Les XftFonts sont remplis par XftFontOpen(), XftFontOpenName(), XftFontOpenXlfd(), XftFontOpenInfo(), ou XftFontOpenPattern(). XftFontCopy() est utilisé pour dupliquer les XftFonts, et XftFontClose() est utilisé pour marquer un XftFont comme non utilisé. Les XftFonts sont alloués en interne, comptés par référence, et libérés par Xft ; le programmeur n'a pas habituellement besoin d'allouer ou de libérer de la mémoire pour eux.

XftDrawGlyphs(), la famille XftDrawString*(), XftDrawCharSpec(), et XftDrawGlyphSpec() utilisent les XftFonts pour rendre le texte dans un objet XftDraw, qui peut correspondre à un drawable X de base ou à un drawable X Rendering Extension.

XftGlyphExtents() et la famille XftTextExtents*() sont utilisés pour déterminer les étendues (dimensions maximales) d'un XftFont.

La couverture des glyphes ou des caractères d'un XftFont peut être déterminée avec XftFontCheckGlyph() ou XftCharExists(). XftCharIndex() renvoie l'index de caractère spécifique à XftFont correspondant à un point de code Unicode donné.

XftGlyphRender(), XftGlyphSpecRender(), XftCharSpecRender(), et la famille XftTextRender*() utilisent les XftFonts pour dessiner dans les structures Picture de X Rendering Extension.

Remarque : XftDrawGlyphs(), la famille XftDrawString*(), XftDrawCharSpec(), et XftDrawGlyphSpec() fournissent un moyen de rendre les polices qui est indépendant de la disponibilité de l'extension X Rendering sur le serveur X.

XftFontInfo

est un objet opaque qui stocke des informations sur une police. Les structures XftFontInfo sont créées avec XftFontInfoCreate(), libérées avec XftFontInfoDestroy(), et comparées avec XftFontInfoEqual(). Les objets XftFontInfo sont alloués et libérés en interne par Xft ; le programmeur n'a pas habituellement besoin d'allouer ou de libérer de la mémoire pour eux.

Chaque structure XftFontInfo en cours d'utilisation est associée à un identifiant unique, qui peut être récupéré avec XftFontInfoHash(). Un XftFont peut être ouvert sur la base des données XftFontInfo avec XftFontOpenInfo().

XftColor


typedef struct _XftColor {
	unsigned long	 pixel;
	XRenderColor	 color;
} XftColor;

Un objet XftColor permet de rendre le texte et d'autres éléments dans une couleur particulière (ou la meilleure approximation offerte par le visuel X utilisé).

DESCRIPTION

Xft is an interface to the FreeType font library that is designed to work with the X Window System. It provides a convenient and efficient way to render fonts using FreeType with Xlib and the X Rendering Extension. This document describes the types and functions provided by the Xft library.

TYPES

Xft defines several opaque types, and a few structures that are used to pass information between the application and the library.

XftDraw

is an opaque object which holds information used to render to an X drawable using either the core protocol or the X Rendering extension.

XftDraw objects are created with any of XftDrawCreate() (which associates an XftDraw with an existing X drawable), XftDrawCreateBitmap(), or XftDrawCreateAlpha(), and destroyed with XftDrawDestroy(). The X drawable associated with an XftDraw can be changed with XftDrawChange(). XftDraw objects are internally allocated and freed by Xft; the programmer does not ordinarily need to allocate or free storage for them.

The X Display, Drawable, Colormap, and Visual properties of an XftDraw can be queried with XftDrawDisplay(), XftDrawDrawable(), XftDrawColormap(), and XftDrawVisual(), respectively.

Several functions use XftDraw objects: XftDrawCharFontSpec(), XftDrawCharSpec(), XftDrawGlyphFontSpec(), XftDrawGlyphSpec(), XftDrawGlyphs(), XftDrawRect(), XftDrawSetClip(), XftDrawSetClipRectangles(), XftDrawSetSubwindowMode(), and the XftDrawString*() family.

The X Rendering Extension Picture associated with an XftDraw is returned by XftDrawPicture(), and XftDrawSrcPicture(). It is used by XftCharFontSpecRender(), XftCharSpecRender(), XftGlyphFontSpecRender(), XftGlyphRender(), XftGlyphSpecRender(), and the XftTextRender*() family.

FUNCTIONS

Initialization

A typical application using Xft does not explicitly initialize the library. That is usually done as a side-effect of opening a font.

When Xft initializes, it collects information about the display, and stores some of that information in a Fontconfig pattern (essentially a collection of properties with typed values). The calling application can modify that pattern to change the library's behavior.

Not all of the collected information is stored in a pattern. The remainder is stored in internal data structures. Xft makes some of that available to the application via functions.

Bool XftDefaultHasRender (
	Display	*dpy);

Obtain information about the display dpy if not done already, and return true if Xft found that the display supports the X Render extension, and if it is able to find a suitable XRenderPictFormat (X Render's datatype which is analogous to Xlib's Visual) on the display.

Bool XftDefaultSet (
	Display	*dpy,
	FcPattern	*defaults);

Obtain information about the display dpy if not done already, and set the Fontconfig pattern holding default properties which Xft will use for this display.

Xft uses those properties initially to obtain these limits:
XFT_MAX_GLYPH_MEMORY
(maxglyphmemory). This is the maximum amount of glyph memory for all fonts used by Xft (default: 4*1024*1024).
XFT_MAX_UNREF_FONTS
(maxunreffonts). This is the maximum number of unreferenced fonts (default: 16).
XFT_TRACK_MEM_USAGE
(trackmemusage). When true, Xft tracks usage of glyph memory to improve performance when deciding which to unload when the maximum amount of glyph memory is reached (default: false).
Xft also uses these default properties in XftDefaultSubstitute().
void XftDefaultSubstitute (
	Display	*dpy,
	int	 screen,
	FcPattern	*pattern);

Xft fills in missing properties in the given pattern using default properties for the specified display dpy, e.g., as set in XftDefaultSet().

Typical Xft applications use this function to help Fontconfig choose a suitable font. These properties are substituted before calling FcDefaultSubstitute():

	_Xconst FcPattern	*pattern,
	FcResult	*result
);

FcPattern	*XftXlfdParse(
	_Xconst char	*xlfd_orig,
	Bool	 ignore_scalable,
	Bool	 complete
);







DESCRIPTION


XftFontOpen opens a font matching the given screen and
    font description. The arguments following the screen number are a list of
    name-value pairs, terminated by 0. These are passed to the Fontconfig
    library's FcNameParse() function to create a font pattern. If
    successful, XftFontOpen() attempts to find a font matching the
    pattern and opens it. It returns a pointer to an opaque font structure, or
    0 if no font could be opened.


XftFontOpenXlfd behaves as XftFontOpen does,
    except that it takes a string containing an X Logical Font Description
    (XLFD), and uses the XftXlfdParse() function.


Also used internally by the XftFontOpen* functions,
    XftFontMatch can also be used directly to determine the Fontconfig
    font pattern resulting from an Xft font open request.


XftXlfdParse parses the xlfd_orig parameter
    according to the X Logical Font Description Conventions document,
    but ignores some of the fields: setwidth_name,
    add_style_name, spacing, and average_width.



  

  
XftXlfdParse creates a Fontconfig pattern, setting the property
      XFT_XLFD to the xlfd_orig value, and maps the collected
      information to Fontconfig properties. Empty or “*” fields
      are ignored:







  
FC_FOUNDRY

  
from foundry.

  
FC_FAMILY

  
from family.

  
FC_WEIGHT

  
weight_name, defaulting to FC_WEIGHT_MEDIUM.

  
FC_SLANT

  
from slant, defaulting to FC_SLANT_ROMAN.

  
FC_SIZE

  
from point_size.

  
FC_PIXEL_SIZE

  
from pixel_size. If point_size was set, as well as
      resolution_xand resolution_y, then the value is scaled
      convert the font's height to points.

Bool XftColorAllocValue (

  

    
	Display	*dpy,
	Visual	*visual,
	Colormap	 cmap,
	_Xconst XRenderColor	*color,
	XftColor	*result);


    
Allocate a color value:

  






    
  
  • If the visual class is TrueColor, XftColorAllocValue() sets
      the pixel field in the XftColor referenced by result

    • 
  
  • If the visual class is not TrueColor, XftColorAllocValue()

    •

      pixel value in the XRenderColor referenced by result and
      returns True.

  

  
If XAllocColor() fails, XftColorAllocValue() returns False
      and does not modify the result.

Bool XftDrawSetClip (

  

    
	XftDraw	*draw,
	Region	 r);


    
Configure le découpage pour le paramètre XftDraw donné
        draw en commençant par une Region :

  






    
  
  • Si le paramètre Region r n'est pas nul, Xft crée une
      nouvelle Region (pour copier le paramètre),
    • 
  
  • Xft détruit toute région de découpage existante.
    • 
  
  • Xft définit le clip_type pour le paramètre draw à
      XftClipTypeRegion si le paramètre r n'était pas nul. Sinon,
      il définit le clip_type à XftClipTypeNone.
    • 
  
  • Enfin, Xft met à jour le découpage pour les objets existants, met
      à jour le masque de découpage pour son objet Picture X Render et
      définit le masque de découpage dans le contexte graphique (GC) associé au
      paramètre XftDraw.
    • 






  

  
XftDrawSetClip() renvoie True si aucun changement n'était
      nécessaire, ou si l'opération a réussi. Elle renvoie False si elle
      n'a pas pu créer la nouvelle Region().

Définit le mode de sous-fenêtre pour le paramètre XftDraw

void XftDrawGlyphFontSpec (

  

    
	XftDraw	*draw,

Dessine une liste de glyphes associés à des polices à des
        coordonnées spécifiées, passée sous forme d'un tableau de len
        structures XftGlyphFontSpec via le paramètre glyphs. Tous
        les glyphes sont dessinés en utilisant la couleur spécifiée dans le
        paramètre color.

  





  

  
Pour chaque entrée du tableau glyphs :






    
  
  • Si la police associée utilise l'extension X Render, alors Xft utilise
      XftGlyphFontSpecRender() pour dessiner le glyphe, en utilisant une
      Picture obtenue en appelant XftDrawSrcPicture () avec les

    •

    • 






  
void XftGlyphFontSpecRender (

  

    
	Display	*dpy,
	int	 op,
	Picture	 src,
	Picture	 dst,
	int	 srcx,
	int	 srcy,
	_Xconst XftGlyphFontSpec	*glyphs,
	int	 nglyphs);


    
Cela implique plusieurs étapes :

  






    
  
  • Premièrement, Xft s'assure que le tableau glyphs est complet
      en utilisant XftFontCheckGlyph() et en chargeant les glyphes
      manquants avec XftFontLoadGlyphs().
    • 
  
  • Ensuite, Xft examine les glyphes pour trouver la valeur Unicode
      maximale. Cela détermine la taille de l'encodage, c'est-à-dire la
      largeur.
    • 
  
  • Ensuite, pour chaque glyphe, Xft vérifie si sa valeur Unicode est
      prise en charge par la police correspondante. Sinon, la valeur est définie
      à zéro (0), pour l'ignorer. Pendant ce processus, Xft se souvient
      également de la première police utilisée et calcule la position à laquelle
      chaque glyphe sera dessiné.
    • 
  
  • Xft construit ensuite un tableau équivalent de glyphes dans le format
      attendu par la bibliothèque X Render.
    • 
  
  • Enfin, XftGlyphFontSpecRender() utilise l'extension X Render pour
      dessiner les glyphes, avec la fonction XRenderCompositeText*()
      appropriée selon la largeur, et écarte les données temporaires.
    • 




  

  
Les paramètres op, dst, src, srcx et
      srcy sont utilisés comme décrit dans la documentation de la
      bibliothèque X Render.

NOM


XftCharSpecRender - rendu de glyphes spécifiés par le caractère






SYNTAXIS


    #include <X11/Xft/Xft.h>

    void XftCharSpecRender (
        Display     *dpy,
        int          screen,
        FcPattern   *font_pattern,
        XftFontSpec *specs,
        int          nspecs,
        GC           gc,
        int          x,
        int          y
    );







DESCRIPTION


La fonction XftCharSpecRender rend un ensemble de glyphes
    spécifiés par des énumérations de caractères UTF-8, utilisant un modèle de
    police donné et une liste de spécifications de glyphes. La sortie est dessinée
    sur l'écran de profondeur spécifié, en utilisant le contexte graphique gc,
    et positionnée à la coordonnée (x, y).


Cette fonction est une primitive pour le rendu de chaînes de
    caractères Unicode. Les spécifications de glyphes dans specs indiquent
    comment les glyphes doivent être interprétés, par exemple s'ils doivent être
    rendus comme des bitmaps, des vecteurs, etc.


La fonction utilise FcFontList pour trouver les polices
    correspondant au font_pattern, puis charge les glyphes nécessaires à
    l'aide de XftFontLoadGlyphs. Enfin, elle utilise l'extension X Render
    pour effectivement dessiner les glyphes.




Paramètres



  
Display *dpy

  
Le descripteur de connexion au serveur X.

  
int screen

  
Le numéro de l'écran sur lequel dessiner.

  
FcPattern *font_pattern

  
Le modèle décrivant la police souhaitée. Fontconfig sera utilisé pour
      trouver une police correspondant à ce modèle.

  
XftFontSpec *specs

  
Un tableau de spécifications de glyphes. Chaque XftFontSpec
      contient un code de caractère, un index de glyphe FreeType et des drapeaux
      indiquant comment le glyphe doit être traité.

  
int nspecs

  
Le nombre d'éléments dans le tableau specs.

  
GC gc

  
Le contexte graphique X à utiliser pour le dessin. Il détermine la couleur,
      le mode d'opération, etc.

  
int x

  
La coordonnée X du coin supérieur gauche où commencer le dessin.

  
int y

  
La coordonnée Y du coin supérieur gauche où commencer le dessin.










CONSTANTES


Les drapeaux dans XftFontSpec peuvent inclure :



  
XFT_GLYPH_BITMAP

  
Le glyphe est une bitmap.

  
XFT_GLYPH_VECTOR

  
Le glyphe est une représentation vectorielle (pour le rendu anti-aliasing).

  
XFT_GLYPH_CLIP

  
Le glyphe doit être découpé selon les limites de la cellule de la police.








TYPES DE DONNÉES



  
XftFontSpec

  

    
    typedef struct {
        FcChar32      codepoint;  /* Code de caractère Unicode */
        FT_UInt         glyph;      /* Index du glyphe FreeType */
        unsigned int    flags;      /* Drapeaux (XFT_GLYPH_*) */
    } XftFontSpec;


    
Cette structure contient les informations nécessaires pour
        spécifier comment un caractère individuel doit être traité et rendu.

  





  
FcPattern

  
Une structure opaque utilisée par Fontconfig pour représenter un ensemble
      de propriétés de police (nom, taille, poids, etc.).





  
XftFont

  
Une structure opaque représentant une police chargée par Xft.





  
Display

  
Le type défini par Xlib pour représenter une connexion au serveur X.





  
GC

  
Le type défini par Xlib pour représenter un contexte graphique.
