XFillRectangle(3) FONCTIONS XLIB XFillRectangle(3)

NOM

XFillRectangle, XFillRectangles, XFillPolygon, XFillArc, XFillArcs - remplir des rectangles, polygones ou arcs

SYNTAXE

int XFillRectangle(Display *display, Drawable d, GC gc, int x, int y, unsigned int width, unsigned int height);

int XFillRectangles(Display *display, Drawable d, GC gc, XRectangle *rectangles, int nrectangles);

int XFillPolygon(Display *display, Drawable d, GC gc, XPoint *points, int npoints, int shape, int mode);

int XFillArc(Display *display, Drawable d, GC gc, int x, int y, unsigned int width, unsigned int height, int angle1, int angle2);

int XFillArcs(Display *display, Drawable d, GC gc, XArc *arcs, int narcs);

ARGUMENTS

angle1
Spécifie le début de l'arc par rapport à la position de trois heures du centre, en unités de degrés * 64.
angle2
Spécifie le chemin et l'étendue de l'arc par rapport au début de l'arc, en unités de degrés * 64.
arcs
Spécifie un tableau d'arcs.
d
Spécifie le drawable.
display
Spécifie la connexion au serveur X.
gc
Spécifie le GC.
mode
Spécifie le mode de coordonnées. Vous pouvez passer CoordModeOrigin ou CoordModePrevious.
narcs
Spécifie le nombre d'arcs dans le tableau.
npoints
Spécifie le nombre de points dans le tableau.
nrectangles
Spécifie le nombre de rectangles dans le tableau.
points
Spécifie un tableau de points.
rectangles
Spécifie un tableau de rectangles.
shape
Spécifie une forme qui aide le serveur à améliorer les performances. Vous pouvez passer Complex, Convex ou Nonconvex.
width

height
Spécifiez la largeur et la hauteur, qui sont les dimensions du rectangle à remplir ou les axes majeur et mineur de l'arc.
x

y
Spécifiez les coordonnées x et y, qui sont relatives à l'origine du drawable et définissent le coin supérieur gauche du rectangle.

DESCRIPTION

Les fonctions XFillRectangle et XFillRectangles remplissent le rectangle ou les rectangles spécifiés comme si une requête de protocole FillPolygon à quatre points avait été spécifiée pour chaque rectangle :

[x,y] [x+width,y] [x+width,y+height] [x,y+height]

Chaque fonction utilise les coordonnées x et y, les dimensions de largeur et hauteur, et le GC que vous spécifiez.

XFillRectangles remplit les rectangles dans l'ordre indiqué dans le tableau. Pour un rectangle donné, XFillRectangle et XFillRectangles ne dessinent pas un pixel plus d'une fois. Si des rectangles s'intersectent, les pixels d'intersection sont dessinés plusieurs fois.

Les deux fonctions utilisent les composants GC suivants : fonction, masque de plan, style de remplissage, mode de sous-fenêtre, origine x du clip, origine y du clip, et masque du clip. Elles utilisent également ces composants dépendants du mode GC : premier plan, arrière-plan, carreau, pointillé, origine x du carreau/pointillé, et origine y du carreau/pointillé.

XFillRectangle et XFillRectangles peuvent générer des erreurs BadDrawable, BadGC et BadMatch.

XFillPolygon remplit la région fermée par le chemin spécifié. Le chemin est fermé automatiquement si le dernier point de la liste ne coïncide pas avec le premier point. XFillPolygon ne dessine pas un pixel de la région plus d'une fois. CoordModeOrigin traite toutes les coordonnées comme relatives à l'origine, et CoordModePrevious traite toutes les coordonnées après la première comme relatives au point précédent.

Selon la forme spécifiée, le comportement suivant se produit :

  • Si shape est Complex, le chemin peut s'auto-intersecter. Notez que les points contigus coïncidents dans le chemin ne sont pas traités comme une auto-intersection.
  • Si shape est Convex, pour toute paire de points à l'intérieur du polygone, le segment de ligne qui les relie n'intersecte pas le chemin. Si le client le sait, spécifier Convex peut améliorer les performances. Si vous spécifiez Convex pour un chemin qui n'est pas convexe, les résultats graphiques sont indéfinis.
  • Si shape est Nonconvex, le chemin ne s'auto-intersecte pas, mais la forme n'est pas entièrement convexe. Si le client le sait, spécifier Nonconvex au lieu de Complex peut améliorer les performances. Si vous spécifiez Nonconvex pour un chemin qui s'auto-intersecte, les résultats graphiques sont indéfinis.

La règle de remplissage du GC contrôle le comportement de remplissage des polygones qui s'auto-intersectent.

Cette fonction utilise les composants GC suivants : fonction, masque de plan, style de remplissage, règle de remplissage, mode de sous-fenêtre, origine x du clip, origine y du clip, et masque du clip. Elle utilise également ces composants dépendants du mode GC : premier plan, arrière-plan, carreau, pointillé, origine x du carreau/pointillé, et origine y du carreau/pointillé.

XFillPolygon peut générer des erreurs BadDrawable, BadGC, BadMatch et BadValue.

Pour chaque arc, XFillArc ou XFillArcs remplit la région fermée par le chemin d'épaisseur infiniment fine décrit par l'arc spécifié et, selon le mode d'arc spécifié dans le GC, un ou deux segments de ligne. Pour ArcChord, le segment de ligne unique reliant les extrémités de l'arc est utilisé. Pour ArcPieSlice, les deux segments de ligne reliant les extrémités de l'arc au point central sont utilisés. XFillArcs remplit les arcs dans l'ordre indiqué dans le tableau. Pour un arc donné, XFillArc et XFillArcs ne dessinent pas un pixel plus d'une fois. Si des régions s'intersectent, les pixels d'intersection sont dessinés plusieurs fois.

Les deux fonctions utilisent les composants GC suivants : fonction, masque de plan, style de remplissage, mode d'arc, mode de sous-fenêtre, origine x du clip, origine y du clip, et masque du clip. Elles utilisent également ces composants dépendants du mode GC : premier plan, arrière-plan, carreau, pointillé, origine x du carreau/pointillé, et origine y du carreau/pointillé.

XFillArc et XFillArcs peuvent générer des erreurs BadDrawable, BadGC et BadMatch.

DIAGNOSTICS

BadDrawable
Une valeur pour un argument Drawable ne nomme pas une Fenêtre ou une Pixmap définie.
BadGC
Une valeur pour un argument GContext ne nomme pas un GContext défini.
BadMatch
Une fenêtre InputOnly est utilisée comme Drawable.
BadMatch
Un argument ou une paire d'arguments a le bon type et la bonne plage, mais ne correspond pas d'une autre manière requise par la requête.
BadValue
Une valeur numérique se situe en dehors de la plage des valeurs acceptées par la requête. Sauf si une plage spécifique est spécifiée pour un argument, la plage complète définie par le type de l'argument est acceptée. Tout argument défini comme un ensemble d'alternatives peut générer cette erreur.
