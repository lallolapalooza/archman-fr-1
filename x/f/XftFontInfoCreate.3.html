NOM

Xft - Bibliothèque d'interface X FreeType

SYNTAXE

#include <X11/Xft/Xft.h>

DESCRIPTION

Xft est une bibliothèque simple qui dessine du texte et des graphiques :

  • en utilisant les informations fournies par la bibliothèque Fontconfig,
  • Xft convertit les glyphes de police en utilisant le moteur de rendu FreeType, et
  • affiche les données de police converties en utilisant l'extension X Rendering Extension.

Cette page de manuel ne fait qu'effleurer la surface de cette bibliothèque.

CONSTANTES

XFT_MAJOR
est le numéro de version majeure de Xft.
XFT_MINOR
est le numéro de version mineure de Xft.
XFT_REVISION
est le numéro de révision de Xft.
XFT_VERSION
est XFT_MAJOR multiplié par 10000 (dix mille), plus XFT_MINOR multiplié par 100, plus XFT_REVISION.
XftVersion
est un alias pour XFT_VERSION.

L'exemple suivant illustre comment les constantes de version de Xft peuvent être utilisées : 

    #if (XFT_VERSION >= 20107)
    (void) puts("Version 2.1.7 ou ultérieure de la bibliothèque Xft est en"
                " usage.");
    #else
    (void) printf("Version insuffisante de Xft (%d.%d.%d) installée ;
                  " besoin d'au moins la version 2.1.7.\n", XFT_MAJOR,
                  XFT_MINOR,
                  XFT_REVISION);
    #endif

TYPES DE DONNÉES

Les types de données Xft suivent une convention de nommage, en préfixant tous les noms par “Xft”

Depuis Xlib...

Les types de données Xlib ne suivent pas une convention de nommage. Ils sont documentés dans Xlib - Interface du langage C.

Xft utilise ces noms : Bool, Colormap, Display, Drawable, Pixmap, Region, Visual, et XRectangle.

Certains types de données sont particulièrement pertinents pour Xft :

Drawable
Déclaré dans <X11/X.h>, c'est un identifiant de ressource X, par exemple une fenêtre associée à un affichage. Les fenêtres et les pixmaps peuvent être utilisés comme sources et destinations dans les opérations graphiques. Ces fenêtres et pixmaps sont collectivement appelés des `drawables`. Cependant, une fenêtre de type InputOnly ne peut pas être utilisée comme source ou destination dans une opération graphique.
Region
Déclaré dans <X11/Xutil.h> et <X11/Xregion.h>, une Region est un ensemble arbitraire d'emplacements de pixels que Xlib peut manipuler. En interne, une Region est représentée par l'union d'un nombre arbitraire de rectangles. Xlib maintient un rectangle qui lui indique l'étendue de cette union.
Visual
Déclaré dans <X11/Xutil.h>, cette structure contient des informations sur la correspondance des couleurs possible.

Depuis XRender...

Les types de données de la bibliothèque X Render Extension sont inspirés de Xlib, mais manquent de la documentation correspondante. Se référer au fichier d'en-tête pour les détails :

<X11/extensions/Xrender.h>

ou lire le code source (qui fournit un aperçu de libXrender).

Xft utilise ces noms : Picture, XGlyphInfo, XRenderColor.

Depuis Fontconfig...

Les types de données Fontconfig suivent une convention de nommage, en préfixant tous les noms par “Fc” qui sont documentés dans le Manuel de référence pour les développeurs Fontconfig.

Xft utilise ces noms Fontconfig : FcBool, FcChar8, FcChar16, FcChar32, FcCharSet, FcEndian, FcFontSet, FcPattern, et FcResult.

Depuis FreeType 2...

Les types de données FreeType 2 suivent une convention de nommage, en préfixant tous les noms par “FT_” qui sont documentés dans le Manuel de référence de l'API FreeType.

Xft utilise ces noms : FT_Face, FT_Library, et FT_UInt.

FreeType 2 utilise FT_UInt (un entier non signé) pour représenter les glyphes.

XftFont


typedef struct _XftFont {
	int	 ascent;
	int	 descent;
	int	 height;
	int	 max_advance_width;
	FcCharSet	*charset;
	FcPattern	*pattern;
} XftFont;

Un XftFont est la structure de données principale qui intéresse les programmeurs utilisant Xft ; il contient des métriques générales de police et des pointeurs vers l'ensemble de caractères et le modèle Fontconfig associés à la police.

Les XftFont sont peuplés avec l'une des fonctions XftFontOpen(), XftFontOpenName(), XftFontOpenXlfd(), XftFontOpenInfo(), ou XftFontOpenPattern(). XftFontCopy() est utilisé pour dupliquer les XftFont, et XftFontClose() est utilisé pour marquer un XftFont comme non utilisé. Les XftFont sont alloués en interne, comptés par référence, et libérés par Xft ; le programmeur n'a normalement pas besoin d'allouer ou de libérer de l'espace pour eux.

XftDrawGlyphs(), la famille XftDrawString*(), XftDrawCharSpec(), et XftDrawGlyphSpec() utilisent les XftFont pour rendre le texte dans un objet XftDraw, qui peut correspondre à un objet dessinable core X ou à un objet dessinable X Rendering Extension.

XftGlyphExtents() et la famille XftTextExtents*() sont utilisés pour déterminer les étendues (dimensions maximales) d'un XftFont.

La couverture des glyphes ou des caractères d'un XftFont peut être déterminée avec XftFontCheckGlyph() ou XftCharExists(). XftCharIndex() retourne l'index de caractère spécifique à XftFont correspondant à un point de code Unicode donné.

XftGlyphRender(), XftGlyphSpecRender(), XftCharSpecRender(), et la famille XftTextRender*() utilisent les XftFont pour dessiner dans des structures Picture de X Rendering Extension.

Remarque : XftDrawGlyphs(), la famille XftDrawString*(), XftDrawCharSpec(), et XftDrawGlyphSpec() fournissent un moyen de rendre les polices qui est indépendant de la disponibilité de l'extension X Rendering sur le serveur X.

XftFontInfo

est un objet opaque qui stocke des informations sur une police. Les structures XftFontInfo sont créées avec XftFontInfoCreate(), libérées avec XftFontInfoDestroy(), et comparées avec XftFontInfoEqual(). Les objets XftFontInfo sont alloués et libérés en interne par Xft ; le programmeur n'a normalement pas besoin d'allouer ou de libérer de l'espace pour eux.

Chaque structure XftFontInfo en cours d'utilisation est associée à un identifiant unique, qui peut être récupéré avec XftFontInfoHash(). Un XftFont peut être ouvert sur la base des données XftFontInfo avec XftFontOpenInfo().

XftColor


typedef struct _XftColor {
	unsigned long	 pixel;
	XRenderColor	 color;
} XftColor;

Un objet XftColor permet de rendre du texte et d'autres éléments dans une couleur particulière (ou la meilleure approximation offerte par le visual X utilisé).

XftColorAllocName() et XftColorAllocValue() demandent une allocation de couleur au serveur X (si nécessaire) et initialisent les membres de XftColor. XftColorFree() demande au serveur X de libérer la couleur actuellement allouée pour un XftColor.

Une fois qu'un XftColor a été initialisé, XftDrawSrcPicture(), XftDrawGlyphs(), la famille XftDrawString*(), XftDrawCharSpec(), XftDrawCharFontSpec(), XftDrawGlyphSpec(), XftDrawGlyphFontSpec(), et XftDrawRect() peuvent être utilisés pour dessiner divers objets en utilisant

STRUCTURES

The Xft library provides structures for holding font information, glyphs, and drawing contexts.

XftDraw

est un objet opaque qui contient des informations utilisées pour rendre sur un drawable X en utilisant soit le protocole de base, soit l'extension X Rendering.

Les objets XftDraw sont créés avec l'une des fonctions XftDrawCreate() (qui associe un XftDraw à un drawable X existant), XftDrawCreateBitmap(), ou XftDrawCreateAlpha(), et détruits avec XftDrawDestroy(). Le drawable X associé à un XftDraw peut être modifié avec XftDrawChange(). Les objets XftDraw sont alloués et libérés en interne par Xft ; le programmeur n'a généralement pas besoin d'allouer ou de libérer de mémoire pour eux.

Les propriétés d'affichage (Display), de drawable (Drawable), de palette de couleurs (Colormap) et de visuel (Visual) d'un XftDraw peuvent être interrogées avec XftDrawDisplay(), XftDrawDrawable(), XftDrawColormap(), et XftDrawVisual(), respectivement.

Plusieurs fonctions utilisent des objets XftDraw : XftDrawCharFontSpec(), XftDrawCharSpec(), XftDrawGlyphFontSpec(), XftDrawGlyphSpec(), XftDrawGlyphs(), XftDrawRect(), XftDrawSetClip(), XftDrawSetClipRectangles(), XftDrawSetSubwindowMode(), et la famille XftDrawString*().

L'extension X Rendering Picture associée à un XftDraw est retournée par XftDrawPicture(), et XftDrawSrcPicture(). Elle est utilisée par XftCharFontSpecRender(), XftCharSpecRender(), XftGlyphFontSpecRender(), XftGlyphRender(), XftGlyphSpecRender(), et la famille XftTextRender*().

FONCTIONS

Initialisation

Une application typique utilisant Xft n'initialise pas explicitement la bibliothèque. Cela se fait généralement par effet de bord lors de l'ouverture d'une police.

Lorsque Xft s'initialise, il collecte des informations sur l'affichage, et stocke certaines de ces informations dans un modèle Fontconfig (essentiellement une collection de propriétés avec des valeurs typées). L'application appelante peut modifier ce modèle pour changer le comportement de la bibliothèque.

Toutes les informations collectées ne sont pas stockées dans un modèle. Le reste est stocké dans des structures de données internes. Xft rend certaines de ces informations disponibles à l'application via des fonctions.

Bool XftDefaultHasRender (
	Display	*dpy);

Obtient des informations sur l'affichage dpy si ce n'est pas déjà fait, et retourne vrai si Xft a constaté que l'affichage prend en charge l'extension X Render, et s'il est capable de trouver un XRenderPictFormat approprié (le type de données de X Render qui est analogue au Visual de Xlib) sur l'affichage.

Bool XftDefaultSet (
	Display	*dpy,
	FcPattern	*defaults);

Obtient des informations sur l'affichage dpy si ce n'est pas déjà fait, et définit le modèle Fontconfig contenant les propriétés par défaut que Xft utilisera pour cet affichage.

Xft utilise ces propriétés initialement pour obtenir ces limites :
XFT_MAX_GLYPH_MEMORY
(maxglyphmemory). C'est la quantité maximale de mémoire de glyphes pour toutes les polices utilisées par Xft (par défaut : 4*1024*1024).
XFT_MAX_UNREF_FONTS
(maxunreffonts). C'est le nombre maximum de polices non référencées (par défaut : 16).
XFT_TRACK_MEM_USAGE
(trackmemusage). Lorsque vrai, Xft suit l'utilisation de la mémoire des glyphes pour améliorer les performances lors de la décision de quels glyphes décharger lorsque la quantité maximale de mémoire de glyphes est atteinte (par défaut : faux).
Xft utilise également ces propriétés par défaut dans XftDefaultSubstitute().
void XftDefaultSubstitute (
	Display	*dpy,
	int	 screen,
	FcPattern	*pattern);

Xft remplit les propriétés manquantes dans le pattern donné en utilisant les propriétés par défaut pour l'affichage spécifié dpy, par exemple telles que définies dans XftDefaultSet().

Les applications Xft typiques utilisent cette fonction pour aider Fontconfig à choisir une police appropriée. Ces propriétés sont substituées avant d'appeler FcDefaultSubstitute() :
FC_ANTIALIAS
Vrai si FreeType doit utiliser l'anti-aliasing (par défaut : Faux). (par défaut : Vrai).
FC_AUTOHINT
Vrai si FreeType doit utiliser l'autohinting (par défaut : Faux).
FC_DPI
Points/pouce utilisés pour la résolution (par défaut : calculé à partir de la hauteur de l'affichage).
FC_EMBOLDEN
Vrai si FT_GlyphSlot_Embolden() doit être utilisé pour renforcer une police (par défaut : Faux).
FC_HINTING
Vrai si l'hinting doit être utilisé lors du remplissage des propriétés pour ouvrir une police (par défaut : Vrai).
FC_HINT_STYLE
Style d'hinting utilisé lors du remplissage des propriétés pour ouvrir une police (par défaut : FC_HINT_FULL).
FC_LCD_FILTER
Paramètre passé à FT_Library_SetLcdFilter() lors du chargement des glyphes (par défaut : FC_LCD_DEFAULT).
FC_MINSPACE
Valeur d'espace minimale utilisée lors du remplissage des propriétés pour ouvrir une police (par défaut : Faux).
FC_RGBA
Valeur RGBA utilisée lors du remplissage des propriétés pour ouvrir une police (par défaut : calculée en appelant XRenderQuerySubpixelOrder()).
FC_SCALE
Échelle utilisée dans Fontconfig (par défaut : 1.0).
XFT_MAX_GLYPH_MEMORY
Mémoire maximale pour une police (par défaut : 1024*1024).
XFT_RENDER
Vrai si l'affichage prend en charge l'extension X Render (par défaut : résultat de XftDefaultHasRender()).
FcBool XftInit (
	_Xconst char	*config);

Initialise la bibliothèque Fontconfig (en appelant FcInit()).

Le paramètre config n'est pas utilisé.

Ouverture et Correspondance des Polices



  
XftFont *XftFontOpen (

  

    
	Display	*dpy,
	int	 screen,
	...);


    
XftFontOpen prend une liste de triplets d'éléments de
        modèle de la forme champ, type, valeur (terminée
        par un NULL), fait correspondre ce modèle aux polices disponibles, et
        ouvre la police correspondante, en la dimensionnant correctement pour
        l'écran numéro screen sur l'affichage dpy. Retourne la
        police correspondante, ou NULL si aucune correspondance n'est trouvée.

  




Exemple :
  




    font = XftFontOpen (dpy, screen,
                        XFT_FAMILY, XftTypeString, "charter",
                        XFT_SIZE, XftTypeDouble, 12.0,
                        NULL);




  

  
Ceci ouvre la police “charter” à 12 points. La taille en
      points est automatiquement convertie en la taille correcte en pixels en
      fonction de la résolution du moniteur.

Gestion   des XftColor



  
Bool XftColorAllocName (

  

    
	Display	*dpy,
	_Xconst Visual	*visual,
	Colormap	 cmap,
	_Xconst char	*name,
	XftColor	*result);


    
Utilise XAllocNamedColor() pour rechercher la couleur nommée
        name pour l'écran associé à la carte de couleurs cmap.

  






    
  
  • Si XAllocNamedColor() retourne une valeur non nulle,
      XftColorAllocName() remplit le champ pixel XftColor résultant
      avec la couleur la plus proche supportée par l'écran, ainsi que les champs
      rouge, vert et bleu exacts de la base de données, et retourne True.
    • 
  
  • Si XAllocNamedColor() retourne zéro, XftColorAllocName()
      retourne False et ne met pas à jour le XftColor référencé par
      result.
    • 






  

  
Le paramètre visual n'est pas utilisé.





  
Bool XftColorAllocValue (

  

    
	Display	*dpy,
	Visual	*visual,
	Colormap	 cmap,
	_Xconst XRenderColor	*color,
	XftColor	*result);


    
Alloue une valeur de couleur :

  






    
  
  • Si la classe visual est TrueColor, XftColorAllocValue()
      définit le champ pixel dans le XftColor référencé par
      result en utilisant les champs rouge, vert et bleu du paramètre
      color.
    • 
  
  • Si la classe visual n'est pas TrueColor, XftColorAllocValue()
      appelle XAllocColor() pour allouer une entrée dans la carte de
      couleurs cmap. qui retourne la valeur pixel de la couleur la plus
      proche des éléments RVB spécifiés supportés par le matériel.
    • 




  

  
Si XAllocColor() réussit, XftColorAllocValue() stocke cette
      valeur pixel dans le XRenderColor référencé par result et
      retourne True.

  

  
Si XAllocColor() échoue, XftColorAllocValue() retourne False
      et ne modifie pas le résultat.

Dessine une liste de glyphes associés à des polices à des
        coordonnées spécifiées, passés sous forme de tableau de structures
        XftGlyphFontSpec de taille len via le paramètre
        glyphs. Tous les glyphes sont dessinés en utilisant la couleur
        spécifiée dans le paramètre color.

  





  

  
Pour chaque entrée dans le tableau glyphs :






    
  
  • Si la police associée utilise l'extension X Render, alors Xft utilise
      XftGlyphFontSpecRender() pour dessiner le glyphe, en utilisant une
      Picture obtenue en appelant XftDrawSrcPicture () avec les
      paramètres draw et color.
    •

    • 






  
void XftGlyphFontSpecRender (

  

    
	Display	*dpy,
	int	 op,
	Picture	 src,
	Picture	 dst,
	int	 srcx,
	int	 srcy,
	_Xconst XftGlyphFontSpec	*glyphs,
	int	 nglyphs);


    
Cela implique plusieurs étapes :

  






    
  
  • D'abord, Xft s'assure que le tableau glyphs est complet en
      utilisant XftFontCheckGlyph() et en chargeant les glyphes manquants
      avec XftFontLoadGlyphs().
    • 
  
  • Ensuite, Xft examine les glyphes pour trouver la valeur Unicode
      maximale. Cela détermine la taille de l'encodage, c'est-à-dire la
      largeur.
    • 
  
  • Ensuite, pour chaque glyphe, Xft vérifie si sa valeur Unicode est
      prise en charge par la police correspondante. Sinon, la valeur est définie
      à zéro (0), pour l'ignorer. Pendant ce processus, Xft se souvient
      également de la première police utilisée et calcule la position à laquelle
      chaque glyphe sera dessiné.
    • 
  
  • Xft construit ensuite un tableau équivalent de glyphes dans le format
      attendu par la bibliothèque X Render.
    • 
  
  • Enfin, XftGlyphFontSpecRender() utilise l'extension X Render pour
      dessiner les glyphes, avec la fonction appropriée XRenderCompositeText*()
      selon la largeur, et rejette les données temporaires.
    • 




  

  
Les paramètres op, dst, src, srcx et
      srcy sont utilisés comme décrit dans la documentation de la
      bibliothèque X Render.

DESCRIPTION


The Xft library is a library for rendering fonts using the FreeType
    library and the X Rendering Extension. It provides a flexible and efficient
    way to display text in X applications.




Font   management



  
XftFontInfoCreate()

  
Creates an XftFontInfo structure, which is used to manage font resources
      for a display. The structure is initialized using the Fontconfig pattern
      pat.

  
XftFontInfoDestroy()

  
Destroys the XftFontInfo structure and frees all associated resources.

  
XftFontInfoOpen()

  
Opens a font based on the Fontconfig pattern pat for the display
      dpy. It returns an XftFontInfo structure containing the font
      information.

  
XftFontInfoMatch()

  
Matches a fontconfig pattern pat against the available fonts on
      display dpy, returning the best matching pattern. This is useful
      for querying available fonts without actually opening them.

  
XftFontInfoGetFont()

  
Retrieves the XftFont structure from an XftFontInfo structure. The
      XftFont structure contains the actual font data and metrics.

  
XftFontOpenName()

  
Opens a font by its name (a string suitable for Fontconfig parsing) for
      the display dpy. Returns an XftFont structure.

  
XftFontOpenPattern()

  
Opens a font based on a Fontconfig pattern pat for the display
      dpy. Returns an XftFont structure.

  
XftFontOpenXlfd()

  
Opens a font using an XLFD (X Logical Font Description) string xlfd
      for the display dpy. Returns an XftFont structure.

  
XftFontClose()

  
Closes a font previously opened with one of the XftFontOpen* functions.
      This frees the font resources associated with the XftFont structure.






Character   and glyph handling



  
XftCharIndex()

  
Returns the glyph index for a character in the given font. The text
      parameter is a pointer to the character to be converted. If the character
      is not found in the font, it returns 0.

  
XftCharValue()

  
Returns the value associated with a character uc in the font
      font. The value is stored in the FcValue structure pointed to by
      val. Returns FcTrue if the value is found,
      FcFalse otherwise.

  
XftCharExists()

  
Checks if a character uc exists in the font font. Returns
      FcTrue if the character exists, FcFalse otherwise.

  
XftGlyphFontInfo()

  
Returns a pointer to an XftGlyphFontInfo structure for the given character
      uc in the font font. This structure contains information
      about the glyph, including its metrics and bitmap.

  
XftGlyphExtents()

  
Calculates the bounding box extents of a glyph. The gfx parameter
      is a pointer to an XftGlyphFontInfo structure obtained from
      XftGlyphFontInfo(). The extents are stored in the XGlyphInfo
      structure pointed to by extents.

  
XftGlyphExtentsUtf16()

  
Calculates the bounding box extents of a sequence of UTF16-encoded
      characters. The text parameter points to the UTF16 character
      data, len is the number of characters, and extents is
      where the results are stored.

  
XftTextExtents8()

  
Calculates the bounding box extents of a string of 8-bit characters. The
      text parameter points to the string, len is the length of
      the string, and extents is where the results are stored.

  
XftTextExtents16()

  
Calculates the bounding box extents of a string of 16-bit characters. The
      text parameter points to the string, len is the length of
      the string, and extents is where the results are stored.

  
XftTextExtentsUtf8()

  
Calculates the bounding box extents of a string of UTF-8 encoded
      characters. The text parameter points to the string, len is
      the length of the string, and extents is where the results are
      stored.

  
XftTextExtentsDraw()

  
Calculates the bounding box extents of a string of 8-bit characters, taking
      into account the drawing context draw. The text parameter
      points to the string, len is the length of the string, and
      extents is where the results are stored.

  
XftTextExtentsDrawUtf16()

  
Calculates the bounding box extents of a string of UTF16-encoded characters,
      taking into account the drawing context draw. The text
      parameter points to the UTF16 character data, len is the number of
      characters, and extents is where the results are stored.

  
XftTextExtentsDrawUtf8()

  
Calculates the bounding box extents of a string of UTF-8 encoded characters,
      taking into account the drawing context draw. The text
      parameter points to the string, len is the length of the string,
      and extents is where the results are stored.

  
XftDrawString8()

  
Draws a string of 8-bit characters using the specified color, font, and
      coordinates.

  
XftDrawString16()

  
Draws a string of 16-bit characters using the specified color, font, and
      coordinates.

  
XftDrawStringUtf8()

  
Draws a string of UTF-8 encoded characters using the specified color, font,
      and coordinates.






Name   parsing



  
XftNameParse()

  

    
	FcPattern	*name);


    
Uses Fontconfig to parse the font name string name.
        It returns a pointer to a Fontconfig pattern structure representing the
        parsed name. This pattern can then be used with functions like
        XftFontOpenPattern().

  

  
XftNameUnparse()

  

    
	FcPattern	*pat,
	char	*dest,
	int	 len);


    
This function is the inverse of XftNameParse(). It takes
        a Fontconfig pattern pat and converts it back into a human-readable
        font name string. The resulting string is stored in the buffer pointed
        to by dest, with a maximum size of len bytes. It returns
        FcTrue if the conversion was successful and the string fits within
        the buffer, and FcFalse otherwise.

  










Manipulating   Font data



  
XftFontLoadGlyphs()

  

    
	Display	*dpy,
	XftFont	*pub,
	FcBool	 need_bitmaps,
	_Xconst FT_UInt	*glyphs,
	int	 nglyph);


    
Using FT_Load_Glyph(), load nglyphs for the
        glyph indices (Unicode values) listed in the array glyphs from
        the given font pub.

  





  

  
Loading a glyph entails more than just reading data into memory.
      Xft uses the Fontconfig pattern associated with the display
      dpy (e.g., via XftDefaultSet()) to determine whether to use
      a bounding box, clip the glyphs into those bounds, scale the glyphs,
      compute font metrics, and add it to the X Render extension using
      XRenderAddGlyphs().





  
XftFontUnloadGlyphs()

  

    
	Display	*dpy,
	XftFont	*pub,
	_Xconst FT_UInt	*glyphs,
	int	 nglyph);


    
Discards data for up to nglyph glyphs whose glyph
        indices (Unicode values) are listed in the array glyphs for the
        given font pub. If the glyphs were added to the X Render
        extension, Xft removes those using XRenderFreeGlyphs().
        Xft keeps track of the amount of memory used for glyphs, and
        updates the usage associated with the display dpy.

  

  
XftLockFace()

  

    
	XftFont	*pub);


    
If no FreeType 2 “face” (in-memory
        representation of a given typeface in a given style) has been created
        for the pub font, create one using FT_New_Face().
        Face-locks are a reference count used by Xft to ensure that only
        one face is created, and that it is retained until the font is no longer
        used.

  





  

  
Face-locking is used directly in XftCharIndex() and
      XftFontLoadGlyphs(), which in turn are used in many functions of
      Xft.

  

  
Face-locking was introduced in version 1 (October 2002). A few
      applications, such as Gdk/Gimp relied upon these functions. In version
      2.1.9 (June 2006), face-locking was retained as part of the public API
      when improved shared-library configurations provided for hiding private
      symbols.





  
XftUnlockFace()

  

    
	XftFont	*pub);


    
Decrements the reference count for the FreeType 2
        “face” associated with the font.

  





  

  
FT_Face objects are deallocated using FT_Done_Face().
      Xft does this in XftFontInfoDestroy() and when cleaning up
      on failure in XftFontInfoCreate() and
    XftFontOpenPattern().










DEBUGGING


Xft reads the environment variable XFT_DEBUG and
    converts that to an integer. Each bit in the resulting value tells
    Xft to print debugging information to the standard output:



  
1

  
font-opening

  
2

  
additional font-matching and opening (verbose)

  
4

  
shows details about the XRenderPictFormat which will be used.

  
8

  
shows the string which XftDrawString8() will draw.

  
16

  
shows which font-ids are matched.

  
32

  
shows useful information about the glyphs which will be drawn

  
64

  
shows an ASCII-art representation of the glyphs.

  
128

  
shows details about the memory-cache management

  
256

  
shows details about managing glyph cached-memory

  
512

  
shows a report on memory-usage

  
1024

  
shows details on extended management of glyph cached-memory








COMPATIBILITY


As of version 2 (May 2002), Xft became relatively stable.
    It is expected to retain source and binary compatibility in future
  releases.


Xft provides a compatibility interface to its previous
    major version, Xft 1.x, described below.




Xft   1.x Header File


#include <X11/Xft/XftCompat.h>






Xft   1.x Data Types



  
XftPattern

  
holds a set of names with associated value lists; each name refers to a
      property of a font. XftPatterns are used as inputs to the matching
      code as well as holding information about specific fonts.

  
XftFontSet

  
contains a list of XftPatterns. Internally, Xft uses this
      data structure to hold sets of fonts. Externally, Xft returns the
      results of listing fonts in this format.

  
XftObjectSet

  
holds a set of names and is used to specify which fields from fonts are
      placed in the list of returned patterns when listing fonts.
