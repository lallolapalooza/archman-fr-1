NOM

Xft - Bibliothèque d'interface X FreeType

SYNTAXE

#include <X11/Xft/Xft.h>

DESCRIPTION

Xft est une bibliothèque simple qui dessine du texte et des graphiques :

  • en utilisant les informations fournies par la bibliothèque Fontconfig,
  • Xft convertit les glyphes de polices en utilisant le rasteriseur FreeType, et
  • affiche les données de polices converties en utilisant l'extension X Rendering Extension.

Cette page de manuel ne fait qu'effleurer la surface de cette bibliothèque.

CONSTANTES

XFT_MAJOR
est le numéro de version majeure de Xft.
XFT_MINOR
est le numéro de version mineure de Xft.
XFT_REVISION
est le numéro de révision de Xft.
XFT_VERSION
est XFT_MAJOR multiplié par 10000 (dix mille), plus XFT_MINOR multiplié par 100, plus XFT_REVISION.
XftVersion
est un alias pour XFT_VERSION.

L'exemple suivant illustre comment les constantes de version de Xft pourraient être utilisées : 

    #if (XFT_VERSION >= 20107)
    (void) puts("Version 2.1.7 ou ultérieure de la bibliothèque Xft est en"
                " cours d'utilisation.");
    #else
    (void) printf("Version insuffisante de Xft (%d.%d.%d) installée ;
                  " besoin d'au moins la version 2.1.7.\n", XFT_MAJOR,
                  XFT_MINOR,
                  XFT_REVISION);
    #endif

TYPES DE DONNÉES

Les types de données Xft suivent une convention de nommage, préfixant tous les noms avec « Xft »

De Xlib...

Les types de données Xlib ne suivent pas de convention de nommage. Ils sont documentés dans Xlib - Interface du langage C.

Xft utilise ces noms : Bool, Colormap, Display, Drawable, Pixmap, Region, Visual, et XRectangle.

Certains types de données sont particulièrement pertinents pour Xft :

Drawable
Déclaré dans <X11/X.h>, il s'agit d'un identifiant de ressource X, par exemple, une fenêtre associée à un affichage. Les fenêtres et les pixmaps peuvent être utilisés comme sources et destinations dans les opérations graphiques. Ces fenêtres et pixmaps sont collectivement appelés drawables. Cependant, une fenêtre InputOnly ne peut pas être utilisée comme source ou destination dans une opération graphique.
Region
Déclaré dans <X11/Xutil.h> et <X11/Xregion.h>, une Region est un ensemble arbitraire d'emplacements de pixels que Xlib peut manipuler. Internelement, une Region est représentée par l'union d'un nombre arbitraire de rectangles. Xlib maintient un rectangle qui indique l'étendue de cette union.
Visual
Déclaré dans <X11/Xutil.h>, cette structure contient des informations sur la cartographie des couleurs possibles.

De XRender...

Les types de données de la bibliothèque X Render Extension sont inspirés de Xlib, mais manquent de la documentation correspondante. Référez-vous au fichier d'en-tête pour plus de détails :

<X11/extensions/Xrender.h>

ou lisez le code source (qui fournit un aperçu de libXrender).

Xft utilise ces noms : Picture, XGlyphInfo, XRenderColor.

De Fontconfig...

Les types de données Fontconfig suivent une convention de nommage, préfixant tous les noms avec « Fc », qui sont documentés dans Fontconfig Developers Reference.

Xft utilise ces noms Fontconfig : FcBool, FcChar8, FcChar16, FcChar32, FcCharSet, FcEndian, FcFontSet, FcPattern, et FcResult.

De FreeType 2...

Les types de données FreeType 2 suivent une convention de nommage, préfixant tous les noms avec « FT_ », qui sont documentés dans FreeType API Reference.

Xft utilise ces noms : FT_Face, FT_Library, et FT_UInt.

FreeType 2 utilise FT_UInt (un entier non signé) pour représenter des glyphes.

XftFont


typedef struct _XftFont {
	int	 ascent;
	int	 descent;
	int	 height;
	int	 max_advance_width;
	FcCharSet	*charset;
	FcPattern	*pattern;
} XftFont;

Un XftFont est la structure de données principale qui intéresse les programmeurs utilisant Xft ; il contient des métriques générales de police et des pointeurs vers l'ensemble de caractères Fontconfig et le motif associés à la police.

Les XftFonts sont remplis par l'une des fonctions XftFontOpen(), XftFontOpenName(), XftFontOpenXlfd(), XftFontOpenInfo(), ou XftFontOpenPattern(). XftFontCopy() est utilisé pour dupliquer les XftFonts, et XftFontClose() est utilisé pour marquer un XftFont comme non utilisé. Les XftFonts sont alloués en interne, comptés par référence et libérés par Xft ; le programmeur n'a généralement pas besoin d'allouer ou de libérer de la mémoire pour eux.

XftDrawGlyphs(), la famille de fonctions XftDrawString*(), XftDrawCharSpec(), et XftDrawGlyphSpec() utilisent les XftFonts pour rendre du texte à un objet XftDraw, qui peut correspondre soit à un drawable X de base, soit à un drawable de l'extension X Rendering Extension.

XftGlyphExtents() et la famille de fonctions XftTextExtents*() sont utilisées pour déterminer les étendues (dimensions maximales) d'un XftFont.

La couverture des glyphes ou des caractères d'un XftFont peut être déterminée avec XftFontCheckGlyph() ou XftCharExists(). XftCharIndex() retourne l'index de caractère spécifique à XftFont correspondant à un point de code Unicode donné.

XftGlyphRender(), XftGlyphSpecRender(), XftCharSpecRender(), et la famille de fonctions XftTextRender*() utilisent les XftFonts pour dessiner dans des structures Picture de l'extension X Rendering Extension.

Remarque : XftDrawGlyphs(), la famille de fonctions XftDrawString*(), XftDrawCharSpec(), et XftDrawGlyphSpec() fournissent un moyen de rendre les polices qui est indépendant de la disponibilité de l'extension X Rendering Extension sur le serveur X.

XftFontInfo

est un objet opaque qui stocke des informations sur une police. Les structures XftFontInfo sont créées avec XftFontInfoCreate(), libérées avec XftFontInfoDestroy(), et comparées avec XftFontInfoEqual(). Les objets XftFontInfo sont alloués et libérés en interne par Xft ; le programmeur n'a généralement pas besoin d'allouer ou de libérer de la mémoire pour eux.

Chaque structure XftFontInfo en cours d'utilisation est associée à un identifiant unique, qui peut être récupéré avec XftFontInfoHash(). Un XftFont peut être ouvert sur la base des données de XftFontInfo avec XftFontOpenInfo().

XftColor


typedef struct _XftColor {
	unsigned long	 pixel;
	XRenderColor	 color;
} XftColor;

Un objet XftColor permet au texte et à d'autres éléments d'être rendus dans une couleur particulière (ou la meilleure approximation offerte par le visual X utilisé).

XftColorAllocName() et XftColorAllocValue() demandent une allocation de couleur au serveur X (si nécessaire) et initialisent les membres de XftColor. XftColorFree() demande au serveur X de libérer la couleur actuellement allouée pour un XftColor.

Une fois qu'un XftColor a été initialisé, XftDrawSrcPicture(), XftDrawGlyphs(), la famille de fonctions XftDrawString*(), XftDrawCharSpec(), XftDrawCharFontSpec(), XftDrawGlyphSpec(), XftDrawGlyphFontSpec(), et XftDrawRect() peuvent être utilisés pour dessiner divers objets en utili

ing it.

XftDraw

est un objet opaque qui contient les informations utilisées pour le rendu vers un objet graphique X en utilisant soit le protocole principal, soit l'extension X Rendering.

Les objets XftDraw sont créés avec XftDrawCreate() (qui associe un XftDraw à un objet graphique X existant), XftDrawCreateBitmap(), ou XftDrawCreateAlpha(), et détruits avec XftDrawDestroy(). L'objet graphique X associé à un XftDraw peut être modifié avec XftDrawChange(). Les objets XftDraw sont alloués et libérés en interne par Xft ; le programmeur n'a pas besoin d'allouer ou de libérer de mémoire pour eux en temps normal.

Les propriétés Display, Drawable, Colormap et Visual d'un XftDraw peuvent être interrogées avec XftDrawDisplay(), XftDrawDrawable(), XftDrawColormap(), et XftDrawVisual(), respectivement.

Plusieurs fonctions utilisent des objets XftDraw : XftDrawCharFontSpec(), XftDrawCharSpec(), XftDrawGlyphFontSpec(), XftDrawGlyphSpec(), XftDrawGlyphs(), XftDrawRect(), XftDrawSetClip(), XftDrawSetClipRectangles(), XftDrawSetSubwindowMode(), et la famille XftDrawString*().

L'extension X Rendering Picture associée à un XftDraw est retournée par XftDrawPicture() et XftDrawSrcPicture(). Elle est utilisée par XftCharFontSpecRender(), XftCharSpecRender(), XftGlyphFontSpecRender(), XftGlyphRender(), XftGlyphSpecRender(), et la famille XftTextRender*().

FONCTIONS

Initialisation

Une application typique utilisant Xft n'initialise pas explicitement la bibliothèque. Ceci est généralement fait comme effet secondaire de l'ouverture d'une police.

Lors de l'initialisation de Xft, il collecte des informations sur l'écran et stocke certaines de ces informations dans un modèle Fontconfig (essentiellement une collection de propriétés avec des valeurs typées). L'application appelante peut modifier ce modèle pour changer le comportement de la bibliothèque.

Toutes les informations collectées ne sont pas stockées dans un modèle. Le reste est stocké dans des structures de données internes. Xft rend certaines de ces informations disponibles à l'application via des fonctions.

Bool XftDefaultHasRender (
	Display	*dpy);

Obtient des informations sur l'écran dpy si ce n'est pas déjà fait, et retourne vrai si Xft a déterminé que l'écran prend en charge l'extension X Render, et s'il est capable de trouver un XRenderPictFormat approprié (le type de données de X Render qui est analogue au Visual de Xlib) sur l'écran.

Bool XftDefaultSet (
	Display	*dpy,
	FcPattern	*defaults);

Obtient des informations sur l'écran dpy si ce n'est pas déjà fait, et définit le modèle Fontconfig contenant les propriétés par défaut que Xft utilisera pour cet écran.

Xft utilise ces propriétés initialement pour obtenir les limites suivantes :
XFT_MAX_GLYPH_MEMORY
(maxglyphmemory). C'est la quantité maximale de mémoire de glyphes pour toutes les polices utilisées par Xft (par défaut : 4*1024*1024).
XFT_MAX_UNREF_FONTS
(maxunreffonts). C'est le nombre maximum de polices non référencées (par défaut : 16).
XFT_TRACK_MEM_USAGE
(trackmemusage). Lorsque vrai, Xft suit l'utilisation de la mémoire des glyphes pour améliorer les performances lors de la décision de ce qu'il faut décharger lorsque la quantité maximale de mémoire des glyphes est atteinte (par défaut : faux).
Xft utilise également ces propriétés par défaut dans XftDefaultSubstitute().
void XftDefaultSubstitute (
	Display	*dpy,
	int	 screen,
	FcPattern	*pattern);

Xft remplit les propriétés manquantes dans le pattern donné en utilisant les propriétés par défaut pour l'écran spécifié dpy, par exemple, tel que défini dans XftDefaultSet().

Les applications Xft typiques utilisent cette fonction pour aider Fontconfig à choisir une police appropriée. Ces propriétés sont substituées avant d'appeler FcDefaultSubstitute():
FC_ANTIALIAS
Vrai si FreeType doit utiliser l'anti-aliasing (par défaut : Faux). (par défaut : Vrai).
FC_AUTOHINT
Vrai si FreeType doit utiliser l'auto-hinting (par défaut : Faux).
FC_DPI
Points/pouce utilisés pour la résolution (par défaut : calculé à partir de la hauteur de l'écran).
FC_EMBOLDEN
Vrai si FT_GlyphSlot_Embolden() doit être utilisé pour épaissir une police (par défaut : Faux).
FC_HINTING
Vrai si l'hinting doit être utilisé lors du remplissage des propriétés pour ouvrir une police (par défaut : Vrai).
FC_HINT_STYLE
Style d'hinting utilisé lors du remplissage des propriétés pour ouvrir une police (par défaut : FC_HINT_FULL).
FC_LCD_FILTER
Paramètre passé à FT_Library_SetLcdFilter() lors du chargement de glyphes (par défaut : FC_LCD_DEFAULT).
FC_MINSPACE
Espace minimum utilisé lors du remplissage des propriétés pour ouvrir une police (par défaut : Faux).
FC_RGBA
Valeur RGBA utilisée lors du remplissage des propriétés pour ouvrir une police (par défaut : calculée en appelant XRenderQuerySubpixelOrder()).
FC_SCALE
Échelle utilisée dans Fontconfig (par défaut : 1.0).
XFT_MAX_GLYPH_MEMORY
Mémoire maximale pour une seule police (par défaut : 1024*1024).
XFT_RENDER
Vrai si l'écran prend en charge l'extension X Render (par défaut : résultat de XftDefaultHasRender()).
FcBool XftInit (
	_Xconst char	*config);

Initialise la bibliothèque Fontconfig (appelant FcInit()).

Le paramètre config n'est pas utilisé.
Xft ne désinitialise pas la bibliothèque Fontconfig lorsqu'elle a terminé.

Initialise la bibliothèque FreeType (appelant
        FT_Init_FreeType() pour créer un objet bibliothèque) si elle n'a pas déjà été initialisée. Ceci est nécessaire avant d'utiliser la bibliothèque FreeType pour lire les données de police à partir d'un fichier.

      XftFontInfoCreate() et XftFontOpenPattern().

      FT_Done_FreeType()) lorsqu'il a terminé.

Ouverture   et Correspondance des Polices



  
XftFont *XftFontOpen (

  

    
	Display	*dpy,
	int	 screen,
	...);


    
XftFontOpen prend une liste de triplets d'éléments de modèle de la forme champ, type, valeur (terminée par NULL), fait correspondre ce modèle aux polices disponibles, et ouvre la police correspondante, en la dimensionnant correctement pour l'écran numéro screen sur l'écran dpy. Retourne la police correspondante, ou NULL si aucune correspondance n'est trouvée.

  




Exemple :
  




    font = XftFontOpen (dpy, screen,
                        XFT_FAMILY, XftTypeString, "charter",
                        XFT_SIZE, XftTypeDouble, 12.0,
                        NULL);




  

  
Ceci ouvre la police “charter” à 12 points. La taille en points est automatiquement convertie en la taille en pixels correcte en fonction de la résolution du moniteur.

Gestion   des XftColor



  
Bool XftColorAllocName (

  

    
	Display	*dpy,
	_Xconst Visual	*visual,
	Colormap	 cmap,
	_Xconst char	*name,
	XftColor	*result);


    
Utilise XAllocNamedColor() pour rechercher la couleur nommée
        name pour l'écran associé à la carte de couleurs cmap.

  






    
  
  • Si XAllocNamedColor() retourne une valeur non nulle,
      XftColorAllocName() remplit le champ pixel du XftColor
      résultant avec la couleur la plus proche prise en charge par l'écran, ainsi
      que les champs rouge, vert et bleu exacts de la base de données, et retourne
      True.
    • 
  
  • Si XAllocNamedColor() retourne zéro, XftColorAllocName()
      retourne False et ne met pas à jour le XftColor référencé par
      result.
    • 






  

  
Le paramètre visual n'est pas utilisé.





  
Bool XftColorAllocValue (

  

    
	Display	*dpy,
	Visual	*visual,
	Colormap	 cmap,
	_Xconst XRenderColor	*color,
	XftColor	*result);


    
Alloue une valeur de couleur :

  






    
  
  • Si la classe visual est TrueColor, XftColorAllocValue()
      définit le champ pixel dans le XftColor référencé par
      result en utilisant les champs rouge, vert et bleu du paramètre
      color.
    • 
  
  • Si la classe visual n'est pas TrueColor, XftColorAllocValue()
      appelle XAllocColor() pour allouer une entrée dans la carte de couleurs
      cmap. qui retourne la valeur pixel de la couleur la plus proche des
      éléments RVB spécifiés pris en charge par le matériel.
    • 




  

  
Si XAllocColor() réussit, XftColorAllocValue() stocke cette
      valeur pixel dans le XRenderColor référencé par result et
      retourne True.

  

  
Si XAllocColor() échoue, XftColorAllocValue() retourne False
      et ne modifie pas le résultat.

Bool XftDrawSetClip (

Configure le découpage pour le paramètre XftDraw donné
        draw en commençant par une Region :

      nécessaire, ou si l'opération a réussi. Il renvoie False s'il n'a

	XftDraw	*draw,
	int	 mode);


    
Définit le mode sous-fenêtre pour le paramètre XftDraw
        donné draw. Le mode peut être soit ClipByChildren (par

      XRenderChangePicture().

void XftDrawGlyphFontSpec (

  

    
	XftDraw	*draw,
	_Xconst XftColor	*color,
	_Xconst XftGlyphFontSpec	*glyphs,
	int	 len);


    
Dessine une liste de glyphes associés à des polices à des
        coordonnées spécifiées, passée sous forme d'un tableau de structures
        XftGlyphFontSpec de taille len via le paramètre
        glyphs. Tous les glyphes sont dessinés en utilisant la couleur
        spécifiée dans le paramètre color.

  





  

  
Pour chaque entrée du tableau glyphs :






    
  
  • Si la police associée utilise l'extension X Render, alors Xft utilise
      XftGlyphFontSpecRender() pour dessiner le glyphe, en utilisant une
      Picture obtenue en appelant XftDrawSrcPicture() avec les
      paramètres draw et color.
    • 
  
  • Sinon, Xft fournit une fonctionnalité analogue en utilisant Xlib.
    • 






  
void XftGlyphFontSpecRender (

  

    
	Display	*dpy,
	int	 op,
	Picture	 src,
	Picture	 dst,
	int	 srcx,
	int	 srcy,
	_Xconst XftGlyphFontSpec	*glyphs,
	int	 nglyphs);


    
Cela implique plusieurs étapes :

  






    
  
  • Premièrement, Xft s'assure que le tableau glyphs est complet
      en utilisant XftFontCheckGlyph() et en chargeant les glyphes
      manquants avec XftFontLoadGlyphs().
    • 
  
  • Ensuite, Xft examine les glyphes pour trouver la valeur Unicode
      maximale. Cela détermine la taille de l'encodage, c'est-à-dire la
      width.
    • 
  
  • Ensuite, pour chaque glyphe, Xft vérifie si sa valeur Unicode est
      prise en charge par la police correspondante. Sinon, la valeur est mise à
      zéro (0), pour l'ignorer. Tout en faisant cela, Xft se souvient
      également de la première police utilisée et calcule la position à laquelle
      chaque glyphe sera dessiné.
    • 
  
  • Xft construit ensuite un tableau de glyphes équivalent dans le format
      attendu par la bibliothèque X Render.
    • 
  
  • Enfin, XftGlyphFontSpecRender() utilise l'extension X Render pour
      dessiner les glyphes, avec la fonction XRenderCompositeText*()
      appropriée selon la width, et élimine les données temporaires.
    • 




  

  
Les paramètres op, dst, src, srcx, et
      srcy sont utilisés comme décrit dans la documentation de la
      bibliothèque X Render.

NAME


Xft, XftDefaultSubstitute, XftFontOpen, XftFontOpenInfo, XftFontOpenPattern, XftFontClose, XftFontNumGlyphs, XftCharIndex, XftCharPrev, XftCharNext, XftGlyphIndex, XftGlyphExtents, XftGlyphFontSpec, XftGlyphSpec, XftGlyphExtents16, XftGlyphExtents32, XftDrawCreate, XftDrawChange, XftDrawDestroy, XftDrawSetClipRects, XftDrawSetClipRegion, XftDrawRectangle, XftDrawTextOutline, XftDrawString8, XftDrawString16, XftDrawString32, XftNameParse, XftNameUnparse, XftFontLoadGlyphs, XftFontUnloadGlyphs, XftLockFace, XftUnlockFace — Xft font library






SYNOPSIS


#include <X11/Xft/Xft.h>







DESCRIPTION


The Xft library is a library for rendering fonts using the FreeType
    library and the X Render extension. It provides functions for opening fonts,
    fetching glyphs, and drawing text. Xft uses Fontconfig for font
    matching.




Opening Fonts



  
FcPattern * XftFontOpen (

  

    
	Display	*dpy,
	FcPattern	*pat);


    
Opens a font matching the pattern pat for the display
        dpy. Fontconfig is used to match the pattern, and FreeType is
        used to load the font. The returned FcPattern
        contains information about the opened font, including the font structure
        itself.

  

  
XftFont * XftFontOpenInfo (

  

    
	Display	*dpy,
	FcPattern	*pat,
	XftFont	*info);


    
Similar to XftFontOpen, but takes an
        optional XftFont structure info to store
        font information. If info is NULL, a new structure is
        allocated.

  

  
XftFont * XftFontOpenPattern (

  

    
	Display	*dpy,
	FcPattern	*pat);


    
Opens a font matching the pattern pat for the display
        dpy. Returns an XftFont pointer, which
        can be used to access font metrics and glyphs. The actual font data is
        loaded using FreeType.

  

  
void XftFontClose (

  

    
	Display	*dpy,
	XftFont	*font);


    
Closes the font font associated with the display
        dpy. This function decrements the reference count of the font. If
        the reference count reaches zero, the font is unloaded and its resources
        are freed.

DEBUGGING


The Xft library provides debugging output
    controlled by the XFT_DEBUG environment variable.
    Setting bits in this variable enables different levels of debugging:



  
1

  
Font opening information.

  
2

  
Verbose font matching and opening.

  
4

  
Details about the XRenderPictFormat used.

  
8

  
The string being drawn by XftDrawString8.

  
16

  
Information about matched font IDs.

  
32

  
Details about glyphs to be drawn.

  
64

  
ASCII-art representation of glyphs.

  
128

  
Details about memory cache management.

  
256

  
Details about glyph cache memory management.

  
512

  
Memory usage report.

  
1024

  
Details about extended glyph cache memory management.








COMPATIBILITY


As of version 2 (May 2002), Xft is considered
    stable and aims to maintain source and binary compatibility in future
    releases.


An compatibility interface to Xft 1.x is provided via
    <X11/Xft/XftCompat.h>.




Xft   1.x Data Types



  
XftPattern

  
Represents a set of font properties (name-value pairs). Used for specifying
      font search criteria and for holding information about matched fonts.

  
XftFontSet

  
A collection of XftPattern objects. Used internally by
      Xft and as the return type for functions listing available fonts.

  
XftObjectSet

  
A set of names, used to specify which font properties should be included
      when listing fonts.
