NOM

Xft - Bibliothèque d'interface X FreeType

SYNOPSIS

#include <X11/Xft/Xft.h>

DESCRIPTION

Xft est une bibliothèque simple qui dessine du texte et des graphiques :

  • en utilisant les informations fournies par la bibliothèque Fontconfig,
  • Xft convertit les glyphes de polices en utilisant le rasteriseur FreeType, et
  • affiche les données de polices converties en utilisant l'extension X Rendering Extension.

Cette page de manuel ne fait qu'effleurer la surface de cette bibliothèque.

CONSTANTES

XFT_MAJOR
est le numéro de version majeure de Xft.
XFT_MINOR
est le numéro de version mineure de Xft.
XFT_REVISION
est le numéro de révision de Xft.
XFT_VERSION
est XFT_MAJOR multiplié par 10000 (dix mille), plus XFT_MINOR multiplié par 100, plus XFT_REVISION.
XftVersion
est un alias pour XFT_VERSION.

L'exemple suivant illustre comment les constantes de version de Xft pourraient être utilisées : 

    #if (XFT_VERSION >= 20107)
    (void) puts("Version 2.1.7 ou ultérieure de la bibliothèque Xft est en"
                " cours d'utilisation.");
    #else
    (void) printf("Version insuffisante de Xft (%d.%d.%d) installée ;"
                  " besoin au moins de la version 2.1.7.\n", XFT_MAJOR,
                  XFT_MINOR,
                  XFT_REVISION);
    #endif

TYPES DE DONNEES

Les types de données Xft suivent une convention de nommage, préfixant tous les noms par « Xft »

Depuis Xlib...

Les types de données Xlib ne suivent pas une convention de nommage. Ils sont documentés dans Xlib - Interface de langage C.

Xft utilise ces noms : Bool, Colormap, Display, Drawable, Pixmap, Region, Visual, et XRectangle.

Certains types de données sont particulièrement pertinents pour Xft :

Drawable
Déclaré dans <X11/X.h>, il s'agit d'un identifiant de ressource X, par exemple, une fenêtre associée à un affichage. Les fenêtres et les pixmaps peuvent être utilisés comme sources et destinations dans les opérations graphiques. Ces fenêtres et pixmaps sont collectivement connus sous le nom de drawables. Cependant, une fenêtre InputOnly ne peut pas être utilisée comme source ou destination dans une opération graphique.
Region
Déclaré dans <X11/Xutil.h> et <X11/Xregion.h>, une Region est un ensemble arbitraire de positions de pixels que Xlib peut manipuler. Interne, une Region est représentée par l'union d'un nombre arbitraire de rectangles. Xlib maintient un rectangle qui lui indique l'étendue de cette union.
Visual
Déclaré dans <X11/Xutil.h>, cette structure contient des informations sur le mappage de couleurs possible.

Depuis XRender...

Les types de données de l'extension X Render sont inspirés de Xlib, mais n'ont pas la documentation correspondante. Référez-vous au fichier d'en-tête pour les détails :

<X11/extensions/Xrender.h>

ou lisez le code source (qui fournit un aperçu de libXrender).

Xft utilise ces noms : Picture, XGlyphInfo, XRenderColor.

Depuis Fontconfig...

Les types de données Fontconfig suivent une convention de nommage, préfixant tous les noms par « Fc », qui sont documentés dans Fontconfig Developers Reference.

Xft utilise ces noms Fontconfig : FcBool, FcChar8, FcChar16, FcChar32, FcCharSet, FcEndian, FcFontSet, FcPattern, et FcResult.

Depuis FreeType 2...

Les types de données FreeType 2 suivent une convention de nommage, préfixant tous les noms par « FT_ », qui sont documentés dans FreeType API Reference.

Xft utilise ces noms : FT_Face, FT_Library, et FT_UInt.

FreeType 2 utilise FT_UInt (un entier non signé) pour représenter les glyphes.

XftFont


typedef struct _XftFont {
	int	 ascent;
	int	 descent;
	int	 height;
	int	 max_advance_width;
	FcCharSet	*charset;
	FcPattern	*pattern;
} XftFont;

Un XftFont est la structure de données principale qui intéresse les programmeurs utilisant Xft ; il contient des métriques de police générales et des pointeurs vers l'ensemble de caractères et le motif Fontconfig associés à la police.

Les XftFonts sont peuplés par XftFontOpen(), XftFontOpenName(), XftFontOpenXlfd(), XftFontOpenInfo(), ou XftFontOpenPattern(). XftFontCopy() est utilisé pour dupliquer les XftFonts, et XftFontClose() est utilisé pour marquer un XftFont comme inutilisé. Les XftFonts sont alloués en interne, comptés par référence et libérés par Xft ; le programmeur n'a généralement pas besoin d'allouer ou de libérer de la mémoire pour eux.

XftDrawGlyphs(), la famille XftDrawString*(), XftDrawCharSpec(), et XftDrawGlyphSpec() utilisent les XftFonts pour rendre le texte dans un objet XftDraw, qui peut correspondre soit à un drawable X de base, soit à un drawable d'extension X Rendering.

XftGlyphExtents() et la famille XftTextExtents*() sont utilisés pour déterminer les étendues (dimensions maximales) d'un XftFont.

La couverture des glyphes ou des caractères d'un XftFont peut être déterminée avec XftFontCheckGlyph() ou XftCharExists(). XftCharIndex() renvoie l'index de caractère spécifique au XftFont correspondant à un point de code Unicode donné.

XftGlyphRender(), XftGlyphSpecRender(), XftCharSpecRender(), et la famille XftTextRender*() utilisent les XftFonts pour dessiner dans des structures Picture de l'extension X Rendering.

Note : XftDrawGlyphs(), la famille XftDrawString*(), XftDrawCharSpec(), et XftDrawGlyphSpec() fournissent un moyen de rendre les polices indépendant de la disponibilité de l'extension X Rendering sur le serveur X.

XftFontInfo

est un objet opaque qui stocke des informations sur une police. Les structures XftFontInfo sont créées avec XftFontInfoCreate(), libérées avec XftFontInfoDestroy(), et comparées avec XftFontInfoEqual(). Les objets XftFontInfo sont alloués et libérés en interne par Xft ; le programmeur n'a généralement pas besoin d'allouer ou de libérer de la mémoire pour eux.

Chaque structure XftFontInfo en cours d'utilisation est associée à un identifiant unique, qui peut être récupéré avec XftFontInfoHash(). Un XftFont peut être ouvert sur la base des données XftFontInfo avec XftFontOpenInfo().

typedef struct _XftColor {

XftDraw

est un objet opaque qui contient les informations utilisées pour le rendu sur un dessin X utilisant soit le protocole de base, soit l'extension X Rendering.

Les objets XftDraw sont créés avec l'une des fonctions XftDrawCreate() (qui associe un XftDraw à un dessin X existant), XftDrawCreateBitmap(), ou XftDrawCreateAlpha(), et détruits avec XftDrawDestroy(). Le dessin X associé à un XftDraw peut être modifié avec XftDrawChange(). Les objets XftDraw sont alloués et libérés en interne par Xft ; le programmeur n'a généralement pas besoin d'allouer ou de libérer de la mémoire pour eux.

Les propriétés Display, Drawable, Colormap et Visual de X d'un XftDraw peuvent être interrogées respectivement avec XftDrawDisplay(), XftDrawDrawable(), XftDrawColormap() et XftDrawVisual().

Plusieurs fonctions utilisent des objets XftDraw : XftDrawCharFontSpec(), XftDrawCharSpec(), XftDrawGlyphFontSpec(), XftDrawGlyphSpec(), XftDrawGlyphs(), XftDrawRect(), XftDrawSetClip(), XftDrawSetClipRectangles(), XftDrawSetSubwindowMode() et la famille XftDrawString*().

L'extension X Rendering, Picture, associée à un XftDraw est retournée par XftDrawPicture() et XftDrawSrcPicture(). Elle est utilisée par XftCharFontSpecRender(), XftCharSpecRender(), XftGlyphFontSpecRender(), XftGlyphRender(), XftGlyphSpecRender() et la famille XftTextRender*().

FONCTIONS

Initialisation

Une application typique utilisant Xft n'initialise pas explicitement la bibliothèque. Ceci est généralement fait comme effet secondaire de l'ouverture d'une police.

Lorsque Xft s'initialise, il collecte des informations sur l'affichage et stocke certaines de ces informations dans un modèle Fontconfig (essentiellement une collection de propriétés avec des valeurs typées). L'application appelante peut modifier ce modèle pour changer le comportement de la bibliothèque.

Toutes les informations collectées ne sont pas stockées dans un modèle. Le reste est stocké dans des structures de données internes. Xft rend une partie de ces informations disponibles à l'application via des fonctions.

Bool XftDefaultHasRender (
	Display	*dpy);

Obtient des informations sur l'affichage dpy si ce n'est pas déjà fait, et retourne vrai si Xft a constaté que l'affichage prend en charge l'extension X Render, et s'il est capable de trouver un XRenderPictFormat approprié (le type de données de X Render analogue au Visual de Xlib) sur l'affichage.

Bool XftDefaultSet (
	Display	*dpy,
	FcPattern	*defaults);

Obtient des informations sur l'affichage dpy si ce n'est pas déjà fait, et définit le modèle Fontconfig contenant les propriétés par défaut que Xft utilisera pour cet affichage.

Xft utilise ces propriétés initialement pour obtenir les limites suivantes :
XFT_MAX_GLYPH_MEMORY
(maxglyphmemory). C'est la quantité maximale de mémoire de glyphes pour toutes les polices utilisées par Xft (par défaut : 4 Mo).
XFT_MAX_UNREF_FONTS
(maxunreffonts). C'est le nombre maximum de polices non référencées (par défaut : 16).
XFT_TRACK_MEM_USAGE
(trackmemusage). Lorsque vrai, Xft suit l'utilisation de la mémoire des glyphes pour améliorer les performances lors de la décision de ce qu'il faut décharger lorsque la quantité maximale de mémoire de glyphes est atteinte (par défaut : faux).
Xft utilise également ces propriétés par défaut dans XftDefaultSubstitute().
void XftDefaultSubstitute (
	Display	*dpy,
	int	 screen,
	FcPattern	*pattern);

Xft remplit les propriétés manquantes dans le pattern donné en utilisant les propriétés par défaut pour l'affichage spécifié dpy, par exemple telles que définies dans XftDefaultSet().

Les applications Xft typiques utilisent cette fonction pour aider Fontconfig à choisir une police appropriée. Ces propriétés sont substituées avant d'appeler FcDefaultSubstitute() :
FC_ANTIALIAS
Vrai si FreeType doit utiliser l'anti-aliasing (par défaut : Faux). (par défaut : Vrai).
FC_AUTOHINT
Vrai si FreeType doit utiliser l'auto-hinting (par défaut : Faux).
FC_DPI
Points par pouce utilisés pour la résolution (par défaut : calculé à partir de la hauteur de l'affichage).
FC_EMBOLDEN
Vrai si FT_GlyphSlot_Embolden() doit être utilisé pour renforcer une police (par défaut : Faux).
FC_HINTING
Vrai si l'hinting doit être utilisé lors du remplissage des propriétés pour ouvrir une police (par défaut : Vrai).
FC_HINT_STYLE
Style d'hinting utilisé lors du remplissage des propriétés pour ouvrir une police (par défaut : FC_HINT_FULL).
FC_LCD_FILTER
Paramètre passé à FT_Library_SetLcdFilter() lors du chargement des glyphes (par défaut : FC_LCD_DEFAULT).
FC_MINSPACE
Valeur d'espace minimum utilisée lors du remplissage des propriétés pour ouvrir une police (par défaut : Faux).
FC_RGBA
Valeur RGBA utilisée lors du remplissage des propriétés pour ouvrir une police (par défaut : calculée en appelant XRenderQuerySubpixelOrder()).
FC_SCALE
Échelle utilisée dans Fontconfig (par défaut : 1.0).
XFT_MAX_GLYPH_MEMORY
Mémoire maximale pour une seule police (par défaut : 1024*1024).
XFT_RENDER
Vrai si l'affichage prend en charge l'extension X Render (par défaut : résultat de XftDefaultHasRender()).
FcBool XftInit (
	_Xconst char	*config);

Initialise la bibliothèque Fontconfig (en appelant FcInit()).

Le paramètre config n'est pas utilisé.
Xft ne désinitialise pas la bibliothèque Fontconfig une fois terminée.

Ouverture et Correspondance des Polices



  
XftFont *XftFontOpen (

  

    
	Display	*dpy,
	int	 screen,
	...);


    
XftFontOpen prend une liste de triplets d'éléments de modèle de la forme champ, type, valeur (terminée par NULL), fait correspondre ce modèle aux polices disponibles et ouvre la police correspondante, en la dimensionnant correctement pour l'écran numéro screen sur l'affichage dpy. Retourne la police correspondante, ou NULL si aucune correspondance n'est trouvée.

  




Exemple :
  




    font = XftFontOpen (dpy, screen,
                        XFT_FAMILY, XftTypeString, "charter",
                        XFT_SIZE, XftTypeDouble, 12.0,
                        NULL);




  

  
Ceci ouvre la police “charter” à 12 points. La taille en points est automatiquement convertie en la taille en pixels correcte en fonction de la résolution du moniteur.

	Display	*dpy,
	_Xconst Visual	*visual,

      result.
    • 






  

  
Le paramètre visual n'est pas utilisé.





  
Bool XftColorAllocValue (

  

    
	Display	*dpy,
	Visual	*visual,
	Colormap	 cmap,
	_Xconst XRenderColor	*color,
	XftColor	*result);


    
Alloue une valeur de couleur :

  






    
  
  • Si la classe visual est TrueColor, XftColorAllocValue() définit
      le champ pixel dans le XftColor référencé par result

    • 
  
  • Si la classe visual n'est pas TrueColor, XftColorAllocValue()
      appelle XAllocColor() pour allouer une entrée dans la carte de

    • 




  

  
Si XAllocColor() réussit, XftColorAllocValue() stocke cette
      valeur de pixel dans le XRenderColor référencé par result
      et renvoie True.

  

  
Si XAllocColor() échoue, XftColorAllocValue() renvoie False
      et ne modifie pas le résultat.

Bool XftDrawSetClip (

  

    
	XftDraw	*draw,
	Region	 r);


    
Set up clipping for the given XftDraw parameter
        draw starting with a Region:

  






    
  
  • If the Region parameter r is not null, Xft creates a
      new Region (to copy the parameter),
    • 
  
  • Xft destroys any existing clipping region.
    • 
  
  • Xft sets the clip_type for the draw parameter to
      XftClipTypeRegion if the r parameter was not null. Otherwise
      it sets the clip_type to XftClipTypeNone.
    • 
  
  • Finally, Xft updates clipping for existing objects, updates the
      clip_mask for its X Render Picture object and sets the
      clipping-mask in the graphic context (GC) associated with the
      XftDraw parameter.
    • 






  

  
XftDrawSetClip() returns True if no change was necessary, or
      if the operation succeeded. It returns False if it was unable to
      create the new Region().

	int	 xOrigin,
	int	 yOrigin,
	_Xconst XRectangle	*rects,
	int	 n);


    
Like XftDrawSetClip(),
        XftDrawSetClipRectangles() sets up clipping for the given
        XftDraw parameter draw but uses a set of n
        rectangles (the rects parameter) which could be used to construct
        a Region.

  





  

  
Xft sets the clip_type for draw to XftClipTypeRectangles and
      uses XSetClipRectangles() for core (X11) clipping and
      XRenderSetPictureClipRectangles() for X Render clipping.





  
void XftDrawSetSubwindowMode (

  

    
	XftDraw	*draw,
	int	 mode);


    
Sets the subwindow-mode for the given XftDraw parameter
        draw. The mode can be either ClipByChildren (the default),
        or IncludeInferiors:

  






    
  
  • For ClipByChildren, both source and destination windows are
      additionally clipped by all viewable InputOutput children.
    • 
  
  • For IncludeInferiors, neither source nor destination window is
      clipped by inferiors. This will result in including subwindow contents in
      the source and drawing through subwindow boundaries of the
    destination.
    • 






  

  
In addition to the subwindow-mode maintained by Xft, it updates the
      subwindow mode for any associated graphics context GC using
      XSetSubwindowMode() as well as for an X Render Picture using
      XRenderChangePicture().

void XftDrawGlyphFontSpec (

  

    
	XftDraw	*draw,
	_Xconst XftColor	*color,
	_Xconst XftGlyphFontSpec	*glyphs,
	int	 len);


    
Draw a list of glyphs associated with fonts at specified
        coordinates, passed as an array of len XftGlyphFontSpec
        structures via the parameter glyphs. All of the glyphs are drawn
        using the color specified in the color parameter.

  





  

  
For each entry in the glyphs array:






    
  
  • If the associated font uses the X Render extension, then Xft uses
      XftGlyphFontSpecRender() to draw the glyph, using a Picture
      obtained from calling XftDrawSrcPicture () with the draw and
      color parameters.
    • 
  
  • Otherwise, Xft provides an analogous feature using Xlib.
    • 






  
void XftGlyphFontSpecRender (

  

    
	Display	*dpy,
	int	 op,
	Picture	 src,
	Picture	 dst,
	int	 srcx,
	int	 srcy,
	_Xconst XftGlyphFontSpec	*glyphs,
	int	 nglyphs);


    
This involves several steps:

  






    
  
  • First, Xft ensures that the glyphs array is complete using
      XftFontCheckGlyph() and loading any missing glyphs with
      XftFontLoadGlyphs().
    • 
  
  • Then Xft examines the glyphs to find the maximum Unicode value.
      That determines the encoding size, i.e., the width.
    • 
  
  • Then, for each glyph, Xft checks if its Unicode value is handled by
      the corresponding font. If not, the value is set to zero (0), to ignore
      it. While doing this, Xft also remembers which was the first font
      used, and computes the position at which each glyph will be drawn.
    • 
  
  • Xft then constructs an equivalent array of glyphs in the format
      expected by the X Render library.
    • 
  
  • Finally, XftGlyphFontSpecRender() uses the X Render extension to
      draw the glyphs, with the appropriate XRenderCompositeText*()
      function according to the width, and discards temporary data.
    • 




  

  
The op, dst, src, srcx, and srcy
      parameters are used as described in the documentation for the X Render
      library.

FT_Face XftLockFace (

  

    
	XftFont	*pub);


    
Si aucun "face" FreeType 2 (représentation en mémoire d'une
        police donnée dans un style donné) n'a été créé pour la police
        pub, en crée un en utilisant FT_New_Face().
        Les verrous de face sont un compteur de références utilisé par
        Xft pour garantir qu'une seule face est créée et qu'elle est
        conservée tant que la police n'est plus utilisée.

  





  

  
Le verrouillage de face est utilisé directement dans XftCharIndex()
      et
      XftFontLoadGlyphs(), qui à leur tour sont utilisés dans de nombreuses
      fonctions de
      Xft.

  

  
Le verrouillage de face a été introduit dans la version 1 (octobre 2002).
      Quelques applications, comme Gdk/Gimp, dépendaient de ces fonctions. Dans la
      version 2.1.9 (juin 2006), le verrouillage de face a été conservé en tant
      que partie de l'API publique lorsque des configurations de bibliothèques
      partagées améliorées ont permis de masquer les symboles privés.

DÉBOGAGE


Xft lit la variable d'environnement XFT_DEBUG et la
    convertit en un entier. Chaque bit de la valeur résultante indique à
    Xft d'imprimer des informations de débogage sur la sortie standard
    :



  
1

  
ouverture de police

  
2

  
correspondance et ouverture de police supplémentaires (verbeux)

  
4

  
affiche les détails sur XRenderPictFormat qui sera utilisé.

  
8

  
affiche la chaîne que XftDrawString8() dessinera.

  
16

  
affiche les identifiants de police qui correspondent.

  
32

  
affiche des informations utiles sur les glyphes qui seront dessinés

  
64

  
affiche une représentation en art ASCII des glyphes.

  
128

  
affiche les détails sur la gestion du cache mémoire

  
256

  
affiche les détails sur la gestion de la mémoire cache des glyphes

  
512

  
affiche un rapport sur l'utilisation de la mémoire

  
1024

  
affiche des détails sur la gestion étendue de la mémoire cache des
      glyphes








COMPATIBILITÉ


Depuis la version 2 (mai 2002), Xft est devenu relativement
    stable. On s'attend à ce qu'il conserve la compatibilité source et binaire dans
    les futures versions.


Xft fournit une interface de compatibilité avec sa version
    majeure précédente, Xft 1.x, décrite ci-dessous.




Fichier   entête Xft 1.x


#include <X11/Xft/XftCompat.h>






Types   de données Xft 1.x



  
XftPattern

  
contient un ensemble de noms avec des listes de valeurs associées ; chaque
      nom fait référence à une propriété d'une police. Les XftPattern sont
      utilisés comme entrées pour le code de correspondance ainsi que pour contenir
      des informations sur des polices spécifiques.

  
XftFontSet

  
contient une liste de XftPattern. Interne, Xft utilise cette
      structure de données pour contenir des ensembles de polices. Externe,
      Xft retourne les résultats de la liste des polices dans ce format.

  
XftObjectSet

  
contient un ensemble de noms et est utilisé pour spécifier quels champs des
      polices sont placés dans la liste des modèles retournés lors de la liste des
      polices.
