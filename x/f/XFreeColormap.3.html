Paquet: libx11

XCreateColormap(3) FONCTIONS XLIB XCreateColormap(3)

NOM

XCreateColormap, XCopyColormapAndFree, XFreeColormap, XColor - créer, copier ou détruire des palettes de couleurs et des structures de couleur

SYNTAXE

Colormap XCreateColormap(Display *display, Window w, Visual *visual, int alloc);

Colormap XCopyColormapAndFree(Display *display, Colormap colormap);

int XFreeColormap(Display *display, Colormap colormap);

ARGUMENTS

alloc
Spécifie les entrées de la palette de couleurs à allouer. Vous pouvez passer AllocNone ou AllocAll.
colormap
Spécifie la palette de couleurs que vous souhaitez créer, copier, définir ou détruire.
display
Spécifie la connexion au serveur X.
visual
Spécifie un type de visualisation pris en charge sur l'écran. Si le type de visualisation n'est pas un de ceux pris en charge par l'écran, une erreur BadMatch en résulte.
w
Spécifie la fenêtre sur l'écran de laquelle vous souhaitez créer une palette de couleurs.

DESCRIPTION

La fonction XCreateColormap crée une palette de couleurs du type de visualisation spécifié pour l'écran sur lequel réside la fenêtre spécifiée et retourne l'identifiant de la palette de couleurs associé. Notez que la fenêtre spécifiée est uniquement utilisée pour déterminer l'écran.

Les valeurs initiales des entrées de la palette de couleurs sont indéfinies pour les classes de visualisation GrayScale, PseudoColor et DirectColor. Pour StaticGray, StaticColor et TrueColor, les entrées ont des valeurs définies, mais ces valeurs sont spécifiques à la visualisation et ne sont pas définies par X. Pour StaticGray, StaticColor et TrueColor, alloc doit être AllocNone, ou une erreur BadMatch en résulte. Pour les autres classes de visualisation, si alloc est AllocNone, la palette de couleurs n'a initialement aucune entrée allouée, et les clients peuvent les allouer. Pour plus d'informations sur les types de visualisation, voir la section 3.1.

Si alloc est AllocAll, l'ensemble de la palette de couleurs est alloué en écriture. Les valeurs initiales de toutes les entrées allouées sont indéfinies. Pour GrayScale et PseudoColor, l'effet est comme si un appel XAllocColorCells retournait toutes les valeurs de pixels de zéro à N - 1, où N est le nombre d'entrées de la palette de couleurs dans la visualisation spécifiée. Pour DirectColor, l'effet est comme si un appel XAllocColorPlanes retournait une valeur de pixel de zéro et des valeurs de masque rouge, vert et bleu contenant les mêmes bits que les masques correspondants dans la visualisation spécifiée. Cependant, dans tous les cas, aucune de ces entrées ne peut être libérée en utilisant XFreeColors.

XCreateColormap peut générer des erreurs BadAlloc, BadMatch, BadValue et BadWindow.

La fonction XCopyColormapAndFree crée une palette de couleurs du même type de visualisation et pour le même écran que la palette de couleurs spécifiée et retourne le nouvel identifiant de la palette de couleurs. Elle déplace également toutes les allocations existantes du client de la palette de couleurs spécifiée vers la nouvelle palette de couleurs en conservant leurs valeurs de couleur intactes et leurs caractéristiques de lecture seule ou d'écriture intactes, puis libère ces entrées dans la palette de couleurs spécifiée. Les valeurs de couleur dans les autres entrées de la nouvelle palette de couleurs sont indéfinies. Si la palette de couleurs spécifiée a été créée par le client avec alloc défini sur AllocAll, la nouvelle palette de couleurs est également créée avec AllocAll, toutes les valeurs de couleur pour toutes les entrées sont copiées de la palette de couleurs spécifiée, puis toutes les entrées dans la palette de couleurs spécifiée sont libérées. Si la palette de couleurs spécifiée n'a pas été créée par le client avec AllocAll, les allocations à déplacer sont tous les pixels et plans qui ont été alloués par le client en utilisant XAllocColor, XAllocNamedColor, XAllocColorCells ou XAllocColorPlanes et qui n'ont pas été libérés depuis leur allocation.

XCopyColormapAndFree peut générer des erreurs BadAlloc et BadColor.

La fonction XFreeColormap supprime l'association entre l'identifiant de la ressource de la palette de couleurs et la palette de couleurs, et libère le stockage de la palette de couleurs. Cependant, cette fonction n'a aucun effet sur la palette de couleurs par défaut d'un écran. Si la palette de couleurs spécifiée est une carte installée pour un écran, elle est désinstallée (voir XUninstallColormap). Si la palette de couleurs spécifiée est définie comme la palette de couleurs pour une fenêtre (par XCreateWindow, XSetWindowColormap ou XChangeWindowAttributes), XFreeColormap change la palette de couleurs associée à la fenêtre à None et génère un événement ColormapNotify. X ne définit pas les couleurs affichées pour une fenêtre avec une palette de couleurs de None.

XFreeColormap peut générer une erreur BadColor.

STRUCTURES

La structure XColor contient :

typedef struct {
        unsigned long pixel;    /* valeur du pixel */
        unsigned short red, green, blue;        /* valeurs rvb */
        char flags;     /* DoRed, DoGreen, DoBlue */
        char pad;
} XColor;

Les valeurs rouge, verte et bleue sont toujours comprises entre 0 et 65535 inclus, indépendamment du nombre de bits réellement utilisés par le matériel d'affichage. Le serveur met à l'échelle ces valeurs pour les ramener à la plage utilisée par le matériel. Le noir est représenté par (0,0,0) et le blanc par (65535,65535,65535). Dans certaines fonctions, le membre flags contrôle lequel des membres rouge, vert et bleu est utilisé et peut être le OU inclusif de zéro ou plus de DoRed, DoGreen et DoBlue.

DIAGNOSTICS

BadAlloc
Le serveur n'a pas pu allouer la ressource demandée ou la mémoire serveur.
BadColor
Une valeur pour un argument Colormap ne nomme pas une Colormap définie.
BadMatch
Une fenêtre InputOnly est utilisée comme Drawable.
BadMatch
Un argument ou une paire d'arguments a le type et la plage corrects, mais ne correspond pas d'une autre manière requise par la requête.
BadValue
Une valeur numérique tombe en dehors de la plage de valeurs acceptées par la requête. Sauf si une plage spécifique est spécifiée pour un argument, la plage complète définie par le type de l'argument est acceptée. Tout argument défini comme un ensemble d'alternatives peut générer cette erreur.
BadWindow
Une valeur pour un argument Window ne nomme pas une Window définie.
