NOM

Xft - bibliothèque d'interface X FreeType

SYNTAXE

#include <X11/Xft/Xft.h>

DESCRIPTION

Xft est une bibliothèque simple qui dessine du texte et des graphiques :

  • en utilisant les informations fournies par la bibliothèque Fontconfig,
  • Xft convertit les glyphes de polices en utilisant le rasteriseur FreeType, et
  • affiche les données de polices converties en utilisant l'extension X Rendering Extension.

Cette page de manuel ne fait qu'effleurer la surface de cette bibliothèque.

CONSTANTES

XFT_MAJOR
est le numéro de version majeure de Xft.
XFT_MINOR
est le numéro de version mineure de Xft.
XFT_REVISION
est le numéro de révision de Xft.
XFT_VERSION
est XFT_MAJOR multiplié par 10000 (dix mille), plus XFT_MINOR multiplié par 100, plus XFT_REVISION.
XftVersion
est un alias pour XFT_VERSION.

L'exemple suivant illustre comment les constantes de version de Xft pourraient être utilisées : 

    #if (XFT_VERSION >= 20107)
    (void) puts("Version 2.1.7 ou ultérieure de la bibliothèque Xft est
                  en cours d'utilisation.");
    #else
    (void) printf("Version insuffisante de Xft (%d.%d.%d) installée ;
                  besoin d'au moins la version 2.1.7.\n", XFT_MAJOR,
                  XFT_MINOR,
                  XFT_REVISION);
    #endif

TYPES DE DONNÉES

Les types de données Xft suivent une convention de nommage, préfixant tous les noms par « Xft »

Depuis Xlib...

Les types de données Xlib ne suivent pas de convention de nommage. Ils sont documentés dans Xlib - C Language Interface.

Xft utilise ces noms : Bool, Colormap, Display, Drawable, Pixmap, Region, Visual, et XRectangle.

Certains types de données sont particulièrement pertinents pour Xft :

Drawable
Déclaré dans <X11/X.h>, c'est un ID de ressource X, par exemple, une fenêtre associée à un afficheur. Les fenêtres et les pixmaps peuvent être utilisés comme sources et destinations dans les opérations graphiques. Ces fenêtres et pixmaps sont collectivement appelés des drawables. Cependant, une fenêtre InputOnly ne peut pas être utilisée comme source ou destination dans une opération graphique.
Region
Déclaré dans <X11/Xutil.h> et <X11/Xregion.h>, une Region est un ensemble arbitraire d'emplacements de pixels que Xlib peut manipuler. Internelement, une Region est représentée par l'union d'un nombre arbitraire de rectangles. Xlib maintient un rectangle qui lui indique l'étendue de cette union.
Visual
Déclaré dans <X11/Xutil.h>, cette structure contient des informations sur le mappage de couleurs possible.

Depuis XRender...

Les types de données de l'extension X Render Extension sont inspirés de Xlib, mais manquent de la documentation correspondante. Référez-vous au fichier d'en-tête pour les détails :

<X11/extensions/Xrender.h>

ou lisez le code source (qui fournit un aperçu de libXrender).

Xft utilise ces noms : Picture, XGlyphInfo, XRenderColor.

Depuis Fontconfig...

Les types de données Fontconfig suivent une convention de nommage, préfixant tous les noms par « Fc », qui sont documentés dans le Fontconfig Developers Reference.

Xft utilise ces noms Fontconfig : FcBool, FcChar8, FcChar16, FcChar32, FcCharSet, FcEndian, FcFontSet, FcPattern, et FcResult.

Depuis FreeType 2...

Les types de données FreeType 2 suivent une convention de nommage, préfixant tous les noms par « FT_ », qui sont documentés dans le FreeType API Reference.

Xft utilise ces noms : FT_Face, FT_Library, et FT_UInt.

FreeType 2 utilise FT_UInt (un entier non signé) pour représenter des glyphes.

XftFont


typedef struct _XftFont {
	int	 ascent;
	int	 descent;
	int	 height;
	int	 max_advance_width;
	FcCharSet	*charset;
	FcPattern	*pattern;
} XftFont;

Un XftFont est la structure de données principale d'intérêt pour les programmeurs utilisant Xft ; elle contient des métriques générales de police et des pointeurs vers le jeu de caractères et le modèle Fontconfig associés à la police.

Les XftFonts sont peuplés par XftFontOpen(), XftFontOpenName(), XftFontOpenXlfd(), XftFontOpenInfo(), ou XftFontOpenPattern(). XftFontCopy() est utilisé pour dupliquer les XftFonts, et XftFontClose() est utilisé pour marquer un XftFont comme non utilisé. Les XftFonts sont alloués en interne, comptés par référence, et libérés par Xft ; le programmeur n'a normalement pas besoin d'allouer ou de libérer de l'espace pour eux.

XftDrawGlyphs(), la famille XftDrawString*(), XftDrawCharSpec(), et XftDrawGlyphSpec() utilisent les XftFonts pour rendre le texte à un objet XftDraw, qui peut correspondre à un drawable X de base ou à un drawable d'extension X Rendering.

XftGlyphExtents() et la famille XftTextExtents*() sont utilisés pour déterminer les étendues (dimensions maximales) d'un XftFont.

La couverture des glyphes ou caractères d'un XftFont peut être déterminée avec XftFontCheckGlyph() ou XftCharExists(). XftCharIndex() retourne l'indice de caractère spécifique à XftFont correspondant à un point de code Unicode donné.

XftGlyphRender(), XftGlyphSpecRender(), XftCharSpecRender(), et la famille XftTextRender*() utilisent les XftFonts pour dessiner dans des structures Picture de l'extension X Rendering.

Note : XftDrawGlyphs(), la famille XftDrawString*(), XftDrawCharSpec(), et XftDrawGlyphSpec() fournissent un moyen de rendre les polices qui est indépendant de la disponibilité de l'extension X Rendering sur le serveur X.

XftFontInfo

est un objet opaque qui stocke des informations sur une police. Les structures XftFontInfo sont créées avec XftFontInfoCreate(), libérées avec XftFontInfoDestroy(), et comparées avec XftFontInfoEqual(). Les objets XftFontInfo sont alloués et libérés en interne par Xft ; le programmeur n'a normalement pas besoin d'allouer ou de libérer de l'espace pour eux.

Chaque structure XftFontInfo en cours d'utilisation est associée à un identifiant unique, qui peut être récupéré avec XftFontInfoHash(). Un XftFont peut être ouvert en se basant sur les données XftFontInfo avec XftFontOpenInfo().

XftColor


typedef struct _XftColor {
	unsigned long	 pixel;
	XRenderColor	 color;
} XftColor;

Un objet XftColor permet de rendre du texte et d'autres éléments dans une couleur particulière (ou la meilleure approximation proposée par le visuel X utilisé).

XftColorAllocName() et XftColorAllocValue() demandent une allocation de couleur au serveur X (si nécessaire) et initialisent les membres de XftColor. XftColorFree() demande au serveur X de libérer la couleur actuellement allouée pour un XftColor.

Une fois qu'un XftColor a été initialisé, XftDrawSrcPicture(), XftDrawGlyphs(), la famille XftDrawString*(), XftDrawCharSpec(), XftDrawCharFontSpec(), XftDrawGlyphSpec(), XftDrawGlyphFontSpec(), et XftDrawRect() peuvent être utilisés pour dessiner divers objets en l'utilisant.

XftDraw

est un objet opaque qui contient les informations utilisées pour rendre sur un drawable X en utilisant soit le protocole de base, soit l'extension X Rendering.

Les objets XftDraw sont créés avec l'une des fonctions XftDrawCreate() (qui associe un XftDraw à un drawable X existant), XftDrawCreateBitmap(), ou XftDrawCreateAlpha(), et détruits avec XftDrawDestroy(). Le drawable X associé à un XftDraw peut être modifié avec XftDrawChange(). Les objets XftDraw sont alloués et libérés en interne par Xft ; le programmeur n'a normalement pas besoin d'allouer ou de libérer de la mémoire pour eux.

Les propriétés Display, Drawable, Colormap, et Visual d'un XftDraw peuvent être interrogées avec XftDrawDisplay(), XftDrawDrawable(), XftDrawColormap(), et XftDrawVisual(), respectivement.

Plusieurs fonctions utilisent les objets XftDraw : XftDrawCharFontSpec(), XftDrawCharSpec(), XftDrawGlyphFontSpec(), XftDrawGlyphSpec(), XftDrawGlyphs(), XftDrawRect(), XftDrawSetClip(), XftDrawSetClipRectangles(), XftDrawSetSubwindowMode(), et la famille XftDrawString*().

L'extension X Rendering Picture associée à un XftDraw est retournée par XftDrawPicture() et XftDrawSrcPicture(). Elle est utilisée par XftCharFontSpecRender(), XftCharSpecRender(), XftGlyphFontSpecRender(), XftGlyphRender(), XftGlyphSpecRender(), et la famille XftTextRender*().

FONCTIONS

Initialisation

Une application typique utilisant Xft n'initialise pas explicitement la bibliothèque. Cela se fait généralement comme effet secondaire de l'ouverture d'une police.

Lorsque Xft s'initialise, il collecte des informations sur l'affichage et stocke certaines de ces informations dans un modèle Fontconfig (essentiellement une collection de propriétés avec des valeurs typées). L'application appelante peut modifier ce modèle pour changer le comportement de la bibliothèque.

Toutes les informations collectées ne sont pas stockées dans un modèle. Le reste est stocké dans des structures de données internes. Xft rend une partie de ces informations disponible à l'application via des fonctions.

Bool XftDefaultHasRender (
	Display	*dpy);

Obtient des informations sur l'affichage dpy si cela n'a pas déjà été fait, et retourne vrai si Xft a constaté que l'affichage prend en charge l'extension X Render, et s'il est capable de trouver un XRenderPictFormat approprié (le type de données de X Render analogue au Visual de Xlib) sur l'affichage.

Bool XftDefaultSet (
	Display	*dpy,
	FcPattern	*defaults);

Obtient des informations sur l'affichage dpy si cela n'a pas déjà été fait, et définit le modèle Fontconfig contenant les propriétés par défaut que Xft utilisera pour cet affichage.

Xft utilise ces propriétés initialement pour obtenir les limites suivantes :
XFT_MAX_GLYPH_MEMORY
(maxglyphmemory). Il s'agit de la quantité maximale de mémoire pour les glyphes de toutes les polices utilisées par Xft (par défaut : 4*1024*1024).
XFT_MAX_UNREF_FONTS
(maxunreffonts). Il s'agit du nombre maximal de polices non référencées (par défaut : 16).
XFT_TRACK_MEM_USAGE
(trackmemusage). Si vrai, Xft suit l'utilisation de la mémoire des glyphes pour améliorer les performances lors de la décision de quels glyphes décharger lorsque la quantité maximale de mémoire de glyphes est atteinte (par défaut : faux).
Xft utilise également ces propriétés par défaut dans XftDefaultSubstitute().
void XftDefaultSubstitute (
	Display	*dpy,
	int	 screen,
	FcPattern	*pattern);

Xft remplit les propriétés manquantes dans le pattern donné en utilisant les propriétés par défaut pour l'affichage spécifié dpy, par exemple, comme défini dans XftDefaultSet().

Les applications Xft typiques utilisent cette fonction pour aider Fontconfig à choisir une police appropriée. Ces propriétés sont substituées avant d'appeler FcDefaultSubstitute():
FC_ANTIALIAS
Vrai si FreeType doit utiliser l'anti-aliasing (par défaut : Faux). (par défaut : Vrai).
FC_AUTOHINT
Vrai si FreeType doit utiliser l'auto-hinting (par défaut : Faux).
FC_DPI
Points/pouce utilisés pour la résolution (par défaut : calculé à partir de la hauteur de l'affichage).
FC_EMBOLDEN
Vrai si FT_GlyphSlot_Embolden() doit être utilisé pour épaissir une police (par défaut : Faux).
FC_HINTING
Vrai si l'hinting doit être utilisé lors du remplissage des propriétés pour ouvrir une police (par défaut : Vrai).
FC_HINT_STYLE
Style d'hinting utilisé lors du remplissage des propriétés pour ouvrir une police (par défaut : FC_HINT_FULL).
FC_LCD_FILTER
Paramètre passé à FT_Library_SetLcdFilter() lors du chargement des glyphes (par défaut : FC_LCD_DEFAULT).
FC_MINSPACE
Espace minimum utilisé lors du remplissage des propriétés pour ouvrir une police (par défaut : Faux).
FC_RGBA
Valeur RGBA utilisée lors du remplissage des propriétés pour ouvrir une police (par défaut : calculée en appelant XRenderQuerySubpixelOrder()).
FC_SCALE
Échelle utilisée dans Fontconfig (par défaut : 1.0).
XFT_MAX_GLYPH_MEMORY
Mémoire maximale pour une police (par défaut : 1024*1024).
XFT_RENDER
Vrai si l'affichage prend en charge l'extension X Render (par défaut : résultat de XftDefaultHasRender()).
FcBool XftInit (
	_Xconst char	*config);

Initialise la bibliothèque Fontconfig (en appelant FcInit()).

Le paramètre config n'est pas utilisé.
Xft ne désinitialise pas la bibliothèque Fontconfig une fois qu'elle a terminé.
FcBool XftInitFtLibrary (void);

    
Initialise la bibliothèque FreeType (en appelant
        FT_Init_FreeType() pour créer un objet bibliothèque) si elle n'a
        pas déjà été initialisée. Ceci est nécessaire avant d'utiliser la
        bibliothèque FreeType pour lire les données de police à partir d'un
        fichier.

  





  

  
Xft appelle XftInitFtLibrary() en interne via
      XftFontInfoCreate() et XftFontOpenPattern().

  

  
Xft ne rejette pas l'objet bibliothèque (par exemple, en utilisant
      FT_Done_FreeType()) une fois qu'il a terminé.

Ouverture et Correspondance des Polices



  
XftFont *XftFontOpen (

  

    
	Display	*dpy,
	int	 screen,
	...);


    
XftFontOpen prend une liste de triplets élémentaires de
        modèle de la forme champ, type, valeur (terminée
        par un NULL), met en correspondance ce modèle avec les polices disponibles,
        et ouvre la police correspondante, en la dimensionnant correctement pour
        l'écran numéro screen sur l'affichage dpy. Retourne la
        police correspondante, ou NULL si aucune correspondance n'est trouvée.

  




Exemple :
  




    font = XftFontOpen (dpy, screen,
                        XFT_FAMILY, XftTypeString, "charter",
                        XFT_SIZE, XftTypeDouble, 12.0,
                        NULL);




  

  
Cela ouvre la police “charter” à 12 points. La taille en
      points est automatiquement convertie en la taille en pixels correcte en
      fonction de la résolution du moniteur.





  
XftFont *XftFontOpenName (

  

    
	Display	*dpy,
	int	 screen,
	_Xconst char	*name);


    
XftFontOpenName se comporte comme

  


XftFontOpen,
        sauf qu'il prend une chaîne de motifs Fontconfig (qui est passée à la
        fonction FcNameParse() de la bibliothèque Fontconfig).

  
  
XftFont *XftFontOpenXlfd (

  

    
	Display	*dpy,
	int	 screen,
	_Xconst char	*xlfd)


    
XftFontOpenXlfd se comporte comme XftFontOpen,
        sauf qu'il prend une chaîne contenant une description logique de police X
        (XLFD) et utilise la fonction XftXlfdParse().

	Display	*dpy,

Également utilisé en interne par les fonctions

FcPattern *XftXlfdParse (

  

    
	_Xconst char	*xlfd_orig,
	Bool	ignore_scalable,
	Bool	complete);


    
XftXlfdParse analyse le paramètre xlfd_orig
        conformément au document X Logical Font Description Conventions,
        mais ignore certains champs : setwidth_name,
        add_style_name, spacing et average_width.

  




  

  
XftXlfdParse crée un motif Fontconfig, définit la propriété
      XFT_XLFD sur la valeur xlfd_orig et mappe les informations
      collectées aux propriétés Fontconfig. Les champs vides ou “*”
      sont ignorés :







  
FC_FOUNDRY

  
provenant de foundry.

  
FC_FAMILY

  
provenant de family.

  
FC_WEIGHT

  
weight_name, par défaut FC_WEIGHT_MEDIUM.

  
FC_SLANT

  
provenant de slant, par défaut FC_SLANT_ROMAN.

  
FC_SIZE

  
provenant de point_size.

  
FC_PIXEL_SIZE

  
provenant de pixel_size. Si point_size était défini, ainsi
      que resolution_x et resolution_y, la valeur est mise à
      l'échelle pour convertir la hauteur de la police en points.

Gestion   de XftColor



  
Bool XftColorAllocName (

  

    
	Display	*dpy,
	_Xconst Visual	*visual,
	Colormap	 cmap,
	_Xconst char	*name,
	XftColor	*result);


    
Utilise XAllocNamedColor() pour rechercher la couleur nommée
        name pour l'écran associé à la table de couleurs cmap.

  






    
  
  • Si XAllocNamedColor() retourne une valeur non nulle,
      XftColorAllocName() remplit le champ pixel résultant de
      XftColor avec la couleur la plus proche supportée par l'écran, ainsi
      que les champs rouge, vert et bleu exacts de la base de données, et retourne
      True.
    • 
  
  • Si XAllocNamedColor() retourne zéro, XftColorAllocName()
      retourne False et ne met pas à jour le XftColor référencé par
      result.
    • 






  

  
Le paramètre visual n'est pas utilisé.





  
Bool XftColorAllocValue (

  

    
	Display	*dpy,
	Visual	*visual,
	Colormap	 cmap,
	_Xconst XRenderColor	*color,
	XftColor	*result);


    
Alloue une valeur de couleur :

  






    
  
  • Si la classe visual est TrueColor, XftColorAllocValue()
      définit le champ pixel dans le XftColor référencé par
      result en utilisant les champs rouge, vert et bleu du paramètre
      color.
    • 
  
  • Si la classe visual n'est pas TrueColor, XftColorAllocValue()
      appelle XAllocColor() pour allouer une entrée dans la table de
      couleurs cmap. qui retourne la valeur pixel de la couleur la plus
      proche des éléments RVB spécifiés supportés par le matériel.
    • 




  

  
Si XAllocColor() réussit, XftColorAllocValue() stocke cette
      valeur pixel dans le XRenderColor référencé par result et
      retourne True.

  

  
Si XAllocColor() échoue, XftColorAllocValue() retourne False
      et ne modifie pas le résultat.







  
void XftColorFree (

  

    
	Display	*dpy,
	Visual	*visual,
	Colormap	 cmap,
	XftColor	*color);


    
Si la classe visual n'est pas TrueColor, Xft appelle
        XFreeColors() pour libérer l'entrée de la table de couleurs
        cmap dont la valeur pixel dans le paramètre color a été

void XftGlyphFontSpecRender (

  

    
	Display	*dpy,
	int	 op,
	Picture	 src,
	Picture	 dst,
	int	 srcx,
	int	 srcy,
	_Xconst XftGlyphFontSpec	*glyphs,
	int	 nglyphs);


    
Cela implique plusieurs étapes :

  






    
  
  • Tout d'abord, Xft s'assure que le tableau glyphs est complet
      en utilisant XftFontCheckGlyph() et en chargeant les glyphes
      manquants avec XftFontLoadGlyphs().
    • 
  
  • Ensuite, Xft examine les glyphes pour trouver la valeur Unicode
      maximale. Cela détermine la taille de l'encodage, c'est-à-dire la
      largeur.
    • 
  
  • Ensuite, pour chaque glyphe, Xft vérifie si sa valeur Unicode est
      prise en charge par la police correspondante. Sinon, la valeur est définie
      à zéro (0), pour l'ignorer. Tout en faisant cela, Xft se souvient
      également de la première police utilisée et calcule la position à laquelle
      chaque glyphe sera dessiné.
    • 
  
  • Xft construit ensuite un tableau équivalent de glyphes dans le format
      attendu par la bibliothèque X Render.
    • 
  
  • Enfin, XftGlyphFontSpecRender() utilise l'extension X Render pour
      dessiner les glyphes, avec la fonction XRenderCompositeText*()
      appropriée en fonction de la largeur, et supprime les données
      temporaires.
    • 




  

  
Les paramètres op, dst, src, srcx, et
      srcy sont utilisés comme décrit dans la documentation de la
      bibliothèque X Render.

NAME


XftDrawGlyphSpec, XftFontLoadGlyphs, XftFontUnloadGlyphs, XftLockFace, XftUnlockFace — manipulate font data and resources

DESCRIPTION


These functions provide low-level access to font data and resources
    used by the Xft library. They are generally intended for use by Xft itself
    or by developers implementing extensions or custom drawing code that needs
    fine-grained control over font loading, glyph management, and FreeType
    integration.




XftDrawGlyphSpec


This function is the primary entry point for managing glyphs for
    drawing. It takes a list of glyph indices and, based on the type
    parameter, performs different actions. If type is
    XftGlyphFace, it ensures that the FreeType face is loaded and
    ready. If type is XftGlyphDraw, it loads the specified
    glyphs, potentially including bitmap data if need_bitmaps is
    true, and adds them to the X Render extension using
    XRenderAddGlyphs().


The pub parameter is a pointer to an opaque
    XftFont structure representing the font. The dpy is the
    display connection.


The glyphs array contains the glyph indices (typically
    Unicode values) to process, and nglyph is the number of glyphs in
    the array.






XftFontLoadGlyphs


This function loads glyphs for a given font. It uses FreeType's
    FT_Load_Glyph() function to load the glyph data for the specified
    glyph indices. In addition to loading the glyph data, Xft may also process
    it based on the Fontconfig pattern associated with the font. This processing
    can include scaling, computing metrics, and adding the glyphs to the X
    Render extension via XRenderAddGlyphs(). The need_bitmaps
    flag indicates whether bitmap versions of the glyphs are required.






XftFontUnloadGlyphs


This function releases the resources associated with specified
    glyphs for a given font. If the glyphs were previously added to the X
    Render extension using XRenderAddGlyphs(), this function removes
    them using XRenderFreeGlyphs(). It also updates the memory usage
    statistics for the display connection.






XftLockFace


This function manages the reference count for the FreeType 2
    “face” object associated with an XftFont. If a face
    has not yet been created for the font, it is created using
    FT_New_Face(). This function ensures that the FreeType face is kept
    loaded as long as it is potentially needed. It returns a pointer to the
    FreeType face object. Face-locking is crucial for functions like
    XftCharIndex() and XftFontLoadGlyphs().






XftUnlockFace


This function decrements the reference count for the FreeType 2
    “face” object associated with the font. When the reference count
    reaches zero, the FreeType face object may be deallocated using
    FT_Done_Face(). This typically happens during font cleanup routines
    like XftFontInfoDestroy() or when errors occur during font
    initialization.








CONSTANTS



  
XftGlyphFace

  
Value for XftGlyphType indicating that the operation pertains to
      managing the FreeType face itself.

  
XftGlyphDraw

  
Value for XftGlyphType indicating that the operation pertains to

DATA TYPES



  
XftFont

  
An opaque structure representing an opened font. It contains font metrics,
      FreeType face information, and a pointer to its Fontconfig pattern.

  
XftPattern

  
An opaque structure representing a font pattern. Used internally by Xft for
      matching and storing font properties.

  
FcPattern

  
A structure defined by Fontconfig representing a font pattern, which is a
      set of name-value pairs describing font characteristics.

  
FcFontSet

  
A structure defined by Fontconfig representing a set of FcPatterns,
      typically used to return lists of available fonts.

  
FcObjectSet

  
A structure defined by Fontconfig used to specify which font properties
      should be returned when listing fonts.

  
XftGlyphSpec

  
A structure used to pass glyph information to functions like
      XftDrawGlyphSpec, containing the glyph type and the glyph index.

void XftFontLoadGlyphs (

  

    
	Display	*dpy,
	XftFont	*pub,
	FcBool	 need_bitmaps,
	_Xconst FT_UInt	*glyphs,
	int	 nglyph);


    
Using FT_Load_Glyph(), load nglyphs for the
        glyph indices (Unicode values) listed in the array glyphs from
        the given font pub.

  





  

  
Loading a glyph entails more than just reading data into memory.
      Xft uses the Fontconfig pattern associated with the display
      dpy (e.g., via XftDefaultSet()) to determine whether to use
      a bounding box, clip the glyphs into those bounds, scale the glyphs,
      compute font metrics, and add it to the X Render extension using
      XRenderAddGlyphs().





  
void XftFontUnloadGlyphs (

  

    
	Display	*dpy,
	XftFont	*pub,
	_Xconst FT_UInt	*glyphs,
	int	 nglyph);


    
Discards data for up to nglyph glyphs whose glyph
        indices (Unicode values) are listed in the array glyphs for the
        given font pub. If the glyphs were added to the X Render
        extension, Xft removes those using XRenderFreeGlyphs().
        Xft keeps track of the amount of memory used for glyphs, and
        updates the usage associated with the display dpy.

  

  
FT_Face XftLockFace (

  

    
	XftFont	*pub);


    
If no FreeType 2 “face” (in-memory
        representation of a given typeface in a given style) has been created
        for the pub font, create one using FT_New_Face().
        Face-locks are a reference count used by Xft to ensure that only
        one face is created, and that it is retained until the font is no longer
        used.

  





  

  
Face-locking is used directly in XftCharIndex() and
      XftFontLoadGlyphs(), which in turn are used in many functions of
      Xft.

  

  
Face-locking was introduced in version 1 (October 2002). A few
      applications, such as Gdk/Gimp relied upon these functions. In version
      2.1.9 (June 2006), face-locking was retained as part of the public API
      when improved shared-library configurations provided for hiding private
      symbols.

        “face” associated with the font.

DEBUGGING


Xft reads the environment variable XFT_DEBUG and
    converts that to an integer. Each bit in the resulting value tells
    Xft to print debugging information to the standard output:



  
1

  
font-opening

  
2

  
additional font-matching and opening (verbose)

  
4

  
shows details about the XRenderPictFormat which will be used.

  
8

  
shows the string which XftDrawString8() will draw.

  
16

  
shows which font-ids are matched.

  
32

  
shows useful information about the glyphs which will be drawn

  
64

  
shows an ASCII-art representation of the glyphs.

  
128

  
shows details about the memory-cache management

  
256

  
shows details about managing glyph cached-memory

  
512

  
shows a report on memory-usage

  
1024

  
shows details on extended management of glyph cached-memory
