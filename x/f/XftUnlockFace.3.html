NOM

Xft - bibliothèque d'interface X FreeType

SYNTAXE

#include <X11/Xft/Xft.h>

DESCRIPTION

Xft est une bibliothèque simple qui dessine du texte et des graphiques :

  • en utilisant les informations fournies par la bibliothèque Fontconfig,
  • Xft convertit les glyphes de polices en utilisant le rasterizer FreeType, et
  • affiche les données de polices converties en utilisant l'extension de rendu X.

Cette page de manuel effleure à peine cette bibliothèque.

CONSTANTES

XFT_MAJOR
est le numéro de version majeure de Xft.
XFT_MINOR
est le numéro de version mineure de Xft.
XFT_REVISION
est le numéro de révision de Xft.
XFT_VERSION
est XFT_MAJOR multiplié par 10000 (dix mille), plus XFT_MINOR multiplié par 100, plus XFT_REVISION.
XftVersion
est un alias pour XFT_VERSION.

L'exemple suivant illustre comment les constantes de version de Xft pourraient être utilisées : 

    #if (XFT_VERSION >= 20107)
    (void) puts("Version 2.1.7 ou ultérieure de la bibliothèque Xft est en"
                " cours d'utilisation.");
    #else
    (void) printf("Version insuffisante de Xft (%d.%d.%d) installée ;"
                  " besoin d'au moins la version 2.1.7.\n", XFT_MAJOR,
                  XFT_MINOR,
                  XFT_REVISION);
    #endif

TYPES DE DONNÉES

Les types de données Xft suivent une convention de nommage, préfixant tous les noms par “Xft”

Depuis Xlib...

Les types de données Xlib ne suivent pas de convention de nommage. Ils sont documentés dans Xlib - C Language Interface.

Xft utilise ces noms : Bool, Colormap, Display, Drawable, Pixmap, Region, Visual, et XRectangle.

Certains types de données sont particulièrement pertinents pour Xft :

Drawable
Déclaré dans <X11/X.h>, c'est un ID de ressource X, par exemple, une fenêtre associée à un affichage. Les fenêtres et les pixmaps peuvent être utilisés comme sources et destinations dans les opérations graphiques. Ces fenêtres et pixmaps sont collectivement connus sous le nom de drawables. Cependant, une fenêtre InputOnly ne peut pas être utilisée comme source ou destination dans une opération graphique.
Region
Déclaré dans <X11/Xutil.h> et <X11/Xregion.h>, une Region est un ensemble arbitraire d'emplacements de pixels que Xlib peut manipuler. Internelement, une Region est représentée par l'union d'un nombre arbitraire de rectangles. Xlib maintient un rectangle qui lui indique l'étendue de cette union.
Visual
Déclaré dans <X11/Xutil.h>, cette structure contient des informations sur le mappage de couleurs possible.

Depuis XRender...

Les types de données de la bibliothèque X Render Extension sont inspirés de Xlib, mais manquent de la documentation correspondante. Référez-vous au fichier d'en-tête pour les détails :

<X11/extensions/Xrender.h>

ou lisez le code source (qui fournit un aperçu de libXrender).

Xft utilise ces noms : Picture, XGlyphInfo, XRenderColor.

Depuis Fontconfig...

Les types de données Fontconfig suivent une convention de nommage, préfixant tous les noms par “Fc” qui sont documentés dans le Fontconfig Developers Reference.

Xft utilise ces noms Fontconfig : FcBool, FcChar8, FcChar16, FcChar32, FcCharSet, FcEndian, FcFontSet, FcPattern, et FcResult.

Depuis FreeType 2...

Les types de données FreeType 2 suivent une convention de nommage, préfixant tous les noms par “FT_” qui sont documentés dans le FreeType API Reference.

Xft utilise ces noms : FT_Face, FT_Library, et FT_UInt.

FreeType 2 utilise FT_UInt (un entier non signé) pour représenter des glyphes.

XftFont


typedef struct _XftFont {
	int	 ascent;
	int	 descent;
	int	 height;
	int	 max_advance_width;
	FcCharSet	*charset;
	FcPattern	*pattern;
} XftFont;

Un XftFont est la structure de données principale d'intérêt pour les programmeurs utilisant Xft ; il contient des métriques générales de police et des pointeurs vers l'ensemble de caractères Fontconfig et le motif associés à la police.

Les XftFont sont peuplés par l'une des fonctions XftFontOpen(), XftFontOpenName(), XftFontOpenXlfd(), XftFontOpenInfo(), ou XftFontOpenPattern(). XftFontCopy() est utilisé pour dupliquer les XftFont, et XftFontClose() est utilisé pour marquer un XftFont comme non utilisé. Les XftFont sont alloués en interne, comptés par référence, et libérés par Xft ; le programmeur n'a pas besoin normalement d'allouer ou de libérer de l'espace pour eux.

XftDrawGlyphs(), la famille XftDrawString*(), XftDrawCharSpec(), et XftDrawGlyphSpec() utilisent les XftFont pour rendre du texte à un objet XftDraw, qui peut correspondre à un drawable X de base ou à un drawable d'extension de rendu X.

XftGlyphExtents() et la famille XftTextExtents*() sont utilisés pour déterminer les étendues (dimensions maximales) d'un XftFont.

La couverture des glyphes ou des caractères d'un XftFont peut être déterminée avec XftFontCheckGlyph() ou XftCharExists(). XftCharIndex() retourne l'index de caractère spécifique à XftFont correspondant à un point de code Unicode donné.

XftGlyphRender(), XftGlyphSpecRender(), XftCharSpecRender(), et la famille XftTextRender*() utilisent les XftFont pour dessiner dans des structures Picture de l'extension de rendu X.

Note : XftDrawGlyphs(), la famille XftDrawString*(), XftDrawCharSpec(), et XftDrawGlyphSpec() fournissent un moyen de rendu des polices qui est indépendant de la disponibilité de l'extension de rendu X sur le serveur X.

XftFontInfo

est un objet opaque qui stocke des informations sur une police. Les structures XftFontInfo sont créées avec XftFontInfoCreate(), libérées avec XftFontInfoDestroy(), et comparées avec XftFontInfoEqual(). Les objets XftFontInfo sont alloués et libérés en interne par Xft ; le programmeur n'a pas besoin normalement d'allouer ou de libérer de l'espace pour eux.

Chaque structure XftFontInfo en cours d'utilisation est associée à un identifiant unique, qui peut être récupéré avec XftFontInfoHash(). Un XftFont peut être ouvert sur la base des données XftFontInfo avec XftFontOpenInfo().

XftColor


typedef struct _XftColor {
	unsigned long	 pixel;
	XRenderColor	 color;
} XftColor;

Un objet XftColor permet de rendre du texte et d'autres éléments dans une couleur particulière (ou la meilleure approximation offerte par le visual X utilisé).

XftColorAllocName() et XftColorAllocValue() demandent une allocation de couleur au serveur X (si nécessaire) et initialisent les membres de XftColor. XftColorFree() demande au serveur X de libérer la couleur actuellement allouée pour un XftColor.

Une fois qu'un XftColor a été initialisé, XftDrawSrcPicture(), XftDrawGlyphs(), la famille XftDrawString*(), XftDrawCharSpec(), XftDrawCharFontSpec(), XftDrawGlyphSpec(), XftDrawGlyphFontSpec(), et XftDrawRect() peuvent être utilisés pour dessiner divers objets en l'utilisant.

XftDraw

est un objet opaque qui contient les informations utilisées pour rendre sur un dessin X en utilisant soit le protocole de base, soit l'extension X Rendering.

Les objets XftDraw sont créés avec l'une des fonctions XftDrawCreate() (qui associe un XftDraw à un dessin X existant), XftDrawCreateBitmap() ou XftDrawCreateAlpha(), et détruits avec XftDrawDestroy(). Le dessin X associé à un XftDraw peut être modifié avec XftDrawChange(). Les objets XftDraw sont alloués et libérés en interne par Xft; le programmeur n'a pas besoin d'allouer ou de libérer de mémoire pour eux en temps normal.

Les propriétés Display, Drawable, Colormap et Visual d'un XftDraw peuvent être interrogées avec respectivement XftDrawDisplay(), XftDrawDrawable(), XftDrawColormap(), et XftDrawVisual().

Plusieurs fonctions utilisent des objets XftDraw: XftDrawCharFontSpec(), XftDrawCharSpec(), XftDrawGlyphFontSpec(), XftDrawGlyphSpec(), XftDrawGlyphs(), XftDrawRect(), XftDrawSetClip(), XftDrawSetClipRectangles(), XftDrawSetSubwindowMode(), et la famille XftDrawString*().

Le Picture de l'extension X Rendering associé à un XftDraw est retourné par XftDrawPicture() et XftDrawSrcPicture(). Il est utilisé par XftCharFontSpecRender(), XftCharSpecRender(), XftGlyphFontSpecRender(), XftGlyphRender(), XftGlyphSpecRender(), et la famille XftTextRender*().

FONCTIONS

Initialisation

Une application typique utilisant Xft n'initialise pas explicitement la bibliothèque. Ceci est généralement fait comme effet secondaire de l'ouverture d'une police.

Lorsque Xft s'initialise, il collecte des informations sur l'affichage et stocke certaines de ces informations dans un modèle Fontconfig (essentiellement une collection de propriétés avec des valeurs typées). L'application appelante peut modifier ce modèle pour changer le comportement de la bibliothèque.

Toutes les informations collectées ne sont pas stockées dans un modèle. Le reste est stocké dans des structures de données internes. Xft rend certaines de ces informations disponibles à l'application via des fonctions.

Bool XftDefaultHasRender (
	Display	*dpy);

Obtient les informations sur l'affichage dpy si ce n'est pas déjà fait, et retourne vrai si Xft a constaté que l'affichage prend en charge l'extension X Render, et s'il est capable de trouver un XRenderPictFormat approprié (le type de données de X Render qui est analogue au Visual de Xlib) sur l'affichage.

Bool XftDefaultSet (
	Display	*dpy,
	FcPattern	*defaults);

Obtient les informations sur l'affichage dpy si ce n'est pas déjà fait, et définit le modèle Fontconfig contenant les propriétés par défaut que Xft utilisera pour cet affichage.

Xft utilise ces propriétés initialement pour obtenir les limites suivantes :
XFT_MAX_GLYPH_MEMORY
(maxglyphmemory). C'est la quantité maximale de mémoire de glyphes pour toutes les polices utilisées par Xft (par défaut : 4*1024*1024).
XFT_MAX_UNREF_FONTS
(maxunreffonts). C'est le nombre maximal de polices non référencées (par défaut : 16).
XFT_TRACK_MEM_USAGE
(trackmemusage). Lorsqu'il est vrai, Xft suit l'utilisation de la mémoire des glyphes pour améliorer les performances lors de la décision de ce qu'il faut décharger lorsque la quantité maximale de mémoire des glyphes est atteinte (par défaut : faux).
Xft utilise également ces propriétés par défaut dans XftDefaultSubstitute().
void XftDefaultSubstitute (
	Display	*dpy,
	int	 screen,
	FcPattern	*pattern);

Xft remplit les propriétés manquantes dans le pattern donné en utilisant les propriétés par défaut pour l'affichage spécifié dpy, par exemple tel que défini dans XftDefaultSet().

Les applications Xft typiques utilisent cette fonction pour aider Fontconfig à choisir une police appropriée. Ces propriétés sont substituées avant d'appeler FcDefaultSubstitute():
FC_ANTIALIAS
Vrai si FreeType doit utiliser l'anticrénelage (par défaut : Faux). (par défaut : Vrai).
FC_AUTOHINT
Vrai si FreeType doit utiliser l'autohinting (par défaut : Faux).
FC_DPI
Points/pouce utilisés pour la résolution (par défaut : calculé à partir de la hauteur de l'affichage).
FC_EMBOLDEN
Vrai si FT_GlyphSlot_Embolden() doit être utilisé pour épaissir une police (par défaut : Faux).
FC_HINTING
Vrai si le hinting doit être utilisé lors du remplissage des propriétés pour ouvrir une police (par défaut : Vrai).
FC_HINT_STYLE
Style de hinting utilisé lors du remplissage des propriétés pour ouvrir une police (par défaut : FC_HINT_FULL).
FC_LCD_FILTER
Paramètre passé à FT_Library_SetLcdFilter() lors du chargement des glyphes (par défaut : FC_LCD_DEFAULT).
FC_MINSPACE
Espace minimum utilisé lors du remplissage des propriétés pour ouvrir une police (par défaut : Faux).
FC_RGBA
Valeur RGBA utilisée lors du remplissage des propriétés pour ouvrir une police (par défaut : calculée en appelant XRenderQuerySubpixelOrder()).
FC_SCALE
Facteur d'échelle utilisé dans Fontconfig (par défaut : 1.0).
XFT_MAX_GLYPH_MEMORY
Mémoire maximale pour une police (par défaut : 1024*1024).
XFT_RENDER
Vrai si l'affichage prend en charge l'extension X Render (par défaut : résultat de XftDefaultHasRender()).
FcBool XftInit (
	_Xconst char	*config);

Initialise la bibliothèque Fontconfig (appelant FcInit()).

Le paramètre config n'est pas utilisé.
Xft ne désinitialise pas la bibliothèque Fontconfig lorsqu'elle a terminé.
FcBool XftInitFtLibrary (void);

    
Initialise la bibliothèque FreeType (appelant
        FT_Init_FreeType() pour créer un objet bibliothèque) si elle n'a pas déjà été initialisée. Ceci est nécessaire avant d'utiliser la bibliothèque FreeType pour lire les données de police à partir d'un fichier.

  





  

  
Xft appelle XftInitFtLibrary() en interne via
      XftFontInfoCreate() et XftFontOpenPattern().

  

  
Xft ne supprime pas l'objet bibliothèque (par exemple, en utilisant
      FT_Done_FreeType()) lorsqu'il a terminé.

Ouverture et Correspondance des Polices



  
XftFont *XftFontOpen (

  

    
	Display	*dpy,
	int	 screen,
	...);


    
XftFontOpen prend une liste de triplets d'éléments de modèle de la forme
        champ, type, valeur (terminée par un
        NULL), fait correspondre ce modèle aux polices disponibles, et ouvre la
        police correspondante, en la dimensionnant correctement pour l'écran numéro screen sur l'affichage dpy. Retourne la police correspondante, ou NULL si aucune correspondance n'est trouvée.

  




Exemple :
  




    font = XftFontOpen (dpy, screen,
                        XFT_FAMILY, XftTypeString, "charter",
                        XFT_SIZE, XftTypeDouble, 12.0,
                        NULL);




  

  
Ceci ouvre la police “charter” à 12 points. La taille en points
      est automatiquement convertie en la taille en pixels correcte en fonction de la
      résolution de l'écran.





  
XftFont *XftFontOpenName (

  

    
	Display	*dpy,
	int	 screen,
	_Xconst char	*name);


    
XftFontOpenName se comporte comme 

XftFontOpen,
        sauf qu'il prend une chaîne de caractères de modèle Fontconfig (qui est passée à
        la fonction FcNameParse() de la bibliothèque Fontconfig).

  

  
XftFont *XftFontOpenXlfd (

  

    
	Display	*dpy,
	int	 screen,
	_Xconst char	*xlfd)


    
XftFontOpenXlfd se comporte comme XftFontOpen,
        sauf qu'il prend une chaîne contenant une description de police logique X
        (XLFD) et utilise la fonction XftXlfdParse().

  

  
FcPattern *XftFontMatch (

  

    
	Display	*dpy,
	int	 screen,

	FcResult	*result);


    
Également utilisée en interne par les fonctions
        XftFontOpen*, XftFontMatch peut également être utilisée

        demande d'ouverture de police Xft.

  

  
FcPattern *XftXlfdParse (

  

    
	_Xconst char	*xlfd_orig,
	Bool	ignore_scalable,
	Bool	complete);


    
XftXlfdParse analyse le paramètre xlfd_orig
        conformément au document Conventions de description de polices logiques X,
        mais ignore certains champs : setwidth_name,
        add_style_name, spacing et average_width.

  





  

  
XftXlfdParse crée un modèle Fontconfig, définit la propriété
      XFT_XLFD à la valeur xlfd_orig et mappe les informations
      collectées aux propriétés Fontconfig. Les champs vides ou contenant « * »
      sont ignorés :







  
FC_FOUNDRY

  
depuis foundry.

  
FC_FAMILY

  
depuis family.

  
FC_WEIGHT

  
weight_name, par défaut FC_WEIGHT_MEDIUM.

  
FC_SLANT

  
depuis slant, par défaut FC_SLANT_ROMAN.

  
FC_SIZE

  
depuis point_size.

  
FC_PIXEL_SIZE

  
depuis pixel_size. Si point_size a été défini, ainsi que
      resolution_x et resolution_y, alors la valeur est mise à
      l'échelle pour convertir la hauteur de la police en points.

Gestion   de XftColor



  
Bool XftColorAllocName (

  

    
	Display	*dpy,
	_Xconst Visual	*visual,
	Colormap	 cmap,
	_Xconst char	*name,
	XftColor	*result);


    
Utilise XAllocNamedColor() pour rechercher la couleur nommée
        name pour l'écran associé à la palette de couleurs cmap.

  






    
  
  • Si XAllocNamedColor() retourne une valeur non nulle,
      XftColorAllocName() remplit le champ pixel résultant de
      XftColor avec la couleur la plus proche supportée par l'écran, ainsi
      que les champs rouge, vert et bleu exacts de la base de données, et retourne
      True.
    • 
  
  • Si XAllocNamedColor() retourne zéro, XftColorAllocName()
      retourne False et ne modifie pas le XftColor référencé par
      result.
    • 






  

  
Le paramètre visual n'est pas utilisé.





  
Bool XftColorAllocValue (

  

    
	Display	*dpy,
	Visual	*visual,
	Colormap	 cmap,
	_Xconst XRenderColor	*color,
	XftColor	*result);


    
Alloue une valeur de couleur :

  






    
  
  • Si la classe du visual est TrueColor, XftColorAllocValue()
      définit le champ pixel dans le XftColor référencé par
      result en utilisant les champs rouge, vert et bleu du paramètre
      color.
    • 
  
  • Si la classe du visual n'est pas TrueColor, XftColorAllocValue()
      appelle XAllocColor() pour allouer une entrée dans la palette de
      couleurs cmap. qui retourne la valeur de pixel de la couleur la plus
      proche des éléments RVB spécifiés supportés par le matériel.
    • 




  

  
Si XAllocColor() réussit, XftColorAllocValue() stocke cette
      valeur de pixel dans le XRenderColor référencé par result et
      retourne True.

  

  
Si XAllocColor() échoue, XftColorAllocValue() retourne False
      et ne modifie pas le résultat.







  
void XftColorFree (

  

    
	Display	*dpy,

Si la classe du visual n'est pas TrueColor, Xft appelle

        cmap dont la valeur de pixel dans le paramètre color a été

void XftGlyphFontSpecRender (

  

    
	Display	*dpy,
	int	 op,
	Picture	 src,
	Picture	 dst,
	int	 srcx,
	int	 srcy,
	_Xconst XftGlyphFontSpec	*glyphs,
	int	 nglyphs);


    
Cela implique plusieurs étapes :

  






    
  
  • Premièrement, Xft s'assure que le tableau glyphs est complet
      en utilisant XftFontCheckGlyph() et en chargeant les glyphes
      manquants avec XftFontLoadGlyphs().
    • 
  
  • Ensuite, Xft examine les glyphes pour trouver la valeur Unicode
      maximale. Cela détermine la taille de l'encodage, c'est-à-dire la
      largeur.
    • 
  
  • Ensuite, pour chaque glyphe, Xft vérifie si sa valeur Unicode est
      gérée par la police correspondante. Sinon, la valeur est définie à zéro
      (0), pour l'ignorer. Tout en faisant cela, Xft se souvient également
      de la première police utilisée et calcule la position à laquelle chaque
      glyphe sera dessiné.
    • 
  
  • Xft construit ensuite un tableau équivalent de glyphes dans le format
      attendu par la bibliothèque X Render.
    • 
  
  • Enfin, XftGlyphFontSpecRender() utilise l'extension X Render pour
      dessiner les glyphes, avec la fonction XRenderCompositeText*()
      appropriée selon la largeur, et écarte les données temporaires.
    • 




  

  
Les paramètres op, dst, src, srcx et
      srcy sont utilisés comme décrit dans la documentation de la
      bibliothèque X Render.
