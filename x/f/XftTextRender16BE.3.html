NOM

Xft - bibliothèque d'interface X FreeType

SYNOPSIS

#include <X11/Xft/Xft.h>

DESCRIPTION

Xft est une bibliothèque simple qui dessine du texte et des graphiques :

  • en utilisant les informations fournies par la bibliothèque Fontconfig,
  • Xft convertit les glyphes de polices en utilisant le rasteriseur FreeType, et
  • affiche les données de polices converties en utilisant l'extension X Rendering Extension.

Cette page de manuel ne fait qu'effleurer la surface de cette bibliothèque.

CONSTANTES

XFT_MAJOR
est le numéro de version majeure de Xft.
XFT_MINOR
est le numéro de version mineure de Xft.
XFT_REVISION
est le numéro de révision de Xft.
XFT_VERSION
est XFT_MAJOR multiplié par 10000 (dix mille), plus XFT_MINOR multiplié par 100, plus XFT_REVISION.
XftVersion
est un alias pour XFT_VERSION.

L'exemple suivant illustre comment les constantes de version de Xft pourraient être utilisées : 

    #if (XFT_VERSION >= 20107)
    (void) puts("Version 2.1.7 ou ultérieure de la bibliothèque Xft est en"
                " cours d'utilisation.");
    #else
    (void) printf("Version insuffisante de Xft (%d.%d.%d) installée ;"
                  " besoin d'au moins la version 2.1.7.\n", XFT_MAJOR,
                  XFT_MINOR,
                  XFT_REVISION);
    #endif

TYPES DE DONNÉES

Les types de données Xft suivent une convention de nommage, préfixant tous les noms par "Xft"

Depuis Xlib...

Les types de données Xlib ne suivent pas une convention de nommage. Ils sont documentés dans Xlib - C Language Interface.

Xft utilise ces noms : Bool, Colormap, Display, Drawable, Pixmap, Region, Visual, et XRectangle.

Certains types de données sont particulièrement pertinents pour Xft :

Drawable
Déclaré dans <X11/X.h>, c'est un ID de ressource X, par ex. une fenêtre associée à un affichage. Les fenêtres et les pixmaps peuvent être utilisés comme sources et destinations dans les opérations graphiques. Ces fenêtres et pixmaps sont collectivement connus sous le nom de drawables. Cependant, une fenêtre **InputOnly** ne peut pas être utilisée comme source ou destination dans une opération graphique.
Region
Déclaré dans <X11/Xutil.h> et <X11/Xregion.h>, une Region est un ensemble arbitraire d'emplacements de pixels que Xlib peut manipuler. Internelement, une Region est représentée par l'union d'un nombre arbitraire de rectangles. Xlib maintient un rectangle qui indique l'étendue de cette union.
Visual
Déclaré dans <X11/Xutil.h>, cette structure contient des informations sur le mappage de couleurs possible.

Depuis XRender...

Les types de données de la bibliothèque X Render Extension sont inspirés de Xlib, mais ne disposent pas de la documentation correspondante. Référez-vous au fichier d'en-tête pour des détails :

<X11/extensions/Xrender.h>

ou lisez le code source (qui fournit un aperçu de libXrender).

Xft utilise ces noms : Picture, XGlyphInfo, XRenderColor.

Depuis Fontconfig...

Les types de données Fontconfig suivent une convention de nommage, préfixant tous les noms par "Fc", qui sont documentés dans le Guide de référence des développeurs Fontconfig.

Xft utilise ces noms Fontconfig : FcBool, FcChar8, FcChar16, FcChar32, FcCharSet, FcEndian, FcFontSet, FcPattern, et FcResult.

Depuis FreeType 2...

Les types de données FreeType 2 suivent une convention de nommage, préfixant tous les noms par "FT_", qui sont documentés dans le Guide de référence de l'API FreeType.

Xft utilise ces noms : FT_Face, FT_Library, et FT_UInt.

FreeType 2 utilise FT_UInt (un entier non signé) pour représenter les *caractères*.

XftFont


typedef struct _XftFont {
	int	 ascent;
	int	 descent;
	int	 height;
	int	 max_advance_width;
	FcCharSet	*charset;
	FcPattern	*pattern;
} XftFont;

Un XftFont est la structure de données principale d'intérêt pour les programmeurs utilisant Xft ; il contient des métriques générales de police et des pointeurs vers l'ensemble de caractères Fontconfig et le modèle associé à la police.

Les XftFont sont remplis par XftFontOpen(), XftFontOpenName(), XftFontOpenXlfd(), XftFontOpenInfo(), ou XftFontOpenPattern(). XftFontCopy() est utilisé pour dupliquer les XftFont, et XftFontClose() est utilisé pour marquer un XftFont comme inutilisé. Les XftFont sont alloués en interne, comptés par référence et libérés par Xft ; le programmeur n'a pas besoin normalement d'allouer ou de libérer de l'espace pour eux.

XftDrawGlyphs(), la famille XftDrawString*(), XftDrawCharSpec(), et XftDrawGlyphSpec() utilisent les XftFont pour rendre du texte dans un objet XftDraw, qui peut correspondre soit à un drawable X de base, soit à un drawable X Rendering Extension.

XftGlyphExtents() et la famille XftTextExtents*() sont utilisés pour déterminer les extents (dimensions maximales) d'un XftFont.

La couverture de glyphes ou de caractères d'un XftFont peut être déterminée avec XftFontCheckGlyph() ou XftCharExists(). XftCharIndex() retourne l'index de caractère spécifique à XftFont correspondant à un point de code Unicode donné.

XftGlyphRender(), XftGlyphSpecRender(), XftCharSpecRender(), et la famille XftTextRender*() utilisent les XftFont pour dessiner dans des structures Picture de X Rendering Extension.

Note : XftDrawGlyphs(), la famille XftDrawString*(), XftDrawCharSpec(), et XftDrawGlyphSpec() fournissent un moyen de rendre les polices qui est indépendant de la disponibilité de l'extension X Rendering Extension sur le serveur X.

XftFontInfo

est un objet opaque qui stocke des informations sur une police. Les structures XftFontInfo sont créées avec XftFontInfoCreate(), libérées avec XftFontInfoDestroy(), et comparées avec XftFontInfoEqual(). Les objets XftFontInfo sont alloués et libérés en interne par Xft ; le programmeur n'a pas besoin normalement d'allouer ou de libérer de l'espace pour eux.

Chaque structure XftFontInfo en cours d'utilisation est associée à un identifiant unique, qui peut être récupéré avec XftFontInfoHash(). Un XftFont peut être ouvert sur la base des données XftFontInfo avec XftFontOpenInfo().

XftColor


typedef struct _XftColor {
	unsigned long	 pixel;

} XftColor;

XftDraw

est un objet opaque qui contient les informations utilisées pour le rendu vers un objet drawable X en utilisant soit le protocole de base, soit l'extension X Rendering.

Les objets XftDraw sont créés avec l'une des fonctions XftDrawCreate() (qui associe un XftDraw à un objet drawable X existant), XftDrawCreateBitmap(), ou XftDrawCreateAlpha(), et détruits avec XftDrawDestroy(). L'objet drawable X associé à un XftDraw peut être modifié avec XftDrawChange(). Les objets XftDraw sont alloués et libérés en interne par Xft ; le programmeur n'a généralement pas besoin d'allouer ou de libérer de la mémoire pour eux.

Les propriétés Display, Drawable, Colormap et Visual X d'un XftDraw peuvent être interrogées avec XftDrawDisplay(), XftDrawDrawable(), XftDrawColormap(), et XftDrawVisual(), respectivement.

Plusieurs fonctions utilisent des objets XftDraw : XftDrawCharFontSpec(), XftDrawCharSpec(), XftDrawGlyphFontSpec(), XftDrawGlyphSpec(), XftDrawGlyphs(), XftDrawRect(), XftDrawSetClip(), XftDrawSetClipRectangles(), XftDrawSetSubwindowMode(), et la famille XftDrawString*().

L'extension X Rendering Picture associée à un XftDraw est retournée par XftDrawPicture() et XftDrawSrcPicture(). Elle est utilisée par XftCharFontSpecRender(), XftCharSpecRender(), XftGlyphFontSpecRender(), XftGlyphRender(), XftGlyphSpecRender(), et la famille XftTextRender*().

FONCTIONS

Initialisation

Une application typique utilisant Xft n'initialise pas explicitement la bibliothèque. Cela se fait généralement comme effet secondaire de l'ouverture d'une police.

Lorsque Xft s'initialise, il collecte des informations sur l'affichage et stocke certaines de ces informations dans un modèle Fontconfig (essentiellement une collection de propriétés avec des valeurs typées). L'application appelante peut modifier ce modèle pour changer le comportement de la bibliothèque.

Toutes les informations collectées ne sont pas stockées dans un modèle. Le reste est stocké dans des structures de données internes. Xft met certaines de ces informations à la disposition de l'application via des fonctions.

Bool XftDefaultHasRender (
	Display	*dpy);

Obtient des informations sur l'affichage dpy si cela n'a pas déjà été fait, et retourne vrai si Xft a constaté que l'affichage prend en charge l'extension X Render, et s'il est capable de trouver un XRenderPictFormat approprié (le type de données de X Render qui est analogue au Visual de Xlib) sur l'affichage.

Bool XftDefaultSet (
	Display	*dpy,
	FcPattern	*defaults);

Obtient des informations sur l'affichage dpy si cela n'a pas déjà été fait, et définit le modèle Fontconfig contenant les propriétés par défaut que Xft utilisera pour cet affichage.

Xft utilise ces propriétés initialement pour obtenir les limites suivantes :
XFT_MAX_GLYPH_MEMORY
(maxglyphmemory). Il s'agit de la quantité maximale de mémoire de glyphes pour toutes les polices utilisées par Xft (par défaut : 4*1024*1024).
XFT_MAX_UNREF_FONTS
(maxunreffonts). Il s'agit du nombre maximum de polices non référencées (par défaut : 16).
XFT_TRACK_MEM_USAGE
(trackmemusage). Lorsque vrai, Xft suit l'utilisation de la mémoire des glyphes pour améliorer les performances lors de la décision de ce qu'il faut décharger lorsque la quantité maximale de mémoire des glyphes est atteinte (par défaut : faux).
Xft utilise également ces propriétés par défaut dans XftDefaultSubstitute().
void XftDefaultSubstitute (
	Display	*dpy,
	int	 screen,
	FcPattern	*pattern);

Xft remplit les propriétés manquantes dans le pattern donné en utilisant les propriétés par défaut pour l'affichage spécifié dpy, par exemple tel que défini dans XftDefaultSet().

Les applications Xft typiques utilisent cette fonction pour aider Fontconfig à choisir une police appropriée. Ces propriétés sont substituées avant d'appeler FcDefaultSubstitute() :
FC_ANTIALIAS
Vrai si FreeType doit utiliser l'anti-crénelage (par défaut : Faux). (par défaut : Vrai).
FC_AUTOHINT
Vrai si FreeType doit utiliser l'autohinting (par défaut : Faux).
FC_DPI
Points/pouce utilisés pour la résolution (par défaut : calculé à partir de la hauteur de l'affichage).
FC_EMBOLDEN
Vrai si FT_GlyphSlot_Embolden() doit être utilisé pour épaissir une police (par défaut : Faux).
FC_HINTING
Vrai si le hinting doit être utilisé lors du remplissage des propriétés pour ouvrir une police (par défaut : Vrai).
FC_HINT_STYLE
Style de hinting utilisé lors du remplissage des propriétés pour ouvrir une police (par défaut : FC_HINT_FULL).
FC_LCD_FILTER
Paramètre passé à FT_Library_SetLcdFilter() lors du chargement des glyphes (par défaut : FC_LCD_DEFAULT).
FC_MINSPACE
Valeur minimale d'espace utilisée lors du remplissage des propriétés pour ouvrir une police (par défaut : Faux).
FC_RGBA
Valeur RGBA utilisée lors du remplissage des propriétés pour ouvrir une police (par défaut : calculée en appelant XRenderQuerySubpixelOrder()).
FC_SCALE
Échelle utilisée dans Fontconfig (par défaut : 1.0).
XFT_MAX_GLYPH_MEMORY
Mémoire maximale pour une police (par défaut : 1024*1024).
XFT_RENDER
Vrai si l'affichage prend en charge l'extension X Render (par défaut : résultat de XftDefaultHasRender()).
FcBool XftInit (
	_Xconst char	*config);

Le paramètre config n'est pas utilisé.

Ouverture et Correspondance des Polices



  
XftFont *XftFontOpen (

  

    
	Display	*dpy,
	int	 screen,
	...);


    
XftFontOpen prend une liste de triplets d'éléments de modèle de la forme
        champ, type, valeur (terminée par NULL), fait correspondre ce modèle aux polices disponibles, et ouvre la police correspondante, en la dimensionnant correctement pour le numéro d'écran screen sur l'affichage dpy. Retourne la police correspondante, ou NULL si aucune correspondance n'est trouvée.

  




Exemple :
  




    font = XftFontOpen (dpy, screen,
                        XFT_FAMILY, XftTypeString, "charter",
                        XFT_SIZE, XftTypeDouble, 12.0,
                        NULL);




  

  
Ceci ouvre la police “charter” à 12 points. La taille en points est automatiquement convertie en la taille en pixels correcte en fonction de la résolution du moniteur.

Gestion des XftColor




Bool XftColorAllocName (




	Display	*dpy,
	_Xconst Visual	*visual,
	Colormap	 cmap,
	_Xconst char	*name,
	XftColor	*result);



Utilise XAllocNamedColor() pour rechercher la couleur nommée
name pour l'écran associé à la palette de couleurs cmap.








    

  • Si XAllocNamedColor() retourne une valeur non nulle,
XftColorAllocName() remplit le champ pixel XftColor résultant
avec la couleur la plus proche supportée par l'écran, ainsi que les champs
rouge, vert et bleu exacts de la base de données, et retourne True.
    • 

  • Si XAllocNamedColor() retourne zéro, XftColorAllocName()
retourne False, et ne met pas à jour le XftColor référencé par
result.
    • 









Le paramètre visual n'est pas utilisé.






Bool XftColorAllocValue (




	Display	*dpy,
	Visual	*visual,
	Colormap	 cmap,
	_Xconst XRenderColor	*color,
	XftColor	*result);



Alloue une valeur de couleur :








    

  • Si la classe visual est TrueColor, XftColorAllocValue() définit
le champ pixel dans le XftColor référencé par result en
utilisant les champs rouge, vert et bleu du paramètre color.
    • 

  • Si la classe visual n'est pas TrueColor, XftColorAllocValue()
appelle XAllocColor() pour allouer une entrée dans la palette de couleurs
cmap, qui retourne la valeur pixel de la couleur la plus proche des
éléments RVB spécifiés supportés par le matériel.
    • 







Si XAllocColor() réussit, XftColorAllocValue() stocke cette
valeur pixel dans le XRenderColor référencé par result et
retourne True.




Si XAllocColor() échoue, XftColorAllocValue() retourne False et
ne modifie pas le résultat.








void XftColorFree (




	Display	*dpy,
	Visual	*visual,
	Colormap	 cmap,
	XftColor	*color);



Si la classe visual n'est pas TrueColor, Xft appelle
XFreeColors() pour libérer l'entrée de la palette de couleurs cmap
dont la valeur pixel dans le paramètre color a été allouée par
XftColorAllocName().

Dessine une liste de gliphes associés à des polices à des

        structures XftGlyphFontSpec via le paramètre glyphs. Tous
        les gliphes sont dessinés en utilisant la couleur spécifiée dans le

      XftGlyphFontSpecRender() pour dessiner le gliphe, en utilisant une

void XftGlyphFontSpecRender (

  

    
	Display	*dpy,
	int	 op,
	Picture	 src,
	Picture	 dst,
	int	 srcx,
	int	 srcy,
	_Xconst XftGlyphFontSpec	*glyphs,
	int	 nglyphs);


    
Cela implique plusieurs étapes :

  






    
  
  • Premièrement, Xft s'assure que le tableau glyphs est complet
      en utilisant XftFontCheckGlyph() et en chargeant les gliphes
      manquants avec XftFontLoadGlyphs().
    • 
  
  • Ensuite, Xft examine les gliphes pour trouver la valeur Unicode
      maximale. Cela détermine la taille de l'encodage, c'est-à-dire la
      largeur.
    • 
  
  • Ensuite, pour chaque gliphe, Xft vérifie si sa valeur Unicode est
      prise en charge par la police correspondante. Sinon, la valeur est définie
      sur zéro (0), pour l'ignorer. Pendant ce processus, Xft se souvient
      également de la première police utilisée et calcule la position à laquelle
      chaque gliphe sera dessiné.
    • 
  
  • Xft construit ensuite un tableau équivalent de gliphes dans le format
      attendu par la bibliothèque X Render.
    • 
  
  • Enfin, XftGlyphFontSpecRender() utilise l'extension X Render pour
      dessiner les gliphes, avec la fonction XRenderCompositeText*()
      appropriée en fonction de la largeur, et abandonne les données
      temporaires.
    • 




  

  
Les paramètres op, dst, src, srcx et
      srcy sont utilisés comme décrit dans la documentation de la
      bibliothèque X Render.

NAME


XftTextRender16BE, XftTextRender16LE, XftTextRender32BE, XftTextRender32LE - render strings using Xft






SYNOPSIS


#include <X11/Xft/Xft.h>

void XftTextRender16BE(
    Display *dpy,
    Picture src,
    XftFont *font,
    FcChar16 *string,
    int len
);

void XftTextRender16LE(
    Display *dpy,
    Picture src,
    XftFont *font,
    FcChar16 *string,
    int len
);

void XftTextRender32BE(
    Display *dpy,
    Picture src,
    XftFont *font,
    FcChar32 *string,
    int len
);

void XftTextRender32LE(
    Display *dpy,
    Picture src,
    XftFont *font,
    FcChar32 *string,
    int len
);






DESCRIPTION


These functions render strings using the Xft font library. They are part of the low-level API and are generally not used directly by applications. Instead, applications usually use higher-level functions like XftDrawString() and XftDrawString16().


The functions differ in the encoding of the input string and the byte order:



  
XftTextRender16BE

  
Renders a UTF-16 string in Big Endian byte order.

  
XftTextRender16LE

  
Renders a UTF-16 string in Little Endian byte order.

  
XftTextRender32BE

  
Renders a UTF-32 string in Big Endian byte order.

  
XftTextRender32LE

  
Renders a UTF-32 string in Little Endian byte order.




All functions take the following arguments:



  
dpy

  
The display connection.

  
src

  
The source picture to use for the text. This is typically a picture containing the desired color.

  
font

  
The XftFont structure representing the font to use for rendering.

  
string

  
A pointer to the string to be rendered.

  
len

  
The number of characters (not bytes) in the string.




Internally, these functions use XftGlyphCache() to load the necessary glyphs from the font and then use XRenderCompositeText() or related functions to draw the glyphs onto the destination drawable associated with the src picture.






CONSTANTS


No constants are directly associated with these functions.






DATA TYPES



  
FcChar16

  
An alias for unsigned short, representing a 16-bit character code, typically used for UTF-16.

  
FcChar32

  
An alias for unsigned int, representing a 32-bit character code, typically used for UTF-32.

  
XftFont

  
A structure representing an open font. It contains information about the font, including its FreeType face, metrics, and associated Fontconfig pattern.








FUNCTIONS



  
FcBool XftNameParse (

  

    
	const char	*name,
	int	 len);


    
This function is not directly related to rendering but is part of the font configuration mechanism used by Xft. It parses a font name string according to Fontconfig rules. The Xft library uses Fontconfig to manage font matching and loading. When a font name is provided, Xft calls FcNameParse() internally to convert the name into a Fontconfig pattern.

  

  
char *XftNameUnparse (

  

    
	FcPattern	*pat);


    
This function is the inverse of FcNameParse(). It converts a Fontconfig pattern back into a human-readable font name string. Xft uses this internally, for example, when reporting which font was chosen or for debugging purposes.

  

  
void XftFontLoadGlyphs (

  

    
	Display	*dpy,
	XftFont	*pub,
	FcBool	 need_bitmaps,
	_Xconst FT_UInt	*glyphs,
	int	 nglyph);


    
Loads glyph data for the specified glyph indices from the given font. It uses FreeType's FT_Load_Glyph() and interacts with the X Render extension to make the glyphs available for drawing. The need_bitmaps flag indicates whether bitmap representations of the glyphs are required.

  

  
void XftFontUnloadGlyphs (

  

    
	Display	*dpy,
	XftFont	*pub,
	_Xconst FT_UInt	*glyphs,
	int	 nglyph);


    
Unloads glyph data that was previously loaded using XftFontLoadGlyphs(). This helps in managing memory by freeing resources associated with glyphs that are no longer needed. It also interacts with the X Render extension to free the corresponding glyph sets.

  

  
FT_Face XftLockFace (

  

    
	XftFont	*pub);


    
Acquires a reference to the FreeType face object associated with the given XftFont. If the face has not been loaded yet, it is loaded using FT_New_Face(). This function increments an internal reference count to ensure the face remains valid as long as it's in use. It is crucial for managing the lifetime of font resources.

  

  
void XftUnlockFace (

  

    
	XftFont	*pub);


    
Releases a reference to the FreeType face object, decrementing the reference count. When the reference count drops to zero, the face object is destroyed using FT_Done_Face(). This function is the counterpart to XftLockFace() and is used to signal that the font face is no longer needed.

  








DEBUGGING


The behavior of Xft can be controlled via the XFT_DEBUG environment variable. Setting this variable to an integer value enables various debugging outputs to standard error. Each bit in the integer corresponds to a different debugging category:



  
1 (0x0001)

  
Font opening information.

  
2 (0x0002)

  
Verbose font matching and opening.

  
4 (0x0004)

  
Details about the XRenderPictFormat used.

  
8 (0x0008)

  
The string being drawn by XftDrawString8().

  
16 (0x0010)

  
Information about matched font IDs.

  
32 (0x0020)

  
Details about glyphs being drawn.

  
64 (0x0040)

  
ASCII art representation of glyphs.

  
128 (0x0080)

  
Details about glyph cache management.

  
256 (0x0100)

  
Details about managing cached glyph memory.

  
512 (0x0200)

  
Memory usage report.

  
1024 (0x0400)

  
Details on extended glyph cache management.




For example, to enable font opening information and glyph details, you would set XFT_DEBUG to 33 (1 + 32).






COMPATIBILITY


The Xft library aims for stability and compatibility. Version 2, released in May 2002, is considered stable, and future releases are expected to maintain source and binary compatibility.


Xft also provides a compatibility layer for applications that may still be using the older Xft 1.x API.




Xft 1.x Header File


To use the Xft 1.x compatibility features, include the following header:


#include <X11/Xft/XftCompat.h>






Xft 1.x Data Types


The following data types were part of the Xft 1.x API and are available for compatibility purposes:



  
XftPattern

  
Represents a set of font properties (name-value pairs). Used for specifying font matching criteria and for holding information about selected fonts.

  
XftFontSet

  
A collection of XftPattern structures. Internally used by Xft to manage sets of fonts and externally returned when listing available fonts.

  
XftObjectSet

  
Used to specify which font properties should be included in the XftFontSet when listing fonts.
