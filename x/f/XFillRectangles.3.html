XFillRectangles(3) FONCTIONS XLIB XFillRectangles(3)

NOM

XFillRectangle, XFillRectangles, XFillPolygon, XFillArc, XFillArcs - remplir des rectangles, polygones ou arcs

SYNTAXE

int XFillRectangle(Display *display, Drawable d, GC gc, int x, int y, unsigned int width, unsigned int height);

int XFillRectangles(Display *display, Drawable d, GC gc, XRectangle *rectangles, int nrectangles);

int XFillPolygon(Display *display, Drawable d, GC gc, XPoint *points, int npoints, int shape, int mode);

int XFillArc(Display *display, Drawable d, GC gc, int x, int y, unsigned int width, unsigned int height, int angle1, int angle2);

int XFillArcs(Display *display, Drawable d, GC gc, XArc *arcs, int narcs);

ARGUMENTS

angle1
Spécifie le début de l'arc par rapport à la position de trois heures du centre, en unités de degrés * 64.
angle2
Spécifie le chemin et l'étendue de l'arc par rapport au début de l'arc, en unités de degrés * 64.
arcs
Spécifie un tableau d'arcs.
d
Spécifie le drawable.
display
Spécifie la connexion au serveur X.
gc
Spécifie le GC.
mode
Spécifie le mode de coordonnées. Vous pouvez passer CoordModeOrigin ou CoordModePrevious.
narcs
Spécifie le nombre d'arcs dans le tableau.
npoints
Spécifie le nombre de points dans le tableau.
nrectangles
Spécifie le nombre de rectangles dans le tableau.
points
Spécifie un tableau de points.
rectangles
Spécifie un tableau de rectangles.
shape
Spécifie une forme qui aide le serveur à améliorer les performances. Vous pouvez passer Complex, Convex ou Nonconvex.
width

height
Spécifient la largeur et la hauteur, qui sont les dimensions du rectangle à remplir ou les axes majeurs et mineurs de l'arc.
x

y
Spécifient les coordonnées x et y, qui sont relatives à l'origine du drawable et spécifient le coin supérieur gauche du rectangle.

DESCRIPTION

Les fonctions XFillRectangle et XFillRectangles remplissent le rectangle ou les rectangles spécifiés comme si une requête de protocole FillPolygon à quatre points était spécifiée pour chaque rectangle :

[x,y] [x+width,y] [x+width,y+height] [x,y+height]

Chaque fonction utilise les coordonnées x et y, les dimensions de largeur et de hauteur, et le GC que vous spécifiez.

XFillRectangles remplit les rectangles dans l'ordre indiqué dans le tableau. Pour tout rectangle donné, XFillRectangle et XFillRectangles ne dessinent pas un pixel plus d'une fois. Si les rectangles s'intersectent, les pixels d'intersection sont dessinés plusieurs fois.

Les deux fonctions utilisent ces composants GC : function, plane-mask, fill-style, subwindow-mode, clip-x-origin, clip-y-origin, et clip-mask. Elles utilisent également ces composants dépendants du mode GC : foreground, background, tile, stipple, tile-stipple-x-origin, et tile-stipple-y-origin.

XFillRectangle et XFillRectangles peuvent générer des erreurs BadDrawable, BadGC et BadMatch.

XFillPolygon remplit la région fermée par le chemin spécifié. Le chemin est fermé automatiquement si le dernier point de la liste ne coïncide pas avec le premier point. XFillPolygon ne dessine pas un pixel de la région plus d'une fois. CoordModeOrigin traite toutes les coordonnées comme relatives à l'origine, et CoordModePrevious traite toutes les coordonnées après la première comme relatives au point précédent.

Selon la forme spécifiée, les actions suivantes se produisent :

  • Si shape est Complex, le chemin peut se croiser lui-même. Notez que les points identiques contigus dans le chemin ne sont pas traités comme une intersection.
  • Si shape est Convex, pour chaque paire de points à l'intérieur du polygone, le segment de droite qui les relie n'intersecte pas le chemin. Si le client le sait, spécifier Convex peut améliorer les performances. Si vous spécifiez Convex pour un chemin qui n'est pas convexe, les résultats graphiques ne sont pas définis.
  • Si shape est Nonconvex, le chemin ne se croise pas lui-même, mais la forme n'est pas entièrement convexe. Si le client le sait, spécifier Nonconvex au lieu de Complex peut améliorer les performances. Si vous spécifiez Nonconvex pour un chemin qui se croise lui-même, les résultats graphiques ne sont pas définis.

La règle de remplissage (fill-rule) du GC contrôle le comportement de remplissage des polygones qui se croisent.

Cette fonction utilise ces composants GC : function, plane-mask, fill-style, fill-rule, subwindow-mode, clip-x-origin, clip-y-origin, et clip-mask. Elle utilise également ces composants dépendants du mode GC : foreground, background, tile, stipple, tile-stipple-x-origin, et tile-stipple-y-origin.

XFillPolygon peut générer des erreurs BadDrawable, BadGC, BadMatch et BadValue.

Pour chaque arc, XFillArc ou XFillArcs remplit la région fermée par le chemin infiniment fin décrit par l'arc spécifié et, selon le mode d'arc (arc-mode) spécifié dans le GC, un ou deux segments de droite. Pour ArcChord, le segment de droite unique joignant les points finaux de l'arc est utilisé. Pour ArcPieSlice, les deux segments de droite joignant les points finaux de l'arc au point central sont utilisés. XFillArcs remplit les arcs dans l'ordre indiqué dans le tableau. Pour tout arc donné, XFillArc et XFillArcs ne dessinent pas un pixel plus d'une fois. Si les régions s'intersectent, les pixels d'intersection sont dessinés plusieurs fois.

Les deux fonctions utilisent ces composants GC : function, plane-mask, fill-style, arc-mode, subwindow-mode, clip-x-origin, clip-y-origin, et clip-mask. Elles utilisent également ces composants dépendants du mode GC : foreground, background, tile, stipple, tile-stipple-x-origin, et tile-stipple-y-origin.

XFillArc et XFillArcs peuvent générer des erreurs BadDrawable, BadGC et BadMatch.

DIAGNOSTICS

BadDrawable
Une valeur pour un argument Drawable ne nomme pas une fenêtre ou unPixmap défini.
BadGC
Une valeur pour un argument GContext ne nomme pas un GContext défini.
BadMatch
Une fenêtre InputOnly est utilisée comme Drawable.
BadMatch
Un argument ou une paire d'arguments a le bon type et la bonne plage, mais ne correspond pas d'une autre manière requise par la requête.
BadValue
Une valeur numérique se situe en dehors de la plage de valeurs acceptées par la requête. Sauf si une plage spécifique est définie pour un argument, la plage complète définie par le type de l'argument est acceptée. Tout argument défini comme un ensemble d'alternatives peut générer cette erreur.

XFillRectangles

XFillRectangles - remplit des rectangles de couleur

SYNTAXE

int XFillRectangles(Display *display, Drawable d, GC gc, const XRectangle *rectangles, int nrectangles);

ARGUMENTS

display
Spécifie la connexion au serveur X.
d
Spécifie le Drawable (une fenêtre ou une pixmap) sur lequel dessiner.
gc
Spécifie le contexte graphique à utiliser.
rectangles
Spécifie un tableau de structures XRectangle, chacune définissant un rectangle à remplir.
nrectangles
Spécifie le nombre de rectangles dans le tableau.

DESCRIPTION

La fonction XFillRectangles remplit une liste de rectangles spécifiée par le client. Les rectangles sont dessinés dans l'ordre où ils apparaissent dans le tableau. L'origine (0,0) est en haut à gauche. Les coordonnées des rectangles sont relatives au coin supérieur gauche du Drawable.

Si un rectangle est complètement ou partiellement en dehors des limites du Drawable, seule la partie située à l'intérieur est dessinée. Le comportement lorsque les rectangles se chevauchent n'est pas spécifié, mais généralement, les derniers rectangles dessinés peuvent masquer les précédents.

DIAGNOSTICS

Aucune.

VOIR AUSSI

XDrawRectangles(3), XFillPolygon(3), XFillArc(3)
