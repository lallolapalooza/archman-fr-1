Xaw(3) Manuel des fonctions de bibliothèque Xaw(3)

NOM

Xaw - Jeu de widgets X Athena

DESCRIPTION

Xaw est un jeu de widgets basé sur la bibliothèque X Toolkit Intrinsics (Xt). Cette version de la Fondation X.Org inclut des ajouts et des modifications initialement apportés pour The XFree86 Project, Inc. Cette page de manuel décrit ces changements ainsi que certaines des interfaces communes entre sa version et la version précédente du Consortium X (Xaw6).

La majeure partie de la documentation Xaw se trouve dans la spécification de l'API qui peut être installée dans /usr/share/doc/libXaw, ou trouvée sur le site Web de X.Org.

ACTIONS

Tous les widgets Xaw ont maintenant les traductions supplémentaires call-proc, declare, get-values et set-values. La syntaxe de ces actions est :

nom-action (expression-booléenne, arguments)

nom-action est l'un de call-proc, declare, get-values ou set-values.

expression-booléenne est composée avec les opérateurs

| (ou),
& (et),
^ (xor), et
~ (non).
Ses opérandes peuvent être
  • un nom de variable, qui commence par un $,
  • un nom de ressource sans les liaisons . ou *, ou
  • un nom constant, y compris
  • mine (event->xany.window == XtWindow(widget)),
  • faked (event->xany.send_event != 0),
  • true (1) et
  • false (0).

arguments sont explicites :

  • lorsqu'ils commencent par un $, ils nomment une variable,
  • sinon, ils indiquent un nom de ressource.
call-proc (expression-booléenne, nom-procédure)
Cette action permet l'évaluation d'une expression booléenne dans le premier paramètre avant d'appeler une procédure d'action. La procédure n'est appelée que si l'expression est évaluée comme vraie. Exemple : 
call-proc("$inside & $pressed", notify)
declare (expression-booléenne, variable, valeur, ...)
Cette action est utilisée pour créer de nouvelles variables ou modifier leurs valeurs. Un nombre quelconque de tuples variable-valeur peut être spécifié. Exemple : 
declare(1, $pressed, 1)
get-values (expression-booléenne, variable, valeur, ...)
Cette action lit la valeur d'une ressource de widget dans une variable. Un nombre quelconque de tuples variable-valeur peut être spécifié. Exemple : 
get-values(1, $fg, foreground, $bg, background)
set-values (expression-booléenne, variable, valeur, ...)
Cette action définit une ressource de widget à la valeur donnée, qui peut être une variable. Un nombre quelconque de tuples variable-valeur peut être spécifié. Exemple : 
set-values(1, foreground, $bg, background, $fg)

Voici un exemple de traduction pour faire qu'un widget de label se comporte comme un bouton :

<Map>:      get-values(1, $fg, foreground, $bg, background)\n\
<Btn1Down>: set-values(1, foreground, yellow, background, gray30)\n\
<Btn1Up>:   set-values(1, foreground, $fg, background, $bg)

LISTES D'AFFICHAGE

Tous les widgets Xaw ont maintenant la ressource supplémentaire displayList. Cette ressource permet de dessiner les décorations du widget en utilisant des commandes intégrées dans une chaîne de ressources. La ressource displayList a la syntaxe :

[nom-classe:]nom-fonction arguments[[{;\n}]...]

nom-classe est un ensemble enregistré de fonctions pour dessiner dans le widget. Actuellement, la seule classe existante est xlib, qui fournit l'accès aux primitives de dessin Xlib.

nom-fonction est la fonction de dessin ou de configuration à appeler, décrite ci-dessous.

arguments peuvent être tout ce qui convient à la fonction displayList appelée. Lorsque la fonction nécessite une coordonnée, la syntaxe est

{+-}<entier> ou
<entier>/<entier>.
Exemples :
+0,+0      haut, gauche
-0,-0      bas, droite
-+10,-+10  bas+10, droite+10
+0,1/2     gauche, centre vertical
mode-arc mode
Définit le mode de l'arc. Les modes acceptés sont "pieslice" et "chord", qui définissent l'arc à ArcPieSlice ou ArcChord, respectivement. Exemple : 
mode-arc chord
bg spec-couleur
background spec-couleur
Définit la couleur d'arrière-plan. spec-couleur doit être une spécification de couleur valide. Exemple : 
background red
style-cap style
Définit le style de terminaison. Les styles acceptés sont "notlast", "butt", "round" et "projecting", qui définissent le style de terminaison à CapNotLast, CapBut, CapRound ou CapProjecting, respectivement. Exemple : 
style-cap round
masque-de-découpage spec-pixmap
Définit la pixmap pour le masque de découpage. Nécessite un paramètre pixmap, comme décrit dans la section PIXMAPS ci-dessous. Exemple : 
masque-de-découpage xlogo11
origine-de-découpage x,y
Définit l'origine x et y du découpage. Nécessite deux arguments, les coordonnées x et y. Exemple : 
origine-de-découpage 10,10
rects-de-découpage x1,y1,x2,y2 [...,xn,yn]
rectangles-de-découpage x1,y1,x2,y2 [...,xn,yn]
Définit une liste de rectangles pour le masque de découpage. Le nombre d'arguments doit être un multiple de quatre. Les arguments sont des coordonnées. L'analyseur calcule la largeur et la hauteur des rectangles. Exemple : 
rects-de-découpage 0,0,10,20, 20,10,30,30
mode-coordonnee mode
Change le mode de coordonnées pour fill-polygon, draw-lines et draw-points. Les paramètres acceptés sont "modeorigin" et "previous", qui définissent le mode de coordonnées à CoordModeOrigin ou CoordModePrevious, respectivement. Exemple : 
mode-coordonnee previous
copier-zone {spec-pixmap|.},dstx,dsty[,x2,y2,srcx,srcy]
Appelle XCopyArea. Le caractère . signifie copier le contenu de la fenêtre ; spec-pixmap est défini dans la section PIXMAPS ci-dessous. X2 et y2 sont les coordonnées de fin de copie, pas la largeur et la hauteur ; si elles ne sont pas définies, l'analyseur les calcule. src_x et src_y valent par défaut zéro. Exemple : 
copier-zone Term,10,10
copier-plan {spec-pixmap|.},dstx,dsty[,x2,y2,srcx,srcy,plane]
Appelle XCopyPlane. Le caractère . signifie copier le contenu de la fenêtre ; spec-pixmap est défini dans la section PIXMAPS ci-dessous. X2 et y2 sont les coordonnées de fin de copie, pas la largeur et la hauteur ; si elles ne sont pas définies, l'analyseur les calcule. src_x et src_y valent par défaut zéro. Plane vaut par défaut un. Exemple : 
copier-plan star,10,10
tirets i1[...,in]
Définit les tirets pour le dessin de lignes. Accepte jusqu'à 127 arguments. Exemple : 
tirets 3,7 9,10
dessiner-arc x1,y1,x2,y2[,angle-debut,angle-fin]
Dessine un arc. Les quatre fi

rst arguments sont le rectangle englobant l'arc. Les deux arguments restants, s'ils sont spécifiés, sont les angles de début et de fin, en degrés. Exemple : 
draw-arc +0,+0,-1,-1,0,90
draw-rect x1,y1,x2,y2
draw-rectangle x1,y1,x2,y2
Dessine un rectangle. Nécessite quatre arguments, qui sont les paires de coordonnées de début et de fin. Exemple : 
draw-rect +1,+1,-5,-5
draw-string x,y,"chaîne"
Dessine une chaîne de caractères. Nécessite trois arguments : une coordonnée x, une coordonnée y et une chaîne. Les chaînes contenant des espaces peuvent être mises entre guillemets avec le caractère " ; le caractère antislash \ peut également être utilisé, mais il devra alors être échappé deux fois. Exemple : 
draw-string 10,10, "Bonjour le monde !"
exposures booléen
Définit les expositions graphiques dans le GC. Les paramètres autorisés sont un entier ou les chaînes "true", "false", "on" et "off". Exemple : 
exposures true
fill-arc x1,y1,x2,y2[,angle-début,angle-fin]
Similaire à draw-arc, mais remplit le contenu de l'arc avec la couleur de premier plan actuellement sélectionnée. Exemple : 
fill-arc +0,+0,-1,-1,0,180
fill-poly x1,y1 [...,xn,yn]
fill-polygon x1,y1 [...,xn,yn]
Similaire à draw-lines, mais remplit le polygone fermé et relie le premier et le dernier point s'ils ne sont pas à la même position. Exemple : 
fill-poly +0,+10, +10,+20, +30,+0
fill-rect x1,y1,x2,y2
fill-rectangle x1,y1,x2,y2
Similaire à draw-rect, mais remplit le contenu du rectangle avec la couleur de premier plan sélectionnée. Exemple : 
fill-rect +10,+10,-20,-20
fill-rule règle
Définit la règle de remplissage. Les paramètres acceptés sont "evenodd" et "winding", qui définissent la règle de remplissage sur EvenOddRule ou WindingRule, respectivement. Exemple : 
fill-rule winding
fill-style style
Définit le style de remplissage. Les paramètres autorisés sont "solid", "tiled", "stippled" et "opaquestippled", qui définissent le style de remplissage sur FillSolid, FillTiled, FillStippled ou FillOpaqueStippled, respectivement. Exemple : 
fill-style tiled
font spéc-police
Définit la police pour les fonctions de texte. Exemple : 
font -*-*-*-R-*-*-*-120-*-*-*-*-ISO8859-1
fg spéc-couleur
foreground spéc-couleur
Similaire à background, mais définit la couleur de premier plan actuelle. Exemple : 
foreground blue
mask
Cette commande est utile lorsque vous souhaitez dessiner uniquement dans la région qui a réellement besoin d'être repeinte. Elle ne nécessite aucun argument.
function spéc-fonction
Définit la fonction GC spécifique. Les paramètres autorisés sont "set", "clear", "and", "andreverse", "copy", "andinverted", "noop", "xor", "or", "nor", "equiv", "invert", "orreverse", "copyinverted" et "nand", qui définissent la fonction sur GXset, GXclear, GXand, GXandReverse, GXcopy, GXandInverted, GXnoop, GXxor, GXor, GXnor, GXequiv, GXinvert, GXorReverse, GXcopyInverted ou GXnand, respectivement. Exemple : 
function xor
join-style style
Définit le style de jointure. Les paramètres autorisés sont "miter", "round" et "bevel", qui définissent le style de jointure sur JoinMiter, JoinRound et JoinBevel, respectivement. Exemple : 
join-style round
image {spéc-pixmap},xs,ys,[xe,ye]
Cette fonction est implémentée comme un moyen de composer rapidement des décorations complexes dans les widgets. Spéc-pixmap est tel que défini dans la section PIXMAPS ci-dessous. xs et ys sont les coordonnées à partir desquelles copier la pixmap ; xe et ye sont optionnels (ils valent par défaut xs + pixmap.width et ys + pixmap.height, respectivement). Si la pixmap a un masque, la copie est masquée en conséquence. Exemple : 
image pixmap.xpm,0,0,20,20
line x1,y1,x2,y2
draw-line x1,y1,x2,y2
Dessine une ligne avec la couleur de premier plan actuelle. Nécessite quatre arguments, les paires de coordonnées de début et de fin. Exemple : 
line +0,+0, -1,-1
line-width entier
Sélectionne une épaisseur de ligne pour le dessin. Exemple : 
line-width 2
line-style style
Définit le style de ligne. Les paramètres acceptés sont "solid", "onoffdash" et "doubledash", qui définissent le style de ligne sur LineSolid, LineOnOffDash ou LineDoubleDash, respectivement. Exemple : 
line-style onoffdash
lines x1,y1,x2,y2 [...,xn,yn]
draw-lines x1,y1,x2,y2 [...,xn,yn]
Dessine une liste de lignes. Tout nombre de paires d'arguments peut être fourni. Exemple : 
lines +0,-1, -1,-1, -1,+0
paint-string x,y,"chaîne"
Identique à draw-string, mais utilise également la couleur d'arrière-plan. Exemple : 
paint-string 10,20, "Texte d'exemple"
point x,y
draw-point x,y
Dessine un point. Nécessite deux arguments, une paire de coordonnées. Exemple : 
point +10,+10
plane-mask entier
Définit le masque de plan. Nécessite un paramètre entier. Exemple : 
plane-mask -1
points x1,y1 [...,xn,yn]
draw-points x1,y1 [...,xn,yn]
Dessine une liste de points aux coordonnées spécifiées. Exemple : 
points +1,+2, +1,+4, +1,+6
segments x1,y1,x2,y2 [...,xn,yn]
draw-segments x1,y1,x2,y2 [...,xn,yn]
Dessine une liste de lignes segmentées. Le nombre de paramètres doit être un multiple de 4. Exemple : 
segments +1,+2,+1,-3, +2,-2,-3,-2
shape-mode mode
Définit le mode de forme utilisé dans fill-polygon. Les paramètres acceptés sont "complex", "convex" ou "nonconvex", qui définissent le mode de forme sur Complex, Convex ou Nonconvex, respectivement. Exemple : 
shape-mode convex
stipple spéc-pixmap
Définit la pixmap pour un estompage. Nécessite un paramètre de pixmap, tel que décrit dans la section PIXMAPS ci-dessous. Exemple : 
stipple plaid
subwindow-mode mode
Définit le mode de sous-fenêtre dans le GC. Les paramètres acceptés sont "includeinferiors" et "clipbychildren", qui définissent le mode de sous-fenêtre sur IncludeInferiors ou ClipByChildren, respectivement. Exemple : 
subwindow-mode includeinferiors
tile spéc-pixmap
Définit la pixmap pour une mosaïque. Nécessite un paramètre de pixmap, tel que décrit dans la section PIXMAPS ci-dessous. Exemple : 
tile xlogo11?foreground=red&background=gray80
ts-origin x,y
Définit l'origine x et y de la mosaïque estompée. Nécessite deux arguments, une coordonnée x et une coordonnée y. Exemple : 
ts-origin 10,10
umask
Désactive le masque du GC, s'il a été défini avec la commande mask. Ne nécessite aucun argument.

Exemple pour dessiner un effet d'ombre dans un widget :

foreground gray30;\
draw-lines +1,-1,-1,-1,-1,+1;\
foreground gray85;\
draw-lines -1,+0,+0,+0,+0,-1

PIXMAPS

Un convertisseur de chaînes en pixmap a été ajouté à Xaw. Ce convertisseur est destiné à être étendu et dispose d'une abstraction suffisante pour permettre le chargement de plusieurs formats d'image. Il utilise un format qui ressemble à une URL, avec la syntaxe :

[type:]nom[?arg=val[{&}...]]

type
peut être l'un des éléments suivants : bitmap, gradient ou xpm.
nom
peut être un nom de fichier, ou, dans le cas du type gradient, peut être soit vertical soit horizontal.
arg=val
est une liste d'arguments pour le convertisseur.
Une liste d'arguments est précédée d'un point d'interrogation, et les arguments multiples sont séparés
par des ampersands.
Les arguments les plus courants sont foreground et background.
Les dégradés prennent également en charge les arguments start et end (couleurs avec lesquelles commencer et terminer le dégradé), l'argument steps (pour permettre l'utilisation de moins de couleurs), et l'argument dimension (pour spécifier la taille du dégradé).
Le convertisseur xpm comprend l'argument closeness, qui aide à utiliser moins de couleurs (utile si vous avez une palette de couleurs limitée).

TEXT WIDGET

La plupart des changements apportés à cette version de la bibliothèque Xaw ont été réalisés dans les fichiers TextWidget, TextSrcObject, TextSinkObject et les fichiers associés.

Quelques changements très visibles dans le widget Text sont dus à de nombreux bogues dans l'implémentation Xaw6 concernant les barres de défilement et le redimensionnement automatique. L'ajout ou la suppression de barres de défilement a causé plusieurs problèmes pour maintenir le curseur de texte visible, et dans Xaw6, il était très facile qu'un widget pense que le curseur était visible alors qu'il ne l'était pas. De plus, permettre le redimensionnement automatique du widget vers une géométrie plus grande a créé d'autres problèmes, rendant difficile d'avoir une mise en page cohérente dans l'application, et, si le gestionnaire de fenêtres n'interférait pas, des fenêtres plus grandes que l'écran pouvaient en résulter. Par conséquent, certaines fonctionnalités impliquant les barres de défilement et le redimensionnement automatique ont été désactivées ; voir la section sur les ressources nouvelles et modifiées du widget Text ci-dessous.

Les liaisons de touches par défaut du widget Text étaient initialement basées sur l'éditeur de texte Emacs. Dans cette version, encore plus d'opérations familières aux utilisateurs d'Emacs ont été ajoutées. Les nouvelles actions textuelles incluent :

indent
Indente les blocs de texte. Pas lié par défaut. Le widget Text n'essaie pas non plus d'effectuer une indentation automatique de son objet source par défaut.
keyboard-reset
Réinitialise l'état du clavier. Ramène le multiplicateur d'action à 1, et si l'annulation est activée, bascule entre annuler et refaire. Lié par défaut à Control<Key>G.
kill-ring-yank
Dans cette version de Xaw, le texte tué dans n'importe quel champ de texte est conservé en mémoire, permettant des opérations de copier-coller internes au programme entre les champs de texte. Lié par défaut à Meta<Key>Y.
numeric
Listé ici uniquement à des fins de documentation. Appelé par défaut lorsqu'un des caractères 1, 2, 3, 4, 5, 6, 7, 8, 9, 0, ou - est tapé, permettant la composition du nombre de multiplication des actions textuelles.
set-keyboard-focus
Définit le focus d'entrée du widget de niveau supérieur sur le champ de texte. Pas activé par défaut, mais lié à l'événement <Btn1Down>.
toggle-overwrite
Bascule le mode d'écrasement. En mode d'écrasement, tout texte inséré dans un champ de texte remplacera le texte existant. Lié par défaut à <Key>Insert.
undo
Définit la ressource enableUndo de l'objet textSrcObject. Pas activé par défaut, mais lié à Control<Key>_.

Les ressources nouvelles et modifiées du widget Text incluent :

justify (Class Justify)
Définit la justification du texte. Peut être l'une des valeurs : left, right, center, ou full. Uniquement activé lorsque la ressource autoFill est définie, et que les ressources leftColumn et rightColumn sont correctement définies.
leftColumn (Class Column)
Spécifie la colonne gauche à laquelle la rupture du texte doit se faire. Les lignes de texte commençant par un caractère alphanumérique commenceront automatiquement à cette colonne.
positionCallback (Class Callback)
Permet d'installer une fonction de rappel qui sera appelée chaque fois que le curseur est déplacé, et/ou que le fichier change de taille. La fonction de rappel est appelée avec un pointeur vers une structure contenant les données suivantes :
typedef struct {
    int line_number;
    int column_number;
    XawTextPosition insert_position;
    XawTextPosition last_position;
    Boolean overwrite_mode;
} XawTextPositionInfo;
Cette fonction de rappel est destinée à aider les programmeurs à écrire des éditeurs de texte basés sur l'ensemble de widgets Xaw.
resize (Class Resize)
N'est plus pris en charge, mais est reconnu pour la compatibilité descendante avec les spécifications de ressources écrites pour le widget Text Xaw6.
rightColumn (Class Column)
Spécifie la colonne droite à laquelle la rupture du texte doit se faire. Les lignes de texte commençant par un caractère alphanumérique se termineront automatiquement à cette colonne.
scrollHorizontal (Class Scroll)
scrollVertical (Class Scroll)
Ces ressources contrôlent le placement des barres de défilement sur les bords gauche et inférieur du widget Text. Elles acceptent les valeurs XawtextScrollAlways et XawtextScrollNever. Un convertisseur est enregistré pour cette ressource qui convertira les chaînes suivantes : always et never. La valeur XawtextScrollWhenNeeded (et whenNeeded, reconnue par le convertisseur) est acceptée pour la compatibilité descendante avec les spécifications de ressources écrites pour le widget Text Xaw6, mais ignorée (effectivement traitée comme XawtextScrollNever).

TEXT SOURCE OBJECT

L'objet textSrcObject permet l'affichage de son contenu à plusieurs fenêtres, et stocke également les informations d'annulation. Les nouvelles ressources pour l'objet textSrcObject sont :

callback (Class Callback)
Les versions précédentes de Xaw avaient cette ressource dans des sous-classes de l'objet TextSource. Cela a été modifié pour permettre de signaler à la fonction de rappel l'état du texte lorsque l'annulation est activée.
enableUndo (Class Undo)
Une ressource booléenne qui active ou désactive la fonction d'annulation. La valeur par défaut est False.
sourceChanged (Class Changed)
Comme la ressource callback, cette ressource se trouvait précédemment dans les sous-classes de l'objet TextSource. Elle se trouve maintenant dans l'objet textSrcObject pour contrôler l'état changé/non changé lorsque l'annulation est activée.

TEXT SINK OBJECT

Les sous-classes textSinkObject asciiSinkObject et multiSinkObject ont été légèrement modifiées pour utiliser une nouvelle forme de curseur (plus un caret sur la ligne de base) qui indique le focus d'entrée du widget de texte, et pour permettre la spécification de la couleur du curseur. La nouvelle ressource est :

cursorColor (Class Color)
Définit la couleur du curseur du texte. Cette couleur est également utilisée pour dessiner le texte sélectionné.

SIMPLE MENU WIDGET

L'algorithme du simpleMenuWidget pour organiser les entrées de menu a été modifié pour permettre plusieurs colonnes lorsqu'une seule colonne ne tient pas sur l'écran. Il a également été modifié pour permettre les sous-menus.

SME BSB OBJECT

Une nouvelle ressource a été ajoutée à l'objet smeBSBObject pour permettre la liaison de sous-menus. La nouvelle ressource est :

menuName (Class MenuName)
Spécifie le nom du widget popup à faire apparaître lorsque le pointeur est sur l'entrée de menu, ou NULL. Notez que le menu nommé doit être un enfant du parent popup de l'objet smeBSBObject.

Xaw - Man Page

Xaw

NOM
Xaw - Bibliothèques pour le toolkit X Athena Widgets

DESCRIPTION
La bibliothèque Xaw fournit un ensemble de widgets standard pour le toolkit X Window System. Ces widgets sont conçus pour être portables et interopérables avec d'autres applications X. La bibliothèque Xaw est divisée en plusieurs sous-bibliothèques, chacune fournissant un ensemble différent de widgets.

Les sous-bibliothèques incluent :

  • Xaw3d : Fournit des widgets 3D pour une apparence améliorée.
  • XawXt : Fournit des widgets basés sur le toolkit Xt.
  • XawLib : Fournit des utilitaires et des fonctions de support pour les autres bibliothèques Xaw.

Les widgets Xaw peuvent être utilisés pour créer des interfaces utilisateur graphiques complexes, notamment des fenêtres, des boutons, des menus, des zones de texte, etc. Ils sont souvent utilisés en conjonction avec des bibliothèques de fenêtrage de plus bas niveau comme Xlib.

La bibliothèque Xaw est particulièrement utile pour les développeurs qui souhaitent créer des applications X portables et visuellement attrayantes sans avoir à réimplémenter des éléments d'interface utilisateur courants.

FONCTIONS

Les fonctions de la bibliothèque Xaw couvrent une large gamme d'opérations d'interface utilisateur, notamment :

  • Création et gestion de widgets.
  • Gestion des événements et des callbacks.
  • Manipulation des ressources des widgets.
  • Dessin et affichage des widgets.
  • Communication inter-widgets.

Par exemple, la création d'un bouton impliquerait généralement l'appel d'une fonction comme XtCreateWidget avec le type de widget approprié (par exemple, "command") et la spécification de ses ressources. La gestion des événements, tels que les clics de souris, est gérée via un système de callbacks, où des fonctions spécifiques sont enregistrées pour être appelées lorsqu'un événement particulier se produit.

EXEMPLES

Voici un exemple simple de création d'une fenêtre avec un bouton en utilisant Xaw : 

#include <X11/Intrinsic.h>
#include <X11/StringDefs.h>
#include <X11/Xaw/Box.h>
#include <X11/Xaw/Command.h>

void quit_callback(Widget w, XtPointer client_data, XtPointer call_data) {
    exit(0);
}

int main(int argc, char **argv) {
    Widget top_level, box, button;
    XtAppContext app_context;

    top_level = XtInitialize("example", "Example", NULL, 0, &argc, argv);

    box = XtCreateManagedWidget("box", boxWidgetClass, top_level, NULL, 0);

    button = XtCreateManagedWidget("quit", commandWidgetClass, box, NULL, 0);
    XtAddCallback(button, XtNcallback, quit_callback, NULL);

    XtRealizeWidget(top_level);
    XtMainLoop();

    return 0;
}
