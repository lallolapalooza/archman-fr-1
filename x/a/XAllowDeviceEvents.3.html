NOM

XAllowDeviceEvents - libère les événements mis en file d'attente

SYNTAXE

#include <X11/extensions/XInput.h>
int XAllowDeviceEvents( Display *display,
                        XDevice *device,
                        int event_mode,
                        Time time);
display
       Spécifie la connexion au serveur X.
device
       Spécifie le périphérique dont les événements doivent être
       autorisés.
event_mode
       Spécifie le mode d'événement. Vous pouvez passer AsyncThisDevice,
       SyncThisDevice, ReplayThisDevice, AsyncOtherDevices,
       SyncAll, ou AsyncAll.
time
       Spécifie le temps. Vous pouvez passer un horodatage ou
       CurrentTime.

DESCRIPTION

La fonction XAllowDeviceEvents libère certains événements mis en file d'attente si le client a provoqué le gel d'un périphérique. Elle n'a aucun effet si le temps spécifié est antérieur au dernier instant de saisie (grab time) de la saisie active la plus récente pour le client et le périphérique, ou si le temps spécifié est postérieur au temps actuel du serveur X.

Ce qui suit décrit le traitement qui se produit en fonction de la constante que vous passez à l'argument event_mode.

•AsyncThisDevice - Si le périphérique spécifié est gelé par le client, le traitement des événements pour ce périphérique continue normalement. Si le périphérique est gelé plusieurs fois par le client pour plusieurs saisies distinctes, AsyncThisDevice débloque pour toutes. AsyncThisDevice n'a aucun effet si le périphérique spécifié n'est pas gelé par le client, mais le périphérique n'a pas besoin d'être saisi par le client.
•SyncThisDevice - Si le périphérique spécifié est gelé et activement saisi par le client, le traitement des événements pour ce périphérique continue normalement jusqu'à ce que le prochain événement de touche ou de bouton soit rapporté au client. À ce moment-là, le périphérique spécifié semble à nouveau gelé. Cependant, si l'événement rapporté entraîne la libération de la saisie, le périphérique spécifié ne sera pas gelé. SyncThisDevice n'a aucun effet si le périphérique spécifié n'est pas gelé par le client ou s'il n'est pas saisi par le client.
•ReplayThisDevice - Si le périphérique spécifié est activement saisi par le client et est gelé à la suite d'un événement envoyé au client (soit par l'activation d'un GrabDeviceButton, soit par un AllowDeviceEvents précédent avec le mode SyncThisDevice, mais pas par un GrabDevice), la saisie est libérée et cet événement est entièrement retraité. Cependant, cette fois, la requête ignore toutes les saisies passives à ou au-dessus (vers la racine) de la fenêtre de saisie qui vient d'être libérée. La requête n'a aucun effet si le périphérique spécifié n'est pas saisi par le client ou s'il n'est pas gelé à la suite d'un événement.
•AsyncOtherDevices - Si les périphériques restants sont gelés par le client, le traitement des événements pour eux continue normalement. Si les autres périphériques sont gelés plusieurs fois par le client pour plusieurs saisies, AsyncOtherDevices débloque pour tous. AsyncOtherDevices n'a aucun effet si les périphériques ne sont pas gelés par le client.
•SyncAll - Si tous les périphériques sont gelés par le client, le traitement des événements (pour tous les périphériques) continue normalement jusqu'à ce que le prochain événement de bouton ou de touche soit rapporté au client pour un périphérique saisi, auquel cas tous les périphériques semblent à nouveau gelés. Cependant, si l'événement rapporté entraîne la libération de la saisie, les périphériques ne seront pas gelés. Si un périphérique est toujours saisi, un événement ultérieur pour celui-ci entraînera toujours le gel de tous les périphériques. SyncAll n'a aucun effet à moins que tous les périphériques ne soient gelés par le client. Si un périphérique est gelé deux fois par le client pour deux saisies distinctes, SyncAll débloque pour les deux. Un gel ultérieur pour SyncAll ne gèlera chaque périphérique qu'une seule fois.
•AsyncAll - Si tous les périphériques sont gelés par le client, le traitement des événements pour tous les périphériques continue normalement. Si un périphérique est gelé plusieurs fois par le client pour plusieurs saisies distinctes, AsyncAll débloque pour tous. AsyncAll n'a aucun effet à moins que tous les périphériques ne soient gelés par le client.

AsyncThisDevice, SyncThisDevice et ReplayThisDevice n'ont aucun effet sur le traitement des événements des périphériques restants. AsyncOtherDevices n'a aucun effet sur le traitement des événements du périphérique spécifié. Lorsque event_mode est SyncAll ou AsyncAll, le paramètre device est ignoré.

Il est possible que plusieurs saisies de périphériques différents par le même client ou des clients différents soient actives simultanément. Si un périphérique est gelé pour une quelconque saisie, aucun traitement d'événement n'est effectué pour ce périphérique. Il est possible qu'un seul périphérique soit gelé en raison de plusieurs saisies. Dans ce cas, le gel doit être levé pour chaque saisie avant que les événements puissent à nouveau être traités.

XAllowDeviceEvents peut générer une erreur BadDevice ou BadValue.

DIAGNOSTICS

BadDevice
       Un périphérique invalide a été spécifié. Le périphérique
       spécifié n'existe pas ou n'a pas été ouvert par ce client
       via XOpenInputDevice. Cette erreur peut également survenir
       si le périphérique spécifié est le clavier X ou le pointeur X.
BadValue
       Un mode invalide a été spécifié dans la requête.
