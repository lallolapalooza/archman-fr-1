NOM

XAllocColor, XAllocNamedColor, XAllocColorCells, XAllocColorPlanes, XFreeColors - allouer et libérer des couleurs

SYNTAXE

Status XAllocColor(Display *display, Colormap colormap, XColor *screen_in_out);

Status XAllocNamedColor(Display *display, Colormap colormap, _Xconst char *color_name, XColor *screen_def_return, XColor *exact_def_return);

Status XAllocColorCells(Display *display, Colormap colormap, Bool contig, unsigned long plane_masks_return[], unsigned int nplanes, unsigned long pixels_return[], unsigned int npixels);

Status XAllocColorPlanes(Display *display, Colormap colormap, Bool contig, unsigned long pixels_return[], int ncolors, int nreds, int ngreens, int nblues, unsigned long *rmask_return, unsigned long *gmask_return, unsigned long *bmask_return);

int XFreeColors(Display *display, Colormap colormap, unsigned long pixels[], int npixels, unsigned long planes);

DESCRIPTION

La fonction XAllocColor alloue une entrée de carte de couleurs en lecture seule correspondant à la valeur RVB la plus proche supportée par le matériel. XAllocColor retourne la valeur du pixel de la couleur la plus proche des éléments RVB spécifiés supportés par le matériel et retourne la valeur RVB réellement utilisée. La cellule de carte de couleurs correspondante est en lecture seule. De plus, XAllocColor retourne une valeur non nulle en cas de succès, ou zéro en cas d'échec. Plusieurs clients demandant la même valeur RVB effective peuvent se voir attribuer la même entrée en lecture seule, permettant ainsi le partage des entrées. Lorsque le dernier client désalloue une cellule partagée, elle est désallouée. XAllocColor n'utilise ni n'affecte les drapeaux de la structure XColor.

XAllocColor peut générer une erreur BadColor.

La fonction XAllocNamedColor recherche la couleur nommée par rapport à l'écran associé à la carte de couleurs spécifiée. Elle retourne à la fois la définition exacte de la base de données et la couleur la plus proche supportée par l'écran. La cellule de couleur allouée est en lecture seule. La valeur du pixel est retournée dans screen_def_return. Si le nom de la couleur n'est pas dans le codage de caractères portable hôte, le résultat dépend de l'implémentation. L'utilisation de majuscules ou de minuscules n'a pas d'importance. Si screen_def_return et exact_def_return pointent vers la même structure, le champ pixel sera correctement défini, mais les valeurs de couleur sont indéfinies. XAllocNamedColor retourne une valeur non nulle si une cellule est allouée ; sinon, elle retourne zéro.

XAllocNamedColor peut générer une erreur BadColor.

La fonction XAllocColorCells alloue des cellules de couleurs en lecture/écriture. Le nombre de couleurs doit être positif et le nombre de plans non négatif, sinon une erreur BadValue est générée. Si ncolors et nplanes sont demandés, alors ncolors pixels et nplane masques de plans sont retournés. Aucun masque n'aura de bits mis à 1 en commun avec un autre masque ou avec l'un des pixels. En combinant par OR chaque pixel avec zéro ou plusieurs masques, 2nplanes pixels distincts peuvent être produits. Tous ceux-ci sont alloués en écriture par la requête. Pour GrayScale ou PseudoColor, chaque masque a exactement un bit mis à 1. Pour DirectColor, chacun a exactement trois bits mis à 1. Si contig est True et si tous les masques sont combinés par OR, un ensemble contigu de bits mis à 1 sera formé pour GrayScale ou PseudoColor et trois ensembles contigus de bits mis à 1 (un à l'intérieur de chaque sous-champ de pixel) pour DirectColor. Les valeurs RVB des entrées allouées sont indéfinies. XAllocColorCells retourne une valeur non nulle en cas de succès, ou zéro en cas d'échec.

XAllocColorCells peut générer des erreurs BadColor et BadValue.

Le nombre de couleurs spécifié doit être positif ; et nreds, ngreens, et nblues doivent être non négatifs, sinon une erreur BadValue est générée. Si ncolors couleurs, nreds rouges, ngreens verts, et nblues bleus sont demandés, ncolors pixels sont retournés ; et les masques ont respectivement nreds, ngreens, et nblues bits mis à 1. Si contig est True, chaque masque aura un ensemble contigu de bits mis à 1. Aucun masque n'aura de bits mis à 1 en commun avec un autre masque ou avec l'un des pixels. Pour DirectColor, chaque masque se situera dans le sous-champ de pixel correspondant. En combinant par OR des sous-ensembles de masques avec chaque valeur de pixel, 2(nreds+ngreens+nblues) valeurs de pixels distinctes peuvent être produites. Toutes celles-ci sont allouées par la requête. Cependant, dans la carte de couleurs, il n'y a que ncolors * 2nreds entrées rouges indépendantes, ncolors * 2ngreens entrées vertes indépendantes, et ncolors * 2nblues entrées bleues indépendantes. Ceci est vrai même pour PseudoColor. Lorsque l'entrée de carte de couleurs d'une valeur de pixel est modifiée (en utilisant XStoreColors, XStoreColor, ou XStoreNamedColor), le pixel est décomposé selon les masques, et les entrées indépendantes correspondantes sont mises à jour. XAllocColorPlanes retourne une valeur non nulle en cas de succès, ou zéro en cas d'échec.

XAllocColorPlanes peut générer des erreurs BadColor et BadValue.

La fonction XFreeColors libère les cellules représentées par les pixels dont les valeurs sont dans le tableau pixels. L'argument planes ne doit pas avoir de bits mis à 1 en commun avec l'un des pixels. L'ensemble de tous les pixels est produit en combinant par OR des sous-ensembles de l'argument planes av XFreeColors(3) — libX11 1.8.12

NAME

XFreeColors — free allocated color cells

SYNTAX

int XFreeColors(Display *display, Colormap cmap, unsigned long *pixels, int npixels, unsigned int planes);

DESCRIPTION

The XFreeColors function frees the specified pixels in the specified colormap. The pixels argument is a list of pixel values to be freed. The npixels argument specifies the number of pixels in the list. The planes argument is used only when freeing cells allocated by XAllocColorPlanes. In this case, planes should be set to the number of red, green, and blue planes that were allocated. Otherwise, planes should be set to zero.

The request frees all of these pixels that were allocated by the client (using XAllocColor, XAllocNamedColor, XAllocColorCells, and XAllocColorPlanes). Note that freeing an individual pixel obtained from XAllocColorPlanes may not actually allow it to be reused until all of its related pixels are also freed. Similarly, a read-only entry is not actually freed until it has been freed by all clients, and if a client allocates the same read-only entry multiple times, it must free the entry that many times before the entry is actually freed.

All specified pixels that are allocated by the client in the colormap are freed, even if one or more pixels produce an error. If a specified pixel is not a valid index into the colormap, a BadValue error results. If a specified pixel is not allocated by the client (that is, is unallocated or is only allocated by another client) or if the colormap was created with all entries writable (by passing AllocAll to XCreateColormap), a BadAccess error results. If more than one pixel is in error, the one that gets reported is arbitrary.

XFreeColors can generate BadAccess, BadColor, and BadValue errors.

DIAGNOSTICS

BadAccess
A client attempted to free a color map entry that it did not already allocate.
BadAccess
A client attempted to store into a read-only color map entry.
BadColor
A value for a Colormap argument does not name a defined Colormap.
BadValue
Some numeric value falls outside the range of values accepted by the request. Unless a specific range is specified for an argument, the full range defined by the argument's type is accepted. Any argument defined as a set of alternatives can generate this error.
