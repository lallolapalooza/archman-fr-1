NOM

XeviQueryExtension, XeviQueryVersion, XeviGetVisualInfo - Fonctions X d'information visuelle étendue

SYNOPSIS

#include <X11/extensions/XEVI.h>

Bool XeviQueryExtension (Display *dpy);

Bool XeviQueryVersion (Display *dpy,
int *major_version_return,
int *minor_version_return);

int XeviGetVisualInfo (Display *dpy, VisualID *visual,
int n_visual, ExtendedVisualInfo ** evi_return,
int * n_info_return);

DESCRIPTION

L'extension Extended Visual Information (EVI) de X11 permet à un client de déterminer des informations sur les visuels de base au-delà de ce que fournit le protocole de base.

La bibliothèque d'interfaces de programmation d'applications EVI contient les interfaces décrites ci-dessous. À l'exception de XeviQueryExtension, si l'une de ces routines est appelée avec un affichage qui ne prend pas en charge l'extension, le ExtensionErrorHandler (qui peut être défini avec XSetExtensionErrorHandler et fonctionne de la même manière que XSetErrorHandler) sera appelé et la fonction retournera alors.

XeviQueryExtension retourne True si l'extension Extended Visual Information est disponible sur l'affichage donné. Un client doit appeler XeviQueryExtension avant d'appeler toute autre fonction EVI afin de négocier une version de protocole compatible ; sinon, le client obtiendra un comportement indéfini (EVI peut fonctionner ou non).

XeviQueryVersion retourne True si la requête a réussi ; les valeurs de la version de protocole majeure et mineure prises en charge par le serveur sont retournées dans major_version_return et minor_version_return.

XeviGetVisualInfo retourne une liste de structures ExtendedVisualInfo qui décrivent des informations visuelles au-delà de ce que prend en charge le protocole de base. Cela inclut les informations de couche pertinentes pour les systèmes prenant en charge les plans de superposition et/ou de sous-couche, et des informations qui permettent aux applications de mieux déterminer le niveau de prise en charge matérielle pour les colormaps multiples. XeviGetVisualInfo retourne Success en cas de succès, ou une erreur X sinon. Si l'argument visual est NULL, alors les informations pour tous les visuels de tous les écrans sont retournées. Sinon, il s'agit d'un pointeur vers une liste de visuels pour lesquels des informations visuelles étendues sont souhaitées. n_visual est le nombre d'éléments dans le tableau visual. evi_return retourne un pointeur vers une liste de ExtendedVisualInfo. Une fois terminé, le client doit libérer la liste en utilisant XFree. n_info_return retourne le nombre d'éléments dans le tableau evi_return.

La structure ExtendedVisualInfo a les champs suivants : 

VisualID	core_visual_id
int 	screen
int 	level
unsigned int	transparency_type
unsigned int	transparency_value
unsigned int	min_hw_colormaps
unsigned int	max_hw_colormaps
unsigned int	num_colormap_conflicts
VisualID *  	colormap_conflicts

La combinaison de core_visual_id et du numéro d'écran spécifie de manière unique le visuel décrit.

level retourne le numéro de niveau pour le visuel, 0 pour les plans normaux, > 0 pour les superpositions, < 0 pour les sous-couches.

transparency_type retourne le type de transparence pris en charge par le visuel. XEVI_TRANSPARENCY_NONE s'il n'y a pas de pixels transparents, XEVI_TRANSPARENCY_PIXEL si le visuel prend en charge un pixel transparent, XEVI_TRANSPARENCY_MASK si le visuel prend en charge des plans transparents.

transparency_value retourne la valeur de pixel/plan à définir pour la transparence si transparency_type n'est pas XEVI_TRANSPARENCY_NONE.

min_hw_colormaps et max_hw_colormaps retournent le nombre minimum et maximum de colormaps matérielles qui sous-tendent le visuel.

num_colormap_conflicts retourne le nombre d'éléments dans colormap_conflicts. Ce tableau retourne une liste de visuels qui peuvent causer des conflits dans l'utilisation de la colormap matérielle. Par exemple, si une colormap matérielle de 12 bits est surchargée pour prendre en charge des colormaps de 8 bits, les visuels de 8 bits correspondants entreraient en conflit avec les visuels de 12 bits.

ERREURS

XeviGetVisualInfo retournera BadValue s'il reçoit un ID visuel illégal, BadAccess si le serveur X ne répond pas, BadAlloc en cas d'échec d'allocation mémoire.
