NOM

Xephyr - Serveur X produisant une sortie dans une fenêtre sur un affichage X préexistant

SYNTAXE

Xephyr [:affichage] [option ...]

DESCRIPTION

Xephyr est un serveur kdrive qui produit une sortie dans une fenêtre sur un affichage X « hôte » préexistant. Pensez à Xnest mais avec la prise en charge des extensions modernes comme composite, damage et randr.

Contrairement à Xnest qui est un proxy X, c'est-à-dire limité aux capacités du serveur X hôte, Xephyr est un vrai serveur X qui utilise la fenêtre du serveur X hôte comme « framebuffer » via des XImages SHM rapides.

Il prend également en charge le débogage « visuel » de ce que le serveur peint.

OPTIONS

Le serveur accepte toutes les options standard de Xserver(1) et les options supplémentaires suivantes :

-screen largeurxhauteur
définit la taille de l'écran.
-parent id
utilise la fenêtre existante id. Si un argument -screen suit un argument -parent, cet écran est intégré dans la fenêtre donnée.
-host-cursor
définit « l'accélération du curseur » : le curseur de l'hôte est réutilisé. Ceci est principalement destiné à faciliter le débogage en évitant que le serveur ne peigne le curseur. L'amélioration des performances est négligeable.
-resizeable
Permet de redimensionner la fenêtre Xephyr, même si elle n'est pas intégrée dans une fenêtre parente. Par défaut, la fenêtre Xephyr a une taille fixe.
-no-host-grab
Désactive la capture du clavier et de la souris.

SIGNaux

Envoyez un signal SIGUSR1 au serveur (par exemple, pkill -USR1 Xephyr) pour activer/désactiver le mode de débogage. Dans ce mode, des rectangles rouges sont peints sur les zones de l'écran avant de peindre le contenu réel. Le délai entre ces peintures peut être modifié en définissant une variable d'environnement XEPHYR_PAUSE à une valeur en microsecondes.

LIMITATIONS

  • Les affichages pivotés sont actuellement mis à jour via des blits complets. Ceci est plus lent qu'un affichage orienté normalement. Le mode de débogage ne sera donc pas très utile en mode pivoté.
  • Le curseur « -host-cursor » est statique dans son apparence.
  • La compilation génère un avertissement concernant « nanosleep ». Je pense que les différents indicateurs de compilation « -D » en sont la cause. Je n'ai pas encore trouvé comment contourner ce problème. Cela ne semble pas pour autant casser quoi que ce soit.
  • La gestion du clavier est basique mais fonctionne.
  • Le bouton de souris 5 ne fonctionnera probablement pas.
