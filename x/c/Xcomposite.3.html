NOM

Xcomposite - Bibliothèque d'extension X Composite

SYNTAXE

#include <X11/extensions/Xcomposite.h>

Bool XCompositeQueryExtension(Display *dpy, int *event_base_return, int *error_base_return);

Status XCompositeQueryVersion(Display *dpy, int *major_version_return, int *minor_version_return);

int XCompositeVersion(void);

void XCompositeRedirectWindow(Display *dpy, Window window, int update);

void XCompositeRedirectSubwindows(Display *dpy, Window window, int update);

void XCompositeUnredirectWindow(Display *dpy, Window window, int update);

void XCompositeUnredirectSubwindows(Display *dpy, Window window, int update);

XserverRegion XCompositeCreateRegionFromBorderClip(Display *dpy, Window window);

Pixmap XCompositeNameWindowPixmap(Display *dpy, Window window);

Window XCompositeGetOverlayWindow(Display *dpy, Window window);

void XCompositeReleaseOverlayWindow(Display *dpy, Window window);

DESCRIPTION

L'extension composite fournit plusieurs mécanismes liés :

Stockage par hiérarchie

Le rendu d'une hiérarchie entière de fenêtres est redirigé vers un stockage hors écran. Les pixels de cette hiérarchie sont disponibles chaque fois qu'elle est visible. Le stockage est automatiquement réalloué lorsque la fenêtre de niveau supérieur change de taille. Le contenu au-delà de la géométrie de la fenêtre supérieure n'est pas conservé.

Mise à jour automatique de l'ombre

Lorsqu'une hiérarchie est rendue hors écran, le serveur X fournit un mécanisme automatique pour présenter ce contenu dans la fenêtre parente. L'implémentation est libre de faire décaler cette mise à jour par rapport aux opérations de rendu réelles d'une durée non spécifiée. Ce mécanisme de mise à jour automatique peut être désactivé afin que le contenu de la fenêtre parente puisse être entièrement déterminé par une application externe.

Fenêtre de superposition composite (Composite Overlay Window)

La version 0.3 du protocole ajoute la Fenêtre de superposition composite, qui fournit aux gestionnaires de composition une surface sur laquelle dessiner sans interférence. Cette fenêtre est toujours au-dessus des fenêtres normales et toujours en dessous de la fenêtre de l'économiseur d'écran. C'est une fenêtre InputOutput dont la largeur et la hauteur correspondent aux dimensions de l'écran. Sa visualisation est la visualisation racine et sa bordure est de largeur zéro. Les tentatives de la rediriger à l'aide de l'extension composite sont ignorées. Cette fenêtre n'apparaît pas dans la réponse de la requête QueryTree. C'est aussi une fenêtre override redirect. Ces deux dernières fonctionnalités la rendent invisible aux gestionnaires de fenêtres et autres clients X11. La seule façon d'accéder au XID de cette fenêtre est via la requête CompositeGetOverlayWindow. Initialement, la Fenêtre de superposition composite est non mappée.

Clipping de la fenêtre parente

La version 0.4 du protocole modifie la sémantique du clipping de la fenêtre parente en présence d'enfants redirigés manuellement. Avec cette version, la zone dans le parent couverte par les enfants redirigés manuellement est laissée dans la liste de clipping du parent au lieu d'être supprimée comme dans les versions antérieures.

Le stockage par hiérarchie peut être créé pour des fenêtres individuelles ou pour tous les enfants d'une fenêtre. La mise à jour manuelle de l'ombre peut être sélectionnée par une seule application pour chaque fenêtre ; la mise à jour manuelle peut également être sélectionnée par fenêtre ou pour chaque enfant d'une fenêtre. La détection du moment où effectuer la mise à jour peut être effectuée avec l'extension Damage.

Le stockage hors écran inclut le contenu de la fenêtre, ses bordures et le contenu de tous les descendants.

ARGUMENTS

display

Pointeur vers la structure Display renvoyée par XOpenDisplay pour la connexion au serveur X.

event_base_return

Pointeur vers un entier où la valeur de base pour les événements de l'extension Composite sera stockée.

error_base_return

Pointeur vers un entier où la valeur de base pour les erreurs de l'extension Composite sera stockée.

major_version_return

Pointeur vers un entier où le numéro de version majeure de l'extension Composite prise en charge par le serveur X sera stocké.

minor_version_return

Pointeur vers un entier où le numéro de version mineure de l'extension Composite prise en charge par le serveur X sera stocké.

window

Spécifie l'ID de la fenêtre sur laquelle opérer.

update

Spécifie le mode de mise à jour du contenu de la fenêtre. Doit être soit CompositeRedirectAutomatic, soit CompositeRedirectManual.

FONCTIONS

XCompositeQueryExtension

XCompositeQueryExtension détermine si l'extension Composite est disponible sur l'affichage donné. Elle renvoie True si l'extension est prise en charge, sinon False. Si l'extension est présente, les valeurs de base pour les événements et les erreurs sont renvoyées et peuvent être utilisées pour décoder les valeurs d'événements et d'erreurs entrantes.

XCompositeQueryVersion

XCompositeQueryVersion détermine si le serveur X prend en charge une version de l'extension X Composite compatible avec la bibliothèque cliente. Un statut non nul est renvoyé si une version compatible de l'extension est prise en charge, sinon un statut nul est renvoyé. Si l'extension est prise en charge, les numéros de version majeure et mineure sont renvoyés pour indiquer le niveau de prise en charge de l'extension Composite. Aucune autre fonction XComposite (sauf XCompositeQueryExtension) ne peut être appelée avant cette fonction. Si un client viole cette règle, les effets de tous les appels XComposite subséquents qu'il effectue sont indéfinis.

XCompositeVersion

XCompositeVersion renvoie la version de la bibliothèque X Composite. Le numéro de version est encodé comme suit : (majeure * 10000) + (mineure * 100) + révision.

Par exemple, la version 1.4.6 serait encodée comme l'entier 10406.

XCompositeRedirectWindow

XCompositeRedirectWindow demande au serveur X de diriger la hiérarchie commençant à window vers un stockage hors écran. L'argument update spécifie si le contenu est mis en miroir automatiquement vers la fenêtre parente ou non. Un seul client à la fois peut spécifier un type de mise à jour CompositeRedirectManual, une autre tentative entraînera une erreur BadAccess. Lorsque tous les clients activant la redirection se terminent, la redirection sera automatiquement désactivée.

La fenêtre racine ne peut pas être redirigée. Faire cela entraîne une erreur BadMatch. Spécifier un ID de fenêtre invalide entraînera une erreur BadWindow.

XCompositeRedirectSubwindows

XCompositeRedirectSubwindows demande au serveur X de rediriger les hiérarchies commençant par tous les enfants actuels et futurs de window comme dans XCompositeRedirectWindow. Si update est CompositeRedirectManual, alors le dessin de l'arrière-plan de la fenêtre pendant la manipulation de la fenêtre et les requêtes ClearArea est inhibé.

XCompositeUnredirectWindow

XCompositeUnredirectWindow demande au serveur X de terminer la redirection de window. Si la fenêtre spécifiée n'était pas sélectionnée pour la redirection par le client actuel, une erreur BadValue en résulte.

XCompositeUnredirectSubwindows

XCompositeUnredirectWindow demande au serveur X de terminer la redirection de tous les enfants de window. Si la fenêtre spécifiée n'était pas sélectionnée pour la sous-redirection par le client actuel, une erreur BadValue en résulte.

Xcomposite

X composite extension − composite manager interface

NAME

XcompositeNameWindowPixmap, XCompositeGetOverlayWindow, XCompositeReleaseOverlayWindow − composite manager interface

SYNOPSIS

#include <X11/Xcomposite.h>

Pixmap XcompositeNameWindowPixmap(Display *dpy, Window window);

Window XcompositeGetOverlayWindow(Display *dpy, Window window);

void XcompositeReleaseOverlayWindow(Display *dpy, Window window);

DESCRIPTION

The Composite extension provides a mechanism for redirecting windows, allowing a composite manager to manage the screen contents. The extension consists of a set of properties and a set of requests.

The property Composite-Redirect is set on a window to request redirection. When a window is redirected, the X server will not display its contents directly, but instead will direct them to a pixmap. The composite manager is then responsible for displaying the window's contents, along with those of other windows.

The property Composite-Clients is set on the root window to indicate the set of clients that are currently redirecting windows. This property is intended for use by the composite manager.

There are two types of redirection: redirection to a pixmap associated with the window itself, and redirection to an overlay window. When a window is redirected to its own pixmap, the X server handles the creation and updating of the pixmap. When a window is redirected to an overlay window, the X server directs the window's contents to a special overlay window, and the composite manager is responsible for copying those contents to the appropriate location on the screen.

The XCompositeGetWindowAttributes function retrieves the attributes of a window, including whether it is redirected and the type of redirection.

The XCompositeRedirectWindow function redirects a window to a pixmap. The redirect_type argument can be either CompositeRedirectManual or CompositeRedirectAutomatic.

The XCompositeRedirectSubwindows function redirects all subwindows of a given window. The redirect_type argument can be either CompositeRedirectManual or CompositeRedirectAutomatic.

The XCompositeUnredirectWindow function unredirects a window. The redirect_type argument can be either CompositeRedirectManual or CompositeRedirectAutomatic.

The XCompositeUnredirectSubwindows function unredirects all subwindows of a given window. The redirect_type argument can be either CompositeRedirectManual or CompositeRedirectAutomatic.

The XCompositeGetScreenBackgroundPixmap retrieves the pixmap representing the screen background. This can be used by the composite manager to draw the background behind redirected windows.

The XCompositeGetWindowBackgroundPixmap retrieves the pixmap representing the background of a specific window. This is typically used when the window itself is not redirected.

The XCompositeGetClipList returns the clipping region for a window. This is the area of the window clipped against siblings and the parent. This region can be used to restrict rendering to suitable areas while updating only a single window. The region is copied at the moment the request is executed; future changes to the window hierarchy will not be reflected in this region.

ARGUMENTS

dpy
Specifies the connection to the X server.
window
Specifies the window of interest.
redirect_type
Specifies the type of redirection. Must be either CompositeRedirectManual or CompositeRedirectAutomatic.

FUNCTIONS

XCompositeNameWindowPixmap

XCompositeNameWindowPixmap creates and returns a pixmap id that serves as a reference to the off-screen storage for window. This pixmap will remain allocated until freed, even if the window is unmapped, reconfigured or destroyed. However, the window will get a new pixmap allocated each time it is mapped or resized, so this function will need to be reinvoked for the client to continue to refer to the storage holding the current window contents. Generates a BadMatch error if window is not redirected or is not visible.

The X server must support at least version 0.2 of the Composite Extension for XCompositeNameWindowPixmap.

XCompositeGetOverlayWindow

XCompositeGetOverlayWindow returns the window ID of the Composite Overlay Window for the screen specified by the argument window. This function notifies the X server that the client wishes to use the Composite Overlay Window of this screen. If this Composite Overlay Window has not yet been mapped, it is mapped by this request.

The Composite Overlay Window for a particular screen will be unmapped when all clients who have called this function have either called XCompositeReleaseOverlayWindow for that screen, or terminated their connection to the X server.

The X server must support at least version 0.3 of the Composite Extension for XCompositeGetOverlayWindow.

XCompositeReleaseOverlayWindow

This request specifies that the client is no longer using the Composite Overlay Window on the screen specified by the argument window. A screen's Composite Overlay Window is unmapped when there are no longer any clients using it.

The X server must support at least version 0.3 of the Composite Extension for XCompositeReleaseOverlayWindow.
