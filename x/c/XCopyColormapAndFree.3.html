XCreateColormap(3) FONCTIONS XLIB XCreateColormap(3)

NOM

XCreateColormap, XCopyColormapAndFree, XFreeColormap, XColor - créer, copier ou détruire des palettes de couleurs et des structures de couleur

SYNTAXE

Colormap XCreateColormap(Display *display, Window w, Visual *visual, int alloc);

Colormap XCopyColormapAndFree(Display *display, Colormap colormap);

int XFreeColormap(Display *display, Colormap colormap);

ARGUMENTS

alloc
Spécifie les entrées de la palette de couleurs à allouer. Vous pouvez passer AllocNone ou AllocAll.
colormap
Spécifie la palette de couleurs que vous souhaitez créer, copier, définir ou détruire.
display
Spécifie la connexion au serveur X.
visual
Spécifie un type de rendu pris en charge sur l'écran. Si le type de rendu n'est pas l'un de ceux pris en charge par l'écran, une erreur BadMatch en résulte.
w
Spécifie la fenêtre sur l'écran de laquelle vous souhaitez créer une palette de couleurs.

DESCRIPTION

La fonction XCreateColormap crée une palette de couleurs du type de rendu spécifié pour l'écran sur lequel réside la fenêtre spécifiée et renvoie l'identifiant de la palette de couleurs associé.

Les valeurs initiales des entrées de la palette de couleurs sont indéfinies pour les classes de rendu GrayScale, PseudoColor et DirectColor. Pour StaticGray, StaticColor et TrueColor, les entrées ont des valeurs définies, mais ces valeurs sont spécifiques au rendu et ne sont pas définies par X. Pour StaticGray, StaticColor et TrueColor, alloc doit être AllocNone, ou une erreur BadMatch en résulte. Pour les autres classes de rendu, si alloc est AllocNone, la palette de couleurs n'a initialement aucune entrée allouée, et les clients peuvent les allouer. Pour plus d'informations sur les types de rendu, voir la section 3.1.

Si alloc est AllocAll, l'intégralité de la palette de couleurs est allouée en écriture. Les valeurs initiales de toutes les entrées allouées sont indéfinies. Pour GrayScale et PseudoColor, l'effet est comme si un appel XAllocColorCells renvoyait toutes les valeurs de pixel de zéro à N - 1, où N est la valeur des entrées de la palette de couleurs dans le rendu spécifié. Pour DirectColor, l'effet est comme si un appel XAllocColorPlanes renvoyait une valeur de pixel de zéro et des valeurs red_mask, green_mask, et blue_mask contenant les mêmes bits que les masques correspondants dans le rendu spécifié. Cependant, dans tous les cas, aucune de ces entrées ne peut être libérée en utilisant XFreeColors.

XCreateColormap peut générer des erreurs BadAlloc, BadMatch, BadValue et BadWindow.

La fonction XCopyColormapAndFree crée une palette de couleurs du même type de rendu et pour le même écran que la palette de couleurs spécifiée et renvoie l'identifiant de la nouvelle palette de couleurs. Elle déplace également toutes les allocations existantes du client de la palette de couleurs spécifiée vers la nouvelle palette de couleurs, en conservant leurs valeurs de couleur et leurs caractéristiques en lecture seule ou en écriture, et libère ces entrées dans la palette de couleurs spécifiée. Les valeurs de couleur dans d'autres entrées de la nouvelle palette de couleurs sont indéfinies. Si la palette de couleurs spécifiée a été créée par le client avec alloc défini à AllocAll, la nouvelle palette de couleurs est également créée avec AllocAll, toutes les valeurs de couleur pour toutes les entrées sont copiées de la palette de couleurs spécifiée, puis toutes les entrées de la palette de couleurs spécifiée sont libérées. Si la palette de couleurs spécifiée n'a pas été créée par le client avec AllocAll, les allocations à déplacer sont toutes les pixels et plans qui ont été alloués par le client en utilisant XAllocColor, XAllocNamedColor, XAllocColorCells ou XAllocColorPlanes et qui n'ont pas été libérés depuis leur allocation.

XCopyColormapAndFree peut générer des erreurs BadAlloc et BadColor.

La fonction XFreeColormap supprime l'association entre l'identifiant de la ressource de la palette de couleurs et la palette de couleurs et libère le stockage de la palette de couleurs. Cependant, cette fonction n'a aucun effet sur la palette de couleurs par défaut pour un écran. Si la palette de couleurs spécifiée est une carte installée pour un écran, elle est désinstallée (voir XUninstallColormap). Si la palette de couleurs spécifiée est définie comme la palette de couleurs pour une fenêtre (par XCreateWindow, XSetWindowColormap ou XChangeWindowAttributes), XFreeColormap modifie la palette de couleurs associée à la fenêtre à None et génère un événement ColormapNotify. X ne définit pas les couleurs affichées pour une fenêtre avec une palette de couleurs de None.

XFreeColormap peut générer une erreur BadColor.

STRUCTURES

La structure XColor contient :

typedef struct {
        unsigned long pixel;    /* valeur du pixel */
        unsigned short red, green, blue;        /* valeurs rgb */
        char flags;     /* DoRed, DoGreen, DoBlue */
        char pad;
} XColor;

Les valeurs rouge, verte et bleue sont toujours dans la plage 0 à 65535 incluse, indépendamment du nombre de bits réellement utilisés dans le matériel d'affichage. Le serveur met à l'échelle ces valeurs vers la plage utilisée par le matériel. Le noir est représenté par (0,0,0) et le blanc par (65535,65535,65535). Dans certaines fonctions, le membre flags contrôle lequel des membres rouge, vert et bleu est utilisé et peut être le OU inclusif de zéro ou plus de DoRed, DoGreen et DoBlue.

DIAGNOSTICS

BadAlloc
Le serveur n'a pas pu allouer la ressource demandée ou la mémoire du serveur.
BadColor
Une valeur pour un argument Colormap ne désigne pas une Colormap définie.
BadMatch
Une fenêtre InputOnly est utilisée comme Drawable.
BadMatch
Un argument ou une paire d'arguments a le bon type et la bonne plage, mais ne correspond pas d'une autre manière requise par la requête.
BadValue
Une valeur numérique se situe en dehors de la plage de valeurs acceptées par la requête. Sauf si une plage spécifique est spécifiée pour un argument, la plage complète définie par le type de l'argument est acceptée. Tout argument défini comme un ensemble d'alternatives peut générer cette erreur.
BadWindow
Une valeur pour un argument Window ne désigne pas une Window définie.

NOM

XCopyColormapAndFree — copie une table de correspondance et libère l'ancienne

SYNTAXE

int XCopyColormapAndFree(Display *display, Colormap src_cmap, Colormap dst_cmap, unsigned long black_pixel, unsigned long white_pixel);

DESCRIPTION

La fonction XCopyColormapAndFree copie les entrées d'une table de correspondance source vers une table de correspondance destination. Les pixels noir et blanc spécifiés sont utilisés pour la nouvelle table de correspondance.

La fonction alloue de la mémoire pour la nouvelle table de correspondance et libère la mémoire de l'ancienne table de correspondance.

ARGUMENTS

  • display : Pointeur vers la structure Display.
  • src_cmap : Le Colormap source à copier.
  • dst_cmap : Le Colormap destination où copier les entrées.
  • black_pixel : La valeur du pixel noir.
  • white_pixel : La valeur du pixel blanc.

VALEUR DE RETOUR

La fonction renvoie Success en cas de succès, ou un code d'erreur X en cas d'échec.

DIAGNOSTICS

La fonction peut échouer si la table de correspondance source ou destination n'est pas valide, ou si une erreur d'allocation mémoire se produit.

VOIR AUSSI

XCreateColormap(3), XFreeColormap(3)
