NOM

Xcomposite - Bibliothèque d'extension X Composite

SYNTAXE

#include <X11/extensions/Xcomposite.h>

Bool XCompositeQueryExtension(Display *dpy, int *event_base_return, int *error_base_return);

Status XCompositeQueryVersion(Display *dpy, int *major_version_return, int *minor_version_return);

int XCompositeVersion(void);

void XCompositeRedirectWindow(Display *dpy, Window window, int update);

void XCompositeRedirectSubwindows(Display *dpy, Window window, int update);

void XCompositeUnredirectWindow(Display *dpy, Window window, int update);

void XCompositeUnredirectSubwindows(Display *dpy, Window window, int update);

XserverRegion XCompositeCreateRegionFromBorderClip(Display *dpy, Window window);

Pixmap XCompositeNameWindowPixmap(Display *dpy, Window window);

Window XCompositeGetOverlayWindow(Display *dpy, Window window);

void XCompositeReleaseOverlayWindow(Display *dpy, Window window);

DESCRIPTION

L'extension composite fournit plusieurs mécanismes connexes :

Stockage par hiérarchie

Le rendu d'une hiérarchie entière de fenêtres est redirigé vers un stockage hors écran. Les pixels de cette hiérarchie sont disponibles dès qu'elle est visible. Le stockage est automatiquement réalloué lorsque la fenêtre de plus haut niveau change de taille. Le contenu au-delà de la géométrie de la fenêtre supérieure n'est pas préservé.

Mise à jour automatique de l'ombre

Lorsqu'une hiérarchie est rendue hors écran, le serveur X fournit un mécanisme automatique pour présenter ce contenu dans la fenêtre parente. L'implémentation est libre de faire en sorte que cette mise à jour soit légèrement décalée par rapport aux opérations de rendu réelles, selon une durée non spécifiée. Ce mécanisme de mise à jour automatique peut être désactivé afin que le contenu de la fenêtre parente puisse être entièrement déterminé par une application externe.

Fenêtre de superposition composite (Composite Overlay Window)

La version 0.3 du protocole ajoute la fenêtre de superposition composite, qui fournit aux gestionnaires de composition une surface sur laquelle dessiner sans interférence. Cette fenêtre est toujours au-dessus des fenêtres normales et toujours en dessous de la fenêtre de l'économiseur d'écran. C'est une fenêtre InputOutput dont la largeur et la hauteur correspondent aux dimensions de l'écran. Son visuel est le visuel racine et sa bordure a une largeur nulle. Les tentatives de redirection de celle-ci à l'aide de l'extension composite sont ignorées. Cette fenêtre n'apparaît pas dans la réponse de la requête QueryTree. C'est également une fenêtre avec redirection prioritaire (override redirect). Ces deux dernières fonctionnalités la rendent invisible aux gestionnaires de fenêtres et autres clients X11. La seule façon d'accéder à l'ID X de cette fenêtre est via la requête CompositeGetOverlayWindow. Initialement, la fenêtre de superposition composite est désaffichée (unmapped).

Découpage de la fenêtre parente

La version 0.4 du protocole modifie la sémantique du découpage de la fenêtre parente en présence d'enfants redirigés manuellement. Avec cette version, la zone de la fenêtre parente couverte par les enfants redirigés manuellement est laissée dans la liste de découpage parente au lieu d'être retirée comme dans les versions précédentes.

Le stockage par hiérarchie peut être créé pour des fenêtres individuelles ou pour tous les enfants d'une fenêtre. La mise à jour manuelle de l'ombre peut être sélectionnée par une seule application pour chaque fenêtre ; la mise à jour manuelle peut également être sélectionnée par fenêtre ou pour chaque enfant d'une fenêtre. La détection du moment de la mise à jour peut être effectuée avec l'extension Damage.

Le stockage hors écran inclut le contenu de la fenêtre, ses bordures et le contenu de tous ses descendants.

ARGUMENTS

display

Pointeur vers la structure Display renvoyée par XOpenDisplay pour la connexion au serveur X.

event_base_return

Pointeur vers un entier où sera stockée la valeur de base pour les événements de l'extension Composite.

error_base_return

Pointeur vers un entier où sera stockée la valeur de base pour les erreurs de l'extension Composite.

major_version_return

Pointeur vers un entier où sera stockée la version majeure de l'extension Composite supportée par le serveur X.

minor_version_return

Pointeur vers un entier où sera stockée la version mineure de l'extension Composite supportée par le serveur X.

window

Spécifie l'identifiant de la fenêtre sur laquelle opérer.

update

Spécifie le mode de mise à jour du contenu de la fenêtre. Doit être soit CompositeRedirectAutomatic, soit CompositeRedirectManual.

FONCTIONS

XCompositeQueryExtension

XCompositeQueryExtension détermine si l'extension Composite est disponible sur l'affichage donné. Elle renvoie True si l'extension est supportée, sinon False. Si l'extension est présente, les valeurs de base pour les événements et les erreurs sont renvoyées et peuvent être utilisées pour décoder les valeurs d'événements et d'erreurs entrantes.

XCompositeQueryVersion

XCompositeQueryVersion détermine si le serveur X supporte une version de l'extension X Composite compatible avec la bibliothèque client. Un Status non nul est renvoyé si une version compatible de l'extension est supportée, sinon un Status nul est renvoyé. Si l'extension est supportée, les numéros de version majeure et mineure sont renvoyés pour indiquer le niveau de support de l'extension Composite. Aucune autre fonction XComposite (sauf XCompositeQueryExtension) ne peut être appelée avant cette fonction. Si un client viole cette règle, les effets de tous les appels XComposite subséquents qu'il effectue sont indéfinis.

XCompositeVersion

XCompositeVersion renvoie la version de la bibliothèque X Composite. Le numéro de version est codé comme suit : (majeur * 10000) + (mineur * 100) + révision

Par exemple, la version 1.4.6 serait codée comme l'entier 10406.

XCompositeRedirectWindow

XCompositeRedirectWindow demande au serveur X de rediriger la hiérarchie commençant à window vers un stockage hors écran. L'argument update spécifie si le contenu est automatiquement mis en miroir dans la fenêtre parente ou non. Un seul client à la fois peut spécifier un type de mise à jour CompositeRedirectManual, une autre tentative résultera en une erreur BadAccess. Lorsque tous les clients activant la redirection se terminent, la redirection sera automatiquement désactivée.

La fenêtre racine ne peut pas être redirigée. Faire ainsi résulte en une erreur BadMatch. Spécifier un identifiant de fenêtre invalide entraînera une erreur BadWindow.

XCompositeRedirectSubwindows

XCompositeRedirectSubwindows demande au serveur X de rediriger les hiérarchies commençant par tous les enfants actuels et futurs de window comme dans XCompositeRedirectWindow. Si update est CompositeRedirectManual, alors la peinture de l'arrière-plan de la fenêtre pendant la manipulation de la fenêtre et les requêtes ClearArea sont inhibées.

XCompositeUnredirectWindow

XCompositeUnredirectWindow demande au serveur X de terminer la redirection de window. Si la fenêtre spécifiée n'était pas sélectionnée pour la redirection par le client actuel, une erreur BadValue en résulte.

XCompositeUnredirectSubwindows

XCompositeUnredirectWindow demande au serveur X de terminer la redirection de tous les enfants de window. Si la fenêtre spécifiée n'était pas sélectionnée pour la sous-redirection par le client actuel, une erreur BadValue en résulte.

XCompositeUnredirectSubwindows(3) — X Composite Extension Library

NAME

XCompositeUnredirectSubwindows, XCompositeRedirectWindow, XCompositeRedirectSubwindow, XCompositeUnredirectWindow, XCompositeCreateRegion, XCompositeNameWindowPixmap, XCompositeGetOverlayWindow, XCompositeReleaseOverlayWindow - Composite extension client functions

SYNOPSIS

#include <X11/Xlib.h>
#include <X11/extensions/Xcomposite.h>

Bool XCompositeQueryExtension(Display *dpy, int *event_base, int *error_base);

XCompositeRedirectHandleException XCompositeRedirectWindow(Display *dpy, Window window,
    XCompositeRedirectMode mode);

XCompositeRedirectHandleException XCompositeRedirectSubwindow(Display *dpy, Window window,
    Window subwindow, XCompositeRedirectMode mode);

XCompositeRedirectHandleException XCompositeUnredirectWindow(Display *dpy, Window window);

XCompositeRedirectHandleException XCompositeUnredirectSubwindow(Display *dpy, Window window,
    Window subwindow);

Region XCompositeCreateRegion(Display *dpy, Window window);

Pixmap XCompositeNameWindowPixmap(Display *dpy, Window window);

Window XCompositeGetOverlayWindow(Display *dpy, Window window);

void XCompositeReleaseOverlayWindow(Display *dpy, Window window);

DESCRIPTION

The Composite Extension provides a mechanism for clients to directly manipulate the contents of windows, overriding the usual X window system protocol. This is typically used for implementing compositing window managers.

XCompositeQueryExtension checks if the Composite extension is available on the specified display. If it is, it returns True and sets the event_base and error_base arguments to the base number for Composite extension events and errors, respectively. If the extension is not available, it returns False.

XCompositeRedirectWindow requests that the X server redirect all rendering operations destined for window to the calling client. When mode is CompositeRedirectManual, the client is responsible for re-rendering the window contents. When mode is CompositeRedirectAutomatic, the server will automatically save the window contents and deliver them to the client via CompositeNotify events. This function generates a BadMatch error if window is already redirected or is not redirectable.

XCompositeRedirectSubwindow is similar to XCompositeRedirectWindow, but it redirects rendering operations for a specific subwindow of window. This allows for more granular control over redirection.

XCompositeUnredirectWindow stops the redirection of rendering operations for window. The X server will resume normal rendering to the window. This function generates a BadMatch error if window is not redirected.

XCompositeUnredirectSubwindow is similar to XCompositeUnredirectWindow, but it stops the redirection for a specific subwindow.

XCompositeCreateRegion creates and returns a Region that represents the clipped area of the window. This region is the intersection of the window's clip-board and the clip regions of its siblings and parent. This region can be used to restrict rendering to suitable areas while updating only a single window. The region is copied at the moment the request is executed; future changes to the window hierarchy will not be reflected in this region.

XCompositeNameWindowPixmap creates and returns a pixmap id that serves as a reference to the off-screen storage for window. This pixmap will remain allocated until freed, even if the window is unmapped, reconfigured or destroyed. However, the window will get a new pixmap allocated each time it is mapped or resized, so this function will need to be reinvoked for the client to continue to refer to the storage holding the current window contents. Generates a BadMatch error if window is not redirected or is not visible.

The X server must support at least version 0.2 of the Composite Extension for XCompositeNameWindowPixmap.

XCompositeGetOverlayWindow returns the window ID of the Composite Overlay Window for the screen specified by the argument window. This function notifies the X server that the client wishes to use the Composite Overlay Window of this screen. If this Composite Overlay Window has not yet been mapped, it is mapped by this request.

The Composite Overlay Window for a particular screen will be unmapped when all clients who have called this function have either called XCompositeReleaseOverlayWindow for that screen, or terminated their connection to the X server.

The X server must support at least version 0.3 of the Composite Extension for XCompositeGetOverlayWindow.

XCompositeReleaseOverlayWindow specifies that the client is no longer using the Composite Overlay Window on the screen specified by the argument window. A screen's Composite Overlay Window is unmapped when there are no longer any clients using it.

The X server must support at least version 0.3 of the Composite Extension for XCompositeReleaseOverlayWindow.

ARGUMENTS

dpy
Specifies the connection to the X server.
window
Specifies the window ID.
subwindow
Specifies the subwindow ID.
mode
Specifies the redirection mode (CompositeRedirectManual or CompositeRedirectAutomatic).

FUNCTIONS

XCompositeUnredirectSubwindows

XCompositeUnredirectSubwindows stops the redirection of rendering operations for all subwindows of window. The X server will resume normal rendering to these subwindows. This function generates a BadMatch error if window is not redirected.

The X server must support at least version 0.3 of the Composite Extension for XCompositeUnredirectSubwindows.
