XCreateGC(3) FONCTIONS XLIB XCreateGC(3)

NOM

XCreateGC, XCopyGC, XChangeGC, XGetGCValues, XFreeGC, XGContextFromGC, XGCValues - créer ou libérer des contextes graphiques et la structure du contexte graphique

SYNTAXE

GC XCreateGC(Display *display, Drawable d, unsigned long valuemask, XGCValues *values);

int XCopyGC(Display *display, GC src, unsigned long valuemask, GC dest);

int XChangeGC(Display *display, GC gc, unsigned long valuemask, XGCValues *values);

Status XGetGCValues(Display *display, GC gc, unsigned long valuemask, XGCValues *values_return);

int XFreeGC(Display *display, GC gc);

GContext XGContextFromGC(GC gc);

ARGUMENTS

d
Spécifie le drawable.
dest
Spécifie le GC de destination.
display
Spécifie la connexion au serveur X.
gc
Spécifie le GC.
src
Spécifie les composantes du GC source.
valuemask
Spécifie quelles composantes du GC doivent être définies, copiées, changées ou renvoyées. Cet argument est le OU binaire inclusif de zéro ou plus des bits de masque de composante GC valides.
values
Spécifie les valeurs comme indiqué par le valuemask.
values_return
Renvoie les valeurs du GC dans la structure XGCValues spécifiée.

DESCRIPTION

La fonction XCreateGC crée un contexte graphique et renvoie un GC. Le GC peut être utilisé avec n'importe quel drawable de destination ayant la même racine et la même profondeur que le drawable spécifié. L'utilisation avec d'autres drawables entraîne une erreur BadMatch.

XCreateGC peut générer des erreurs BadAlloc, BadDrawable, BadFont, BadMatch, BadPixmap et BadValue.

La fonction XCopyGC copie les composantes spécifiées de la GC source vers la GC de destination. Les GC source et destination doivent avoir la même racine et la même profondeur, sinon une erreur BadMatch se produit. Le valuemask spécifie quelle composante copier, comme pour XCreateGC.

XCopyGC peut générer des erreurs BadAlloc, BadGC et BadMatch.

La fonction XChangeGC modifie les composantes spécifiées par valuemask pour le GC spécifié. L'argument values contient les valeurs à définir. Les valeurs et les restrictions sont les mêmes que pour XCreateGC. La modification du masque de coupure annule toute demande XSetClipRectangles précédente sur le contexte. La modification du décalage de tirets ou de la liste de tirets annule toute demande XSetDashes précédente sur le contexte. L'ordre dans lequel les composantes sont vérifiées et modifiées dépend du serveur. Si une erreur est générée, un sous-ensemble des composantes peut avoir été modifié.

XChangeGC peut générer des erreurs BadAlloc, BadFont, BadGC, BadMatch, BadPixmap et BadValue.

La fonction XGetGCValues renvoie les composantes spécifiées par valuemask pour le GC spécifié. Si valuemask contient un ensemble valide de bits de masque GC (GCFunction, GCPlaneMask, GCForeground, GCBackground, GCLineWidth, GCLineStyle, GCCapStyle, GCJoinStyle, GCFillStyle, GCFillRule, GCTile, GCStipple, GCTileStipXOrigin, GCTileStipYOrigin, GCFont, GCSubwindowMode, GCGraphicsExposures, GCClipXOrigin, GCClipYOrigin, GCDashOffset ou GCArcMode) et qu'aucune erreur ne se produit, XGetGCValues définit les composantes demandées dans values_return et renvoie un statut non nul. Sinon, il renvoie un statut zéro. Notez que le masque de coupure et la liste de tirets (représentés par les bits GCClipMask et GCDashList, respectivement, dans le valuemask) ne peuvent pas être demandés. Notez également qu'un identifiant de ressource invalide (avec un ou plusieurs des trois bits les plus significatifs définis à 1) sera renvoyé pour GCFont, GCTile et GCStipple si la composante n'a jamais été explicitement définie par le client.

La fonction XFreeGC détruit le GC spécifié ainsi que tout le stockage associé.

XFreeGC peut générer une erreur BadGC.

De nombreuses opérations graphiques dépendent soit des valeurs de pixels, soit des plans dans un GC. L'attribut des plans est de type long, et il spécifie quels plans de la destination doivent être modifiés, un bit par plan. Un affichage monochrome n'a qu'un seul plan et sera le bit le moins significatif du mot. À mesure que des plans sont ajoutés au matériel d'affichage, ils occuperont des bits plus significatifs dans le masque de plans.

Dans les opérations graphiques, étant donné un pixel source et un pixel destination, le résultat est calculé bit par bit sur les bits correspondants des pixels. C'est-à-dire qu'une opération booléenne est effectuée dans chaque plan de bits. Le `plane_mask` restreint l'opération à un sous-ensemble de plans. Une constante macro AllPlanes peut être utilisée pour faire référence simultanément à tous les plans de l'écran. Le résultat est calculé par la formule suivante :

((src FONCTION dst) ET plane-mask) OU (dst ET (NON plane-mask))

Aucune vérification de plage n'est effectuée sur les valeurs de premier plan (foreground), d'arrière-plan (background) ou de `plane_mask`. Elles sont simplement tronquées au nombre approprié de bits. L'épaisseur de ligne (line-width) est mesurée en pixels et peut être supérieure ou égale à un (ligne épaisse) ou peut être la valeur spéciale zéro (ligne fine).

Les lignes épaisses sont dessinées centrées sur le chemin décrit par la requête graphique. Sauf indication contraire spécifiée par le style de jointure (`join-style`) ou le style d'extrémité (`cap-style`), la boîte englobante d'une ligne épaisse avec les points d'extrémité [x1, y1], [x2, y2] et d'épaisseur w est un rectangle dont les sommets sont aux coordonnées réelles suivantes :

[x1-(w*sn/2), y1+(w*cs/2)], [x1+(w*sn/2), y1-(w*cs/2)],
[x2-(w*sn/2), y2+(w*cs/2)], [x2+(w*sn/2), y2-(w*cs/2)]

Ici, sn est le sinus de l'angle de la ligne, et cs est le cosinus de l'angle de la ligne. Un pixel fait partie de la ligne et est donc dessiné si le centre du pixel est entièrement à l'intérieur de la boîte englobante (qui est vue comme ayant des bords infiniment fins). Si le centre du pixel est exactement sur la boîte englobante, il fait partie de la ligne si et seulement si l'intérieur est immédiatement à sa droite (direction d'augmentation de x). Les pixels dont les centres se trouvent sur un bord horizontal constituent un cas particulier et font partie de la ligne si et seulement si l'intérieur ou la bordure est immédiatement en dessous (direction d'augmentation de y) et que l'intérieur ou la bordure est immédiatement à droite (direction d'augmentation de x).

Les lignes fines (épaisseur de ligne zéro) sont des lignes d'un pixel de largeur dessinées à l'aide d'un algorithme non spécifié et dépendant de l'appareil. Il n'y a que deux contraintes sur cet algorithme.

1.
Si une ligne est dessinée sans être délimitée de [x1,y1] à [x2,y2] et si une autre ligne est dessinée sans être délimitée de [x1+dx,y1+dy] à [x2+dx,y2+dy], un point [x,y] est touché par le dessin de la première ligne si et seulement si le point [x+dx,y+dy] est touché par le dessin de la seconde ligne.
2.
L'ensemble effectif de points constituant une ligne ne peut pas être affecté par le découpage. C'est-à-dire qu'un point est touché dans une ligne découpée si et seulement si le point se trouve à l'intérieur de la région de découpage et que le point serait touché par la ligne lorsqu'elle est dessinée sans découpage.

Une ligne épaisse dessinée de [x1,y1] à [x2,y2] dessine toujours les mêmes pixels qu'une ligne épaisse dessinée de [x2,y2] à [x1,y1], sans compter le style d'extrémité (`cap-style`) et le style de jointure (`join-style`). Il est recommandé que cette propriété soit vraie pour les lignes fines, mais ce n'est pas obligatoire. Une épaisseur de ligne de zéro peut différer d'une épaisseur de ligne de un dans les pixels dessinés. Cela permet l'utilisation de nombreux matériels de dessin de lignes de fabricants, qui peuvent être beaucoup plus rapides que les lignes épaisses spécifiées plus précisément.

En général, dessiner une ligne fine sera plus rapide que dessiner une ligne épaisse d'épaisseur un. Cependant, en raison de leurs différents algorithmes de dessin, les lignes fines peuvent ne pas bien s'harmoniser esthétiquement avec les lignes épaisses. S'il est souhaitable d'obtenir des résultats précis et uniformes sur tous les affichages, un client doit toujours utiliser une épaisseur de ligne de un plutôt qu'une épaisseur de ligne de zéro.

Le style de ligne (`line-style`) définit quelles sections d'une ligne sont dessinées :

LineSolid Le chemin complet de la ligne est dessiné.
LineDoubleDash Le chemin complet de la ligne est dessiné, mais les tirets pairs sont remplis différemment des tirets impairs (voir le style de remplissage) avec le style CapButt utilisé là où les tirets pairs et impairs se rencontrent.
LineOnOffDash Seuls les tirets pairs sont dessinés, et le style d'extrémité s'applique à toutes les extrémités internes des tirets individuels, sauf que CapNotLast est traité comme CapButt.

Le style d'extrémité (`cap-style`) définit comment les extrémités d'un chemin sont dessinées :

CapNotLast Ceci est équivalent à CapButt, sauf que pour une épaisseur de ligne de zéro, la dernière extrémité n'est pas dessinée.
CapButt La ligne est carrée à l'extrémité (perpendiculaire à la pente de la ligne) sans projection au-delà.
CapRound La ligne a un arc circulaire dont le diamètre est égal à l'épaisseur de ligne, centré sur l'extrémité. (Ceci est équivalent à CapButt pour une épaisseur de ligne de zéro).
CapProjecting La ligne est carrée à l'extrémité, mais le chemin se prolonge au-delà de l'extrémité sur une distance égale à la moitié de l'épaisseur de ligne. (Ceci est équivalent à CapButt pour une épaisseur de ligne de zéro).

Le style de jointure (`join-style`) définit comment les coins sont dessinés pour les lignes épaisses :

JoinMiter Les bords extérieurs de deux lignes s'étendent pour se rencontrer à un angle. Cependant, si l'angle est inférieur à 11 degrés, alors un style de jointure JoinBevel est utilisé à la place.
JoinRound Le coin est un arc circulaire dont le diamètre est égal à l'épaisseur de ligne, centré sur le point de jonction.
JoinBevel Le coin a des styles d'extrémité CapButt avec l'encoche triangulaire remplie.

Pour une ligne avec des points d'extrémité coïncidents (x1=x2, y1=y2), lorsque le style d'extrémité est appliqué aux deux extrémités, la sémantique dépend de l'épaisseur de ligne et du style d'extrémité :

CapNotLast fine Les résultats dépendent de l'appareil, mais l'effet désiré est que rien ne soit dessiné.
CapButt fine Les résultats dépendent de l'appareil, mais l'effet désiré est qu'un seul pixel soit dessiné.
CapRound fine Les résultats sont les mêmes que pour CapButt /fine.
CapProjecting fine Les résultats sont les mêmes que pour CapButt /fine.
CapButt épaisse Rien n'est dessiné.
CapRound épaisse Le chemin fermé est un cercle, centré sur le point d'extrémité, et avec un diamètre égal à l'épaisseur de ligne.
CapProjecting épaisse Le chemin fermé est un carré, aligné avec les axes de coordonnées, centré sur le point d'extrémité, et avec des côtés égaux à l'épaisseur de ligne.

Pour une ligne avec des points d'extrémité coïncidents (x1=x2, y1=y2), lorsque le style de jointure est appliqué à une ou deux extrémités, l'effet est comme si la ligne était retirée du chemin global. Cependant, si le chemin total consiste en un seul point joint à lui-même ou s'y réduit, l'effet est le même que lorsque le style d'extrémité est appliqué aux deux extrémités.

La mosaïque/le motif (`tile`/`stipple`) représente un plan bidimensionnel infini, la mosaïque/le motif étant répété dans toutes les dimensions. Lorsque ce plan est superposé sur le drawable pour être utilisé dans une opération graphique, le coin supérieur gauche d'une instance quelconque de la mosaïque/du motif se trouve aux coordonnées spécifiées dans le drawable par l'origine de la mosaïque/du motif (`tile`/`stipple origin`). Les origines de la mosaïque/du motif et du découpage sont interprétées par rapport à l'origine de tout drawable de destination spécifié dans une requête graphique. La pixmap de mosaïque doit avoir la même racine (`root`) et la même profondeur (`depth`) que le GC, sinon une erreur BadMatch se produit. La pixmap de motif doit avoir une profondeur de un et doit avoir la même racine que le GC, sinon une erreur BadMatch se produit. Pour les opérations de motif où le style de remplissage est FillStippled mais pas FillOpaqueStippled, le motif est carrelé dans un seul plan et agit comme un masque de découpage supplémentaire à combiner par un ET logique avec le masque de découpage. Bien que certaines tailles puissent être plus rapides à utiliser que d'autres, n'importe quelle pixmap de n'importe quelle taille peut être utilisée pour le carrelage ou le motif.

Le style de remplissage (`fill-style`) définit le contenu de la source pour les requêtes de ligne, de texte et de remplissage. Pour toutes les requêtes de texte et de remplissage (par exemple, XDrawText, XDrawText16, XFillRectangle, XFillPolygon et XFillArc) ; pour les requêtes de ligne avec le style de ligne LineSolid (par exemple, XDrawLine, XDrawSegments, XDrawRectangle, XDrawArc) ; et pour les tirets pairs des requêtes de ligne avec le style de ligne LineOnOffDash ou LineDoubleDash, ce qui suit s'applique :

FillSolid Premier plan (Foreground)
FillTiled Mosaïque (Tile)
FillOpaqueStippled Une mosaïque de même largeur et hauteur que le motif, mais avec l'arrière-plan partout où le motif a un zéro et avec le premier plan partout où le motif a un un
FillStippled Premier plan masqué par le motif

NAME

SYNTAX

    Display *display,
    GC gc,

    XGCValues *values
);

DESCRIPTION

The XChangeGC function copies the specified components from the values structure to the specified graphics context.

The valueMask specifies which components are copied from values to the GC. Only the components whose corresponding bits are set in valueMask are changed.

The following table shows the valid mask bits and the corresponding structure members and values:

If the value specified for fill_style is FillOpaqueStippled, the foreground and background colors are used.

If the value specified for fill_style is FillSolid, FillTiled, or FillOpaqueStippled, the fill_rule value is used.

If the value specified for line_style is LineOnOffDash or LineDoubleDash, the dash_offset, line_width, cap_style, and join_style values are used.

If the value specified for line_style is LineSolid, the line_width, cap_style, and join_style values are used.

If the value specified for fill_style is FillTiled or FillStippled, the tile and stipple values are used. The tile and stipple pixmaps must have the same root as the GC and must have the same depth. The tile_x_origin and tile_y_origin values specify the origin of the tile pattern relative to the window origin. The stipple_x_origin and stipple_y_origin values specify the origin of the stipple pattern relative to the window origin.

When drawing lines with line-style LineDoubleDash, the odd dashes are controlled by the fill-style in the following manner:

FillSolid Background
FillTiled Same as for even dashes
FillOpaqueStippled Same as for even dashes
FillStippled Background masked by stipple

Storing a pixmap in a GC might or might not result in a copy being made. If the pixmap is later used as the destination for a graphics request, the change might or might not be reflected in the GC. If the pixmap is used simultaneously in a graphics request both as a destination and as a tile or stipple, the results are undefined.

For optimum performance, you should draw as much as possible with the same GC (without changing its components). The costs of changing GC components relative to using different GCs depend on the display hardware and the server implementation. It is quite likely that some amount of GC information will be cached in display hardware and that such hardware can only cache a small number of GCs.

The dashes value is actually a simplified form of the more general patterns that can be set with XSetDashes. Specifying a value of N is equivalent to specifying the two-element list [N, N] in XSetDashes. The value must be nonzero, or a BadValue error results.

The clip-mask restricts writes to the destination drawable. If the clip-mask is set to a pixmap, it must have depth one and have the same root as the GC, or a BadMatch error results. If clip-mask is set to None, the pixels are always drawn regardless of the clip origin. The clip-mask also can be set by calling the XSetClipRectangles or XSetRegion functions. Only pixels where the clip-mask has a bit set to 1 are drawn. Pixels are not drawn outside the area covered by the clip-mask or where the clip-mask has a bit set to 0. The clip-mask affects all graphics requests. The clip-mask does not clip sources. The clip-mask origin is interpreted relative to the origin of whatever destination drawable is specified in a graphics request.

You can set the subwindow-mode to ClipByChildren or IncludeInferiors. For ClipByChildren, both source and destination windows are additionally clipped by all viewable InputOutput children. For IncludeInferiors, neither source nor destination window is clipped by inferiors. This will result in including subwindow contents in the source and drawing through subwindow boundaries of the destination. The use of IncludeInferiors on a window of one depth with mapped inferiors of differing depth is not illegal, but the semantics are undefined by the core protocol.

The fill-rule defines what pixels are inside (drawn) for paths given in XFillPolygon requests and can be set to EvenOddRule or WindingRule. For EvenOddRule, a point is inside if an infinite ray with the point as origin crosses the path an odd number of times. For WindingRule, a point is inside if an infinite ray with the point as origin crosses an unequal number of clockwise and counterclockwise directed path segments. A clockwise directed path segment is one that crosses the ray from left to right as observed from the point. A counterclockwise segment is one that crosses the ray from right to left as observed from the point. The case where a directed line segment is coincident with the ray is uninteresting because you can simply choose a different ray that is not coincident with a segment.

For both EvenOddRule and WindingRule, a point is infinitely small, and the path is an infinitely thin line. A pixel is inside if the center point of the pixel is inside and the center point is not on the boundary. If the center point is on the boundary, the pixel is inside if and only if the polygon interior is immediately to its right (x increasing direction). Pixels with centers on a horizontal edge are a special case and are inside if and only if the polygon interior is immediately below (y increasing direction).

The arc-mode controls filling in the XFillArcs function and can be set to ArcPieSlice or ArcChord. For ArcPieSlice, the arcs are pie-slice filled. For ArcChord, the arcs are chord filled.

The graphics-exposure flag controls GraphicsExpose event generation for XCopyArea and XCopyPlane requests (and any similar requests defined by extensions).

BadAlloc
The server failed to allocate the requested resource or server memory.

A value for a Drawable argument does not name a defined Window or Pixmap.

A value for a Font or GContext argument does not name a defined Font.

A value for a GContext argument does not name a defined GContext.

An InputOnly window is used as a Drawable.

Some argument or pair of arguments has the correct type and range but fails to match in some other way required by the request.
BadPixmap
A value for a Pixmap argument does not name a defined Pixmap.
BadValue
