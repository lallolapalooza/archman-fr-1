NOM

Xcursor — Bibliothèque de gestion des curseurs

SYNTAXE

#include <X11/Xcursor/Xcursor.h>

DESCRIPTION

Xcursor est une bibliothèque simple conçue pour aider à localiser et charger des curseurs. Les curseurs peuvent être chargés à partir de fichiers ou de la mémoire. Il existe une bibliothèque de curseurs courants qui correspondent aux noms de curseurs X standard. Les curseurs peuvent exister dans plusieurs tailles et la bibliothèque choisit automatiquement la meilleure taille.

APERÇU FONCTIONNEL

Xcursor est construit en plusieurs couches ; la couche inférieure contient le code qui peut charger des images de curseur à partir de fichiers. Au-dessus se trouve une couche qui localise les fichiers de curseur en fonction du chemin de la bibliothèque et du thème. Au sommet se trouve une couche qui construit des curseurs soit à partir d'une image chargée à partir d'un fichier, soit à partir d'un des curseurs X standard. Lors de l'utilisation d'images chargées à partir de fichiers, Xcursor préfère utiliser la requête CreateCursor de l'extension Render si elle est prise en charge par le serveur X. Lorsque ce n'est pas pris en charge, Xcursor mappe l'image du curseur à un curseur X standard et utilise la requête CreateCursor principale.

FICHIERS DE CURSEUR

Xcursor définit un nouveau format pour les curseurs sur disque. Chaque fichier contient une ou plusieurs images de curseur. Chaque image de curseur est étiquetée avec une taille nominale afin que la meilleure taille puisse être sélectionnée automatiquement. Plusieurs curseurs de la même taille nominale peuvent être chargés ensemble ; les applications sont censées les utiliser comme une séquence animée.

Les fichiers de curseur sont stockés sous la forme d'un en-tête contenant une table des matières suivie d'une séquence de blocs. La table des matières indique le type, le sous-type et la position dans le fichier de chaque bloc. L'en-tête du fichier ressemble à ceci :


magie:	CARD32 "Xcur" (0x58, 0x63, 0x75, 0x72)
en-tête:	CARD32 octets dans cet en-tête
version:	CARD32 numéro de version du fichier
ntoc:	CARD32 nombre d'entrées de table des matières
toc:	LISTofTOC table des matières

Chaque entrée de la table des matières ressemble à ceci :


type:	CARD32 type d'entrée
sous-type:	CARD32 étiquette spécifique au type - taille pour les images
position:	CARD32 position absolue en octets de la table dans le fichier

Chaque bloc dans le fichier a un ensemble de champs d'en-tête communs suivis de champs supplémentaires spécifiques au type :


en-tête:	CARD32 octets dans l'en-tête du bloc (y compris les champs spécifiques au type)
type:	CARD32 doit correspondre au type dans la table des matières pour ce bloc
sous-type:	CARD32 doit correspondre au sous-type dans la table des matières pour ce bloc
version:	CARD32 numéro de version pour ce type de bloc

Il existe actuellement deux types de blocs définis pour les fichiers de curseurs ; commentaires et images. Les commentaires ressemblent à ceci :


en-tête:	20 Les en-têtes de commentaires font 20 octets
type:	0xfffe0001 Le type de commentaire est 0xfffe0001
sous-type:	{ 1 (DROIT D'AUTEUR), 2 (LICENCE), 3 (AUTRE) }
version:	1
longueur:	CARD32 longueur en octets de la chaîne UTF-8
chaîne:	LISTofCARD8 chaîne UTF-8

Les images ressemblent à ceci :


en-tête:	36 Les en-têtes d'image font 36 octets
type:	0xfffd0002 Le type d'image est 0xfffd0002
sous-type:	CARD32 Le sous-type d'image est la taille nominale
version:	1
largeur:	CARD32 Doit être inférieur ou égal à 0x7fff
hauteur:	CARD32 Doit être inférieur ou égal à 0x7fff
xhot:	CARD32 Doit être inférieur ou égal à la largeur
yhot:	CARD32 Doit être inférieur ou égal à la hauteur
délai:	CARD32 Délai entre les images d'animation en millisecondes
pixels:	LISTofCARD32 Pixels au format ARGB compressé

THÉMATIQUES

Xcursor suit (principalement) la spécification freedesktop.org pour la thématisation des icônes. Le chemin de recherche par défaut qu'il utilise est

~/.local/share/icons, ~/.icons, /usr/share/icons, /usr/share/pixmaps

Dans chacun de ces répertoires, il recherche un répertoire portant le nom du thème :

•
Dans le répertoire du thème, il recherche des fichiers de curseurs dans le sous-répertoire « cursors ».
Xcursor recherche un fichier spécifique, qui doit être l'un des noms de forme du curseur, par exemple, tel qu'utilisé dans XcursorLibraryLoadImage ou XcursorLibraryShape.
•
S'il ne trouve aucun fichier de curseur correspondant dans le sous-répertoire « cursors », Xcursor recherche ensuite un fichier « index.theme » dans chaque répertoire de thème pour rechercher les thèmes hérités. Ce sont des lignes dans ce format :
Hérite = nom-du-thème

Xcursor utilise le premier nom-du-thème hérité, ignorant les autres qui peuvent exister dans un fichier « index.theme » donné. S'il trouve un thème hérité, Xcursor recherche également le long du chemin pour l'utiliser. Xcursor ignore les autres clés dans le fichier « index.theme », y compris « Nom » (c'est-à-dire le nom qu'une application graphique peut utiliser comme nom de présentation).

Plusieurs noms-de-thème peuvent être listés sur la ligne Hérite=. La spécification freedesktop.org indique que les éléments de la liste sont séparés par des virgules. Xcursor accepte également le point-virgule, mais traduit les deux en deux-points lors de la recherche dans le chemin. Xcursor attend une seule ligne Hérite= ; la spécification freedesktop.org ne précise pas si plusieurs clés sont autorisées.

Si aucun thème n'est défini, ou si aucun curseur n'est trouvé pour le thème spécifié n'importe où sur le chemin, Xcursor vérifie le thème « default ».

Lorsque Xcursor trouve un fichier de curseur, il arrête la recherche. Il utilise toujours le premier fichier de curseur trouvé lors de la recherche le long du chemin.

TYPES DE DONNÉES

XcursorImage
contient une seule image de curseur en mémoire. Chaque pixel du curseur est une valeur de 32 bits contenant ARGB avec A dans l'octet de poids fort. 


typedef struct _XcursorImage {
    XcursorDim 	 size; 	/* taille nominale pour la correspondance */
    XcursorDim 	 width; 	/* largeur réelle */
    XcursorDim 	 height; 	/* hauteur réelle */
    XcursorDim 	 xhot; 	/* point chaud x (doit être à l'intérieur de l'image) */
    XcursorDim 	 yhot; 	/* point chaud y (doit être à l'intérieur de l'image) */
    XcursorPixel 	*pixels; 	/* pointeur vers les pixels */
} XcursorImage;
XcursorImages
contient plusieurs structures XcursorImage. Elles sont toutes libérées lorsque les XcursorImages sont libérées dans XcursorImagesDestroy. 


typedef struct _XcursorImages {
    int 	 nimage; 	/* nombre d'images */
    XcursorImage 	**images; 	/* tableau de pointeurs XcursorImage */
} XcursorImages;
XcursorCursors
Contient plusieurs objets Cursor. Ils sont tous libérés lorsque le XcursorCursors est libéré. Ils sont référencés par comptage afin que plusieurs structures XcursorAnimate puissent utiliser le même XcursorCursors. 


typedef struct _XcursorCursors {
    Display 	*dpy; 	/* Affichage contenant les curseurs */
    int 	 ref; 	/* compteur de références */
    int 	 ncursor; 	/* nombre de curseurs */
    Cursor 	*cursors; 	/* tableau de curseurs */
} XcursorCursors;
XcursorAnimate
Référence un ensemble de curseurs et une séquence dans cet ensemble. Plusieurs structures XcursorAnimate peuvent référencer le même XcursorCursors ; chacune détient une référence qui est supprimée lorsque le XcursorAnimate est libéré. 


typedef struct _XcursorAnimate {
    XcursorCursors 	*cursors; 	/* liste des curseurs à utiliser */
    int 	 sequence; 	/* quel curseur est le prochain */
} XcursorAnimate;

Ces fonctions recherchent dans le chemin de la bibliothèque, en chargeant le premier fichier trouvé de la taille souhaitée, en utilisant une fonction privée (XcursorScanTheme) pour trouver le thème approprié :

  • Si theme n'est pas NULL, utilisez-le.
  • Si theme est NULL, ou s'il n'y a pas eu de correspondance pour le thème souhaité, utilisez “default” comme nom de thème.
  • Si aucune des recherches ne réussit, ces fonctions retournent NULL.
Les deux fonctions diffèrent par plus que le nombre d'images chargées :
  • XcursorLibraryLoadImage appelle XcursorFileLoadImage mais
  • XcursorLibraryLoadImages appelle XcursorFileLoadImages, et (en cas de succès) il appelle XcursorImagesSetName pour associer name au résultat.

ENVIRONNEMENT


Les variables d'environnement peuvent être utilisées pour remplacer
    les paramètres de ressources, qui à leur tour remplacent les valeurs par
    défaut compilées.


Certaines des variables d'environnement reconnues par Xcursor sont
    des booléens, spécifiés comme suit :





  
vrai pour
    “t”, “1”, “y” ou
    “on”

  

  
faux pour
    “f”, “0”, “n” ou
    “off”

  






Xcursor ignore les autres valeurs pour ces booléens.



  
HOME

  
Xcursor interprète “~” dans la liste de recherche comme le
      répertoire personnel, en utilisant cette variable plutôt que la base de
      données de mots de passe.

  
XCURSOR_ANIM

  
Si l'affichage prend en charge la requête Render CreateCursor et que la
      fonctionnalité Render est activée, désactive les curseurs animés si
      la variable d'environnement est false.





  

  
Si la variable d'environnement n'est pas fournie, Xcursor utilise la
      ressource Xcursor.anim.





  
XCURSOR_CORE

  
Si l'affichage prend en charge la requête Render CreateCursor, désactive la
      fonctionnalité Render si la variable d'environnement est false.





  

  
Si la variable d'environnement n'est pas fournie, Xcursor utilise la
      ressource Xcursor.core.





  
XCURSOR_DISCOVER

  
Si la variable est définie, Xcursor active une fonctionnalité de journalisation.
      Elle affiche la valeur de hachage et l'image afin que les utilisateurs
      puissent voir quel nom de curseur est associé à chaque image.





  

  
Il n'y a pas de paramètre de ressource correspondant.





  
XCURSOR_DITHER

  
Cette variable définit le dithering souhaité.





  

  
Si la variable d'environnement n'est pas fournie, Xcursor utilise la
      ressource Xcursor.dither.

  

  
Si ni la variable d'environnement ni la ressource ne sont trouvées, Xcursor
      utilise “threshold”

  

  
Ce sont les valeurs reconnues :







  
diffuse

  

  
median

  

  
ordered

  

  
threshold

  







  
XCURSOR_PATH

  
Cette variable définit la liste des chemins dans lesquels rechercher les
      curseurs, plutôt que la liste par défaut compilée.





  

  
Les répertoires de ce chemin sont séparés par des deux-points (:).





  
XCURSOR_RESIZED

  
Active le redimensionnement automatique des curseurs pour améliorer leur
      taille affichée si la variable d'environnement est true.





  

  
Si la variable d'environnement n'est pas fournie, Xcursor essaie la
      ressource Xcursor.resized.





  
XCURSOR_SIZE

  
Cette variable définit la taille de curseur souhaitée, en pixels.





  

  
Si la variable d'environnement n'est pas fournie, Xcursor essaie la
      ressource Xcursor.size.

  

  
Si aucune taille n'est fournie, que ce soit par variable d'environnement ou
      paramètre de ressource, Xcursor essaie ensuite le paramètre de ressource
      Xft.dpi pour deviner la taille d'un curseur de 16 points.

  

  
Enfin, si Xft.dpi n'est pas défini, Xcursor utilise la hauteur de
      l'affichage, divisée par 48 (en supposant que la hauteur est de 768).





  
XCURSOR_THEME

  
Cette variable sélectionne le thème souhaité.





  

  
Si la variable d'environnement n'est pas fournie, Xcursor essaie la
      ressource Xcursor.theme.

  

  
Si ni la variable d'environnement ni la ressource ne sont trouvées, Xcursor
      utilise le thème par défaut.





  
XCURSOR_THEME_CORE

  
Active les thèmes pour les curseurs de base si la variable d'environnement est
      true.





  

  
Si la variable d'environnement n'est pas fournie, Xcursor essaie la
      ressource Xcursor.theme_core.

  

  
Une application peut activer ou désactiver les thèmes en utilisant
    XcursorSetThemeCore.
