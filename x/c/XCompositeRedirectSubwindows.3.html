NOM

Xcomposite - Bibliothèque d'extension X Composite

SYNTAXE

#include <X11/extensions/Xcomposite.h>

Bool XCompositeQueryExtension(Display *dpy, int *event_base_return, int *error_base_return);

Status XCompositeQueryVersion(Display *dpy, int *major_version_return, int *minor_version_return);

int XCompositeVersion(void);

void XCompositeRedirectWindow(Display *dpy, Window window, int update);

void XCompositeRedirectSubwindows(Display *dpy, Window window, int update);

void XCompositeUnredirectWindow(Display *dpy, Window window, int update);

void XCompositeUnredirectSubwindows(Display *dpy, Window window, int update);

XserverRegion XCompositeCreateRegionFromBorderClip(Display *dpy, Window window);

Pixmap XCompositeNameWindowPixmap(Display *dpy, Window window);

Window XCompositeGetOverlayWindow(Display *dpy, Window window);

void XCompositeReleaseOverlayWindow(Display *dpy, Window window);

DESCRIPTION

L'extension composite fournit plusieurs mécanismes connexes :

Stockage par hiérarchie

Le rendu d'une hiérarchie entière de fenêtres est redirigé vers un stockage hors écran. Les pixels de cette hiérarchie sont disponibles dès qu'elle est visible. Le stockage est automatiquement réalloué lorsque la fenêtre de niveau supérieur change de taille. Le contenu au-delà de la géométrie de la fenêtre supérieure n'est pas préservé.

Mise à jour automatique des ombres

Lorsqu'une hiérarchie est rendue hors écran, le serveur X fournit un mécanisme automatique pour présenter ce contenu dans la fenêtre parente. L'implémentation est libre de faire en sorte que cette mise à jour soit légèrement retardée par rapport aux opérations de rendu réelles. Ce mécanisme de mise à jour automatique peut être désactivé afin que le contenu de la fenêtre parente puisse être entièrement déterminé par une application externe.

Fenêtre de superposition composite

La version 0.3 du protocole ajoute la fenêtre de superposition composite, qui fournit aux gestionnaires de composition une surface sur laquelle dessiner sans interférence. Cette fenêtre est toujours au-dessus des fenêtres normales et toujours en dessous de la fenêtre de l'économiseur d'écran. C'est une fenêtre InputOutput dont la largeur et la hauteur correspondent aux dimensions de l'écran. Son visuel est le visuel racine et sa bordure est de largeur zéro. Les tentatives de redirection à l'aide de l'extension composite sont ignorées. Cette fenêtre n'apparaît pas dans la réponse de la requête QueryTree. C'est également une fenêtre override-redirect. Ces deux dernières caractéristiques la rendent invisible aux gestionnaires de fenêtres et autres clients X11. La seule façon d'accéder au XID de cette fenêtre est via la requête CompositeGetOverlayWindow. Initialement, la fenêtre de superposition composite est non mappée.

Clipping de la fenêtre parente

La version 0.4 du protocole modifie la sémantique du clipping de la fenêtre parente en présence d'enfants redirigés manuellement. Avec cette version, la zone dans le parent couverte par les enfants redirigés manuellement est laissée dans la liste de clipping du parent au lieu d'être supprimée comme dans les versions précédentes.

Le stockage hors écran comprend le contenu de la fenêtre, ses bordures et le contenu de tous les descendants.

ARGUMENTS

display

Pointeur vers la structure Display retournée par XOpenDisplay pour la connexion au serveur X.

event_base_return

Pointeur vers un entier où sera stockée la valeur de base pour les événements de l'extension Composite.

error_base_return

Pointeur vers un entier où sera stockée la valeur de base pour les erreurs de l'extension Composite.

major_version_return

Pointeur vers un entier où sera stockée la version majeure de l'extension Composite prise en charge par le serveur X.

minor_version_return

Pointeur vers un entier où sera stockée la version mineure de l'extension Composite prise en charge par le serveur X.

window

Spécifie l'ID de la fenêtre sur laquelle opérer.

update

Spécifie le mode de mise à jour du contenu de la fenêtre. Doit être soit CompositeRedirectAutomatic, soit CompositeRedirectManual.

FONCTIONS

XCompositeQueryExtension

XCompositeQueryExtension détermine si l'extension Composite est disponible sur l'affichage donné. Elle retourne True si l'extension est prise en charge, sinon False. Si l'extension est présente, les valeurs de base pour les événements et les erreurs sont retournées et peuvent être utilisées pour décoder les valeurs d'événements et d'erreurs entrantes.

XCompositeQueryVersion

XCompositeQueryVersion détermine si le serveur X prend en charge une version de l'extension X Composite compatible avec la bibliothèque client. Un statut non nul est retourné si une version compatible de l'extension est prise en charge, sinon un statut nul est retourné. Si l'extension est prise en charge, les numéros de version majeure et mineure sont retournés pour indiquer le niveau de prise en charge de l'extension Composite. Aucune autre fonction XComposite (sauf XCompositeQueryExtension) ne peut être appelée avant cette fonction. Si un client viole cette règle, les effets de tous les appels XComposite ultérieurs qu'il effectue sont indéfinis.

XCompositeVersion

XCompositeVersion retourne la version de la bibliothèque X Composite. Le numéro de version est codé comme suit : (majeure * 10000) + (mineure * 100) + révision

Par exemple, la version 1.4.6 serait codée comme l'entier 10406.

XCompositeRedirectWindow

XCompositeRedirectWindow demande au serveur X de rediriger la hiérarchie commençant à window vers un stockage hors écran. L'argument update spécifie si le contenu est automatiquement mis en miroir dans la fenêtre parente ou non. Un seul client à la fois peut spécifier un type de mise à jour CompositeRedirectManual ; une autre tentative entraînera une erreur BadAccess. Lorsque tous les clients activant la redirection terminent, la redirection sera automatiquement désactivée.

La fenêtre racine ne peut pas être redirigée. Cela entraîne une erreur BadMatch. La spécification d'un identifiant de fenêtre invalide entraînera une erreur BadWindow.

XCompositeRedirectSubwindows

XCompositeRedirectSubwindows demande au serveur X de rediriger les hiérarchies commençant à tous les enfants actuels et futurs de window comme dans XCompositeRedirectWindow. Si update est CompositeRedirectManual, alors la peinture de l'arrière-plan de la fenêtre pendant la manipulation de la fenêtre et les requêtes ClearArea est inhibée.

XCompositeUnredirectWindow

XCompositeUnredirectWindow demande au serveur X de terminer la redirection de window. Si la fenêtre spécifiée n'a pas été sélectionnée pour la redirection par le client actuel, une erreur BadValue en résulte.

XCompositeUnredirectSubwindows

XCompositeUnredirectSubwindows demande au serveur X de terminer la redirection de tous les enfants de window. Si la fenêtre spécifiée n'a pas été sélectionnée pour la sous-redirection par le client actuel, une erreur BadValue en résulte.

XCompositeCreateRegionFromBorderClip

Cette région peut être utilisée pour restreindre le rendu aux zones appropriées tout en mettant à jour une seule fenêtre. La région est copiée au moment où la requête est exécutée ; les changements futurs de la hiérarchie des fenêtres ne seront pas reflétés dans cette région.

XCompositeNameWindowPixmap

XCompositeNameWindowPixmap crée et retourne un identifiant de pixmap qui sert de référence au stockage hors écran pour window. Ce pixmap restera alloué jusqu'à sa libération, même si la fenêtre est démappée, reconfigurée ou détruite. Cependant, la fenêtre obtiendra un nouveau pixmap alloué chaque fois qu'elle sera mappée ou redimensionnée, donc cette fonction devra être réinvoquée pour que le client puisse continuer à faire référence au stockage contenant le contenu actuel de la fenêtre. Génère une erreur BadMatch si window n'est pas redirigée ou n'est pas visible.

Le serveur X doit supporter au moins la version 0.2 de l'Extension Composite pour XCompositeNameWindowPixmap.

XCompositeGetOverlayWindow

XCompositeGetOverlayWindow retourne l'identifiant de la fenêtre de la fenêtre de superposition Composite pour l'écran spécifié par l'argument window. Cette fonction notifie le serveur X que le client souhaite utiliser la fenêtre de superposition Composite de cet écran. Si cette fenêtre de superposition Composite n'a pas encore été mappée, elle est mappée par cette requête.

La fenêtre de superposition Composite pour un écran particulier sera démappée lorsque tous les clients qui ont appelé cette fonction auront soit appelé XCompositeReleaseOverlayWindow pour cet écran, soit terminé leur connexion au serveur X.

Le serveur X doit supporter au moins la version 0.3 de l'Extension Composite pour XCompositeGetOverlayWindow.

XCompositeReleaseOverlayWindow

Cette requête spécifie que le client n'utilise plus la fenêtre de superposition Composite sur l'écran spécifié par l'argument window. La fenêtre de superposition Composite d'un écran est démappée lorsqu'il n'y a plus de clients qui l'utilisent.

Le serveur X doit supporter au moins la version 0.3 de l'Extension Composite pour XCompositeReleaseOverlayWindow.
