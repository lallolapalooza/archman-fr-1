NOM

Xcursor — Bibliothèque de gestion des curseurs

SYNTAXE

#include <X11/Xcursor/Xcursor.h>

DESCRIPTION

Xcursor est une bibliothèque simple conçue pour aider à localiser et charger les curseurs. Les curseurs peuvent être chargés à partir de fichiers ou de la mémoire. Une bibliothèque de curseurs courants existe et correspond aux noms de curseurs X standard. Les curseurs peuvent exister en plusieurs tailles et la bibliothèque sélectionne automatiquement la meilleure taille.

APERÇU FONCTIONNEL

Xcursor est construit en plusieurs couches ; la couche inférieure contient le code qui peut charger des images de curseurs à partir de fichiers. Au-dessus se trouve une couche qui localise les fichiers de curseurs en fonction du chemin de la bibliothèque et du thème. Au sommet se trouve une couche qui construit les curseurs soit à partir d'une image chargée à partir d'un fichier, soit à partir d'un des curseurs X standard. Lors de l'utilisation d'images chargées à partir de fichiers, Xcursor préfère utiliser la requête CreateCursor de l'extension Render si elle est prise en charge par le serveur X. Là où elle n'est pas prise en charge, Xcursor mappe l'image du curseur vers un curseur X standard et utilise la requête CreateCursor principale.

FICHIERS DE CURSEURS

Xcursor définit un nouveau format pour les curseurs sur disque. Chaque fichier contient une ou plusieurs images de curseurs. Chaque image de curseur est étiquetée avec une taille nominale afin que la meilleure taille puisse être sélectionnée automatiquement. Plusieurs curseurs de la même taille nominale peuvent être chargés ensemble ; les applications sont censées les utiliser comme une séquence animée.

Les fichiers de curseurs sont stockés sous forme d'en-tête contenant une table des matières suivie d'une séquence de blocs. La table des matières indique le type, le sous-type et la position dans le fichier de chaque bloc. L'en-tête du fichier ressemble à ceci :


magic:	CARD32 "Xcur" (0x58, 0x63, 0x75, 0x72)
header:	CARD32 octets dans cet en-tête
version:	CARD32 numéro de version du fichier
ntoc:	CARD32 nombre d'entrées toc
toc:	LISTofTOC table des matières

Chaque entrée de table des matières ressemble à ceci :


type:	CARD32 type d'entrée
subtype:	CARD32 étiquette spécifique au type - taille pour les images
position:	CARD32 position absolue en octets de la table dans le fichier

Chaque bloc dans le fichier a un ensemble d'en-têtes communs suivis de champs supplémentaires spécifiques au type :


header:	CARD32 octets dans l'en-tête du bloc (y compris les champs spécifiques au type)
type:	CARD32 doit correspondre au type dans le TOC pour ce bloc
subtype:	CARD32 doit correspondre au sous-type dans le TOC pour ce bloc
version:	CARD32 numéro de version pour ce type de bloc

Il existe actuellement deux types de blocs définis pour les fichiers de curseurs ; les commentaires et les images. Les commentaires ressemblent à ceci :


header:	20 Les en-têtes de commentaires font 20 octets
type:	0xfffe0001 Le type de commentaire est 0xfffe0001
subtype:	{ 1 (COPYRIGHT), 2 (LICENSE), 3 (OTHER) }
version:	1
length:	CARD32 longueur en octets de la chaîne UTF-8
string:	LISTofCARD8 chaîne UTF-8

Les images ressemblent à ceci :


header:	36 Les en-têtes d'images font 36 octets
type:	0xfffd0002 Le type d'image est 0xfffd0002
subtype:	CARD32 Le sous-type d'image est la taille nominale
version:	1
width:	CARD32 Doit être inférieur ou égal à 0x7fff
height:	CARD32 Doit être inférieur ou égal à 0x7fff
xhot:	CARD32 Doit être inférieur ou égal à la largeur
yhot:	CARD32 Doit être inférieur ou égal à la hauteur
delay:	CARD32 Délai entre les images animées en millisecondes
pixels:	LISTofCARD32 Pixels au format ARGB packé

THÈMES

Xcursor suit (principalement) les spécifications de freedesktop.org pour les thèmes d'icônes. Le chemin de recherche par défaut qu'il utilise est

~/.local/share/icons, ~/.icons, /usr/share/icons, /usr/share/pixmaps

Dans chacun de ces répertoires, il recherche un répertoire utilisant le nom du thème :

•
Dans le répertoire du thème, il recherche les fichiers de curseurs dans le sous-répertoire “cursors”.
Xcursor recherche un fichier spécifique, qui doit être l'un des noms de forme du curseur, par exemple, tels qu'utilisés dans XcursorLibraryLoadImage ou XcursorLibraryShape.
•
S'il ne trouve aucun fichier de curseur correspondant dans le sous-répertoire “cursors”, Xcursor recherche ensuite un fichier “index.theme” dans chaque répertoire de thème pour rechercher les thèmes hérités. Ceux-ci sont au format :
Inherits = nom-du-thème

Xcursor utilise le premier nom-du-thème hérité, ignorant les autres qui peuvent exister dans un fichier “index.theme” donné. S'il trouve un thème hérité, Xcursor recherche le chemin pour l'utiliser également. Xcursor ignore les autres clés dans le fichier “index.theme”, y compris “Name” (c'est-à-dire le nom qu'une application graphique peut utiliser comme nom de présentation).

Plusieurs nom-du-thème peuvent être listés sur la ligne Inherits=. La spécification freedesktop.org indique que les éléments de la liste sont séparés par des virgules. Xcursor accepte également le point-virgule, mais traduit les deux en deux-points lors de la recherche dans le chemin. Xcursor attend une seule ligne Inherits= ; la spécification freedesktop.org n'est pas claire quant à savoir si plusieurs clés sont autorisées.

Si aucun thème n'est défini, ou si aucun curseur n'est trouvé pour le thème spécifié quelque part dans le chemin, Xcursor vérifie le thème “default”.

Lorsque Xcursor trouve un fichier de curseur, il arrête la recherche. Il utilise toujours le premier fichier de curseur trouvé lors de la recherche le long du chemin.

TYPES DE DONNÉES

XcursorImage
contient une seule image de curseur en mémoire. Chaque pixel du curseur est une valeur de 32 bits contenant ARGB avec A dans l'octet de poids fort. 


typedef struct _XcursorImage {
    XcursorDim 	 size; 	/* taille nominale pour la correspondance */
    XcursorDim 	 width; 	/* largeur réelle */
    XcursorDim 	 height; 	/* hauteur réelle */
    XcursorDim 	 xhot; 	/* point chaud x (doit être à l'intérieur de l'image) */
    XcursorDim 	 yhot; 	/* point chaud y (doit être à l'intérieur de l'image) */
    XcursorPixel 	*pixels; 	/* pointeur vers les pixels */
} XcursorImage;
XcursorImages
contient plusieurs structures XcursorImage. Elles sont toutes libérées lorsque XcursorImages est libéré dans XcursorImagesDestroy. 


typedef struct _XcursorImages {
    int 	 nimage; 	/* nombre d'images */
    XcursorImage 	**images; 	/* tableau de pointeurs XcursorImage */
} XcursorImages;
XcursorCursors
Contient plusieurs objets Cursor. Ils sont tous libérés lorsque XcursorCursors est libéré. Ceux-ci sont comptés par référence afin que plusieurs structures XcursorAnimate puissent utiliser le même XcursorCursors. 


typedef struct _XcursorCursors {
    Display 	*dpy; 	/* Affichage contenant les curseurs */
    int 	 ref; 	/* compteur de références */
    int 	 ncursor; 	/* nombre de curseurs */
    Cursor 	*cursors; 	/* tableau de curseurs */
} XcursorCursors;
XcursorAnimate
Fait référence à un ensemble de curseurs et à une séquence dans cet ensemble. Plusieurs structures XcursorAnimate peuvent faire référence au même XcursorCursors ; chacune détient une référence qui est supprimée lorsque XcursorAnimate est libéré. 


typedef struct _XcursorAnimate {
    XcursorCursors 	*cursors; 	/* liste des curseurs à utiliser */
    int 	 sequence; 	/* quel curseur est le suivant */
} XcursorAnimate;
XcursorFile
Xcursor fournit une API abstraite pour accéder aux données des fichiers. Xcursor fournit une implémentation stdio de cette API abstraite ; les applications sont libres de créer des implémentations supplémentaires. Ces fonctions sont parallèles aux fonctions stdi

Lecture des images de la bibliothèque

XcursorImage *XcursorLibraryLoadImage (
const char 	*name,
const char 	*theme,
int 	 size)
XcursorImages *XcursorLibraryLoadImages (
	const char 	*name,
	const char 	*theme,
	int 	 size)

Ces fonctions recherchent dans le chemin de la bibliothèque, chargeant le premier fichier trouvé de la taille désirée, en utilisant une fonction privée (XcursorScanTheme) pour trouver le thème approprié :

  • Si theme n'est pas NULL, il est utilisé.
  • Si theme est NULL, ou s'il n'y a pas eu de correspondance pour le thème désiré, "default" est utilisé comme nom de thème.
  • Si aucune des recherches ne réussit, ces fonctions retournent NULL.
Les deux fonctions diffèrent par plus que le nombre d'images chargées :
  • XcursorLibraryLoadImage appelle XcursorFileLoadImage mais
  • XcursorLibraryLoadImages appelle XcursorFileLoadImages, et (en cas de succès) elle appelle XcursorImagesSetName pour associer name au résultat.

R_THEME_CORE
  
Active les thèmes pour les curseurs de base si la variable d'environnement est
      true.




  

  
Si la variable d'environnement n'est pas fournie, Xcursor essaie la
      ressource Xcursor.theme_core.

  

  
Une application peut activer ou désactiver les thèmes en utilisant
    XcursorSetThemeCore.
