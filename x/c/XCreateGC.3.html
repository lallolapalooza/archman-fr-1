XCreateGC(3) FONCTIONS XLIB XCreateGC(3)

NOM

XCreateGC, XCopyGC, XChangeGC, XGetGCValues, XFreeGC, XGContextFromGC, XGCValues - créer ou libérer des contextes graphiques et la structure du contexte graphique

SYNTAXE

GC XCreateGC(Display *display, Drawable d, unsigned long valuemask, XGCValues *values);

int XCopyGC(Display *display, GC src, unsigned long valuemask, GC dest);

int XChangeGC(Display *display, GC gc, unsigned long valuemask, XGCValues *values);

Status XGetGCValues(Display *display, GC gc, unsigned long valuemask, XGCValues *values_return);

int XFreeGC(Display *display, GC gc);

GContext XGContextFromGC(GC gc);

ARGUMENTS

d
Spécifie le drawable.
dest
Spécifie le GC de destination.
display
Spécifie la connexion au serveur X.
gc
Spécifie le GC.
src
Spécifie les composants du GC source.
valuemask
Spécifie quels composants dans le GC doivent être définis, copiés, changés ou retournés. Cet argument est le OU binaire inclusif de zéro ou plus des bits de masque de composant GC valides.
values
Spécifie les valeurs comme indiqué par le valuemask.
values_return
Retourne les valeurs du GC dans la structure XGCValues spécifiée.

DESCRIPTION

La fonction XCreateGC crée un contexte graphique et retourne un GC. Le GC peut être utilisé avec n'importe quel drawable de destination ayant la même racine et la même profondeur que le drawable spécifié. L'utilisation avec d'autres drawables entraîne une erreur BadMatch.

XCreateGC peut générer des erreurs BadAlloc, BadDrawable, BadFont, BadMatch, BadPixmap, et BadValue.

La fonction XCopyGC copie les composants spécifiés de la GC source vers la GC de destination. Les GC source et destination doivent avoir la même racine et la même profondeur, sinon une erreur BadMatch est générée. Le valuemask spécifie quel composant copier, comme pour XCreateGC.

XCopyGC peut générer des erreurs BadAlloc, BadGC, et BadMatch.

La fonction XChangeGC modifie les composants spécifiés par le valuemask pour la GC spécifiée. L'argument values contient les valeurs à définir. Les valeurs et les restrictions sont les mêmes que pour XCreateGC. La modification du masque de découpage écrase toute requête précédente XSetClipRectangles sur le contexte. La modification du décalage des tirets ou de la liste des tirets écrase toute requête précédente XSetDashes sur le contexte. L'ordre dans lequel les composants sont vérifiés et modifiés dépend du serveur. Si une erreur est générée, un sous-ensemble des composants peut avoir été altéré.

XChangeGC peut générer des erreurs BadAlloc, BadFont, BadGC, BadMatch, BadPixmap, et BadValue.

La fonction XGetGCValues retourne les composants spécifiés par le valuemask pour la GC spécifiée. Si le valuemask contient un ensemble valide de bits de masque GC (GCFunction, GCPlaneMask, GCForeground, GCBackground, GCLineWidth, GCLineStyle, GCCapStyle, GCJoinStyle, GCFillStyle, GCFillRule, GCTile, GCStipple, GCTileStipXOrigin, GCTileStipYOrigin, GCFont, GCSubwindowMode, GCGraphicsExposures, GCClipXOrigin, GCClipYOrigin, GCDashOffset, ou GCArcMode) et qu'aucune erreur ne se produit, XGetGCValues définit les composants demandés dans values_return et retourne un statut non nul. Sinon, il retourne un statut nul. Notez que le masque de découpage et la liste des tirets (représentés respectivement par les bits GCClipMask et GCDashList dans le valuemask) ne peuvent pas être demandés. Notez également qu'un identifiant de ressource invalide (avec un ou plusieurs des trois bits les plus significatifs mis à 1) sera retourné pour GCFont, GCTile, et GCStipple si le composant n'a jamais été explicitement défini par le client.

La fonction XFreeGC détruit la GC spécifiée ainsi que tout le stockage associé.

XFreeGC peut générer une erreur BadGC.

La fonction dans un GC définit comment les nouveaux bits de destination doivent être calculés à partir des bits source et des anciens bits de destination. GXcopy est généralement le plus utile car il fonctionnera sur un écran couleur, mais des applications spéciales peuvent utiliser d'autres fonctions, en particulier en concertation avec des plans particuliers d'un écran couleur. De nombreuses opérations graphiques dépendent soit des valeurs des pixels, soit des plans dans un GC. L'attribut des plans est de type long, et il spécifie quels plans de la destination doivent être modifiés, un bit par plan. Un écran monochrome n'a qu'un seul plan et sera le bit le moins significatif du mot. Au fur et à mesure que des plans sont ajoutés au matériel d'affichage, ils occuperont des bits plus significatifs dans le masque de plans.

Dans les opérations graphiques, étant donné un pixel source et un pixel destination, le résultat est calculé bit par bit sur les bits correspondants des pixels. C'est-à-dire qu'une opération booléenne est effectuée dans chaque plan de bits. Le masque de plans restreint l'opération à un sous-ensemble de plans. Une constante macro AllPlanes peut être utilisée pour faire référence à tous les plans de l'écran simultanément. Le résultat est calculé par l'opération suivante :

((src FONCTION dst) ET masque-de-plans) OU (dst ET (NON masque-de-plans))

Aucune vérification des plages n'est effectuée sur les valeurs de premier plan, d'arrière-plan ou de masque de plans. Elles sont simplement tronquées au nombre approprié de bits. La largeur de ligne est mesurée en pixels et peut être supérieure ou égale à un (ligne épaisse) ou peut être la valeur spéciale zéro (ligne fine).

Les lignes épaisses sont dessinées centrées sur le chemin décrit par la requête graphique. Sauf indication contraire de la style de jointure ou du style de bout, la boîte englobante d'une ligne épaisse avec les points d'extrémité [x1, y1], [x2, y2] et une largeur w est un rectangle avec des sommets aux coordonnées réelles suivantes :

[x1-(w*sn/2), y1+(w*cs/2)], [x1+(w*sn/2), y1-(w*cs/2)],
[x2-(w*sn/2), y2+(w*cs/2)], [x2+(w*sn/2), y2-(w*cs/2)]

Ici, sn est le sinus de l'angle de la ligne et cs est le cosinus de l'angle de la ligne. Un pixel fait partie de la ligne et est donc dessiné si le centre du pixel est entièrement à l'intérieur de la boîte englobante (qui est considérée comme ayant des bords infiniment fins). Si le centre du pixel est exactement sur la boîte englobante, il fait partie de la ligne si et seulement si l'intérieur est immédiatement à sa droite (direction d'augmentation de x). Les pixels dont le centre se trouve sur un bord horizontal sont un cas particulier et font partie de la ligne si et seulement si l'intérieur ou la bordure est immédiatement en dessous (direction d'augmentation de y) et que l'intérieur ou la bordure est immédiatement à droite (direction d'augmentation de x).

Les lignes fines (largeur de ligne zéro) sont des lignes d'un pixel de large dessinées à l'aide d'un algorithme non spécifié et dépendant du périphérique. Il n'y a que deux contraintes sur cet algorithme.

1.
Si une ligne est dessinée sans découpage de [x1,y1] à [x2,y2] et si une autre ligne est dessinée sans découpage de [x1+dx,y1+dy] à [x2+dx,y2+dy], un point [x,y] est touché en dessinant la première ligne si et seulement si le point [x+dx,y+dy] est touché en dessinant la deuxième ligne.
2.
L'ensemble effectif de points constituant une ligne ne peut pas être affecté par le découpage. C'est-à-dire qu'un point est touché dans une ligne découpée si et seulement si le point se trouve à l'intérieur de la région de découpage et que le point serait touché par la ligne lorsqu'elle est dessinée sans découpage.

Une ligne épaisse dessinée de [x1,y1] à [x2,y2] dessine toujours les mêmes pixels qu'une ligne épaisse dessinée de [x2,y2] à [x1,y1], sans tenir compte du style de bout et du style de jointure. Il est recommandé que cette propriété soit vraie pour les lignes fines, mais ce n'est pas obligatoire. Une largeur de ligne nulle peut différer d'une largeur de ligne de un en ce qui concerne les pixels dessinés. Cela permet d'utiliser le matériel de dessin de lignes de nombreux fabricants, qui peut fonctionner beaucoup plus rapidement que les lignes épaisses spécifiées plus précisément.

En général, le dessin d'une ligne fine sera plus rapide que le dessin d'une ligne épaisse de largeur un. Cependant, en raison de leurs algorithmes de dessin différents, les lignes fines peuvent ne pas bien s'intégrer esthétiquement avec les lignes épaisses. S'il est souhaitable d'obtenir des résultats précis et uniformes sur tous les affichages, un client doit toujours utiliser une largeur de ligne de un plutôt qu'une largeur de ligne de zéro.

Le style de ligne définit les sections d'une ligne qui sont dessinées :

LineSolid Le chemin complet de la ligne est dessiné.
LineDoubleDash Le chemin complet de la ligne est dessiné, mais les tirets pairs sont remplis différemment des tirets impairs (voir style de remplissage) avec un style CapButt utilisé là où les tirets pairs et impairs se rencontrent.
LineOnOffDash Seuls les tirets pairs sont dessinés, et le style de bout s'applique à toutes les extrémités internes des tirets individuels, sauf que CapNotLast est traité comme CapButt.

Le style de bout définit comment les extrémités d'un chemin sont dessinées :

CapNotLast Ceci est équivalent à CapButt, sauf que pour une largeur de ligne nulle, la dernière extrémité n'est pas dessinée.
CapButt La ligne est carrée à l'extrémité (perpendiculaire à la pente de la ligne) sans projection au-delà.
CapRound La ligne a un arc circulaire dont le diamètre est égal à la largeur de ligne, centré sur l'extrémité. (Ceci est équivalent à CapButt pour une largeur de ligne nulle).
CapProjecting La ligne est carrée à l'extrémité, mais le chemin continue au-delà de l'extrémité sur une distance égale à la moitié de la largeur de ligne. (Ceci est équivalent à CapButt pour une largeur de ligne nulle).

Le style de jointure définit comment les coins sont dessinés pour les lignes épaisses :

JoinMiter Les bords extérieurs de deux lignes s'étendent pour se rencontrer à un angle. Cependant, si l'angle est inférieur à 11 degrés, un style de jointure JoinBevel est utilisé à la place.
JoinRound Le coin est un arc circulaire dont le diamètre est égal à la largeur de ligne, centré sur le point de jointure.
JoinBevel Le coin a des styles d'extrémité CapButt avec l'encoche triangulaire remplie.

Pour une ligne avec des points d'extrémité coïncidents (x1=x2, y1=y2), lorsque le style de bout est appliqué aux deux points d'extrémité, la sémantique dépend de la largeur de ligne et du style de bout :

CapNotLast fine Les résultats sont dépendants du périphérique, mais l'effet désiré est que rien ne soit dessiné.
CapButt fine Les résultats sont dépendants du périphérique, mais l'effet désiré est qu'un seul pixel soit dessiné.
CapRound fine Les résultats sont les mêmes que pour CapButt /fine.
CapProjecting fine Les résultats sont les mêmes que pour CapButt /fine.
CapButt épaisse Rien n'est dessiné.
CapRound épaisse Le chemin fermé est un cercle, centré sur le point d'extrémité, et dont le diamètre est égal à la largeur de ligne.
CapProjecting épaisse Le chemin fermé est un carré, aligné avec les axes de coordonnées, centré sur le point d'extrémité, et dont les côtés sont égaux à la largeur de ligne.

Pour une ligne avec des points d'extrémité coïncidents (x1=x2, y1=y2), lorsque le style de jointure est appliqué à un ou deux points d'extrémité, l'effet est comme si la ligne avait été retirée du chemin global. Cependant, si le chemin total consiste en ou est réduit à un seul point joint à lui-même, l'effet est le même que lorsque le style de bout est appliqué aux deux points d'extrémité.

Le motif de pavage/hachurage représente un plan bidimensionnel infini, le motif de pavage/hachurage étant répété dans toutes les dimensions. Lorsque ce plan est superposé au drawable pour être utilisé dans une opération graphique, le coin supérieur gauche d'une instance du motif de pavage/hachurage se trouve aux coordonnées du drawable spécifiées par l'origine du motif de pavage/hachurage. Les origines du motif de pavage/hachurage et du découpage sont interprétées par rapport à l'origine de tout drawable de destination spécifié dans une requête graphique. Le pixmap de pavage doit avoir la même racine et la même profondeur que le GC, sinon une erreur BadMatch se produit. Le pixmap de hachurage doit avoir la profondeur un et doit avoir la même racine que le GC, sinon une erreur BadMatch se produit. Pour les opérations de hachurage où le style de remplissage est FillStippled mais pas FillOpaqueStippled, le motif de hachurage est pavé sur un seul plan et agit comme un masque de découpage supplémentaire à faire avec un ET avec le masque de découpage. Bien que certaines tailles puissent être plus rapides à utiliser que d'autres, n'importe quelle taille de pixmap peut être utilisée pour le pavage ou le hachurage.

Le style de remplissage définit le contenu de la source pour les requêtes de ligne, de texte et de remplissage. Pour toutes les requêtes de texte et de remplissage (par exemple, XDrawText, XDrawText16, XFillRectangle, XFillPolygon et XFillArc) ; pour les requêtes de ligne avec le style de ligne LineSolid (par exemple, XDrawLine, XDrawSegments, XDrawRectangle, XDrawArc) ; et pour les tirets pairs pour les requêtes de ligne avec le style de ligne LineOnOffDash ou LineDoubleDash, les règles suivantes s'appliquent :

FillSolid Premier plan
FillTiled Pavé
FillOpaqueStippled Un pavage de même largeur et hauteur que le hachurage, mais avec l'arrière-plan partout où le hachurage a un zéro et avec le premier plan partout où le hachurage a un un.
FillStippled Premier plan masqué par le hachurage
XCreateGC(3) — X Version 11

NAME

XCreateGC, XGcontext — create, copy, and destroy Graphics Contexts

SYNTAX

/* Create a GC */
GC XCreateGC(Display *display, Drawable d,
             unsigned long value_mask,
             XGCValues *values);

/* Copy a GC */
GC XCopyGC(Display *display, GC old_gc,
           unsigned long value_mask,
           XGCValues *values);

/* Destroy a GC */
int XFreeGC(Display *display, GC gc);

/* Query GC attributes */
void XQueryGC(Display *display, GC gc,
              unsigned long value_mask,
              XGCValues *values);

ARGUMENTS

display
Specifies the connection to the X server.
d
Specifies the drawable for which the GC is created. The root window of the screen is used if the specified drawable is a window that has no screen.
old_gc
Specifies the graphics context to be copied.
gc
Specifies the graphics context.
value_mask
Specifies which of the optional values (if any) in the specified GC values structure are to be used.
values
Specifies the XGCValues structure, which contains the values for the GC components.

DESCRIPTION

A graphics context (GC) is a collection of graphic attributes that contain information about how output is produced by the X server. The attributes are grouped into the following core components:

Foreground and Background colors.

Function: logical function used in combining.

Fill style: FillSolid, FillTiled, FillStippled, or FillOpaqueStippled.

Fill rule: EvenOddRule or WindingRule.

Arc mode: ArcPieSlice or ArcChord.

Subwindow mode: ClipByChildren or IncludeInferiors.

Tiling and stippling origin.

Font.

Sub-pixel precision: True or False.

Graphics exposure: True or False.

Clip mask: Pixmap or None.

Dash list and dash offset for dashed lines.

Client clip mask: Pixmap or None.

Subwindow mode and graphics exposure are set using XSetSubwindowMode and XSetGraphicsExposures, respectively.

The components of a GC are set using the XSetXXX functions. The initial values for these components are set by the server.

When drawing lines with line-style LineDoubleDash, the odd dashes are controlled by the fill-style in the following manner:

FillSolid Background
FillTiled Same as for even dashes
FillOpaqueStippled Same as for even dashes
FillStippled Background masked by stipple

Storing a pixmap in a GC might or might not result in a copy being made. If the pixmap is later used as the destination for a graphics request, the change might or might not be reflected in the GC. If the pixmap is used simultaneously in a graphics request both as a destination and as a tile or stipple, the results are undefined.

For optimum performance, you should draw as much as possible with the same GC (without changing its components). The costs of changing GC components relative to using different GCs depend on the display hardware and the server implementation. It is quite likely that some amount of GC information will be cached in display hardware and that such hardware can only cache a small number of GCs.

The dashes value is actually a simplified form of the more general patterns that can be set with XSetDashes. Specifying a value of N is equivalent to specifying the two-element list [N, N] in XSetDashes. The value must be nonzero, or a BadValue error results.

The clip-mask restricts writes to the destination drawable. If the clip-mask is set to a pixmap, it must have depth one and have the same root as the GC, or a BadMatch error results. If clip-mask is set to None, the pixels are always drawn regardless of the clip origin. The clip-mask also can be set by calling the XSetClipRectangles or XSetRegion functions. Only pixels where the clip-mask has a bit set to 1 are drawn. Pixels are not drawn outside the area covered by the clip-mask or where the clip-mask has a bit set to 0. The clip-mask affects all graphics requests. The clip-mask does not clip sources. The clip-mask origin is interpreted relative to the origin of whatever destination drawable is specified in a graphics request.

You can set the subwindow-mode to ClipByChildren or IncludeInferiors. For ClipByChildren, both source and destination windows are additionally clipped by all viewable InputOutput children. For IncludeInferiors, neither source nor destination window is clipped by inferiors. This will result in including subwindow contents in the source and drawing through subwindow boundaries of the destination. The use of IncludeInferiors on a window of one depth with mapped inferiors of differing depth is not illegal, but the semantics are undefined by the core protocol.

The fill-rule defines what pixels are inside (drawn) for paths given in XFillPolygon requests and can be set to EvenOddRule or WindingRule. For EvenOddRule, a point is inside if an infinite ray with the point as origin crosses the path an odd number of times. For WindingRule, a point is inside if an infinite ray with the point as origin crosses an unequal number of clockwise and counterclockwise directed path segments. A clockwise directed path segment is one that crosses the ray from left to right as observed from the point. A counterclockwise segment is one that crosses the ray from right to left as observed from the point. The case where a directed line segment is coincident with the ray is uninteresting because you can simply choose a different ray that is not coincident with a segment.

For both EvenOddRule and WindingRule, a point is infinitely small, and the path is an infinitely thin line. A pixel is inside if the center point of the pixel is inside and the center point is not on the boundary. If the center point is on the boundary, the pixel is inside if and only if the polygon interior is immediately to its right (x increasing direction). Pixels with centers on a horizontal edge are a special case and are inside if and only if the polygon interior is immediately below (y increasing direction).

The arc-mode controls filling in the XFillArcs function and can be set to ArcPieSlice or ArcChord. For ArcPieSlice, the arcs are pie-slice filled. For ArcChord, the arcs are chord filled.

The graphics-exposure flag controls GraphicsExpose event generation for XCopyArea and XCopyPlane requests (and any similar requests defined by extensions).

DIAGNOSTICS

BadAlloc
The server failed to allocate the requested resource or server memory.
BadDrawable
A value for a Drawable argument does not name a defined Window or Pixmap.
BadFont
A value for a Font or GContext argument does not name a defined Font.
BadGC
A value for a GContext argument does not name a defined GContext.
BadMatch
An InputOnly window is used as a Drawable.
BadMatch
Some argument or pair of arguments has the correct type and range but fails to match in some other way required by the request.
BadPixmap
A value for a Pixmap argument does not name a defined Pixmap.
BadValue
Some numeric value falls outside the range of values accepted by the request. Unless a specific range is specified for an argument, the full range defined by the argument's type is accepted. Any argument defined as a set of alternatives can generate this error.
