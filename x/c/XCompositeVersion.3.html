NOM

Xcomposite - Bibliothèque d'extension X Composite

SYNTAXE

#include <X11/extensions/Xcomposite.h>

Bool XCompositeQueryExtension(Display *dpy, int *event_base_return, int *error_base_return);

Status XCompositeQueryVersion(Display *dpy, int *major_version_return, int *minor_version_return);

int XCompositeVersion(void);

void XCompositeRedirectWindow(Display *dpy, Window window, int update);

void XCompositeRedirectSubwindows(Display *dpy, Window window, int update);

void XCompositeUnredirectWindow(Display *dpy, Window window, int update);

void XCompositeUnredirectSubwindows(Display *dpy, Window window, int update);

XserverRegion XCompositeCreateRegionFromBorderClip(Display *dpy, Window window);

Pixmap XCompositeNameWindowPixmap(Display *dpy, Window window);

Window XCompositeGetOverlayWindow(Display *dpy, Window window);

void XCompositeReleaseOverlayWindow(Display *dpy, Window window);

DESCRIPTION

L'extension composite fournit plusieurs mécanismes connexes :

Stockage par hiérarchie

Le rendu d'une hiérarchie entière de fenêtres est redirigé vers un stockage hors écran. Les pixels de cette hiérarchie sont disponibles dès qu'elle est visible. Le stockage est automatiquement réalloué lorsque la fenêtre de plus haut niveau change de taille. Le contenu au-delà de la géométrie de la fenêtre supérieure n'est pas conservé.

Mise à jour automatique de l'ombre

Lorsque une hiérarchie est rendue hors écran, le serveur X fournit un mécanisme automatique pour présenter ce contenu dans la fenêtre parente. L'implémentation est libre de faire en sorte que cette mise à jour retarde les opérations de rendu réelles d'une quantité de temps non spécifiée. Ce mécanisme de mise à jour automatique peut être désactivé afin que le contenu de la fenêtre parente puisse être entièrement déterminé par une application externe.

Fenêtre de superposition composite

La version 0.3 du protocole ajoute la Fenêtre de superposition composite, qui fournit aux gestionnaires de composition une surface sur laquelle dessiner sans interférence. Cette fenêtre est toujours au-dessus des fenêtres normales et toujours en dessous de la fenêtre de l'économiseur d'écran. C'est une fenêtre InputOutput dont la largeur et la hauteur correspondent aux dimensions de l'écran. Son visuel est le visuel de la racine et sa bordure a une largeur de zéro. Les tentatives de la rediriger en utilisant l'extension composite sont ignorées. Cette fenêtre n'apparaît pas dans la réponse de la requête QueryTree. C'est également une fenêtre override redirect. Ces deux dernières caractéristiques la rendent invisible aux gestionnaires de fenêtres et autres clients X11. La seule façon d'accéder au XID de cette fenêtre est via la requête CompositeGetOverlayWindow. Initialement, la Fenêtre de superposition composite est non mappée.

Clipping de la fenêtre parente

La version 0.4 du protocole modifie la sémantique du clipping de la fenêtre parente en présence d'enfants redirigés manuellement. Avec cette version, la zone du parent couverte par les enfants redirigés manuellement est laissée dans la liste de clipping du parent au lieu d'être supprimée comme dans les versions plus anciennes.

Le stockage par hiérarchie peut être créé pour des fenêtres individuelles ou pour tous les enfants d'une fenêtre. La mise à jour manuelle de l'ombre peut être sélectionnée par une seule application à la fois pour chaque fenêtre ; la mise à jour manuelle peut également être sélectionnée fenêtre par fenêtre ou pour chaque enfant d'une fenêtre. La détection du moment de la mise à jour peut être faite avec l'extension Damage.

Le stockage hors écran comprend le contenu de la fenêtre, ses bordures et le contenu de tous les descendants.

ARGUMENTS

display

Pointeur vers la structure Display retournée par XOpenDisplay pour la connexion au serveur X.

event_base_return

Pointeur vers un entier où la valeur de base pour les événements de l'extension Composite sera stockée.

error_base_return

Pointeur vers un entier où la valeur de base pour les erreurs de l'extension Composite sera stockée.

major_version_return

Pointeur vers un entier où le numéro de version majeure de l'extension Composite prise en charge par le serveur X sera stocké.

minor_version_return

Pointeur vers un entier où le numéro de version mineure de l'extension Composite prise en charge par le serveur X sera stocké.

window

Spécifie l'ID de la fenêtre sur laquelle opérer.

update

Spécifie le mode de mise à jour du contenu de la fenêtre. Doit être soit CompositeRedirectAutomatic, soit CompositeRedirectManual.

FONCTIONS

XCompositeQueryExtension

XCompositeQueryExtension détermine si l'extension Composite est disponible sur l'affichage donné. Elle retourne True si l'extension est prise en charge, sinon False. Si l'extension est présente, les valeurs de base pour les événements et les erreurs sont retournées, et peuvent être utilisées pour décoder les valeurs des événements et erreurs entrants.

XCompositeQueryVersion

XCompositeQueryVersion détermine si le serveur X prend en charge une version de l'extension X Composite compatible avec la bibliothèque cliente. Un Status non nul est retourné si une version compatible de l'extension est prise en charge, sinon un Status nul est retourné. Si l'extension est prise en charge, les numéros de version majeure et mineure sont retournés pour indiquer le niveau de prise en charge de l'extension Composite. Aucune autre fonction XComposite (sauf XCompositeQueryExtension) ne peut être appelée avant cette fonction. Si un client viole cette règle, les effets de tous les appels XComposite ultérieurs qu'il effectue sont indéfinis.

XCompositeVersion

XCompositeVersion retourne la version de la bibliothèque X Composite. Le numéro de version est encodé comme suit : (major * 10000) + (minor * 100) + revision

Par exemple, la version 1.4.6 serait encodée sous forme de l'entier 10406.

XCompositeRedirectWindow

XCompositeRedirectWindow demande au serveur X de diriger la hiérarchie commençant à window vers un stockage hors écran. L'argument update spécifie si le contenu est automatiquement mis en miroir vers la fenêtre parente ou non. Un seul client à la fois peut spécifier un type de mise à jour CompositeRedirectManual, une autre tentative résultera en une erreur BadAccess. Lorsque tous les clients activant la redirection se terminent, la redirection sera automatiquement désactivée.

La fenêtre racine ne peut pas être redirigée. Cela entraîne une erreur BadMatch. La spécification d'un ID de fenêtre invalide entraînera une erreur BadWindow.

XCompositeRedirectSubwindows

XCompositeRedirectSubwindows demande au serveur X de rediriger les hiérarchies commençant par tous les enfants actuels et futurs de window comme dans XCompositeRedirectWindow. Si update est CompositeRedirectManual, alors la peinture de l'arrière-plan de la fenêtre lors de la manipulation de la fenêtre et les requêtes ClearArea sont inhibées.

XCompositeUnredirectWindow

XCompositeUnredirectWindow demande au serveur X de terminer la redirection de window. Si la fenêtre spécifiée n'était pas sélectionnée pour la redirection par le client actuel, une erreur BadValue en résulte.

XCompositeUnredirectSubwindows

XCompositeUnredirectWindow demande au serveur X de terminer la redirection de tous les enfants de window. Si la fenêtre spécifiée n'était pas sélectionnée pour la sous-redirection par le client actuel, une erreur BadValue en résulte.

XCompositeCreateRegionFromBorderClip

XCompositeCreateRegionFromBorderClip crée une région contenant la zone de clipping de bordure "habituelle"

NAME

XCompositeVersion — query the Composite extension version

SYNOPSIS

#include <X11/Xlib.h>
#include <X11/extensions/Xcomposite.h>

General 32-bit status:
Status XCompositeQueryVersion(Display *dpy, int *major_version_return, int *minor_version_return);

General 64-bit status:
Status XCompositeQueryVersion64(Display *dpy, int *major_version_return, int *minor_version_return);

DESCRIPTION

The Composite extension provides a mechanism for redirecting the contents of a window to an off-screen pixmap. This allows for effects such as transparency and compositing. The Composite extension also provides overlay windows for applications that need direct access to the screen for things like input methods.

XCompositeQueryVersion is used to query the version of the Composite extension supported by the X server. It should be called before any other Composite extension requests. It returns True if the extension is supported, and sets major_version_return and minor_version_return to the major and minor version numbers of the extension, respectively. It returns False if the extension is not supported.

XCompositeQueryVersion64 is the same as XCompositeQueryVersion, but it is used when the X server supports 64-bit pixmap data.

ARGUMENTS

dpy
Specifies the connection to the X server.
major_version_return
Returns the major version number of the Composite extension.
minor_version_return
Returns the minor version number of the Composite extension.

FUNCTIONS

XCompositeRedirectWindow

XCompositeRedirectWindow redirects the contents of window to the pixmap specified by redirect_pixmap. The update_type argument specifies how the redirected contents should be updated. If update_type is CompositeRedirectAutomatic, the server will update the pixmap automatically whenever the window contents change. If update_type is CompositeRedirectManual, the client is responsible for updating the pixmap manually. If update_type is CompositeRedirectAutomaticInverted, the server will update the pixmap automatically whenever the window contents change, but will not send update notifications to clients. Generates a BadMatch error if window is not redirectable or is already redirected.

The X server must support at least version 0.2 of the Composite Extension for XCompositeRedirectWindow.

XCompositeRedirectSubwindows

XCompositeRedirectSubwindows redirects the contents of all viewable subwindows of window to off-screen pixmaps. The update_type argument specifies how the redirected contents should be updated. If update_type is CompositeRedirectAutomatic, the server will update the pixmaps automatically whenever the window contents change. If update_type is CompositeRedirectManual, the client is responsible for updating the pixmaps manually. If update_type is CompositeRedirectAutomaticInverted, the server will update the pixmaps automatically whenever the window contents change, but will not send update notifications to clients. Generates a BadMatch error if window is not redirectable or is already redirected.

The X server must support at least version 0.2 of the Composite Extension for XCompositeRedirectSubwindows.

XCompositeUnredirectWindow

XCompositeUnredirectWindow stops redirecting the contents of window. The update_type argument specifies whether the client has already updated the pixmap since the last redirect request. If update_type is CompositeRedirectAutomatic, the client has not yet updated the pixmap, and the server will discard the contents. If update_type is CompositeRedirectManual, the client has already updated the pixmap, and the server will keep the pixmap. Generates a BadMatch error if window is not redirected.

The X server must support at least version 0.2 of the Composite Extension for XCompositeUnredirectWindow.

XCompositeUnredirectSubwindows

XCompositeUnredirectSubwindows stops redirecting the contents of all viewable subwindows of window. The update_type argument specifies whether the client has already updated the pixmaps since the last redirect request. If update_type is CompositeRedirectAutomatic, the client has not yet updated the pixmaps, and the server will discard the contents. If update_type is CompositeRedirectManual, the client has already updated the pixmaps, and the server will keep the pixmaps. Generates a BadMatch error if any of the subwindows are not redirected.

The X server must support at least version 0.2 of the Composite Extension for XCompositeUnredirectSubwindows.

XCompositeCreateRegionFromWindow

XCompositeCreateRegionFromWindow returns a region that describes the area of window that is not obscured by its siblings or its parent. This region can be used to restrict rendering to suitable areas while updating only a single window. The region is copied at the moment the request is executed; future changes to the window hierarchy will not be reflected in this region.

XCompositeNameWindowPixmap

XCompositeNameWindowPixmap creates and returns a pixmap id that serves as a reference to the off-screen storage for window. This pixmap will remain allocated until freed, even if the window is unmapped, reconfigured or destroyed. However, the window will get a new pixmap allocated each time it is mapped or resized, so this function will need to be reinvoked for the client to continue to refer to the storage holding the current window contents. Generates a BadMatch error if window is not redirected or is not visible.

The X server must support at least version 0.2 of the Composite Extension for XCompositeNameWindowPixmap.

XCompositeGetOverlayWindow

XCompositeGetOverlayWindow returns the window ID of the Composite Overlay Window for the screen specified by the argument window. This function notifies the X server that the client wishes to use the Composite Overlay Window of this screen. If this Composite Overlay Window has not yet been mapped, it is mapped by this request.

The Composite Overlay Window for a particular screen will be unmapped when all clients who have called this function have either called XCompositeReleaseOverlayWindow for that screen, or terminated their connection to the X server.

The X server must support at least version 0.3 of the Composite Extension for XCompositeGetOverlayWindow.

XCompositeReleaseOverlayWindow

This request specifies that the client is no longer using the Composite Overlay Window on the screen specified by the argument window. A screen's Composite Overlay Window is unmapped when there are no longer any clients using it.

The X server must support at least version 0.3 of the Composite Extension for XCompositeReleaseOverlayWindow.
