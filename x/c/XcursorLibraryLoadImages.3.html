Paquet: libxcursor

XCURSOR(3) Version X 11 XCURSOR(3)

NOM

Xcursor - Bibliothèque de gestion des curseurs

SYNTAXE

#include <X11/Xcursor/Xcursor.h>

DESCRIPTION

Xcursor est une bibliothèque simple conçue pour aider à localiser et charger les curseurs. Les curseurs peuvent être chargés à partir de fichiers ou de la mémoire. Une bibliothèque de curseurs courants existe, qui correspond aux noms de curseurs X standards. Les curseurs peuvent exister en plusieurs tailles et la bibliothèque choisit automatiquement la meilleure taille.

APERÇU FONCTIONNEL

Xcursor est construit en plusieurs couches ; la couche inférieure contient le code qui peut charger les images de curseur à partir de fichiers. Au-dessus se trouve une couche qui localise les fichiers de curseur en fonction du chemin de la bibliothèque et du thème. Au sommet se trouve une couche qui construit des curseurs soit à partir d'une image chargée depuis un fichier, soit à partir de l'un des curseurs X standards. Lors de l'utilisation d'images chargées à partir de fichiers, Xcursor préfère utiliser la requête CreateCursor de l'extension Render si elle est prise en charge par le serveur X. Là où elle n'est pas prise en charge, Xcursor mappe l'image du curseur à un curseur X standard et utilise la requête CreateCursor de base.

FICHIERS DE CURSEUR

Xcursor définit un nouveau format pour les curseurs sur disque. Chaque fichier contient une ou plusieurs images de curseur. Chaque image de curseur est étiquetée avec une taille nominale afin que la meilleure taille puisse être sélectionnée automatiquement. Plusieurs curseurs de la même taille nominale peuvent être chargés ensemble ; les applications sont censées les utiliser comme une séquence animée.

Les fichiers de curseur sont stockés sous forme d'en-tête contenant une table des matières suivie d'une séquence de blocs. La table des matières indique le type, le sous-type et la position dans le fichier de chaque bloc. L'en-tête du fichier ressemble à ceci :


magie:	CARD32 « Xcur » (0x58, 0x63, 0x75, 0x72)
en-tête:	CARD32 octets dans cet en-tête
version:	CARD32 numéro de version du fichier
ntoc:	CARD32 nombre d'entrées TOC
toc:	LISTofTOC table des matières

Chaque entrée de table des matières ressemble à ceci :


type:	CARD32 type d'entrée
sous-type:	CARD32 étiquette spécifique au type - taille pour les images
position:	CARD32 position absolue en octets de la table dans le fichier

Chaque bloc dans le fichier possède un ensemble de champs d'en-tête communs suivis de champs supplémentaires spécifiques au type :


en-tête:	CARD32 octets dans l'en-tête du bloc (y compris les champs spécifiques au type)
type:	CARD32 doit correspondre au type dans TOC pour ce bloc
sous-type:	CARD32 doit correspondre au sous-type dans TOC pour ce bloc
version:	CARD32 numéro de version pour ce type de bloc

Il existe actuellement deux types de blocs définis pour les fichiers de curseur : les commentaires et les images. Les commentaires ressemblent à ceci :


en-tête:	20 Les en-têtes de commentaires font 20 octets
type:	0xfffe0001 Le type de commentaire est 0xfffe0001
sous-type:	{ 1 (COPYRIGHT), 2 (LICENSE), 3 (AUTRE) }
version:	1
longueur:	CARD32 longueur en octets de la chaîne UTF-8
chaîne:	LISTofCARD8 chaîne UTF-8

Les images ressemblent à ceci :


en-tête:	36 Les en-têtes d'image font 36 octets
type:	0xfffd0002 Le type d'image est 0xfffd0002
sous-type:	CARD32 Le sous-type d'image est la taille nominale
version:	1
largeur:	CARD32 Doit être inférieur ou égal à 0x7fff
hauteur:	CARD32 Doit être inférieur ou égal à 0x7fff
xhot:	CARD32 Doit être inférieur ou égal à la largeur
yhot:	CARD32 Doit être inférieur ou égal à la hauteur
délai:	CARD32 Délai entre les images d'animation en millisecondes
pixels:	LISTofCARD32 Pixels au format ARGB compacté

THÈMES

Xcursor suit (principalement) la spécification freedesktop.org pour les thèmes d'icônes. Le chemin de recherche par défaut qu'il utilise est

~/.local/share/icons, ~/.icons, /usr/share/icons, /usr/share/pixmaps

Dans chacun de ces répertoires, il recherche un répertoire en utilisant le nom du thème :

•
Dans le répertoire du thème, il recherche les fichiers de curseur dans le sous-répertoire « cursors ».
Xcursor recherche un fichier spécifique, qui doit être l'un des noms de forme du curseur, par exemple, tels qu'utilisés dans XcursorLibraryLoadImage ou XcursorLibraryShape.
•
S'il ne trouve aucun fichier de curseur correspondant dans le sous-répertoire « cursors », Xcursor recherche ensuite un fichier « index.theme » dans chaque répertoire de thème pour rechercher les thèmes hérités. Ce sont des lignes de ce format :
Hérite = nom-du-thème

Xcursor utilise le premier nom-du-thème hérité, ignorant les autres qui peuvent exister dans un fichier « index.theme » donné. S'il trouve un thème hérité, Xcursor cherche également le long du chemin pour l'utiliser. Xcursor ignore les autres clés dans le fichier « index.theme », y compris « Nom » (c'est-à-dire le nom qu'une application graphique peut utiliser comme nom de présentation).

Plusieurs noms-de-thème peuvent être listés sur la ligne Hérite=. La spécification freedesktop.org stipule que les éléments de la liste sont séparés par des virgules. Xcursor accepte également le point-virgule, mais traduit les deux en deux-points lors de la recherche dans le chemin. Xcursor attend une seule ligne Hérite= ; la spécification freedesktop.org n'est pas claire quant à savoir si plusieurs clés sont autorisées.

Si aucun thème n'est défini, ou si aucun curseur n'est trouvé pour le thème spécifié nulle part le long du chemin, Xcursor vérifie le thème « par défaut ».

Lorsque Xcursor trouve un fichier de curseur, il arrête la recherche. Il utilise toujours le premier fichier de curseur trouvé lors de la recherche le long du chemin.

TYPES DE DONNÉES

XcursorImage
contient une seule image de curseur en mémoire. Chaque pixel du curseur est une valeur de 32 bits contenant ARGB avec A dans l'octet de poids fort. 


typedef struct _XcursorImage {
    XcursorDim 	 size; 	/* taille nominale pour la correspondance */
    XcursorDim 	 width; 	/* largeur réelle */
    XcursorDim 	 height; 	/* hauteur réelle */
    XcursorDim 	 xhot; 	/* point chaud x (doit être à l'intérieur de l'image) */
    XcursorDim 	 yhot; 	/* point chaud y (doit être à l'intérieur de l'image) */
    XcursorPixel 	*pixels; 	/* pointeur vers les pixels */
} XcursorImage;
XcursorImages
contient plusieurs structures XcursorImage. Elles sont toutes libérées lorsque XcursorImages est libéré dans XcursorImagesDestroy. 


typedef struct _XcursorImages {
    int 	 nimage; 	/* nombre d'images */
    XcursorImage 	**images; 	/* tableau de pointeurs XcursorImage */
} XcursorImages;
XcursorCursors
Contient plusieurs objets Cursor. Ils sont tous libérés lorsque XcursorCursors est libéré. Ceux-ci sont comptés par référence afin que plusieurs structures XcursorAnimate puissent utiliser le même XcursorCursors. 


typedef struct _XcursorCursors {
    Display 	*dpy; 	/* Affichage contenant les curseurs */
    int 	 ref; 	/* compteur de références */
    int 	 ncursor; 	/* nombre de curseurs */
    Cursor 	*cursors; 	/* tableau de curseurs */
} XcursorCursors;
XcursorAnimate
Fait référence à un ensemble de curseurs et à une séquence dans cet ensemble. Plusieurs structures XcursorAnimate peuvent faire référence au même XcursorCursors ; chacune détient une référence qui est supprimée lorsque XcursorAnimate est libéré. 


typedef struct _XcursorAnimate {
    XcursorCursors 	*cursors; 	/* liste des curseurs à utiliser */
    int 	 sequence; 	/* quel curseur est le suivant */
} XcursorAnimate;
XcursorFile
Xcursor fournit une API abstraite pour accéder aux données du fichier. Xcursor fournit une implémentation stdio de cette API abstraite ; les applications sont libres de créer des implémentations supplémentaires. Ces fonctions sont parallèles aux fonctions stdi
o fonctions dans la valeur de retour et les valeurs d'arguments attendues ; les fonctions read et write inversent les arguments pour correspondre aux versions POSIX. 


typedef struct _XcursorFile {
    void *closure;
    int (*read)  (XcursorFile *file, unsigned char *buf, int len);
    int (*write) (XcursorFile *file, unsigned char *buf, int len);
    int (*seek)  (XcursorFile *file, long offset, int whence);
};

Lecture des images de la bibliothèque

XcursorImage *XcursorLibraryLoadImage (
const char 	*name,
const char 	*theme,
int 	 size)
XcursorImages *XcursorLibraryLoadImages (
	const char 	*name,
	const char 	*theme,
	int 	 size)

Ces fonctions recherchent dans le chemin de la bibliothèque, en chargeant le premier fichier trouvé de la size souhaitée, en utilisant une fonction privée (XcursorScanTheme) pour trouver le thème approprié :

  • Si theme n'est pas NULL, utilisez celui-ci.
  • Si theme est NULL, ou s'il n'y a pas eu de correspondance pour le thème souhaité, utilisez "default" comme nom de thème.
  • Si aucune des recherches ne réussit, ces fonctions retournent NULL.
Les deux fonctions diffèrent par plus que le nombre d'images chargées :
  • XcursorLibraryLoadImage appelle XcursorFileLoadImage mais
  • XcursorLibraryLoadImages appelle XcursorFileLoadImages, et (en cas de succès) elle appelle XcursorImagesSetName pour associer name au résultat.

\n
\n
HOME
\n
Xcursor interprets “~” in the search list as the home\n    directory, using this variable rather than the password database.
\n
XCURSOR_ANIM
\n
If the display supports the Render CreateCursor request, and the Render\n    feature is enabled, disable animated cursors if the environment\n    variable is false.
\n
\n
\n
\n
If the environment variable is not given, Xcursor uses the resource\n    Xcursor.anim.
\n
\n
\n
XCURSOR_CORE
\n
If the display supports the Render CreateCursor request disable the Render\n    feature if the environment variable is false.
\n
\n
\n
\n
If the environment variable is not given, Xcursor uses the resource\n    Xcursor.core.
\n
\n
\n
XCURSOR_DISCOVER
\n
If the variable is set, Xcursor turns on a logging feature. It displays\n    the hash value and the image so that users can see which cursor name is\n    associated with each image.
\n
\n
\n
\n
There is no corresponding resource setting.
\n
\n
\n
XCURSOR_DITHER
\n
This variable sets the desired dither.
\n
\n
\n
\n
If the environment variable is not given, Xcursor uses the resource\n    Xcursor.dither.
\n
\n
If neither environment variable or resource is found, Xcursor uses\n    “threshold”
\n
\n
These are the recognized values:
\n
\n
\n
\n
diffuse
\n
\n
median
\n
\n
ordered
\n
\n
threshold
\n
\n
\n
\n
\n
XCURSOR_PATH
\n
This variable sets the list of paths in which to search for cursors,\n    rather than the compiled-in default list.
\n
\n
\n
\n
Directories in this path are separated by colons (:).
\n
\n
\n
XCURSOR_RESIZED
\n
Enables automatic resizing of cursors to improve their displayed size if\n    the environment variable is true.
\n
\n
\n
\n
If the environment variable is not given, Xcursor tries the\n    Xcursor.resized resource.
\n
\n
\n
XCURSOR_SIZE
\n
This variable sets the desired cursor size, in pixels.
\n
\n
\n
\n
If the environment variable is not given, Xcursor tries the\n    Xcursor.size resource.
\n
\n
If no size is given, whether by environment variable or resource setting,\n    Xcursor next tries the Xft.dpi resource setting to guess the size\n    of a 16-point cursor.
\n
\n
Finally, if Xft.dpi is not set, Xcursor uses the display height,\n    dividing by 48 (assuming that the height is 768).
\n
\n
\n
XCURSOR_THEME
\n
This variable selects the desired theme.
\n
\n
\n
\n
If the environment variable is not given, Xcursor tries the\n    Xcursor.theme resource.
\n
\n
If neither environment variable or resource is found, Xcursor uses the\n    default theme.
\n
\n
\n
XCURSO\n
\n
This variable selects whether to use themes for core X cursors.\n    See XcursorSetThemeCore(3) and XcursorGetThemeCore(3).
\n
\n
\n
\n
If the environment variable is not given, Xcursor uses the resource\n    Xcursor.theme_core.
\n
