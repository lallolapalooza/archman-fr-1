NOM

Xcomposite - bibliothèque de l'extension X Composite

SYNTAXE

#include <X11/extensions/Xcomposite.h>

Bool XCompositeQueryExtension(Display *dpy, int *event_base_return, int *error_base_return);

Status XCompositeQueryVersion(Display *dpy, int *major_version_return, int *minor_version_return);

int XCompositeVersion(void);

void XCompositeRedirectWindow(Display *dpy, Window window, int update);

void XCompositeRedirectSubwindows(Display *dpy, Window window, int update);

void XCompositeUnredirectWindow(Display *dpy, Window window, int update);

void XCompositeUnredirectSubwindows(Display *dpy, Window window, int update);

XserverRegion XCompositeCreateRegionFromBorderClip(Display *dpy, Window window);

Pixmap XCompositeNameWindowPixmap(Display *dpy, Window window);

Window XCompositeGetOverlayWindow(Display *dpy, Window window);

void XCompositeReleaseOverlayWindow(Display *dpy, Window window);

DESCRIPTION

L'extension composite fournit plusieurs mécanismes connexes :

Stockage par hiérarchie

Le rendu d'une hiérarchie entière de fenêtres est redirigé vers un stockage hors écran. Les pixels de cette hiérarchie sont disponibles chaque fois qu'elle est visible. Le stockage est automatiquement réalloué lorsque la fenêtre de plus haut niveau change de taille. Le contenu au-delà de la géométrie de la fenêtre supérieure n'est pas préservé.

Mise à jour automatique de l'ombre

Lorsqu'une hiérarchie est rendue hors écran, le serveur X fournit un mécanisme automatique pour présenter ce contenu dans la fenêtre parente. L'implémentation est libre de laisser cette mise à jour avoir un délai par rapport aux opérations de rendu réelles d'une durée non spécifiée. Ce mécanisme de mise à jour automatique peut être désactivé afin que le contenu de la fenêtre parente puisse être entièrement déterminé par une application externe.

Fenêtre de superposition composite

La version 0.3 du protocole ajoute la Fenêtre de superposition composite, qui fournit aux gestionnaires de composition une surface sur laquelle dessiner sans interférence. Cette fenêtre est toujours au-dessus des fenêtres normales et toujours en dessous de la fenêtre d'économiseur d'écran. C'est une fenêtre InputOutput dont la largeur et la hauteur correspondent aux dimensions de l'écran. Son visuel est le visuel racine et sa bordure est de largeur zéro. Les tentatives de la rediriger à l'aide de l'extension composite sont ignorées. Cette fenêtre n'apparaît pas dans la réponse de la requête QueryTree. C'est aussi une fenêtre override redirect. Ces deux dernières fonctionnalités la rendent invisible aux gestionnaires de fenêtres et autres clients X11. Le seul moyen d'accéder au XID de cette fenêtre est via la requête CompositeGetOverlayWindow. Initialement, la Fenêtre de superposition composite est désaffichée.

Clipping de la fenêtre parente

La version 0.4 du protocole modifie la sémantique du clipping de la fenêtre parente en présence d'enfants redirigés manuellement. Avec cette version, la zone dans le parent couverte par les enfants redirigés manuellement est laissée dans la liste de clipping du parent au lieu d'être retirée comme dans les versions précédentes.

Le stockage hors écran peut être créé pour des fenêtres individuelles ou pour tous les enfants d'une fenêtre. La mise à jour manuelle de l'ombre peut être sélectionnée par une seule application pour chaque fenêtre ; la mise à jour manuelle peut également être sélectionnée par fenêtre ou pour chaque enfant d'une fenêtre. La détection du moment où effectuer la mise à jour peut être faite avec l'extension Damage.

Le stockage hors écran comprend le contenu de la fenêtre, ses bordures et le contenu de tous les descendants.

ARGUMENTS

display

Pointeur vers la structure Display retournée par XOpenDisplay pour la connexion au serveur X.

event_base_return

Pointeur vers un entier où la valeur de base pour les événements de l'extension Composite sera stockée.

error_base_return

Pointeur vers un entier où la valeur de base pour les erreurs de l'extension Composite sera stockée.

major_version_return

Pointeur vers un entier où le numéro de version majeure de l'extension Composite prise en charge par le serveur X sera stocké.

minor_version_return

Pointeur vers un entier où le numéro de version mineure de l'extension Composite prise en charge par le serveur X sera stocké.

window

Spécifie l'ID de la fenêtre à opérer.

update

Spécifie le mode de mise à jour du contenu de la fenêtre. Doit être soit CompositeRedirectAutomatic, soit CompositeRedirectManual.

FONCTIONS

XCompositeQueryExtension

XCompositeQueryExtension détermine si l'extension Composite est disponible sur l'affichage donné. Elle retourne True si l'extension est prise en charge, sinon False. Si l'extension est présente, les valeurs de base pour les événements et les erreurs sont retournées, et peuvent être utilisées pour décoder les valeurs d'événements et d'erreurs entrantes.

XCompositeQueryVersion

XCompositeQueryVersion détermine si le serveur X prend en charge une version de l'extension X Composite compatible avec la bibliothèque client. Une valeur Status non nulle est retournée si une version compatible de l'extension est prise en charge, sinon une valeur Status nulle est retournée. Si l'extension est prise en charge, les numéros de version majeure et mineure sont retournés pour indiquer le niveau de prise en charge de l'extension Composite. Aucune autre fonction XComposite (sauf XCompositeQueryExtension) ne peut être appelée avant cette fonction. Si un client viole cette règle, les effets de tous les appels XComposite ultérieurs qu'il effectue sont indéfinis.

XCompositeVersion

XCompositeVersion retourne la version de la bibliothèque X Composite. Le numéro de version est codé comme suit : (majeur * 10000) + (mineur * 100) + révision

Par exemple, la version 1.4.6 serait codée comme l'entier 10406.

XCompositeRedirectWindow

XCompositeRedirectWindow demande au serveur X de diriger la hiérarchie commençant à window vers un stockage hors écran. L'argument update spécifie si le contenu est mis en miroir automatiquement vers la fenêtre parente ou non. Un seul client à la fois peut spécifier un type de mise à jour de CompositeRedirectManual, une autre tentative entraînera une erreur BadAccess. Lorsque tous les clients activant la redirection se terminent, la redirection sera automatiquement désactivée.

La fenêtre racine ne peut pas être redirigée. Cela entraîne une erreur BadMatch. Spécifier un ID de fenêtre invalide entraînera une erreur BadWindow.

XCompositeRedirectSubwindows

XCompositeRedirectSubwindows demande au serveur X de rediriger les hiérarchies commençant à tous les enfants actuels et futurs de window comme dans XCompositeRedirectWindow. Si update est CompositeRedirectManual, alors la peinture de l'arrière-plan de la fenêtre lors de la manipulation de la fenêtre et les requêtes ClearArea sont inhibées.

XCompositeUnredirectWindow

XCompositeUnredirectWindow demande au serveur X de terminer la redirection de window. Si la fenêtre spécifiée n'a pas été sélectionnée pour la redirection par le client actuel, une erreur BadValue en résulte.

XCompositeUnredirectSubwindows

XCompositeUnredirectSubwindows demande au serveur X de terminer la redirection de tous les enfants de window. Si la fenêtre spécifiée n'a pas été sélectionnée pour la sous-redirection par le client actuel, une erreur BadValue en résulte.

XCompositeCreateRegionFromBorderClip

XCompositeCreateRegionFromBorderClip crée une région contenant le "clipping" de bordure "habituel"

XCompositeNameWindowPixmap

XCompositeNameWindowPixmap demande au serveur X de créer une PixMap contenant les pixels de la fenêtre spécifiée. La PixMap sera mise à jour par le serveur lorsque le contenu de la fenêtre change. La PixMap est rendue dans le même espace d'adressage que les autres PixMaps et peut être utilisée avec des fonctions X standard comme XCopyArea. Le drapeau de contenu (content_region) doit contenir les régions que le client souhaite voir mises à jour. Pour mettre à jour la fenêtre entière, utilisez la région entière de la fenêtre.

XCompositeGetOverlayWindow

XCompositeGetOverlayWindow retourne l'ID de la fenêtre de superposition composite. Si la fenêtre spécifiée est une fenêtre racine, une erreur BadMatch est retournée. Si la fenêtre spécifiée n'est pas une fenêtre racine, et qu'il n'y a pas de fenêtre de superposition pour cette fenêtre, alors une fenêtre de superposition sera créée.

XCompositeReleaseOverlayWindow

XCompositeReleaseOverlayWindow retire la fenêtre de superposition composite pour la fenêtre spécifiée. Si la fenêtre spécifiée n'est pas une fenêtre racine, et qu'il n'y a pas de fenêtre de superposition pour cette fenêtre, alors une erreur BadValue est retournée.

DIAGNOSTICS

Des erreurs peuvent être retournées par les requêtes du Composite Extension.

BadMatch
Une requête a été faite sur une fenêtre qui n'est pas appropriée pour cette requête. Par exemple, essayer de rediriger la fenêtre racine.
BadValue
Une valeur invalide a été fournie. Par exemple, passer un argument update incorrect à XCompositeRedirectWindow, ou demander le retrait d'une redirection non configurée.
BadWindow
Une fenêtre spécifiée dans la requête n'existe pas.
Access
Une autre application a déjà redirigé la fenêtre en mode manuel.

NAME

XCompositeGetWindowPixmap, XCompositeNameWindowPixmap, XCompositeGetOverlayWindow, XCompositeReleaseOverlayWindow ― manipulating composite window contents and overlay windows

SYNOPSIS

XCompositeWindow_t
XCompositeGetWindowPixmap(Display *display, Window window, XRectangle *clip_y_off)
XCompositeWindow_t
XCompositeNameWindowPixmap(Display *display, Window window, XRectangle *clip_y_off)
Window
XCompositeGetOverlayWindow(Display *display, Window window)
void
XCompositeReleaseOverlayWindow(Display *display, Window window)

DESCRIPTION

The Composite extension provides a way for clients to access the contents of redirected windows and to manage overlay windows.

When a window is redirected by the Composite extension, the X server directs the drawing operations for that window to an off-screen pixmap. The functions described here allow clients to access that pixmap and manage overlay windows.

ARGUMENTS

display
Specifies the connection to the X server.
window
Specifies the window of interest.
clip_y_off
If not NULL, the offset of the clipped region of the window relative to the window's origin is returned here.

FUNCTIONS

XCompositeGetWindowPixmap

XCompositeGetWindowPixmap returns a XCompositeWindow_t structure containing the pixmap id and dimensions of the off-screen pixmap for the specified window. The pixmap contains the current contents of the window. This pixmap is only valid as long as the window remains mapped and the Composite extension continues to redirect it. If the window is unmapped or is no longer redirected, the pixmap becomes invalid.

The clip_y_off argument, if not NULL, will be filled with the bounding box of the window clipped against siblings and the parent. This region can be used to restrict rendering to suitable areas while updating only a single window. The region is copied at the moment the request is executed; future changes to the window hierarchy will not be reflected in this region.

The X server must support at least version 0.2 of the Composite Extension for XCompositeGetWindowPixmap.

XCompositeNameWindowPixmap

XCompositeNameWindowPixmap creates and returns a pixmap id that serves as a reference to the off-screen storage for window. This pixmap will remain allocated until freed, even if the window is unmapped, reconfigured or destroyed. However, the window will get a new pixmap allocated each time it is mapped or resized, so this function will need to be reinvoked for the client to continue to refer to the storage holding the current window contents. Generates a BadMatch error if window is not redirected or is not visible.

The X server must support at least version 0.2 of the Composite Extension for XCompositeNameWindowPixmap.

XCompositeGetOverlayWindow

XCompositeGetOverlayWindow returns the window ID of the Composite Overlay Window for the screen specified by the argument window. This function notifies the X server that the client wishes to use the Composite Overlay Window of this screen. If this Composite Overlay Window has not yet been mapped, it is mapped by this request.

The Composite Overlay Window for a particular screen will be unmapped when all clients who have called this function have either called XCompositeReleaseOverlayWindow for that screen, or terminated their connection to the X server.

The X server must support at least version 0.3 of the Composite Extension for XCompositeGetOverlayWindow.

XCompositeReleaseOverlayWindow

This request specifies that the client is no longer using the Composite Overlay Window on the screen specified by the argument window. A screen's Composite Overlay Window is unmapped when there are no longer any clients using it.

The X server must support at least version 0.3 of the Composite Extension for XCompositeReleaseOverlayWindow.
