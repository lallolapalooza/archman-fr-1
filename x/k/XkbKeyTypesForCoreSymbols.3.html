NOM

XkbKeyTypesForCoreSymbols - Déterminer les types de touches Xkb appropriés pour les symboles liés à une touche dans un mappage clavier principal

SYNOPIS

int XkbKeyTypesForCoreSymbols (XkbDescPtr xkb, int map_width, KeySym *core_syms, unsigned int protected, int *types_inout, KeySym *xkb_syms_rtrn);

ARGUMENTS

xkb
description du clavier dans laquelle placer les symboles
map_width
largeur de la table des correspondances du protocole principal dans xkb_syms_rtrn
core_syms
tableau de KeySym au format du protocole principal
protected
types de touches explicites
types_inout
rempli avec les types canoniques liés aux groupes un et deux pour la touche
xkb_syms_rtrn
rempli avec les symboles liés à la touche dans le mappage Xkb

DESCRIPTION

XkbKeyTypesForCoreSymbols développe les symboles dans core_syms et les types dans types_inout, puis choisit des types de touches canoniques (les types de touches canoniques sont définis dans Les Types de Touches Canoniques) pour les groupes 1 et 2 en utilisant les règles spécifiées par le protocole Xkb et les place dans xkb_syms_rtrn, qui ne sera pas NULL.

Les Types de Touches Canoniques

Xkb autorise jusqu'à XkbMaxKeyTypes (255) types de touches à être définis, mais exige qu'au moins XkbNumRequiredTypes (4) types prédéfinis soient présents dans une table des correspondances de touches. Ces types de touches prédéfinis sont appelés types de touches canoniques et décrivent les types de touches disponibles sur la plupart des claviers. Les définitions des types de touches canoniques sont conservées dans les XkbNumRequiredTypes premières entrées du champ types de la table des correspondances client et sont indexées en utilisant les constantes suivantes :

    XkbOneLevelIndex
    XkbTwoLevelIndex
    XkbAlphabeticIndex
    XkbKeypadIndex

ONE_LEVEL

Le type de touche ONE_LEVEL décrit des groupes qui n'ont qu'un seul symbole. Le type ONE_LEVEL par défaut n'a pas d'entrées de mappage et ne prête aucune attention aux modificateurs. Une représentation symbolique de ce type de touche pourrait ressembler à ce qui suit :

    type "ONE_LEVEL" {
         modifiers = None;
         map[None]= Level1;
         level_name[Level1]= "Any";
    };
La description du type de touche ONE_LEVEL est stockée dans l'entrée types[XkbOneLevelIndex] de la table des correspondances client.

TWO_LEVEL

Le type de touche TWO_LEVEL décrit des groupes qui consistent en deux symboles mais ne sont ni des touches alphabétiques ni des touches du pavé numérique. Le type TWO_LEVEL par défaut utilise uniquement le modificateur Shift. Il renvoie le niveau deux si Shift est activé, et le niveau un s'il ne l'est pas. Une représentation symbolique de ce type de touche pourrait ressembler à ce qui suit :

    type "TWO_LEVEL" {
        modifiers = Shift;
        map[Shift]= Level2;
        level_name[Level1]= "Base";
        level_name[Level2]= "Shift";
    };

La description du type de touche TWO_LEVEL est stockée dans l'entrée types[XkbTwoLevelIndex] de la table des correspondances client.

ALPHABETIC

Le type de touche ALPHABETIC décrit des groupes consistant en deux symboles : la forme minuscule d'un symbole suivie de la forme majuscule du même symbole. Le type ALPHABETIC par défaut implémente un comportement sensible aux locales de "Shift annule CapsLock" en utilisant les modificateurs Shift et Lock comme suit :

  • Si Shift et Lock sont tous deux activés, le type ALPHABETIC par défaut renvoie le niveau un.
  • Si Shift seul est activé, il renvoie le niveau deux.
  • Si Lock seul est activé, il renvoie le niveau un, mais préserve le modificateur Lock afin que Xlib remarque et applique les règles de mise en majuscules appropriées. Les fonctions Xlib sont sensibles aux locales et appliquent différentes règles de mise en majuscules pour différentes locales.
  • Si ni Shift ni Lock ne sont activés, il renvoie le niveau un.

    Une représentation symbolique de ce type de touche pourrait ressembler à ce qui suit :

        type "ALPHABETIC" {
        modifiers = Shift+Lock;
        map[Shift]= Level2;
        preserve[Lock]= Lock;
        level_name[Level1]= "Base";
        level_name[Level2]= "Caps";
    };
    La description du type de touche ALPHABETIC est stockée dans l'entrée types[XkbAlphabeticIndex] de la table des correspondances client.

    KEYPAD

    Le type de touche KEYPAD décrit des groupes consistant en deux symboles, dont au moins un est un symbole de pavé numérique. Le symbole de pavé numérique est supposé résider au niveau deux. Le type KEYPAD par défaut implémente le comportement "Shift annule NumLock" en utilisant le modificateur Shift et le modificateur réel lié au modificateur virtuel nommé "NumLock", connu sous le nom de modificateur NumLock, comme suit :

  • Si Shift et NumLock sont tous deux activés, le type KEYPAD par défaut renvoie le niveau un.
  • Si Shift seul est activé, il renvoie le niveau deux.
  • Si NumLock seul est activé, il renvoie le niveau deux.
  • Si ni Shift ni NumLock ne sont activés, il renvoie le niveau un.

    Une représentation symbolique de ce type de touche pourrait ressembler à ce qui suit :

        type "KEYPAD" {
        modifiers = Shift+NumLock;
        map[None]= Level1;
        map[Shift]= Level2;
        map[NumLock]= Level2;
        map[Shift+NumLock]= Level1;
        level_name[Level1]= "Base";
        level_name[Level2]= "Caps";
    };
    La description du type de touche KEYPAD est stockée dans l'entrée types[XkbKeypadIndex] de la table des correspondances client.

    Une table des correspondances principale est un tableau à deux dimensions de keysyms. Elle a map_width colonnes et max_key_code lignes. XkbKeyTypesForCoreSymbols prend une seule ligne d'une table des correspondances principale, détermine le nombre de groupes qui lui sont associés, le type de chaque groupe, et les symboles liés à chaque groupe. La valeur de retour est le nombre de groupes, types_inout contient les types pour chaque groupe, et xkb_syms_rtrn contient les symboles dans l'ordre Xkb (c'est-à-dire, les groupes sont contigus, quelle que soit leur taille).

    protected contient les types de touches explicitement protégés. Il y a un contrôle de substitution explicite associé à chacun des quatre groupes possibles pour chaque touche Xkb, ExplicitKeyType1 jusqu'à ExplicitKeyType4 ; protected est un OU inclusif de ces contrôles. map_width est la largeur de la table des correspondances principale et ne dépend d'aucune définition Xkb. types_inout est un tableau de quatre indices de type. En entrée, types_inout contient les indices des types déjà attribués à la touche, au cas où ils seraient explicitement protégés contre les changements.

    Au retour, types_inout contient les types canoniques automatiquement sélectionnés (c'est-à-dire) plus les types protégés. Les types canoniques sont attribués aux quatre groupes s'il y a suffisamment de symboles pour le faire. Les quatre entrées de types_inout correspondent aux quatre groupes pour la touche en question.
