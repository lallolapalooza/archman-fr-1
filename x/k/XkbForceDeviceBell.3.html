XkbForceDeviceBell(3) FONCTIONS XKB XkbForceDeviceBell(3)

NOM

XkbForceDeviceBell - Fait sonner la cloche de n'importe quel clavier, en remplaçant les préférences utilisateur pour les cloches sonores

SYNTAXE

Bool XkbForceDeviceBell (Display *display, Window window, unsigned int device_spec, unsigned int bell_class, unsigned int bell_id, int percent);

ARGUMENTS

display
connexion au serveur X
window
fenêtre d'événement, ou None
device_spec
identifiant de périphérique, ou XkbUseCoreKbd
bell_class
classe d'extension d'entrée de la cloche à faire sonner
bell_id
identifiant d'extension d'entrée de la cloche à faire sonner
percent
volume relatif, qui peut varier de -100 à 100 inclus

DESCRIPTION

Le protocole X de base ne permet qu'aux applications de déclencher explicitement la cloche système avec une durée, une hauteur et un volume donnés. Xkb étend cette capacité en permettant aux clients d'associer des noms symboliques aux cloches, de désactiver les cloches sonores et de recevoir un événement chaque fois que la cloche du clavier est déclenchée. Aux fins de ce document, la cloche sonore est définie comme la cloche système, ou la cloche de clavier par défaut, par opposition à tout autre son généré ailleurs dans le système. Vous pouvez demander à recevoir des événements XkbBellNotify lorsque n'importe quel client déclenche l'une des cloches suivantes :

  • La cloche par défaut
  • Toute cloche sur un périphérique d'entrée qui peut être spécifié par une paire bell_class et bell_id
  • Toute cloche spécifiée uniquement par un nom arbitraire. (Ceci est, du point de vue du serveur, simplement un nom, et n'est pas connecté à un quelconque périphérique physique générant du son. Une application client doit générer le son, ou le retour visuel, le cas échéant, associé au nom.)

Vous pouvez également demander à recevoir des événements XkbBellNotify lorsque le serveur déclenche la cloche par défaut ou si un client a demandé des événements uniquement (sans que la cloche ne sonne) pour l'un des types de cloche listés précédemment.

Vous pouvez désactiver les cloches sonores globalement. Par exemple, un client qui remplace la cloche du clavier par une autre indication sonore pourrait vouloir désactiver le contrôle AudibleBell afin d'empêcher le serveur de générer également un son et d'éviter la cacophonie. Si vous désactivez les cloches sonores et demandez à recevoir des événements XkbBellNotify, vous pouvez générer un retour différent de la cloche par défaut.

Vous pouvez cependant outrepasser le contrôle AudibleBell en appelant l'une des fonctions qui forcent la sonnerie d'une cloche malgré le réglage du contrôle AudibleBell - XkbForceDeviceBell ou XkbForceBell. Dans ce cas, le serveur ne génère pas d'événement de cloche.

Tout comme certains claviers peuvent produire des clics de touche pour indiquer quand une touche est enfoncée ou répétée, Xkb peut fournir un retour pour les contrôles en utilisant des codes sonores spéciaux. Le contrôle AccessXFeedback est utilisé pour configurer les types spécifiques d'opérations qui génèrent un retour.

Noms de cloches

Vous pouvez associer un nom à un acte de déclenchement d'une cloche en convertissant le nom en un Atom, puis en utilisant ce nom lorsque vous appelez les fonctions listées dans ce chapitre. Si un événement est généré en conséquence, le nom est ensuite transmis à tous les autres clients intéressés par la réception d'événements XkbBellNotify. Notez qu'il s'agit de noms arbitraires et qu'il n'y a aucun lien avec des sons quelconques. Tous les sons ou autres effets (tels que des cloches visuelles à l'écran) doivent être générés par une application cliente lors de la réception de l'événement de cloche contenant le nom. Il n'y a pas de nom par défaut pour la cloche de clavier par défaut. Le serveur génère certaines cloches prédéfinies pour les contrôles AccessX. Ces cloches nommées sont présentées dans le Tableau 1 ; le nom est inclus dans tout événement de cloche envoyé aux clients qui ont demandé à recevoir des événements XkbBellNotify.

Cloches sonores

Avec Xkb, vous pouvez générer des événements de cloche qui ne font pas nécessairement sonner la cloche système. Ceci est utile si vous avez besoin d'utiliser un serveur audio au lieu du bip système. Par exemple, lorsqu'un client audio démarre, il pourrait désactiver la cloche sonore (la cloche système), puis écouter les événements XkbBellNotify. Lorsqu'il reçoit un événement XkbBellNotify, le client audio pourrait alors envoyer une requête à un serveur audio pour jouer un son.

Vous pouvez contrôler la fonction des cloches sonores en passant le XkbAudibleBellMask à XkbChangeEnabledControls. Si vous activez XkbAudibleBellMask, le serveur fait sonner la cloche système lorsqu'un événement de cloche se produit. C'est le comportement par défaut. Si vous désactivez XkbAudibleBellMask et qu'un événement de cloche se produit, le serveur ne fait pas sonner la cloche système à moins que vous n'appeliez XkbForceDeviceBell ou XkbForceBell.

Les cloches sonores font également partie des contrôles de réinitialisation automatique par client.

Fonctions de cloche

Utilisez les fonctions décrites dans cette section pour faire sonner les cloches et générer des événements de cloche.

L'extension d'entrée dispose de deux types de retours qui peuvent générer des cloches - le retour de cloche et le retour de clavier. Certaines des fonctions de cette section ont des paramètres bell_class et bell_id ; définissez-les comme suit : Définissez bell_class sur BellFeedbackClass ou KbdFeedbackClass. Un périphérique peut avoir plus d'un retour de chaque type ; définissez bell_id sur la cloche de retour particulière de type bell_class.

Si une extension de clavier compatible n'est pas présente dans le serveur X, XkbForceDeviceBell renvoie immédiatement False. Sinon, XkbForceDeviceBell fait sonner la cloche comme spécifié pour le périphérique d'affichage et de clavier et renvoie True. Définissez percent pour qu'il représente le volume par rapport au volume de base du clavier, comme décrit pour XBell.

STRUCTURES

Xkb génère des événements XkbBellNotify pour toutes les cloches, à l'exception de celles résultant d'appels à XkbForceDeviceBell et XkbForceBell. Pour recevoir des événements XkbBellNotify dans toutes les conditions possibles, passez XkbBellNotifyMask dans les paramètres bits_to_change et values_for_bits à XkbSelectEvents.

L'événement XkbBellNotify n'a pas de détails d'événement. Il est soit sélectionné, soit il ne l'est pas. Cependant, vous pouvez appeler XkbSelectEventDetails en utilisant XkbBellNotify comme event_type et en spécifiant XkbAllBellEventsMask dans bits_to_change et values_for_bits. Cela a le même effet qu'un appel à XkbSelectEvents.

La structure pour le type d'événement XkbBellNotify contient :

   typedef struct _XkbBellNotify {
       int            type;        /* Code de base de l'événement de l'extension Xkb */
       unsigned long  serial;      /* Numéro de série du serveur X pour l'événement */
       Bool           send_event;  /* True => généré synthétiquement */
       Display *      display;     /* Connexion au serveur où l'événement a été généré */
       Time           time;        /* Temps du serveur au moment de la génération de l'événement */
       int            xkb_type;    /* XkbBellNotify */
       unsigned int   device;      /* ID du périphérique Xkb, ne sera pas XkbUseCoreKbd */
       int            percent;     /* Volume demandé en % du maximum */
       int            pitch;       /* Hauteur d'onde demandée en Hz */
       int            duration;    /* Durée demandée en microsecondes */
       unsigned int   bell_class;  /* Classe de rétroaction de l'extension d'entrée X */
       unsigned int   bell_id;     /* ID de rétroaction de l'extension d'entrée X */
       Atom           name;        /* "Nom" de la cloche demandée */
       Window         window;      /* Fenêtre associée à l'événement */
       Bool           event_only;  /* False => le serveur n'a pas produit de sonnerie */
   } XkbBellNotifyEvent;
Si votre application a besoin de générer un retour visuel sur l'écran lorsque elle reçoit un événement de cloche, utilisez l'ID de la fenêtre dans XkbBellNotifyEvent, s'il est présent.
