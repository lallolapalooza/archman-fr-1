XkbGetKeyboardByName(3) FONCTIONS XKB XkbGetKeyboardByName(3)

NOM

XkbGetKeyboardByName - Construit une nouvelle description de clavier à partir d'un ensemble de composants nommés, et éventuellement fait en sorte que le serveur utilise la description résultante pour remplacer une description active

SYNTAXE

XkbDescPtr XkbGetKeyboardByName (Display *dpy, unsigned int device_spec, XkbComponentNamesPtr names, unsigned int want, unsigned int need, Bool load);

ARGUMENTS

dpy
connexion au serveur X
device_spec
spécificateur de périphérique, ou XkbUseCoreKbd
names
noms des composants à récupérer
want
structures désirées dans l'enregistrement retourné
need
structures obligatoires dans l'enregistrement retourné
load
True => charger dans device_spec

DESCRIPTION

Un client peut demander au serveur de récupérer un ou plusieurs composants de sa base de données et d'utiliser ces composants pour construire une nouvelle description de clavier pour le serveur. La nouvelle description de clavier peut être construite à partir de zéro, ou elle peut être construite en commençant par la description de clavier actuelle pour un périphérique donné. Une fois la description du clavier construite, tout ou partie de celle-ci peut être retournée au client. Les parties retournées au client n'incluent pas nécessairement toutes les parties utilisées pour construire la description. Au moment où il demande au serveur de construire une nouvelle description de clavier, un client peut également demander au serveur d'utiliser la nouvelle description en interne pour remplacer la description de clavier actuelle pour un périphérique spécifique, auquel cas le comportement du périphérique change en conséquence.

Pour construire une nouvelle description de clavier à partir d'un ensemble de composants nommés, et éventuellement faire en sorte que le serveur utilise la description résultante pour remplacer une description active, utilisez XkbGetKeyboardByName.

names contient un ensemble d'expressions décrivant les composants du clavier que le serveur doit utiliser pour construire la nouvelle description du clavier. want et need sont des champs de bits décrivant les parties de la description du clavier résultante qui doivent être présentes dans le XkbDescRec retourné.

Les champs individuels dans names sont des expressions de composant composées de noms de composants de clavier (pas de caractères génériques comme ceux utilisés dans XkbListComponents), du nom de composant spécial symbole `%', et des caractères opérateurs spéciaux `+' et `|'. Une expression de composant est analysée de gauche à droite, comme suit :

  • Le nom de composant spécial "computed" peut être utilisé dans les expressions de composants de keycodes et fait référence à un composant constitué d'un ensemble de keycodes calculés automatiquement par le serveur si nécessaire.
  • Le nom de composant spécial "canonical" peut être utilisé dans les expressions de composants de types et fait référence à un composant partiel définissant les quatre types de touches standard : ALPHABETIC, ONE_LEVEL, TWO_LEVEL et KEYPAD.
  • Le nom de composant spécial `%' fait référence à la description du clavier pour le périphérique spécifié dans device_spec ou le composant des noms de keymap. Si un composant de noms de keymap est spécifié qui ne commence pas par `+' ou `|' et ne contient pas `%', alors `%' fait référence à la description générée par le composant de noms de keymap. Sinon, il fait référence à la description du clavier pour device_spec.
  • L'opérateur `+' spécifie que le composant suivant doit remplacer la description actuellement assemblée ; toute définition présente dans les deux composants est prise du second.
  • L'opérateur `|' spécifie que le composant spécifié suivant doit augmenter la description actuellement assemblée ; toute définition présente dans les deux composants est prise du premier.
  • Si l'expression du composant commence par un opérateur, un `%' principal est implicite.
  • Si des caractères inconnus ou illégaux apparaissent n'importe où dans l'expression, l'expression entière est invalide et est ignorée.

    Par exemple, si names->symbols contenait l'expression "+de", elle spécifie que le membre par défaut de la classe "de" des symboles doit être appliqué au mappage de clavier actuel, remplaçant toutes les définitions existantes (elle pourrait aussi être écrite "+de(default)").

    Voici un exemple un peu plus complexe : l'expression "acme(ascii)+de(basic)|iso9995-3" construit un mappage allemand (de) pour le clavier ASCII fourni par le vendeur "acme". La nouvelle définition commence par les symboles du clavier ASCII pour Acme (acme(ascii)), les remplace par les définitions du clavier allemand de base (de(basic)), puis applique les définitions du clavier iso9995-3 par défaut (iso9995-3) à toutes les touches ou groupes de touches non définis (la partie trois de la norme iso9995 définit un ensemble commun de liaisons pour le groupe secondaire, mais permet aux dispositions nationales de remplacer ces définitions si nécessaire).

    NOTE L'interprétation des composants d'expression ci-dessus (acme, ascii, de, basic, iso9995-3) n'est pas définie par Xkb ; seules les opérations et leur ordre le sont.

    Notez que la présence d'un composant names de keymap qui ne contient pas de `%' (explicite ou implicite du fait qu'une expression commence par un opérateur) indique une description indépendante de la description du clavier pour le périphérique spécifié dans device_spec. Il en va de même pour les requêtes dans lesquelles le composant de noms de keymap est vide et tous les cinq autres composants de noms contiennent des expressions vides de références à `%'. Les requêtes de cette forme vous permettent de traiter des définitions de clavier indépendantes de tout périphérique réel.

    Le serveur analyse tous les champs non NUL dans names et les utilise pour construire une description de clavier. Cependant, avant d'analyser les expressions dans names, le serveur effectue un OR bit à bit des bits dans want et need et examine le résultat par rapport aux expressions dans names. Le Tableau 1 identifie les composants requis pour chacun des bits possibles dans want ou need. Si un composant requis n'a pas été spécifié dans la structure names (le champ correspondant est NULL), le serveur substitue l'expression "%", ce qui donne que les valeurs des composants sont prises de device_spec. De plus, si load est True, le serveur modifie names si nécessaire (à nouveau en utilisant une entrée "%") pour s'assurer que tous les champs suivants ne sont pas NUL : types, keycodes, symbols, et compat.

    Tableau 1 Bits du masque Want et Need et Composants de noms requis
    bit du masque want ou need Composants de noms requis valeur
    XkbGBN_TypesMask Types (1L<<0)
    XkbGBN_CompatMapMask Compat (1L<<1)
    XkbGBN_ClientSymbolsMask Types + Symbols + Keycodes (1L<<2)
    XkbGBN_ServerSymbolsMask Types + Symbols + Keycodes (1L<<3)
    XkbGBN_SymbolsMask Symbols (1L<<1)
    XkbGBN_IndicatorMapMask Compat (1L<<4)
    XkbGBN_KeyNamesMask Keycodes (1L<<5)
    XkbGBN_GeometryMask Geometry (1L<<6)
    XkbGBN_OtherNamesMask Types + Symbols + Keycodes + Compat + Geometry (1L<<7)
    XkbGBN_AllComponentsMask (0xff)

    need spécifie un ensemble de composants de clavier que le serveur doit pouvoir résoudre pour que XkbGetKeyboardByName réussisse ; si l'un des composants spécifiés dans need ne peut pas être résolu avec succès, XkbGetKeyboardByName échoue

XkbGetKeyboardByName(3) - Arch Linux

NAME

XkbGetKeyboardByName - build a keyboard description from the Xkb server database

SYNOPSIS

#include <X11/Xlib.h>
#include <X11/Xutil.h>
#include <X11/Xos.h>
#include <X11/extensions/XKB.h>
#include <X11/extensions/XKBstr.h>

XkbDescPtr
XkbGetKeyboardByName (
    Display *dpy,
    XkbKeyNameRec *keyboard_name,
    unsigned int want,
    unsigned int need,
    Bool load
);

ARGUMENTS

dpy
connection to X server
keyboard_name
names of the components to use to build the keyboard description.
want
components that the server should attempt to resolve, but that are not mandatory. (See XkbComponentNames)
need
components that must be resolved for the keyboard description to be valid. (See XkbComponentNames)
load
if True, the server updates its keyboard description for device_spec to match the result of the keyboard description just built.

DESCRIPTION

XkbGetKeyboardByName attempts to build a new keyboard description for the Xkb extension from the components specified in keyboard_name. These components are looked up in the Xkb server database.

need specifies a set of keyboard components that the server must successfully resolve in order for the keyboard description to be considered valid. If any of these components cannot be resolved, XkbGetKeyboardByName returns NULL and generates a BadMatch protocol error.

want specifies a set of keyboard components that the server should attempt to resolve, but that are not mandatory. If the server is unable to resolve any of these components, XkbGetKeyboardByName still succeeds. Bits specified in want that are also specified in need have no effect in the context of want.

If load is True, the server updates its keyboard description for device_spec to match the result of the keyboard description just built. If load is False, the server's description for device device_spec is not updated. In all cases, the parts specified by want and need from the just-built keyboard description are returned.

The names structure in an XkbDescRec keyboard description record contains one field for each of the five component types used to build a keyboard description. When a keyboard description is built from a set of database components, the corresponding fields in this names structure are set to match the expressions used to build the component.

Building a New Keyboard Description from the Server Database

The information returned to the client in the XkbDescRec is essentially the result of a series of calls to extract information from a fictitious device whose description matches the one just built. The calls corresponding to each of the mask bits are summarized in Table 2, together with the XkbDescRec components that are filled in.

There is no way to determine which components specified in want (but not in need) were actually fetched, other than breaking the call into successive calls to XkbGetKeyboardByName and specifying individual components.

XkbGetKeyboardByName always sets min_key_code and max_key_code in the returned XkbDescRec structure.

XkbGetKeyboardByName is synchronous; it sends the request to the server to build a new keyboard description and waits for the reply. If successful, the return value is non-NULL. XkbGetKeyboardByName generates a BadMatch protocol error if errors are encountered when building the keyboard description.

STRUCTURES

The complete description of an Xkb keyboard is given by an XkbDescRec. The component structures in the XkbDescRec represent the major Xkb components outlined in Figure 1.1.

typedef struct {
   struct _XDisplay * display;      /* connection to X server */
   unsigned short     flags;        /* private to Xkb, do not modify */
   unsigned short     device_spec;  /* device of interest */
   KeyCode            min_key_code; /* minimum keycode for device */
   KeyCode            max_key_code; /* maximum keycode for device */
   XkbControlsPtr     ctrls;        /* controls */
   XkbServerMapPtr    server;       /* server keymap */
   XkbClientMapPtr    map;          /* client keymap */
   XkbIndicatorPtr    indicators;   /* indicator map */
   XkbNamesPtr        names;        /* names for all components */
   XkbCompatMapPtr    compat;       /* compatibility map */
   XkbGeometryPtr     geom;         /* physical geometry of keyboard */
} XkbDescRec, *XkbDescPtr;
The display field points to an X display structure. The flags field is private to the library: modifying flags may yield unpredictable results. The device_spec field specifies the device identifier of the keyboard input device, or XkbUseCoreKeyboard, which specifies the core keyboard device. The min_key_code and max_key_code fields specify the least and greatest keycode that can be returned by the keyboard.

Each structure component has a corresponding mask bit that is used in function calls to indicate that the structure should be manipulated in some manner, such as allocating it or freeing it. These masks and their relationships to the fields in the XkbDescRec are shown in Table 3.

Table 3 Mask Bits for XkbDescRec
Mask Bit XkbDescRec Field Value
XkbControlsMask ctrls (1L<<0)
XkbServerMapMask server (1L<<1)
XkbIClientMapMask map (1L<<2)
XkbIndicatorMapMask indicators (1L<<3)
XkbNamesMask names (1L<<4)
XkbCompatMapMask compat (1L<<5)
XkbGeometryMask geom (1L<<6)
XkbAllComponentsMask All Fields (0x7f)

DIAGNOSTICS

BadMatch
A compatible version of Xkb was not available in the server or an argument has correct type and range, but is otherwise invalid
