NOM

XkbGetNamedGeometry - Charge une description de géométrie de clavier depuis cette base de données par nom

SYNTAXE

Status XkbGetNamedGeometry (Display *dpy, XkbDescPtr xkb, Atom name);

ARGUMENTS

dpy
connexion au serveur X
xkb
description du clavier dans laquelle la géométrie doit être chargée
name
nom de la géométrie à charger

DESCRIPTION

Il est également possible de charger une géométrie de clavier par nom. Le serveur X maintient une base de données de composants de clavier (voir ci-dessous).

XkbGetNamedGeometry peut retourner BadName si le nom ne peut pas être trouvé.

Le serveur X maintient une base de données de composants de clavier, identifiés par type de composant. La base de données contient toutes les informations nécessaires pour construire une description complète du clavier pour un appareil particulier, ainsi que pour assembler des descriptions partielles. Le tableau 1 identifie les types de composants et le type d'informations qu'ils contiennent.

Tableau 1 Composants de clavier de la base de données du serveur
Composant Contenu principal du composant Peut aussi contenir
Type
Keymap Description complète du clavier Normalement assemblée en utilisant un composant complet de chacun des autres types
Keycodes Nom symbolique pour chaque touche Codes de touche minimum et maximum légaux Alias pour certaines touches Noms symboliques pour les indicateurs Description des indicateurs physiquement présents
Types Types de touches Liaisons de modificateurs réelles et noms symboliques pour certains modificateurs virtuels
Compatibilité Règles utilisées pour assigner des actions aux keysyms Mappages pour certains indicateurs Liaisons de modificateurs réelles et noms symboliques pour certains modificateurs virtuels
Symboles Mappage de symboles pour les touches du clavier Mappage des modificateurs Noms symboliques pour les groupes Actions et comportements explicites pour certaines touches Liaisons de modificateurs réelles et noms symboliques pour certains modificateurs virtuels
Géométrie Disposition du clavier Alias pour certaines touches ; remplace les alias du composant keycodes Noms symboliques pour certains indicateurs Description des indicateurs physiquement présents

Bien qu'une keymap soit une entrée de base de données pour une description complète du clavier, et donc logiquement différente des entrées individuelles de la base de données des composants, les règles de traitement des entrées de keymap sont identiques à celles des composants individuels. Dans la discussion qui suit, le terme composant est utilisé pour désigner soit des composants individuels, soit une keymap.

Il peut y avoir plusieurs entrées pour chacun des types de composants. Une entrée peut être soit complète, soit partielle. Les entrées partielles décrivent seulement une partie du composant de clavier correspondant et sont conçues pour être combinées avec d'autres entrées du même type pour former une entrée complète.

Par exemple, un mappage de symboles partiel pourrait décrire les différences entre un clavier ASCII courant et une disposition nationale quelconque. Un tel mappage partiel n'est pas utile en soi car il n'inclut pas les symboles qui sont identiques sur les deux dispositions ASCII et nationale (comme les touches de fonction). D'un autre côté, ce mappage partiel peut être utilisé pour configurer n'importe quel clavier ASCII pour utiliser une disposition nationale.

Lorsqu'une description de clavier est construite, les composants sont traités dans l'ordre où ils apparaissent dans le Tableau 1 ; les définitions ultérieures remplacent les précédentes.

DIAGNOSTICS

BadName
Une police ou une couleur du nom spécifié n'existe pas.
