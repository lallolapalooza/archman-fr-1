XkbForceBell(3) FONCTIONS XKB XkbForceBell(3)

NOM

XkbForceBell - Remplace les paramètres de préférence utilisateur pour que les carillons sonores résonnent sur le clavier par défaut

SYNOPSIS

Bool XkbForceBell (Display *display, int percent);

ARGUMENTS

display
connexion au serveur X
percent
volume du carillon, qui peut varier de -100 à 100 inclus

DESCRIPTION

Le protocole X de base ne permet qu'aux applications de faire sonner explicitement le carillon système avec une durée, une hauteur et un volume donnés. Xkb étend cette capacité en permettant aux clients de joindre des noms symboliques aux carillons, de désactiver les carillons sonores et de recevoir un événement chaque fois que le carillon du clavier résonne. Aux fins de ce document, le carillon sonore est défini comme le carillon système, ou le carillon du clavier par défaut, par opposition à tout autre son sonore généré ailleurs dans le système. Vous pouvez demander à recevoir des événements XkbBellNotify lorsque n'importe quel client fait sonner l'un des carillons suivants :

  • Le carillon par défaut
  • N'importe quel carillon sur un périphérique d'entrée qui peut être spécifié par une paire bell_class et bell_id
  • N'importe quel carillon spécifié uniquement par un nom arbitraire. (Ceci est, du point de vue du serveur, simplement un nom, et non connecté à un périphérique physique générant du son. Une application cliente doit générer le son, ou le retour visuel, le cas échéant, associé au nom.)

Vous pouvez également demander à recevoir des événements XkbBellNotify lorsque le serveur fait sonner le carillon par défaut ou si un client a demandé des événements uniquement (sans que le carillon ne sonne) pour l'un des types de carillon listés précédemment.

Vous pouvez désactiver les carillons sonores globalement. Par exemple, un client qui remplace le carillon du clavier par une autre indication sonore pourrait vouloir désactiver le contrôle AudibleBell pour éviter que le serveur ne génère également un son et éviter la cacophonie. Si vous désactivez les carillons sonores et demandez à recevoir des événements XkbBellNotify, vous pouvez générer un retour différent du carillon par défaut.

Vous pouvez cependant ignorer le contrôle AudibleBell en appelant l'une des fonctions qui forcent la résonance d'un carillon malgré le réglage du contrôle AudibleBell - XkbForceDeviceBell ou XkbForceBell. Dans ce cas, le serveur ne génère pas d'événement de carillon.

Tout comme certains claviers peuvent produire des clics de touches pour indiquer quand une touche est enfoncée ou répétée, Xkb peut fournir un retour pour les contrôles en utilisant des codes de bip spéciaux. Le contrôle AccessXFeedback est utilisé pour configurer les types spécifiques d'opérations qui génèrent un retour.

Noms des carillons

Vous pouvez associer un nom à un acte de faire sonner un carillon en convertissant le nom en un Atom, puis en utilisant ce nom lorsque vous appelez les fonctions répertoriées dans ce chapitre. Si un événement est généré en conséquence, le nom est ensuite transmis à tous les autres clients intéressés par la réception d'événements XkbBellNotify. Notez qu'il s'agit de noms arbitraires et qu'il n'y a pas de lien avec des sons. Tous les sons ou autres effets (tels que des carillons visuels à l'écran) doivent être générés par une application cliente lors de la réception de l'événement de carillon contenant le nom. Il n'y a pas de nom par défaut pour le carillon du clavier par défaut. Le serveur génère certains carillons prédéfinis pour les contrôles AccessX. Ces carillons nommés sont présentés dans le Tableau 1 ; le nom est inclus dans tout événement de carillon envoyé aux clients qui ont demandé à recevoir des événements XkbBellNotify.

Carillons sonores

En utilisant Xkb, vous pouvez générer des événements de carillon qui ne font pas nécessairement sonner le carillon système. Ceci est utile si vous avez besoin d'utiliser un serveur audio au lieu du bip système. Par exemple, lorsqu'un client audio démarre, il pourrait désactiver le carillon sonore (le carillon système) puis écouter les événements XkbBellNotify. Lorsqu'il reçoit un événement XkbBellNotify, le client audio pourrait alors envoyer une requête à un serveur audio pour jouer un son.

Vous pouvez contrôler la fonctionnalité des carillons sonores en passant XkbAudibleBellMask à XkbChangeEnabledControls. Si vous activez XkbAudibleBellMask, le serveur fait sonner le carillon système lorsqu'un événement de carillon se produit. C'est le comportement par défaut. Si vous désactivez XkbAudibleBellMask et qu'un événement de carillon se produit, le serveur ne fait pas sonner le carillon système à moins que vous n'appeliez XkbForceDeviceBell ou XkbForceBell.

Les carillons sonores font également partie des contrôles de réinitialisation automatique par client.

Fonctions de carillon

Utilisez les fonctions décrites dans cette section pour faire sonner les carillons et générer des événements de carillon.

L'extension d'entrée a deux types de retours qui peuvent générer des carillons - le retour de carillon et le retour de clavier. Certaines des fonctions de cette section ont des paramètres bell_class et bell_id ; définissez-les comme suit : Définissez bell_class sur BellFeedbackClass ou KbdFeedbackClass. Un périphérique peut avoir plusieurs retours de chaque type ; définissez bell_id sur le retour de carillon particulier du type bell_class.

Le tableau 2 montre les conditions qui provoquent la sonnerie d'un carillon ou la génération d'un événement XkbBellNotify lorsqu'une fonction de carillon est appelée.

Fonction appelée AudibleBell Le serveur fait sonner un carillon Le serveur envoie un
XkbBellNotifyEvent
XkbDeviceBell Activé Oui Oui
XkbDeviceBell Désactivé Non Oui
XkbBell Activé Oui Oui
XkbBell Désactivé Non Oui
XkbDeviceBellEvent Activé ou Désactivé Non Oui
XkbBellEvent Activé ou Désactivé Non Oui
XkbDeviceForceBell Activé ou Désactivé Oui Non
XkbForceBell Activé ou Désactivé Oui Non

Si une extension de clavier compatible n'est pas présente dans le serveur X, XkbForceBell appelle XBell avec le display et le percent spécifiés et retourne False. Sinon, XkbForceBell appelle XkbForceDeviceBell avec le display et le percent spécifiés, device_spec =XkbUseCoreKbd, bell_class = XkbDfltXIClass, bell_id = XkbDfltXIId, window = None, et name = NULL, et retourne ce que retourne XkbForceDeviceBell.

XkbForceBell ne provoque pas d'événement XkbBellNotify.

Vous pouvez appeler XkbBell sans initialiser préalablement l'extension du clavier.

VALEURS DE RETOUR

Faux
La fonction XkbForceBell retourne Faux lorsqu'une extension de clavier compatible n'est pas présente dans le serveur X.

VOIR AUSSI

XkbBell(3), XkbBellNotifyEvent(3), XkbChangeEnabledControls(3), XkbDeviceBell(3), XkbForceDeviceBell(3)

STRUCTURES

Xkb génère des événements XkbBellNotify pour toutes les cloches sauf celles résultant des appels à XkbForceDeviceBell et XkbForceBell. Pour recevoir des événements XkbBellNotify dans toutes les conditions possibles, passez XkbBellNotifyMask dans les paramètres bits_to_change et values_for_bits à XkbSelectEvents.

L'événement XkbBellNotify n'a pas de détails d'événement. Il est soit sélectionné, soit non. Cependant, vous pouvez appeler XkbSelectEventDetails en utilisant XkbBellNotify comme event_type et en spécifiant XkbAllBellEventsMask dans bits_to_change et values_for_bits. Ceci a le même effet qu'un appel à XkbSelectEvents.

La structure pour le type d'événement XkbBellNotify contient :

   typedef struct _XkbBellNotify {
       int            type;        /* Xkb extension base event code */
       unsigned long  serial;      /* X server serial number for event */
       Bool           send_event;  /* True => synthetically generated */
       Display *      display;     /* server connection where event generated */
       Time           time;        /* server time when event generated */
       int            xkb_type;    /* XkbBellNotify */
       unsigned int   device;      /* Xkb device ID, will not be XkbUseCoreKbd */
       int            percent;     /* requested volume as % of max */
       int            pitch;       /* requested pitch in Hz */
       int            duration;    /* requested duration in microseconds */
       unsigned int   bell_class;  /* X input extension feedback class */
       unsigned int   bell_id;     /* X input extension feedback ID */
       Atom           name;        /* "name" of requested bell */
       Window         window;      /* window associated with event */
       Bool           event_only;  /* False -> the server did not produce a beep */
   } XkbBellNotifyEvent;
Si votre application a besoin de générer un retour visuel sur l'écran lorsqu'elle reçoit un événement de cloche, utilisez l'identifiant de fenêtre présent dans XkbBellNotifyEvent, s'il est disponible.

VOIR AUSSI

XBell(3), XkbBell(3), XkbChangeEnabledControls(3), XkbForceDeviceBell(3), XkbSelectEventDetails(3), XkbSelectEvents(3)
