XkbBellEvent(3) FONCTIONS XKB XkbBellEvent(3)

NOM

XkbBellEvent - Fournit une fonction qui déclenche un événement de sonnerie pour le clavier sans faire sonner la sonnerie

SYNTAXE

Bool XkbBellEvent (Display *display, Window window, int percent, Atom name);

ARGUMENTS

display
connexion au serveur X
window
la fenêtre d'événement, ou None
percent
volume relatif, qui peut varier de -100 à 100 inclus
name
un nom de sonnerie, ou NULL

DESCRIPTION

Le protocole X de base ne permet qu'aux applications de déclencher explicitement la sonnerie système avec une durée, une hauteur et un volume donnés. Xkb étend cette capacité en permettant aux clients d'associer des noms symboliques aux sonneries, de désactiver les sonneries audibles et de recevoir un événement chaque fois que la sonnerie du clavier est activée. Pour les besoins de ce document, la sonnerie audible est définie comme étant la sonnerie système, ou la sonnerie du clavier par défaut, par opposition à tout autre son audible généré ailleurs dans le système. Vous pouvez demander à recevoir des événements XkbBellNotify lorsque tout client déclenche l'une des sonneries suivantes :

  • La sonnerie par défaut
  • Toute sonnerie sur un périphérique d'entrée qui peut être spécifié par une paire bell_class et bell_id
  • Toute sonnerie spécifiée uniquement par un nom arbitraire. (Ceci est, du point de vue du serveur, simplement un nom, et n'est pas connecté à un périphérique physique générant du son. Une application client doit générer le son, ou le retour visuel, le cas échéant, associé au nom.)

    Vous pouvez également demander à recevoir des événements XkbBellNotify lorsque le serveur déclenche la sonnerie par défaut ou si un client a demandé uniquement des événements (sans que la sonnerie ne retentisse) pour l'un des types de sonneries listés précédemment.

    Vous pouvez désactiver les sonneries audibles de manière globale. Par exemple, une application cliente qui remplace la sonnerie du clavier par un autre indice sonore pourrait vouloir désactiver le contrôle AudibleBell pour empêcher le serveur de générer également un son et d'éviter la cacophonie. Si vous désactivez les sonneries audibles et demandez à recevoir des événements XkbBellNotify, vous pouvez générer un retour différent de la sonnerie par défaut.

    Vous pouvez cependant outrepasser le contrôle AudibleBell en appelant l'une des fonctions qui forcent le déclenchement d'une sonnerie malgré le réglage du contrôle AudibleBell - XkbForceDeviceBell ou XkbForceBell. Dans ce cas, le serveur ne génère pas d'événement de sonnerie.

    Tout comme certains claviers peuvent produire des clics de touches pour indiquer quand une touche est enfoncée ou répétée, Xkb peut fournir un retour pour les contrôles en utilisant des codes de bip spéciaux. Le contrôle AccessXFeedback est utilisé pour configurer les types spécifiques d'opérations qui génèrent un retour.

    Noms des sonneries

    Vous pouvez associer un nom à l'action de déclencher une sonnerie en convertissant le nom en Atom, puis en utilisant ce nom lorsque vous appelez les fonctions listées dans ce chapitre. Si un événement est généré en conséquence, le nom est ensuite transmis à tous les autres clients intéressés par la réception d'événements XkbBellNotify. Notez qu'il s'agit de noms arbitraires et qu'il n'y a aucun lien avec des sons. Tous les sons ou autres effets (tels que des sonneries visuelles à l'écran) doivent être générés par une application cliente lors de la réception de l'événement de sonnerie contenant le nom. Il n'y a pas de nom par défaut pour la sonnerie du clavier par défaut. Le serveur génère quelques sonneries prédéfinies pour les contrôles AccessX. Ces sonneries nommées sont présentées dans le Tableau 1 ; le nom est inclus dans tout événement de sonnerie envoyé aux clients qui ont demandé à recevoir des événements XkbBellNotify.

    Sonneries audibles

    En utilisant Xkb, vous pouvez générer des événements de sonnerie qui ne font pas nécessairement sonner la sonnerie système. Ceci est utile si vous avez besoin d'utiliser un serveur audio au lieu du bip système. Par exemple, lorsqu'un client audio démarre, il peut désactiver la sonnerie audible (la sonnerie système), puis écouter les événements XkbBellNotify. Lorsqu'il reçoit un événement XkbBellNotify, le client audio peut alors envoyer une requête à un serveur audio pour jouer un son.

    Vous pouvez contrôler la fonction de sonneries audibles en passant XkbAudibleBellMask à XkbChangeEnabledControls. Si vous activez XkbAudibleBellMask, le serveur fait sonner la sonnerie système lorsqu'un événement de sonnerie se produit. C'est le comportement par défaut. Si vous désactivez XkbAudibleBellMask et qu'un événement de sonnerie se produit, le serveur ne fait pas sonner la sonnerie système à moins que vous n'appeliez XkbForceDeviceBell ou XkbForceBell.

    Les sonneries audibles font également partie des contrôles de réinitialisation automatique par client.

    Fonctions de sonnerie

    Utilisez les fonctions décrites dans cette section pour déclencher des sonneries et générer des événements de sonnerie.

    L'extension d'entrée possède deux types de retours qui peuvent générer des sonneries : le retour de sonnerie et le retour clavier. Certaines des fonctions de cette section ont des paramètres bell_class et bell_id ; configurez-les comme suit : Définissez bell_class sur BellFeedbackClass ou KbdFeedbackClass. Un périphérique peut avoir plusieurs retours de chaque type ; définissez bell_id sur le retour de sonnerie particulier de type bell_class.

XkbBellEvent retourne immédiatement False. Sinon, XkbBellEvent appelle XkbDeviceBellEvent avec le display, window, percent, et name, spécifiés, un device_spec de XkbUseCoreKbd, une bell_class de XkbDfltXIClass, et un bell_id de XkbDfltXIId, et retourne ce que XkbDeviceBellEvent retourne.

XkbBellEvent génère un événement XkbBellNotify.

Vous pouvez appeler XkbBellEvent sans initialiser l'extension du clavier au préalable.

VALEURS DE RETOUR

Faux
XkbBellEvent retourne immédiatement Faux si une extension de clavier compatible n'est pas présente dans le serveur X.

STRUCTURES

Xkb génère des événements XkbBellNotify pour toutes les cloches, sauf pour celles résultant d'appels à XkbForceDeviceBell et XkbForceBell. Pour recevoir des événements XkbBellNotify dans toutes les conditions possibles, passez XkbBellNotifyMask dans les paramètres bits_to_change et values_for_bits à XkbSelectEvents.

L'événement XkbBellNotify n'a pas de détails d'événement. Il est soit sélectionné, soit non. Cependant, vous pouvez appeler XkbSelectEventDetails en utilisant XkbBellNotify comme event_type et en spécifiant XkbAllBellEventsMask dans bits_to_change et values_for_bits. Cela a le même effet qu'un appel à XkbSelectEvents.

La structure pour le type d'événement XkbBellNotify contient :

   typedef struct _XkbBellNotify {
       int            type;        /* Code d'événement de base de l'extension Xkb */
       unsigned long  serial;      /* Numéro de série du serveur X pour l'événement */
       Bool           send_event;  /* True => généré synthétiquement */
       Display *      display;     /* Connexion au serveur où l'événement a été généré */
       Time           time;        /* Temps du serveur lors de la génération de l'événement */
       int            xkb_type;    /* XkbBellNotify */
       unsigned int   device;      /* ID du périphérique Xkb, ne sera pas XkbUseCoreKbd */
       int            percent;     /* Volume demandé en % du maximum */
       int            pitch;       /* Hauteur demandée en Hz */
       int            duration;    /* Durée demandée en microsecondes */
       unsigned int   bell_class;  /* Classe de rétroaction de l'extension d'entrée X */
       unsigned int   bell_id;     /* ID de rétroaction de l'extension d'entrée X */
       Atom           name;        /* "nom" de la cloche demandée */
       Window         window;      /* fenêtre associée à l'événement */
       Bool           event_only;  /* False -> le serveur n'a pas produit de sonnerie */
   } XkbBellNotifyEvent;
Si votre application doit générer un retour visuel de cloche à l'écran lorsqu'elle reçoit un événement de cloche, utilisez l'ID de fenêtre dans le XkbBellNotifyEvent, s'il est présent.
