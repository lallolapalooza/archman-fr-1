XkbBell(3) FONCTIONS XKB XkbBell(3)

NOM

XkbBell - Fait sonner la cloche du clavier par défaut

SYNTAXE

Bool XkbBell (Display *display, Window window, int percent, Atom name);

ARGUMENTS

display
connexion au serveur X
window
fenêtre d'événement, ou None
percent
volume relatif, qui peut varier de -100 à 100 inclus
name
un nom de cloche, ou NULL

DESCRIPTION

Le protocole X de base ne permet qu'aux applications de faire sonner explicitement la cloche système avec une durée, une hauteur et un volume donnés. Xkb étend cette capacité en permettant aux clients d'associer des noms symboliques aux cloches, de désactiver les cloches sonores et de recevoir un événement chaque fois que la cloche du clavier sonne. Aux fins de ce document, la cloche sonore est définie comme la cloche système, ou la cloche du clavier par défaut, par opposition à tout autre son audible généré ailleurs dans le système. Vous pouvez demander à recevoir des événements XkbBellNotify lorsque n'importe quel client fait sonner l'une des cloches suivantes :

  • La cloche par défaut
  • Toute cloche sur un périphérique d'entrée pouvant être spécifié par une paire classe-cloche et id-cloche
  • Toute cloche spécifiée uniquement par un nom arbitraire. (Ceci est, du point de vue du serveur, simplement un nom, et non connecté à un périphérique générant du son physique. Une application client doit générer le son, ou le retour visuel, le cas échéant, associé au nom.)

Vous pouvez également demander à recevoir des événements XkbBellNotify lorsque le serveur fait sonner la cloche par défaut ou si un client a demandé des événements uniquement (sans que la cloche ne sonne) pour l'un des types de cloches précédemment listés.

Vous pouvez désactiver les cloches sonores de manière globale. Par exemple, un client qui remplace la cloche du clavier par un autre signal sonore pourrait vouloir désactiver le contrôle AudibleBell pour empêcher le serveur de générer également un son et éviter la cacophonie. Si vous désactivez les cloches sonores et demandez à recevoir des événements XkbBellNotify, vous pouvez générer un retour différent de la cloche par défaut.

Vous pouvez cependant outrepasser le contrôle AudibleBell en appelant l'une des fonctions qui forcent la sonnerie d'une cloche malgré le réglage du contrôle AudibleBell - XkbForceDeviceBell ou XkbForceBell. Dans ce cas, le serveur ne génère pas d'événement de cloche.

Tout comme certains claviers peuvent produire des clics de touche pour indiquer quand une touche est pressée ou répétée, Xkb peut fournir un retour pour les contrôles en utilisant des codes de bip spéciaux. Le contrôle AccessXFeedback est utilisé pour configurer les types spécifiques d'opérations qui génèrent un retour.

Noms de cloche

Vous pouvez associer un nom à un acte de sonner une cloche en convertissant le nom en Atom, puis en utilisant ce nom lors de l'appel des fonctions listées dans ce chapitre. Si un événement est généré en conséquence, le nom est alors transmis à tous les autres clients intéressés par la réception d'événements XkbBellNotify. Notez qu'il s'agit de noms arbitraires et qu'il n'y a pas de lien avec des sons. Tous les sons ou autres effets (tels que des cloches visuelles à l'écran) doivent être générés par une application cliente lors de la réception de l'événement de cloche contenant le nom. Il n'y a pas de nom par défaut pour la cloche du clavier par défaut. Le serveur génère quelques cloches prédéfinies pour les contrôles AccessX. Ces cloches nommées sont présentées dans le tableau 1 ci-dessous ; le nom est inclus dans tout événement de cloche envoyé aux clients qui ont demandé à recevoir des événements XkbBellNotify.

Cloches sonores

En utilisant Xkb, vous pouvez générer des événements de cloche qui ne font pas nécessairement sonner la cloche système. Ceci est utile si vous avez besoin d'utiliser un serveur audio au lieu du bip système. Par exemple, lorsqu'un client audio démarre, il pourrait désactiver la cloche sonore (la cloche système), puis écouter les événements XkbBellNotify. Lorsqu'il reçoit un événement XkbBellNotify, le client audio pourrait alors envoyer une requête à un serveur audio pour jouer un son.

Vous pouvez contrôler la fonctionnalité des cloches sonores en passant XkbAudibleBellMask à XkbChangeEnabledControls. Si vous activez XkbAudibleBellMask, le serveur fait sonner la cloche système lorsqu'un événement de cloche se produit. C'est le comportement par défaut. Si vous désactivez XkbAudibleBellMask et qu'un événement de cloche se produit, le serveur ne fait pas sonner la cloche système à moins que vous n'appeliez XkbForceDeviceBell ou XkbForceBell.

Les cloches sonores font également partie des contrôles de réinitialisation automatique par client.

Fonctions de cloche

Utilisez les fonctions décrites dans cette section pour faire sonner les cloches et générer des événements de cloche.

L'extension d'entrée possède deux types de retours qui peuvent générer des cloches - le retour de cloche et le retour clavier. Certaines fonctions de cette section ont des paramètres bell_class et bell_id ; définissez-les comme suit : Définissez bell_class sur BellFeedbackClass ou KbdFeedbackClass. Un périphérique peut avoir plusieurs retours de chaque type ; définissez bell_id sur le retour de cloche particulier de type bell_class.

Le tableau 2 montre les conditions qui provoquent le son d'une cloche ou la génération d'un événement XkbBellNotify lors de l'appel d'une fonction de cloche.

Tableau 2 Son de cloche et génération d'événement de cloche
Fonction appelée AudibleBell Le serveur fait sonner une cloche Le serveur envoie un événement
XkbBellNotifyEvent
XkbDeviceBell Activé Oui Oui
XkbDeviceBell Désactivé Non Oui
XkbBell Activé Oui Oui
XkbBell Désactivé Non Oui
XkbDeviceBellEvent Activé ou Désactivé Non Oui
XkbBellEvent Activé ou Désactivé Non Oui
XkbDeviceForceBell Activé ou Désactivé Oui Non
XkbForceBell Activé ou Désactivé Oui Non

Si une extension de clavier compatible n'est pas présente dans le serveur X, XkbBell appelle XBell avec le display et le percent spécifiés, et retourne False. Sinon, XkbBell appelle XkbDeviceBell avec le display, window, percent, et name spécifiés, un device_spec de XkbUseCoreKbd, une bell_class de XkbDfltXIClass, et une bell_id de XkbDfltXIId, et retourne True.

Si vous avez désactivé la cloche sonore, le serveur ne fait pas sonner la cloche système, bien qu'il génère un événement XkbBellNotify.

Vous pouvez appeler XkbBell sans initialiser préalablement l'extension clavier.

VALEURS DE RETOUR

FAUX
La fonction XkbBell retourne FALSE si XlibDisplayNoXkb est défini.

STRUCTURES

Xkb génère des événements XkbBellNotify pour toutes les cloches, à l'exception de celles résultant d'appels à XkbForceDeviceBell et XkbForceBell. Pour recevoir des événements XkbBellNotify dans toutes les conditions possibles, passez XkbBellNotifyMask dans les paramètres bits_to_change et values_for_bits à XkbSelectEvents.

L'événement XkbBellNotify n'a pas de détails d'événement. Il est soit sélectionné, soit il ne l'est pas. Cependant, vous pouvez appeler XkbSelectEventDetails en utilisant XkbBellNotify comme event_type et en spécifiant XkbAllBellEventsMask dans bits_to_change et values_for_bits. Cela a le même effet qu'un appel à XkbSelectEvents.

La structure pour le type d'événement XkbBellNotify contient :

   typedef struct _XkbBellNotify {
       int            type;        /* Code d'événement de base de l'extension Xkb */
       unsigned long  serial;      /* Numéro de série du serveur X pour l'événement */
       Bool           send_event;  /* True => généré synthétiquement */
       Display *      display;     /* Connexion au serveur où l'événement a été généré */
       Time           time;        /* Heure du serveur à laquelle l'événement a été généré */
       int            xkb_type;    /* XkbBellNotify */
       unsigned int   device;      /* ID du périphérique Xkb, ne sera pas XkbUseCoreKbd */
       int            percent;     /* Volume demandé en % du maximum */
       int            pitch;       /* Hauteur demandée en Hz */
       int            duration;    /* Durée demandée en microsecondes */
       unsigned int   bell_class;  /* Classe de retour d'information de l'extension d'entrée X */
       unsigned int   bell_id;     /* ID de retour d'information de l'extension d'entrée X */
       Atom           name;        /* "Nom" de la cloche demandée */
       Window         window;      /* Fenêtre associée à l'événement */
       Bool           event_only;  /* False -> le serveur n'a pas produit de bip */
   } XkbBellNotifyEvent;
Si votre application doit générer un retour visuel sur l'écran lorsqu'elle reçoit un événement de cloche, utilisez l'ID de fenêtre dans XkbBellNotifyEvent, s'il est présent.
