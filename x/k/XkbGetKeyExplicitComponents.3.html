XkbGetKeyExplicitComponents(3) FONCTION XKB XkbGetKeyExplicitComponents(3)

NOM

XkbGetKeyExplicitComponents - Obtenir les composants explicites (le tableau explicite) pour un sous-ensemble de touches dans une description de clavier

SYNTAXE

Status XkbGetKeyExplicitComponents (Display *dpy, unsigned int first, unsigned int num, XkbDescPtr xkb);

ARGUMENTS

dpy
connexion au serveur
first
code de touche de la première touche à récupérer
num
nombre de touches pour lesquelles obtenir les informations explicites
xkb
description Xkb dans laquelle placer les résultats

DESCRIPTION

Chaque fois qu'un client remappe le clavier à l'aide des requêtes du protocole de base, Xkb examine la carte pour déterminer les valeurs par défaut probables pour les composants qui ne peuvent pas être spécifiés à l'aide du protocole de base (voir Transformation du mappage du clavier de base vers le mappage du clavier Xkb pour plus d'informations sur la manière dont Xkb choisit les valeurs par défaut).

FAUT-IL AJOUTER LES QUATRE PAGES DE "TRANSFORMATION DU MAPPAGE DU CLAVIER DE BASE VERS LE MAPPAGE DU CLAVIER XKB" ICI ?

Ce remappage automatique peut remplacer les définitions explicitement demandées par une application. La description du clavier Xkb définit donc un masque de composants explicites pour chaque touche. Tous les aspects du remappage automatique listés dans le masque de composants explicites d'une touche ne sont pas modifiés par le mappage automatique du clavier.

Les masques de composants explicites sont stockés dans le champ explicit de la carte serveur, qui est un tableau indexé par le code de touche. Chaque entrée de ce tableau est un masque qui est un OU inclusif bit à bit des valeurs indiquées dans le Tableau 1.

Tableau 1 Masques de composants explicites
Bit dans le masque explicite Valeur Protège contre
ExplicitKeyType1 (1<<0) Détermination automatique du type de touche associé au Groupe 1.
ExplicitKeyType2 (1<<1) Détermination automatique du type de touche associé au Groupe 2.
ExplicitKeyType3 (1<<2) Détermination automatique du type de touche associé au Groupe 3.
ExplicitKeyType4 (1<<3) Détermination automatique du type de touche associé au Groupe 4.
ExplicitInterpret (1<<4) Application de l'un des champs d'une interprétation de symbole à la touche en question.
ExplicitAutoRepeat (1<<5) Détermination automatique de l'état de répétition automatique de la touche, tel que spécifié dans une interprétation de symbole.
ExplicitBehavior (1<<6) Assignation automatique du comportement XkbKB_Lock à la touche, si le drapeau XkbSI_LockingKey est défini dans une interprétation de symbole.
ExplicitVModMap (1<<7) Détermination automatique du mappage des modificateurs virtuels pour la touche en fonction des actions assignées à la touche et des interprétations de symboles qui correspondent à la touche.

XkbGetKeyExplicitComponents envoie une requête au serveur pour obtenir les composants explicites de num touches du clavier, à partir de la touche first. Il attend une réponse et renvoie les composants explicites dans le tableau server->explicit de xkb. En cas de succès, XkbGetKeyExplicitComponents retourne Success. Le paramètre xkb doit être un pointeur vers une description de clavier Xkb valide.

Si la carte server du paramètre xkb n'a pas été allouée, XkbGetKeyExplicitComponents l'alloue et l'initialise avant d'obtenir les actions.

Si le serveur n'a pas une version compatible de Xkb, ou si l'extension Xkb n'a pas été correctement initialisée, XkbGetKeyExplicitComponents retourne BadMatch. Si num est inférieur à 1 ou supérieur à XkbMaxKeyCount, XkbGetKeyExplicitComponents retourne BadValue. Si des erreurs d'allocation se produisent, XkbGetKeyExplicitComponents retourne BadAlloc.

DIAGNOSTICS

BadAlloc
Impossible d'allouer de l'espace
BadMatch
Une version compatible de Xkb n'était pas disponible sur le serveur ou un argument a un type et une plage corrects, mais est par ailleurs invalide
BadValue
Un argument est hors plage
