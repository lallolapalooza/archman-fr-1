XkbKeyActionEntry(3) FONCTIONS XKB XkbKeyActionEntry(3)

NOM

XkbKeyActionEntry - Retourne un pointeur vers l'action de touche correspondant au groupe grp et au niveau de décalage lvl à partir de la table bidimensionnelle des actions de touche associées à la touche correspondant au keycode

SYNTAXE

XkbAction * XkbKeyActionEntry (XkbDescPtr xkb, KeyCode keycode, int shift, int grp);

ARGUMENTS

xkb
Description Xkb d'intérêt
keycode
Code de touche d'intérêt
shift
Niveau de décalage dans le groupe
grp
Indice de groupe pour le groupe d'intérêt

DESCRIPTION

Une action de touche définit l'effet des pressions et des relâchements de touche sur l'état interne du serveur. Par exemple, l'action de touche attendue associée à la pression de la touche Maj est de définir le modificateur Maj. Il y a zéro ou une action de touche associée à chaque keysym lié à chaque touche.

Tout comme la liste complète des symboles de touche pour le mappage du clavier est conservée dans le champ syms de la carte client, la liste complète des actions de touche pour le mappage du clavier est conservée dans le tableau acts de la carte serveur. La taille totale de acts est spécifiée par size_acts, et le nombre d'entrées est spécifié par num_acts.

Le tableau key_acts, indexé par code de touche, décrit les actions associées à une touche. Le tableau key_acts contient min_key_code entrées inutilisées au début pour permettre l'indexation directe à l'aide d'un code de touche. Si une entrée key_acts est nulle, cela signifie que la touche n'a aucune action associée. Si une entrée n'est pas nulle, l'entrée représente un index dans le champ acts de la carte serveur, tout comme le champ offset d'une structure KeySymMapRec est un index dans le champ syms de la carte client.

La raison pour laquelle le champ acts est une liste linéaire de XkbActions est de réduire la consommation de mémoire associée à une carte de touches. Étant donné que Xkb permet aux touches individuelles d'avoir plusieurs niveaux de décalage et un nombre différent de groupes par touche, un seul tableau bidimensionnel de KeySyms serait potentiellement très grand et éparse. Au lieu de cela, Xkb fournit un petit tableau bidimensionnel d'actions Xkb pour chaque touche. Pour stocker chacun de ces tableaux individuels, Xkb concatène chaque tableau dans le champ acts de la carte serveur.

Les structures d'action de touche ne contiennent que des champs de type char ou unsigned char. Ceci est fait pour optimiser le transfert de données lorsque le serveur envoie des octets sur le réseau. Si les champs sont autre chose que des octets, le serveur doit parcourir toutes les actions et échanger les champs non-octets. Parce qu'ils ne contiennent que des octets, il peut simplement les copier.

XkbKeyActionEntry retourne l'action de touche correspondant au groupe grp et au niveau de décalage lvl à partir de la table bidimensionnelle des actions de touche associées à la touche correspondant à keycode.

STRUCTURES

La structure KeySymMapRec est définie comme suit :

    #define XkbNumKbdGroups             4
    #define XkbMaxKbdGroup              (XkbNumKbdGroups-1)
    typedef struct {                    /* carte vers les keysyms pour un code de touche unique */
        unsigned char       kt_index[XkbNumKbdGroups];  /* index du type de touche pour chaque groupe */
        unsigned char       group_info; /* # de groupes et gestion des groupes hors limites */
        unsigned char       width;      /* nombre max de niveaux de décalage pour la touche */
        unsigned short      offset;     /* index de la table des keysyms dans le tableau syms */
} XkbSymMapRec, *XkbSymMapPtr;
