XkbDeviceBell(3) FONCTIONS XKB XkbDeviceBell(3)

NOM

XkbDeviceBell - Fait sonner la cloche sur un périphérique d'extension d'entrée X ou le clavier par défaut

SYNTAXE

Bool XkbDeviceBell (Display *display, Window window, unsigned int device_spec, unsigned int bell_class, unsigned int bell_id, int percent, Atom name);

ARGUMENTS

display
connexion au serveur X
window
fenêtre pour laquelle la cloche est générée, ou None
device_spec
ID du périphérique, ou XkbUseCoreKbd
bell_class
classe de cloche de l'extension d'entrée X de la cloche à faire sonner
bell_id
ID de cloche de l'extension d'entrée X de la cloche à faire sonner
percent
volume de la cloche, de -100 à 100 inclus
name
un nom pour la cloche, ou NULL

DESCRIPTION

Le protocole X principal permet uniquement aux applications de faire sonner explicitement la cloche système avec une durée, une hauteur et un volume donnés. Xkb étend cette capacité en permettant aux clients d'associer des noms symboliques aux cloches, de désactiver les cloches audibles et de recevoir un événement chaque fois que la cloche du clavier sonne. Aux fins de ce document, la cloche audible est définie comme la cloche système, ou la cloche du clavier par défaut, par opposition à tout autre son audible généré ailleurs dans le système. Vous pouvez demander à recevoir des événements XkbBellNotify lorsque n'importe quel client fait sonner l'une des cloches suivantes :

  • La cloche par défaut
  • Toute cloche sur un périphérique d'entrée qui peut être spécifié par une paire bell_class et bell_id
  • Toute cloche spécifiée uniquement par un nom arbitraire. (Ceci est, du point de vue du serveur, simplement un nom, et n'est pas connecté à un périphérique physique générant du son. Une application client doit générer le son, ou le retour visuel, le cas échéant, qui est associé au nom.)

    Vous pouvez également demander à recevoir des événements XkbBellNotify lorsque le serveur fait sonner la cloche par défaut ou si un client a demandé des événements uniquement (sans que la cloche ne sonne) pour l'un des types de cloches précédemment listés.

    Vous pouvez désactiver les cloches audibles globalement. Par exemple, une application qui remplace la cloche du clavier par un autre indice sonore pourrait vouloir désactiver le contrôle AudibleBell pour éviter que le serveur ne génère également un son et n'évite la cacophonie. Si vous désactivez les cloches audibles et demandez à recevoir des événements XkbBellNotify, vous pouvez générer un retour différent de la cloche par défaut.

    Vous pouvez, cependant, outrepasser le contrôle AudibleBell en appelant l'une des fonctions qui forcent le son de la cloche malgré le réglage du contrôle AudibleBell - XkbForceDeviceBell ou XkbForceBell. Dans ce cas, le serveur ne génère pas d'événement de cloche.

    Tout comme certains claviers peuvent produire des clics de touches pour indiquer quand une touche est enfoncée ou répétée, Xkb peut fournir un retour pour les contrôles en utilisant des codes de bip spéciaux. Le contrôle AccessXFeedback est utilisé pour configurer les types spécifiques d'opérations qui génèrent un retour.

    Noms des cloches

    Vous pouvez associer un nom à un acte de faire sonner une cloche en convertissant le nom en un Atom, puis en utilisant ce nom lors de l'appel des fonctions décrites dans ce chapitre. Si un événement est généré en conséquence, le nom est ensuite transmis à tous les autres clients intéressés par la réception d'événements XkbBellNotify. Notez qu'il s'agit de noms arbitraires et qu'il n'y a aucun lien avec des sons. Tous les sons ou autres effets (tels que des cloches visuelles à l'écran) doivent être générés par une application cliente lors de la réception de l'événement de cloche contenant le nom. Il n'y a pas de nom par défaut pour la cloche du clavier par défaut. Le serveur génère quelques cloches prédéfinies pour les contrôles AccessX. Ces cloches nommées sont présentées dans le Tableau 1 ; le nom est inclus dans tout événement de cloche envoyé aux clients qui ont demandé à recevoir des événements XkbBellNotify.

    Cloches audibles

    Avec Xkb, vous pouvez générer des événements de cloche qui ne font pas nécessairement sonner la cloche système. Ceci est utile si vous avez besoin d'utiliser un serveur audio au lieu du bip système. Par exemple, lorsqu'un client audio démarre, il pourrait désactiver la cloche audible (la cloche système), puis écouter les événements XkbBellNotify. Lorsqu'il reçoit un événement XkbBellNotify, le client audio pourrait alors envoyer une requête à un serveur audio pour jouer un son.

    Vous pouvez contrôler la fonction de cloches audibles en passant XkbAudibleBellMask à XkbChangeEnabledControls. Si vous activez XkbAudibleBellMask, le serveur fait sonner la cloche système lorsqu'un événement de cloche se produit. C'est le comportement par défaut. Si vous désactivez XkbAudibleBellMask et qu'un événement de cloche se produit, le serveur ne fait pas sonner la cloche système à moins que vous n'appeliez XkbForceDeviceBell ou XkbForceBell.

    Les cloches audibles font également partie des contrôles de réinitialisation automatique par client.

    Fonctions de cloche

    Utilisez les fonctions décrites dans cette section pour faire sonner les cloches et générer des événements de cloche.

    L'extension d'entrée possède deux types de retours qui peuvent générer des cloches - le retour de cloche et le retour de clavier. Certaines des fonctions de cette section ont des paramètres bell_class et bell_id ; définissez-les comme suit : Définissez bell_class sur BellFeedbackClass ou KbdFeedbackClass. Un périphérique peut avoir plus d'un retour de chaque type ; définissez bell_id sur le retour de cloche particulier du type bell_class.

Définissez percent pour être le volume relatif au volume de base du clavier tel que décrit pour .I XBell.

Notez que bell_class et bell_id indiquent la sonnerie à faire retentir physiquement. name est simplement un nom arbitraire pour l'utilisation de l'application cliente.

Pour déterminer les paramètres de retour actuels d'un périphérique d'entrée d'extension, utilisez XGetFeedbackControl. Voir la documentation de l'extension d'entrée X pour plus d'informations sur XGetFeedbackControl et les structures de données associées.

Si une extension de clavier compatible n'est pas présente dans le serveur X, XkbDeviceBell renvoie immédiatement False. Sinon, XkbDeviceBell fait retentir la sonnerie comme spécifié pour le périphérique d'affichage et de clavier et renvoie True. Si vous avez désactivé la sonnerie audible, le serveur ne fait pas retentir la sonnerie système, bien qu'il génère un événement XkbBellNotify.

Vous pouvez appeler XkbDeviceBell sans avoir initialisé l'extension du clavier au préalable.

STRUCTURES

Xkb génère des événements XkbBellNotify pour toutes les sonneries, sauf celles résultant d'appels à XkbForceDeviceBell et XkbForceBell. Pour recevoir des événements XkbBellNotify dans toutes les conditions possibles, passez XkbBellNotifyMask dans les paramètres bits_to_change et values_for_bits à XkbSelectEvents.

L'événement XkbBellNotify n'a pas de détails d'événement. Il est soit sélectionné, soit il ne l'est pas. Cependant, vous pouvez appeler XkbSelectEventDetails en utilisant XkbBellNotify comme event_type et en spécifiant XkbAllBellEventsMask dans bits_to_change et values_for_bits. Cela a le même effet qu'un appel à XkbSelectEvents.

La structure pour le type d'événement XkbBellNotify contient:

   typedef struct _XkbBellNotify {
       int            type;        /* code d'événement de base de l'extension Xkb */
       unsigned long  serial;      /* numéro de série du serveur X pour l'événement */
       Bool           send_event;  /* True => généré synthétiquement */
       Display *      display;     /* connexion au serveur où l'événement a été généré */
       Time           time;        /* temps du serveur lors de la génération de l'événement */
       int            xkb_type;    /* XkbBellNotify */
       unsigned int   device;      /* ID du périphérique Xkb, ne sera pas XkbUseCoreKbd */
       int            percent;     /* volume demandé en % du maximum */
       int            pitch;       /* hauteur demandée en Hz */
       int            duration;    /* durée demandée en microsecondes */
       unsigned int   bell_class;  /* classe de retour de l'extension d'entrée X */
       unsigned int   bell_id;     /* ID de retour de l'extension d'entrée X */
       Atom           name;        /* "nom" de la sonnerie demandée */
       Window         window;      /* fenêtre associée à l'événement */
       Bool           event_only;  /* False => le serveur n'a pas produit de bip */
   } XkbBellNotifyEvent;
Si votre application doit générer un retour visuel sur l'écran lors de la réception d'un événement de sonnerie, utilisez l'ID de fenêtre dans le XkbBellNotifyEvent, s'il est présent.
