Paquet: libx11

XkbAllocClientMap(3) FONCTIONS XKB XkbAllocClientMap(3)

NOM

XkbAllocClientMap - Alloue et initialise un enregistrement de description de carte client vide

SYNTAXE

Status XkbAllocClientMap (XkbDescPtr xkb, unsigned int which, unsigned int type_count);

ARGUMENTS

xkb
description du clavier dans laquelle allouer la carte client
which
masque sélectionnant les composants de carte à allouer
type_count
valeur du champ num_types dans la carte à allouer

DESCRIPTION

L'appel à XkbGetMap devrait suffire à la plupart des applications pour obtenir les cartes client et serveur. Par conséquent, la plupart des applications n'ont pas besoin d'allouer directement les cartes client et serveur.

Si vous modifiez le nombre de types de touches ou si vous construisez des composants de carte sans charger les composants nécessaires depuis le serveur X, n'allouez aucun composant de carte directement en utilisant malloc ou Xmalloc. Utilisez plutôt les allocateurs Xkb, XkbAllocClientMap, et XkbAllocServerMap.

De même, utilisez les destructeurs Xkb, XkbFreeClientMap, et XkbFreeServerMap au lieu de free ou Xfree.

XkbAllocClientMap alloue et initialise une carte client vide dans le champ map de la description du clavier spécifiée par xkb. Le paramètre which spécifie les composants particuliers de la structure de la carte client à allouer et est un masque composé d'un OU inclusif au niveau du bit de un ou plusieurs des masques indiqués dans le Tableau 1.

Tableau 1 Masques XkbAllocClientMap
Masque Effet
XkbKeyTypesMask Le champ type_count spécifie le nombre d'entrées à préallouer pour le champ types de la carte client. Si le champ type_count est inférieur à XkbNumRequiredTypes, une erreur BadValue est retournée.
XkbKeySymsMask Les champs min_key_code et max_key_code du paramètre xkb sont utilisés pour allouer les champs syms et key_sym_map de la carte client. Les champs sont alloués pour contenir le nombre maximum d'entrées nécessaires pour max_key_code - min_key_code + 1 touches.
XkbModifierMapMask Les champs min_key_code et max_key_code du paramètre xkb sont utilisés pour allouer le champ modmap de la carte client. Le champ est alloué pour contenir le nombre maximum d'entrées nécessaires pour max_key_code - min_key_code + 1 touches.

NOTE : Les champs min_key_code et max_key_code du paramètre xkb doivent être des valeurs valides si les masques XkbKeySymsMask ou XkbModifierMapMask sont définis dans le paramètre which. S'ils ne sont pas valides, XkbAllocClientMap retourne BadValue.

Si la carte client de la description du clavier n'est pas NULL, et que certains champs sont déjà alloués dans la carte client, XkbAllocClientMap ne remplace pas les valeurs existantes ; il ignore simplement cette partie de la requête. La seule exception est le tableau types. Si type_count est supérieur au champ num_types actuel de la carte client, XkbAllocClientMap redimensionne le tableau types et réinitialise le champ num_types en conséquence.

Si XkbAllocClientMap réussit, il retourne Success. Sinon, il peut retourner soit des erreurs BadMatch, BadAlloc, ou BadValue.

DIAGNOSTICS

BadAlloc
Impossible d'allouer le stockage
BadMatch
Une version compatible de Xkb n'était pas disponible sur le serveur ou un argument a un type et une plage corrects, mais est par ailleurs invalide
BadValue
Un argument est hors limites
