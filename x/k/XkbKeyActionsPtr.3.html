XkbKeyActionsPtr(3) FONCTIONS XKB XkbKeyActionsPtr(3)

NOM

XkbKeyActionsPtr - Retourne un pointeur vers le tableau bidimensionnel des actions de touche associées à la touche correspondant au `keycode`

SYNTAXE

XkbKeyActionPtr XkbKeyActionsPtr (XkbDescPtr xkb, KeyCode keycode);

ARGUMENTS

xkb
Description Xkb d'intérêt
keycode
`keycode` d'intérêt

DESCRIPTION

Une action de touche définit l'effet des pressions et relâchements de touche sur l'état interne du serveur. Par exemple, l'action de touche attendue associée à la pression de la touche Maj (Shift) est de définir le modificateur Maj. Il y a zéro ou une action de touche associée à chaque `keysym` lié à chaque touche.

Tout comme la liste complète des symboles de touche pour la disposition du clavier est contenue dans le champ syms de la carte client, la liste complète des actions de touche pour la disposition du clavier est contenue dans le tableau acts de la carte serveur. La taille totale de acts est spécifiée par size_acts, et le nombre d'entrées est spécifié par num_acts.

Le tableau key_acts, indexé par `keycode`, décrit les actions associées à une touche. Le tableau key_acts comporte min_key_code entrées inutilisées au début pour permettre l'indexation directe à l'aide d'un `keycode`. Si une entrée key_acts est nulle, cela signifie que la touche n'a aucune action associée. Si une entrée n'est pas nulle, elle représente un index dans le champ acts de la carte serveur, de la même manière que le champ offset d'une structure `KeySymMapRec` est un index dans le champ syms de la carte client.

La raison pour laquelle le champ acts est une liste linéaire de `XkbActions` est de réduire la consommation mémoire associée à une `keymap`. Étant donné que Xkb permet à des touches individuelles d'avoir plusieurs niveaux de décalage (shift) et un nombre différent de groupes par touche, un seul tableau bidimensionnel de `KeySyms` pourrait potentiellement être très grand et épars. Au lieu de cela, Xkb fournit un petit tableau bidimensionnel de `XkbActions` pour chaque touche. Pour stocker tous ces tableaux individuels, Xkb concatène chaque tableau dans le champ acts de la carte serveur.

Les structures d'action de touche ne sont composées que de champs de type `char` ou `unsigned char`. Ceci est fait pour optimiser le transfert de données lorsque le serveur envoie des octets sur le réseau. Si les champs sont autres que des octets, le serveur doit parcourir toutes les actions et échanger tout champ non-octet. Comme ils ne contiennent que des octets, il peut simplement les copier.

XkbKeyActionsPtr retourne un pointeur vers le tableau bidimensionnel des actions de touche associées à la touche correspondant au keycode. Utilisez XkbKeyActionsPtr uniquement si la touche a réellement des actions associées, c'est-à-dire si XkbKeyNumActions (xkb, keycode) renvoie quelque chose de supérieur à zéro.

STRUCTURES

La structure `KeySymMapRec` est définie comme suit :

    #define XkbNumKbdGroups             4
    #define XkbMaxKbdGroup              (XkbNumKbdGroups-1)
    typedef struct {                    /* map to keysyms for a single keycode */
        unsigned char       kt_index[XkbNumKbdGroups];  /* key type index for each group */
        unsigned char       group_info; /* # of groups and out of range group handling */
        unsigned char       width;      /* max # of shift levels for key */
        unsigned short      offset;     /* index to keysym table in syms array */
} XkbSymMapRec, *XkbSymMapPtr;
