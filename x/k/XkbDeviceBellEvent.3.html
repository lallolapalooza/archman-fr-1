XkbDeviceBellEvent(3) FONCTIONS XKB XkbDeviceBellEvent(3)

NOM

XkbDeviceBellEvent - Crée un événement de sonnerie pour un périphérique d'extension d'entrée X ou pour le clavier, sans déclencher la sonnerie correspondante

SYNTAXE

Bool XkbDeviceBellEvent (Display *display, Window window, unsigned int device_spec, unsigned int bell_class, unsigned int bell_id, int percent, Atom name);

ARGUMENTS

display
connexion au serveur X
window
fenêtre d'événement, ou None
device_spec
identifiant du périphérique, ou XkbUseCoreKbd
bell_class
classe de sonnerie de l'extension d'entrée pour l'événement
bell_id
identifiant de sonnerie de l'extension d'entrée pour l'événement
percent
volume de la sonnerie, qui peut varier de -100 à 100 inclus
name
un nom de sonnerie, ou NULL

DESCRIPTION

Le protocole X de base ne permet qu'aux applications de déclencher explicitement la sonnerie système avec une durée, une hauteur et un volume donnés. Xkb étend cette capacité en permettant aux clients d'associer des noms symboliques aux sonneries, de désactiver les sonneries audibles et de recevoir un événement chaque fois que la sonnerie du clavier est déclenchée. Aux fins de ce document, la sonnerie audible est définie comme étant la sonnerie système, ou la sonnerie par défaut du clavier, par opposition à tout autre son audible généré ailleurs dans le système. Vous pouvez demander à recevoir des événements XkbBellNotify lorsque n'importe quel client déclenche l'une des sonneries suivantes :

  • La sonnerie par défaut
  • Toute sonnerie sur un périphérique d'entrée qui peut être spécifié par une paire bell_class et bell_id
  • Toute sonnerie spécifiée uniquement par un nom arbitraire. (Ceci est, du point de vue du serveur, simplement un nom et n'est pas connecté à un périphérique physique générant du son. Une application client doit générer le son, ou le retour visuel, le cas échéant, associé au nom.)

    Vous pouvez également demander à recevoir des événements XkbBellNotify lorsque le serveur déclenche la sonnerie par défaut ou si n'importe quel client a demandé des événements uniquement (sans déclenchement de sonnerie) pour l'un des types de sonnerie précédemment listés.

    Vous pouvez désactiver les sonneries audibles globalement. Par exemple, un client qui remplace la sonnerie du clavier par une autre indication sonore peut vouloir désactiver le contrôle AudibleBell pour éviter que le serveur ne génère également un son et éviter la cacophonie. Si vous désactivez les sonneries audibles et demandez à recevoir des événements XkbBellNotify, vous pouvez générer un retour différent de la sonnerie par défaut.

    Vous pouvez cependant outrepasser le contrôle AudibleBell en appelant l'une des fonctions qui forcent le déclenchement d'une sonnerie malgré le réglage du contrôle AudibleBell - XkbForceDeviceBell ou XkbForceBell. Dans ce cas, le serveur ne génère pas d'événement de sonnerie.

    De même que certains claviers peuvent produire des "keyclicks" pour indiquer quand une touche est enfoncée ou répétée, Xkb peut fournir un retour pour les contrôles en utilisant des codes de bip spéciaux. Le contrôle AccessXFeedback est utilisé pour configurer les types spécifiques d'opérations qui génèrent un retour.

    Noms de sonneries

    Vous pouvez associer un nom à un acte de déclenchement de sonnerie en convertissant le nom en un Atom, puis en utilisant ce nom lorsque vous appelez les fonctions décrites dans ce chapitre. Si un événement est généré en conséquence, le nom est ensuite transmis à tous les autres clients intéressés par la réception d'événements XkbBellNotify. Notez que ce sont des noms arbitraires et qu'il n'y a pas de liaison avec des sons. Tous les sons ou autres effets (tels que des sonneries visuelles à l'écran) doivent être générés par une application cliente lors de la réception de l'événement de sonnerie contenant le nom. Il n'y a pas de nom par défaut pour la sonnerie par défaut du clavier. Le serveur génère quelques sonneries prédéfinies pour les contrôles AccessX. Ces sonneries nommées sont affichées dans le Tableau 1 ci-dessous ; le nom est inclus dans tout événement de sonnerie envoyé aux clients qui ont demandé à recevoir des événements XkbBellNotify.

    Sonneries audibles

    Avec Xkb, vous pouvez générer des événements de sonnerie qui ne déclenchent pas nécessairement la sonnerie système. Ceci est utile si vous avez besoin d'utiliser un serveur audio au lieu du bip système. Par exemple, lorsqu'un client audio démarre, il pourrait désactiver la sonnerie audible (la sonnerie système), puis écouter les événements XkbBellNotify. Lorsqu'il reçoit un événement XkbBellNotify, le client audio pourrait alors envoyer une requête à un serveur audio pour jouer un son.

    Vous pouvez contrôler la fonctionnalité des sonneries audibles en passant XkbAudibleBellMask à XkbChangeEnabledControls. Si vous activez XkbAudibleBellMask, le serveur déclenche la sonnerie système lorsqu'un événement de sonnerie se produit. C'est le comportement par défaut. Si vous désactivez XkbAudibleBellMask et qu'un événement de sonnerie se produit, le serveur ne déclenche pas la sonnerie système à moins que vous n'appeliez XkbForceDeviceBell ou XkbForceBell.

    Les sonneries audibles font également partie des contrôles d'auto-réinitialisation par client.

    Fonctions de sonnerie

    Utilisez les fonctions décrites dans cette section pour déclencher des sonneries et générer des événements de sonnerie.

    L'extension d'entrée dispose de deux types de retours qui peuvent générer des sonneries : le retour de sonnerie et le retour de clavier. Certaines fonctions de cette section ont des paramètres bell_class et bell_id ; définissez-les comme suit : Définissez bell_class sur BellFeedbackClass ou KbdFeedbackClass. Un périphérique peut avoir plus d'un retour de chaque type ; définissez bell_id sur le retour de sonnerie particulier du type bell_class.

    NAME

    XkbDeviceBellEvent, XkbBellEvent, XkbDeviceForceBell, XkbForceBell - écouter les événements de cloche du clavier X

    SYNOPSIS

    #include <X11/extensions/XkbBell.h>

Bool XkbDeviceBellEvent(
    Display *dpy,
    unsigned int device_spec,
    int percent,
    Atom name
);
Bool XkbBellEvent(
    Display *dpy,
    int percent,
    Atom name
);
Bool XkbDeviceForceBell(
    Display *dpy,
    unsigned int device_spec,
    int percent,
    Atom name
);
Bool XkbForceBell(
    Display *dpy,
    int percent,
    Atom name
);

    ARGUMENTS

    · dpy
    Spécifie la connexion au serveur X.
    · device_spec
    Spécifie le périphérique de clavier dont la cloche doit être déclenchée. Peut être un identifiant de périphérique ou XkbUseCoreKbd pour le périphérique de clavier de base.
    · percent
    Spécifie le volume de la cloche. Une valeur de 0 désactive la cloche, tandis que 100 spécifie le volume maximal. Les valeurs peuvent être comprises entre 0 et 100.
    · name
    Un atome représentant le nom de la cloche souhaitée. Peut être None.

    DESCRIPTION

    Les fonctions XkbDeviceBellEvent et XkbBellEvent déclenchent une cloche sur le système. Ces fonctions sont destinées à être utilisées par les gestionnaires d'événements lorsqu'un événement se produit qui doit générer une cloche.

    Les fonctions XkbDeviceForceBell et XkbForceBell sont similaires, mais elles ne génèrent pas d'événement XkbBellNotify. Elles sont utilisées lorsque le client souhaite déclencher une cloche sans que le serveur ne doive envoyer de notification.

    Si une extension de clavier compatible n'est pas présente dans le serveur X, XkbDeviceBellEvent retourne immédiatement False. Sinon, XkbDeviceBellEvent provoque l'envoi d'un événement XkbBellNotify à tous les clients intéressés et retourne True. Définissez percent pour qu'il représente le volume par rapport au volume de base pour le clavier, comme décrit pour XBell.

    En outre, XkbDeviceBellEvent peut générer des erreurs de protocole Atom ainsi que des événements XkbBellNotify. Vous pouvez appeler XkbBell sans avoir initialisé au préalable l'extension du clavier.

RETURN VALUES

True
La fonction XkbDeviceBellEvent envoie un événement XkbBellNotify à tous les clients intéressés et retourne True.
False
Si une extension de clavier compatible n'est pas présente dans le serveur X, XkbDeviceBellEvent retourne immédiatement False.

STRUCTURES

Xkb génère des événements XkbBellNotify pour toutes les cloches, à l'exception de celles résultant des
appels à XkbForceDeviceBell et XkbForceBell. Pour recevoir des événements XkbBellNotify dans toutes les conditions possibles, passez XkbBellNotifyMask dans les paramètres bits_to_change et values_for_bits à XkbSelectEvents.

L'événement XkbBellNotify n'a pas de détails d'événement. Il est soit sélectionné, soit il ne l'est pas. Cependant, vous pouvez appeler XkbSelectEventDetails en utilisant XkbBellNotify comme event_type et en spécifiant XkbAllBellEventsMask dans bits_to_change et values_for_bits. Cela a le même effet qu'un appel à XkbSelectEvents.

La structure pour le type d'événement XkbBellNotify contient :

   typedef struct _XkbBellNotify {
       int            type;        /* Code d'événement de base de l'extension Xkb */
       unsigned long  serial;      /* Numéro de série du serveur X pour l'événement */
       Bool           send_event;  /* True => généré synthétiquement */
       Display *      display;     /* Connexion au serveur où l'événement a été généré */
       Time           time;        /* Heure du serveur à laquelle l'événement a été généré */
       int            xkb_type;    /* XkbBellNotify */
       unsigned int   device;      /* ID du périphérique Xkb, ne sera pas XkbUseCoreKbd */
       int            percent;     /* Volume demandé en % du maximum */
       int            pitch;       /* Hauteur demandée en Hz */
       int            duration;    /* Durée demandée en microsecondes */
       unsigned int   bell_class;  /* Classe de retour d'information de l'extension d'entrée X */
       unsigned int   bell_id;     /* ID de retour d'information de l'extension d'entrée X */
       Atom           name;        /* "Nom" de la cloche demandée */
       Window         window;      /* Fenêtre associée à l'événement */
       Bool           event_only;  /* False -> le serveur n'a pas produit de sonnerie */
   } XkbBellNotifyEvent;
Si votre application a besoin de générer un retour visuel de cloche à l'écran lorsqu'elle reçoit un événement de cloche, utilisez l'ID de fenêtre dans XkbBellNotifyEvent, s'il est présent.
