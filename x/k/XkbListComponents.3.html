XkbListComponents(3) FONCTIONS XKB XkbListComponents(3)

NOM

XkbListComponents - Liste des composants pour un ou plusieurs types de composants

SYNTAXE

XkbComponentListPtr XkbListComponents (Display *dpy, unsigned int device_spec, XkbComponentNamesPtr ptrns, int *max_inout);

ARGUMENTS

dpy
connexion au serveur X
device_spec
ID de l'appareil, ou XkbUseCoreKbd
ptrns
liste de noms pour les composants d'intérêt
max_inout
nombre max de noms retournés, nombre restant

DESCRIPTION

Vous pouvez demander au serveur une liste de composants pour un ou plusieurs types de composants. La requête prend la forme d'un ensemble de modèles, un modèle pour chacun des types de composants, y compris un modèle pour la description complète du clavier. Pour obtenir cette liste, utilisez XkbListComponents.

XkbListComponents interroge le serveur pour obtenir une liste de noms de composants correspondant aux modèles spécifiés dans ptrns. Il attend une réponse et retourne les noms de composants correspondants dans une structure XkbComponentListRec. Lorsque vous avez fini d'utiliser la structure, vous devez la libérer en utilisant XkbFreeComponentList. device_spec indique un appareil particulier pour lequel l'appelant est intéressé. Un serveur est autorisé (mais pas obligé) à restreindre sa réponse aux parties de la base de données qui sont pertinentes pour cet appareil particulier.

ptrns est un pointeur vers une XkbComponentNamesRec. Chacun des champs de ptrns contient un modèle nommant les composants d'intérêt. Chacun des modèles est composé de caractères de l'encodage ISO Latin1, mais ne peut contenir que des parenthèses, les caractères joker `?' et `*', et les caractères autorisés dans un nom de classe ou de membre de composant. Un modèle peut être NULL, auquel cas aucun composant de ce type n'est retourné. Les correspondances de modèles avec les noms de composants sont sensibles à la casse. Le joker `?' correspond à n'importe quel caractère unique, à l'exception d'une parenthèse gauche ou droite ; le joker `*' correspond à n'importe quel nombre de caractères, à l'exception d'une parenthèse gauche ou droite. Si une implémentation autorise des caractères supplémentaires dans un nom de classe ou de membre autres que ceux requis par l'extension Xkb, le résultat de la comparaison de l'un des caractères supplémentaires avec l'un des caractères joker est dépendant de l'implémentation.

Si un modèle contient des caractères illégaux, les caractères illégaux sont ignorés. Le processus de correspondance est effectué comme si les caractères illégaux avaient été omis du modèle.

max_inout est utilisé pour limiter la quantité de données transmises vers et depuis le serveur. En entrée, il spécifie le nombre maximum de noms à retourner (le nombre total de noms dans toutes les catégories de composants). Au retour de XkbListComponents, max_inout contient le nombre de noms qui correspondaient à la requête mais n'ont pas été retournés en raison de la limite.

Noms de composants

Les noms de composants ont la forme classe(membre) où classe décrit un sous-ensemble des composants disponibles pour un type particulier et le membre optionnel identifie un composant spécifique de ce sous-ensemble. Par exemple, le nom "atlantis(acme)" pour un composant de symboles pourrait spécifier les symboles utilisés pour la disposition de clavier nationale atlantis par le fournisseur "acme". Chaque classe a un membre défaut optionnel ; les références qui spécifient une classe mais pas un membre font référence au membre par défaut de la classe, si elle existe. Xkb ne place aucune contrainte sur l'interprétation des noms de classe et de membre utilisés dans les noms de composants.

Les noms de classe et de membre sont tous deux spécifiés en utilisant des caractères de l'ensemble de caractères Latin-1. Les implémentations Xkb doivent accepter tous les caractères alphanumériques, le tiret (`-') et le trait de soulignement (`_') dans les noms de classe ou de membre, et ne doivent pas accepter les parenthèses, le signe plus, la barre verticale, le signe pour cent, l'astérisque, le point d'interrogation ou les espaces blancs. L'utilisation d'autres caractères est dépendante de l'implémentation.

STRUCTURES

Les modèles de noms de composants utilisés pour décrire la requête sont passés à XkbListComponents en utilisant une structure XkbComponentNamesRec. Cette structure n'a pas de contraintes d'allocation spéciales ni d'interrelations avec d'autres structures ; allouez et libérez cette structure en utilisant les appels standard malloc et free ou leurs équivalents :

    typedef struct _XkbComponentNames {
        char *         keymap;           /* noms de keymap */
        char *         keycodes;         /* noms de keycodes */
        char *         types;            /* noms de types */
        char *         compat;           /* noms de maps de compatibilité */
        char *         symbols;          /* noms de symboles */
        char *         geometry;         /* noms de géométries */
    } XkbComponentNamesRec, *XkbComponentNamesPtr;

XkbListComponents retourne un pointeur vers une XkbComponentListRec :

    typedef struct _XkbComponentList {
        int                      num_keymaps;  /* nombre d'entrées dans keymap */
        int                      num_keycodes; /* nombre d'entrées dans keycodes */
        int                      num_types;    /* nombre d'entrées dans types */
        int                      num_compat;   /* nombre d'entrées dans compat */
        int                      num_symbols;  /* nombre d'entrées dans symbols */
        int                      num_geometry; /* nombre d'entrées dans geometry;
        XkbComponentNamePtr      keymap;       /* noms de keymap */
        XkbComponentNamePtr      keycodes;     /* noms de keycodes */
        XkbComponentNamePtr      types;        /* noms de types */
        XkbComponentNamePtr      compat;       /* noms de maps de compatibilité */
        XkbComponentNamePtr      symbols;      /* noms de symboles */
        XkbComponentNamePtr      geometry;     /* noms de géométries */
    } XkbComponentListRec, *XkbComponentListPtr;
    typedef struct _XkbComponentName {
        unsigned short           flags;        /* indices concernant le nom du composant */
        char *                   name;         /* nom du composant */
    } XkbComponentNameRec, *XkbComponentNamePtr;

VOIR AUSSI

XkbFreeComponentList(3)

NOTES

Notez que la structure utilisée pour spécifier les modèles en entrée est une XkbComponentNamesRec, et celle utilisée pour contenir les noms de composants individuels au retour est une XkbComponentNameRec (pas de `s' à la fin de Name).
