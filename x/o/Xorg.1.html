Xorg(1) Manuel des commandes générales Xorg(1)

NOM

Xorg - serveur X X11R7

SYNTAXE

Xorg [:affichage] [option ...]

DESCRIPTION

Xorg est un serveur X complet conçu à l'origine pour les systèmes d'exploitation UNIX et UNIX-like fonctionnant sur du matériel Intel x86. Il fonctionne désormais sur une plus large gamme de plates-formes matérielles et logicielles.

Ce travail a été dérivé par la X.Org Foundation de la version XFree86 4.4rc2 du projet XFree86. La version XFree86 était originellement dérivée de X386 1.2 de Thomas Roell, qui avait été contribuée à X11R5 par Snitily Graphics Consulting Service.

PLATEFORMES

Xorg fonctionne sous une large gamme de systèmes d'exploitation et de plates-formes matérielles. L'architecture Intel x86 (IA32) est la plate-forme matérielle la plus largement prise en charge. D'autres plates-formes matérielles incluent Compaq Alpha, Intel IA64, AMD64, SPARC et PowerPC. Les systèmes d'exploitation les plus largement pris en charge sont les systèmes UNIX-like libres/OpenSource tels que Linux, FreeBSD, NetBSD, OpenBSD et Solaris. Les systèmes d'exploitation UNIX commerciaux tels que UnixWare sont également pris en charge. D'autres systèmes d'exploitation pris en charge incluent GNU Hurd. Mac OS X est pris en charge avec le serveur X Xquartz(1). Win32/Cygwin est pris en charge avec le serveur X XWin(1).

CONNEXIONS RÉSEAU

Xorg prend en charge les connexions établies à l'aide des flux d'octets fiables suivants :

Local
Sur la plupart des plates-formes, le type de connexion « Local » est une socket de domaine UNIX. Sur certaines plates-formes System V, les types de connexion « local » incluent également des pipes STREAMS, des pipes nommés et d'autres mécanismes. Voir la section « CONNEXIONS LOCALES » de X(7) pour plus de détails.
TCP/IP
Xorg écoute sur le port 6000+n, où n est le numéro d'affichage. Ce type de connexion est généralement désactivé par défaut, mais peut être activé avec l'option -listen (voir la page de manuel de Xserver(1) pour plus de détails).

OPTIONS

Xorg prend en charge plusieurs mécanismes pour fournir/obtenir des paramètres de configuration et d'exécution : options de ligne de commande, variables d'environnement, fichiers de configuration xorg.conf(5), auto-détection et valeurs par défaut de secours. Lorsque les mêmes informations sont fournies de plusieurs manières, le mécanisme ayant la priorité la plus élevée est utilisé. La liste des mécanismes est ordonnée de la priorité la plus élevée à la plus basse. Notez que tous les paramètres ne peuvent pas être fournis par toutes les méthodes. Les options de ligne de commande et variables d'environnement disponibles (et certaines valeurs par défaut) sont décrites ici et dans la page de manuel de Xserver(1). La plupart des paramètres de fichier de configuration, avec leurs valeurs par défaut, sont décrits dans la page de manuel de xorg.conf(5). Les paramètres de configuration spécifiques aux pilotes et aux modules sont décrits dans la page de manuel du pilote ou du module concerné.

En plus des options normales du serveur décrites dans la page de manuel de Xserver(1), Xorg accepte les commutateurs de ligne de commande suivants :

vtXX
XX spécifie le numéro du terminal virtuel que Xorg utilisera. Sans cette option, Xorg choisira le premier terminal virtuel disponible qu'il pourra localiser. Cette option ne s'applique qu'aux plates-formes qui ont un support de terminal virtuel, comme Linux, BSD, OpenSolaris, SVR3 et SVR4.
-allowMouseOpenFail
Permet au serveur de démarrer même si le périphérique de la souris ne peut pas être ouvert ou initialisé. Ceci est équivalent à l'option de fichier xorg.conf(5) AllowMouseOpenFail.
-allowNonLocalXvidtune
Rend l'extension VidMode disponible pour les clients distants. Cela permet au client xvidtune de se connecter depuis un autre hôte. Ceci est équivalent à l'option de fichier xorg.conf(5) AllowNonLocalXvidtune. Par défaut, les connexions non locales ne sont pas autorisées.
-bgamma valeur
Définit la correction gamma bleue. valeur doit être comprise entre 0,1 et 10. La valeur par défaut est 1,0. Tous les pilotes ne prennent pas en charge cela. Voir également les options -gamma, -rgamma et -ggamma.
-bpp n
N'est plus pris en charge. Utilisez -depth pour définir la profondeur de couleur, et utilisez -fbbpp si vous avez vraiment besoin de forcer un format de pixels de la mémoire tampon d'image (matériel) différent de la valeur par défaut.
-config fichier
Lit la configuration du serveur à partir du fichier. Cette option fonctionnera pour n'importe quel fichier lorsque le serveur est exécuté en tant que root (c'est-à-dire, avec un uid réel de 0), ou pour les fichiers relatifs à un répertoire dans le chemin de recherche de configuration pour tous les autres utilisateurs.
-configdir répertoire
Lit les fichiers de configuration du serveur à partir du répertoire. Cette option fonctionnera pour n'importe quel répertoire lorsque le serveur est exécuté en tant que root (c'est-à-dire, avec un uid réel de 0), ou pour les répertoires relatifs à un répertoire dans le chemin de recherche des répertoires de configuration pour tous les autres utilisateurs.
-configure
Lorsque cette option est spécifiée, le serveur Xorg charge tous les modules de pilotes vidéo, sonde le matériel disponible et écrit un fichier xorg.conf(5) initial basé sur ce qui a été détecté. Cette option présente actuellement quelques problèmes sur certaines plates-formes, mais dans la plupart des cas, c'est un bon moyen d'amorcer le processus de configuration. Cette option n'est disponible que lorsque le serveur est exécuté en tant que root (c'est-à-dire, avec un uid réel de 0).
-crt /dev/ttyXX
SCO uniquement. Ceci est identique à l'option vt et est fourni pour la compatibilité avec le serveur X natif de SCO.
-depth n
Définit la profondeur de couleur par défaut. Les valeurs valides sont 1, 4, 8, 15, 16 et 24. Tous les pilotes ne prennent pas en charge toutes les valeurs.
-disableVidMode
Désactive les parties de l'extension VidMode (utilisée par le client xvidtune) qui peuvent être utilisées pour modifier les modes vidéo. Ceci est équivalent à l'option de fichier xorg.conf(5) DisableVidModeExtension.
-fbbpp n
Définit le nombre de bits par pixel de la mémoire tampon d'image. Vous ne devriez définir cela que si vous êtes sûr que c'est nécessaire ; normalement, le serveur peut déduire la valeur correcte de -depth ci-dessus. Utile si vous souhaitez exécuter une configuration de profondeur 24 avec une mémoire tampon d'image de 24 bpp plutôt que 32 bpp (ou vice versa). Les valeurs valides sont 1, 8, 16, 24, 32. Tous les pilotes ne prennent pas en charge toutes les valeurs.
-gamma valeur
Définit la correction gamma. valeur doit être comprise entre 0,1 et 10. La valeur par défaut est 1,0. Cette valeur est appliquée de manière égale aux valeurs R, G et B. Ces valeurs peuvent être définies indépendamment avec les options -rgamma, -bgamma et -ggamma. Tous les pilotes ne prennent pas en charge cela.
-ggamma valeur
Définit la correction gamma verte. valeur doit être comprise entre 0,1 et 10. La valeur par défaut est 1,0. Tous les pilotes ne prennent pas en charge cela. Voir également les options -gamma, -rgamma et -bgamma.
-ignoreABI
Le serveur Xorg vérifie les niveaux de révision ABI de chaque module qu'il charge. Il refusera normalement de charger des modules dont les révisions ABI sont plus récentes que celles du serveur. En effet, de tels modules pourraient utiliser des interfaces que le serveur ne possède pas. Lorsque cette option est spécifiée, les divergences de ce type sont déclassées d'erreurs fatales en avertissements. Cette option doit être utilisée avec prudence.
-isolateDevice id-bus
Restreint les réinitialisations de périphériques au périphérique situé à id-bus. La chaîne id-bus a le format type-bus:bus:périphérique:fonction (par exemple, « PCI:1:0:0 »). -keeptty
Empêche le serveur de se détacher de son terminal de contrôle initial. Si vous souhaitez utiliser l'intégration systemd-logind, vous devez spécifier cette option. Toutes les plateformes ne prennent pas en charge (ou ne peuvent pas utiliser) cette option.
-keyboard nom-clavier
Utilise la section InputDevice du fichier xorg.conf(5) nommée nom-clavier comme clavier principal. Cette option est ignorée lorsque la section Layout spécifie un clavier principal. En l'absence d'une section Layout et de cette option, la première section InputDevice pertinente est utilisée pour le clavier principal.
-layout nom-disposition
Utilise la section Layout du fichier xorg.conf(5) nommée nom-disposition. Par défaut, la première section Layout est utilisée.
-logfile nom-fichier
Utilise le fichier nommé nom-fichier comme fichier journal du serveur Xorg. Le fichier journal par défaut lorsque le serveur fonctionne en tant que root est /var/log/Xorg.n.log et pour les non-root, il s'agit de $XDG_DATA_HOME/xorg/Xorg.n.log où n est le numéro d'affichage du serveur Xorg. Le défaut peut se trouver dans un répertoire différent sur certaines plateformes. Cette option n'est disponible que lorsque le serveur est exécuté en tant que root (c'est-à-dire avec real-uid 0).
-logverbose [n]
Définit le niveau de verbosité pour les informations imprimées dans le fichier journal du serveur Xorg. Si la valeur n n'est pas fournie, chaque occurrence de cette option incrémente le niveau de verbosité du fichier journal. Lorsque la valeur n est fournie, le niveau de verbosité du fichier journal est défini sur cette valeur. Le niveau de verbosité par défaut du fichier journal est 3.
-modulepath chemin-recherche
Définit le chemin de recherche des modules sur chemin-recherche. chemin-recherche est une liste de répertoires séparés par des virgules où rechercher les modules du serveur Xorg. Cette option n'est disponible que lorsque le serveur est exécuté en tant que root (c'est-à-dire avec real-uid 0).
-noautoBindGPU
Désactive la configuration automatique des GPU secondaires en tant que récepteurs de sortie et sources de déchargement. Ceci est équivalent à définir l'option de fichier xorg.conf(__filemansuffix__) AutoBindGPU sur false.
-nosilk
Désactive le support de la souris soyeuse (Silken Mouse).
-novtswitch
Désactive le passage automatique au VT qui était actif lorsque le serveur a démarré, lors de la réinitialisation et de l'arrêt du serveur X, si le système d'exploitation le permet.
-pointer nom-pointeur
Utilise la section InputDevice du fichier xorg.conf(5) nommée nom-pointeur comme pointeur principal. Cette option est ignorée lorsque la section Layout spécifie un pointeur principal. En l'absence d'une section Layout et de cette option, la première section InputDevice pertinente est utilisée pour le pointeur principal.
-quiet
Supprime la plupart des messages d'information au démarrage. Le niveau de verbosité est mis à zéro.
-rgamma valeur
Définit la correction gamma rouge. valeur doit être comprise entre 0.1 et 10. La valeur par défaut est 1.0. Tous les pilotes ne prennent pas en charge cette option. Voir également les options -gamma, -bgamma et -ggamma.
-sharevts
Partage les terminaux virtuels avec un autre serveur X, si le système d'exploitation le permet.
-screen nom-ecran
Utilise la section Screen du fichier xorg.conf(5) nommée nom-ecran. Par défaut, les écrans référencés par la section Layout par défaut sont utilisés, ou la première section Screen s'il n'y a pas de section Layout.
-showconfig
Ceci est identique à l'option -version, et est inclus pour des raisons de compatibilité. Elle pourrait être supprimée dans une future version, donc l'option -version devrait être utilisée à la place.
-showDefaultModulePath
Affiche le chemin des modules par défaut avec lequel le serveur a été compilé.
-showDefaultLibPath
Affiche le chemin où les bibliothèques devraient être installées.
-showopts
Pour chaque module de pilote installé, affiche la liste des options et leurs types d'arguments.
-weight nnn
Définit le poids RGB à 16 bpp. La valeur par défaut est 565. Ceci ne s'applique qu'aux pilotes qui prennent en charge le 16 bpp.
-verbose [n]
Définit le niveau de verbosité pour les informations imprimées sur stderr. Si la valeur n n'est pas fournie, chaque occurrence de cette option incrémente le niveau de verbosité. Lorsque la valeur n est fournie, le niveau de verbosité est défini sur cette valeur. Le niveau de verbosité par défaut est 0.
-version
Affiche la version du serveur, le niveau de correctif (patchlevel), la date de publication, le système d'exploitation/plateforme sur lequel il a été compilé, et s'il inclut le support du chargeur de modules.

CLAVIER

Le serveur Xorg est normalement configuré pour reconnaître diverses combinaisons spéciales de frappes qui instruisent le serveur à effectuer une action, plutôt que de simplement envoyer l'événement de frappe à une application cliente. Ces actions dépendent de la configuration du clavier XKB chargée par un périphérique de clavier particulier et peuvent ou non être disponibles dans une configuration donnée.

Les combinaisons de touches suivantes font couramment partie de la configuration du clavier XKEYBOARD par défaut.

Ctrl+Alt+Backspace
Tue immédiatement le serveur -- sans poser de questions. Il peut être désactivé en définissant l'option de fichier xorg.conf(5) DontZap sur une valeur TRUE.
Il convient de noter que le "zapping" est déclenché par l'action Terminate_Server dans la configuration du clavier. Cette action ne fait pas partie des configurations par défaut mais peut être activée avec l'option XKB "terminate:ctrl_alt_bksp".
Ctrl+Alt+Keypad-Plus
Change le mode vidéo au suivant spécifié dans le fichier de configuration. Ceci peut être désactivé avec l'option de fichier xorg.conf(5) DontZoom.
Ctrl+Alt+Keypad-Minus
Change le mode vidéo au précédent spécifié dans le fichier de configuration. Ceci peut être désactivé avec l'option de fichier xorg.conf(5) DontZoom.
Ctrl+Alt+F1...F12
Pour les systèmes prenant en charge les terminaux virtuels, ces combinaisons de touches sont utilisées pour basculer vers les terminaux virtuels 1 à 12, respectivement. Ceci peut être désactivé avec l'option de fichier xorg.conf(5) DontVTSwitch.

CONFIGURATION

Xorg utilise généralement un fichier de configuration appelé xorg.conf et des fichiers de configuration avec le suffixe .conf dans un répertoire appelé xorg.conf.d pour sa configuration initiale. Reportez-vous à la page de manuel xorg.conf(5) pour des informations sur le format de ce fichier.

Xorg dispose d'un mécanisme pour générer automatiquement une configuration intégrée au moment de l'exécution lorsqu'aucun fichier xorg.conf ou fichiers xorg.conf.d n'est présent. La version actuelle de ce mécanisme de configuration automatique fonctionne de deux manières.

La première consiste en des améliorations qui ont rendu de nombreux composants du fichier xorg.conf optionnels. Cela signifie que les informations qui peuvent être sondées ou raisonnablement déduites n'ont pas besoin d'être spécifiées explicitement, réduisant ainsi considérablement la quantité d'informations de configuration intégrées qui doivent être générées au moment de l'exécution.

La seconde consiste à avoir des solutions de repli "sûres" pour la plupart des informations de configuration. Cela maximise la probabilité que le serveur Xorg démarre dans une configuration utilisable même lorsque les informations sur le matériel spécifique ne sont pas disponibles.

Le support de configuration automatique pour Xorg est en cours de développement. Il vise actuellement les plateformes matérielles et logicielles les plus couramment prises en charge par Xorg. Des améliorations sont prévues pour les futures versions.
