XtDispatchEvent(3)

Paquet: libxt

Licences: MIT, HPND-sell-variant, SMLNJ, MIT-open-group, X11

XtAppNextEvent(3) FONCTIONS XT XtAppNextEvent(3)

NOM

XtAppNextEvent, XtAppPending, XtAppPeekEvent, XtAppProcessEvent, XtDispatchEvent, XtAppMainLoop - interroger et traiter les événements et les entrées

SYNTAXE

#include <X11/Intrinsic.h>

void XtAppNextEvent(XtAppContext app_context, XEvent *event_return);

Boolean XtAppPeekEvent(XtAppContext app_context, XEvent *event_return);

XtInputMask XtAppPending(XtAppContext app_context);

void XtAppProcessEvent(XtAppContext app_context, XtInputMask mask);

Boolean XtDispatchEvent(XEvent *event);

void XtAppMainLoop(XtAppContext app_context);

ARGUMENTS

app_context
Spécifie le contexte de l'application qui identifie l'application.
event
Spécifie un pointeur vers la structure d'événement qui doit être envoyée au gestionnaire d'événements approprié.
event_return
Retourne les informations de l'événement à la structure d'événement spécifiée.
mask
Spécifie quels types d'événements traiter. Le masque est le OU inclusif binaire de n'importe quelle combinaison de XtIMXEvent, XtIMTimer, XtIMAlternateInput, et XtIMSignal. Par commodité, le kit d'outils X définit le nom symbolique XtIMAll pour être le OU inclusif binaire de tous les types d'événements.

DESCRIPTION

Si la file d'attente d'événements X est vide, XtAppNextEvent vide les tampons de sortie X de chaque Display dans le contexte de l'application et attend un événement tout en examinant les autres sources d'entrée, les valeurs de délai d'attente et les gestionnaires de signaux, et en appelant toute procédure de rappel déclenchée par eux. Ce temps d'attente peut être utilisé pour le traitement en arrière-plan (voir Section 7.8).

S'il y a un événement dans la file d'attente, XtAppPeekEvent remplit l'événement et retourne une valeur non nulle. S'il n'y a pas d'entrée X dans la file d'attente, XtAppPeekEvent vide le tampon de sortie et bloque jusqu'à ce qu'une entrée soit disponible (appelant potentiellement certaines procédures de rappel de délai d'attente dans le processus). Si l'entrée est un événement, XtAppPeekEvent remplit l'événement et retourne une valeur non nulle. Sinon, l'entrée concerne une source d'entrée alternative, et XtAppPeekEvent retourne zéro.

La fonction XtAppPending retourne une valeur non nulle s'il y a des événements en attente du serveur X, un temporisateur en attente, ou d'autres sources d'entrée en attente. La valeur retournée est un masque binaire qui est le OU de XtIMXEvent, XtIMTimer, XtIMAlternateInput, et XtIMSignal (voir XtAppProcessEvent). S'il n'y a pas d'événements en attente, XtAppPending vide le tampon de sortie et retourne zéro.

La fonction XtAppProcessEvent traite un temporisateur, une entrée alternative, une source de signal, ou un événement X. S'il n'y a rien du type approprié à traiter, XtAppProcessEvent bloque jusqu'à ce qu'il y en ait. S'il y a plus d'un type de chose disponible à traiter, lequel sera traité est indéfini. Habituellement, cette procédure n'est pas appelée par les applications clientes (voir XtAppMainLoop). XtAppProcessEvent traite les événements de temporisateur en appelant les procédures de rappel de temporisateur appropriées, les entrées alternatives en appelant les procédures de rappel d'entrée alternatives appropriées, les sources de signaux en appelant les procédures de rappel de sources de signaux appropriées, et les événements X en appelant XtDispatchEvent.

Lorsqu'un événement X est reçu, il est passé à XtDispatchEvent, qui appelle les gestionnaires d'événements appropriés et leur passe le widget, l'événement, et les données spécifiques au client enregistrées avec chaque procédure. S'il n'y a pas de gestionnaires pour cet événement enregistrés, l'événement est ignoré et le dispatcheur retourne simplement. L'ordre dans lequel les gestionnaires sont appelés est indéfini.

La fonction XtDispatchEvent envoie ces événements aux fonctions de gestion des événements qui ont été précédemment enregistrées auprès de la routine de dispatch. XtDispatchEvent retourne True s'il a envoyé l'événement à un gestionnaire et False s'il n'a trouvé aucun gestionnaire auquel envoyer l'événement. L'utilisation la plus courante de XtDispatchEvent est d'envoyer les événements acquis avec la procédure XtAppNextEvent. Cependant, elle peut également être utilisée pour envoyer des événements construits par l'utilisateur. XtDispatchEvent est également responsable de la mise en œuvre des sémantiques de saisie pour XtAddGrab.

La fonction XtAppMainLoop traite les événements en utilisant XtAppProcessEvent, en variant le paramètre mask et en utilisant XtAppPending pour s'assurer qu'elle a la possibilité de gérer les événements de tous les types, c'est-à-dire les événements X, les événements de temporisateur, les événements d'entrée et les sources de signaux. Cela constitue la boucle principale des applications X Toolkit, et, à ce titre, elle ne retourne pas à moins que XtAppSetExitFlag ne soit appelée. Les applications sont censées se terminer en réponse à une action de l'utilisateur. Il n'y a rien de spécial dans XtAppMainLoop; c'est simplement une boucle qui traite les événements jusqu'à ce que XtAppGetExitFlag() retourne vrai.

Les applications peuvent fournir leur propre version de cette boucle, qui teste un indicateur de terminaison global ou teste que le nombre de widgets de premier niveau est supérieur à zéro avant de revenir pour le prochain événement.
