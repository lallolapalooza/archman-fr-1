XtInsertEventTypeHandler(3) FONCTIONS XT XtInsertEventTypeHandler(3)

NOM

XtInsertEventTypeHandler, XtRemoveEventTypeHandler, XtRegisterExtensionSelector, XtSetEventDispatcher, XtDispatchEventToWidget - gestion des événements d'extension

SYNTAXE

#include <X11/Intrinsic.h>

void XtInsertEventTypeHandler(Widget widget, int event_type, XtPointer select_data, XtEventHandler proc, XtPointer client_data, XtListPosition position);

void XtRemoveEventTypeHandler(Widget widget, int event_type, XtPointer select_data, XtEventHandler proc, XtPointer client_data);

void XtRegisterExtensionSelector(Display* display, int min_event_type, int max_event_type, XtExtensionSelectProc proc, XtPointer client_data);

XtEventDispatchProc XtSetEventDispatcher(Display* display, int event_type, XtEventDispatchProc proc);

Boolean XtDispatchEventToWidget(Widget widget, XEvent* event);

ARGUMENTS

widget
Spécifie le widget pour ce gestionnaire d'événements. Doit être de classe Core ou de l'une de ses sous-classes.
event_type
Spécifie le type d'événement.
select_data
Spécifie les données utilisées pour sélectionner ou désélectionner les événements du serveur.
proc
Spécifie la procédure.
client_data
Spécifie des données supplémentaires à passer au gestionnaire d'événements.
position
Spécifie quand le gestionnaire d'événements doit être appelé par rapport aux autres gestionnaires précédemment enregistrés.
display
Spécifie l'affichage.
min_event_type, max_event_type
Spécifie la plage des types d'événements pour cette extension.
event
Spécifie un pointeur vers l'événement à distribuer.

DESCRIPTION

La fonction XtInsertEventTypeHandler enregistre une procédure auprès du mécanisme de distribution qui doit être appelée lorsqu'un événement correspondant au event_type spécifié est distribué au widget spécifié.

Si event_type est l'un des événements de protocole X de base, alors select_data doit être un pointeur vers une valeur de type EventMask, indiquant le masque d'événements à utiliser pour sélectionner l'événement désiré. Ce masque d'événements sera inclus dans la valeur retournée par XtBuildEventMask. Si le widget est réalisé, XtInsertEventTypeHandler appelle XSelectInput si nécessaire. Spécifier NULL pour select_data est équivalent à spécifier un pointeur vers un masque d'événements contenant 0. Ceci est similaire à la fonction XtInsertRawEventHandler.

Si event_type spécifie un type d'événement d'extension, alors la sémantique des données pointées par select_data est définie par le sélecteur d'extension enregistré pour le type d'événement spécifié.

Dans les deux cas, les Intrinsèques ne sont pas obligés de copier les données pointées par select_data, de sorte que l'appelant doit s'assurer qu'elles restent valides tant que le gestionnaire d'événements reste enregistré avec cette valeur de select_data.

L'argument position permet au client de contrôler l'ordre d'invocation des gestionnaires d'événements enregistrés pour le même type d'événement. Si le client ne se soucie pas de l'ordre, il devrait normalement spécifier XtListTail, ce qui enregistre ce gestionnaire d'événements après tous les gestionnaires précédemment enregistrés pour ce type d'événement.

La fonction XtRemoveEventTypeHandler désenregistre un gestionnaire d'événements enregistré avec XtInsertEventTypeHandler pour le type d'événement spécifié. La requête est ignorée si client_data ne correspond pas à la valeur donnée lors de l'enregistrement du gestionnaire.

Si event_type spécifie l'un des événements de protocole X de base, select_data doit être un pointeur vers une valeur de type EventMask, indiquant le masque à utiliser pour désélectionner l'événement approprié. Si le widget est réalisé, XtRemoveEventTypeHandler appelle XSelectInput si nécessaire. Spécifier NULL pour select_data est équivalent à spécifier un pointeur vers un masque d'événements contenant 0. Ceci est similaire à la fonction XtRemoveRawEventHandler.

Si event_type spécifie un type d'événement d'extension, alors la sémantique des données pointées par select_data est définie par le sélecteur d'extension enregistré pour le type d'événement spécifié.

La fonction XtRegisterExtensionSelector enregistre une procédure pour organiser la livraison des événements d'extension aux widgets.

Si min_event_type et max_event_type correspondent aux paramètres d'un appel précédent à XtRegisterExtensionSelector pour le même affichage, le proc et le client_data remplacent les valeurs précédemment enregistrées. Si la plage spécifiée par min_event_type et max_event_type chevauche la plage des paramètres d'un appel précédent pour le même affichage d'une autre manière, une erreur se produit.

La fonction XtSetEventDispatcher enregistre la procédure de distribution d'événements spécifiée par proc pour les événements du type event_type. Le dispatcher précédemment enregistré (ou le dispatcher par défaut s'il n'y avait pas de dispatcher précédemment enregistré) est retourné. Si proc est NULL, le dispatcher par défaut est restauré pour le type spécifié.

À l'avenir, lorsque XtDispatchEvent sera appelé avec un événement de type event_type, le proc spécifié (ou le dispatcher par défaut) sera invoqué pour déterminer un widget auquel distribuer l'événement.

La fonction XtDispatchEventToWidget parcourt la liste des gestionnaires d'événements enregistrés pour le widget spécifié et appelle chaque gestionnaire qui a été enregistré pour le type d'événement spécifié, sous réserve de la valeur continue_to_dispatch retournée par chaque gestionnaire. Les Intrinsèques se comportent comme si des gestionnaires d'événements étaient enregistrés en tête de liste pour les événements Expose, NoExpose, GraphicsExpose et VisibilityNotify pour appeler la procédure d'exposition du widget selon les règles de compression d'exposition et pour mettre à jour le champ visible du widget si visible_interest est True. Ces gestionnaires d'événements internes ne définissent jamais continue_to_dispatch sur False.

XtDispatchEventToWidget retourne True si un gestionnaire d'événements a été appelé et False sinon.
