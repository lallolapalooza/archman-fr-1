XtManageChildren(3) FONCTIONS XT XtManageChildren(3)

NOM

XtManageChildren, XtManageChild, XtUnmanageChildren, XtUnmanageChild, XtChangeManagedSet, XtIsManaged - gérer et dégerer des enfants

SYNTAXE

#include <X11/Intrinsic.h>

typedef Widget *WidgetList;

void XtManageChildren(WidgetList enfants, Cardinal nombre_enfants);

void XtManageChild(Widget enfant);

void XtUnmanageChildren(WidgetList enfants, Cardinal nombre_enfants);

void XtUnmanageChild(Widget enfant);

void XtChangeManagedSet(WidgetList enfants_a_desgerer, Cardinal nombre_enfants_a_desgerer, XtDoChangeProc proc_changement, XtPointer donnees_client, WidgetList enfants_a_gerer, Cardinal nombre_enfants_a_gerer);

Boolean XtIsManaged(Widget widget);

ARGUMENTS

enfant
Spécifie l'enfant.
enfants
Spécifie une liste d'enfants.
nombre_enfants
Spécifie le nombre d'enfants.
widget
Spécifie le widget.
enfants_a_gerer
Spécifie la liste des enfants widgets à ajouter à l'ensemble géré.
nombre_enfants_a_gerer
Spécifie le nombre d'entrées dans la liste enfants_a_gerer.
enfants_a_desgerer
Spécifie la liste des enfants widgets à retirer de l'ensemble géré.
nombre_enfants_a_desgerer
Spécifie le nombre d'entrées dans la liste enfants_a_desgerer.
proc_changement
Spécifie la procédure de crochet post-dégestion, pré-gestion à appeler.
donnees_client
Spécifie les données client à passer à la procédure de crochet.

DESCRIPTION

La fonction XtManageChildren effectue les opérations suivantes :

  • Émet une erreur si les enfants n'ont pas tous le même parent ou si le parent n'est pas une sous-classe de compositeWidgetClass.
  • Retourne immédiatement si le parent commun est en cours de destruction ; sinon, pour chaque enfant unique de la liste, XtManageChildren ignore l'enfant s'il est déjà géré ou en cours de destruction et le marque si ce n'est pas le cas.
  • Si le parent est réalisé et après que tous les enfants aient été marqués, il rend visibles certains des enfants nouvellement gérés :
  • Appelle la routine change_managed des enfants du parent.
  • Appelle XtRealizeWidget sur chaque enfant précédemment non géré qui n'est pas réalisé.
  • Mappe chaque enfant précédemment non géré dont map_when_managed est True.

La gestion des enfants est indépendante de l'ordre des enfants et indépendante de la création et de la suppression des enfants. La routine de disposition du parent doit considérer les enfants dont le champ managed est True et ignorer tous les autres enfants. Notez que certains widgets composites, en particulier les boîtes fixes, appellent XtManageChild depuis leur procédure insert_child.

Si le widget parent est réalisé, sa procédure change_managed est appelée pour l'informer que son ensemble d'enfants gérés a changé. Le parent peut repositionner et redimensionner n'importe lequel de ses enfants. Il déplace chaque enfant si nécessaire en appelant XtMoveWidget, qui met d'abord à jour les champs x et y puis appelle XMoveWindow si le widget est réalisé.

La fonction XtManageChild construit une WidgetList de longueur un et appelle XtManageChildren.

La fonction XtUnmanageChildren effectue les opérations suivantes :

  • Émet une erreur si les enfants n'ont pas tous le même parent ou si le parent n'est pas une sous-classe de compositeWidgetClass.
  • Retourne immédiatement si le parent commun est en cours de destruction ; sinon, pour chaque enfant unique de la liste, XtUnmanageChildren effectue les opérations suivantes :
  • Ignore l'enfant s'il est déjà non géré ou en cours de destruction et le marque si ce n'est pas le cas.
  • Si l'enfant est réalisé, il est rendu invisible en le désactivant (unmapping).
•
Appelle la routine change_managed des enfants des widgets après que tous les enfants aient été marqués si le parent est réalisé.

XtUnmanageChildren ne détruit pas les widgets enfants. Retirer des widgets de l'ensemble géré d'un parent est souvent un bannissement temporaire, et, un peu plus tard, vous pouvez gérer à nouveau ces enfants.

La fonction XtUnmanageChild construit une liste de widgets de longueur un et appelle XtUnmanageChildren.

La fonction XtChangeManagedSet effectue les opérations suivantes :

  • Émet une erreur si les widgets spécifiés dans les listes manage_children et unmanage_children n'ont pas tous le même parent, ou si ce parent n'est pas une sous-classe de compositeWidgetClass.
  • Retourne immédiatement si le parent commun est en cours de destruction.
  • Si aucune CompositeClassExtension n'est définie, ou si une CompositeClassExtension est définie mais avec un champ allows_change_managed_set ayant la valeur False, et que XtChangeManagedSet a été invoqué avec une procédure do_change_proc non NULL, alors XtChangeManagedSet effectue les opérations suivantes :
  • Appelle XtUnmanageChildren (unmanage_children, num_unmanage_children).
  • Appelle la procédure do_change_proc spécifiée.
  • Appelle XtManageChildren (manage_children, num_manage_children) puis retourne immédiatement.
•
Sinon, si une CompositeClassExtension est définie avec un champ allows_change_managed_set ayant la valeur True, ou si aucune CompositeClassExtension n'est définie, et que XtChangeManagedSet a été invoqué avec une procédure do_change_proc NULL, alors les opérations suivantes sont effectuées :
  • Pour chaque enfant de la liste unmanage_children ; si l'enfant est déjà non géré ou en cours de destruction, il est ignoré, sinon il est marqué comme étant non géré et s'il est réalisé, il est rendu non visible en étant désactivé (unmapped).
  • Si la procédure do_change_proc n'est pas NULL, elle est invoquée comme spécifié.
  • Pour chaque enfant de la liste manage_children ; si l'enfant est déjà géré ou s'il est en cours de destruction, il est ignoré, sinon il est marqué comme géré
•
Si le parent est réalisé et après que tous les enfants aient été marqués, la méthode change_managed du parent est invoquée et par la suite certains des enfants nouvellement gérés sont rendus visibles par :
  • Appel de XtRealizeWidget sur chacun des enfants précédemment non gérés qui ne sont pas réalisés.
  • Mappage de chaque enfant précédemment non géré dont map_when_managed est True.

La fonction XtIsManaged retourne True si le widget spécifié est de classe RectObj ou de l'une de ses sous-classes et est géré, ou False sinon.

NOM

XtIsManaged - vérifier si un widget est géré

SYNTAXE

#include <X11/Intrinsic.h>

XtBoolean XtIsManaged(Widget widget);

ARGUMENTS

widget
Le widget à vérifier.

DESCRIPTION

La fonction XtIsManaged renvoie True si le widget spécifié est actuellement géré par son parent, et False sinon.

Un widget est considéré comme géré s'il a été explicitement rendu géré par son parent à l'aide de la fonction XtManageChild ou XtManageChildren. Les widgets non gérés ne sont pas affichés et ne participent pas à la mise en page.
