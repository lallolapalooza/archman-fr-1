DESCRIPTION

Cette extension est un ensemble minimal d'extensions client et serveur requis pour tester complètement le serveur X11 sans intervention utilisateur. Cette extension n'est pas destinée à supporter la journalisation et la relecture générales des actions utilisateur.

Les fonctions fournies par cette extension se divisent en deux groupes :

Opérations Client

Ces routines manipulent le comportement côté client, sinon caché. L'implémentation réelle dépendra des détails de la liaison de langage spécifique et du degré de mise en tampon des requêtes, de la mise en cache des GContext, etc., qui est fourni. Dans la liaison C, des routines sont fournies pour accéder aux internes de deux structures de données opaques — les GC et les Visuals — et pour rejeter toute requête en attente dans le tampon de sortie d'une connexion. Les détails exacts peuvent différer pour d'autres liaisons de langage.

Requêtes Serveur

La première de ces requêtes est similaire à celle fournie dans la plupart des extensions : elle permet à un client de spécifier un numéro de version majeure et mineure au serveur, et au serveur de répondre avec ses propres numéros de version majeure et mineure. Les deux requêtes restantes permettent ce qui suit :
•L'accès à une ressource serveur sinon en écriture seule : le curseur associé à une fenêtre donnée
•Peut-être le plus important, la synthèse limitée d'événements de périphérique d'entrée, presque comme si un utilisateur coopératif avait déplacé le périphérique de pointage ou appuyé sur une touche ou un bouton.

Toutes les fonctions et procédures d'extension XTEST, ainsi que tous les constantes et macros manifestes, commenceront par la chaîne XTest. Toutes les opérations sont classées comme serveur/client (Serveur) ou client uniquement (Client).

XTestQueryExtension renvoie True si l'affichage spécifié supporte l'extension XTEST, sinon False. Si l'extension est supportée, *event_base sera défini sur le numéro d'événement pour le premier événement de cette extension et *error_base sera défini sur le numéro d'erreur pour le premier erreur de cette extension. Comme aucune erreur ou événement n'est défini pour cette version de l'extension, les valeurs retournées ici ne sont pas définies (ni utiles). Si l'extension est supportée, *major_version et *minor_version sont définis sur les numéros de version majeure et mineure de l'extension supportée par l'affichage. Sinon, aucun des arguments n'est défini.

Si l'extension est supportée, XTestCompareCursorWithWindow effectue une comparaison du curseur dont l'identifiant est spécifié par cursor (qui peut être None) avec le curseur de la fenêtre spécifiée par window, renvoyant True s'ils sont identiques et False sinon. Si l'extension n'est pas supportée, alors la requête est ignorée et zéro est renvoyé.

Si l'extension est supportée, XTestCompareCurrentCursorWithWindow effectue une comparaison du curseur actuel avec le curseur de la fenêtre spécifiée, renvoyant True s'ils sont identiques et False sinon. Si l'extension n'est pas supportée, alors la requête est ignorée et zéro est renvoyé.

Si l'extension est supportée, XTestFakeKeyEvent demande au serveur de simuler soit une KeyPress (si is_press est True) soit une KeyRelease (si is_press est False) de la touche avec le keycode spécifié ; sinon, la requête est ignorée.

Si l'extension est supportée, l'événement simulé ne sera pas traité avant que delay millisecondes ne se soient écoulées après la réception de la requête (si delay est CurrentTime, cela est interprété comme aucun délai). Aucune autre requête de ce client ne sera traitée tant que ce délai, le cas échéant, n'aura pas expiré et que le traitement ultérieur de l'événement simulé n'aura pas été terminé.

Si l'extension est supportée, XTestFakeButtonEvent demande au serveur de simuler soit une ButtonPress (si is_press est True) soit une ButtonRelease (si is_press est False) du bouton logique numéroté par le bouton spécifié ; sinon, la requête est ignorée.

Si l'extension est supportée, l'événement simulé ne sera pas traité avant que delay millisecondes ne se soient écoulées après la réception de la requête (si delay est CurrentTime, cela est interprété comme aucun délai). Aucune autre requête de ce client ne sera traitée tant que ce délai, le cas échéant, n'aura pas expiré et que le traitement ultérieur de l'événement simulé n'aura pas été terminé.

Si l'extension est supportée, XTestFakeMotionEvent demande au serveur de simuler un mouvement du pointeur à la position spécifiée (x, y) sur la fenêtre racine de screen_number ; sinon, la requête est ignorée. Si screen_number est -1, l'écran courant (sur lequel se trouve le pointeur) est utilisé.

Si l'extension est supportée, l'événement simulé ne sera pas traité avant que delay millisecondes ne se soient écoulées après la réception de la requête (si delay est CurrentTime, cela est interprété comme aucun délai). Aucune autre requête de ce client ne sera traitée tant que ce délai, le cas échéant, n'aura pas expiré et que le traitement ultérieur de l'événement simulé n'aura pas été terminé.

Si l'extension est supportée, XTestFakeRelativeMotionEvent demande au serveur de simuler un mouvement du pointeur par les décalages spécifiés (x, y) par rapport à la position actuelle du pointeur sur screen_number ; sinon, la requête est ignorée. Si screen_number est -1, l'écran courant (sur lequel se trouve le pointeur) est utilisé.

Si l'extension est supportée, l'événement simulé ne sera pas traité avant que delay millisecondes ne se soient écoulées après la réception de la requête (si delay est CurrentTime, cela est interprété comme aucun délai). Aucune autre requête de ce client ne sera traitée tant que ce délai, le cas échéant, n'aura pas expiré et que le traitement ultérieur de l'événement simulé n'aura pas été terminé.

Si impervious est True, alors le client exécutant devient impérial aux captures serveur. Si impervious est False, alors le client exécutant revient à l'état normal d'être susceptible aux captures serveur.

XTestSetGContextOfGC définit le GContext dans le type de données opaque référencé par gc pour être celui spécifié par gid.

XTestSetVisualIDOfVisual définit le VisualID dans le type de données opaque référencé par visual pour être celui spécifié par visualid.

XTestDiscard rejette toutes les requêtes dans le tampon de sortie pour l'affichage spécifié. Il renvoie True si des requêtes ont été rejetées ; sinon, il renvoie False.

VALEURS DE RETOUR

Toutes les routines dont le type de retour est Status retourneront une valeur non nulle en cas de succès et zéro en cas d'échec. Même si l'extension XTEST est prise en charge, le serveur peut retirer arbitrairement ces installations ; auquel cas elles retourneront par la suite zéro.
