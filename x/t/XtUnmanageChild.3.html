XtManageChildren(3) FONCTIONS XT XtManageChildren(3)

NOM

XtManageChildren, XtManageChild, XtUnmanageChildren, XtUnmanageChild, XtChangeManagedSet, XtIsManaged - gérer et dégerer des enfants

SYNTAXE

#include <X11/Intrinsic.h>

typedef Widget *WidgetList;

void XtManageChildren(WidgetList children, Cardinal num_children);

void XtManageChild(Widget child);

void XtUnmanageChildren(WidgetList children, Cardinal num_children);

void XtUnmanageChild(Widget child);

void XtChangeManagedSet(WidgetList unmanage_children, Cardinal num_unmanage_children, XtDoChangeProc do_change_proc, XtPointer client_data, WidgetList manage_children, Cardinal num_manage_children);

Boolean XtIsManaged(Widget widget);

ARGUMENTS

child
Spécifie l'enfant.
children
Spécifie une liste de widgets enfants.
num_children
Spécifie le nombre d'enfants.
widget
Spécifie le widget.
manage_children
Spécifie la liste des widgets enfants à ajouter à l'ensemble géré.
num_manage_children
Spécifie le nombre d'éléments dans la liste manage_children.
unmanage_children
Spécifie la liste des widgets enfants à retirer de l'ensemble géré.
num_unmanage_children
Spécifie le nombre d'éléments dans la liste unmanage_children.
do_change_proc
Spécifie la procédure de crochet post-dégestion, pré-gestion à invoquer.
client_data
Spécifie les données client à passer à la procédure de crochet.

DESCRIPTION

La fonction XtManageChildren effectue les opérations suivantes :

  • Émet une erreur si les enfants n'ont pas tous le même parent ou si le parent n'est pas une sous-classe de compositeWidgetClass.
  • Retourne immédiatement si le parent commun est en cours de destruction ; sinon, pour chaque enfant unique dans la liste, XtManageChildren ignore l'enfant s'il est déjà géré ou en cours de destruction et le marque si ce n'est pas le cas.
  • Si le parent est réalisé et après que tous les enfants aient été marqués, il rend visibles certains des enfants nouvellement gérés :
  • Appelle la routine change_managed des widgets parents.
  • Appelle XtRealizeWidget sur chaque enfant précédemment non géré qui est non réalisé.
  • Mappe chaque enfant précédemment non géré dont map_when_managed est True.

La gestion des enfants est indépendante de l'ordre des enfants et indépendante de la création et de la suppression des enfants. La routine de mise en page du parent doit prendre en compte les enfants dont le champ managed est True et ignorer tous les autres enfants. Notez que certains widgets composites, en particulier les boîtes fixes, appellent XtManageChild depuis leur procédure insert_child.

Si le widget parent est réalisé, sa procédure change_managed est appelée pour l'informer que son ensemble d'enfants gérés a changé. Le parent peut repositionner et redimensionner n'importe lequel de ses enfants. Il déplace chaque enfant au besoin en appelant XtMoveWidget, qui met d'abord à jour les champs x et y, puis appelle XMoveWindow si le widget est réalisé.

La fonction XtManageChild construit une WidgetList de longueur un et appelle XtManageChildren.

La fonction XtUnmanageChildren effectue les opérations suivantes :

  • Émet une erreur si les enfants n'ont pas tous le même parent ou si le parent n'est pas une sous-classe de compositeWidgetClass.
  • Retourne immédiatement si le parent commun est en cours de destruction ; sinon, pour chaque enfant unique dans la liste, XtUnmanageChildren effectue les opérations suivantes :
  • Ignore l'enfant s'il est déjà non géré ou en cours de destruction et le marque si ce n'est pas le cas.
  • Si l'enfant est réalisé, il est rendu non visible en étant démappé.
•
Appelle la routine change_managed des widgets parents après que tous les enfants aient été marqués si le parent est réalisé.

XtUnmanageChildren ne détruit pas les widgets enfants. Retirer les widgets de l'ensemble géré d'un parent est souvent un bannissement temporaire, et, quelque temps plus tard, vous pouvez gérer à nouveau les enfants.

La fonction XtUnmanageChild construit une liste de widgets de longueur un et appelle XtUnmanageChildren.

La fonction XtChangeManagedSet effectue les opérations suivantes :

  • Émet une erreur si les widgets spécifiés dans les listes manage_children et unmanage_children n'ont pas tous le même parent, ou si ce parent n'est pas une sous-classe de compositeWidgetClass.
  • Retourne immédiatement si le parent commun est en cours de destruction.
  • Si aucune CompositeClassExtension n'est définie, ou si une CompositeClassExtension est définie mais avec un champ allows_change_managed_set dont la valeur est False, et que XtChangeManagedSet a été invoqué avec une procédure do_change_proc non NULL, alors XtChangeManagedSet effectue les opérations suivantes :
  • Appelle XtUnmanageChildren (unmanage_children, num_unmanage_children).
  • Appelle la procédure do_change_proc spécifiée.
  • Appelle XtManageChildren (manage_children, num_manage_children) puis retourne immédiatement.
•
Sinon, si une CompositeClassExtension est définie avec un champ allows_change_managed_set dont la valeur est True, ou si aucune CompositeClassExtension n'est définie, et que XtChangeManagedSet a été invoqué avec une procédure do_change_proc NULL, alors les opérations suivantes sont effectuées :
  • Pour chaque enfant de la liste unmanage_children ; si l'enfant est déjà non géré ou en cours de destruction, il est ignoré, sinon il est marqué comme non géré et s'il est réalisé, il est rendu non visible en étant démappé.
  • Si la procédure do_change_proc n'est pas NULL, elle est invoquée comme spécifié.
  • Pour chaque enfant de la liste manage_children ; si l'enfant est déjà géré ou en cours de destruction, il est ignoré, sinon il est marqué comme géré.
•
Si le parent est réalisé et après que tous les enfants aient été marqués, la méthode change_managed du parent est invoquée et ensuite certains des enfants nouvellement gérés sont rendus visibles par :
  • Appel de XtRealizeWidget sur chaque enfant précédemment non géré qui est non réalisé.
  • Mappage de chaque enfant précédemment non géré dont map_when_managed est True.

La fonction XtIsManaged retourne True si le widget spécifié est de classe RectObj ou d'une sous-classe de celle-ci et est géré, ou False sinon.

XtUnmanageChild

NOM

XtUnmanageChild - Ne pas gérer un widget enfant

SYNTAXE

#include <X11/Intrinsic.h>

void XtUnmanageChild(
    Widget widget
);

ARGUMENTS

widget
Spécifie le widget enfant à ne pas gérer.

DESCRIPTION

La fonction XtUnmanageChild ne gère pas un widget enfant spécifié. Cela signifie que le widget ne sera plus soumis à l'arrangement d'un gestionnaire de disposition parent. Par exemple, si le parent est un Composite ou un Constraint widget, cela aura pour effet de supprimer le widget de la liste des enfants gérés par le parent.

Cependant, le widget enfant n'est pas détruit ; il reste un enfant valide du parent. Vous pouvez appeler XtManageChild plus tard pour le gérer à nouveau.

VOIR AUSSI

XtManageChild, XtSetManagedWidgetSet, XtDisownWidget
