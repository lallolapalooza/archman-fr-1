XtManageChildren(3) FONCTIONS XT XtManageChildren(3)

NOM

XtManageChildren, XtManageChild, XtUnmanageChildren, XtUnmanageChild, XtChangeManagedSet, XtIsManaged - gérer et dégérer des enfants

SYNTAXE

#include <X11/Intrinsic.h>

typedef Widget *WidgetList;

void XtManageChildren(WidgetList children, Cardinal num_children);

void XtManageChild(Widget child);

void XtUnmanageChildren(WidgetList children, Cardinal num_children);

void XtUnmanageChild(Widget child);

void XtChangeManagedSet(WidgetList unmanage_children, Cardinal num_unmanage_children, XtDoChangeProc do_change_proc, XtPointer client_data, WidgetList manage_children, Cardinal num_manage_children);

Boolean XtIsManaged(Widget widget);

ARGUMENTS

child
Spécifie l'enfant.
children
Spécifie une liste d'enfants.
num_children
Spécifie le nombre d'enfants.
widget
Spécifie le widget.
manage_children
Spécifie la liste des widgets enfants à ajouter à l'ensemble géré.
num_manage_children
Spécifie le nombre d'entrées dans la liste manage_children.
unmanage_children
Spécifie la liste des widgets enfants à retirer de l'ensemble géré.
num_unmanage_children
Spécifie le nombre d'entrées dans la liste unmanage_children.
do_change_proc
Spécifie la procédure de rappel après dégérer, avant gérer à appeler.
client_data
Spécifie les données client à passer à la procédure de rappel.

DESCRIPTION

La fonction XtManageChildren effectue les actions suivantes :

  • Génère une erreur si les enfants n'ont pas tous le même parent ou si le parent n'est pas une sous-classe de compositeWidgetClass.
  • Retourne immédiatement si le parent commun est en cours de destruction ; sinon, pour chaque enfant unique de la liste, XtManageChildren ignore l'enfant s'il est déjà géré ou en cours de destruction et le marque sinon.
  • Si le parent est réalisé et une fois que tous les enfants ont été marqués, elle rend certains des enfants nouvellement gérés visibles :
  • Appelle la routine de changement de gestion (change_managed) des widgets parents.
  • Appelle XtRealizeWidget sur chaque enfant précédemment non géré qui n'est pas réalisé.
  • Mappe chaque enfant précédemment non géré dont le champ map_when_managed est défini à True.

La gestion des enfants est indépendante de l'ordre des enfants et de la création et suppression des enfants. La routine de mise en page du parent doit prendre en compte les enfants dont le champ managed est défini à True et ignorer tous les autres enfants. Notez que certains widgets composites, en particulier les boîtes fixes, appellent XtManageChild depuis leur procédure insert_child.

Si le widget parent est réalisé, sa procédure change_managed est appelée pour l'informer que son ensemble d'enfants gérés a changé. Le parent peut repositionner et redimensionner n'importe lequel de ses enfants. Il déplace chaque enfant si nécessaire en appelant XtMoveWidget, qui met d'abord à jour les champs x et y, puis appelle XMoveWindow si le widget est réalisé.

La fonction XtManageChild construit une WidgetList de longueur un et appelle XtManageChildren.

La fonction XtUnmanageChildren effectue les actions suivantes :

  • Génère une erreur si les enfants n'ont pas tous le même parent ou si le parent n'est pas une sous-classe de compositeWidgetClass.
  • Retourne immédiatement si le parent commun est en cours de destruction ; sinon, pour chaque enfant unique de la liste, XtUnmanageChildren effectue les actions suivantes :
  • Ignore l'enfant s'il est déjà non géré ou en cours de destruction et le marque sinon.
  • Si l'enfant est réalisé, il est rendu invisible en étant désactivé (unmapped).
•
Appelle la routine de changement de gestion (change_managed) des widgets parents après que tous les enfants aient été marqués si le parent est réalisé.

XtUnmanageChildren ne détruit pas les widgets enfants. Retirer des widgets de l'ensemble géré d'un parent est souvent un bannissement temporaire, et, plus tard, vous pourrez gérer à nouveau les enfants.

La fonction XtUnmanageChild construit une liste de widgets de longueur un et appelle XtUnmanageChildren.

La fonction XtChangeManagedSet effectue les actions suivantes :

  • Génère une erreur si les widgets spécifiés dans les listes manage_children et unmanage_children n'ont pas tous le même parent, ou si ce parent n'est pas une sous-classe de compositeWidgetClass.
  • Retourne immédiatement si le parent commun est en cours de destruction.
  • Si aucune CompositeClassExtension n'est définie, ou si une CompositeClassExtension est définie mais avec un champ allows_change_managed_set ayant la valeur False, et si XtChangeManagedSet a été invoqué avec une procédure do_change_proc non NULL, alors XtChangeManagedSet effectue les actions suivantes :
  • Appelle XtUnmanageChildren (unmanage_children, num_unmanage_children).
  • Appelle la procédure do_change_proc spécifiée.
  • Appelle XtManageChildren (manage_children, num_manage_children) puis retourne immédiatement.
•
Sinon, si une CompositeClassExtension est définie avec un champ allows_change_managed_set ayant la valeur True, ou si aucune CompositeClassExtension n'est définie, et si XtChangeManagedSet a été invoqué avec une procédure do_change_proc NULL, alors les actions suivantes sont effectuées :
  • Pour chaque enfant de la liste unmanage_children ; si l'enfant est déjà non géré ou en cours de destruction, il est ignoré, sinon il est marqué comme étant non géré et s'il est réalisé, il est rendu non visible en étant désactivé (unmapped).
  • Si la procédure do_change_proc n'est pas NULL, elle est appelée comme spécifié.
  • Pour chaque enfant de la liste manage_children ; si l'enfant est déjà géré ou en cours de destruction, il est ignoré, sinon il est marqué comme géré.
•
Si le parent est réalisé et après que tous les enfants aient été marqués, la méthode change_managed du parent est invoquée et ensuite certains des enfants nouvellement gérés sont rendus visibles par :
  • L'appel de XtRealizeWidget sur chacun des enfants précédemment non gérés qui n'est pas réalisé.
  • Le mappage de chaque enfant précédemment non géré dont le champ map_when_managed est défini à True.

La fonction XtIsManaged retourne True si le widget spécifié est de classe RectObj ou de l'une de ses sous-classes et est géré, ou False sinon.

XtManageChildren

NOM

XtManageChildren - gère des enfants de widget

SYNTAXE

#include <X11/Xtlib.h>

Cardinal XtManageChildren(
    WidgetList children,
    Cardinal num_children
);

ARGUMENTS

  • children: Spécifie une liste de widgets enfants à gérer.

  • num_children: Spécifie le nombre de widgets dans la liste children.

DESCRIPTION

La fonction XtManageChildren demande au gestionnaire de géométrie de chaque widget parent de gérer les widgets enfants spécifiés dans la liste children. Cela inclut généralement l'appel de la procédure XtMapWidget pour chaque enfant.

Le gestionnaire de géométrie de chaque widget parent est responsable de déterminer la taille et la position de ses enfants. Si un widget parent n'a pas de gestionnaire de géométrie défini, aucun changement ne sera apporté aux enfants.

La fonction XtManageChildren renvoie le nombre d'enfants qui ont été gérés avec succès. Les enfants qui échouent à être gérés ne sont pas inclus dans le compte.

VOIR AUSSI

XtMapWidget, XtSetValues, XtCreateWidget
