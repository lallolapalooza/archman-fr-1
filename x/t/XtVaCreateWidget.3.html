XtCreateWidget(3) FONCTIONS XT XtCreateWidget(3)

NOM

XtCreateWidget, XtVaCreateWidget, XtCreateManagedWidget, XtVaCreateManagedWidget, XtDestroyWidget - créer et détruire des widgets

SYNTAXE

#include <X11/Intrinsic.h>

Widget XtCreateWidget(const char *nom, WidgetClass classe_widget, Widget parent, ArgList args, Cardinal nb_args);

Widget XtVaCreateWidget(const char *nom, WidgetClass classe_widget, Widget parent, ...);

Widget XtCreateManagedWidget(const char *nom, WidgetClass classe_widget, Widget parent, ArgList args, Cardinal nb_args);

Widget XtVaCreateManagedWidget(const char *nom, WidgetClass classe_widget, Widget parent, ...);

void XtDestroyWidget(Widget w);

ARGUMENTS

args
Spécifie la liste d'arguments pour remplacer les valeurs par défaut des ressources.
nom
Spécifie le nom de la ressource pour le widget créé, utilisé pour récupérer les ressources et, pour cette raison, ne doit pas être le même que tout autre widget enfant du même parent.
nb_args
Spécifie le nombre d'arguments dans la liste d'arguments.
parent
Spécifie le widget parent.
w
Spécifie le widget.
classe_widget
Spécifie le pointeur de classe de widget pour le widget créé.
...
Spécifie la liste d'arguments variables pour remplacer les valeurs par défaut des ressources.

DESCRIPTION

La fonction XtCreateWidget effectue une grande partie des opérations répétitives de création de widget :

  • Vérifie si la procédure class_initialize a été appelée pour cette classe et pour toutes les superclasses et, sinon, appelle celles qui sont nécessaires dans un ordre de superclasse à sous-classe.
  • Alloue de la mémoire pour l'instance du widget.
  • Si le parent est une sous-classe de constraintWidgetClass, il alloue de la mémoire pour les contraintes du parent et stocke l'adresse de cette mémoire dans le champ constraints.
  • Initialise les champs de données non-ressources de base (par exemple, parent et visible).
  • Initialise les champs de ressources (par exemple, background_pixel) en utilisant les listes de ressources spécifiées pour cette classe et toutes les superclasses.
  • Si le parent est une sous-classe de constraintWidgetClass, il initialise les champs de ressources de l'enregistrement de contraintes en utilisant la liste de ressources de contraintes spécifiée pour la classe du parent et toutes les superclasses jusqu'à constraintWidgetClass.
  • Appelle les procédures d'initialisation pour le widget en commençant par la procédure d'initialisation Core jusqu'à la procédure d'initialisation du widget.
  • Si le parent est une sous-classe de compositeWidgetClass, il place le widget dans la liste des enfants de son parent en appelant la procédure insert_child de son parent. Pour plus d'informations, voir la section 3.5.
  • Si le parent est une sous-classe de constraintWidgetClass, il appelle les procédures d'initialisation de contraintes, en commençant par constraintWidgetClass jusqu'à la procédure d'initialisation de contraintes du parent.

Notez que vous pouvez déterminer le nombre d'arguments dans une liste d'arguments en utilisant la macro XtNumber. Pour plus d'informations, voir la section 11.1.

La fonction XtCreateManagedWidget est une routine pratique qui appelle XtCreateWidget et XtManageChild.

La fonction XtDestroyWidget fournit la seule méthode pour détruire un widget, y compris les widgets qui ont besoin de se détruire eux-mêmes. Elle peut être appelée à tout moment, y compris depuis une routine de rappel d'application du widget en cours de destruction. Cela nécessite un processus de destruction en deux phases afin d'éviter les références orphelines aux widgets détruits.

En phase un, XtDestroyWidget effectue les opérations suivantes :

  • Si le champ being_destroyed du widget est True, elle retourne immédiatement.
  • Descend récursivement dans l'arbre des widgets et définit le champ being_destroyed à True pour le widget et tous ses enfants.
  • Ajoute le widget à une liste de widgets (la liste de destruction) qui doivent être détruits lorsqu'il sera sûr de le faire.

Les entrées de la liste de destruction satisfont l'invariant selon lequel si w2 se trouve après w1 sur la liste de destruction, alors w2 n'est pas un descendant de w1. (Un descendant fait référence aux enfants normaux et aux fenêtres pop-up.)

La phase deux se produit lorsque toutes les procédures qui doivent s'exécuter suite à l'événement actuel ont été appelées (y compris toutes les procédures enregistrées auprès des gestionnaires d'événements et de traduction), c'est-à-dire lorsque l'invocation actuelle de XtDispatchEvent est sur le point de retourner ou immédiatement si elle n'est pas dans XtDispatchEvent.

En phase deux, XtDestroyWidget effectue les opérations suivantes sur chaque entrée de la liste de destruction :

  • Appelle les procédures de rappel de destruction enregistrées sur le widget (et tous ses descendants) en post-ordre (elle appelle les rappels des enfants avant les rappels des parents).
  • Si le parent du widget est une sous-classe de compositeWidgetClass et si le parent n'est pas en cours de destruction, elle appelle XtUnmanageChild sur le widget, puis appelle la procédure delete_child du parent du widget (voir la section 3.4).
  • Si le parent du widget est une sous-classe de constraintWidgetClass, elle appelle la procédure de destruction de contrainte pour le parent, puis pour la superclasse du parent, jusqu'à ce qu'elle appelle enfin la procédure de destruction de contrainte pour constraintWidgetClass.
  • Appelle les méthodes de destruction pour le widget (et tous ses descendants) en post-ordre. Pour chaque widget, elle appelle la procédure de destruction déclarée dans la classe du widget, puis la procédure de destruction déclarée dans sa superclasse, jusqu'à ce qu'elle appelle enfin la procédure de destruction déclarée dans l'enregistrement de la classe Core.
  • Appelle XDestroyWindow si le widget est réalisé (c'est-à-dire qu'il a une fenêtre X). Le serveur détruit récursivement toutes les fenêtres descendantes.
  • Descend récursivement dans l'arbre et désalloue tous les widgets pop-up, les enregistrements de contraintes, les listes de rappels et, si le widget est une sous-classe de compositeWidgetClass, les enfants.
