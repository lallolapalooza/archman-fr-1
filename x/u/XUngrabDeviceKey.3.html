Paquet: libxi

XGRABDEVICEKEY(3)   XGRABDEVICEKEY(3)

NOM

XGrabDeviceKey, XUngrabDeviceKey - capture/libérer des touches d'un périphérique d'extension

SYNTAXE

#include <X11/extensions/XInput.h>
int XGrabDeviceKey( Display *display,
                    XDevice *device,
                    unsigned int key,
                    unsigned int modifiers,
                    XDevice *modifier_device,
                    Window grab_window,
                    Bool owner_events,
                    unsigned int event_count,
                    XEventClass *event_list,
                    int this_device_mode,
                    int other_devices_mode);
int XUngrabDeviceKey( Display *display,
                      XDevice *device,
                      unsigned int key,
                      unsigned int modifiers,
                      XDevice *modifier_device,
                      Window grab_window);
display
       Spécifie la connexion au serveur X.
device
       Spécifie le périphérique qui doit être capturé ou libéré.
Key
       Spécifie la touche du périphérique qui doit être capturée ou libérée,
       ou AnyKey.
modifiers
       Spécifie l'ensemble des masques de touches ou AnyModifier. Le masque est
       l'OU bit à bit inclus des bits de masque de touches valides. Les bits valides sont :
       ShiftMask, LockMask, ControlMask, Mod1Mask,
       Mod2Mask, Mod3Mask, Mod4Mask, Mod5Mask.
modifier_device
       Spécifie le périphérique dont les modificateurs doivent être utilisés. Si
       un modifier_device de NULL est spécifié, le clavier X sera utilisé comme
       modifier_device.
grab_window
       Spécifie la fenêtre de capture.
owner_events
       Spécifie une valeur booléenne indiquant si les événements du périphérique
       doivent être rapportés comme d'habitude ou rapportés par rapport à la
       fenêtre de capture s'ils sont sélectionnés par la liste d'événements.
event_count
       Spécifie le nombre de classes d'événements dans la liste d'événements.
event_list
       Spécifie quels événements du périphérique sont rapportés au
       client.
this_device_mode
       Spécifie le traitement supplémentaire des événements de ce
       périphérique. Vous pouvez passer GrabModeSync ou GrabModeAsync.
other_devices_mode
       Spécifie le traitement supplémentaire des événements des autres
       périphériques. Vous pouvez passer GrabModeSync ou GrabModeAsync.

DESCRIPTION

La requête XGrabDeviceKey établit une capture passive. À l'avenir, le périphérique est
activement capturé (comme pour XGrabDevice, l'heure de dernière capture de périphérique
est définie à l'heure à laquelle la touche a été pressée (telle que transmise dans l'événement DeviceKeyPress),
et l'événement DeviceKeyPress est rapporté si toutes les conditions suivantes sont vraies :
  * Le périphérique n'est pas capturé, et la touche spécifiée est
    logiquement pressée lorsque les touches modificateurs spécifiées sont
    logiquement enfoncées, et aucune autre touche ou touche modificateur n'est
    logiquement enfoncée.
  * La grab_window est un ancêtre (ou est) la fenêtre de focus OU
    la grab_window est un descendant de la fenêtre de focus et
    contient le périphérique.
  * La confine_to window (s'il y en a une) est visible.
  * Une capture passive sur la même combinaison touche/modificateur n'existe pas
    sur un ancêtre de la grab_window.
L'interprétation des arguments restants est la même que pour
XGrabDevice. La capture active est terminée automatiquement lorsque
l'état logique du périphérique a la touche spécifiée relâchée.
Notez que l'état logique d'un périphérique (vu par le biais du
protocole X) peut être en retard par rapport à l'état physique si le
traitement des événements du périphérique est gelé.
Si la touche n'est pas AnyKey, elle doit être dans la plage spécifiée par
min_keycode et max_keycode tels que retournés par la
requête XListInputDevices. Sinon, une erreur BadValue en résulte.
Cette requête remplace toutes les captures précédentes par le même client sur
les mêmes combinaisons Touche/modificateur sur la même fenêtre. Un modificateur de AnyModifier équivaut à émettre la requête de capture
pour toutes les combinaisons de modificateurs possibles (y compris la combinaison sans modificateur).
Il n'est pas requis que tous les modificateurs spécifiés aient actuellement des KeyCodes attribués. Une touche de AnyKey équivaut à émettre la requête pour toutes les touches possibles.
Sinon, il n'est pas requis que la touche spécifiée soit actuellement attribuée à une touche physique.
Si un modifier_device de NULL est spécifié, le clavier X sera
utilisé comme modifier_device.
Si un autre client a déjà émis un XGrabDeviceKey avec la même combinaison Touche/modificateur
sur la même fenêtre, une erreur BadAccess en résulte. Lors de l'utilisation de AnyModifier ou AnyKey, la
requête échoue complètement, et une erreur BadAccess en résulte (aucune capture n'est établie) s'il existe une capture conflictuelle pour une combinaison.
XGrabDeviceKey n'a aucun effet sur une capture active.
XGrabDeviceKey peut générer des erreurs BadAccess, BadClass, BadDevice,
BadMatch, BadValue et BadWindow. Elle retourne Success à la fin réussie de la requête.
La requête XUngrabDeviceKey libère la capture passive pour une combinaison touche/modificateur
sur la fenêtre spécifiée si elle a été capturée par ce client. Un modificateur de AnyModifier équivaut à émettre la requête de libération pour toutes les combinaisons de modificateurs possibles,
y compris la combinaison sans modificateur. Une Touche de AnyKey équivaut à émettre la requête pour toutes les Touches possibles.
XUngrabDeviceKey n'a aucun effet sur une capture active.
Si un modifier_device de NULL est spécifié, le clavier X sera
utilisé comme modifier_device.
XUngrabDeviceKey peut générer des erreurs BadDevice, BadMatch, BadValue et
BadWindow.

DIAGNOSTIQUES

BadDevice
       Un périphérique invalide a été spécifié. Le périphérique spécifié
       n'existe pas ou n'a pas été ouvert par ce client via
       XOpenInputDevice. Cette erreur peut également survenir si le
       périphérique spécifié est le clavier ou le pointeur X.
BadMatch
       Cette erreur peut survenir si une requête XGrabDeviceKey a été faite
       spécifiant un périphérique qui n'a pas de touches, ou un périphérique
       modificateur qui n'a pas de touches.
BadValue
       Une valeur numérique tombe en dehors de la plage de valeurs
       acceptées par la requête. Sauf si une plage spécifique est
       spécifiée pour un argument, la plage complète définie par le
       type de l'argument est acceptée. Tout argument défini comme un
       ensemble d'alternatives peut générer cette erreur.
BadWindow
       Une valeur pour un argument Window ne nomme pas une Window définie.

Paquetage Arch Linux

Bienvenue dans le monde du paquetage Arch Linux

Ce document explique le fonctionnement du système de paquetage d'Arch Linux, basé sur makepkg et le dépôt de paquets.

Qu'est-ce qu'un paquet Arch Linux ?

Un paquet Arch Linux est une archive tar compressée (généralement .tar.zst) contenant :

  • Les fichiers binaires ou scripts compilés.
  • Les fichiers de configuration.
  • Les pages de manuel (man pages).
  • Les informations nécessaires à l'installation et à la désinstallation.
  • Les métadonnées du paquet (nom, version, dépendances, etc.).

Le rôle de makepkg

makepkg est l'outil principal pour construire des paquets Arch Linux à partir de leurs sources. Les sources sont généralement définies dans un fichier PKGBUILD.

Le fichier PKGBUILD

Le PKGBUILD est un script shell qui décrit comment construire un paquet. Il contient des variables définissant :

  • Le nom du paquet.
  • La version.
  • Les dépendances de compilation (makedepends).
  • Les dépendances d'exécution (depends).
  • Les checksums des sources.
  • Les URL des sources.
  • Les fonctions pour télécharger, vérifier, compiler et installer les fichiers (prepare(), build(), package()).
makepkg lit ce fichier et exécute les étapes nécessaires pour créer le paquet .pkg.tar.zst.

Gestion des paquets avec pacman

pacman est le gestionnaire de paquets d'Arch Linux. Il est utilisé pour installer, mettre à jour, supprimer et gérer les paquets locaux et distants.

Les dépôts de paquets

Les paquets compilés sont généralement stockés dans des dépôts. Arch Linux maintient des dépôts officiels (core, extra, community, etc.) contenant des milliers de paquets. Vous pouvez également créer vos propres dépôts personnels ou communautaires.

Utilisation de pacman

Voici quelques commandes courantes de pacman :

  • sudo pacman -Syu : Synchronise les bases de données des dépôts et met à jour tous les paquets installés.
  • sudo pacman -S : Installe un paquet.
  • sudo pacman -R : Supprime un paquet.
  • sudo pacman -Ss : Recherche un paquet dans les dépôts.
  • sudo pacman -Qi : Affiche des informations détaillées sur un paquet installé.

Le "User Repository" (AUR)

L'Arch User Repository (AUR) est un dépôt communautaire pour les utilisateurs d'Arch Linux. Il contient des milliers de PKGBUILDs créés et maintenus par la communauté.

Vous ne téléchargez pas directement les paquets de l'AUR, mais plutôt les scripts PKGBUILD. Vous utilisez ensuite makepkg pour construire le paquet vous-même, puis pacman pour l'installer. Des outils comme yay ou paru peuvent automatiser ce processus.

Avantages du système de paquetage Arch

  • Simplicité : Le système est basé sur des scripts simples et des outils standards.
  • Flexibilité : Les utilisateurs ont un contrôle total sur la compilation et l'installation.
  • Transparence : Les PKGBUILDs sont des scripts shell lisibles, permettant de comprendre ce qui est installé.
  • Rapidité : Le système de paquets est rapide et efficace.

Contribuez à l'écosystème Arch en créant ou en améliorant des paquets !
