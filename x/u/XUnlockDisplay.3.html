XInitThreads(3) FONCTIONS XLIB XInitThreads(3)

NOM

XInitThreads, XLockDisplay, XUnlockDisplay - support multi-thread

SYNTAXE

Status XInitThreads(void);

Status XFreeThreads(void);

void XLockDisplay(Display *display);

void XUnlockDisplay(Display *display);

ARGUMENTS

display
Spécifie la connexion au serveur X.

DESCRIPTION

La fonction XInitThreads initialise le support de Xlib pour les threads concurrents. Cette fonction doit être la première fonction Xlib appelée par un programme multi-thread, et elle doit se terminer avant que tout autre appel Xlib ne soit effectué. Cette fonction retourne un statut non nul si l'initialisation a réussi ; sinon, elle retourne zéro. Sur les systèmes qui ne supportent pas les threads, cette fonction retourne toujours zéro.

Il est seulement nécessaire d'appeler cette fonction si plusieurs threads peuvent utiliser Xlib de manière concurrente. Si tous les appels aux fonctions Xlib sont protégés par un autre mécanisme d'accès (par exemple, un verrou d'exclusion mutuelle dans un toolkit ou par programmation explicite du client), l'initialisation des threads Xlib n'est pas requise. Il est recommandé que les programmes mono-thread n'appellent pas cette fonction.

La fonction XFreeThreads libère la mémoire allouée par XInitThreads.

La fonction XLockDisplay bloque tous les autres threads de l'utilisation de l'affichage spécifié. Les autres threads tentant d'utiliser l'affichage seront bloqués jusqu'à ce que l'affichage soit déverrouillé par ce thread. Les appels imbriqués à XLockDisplay fonctionnent correctement ; l'affichage ne sera réellement déverrouillé que lorsque XUnlockDisplay aura été appelé autant de fois que XLockDisplay. Cette fonction n'a aucun effet à moins que Xlib n'ait été initialisé avec succès pour les threads en utilisant XInitThreads.

La fonction XUnlockDisplay permet à nouveau aux autres threads d'utiliser l'affichage spécifié. Tous les threads qui ont été bloqués sur l'affichage sont autorisés à continuer. Le verrouillage imbriqué fonctionne correctement ; si XLockDisplay a été appelé plusieurs fois par un thread, alors XUnlockDisplay doit être appelé un nombre égal de fois avant que l'affichage ne soit effectivement déverrouillé. Cette fonction n'a aucun effet à moins que Xlib n'ait été initialisé avec succès pour les threads en utilisant XInitThreads.
