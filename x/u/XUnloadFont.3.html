XUnloadFont(3)

Paquet: libx11

Licences: MIT AND X11

XLoadFont(3) FONCTIONS XLIB XLoadFont(3)

NOM

XLoadFont, XQueryFont, XLoadQueryFont, XFreeFont, XGetFontProperty, XUnloadFont, XCharStruct, XFontProp, XChar2b, XFontStruct - charger ou décharger des polices et des structures de métriques de police

SYNTAXE

Font XLoadFont(Display *display, _Xconst char *name);

XFontStruct *XQueryFont(Display *display, XID font_ID);

XFontStruct *XLoadQueryFont(Display *display, _Xconst char *name);

int XFreeFont(Display *display, XFontStruct *font_struct);

Bool XGetFontProperty(XFontStruct *font_struct, Atom atom, unsigned long *value_return);

int XUnloadFont(Display *display, Font font);

ARGUMENTS

atom
Spécifie l'atome pour le nom de la propriété que vous souhaitez obtenir.
display
Spécifie la connexion au serveur X.
font
Spécifie la police.
font_ID
Spécifie l'ID de la police ou l'ID du GContext.
font_struct
Spécifie le stockage associé à la police.
gc
Spécifie le GC.
name
Spécifie le nom de la police, qui est une chaîne terminée par un caractère nul.
value_return
Retourne la valeur de la propriété de la police.

DESCRIPTION

La fonction XLoadFont charge la police spécifiée et renvoie son ID de police associé. Si le nom de la police n'est pas dans le codage de caractères portable hôte (Host Portable Character Encoding), le résultat dépend de l'implémentation. L'utilisation des majuscules ou des minuscules n'a pas d'importance. Lorsque les caractères “?” et “” sont utilisés dans un nom de police, une correspondance de modèle est effectuée et toute police correspondante est utilisée. Dans le modèle, le caractère “?” correspond à n'importe quel caractère unique, et le caractère “” correspond à n'importe quel nombre de caractères. Un format structuré pour les noms de polices est spécifié dans les conventions de description des polices logiques X (X Logical Font Description Conventions) de la norme du Consortium X. Si XLoadFont n'a pas réussi à charger la police spécifiée, une erreur BadName se produit. Les polices ne sont pas associées à un écran particulier et peuvent être stockées en tant que composant de n'importe quel GC. Lorsque la police n'est plus nécessaire, appelez XUnloadFont.

XLoadFont peut générer les erreurs BadAlloc et BadName.

La fonction XQueryFont renvoie un pointeur vers la structure XFontStruct, qui contient des informations associées à la police. Vous pouvez interroger une police ou la police stockée dans un GC. L'ID de police stocké dans la structure XFontStruct sera l'ID du GContext, et vous devez être prudent lorsque vous utilisez cet ID dans d'autres fonctions (voir XGContextFromGC). Si la police n'existe pas, XQueryFont renvoie NULL. Pour libérer ces données, utilisez XFreeFontInfo.

XLoadQueryFont peut générer une erreur BadAlloc.

La fonction XLoadQueryFont fournit le moyen le plus courant d'accéder à une police. XLoadQueryFont ouvre (charge) la police spécifiée et renvoie un pointeur vers la structure XFontStruct appropriée. Si le nom de la police n'est pas dans le codage de caractères portable hôte, le résultat dépend de l'implémentation. Si la police n'existe pas, XLoadQueryFont renvoie NULL.

La fonction XFreeFont supprime l'association entre l'ID de ressource de police et la police spécifiée et libère la structure XFontStruct. La police elle-même sera libérée lorsqu'aucune autre ressource ne la référencera. Les données et la police ne doivent plus être référencées.

XFreeFont peut générer une erreur BadFont.

Étant donné l'atome pour cette propriété, la fonction XGetFontProperty renvoie la valeur de la propriété de police spécifiée. XGetFontProperty renvoie également False si la propriété n'était pas définie ou True si elle l'était. Un ensemble d'atomes prédéfinis existe pour les propriétés de police, qui se trouvent dans X11/Xatom.h. Cet ensemble contient les propriétés standard associées à une police. Bien que ce ne soit pas garanti, il est probable que les propriétés de police prédéfinies soient présentes.

La fonction XUnloadFont supprime l'association entre l'ID de ressource de police et la police spécifiée. La police elle-même sera libérée lorsqu'aucune autre ressource ne la référencera. La police ne doit plus être référencée.

XUnloadFont peut générer une erreur BadFont.

STRUCTURES

La structure XFontStruct contient toutes les informations de la police et se compose des informations spécifiques à la police ainsi que d'un pointeur vers un tableau de structures XCharStruct pour les caractères contenus dans la police. Les structures XFontStruct, XFontProp et XCharStruct contiennent :

typedef struct {
	short lbearing;	/* origine vers le bord gauche du raster */
	short rbearing;	/* origine vers le bord droit du raster */
	short width;	/* avance vers l'origine du caractère suivant */
	short ascent;	/* ligne de base vers le bord supérieur du raster */
	short descent;	/* ligne de base vers le bord inférieur du raster */
	unsigned short attributes;	/* indicateurs par caractère (non prédéfinis) */
} XCharStruct;
typedef struct {
	Atom	name;
	unsigned long card32;
} XFontProp;
typedef struct {	/* les caractères normaux de 16 bits sont deux octets */
    unsigned char byte1;
    unsigned char byte2;
} XChar2b;
typedef struct {
	XExtData *ext_data;	/* crochet pour que l'extension accroche des données */
	Font fid;	/* ID de police pour cette police */
	unsigned direction;	/* indice sur la direction dans laquelle la police est peinte */
	unsigned min_char_or_byte2;	/* premier caractère */
	unsigned max_char_or_byte2;	/* dernier caractère */
	unsigned min_byte1;	/* première ligne qui existe */
	unsigned max_byte1;	/* dernière ligne qui existe */
	Bool all_chars_exist;	/* indicateur si tous les caractères ont une taille non nulle */
	unsigned default_char;	/* caractère à imprimer pour un caractère non défini */
	int n_properties;	/* nombre de propriétés */
	XFontProp *properties;	/* pointeur vers le tableau de propriétés supplémentaires */
	XCharStruct min_bounds;	/* limites minimales sur tous les caractères existants */
	XCharStruct max_bounds;	/* limites maximales sur tous les caractères existants */
	XCharStruct *per_char;	/* informations de first_char à last_char */
	int ascent;	/* étendue logique au-dessus de la ligne de base pour l'espacement */
	int descent;	/* étendue logique en dessous de la ligne de base pour l'espacement */
} XFontStruct;

X prend en charge les opérations de texte sur un seul octet/caractère, une matrice de deux octets/caractères et un caractère de 16 bits. Notez que n'importe laquelle de ces formes peut être utilisée avec une police, mais une requête de texte sur un seul octet/caractère ne peut spécifier qu'un seul octet (c'est-à-dire la première ligne d'une police de 2 octets). Vous devriez voir les polices de 2 octets comme une matrice bidimensionnelle de caractères définis : byte1 spécifie la plage de lignes définies et byte2 définit la plage de colonnes définies de la police. Les polices sur un seul octet/caractère ont une seule ligne définie, et la plage byte2 spécifiée dans la structure définit une plage de caractères.

La boîte englobante d'un caractère est définie par le XCharStruct de ce caractère. Lorsque des caractères sont absents d'une police, le default_char est utilisé. Lorsque les polices ont des caractères de même taille, seules les informations dans les limites min et max de XFontStruct sont utilisées.

Les membres de XFontStruct ont les sémantiques suivantes :

  • Le membre direction peut être soit FontLeftToRight, soit FontRightToLeft. Il s'agit juste d'un indice indiquant si la plupart des éléments XCharStruct ont une métrique de largeur de caractère positive (FontLeftToRight) ou négative (FontRightToLeft). Le protocole de base ne définit aucun support pour le texte vertical.
  • Si les membres min_byte1 et max_byte1 sont tous deux nuls, min_char_or_byte2 spécifie l'index de caractère linéaire correspondant au premier élément du tableau per_char, et max_char_or_byte2 spécifie l'index de caractère linéaire du dernier élément.
Si min_byte1 ou max_byte1 sont non nuls, min_char_or_byte2 et max_char_or_byte2 sont tous deux inférieurs à 256, et les valeurs d'index de caractères à 2 octets correspondant à l'élément N du tableau per_char (en comptant à partir de 0) sont :
byte1 = N/D + min_byte1
byte2 = N%D + min_char_or_byte2
où: 
        D = max_char_or_byte2 - min_char_or_byte2 + 1
        / = division entière
        % = modulo

modulus entier
  • Si le pointeur per_char est NULL, toutes les glyphes entre les index des caractères premier et dernier inclus ont les mêmes informations, telles que fournies par min_bounds et max_bounds.
  • Si all_chars_exist est True, tous les caractères du tableau per_char ont des boîtes englobantes non nulles.
  • Le membre default_char spécifie le caractère qui sera utilisé lorsqu'un caractère indéfini ou inexistant est imprimé. Le default_char est un caractère de 16 bits (pas un caractère de 2 octets). Pour une police utilisant le format de matrice de 2 octets, le default_char a byte1 dans l'octet le plus significatif et byte2 dans l'octet le moins significatif. Si le default_char lui-même spécifie un caractère indéfini ou inexistant, aucune impression n'est effectuée pour un caractère indéfini ou inexistant.
  • Les membres min_bounds et max_bounds contiennent les valeurs les plus extrêmes de chaque composant individuel de XCharStruct sur tous les éléments de ce tableau (et ignorent les caractères inexistants). La boîte englobante de la police (le plus petit rectangle englobant la forme obtenue en superposant tous les caractères à la même origine [x,y]) a sa coordonnée supérieure gauche à : 
    [x + min_bounds.lbearing, y - max_bounds.ascent]
Sa largeur est : 
max_bounds.rbearing - min_bounds.lbearing
Sa hauteur est : 
max_bounds.ascent + max_bounds.descent
  • Le membre ascent est l'extension logique de la police au-dessus de la ligne de base utilisée pour déterminer l'espacement des lignes. Les caractères spécifiques peuvent dépasser cette limite.
  • Le membre descent est l'extension logique de la police sur ou sous la ligne de base utilisée pour déterminer l'espacement des lignes. Les caractères spécifiques peuvent dépasser cette limite.
  • Si la ligne de base est à la coordonnée Y y, l'extension logique de la police est incluse entre les coordonnées Y (y - font.ascent) et (y + font.descent - 1). Généralement, l'espacement minimum entre les lignes de texte est donné par ascent + descent.

Pour une origine de caractère à [x,y], la boîte englobante d'un caractère (c'est-à-dire le plus petit rectangle qui englobe la forme du caractère) décrite en termes de composants XCharStruct est un rectangle dont le coin supérieur gauche est à :

[x + lbearing, y - ascent]

Sa largeur est :

rbearing - lbearing

Sa hauteur est :

ascent + descent

L'origine du caractère suivant est définie comme suit :

[x + width, y]

Le membre lbearing définit l'extension du bord gauche de l'encre du caractère par rapport à l'origine. Le membre rbearing définit l'extension du bord droit de l'encre du caractère par rapport à l'origine. Le membre ascent définit l'extension du bord supérieur de l'encre du caractère par rapport à l'origine. Le membre descent définit l'extension du bord inférieur de l'encre du caractère par rapport à l'origine. Le membre width définit la largeur logique du caractère.

DIAGNOSTICS

BadAlloc
Le serveur n'a pas pu allouer la ressource ou la mémoire serveur demandée.
BadFont
Une valeur pour un argument Font ou GContext ne nomme pas une police définie.
BadName
Une police ou une couleur du nom spécifié n'existe pas.
