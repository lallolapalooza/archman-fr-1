NOM

X11::Protocol::Ext::MIT_SHM - images en mémoire partagée de style SysV

SYNTAXE

use X11::Protocol;
my $X = X11::Protocol->new;
$X->init_extension('MIT-SHM')
  or print "Extension MIT-SHM non disponible";
use IPC::SysV;
my $shmid = shmget (IPC::SysV::IPC_PRIVATE(),
                    100000,  # octets
                    IPC::SysV::IPC_CREAT() | 0666);
my $shmseg = $X->new_rsrc;
$X->MitShmAttach ($shmseg, $shmid, 0);
my ($depth, $visual, $size) =  $X->MitShmGetImage
      ($window, 0,0, 16,16, ~0, 'ZPixmap', $shmseg, 0);
my $image_bytes;
shmread ($shmid, $image_bytes, 0, 16*16*$bpp) || die "$!";
# $image_bytes contient les 16x16 pixels du coin supérieur gauche de l'écran

DESCRIPTION

L'extension MIT-SHM permet à un client et à un serveur s'exécutant sur la même machine de transférer des données d'image via des segments de mémoire partagée System-V.

Le client crée un segment de mémoire avec shmget() (voir "shmget" dans perlfunc et "SysV IPC" dans perlipc) et demande au serveur de s'y attacher et ensuite de lire ou d'écrire avec des équivalents aux GetImage et PutImage de base.

L'objectif est d'éviter d'envoyer de grandes images via la connexion d'E/S lorsqu'elles sont sur la même machine. La mémoire est plus rapide et peut aider à éviter les limites de taille des requêtes pour de très grandes images.

L'ordre des octets, le remplissage, etc., requis ou générés dans les images sont spécifiés par le serveur "$X->{'image_byte_order'}", "$X->{'pixmap_formats'}", etc., de la même manière que pour les fonctions de base GetImage() et PutImage(). Il appartient au client de s'adapter à la disposition du serveur, ce qui peut être une tâche ardue.

Shm depuis Perl

Un segment de mémoire partagée peut être créé depuis Perl avec shmget(), puis son contenu peut être lu ou écrit avec shmread() et shmwrite(). Ces fonctions attachent et détachent le segment à chaque fois avec les appels système shmat() et shmdt(), ce qui convient pour récupérer l'ensemble des données, mais sera un peu lent pour de nombreux accès de petite taille.

"IPC::SysV" (version 2 et supérieure) propose une fonction shmat() pour garder le bloc attaché et les fonctions memread() et memwrite() pour y accéder (voir IPC::SysV). Voir IPC::SharedMem pour un wrapper orienté objet autour de cela également.

Soit dit en passant, si shmget() n'est pas disponible sur le système, alors shmget() de Perl plante. Il est également toujours possible qu'il retourne "undef" en cas de manque de mémoire, etc. Avec cela, le fait de ne pas être sur la même machine, de ne pas avoir de permissions identifiables, etc., il existe plusieurs cas où un recours à une simple E/S sera nécessaire.

Permissions Shm

Un segment de mémoire partagée SysV a des bits de permission propriétaire/groupe/autres similaires à ceux d'un fichier. Le serveur ne s'attachera aux segments que si l'UID/GID du client demandeur a les permissions de lire ou d'écrire.

Le serveur peut généralement déterminer l'UID/GID d'un client sur une connexion locale telle qu'un socket Unix (X11::Protocol::Connection::UNIXSocket, et "SO_PEERCRED" dans socket(7)), et peut-être sur une boucle locale TCP. À défaut, le serveur traite le client comme "autre" et ne s'attachera qu'à des segments lisibles par tous (ou lisibles et écrivables par tous).

Vous pouvez rendre un segment shm lisible par tous pour vous assurer que le serveur peut le lire. Si les données pour un PutImage, etc., proviennent déjà d'un fichier lisible par tous ou sont publiques, alors peu importe qui d'autre lit le segment. N'oubliez pas de demander en lecture seule dans MitShmAttach() afin que le serveur ne demande pas également l'accès en écriture.

Il est probablement inutile de risquer d'assouplir les permissions pour l'écriture de segments. Il est fort probable que si l'UID/GID du client ne peut pas être identifié, c'est parce que la connexion n'est pas locale et que le serveur est sur une machine différente, donc la mémoire partagée ne peut pas être utilisée de toute façon.

Il est courant que le serveur s'exécute en tant que root, d'où ses propres vérifications de permissions, mais il est également possible que le serveur soit un utilisateur ordinaire. Dans ce cas, les segments shm auxquels il peut accéder seront limités de la manière habituelle pour l'utilisateur sous lequel il s'exécute.

REQUETES

Les requêtes suivantes sont disponibles après un appel à init_extension() comme décrit dans "EXTENSIONS" dans X11::Protocol.

my $bool = $X->init_extension('MIT-SHM');

Dans les appels suivants, $shmid est l'identifiant de la mémoire partagée (un entier) obtenu du noyau avec shmget(). $shmseg est un XID (alloué comme d'habitude par le client "$X->new_rsrc()") sur le serveur représentant l'attachement du serveur au bloc.

"($server_major, $server_minor, $uid, $gid, $shared_pixmaps, $pixmap_format) = $X->MitShmQueryVersion ()"
Retourne des informations sur l'extension MIT-SHM. Contrairement aux autres extensions, il n'y a pas de négociation entre version client et version serveur.

$server_major et $server_minor sont les numéros de version de l'extension implémentée par le serveur.

$uid et $gid (entiers) sont les identifiants effectifs de l'utilisateur et du groupe du serveur (geteuid() et getegid()). Zéro signifie root.

$shared_pixmaps est différent de zéro si les pixmaps en mémoire partagée sont supportés (voir MitShmCreatePixmap() ci-dessous). $pixmap_format (un ImageFormat) est "XYPixmap" ou "ZPixmap" pour la disposition requise dans un tel pixmap.

"$X->MitShmAttach ($shmseg, $shmid, $readonly)"
Attache le serveur à un segment de mémoire partagée donné. $shmseg est un nouveau XID pour représenter la mémoire attachée. 
my $shmseg = $X->new_rsrc;
$X->MitShmAttach ($shmseg, $shmid, 0); # lecture/écriture

$shmid est l'identifiant de mémoire partagée à attacher, tel qu'obtenu via shmget() (voir "shmget" dans perlfunc).

$readonly est 1 pour que le serveur s'attache en lecture seule, ou 0 pour lecture/écriture. La lecture seule suffit pour MitShmPutImage(), mais la lecture/écriture est nécessaire pour MitShmGetImage() et MitShmCreatePixmap().

"$X->MitShmDetach ($shmseg)"
Détache le serveur de la mémoire partagée $shmseg (un XID) et libère ce XID. 
$X->MitShmDetach ($shmseg);
"$X->MitShmPutImage ($drawable, $gc, $depth, $total_width, $total_height, $src_x, $src_y, $src_width, $src_height, $dst_x, $dst_y, $format, $send_event, $shmseg, $offset)"
Place les données d'image de $shmseg (un XID) sur $drawable. Les paramètres sont similaires à la fonction de base PutImage().

$depth est la profondeur de l'image. Pour le format "Bitmap", il doit être 1 et les couleurs de premier plan et d'arrière-plan de $gc sont alors dessinées. Pour les formats "XYPixmap" et "ZPixmap", $depth doit être la profondeur de $drawable.

$total_width, $total_height est la taille complète de l'image dans la mémoire partagée. $src_x, $src_y et $src_width, $src_height sont la partie à dessiner. $dst_x, $dst_y est l'endroit où le placer dans $drawable.

$format est "Bitmap", "XYPixmap" ou "ZPixmap" (un ImageFormat).

X11::Protocol::Ext::MIT_SHM(3pm) — Arch Linux man pages

NAME

X11::Protocol::Ext::MIT_SHM - MIT Shared Memory Extension (XShm)

SYNOPSIS

  use X11::Protocol::Ext::MIT_SHM;
  my $shm = $X->require_extension("MIT-SHM");
  my ($major_opcode, $event, $error) = $shm->query_version;
  # ...
  my $shminfo = $X->MitShmAllocate ($size);
  my $shmseg = $shminfo->{shmseg};
  $X->MitShmAttach ($shmseg, 0); # attach to client's address space
  my $img = $X->MitShmGetImage ($drawable, $x, $y, $width, $height, $planemask, $format, $shmseg, $offset);
  $X->MitShmPutImage ($drawable, $x, $y, $width, $height, $planemask, $format, $shmseg, $offset);
  $X->MitShmCreatePixmap ($pixmap, $drawable, $depth, $width, $height, $shmseg, $offset);
  $X->MitShmPutImage ($drawable, $x, $y, $width, $height, $planemask, $format, $shmseg, $offset, 1); # completion event
  # ...
  $X->MitShmDetach ($shmseg);
  $X->MitShmFree ($shminfo);

DESCRIPTION

The MIT Shared Memory Extension (XShm) allows efficient transfer of image data between the X server and clients. It can be significantly faster than the core X protocol for operations involving large amounts of image data, such as displaying images or screen grabs.

This module provides access to the XShm extension functions.

The require_extension call returns a proxy object for the extension. You use this object to call the extension's functions.

REQUESTS

"$shm->query_version"
Check if the X server supports the MIT-SHM extension. Returns a list: ($major_opcode, $event, $error). $major_opcode is the extension's major opcode. $event is the event code for completion events. $error is the error code for shared memory segment errors.
"$shminfo = $X->MitShmAllocate ($size)"
Allocate shared memory of $size bytes. Returns a hash ref $shminfo containing information about the shared memory segment. This information includes:
shmseg
The shared memory segment ID (XID).
shmid
The system's shared memory ID.
shmaddr
The address of the shared memory segment in the client's address space.

The client must later call MitShmAttach with the $shmseg to make the segment accessible.

"$X->MitShmAttach ($shmseg, $extend)"
Attach the shared memory segment identified by $shmseg to the client's address space. $extend is a boolean indicating whether to extend the segment (typically 0).
"$X->MitShmDetach ($shmseg)"
Detach the shared memory segment identified by $shmseg from the client's address space.
"$X->MitShmFree ($shminfo)"
Free the shared memory segment described by $shminfo (obtained from MitShmAllocate).
"$X->MitShmPutImage ($drawable, $x, $y, $width, $height, $planemask, $format, $shmseg, $offset, $send_event)"
Copy an image from client memory to the X server.

$drawable is the destination drawable.

$x, $y, $width, $height define the destination region on the drawable.

$planemask is a bit mask for which bit planes of the pixels are to be written.

$format is either "XYPixmap" or "ZPixmap", describing the layout of the image data in shared memory.

$shmseg is the XID of the shared memory segment containing the image data.

$offset is a byte offset into the shared memory where the image data begins.

$send_event is a boolean. If true (1), a MitShmCompletionEvent will be sent to the client when the server has finished writing the image. If false (0) or omitted, no event is sent.

Returns the depth of the drawable, its visual type, and the number of bytes written.

"($depth, $visual, $size) = $X->MitShmGetImage ($drawable, $x, $y, $width, $height, $planemask, $format, $shmseg, $offset)"
Copy an image from $drawable to shared memory $shmseg (an XID). The parameters are similar to the core GetImage().

$x,$y, $width,$height are the part of $drawable to get. $planemask is a bit mask for which bit planes of the pixels are wanted.

$format is "XYPixmap" or "ZPixmap" for the layout to be written to the shared memory, and $offset is a byte offset into the memory where the image should start.

The returned $depth (an integer) is the depth of $drawable. $visual (integer ID) is its visual for a window, or "None" for a pixmap. $size is how many bytes were written.

$shmseg must be attached read-write in the MitShmAttach() or an "Access" error results.

"$X->MitShmCreatePixmap ($pixmap, $drawable, $depth, $width, $height, $shmseg, $offset)"
Create $pixmap (a new XID) as a pixmap with contents in shared memory $shmseg (an XID). When the client reads or writes that memory it changes the pixmap contents. The parameters are similar to the core CreatePixmap(). 
my $pixmap = $X->new_rsrc;
$X->MitShmCreatePixmap ($pixmap,         # new XID
                        $X->root,        # for the screen
                        $X->root_depth,  # depth
                        10,10,           # width,height
                        $shmseg,
                        0);      # byte offset into shm

The MitShmQueryVersion() request above reports whether shared memory pixmaps are supported, and if so whether they're "XYPixmap" or "ZPixmap" layout.

$drawable is used to determine the screen for the new $pixmap. $offset is a byte offset into the shared memory where the pixmap data will begin.

If damage objects from the DAMAGE extension (see X11::Protocol::Ext::DAMAGE) are monitoring a shared $pixmap then client writes to the shared memory generally don't produce "DamageNotify" events. The client can use DamageAdd() requests (in Damage version 1.1) to tell the server about changes made, which it will broadcast to interested damage objects. It's probably unusual to have damage objects listening to a shared pixmap though.

EVENTS

"MitShmCompletionEvent" is sent to the client when requested in an MitShmPutImage(). It says the server has finished reading the memory. The event has the usual fields

name             "MitShmCompletionEvent"
synthetic        true if from a SendEvent
code             integer opcode
sequence_number  integer

and event-specific fields

drawable       XID, target as from request
shmseg         XID, source as from request
offset         integer, byte offset as from request
major_opcode   integer, MIT-SHM extension code
minor_opcode   integer, 3 for MitShmPutImage

"major_opcode" and "minor_opcode" are the codes of the originating MitShmPutImage(). These fields are similar to the core "GraphicsExposure" and "NoExposure" events, but here there's only one request (MitShmPutImage()) which gives a completion event.

ERRORS

Error type "ShmSeg" is a bad $shmseg resource XID in a request.
