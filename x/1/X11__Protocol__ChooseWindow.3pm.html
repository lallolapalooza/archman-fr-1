X11::Protocol::ChooseWindow(3) Documentation Perl fournie par l'utilisateur X11::Protocol::ChooseWindow(3)

NOM

X11::Protocol::ChooseWindow -- l'utilisateur clique pour choisir une fenêtre

SYNOPSIS

use X11::Protocol::ChooseWindow;
my $client_window = X11::Protocol::ChooseWindow->choose (X => $X);

DESCRIPTION

Ce bloc de code permet à l'utilisateur de cliquer sur une fenêtre de plus haut niveau pour la choisir, dans un style similaire aux programmes "xwininfo" ou "xkill".

Implémentation

Le choix est implémenté de manière similaire aux programmes "xwininfo" etc. Il consiste en GrabPointer() sur la fenêtre racine, attente d'un "ButtonPress" et "ButtonRelease" de l'utilisateur, récupération de la fenêtre de cadre depuis l'événement "ButtonPress", puis de la fenêtre client située en dessous grâce à frame_window_to_client() de "X11::Protocol::WM".

Les événements "KeyPress" ne sont pas utilisés et vont à la fenêtre focalisée de la manière habituelle. Ceci peut être utile dans un programme en ligne de commande car cela permet à l'utilisateur d'appuyer sur "^C" ("SIGINT") dans un "xterm" ou similaire. Peut-être qu'à l'avenir, une option permettra de surveiller la touche "Esc" pour annuler ou autre.

Une racine virtuelle, via root_to_virtual_root() dans "X11::Protocol::WM", est utilisée si présente. Cela aide "ChooseWindow" à fonctionner avec "amiwm" et des gestionnaires de fenêtres à racine virtuelle similaires.

FONCTIONS

La fonction choose() suivante est dans le style de méthode de classe, avec l'intention future d'avoir des objets de type "X11::Protocol::ChooseWindow" qui maintiendraient l'état et avanceraient par les événements fournis par une boucle principale externe.

Choix

"$window = X11::Protocol::ChooseWindow->choose (key=>value,...)"
Lit un clic de bouton utilisateur pour choisir une fenêtre de plus haut niveau. Les options clé/valeur sont les suivantes : 
X        => objet X11::Protocol
display  => chaîne de caractères ":0:0" etc
screen   => entier, par exemple 0
root     => XID de la fenêtre racine
time     => horodatage serveur entier
event    => hashref de l'événement initiant le choix
cursor       => XID du curseur
cursor_glyph => glyphe entier pour la police de curseur
cursor_name  => nom de chaîne depuis la police de curseur

"X" ou "display" spécifie le serveur, ou par défaut, ouvre la variable d'environnement "DISPLAY". Utiliser "X" pour un objet "X11::Protocol" est courant, mais il peut parfois être judicieux d'ouvrir une nouvelle connexion juste pour le choix.

"root" ou "screen" spécifie la fenêtre racine sur laquelle choisir, ou par défaut, l'écran actuel de $X, qui à son tour prend par défaut la partie écran du nom d'affichage. S'il existe une racine virtuelle de gestionnaire de fenêtres, celle-ci est automatiquement utilisée si nécessaire.

"time" ou le champ temporel dans "event" est un horodatage serveur pour GrabPointer(). Cela protège contre le vol d'un grab d'un autre client en cas de léger décalage. Si omis ou "undef", cela signifie "CurrentTime". Dans un programme en ligne de commande, il peut ne pas y avoir d'événement initiateur, rendant "CurrentTime" la seule option possible.

"cursor" etc. représente le curseur de la souris à afficher pendant le choix, comme indication visuelle pour l'utilisateur. Par défaut, c'est une "croix". "cursor_name" ou "cursor_glyph" proviennent de la police de curseur habituelle. Voir X11::CursorFont pour les noms disponibles. Par exemple, peut-être le curseur "échange" pour choisir une fenêtre pour une sorte d'échange ou d'inversion,

$window = X11::Protocol::ChooseWindow->choose
            (X => $X,
             cursor_name => "exchange");

Un XID de "cursor" peut être créé par n'importe quel client comme d'habitude. N'oubliez pas d'effectuer un flush si vous créez un curseur à partir d'une connexion, afin qu'il soit prêt à être utilisé par une autre.
