X11::Protocol::Ext::XFIXES(3) Documentation Perl fournie par l'utilisateur X11::Protocol::Ext::XFIXES(3)

NOM

X11::Protocol::Ext::XFIXES - extension « fixes » divers

SYNOPIS

use X11::Protocol;
my $X = X11::Protocol->new;
$X->init_extension('XFIXES')
  or print "Extension XFIXES non disponible";

DESCRIPTION

L'extension XFIXES ajoute certaines fonctionnalités conçues comme des « corrections » aux omissions du protocole X11 de base, y compris :

  • Événements pour les changements de sélection (copier-coller entre clients).
  • Récupération de l'image actuelle du curseur, événements de changement de curseur, et nommage et masquage du curseur.
  • Objets « région » côté serveur représentant un ensemble de rectangles.

REQUÊTES

Les éléments suivants sont rendus disponibles avec un init_extension() par « EXTENSIONS » dans X11::Protocol.

my $bool = $X->init_extension('XFIXES');

XFIXES version 1.0

"($server_major, $server_minor) = $X->XFixesQueryVersion ($client_major, $client_minor)"
Négocier une version de protocole avec le serveur. $client_major et $client_minor représentent ce que le client souhaite, les valeurs retournées $server_major et $server_minor représentent ce que le serveur fera, ce qui peut être inférieur à la demande (mais pas plus).

Le code actuel de ce module supporte jusqu'à la version 4.0 et négocie automatiquement lors de init_extension(), donc l'utilisation directe de XFixesQueryVersion() n'est pas nécessaire. Demander une version supérieure à ce que le code supporte peut être une mauvaise idée.

"($atom, $str) = $X->XFixesChangeSaveSet ($window, $mode, $target, $map)"
Insérer ou supprimer $window (un XID) de l'ensemble d'enregistrement (« save set ») des ressources à conserver sur le serveur lors de la déconnexion du client. Il s'agit d'une version étendue de la requête de base ChangeSaveSet().

$mode est soit « Insert » soit « Delete ».

$target indique comment re-parenter $window lors de la fermeture du client, soit « Nearest » soit « Root ». La requête de base ChangeSaveSet() utilise « Nearest » et signifie aller au parent non-client le plus proche. « Root » signifie aller à la fenêtre racine.

$map est soit « Map » soit « Unmap » à appliquer à $window lors de la fermeture. La requête de base ChangeSaveSet() utilise « Map ».

$X->XFixesSelectSelectionInput ($window, $selection, $event_mask)>
Sélectionner les événements "XFixesSelectionNotify" (voir « EVENTS » ci-dessous) à envoyer à $window lorsque $selection (un atome) change. 
$X->XFixesSelectSelectionInput ($my_window,
                                $X->atom('PRIMARY'),
                                0x07);

$window est donné dans le résultat de "XFixesSelectionNotify". Il est probablement préférable de le définir comme une fenêtre racine. Les sélections sont globales à tout le serveur, donc la fenêtre ne choisit pas implicitement un écran ou autre chose.

$event_mask a trois bits pour indiquer quels sous-types d'événements doivent être rapportés.

                        position du bit  valeur du bit
SetSelectionOwner         0              0x01
SelectionWindowDestroy    1              0x02
SelectionClientClose      2              0x04

Il n'y a pas encore de fonction de paquetage pour cela, donc donnez simplement un entier, par exemple 0x07 pour les trois.

Voir examples/xfixes-selection.pl pour un exemple de programme écoutant les changements de sélection avec cette requête.

$X->XFixesSelectCursorInput ($window, $event_mask)>
Sélectionner les événements "XFixesCursorNotify" (voir « EVENTS » ci-dessous) à envoyer au client.

$window est donné dans le résultat de "XFixesSelectionNotify". Il est probablement préférable de le définir comme une fenêtre racine. L'image du curseur est globale et les événements concernent tout changement, pas seulement ceux à l'intérieur de $window.

$event_mask n'a qu'un seul bit, demandant les changements de curseur affichés,

                 position du bit  valeur du bit
DisplayCursor      0              0x01

Il n'y a pas encore de fonction de paquetage pour cela, donnez simplement l'entier 1 ou 0.

($root_x,$root_y, $width,$height, $xhot,$yhot, $serial, $pixels) = $X->XFixesGetCursorImage ()>
Retourne la taille et le contenu pixel de l'image du curseur de souris actuellement affichée.

$root_x,$root_y retournés sont la position du pointeur dans les coordonnées de la fenêtre racine (similaire à QueryPointer()).

$width,$height est la taille de l'image du curseur. $xhot,$yhot est la position du « point chaud » dans cette image, qui est le pixel qui suit la position du pointeur.

$pixels est une chaîne d'octets de pixels « ARGB » empaquetés. Chaque pixel est de 32 bits dans l'ordre des octets du client, avec $width pixels par ligne et $height lignes, sans rembourrage entre elles, soit un total de "4*$width*$height" octets. Cela peut être décompressé avec par exemple :

my @argb = unpack 'L*', $pixels; # chaque 0xAARRGGBB
# le pixel en haut à gauche est dans $argb[0]
my $alpha = ($argb[0] >> 24) & 0xFF;  # chaque valeur
my $red   = ($argb[0] >> 16) & 0xFF;  # 0 à 255
my $green = ($argb[0] >> 8)  & 0xFF;
my $blue  =  $argb[0]        & 0xFF;

La transparence alpha est pré-multipliée dans les composantes RGB, donc si l'alpha est zéro (transparent), les composantes sont également zéro.

Le masque de bits de base CreateCursor() rend toujours les pixels alpha=0 transparents ou alpha=255 opaques. L'extension RENDER (voir X11::Protocol::Ext::RENDER) peut créer des curseurs partiellement transparents.

Il n'y a pas de moyen direct d'obtenir l'image d'un curseur par son XID (sauf quelque chose de délicat comme un GrabPointer() pour en faire le curseur affiché). Habituellement, les XID de curseur ne sont créés que par un client lui-même, donc il n'est pas nécessaire de les relire (et le XID du curseur ne peut pas être lu à partir d'une fenêtre arbitraire -- bien que l'extension XTEST puisse faire des comparaisons, voir X11::Protocol::Ext::XTEST).

Pour référence, dans le serveur X.org aux alentours de la version 1.11, le serveur peut démarrer sans curseur du tout, et lorsque cela se produit, une tentative de XFixesGetCursorImage() génère une erreur « Cursor ». En pratique, cela ne se produit probablement qu'en utilisant un Xvfb nu ou similaire, car en utilisation normale, xdm ou le gestionnaire de fenêtres auront très certainement défini un curseur.

Voir examples/xfixes-cursor-image.pl pour un exemple de programme obtenant l'image du curseur avec cette requête.

XFIXES version 2.0

Un objet région sur le serveur représente un ensemble de rectangles, chacun avec x, y, largeur, hauteur, avec des coordonnées x, y positives ou négatives, et l'ensemble pouvant être composé de sections déconnectées, etc. (En gros, une copie côté serveur du code de région de Xlib, voir XCreateRegion(3).)

Chaque rectangle peut être simplement de 1x1 pour un pixel unique, donc une région peut représenter n'importe quel bitmap, mais elle est conçue pour le type d'arithmétique rectangulaire qui découle des fenêtres rectangulaires qui se chevauchent, etc.

"$X->XFixesCreateRegion ($region, $rect...)"
Crée $region (un nouveau XID) comme une région et l'initialise à l'union des rectangles donnés, ou à l'ensemble vide si aucun n'est fourni. Chaque $rect est un tableau référencé "[$x,$y,$width,$height]". 
my $region = $X->new_rsrc;
$X->XFixesCreateRegion ($region, [0,0,10,5], [100,100,1,1]);
"$X->XFixesDestroyRegion ($region)"
Libère la région représentée par $region.
"$X->XFixesTranslateRegion ($region, $dx, $dy)"
Déplace la région par $dx pixels en x et $dy pixels en y.
"$X->XFixesUnion ($region, $rect1, $rect2)"
Définit $region comme l'union des deux rectangles fournis. Les rectangles sont des tableaux référencés "[$x,$y,$width,$height]".
"$X->XFixesIntersect ($region, $rect1, $rect2)"
Définit $region comme l'intersection des deux rectangles fournis.
"$X->XFixesSubtract ($region, $rect1, $rect2)"
Définit $region comme la différence entre $rect1 et $rect2 (c'est-à-dire $rect1 moins les parties de $rect2 qui se chevauchent).
"$X->XFixesInverse ($region, $rect1, $rect2)"
Définit $region comme l'inverse de $rect1 relativement à $rect2 (c'est-à-dire, les parties de $rect2 qui ne se chevauchent pas avec $rect1).
"$X->XFixesRegionNotEmpty ($region)"
Retourne vrai si la région n'est pas vide.
"($x, $y, $width, $height) = $X->XFixesRegion (<region_id>)"
Retourne la liste des rectangles qui composent la région. Notez que cela peut être très long pour des régions complexes.

XFIXES version 3.0

"$X->XFixesSetWindowShapeRegion ($window, $shape_kind, $x_offset, $y_offset, $region)"
Définit la forme de la fenêtre. $shape_kind peut être « Bounding » ou « Input ».

XFIXES version 4.0

"$X->XFixesGetWindowShapeRegion ($window, $shape_kind)"
Obtient la région de forme d'une fenêtre.
"$X->XFixesGetWindowAttributtes ($window)"
Obtient les attributs de forme d'une fenêtre.
"$X->XFixesGetWindow (window)"
Obtient les attributs de forme d'une fenêtre, y compris le masque d'entrée et le masque de délimitation, ainsi que leurs décalages et leurs régions associées.

EVENTS

Les événements suivants sont disponibles lorsque l'extension XFIXES est initialisée et que les requêtes appropriées ont été effectuées.

XFixesSelectionNotify

Envoyé lorsqu'une sélection pour laquelle un client a demandé des notifications change. Les champs pertinents sont :

selection
L'atome de la sélection qui a changé.
owner
Le client qui possède maintenant la sélection (0 si aucun).
timestamp
Le moment où le changement s'est produit.
selection_window
La fenêtre associée à cette sélection.

XFixesCursorNotify

Envoyé lorsqu'un changement de curseur est détecté. Les champs pertinents sont :

timestamp
Le moment où le changement s'est produit.
x, y
Les coordonnées du curseur dans la fenêtre racine.
deviceid
L'identifiant du périphérique d'entrée (généralement 0 pour la souris).

VOIR AUSSI

X11::Protocol, X11::Protocol::Ext::XTEST, X11::Protocol::Ext::RENDER.

Ce site n'est en aucun cas associé à Arch Linux ni affilié à ce projet. Le contenu est uniquement une traduction des pages de manuel d'Arch publiées sur man.archlinux.org.

"$X->XFixesCreateRegionFromBitmap ($region, $bitmap)"
Crée une région initialisée à partir des bits à 1 de $bitmap (un XID de pixmap). 
my $region = $X->new_rsrc;
$X->XFixesCreateRegionFromBitmap ($region, $bitmap);
"$X->XFixesCreateRegionFromWindow ($region, $window, $kind)"
Crée une région initialisée à partir de la forme de $window (un XID). $kind est soit "Bounding" soit "Clip", conformément à l'extension SHAPE (voir X11::Protocol::Ext::SHAPE). 
my $region = $X->new_rsrc;
$X->XFixesCreateRegionFromBitmap ($region, $window, 'Clip');

Il n'est pas nécessaire de "$X->init_extension('SHAPE')" avant d'utiliser cette requête. Toute forme est simplement sur le serveur et résulte en une $region soit d'un seul rectangle, soit d'un ensemble de rectangles pour une forme.

"$X->XFixesCreateRegionFromGC ($region, $gc)"
Crée une région initialisée à partir du masque de découpage de $gc (un XID). 
my $region = $X->new_rsrc;
$X->XFixesCreateRegionFromGC ($region, $gc);

La région est relative à l'origine "clip_x_origin" et "clip_y_origin" du GC, c'est-à-dire que ces décalages ne sont pas appliqués aux X,Y dans la région.

"$X->XFixesCreateRegionFromPicture ($region, $picture)"
Crée une région initialisée à partir d'une $picture RENDER (un XID). 
my $region = $X->new_rsrc;
$X->XFixesCreateRegionFromBitmap ($region, $picture);

La région est relative à l'origine "clip_x_origin" et "clip_y_origin" de la picture, c'est-à-dire que ces décalages ne sont pas appliqués aux X,Y dans la région.

Les objets Picture proviennent de l'extension RENDER (voir X11::Protocol::Ext::RENDER). Cette requête existe toujours, mais n'est pas utile sans RENDER.

"$X->XFixesDestroyRegion ($region)"
Détruit $region.
"$X->XFixesSetRegion ($region, $rect...)"
Définit $region comme l'union des rectangles donnés, ou vide si aucun. Chaque $rect est un arrayref "[$x,$y,$width,$height]", comme pour XFixesCreateRegion() ci-dessus. 
$X->XFixesSetRegion ($region, [0,0,20,10], [100,100,5,5])
"$X->XFixesCopyRegion ($dst, $src)"
Copie une région $src vers la région $dst.
"$X->XFixesUnionRegion ($src1, $src2, $dst)"
"$X->XFixesIntersectRegion ($src1, $src2, $dst)"
"$X->XFixesSubtractRegion ($src1, $src2, $dst)"
Définit la région $dst comme respectivement l'union ou l'intersection de $src1 et $src2, ou la soustraction $src1 - $src2.

$dst peut être l'une des régions sources si désiré, pour une modification en place.

"$X->XFixesInvertRegion ($src, $rect, $dst)"
Définit la région $dst comme l'inverse de $src délimitée par le rectangle $rect, c'est-à-dire $rect moins $src. $rect est un arrayref "[$x,$y,$width,$height]". 
$X-XFixesInvertRegion ($src, [10,10, 200,100], $dst)>

$dst peut être identique à $src pour effectuer une inversion "en place".

"$X->XFixesTranslateRegion ($region, $dx, $dy)"
Déplace la zone couverte par $region d'un décalage $dx et $dy (entiers).
"$X->XFixesRegionExtents ($dst, $src)"
Définit la région $dst comme les limites rectangulaires de la région $src. Si $src est vide, alors $dst est définie comme vide.
"($bounding, @parts) = $X->XFixesFetchRegion ($region)"
Retourne les rectangles qui couvrent $region. Chaque élément retourné est un arrayref 
[$x,$y,$width,$height]

Le premier est un rectangle englobant, et après cela, les rectangles individuels formant la région, dans l'ordre "bande YX".

my ($bounding, @rects) = $X->XFixesFetchRegion ($region);
print "bounded by ",join(',',@$bounding);
foreach my $rect (@rects) {
  print "  rect part ",join(',',@$rect);
}
"$X->XFixesSetGCClipRegion ($gc, $clip_x_origin, $clip_y_origin, $region)"
Définit le masque de découpage de $gc (un XID) à $region (un XID), et définit l'origine du découpage à $clip_x_origin,$clip_x_origin.

Ceci est similaire à la fonction de base SetClipRectangles(), mais les rectangles proviennent de $region (et aucun paramètre "ordering").

"$X->XFixesSetWindowShapeRegion ($window, $kind, $x_offset, $y_offset, $region)"
Définit le masque de forme de $window (un XID) à $region, au décalage $x_offset,$y_offset dans la fenêtre. $kind est un ShapeKind, soit "Bounding" soit "Clip".

Ceci est similaire à ShapeMask() (voir X11::Protocol::Ext::SHAPE) avec l'opération "Set" et une région au lieu d'une bitmap.

Il n'est pas nécessaire de "$X->init_extension('SHAPE')" avant d'utiliser cette requête. Si SHAPE n'est pas disponible sur le serveur, cette requête renverra probablement une réponse d'erreur.

"$X->XFixesSetPictureClipRegion ($picture, $clip_x_origin, $clip_y_origin, $region)"
Définit le masque de découpage de la $picture RENDER (un XID) à $region, et définit l'origine du découpage à $clip_x_origin,$clip_x_origin.

Ceci est similaire à RenderSetPictureClipRectangles(), mais les rectangles proviennent de $region.

Les objets Picture proviennent de l'extension RENDER (voir X11::Protocol::Ext::RENDER). La requête existe toujours, mais n'est pas utile sans RENDER.

"$X->XFixesSetCursorName ($cursor, $str)"
Définit un nom pour l'objet curseur $cursor (un XID). Le nom de chaîne $str est intégré comme un atome dans le serveur et doit donc être une chaîne d'octets de caractères latin-1. (Peut-être qu'à l'avenir, cela sera appliqué ici, ou que les caractères larges seront convertis.)
"($atom, $str) = $X->XFixesGetCursorName ($cursor)"
Obtient le nom du curseur de pointeur de souris $cursor (un XID), tel que défini par XFixesSetCursorName().

L'$atom retourné est l'atome de nom (un entier) et $str est la chaîne de nom (qui est le nom de l'atome). S'il n'y a pas de nom pour $cursor, alors $atom est la chaîne "None" (ou 0 si "$X->{'do_interp'}" n'est pas défini) et $str est une chaîne vide "".

"($x,$y, $width,$height, $xhot,$yhot, $serial, $pixels, $atom, $str) = $X->XFixesGetCursorImageAndName ()"
Obtient l'image et le nom du curseur de pointeur de souris actuel. Le retour est par XFixesGetCursorImage() plus XFixesGetCursorName() décrit ci-dessus.
"$X->XFixesChangeCursor ($src, $dst)"
Change le contenu du curseur $dst (un XID) au contenu du curseur $src (un XID).
"$X->XFixesChangeCursorByName ($src, $dst_str)"
Change le contenu de tous les curseurs portant le nom $dst_str (une chaîne) au contenu du curseur $src. S'il n'y a pas de curseurs portant le nom $dst_str, alors ne fait rien.

XFIXES version 3.0

"$X->XFixesExpandRegion ($src, $dst, $left,$right,$top,$bottom)"
Définit la région $dst (un XID) avec les rectangles de la région $src, chaque rectangle étant agrandi de $left, $right, $top, $bottom pixels dans les directions respectives.

Notez qu'il n'est pas important comment $src est exprimé en rectangles, l'effet est comme si chaque pixel individuel de $src était agrandi et que l'union du résultat était prise.

XFIXES version 4.0

"$X->XFixesHideCursor ($window)"
"$X->XFixesShowCursor ($window)"
Masque ou affiche le curseur de pointeur de souris lorsqu'il se trouve dans $window (un XID) ou dans l'une de ses sous-fenêtres.

Ce masquage pour chaque fenêtre est un réglage par client. Si plusieurs clients demandent le masquage, le curseur reste masqué jusqu'à ce que tous aient à nouveau demandé l'affichage. Si un client se déconnecte ou est arrêté, ses demandes de masquage sont automatiquement annulées.

XFIXES version 5.0

"$X->XFixesCreatePointerBarrier ($barrier, $drawable, $x1,$y1, $x2,$y2, $directions)"
"$X->XFixesCreatePointerBarrier ($barrier, $drawable, $x1,$y1, $x2,$y2, $directions, $deviceid...)"
Crée $barrier (un nouveau XID) comme un objet barrière qui empêche le mouvement du pointeur de souris de l'utilisateur à travers une ligne entre les points "$x1,$y1" et "$x2,$y2". Par exemple 
my $barrier = $X->new_rsrc;
$X->XFixesCreatePointerBarrier ($barrier, $X->root,
                                100,100, 100,500,
                                0);

Les coordonnées X,Y sont des coordonnées écran sur l'écran de $drawable. La ligne doit être horizontale ou verticale, donc soit "$x1==$x2" soit "$y1==$y2" (mais pas les deux). Une barrière horizontale se trouve sur le bord supérieur des pixels de la ligne, une barrière verticale se trouve le long du bord gauche des pixels de la ligne.

$directions est un entier OR des bits suivants pour les directions pour lesquelles un mouvement à travers la ligne est autorisé. Une valeur 0 signifie qu'aucun mouvement à travers n'est autorisé.

PositiveX    1
PositiveY    2
NegativeX    4
NegativeY    8

Par exemple, sur une ligne horizontale, la valeur 8 permettrait au pointeur de traverser la ligne dans la direction Y négative (vers le haut de l'écran), et le mouvement dans la direction Y positive (vers le bas de l'écran) serait toujours interdit.

$directions peut permettre à l'utilisateur de sortir d'une sorte de région interdite mais de ne pas y revenir.

Les arguments optionnels $deviceid sont les périphériques X Input Extension 2.0 auxquels la barrière doit s'appliquer (voir X11::Protocol::Ext::XInputExtension). Sans arguments, la barrière ne concerne que le pointeur de souris du protocole principal. Chaque argument peut être

device ID                integer
"AllDevices"             enum string, 0
"AllMasterDevices"       enum string, 1

Il n'est pas nécessaire de "$X->init_extension('XInputExtension')" avant d'utiliser cette requête de barrière.

L'utilisateur peut déplacer le pointeur de la souris pour contourner une ligne de barrière, mais en assemblant des lignes, une région peut être construite maintenant le pointeur à l'intérieur ou à l'extérieur, ou même un labyrinthe pour piéger l'utilisateur !

Les entrées tactiles des écrans tactiles ne sont pas affectées par les barrières, et "$X->WarpPointer()" peut toujours déplacer le pointeur n'importe où.

Une utilisation prévue est lorsqu'un écran Xinerama (voir X11::Protocol::Ext::XINERAMA) est composé de moniteurs de tailles de pixels différentes, de sorte que des parties de l'étendue logique de l'écran se trouvent en dehors du bord d'un des moniteurs plus petits. Les barrières peuvent empêcher l'utilisateur de perdre la souris dans une de ces régions mortes.

Pour référence, certaines versions du serveur X.org antérieures à une date autour de la version 1.14 n'acceptaient pas les arguments $deviceid dans la requête et renvoyaient une erreur "Length" en tentant de les passer. Ces serveurs auraient pu renvoyer une erreur "Implementation" de toute façon (la fonctionnalité de barrière n'étant pas encore implémentée).

"$X->XFixesDestroyPointerBarrier ($barrier)"
Détruit la barrière donnée (un XID).

ÉVÉNEMENTS

Les événements suivants ont les champs habituels

name             "XFixes..."
synthetic        true si provient d'un SendEvent
code             entier opcode
sequence_number  entier
"XFixesSelectionNotify"
Ceci est envoyé au client lorsqu'il est sélectionné par "XFixesSelectSelectionInput" ci-dessus. Il signale les changements de sélection. Les champs spécifiques à l'événement sont 
subtype         enum string
window          XID
owner           XID de la fenêtre propriétaire, ou "None"
selection       atom integer
time            entier, horodatage serveur
selection_time  entier, horodatage serveur

"subtype" est l'un des suivants

SetSelectionOwner
SelectionWindowDestroy
SelectionClientClose

"time" est le moment où l'événement a été généré, "selection_time" est le moment où la sélection a été possédée.

"XFixesCursorNotify"
Ceci est envoyé au client lorsqu'il est sélectionné par XFixesSelectCursorInput() ci-dessus. Il signale lorsque le curseur de la souris actuellement affiché a changé. Il a les champs spécifiques à l'événement suivants, 
subtype         enum string, actuellement toujours "DisplayCursor"
window          XID
cursor_serial   entier
time            entier, horodatage serveur
cursor_name     atom ou "None" (XFIXES 2.0 et supérieur)

"subtype" est "DisplayCursor" lorsque le curseur affiché a changé. C'est le seul sous-type actuellement.

"cursor_serial" est un numéro de série comme dans XFixesGetCursorImage(). Un client peut l'utiliser pour savoir quand le curseur affiché est quelque chose qu'il a déjà récupéré avec XFixesGetCursorImage().

"cursor_name" est l'atome du nom donné au curseur par "XFixesSetCursorName", ou la chaîne "None" s'il n'y a pas de nom. Ce champ est nouveau dans XFIXES 2.0 et est présent dans le dépaquetage de l'événement uniquement si le serveur exécute XFIXES 2.0 ou une version supérieure. Pour "$X->pack_event()", "cursor_name" est facultatif et le champ est défini s'il est fourni.

ERREURS

Le type d'erreur "Region" est un XID de ressource $region incorrect dans une requête (XFIXES 2.0 et supérieur).
