NOM

X11::Protocol::Ext::X_Resource - utilisation des ressources du serveur

SYNTHÈSE

use X11::Protocol;
my $X = X11::Protocol->new;
$X->init_extension('X-Resource')
  or print "extension X-Resource non disponible";
my @clients = $X->XResourceQueryClients();
my %resources = $X->XResourceQueryClientResources ($client_xid);
my $bytes = $X->XResourceQueryClientPixmapBytes ($client_xid);

DESCRIPTION

L'extension X-Resource fournit des informations sur l'utilisation des ressources du serveur, principalement à des fins de diagnostic.

  • Connexions clients actuelles et leurs plages de XID.
  • Nombre de fenêtres, pixmaps, GC, etc. utilisés par un client donné.
  • Mémoire totale utilisée par tous les pixmaps d'un client donné.

"Ressources" ici signifie mémoire, objets, etc., à ne pas confondre avec la base de données des ressources des préférences utilisateur et des configurations de widgets de "RESSOURCES" dans X(7).

Voir examples/xresource-print.pl pour un simple vidage des ressources signalées.

REQUÊTES

Les requêtes suivantes sont rendues disponibles avec un init_extension(), conformément à "EXTENSIONS" dans X11::Protocol.

my $is_available = $X->init_extension('X-Resource');
"($server_major, $server_minor) = $X->XResourceQueryVersion ($client_major, $client_minor)"
Négocie la version de l'extension. $client_major et $client_minor est ce que le client souhaite, le retour $server_major et $server_minor est ce que le serveur fera, ce qui peut être inférieur à la demande (mais pas supérieur).

Le code actuel supporte X-Resource 1.0. L'intention est que ce module négocie automatiquement dans "$X->init_extension()" si/quand nécessaire.

"@clients = $X->XResourceQueryClients ()"
Retourne une liste des connexions clients sur le serveur. Chaque valeur retournée est une paire d'arrayref 
[ $xid_base, $xid_mask ]

$xid_base (un entier) est le début des XID pour le client.

$xid_mask (un entier) est un masque de bits pour les XID ci-dessus que le client peut utiliser. Par exemple $xid_base pourrait être 0xA00000 et $xid_mask 0x1FFFFF, ce qui signifie que 0xA00000 à 0xBFFFFF correspond à ce client.

my @clients = $X->XResourceQueryClients;
print "il y a ",scalar(@clients)," clients\n";
foreach my $aref (@clients) {
  my $xid_base = $aref->[0];
  my $xid_mask = $aref->[1];
  printf "client base %X masque %X\n", $xid_base, $xid_mask;
}

La connexion $X donnée elle-même est incluse dans le retour. Sa base et son masque sont par "$X->{'resource_id_base'}" et "$X->{'resource_id_mask'}".

"($atom,$count,...) = $X->XResourceQueryClientResources ($xid)"
Retourne une liste du nombre de divers types de choses côté serveur utilisés par un client donné.

Le client est identifié par un $xid. Il peut s'agir de n'importe quelle valeur dans la plage XID du client et il n'est pas nécessaire qu'elle soit actuellement allouée ou créée. Par exemple, pour interroger l'utilisation par le client actuel "$X->{'resource_id_base'}".

Le retour est une liste de type de ressource (un entier d'atome) et du nombre de ces choses,

($atom, $count, $atom, $count, ...)

Donc, par exemple, pour afficher toutes les ressources,

my @res = $X->XResourceQueryClientResources ($xid);
while (@res) {
  my $type_atom = shift @res;
  my $count = shift @res;
  my $type_name = $X->atom_name($type_atom);
  printf "type $type_name count $count\n";
}

Ou mettre la liste dans une table de hachage pour rechercher un type de ressource particulier,

my %res = $X->XResourceQueryClientResources ($xid);
my $window_atom = X11::AtomConstants::WINDOW();
my $windows = $res{$window_atom} || 0;
my $grab_atom = $X->atom('PASSIVE GRAB');
my $grabs = $res{$grab_atom} || 'non';
print "utilise $windows fenêtres, et $grabs saisies passives";

"List::Pairwise" a mapp() et d'autres fonctions pour travailler avec ce type de liste deux par deux. Voir examples/xresource-pairwise.pl pour un programme complet.

Généralement, une entrée de compte n'est présente que lorsque le client a 1 ou plusieurs éléments de ce type. Donc, s'il n'y a pas de pixmaps, il n'y a pas d'entrée "PIXMAP" du tout.

Les éléments de base comme "WINDOW", "PIXMAP", "GC" "COLORMAP", "FONT" et "CURSOR" indiquent combien de ces éléments sont utilisés. Le serveur peut également signaler des éléments comme "PASSIVE GRAB" ou "COLORMAP ENTRY" (atomes avec espaces dans leurs noms). Le serveur X.org (vers la version 1.9) signale même parfois des éléments comme "Unregistered resource 30" (un atome avec ce nom), qui est une sorte de chose.

Si le $xid donné n'est pas un client connecté, une erreur "BadValue" en résulte. Soyez prudent lors de l'interrogation des ressources d'un autre client, car le client peut se déconnecter à tout moment. "$X->robust_req()" est une bonne pratique, ou peut-être "GrabServer" pour maintenir les connexions entre XResourceQueryClients() et XResourceQueryClientResources().

"$bytes = $X->XResourceQueryClientPixmapBytes ($xid)"
Retourne le nombre total d'octets de mémoire sur le serveur utilisée par tous les pixmaps d'un client donné. Les pixmaps qui n'existent que comme arrière-plans de fenêtre ou comme tuiles GC ou stipples sont inclus, ou devraient l'être. Si le client n'a aucun pixmap du tout, le retour est de 0.

Le client est identifié par un $xid comme pour XResourceQueryClientResources() ci-dessus. Il peut s'agir de n'importe quelle valeur dans la plage XID du client, allouée ou non.

my $pixmap = $X->new_rsrc;
$X->CreatePixmap ($pixmap,
                  $X->{'root'},
                  $X->{'root_depth'},
                  100, 100);  # largeur, hauteur
my $xid = $X->{'resource_id_base'};  # utilisation propre
my $bytes = $X->XResourceQueryClientPixmapBytes ($xid);
print "total de tous les pixmaps est $bytes octets de mémoire\n";

Le retour est une valeur de 64 bits. Sur un Perl 32 bits, une valeur supérieure à 32 bits est retournée en virgule flottante, ou supérieure à 53 bits en virgule flottante en tant que "Math::BigInt". La plupart du temps, 32 bits suffisent, car cela représenterait 4 Giga-octets de pixmaps, et la virgule flottante 53 bits devrait être suffisante, soit environ 8192 téra-octets !

Pour référence, le serveur X.org vers la version 1.11.4 avait un bug où il ne comptait pas l'espace utilisé par les pixmaps de profondeur inférieure à 8 (y compris les bitmaps de profondeur 1) dans les octets retournés.
