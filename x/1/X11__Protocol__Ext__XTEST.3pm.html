X11::Protocol::Ext::XTEST(3) Documentation Perl fournie par l'utilisateur X11::Protocol::Ext::XTEST(3)

NOM

X11::Protocol::Ext::XTEST - entrées utilisateur synthétiques et plus

SYNOPSIS

use X11::Protocol;
my $X = X11::Protocol->new;
$X->init_extension('XTEST')
  or print "Extension XTEST non disponible";
$X->XTestFakeInput (name   => 'ButtonPress',
                    detail => 3);  # bouton physique 3
$X->XTestFakeInput (name   => 'ButtonRelease',
                    detail => 3);

DESCRIPTION

L'extension XTEST fournit

  • Des actions synthétiques de clavier et de pointeur de souris.
  • Des comparaisons de curseur affiché.
  • Des programmes de test continuant pendant "GrabServer" par d'autres clients.

Ces éléments aident à exercer des fonctionnalités de bibliothèque ou de serveur qui nécessiteraient autrement une interaction utilisateur.

REQUETES

Les requêtes suivantes sont rendues disponibles avec un init_extension(), conformément à "EXTENSIONS" dans X11::Protocol.

my $is_available = $X->init_extension('XTEST');
"($server_major, $server_minor) = $X->XTestGetVersion ($client_major, $client_minor)"
Négocie une version de protocole avec le serveur. $client_major et $client_minor représentent ce que le client souhaite. $server_major et $server_minor retournés sont ce que le serveur fera.

Le code actuel supporte jusqu'à 2.1. L'intention serait de négocier automatiquement dans init_extension() si/quand nécessaire.

Comparaisons de curseurs

"$is_same = $X->XTestCompareCursor ($window, $cursor)"
Retourne vrai si l'attribut du curseur de $window est égal à $cursor. $cursor peut être
  • XID (un entier) d'un curseur.
  • "None" (ou 0).
  • "CurrentCursor" (ou 1) pour le curseur actuellement affiché.

Ceci peut être utilisé pour vérifier si l'attribut du curseur d'une $window correspond à un réglage souhaité, par exemple

$desired_cursor = $X->new_rsrc;
$X->CreateGlyphCursor ($desired_cursor, ...);
$X->XTestCompareCursor ($window, $desired_cursor)
  or die "Oups, $window n'a pas le curseur désiré";

Ou alternativement, construire une fenêtre avec un curseur particulier et utiliser "CurrentCursor" pour vérifier que ce qui est actuellement affiché correspond aux attentes, par exemple pour voir si un GrabPointer() affiche ce qui est prévu,

my $test_window = $X->new_rsrc;
$X->CreateWindow ($test_window, ...,
                  cursor => $desired_cursor);
$X->XTestCompareCursor ($test_window, "CurrentCursor");
  or die "Oups, le curseur actuellement affiché n'est pas celui désiré";

Entrées simulées

"$X->XTestFakeInput (name=>...)"
"$X->XTestFakeInput ([ name=>... ])"
"$X->XTestFakeInput ([ name=>], [name=>], ...)"
Simule des entrées utilisateur pour des appuis de bouton, des appuis de touche et des mouvements de pointeur.

Une action d'entrée est spécifiée comme un paquet d'événement en utilisant des champs similaires à "$X->pack_event()".

XTestFakeInput() est toujours une action utilisateur unique, donc par exemple un appui sur un bouton et un relâchement de bouton sont deux requêtes XTestFakeInput() distinctes. Pour les événements principaux, un seul paquet d'événement suffit à décrire une entrée, mais certaines extensions comme "XInputExtension" peuvent nécessiter plus.

Appui et relâchement de bouton
Les champs d'argument sont 
name       "ButtonPress" ou "ButtonRelease"
detail     numéro de bouton physique (à partir de 1)
time       délai en millisecondes avant l'événement, par défaut 0

Par exemple, pour simuler un appui sur le bouton physique 3

$X->XTestFakeInput (name   => 'ButtonPress',
                    detail => 3);

"detail" est le numéro du bouton physique, avant que la traduction du protocole principal SetPointerMapping() ne soit appliquée. Pour simuler un bouton logique, il est nécessaire de vérifier GetPointerMapping() pour voir quel bouton physique, le cas échéant, correspond.

Faites attention lorsque vous simulez un "ButtonPress" car il peut être important de simuler également un "ButtonRelease" correspondant. Sur le serveur X.org environ 1.9.x après un appui synthétique, la souris physique ne fonctionne plus pour générer un relâchement et le bouton reste bloqué (vraisemblablement dans son grab de pointeur implicite normal).

Appui et relâchement de touche
Les champs d'argument sont 
name       "KeyPress" ou "KeyRelease"
detail     keycode (entier)
time       délai en millisecondes avant l'événement, par défaut 0
Mouvement du pointeur de souris
Le mouvement du pointeur de souris peut être induit avec ce qui suit. L'effet est similaire à un WarpPointer(). 
name       "MotionNotify"
root       XID de la fenêtre racine, par défaut "None" pour la fenêtre actuelle
root_x     \ position du pointeur à atteindre
root_y     /
detail     indicateur 0=absolu, 1=relatif, par défaut 0
time       délai en millisecondes avant l'événement, par défaut 0

"root" est la fenêtre racine (XID entier) sur laquelle se déplacer. Le défaut "None" (ou 0) signifie l'écran sur lequel se trouve actuellement le pointeur.

$X->XTestFakeInput (name   => 'MotionNotify',
                    root_x => 123,
                    root_y => 456);

"detail" peut être 1 pour se déplacer relativement à la position actuelle de la souris.

$X->XTestFakeInput (name   => 'MotionNotify',
                    root_x => 10,
                    root_y => -20,
                    detail => 1); # mouvement relatif
Autres événements
Les événements d'extension peuvent être simulés après un init_extension() afin qu'ils soient reconnus par "$X->pack_event()". Il appartient au serveur ou à l'extension de déterminer quels événements peuvent réellement être simulés.

Si une entrée d'extension nécessite plus d'un paquet d'événement pour être décrite, passez plusieurs tableaux références. Par exemple, "DeviceMotion" (de "XInputExtension") peut nécessiter des paquets "DeviceValuator" supplémentaires,

$X->XTestFakeInput ([ name => 'DeviceMotion', ... ],
                    [ name => 'DeviceValuator', ... ],
                    [ name => 'DeviceValuator',  ... ]);

Pour tous les événements, "time" correspond à la durée en millisecondes pendant laquelle le serveur doit attendre avant de jouer l'événement. La valeur par défaut est 0 pour aucun délai. Aucune requête supplémentaire n'est traitée par le client actuel pendant le délai, donc une séquence de XTestFakeInput() avec des délais s'exécutera séquentiellement, un délai après l'autre.

En général, les champs d'événement d'une fonction "$X->{'event_handler'}" ne peuvent pas être passés directement à XTestFakeInput() pour les rejouer. En particulier,

  • "time" d'un événement est un horodatage, il faudrait donc le zéro ou l'ajuster à un temps relatif pour un délai dans XTestFakeInput().
  • Pour "MotionNotify", "detail" d'un événement est le mécanisme d'indication, il faudrait donc le zéro pour l'indicateur absolu/relatif dans XTestFakeInput().
  • Pour "ButtonPress" et "ButtonRelease",
X11::Protocol::Ext::XTEST(3pm)

NAME

X11::Protocol::Ext::XTEST - Perl interface to the XTEST extension

SYNOPSIS

 use X11::Protocol::Ext::XTEST;

 # Query extension
 my $xtest = X11::Protocol::Ext::XTEST->new($protocol);
 $xtest->query_extension;
 if ($xtest->major_opcode) {
     print "XTEST extension is available.\n";
 }

 # Input simulation
 my $event = $xtest->fake_input(
     type     => 2,  # MotionNotify
     detail   => 1,  # relative motion
     root     => $root_window,
     event    => $root_window,
     sequence => $protocol->{sequence},
     x        => 100,
     y        => 200,
 );
 $protocol->send_event($event);

 # Grab server
 $xtest->grab_control(1); # Impervious to server grabs
 # ... do stuff ...
 $xtest->grab_control(0); # Normal behavior

DESCRIPTION

This module provides a Perl interface to the XTEST extension protocol. The XTEST extension allows clients to simulate input events and control server grabs.

REQUESTS

"XTEST Extension"
This section documents the XTEST extension itself, and not specific functions within the module.
 The XTEST extension provides the following requests:
  • XTestFakeInput: Simulate an input event. 
    XTestFakeInput(detail: CARD8, type: CARD8, root: WINDOW, event: WINDOW, sequence: CARD16, x: INT16, y: INT16)

    The "detail" from an event is a logical button number after SetPointerMapping() transformation, whereas XFakeInput() takes a physical number. A reverse lookup through the GetPointerMapping() table would be needed.

GrabServer Imperviousness

"$X->XTestGrabControl ($impervious)"
Control the current client's behaviour during a GrabServer() by another client.

If $impervious is 1 then the current client can continue to make requests, ie. it's impervious to server grabs by other clients.

If $impervious is 0 then the current client behaves as normal. Its requests wait during any GrabServer() by another client.
