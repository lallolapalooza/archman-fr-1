NOM

X11::Protocol::WM -- choses relatives au gestionnaire de fenêtres pour les programmes clients

SYNTAXE

use X11::Protocol::WM;

DESCRIPTION

Ceci contient des fonctions relatives au gestionnaire de fenêtres pour l'utilisation par les programmes clients, conformément au "Inter-Client Communication Conventions Manual" et à certains "Extended Window Manager Hints" du Net-WM.

/usr/share/doc/xorg-docs/icccm/icccm.txt.gz

http://www.freedesktop.org/wiki/Specifications/wm-spec

Propriétés usuelles

Chaque fenêtre cliente de premier niveau devrait habituellement

  • set_wm_class() pour s'identifier aux autres programmes (voir "WM_CLASS" ci-dessous).
  • set_wm_name() et set_wm_icon_name() pour le nom de fenêtre visible par l'utilisateur (voir "WM_NAME, WM_ICON_NAME" ci-dessous).
  • set_wm_client_machine_from_syshostname() et set_wm_pid() pour le processus en cours d'exécution (voir "WM_CLIENT_MACHINE" et "_NET_WM_PID" ci-dessous).

Ensuite, facultativement,

  • Si vous avez une icône, alors set_wm_hints() avec un bitmap ou une fenêtre (voir "WM_HINTS" ci-dessous).
  • Si l'utilisateur a spécifié une taille ou une position initiale sur la ligne de commande, alors set_wm_normal_hints(). Idem si le programme a des tailles min/max ou un rapport d'aspect souhaité (voir "WM_NORMAL_HINTS" ci-dessous).
  • Si une commande pour relancer le programme peut être construite, alors set_wm_command(), et de préférence la maintenir à jour avec les changements tels que le fichier actuellement ouvert, etc. (voir "WM_COMMAND" ci-dessous).

FONCTIONS

Propriétés textuelles

Les fonctions de propriété prenant des chaînes de caractères telles que set_wm_name() acceptent des chaînes d'octets ou des chaînes de caractères larges (Perl 5.8 et versions ultérieures). Les chaînes d'octets sont supposées être en Latin-1 et définies comme type "STRING" dans les propriétés. Les chaînes de caractères larges sont stockées comme "STRING" si elles sont entièrement en Latin-1, ou encodées en "COMPOUND_TEXT" pour d'autres caractères (voir Encode::X11).

À l'avenir, peut-être que les fonctions de chaîne pourraient accepter une sorte d'objet texte composé pour représenter des segments de différents encodages afin de devenir "COMPOUND_TEXT", ainsi que des manipulations pour un tel contenu, etc. Si le texte est constitué d'octets dans l'un des encodages ICCCM, il pourrait être plus efficace de le représenter directement sous forme de segments "COMPOUND_TEXT" plutôt que de passer par des caractères larges et revenir en arrière.

"set_text_property ($X, $window, $prop, $str)"
Définit la propriété $prop (atome entier) spécifiée sur $window (XID entier) en utilisant soit "STRING" soit "COMPOUND_TEXT" comme décrit ci-dessus. Si $str est "undef", alors $prop est supprimée.

$str est limité à "$X->maximum_request_length()". En théorie, des chaînes plus longues peuvent être stockées par morceaux, mais aucune tentative n'est faite ici. La limite de requête maximale est d'au moins 16384 octets et le serveur peut en autoriser plus, potentiellement beaucoup plus.

WM_CLASS

"X11::Protocol::WM::set_wm_class ($X, $window, $instance, $class)"
Définit la propriété "WM_CLASS" sur $window (un XID).

Cette propriété peut être utilisée par le gestionnaire de fenêtres pour rechercher des paramètres et des préférences pour le programme via le système de ressources X (voir "RESOURCES" dans X(7)) ou des mécanismes similaires.

Habituellement, le nom de l'instance est la commande du programme telle que "xterm" et le nom de la classe est quelque chose comme "XTerm". Certains programmes ont des options en ligne de commande pour définir la classe et/ou l'instance afin que l'utilisateur puisse appliquer des paramètres de gestionnaire de fenêtres différents à une copie particulière d'un programme en cours d'exécution.

X11::Protocol::WM::set_wm_class ($X, $window,
                                 "monprog", "MonProg");

$instance et $class doivent être uniquement en ASCII ou Latin-1. Les chaînes de caractères larges qui sont en Latin-1 sont converties si nécessaire.

WM_CLIENT_MACHINE

"X11::Protocol::WM::set_wm_client_machine ($X, $window, $hostname)"
Définit la propriété "WM_CLIENT_MACHINE" sur $window à $hostname (une chaîne).

$hostname devrait être le nom de la machine cliente tel que vu depuis le serveur. Si $hostname est "undef", alors la propriété est supprimée.

Habituellement, un nom de machine est uniquement en ASCII, mais tout ce qui est conforme à "Propriétés textuelles" ci-dessus est accepté.

"X11::Protocol::WM::set_wm_client_machine_from_syshostname ($X, $window)"
Définit la propriété "WM_CLIENT_MACHINE" sur $window en utilisant le module Sys::Hostname.

Si "Sys::Hostname" ne peut pas déterminer un nom d'hôte par ses divers moyens, alors actuellement la propriété est supprimée. Serait-il préférable de la laisser inchangée, ou de retourner un indicateur pour dire si elle a été définie ?

Certains cas de "Sys::Hostname" pourraient retourner "localhost". Cela est traité tel quel, en supposant que ce soit lorsque qu'il n'y a pas de réseau au-delà de la machine locale, donc client et serveur sont sur la même machine et le nom "localhost" suffit.

WM_COMMAND

"X11::Protocol::WM::set_wm_command ($X, $window, $command, $arg...)"
Définit la propriété "WM_COMMAND" sur $window (un XID).

Ceci devrait être un nom de programme et des chaînes d'arguments qui relanceront le client. $command est le nom du programme, suivi des chaînes d'arguments éventuelles.

X11::Protocol::WM::set_wm_command ($X, $window,
                                   'monprog',
                                   '--option',
                                   'fichier.txt');

La commande devrait lancer le client dans son état actuel, donc la commande pourrait inclure un nom de fichier, des options de ligne de commande pour les paramètres actuels, etc.

Les caractères non-ASCII sont autorisés conformément à "Propriétés textuelles" ci-dessus. La spécification ICCCM est pour que Latin-1 fonctionne sur un système Latin-1 POSIX, mais la façon dont d'autres caractères survivront à un gestionnaire de session, etc., est une autre affaire.

Un client peut définir ceci à tout moment, ou s'il participe au protocole de gestion de session "WM_SAVE_YOURSELF", alors il devrait définir en réponse à un "ClientMessage" de "WM_SAVE_YOURSELF".

Pour référence, sous "mwm" vers 2017, un client avec "WM_SAVE_YOURSELF" reçoit ce message pour le bouton Fermer de "mwm" ("f.kill") et est censé répondre dans un délai imparti (par défaut 1 seconde), après quoi "mwm" ferme la connexion du client ("KillClient"). Malheureusement, si à la fois "WM_SAVE_YOURSELF" et "WM_DELETE_WINDOW" sont présents, alors "mwm" fait toujours le "

Ceci est d'ailleurs tout à fait raisonnable, étant donné qu'un message "WM_SAVE_YOURSELF" a une utilité assez limitée, car la perte de connexion ou d'autres terminaisons peuvent se produire à tout moment ; donc, si l'état est important, il serait prudent de le sauvegarder.

WM_ICON_SIZE

"($min_width,$min_height, $max_width,$max_height, $width_inc,$height_inc) = X11::Protocol::WM::get_wm_icon_size($X,$root)"
Retourne les tailles d'icônes recommandées par le gestionnaire de fenêtres ("WM_ICON_SIZE") (en pixels) sous forme de plage, et d'incrément au-dessus du minimum. S'il n'y a pas de propriété "WM_ICON_SIZE", retourne une liste vide.

$root est la fenêtre racine à lire. Si omis, lit la valeur par défaut de "$X->root".

Un pixmap d'icône ou une fenêtre dans "WM_HINTS" devrait avoir une taille dans cette plage. De nombreux gestionnaires de fenêtres ne définissent pas de taille d'icône préférée. 32x32 pourrait être typique sur un petit écran ou 48x48 sur un écran plus grand.

WM_HINTS

"X11::Protocol::WM::set_wm_hints ($X, $window, key=>value, ...)"
Définit la propriété "WM_HINTS" sur $window (un XID). Par exemple, 
X11::Protocol::WM::set_wm_hints
    ($X, $my_window,
     input         => 1,
     initial_state => 'NormalState',
     icon_pixmap   => $my_pixmap);

Les paramètres clé/valeur sont les suivants.

input             entier 0 ou 1
initial_state     chaîne d'énumération ou nombre
icon_pixmap       pixmap (entier XID), profondeur 1
icon_window       fenêtre (entier XID)
icon_x            \ coordonnée entière
icon_y            / coordonnée entière
icon_mask         pixmap (entier XID)
window_group      fenêtre (entier XID)
urgency           booléen

"input" vaut 1 si le client souhaite que le gestionnaire de fenêtres donne le focus clavier à $window. Ce sera avec "$X->SetInputFocus()", ou si "WM_TAKE_FOCUS" est dans "WM_PROTOCOLS", alors via un "ClientMessage".

"input" vaut 0 si le gestionnaire de fenêtres ne doit pas donner le focus au client. C'est soit parce que $window est en sortie uniquement, soit parce que "WM_TAKE_FOCUS" est dans "WM_PROTOCOLS" alors que le client effectuera un SetInputFocus() sur lui-même lors d'une pression de bouton appropriée, etc.

"initial_state" est une chaîne ou un nombre. L'ICCCM autorise "NormalState" ou "IconicState" comme états initiaux.

"NormalState"       1
"IconicState"       3

"icon_pixmap" devrait être un bitmap, c'est-à-dire un pixmap (XID) avec une profondeur de 1. Le gestionnaire de fenêtres le dessinera dans des couleurs contrastées appropriées. Les pixels "1" sont au premier plan et "0" est à l'arrière-plan. Le bitmap "icon_mask" est appliqué à l'icône affichée. Il peut être utilisé pour créer une icône non rectangulaire.

"icon_window" est une fenêtre que le gestionnaire de fenêtres peut afficher lorsque $window est icônifiée. Ceci peut être utilisé pour une icône multicolore, réalisée soit par un arrière-plan, soit par le dessin du client (en réponse aux événements "Expose", ou mis à jour périodiquement pour une horloge, etc). La "icon_window" devrait être un enfant de la racine et devrait utiliser le visuel et la table des couleurs par défaut de l'écran. Le gestionnaire de fenêtres pourrait redimensionner la fenêtre et/ou la bordure.

Le gestionnaire de fenêtres pourrait définir une propriété "WM_ICON_SIZE" sur la fenêtre racine pour de bonnes tailles d'icônes. Voir "WM_ICON_SIZE" ci-dessus.

"window_group" est le XID d'une fenêtre qui est le leader du groupe d'une série de fenêtres de niveau supérieur utilisées par le client. Le gestionnaire de fenêtres pourrait fournir un moyen de manipuler le groupe dans son ensemble, par exemple pour tout icônifier. Si icônifié, les indications d'icône du leader sont utilisées pour l'icône. Le leader du groupe peut être une fenêtre non mappée. Il peut être pratique d'utiliser une fenêtre jamais mappée comme leader pour toutes les fenêtres suivantes.

"urgency" vrai signifie que la fenêtre est importante et que le gestionnaire de fenêtres devrait attirer l'attention de l'utilisateur d'une manière ou d'une autre. Le client peut changer cette indication à tout moment pour modifier l'importance actuelle.

"(key => $value, ...) = X11::Protocol::WM::get_wm_hints ($X, $window)"
Retourne la propriété "WM_HINTS" de $window. Le retour est une liste de paires clé/valeur comme pour set_wm_hints() ci-dessus 
input => 1,
icon_pixmap => 1234,
...

Seuls les champs dont les bits indicateurs sont activés dans les indications sont inclus dans le retour. S'il n'y a pas de "WM_HINTS" du tout ou si son champ indicateur est zéro, le retour est une liste vide.

Le retour peut être placé dans une table de hachage pour obtenir les champs par nom,

my %hints = X11::Protocol::WM::get_wm_hints ($X, $window);
if (exists $hints{'icon_pixmap'}) {
  print "l'icon_pixmap est ", $hints{'icon_pixmap'}, "\n";
}

"initial_state" est une chaîne telle que "NormalState". Les pixmaps et les fenêtres sont des chaînes "None" si elles sont définies mais à zéro (ce qui est probablement inhabituel). Si "$X->{'do_interp'}" est désactivé, alors tous sont des nombres.

X11R2 Xlib avait un bug dans son XSetWMHints() qui tronquait la valeur "window_group" des indications stockées. Le champ "window_group" est omis du retour si les données lues ne contiennent pas ce champ.

"(key => $value, ...) = X11::Protocol::WM::change_wm_hints ($X, $window, key=>value, ...)"
Modifie certains champs de la propriété "WM_HINTS" sur $window. Les champs clé/valeur donnés sont modifiés. Les autres champs sont laissés inchangés. Par exemple, 
X11::Protocol::WM::set_wm_hints ($X, $window,
                                 urgency => 1);

Une valeur "undef" signifie supprimer un champ,

X11::Protocol::WM::set_wm_hints ($X, $window,
                                 icon_pixmap => undef,
                                 icon_mask   => undef);

La modification nécessite un aller-retour serveur pour récupérer les valeurs actuelles de $window. Une application pourrait préférer se souvenir de ses indications souhaitées et envoyer un set_wm_hints() complet à chaque fois.

"$bytes = X11::Protocol::WM::pack_wm_hints ($X, key=>value...)"
Empaquette un ensemble de valeurs dans une chaîne d'octets au format "WM_HINTS". Les arguments clé/valeur sont ceux de set_wm_hints() ci-dessus et le résultat est les octets bruts stockés dans une propriété "WM_HINTS".

L'argument $X n'est actuellement pas utilisé, mais il est présent au cas où "initial_state" ou d'autres valeurs pourraient utiliser un lookup "$X->num()" à l'avenir.

"(key => $value, ...) = X11::Protocol::WM::unpack_wm_hints ($X, $bytes)"
Désépaquète une chaîne d'octets comme une structure "WM_HINTS". Le retour est une liste de paires clé/valeur comme pour get_wm_hints() ci-dessus. Le paramètre $X est utilisé pour "do_interp". Il n'y a aucune communication avec le serveur.

WM_NAME, WM_ICON_NAME

"X11::Protocol::WM::set_wm_name ($X, $window, $name)"
Définit la propriété "WM_NAME" sur $window (un XID entier) à $name (une chaîne).

Le gestionnaire de fenêtres peut l'afficher comme un titre au-dessus de la fenêtre, ou dans un menu de fenêtres, etc. Il peut s'agir d'une chaîne wide-char de Perl 5.8 conformément à "Text Properties" ci-dessus. Un bon gestionnaire de fenêtres devrait prendre en charge les titres non ASCII ou non Latin-1, mais la façon dont il s'affiche peut dépendre des polices, etc.

"X11::Protocol::WM::set_wm_icon_name ($X, $window, $name)"
Définit la propriété "WM_ICON_NAME" sur $window (un XID entier) à $name (une chaîne).

Le gestionnaire de fenêtres peut l'afficher lorsque $window est icônifiée. Si $window n'a pas d'icône (dans "WM_HINTS" ou du gestionnaire de fenêtres lui-même), ce texte pourrait être tout ce qui est affiché. Dans tous les cas, il devrait être court. Il peut s'agir d'une chaîne wide-char de Perl 5.8 conformément à "Text Properties" ci-dessus.

WM_NORMAL_HINTS

"X11::Protocol::WM::set_wm_normal_hints ($X, $window, key=>value,...)"
Définit la propriété "WM_NORMAL_HINTS" sur $window (un XID entier). Il s'agit d'une structure "WM_SIZE_HINTS" qui indique au gestionnaire de fenêtres les tailles souhaitées par le client. Par exemple, 
set_wm_normal_hints ($X, $window,
                     min_width => 200,
                     min_height => 100);

En général, le gestionnaire de fenêtres restreint le redimensionnement par l'utilisateur aux limites indiquées. La plupart des gestionnaires de fenêtres utilisent ces indications, mais ce ne sont bien sûr que des indications et un bon programme doit être préparé à d'autres tailles, même si cela n'aura pas une belle apparence ou ne sera pas très utile lorsque la fenêtre est trop grande ou trop petite, etc.

Les paramètres clé/valeur sont :

user_position      booléen, x,y de la fenêtre spécifiés par l'utilisateur
user_size          booléen, largeur,hauteur de la fenêtre spécifiées par l'utilisateur
program_position   booléen, x,y de la fenêtre spécifiés par le programme
program_size       booléen, largeur,hauteur de la fenêtre spécifiées par le programme
min_width          \ entiers, taille minimale en pixels
min_height         /
max_width          \ entiers, taille maximale en pixels
max_height         /
base_width         \ entiers, base de taille en pixels
base_height        /
width_inc          \ entiers, incrément de taille en pixels
height_inc         /
min_aspect         \  fraction 2/3 ou décimal 2 ou 1.5
min_aspect_num      | ou entier num/den jusqu'à 0x7FFFFFFF
min_aspect_den      |
max_aspect          |
max_aspect_num      |
max_aspect_den     /
win_gravity        Enum WinGravity "NorthEast" etc.

"user_position" et "user_size" sont des drapeaux signifiant que les coordonnées x,y ou la largeur,hauteur de la fenêtre (dans le `core $X->SetWindowAttributes()` habituel) ont été fournies par l'utilisateur, par exemple via une option de ligne de commande . Le gestionnaire de fenêtres respectera généralement ces valeurs et ignorera tout positionnement automatique ou placement interactif qu'il pourrait autrement effectuer.

"program_position" et "program_size" sont des drapeaux signifiant que les coordonnées x,y ou la largeur,hauteur de la fenêtre ont été calculées par le programme. Le gestionnaire de fenêtres pourrait les remplacer par sa propre politique de positionnement ou de mise à l'échelle. Il n'est généralement pas nécessaire de définir ces champs, sauf si le programme a une idée précise de l'endroit où il doit être et de sa taille. Pour une taille, il suffit de définir la largeur et la hauteur de la fenêtre principale et de laisser le gestionnaire de fenêtres (s'il est en cours d'exécution) faire le reste.

Les éléments regroupés ci-dessus doivent être fournis ensemble. Ainsi, par exemple, si un "min_width" est donné, alors un "min_height" doit également être donné.

"base_width", "base_height" et "width_inc", "height_inc" demandent que la fenêtre ait une certaine taille de base en pixels, puis un multiple de "inc" pixels au-dessus de cela. Ceci peut être utilisé par des éléments tels que "xterm" qui souhaitent une taille fixe pour la bordure ou la barre de défilement, puis un multiple de la taille des caractères au-dessus de cela. Si "base_width" et "base_height" ne sont pas donnés, alors "min_width" et "min_height" constituent la taille de base.

"base_width" et "base_height" peuvent être plus petits que "min_width" et "min_height". Cela signifie que la taille doit toujours être un multiple base+inc, mais le premier tel multiple qui est au moins la taille minimale. Le gestionnaire de fenêtres présente généralement le multiple "inc" à l'utilisateur, de sorte que, par exemple, sur un xterm, l'utilisateur voit un nombre de caractères. Une taille minimale peut alors exiger, par exemple, une taille minimale de 1x1 ou 2x2 caractères.

"min_aspect" et "max_aspect" demandent que la fenêtre ait un certain rapport largeur/hauteur minimum ou maximum. Par exemple, un rapport de 2/1 signifie qu'elle doit être deux fois plus large que haute. Ceci s'applique à la taille au-dessus de "base_width" et "base_height", ou si la base n'est pas donnée, à la taille totale de la fenêtre.

"min_aspect_num", "min_aspect_den" et "max_aspect_num", "max_aspect_den" définissent directement les valeurs du numérateur et du dénominateur (INT32, donc maximum 0x7FFF_FFFF). Ou "min_aspect" et "max_aspect" acceptent une seule valeur sous diverses formes qui sont converties en valeurs num/den.

2         entier
1.125     décimal, signifiant 1125/1000
2/3       fraction
1.5/4.5   fraction avec des décimales

Les valeurs supérieures à 0x7FFFFFFF sous ces formes sont réduites proportionnellement si nécessaire. Une valeur à virgule flottante Perl aura généralement plus de bits de précision que 0x7FFFFFFF et sera tronquée à quelque chose qui rentre.

"win_gravity" indique comment le client souhaite être décalé pour faire place à tout cadre environnant que le gestionnaire de fenêtres pourrait ajouter. Par exemple, si le programme a calculé la taille et la position de la fenêtre pour s'assurer que le coin nord-est est à une position souhaitée, alors donnez "win_gravity => "NorthEast"" afin que le gestionnaire de fenêtres conserve le coin nord-est tel quel lorsqu'il applique son cadre.

"win_gravity => "Static"" signifie que le cadre est placé autour de la fenêtre et que la fenêtre n'est pas du tout déplacée. Bien sûr, cela peut signifier qu'une partie du cadre se retrouve hors écran.

"$bytes = X11::Protocol::WM::pack_size_hints ($X, key=>value,...)"
Retourne une chaîne d'octets qui est une structure "WM_SIZE_HINTS" créée à partir des paramètres clé/valeur donnés. "WM_SIZE_HINTS" est le type de structure pour "WM_NORMAL_HINTS" décrit ci-dessus, et les paramètres clé/valeur sont tels que décrits ci-dessus.

Le paramètre $X est utilisé pour interpréter les valeurs d'énumération "win_gravity". Il n'y a pas de communication avec le serveur.

"($num,$den) = X11::Protocol::WM::aspect_to_num_den ($aspect)"
Retourne une paire d'entiers INT32 de 0 à 0x7FFF_FFFF pour le rapport d'aspect donné $aspect. C'est la conversion appliquée à "min_aspect" et "max_aspect" ci-dessus. $aspect peut être n'importe lequel des types entier, décimal ou fraction décrit.

WM_PROTOCOLS

"X11::Protocol::WM::set_wm_protocols ($X, $window, $protocol,...)"
Définit la propriété "WM_PROTOCOLS" sur $window (un XID). Chaque argument est un nom de protocole sous forme de chaîne ou un identifiant d'atome entier. 
X11::Protocol::WM::set_wm_protocols
  ($X, $window, 'WM_DELETE_WINDOW', '_NET_WM_PING')

Par exemple, "WM_DELETE_WINDOW" signifie que lorsque l'utilisateur clique sur le bouton de fermeture, le gestionnaire de fenêtres envoie un événement "ClientMessage" plutôt que d'effectuer un KillClient(). L'événement "ClientMessage" permet à un programme de se nettoyer ou de demander à l'utilisateur s'il souhaite enregistrer un document avant de quitter, etc.

WM_STATE

Le gestionnaire de fenêtres maintient un état pour chaque fenêtre cliente qu'il gère,

WithdrawnState
NormalState
IconicState

"WithdrawnState" signifie que la fenêtre n'est pas mappée et que le gestionnaire de fenêtres ne la gère pas. Une fenêtre nouvellement créée ("$X->CreateWindow()") est initialement dans l'"WithdrawnState" et lors du premier "$X->MapWindow()" passe à "NormalState" (ou à "IconicState" si tel est l'état initial demandé dans "WM_HINTS").

iconify() et withdraw() ci-dessous peuvent changer l'état à iconique ou retiré. Une fenêtre peut être restaurée de l'état iconique à l'état normal par un MapWindow().

"($state, $icon_window) = X11::Protocol::WM::get_wm_state ($X, $window)"
Retourne la propriété "WM_STATE" de $window. Celle-ci est définie par le gestionnaire de fenêtres sur les fenêtres d'application de premier niveau. S'il n'y a pas de telle propriété, le retour est une liste vide.

$state retourné est une chaîne d'énumération, ou une valeur entière si "$X->{'do_interp'}" est désactivé ou si la valeur n'est pas reconnue.

"WithdrawnState"    0      non affiché
"NormalState"       1      fenêtre affichée
"IconicState"       3      iconifiée d'une manière ou d'une autre
"ZoomState"         2      \ n'est plus dans ICCCM
"InactiveState"     4      /   (zoom signifiait maximisé)

$icon_window retourné est la fenêtre (XID entier) utilisée par le gestionnaire de fenêtres pour afficher une icône de $window. S'il n'y a pas de telle fenêtre, alors $icon_window est "None" (ou 0 si "$X->{'do_interp'}" est désactivé).

$icon_window peut être la fenêtre icône des "WM_HINTS" du client, ou il peut s'agir d'une fenêtre créée par le gestionnaire de fenêtres. Le client peut y dessiner pour des animations, etc., en sélectionnant peut-être des événements "Expose" sur celle-ci pour savoir quand redessiner.

"WM_STATE" est défini par le gestionnaire de fenêtres lorsque la première fenêtre de niveau supérieur est mappée (ou peut-être plus tôt), puis est maintenu à jour. Généralement, l'absence de propriété "WM_STATE" ou une "WM_STATE" définie sur WithdrawnState signifie que le gestionnaire de fenêtres ne gère pas la fenêtre, ou ne le fait pas encore. Un client peut sélectionner le masque d'événements "PropertyChange" de la manière habituelle pour écouter les changements de "WM_STATE".

"($state, $icon_window) = X11::Protocol::WM::unpack_wm_state ($X, $bytes)"
Désérialise les octets d'une propriété "WM_STATE" en un $state

WM FUNCTIONS

"X11::Protocol::WM::get_wm_state ($X, $window)"
Return the "WM_STATE" property of $window, or "undef" if the property does not exist.

The property is a list of two integers. The first is the current state, the second is the icon window (if any).

Possible states are:

NormalState  0
IconicState  1
WithdrawnState 2

The window manager sets this property. It should always be present on toplevel windows. If it's absent, then it is likely that there is no window manager running.

The icon window is a window ID for the application's icon. If the state is NormalState or WithdrawnState, the icon window is "undef".

This is a convenience function; the raw property is "WM_STATE".

"X11::Protocol::WM::set_wm_state ($X, $window, $state, $icon_window)"
Set the "WM_STATE" property on $window.

$state should be one of NormalState, IconicState, or WithdrawnState.

$icon_window is the window ID of the icon window, or "undef".

The window manager should keep this property up to date. You should not need to call this yourself.

"X11::Protocol::WM::set_normal ($X, $window)"
Change $window to NormalState and set the "WM_STATE" property accordingly. $icon_window is obtained from get_wm_state() above.

$X is used for "$X->{'do_interp'}" but there's no communication with the server.

"X11::Protocol::WM::iconify ($X, $window)"
"X11::Protocol::WM::iconify ($X, $window, $root)"
Change $window to "IconicState" by sending a "ClientMessage" to the window manager.

If the window manager does not have any iconification then it might do nothing (eg. some tiling window managers). If there's no window manager running then iconification is not possible and this message will do nothing.

$root should be the root window of $window. If not given or "undef" then it's obtained by a QueryTree() here. Any client can iconify any top level window.

If $window has other windows which are "WM_TRANSIENT_FOR" for it then generally the window manager will iconify or hide those windows too (see "WM_TRANSIENT_FOR" below).

"X11::Protocol::WM::withdraw ($X, $window)"
"X11::Protocol::WM::withdraw ($X, $window, $root)"
Change $window to "WithdrawnState" by an "$X->UnmapWindow()" and a synthetic "UnmapNotify" message to the window manager.

If there's no window manager running then the UnmapWindow() unmaps and the "UnmapNotify" message does nothing.

$root should be the root window of $window. If not given or "undef" then it's obtained by a QueryTree() here.

If other windows are "WM_TRANSIENT_FOR" this $window (eg. open dialog windows) then generally the client should withdraw them too. The window manager might make such other windows inaccessible anyway.

The ICCCM specifies an "UnmapNotify" message so the window manager is notified of the desired state change even if $window is already unmapped, such as in "IconicState" or perhaps during some window manager reparenting, etc.

$window can be changed back to NormalState or IconicState later with "$X->MapWindow()" the same as for a newly created window. (And "WM_HINTS" "initial_state" can give a desired initial iconic/normal state). But before doing so be sure the window manager has recognised the withdraw(). This will be when the window manager changes the "WM_STATE" property to "WithdrawnState", or deletes that property.

Any client can withdraw any toplevel window, but it's unusual for a client to withdraw windows which are not its own.

WM_TRANSIENT_FOR

"X11::Protocol::WM::set_wm_transient_for ($X, $window, $transient_for)"
Set the "WM_TRANSIENT_FOR" property on $window (an XID).

$transient_for is another window XID, or "undef" if $window is not transient for anything so "WM_TRANSIENT_FOR" should be deleted.

"Transient for" means $window is some sort of dialog or menu related to the given $transient_for window. The window manager will generally iconify $window together with its $transient_for, etc. See set_motif_wm_hints() below for "modal" transients.

_MOTIF_WM_HINTS

"X11::Protocol::WM::set_motif_wm_hints ($X, $window, key=>value...)"
Set the "MOTIF_WM_HINTS" property on $window (an XID).

These hints control window decorations and "modal" state. It originated in the Motif "mwm" window manager but is recognised by most other window managers. It should be set on a toplevel window before mapping. Changes made later might not affect what the window manager does.

X11::Protocol::WM::set_motif_wm_hints
  ($X, $dialog_window,
   input_mode => "full_application_modal");
$X->MapWindow ($dialog_window);

Ordinary windows generally don't need to restrict their decorations etc, but something special like a clock or gadget might benefit.

X11::Protocol::WM::set_motif_wm_hints
  ($X, $my_gadget_window,
   functions   => 4+32,   # move+close
   decorations => 1+4+8); # border+title+menu

The key/value arguments are

functions   => integer bits
decorations => integer bits
input_mode  => enum string or integer
status      => integer bits

"functions" is what actions the window manager should offer to the user in a drop-down menu or similar. It's an integer bitwise OR of the following values. If not given then the default is normally all functions.

bit    actions offered
---    ---------------
 1     all functions
 2     resize window
 4     move window
 8     minimize, to iconify
16     maximize, to full-screen (with a frame still)
32     close window

"decorations" is what visual decorations the window manager should show around the window. It's an integer bitwise OR of the following values. If not given then the default is normally all decorations.

bit       decorations displayed
---       ---------------------
 1        all decorations
 2        border around the window
 4        resizeh, handles to resize by dragging
 8        title bar, showing WM_NAME
16        menu, drop-down menu of the "functions" above
32        minimize button, to iconify
64        maximize button, to full-screen

"input_mode" allows a window to be "modal", meaning the user should interact only with $window. The window manager will generally keep it on top, not move the focus to other windows, etc. The value is one of the following strings or corresponding integer,

  string                   integer
"modeless"                    0    not modal (the default)
"primary_application_modal"   1    modal to its "transient for"
"system_modal"                2    modal to the whole display
"full_application_modal"      3    modal to the current client

"primary_application_modal" means $window is modal for the "WM_TRANSIENT_FOR" set on $window (see "WM_TRANSIENT_FOR" above), but other windows on the display can be used normally. "full_application_modal" means modal for all windows of the same client, but other clients can be used normally.

Modal behaviour is important for good user interaction and therefore ought to be implemented by a window manager, but a good program should be prepared to do something with input on other windows.

"status" field is a bitwise OR of the following bits (only one currently).

bit
 1    tearoff menu window

Tearoff menu flag is intended for tearoff menus, as the name suggests.

X11::Protocol::WM::set_motif_wm_hints
  ($X, $my_tearoff_window, status => 1);

Motif "mwm" will expand the window to make it wide enough for the "WM_NAME" in the frame title bar. Otherwise a title is generally truncated to as much as fits the window's current width. Expanding can be good for tearoffs where the title bar is some originating item name etc which the user should see. But don't be surprised if this flag is ignored by other window managers.

Perhaps in the future the individual bits above will have some symbolic names. Either constants or string values interpreted. What would a possible get_hints() return, and what might be convenient to add/subtract bits?

See /usr/include/Xm/MwmUtil.h on the hints bits, and see "mwm" sources WmWinInfo.c ProcessWmWindowTitle() for the "status" tearoff window flag.

_NET_FRAME_EXTENTS

"my ($left,$right, $top,$bottom) = X11::Protocol::WM::get_net_frame_extents ($X, $window)"
Get the "_NET_FRAME_EXTENTS" property from $window.

This is set on top-level windows by the window manager to report how many pixels of frame or decoration it has added around $window.

If there's no such property set then the return is an empty list. So for example

my ($left,$right,$top,$bottom)
      = get_net_frame_extents ($X, $window)
  or print "no frame extents";
my ($left,$right,$top,$bottom)
  = get_net_frame_extents ($X, $window);
if (! defined $left) {
  print "no frame extents";
}

A client might look at the frame size if moving a window programmatically so as not to put the title bar etc off-screen. Oldish window managers might not provide this information though.

_NET_WM_PID

"X11::Protocol::WM::set_ne
t_wm_pid ($X, $window)"
"X11::Protocol::WM::set_net_wm_pid ($X, $window, $pid)"
"X11::Protocol::WM::set_net_wm_pid ($X, $window, undef)"
Définit la propriété "_NET_WM_PID" sur $window à l'identifiant de processus $pid fourni, ou à l'identifiant de processus actuel $$ s'il est omis. (Voir perlvar pour $$.) Si $pid est "undef" alors la propriété est supprimée.

Un gestionnaire de fenêtres ou similaire pourrait utiliser le PID pour tuer de force un client qui ne répond pas. Cela n'est utile que si "WM_CLIENT_MACHINE" (ci-dessus) est également défini, pour savoir où le client s'exécute.

_NET_WM_STATE

Un gestionnaire de fenêtres conforme à EWMH maintient un ensemble d'indicateurs d'état pour chaque fenêtre cliente. Un état est un atome tel que "_NET_WM_STATE_FULLSCREEN" et chaque état peut être présent ou absent. Les états pris en charge sont listés dans la propriété "_NET_SUPPORTED" sur la racine (avec d'autres fonctionnalités). Par exemple,

my @net_supported = X11::Protocol::Other::get_property_atoms
                     ($X, $X->root, $X->atom('_NET_SUPPORTED'));
if (grep {$_ == $X->atom('_NET_WM_STATE_FULLSCREEN')}
         @net_supported) { 
  print "Have _NET_WM_STATE_FULLSCREEN\n";
}

Tout client peut demander au gestionnaire de fenêtres de changer les états de n'importe quelle fenêtre. Un client peut définir des états initiaux sur une nouvelle fenêtre avec set_net_wm_state() ci-dessous. Les états possibles incluent

_NET_WM_STATE_MODAL
La fenêtre est modale par rapport à son parent "WM_TRANSIENT_FOR", ou si "WM_TRANSIENT_FOR" n'est pas défini, alors modale par rapport à son groupe de fenêtres.

Voir "_MOTIF_WM_HINTS" pour définir modal avec les indications de style Motif.

_NET_WM_STATE_STICKY
La fenêtre est maintenue dans une position fixe à l'écran lorsque le bureau défile.
_NET_WM_STATE_MAXIMIZED_VERT
_NET_WM_STATE_MAXIMIZED_HORZ
La fenêtre est de taille maximale verticalement ou horizontalement, ou les deux. La fenêtre a toujours sa décoration environnante et la taille doit respecter les incréments de taille spécifiés dans "WM_NORMAL_HINTS".
_NET_WM_STATE_FULLSCREEN
La fenêtre occupe tout l'écran sans décoration autour, occupant ainsi tout l'écran.

Le gestionnaire de fenêtres se souvient de la taille "normale" de la fenêtre afin que lorsque les états maximisé ou plein écran sont supprimés, la taille précédente soit restaurée.

_NET_WM_STATE_SHADED
La fenêtre est "ombrée" ce qui signifie généralement que sa barre de titre est affichée mais pas la fenêtre cliente elle-même. C'est une alternative à l'iconification d'une fenêtre.
_NET_WM_STATE_SKIP_TASKBAR
_NET_WM_STATE_SKIP_PAGER
Ne pas afficher la fenêtre sur une barre des tâches ou dans un paginateur, respectivement.
_NET_WM_STATE_HIDDEN (lecture seule)
Cet état est défini par le gestionnaire de fenêtres lorsque la fenêtre est iconifiée ou similaire et n'apparaît donc pas à l'écran. Les clients ne peuvent pas le modifier.
_NET_WM_STATE_ABOVE
_NET_WM_STATE_BELOW
La fenêtre est maintenue au-dessus ou en dessous des autres fenêtres clientes. L'ordre d'empilement maintenu est approximativement 
 haut
+-----------------------------+
|  _NET_WM_WINDOW_TYPE_DOCK   |   Panneaux "DOCK" (etc) en haut,
+-----------------------------+   sauf peut-être les fenêtres
|     _NET_WM_STATE_ABOVE     |   FULLSCREEN au-dessus de ces
+-----------------------------+   panneaux lorsqu'elles sont
|            normal           |   focalisées
+-----------------------------+
|     _NET_WM_STATE_BELOW     |
+-----------------------------+
| _NET_WM_WINDOW_TYPE_DESKTOP |
+-----------------------------+
 bas
_NET_WM_STATE_DEMANDS_ATTENTION
La fenêtre doit attirer l'attention de l'utilisateur d'une manière ou d'une autre. Un client définit ceci et le gestionnaire de fenêtres le supprime une fois que la fenêtre a reçu l'attention de l'utilisateur (ce qui pourrait signifier le focus clavier ou similaire).

Les fonctions suivantes obtiennent ou définissent les états.

"change_net_wm_state($X, $window, $action, $state, key=>value,...)"
Change l'un des indicateurs d'état "_NET_WM_STATE" sur $window en envoyant un message au gestionnaire de fenêtres. Par exemple, 
change_net_wm_state ($X, $window, "toggle", "FULLSCREEN");

$window doit être une fenêtre gérée, c'est-à-dire qu'elle doit avoir eu son MapWindow() initial et ne pas être en override-redirect. Si ce n'est pas le cas ou s'il n'y a pas de gestionnaire de fenêtres ou s'il n'a pas EWMH, alors ce message de changement n'aura aucun effet.

$action est une chaîne ou un entier indiquant comment changer l'état,

"remove"       0
"add"          1
"toggle"       2

$state est une chaîne telle que "FULLSCREEN" ou un entier d'atome tel que "$X->atom("_NET_WM_STATE_FULLSCREEN")".

Les autres paramètres optionnels clé/valeur sont

state2   => chaîne ou atome
source   => "none", "normal", "user", 0,1,2
root     => entier XID, ou undef

Un message de changement peut agir sur un ou deux états. Pour deux états, le second est "state2". Par exemple, pour maximiser verticalement et horizontalement en une seule opération,

change_net_wm_state ($X, $window, "add", "MAXIMIZED_VERT",
                     state2 => "MAXIMIZED_HORZ");

"source" indique l'origine de la demande de changement. La valeur par défaut est "normal", ce qui signifie une application normale. "user" est pour un programme de contrôle d'interface utilisateur tel qu'un paginateur. ("none"=0 est ce que les clients avant EWMH 1.2 fournissaient.)

"root" est la fenêtre racine (XID entier) de $window. Si "undef" ou non donné, il est trouvé par "$X->QueryTree()". Si vous connaissez déjà la racine, la donner évite cette requête aller-retour.

"@strings = get_net_wm_state ($X, $window)"
"@atoms = get_net_wm_state_atoms ($X, $window)"
Obtient la propriété "_NET_WM_STATE" de $window. get_net_wm_state() renvoie une liste de chaînes telles que "FULLSCREEN". get_net_wm_state_atoms() renvoie une liste d'entiers d'atomes tels que "$X->atom('_NET_WM_STATE_FULLSCREEN')". Dans les deux cas, s'il n'y a pas de telle propriété ou si elle est vide, renvoie une liste vide.
"set_net_wm_state ($X, $window, $state,...)"
Définit la propriété "_NET_WM_STATE" sur $window. Chaque $state peut être 
une chaîne comme "FULLSCREEN"
une chaîne comme "_NET_WM_STATE_FULLSCREEN"
un entier d'atome d'un nom comme _NET_WM_STATE_FULLSCREEN

Un client peut définir "_NET_WM_STATE" sur une nouvelle fenêtre pour informer le gestionnaire de fenêtres des états initiaux souhaités. C'est seulement un "devrait" dans la spécification EWMH, donc cela pourrait ne pas être respecté.

# état initial souhaité
set_net_wm_state ($X, $window,
                  "MAXIMIZED_HORZ", "MAXIMIZED_VERT");

Une fois que la fenêtre est gérée par le gestionnaire de fenêtres (une fois mappée), les clients ne devraient pas définir "_NET_WM_STATE" mais demander plutôt au gestionnaire de fenêtres avec le message change_net_wm_state() ci-dessus.

_NET_WM_USER_TIME

"set_net_wm_user_time ($X, $window, $time)"
Définit la propriété "_NET_WM_USER_TIME" sur $window.

$time devrait être une valeur de temps serveur (un entier) de la dernière pression de touche utilisateur etc événement dans $window. Ou lors de la création de $window, le temps de l'événement qui a provoqué son ouverture.

Sur une fenêtre nouvellement créée, une valeur spéciale $time de 0 signifie que la fenêtre ne devrait pas recevoir le focus lorsqu'elle est mappée -- en supposant que le gestionnaire de fenêtres reconnaisse "_NET_WM_USER_TIME", bien sûr.

Si le client a la fenêtre active, il devrait mettre à jour "_NET_WM_USER_TIME" pour chaque entrée utilisateur. Généralement, les événements KeyPress et ButtonPress sont des entrées utilisateur, mais normalement KeyRelease et ButtonRelease ne le sont pas car ce sont les événements Press qui indiquent que l'utilisateur fait activement quelque chose.

Le gestionnaire de fenêtres pourrait utiliser "_NET_WM_USER_TIME" pour contrôler le focus et/ou l'ordre d'empilement afin que, par exemple, une fenêtre pop-up lente ne vole pas le focus si vous êtes allé dans une autre fenêtre pour faire d'autres travaux dans l'intervalle.

_NET_WM_WINDOW_TYPE

"X11::Protocol::WM::set_net_wm_window_type ($X, $window, $window_type)"
Définit la propriété "_NET_WM_WINDOW_TYPE" sur $window (un XID). $window_type peut être 
une chaîne comme "NORMAL"
un entier d'atome d'un nom comme _NET_WM_WINDOW_TYPE_NORMAL

Les types de fenêtres d'EWMH sont les suivants.

"NORMAL"
"DIALOG"
"DESKTOP"
"DOCK"
"TOOLBAR"
"MENU"
"UTILITY"
"SPLASH"

Cadre vers Client

"$window = X11::Protocol::WM::frame_window_to_client ($X, $frame)"
Renvoie la fenêtre cliente (un XID) contenue dans la fenêtre du gestionnaire de fenêtres $frame (un XID). $frame est généralement un enfant immédiat de la fenêtre racine.

Si aucune fenêtre cliente ne peut être trouvée dans $frame, alors renvoie "undef".

NAME

X11::Protocol::WM - functions related to window management

SYNOPSIS

    use X11::Protocol;
    use X11::Protocol::WM;

    # $X is a X11::Protocol object
    my $X = X11::Protocol->new;

    # get window XID from a frame window
    my $client = X11::Protocol::WM::get_client_window($X, $frame);

    # check if window manager is running
    if (X11::Protocol::WM::is_running($X)) { ... }

    # get the virtual root window if any
    my $vroot = X11::Protocol::WM::root_to_virtual_root($X, $root);

    # set window manager hints
    X11::Protocol::WM::set_wm_hints($X, $window,
        input => 1,
        is_override_redirect => 0,
        window_group => $window,
        ...
    );

DESCRIPTION

This module provides functions for dealing with window manager specific things, like getting the actual client window from a given frame window, checking if a window manager is running, or setting window manager hints.

It is mostly implemented using the ICCCM standard, but also some Extended Window Manager Hints (_NET_WM) and proprietary hints like __SWM_VROOT.

Finding the Client Window

When you have a window XID, it might be the frame window used by the window manager for decorations, or it could be the client window itself. The functions in this module often need to find the actual client window from a given window XID.

"$client = X11::Protocol::WM::get_client_window ($X, $frame)"
This function tries to find the client window, given a window XID $frame. It might be that the window manager has put a frame around the client window, or not. In the latter case, $frame would be the client window itself.

This might happen if $frame is an icon window or similar created by the window manager itself, or an override-redirect client without a frame, or if there's no window manager running at all. In the latter two cases $frame would be the client already.

The strategy is to look at $frame and down the window tree seeking a "WM_STATE" property which the window manager puts on a client's toplevel when mapped. The search depth and total windows are limited in case the window manager does its decoration in some ridiculous way or the client uses excessive windows (which would be traversed if there's no window manager).

+-rootwin--------------------------+
|                                  |
|                                  |
|    +-frame-win--------+          |
|    | +-client-win---+ |          |
|    | | WM_STATE ... | |          |
|    | |              | |          |
|    | +--------------+ |          |
|    +------------------+          |
|                                  |
+----------------------------------+

Care is taken not to error out if some windows are destroyed during the search. When a window belongs to other clients it could be destroyed at any time. If $frame itself doesn't exist then the return is "undef".

This function is similar to what "xwininfo" and similar programs do to go from a toplevel root window child down to the client window, per dmsimple.c Select_Window() or Xlib XmuClientWindow(). (See also X11::Protocol::ChooseWindow.)

Virtual Root

Some window managers use a "virtual root" window covering the entire screen. Application windows or frame windows are then children of that virtual root. This can help the window manager implement a large desktop or multiple desktops, though it tends to fail in subtle ways with various root oriented programs, including for example xsetroot(1) or the click-to-select in xwininfo(1) and xprop(1).

"$window = X11::Protocol::WM::root_to_virtual_root ($X, $root)"
If the window manager is using a virtual root then return that window XID. If not then return "undef".

The current implementation searches for a window with an "__SWM_VROOT" property, as per the "swm", "tvtwm" and "amiwm" window managers, and as used by the "xscreensaver" program and perhaps some versions of KDE.

There's nothing yet for EWMH "_NET_VIRTUAL_ROOTS". Do any window managers use it? Is "_NET_CURRENT_DESKTOP" an index into that virtual roots list?

(See X11::Protocol::XSetRoot for changing the background of a root or virtual root.)

EXPORTS

Nothing is exported by default, but the functions can be requested in usual "Exporter" style,

use X11::Protocol::WM 'set_wm_hints';
set_wm_hints ($X, $window, input => 1, ...);

Or just call with full package name

use X11::Protocol::WM;
X11::Protocol::WM::set_wm_hints ($X, $window, input => 1, ...);

There's no ":all" tag since this module is meant as a grab-bag of functions and to import as-yet unknown things would be asking for name clashes.

BUGS

Not much attention is paid to text on an EBCDIC system. Wide char strings probably work, but byte strings may go straight through whereas they ought to be re-coded to Latin-1. But the same probably applies to parts of the core "X11::Protocol" such as "$X->atom_name()" where you'd want to convert Latin-1 from the server to native EBCDIC.
