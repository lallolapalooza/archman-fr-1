XSetErrorHandler(3) FONCTIONS XLIB XSetErrorHandler(3)

NOM

XSetErrorHandler, XGetErrorText, XDisplayName, XSetIOErrorHandler, XSetIOErrorExitHandler, XGetErrorDatabaseText - gestionnaires d'erreurs par défaut

SYNTAXE

int (*XSetErrorHandler(int (*gestionnaire)(Display *, XErrorEvent *)))();

int XGetErrorText(Display *display, int code, char *buffer_retour, int longueur);

char *XDisplayName(_Xconst char *chaine);

int (*XSetIOErrorHandler(int (*gestionnaire)(Display *)))();

void (*XSetIOErrorExitHandler(Display *display, void (*gestionnaire)(Display *, void *), void *donnees_utilisateur))();

int XGetErrorDatabaseText(Display *display, _Xconst char *nom, _Xconst char *message, _Xconst char *chaine_par_defaut, char *buffer_retour, int longueur);

ARGUMENTS

buffer_retour
Retourne la description de l'erreur.
code
Spécifie le code d'erreur pour lequel vous souhaitez obtenir une description.
chaine_par_defaut
Spécifie le message d'erreur par défaut si aucun n'est trouvé dans la base de données.
display
Spécifie la connexion au serveur X.
gestionnaire
Spécifie le gestionnaire d'erreurs fourni par le programme.
longueur
Spécifie la taille du tampon.
message
Spécifie le type du message d'erreur.
nom
Spécifie le nom de l'application.
chaine
Spécifie la chaîne de caractères.
donnees_utilisateur
Données utilisateur facultatives à passer au gestionnaire d'erreurs.

DESCRIPTION

Xlib appelle généralement le gestionnaire d'erreurs fourni par le programme chaque fois qu'une erreur est reçue. Il n'est pas appelé pour les erreurs BadName des requêtes de protocole OpenFont, LookupColor ou AllocNamedColor, ni pour les erreurs BadFont d'une requête de protocole QueryFont. Ces erreurs sont généralement renvoyées au programme via l'interface procédurale. Comme cette condition n'est pas supposée être fatale, il est acceptable que votre gestionnaire d'erreurs revienne ; la valeur retournée est ignorée. Cependant, le gestionnaire d'erreurs ne doit pas appeler de fonctions (directement ou indirectement) sur l'affichage qui généreraient des requêtes de protocole ou qui attendraient des événements d'entrée. Le gestionnaire d'erreurs précédent est retourné.

La fonction XGetErrorText copie une chaîne terminée par un caractère nul décrivant le code d'erreur spécifié dans le tampon spécifié. Le texte retourné est dans le codage de la locale actuelle. Il est recommandé d'utiliser cette fonction pour obtenir une description d'erreur car les extensions de Xlib peuvent définir leurs propres codes d'erreur et chaînes d'erreur.

La fonction XDisplayName retourne le nom de l'affichage que XOpenDisplay essaierait d'utiliser. Si une chaîne NULL est spécifiée, XDisplayName recherche l'affichage dans l'environnement et retourne le nom de l'affichage que XOpenDisplay essaierait d'utiliser. Cela facilite le signalement à l'utilisateur de l'affichage précis que le programme a tenté d'ouvrir lorsque la tentative de connexion initiale a échoué.

La fonction XSetIOErrorHandler définit le gestionnaire d'erreurs d'E/S fatales. Xlib appelle le gestionnaire d'erreurs fourni par le programme si une erreur de type appel système se produit (par exemple, la connexion au serveur a été perdue). Ceci est supposé être une condition fatale, et la routine appelée ne devrait normalement pas revenir. Si le gestionnaire d'erreurs d'E/S revient, le processus client se termine par défaut, ce comportement peut être modifié avec la fonction XSetIOErrorExitHandler.

Notez que le gestionnaire d'erreurs précédent est retourné.

La fonction XGetErrorDatabaseText retourne un message terminé par un caractère nul (ou le message par défaut) à partir de la base de données des messages d'erreur. Xlib utilise cette fonction en interne pour rechercher ses messages d'erreur. Le texte dans l'argument default_string est supposé être dans le codage de la locale actuelle, et le texte stocké dans l'argument buffer_return est dans le codage de la locale actuelle.

L'argument nom devrait généralement être le nom de votre application. L'argument message devrait indiquer quel type de message d'erreur vous souhaitez. Si le nom et le message ne sont pas dans le codage de caractères portables hôtes (Host Portable Character Encoding), le résultat dépend de l'implémentation. Xlib utilise trois “noms d'application” prédéfinis pour signaler les erreurs. Dans ces noms, la casse est importante.

XProtoError
Le numéro d'erreur du protocole est utilisé comme chaîne pour l'argument message.
XlibMessage
Ce sont les chaînes de messages utilisées en interne par la bibliothèque.
XRequest
Pour une requête de protocole principale, le numéro de protocole de requête principale est utilisé pour l'argument message. Pour une requête d'extension, le nom de l'extension (tel que donné par InitExtension) suivi d'un point (.) et du numéro de protocole de requête mineure est utilisé pour l'argument message. Si aucune chaîne n'est trouvée dans la base de données d'erreurs, le default_string est retourné dans le buffer.
