XSETDEVICEFOCUS(3)   XSETDEVICEFOCUS(3)

NOM

XSetDeviceFocus, XGetDeviceFocus - contrôler le focus des périphériques d'entrée d'extension

SYNTAXE

#include <X11/extensions/XInput.h>
XSetDeviceFocus( Display *display,
                 XDevice *device,
                 Window focus,
                 int revert_to,
                 Time time);
XGetDeviceFocus( Display *display,
                 XDevice *device,
                 Window *focus_return,
                 int *revert_to_return,
                 int * time_return);

Arguments

display
       Spécifie la connexion au serveur X.
device
       Spécifie le périphérique dont le focus doit être interrogé ou
       modifié.
focus
       Spécifie la fenêtre, PointerRoot, FollowKeyboard, ou
       None.
focus_return
       Retourne la fenêtre de focus, PointerRoot, FollowKeyboard, ou
       None.
revert_to
       Spécifie où le focus d'entrée est rétabli si la fenêtre devient
       non visible. Vous pouvez passer RevertToParent,
       RevertToPointerRoot, RevertToFollowKeyboard, ou
       RevertToNone.
revert_to_return
       Retourne l'état de focus actuel RevertToParent,
       RevertToPointerRoot, RevertToFollowKeyboard, ou
       RevertToNone.
time_return
       Retourne le dernier temps de changement de focus pour le périphérique.
time
       Spécifie le temps. Vous pouvez passer soit un timestamp, soit
       CurrentTime.

DESCRIPTION

La requête XSetDeviceFocus change le focus du périphérique spécifié
et son dernier temps de changement de focus. Elle n'a aucun effet si
le temps spécifié est antérieur au dernier temps de changement de focus
actuel ou est postérieur à l'heure actuelle du serveur X. Sinon, le
dernier temps de changement de focus est défini à l'heure spécifiée
(CurrentTime est remplacé par l'heure actuelle du serveur X).
XSetDeviceFocus provoque la génération d'événements DeviceFocusIn et
DeviceFocusOut par le serveur X.
Selon l'argument focus, ce qui suit se produit :
  * Si focus est None , tous les événements du périphérique sont
    ignorés jusqu'à ce qu'une nouvelle fenêtre de focus soit définie,
    et l'argument revert_to est ignoré.
  * Si focus est une fenêtre, elle devient la fenêtre de focus du
    périphérique. Si un événement de périphérique généré devait
    normalement être signalé à cette fenêtre ou à l'un de ses
    inférieurs, l'événement est signalé comme d'habitude. Sinon,
    l'événement est signalé par rapport à la fenêtre de focus.
  * Si focus est PointerRoot, la fenêtre de focus est considérée
    dynamiquement comme la fenêtre racine de l'écran sur lequel le
    pointeur se trouve à chaque événement du périphérique spécifié.
    Dans ce cas, l'argument revert_to est ignoré.
  * Si focus est FollowKeyboard, la fenêtre de focus est considérée
    dynamiquement comme la fenêtre à laquelle le focus clavier X est
    défini à chaque événement d'entrée.
La fenêtre de focus spécifiée doit être visible au moment où
XSetDeviceFocus est appelée, sinon une erreur BadMatch se produit. Si
la fenêtre de focus devient plus tard non visible, le serveur X
évalue l'argument revert_to pour déterminer la nouvelle fenêtre de
focus comme suit :
  * Si revert_to est RevertToParent, le focus est rétabli vers le
    parent (ou l'ancêtre visible le plus proche), et la nouvelle
    valeur revert_to est considérée comme RevertToNone.
  * Si revert_to est RevertToPointerRoot,
    RevertToFollowKeyboard, ou RevertToNone, le focus est rétabli
    respectivement vers PointerRoot, FollowKeyboard, ou None.
Lorsque le focus est rétabli, le serveur X génère des événements
DeviceFocusIn et DeviceFocusOut, mais le dernier temps de changement
de focus n'est pas affecté.
Les périphériques d'extension d'entrée ne sont pas tenus de prendre
en charge la capacité d'être focalisés. Tenter de définir le focus d'un
périphérique qui ne prend pas en charge cette requête entraînera une
erreur BadMatch. Le fait qu'un périphérique donné puisse prendre en
charge cette requête peut être déterminé par les informations
retournées par XOpenDevice. Pour les périphériques qui prennent en
charge le focus, XOpenDevice retournera une structure XInputClassInfo
avec le champ input_class égal à la constante FocusClass (définie dans
le fichier XI.h).
XSetDeviceFocus peut générer des erreurs BadDevice, BadMatch, BadValue
et BadWindow.
La requête XGetDeviceFocus retourne la fenêtre de focus et l'état de
focus actuel.
Tous les périphériques d'extension d'entrée ne peuvent pas être
focalisés. Tenter d'interroger l'état de focus d'un périphérique qui ne
peut pas être focalisé entraîne une erreur BadMatch. Un périphérique qui
peut être focalisé retourne des informations pour la classe d'entrée
Focus lors d'une requête XOpenDevice.
XGetDeviceFocus peut générer des erreurs BadDevice et BadMatch.

DIAGNOSTICS

BadDevice
       Un périphérique invalide a été spécifié. Le périphérique spécifié
       n'existe pas ou n'a pas été ouvert par ce client via
       XOpenInputDevice. Cette erreur peut également survenir si le
       périphérique spécifié est le clavier X ou le pointeur X.
BadValue
       Une valeur numérique se situe en dehors de la plage de valeurs
       acceptées par la requête. Sauf si une plage spécifique est
       spécifiée pour un argument, toute la plage définie par le type
       de l'argument est acceptée. Tout argument défini comme un
       ensemble d'alternatives peut générer cette erreur.
BadWindow
       Une valeur pour un argument Window ne nomme pas une fenêtre
       définie.
BadMatch
       Cette erreur peut survenir si une requête XGetDeviceFocus ou
       XSetDeviceFocus a été faite en spécifiant un périphérique que
       l'implémentation du serveur ne permet pas de focaliser.
