XGrabPointer(3) FONCTIONS XLIB XGrabPointer(3)

NOM

XGrabPointer, XUngrabPointer, XChangeActivePointerGrab - saisir le pointeur

SYNTAXE

int XGrabPointer(Display *display, Window grab_window, Bool owner_events, unsigned int event_mask, int pointer_mode, int keyboard_mode, Window confine_to, Cursor cursor, Time time);

int XUngrabPointer(Display *display, Time time);

int XChangeActivePointerGrab(Display *display, unsigned int event_mask, Cursor cursor, Time time);

ARGUMENTS

confine_to
Spécifie la fenêtre dans laquelle le pointeur doit être confiné ou None.
cursor
Spécifie le curseur qui doit être affiché pendant la saisie ou None.
display
Spécifie la connexion au serveur X.
event_mask
Spécifie quels événements du pointeur sont rapportés au client. Le masque est le OU inclusif binaire des bits de masque d'événements du pointeur valides.
grab_window
Spécifie la fenêtre de saisie.
keyboard_mode
Spécifie le traitement ultérieur des événements clavier. Vous pouvez passer GrabModeSync ou GrabModeAsync.
owner_events
Spécifie une valeur booléenne indiquant si les événements du pointeur doivent être rapportés comme d'habitude ou rapportés par rapport à la fenêtre de saisie s'ils sont sélectionnés par le masque d'événements.
pointer_mode
Spécifie le traitement ultérieur des événements du pointeur. Vous pouvez passer GrabModeSync ou GrabModeAsync.
time
Spécifie l'heure. Vous pouvez passer un horodatage ou CurrentTime.

DESCRIPTION

La fonction XGrabPointer saisit activement le contrôle du pointeur et retourne GrabSuccess si la saisie a réussi. Les événements du pointeur suivants ne sont rapportés qu'au client saisissant. XGrabPointer remplace toute saisie active du pointeur par ce client. Si owner_events est False, tous les événements du pointeur générés sont rapportés par rapport à grab_window et ne sont rapportés que s'ils sont sélectionnés par event_mask. Si owner_events est True et si un événement du pointeur généré serait normalement rapporté à ce client, il est rapporté comme d'habitude. Sinon, l'événement est rapporté par rapport à la fenêtre de saisie et n'est rapporté que s'il est sélectionné par event_mask. Pour l'une ou l'autre valeur de owner_events, les événements non rapportés sont ignorés.

Si pointer_mode est GrabModeAsync, le traitement des événements du pointeur continue comme d'habitude. Si le pointeur est actuellement gelé par ce client, le traitement des événements pour le pointeur est repris. Si pointer_mode est GrabModeSync, l'état du pointeur, tel que vu par les applications clientes, semble se figer, et le serveur X ne génère aucun autre événement de pointeur jusqu'à ce que le client saisissant appelle XAllowEvents ou jusqu'à ce que la saisie du pointeur soit libérée. Les changements réels du pointeur ne sont pas perdus pendant que le pointeur est gelé ; ils sont simplement mis en file d'attente dans le serveur pour un traitement ultérieur.

Si keyboard_mode est GrabModeAsync, le traitement des événements clavier n'est pas affecté par l'activation de la saisie. Si keyboard_mode est GrabModeSync, l'état du clavier, tel que vu par les applications clientes, semble se figer, et le serveur X ne génère aucun autre événement clavier jusqu'à ce que le client saisissant appelle XAllowEvents ou jusqu'à ce que la saisie du pointeur soit libérée. Les changements réels du clavier ne sont pas perdus pendant que le pointeur est gelé ; ils sont simplement mis en file d'attente dans le serveur pour un traitement ultérieur.

Si un curseur est spécifié, il est affiché quelle que soit la fenêtre dans laquelle se trouve le pointeur. Si None est spécifié, le curseur normal de cette fenêtre est affiché lorsque le pointeur se trouve dans grab_window ou l'une de ses sous-fenêtres ; sinon, le curseur de grab_window est affiché.

Si une fenêtre de confinement (confine_to) est spécifiée, le pointeur est restreint à rester à l'intérieur de cette fenêtre. La fenêtre de confinement n'a pas besoin d'avoir de relation avec la fenêtre de saisie. Si le pointeur ne se trouve pas initialement dans la fenêtre de confinement, il est automatiquement déplacé vers le bord le plus proche juste avant que la saisie ne s'active et que les événements d'entrée/sortie ne soient générés comme d'habitude. Si la fenêtre de confinement est reconfigurée ultérieurement, le pointeur est automatiquement déplacé, si nécessaire, pour le maintenir à l'intérieur de la fenêtre.

L'argument time permet d'éviter certaines situations qui se produisent si les applications mettent du temps à répondre ou s'il y a de longs retards réseau. Considérez une situation où vous avez deux applications, toutes deux saisissent normalement le pointeur lorsqu'elles sont cliquées. Si les deux applications spécifient l'horodatage de l'événement, la deuxième application peut se réveiller plus rapidement et réussir à saisir le pointeur avant la première application. La première application recevra alors une indication que l'autre application a saisi le pointeur avant que sa requête ne soit traitée.

XGrabPointer génère des événements EnterNotify et LeaveNotify.

Soit si la fenêtre grab_window ou la fenêtre de confinement n'est pas visible, soit si la fenêtre de confinement se trouve entièrement en dehors des limites de la fenêtre racine, XGrabPointer échoue et retourne GrabNotViewable. Si le pointeur est activement saisi par un autre client, il échoue et retourne AlreadyGrabbed. Si le pointeur est gelé par une saisie active d'un autre client, il échoue et retourne GrabFrozen. Si l'heure spécifiée est antérieure à la dernière heure de saisie du pointeur ou ultérieure à l'heure actuelle du serveur X, il échoue et retourne GrabInvalidTime. Sinon, la dernière heure de saisie du pointeur est définie à l'heure spécifiée (CurrentTime est remplacé par l'heure actuelle du serveur X).

XGrabPointer peut générer des erreurs BadCursor, BadValue et BadWindow.

La fonction XUngrabPointer libère le pointeur et tous les événements mis en file d'attente si ce client a activement saisi le pointeur depuis XGrabPointer, XGrabButton, ou depuis une pression de bouton normale. XUngrabPointer ne libère pas le pointeur si l'heure spécifiée est antérieure à la dernière heure de saisie du pointeur ou est ultérieure à l'heure actuelle du serveur X. Elle génère également des événements EnterNotify et LeaveNotify. Le serveur X effectue automatiquement une requête UngrabPointer si la fenêtre d'événement ou la fenêtre de confinement pour une saisie active du pointeur devient non visible ou si la reconfiguration de la fenêtre fait que la fenêtre de confinement se trouve entièrement en dehors des limites de la fenêtre racine.

La fonction XChangeActivePointerGrab modifie les paramètres dynamiques spécifiés si le pointeur est activement saisi par le client et si l'heure spécifiée n'est pas antérieure à l'heure de dernière saisie du pointeur et n'est pas postérieure à l'heure actuelle du serveur X. Cette fonction n'a aucun effet sur les paramètres passifs d'un XGrabButton. L'interprétation d'event_mask et de cursor est la même que celle décrite dans XGrabPointer.

XChangeActivePointerGrab peut générer une erreur BadCursor et BadValue.

DIAGNOSTICS

BadCursor
Une valeur pour un argument Cursor ne nomme pas un Cursor défini.
BadValue
Une valeur numérique se situe en dehors de la plage de valeurs acceptées par la requête. Sauf si une plage spécifique est spécifiée pour un argument, la plage complète définie par le type de l'argument est acceptée. Tout argument défini comme un ensemble d'alternatives peut générer cette erreur.
BadWindow
Une valeur pour un argument Window ne nomme pas une Window définie.
