NOM

Tableaux Judy - Fonctions de bibliothèque C pour créer et accéder à des tableaux dynamiques

SYNOPSIS

Judy1  - mappe un Index (mot) à un bit
JudyL  - mappe un Index (mot) à une Valeur (mot/pointeur)
JudySL - mappe un Index (chaîne terminée par un caractère nul) à une Valeur
JudyHS - mappe un Index (tableau d'octets) de Longueur à une Valeur

DESCRIPTION

La famille de fonctions Judy prend en charge les tableaux entièrement dynamiques. Ces tableaux peuvent être indexés par un mot de 32 ou 64 bits (selon la taille du mot du processeur), une chaîne terminée par un caractère nul ou un tableau d'octets plus une longueur. Un tableau dynamique (peuplé sparsement) peut également être considéré comme une fonction de mapping ou une mémoire associative.

Un Word_t est un typedef unsigned long int dans Judy.h et doit avoir la même taille que sizeof(void *), c'est-à-dire un pointeur.

Fonctions Judy1 : Index est un Word_t et Value est juste un bit ou simplement un indicateur que l'Index est présent ou absent du tableau. Cela peut être considéré comme un énorme bitmap.

Fonctions JudyL : Index est un Word_t et Value est un Word_t. Cela fait de JudyL un mappeur pur mot-à-mot/pointeur. JudySL et JudyHL sont basés sur cette propriété de JudyL.

Fonctions JudySL : Index est une chaîne terminée par un caractère nul et Value est un Word_t.

Fonctions JudyHS : Index est un tableau d'octets de longueur : Length. Value est un Word_t. Cette nouvelle addition (mai 2004) à Judy est un hybride utilisant les meilleures caractéristiques des méthodes de hachage et de Judy. L'auteur pense que JudyHS est un bon remplacement pour une méthode de hachage lorsque le redimensionnement de la table de hachage est effectué lors de la croissance de la population. Une méthode de hachage correctement réglée avec une taille de table de hachage statique et une population est imbattable en termes de vitesse. Cependant, JudyHS sera plus performant qu'une méthode de hachage avec des populations plus petites et plus grandes que la taille optimale de la table de hachage. JudyHS n'a pas de cas de performance dégénérée où la connaissance de l'algorithme de hachage peut être exploitée. (C'est-à-dire que JudyHS n'utilise pas de liste chaînée pour gérer les collisions de hachage, il utilise un arbre de tableaux JudyL et une taille de table de hachage virtuelle de 4 milliards).

Les tableaux Judy sont à la fois rapides et écoénergétiques en mémoire, sans réglage ni configuration requis, sur une large gamme de types d'ensembles d'index (séquentiels, périodiques, groupés, aléatoires). La vitesse et l'utilisation de la mémoire de Judy sont généralement meilleures que d'autres modèles de stockage de données tels que les skiplists, les listes chaînées, les arbres binaires, ternaires, b-trees, ou même le hachage, et s'améliorent avec de très grands ensembles de données.

Un tableau Judy est créé simplement en définissant un pointeur nul, puis en stockant (insérant) le premier élément dans le tableau sous ce pointeur. La mémoire utilisée par un tableau Judy est presque proportionnelle à la population (nombre d'éléments).

Judy a deux interfaces de programmation d'applications (API) : une interface de macros C et une interface d'appels de fonctions. Parce que les formes de macros sont parfois plus rapides et ont une interface de gestion des erreurs plus simple que les fonctions équivalentes, elles constituent le moyen préféré d'utiliser les fonctions Judy.

Étant donné qu'un tableau Judy initial (vide) est représenté par un pointeur nul, il est possible de construire un tableau de tableaux Judy. En d'autres termes, les Valeurs d'un tableau Judy (sauf Judy1) peuvent être des pointeurs vers d'autres tableaux Judy. Cela rend très simple la construction d'un tableau avec un nombre arbitraire de dimensions ou de tailles d'Index. (JudySL et JudyHS sont implémentés en utilisant JudyL de cette manière).

ERREURS

Beaucoup de réflexion (et de temps) ont été consacrées à rendre la gestion des erreurs dans Judy simple, tout en maintenant la flexibilité et la capacité. La gestion des erreurs est un sujet très ennuyeux, même à écrire. Lisez donc cette courte section et utilisez la deuxième méthode recommandée. Elle génère le code le plus rapide, utilise le moins de mémoire et nécessite d'écrire du code supplémentaire uniquement pour les fonctions d'insertion/suppression. De plus, elle est compatible avec les deux autres méthodes. Cette méthode est destinée au code de production qui pourrait vouloir gérer les échecs de malloc() différemment du défaut Judy. Si la méthode par défaut de Judy pour gérer les échecs de malloc() vous convient, utilisez la première méthode.

Il existe deux (2) catégories de retours d'erreur Judy, (ou pour tout ADT dynamique) :

1) Erreurs de programmation utilisateur (bugs) telles que corruption de mémoire ou pointeurs invalides.
2) Manque de mémoire (échec de malloc()) lors de l'Insertion (Set) ou de la Delete (Unset) lors de la modification d'un tableau Judy. Tous les appels à insert et delete n'appellent pas malloc(), ils peuvent donc réussir même lorsqu'un appel à malloc() échouerait.

Il existe environ trois (3) méthodes pour gérer les erreurs lors de l'utilisation des macros :

1) Méthode de gestion des erreurs par défaut

Par défaut, les messages d'erreur sont imprimés sur stderr, par exemple :

Fichier 'VotreFichierC.c', ligne 1234: JudyLIns(), JU_ERRNO_* == 2, ID == 321
Cela indique qu'une erreur s'est produite dans la fonction JudyLIns() à la ligne 321. La ligne 1234 est la ligne dans 'VotreFichierC.c' où l'appel JLI() a échoué. JU_ERRNO_* == 2 est égal à JU_ERRNO_NOMEM (tel que défini dans le fichier Judy.h). Le numéro ID indique le numéro de ligne source dans la fonction d'où provient l'erreur. Votre programme se termine ensuite avec un exit(1);. Par défaut, les deux catégories de retours d'erreur Judy sont imprimées de cette manière. (L'ID == 321 est pour les têtes brûlées qui veulent plus de détails ou pour déboguer Judy elle-même.)

2) Désactiver la gestion des erreurs par macro

Lorsque votre programme est "sans bugs", les seules erreurs renvoyées devraient être des échecs de malloc(). Par conséquent, toutes les erreurs retournées peuvent être traitées comme un échec de malloc(). En utilisant le #define ci-dessous, tous les tests et l'impression d'erreurs sont désactivés. Du code supplémentaire doit être ajouté au code qui peut avoir des échecs de malloc(). Judy a été conçu pour laisser les mêmes données dans le tableau avant l'appel si un échec de malloc() se produit. (Lors des tests de Judy, nous avons trouvé très peu de malloc()/OS exempts de bugs après un échec de malloc(). Parfois, il fallait des semaines pour le découvrir car la plupart des systèmes entrent dans une frénésie de pagination avant de manquer de mémoire).

#define JUDYERROR_NOTEST 1
(dans le code de votre programme), ou 
cc -DJUDYERROR_NOTEST votrefichiercode -lJudy
(sur votre ligne de commande). 
// Ceci est un exemple de la façon de programmer u
méthode sing deux (2). 
JLI(PValue, PLArray, Index);
if (PValue == PJERR) goto out_of_memory_handling
; 
JLD(RC_int, PLArray, Index);
if (RC_int == JERR) goto out_of_memory_handling
; 
J1S(RC_int, P1Array, Index);
if (RC_int == JERR) goto out_of_memory_handling
; 
J1U(RC_int, P1Array, Index);
if (RC_int == JERR) goto out_of_memory_handling;
Note
: Sans la définition de 'JUDYERROR_NOTEST', le 'goto out_of_memory_handling' ne sera jamais exécuté et sera optimisé par le compilateur. La méthode par défaut sera utilisée -- La macro affichera des informations d'erreur si une erreur se produit comme expliqué ci-dessus.

Avec 'JUDYERROR_NOTEST' défini, le 'goto out_of_memory_handling' sera exécuté lorsqu'une erreur se produit -- ce qui ne devrait se produire que lorsque malloc()

échoue.

3) Méthode de macro JUDYERROR() spécifiée par

l'utilisateur

La macro JUDYERROR() (dans Judy.h) offre une flexibilité pour gérer les retours d'erreur selon les besoins de votre programme tout en utilisant toujours les macros de tableaux Judy au lieu d'appels de fonctions. Vous pouvez utiliser une macro JUDYERROR() différente pour répondre à vos besoins. L'exemple suivant est une alternative possible à la méthode par défaut. Elle est utilisée pour distinguer entre les deux types d'erreurs (décrits ci-dessus), et tester explicitement pour les erreurs JU_ERRNO_NOMEM restantes possibles dans votre

programme. 
// Ceci est un exemple d'API de macro Judy pour continuer lorsque la mémoire est épuisée
// et imprimer et exit(1) lorsque toute autre erreur se
produit. 
#ifndef JUDYERROR_NOTEST
#include <stdio.h>  // nécessaire pour
fprintf() 
// Ceci est la macro que les API de macro Judy utilisent pour les codes de retour de -1
: 
#define JUDYERROR(CallerFile, CallerLine, JudyFunc, JudyErrno, JudyErrID) \
{                                                                         \
    if ((JudyErrno) != JU_ERRNO_NOMEM) /* ! un échec de malloc() */       \
    {                                                                     \
        (void) fprintf(stderr, "File '%s', line %d: %s(), "               \
            "JU_ERRNO_* == %d, ID == %d\n",                               \
            CallerFile, CallerLine,                                       \
            JudyFunc, JudyErrno, JudyErrID);                              \
        exit(1);                                                          \
    }                                                                     \
}
#endif // JUDYERROR_NOTEST non défini
Cette macro de gestion d'erreur doit être incluse avant la déclaration #include <Judy.h> dans votre
programme.
