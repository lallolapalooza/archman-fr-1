NOM

JSON::Syck - JSON est YAML (mais envisagez d'utiliser JSON::XS à la place !)

SYNOPSIS

use JSON::Syck; # pas d'exportations par défaut 
my $data = JSON::Syck::Load($json);
my $json = JSON::Syck::Dump($data);
# $file peut être un objet IO, ou un nom de fichier
my $data = JSON::Syck::LoadFile($file);
JSON::Syck::DumpFile($file, $data);
# Dump dans un tampon préexistant
my $json;
JSON::Syck::DumpInto(\$json, $data);

DESCRIPTION

JSON::Syck est une implémentation syck de l'analyse et de la génération JSON. Parce que JSON est YAML (http://redhanded.hobix.com/inspect/yamlIsJson.html), l'utilisation de syck vous offre un analyseur et un dump rapide et efficace en mémoire pour la représentation des données JSON.

Cependant, un module plus récent, JSON::XS, a depuis émergé. Il est plus flexible, efficace et robuste, alors veuillez envisager de l'utiliser à la place de ce module.

DIFFÉRENCE AVEC JSON

Vous pourriez vouloir connaître la différence entre le module JSON et celui-ci.

Puisque JSON est un module pure Perl et JSON::Syck est basé sur libsyck, JSON::Syck est censé être très rapide et efficace en mémoire. Voir le tableau de benchmark de chansen à http://idisk.mac.com/christian.hansen/Public/perl/serialize.pl

JSON.pm est livré avec des dizaines de façons de faire la même chose et de nombreuses options, tandis que JSON::Syck n'en a pas. Il n'y a que "Load" et "Dump".

Oh, et JSON::Syck n'utilise pas les noms de méthodes camelCase :-)

RÉFÉRENCES

RÉFÉRENCE SCALAIRE

Pour l'instant, lorsque vous passez une référence scalaire à JSON::Syck, il la déréférence pour obtenir la valeur scalaire réelle.

JSON::Syck lève une exception lorsque vous passez des références circulaires.

Si vous souhaitez sérialiser des éléments auto-référencés, vous devriez utiliser YAML qui le prend en charge.

RÉFÉRENCE DE SOUS-ROUTINE

Lorsque vous passez une référence de sous-routine, JSON::Syck la dump en tant que null.

INDICATEURS UTF-8

Par défaut, ce module ne touche à aucun des indicateurs utf-8 définis dans les chaînes, et suppose que les octets UTF-8 sont passés et émis.

Cependant, lorsque vous définissez $JSON::Syck::ImplicitUnicode à 1, ce module décode correctement les binaires UTF-8 et définit l'indicateur UTF-8 partout, comme suit :

JSON (octets UTF-8)   => Perl (avec indicateur UTF-8)
JSON (avec indicateur UTF-8) => Perl (avec indicateur UTF-8)
Perl (octets UTF-8)   => JSON (avec indicateur UTF-8)
Perl (avec indicateur UTF-8) => JSON (avec indicateur UTF-8)

Par défaut, JSON::Syck::Dump ne parcourra que jusqu'à 512 niveaux d'une structure de données afin d'éviter une boucle infinie lorsqu'il est confronté à une référence circulaire.

Cependant, vous pouvez définir $JSON::Syck::MaxLevels à une valeur plus grande si vous avez des structures très complexes.

Malheureusement, il n'y a pas de moyen implicite de dumper des données Perl avec l'indicateur UTF-8 en JSON encodé en utf-8. Pour ce faire, utilisez simplement le module Encode, par exemple :

use Encode;
use JSON::Syck qw(Dump);
my $json = encode_utf8( Dump($data) );

Alternativement, vous pouvez utiliser Encode::JavaScript::UCS pour encoder les chaînes Unicode sous la forme %uXXXX.

use Encode;
use Encode::JavaScript::UCS;
use JSON::Syck qw(Dump);
my $json_unicode_escaped = encode( 'JavaScript-UCS', Dump($data) );

GUILLEMETS

Conformément à la spécification JSON, toutes les chaînes JSON doivent être entre guillemets doubles. Cependant, lors de l'intégration de JavaScript dans des attributs HTML, il peut être plus pratique d'utiliser des guillemets simples.

Définir $JSON::Syck::SingleQuote à 1 permettra à la fois à "Dump" et "Load" d'attendre des littéraux de chaîne entre guillemets simples.

BOGUES

Dumping dans des variables liées (ou autres variables magiques) avec "DumpInto" pourrait ne pas fonctionner correctement dans tous les cas.

Lors du dump avec "DumpFile", un certain espacement pourrait être incorrect et $JSON::Syck::SingleQuote pourrait être mal géré.
