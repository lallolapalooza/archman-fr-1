La vitesse et l'utilisation mémoire de Judy sont généralement meilleures que d'autres modèles de stockage de données tels que les skiplists, les listes chaînées, les arbres binaires, ternaires, b-arbres, ou même le hachage, et s'améliorent avec de très grands ensembles de données. Un tableau Judy est créé simplement en définissant un pointeur nul puis en stockant (insérant) le premier élément dans le tableau sous ce pointeur. La mémoire utilisée par un tableau Judy est presque proportionnelle à la population (nombre d'éléments). Judy a deux interfaces de programmation d'application (API) : une interface de macro C et une interface d'appel de fonction. Comme les formes de macro sont parfois plus rapides et ont une interface de gestion d'erreur plus simple que les fonctions équivalentes, elles sont la façon

Puisqu'un tableau Judy initial (vide) est représenté par un pointeur nul, il est possible de construire un tableau de tableaux Judy. En d'autres termes, les Valeurs d'un tableau Judy (sauf Judy1) peuvent être des pointeurs vers d'autres tableaux Judy. Cela rend très simple la construction d'un tableau avec un nombre arbitraire de dimensions ou de tailles d'Index . (JudySL et JudyHS sont implémentés en utilisant JudyL de cette façon). La gestion des erreurs est un sujet très ennuyeux, même à écrire. Lisez donc cette courte section et utilisez la deuxième méthode recommandée. Remarque : Sans la définition de 'JUDYERROR_NOTEST', le 'goto out_of_memory_handling' ne sera jamais exécuté et sera optimisé par le compilateur. La méthode par défaut sera utilisée -- la macro affichera les informations d'erreur si une erreur se produit comme expliqué ci-dessus.

Avec 'JUDYERROR_NOTEST' défini, le 'goto out_of_memory_handling' sera exécuté lorsqu'une erreur se produit -- ce qui ne devrait se produire que lorsque malloc() échoue.

3) Méthode de macro JUDYERROR() spécifiée par l'utilisateur

La JUDYERROR() macro (dans Judy.h) offre de la flexibilité pour gérer les retours d'erreur selon les besoins de votre programme tout en utilisant toujours les macros de tableaux Judy au lieu d'appels de fonctions. Vous pouvez utiliser une macro JUDYERROR() différente pour répondre à vos besoins. L'exemple suivant est une alternative possible à la méthode par défaut. Elle est utilisée pour distinguer entre les deux types d'erreurs (décrits ci-dessus), et tester explicitement pour les erreurs JU_ERRNO_NOMEM restantes possibles dans votre programme.

// Ceci est un exemple de macro API Judy pour continuer en cas de mémoire insuffisante
// et imprimer et exit(1) lorsque toute autre erreur se produit.
#ifndef JUDYERROR_NOTEST
#include <stdio.h>  // nécessaire pour fprintf()
// Ceci est la macro que les API macro Judy utilisent pour les codes de retour de -1 :
#define JUDYERROR(CallerFile, CallerLine, JudyFunc, JudyErrno, JudyErrID) \
{                                                                         \
    if ((JudyErrno) != JU_ERRNO_NOMEM) /* ! un échec de malloc() */       \
    {                                                                     \
        (void) fprintf(stderr, "File '%s', line %d: %s(), "               \
            "JU_ERRNO_* == %d, ID == %d\n",                               \
            CallerFile, CallerLine,                                       \
            JudyFunc, JudyErrno, JudyErrID);                              \
        exit(1);                                                          \
    }                                                                     \
}
#endif // JUDYERROR_NOTEST non défini
Cette macro de gestion d'erreurs doit être incluse avant la #include <Judy.h> instruction dans votre programme.
