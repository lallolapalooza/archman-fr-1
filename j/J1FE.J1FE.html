DESCRIPTION La famille de fonctions Judy prend en charge des tableaux entièrement dynamiques. Ces tableaux peuvent être indexés par un mot de 32 ou 64 bits (selon la taille du mot du processeur), une chaîne terminée par un caractère nul ou un tableau d'octets avec une longueur. Un tableau dynamique (peuplé de manière sparse) peut aussi être considéré comme une fonction de correspondance ou une mémoire associative.
Un Word_t est un typedef unsigned long int dans Judy.h et doit être de la même taille que sizeof(void *), c'est-à-dire un pointeur.
Fonctions Judy1 : Index est un Word_t et Valeur est simplement un bit ou un simple indicateur qui indique si l'
Index est présent ou absent du tableau. Cela peut être considéré comme un énorme bitmap. Fonctions

Length. Valeur est un Word_t. Cette nouvelle addition (mai 2004) à Judy est un hybride utilisant les meilleures caractéristiques des méthodes de hachage et de Judy. L'auteur pense que JudyHS est un bon remplacement pour une méthode de hachage lorsque le redimensionnement de la table de hachage est effectué lors de la croissance de la population. Une méthode de hachage correctement réglée avec une taille de table de hachage statique et une population est imbattable en vitesse. Cependant, JudyHS sera plus performant qu'une méthode de hachage avec des populations plus petites et plus grandes que la taille optimale de la table de hachage. JudyHS n'a pas de cas de performance dégénéré où la connaissance de l'algorithme de hachage peut être exploitée. (C'est-à-dire que JudyHS n'utilise pas de liste chaînée pour gérer les collisions de hachage, il utilise un arbre de tableaux JudyL et une taille de table de hachage virtuelle de 4

milliards).

Les tableaux Judy sont à la fois efficaces en vitesse et en mémoire, sans réglage ni configuration requis, à travers une large gamme de types d'ensembles d'index (séquentiels, périodiques, groupés, aléatoires). La vitesse et l'utilisation mémoire de Judy sont généralement meilleures que d'autres modèles de stockage de données tels que les skiplists, les listes chaînées, les arbres binaires, ternaires, b-arbres, ou même le hachage, et s'améliorent avec de très grands ensembles de données. Un tableau Judy est créé simplement en définissant un pointeur nul puis en stockant (insérant) le premier élément dans le tableau sous ce pointeur. La mémoire utilisée par un tableau Judy est presque proportionnelle à la population (nombre d'éléments). Judy a deux interfaces de programmation d'application (API) : une interface de macro C et une interface d'appel de fonction. Parce que les formes de macro sont parfois plus rapides et ont une interface de gestion d'erreurs plus simple que les fonctions équivalentes, elles sont la façon

préférée d'utiliser les fonctions Judy.

Puisqu'un tableau Judy initial (vide) est représenté par un pointeur nul, il est possible de construire un tableau de tableaux Judy. En d'autres termes, les Valeurs d'un tableau Judy (sauf Judy1) peuvent être des pointeurs vers d'autres tableaux Judy. Cela rend très simple la construction d'un tableau avec un nombre arbitraire de dimensions ou de tailles d'Index. (JudySL et JudyHS sont implémentés en utilisant JudyL de cette manière). 3) Méthode de macro JUDYERROR() spécifiée par

l'utilisateur

La macro JUDYERROR() (dans Judy.h) fournit la flexibilité nécessaire pour gérer les retours d'erreur selon les besoins de votre programme tout en utilisant les macros de tableau Judy au lieu d'appels de fonctions. Vous pouvez utiliser une macro JUDYERROR() différente pour répondre à vos besoins. L'exemple suivant est une alternative possible à la méthode par défaut. Elle est utilisée pour distinguer entre les deux types d'erreurs (décrits ci-dessus), et tester explicitement les erreurs JU_ERRNO_NOMEM restantes possibles dans votre

programme. 
// Ceci est un exemple de macro API Judy pour continuer en cas de manque de mémoire
// et imprimer et exit(1) lorsqu'une autre erreur se
produit. 
#ifndef JUDYERROR_NOTEST
#include <stdio.h>  // nécessaire pour
fprintf() 
// Ceci est la macro que les API macro Judy utilisent pour les codes de retour de -1
: 
#define JUDYERROR(CallerFile, CallerLine, JudyFunc, JudyErrno, JudyErrID) \
{                                                                         \
    if ((JudyErrno) != JU_ERRNO_NOMEM) /* ! échec de malloc() */          \
    {                                                                     \
        (void) fprintf(stderr, "File '%s', line %d: %s(), "               \
            "JU_ERRNO_* == %d, ID == %d\n",                               \
            CallerFile, CallerLine,                                       \
            JudyFunc, JudyErrno, JudyErrID);                              \
        exit(1);                                                          \
    }                                                                     \
}
#endif // JUDYERROR_NOTEST non défini
Cette macro de gestion d'erreurs doit être incluse avant la #include <Judy.h> dans votre
programme.
