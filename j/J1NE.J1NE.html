NOM

Judy arrays - Fonctions de bibliothèque C pour la création et l'accès aux tableaux dynamiques

SYNOPIS

Judy1  - associe un Index (mot) à un bit
JudyL  - associe un Index (mot) à une Valeur (mot/pointeur)
JudySL - associe un Index (chaîne de caractères terminée par un nul) à une Valeur
JudyHS - associe un Index (tableau d'octets) de Longueur à une Valeur

DESCRIPTION

La famille de fonctions Judy prend en charge les tableaux entièrement dynamiques. Ces tableaux peuvent être indexés par un mot de 32 ou 64 bits (selon la taille du mot du processeur), une chaîne terminée par un nul ou un tableau d'octets plus une longueur. Un tableau dynamique (peu peuplé) peut également être considéré comme une fonction de mappage ou une mémoire associative.

Un Word_t est un typedef unsigned long int dans Judy.h et doit avoir la même taille que sizeof(void *), c'est-à-dire un pointeur.

Fonctions Judy1 : L'Index est un Word_t et la Valeur est juste un bit ou simplement un indicateur que l'Index est présent ou absent du tableau. Ceci peut être considéré comme une énorme bitmap.

Fonctions JudyL : L'Index est un Word_t et la Valeur est un Word_t. Cela fait de JudyL un simple mappeur mot-à-mot/pointeur. JudySL et JudyHL sont basés sur cette propriété de JudyL.

Fonctions JudySL : L'Index est une chaîne terminée par un nul et la Valeur est un Word_t.

Fonctions JudyHS : L'Index est un tableau d'octets de longueur : Length. La Valeur est un Word_t. Ce nouvel ajout (mai 2004) à Judy est un hybride utilisant les meilleures caractéristiques des méthodes de hachage et de Judy. L'auteur estime que JudyHS est un bon remplacement pour une méthode de hachage lorsque le redimensionnement de la table de hachage est effectué pendant la croissance de la population. Une méthode de hachage correctement réglée avec une taille de table de hachage statique et une population est imbattable en termes de vitesse. Cependant, JudyHS sera plus performant qu'une méthode de hachage avec des populations plus petites et plus grandes que la taille optimale de la table de hachage. JudyHS n'a pas de cas de performance dégénérée où la connaissance de l'algorithme de hachage peut être exploitée. (C'est-à-dire que JudyHS n'utilise pas de liste chaînée pour gérer les collisions de hachage, il utilise un arbre de tableaux JudyL et une taille de table de hachage virtuelle de 4 milliards).

Les tableaux Judy sont à la fois rapides et économes en mémoire, sans nécessiter de réglage ou de configuration, pour une large gamme de types d'ensembles d'index (séquentiels, périodiques, groupés, aléatoires). La vitesse et l'utilisation de la mémoire de Judy sont généralement meilleures que celles d'autres modèles de stockage de données tels que les skiplists, les listes chaînées, les arbres binaires, ternaires, b-trees, ou même le hachage, et s'améliorent avec de très grands ensembles de données.

Un tableau Judy est créé simplement en définissant un pointeur nul, puis en stockant (en insérant) le premier élément dans le tableau sous ce pointeur. La mémoire utilisée par un tableau Judy est presque proportionnelle à la population (nombre d'éléments).

Judy a deux interfaces de programmation d'application (API) : une interface de macros C et une interface d'appel de fonction. Parce que les formes de macros sont parfois plus rapides et ont une interface de gestion des erreurs plus simple que les fonctions équivalentes, elles sont la manière préférée d'utiliser les fonctions Judy.

Puisqu'un tableau Judy initial (vide) est représenté par un pointeur nul, il est possible de construire un tableau de tableaux Judy. Autrement dit, les Valeurs d'un tableau Judy (sauf Judy1) peuvent être des pointeurs vers d'autres tableaux Judy. Cela rend très simple la construction d'un tableau avec un nombre arbitraire de dimensions ou de tailles d'Index. (JudySL et JudyHS sont implémentés en utilisant JudyL de cette manière).

ERREURS

Beaucoup de réflexion (et de temps) ont été consacrées à rendre la gestion des erreurs dans Judy simple, tout en maintenant la flexibilité et les capacités. La gestion des erreurs est un sujet très ennuyeux, même à écrire. Lisez donc cette courte section et utilisez la deuxième méthode recommandée. Elle génère le code le plus rapide, utilise le moins de mémoire et vous oblige à écrire du code supplémentaire uniquement pour les fonctions d'insertion/suppression. De plus, elle est compatible avec les deux autres méthodes. Cette méthode est destinée au code de production qui pourrait vouloir gérer les échecs de malloc() différemment de la valeur par défaut de Judy. Si la méthode par défaut de Judy pour gérer les échecs de malloc() est acceptable, utilisez la première méthode.

Il existe deux (2) catégories de retours d'erreur Judy, (ou pour tout ADT dynamique) :

1) Erreurs de programmation utilisateur (bugs) telles que corruption de mémoire ou pointeurs invalides.
2) Manque de mémoire (échec de malloc()) lors de l'Insertion (Set) ou de la Suppression (Unset) lors de la modification d'un tableau Judy. Tous les appels d'insertion et de suppression n'appellent pas malloc(), ils peuvent donc réussir même lorsqu'un appel à malloc() échouerait.

Il existe environ trois (3) méthodes de gestion des erreurs lors de l'utilisation des macros :

1) MÉTHODE DE GESTION DES ERREURS PAR DÉFAUT

Par défaut, les messages d'erreur sont imprimés sur stderr, par exemple :

Fichier 'YourCfile.c', ligne 1234 : JudyLIns(), JU_ERRNO_* == 2, ID == 321
Ceci indique qu'une erreur s'est produite dans la fonction JudyLIns() à la ligne 321. La ligne 1234 est la ligne dans 'YourCfile.c' où l'appel JLI() a échoué. JU_ERRNO_* == 2 est égal à JU_ERRNO_NOMEM (tel que défini dans le fichier Judy.h). Le numéro d'ID indique le numéro de la ligne source dans la fonction d'où provient l'erreur. Votre programme se termine alors avec un exit(1);. Par défaut, les deux catégories de retours d'erreur Judy sont imprimées de cette manière. (L'ID == 321 est pour les acharnés qui veulent plus de détails ou pour le débogage de Judy lui-même.)

2) DÉSACTIVER LA GESTION DES ERREURS DES MACROS

Lorsque votre programme est « sans bug », les seules erreurs retournées devraient être des échecs de malloc(). Par conséquent, tous les retours d'erreur peuvent être traités comme un échec de malloc(). En utilisant le #define ci-dessous, tous les tests et l'impression des erreurs sont désactivés. Du code supplémentaire doit être ajouté au code susceptible de subir des échecs de malloc(). Judy a été conçu pour laisser les mêmes données dans le tableau avant l'appel si un échec de malloc() se produit. (Lors des tests de Judy, nous avons trouvé très peu de malloc()/OS sans bugs après un échec de malloc(). Parfois, il fallait des semaines pour le découvrir car la plupart des systèmes entrent dans une frénésie de pagination avant de manquer de mémoire).

#define JUDYERROR_NOTEST 1
(dans le code de votre programme), ou 
cc -DJUDYERROR_NOTEST votre_fichier_source -lJudy
(sur votre ligne de commande). 
// Ceci est un exemple de la façon de programmer
en utilisant la méthode deux (2). 
JLI(PValue, PLArray, Index);
if (PValue == PJERR) goto out_of_memory_handling
; 
JLD(RC_int, PLArray, Index);
if (RC_int == JERR) goto out_of_memory_handling
; 
J1S(RC_int, P1Array, Index);
if (RC_int == JERR) goto out_of_memory_handling
; 
J1U(RC_int, P1Array, Index);
if (RC_int == JERR) goto out_of_memory_handling;
Note
: Sans 'JUDYERROR_NOTEST' défini, le 'goto out_of_memory_handling' ne sera jamais exécuté et sera optimisé par le compilateur. La méthode par défaut sera utilisée -- La macro affichera les informations d'erreur si une erreur se produit, comme expliqué ci-dessus.

Avec 'JUDYERROR_NOTEST' défini, le 'goto out_of_memory_handling' sera exécuté lorsqu'une erreur se produit -- ce qui ne devrait se produire que lorsque malloc()

échoue.

3) Méthode de macro JUDYERROR() spécifiée par

l'utilisateur

La macro JUDYERROR() (dans Judy.h) offre la flexibilité pour gérer les retours d'erreur selon les besoins de votre programme tout en utilisant toujours les macros de tableaux Judy au lieu d'appels de fonctions. Vous pouvez utiliser une macro JUDYERROR() différente pour répondre à vos besoins. L'exemple suivant est une alternative possible à la méthode par défaut. Elle est utilisée pour distinguer entre les deux types d'erreurs (décrits ci-dessus), et tester explicitement les erreurs JU_ERRNO_NOMEM restantes possibles dans votre

programme. 
// Ceci est un exemple de l'API de macro Judy pour continuer en cas de mémoire insuffisante
// et imprimer et exit(1) lorsque toute autre erreur se
produit. 
#ifndef JUDYERROR_NOTEST
#include <stdio.h>  // nécessaire pour
fprintf() 
// Ceci est la macro que les API de macro Judy utilisent pour les codes de retour de -1
: 
#define JUDYERROR(CallerFile, CallerLine, JudyFunc, JudyErrno, JudyErrID) \
{                                                                         \
    if ((JudyErrno) != JU_ERRNO_NOMEM) /* ! un échec de malloc() */       \
    {                                                                     \
        (void) fprintf(stderr, "File '%s', line %d: %s(), "               \
            "JU_ERRNO_* == %d, ID == %d\n",                               \
            CallerFile, CallerLine,                                       \
            JudyFunc, JudyErrno, JudyErrID);                              \
        exit(1);                                                          \
    }                                                                     \
}
#endif // JUDYERROR_NOTEST non défini
Cette macro de gestion d'erreurs doit être incluse avant la #include <Judy.h> dans votre
programme.
