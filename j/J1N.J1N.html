NAME

Judy(3) - Fonctions C de la bibliothèque pour créer et accéder à des tableaux dynamiques

SYNOPSIS

Judy1  - mappe un Index (mot) à un bit
JudyL  - mappe un Index (mot) à une Valeur (mot/pointeur)
JudySL - mappe un Index (chaîne de caractères terminée par nul) à une Valeur
JudyHS - mappe un Index (tableau d'octets de longueur) à une Valeur

DESCRIPTION

Les fonctions de la famille Judy prennent en charge des tableaux dynamiques complets. Ces tableaux peuvent être indexés par un mot de 32 ou 64 bits (selon la taille de mot du processeur), une chaîne de caractères terminée par nul, ou un tableau d'octets plus une longueur. Un tableau dynamique (donné de manière éparse) peut également être considéré comme une fonction de mappage ou une mémoire associative.

Un Word_t est un typedef unsigned long int dans Judy.h et doit être de la même taille que sizeof(void *), c'est-à-dire un pointeur.

Fonctions Judy1 : Index est un Word_t et Valeur est juste un bit ou simplement un indicateur que Index est présent ou non dans le tableau. Ceci peut être considéré comme une grande table de bits.

Fonctions JudyL : Index est un Word_t et Valeur est un Word_t. Ceci fait de JudyL un mappeur de Word_t à Word_t ou pointeur. JudySL et JudyHL sont basés sur cette propriété de JudyL.

Fonctions JudySL : Index est une chaîne de caractères terminée par nul et Valeur est un Word_t.

Fonctions JudyHS : Index est un tableau d'octets de longueur Length et Valeur est un Word_t. Cette nouvelle fonction (de 2004) de Judy est un mappeur qui combine les améliorations du hachage et les méthodes de Judy. L'auteur pense que JudyHS est un bon substitut à une méthode de hachage lors de la reconstruction d'une table de hachage lors de l'agrandissement du tableau. Une table de hachage de taille statique et avec une population appropriée est imbattable en termes de vitesse. Cependant, JudyHS sera plus efficace qu'une méthode de hachage avec des populations plus petites et plus grandes que la taille optimale de la table de hachage. JudyHS n'a pas de situation de performance dégénérée où un algorithme de hachage connu peut être exploité. (C'est-à-dire que JudyHS n'utilise pas de liste chaînée pour gérer les collisions de hachage, mais un arbre de tableaux JudyL et une table de hachage virtuelle de 4 billions).

Les tableaux Judy sont à la fois rapides et efficaces en mémoire, sans réglage ni configuration nécessaires, pour un large éventail de types d'index (séquentiels, périodiques, groupés, aléatoires). La vitesse et l'utilisation de la mémoire de Judy sont typiquement meilleures que celles de modèles de stockage tels que les skiplists, les listes chaînées, les arbres binaires, ternaires, b-trees, ou même le hachage, et s'améliorent avec de grandes quantités de données.

Un tableau Judy est créé en initialisant simplement un pointeur à nul, puis en stockant (en insérant) le premier élément dans le tableau sous ce pointeur. La mémoire utilisée par un tableau Judy est presque proportionnelle au nombre d'éléments (population).

Judy a deux interfaces d'application (API) : une interface de macros et une interface de fonctions d'appel. Bien que les formes de macros puissent être plus rapides et aient une interface d'erreur plus simple que les fonctions équivalentes, elles sont la manière préférée d'utiliser les fonctions Judy.

Étant donné qu'un tableau Judy vide (sans aucun élément) est représenté par un pointeur nul, il est possible de construire un tableau de tableaux Judy. Autrement dit, les Valeurs (sauf pour Judy1) d'un tableau Judy peuvent être des pointeurs vers d'autres tableaux Judy. Cela rend très simple la construction d'un tableau avec un nombre arbitraire de dimensions ou de tailles d'Index. (JudySL et JudyHS sont implémentés de cette manière).

ERREURS

Une grande réflexion (et du temps) a été consacrée à rendre la gestion des erreurs dans Judy simple, tout en conservant la flexibilité et la capacité. La gestion des erreurs est un sujet assez ennuyeux, même à écrire. Par conséquent, lisez cette section courte et utilisez la deuxième méthode recommandée. Cette méthode génère le code le plus rapide, utilise le moins de mémoire et ne nécessite qu'un code supplémentaire pour les fonctions d'insertion et de suppression. Elle est également compatible avec les deux autres méthodes. Cette méthode concerne le code de production qui souhaite gérer malloc() différemment de la méthode par défaut de Judy. Si la méthode par défaut de Judy pour gérer malloc() est acceptable, utilisez la première méthode.

Il existe deux (2) catégories de retours d'erreur de Judy, (ou pour tout ADT dynamique) :

1) Erreurs de programmation de l'utilisateur (bugs) telles que corruption de mémoire ou pointeurs invalides.
2) Échec de malloc() lors de l'insertion (Insert) ou de la suppression (Delete) lorsque le tableau Judy est modifié. Tous les appels d'insertion et de suppression n'utilisent pas malloc(), ils peuvent donc réussir même si malloc() était appelé et échouait.

Il existe environ trois (3) méthodes de gestion des erreurs lors de l'utilisation des macros :

1) Méthode de gestion des erreurs par défaut

La méthode par défaut consiste à imprimer des messages d'erreur sur stderr, par exemple :

File 'YourCfile.c', line 1234: JudyLIns(), JU_ERRNO_* == 2, ID == 321
Ceci indique qu'une erreur s'est produite dans la fonction JudyLIns() à la ligne 321. La ligne 1234 est la ligne dans 'YourCfile.c' où JLI() a été appelée et a échoué. JU_ERRNO_* == 2 est égal à JU_ERRNO_NOMEM (tel que défini dans le fichier Judy.h). Le numéro d'ID indique la ligne de code dans la fonction d'où provient l'erreur. Votre programme se termine avec exit(1);. Par défaut, les deux types de retours d'erreur de Judy sont imprimés de cette manière. (L'ID == 321 est pour ceux qui souhaitent plus de détails ou pour le débogage de Judy lui-même.)

2) Désactivation de la gestion des erreurs par macros

Lorsque votre programme est "sans bugs", les seuls retours d'erreur que vous devriez recevoir sont les échecs de malloc(). Par conséquent, toutes les erreurs peuvent être traitées comme des échecs de malloc(). En utilisant le #define suivant, tous les tests et l'impression d'erreurs sont désactivés. Vous devez ajouter du code supplémentaire au code qui pourrait échouer lors de malloc(). Judy a été conçue pour laisser les mêmes données dans le tableau avant l'appel si un échec de malloc() se produit. (Lors des tests de Judy, nous avons constaté que très peu de malloc()/OS réussissaient après un échec de malloc(). Cela prenait parfois des semaines pour le découvrir car de nombreux systèmes entraient en page lente avant d'épuiser la mémoire).

#define JUDYERROR_NOTEST 1
(dans votre code programme), ou 
cc -DJUDYERROR_NOTEST sourcefile -lJudy
(dans votre ligne de commande).

3) Méthode de la macro JUDYERROR() spécifiée par l'utilisateur

La macro JUDYERROR() (dans Judy.h) offre une flexibilité pour gérer les retours d'erreur selon les besoins de votre programme, même lors de l'utilisation des macros Judy au lieu d'appels de fonctions. Vous pouvez utiliser une macro JUDYERROR() différente selon vos besoins. L'exemple suivant est une alternative possible à la méthode par défaut. Il est utilisé pour distinguer les deux types d'erreurs (décrits ci-dessus) et pour tester explicitement les erreurs JU_ERRNO_NOMEM restantes possibles dans votre programme.

// Ceci est un exemple d'API de macros Judy pour continuer en cas de manque de mémoire et imprimer et quitter(1) en cas de toute autre erreur.
#ifndef JUDYERROR_NOTEST
#include <stdio.h>  // requis pour fprintf()
// Ceci est la macro que les APIs de macros Judy utilisent pour les codes de retour -1 :
#define JUDYERROR(CallerFile, CallerLine, JudyFunc, JudyErrno, JudyErrID) \
{                                                                         \
    if ((JudyErrno) != JU_ERRNO_NOMEM) /* ! un échec de malloc() */         \
    {                                                                     \
        (void) fprintf(stderr, "Fichier '%s', ligne %d: %s(), "               \
            "JU_ERRNO_* == %d, ID == %d\n",                               \
            CallerFile, CallerLine,                                       \
            JudyFunc, JudyErrno, JudyErrID);                              \
        exit(1);                                                          \
    }                                                                     \
}
#endif // JUDYERROR_NOTEST non défini
Cette macro de gestion des erreurs doit être incluse avant l'instruction #include <Judy.h> dans votre programme.
