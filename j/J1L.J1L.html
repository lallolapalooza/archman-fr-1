SYNOPSI

S 
Judy1  - associe un Index (mot) à un bit
JudyL  - associe un Index (mot) à une Valeur (mot/pointeur)
JudySL - associe un Index (chaîne terminée par un caractère nul) à une Valeur

DESCRIPTIO

N

La famille de fonctions Judy prend en charge des tableaux entièrement dynamiques. Ces tableaux peuvent être indexés par un mot de 32 ou 64 bits (selon la taille du mot du processeur), une chaîne terminée par un caractère nul ou un tableau d'octets avec une longueur. Un tableau dynamique (peuplé de manière sparse) peut aussi être considéré comme une fonction d'association ou une mémoire assoc

iative.

Un Word_t est un typedef unsigned long int dans Judy.h et doit être de la même taille que sizeof(void *) c'est-à-dire un

pointeur.

Fonctions Judy1 : Index est un Word_t et Valeur est simplement un bit ou simplement un indicateur qui indique si Index est présent ou absent du tableau. Cela peut être considéré comme un énorme

bitmap.

Fonctions JudyL : Index est un Word_t et Valeur est un Word_t. Cela fait de JudyL un associateur pur mot-vers-mot/pointeur. JudySL et JudyHL sont basés sur cette propriété de JudyL

.

Fonctions JudySL : Index est une chaîne terminée par un caractère nul et Valeur est un Word_t

.

Fonctions JudyHS : Index est un tableau d'octets de longueur : Length. Valeur est un Word_t. Cette nouvelle addition (mai 2004) à Judy est un hybride utilisant les meilleures caractéristiques du hachage et des méthodes Judy. L'auteur pense que JudyHS est un bon remplacement pour une méthode de hachage lorsque la redimensionnement de la table de hachage est effectué lors de la croissance de la population. Une méthode de hachage correctement réglée avec une taille de table de hachage statique et une population est imbattable en vitesse. Cependant, JudyHS sera plus performant qu'une méthode de hachage avec des populations plus petites et plus grandes que la taille optimale de la table de hachage. JudyHS n'a pas de cas de performance dégénéré où la connaissance de l'algorithme de hachage peut être exploitée. (C'est-à-dire que JudyHS n'utilise pas de liste chaînée pour gérer les collisions de hachage, il utilise un arbre de tableaux JudyL et une taille de table de hachage virtuelle de 4 milliards)

.

Les tableaux Judy sont à la fois efficaces en vitesse et efficaces en mémoire, sans réglage ni configuration requis, à travers une large gamme de types d'ensembles d'index (séquentiels, périodiques, groupés, aléatoires). La vitesse et l'utilisation mémoire de Judy sont généralement meilleures que d'autres modèles de stockage de données tels que les skiplists, les listes chaînées, les arbres binaires, ternaires, b-arbres, ou même le hachage, et s'améliorent avec de très grands ensembles de

données.

Un tableau Judy est créé simplement en définissant un pointeur nul puis en stockant (insérant) le premier élément dans le tableau sous ce pointeur. La mémoire utilisée par un tableau Judy est presque proportionnelle à la population (nombre d'éléments)

.

Judy a deux interfaces de programmation d'application (API) : une interface de macro C et une interface d'appel de fonction. Comme les formes de macro sont parfois plus rapides et ont une interface de gestion d'erreurs plus simple que les fonctions équivalentes, elles sont la façon préférée d'utiliser les fonctions

Judy.

Puisqu'un tableau Judy initial (vide) est représenté par un pointeur nul, il est possible de construire un tableau de tableaux Judy. En d'autres termes, les Valeurs d'un tableau Judy (sauf Judy1) peuvent être des pointeurs vers d'autres tableaux Judy. Cela rend très simple la construction d'un tableau avec un nombre arbitraire de dimensions ou de tailles d'Index. (JudySL et JudyHS sont im

plémentés en utilisant
JudyL de cette façon).

ERREUR

S

Beaucoup de réflexion (et de temps) a été consacré à rendre la gestion des erreurs dans Judy simple, tout en maintenant la flexibilité et les capacités. La gestion des erreurs est un sujet très ennuyeux même à écrire. Lisez donc cette courte section et utilisez la deuxième méthode recommandée. Elle génère le code le plus rapide, utilise la plus petite quantité de mémoire et vous oblige à écrire du code supplémentaire uniquement pour les fonctions d'insertion/suppression. De plus, elle est compatible avec les deux autres méthodes. Cette méthode est destinée au code de production qui peut vouloir gérer les échecs de malloc() différemment de la méthode par défaut de Judy. Si la méthode par défaut de Judy pour gérer les échecs de malloc() vous convient, utilisez la première

méthode.

Il y a deux (2) catégories de retours d'erreur de Judy, (ou pour n'importe quel ADT dynamique)

:

1) Erreurs de programmation de l'utilisateur (bugs) telles que corruption mémoire ou pointeurs invalides.
2) Mémoire insuffisante (échec de malloc()) avec Insert (Set) ou Delete (Unset) lors de la modification d'un tableau Judy. Tous les appels à l'insertion et à la suppression n'appellent pas malloc(), donc ils peuvent réussir même si un appel à malloc() échouerait.

Il y a environ trois (3) méthodes pour gérer les erreur

s lors de l'util
isation des macros :

1) Méthode par défaut de gestion des

erreurs

Par défaut, les messages d'erreur sont imprimés sur stderr, par exemple

: 
File 'YourCfile.c', line 1234: JudyLIns(), JU_ERRNO_* == 2, ID == 321
Cela indique qu'une erreur s'est produite dans la fonction JudyLIns() à la ligne 321. La ligne 1234 est la ligne dans 'YourCfile.c' où l'appel JLI() a échoué. JU_ERRNO_* == 2 est égal à JU_ERRNO_NOMEM (tel que défini dans le fichier Judy.h). Le numéro ID indique le numéro de ligne source dans la fonction où l'erreur est survenue. Votre programme se termine ensuite avec un exit(1);. Par défaut, les deux catégories de retours d'erreur de Judy sont imprimées de cette façon. (Le 'ID == 321' est pour les inconditionnels qui veulent plus de détails ou pour déboguer Judy lui-même.)

2) Désactiver la gestion des erreurs des

macros

Quand votre programme est « sans bug », les seules erreurs retournées devraient être des échecs de malloc(). Par conséquent, tous les retours d'erreur peuvent être traités comme un échec de malloc(). En utilisant le #define ci-dessous, tous les tests et impressions d'erreurs sont désactivés. Un code supplémentaire doit être ajouté au code qui peut avoir des échecs de malloc(). Judy a été conçu pour laisser les mêmes données dans le tableau avant l'appel si un échec de malloc() se produit. (Lors des tests de Judy, nous avons trouvé très peu de malloc()/systèmes d'exploitation qui étaient sans bug après un échec de malloc(). Parfois, cela a pris des semaines pour le découvrir car la plupart des systèmes entrent dans une frénésie de pagination avant de manquer de mémoire)

. 
#define JUDYERROR_NOTEST 1
(dans
le code de votre programme), ou 
cc -DJUDYERROR_NOTEST sourcefile -lJudy
(sur votre ligne de commande).

NAME

                    
J1L, J1S, J1U, JLI, JLD, P1S, P1U, PLS, PLU, PJL, PJD, PJERR, JERR, JU_ERRNO_NOMEM, JUDYERROR — Judy array macros

                

                

                    
SYNOPSIS

                    
#include <Judy.h>

   Field *FieldP = JudySL(NULL, Key, Value);
   Field *FieldP = JudyHS(NULL, Key, Value);



                

                

                    
DESCRIPTION

                    
The Judy array macros are designed to be faster than the
                        corresponding Judy array functions, and use less memory. If error
                        checking is desired, the JUDYERROR() macro is invoked.
                        The Judy array macros are generally used to build the Judy array
                        and not for the Judy array implementation itself.

                    
The macros are inline functions that are expanded
                        in-line by the C compiler. They are generally faster than the
                        corresponding Judy array functions. The macros are generally
                        smaller than the corresponding Judy array functions.

                    
The JUDYERROR() macro is invoked when an error
                        occurs. The default JUDYERROR() macro prints an error
                        message to stderr and exits.

                

                

                    
A 10 MINUTE TECHNICAL DESCRIPTION

                    
The Judy array macros are a set of C macros that are used
                        to interact with the Judy array library. These macros are designed
                        to be faster and more memory-efficient than the corresponding
                        Judy array functions. The macros are expanded inline by the C
                        compiler, which means that they are essentially compiled directly
                        into your code. This can lead to performance improvements, as it
                        eliminates the overhead of function calls.

                    
The macros also provide a convenient way to handle errors.
                        When an error occurs, the JUDYERROR() macro is invoked.
                        This macro can be customized to handle errors in a way that suits
                        your application. The default behavior is to print an error message
                        to stderr and exit the program.

                

                

                    
A 3 HOUR TECHNICAL DESCRIPTION (out of date and a bit corny)

                    
Imagine you have a big, messy room (your computer’s memory)
                        and you need to store and find things (data) very quickly. Judy arrays
                        are like a super-organized filing cabinet system that helps you do
                        this efficiently. Now, these Judy array *macros* are like tiny,
                        super-fast robots that help you use the filing cabinet. Instead of
                        calling a human librarian (a function) every time you need to put a
                        file away or find one, you give a direct command to one of these
                        robots (a macro). Since the robot works right there with you, it’s
                        much quicker than sending a message across the room to the librarian.

                    
Sometimes, things can go wrong. Maybe you run out of space
                        in the filing cabinet (out of memory), or you try to put a file
                        in the wrong place. Judy arrays have a built-in safety system, the
                        JUDYERROR() macro. Think of it as a little alarm bell. By
                        default, when the alarm rings (an error happens), it shouts out what
                        went wrong, where it happened, and then shuts everything down (exits)
                        to prevent further chaos. You can even customize this alarm system.
                        You could tell it to only ring loudly for major problems, or maybe just
                        make a quiet beep for minor issues, or even ignore certain beeps if
                        you know you can handle them yourself.

1) Default Error Handling Method

                    
J1L(PValue, P1Array, Index);
if (PValue == PJERR) goto out_of_memory_handling;

JLD(RC_int, P1Array, Index);
if (RC_int == JERR) goto out_of_memory_handling;

P1S(RC_int, P1Array, Index);
if (RC_int == JERR) goto out_of_memory_handling;

P1U(RC_int, P1Array, Index);
if (RC_int == JERR) goto out_of_memory_handling;

                    
If JUDYERROR() is not defined, the default method
                        is used. The default method consists of checking the return code
                        from the Judy macro. If the return code indicates an error, the
                        JUDYERROR() macro is invoked. The default JUDYERROR()
                        macro prints an error message to stderr and exits the
                        program.

                    
If JUDYERROR() is not defined, and the macro is
                        invoked, the default error handling is used. The default error
                        handling prints an error message to stderr and exits the
                        program.

                

                

                    
2) Disable Macro Error Handling

                    
#define JUDYERROR_NOTEST
#include <Judy.h>

JLI(PValue, PLArray, Index);
if (PValue == PJERR) goto out_of_memory_handling;

                    
JLD(RC_int, PLArray, Index);
if (RC_int == JERR) goto out_of_memory_handling;

                    
J1S(RC_int, P1Array, Index);
if (RC_int == JERR) goto out_of_memory_handling;

                    
J1U(RC_int, P1Array, Index);
if (RC_int == JERR) goto out_of_memory_handling;

                    
Note: Without 'JUDYERROR_NOTEST' defined, the 'goto
                        out_of_memory_handling' will never be executed and will be
                        optimized out by the compiler. The default method will be used
                        -- Macro will print error information if an error occurs as
                        explained above.

                    
With 'JUDYERROR_NOTEST' defined, the 'goto
                        out_of_memory_handling' will be executed when an error occurs --
                        which should only happen when malloc() fails.

                

                

                    
3) User-Specified JUDYERROR() Macro Method

                    
The JUDYERROR() macro (in Judy.h) provides
                        flexibility for handling error returns as needed to suit your
                        program while still using the Judy array macros instead of
                        function calls. You can use a different JUDYERROR() macro
                        to suit your needs. The following example is a possible alternative
                        to the default. It is used to distinguish between the two types of
                        errors (described above), and explicitly test for the remaining
                        JU_ERRNO_NOMEM errors possible in your program.

                    
// This is an example of Judy macro API to continue when out of memory
// and print and exit(1) when any other error occurs.

                    
#ifndef JUDYERROR_NOTEST
#include <stdio.h>  // needed for fprintf()

                    
// This is the macro that the Judy macro APIs use for return codes of -1:

                    
#define JUDYERROR(CallerFile, CallerLine, JudyFunc, JudyErrno, JudyErrID) \
{                                                                         \
    if ((JudyErrno) != JU_ERRNO_NOMEM) /* ! a malloc() failure */         \
    {                                                                     \
        (void) fprintf(stderr, "File '%s', line %d: %s(), "\
            "JU_ERRNO_* == %d, ID == %d\n",\
            CallerFile, CallerLine,\
            JudyFunc, JudyErrno, JudyErrID);\
        exit(1);\
    }\
}
#endif // JUDYERROR_NOTEST not defined
                    

                    
This error handling macro must be included before the
                        #include <Judy.h> statement in your program.
