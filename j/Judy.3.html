S 
Judy1 - associe un Index (mot) à un bit
JudyL - associe un Index (mot) à une Valeur (mot/pointeur)
JudySL - associe un Index (chaîne terminée par un caractère nul) à une Valeur
JudyHS - associe un Index (tableau d'octets) de Longueur à une Vale

DESCRIPTIO

N

La famille de fonctions Judy prend en charge des tableaux entièrement dynamiques. Ces tableaux peuvent être indexés par un mot de 32 ou 64 bits (selon la taille du mot du processeur), une chaîne terminée par un caractère nul ou un tableau d'octets avec une longueur. Un tableau dynamique (peuplé de manière sparse) peut aussi être considéré comme une fonction d'association ou une mémoire assoc

iative.

Un Word_t est un typedef unsigned long int dans Judy.h et doit avoir la même taille que sizeof(void *), c'est-à-dire un

pointeur.

Fonctions Judy1 : Index est un Word_t et Valeur est simplement un bit, ou simplement un indicateur qui indique si Index est présent ou absent du tableau. On peut considérer cela comme un énorme

bitmap.

Fonctions JudyL : Index est un Word_t et Valeur est un Word_t. Cela fait de JudyL un simple associateur mot-vers-mot/pointeur. JudySL et JudyHL sont basés sur cette propriété de JudyL

.

Fonctions JudySL : Index est une chaîne terminée par un caractère nul et Valeur est un Word_t

.

Fonctions JudyHS : Index est un tableau d'octets de longueur : Length. Valeur est un Word_t. Cette nouvelle addition (mai 2004) à Judy est un hybride utilisant les meilleures caractéristiques du hachage et des méthodes Judy. L'auteur pense que JudyHS est un bon remplacement pour une méthode de hachage lorsque la redimensionnement de la table de hachage est effectué lors de la croissance de la population. Une méthode de hachage correctement réglée avec une taille de table de hachage statique et une population est imbattable en vitesse. Cependant, JudyHS sera plus performant qu'une méthode de hachage avec des populations plus petites et plus grandes que la taille optimale de la table de hachage. JudyHS n'a pas de cas de performance dégénéré où la connaissance de l'algorithme de hachage peut être exploitée. (C'est-à-dire que JudyHS n'utilise pas de liste chaînée pour gérer les collisions de hachage, il utilise un arbre de tableaux JudyL et une taille de table de hachage virtuelle de 4 milliards)

.

Les tableaux Judy sont à la fois efficaces en vitesse et en mémoire, sans réglage ni configuration requis, à travers un large éventail de types d'ensembles d'index (séquentiels, périodiques, groupés, aléatoires). La vitesse et l'utilisation mémoire de Judy sont généralement meilleures que d'autres modèles de stockage de données tels que les skiplists, les listes chaînées, les arbres binaires, ternaires, b-arbres, ou même le hachage, et s'améliorent avec de très grands ensembles de

données.

Un tableau Judy est créé simplement en définissant un pointeur nul puis en stockant (insérant) le premier élément dans le tableau sous ce pointeur. La mémoire utilisée par un tableau Judy est presque proportionnelle à la population (nombre d'éléments)

.

Judy a deux interfaces de programmation d'application (API) : une interface de macro C et une interface d'appel de fonction. Parce que les formes de macro sont parfois plus rapides et ont une interface de gestion d'erreurs plus simple que les fonctions équivalentes, elles sont la façon préférée d'utiliser les fonctions

Judy.

Puisqu'un tableau Judy initial (vide) est représenté par un pointeur nul, il est possible de construire un tableau de tableaux Judy. En d'autres termes, les Valeurs d'un tableau Judy (sauf Judy1) peuvent être des pointeurs vers d'autres tableaux Judy. Cela rend très simple la construction d'un tableau avec un nombre arbitraire de dimensions ou de tailles d'Index. (JudySL et JudyHS sont im

plémentés en utilisant J
udyL de cette manière).

ERREUR

S

Beaucoup de réflexion (et de temps) a été consacré à rendre la gestion des erreurs dans Judy simple, tout en maintenant la flexibilité et les capacités. La gestion des erreurs est un sujet très ennuyeux même à écrire. Lisez donc cette courte section et utilisez la deuxième méthode recommandée. Elle génère le code le plus rapide, utilise la plus petite quantité de mémoire et vous oblige à écrire du code supplémentaire uniquement pour les fonctions d'insertion/suppression. De plus, elle est compatible avec les deux autres méthodes. Cette méthode est destinée au code de production qui pourrait vouloir gérer malloc() échoue différemment de la valeur par défaut de Judy. Si la méthode par défaut de Judy pour gérer malloc() échoue convient, utilisez la première

méthode.

Il y a deux (2) catégories de retours d'erreur de Judy, (ou pour n'importe quel ADT dynamique)

:

1) Erreurs de programmation de l'utilisateur (bugs) telles que la corruption de la mémoire ou des pointeurs invalides.
2) Mémoire insuffisante (échec de malloc()) lors de Insert (Set) ou Delete (Unset) lors de la modification d'un tableau Judy. Tous les appels à l'insertion et à la suppression n'appellent pas malloc(), donc ils peuvent réussir même si un appel à malloc() échouerait.

Il y a environ trois (3) méthodes pour gérer les erre

urs lors de l'utili
sation des macros :

1) Méthode par défaut de gestion des

erreurs

Par défaut, les messages d'erreur sont imprimés sur stderr, par exemple

: 
File 'YourCfile.c', line 1234: JudyLIns(), JU_ERRNO_* == 2, ID == 321
Cela indique qu'une erreur s'est produite dans la fonction JudyLIns() à la ligne 321. La ligne 1234 est la ligne dans 'YourCfile.c' où l'appel JLI() a échoué. JU_ERRNO_* == 2 est égal à JU_ERRNO_NOMEM (tel que défini dans le fichier Judy.h). Le numéro ID indique le numéro de ligne source dans la fonction où l'erreur est survenue. Votre programme se termine ensuite avec un exit(1);. Par défaut, les deux catégories de retours d'erreur de Judy sont imprimées de cette manière. (Le 'ID == 321' est pour les inconditionnels qui veulent plus de détails ou pour déboguer Judy lui-même.)

2) Désactiver la gestion des erreurs des

macros

Quand votre programme est "sans bug", les seules erreurs retournées devraient être des échecs de malloc(). Par conséquent, tous les retours d'erreur peuvent être traités comme un échec de malloc(). En utilisant le #define ci-dessous, tous les tests et impressions d'erreurs sont désactivés. Un code supplémentaire doit être ajouté au code qui peut avoir des échecs de malloc(). Judy a été conçu pour laisser les mêmes données dans le tableau avant l'appel si un échec de malloc() se produit. (Lors des tests de Judy, nous avons trouvé très peu de malloc()/systèmes d'exploitation qui étaient sans bug après un échec de malloc(). Parfois, cela a pris des semaines pour le découvrir car la plupart des systèmes entrent dans une frénésie de pagination avant de manquer de mémoire)

. 
#define JUDYERROR_NOTEST 1
(dans
le code de votre programme), ou 
cc -DJUDYERROR_NOTEST sourcefile -lJudy
(sur votre ligne de commande). 
// Ceci est un exemple de la façon de programmering method two (2)
. 
JLI(PValue, PLArray, Index);
if (PValue == PJERR) goto out_of_memory_handling
; 
JLD(RC_int, PLArray, Index);
if (RC_int == JERR) goto out_of_memory_handling
; 
J1S(RC_int, P1Array, Index);
if (RC_int == JERR) goto out_of_memory_handling
; 
J1U(RC_int, P1Array, Index);
if (RC_int == JERR) goto out_of_memory_handling;
Note:
Sans la définition de 'JUDYERROR_NOTEST', le 'goto out_of_memory_handling' ne sera jamais exécuté et sera optimisé par le compilateur. La méthode par défaut sera utilisée -- la macro affichera les informations d'erreur si une erreur se produit comme expliqué ci-dessus.

Avec 'JUDYERROR_NOTEST' défini, le 'goto out_of_memory_handling' sera exécuté lorsqu'une erreur se produit -- ce qui ne devrait se produire que lorsque malloc()

éch
oue.

3) Méthode de macro JUDYERROR() spécifiée par

l'utilisateur

La macro JUDYERROR() (dans Judy.h) offre la flexibilité nécessaire pour gérer les retours d'erreur selon les besoins de votre programme tout en utilisant les macros de tableaux Judy au lieu d'appels de fonctions. Vous pouvez utiliser une macro JUDYERROR() différente pour répondre à vos besoins. L'exemple suivant est une alternative possible à la méthode par défaut. Elle est utilisée pour distinguer entre les deux types d'erreurs (décrits ci-dessus), et tester explicitement pour les erreurs JU_ERRNO_NOMEM restantes possibles dans votre

programme. 
// Ceci est un exemple de macro API Judy pour continuer en cas de mémoire insuffisante
// et imprimer et exit(1) si une autre erreur se
produit. 
#ifndef JUDYERROR_NOTEST
#include <stdio.h>  // nécessaire pour
fprintf() 
// Ceci est la macro que les API de macros Judy utilisent pour les codes de retour de -1
: 
#define JUDYERROR(CallerFile, CallerLine, JudyFunc, JudyErrno, JudyErrID) \
{                                                                         \
    if ((JudyErrno) != JU_ERRNO_NOMEM) /* ! un échec de malloc() */        \
    {                                                                     \
        (void) fprintf(stderr, "File '%s', line %d: %s(), "               \
            "JU_ERRNO_* == %d, ID == %d\n",                               \
            CallerFile, CallerLine,                                       \
            JudyFunc, JudyErrno, JudyErrID);                              \
        exit(1);                                                          \
    }                                                                     \
}
#endif // JUDYERROR_NOTEST non défini
Cette macro de gestion d'erreurs doit être incluse avant la #include <Judy.h> statement in your
program.
