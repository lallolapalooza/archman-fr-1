DESCRIPTION

Un équivalent macro existe pour chaque appel de fonction. Comme les formes macro sont parfois plus rapides et ont une interface de gestion d'erreurs plus simple que les fonctions équivalentes, elles sont le moyen préféré pour appeler les fonctions JudyL. Voir JudyL(3) pour plus d'informations. Les définitions d'appels de fonction sont incluses ici pour complétude.

L'une des difficultés d'utilisation des appels de fonction JudyL réside dans la détermination s'il faut passer un pointeur ou l'adresse d'un pointeur. Comme les fonctions qui modifient le tableau JudyL doivent également modifier le pointeur vers le tableau JudyL, vous devez passer l'adresse du pointeur plutôt que le pointeur lui-même. Cela conduit souvent à des erreurs programmatiques difficiles à déboguer. En pratique, les macros permettent au compilateur de détecter les erreurs de programmation lorsque des pointeurs sont passés au lieu d'adresses de pointeurs.

Les appels de fonction JudyL ont un paramètre supplémentaire par rapport à ceux spécifiés dans les appels de macros. Ce paramètre est soit un pointeur vers une structure d'erreur, soit NULL (auquel cas les informations d'erreur détaillées ne sont pas retournées).

Dans les descriptions suivantes, les fonctions sont décrites en termes de la manière dont les macros les utilisent (uniquement dans le cas de #define JUDYERROR_NOTEST 1). C'est l'utilisation suggérée des macros une fois votre programme entièrement débogué. Lorsque la macro JUDYERROR_NOTEST n'est pas spécifiée, une structure d'erreur est déclarée pour stocker les informations d'erreur renvoyées par les fonctions JudyL en cas d'erreur.

Notez le placement du & dans les différentes fonctions.
