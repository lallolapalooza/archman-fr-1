DESCRIPTION

Un équivalent macro existe pour chaque appel de fonction. Comme les formes macros sont parfois plus rapides et ont une interface de gestion des erreurs plus simple que les fonctions équivalentes, elles constituent le moyen privilégié d'appeler les fonctions JudyL. Voir JudyL(3) pour plus d'informations. Les définitions d'appels de fonction sont incluses ici pour plus de complétude.

L'une des difficultés d'utilisation des appels de fonction JudyL réside dans la détermination de la manière de passer un pointeur ou l'adresse d'un pointeur. Comme les fonctions qui modifient le tableau JudyL doivent également modifier le pointeur vers le tableau JudyL, vous devez passer l'adresse du pointeur plutôt que le pointeur lui-même. Cela conduit souvent à des erreurs de programmation difficiles à déboguer. En pratique, les macros permettent au compilateur de détecter les erreurs de programmation lorsque des pointeurs au lieu d'adresses de pointeurs sont passés.

Les appels de fonction JudyL ont un paramètre supplémentaire au-delà de ceux spécifiés dans les appels de macro. Ce paramètre est soit un pointeur vers une structure d'erreur, soit NULL (auquel cas les informations d'erreur détaillées ne sont pas retournées).

Dans les descriptions suivantes, les fonctions sont décrites en termes de la manière dont les macros les utilisent (uniquement dans le cas de #define JUDYERROR_NOTEST 1). C'est l'utilisation suggérée des macros une fois votre programme entièrement débogué. Lorsque la macro JUDYERROR_NOTEST n'est pas spécifiée, une structure d'erreur est déclarée pour stocker les informations d'erreur retournées par les fonctions JudyL lorsqu'une erreur se produit.

Notez le placement du & dans les différentes fonctions.

JudyL(3) — JudyLNextEmpty

NOM

JudyLNextEmpty — Trouve le prochain index vide dans le tableau JudyL.

SYNTAXIS

 JudyCounter_t
 JudyLNextEmpty(JudyLHandle ch, Word_t index);

DESCRIPTION

La fonction JudyLNextEmpty recherche un index dans le tableau JudyL qui n'est pas utilisé, en commençant par l'index donné et en allant de l'avant.

Elle renvoie le nombre d'éléments qui ont été parcourus pour trouver l'index vide, ou une valeur indiquant une erreur.

L'index renvoyé peut être passé à la fonction JudyLSet pour y insérer une valeur.

VALEUR DE RETOUR

En cas de succès, JudyLNextEmpty renvoie le nombre d'éléments qui ont été parcourus pour trouver l'index vide. La valeur renvoyée est un JudyCounter_t.

En cas d'erreur (par exemple, si le handle JudyL est invalide ou si la mémoire n'a pas pu être allouée), une valeur négative est renvoyée, indiquant le type d'erreur. Les codes d'erreur courants incluent:

  • -1 : Handle JudyL invalide.
  • -2 : Erreur d'allocation mémoire.

EXEMPLES

 JudyLHandle ch = JudyLNew();
 Word_t index;
 JudyCounter_t count;

 // Recherche du premier index vide
 count = JudyLNextEmpty(ch, 0);
 if (count >= 0) {
  index = count; // L'index vide trouvé
  printf("Premier index vide trouvé à : %lu\n", (unsigned long)index);
  // Vous pouvez maintenant utiliser JudyLSet pour insérer une valeur à cet index
  // JudyLSet(ch, index, (void *)nouvelle_valeur);
 } else {
  fprintf(stderr, "Erreur lors de la recherche du prochain index vide.\n");
 }

 JudyLFree(ch);

NOTE

Le type Word_t est un type entier sans signe de 64 bits. Le type JudyCounter_t est également un type entier sans signe de 64 bits, utilisé pour compter les éléments.

Le handle JudyLHandle est un pointeur vers une structure JudyL qui représente le tableau JudyL. Il est généralement obtenu par JudyLNew().

Il est important de gérer les valeurs de retour négatives pour détecter et traiter les erreurs qui peuvent survenir lors de l'utilisation des fonctions JudyL.

Le tableau JudyL peut stocker des pointeurs vers des données. Le type void_t peut être passé par valeur aux fonctions qui acceptent Pcvoid_t (constante Pvoid_t), et également par adresse aux fonctions qui acceptent PPvoid_t.

Le type de retour des fonctions JudyL les plus courantes est PPvoid_t, de sorte que les valeurs stockées dans le tableau puissent être des pointeurs vers d'autres objets, ce qui est une utilisation typique, ou puissent être converties en Word_t * lorsqu'un pointeur vers une Value est nécessaire au lieu d'un pointeur vers un pointeur.
