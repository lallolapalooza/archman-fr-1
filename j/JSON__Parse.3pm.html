NOM

JSON::Parse - Analyser le JSON

SYNOPSIS

use JSON::Parse 'parse_json';
my $json = '["golden", "fleece"]';
my $perl = parse_json ($json);
# Même effet que $perl = ['golden', 'fleece'];

Convertir du JSON en Perl.

VERSION

Ceci documente la version 0.62 de JSON::Parse correspondant au commit git d04630086f6c92fea720cba4568faa0cbbdde5a6 https://github.com/benkasminbullock/JSON-Parse/commit/d04630086f6c92fea720cba4568faa0cbbdde5a6 publié le Sam 16 Juil 08:23:13 2022 +0900.

DESCRIPTION

Un module pour analyser le JSON. (JSON signifie "JavaScript Object Notation" et est spécifié dans le "RFC 8259".)

JSON::Parse propose la fonction "parse_json", qui prend une chaîne contenant du JSON et renvoie une structure Perl équivalente. Il propose également la validation du JSON via "valid_json", qui renvoie vrai ou faux selon que le JSON est correct ou non, et "assert_valid_json", qui produit une erreur fatale descriptive si le JSON est invalide. Une fonction "read_json" lit le JSON à partir d'un fichier, et il existe une version plus sûre de "parse_json" appelée "parse_json_safe" qui ne lève pas d'exceptions.

Pour des cas spéciaux d'analyse, il existe également les méthodes "new" et "parse", qui créent un objet d'analyse JSON et l'exécutent sur du texte. Voir "MÉTHODES".

JSON::Parse n'accepte que l'UTF-8 en entrée. Voir "Uniquement UTF-8" et "Gestion de l'Unicode".

parse_json

use JSON::Parse 'parse_json';
my $perl = parse_json ('{"x":1, "y":2}');

Cette fonction convertit le JSON en une structure Perl, soit une référence de tableau, une référence de hachage, ou un scalaire.

Si le premier argument ne contient pas un texte JSON complet et valide, est la valeur indéfinie, une chaîne vide, ou une chaîne contenant uniquement des espaces blancs, "parse_json" lance une erreur fatale ("dies").

Si l'argument contient du JSON valide, la valeur de retour est soit une référence de hachage, une référence de tableau, soit un scalaire. Si le texte JSON d'entrée est un objet sérialisé, une référence de hachage est retournée :

use JSON::Parse ':all';
my $perl = parse_json ('{"a":1, "b":2}');
print ref $perl, "\n";

parse_json_safe

C'est presque la même chose que "parse_json", mais avec les différences suivantes :

Ne lance pas d'exceptions
Si le JSON est invalide, un avertissement est affiché et la valeur indéfinie est retournée, comme si l'on appelait "parse_json" ainsi : 
eval {
    $out = parse_json ($json);
};
if ($@) {
    carp $@;
    $out = undef;
}
Détecte les collisions de clés
Ceci active "detect_collisions", donc si le JSON contient des noms non uniques, un avertissement est affiché et la valeur indéfinie est retournée. Voir "Collisions de clés" pour une explication de ce qu'est une collision de clé.
Les booléens ne sont pas en lecture seule
Ceci active "copy_literals" afin que les valeurs JSON true, false et null soient copiées. Ces valeurs peuvent être modifiées, mais elles ne seront pas reconverties en "true" et "false" par JSON::Create.
Les erreurs sont signalées par carp
Les erreurs d'analyse sont signalées par "carp" dans Carp, donc le numéro de ligne de l'erreur se réfère à la ligne de l'appelant.

Comme son nom l'indique, il s'agit d'une version de "parse_json" privilégiant la sécurité.

🎲 Cette fonction a été ajoutée dans la version 0.38.

read_json

use JSON::Parse 'read_json';
my $p = read_json ('filename');

C'est exactement la même chose que "parse_json" sauf qu'elle lit le JSON à partir du fichier spécifié plutôt que d'une chaîne. Le fichier doit être encodé en UTF-8, et est ouvert en tant que fichier caractère en utilisant :encoding(utf8) (voir PerlIO::encoding et perluniintro). La sortie est marquée comme des chaînes caractères.

L'équivalent de la méthode est "read".

C'est une fonction de commodité écrite en Perl. Vous pourriez préférer lire vous-même le fichier en utilisant un autre module si vous avez besoin de plus de performance.

Elle a été renommée depuis "json_file_to_perl" dans la version 0.59. L'ancien nom continuera également de fonctionner indéfiniment.

valid_json

use JSON::Parse 'valid_json';
if (valid_json ($json)) {
    # fais quelque chose
}

"valid_json" renvoie 1 si son argument est du JSON valide et 0 sinon. Elle s'exécute plusieurs fois plus vite que "parse_json". Ce gain de vitesse est obtenu car elle rejette les données d'entrée après les avoir lues, au lieu de les stocker dans des variables Perl.

Ceci ne fournit pas les erreurs réelles qui ont causé l'invalidité. Utilisez "assert_valid_json" pour obtenir des messages d'erreur lorsque le JSON est invalide.

Ceci ne peut pas détecter les clés dupliquées dans les objets JSON car il ne stocke pas les valeurs. Voir "Collisions de clés" pour plus d'informations sur la gestion par ce module des noms non uniques dans le JSON.

Correspondance de JSON vers

Perl

Les éléments JSON sont mappés vers Perl comme suit

:

Nombres

JSON

Les nombres JSON deviennent des nombres Perl, soit des entiers, soit des nombres flottants en double précision, ou éventuellement des chaînes contenant le nombre si l'analyse d'un nombre par les méthodes habituelles échoue d'une manière ou d'une

autre.

JSON ne permet pas les zéros de tête, comme 0123, ni les signes plus de tête, comme +100, dans les nombres, ceux-ci provoquent donc une erreur "Unexpected character". JSON ne permet pas non plus les nombres de la forme 1., mais il permet des choses comme 0e0 ou 1E999999. Dans la mesure du possible

, ceux-ci sont accep
tés par JSON::Parse.

Chaînes

JSON

Les chaînes JSON deviennent des chaînes Perl. Les caractères d'échappement JSON tels que "\t" pour le caractère tabulation (voir la section 2.5 de la "RFC 8259") sont mappés vers le caractère ASCII

équivalent.

Gestion

d'Unicode

Les entrées doivent être au format UTF-8. Voir "UTF-8

uniquement".

De plus, JSON::Parse rejette le UTF-8 qui encode des non-caractères tels que "U+FFFF" et des caractères mal formés tels que des moitiés incomplètes de paires de

substitution.

Les points d'encodage Unicode dans l'entrée de la forme "\u3000" sont convertis en les octets UTF-8

équivalents.

Les paires de substitution de la forme "\uD834\uDD1E" sont également gérées. Si la seconde moitié de la paire de substitution est manquante, une erreur "Unexpected character" ou "Unexpected end of input" est levée. Si la seconde moitié de la paire de substitution est présente mais contient une valeur impossible, une erreur "Not surrogate pair" est

levée.

Si l'entrée de "parse_json" est marquée comme des caractères Unicode, les chaînes de sortie seront marquées comme des caractères Unicode. Si l'entrée n'est pas marquée comme des caractères Unicode, les chaînes de sortie ne seront pas marquées comme des caractères Unicode.

Ainsi, 
use JSON::Parse ':all';
# Le scalaire $sasori ressemble à de l'Unicode pour Perl
use utf8;
my $sasori = '["蠍"]';
my $p = parse_json ($sasori);
print utf8::is_utf8 ($p->[0]);
# Affiche
1.

mai

s 
use JSON::Parse ':all';
# Le scalaire $ebi ne ressemble pas à de l'Unicode pour Perl
no utf8;
my $ebi = '["海老"]';
my $p = parse_json ($ebi);
print utf8::is_utf8 ($p->[0]);
# N'affiche
rien.

Les échappements de la forme \uXXXX (voir la page trois de la "RFC 8259") sont mappés vers l'ASCII si XXXX est inférieur à 0x80, ou vers le UTF-8 si XXXX est supérieur ou égal à

0x80.

Les chaînes contenant des échappements \uXXXX supérieurs à 0x80 sont également promues en chaînes de caractères, que l'entrée soit une chaîne de caractères ou une chaîne d'octets, donc indépendamment du fait que Perl considère ou non la chaîne d'entrée comme de l'Unicode, des échappements comme \u87f9 sont convertis en les octets UTF-8 équivalents et la chaîne particulière dans laquelle ils apparaissent est marquée comme une chaîne de caractères

: 
use JSON::Parse ':all';
no utf8;
# 蟹
my $kani = '["\u87f9"]';
my $p = parse_json ($kani);
print "It's marked as a character string" if utf8::is_utf8 ($p->[0]);
# Affiche "It's marked as a character string" parce qu'elle est promue
# indépendamment des indicateurs de la chaîne
d'entrée.

Ceci est modelé sur le comportement de "chr" de Perl

: 
no utf8;
my $kani = '87f9';
print "hex is character string\n" if utf8::is_utf8 ($kani);
# n'affiche rien
$kani = chr (hex ($kani));
print "chr makes it a character string\n" if utf8::is_utf8 ($kani);
# affiche "chr makes it a character
string"

Cependant, JSON::Parse promeut également le reste de la chaîne en une chaîne de caractères, même lorsqu'elle n'est pas marquée comme une chaîne de caractères. Par

exemple, 
use JSON::Parse ':all';
use Unicode::UTF8 'decode_utf8';
no utf8;
my $highbytes = "か";
my $not_utf8 = "$highbytes\\u3042";
my $test = "{\"a\":\"$not_utf8\"}";
my $out = parse_json ($test);
# JSON::Parse fait quelque chose d'inhabituel ici en promouvant la première partie
# de la chaîne en UTF-8.
print "JSON::Parse gives this: ", $out->{a}, "\n";
# Perl ne peut pas supposer que $highbytes est en UTF-8, donc il doit simplement
# transformer les caractères initiaux en caractères illisibles.
my $add_chr = $highbytes . chr (0x3042);
print "Perl's output is like this: ", $add_chr, "\n";
# En fait, le comportement de JSON::Parse est équivalent à ceci :
my $equiv = decode_utf8 ($highbytes) . chr (0x3042);
print "JSON::Parse did something like this: ", $equiv, "\n";
# Avec les chaînes de caractères activées, Perl et JSON::Parse font la même
# chose.
use utf8;
my $is_utf8 = "か";
my $test2 = "{\"a\":\"$is_utf8\\u3042\"}";

RESTRICTION

S

Ce module impose les restrictions suivantes sur son

entrée.
JSON
uniquement
JSON::Parse est un analyseur strict. Il n'accepte que les entrées qui répondent exactement aux critères de la « RFC 8259 ». Cela signifie, par exemple, que JSON::Parse n'accepte pas les guillemets simples (') au lieu des guillemets doubles ("), ou les nombres avec des zéros non significatifs, comme 0123. JSON::Parse n'accepte pas les caractères de contrôle (0x00 - 0x1F) dans les chaînes, les virgules manquantes entre les éléments de tableau ou de hachage comme "["a" "b"]", ou les virgules finales comme "["a","b","c",]". Il n'accepte pas non plus les caractères non blancs finaux, comme le deuxième "]" dans "["a"]]".

Vous pourriez trouver « JSON::Repair » par les mêmes aute

urs que JSON::Parse utile si vous devez traiter
du texte de type JSON avec tolérance aux erreurs.
Pas d'analyse
incrémentale
JSON::Parse n'analyse pas de manière incrémentale. Il n'analyse que les chaînes JSON entièrement formées qui incluent toutes les accolades ouvrantes et fermantes. C'est une partie inhérente de la conception du module. L'analyse incrémentale dans le style de XML::Parser nécessiterait une sorte de structure de rappel pour gérer les éléments des structures partiellement digérées, mais JSON::Parse n'a jamais été conçu pour faire cela ; il convertit simplement ce qu'il voit en une structure Perl. Les affirmations d'offrir une analyse JSON incrémentale dans la documentation d'autres modules devraient être vérifiées avec
diligence.
UTF-8
uniquement
JSON::Parse n'analyse que le format UTF-8. Si l'entrée est dans une encodage Unicode différent de UTF-8, convertissez l'entrée avant de la remettre à ce module. Par exemple, pour le format UTF-16, 
use Encode 'decode';
my $input_utf8 = decode ('UTF-16', $input);
my $perl = parse_json ($input_utf8)
;

ou, pour un fichier, utilisez ":encoding" (voir PerlIO::encoding et perluniintro)

: 
open my $input, "<:encoding(UTF-16)",
'some-json-file';

JSON::Parse n'essaie pas de déterminer la nature du flux d'octets à l'aide des marqueurs BOM. Un marqueur BOM dans l'entrée se compose des octets 0xFE et 0xFF, qui sont tous deux invalides en tant qu'UTF-8, et provoqueront donc une erreur

fatale.

Cette restriction à l'UTF-8 s'applique indépendamment du fait que Perl considère que la chaîne d'entrée est une chaîne de caractères ou une chaîne d'octets. Une entrée non UTF-8 provoquera une erreur « Unexpected character

».

La dernière spécification pour JSON, la « RFC 8259 », spécifie qu'il s'agit d'un format exclusivement

UTF-8.

JSON::Parse n'accepte pas les non-caractères Unic

ode (U+FFFF, UFDDO, etc.), l'UTF-8 représ
entant des points de code de paire de substitutio
n, ou des octets en dehors de la plage de
s points de code Unicode en tant qu'octets UTF-8.

Un code de test plus étendu se trouve dans le dépôt git. Il n'est pas fourni dans la distribution CPAN. Un script, randomjson.pl https://github.com/benkasminbullock/JSON-Parse/d04630086f6c92fea720cba4568faa0cbbdde5a6/randomjson.pl, génère un nombre défini d'octets de JSON aléatoire et vérifie que la validation octet par octet des entrées par le module est correcte. Pour ce faire, il prend un fragment valide, puis ajoute chaque octet possible de 0 à 255 pour voir si le module identifie correctement celui-ci comme valide ou invalide à ce point, puis choisit au hasard l'un des octets valides et l'ajoute au fragment, et continue le processus jusqu'à ce qu'une entrée JSON valide complète soit formée. Le module a subi environ un milliard de répétitions de ce

Cette configuration repose sur un fichier C, json-random-test.c https://github.com/benkasminbullock/JSON-Parse/d04630086f6c92fea720cba4568faa0cbbdde5a6/json-random-test.c, qui n'est pas dans la distribution CPAN, et elle nécessite également que Json3.xs https://github.com/benkasminbullock/JSON-Parse/d04630086f6c92fea720cba4568faa0cbbdde5a6/Json3.xs soit modifié pour rendre la macro "TESTRANDOM" vraie (décommentez la ligne 7 du fichier). Le code de test utilise setjmp/longjmp en C, il n'est donc pas garanti de fonctionner sur tous les systèmes d'exploitation et est commenté pour les versions

CPAN.

Une version en C pur appelée random-test.c https://github.com/benkasminbullock/JSON-Parse/d04630086f6c92fea720cba4568faa0cbbdde5a6/random-test.c existe également. Elle applique exactement les mêmes tests et ne nécessite aucun

Perl.

Si vous êtes intéressé par le test de votre propre analyseur JSON, les sorties générées par randomjson.pl https://github.com/benkasminbullock/JSON-Parse/d04630086f6c92fea720cba4568faa0cbbdde5a6/randomjson.pl sont un très bon point de départ. Par défaut, il produit une sortie UTF-8, ce qui semble assez horrible car il tend à produire de longues chaînes de caractères UTF-8 inutiles. (C'est parce qu'il choisit au hasard parmi 256 octets et que le marqueur de fin de chaîne """ n'a qu'une chance sur 256 d'être choisi, les chaînes ont donc tendance à devenir longues et désordonnées). Vous pouvez modifier les entrailles de JSON::Parse en définissant MAXBYTE dans json-common.c à 0x80, en recompilant (vous pouvez ignorer les avertissements du compilateur), et en relançant randomjson.pl pour obtenir uniquement des objets JSON aléatoires en ASCII. Cela casse

la fonctionnalité UTF-8 de JSON::Parse, veui
llez donc ne pas installer cette version.

Suite de tests d'analyse

JSON

JSON::Parse version 0.58 passe la plupart de la suite de tests d'analyse JSON, à l'exception du fait que JSON::Parse rejette diverses entrées UTF-8 erronées ; par exemple, JSON::Parse lèvera une erreur pour des points de code non caractères tels qu'Unicode U+FFFF et U+10FFFF. Cet analyseur n'accepte que du UTF-8 valide en entrée. Voir "UTF-8

only".

À notre avis, ce serait un mauvais service aux utilisateurs de ce module que d'autoriser des octets contenant des fragments inutiles tels que des parties incomplètes de paires de substitution, ou des caractères invalides, juste parce que la spécification JSON n'exige pas explicitement de rejeter ces kinds d'entrées inutiles. Veuillez voir la fonction "daft_test" dans le fichier xt/JPXT.pm pour savoir exactement lesquels de ces éléments de la suite de tests nous ne respectons pas. Nous notons que ce commentaire de Douglas Crockford, l'inventeur de JSON, dans l'analyseur JSON https://github.com/douglascrockford/JSON-c/blob/master/utf8_decode.c#L38-L43, datant de 2005, est d'accord avec notre opinion sur ce

point.
