DESCRIPTIO

N

"IO::Socket" fournit une interface orientée objet, basée sur IO::Handle, pour la création et l'utilisation de sockets via Socket, qui fournit une interface quasi un pour un à la bibliothèque de sockets

C.

"IO::Socket" est une classe de base qui définit réellement uniquement des méthodes pour les opérations communes à tous les types de sockets. Les opérations spécifiques à un domaine de socket particulier ont des méthodes définies dans des sous-classes de "IO::Socket". Voir IO::Socket::INET, IO::Socket::UNIX et IO::Socket::IP pour des exemples de telles

sous-classes.

"IO::Socket" exportera toutes les fonc

tions (et constantes)
définies par Socket.

MÉTHODE

S

"IO::Socket" hérite de toutes les méthodes de IO::Handle et implémente les nouvelles

suivantes.

accep

t 
my $client_sock = $sock->accept();
my $inet_sock = $sock->accept('IO::Socket::INET')
;

La méthode accept effectuera l'appel système "accept" sur la socket et renverra un nouvel objet. Le nouvel objet sera créé dans la même classe que la socket d'écoute, sauf si un nom de paquet spécifique est spécifié. Cet objet peut être utilisé pour communiquer avec le client qui essayait de se

connecter.

Cela diffère légèrement de la fonction "accept" dans

perlfunc.

Dans un contexte scalaire, la nouvelle socket est renvoyée, ou "undef" en cas d'échec. Dans un contexte de liste, un tableau à deux éléments est renvoy

é contenant la nouvelle socket et l'adress
e du pair ; la liste sera vide en cas d'échec.

atmar

k 
my $integer = $sock->atmark();
# lire des données sur une socket donnée
my $data;
$sock->read($data, 1024) until $sock->atmark;
# ou, exporter la fonction pour l'utiliser :
use IO::Socket 'sockatmark';
$sock->read($data, 1024) until sockatmark($sock)
;

Vrai si la socket est actuellement positionnée à la marque de données urgentes, faux sinon. Si votre système n'implémente pas encore "sockatmark", cela lèvera une

exception.

Si votre système ne prend pas en charge "sockatmark", le "use" la déclaration échouera à la compilation au moment de l'exécution.

autoflush

# par défaut, autoflush sera activé lors de sa référence
$sock->autoflush(); # active autoflush
# désactiver autoflush
$sock->autoflush(0);
# activer autoflush
$sock->autoflush(1);

Cet attribut n'est pas remplacé par l'implémentation d'IO::Handle. Cependant, comme nous l'activons par défaut, il est utile de le mentionner ici.

bind

use Socket qw(pack_sockaddr_in);
my $port = 3000;
my $ip_address = '0.0.0.0';
my $packed_addr = pack_sockaddr_in($port, $ip_address);
$sock->bind($packed_addr);

Lie une adresse réseau à un socket, tout comme le fait bind(2). Renvoie vrai si cela a réussi, faux sinon. Vous devez fournir une adresse encapsulée du type approprié pour le socket.

connected

my $peer_addr = $sock->connected();
if ($peer_addr) {
    say "Nous sommes connectés à $peer_addr";
}

Si le socket est dans un état connecté, l'adresse du pair est renvoyée. Si le socket n'est pas dans un état connecté, "undef" est renvoyé.

Notez que cette méthode considère un socket TCP semi-ouvert comme "dans un état connecté". Spécifiquement, elle ne fait pas la distinction entre les états TCP ESTABLISHED et CLOSE-WAIT ; elle renvoie l'adresse du pair, plutôt que "undef", dans les deux cas. Ainsi, en général, elle ne peut pas être utilisée pour savoir de manière fiable si le pair a initié un arrêt progressif car dans la plupart des cas (voir ci-dessous) la machine d'état TCP locale reste en CLOSE-WAIT jusqu'à ce que l'application locale appelle "shutdown" dans IO::Socket ou "close". Ce n'est qu'à ce moment-là que cette fonction renvoie "undef".

La réserve "dans la plupart des cas" est due au fait que le comportement de la machine d'état TCP locale peut dépendre des options du socket du pair. En particulier, si le socket du pair a "SO_LINGER" activé avec un délai nul, alors le "close" du pair générera un segment "RST". Lors de la réception de ce segment, la pile TCP locale passe immédiatement à l'état CLOSED, et dans cet état, cette méthode renverra "undef".

getsockopt

my $value = $sock->getsockopt(SOL_SOCKET, SO_REUSEADDR);
my $buf = $socket->getsockopt(SOL_SOCKET, SO_RCVBUF);
say "Le tampon de réception fait $buf octets";

Obtient une option associée au socket. Des niveaux autres que "SOL_SOCKET" peuvent être spécifiés ici. Par commodité, cette méthode désencapsulera un tampon d'octets de la bonne taille pour en faire un nombre.

listen

$sock->listen(5);

Fait la même chose que l'appel système listen(2). Renvoie vrai si cela a réussi, faux sinon. Écoute un socket avec une taille de file d'attente donnée.

peername

my $sockaddr_in = $sock->peername();

Renvoie l'adresse "sockaddr" encapsulée de l'autre extrémité de la connexion socket. Elle appelle "getpeername".

protocol

my $proto = $sock->protocol();

Renvoie le numéro du protocole utilisé sur le socket, si connu. Si le protocole est inconnu, comme avec un socket "AF_UNIX", zéro est renvoyé.

recv

my $buffer = "";
my $length = 1024;
my $flags = 0; # par défaut. optionnel
$sock->recv($buffer, $length);
$sock->recv($buffer, $length, $flags);

Similaire en fonctionnalité à "recv" dans perlfunc.

Reçoit un message sur un socket. Tente de recevoir $length caractères de données dans $buffer à partir du socket spécifié. $buffer sera agrandi ou rétréci à la longueur réellement lue. Prend les mêmes drapeaux que l'appel système du même nom. Renvoie l'adresse de l'expéditeur si le protocole du socket le prend en charge ; renvoie une chaîne vide sinon. En cas d'erreur, renvoie "undef". Cet appel est en fait implémenté en utilisant l'appel système recvfrom(2).

Les drapeaux sont des valeurs combinées par OR, comme "MSG_BCAST", "MSG_OOB", "MSG_TRUNC". La valeur par défaut pour les drapeaux est 0.

La valeur mise en cache de "peername" dans IO::Socket est mise à jour avec le résultat de "recv".

Note: Dans Perl v5.30 et plus récent, si le socket a été marqué comme ":utf8", "recv" lèvera une exception. La couche :encoding(...) introduit implicitement la couche ":utf8". Voir "binmode" dans perlfunc.

Note: Dans les versions de Perl antérieures à v5.30, selon l'état du socket, des octets (8 bits) ou des caractères sont reçus. Par défaut, tous les sockets fonctionnent sur des octets, mais par exemple, si le socket a été modifié à l'aide de "binmode" dans perlfunc pour fonctionner avec la couche d'E/S :encoding(UTF-8) (voir le pragma "open" dans perlfunc), les E/S fonctionneront sur des caractères Unicode encodés en UTF8, pas sur des octets. De même pour la couche ":encoding" : dans ce cas, presque tous les caractères peuvent être lus.

send

my $message = "Bonjour tout le monde !";
my $flags = 0; # par défaut à zéro
my $to = '0.0.0.0'; # destination optionnelle
my $sent = $sock->send($message);
$sent = $sock->send($message, $flags);
$sent = $sock->send($message, $flags, $to);

Similaire en fonctionnalité à "send" dans perlfunc.

Envoie un message sur un socket. Tente d'envoyer le message scalaire au socket. Prend les mêmes drapeaux que l'appel système du même nom. Sur les sockets non connectés, vous devez spécifier une destination à laquelle envoyer, auquel cas cela effectue un appel système sendto(2). Renvoie le nombre d'octets envoyés, ou "undef" en cas d'erreur. L'appel système sendmsg(2) est actuellement non implémenté.

L'option "flags" est optionnelle et est par défaut à 0.

Après un envoi réussi avec $to, les appels suivants à "send" sur un socket non connecté sans $to enverront à la même adresse, et $to sera utilisé comme résultat de "peername" dans IO::Socket.

Note: Dans Perl v5.30 et plus récent, si le socket a été marqué comme ":utf8", "send" lèvera une exception. La couche :encoding(...) introduit implicitement la couche ":utf8". Voir "binmode" dans perlfunc.

Note: Dans les versions de Perl antérieures à v5.30, selon l'état du socket, des octets (8 bits) ou des caractères sont envoyés. Par défaut, tous les sockets fonctionnent sur des octets, mais par exemple, si le socket a été modifié à l'aide de "binmode" dans perlfunc pour fonctionner avec la couche d'E/S :encoding(UTF-8) (voir le pragma "open" dans perlfunc), les E/S fonctionneront sur des caractères Unicode encodés en UTF8, pas sur des octets. De même pour la couche ":encoding" : dans ce cas, presque tous les caractères peuvent être envoyés.

setsockopt

$sock->setsockopt(SOL_SOCKET, SO_REUSEADDR, 1);
$sock->setsockopt(SOL_SOCKET, SO_RCVBUF, 64*1024);

Définit une option associée au socket. Des niveaux autres que "SOL_SOCKET" peuvent être spécifiés ici. Par commodité, cette méthode convertira un nombre en un tampon d'octets encapsulé.

shutdown

$sock->shutdown(SHUT_RD); # nous avons arrêté de lire les données
$sock->shutdown(SHUT_WR); # nous avons arrêté d'écrire les données
$sock->shutdown(SHUT_RDWR); # nous avons arrêté d'utiliser ce socket

Arrête une connexion socket de la manière indiquée par la valeur passée, qui a la même interprétation que dans l'appel système du même nom.

Ceci est utile avec les sockets lorsque vous voulez dire à l'autre partie que vous avez fini d'écrire mais pas de lire, ou vice versa. C'est aussi une forme plus insistante de "close" car elle désactive également le descripteur de fichier dans toutes les copies forkées dans d'autres processus.

Renvoie 1 en cas de succès ; en cas d'erreur, renvoie "undef" si le socket n'est pas un descripteur de fichier valide, ou renvoie 0 et définit $! pour toute autre défaillance.

sockdomain

my $domain = $sock->sockdomain();

Renvoie le numéro du type de domaine de socket. Par exemple, pour un socket "AF_INET", la valeur de &AF_INET sera renvoyée.

socket

my $sock = IO::Socket->new(); # aucune valeur donnée
# maintenant créons réellement un socket avec la méthode socket
# le domaine, le type et le protocole sont requis
$sock = $sock->socket(AF_INET, SOCK_STREAM, 'tcp');

Ouvre un socket du type spécifié et le renvoie. Le domaine, le type et le protocole sont spécifiés comme pour l'appel système du même nom.
