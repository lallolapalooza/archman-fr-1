NOM

IO::HTML - Ouvrir un fichier HTML avec détection automatique du jeu de caractères

VERSION

Ce document décrit la version 1.004 de IO::HTML, publiée le 26 septembre 2020.

SYNOPSIS

use IO::HTML;                 # exporte html_file par défaut
use HTML::TreeBuilder;
my $tree = HTML::TreeBuilder->new_from_file(
             html_file('foo.html')
           );
# Interface alternative :
open(my $in, '<:raw', 'bar.html');
my $encoding = IO::HTML::sniff_encoding($in, 'bar.html');

DESCRIPTION

IO::HTML fournit un moyen simple d'ouvrir un fichier contenant du HTML tout en déterminant automatiquement son encodage. Il utilise l'algorithme de détection d'encodage HTML5 spécifié dans la section 8.2.2.2 de la norme provisoire.

L'algorithme tel qu'implémenté ici est le suivant :

1.
Si le fichier commence par un marqueur d'ordre des octets (BOM) indiquant UTF-16LE, UTF-16BE ou UTF-8, alors c'est l'encodage.
2.
Si les premiers $bytes_to_check octets du fichier contiennent une balise "<meta>" qui indique le jeu de caractères, et que Encode reconnaît le nom du jeu de caractères spécifié, alors c'est l'encodage. (Cette partie de l'algorithme est implémentée par "find_charset_in".)

La balise "<meta>" peut être dans l'un des deux formats suivants :

<meta charset="...">
<meta http-equiv="Content-Type" content="...charset=...">

La recherche est insensible à la casse, et l'ordre des attributs dans la balise est sans importance. Les attributs supplémentaires de la balise sont ignorés. La première balise correspondante avec un encodage reconnu met fin à la recherche.

3.
Si les premiers $bytes_to_check octets du fichier sont valides en UTF-8 (avec au moins 1 caractère non ASCII), alors l'encodage est UTF-8.
4.
À défaut, utiliser l'encodage de caractères par défaut. La norme HTML5 suggère que l'encodage par défaut doit dépendre de la locale, mais actuellement, il s'agit toujours de "cp1252" sauf si vous définissez $IO::HTML::default_encoding à une autre valeur. Note : "sniff_encoding" n'applique pas cette étape ; seule "html_file" le fait.

SOUS_ROUTINES

html_file

$descripteur_fichier = html_file($nom_fichier, \%options);

Cette fonction (exportée par défaut) est le point d'entrée principal. Elle ouvre le fichier spécifié par $nom_fichier en lecture, utilise "sniff_encoding" pour trouver une couche d'encodage appropriée, et l'applique. Elle applique également la couche ":crlf". Si le fichier commence par un BOM, le descripteur de fichier est positionné juste après le BOM.

Le deuxième argument optionnel est un hashref contenant des options. Les clés possibles sont décrites sous "find_charset_in".

Si "sniff_encoding" ne parvient pas à déterminer l'encodage, il utilise par défaut $IO::HTML::default_encoding, qui est défini sur "cp1252" (alias Windows-1252) par défaut. Selon la norme, l'encodage par défaut devrait dépendre de la locale, mais ce n'est pas actuellement implémenté.

Elle meurt si le fichier ne peut pas être ouvert, ou si "sniff_encoding" ne parvient pas à déterminer l'encodage et que $IO::HTML::default_encoding a été défini sur "undef".

html_file_and_encoding

($descripteur_fichier, $encoding, $bom)
  = html_file_and_encoding($nom_fichier, \%options);

Cette fonction (exportée uniquement sur demande) est identique à "html_file", mais retourne plus d'informations. En plus du descripteur de fichier, elle retourne le nom de l'encodage utilisé, et un indicateur indiquant si un marqueur d'ordre des octets a été trouvé (si $bom est vrai, le fichier commençait par un BOM). Cela peut être utile si vous souhaitez réécrire le fichier (surtout en conjonction avec la fonction "html_outfile").

Le deuxième argument optionnel est un hashref contenant des options. Les clés possibles sont décrites sous "find_charset_in".

Elle meurt si le fichier ne peut pas être ouvert, ou si "sniff_encoding" ne parvient pas à déterminer l'encodage et que $IO::HTML::default_encoding a été défini sur "undef".

Le résultat de l'appel de "html_file_and_encoding" en contexte scalaire est indéfini (au sens C, il n'y a aucune garantie de ce que vous obtiendrez).

html_outfile

$descripteur_fichier = html_outfile($nom_fichier, $encoding, $bom);

Cette fonction (exportée uniquement sur demande) ouvre $nom_fichier en sortie en utilisant $encoding, et y écrit un BOM si $bom est vrai. Si $encoding est "undef", il utilise par défaut $IO::HTML::default_encoding. $encoding peut être soit un nom d'encodage, soit un objet Encode::Encoding.

Elle meurt si le fichier ne peut pas être ouvert, ou si $encoding et $IO::HTML::default_encoding sont tous deux "undef".

sniff_encoding

($encoding, $bom) = sniff_encoding($descripteur_fichier, $nom_fichier, \%options);

Cette fonction (exportée uniquement sur demande) exécute l'algorithme de détection d'encodage HTML5 sur $descripteur_fichier (qui doit être positionnable, et devrait avoir été ouvert en mode ":raw"). $nom_fichier n'est utilisé que pour les messages d'erreur (en cas de problème lors de l'utilisation du descripteur de fichier), et vaut par défaut "file" s'il est omis. Le troisième argument optionnel est un hashref contenant des options. Les clés possibles sont décrites sous "find_charset_in".

Elle retourne le nom canonique de Perl pour l'encodage, qui n'est pas nécessairement le même que le nom du jeu de caractères MIME ou IANA. Elle retourne "undef" si l'encodage ne peut être déterminé. $bom est vrai si le fichier commençait par un marqueur d'ordre des octets. En contexte scalaire, elle ne retourne que $encoding.

La position du descripteur de fichier est restaurée à sa position d'origine (normalement le début du fichier) à moins que $bom soit vrai. Dans ce cas, la position est immédiatement après le BOM.

Astuce : Si vous souhaitez exécuter "sniff_encoding" sur un fichier que vous avez déjà chargé dans une chaîne, ouvrez un fichier en mémoire sur la chaîne, et passez ce descripteur :

($encoding, $bom) = do {
  open(my $fh, '<', \$chaine);  sniff_encoding($fh)
};

(Cela n'a de sens que si $chaine contient des octets, pas des caractères.)

find_charset_in

$encoding = find_charset_in($chaine_contenant_HTML, \%options);

Cette fonction (exportée uniquement sur demande) recherche des informations sur le jeu de caractères dans une balise "<meta>" dans un document HTML éventuellement incomplet en utilisant l'algorithme en "deux étapes" spécifié par HTML5. Elle ne recherche pas de BOM. La balise "<meta>" doit commencer dans les $IO::HTML::bytes_to_check premiers octets de la chaîne.

Elle retourne le nom canonique de Perl pour l'encodage, qui n'est pas nécessairement le même que le nom du jeu de caractères MIME ou IANA. Elle retourne "undef" si aucun jeu de caractères n'est spécifié ou si le jeu de caractères spécifié n'est pas reconnu par le module Encode.

Le deuxième argument optionnel est un hashref contenant des options. Les clés suivantes sont reconnues :

"encoding"
Si vrai, renvoie l'objet Encode::Encoding au lieu de son nom. Défaut à faux.
"need_pragma"
Si vrai (par défaut), suit la spécification HTML5 et examine l'attribut "content" uniquement de "<meta http-equiv="Content-Type"". S'il est défini à 0, assouplit la spécification HTML5 et recherche "charset=" dans l'attribut "content" de *toutes* les balises meta.

EXPORTATIONS

Par défaut, seule "html_file" est exportée. D'autres fonctions peuvent être exportées sur demande.

Pour ceux qui préfèrent ne pas exporter de fonctions, toutes les fonctions commençant par "html_" ont un alias sans ce préfixe (par exemple, vous pouvez appeler IO::HTML::file(...) au lieu de IO::HTML::html_file(...). Ces alias ne sont pas exportables.

Les balises d'exportation suivantes sont disponibles :

":all"
Toutes les fonctions exportables.
":rw"
"html_file", "html_file_and_encoding", "html_outfile".

VOIR AUSSI

La spécification HTML5, section 8.2.2.2 Détermination de l'encodage des caractères : http://www.w3.org/TR/html5/syntax.html#determining-the-character-encoding

DIAGNOSTICS

"Impossible de lire %s : %s"
Le fichier spécifié n'a pas pu être lu pour la raison spécifiée par $!.
"Impossible de se positionner sur %s : %s"
Le fichier spécifié n'a pas pu être réinitialisé pour la raison spécifiée par $!.
"Échec d'ouverture de %s : %s"
Le fichier spécifié n'a pas pu être ouvert en lecture pour la raison spécifiée par $!.
"Aucun encodage par défaut spécifié"
L'algorithme "sniff_encoding" n'a pas trouvé d'encodage à utiliser, et vous avez défini $IO::HTML::default_encoding à "undef".

CONFIGURATION ET ENVIRONNEMENT

Il existe deux variables globales qui affectent IO::HTML. Si vous avez besoin de les modifier, vous devriez le faire en utilisant "local" si possible :

my $file = do {
  # Ce fichier peut définir le charset plus tard dans l'en-tête
  local $IO::HTML::bytes_to_check = 4096;
  html_file(...);
};
$bytes_to_check
C'est le nombre d'octets que "sniff_encoding" lira depuis le flux. C'est aussi le nombre d'octets que "find_charset_in" recherchera pour une balise "<meta>" contenant des informations sur le charset. Il doit s'agir d'un entier positif.

La spécification HTML 5 recommande d'utiliser la valeur par défaut de 1024, mais certaines pages ne suivent pas la spécification.

$default_encoding
C'est l'encodage que "html_file" et "html_file_and_encoding" utiliseront si aucun encodage ne peut être détecté par "sniff_encoding". La valeur par défaut est "cp1252" (alias Windows-1252).

Le définir à "undef" fera échouer les sous-routines de fichier si "sniff_encoding" ne parvient pas à déterminer l'encodage. ( "sniff_encoding" lui-même n'utilise pas $default_encoding).

DÉPENDANCES

IO::HTML n'a aucune dépendance non standard pour Perl 5.8.7+. Avec les versions antérieures de Perl 5.8, vous devez mettre à jour Encode à au moins la version 2.10, et vous devrez peut-être mettre à jour Exporter à au moins la version 5.57.
