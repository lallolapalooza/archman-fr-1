IO::Compress::Bzip2 - Écrire des fichiers/tampons bzip2

RÉSUMÉ

use IO::Compress::Bzip2 qw(bzip2 $Bzip2Error) ;

    or die "bzip2 failed: $Bzip2Error\n";
my $z = IO::Compress::Bzip2->new( $output [,OPTS] )
    or die "bzip2 failed: $Bzip2Error\n";
$z->print($string);
$z->printf($format, $string);
$z->write($string);
$z->syswrite($string [, $length, $offset]);
$z->flush();
$z->tell();
$z->eof();
$z->seek($position, $whence);
$z->binmode();
$z->fileno();

$z->autoflush();

printf $z $format, $string;

eof $z

binmode $z

DESCRIPTION

Ce module fournit une interface Perl qui permet d'écrire des données compressées bzip2 vers des fichiers ou des tampons.

Pour lire des fichiers/tampons bzip2, voir le module compagnon IO::Uncompress::Bunzip2.

Interface fonctionnelle

Une fonction de premier niveau, "bzip2", est fournie pour effectuer une compression « en une seule fois » entre des tampons et/ou des fichiers. Pour un contrôle plus fin du processus de compression, voir la section « Interface OO ».

use IO::Compress::Bzip2 qw(bzip2 $Bzip2Error) ;
bzip2 $input_filename_or_reference => $output_filename_or_reference [,OPTS]
    or die "bzip2 failed: $Bzip2Error\n";

L'interface fonctionnelle nécessite Perl 5.005 ou supérieur.

bzip2 $input_filename_or_reference => $output_filename_or_reference [, OPTS]

"bzip2" attend au moins deux paramètres, $input_filename_or_reference et $output_filename_or_reference et zéro ou plusieurs paramètres optionnels (voir « Paramètres optionnels »)

Le $input_filename_or_reference paramètre

Le paramètre, $input_filename_or_reference, est utilisé pour définir la source des données non compressées.

Il peut prendre l'une des formes suivantes :

Un nom de fichier
Si le $input_filename_or_reference paramètre est un scalaire simple, il est supposé être un nom de fichier. Ce fichier sera ouvert en lecture et les données d'entrée seront lues à partir de celui-ci.
Un filehandle
Si le $input_filename_or_reference paramètre est un filehandle, les données d'entrées seront lues à partir de celui-ci. La chaîne '-' peut être utilisée comme alias pour l'entrée standard.
Une référence scalaire
Si $input_filename_or_reference est une référence scalaire, les données d'entrée seront lues à partir de $$input_filename_or_reference.
Une référence de tableau
Si $input_filename_or_reference est une référence de tableau, chaque élément du tableau doit être un nom de fichier.

Les données d'entrée seront lues à partir de chaque fichier à tour de rôle.

Le tableau complet sera parcouru pour s'assurer qu'il ne contient que des noms de fichiers valides avant que des données ne soient compressées.

Une chaîne Input FileGlob
Si $input_filename_or_reference est une chaîne qui est délimitée par les caractères "<" et ">" "bzip2" supposera qu'il s'agit d'une chaîne input fileglob. L'entrée est la liste des fichiers qui correspondent au fileglob.

Voir File::GlobMapper pour plus de détails.

Si le $input_filename_or_reference paramètre est de tout autre type, "undef" sera retourné.

Le $output_filename_or_reference paramètre

Le paramètre $output_filename_or_reference est utilisé pour contrôler la destination des données compressées. Ce paramètre peut prendre l'une de ces formes.

Un nom de fichier
Si le $output_filename_or_reference paramètre est un scalaire simple, il est supposé être un nom de fichier. Ce fichier sera ouvert en écriture et les données compressées seront écrites dans celui-ci.
Un filehandle
Si le $output_filename_or_reference paramètre est un filehandle, les données compressées seront écrites dans celui-ci. La chaîne '-' peut être utilisée comme alias pour la sortie standard.
Une référence scalaire
Si $output_filename_or_reference est une référence scalaire, les données compressées seront stockées dans $$output_filename_or_reference.
Une référence de tableau
Si $output_filename_or_reference est une référence de tableau, les données compressées seront ajoutées au tableau.
Une chaîne Output FileGlob
Si $output_filename_or_reference est une chaîne qui est délimitée par les caractères "<" et ">" "bzip2" supposera qu'il s'agit d'une chaîne output fileglob. La sortie est la liste des fichiers qui correspondent au fileglob.

Quand $output_filename_or_reference est une chaîne fileglob, $input_filename_or_reference doit également être une chaîne fileglob. Tout autre cas est une erreur.

Voir File::GlobMapper pour plus de détails.

Si le $output_filename_or_reference paramètre est de tout autre type, "undef" sera retourné.

Notes

Quand $input_filename_or_reference correspond à plusieurs fichiers/tampons et $output_filename_or_reference est un seul fichier/tampon, les fichiers/tampons d'entrée seront stockés dans $output_filename_or_reference sous forme de série concaténée de flux de données compressés.

Paramètres optionnels

Les paramètres optionnels pour la fonction en une seule fois "bzip2" sont (pour la plupart) identiques à ceux utilisés avec l'interface OO définie dans la section « Options du constructeur ». Les exceptions sont listées ci-dessous

"AutoClose => 0|1"
Cette option s'applique à tout flux de données d'entrée ou de sortie de "bzip2" qui sont des filehandles.

Si "AutoClose" est spécifié, et que la valeur est vraie, cela entraînera la fermeture de tous les filehandles d'entrée et/ou de sortie une fois que "bzip2" sera terminé.

Ce paramètre vaut 0 par défaut.

"BinModeIn => 0|1"
Cette option est désormais sans effet. Tous les fichiers seront lus en binmode.
"Append => 0|1"
Le comportement de cette option dépend du type de flux de données de sortie.
  • Un tampon

    Si "Append" est activé, toutes les données compressées seront ajoutées à la fin du tampon de sortie. Sinon, le tampon de sortie sera vidé avant qu'aucune donnée compressée n'y soit écrite.

  • Un nom de fichier

    Si "Append" est activé, le fichier sera ouvert en mode ajout. Sinon, le contenu du fichier, s'il y en a un, sera tronqué avant qu'aucune donnée compressée n'y soit écrite.

  • Un filehandle

    Si "Append" est activé, le filehandle sera positionné à la fin du fichier via un appel à "seek" avant qu'aucune donnée compressée ne soits écrits dedans. Sinon, le pointeur de fichier ne sera pas déplacé.

Lorsque "Append" est spécifié et défini à true, il ajoutera toutes les données compressées au flux de données de sortie.

Ainsi, lorsque la sortie est un gestionnaire de fichier, il effectuera un seek vers la fin de fichier (eof) avant d'écrire des données compressées. Si la sortie est un nom de fichier, il sera ouvert en mode ajout. Si la sortie est un tampon, toutes les données compressées seront ajoutées au tampon existant.

Inversement, lorsque "Append" n'est pas spécifié, ou s'il est présent et défini à false, il fonctionnera comme suit.

Lorsque la sortie est un nom de fichier, il tronquera le contenu du fichier avant d'écrire des données compressées. Si la sortie est un gestionnaire de fichier, sa position ne sera pas modifiée. Si la sortie est un tampon, il sera effacé avant que des données compressées ne soient produites.

Valeur par défaut : 0.

Oneshot Exemples

Voici quelques exemples qui montrent les capacités du module.

Streaming

Cet exemple de ligne de commande très simple démontre les capacités de streaming du module. Le code lit des données depuis STDIN, les compresse, et écrit les données compressées vers STDOUT.

$ echo hello world | perl -MIO::Compress::Bzip2=bzip2 -e 'bzip2 \*STDIN => \*STDOUT' >output.bz2

Le nom de fichier spécial "-" peut être utilisé comme substitut pour à la fois "\*STDIN" et "\*STDOUT", donc ce qui précède peut être réécrit comme

$ echo hello world | perl -MIO::Compress::Bzip2=bzip2 -e 'bzip2 "-" => "-"' >output.bz2

Compression d'un fichier du système de fichiers

Pour lire le contenu du fichier "file1.txt" et écrire les données compressées dans le fichier "file1.txt.bz2".

use strict ;
use warnings ;
use IO::Compress::Bzip2 qw(bzip2 $Bzip2Error) ;
my $input = "file1.txt";
bzip2 $input => "$input.bz2"
    or die "bzip2 failed: $Bzip2Error\n";

Lecture depuis un gestionnaire de fichier et écriture dans un tampon en mémoire

Pour lire depuis un gestionnaire de fichier Perl existant, $input, et écrire les données compressées dans un tampon, $buffer.

use strict ;
use warnings ;
use IO::Compress::Bzip2 qw(bzip2 $Bzip2Error) ;
use IO::File ;
my $input = IO::File->new( "<file1.txt" )
    or die "Cannot open 'file1.txt': $!\n" ;
my $buffer ;
bzip2 $input => \$buffer
    or die "bzip2 failed: $Bzip2Error\n";

Compression de plusieurs fichiers

Pour compresser tous les fichiers du répertoire "/my/home" qui correspondent à "*.txt" et stocker les données compressées dans le même répertoire

use strict ;
use warnings ;
use IO::Compress::Bzip2 qw(bzip2 $Bzip2Error) ;
bzip2 '</my/home/*.txt>' => '<*.bz2>'
    or die "bzip2 failed: $Bzip2Error\n";

et si vous voulez compresser chaque fichier un par un, ceci fera l'affaire

use strict ;
use warnings ;
use IO::Compress::Bzip2 qw(bzip2 $Bzip2Error) ;
for my $input ( glob "/my/home/*.txt" )
{
    my $output = "$input.bz2" ;
    bzip2 $input => $output
        or die "Error compressing '$input': $Bzip2Error\n";
}

Interface OO

Constructeur

Le format du constructeur pour "IO::Compress::Bzip2" est montré ci-dessous

my $z = IO::Compress::Bzip2->new( $output [,OPTS] )
    or die "IO::Compress::Bzip2 failed: $Bzip2Error\n";

Le constructeur prend un paramètre obligatoire, $output, défini ci-dessous, et zéro ou plusieurs "OPTS", définis dans "Options du constructeur".

Il renvoie un objet "IO::Compress::Bzip2" en cas de succès et "undef" en cas d'échec. La variable $Bzip2Error contiendra un message d'erreur en cas d'échec.

Si vous utilisez Perl 5.005 ou une version supérieure, l'objet, $z, renvoyé par IO::Compress::Bzip2 peut être utilisé exactement comme un gestionnaire de fichier IO::File. Cela signifie que toutes les opérations de fichier de sortie normales peuvent être effectuées avec $z. Par exemple, pour écrire dans un fichier/tampon compressé, vous pouvez utiliser l'une ou l'autre de ces formes

$z->print("hello world\n");
print $z "hello world\n";

Voici un exemple simple d'utilisation de l'interface OO pour créer un fichier de sortie "myfile.bz2" et y écrire des données.

my $filename = "myfile.bz2";
my $z = IO::Compress::Bzip2->new($filename)
    or die "IO::Compress::Bzip2 failed: $Bzip2Error\n";
$z->print("abcde");
$z->close();

Voir les "Exemples" pour plus de détails.

Le paramètre obligatoire $output est utilisé pour contrôler la destination des données compressées. Ce paramètre peut prendre l'une de ces formes.

Un nom de fichier
Si le $output paramètre est un scalaire simple, on suppose qu'il s'agit d'un nom de fichier. Ce fichier sera ouvert en écriture et les données compressées y seront écrites.
Un gestionnaire de fichier
Si le $output paramètre est un gestionnaire de fichier, les données compressées y seront écrites. La chaîne '-' peut être utilisée comme alias pour la sortie standard.
Une référence de scalaire
Si $output est une référence de scalaire, les données compressées seront stockées dans $$output.

Si le $output paramètre est de tout autre type, "IO::Compress::Bzip2"::new renverra undef.

Options du constructeur

"OPTS" est toute combinaison de zéro ou plusieurs des options suivantes :

"AutoClose => 0|1"
Cette option n'est valide que lorsque le $output paramètre est un gestionnaire de fichier. Si spécifiée et si la valeur est vraie, elle entraînera la fermeture du $output une fois que la méthode "close" est appelée ou que l'objet "IO::Compress::Bzip2" est détruit.

Ce paramètre a une valeur par défaut de 0.

"Append => 0|1"
Ouvre $output en mode ajout.

Le comportement de cette option dépend du type de $output.

  • Un tampon

    Si $output est un tampon et que "Append" est activé, toutes les données compressées seront ajoutées à la fin de $output. Sinon, $output sera effacé avant que des données n'y soient écrites.

  • Un nom de fichier

    Si $output est un nom de fichier et que "Append" est activé, le fichier sera ouvert en mode ajout. Sinon, le contenu du fichier, s'il y en a un, sera tronqué avant que des données compressées n'y soient écrites.

  • Un gestionnaire de fichier

    Si $output est un gestionnaire de fichier, le pointeur de fichier sera positionné à la fin du fichier via un appel à "seek" avant que des données compressées n'y soient écrites. Sinon, le pointeur de fichier ne sera pas déplacé.

Ce paramètre a une valeur par défaut de 0.

"BlockSize100K => number"
Spécifie le nombre de blocs de 100K que bzip2 utilise lors de la compression.

Les valeurs valides vont de 1 à 9, où 9 est la meilleure compression.

La valeur par défaut est 1.

"WorkFactor => number"
Spécifie l'effort que bzip2 doit fournir avant de recourir à un algorithme de compression de repli plus lent.

Les valeurs valides vont de 0 à 250, où 0 signifie utiliser la valeur par défaut 30.

La valeur par défaut est 0.

"Strict => 0|1"
Ceci est une option de remplissage.

Exemples

Streaming

Cet exemple de ligne de commande très simple démontre les capacités de streaming du module. Le code lit des données depuis STDIN ou tous les fichiers donnés sur la ligne de commande, les compresse, et écrit les données compressées vers STDOUT.

use strict ;
use warnings ;
use IO::Compress::Bzip2 qw(bzip2 $Bzip2Error) ;
my $z = IO::Compress::Bzip2->new("-", Stream => 1)
    or die "IO::Compress::Bzip2 failed: $Bzip2Error\n";
while (<>) {
    $z->print("abcde");
}
$z->close();

Notez l'utilisation de "-" pour signifier "STDOUT". Alternativement, vous pouvez utiliser "\*STDOUT".

Compression d'un fichier du système de fichiers

Pour lire le contenu du fichier "file1.txt" et écrire les données compressées dans le fichier "file1.txt.bz2" il y a quelques options

Commencez par créer l'objet de compression et ouvrir le fichier d'entrée

use strict ;
use warnings ;
use IO::Compress::Bzip2 qw(bzip2 $Bzip2Error) ;
my $input = "file1.txt";
my $z = IO::Compress::Bzip2->new("file1.txt.bz2")
    or die "IO::Compress::Bzip2 failed: $Bzip2Error\n";
# open the input file
open my $fh, "<", "file1.txt"
    or die "Cannot open file1.txt: $!\n";
# loop through the input file & write to the compressed file
while (<$fh>) {
    $z->print($_);
}
# not forgetting to close the compressed file
$z->close();

NAME

IO::Compress::Bzip2 - Perl interface to the bzip2 compression library

SYNOPSIS

use IO::Compress::Bzip2 ([FILTER]) ;

# Functional interface
my $z = bzip2 $inputfile, $outputfile, FILTER, ... ;
my $z = bzip2 \$inputstring, \$outputstring, FILTER, ... ;

# OO interface
my $z = IO::Compress::Bzip2->new( $outputfile, FILTER, ... ) ;
my $z = IO::Compress::Bzip2->new( \$outputstring, FILTER, ... ) ;

# Common methods
$z->write( $data ) ;
$z->syswrite( $data ) ;
$z->print( $data ) ;
$z->printf( $format, $data ) ;
$z->read( $buffer, $length ) ;
$z->sysread( $buffer, $length ) ;
$z->close() ;

# Functional interface specific
my $status = bzip2( $inputfile, $outputfile, FILTER, ... ) ;
my $status = bzip2( \$inputstring, \$outputstring, FILTER, ... ) ;

# Uncompressing (see IO::Uncompress::Bunzip2)
use IO::Uncompress::Bunzip2 ;
my $z = Bunzip2->new( $inputfile ) ;
my $z = Bunzip2->new( \$inputstring ) ;
my $string = $z->read( $buffer, $length ) ;
my $status = $z->close() ;

DESCRIPTION

This module provides a Perl interface to the bzip2 compression library, allowing you to compress and uncompress data transparently.

It can operate in two modes:

  • Functional Interface: A single function call is used to compress an entire file or string.

  • OO Interface: An object is created and methods are called on it to write data, which is then compressed on the fly.

The OO interface provides a filehandle-like interface to the compressor, allowing you to write data in chunks.

It is also possible to uncompress bzip2 compressed data using the related module IO::Uncompress::Bunzip2.

Constructor Options

The following options can be passed to the new method or the functional interface:

Append
If this option is set, the output file will be appended to, rather than overwritten.
AutoClose
If this option is set, the output filehandle will be closed when the object is destroyed.
BlockSize
Sets the block size used for compression. The default block size is 900k. Valid values are between 1 and 900 (in k).
CompressLevel
Sets the compression level. This is a value between 0 and 9. The default is 9.
-Level
An alias for CompressLevel.
Name
The name of the file the object is associated with. This is used when generating error messages.
Debug
Enables or disables debugging messages.
Warn
Enables or disables warnings.
CloseOnExec
If set, the underlying filehandle will have its close-on-exec flag set. This is disabled by default.

Functional Interface

The functional interface is simpler to use for one-off compressions:

use IO::Compress::Bzip2 ;

# Compress a file
my $status = bzip2( 'input.txt', 'output.bz2' ) ;
die "Compression failed: $!" unless $status ;

# Compress a string
my $output_string = bzip2( \$input_string ) ;
die "Compression failed: $!" unless defined $output_string ;

The functional interface accepts the same options as the OO interface.

OO Interface

The OO interface provides more flexibility, allowing you to compress data in chunks:

use IO::Compress::Bzip2 ;

my $z = IO::Compress::Bzip2->new( 'output.bz2' )
    or die "Could not open output.bz2: $!" ;

$z->write( "This is the first part.\n" ) ;
$z->write( "This is the second part.\n" ) ;
$z->close() ;

You can also compress strings:

use IO::Compress::Bzip2 ;

my $z = IO::Compress::Bzip2->new( \$output_string )
    or die "Could not create output string buffer: $!" ;

$z->write( "This is the first part.\n" ) ;
$z->write( "This is the second part.\n" ) ;
$z->close() ;

Methods

print

Usage is

$z->print($data)
print $z $data

Compresses and outputs the contents of the $data parameter using the underlying "print" built-in.

Returns true if successful.

printf

Usage is

$z->printf($format, $data)
printf $z $format, $data

Compresses and outputs the contents of the $data parameter.

Returns true if successful.

syswrite

Usage is

$z->syswrite $data
$z->syswrite $data, $length
$z->syswrite $data, $length, $offset

Compresses and outputs the contents of the $data parameter.

Returns the number of uncompressed bytes written, or "undef" if unsuccessful.

write

Usage is

$z->write $data
$z->write $data, $length
$z->write $data, $length, $offset

Compresses and outputs the contents of the $data parameter.

Returns the number of uncompressed bytes written, or "undef" if unsuccessful.

flush

Usage is

$z->flush;

Flushes any pending compressed data to the output file/buffer.

TODO

Returns true on success.

tell

Usage is

$z->tell()
tell $z

Returns the uncompressed file offset.

eof

Usage is

$z->eof();
eof($z);

Returns true if the "close" method has been called.

seek

$z->seek($position, $whence);
seek($z, $position, $whence);

Provides a sub-set of the "seek" functionality, with the restriction that it is only legal to seek forward in the output file/buffer. It is a fatal error to attempt to seek backward.

Empty parts of the file/buffer will have NULL (0x00) bytes written to them.

The $whence parameter takes one the usual values, namely SEEK_SET, SEEK_CUR or SEEK_END.

Returns 1 on success, 0 on failure.

binmode

Usage is

$z->binmode
binmode $z ;

This is a noop provided for completeness.

opened

$z->opened()

Returns true if the object currently refers to a opened file/buffer.

autoflush

my $prev = $z->autoflush()
my $prev = $z->autoflush(EXPR)

If the $z object is associated with a file or a filehandle, this method returns the current autoflush setting for the underlying filehandle. If "EXPR" is present, and is non-zero, it will enable flushing after every write/print operation.

If $z is associated with a buffer, this method has no effect and always returns "undef".

Note that the special variable $| cannot be used to set or retrieve the autoflush setting.

input_line_number

$z->input_line_number()
$z->input_line_number(EXPR)

This method always returns "undef" when compressing.

fileno

$z->fileno()
fileno($z)

If the $z object is associated with a file or a filehandle, "fileno" will return the underlying file descriptor. Once the "close" method is called "fileno" will return "undef".

If the $z object is associated with a buffer, this method will return "undef".

close

$z->close() ;
close $z ;

Flushes any pending compressed data and then closes the output file/buffer.

For most versions of Perl this method will be automatically invoked if the IO::Compress::Bzip2 object is destroyed (either explicitly or by the variable with the reference to the object going out of scope). The exceptions are Perl versions 5.005 through 5.00504 and 5.8.0. In these cases, the "close" method will be called automatically, but not until global destruction of all live objects when the program is terminating.

Therefore, if you want your scripts to be able to run on all versions of Perl, you should call "close" explicitly and not rely on automatic closing.

Returns true on success, otherwise 0.

If the "AutoClose" option has been enabled when the IO::Compress::Bzip2 object was created, and the object is associated with a file, the underlying file will also be closed.

newStream([OPTS])

Usage is

$z->newStream( [OPTS] )

Closes the current compressed data stream and starts a new one.

OPTS consists of any of the options that are available when creating the $z object.

See the "Constructor Options" section for more details.
