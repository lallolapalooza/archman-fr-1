DESCRIPTIO

N

Appeler la fonction intégrée de Perl system() est facile, déterminer si elle a réussi est difficile. Soyons honnêtes, $? n'est pas la plus agréable des variables avec laquelle jouer, et même si vous la vérifiez, produire une chaîne d'erreur bien formatée demande beaucoup de travail. "IPC::System::Simple" supprime le travail difficile d'appel des commandes externes. En fait, si vous voulez vraiment être paresseux, vous pouvez simplement écrire

:

use IPC::System::Simple qw(system)

; 
et toutes
vos

commandes "system" réussiront (s'exécuteront jusqu'à la fin et renverront une valeur de sortie nulle) ou mourront avec des messages de diagnostic

riches.

Le module "IPC::System::Simple" fournit également un remplacement simple de l'opérateur guillemets droits de Perl. Écrivez simplement

: 
use IPC::System::Simple qw(capture)
;

et utilisez ensuite la commande "capture()" comme vous utiliseriez les guillemets droits. S'il y a une erreur, elle mourra avec une description détaillée de ce qui s'est mal passé. Mieux encore, vous pouvez même utiliser capturex() pour exécuter l'équivalent des guillemets droits, mais sans le shell

: 
use IPC::System::Simple qw(capturex);
my $result = capturex($command, @args)
;

Si vous voulez plus de puissance que l'interface de base, y compris la

possibilité de spécifier quelles valeurs de sortie sont acceptables, de ca
pturer les erreurs ou de traiter les diagnostics, alors continuez à lire !

UTILISATION

AVANCÉE

run() et system(

)

"IPC::System::Simple" fournit une sous-routine appelée "run", qui exécute une commande en utilisant la même sémantique que le "system" intégré de Perl

: 
use IPC::System::Simple qw(run);
run("cat *.txt");           # Exécute la commande via le shell
run("cat","/etc/motd");     # Exécute la commande sans
shell

La différence principale entre le system intégré de Perl et la commande "run" est que "run" lancera une exception en cas d'échec, et permet de définir une liste de valeurs de sortie acceptables. Voir « Valeurs de sortie » pour plus

d'informations.

En fait, vous pouvez même faire en sorte que "IPC::System::Simple" remplace la fonction "system" par défaut pour votre paquet afin qu'elle ait le même comportement

: 
use IPC::System::Simple qw(system);
system("cat *.txt");  # system réussit maintenant ou meurt
!

"system" et "run" sont des alias l'un de

l'autre.

Voir aussi "runx(), systemx() et capturex()" pour les variantes de system() et run() qui n'invoquent jamais le she

ll, même avec un
seul argument.

capture(

)

Une deuxième sous-routine, nommée "capture", exécute une commande avec la même sémantique que les guillemets droits intégrés de Perl (et qx())

: 
use IPC::System::Simple qw(capture);
# Capture du texte tout en invoquant le shell.
my $file  = capture("cat /etc/motd");
my @lines = capture("cat /etc/passwd")
;

Cependant, contrairement aux guillemets droits réguliers, qui utilisent toujours le shell, "capture" contournera le shell lorsqu'elle est appelée avec plusieurs arguments

: 
# Capture du texte tout en évitant le shell.
my $file  = capture("cat", "/etc/motd");
my @lines = capture("cat", "/etc/passwd")
;

Voir aussi "runx(), systemx() et capturex()" pour une variante de capture() qui n'invoque jamais l

e shell, même avec
un seul argument.

runx(), systemx() et capturex(

)

Les commandes runx(), systemx() et capturex() sont identiques aux formes à arguments multiples de run(), system() et capture() respectivement, mais n'invoquent jamais le shell, même lorsqu'elles sont appelées avec un seul argument. Ces formes sont particulièrement utiles lorsque la liste d'arguments d'une commande peut être vide, par exemple

: 
systemx($cmd, @args)
;

L'utilisation de systemx() ici garantit que le shell ne sera jamais invoqué, même si @args es

t v
ide.

Gestion des

exceptions

Dans le cas où la commande renvoie un statut inattendu, à la fois "run" et "capture" lanceront une exception, qui si elle n'est pas interceptée, terminera votre programme avec une

erreur.

Capturer l'exception est facile

: 
eval {
    run("cat *.txt");
};
if ($@) {
    print "Something went wrong - $@\n";
}

Voir la section diagnostics ci-dessous pour plus de

détails.

Cas

d'exception

"IPC::System::Simple" considère ce qui suit comme inattendu, et digne d'une exception

:
  • Échec total du démarrage (par ex., commande introuvable, permission refusée)
    • .
  • Renvoi d'une valeur de sortie autre que zéro (mais voir ci-dessous)
    • .
  • Être tué par un
    • signal.
  • Recevoir des
    • données con
taminées (en
mode taint).

Valeurs de

sortie

Traditionnellement, les commandes système renvoient un statut zéro pour le succès et un statut non nul pour l'échec. "IPC::System::Simple" lancera par défaut une exception si une valeur de sortie non nulle est

renvoyée.

Vous pouvez spécifier une plage de valeurs considérées comme des valeurs de sortie acceptables en passant une référence de tableau comme premier argument. La constante spéciale "EXIT_ANY" peut être utilisée pour permettre à n'importe quelle valeur de sortie d'être

renvoyée. 
use IPC::System::Simple qw(run system capture EXIT_ANY);
run( [0..5], "cat *.txt");             # Les valeurs de sortie 0-5 sont OK
system( [0..5], "cat *.txt");          # Cela fonctionne de la même manière
my @lines = capture( EXIT_ANY, "cat *.txt"); # N'importe quelle sortie
convient.

Le ass="Li">"run" et le remplacement "system" retournent la valeur de sortie du processus

: 
my $exit_value = run( [0..5], "cat *.txt");
# OU :
my $exit_value = system( [0..5] "cat *.txt");
print "Program exited with value
$exit_value\n";

$EXITVAL

La valeur de sortie de toute commande exécutée par "IPC::System::Simple" peut toujours être récupérée depuis la variable $IPC::System::Simple::EXITVAL

:

C'est particulièrement utile lors de l'inspection des résultats de "capture", qui retourne le texte capturé de la

commande. 
use IPC::System::Simple qw(capture $EXITVAL EXIT_ANY);
my @enemies_defeated = capture(EXIT_ANY, "defeat_evil", "/dev/mordor");
print "Program exited with value
$EXITVAL\n";

$EXITVAL sera défini à -1 si la commande ne s'est pas terminée normalement (par ex, si elle a été terminée par

un signal) ou n'a pas démarré. Dans cette situ
ation, une exception sera également levée.

NOTES SPÉFIQUES À

WINDOWS

Le sous-programme "run" rend disponible la valeur de sortie complète sur 32 bits sur les systèmes Win32. Cela a été le cas depuis "IPC::System::Simple" v0.06 lorsqu'il est appelé avec plusieurs arguments, et depuis v1.25 lorsqu'il est appelé avec un seul argument. C'est différent des versions précédentes de "IPC::System::Simple" et de la fonction intégrée de Perl system(), qui ne peut traiter que des valeurs de retour sur 8

bits.

Le sous-programme "capture" retourne toujours la valeur de sortie sur 32 bits sous Windows. Le sous-programme "capture" n'utilise non plus jamais le shell, même lorsqu'il est passé un seul

argument.

Le sous-programme "run" utilise toujours un shell lorsqu'il est passé un seul argument. Sur les systèmes NT, il utilise "cmd.exe" dans la racine du système, et sur les systèmes non-NT il utilise "command.com" dans la racine du

système.

Depuis "IPC::System::Simple" v1.25, les sous-programmes "runx" et "capturex", ainsi que les appels à plusieurs arguments aux sous-programmes "run" et "capture", ont leurs arguments correctement échappés, de sorte que les arguments contenant des espaces et le genre fonctionnent correctement. Malheureusement, cela casse toute tentative d'invoquer le shell lui-même. Si vous avez vraiment besoin d'exécuter "cmd.exe" ou "command.com", utilisez la forme à un seul argument. Pour les appels à un seul argument à "run" et "capture", l'argument doit être correctement échappé pour le shell avant

l'appel.

Les versions de "IPC::System::Simple" antérieures à v0.09 ne cherchaient pas dans la variable d'environnement "PATH" lorsque la forme à plusieurs arguments de run() était appelée. Les versions à partir de v0.09 cherchent correctement dans le chemin à condition que la commande soit fournie avec son extension (par ex, "notepad.exe" plutôt que simplement "notepad", ou "gvim.bat" plutôt que simplement "gvim"). Si aucune extension n'est fournie, ".exe" est

supposée.

Les signaux ne sont pas pris en charge sur l

es systèmes Windows. L'envoi d'un signal à
un processus Windows le fera généralemen
t sortir avec le numéro du signal utilisé.

COMPARAISON AVEC D'AUTRES

API

Perl fournit une gamme de fonctions intégrées pour gérer les commandes externes, et CPAN en fournit encore plus. Le "IPC::System::Simple" se différencie des autres options en fournissant

:
Des diagnostics extrêmement
détaillés
Les diagnostics produits par "IPC::System::Simple" sont conçus pour fournir autant d'informations que possible. Plutôt que de demander au développeur d'inspecter $?, "IPC::System::Simple" fait le travail difficile pour vous.

Si un statut de sortie inhabituel est fourni, vous êtes informé de ce qu'il est. Si un signal tue votre processus, vou

s êtes informé à la fois de son nom et de son numéro. Si des données ou un environnement contaminés empêchent votre com
mande de s'exécuter, vous êtes informé exactement de quelle donnée ou variable d'environnement est contaminée.
Exceptions en cas
d'échec
"IPC::System::Simple" adopte une approche agressive de la gestion des erreurs. Plutôt que de laisser les commandes échouer silencieusement, des exceptions sont levées lorsque des résultats inattendus sont vus. Cela permet un développement facile en utilisant un style try/catch, et évite la possibilité de continuer accidentellement après une commande
échouée.
Accès facile au statut de
sortie
Les commandes "run", "system" et "capture" définissent toutes $EXITVAL, ce qui facilite la détermination du statut de sortie d'une commande. De plus, les interfaces "system" et "run" retournent le statut de
sortie.
Interfaces
cohérentes
Lorsqu'elles sont appelées avec plusieurs arguments, les interfaces "run", "system" et "capture" n'invoquent jamais le shell. Cela diffère de la commande intégrée de Perl "system" qui peut invoquer le shell sous Windows lorsqu'elle est appelée
avec plusieurs arguments. Cela diffère
de l'opérateur backticks intégré
de Perl qui invoque toujours le shell.

BUGS

If you are calling "system" in an exotic way such as:

    $cmd = "ls -l";
    system { $cmd } @args; # WRONG!

And the "system" function is exported, the exotic form "system { $cmd } @args" is not supported. Attempting to use the exotic form is a syntax error. This affects the calling package only. Use "CORE::system" if you need it, or consider using the autodie module to replace "system" with lexical scope.

Core dumps are only checked for when a process dies due to a signal. It is not believed there are any systems where processes can dump core without dying to a signal.

"WIFSTOPPED" status is not checked, as perl never spawns processes with the "WUNTRACED" option.

Signals are not supported under Win32 systems, since they don't work at all like Unix signals. Win32 signals cause commands to exit with a given exit value, which this modules does capture.

Reporting bugs

Before reporting a bug, please check to ensure you are using the most recent version of "IPC::System::Simple". Your problem may have already been fixed in a new release.

You can find the "IPC::System::Simple" bug-tracker at http://rt.cpan.org/Public/Dist/Display.html?Name=IPC-System-Simple . Please check to see if your bug has already been reported; if in doubt, report yours anyway.

Submitting a patch and/or failing test case will greatly expedite the fixing of bugs.
