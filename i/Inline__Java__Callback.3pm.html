use Inline Java => <<'END' ;
   import org.perl.inline.java.* ;
   class Pod_caller extends InlineJavaPerlCaller { 
      public Pod_caller() throws InlineJavaException {
      }
      public String perl()
         throws InlineJavaException, InlineJavaPerlException {
         return (String)CallPerlSub("main::perl",
            new Object [] {}) ;
      }
   }
END

   return "perl" ;

DESCRIPTIO

N

"Inline::Java::Callback" vous permet d'appeler des fonctions Perl depuis Java. Pour ce faire, vous devez créer un objet "org.perl.inline.java.InlinePerlCaller". Voici un exemple d'utilisation typique

: 
use Inline Java => <<'END' ;
   import java.util.* ;
   import org.perl.inline.java.* ;
   class Pod_regexp extends InlineJavaPerlCaller {
      public Pod_regexp() throws InlineJavaException {
      }
      public boolean match(String target, String pattern)
         throws InlineJavaException {
         try {
            String m = (String)CallPerlSub("main::regexp",
               new Object [] {target, pattern}) ;
            if (m.equals("1")){
               return true ;
            }
         }
         catch (InlineJavaPerlException pe){
            // $@ est dans pe.GetObject()
         }
         return false ;
      }
   }
END
my $re = new Pod_regexp() ;
my $match = $re->match("Inline::Java", "^Inline") ;
print($match . "\n") ; # affiche 1
sub regexp {
   my $target = shift ;
   my $pattern = shift ;
   return ($target =~ /$pattern/) ;
}

Ces méthodes peuvent lever 2 types d'exceptions : "InlineJavaException" et "InlineJavaPerlException" (ces deux exceptions appartiennent au paquet "org.perl.inline.java"). La première désigne une erreur interne d'"Inline::Java" et la seconde indique que le rappel Perl a levé une exception (die() ou croak()). La valeur de $@ (celle-ci peut être un scalaire ou n'importe quel objet "Inline::Java" valide) peut être récupérée en utilisant la méthode GetObject() de l'objet "InlineJavaPerlException" (si vous êtes certain que $@ était un scalaire Perl, vous pouvez utiliser la méthode GetStr

CONTEXTE DES

RAPPELS

Par défaut, les rappels sont exécutés en contexte scalaire. Cependant, si vous voulez appeler certaines fonctions en contexte liste, vous devez insérer "@" devant le nom de la fonction. Le résultat sera alors passé à Java sous forme de tableau (Array)

: 
use Inline Java => <<'END' ;
   import org.perl.inline.java.* ;
   class Pod_Context {
      static private String dummy[] = {} ;
      static public String [] get_list()
         throws InlineJavaException, InlineJavaPerlException {
         InlineJavaPerlCaller pc = new InlineJavaPerlCaller() ;
         return (String [])pc.CallPerlSub("@main::list",
             null, dummy.getClass()) ;
      }
   }
END
sub list {
   return ('a', 'b', 'c') ;
}
print(Pod_Context->get_list()->[1] . "\n") ; # affiche
b

Remarque : Lorsque vous appelez une fonction Perl qui retourne une liste ou un tableau, vous devrez passer l'objet Class pour le type de tableau attendu (dans ce cas, String []). Puisque ces objets Class sont difficiles d'accès pour les types de tableaux, la façon la plus simple de faire cela est de créer un tableau factice du type désiré et d'appeler la méthode getClass() sur cet objet

(comme vu
ci-dessus).

BOUCLES DE

RAPPELS

Il est désormais possible d'utiliser des rappels depuis différents fils d'exécution (threads) Java. L'un des grands avantages de cela est que vous pouvez désormais gérer, par exemple, des événements SWING en Perl. Voici un exemple

: 
use Inline Java => <<'END' ;
   import java.util.* ;
   import org.perl.inline.java.* ;
   import javax.swing.* ;
   import java.awt.event.* ;
   class Pod_Button extends InlineJavaPerlCaller
                    implements ActionListener {
      JFrame frame = null ;
      public Pod_Button() throws InlineJavaException {
         frame = new JFrame("Pod_Button") ;
         frame.setSize(100,100) ;
         JButton button = new JButton("Click Me!") ;
         frame.getContentPane().add(button) ;
         button.addActionListener(this) ;
         frame.setDefaultCloseOperation(JFrame.DO_NOTHING_ON_CLOSE) ; 
         frame.show() ;
      }
      public void actionPerformed(ActionEvent e){
         try {
            CallPerlSub("main::button_pressed", new Object [] {}) ;
         }
         catch (InlineJavaPerlException pe){
            // $@ est dans pe.GetObject()
         }
         catch (InlineJavaException pe) {
            pe.printStackTrace() ;
         }
      }
      public void close(){
         frame.dispose() ;
         frame.hide() ;
         frame = null ;
      }
      public void quit(){
         System.exit(0) ;
      }
   }
END
my $b = new Pod_Button() ;
$b->StartCallbackLoop() ;
$b->close() ;
# Peut-être faire autre chose
exit() ;      # en mode client-serveur, facultatif
$b->quit() ;  # en mode JNI
sub button_pressed {
   print("click!\n") ; # affiche click!
   $b->StopCallbackLoop() ;
}

La méthode StartCallbackLoop peut être appelée sur n'importe quel objet "org.perl.inline.java.InlineJavaPerlCaller" et bloquera le fil d'exécution courant en permettant la réception de rappels via n'importe quel InlineJavaPerlCaller qui a été créé par le même fil d'exécution (courant). La seule façon d'interrompre une telle méthode StartCallbackLoop est d'appeler la méthode StopCallbackLoop sur n'importe quel objet "org.perl.inline.java.InlineJavaPerlCaller" qui a été créé par ce même fil

d'exécution.

De plus, seuls les fils d'exécution qui communiquent avec Perl via &quot;Inline::Java" sont autorisés à créer des objets "org.perl.inline.java.InlineJavaPerlCaller" et à invoquer leurs méthodes StartCallbackLoop / StopCallbackLoo

p
.

BOUCLES DE RAPPEL DE STYLE

SELECT

L'inconvénient du type de boucle de rappel présenté dans la section précédente est que la partie principale du programme Perl est complètement bloquée en attendant des rappels. Dans la version 0.51, une nouvelle API pour les boucles de rappel a été introduite, permettant le traitement des rappels de la même manière que l'on utilise select(2) pour lire des données depuis un descripteur de fichier. Voici un exemple

: 
use Inline Java => <<'END' ;
   import java.util.* ;
   import org.perl.inline.java.* ;
   import javax.swing.* ;
   import java.awt.event.* ;
   class Pod_Button extends InlineJavaPerlCaller
                    implements ActionListener {
      JFrame frame = null ;
      public Pod_Button() throws InlineJavaException {
         frame = new JFrame("Pod_Button") ;
         frame.setSize(100,100) ;
         JButton button = new JButton("Click Me!") ;
         frame.getContentPane().add(button) ;
         button.addActionListener(this) ;
         frame.setDefaultCloseOperation(JFrame.DO_NOTHING_ON_CLOSE) ; 
         frame.show() ;
      }
      public void actionPerformed(ActionEvent e){
         try {
            CallPerlSub("main::button_pressed", new Object [] {}) ;
         }
         catch (InlineJavaPerlException pe){
            // $@ est dans pe.GetObject()
         }
         catch (InlineJavaException pe) {
            pe.printStackTrace() ;
         }
      }
      public void close(){
         frame.dispose() ;
         frame.hide() ;
         frame = null ;
      }
      public void quit(){
         System.exit(0) ;
      }
   }
END
my $b = new Pod_Button() ;  
$b->OpenCallbackStream() ;
while ((my $rc = $b->WaitForCallback(5)) > -1){
   if ($rc > 0){
      # Un rappel est en attente, nous devons le traiter.
      $b->ProcessNextCallback() ;
   }
   else {
      # Un délai d'attente s'est écoulé, dans ce cas, 5 secondes.
      print "5 secondes se sont écoulées, toujours en attente d'un rappel...\n" ;
      # Peut-être faire autre chose
   }
}
$b->close() ;
# Peut-être faire autre chose
exit() ;      # en mode client-serveur, facultatif
$b->quit() ;  # en mode JNI
sub button_pressed {
   print('click!' . "\n") ; # affiche click!
   $b->CloseCallbackStream() ;
}

La méthode StartCallbackStream peut être appelée sur n'importe quel objet InlineJavaPerlCaller pour initialiser un canal de réception des rappels. La méthode WaitForCallback peut ensuite être appelée avec une valeur de délai d'attente flottante (-1 signifie attendre indéfiniment, 0 signifie retourner immédiatement). La méthode WaitForCallback peut retourner

: 
rc  >  0, indiquant que rc rappels sont en attente d'être traités
rc ==  0, indiquant qu'un délai d'attente s'est écoulé et qu'aucun rappel n'est en attente
rc == -1, indiquant que le flux de rappels a été
fermé

Le flux de rappels peut être fermé en appelant CloseCallbackStream, qui fonctionne de manière similaire à la méthode StopCallbackLoop utilisée dans la section

précédente.

De plus, les restrictions concernant la communica

tion entre les threads énoncées dans la sectio
n précédente sont valables dans ce cas également.
