NAME

IO::Uncompress::Unzip - Interface to the unzip compression format

SYNOPSIS

    use IO::Uncompress::Unzip qw(unzip $UnzipError);
    my $zip = IO::Uncompress::Unzip->new($file)
        or die "Could not open $file: $UnzipError";
    while (my $data = $zip->read(\$buffer, 1024)) {
        # process $buffer
    }
    $zip->close();

    # Functional interface
    my $status = unzip $file_or_fh => $output_file_or_fh
        or die "unzip failed: $UnzipError";

    my $status = unzip $file_or_fh => \$output_buffer
        or die "unzip failed: $UnzipError";

DESCRIPTION

This module provides an interface to the unzip compression format.

It supports both an object-oriented interface and a functional interface.

Functional Interface

The functional interface is provided by the "unzip" function.

    use IO::Uncompress::Unzip qw(unzip $UnzipError);

    my $status = unzip $input => $output
        or die "unzip failed: $UnzipError";

The "unzip" function takes two arguments:

$input
Can be a filename, a filehandle or a symbolic reference to a scalar containing the compressed data.
$output
Can be a filename, a filehandle or a symbolic reference to a scalar that will contain the uncompressed data.

The function returns true on success and false on failure. In the event of failure, the global variable $UnzipError will contain a message describing the error.

The "unzip" function can handle zip files containing multiple members. In this case, it will unzip the first member it finds. If you need to process all members, or a specific member, you should use the OO interface.

OO Interface

The object oriented interface involves creating an IO::Uncompress::Unzip object, and then reading from it.

    use IO::Uncompress::Unzip;
    my $zip = IO::Uncompress::Unzip->new($file_or_fh_or_buffer, %options)
        or die "Could not open $file_or_fh_or_buffer: $UnzipError";
    while (my $bytesread = $zip->read($buffer, $buffer_size)) {
        # process $buffer, which now contains $bytesread bytes of uncompressed data
    }
    $zip->close();

Methods

new
The constructor.
    my $z = IO::Uncompress::Unzip->new($input, %options)
        or die "Could not create object: $UnzipError";

The constructor takes a mandatory first argument which can be a filename, a filehandle, or a symbolic reference to a scalar containing the compressed data. It can also take optional arguments in a key => value format.

Valid options are:

Name

If the zip file contains multiple members, this option allows you to specify which member to extract. If this option is omitted, the first member in the archive will be extracted.

    my $z = IO::Uncompress::Unzip->new("archive.zip", Name => "file1.txt");
Name_matches

This option is like Name, but the value is treated as a regular expression. The first member in the archive whose name matches the regular expression will be extracted.

    my $z = IO::Uncompress::Unzip->new("archive.zip", Name_matches => qr/^file\d+\.txt$/);
InputLength

If you know the exact size of the compressed data within the input stream, you can specify it here. This allows the module to determine when the compressed data ends, and therefore when any trailing data begins.

    my $z = IO::Uncompress::Unzip->new($fh, InputLength => $size);
TrailingData

If set to a true value, the "read" method will return data that follows the compressed stream. This is only relevant when the input is a filehandle or a buffer.

    my $z = IO::Uncompress::Unzip->new($fh, TrailingData => 1);
    my $status;
    while (($status = $z->read(\$buf, 1024)) > 0) {
        # process uncompressed data in $buf
    }
    if ($status == 0) { # End of compressed data stream reached
        # $buf now contains any trailing data.
        # If input was a filehandle, the filehandle is now positioned
        # at the start of the trailing data.
    } else {
        # an error occurred
    }
UncompressedSize

If the size of the uncompressed data is known, it can be specified here. This is mainly for diagnostics.

If the constructor fails, it will return undef and the global variable $UnzipError will contain an error message.

read

Reads uncompressed data from the archive.

    my $bytesread = $z->read(\$buffer, $max_bytes_to_read)

Returns the number of bytes read into the supplied buffer \$buffer. Returns 0 if the end of the compressed data stream has been reached. Returns undef if an error occurred.

If the TrailingData option was set to true in the constructor, and the end of the compressed data stream is reached, then "read" will return the data that follows the compressed stream. This is only meaningful if the input was a buffer or a filehandle.

If the input is a buffer, and the TrailingData option was set to true, "read" will return the rest of the buffer when the end of the compressed data stream is reached.

If the input is a filehandle, and the TrailingData option was set to true, "read" will return any data remaining in the filehandle's buffer when the end of the compressed data stream is reached. The filehandle itself will be positioned at the start of the trailing data.

Don't bother using TrailingData if the input is a filename.

If you know the length of the compressed data stream before you start uncompressing, you can avoid having to use TrailingData by setting the InputLength option in the constructor.

close

Closes the archive and releases any resources.

    $z->close();

Returns true on success, false on failure.

getHeaderInfo

Returns a hash reference containing information about the current member in the archive.

    my $info = $z->getHeaderInfo();
    my $filename = $info->{Name};
    my $size = $info->{UncompressedSize};

The hash contains the following keys:

Name
The name of the member within the archive.
UncompressedSize
The size of the uncompressed member.
CompressedSize
The size of the compressed member.
MTime
The modification time of the member.
CRC
The CRC checksum of the uncompressed member.

nextStream

Advances to the next member in the archive.

    my $status = $z->nextStream();

Returns true if successful, false if there are no more members or an error occurred.

This method is useful when reading a zip archive that contains multiple members, and you want to process them sequentially.

Note that calling nextStream resets the end-of-file status. If you have reached the end of a compressed data stream, and TrailingData was enabled, calling nextStream will allow you to read the next compressed data stream.

eof

Returns true if the end of the current compressed data stream has been reached.

    if ($z->eof) {
        # ...
    }

error

Returns the last error message.

    my $message = $z->error();

trailingData

This method is only relevant if the constructor was called with the TrailingData option set to true.

It returns any data that immediately follows the compressed data stream, and you don't know the length of the compressed data stream.

If the input is a buffer, "trailingData" will return everything from the end of the compressed data stream to the end of the buffer.

If the input is a filehandle, "trailingData" will return the data that is left in the filehandle input buffer once the end of the compressed data stream has been reached. You can then use the filehandle to read the rest of the input file.

Don't bother using "trailingData" if the input is a filename.

If you know the length of the compressed data stream before you start uncompressing, you can avoid having to use "trailingData" by setting the "InputLength" option in the constructor.

Importing

No symbolic constants are required by IO::Uncompress::Unzip at present.

:all
Imports "unzip" and $UnzipError. Same as doing this 
use IO::Uncompress::Unzip qw(unzip $UnzipError) ;

EXAMPLES

Simple Read

Say you have a zip file, "file1.zip", that only contains a single member, you can read it and write the uncompressed data to the file "file1.txt" like this.

use strict ;
use warnings ;
use IO::Uncompress::Unzip qw(unzip $UnzipError) ;
my $filename = "file1.zip";
my $z = IO::Uncompress::Unzip->new($filename)
    or die "IO::Uncompress::Unzip failed: $UnzipError\n";
open my $out, ">", "file1.txt";
while (<$z>) {
    print $out $_;
}
$z->close();

If you have a zip file that contains multiple members and want to read a specific member from the file, say "data1", use the "Name" option when constructing the

use strict ;
use warnings ;
use IO::Uncompress::Unzip qw(unzip $UnzipError) ;
my $filename = "file1.zip";
my $z = IO::Uncompress::Unzip->new($filename, Name => "data1")
    or die "IO::Uncompress::Unzip failed: $UnzipError\n";

Walking through a zip file

The code below can be used to traverse a zip file, one compressed data stream at a time.

use IO::Uncompress::Unzip qw($UnzipError);
my $zipfile = "somefile.zip";
my $u = IO::Uncompress::Unzip->new( $zipfile )
    or die "Cannot open $zipfile: $UnzipError";
my $status;
for ($status = 1; $status > 0; $status = $u->nextStream())
{
    my $name = $u->getHeaderInfo()->{Name};
    warn "Processing member $name\n" ;
    my $buff;
    while (($status = $u->read($buff)) > 0) {
        # Do something here
    }
    last if $status < 0;
}
die "Error processing $zipfile: $!\n"
    if $status < 0 ;

Each individual compressed data stream is read until the logical end-of-file is reached. Then "nextStream" is called. This will skip to the start of the next compressed data stream and clear the end-of-file flag.

It is also worth noting that "nextStream" can be called at any time -- you don't have to wait until you have exhausted a compressed data stream before skipping to the next one.

Unzipping a complete zip file to disk
