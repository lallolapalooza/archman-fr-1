NOM

Image::ExifTool::AES - chiffrement AES avec chaînage de blocs de chiffrement

SYNTAXE

use Image::ExifTool::AES qw(Crypt);
$err = Crypt(\$plaintext, $key, 1);   # chiffrement
$err = Crypt(\$ciphertext, $key);     # déchiffrement

DESCRIPTION

Ce module contient une implémentation des algorithmes de chiffrement/déchiffrement AES avec chaînage de blocs de chiffrement (CBC) et remplissage PKCS #5 selon la RFC 2898. C'est le mode de chiffrement AESV2 et AESV3 utilisé dans les documents PDF.

EXPORTATIONS

N'exporte rien par défaut, mais "Crypt" peut être exporté.

MÉTHODES

Crypt

Implémente le chiffrement/déchiffrement AES avec chaînage de blocs de chiffrement.

Entrées :
0) Référence scalaire pour les données à chiffrer/déchiffrer.

1) Chaîne de clé de chiffrement (doit avoir une longueur de 16, 24 ou 32).

2) [optionnel] Indicateur de chiffrement (faux pour déchiffrer).

3) [optionnel] Indicateur pour éviter de supprimer le remplissage après déchiffrement, ou pour éviter d'ajouter 16 octets de remplissage avant le chiffrement lorsque la longueur des données est déjà un multiple de 16 octets.

Retourne :
En cas de succès, la valeur de retour est indéfinie et les données sont chiffrées ou déchiffrées comme spécifié. Sinon, retourne une chaîne d'erreur et les données sont laissées dans un état indéterminé.
Notes :
La longueur de la clé de chiffrement détermine le mode AES, les longueurs de 16, 24 et 32 octets résultant en AES-128, AES-192 et AES-256.

Lors du chiffrement, les données d'entrée peuvent avoir n'importe quelle longueur et seront remplies à une taille de bloc paire de 16 octets en utilisant la technique de remplissage spécifiée. Si l'indicateur de chiffrement a une longueur de 16, il est utilisé comme vecteur d'initialisation pour le chaînage de blocs de chiffrement, sinon un IV aléatoire est généré. Après un retour réussi, les données seront chiffrées, les 16 premiers octets des données étant l'IV du CBC.

Lors du déchiffrement, les données d'entrée commencent par le vecteur d'initialisation du chaînage de blocs de chiffrement de 16 octets.

BOGUES

Ce code est d'une lenteur aveuglante. Mais en vérité, ralentir le traitement est le but principal du chiffrement, donc cela ne peut pas vraiment être considéré comme un bogue.
