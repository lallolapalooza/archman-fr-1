Image::Sane(3) Documentation Perl contribuée par les utilisateurs Image::Sane(3)

NOM

Image::Sane - Extension Perl pour le projet SANE (Scanner Access Now Easy)

VERSION

5

SYNOPSIS

use Image::Sane;
my @devices = Image::Sane->get_devices;
my $device = Image::Sane::Device->open($devices[0]->{name});
my $param = $device->get_parameters;
$device->write_pnm_header($fh, $param);
my ($data, $len) = $device->read ($param->{bytes_per_line});
print $fh $data;

DESCRIPTION

Ces liaisons Perl pour le projet SANE (Scanner Access Now Easy) vous permettent d'accéder aux scanners compatibles SANE de manière orientée objet et « à la Perl », vous libérant des conversions de types et de la gestion de la mémoire en C, tout en restant très fidèle à l'esprit de l'API originale.

Pour en savoir plus sur SANE, consultez http://www.sane-project.org.

SOUS-PROGRAMMES/MÉTHODES

Image::Sane->get_version

Renvoie un tableau contenant les versions SANE_VERSION_(MAJOR|MINOR|BUILD) :

join('.', Image::Sane->get_version)

Image::Sane->get_version_scalar

Renvoie un scalaire avec les versions SANE_VERSION_(MAJOR|MINOR|BUILD) combinées selon la numérotation des versions Perl, c'est-à-dire que sane 1.0.19 donne 1.000019. Cela permet des comparaisons de versions simples.

Image::Sane->get_devices

Cette fonction peut être utilisée pour interroger la liste des périphériques disponibles. Si la fonction s'exécute avec succès, elle renvoie un tableau de références de hachage contenant les périphériques trouvés. La liste renvoyée reste garantie valide jusqu'à ce que (a) un autre appel à cette fonction soit effectué ou (b) un appel à sane_exit() soit effectué. Cette fonction peut être appelée à plusieurs reprises pour détecter quand de nouveaux périphériques deviennent disponibles.

Si l'argument local_only est vrai, seuls les périphériques locaux sont renvoyés (les périphériques directement connectés à la machine sur laquelle SANE s'exécute). S'il est faux, la liste des périphériques inclut tous les périphériques distants accessibles à la bibliothèque SANE.

try {
    @devices = Image::Sane->get_devices;
    print "Name: $devices[0]->{name}\n";
    print "Vendor: $devices[0]->{vendor}\n";
    print "Model: $devices[0]->{model}\n";
    print "Type: $devices[0]->{type}\n";
}
catch {
    print "Error getting devices:", $_->error, "\n";
};

Image::Sane::Device->open

Cette fonction est utilisée pour établir une connexion à un périphérique particulier. Le nom du périphérique à ouvrir est passé dans l'argument name. Si l'appel se termine avec succès, un objet Image::Sane::Device est renvoyé. Dans un cas particulier, spécifier une chaîne de longueur nulle comme périphérique demande l'ouverture du premier périphérique disponible (s'il y en a un).

my $device = Image::Sane::Device->open($device_name);

Image::Sane::Device->get_option_descriptor

Cette fonction est utilisée pour accéder aux descripteurs d'options. La fonction renvoie une référence de hachage contenant le descripteur de l'option numéro n de l'objet Image::Sane::Device. L'option numéro 0 est garantie être une option valide. Sa valeur est un entier qui spécifie le nombre d'options disponibles pour l'objet Image::Sane::Device (le comptage inclut l'option 0). Si n n'est pas un index d'option valide, la fonction provoque une erreur fatale.

try {
    $option = $device->get_option_descriptor($n);
    print "Name: $option->{name}\n";
    print "Name: $option->{title}\n";
    print "Name: $option->{desc}\n";
    print "Name: $option->{type}\n";
    print "Name: $option->{unit}\n";
    print "Name: $option->{cap}\n";
    print "Name: $option->{max_values}\n";
    print "Name: $option->{constraint_type}\n";
}
catch {
    print "Error getting option descriptor:", $_->error, "\n";
};

Le contenu des clés de hachage "name", "title", "desc", "type", "unit", "cap" et "constraint_type" est conforme à la description de l'API C (http://www.sane-project.org/html). Il existe une clé de contrainte supplémentaire qui contient soit un tableau avec les valeurs possibles de l'option, soit un hachage avec les clés "max", "min" et "quant".

La clé max_values a remplacé la clé size dans l'API C, et contient le nombre maximal de valeurs que l'option peut contenir.

Image::Sane::Device->get_option

Renvoie la valeur actuelle de l'option sélectionnée.

try {
    $value = $device->get_option($n);
    print "value: $value\n";
}
catch {
    print "Error getting option:", $_->error, "\n";
};

Pour $option->{max_values} > 1, $value est une référence à un tableau.

Image::Sane::Device->set_auto

Commande le périphérique sélectionné pour sélectionner automatiquement une valeur appropriée. Ce mode reste actif jusqu'à ce qu'il soit remplacé par une requête set_option explicite.

$device->set_auto($n);

Image::Sane::Device->set_option

Définit l'option sélectionnée, en renvoyant des indicateurs dans $info, qui sont décrits dans l'API C (http://www.sane-project.org/html).

$orig = $device->get_option($n);
$info = $device->set_option($n, $value);
if ($info & SANE_INFO_INEXACT) {
 $value = $device->get_option($n);
 print "rounded value of $opt->{name} from $orig to $value\n";
}

Pour $option->{max_values} > 1, $value peut être une référence à un tableau.

Image::Sane::Device->get_parameters

Cette fonction est utilisée pour obtenir les paramètres de numérisation actuels. Les paramètres renvoyés sont garantis être exacts entre le moment où une numérisation a été démarrée (Image::Sane::Device->start() a été appelé) et l'achèvement de cette requête. En dehors de cette fenêtre, les valeurs renvoyées sont des estimations au mieux de ce que seront les paramètres lorsque Image::Sane::Device->start() sera invoqué. Appeler cette fonction avant qu'une numérisation n'ait réellement commencé permet, par exemple, d'obtenir une estimation de la taille de l'image numérisée.

try {
    $param = $device->get_parameters;
    print "format $param->{format}\n";
    print "last_frame $param->{last_frame}\n";
    print "bytes_per_line $param->{bytes_per_line}\n";
    print "pixels_per_line $param->{pixels_per_line}\n";
    print "lines $param->{lines}\n";
    print "depth $param->{depth}\n";
}
catch {
    print "Error getting parameters:", $_->error, "\n";
};

Veuillez consulter la documentation C (http://www.sane-project.org/html) pour plus de détails sur les valeurs ci-dessus.

Image::Sane::Device->start

Cette fonction initie l'acquisition d'une image à partir du périphérique spécifié.

$device->start;

Image::Sane::Device->read

Cette fonction est utilisée pour lire les données d'image à partir du périphérique spécifié. Le nombre d'octets retournés dans $buf est stocké dans $len. Un backend doit mettre ceci à zéro lorsqu'une erreur est levée. Si l'appel réussit, le nombre d'octets retournés peut être n'importe où dans la plage de 0 à $maxlen octets.

$param = $device->get_parameters;
$maxlen = $param->{bytes_per_line};
($buf, $len) = $test->read ($maxlen);

Si cette fonction est appelée alors qu'aucune donnée n'est disponible, deux choses peuvent se produire, selon le mode d'E/S en vigueur pour le périphérique.

1. Si le périphérique est en mode d'E/S bloquant (le mode par défaut), l'appel se bloque jusqu'à ce qu'au moins un octet de données soit disponible (ou jusqu'à ce qu'une erreur se produise).
2. Si le périphérique est en mode d'E/S non bloquant, l'appel retourne immédiatement avec $len mis à zéro.

Le mode d'E/S du périphérique peut être défini via un appel à Image::Sane::Device->set_io_mode().

Image::Sane::Device->cancel

Cette fonction est utilisée pour annuler immédiatement ou aussi vite que possible l'opération actuellement en attente du périphérique.

$device->cancel;

Cette fonction peut être appelée à tout moment (tant que $device est valide) mais n'affecte généralement que les opérations de longue durée (comme l'acquisition d'image). Il est sûr d'appeler cette fonction de manière asynchrone (par exemple, depuis un gestionnaire de signal). Il est important de noter que l'achèvement de cette opération n'implique pas que l' opération actuellement en attente a été annulée. Elle ne garantit qu' que l'annulation a été initiée. L'annulation n'est terminée que lorsque l'appel annulé lève une exception (généralement avec une valeur de statut de SANE_STATUS_CANCELLED). Puisque l'API SANE ne requiert pas que les autres opérations soient réentrantes, cela implique qu'un frontend ne doit pas appeler une autre opération jusqu'à ce que l'opération annulée soit retournée.

Image::Sane::Device->set_io_mode

Cette fonction est utilisée pour définir le mode d'E/S du périphérique. Le mode d'E/S peut être bloquant ou non bloquant. Si l'argument $bool est SANE_TRUE, le mode est défini sur non bloquant , sinon il est défini sur bloquant. Cette fonction ne peut être appelée qu'après qu'un appel à Image::Sane::Device->start() a été effectué.

$device->set_io_mode ($bool);

Par défaut, les descripteurs nouvellement ouverts fonctionnent en mode bloquant. Un backend peut choisir de ne pas supporter le mode d'E/S non bloquant. Dans un tel cas, l' appelle lève une exception avec la valeur de statut SANE_STATUS_UNSUPPORTED. Le mode d'E/S bloquant doit être supporté par tous les backends, donc appeler cette fonction avec SANE_FALSE est garanti de se terminer avec succès.

Image::Sane::Device->get_select_fd

Cette fonction est utilisée pour obtenir un descripteur de fichier (spécifique à la plateforme) pour le périphérique qui est lisible si et seulement si des données d'image sont disponibles (c'est-à-dire, quand un appel à Image::Sane::Device->read() retournera au moins un octet de données).

$fd = $device->get_select_fd;

Cette fonction ne peut être appelée qu'après qu'un appel à Image::Sane::Device->start() a été effectué et le descripteur de fichier retourné est garanti de rester valide pour la durée de l'acquisition d'image en cours (c'est-à-dire, jusqu'à ce que Image::Sane::Device->cancel() ou Image::Sane::Device->start() soit rappelé ou jusqu'à ce que Image::Sane::Device->read() lève une exception avec le statut SANE_STATUS_EOF). En effet, un backend doit garantir de fermer le descripteur de fichier select retourné au moment où le prochain Image::Sane::Device->read() appelle lèverait une exception avec SANE_STATUS_EOF. C'est nécessaire pour s'assurer que l'application peut détecter quand cette condition se produit sans avoir à appeler Image::Sane::Device->read().

Un backend peut choisir de ne pas supporter cette opération. Dans un tel cas, la fonction lève une exception avec le code de statut SANE_STATUS_UNSUPPORTED.

Notez que la seule opération supportée par le descripteur de fichier retourné est un test dépendant du système d'exploitation hôte sur le fait que le descripteur de fichier est lisible (par exemple, ce test peut être implémenté en utilisant select() ou poll() sous UNIX). Si une autre opération est effectuée sur le descripteur de fichier, le comportement du backend devient imprévisible. Une fois que le descripteur de fichier signale le statut « lisible », il restera dans cet état jusqu'à ce qu'un appel à sane_read() soit effectué. Puisque de nombreux périphériques d'entrée sont très lents, le support pour cette opération est fortement encouragé car il permet à une application de faire d'autres travaux pendant que l'acquisition d'image est en cours.

Image::Sane::Device->write_pnm_header

Cette fonction est une fonction d'aide pure-Perl pour écrire un en-tête PNM. Elle récupérera les paramètres d'image actuels en utilisant Image::Sane::Device->get_parameters, s'ils ne sont pas déjà fournis, p. ex. :

$device->write_pnm_header($fh);

ou

$parm = $device->get_parameters;
$device->write_pnm_header ($fh, $parm->{format}, 
                                $parm->{pixels_per_line},
                                $parm->{lines}, $parm->{depth});

DIAGNOSTICS

Si la bibliothèque SANE sous-jacente retourne une valeur de statut autre que SANE_STATUS_GOOD, une exception est levée. Il est donc suggéré que celles-ci soient capturées en utilisant le module Try::Tiny. $_->status et $_->error peuvent être utilisés dans la clause catch{} pour donner le code de statut et sa chaîne équivalente.

CONFIGURATION ET ENVIRONNEMENT

Ce module ne nécessite aucune configuration ou environnement spécial, au-delà de ce qui est nécessaire pour Perl et SANE.

DÉPENDANCES

Évidemment, la bibliothèque SANE est requise, ainsi que les backends pour les scanners à utiliser.
Exception::Class est utilisé pour lever des exceptions. Il est suggéré que celles-ci soient capturées avec Try::Tiny.

VOIR AUSSI

La Référence Standard SANE http://www.sane-project.org/html est un compagnon pratique. Les liaisons Perl suivent très étroitement l'API C, et la documentation de référence C doit être considérée comme la source canonique.
