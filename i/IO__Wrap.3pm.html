NOM

IO::Wrap - Envelopper des descripteurs de fichiers bruts dans l'interface IO::Handle

SYNOPSIS

use strict;
use warnings;
use IO::Wrap;
# c'est un cas d'utilisation assez insensé car IO::Handle le fait déjà.
my $wrap_fh = IO::Wrap->new(\*STDIN);
my $line = $wrap_fh->getline();
# Faites des choses avec n'importe quel descripteur de fichier (y compris une référence glob brute), ou
# n'importe quel objet béni qui répond à un message print().
# vous avez déjà une référence glob ? un FileHandle ? un nom de descripteur de fichier scalaire ?
$wrap_fh = IO::Wrap->new($some_unknown_thing);
# À ce stade, nous savons que nous avons un objet de type IO::Handle ! OUAYE
$wrap_fh->print("Salut !");

Vous pouvez également le faire en utilisant une fonction d'enveloppement pratique

use strict;
use warnings;
use IO::Wrap qw(wraphandle);
# c'est un cas d'utilisation assez insensé car IO::Handle le fait déjà.
my $wrap_fh = wraphandle(\*STDIN);
my $line = $wrap_fh->getline();
# Faites des choses avec n'importe quel descripteur de fichier (y compris une référence glob brute), ou
# n'importe quel objet béni qui répond à un message print().
# vous avez déjà une référence glob ? un FileHandle ? un nom de descripteur de fichier scalaire ?
$wrap_fh = wraphandle($some_unknown_thing);
# À ce stade, nous savons que nous avons un objet de type IO::Handle ! OUAYE
$wrap_fh->print("Salut !");

DESCRIPTION

Disons que vous voulez écrire du code qui effectue des I/O, mais vous ne voulez pas forcer l'appelant à vous fournir un objet FileHandle ou IO::Handle. Vous voulez qu'il puisse dire :

do_stuff(\*STDOUT);
do_stuff('STDERR');
do_stuff($some_FileHandle_object);
do_stuff($some_IO_Handle_object);

Et même :

do_stuff($any_object_with_a_print_method);

Bien sûr, une façon de faire est de forcer l'appelant à utiliser tiehandle(). Mais cela lui incombe. Une autre façon de faire est d'utiliser IO::Wrap.

Clairement, en enveloppant un descripteur de fichier externe brut (comme "\*STDOUT"), je ne voulais pas fermer le descripteur de fichier lorsque l'objet enveloppant est détruit ; l'utilisateur pourrait ne pas apprécier cela ! Par conséquent, il n'y a pas de "DESTROY" dans cette classe.

Lors de l'enveloppement d'un objet FileHandle, cependant, je pense que Perl invoquera le "FileHandle::DESTROY" lorsque la dernière référence disparaîtra, donc dans ce cas, le descripteur de fichier sera fermé si le FileHandle enveloppé était bien la dernière référence à celui-ci.

FONCTIONS

IO::Wrap met à disposition les fonctions suivantes.

wraphandle

# enveloppe un glob de descripteur de fichier
my $fh = wraphandle(\*STDIN);
# enveloppe un glob de descripteur de fichier brut par nom
$fh = wraphandle('STDIN');
# enveloppe un handle dans un objet
$fh = wraphandle('Class::HANDLE');
# enveloppe un objet FileHandle béni
use FileHandle;
my $fho = FileHandle->new("/tmp/foo.txt", "r");
$fh = wraphandle($fho);
# enveloppe tout autre objet béni qui partage l'interface IO::Handle
$fh = wraphandle($some_object);

Cette fonction est simplement un enveloppement de la méthode du constructeur "new" dans IO::Wrap.

MÉTHODES

IO::Wrap implémente les méthodes suivantes.

close

$fh->close();

La méthode "close" tentera de fermer le descripteur de fichier système. Pour une description plus complète, lisez "close" in perlfunc.

fileno

my $int = $fh->fileno();

La méthode "fileno" renvoie le descripteur de fichier pour le descripteur de fichier enveloppé. Voir "fileno" in perlfunc pour plus d'informations.

getline

my $data = $fh->getline();

La méthode "getline" imite la fonction du même nom dans IO::Handle. C'est comme appeler "my $data = <$fh>;" mais uniquement en contexte scalaire.

getlines

my @data = $fh->getlines();

La méthode "getlines" imite la fonction du même nom dans IO::Handle. C'est comme appeler "my @data = <$fh>;" mais uniquement en contexte de liste. Appeler cette méthode en contexte scalaire entraînera un plantage.

new

# enveloppe un glob de descripteur de fichier
my $fh = IO::Wrap->new(\*STDIN);
# enveloppe un glob de descripteur de fichier brut par nom
$fh = IO::Wrap->new('STDIN');
# enveloppe un handle dans un objet
$fh = IO::Wrap->new('Class::HANDLE');
# enveloppe un objet FileHandle béni
use FileHandle;
my $fho = FileHandle->new("/tmp/foo.txt", "r");
$fh = IO::Wrap->new($fho);
# enveloppe tout autre objet béni qui partage l'interface IO::Handle
$fh = IO::Wrap->new($some_object);

La méthode du constructeur "new" prend un seul argument et décide de l'envelopper ou non en fonction de ce qu'il semble être.

Un nom de descripteur de fichier scalaire brut, comme "STDOUT" ou "Class::HANDLE" peut être enveloppé, renvoyant une instance d'objet IO::Wrap.

Un glob de descripteur de fichier brut, comme "\*STDOUT" peut également être enveloppé, renvoyant une instance d'objet IO::Wrawp.

Un objet FileHandle béni peut également être enveloppé. Il s'agit d'un cas spécial où une instance d'objet IO::Wrap ne sera renvoyée que si votre objet FileHandle ne prend pas en charge la méthode "read".

De plus, tout autre type d'objet béni qui respecte l'interface IO::Handle peut être passé. Dans ce cas, vous récupérez simplement cet objet.

En d'autres termes, nous ne l'enveloppons dans un objet IO::Wrap que lorsque ce que vous avez fourni ne respecte pas déjà l'interface IO::Handle.

Si vous récupérez un objet IO::Wrap, il respectera un sous-ensemble basique de l'interface "IO::". Il le fera avec des méthodes d'objet, pas avec des opérateurs.

AVERTISSEMENTS

Ce module ne vous permet pas d'envelopper des noms de descripteurs de fichiers qui sont fournis sous forme de chaînes de caractères sans le paquet dans lequel ils ont été ouverts. C'est-à-dire, si un utilisateur ouvre FOO dans le paquet Foo, il doit vous le passer soit comme "\*FOO", soit comme "Foo::FOO". Cependant, "STDIN" et les similaires fonctionneront parfaitement.

print

$fh->print("Une chaîne");
$fh->print("plus", " d'une", " chaîne");

La méthode "print" tentera d'imprimer une chaîne ou une liste de chaînes dans le descripteur de fichier. Pour une description plus complète, lisez "print" in perlfunc.

read

my $buffer;
# essaie de lire 30 caractères dans le buffer à partir de la
# position actuelle du curseur.
my $num_chars_read = $fh->read($buffer, 30);

La méthode read tente de lire un nombre de caractères, en commençant par la position actuelle du curseur du descripteur de fichier. Elle renvoie le nombre de caractères effectivement lus. Voir "read" in perlfunc pour plus d'informations.

seek

use Fcntl qw(:seek); # importe les constantes SEEK_CUR, SEEK_SET, SEEK_END
# recherche la position en octets
$fh->seek(0, SEEK_SET);
# recherche la position en octets à partir de la position actuelle
$fh->seek(22, SEEK_CUR);
# recherche à la fin du fichier plus les octets
$fh->seek(0, SEEK_END);

La méthode "seek" tentera de définir le curseur à une position donnée en octets pour le descripteur de fichier enveloppé. Voir "seek" in perlfunc pour plus d'informations.

tell

my $bytes = $fh->tell();

La méthode "tell" tentera de renvoyer la position actuelle du curseur en octets pour le descripteur de fichier enveloppé. Voir "tell" in perlfunc pour plus d'informations.
