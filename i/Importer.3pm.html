VARIABLES PRIS EN CHARGE

@EXPORT

C'est utilisé exactement de la même manière que par Exporter.

Liste des symboles à exporter. Le sigle est facultatif pour les subs. Les symboles listés ici sont exportés par défaut. Si possible, vous devriez mettre les symboles dans @EXPORT_OK à la place.

our @EXPORT = qw/foo bar &baz $BAT/;

@EXPORT_OK

C'est utilisé exactement de la même manière que par Exporter.

Liste des symboles qui peuvent être importés. Le sigle est facultatif pour les subs. Les symboles listés ici ne sont pas exportés par défaut. C'est préférable par rapport à @EXPORT.

our @EXPORT_OK = qw/foo bar &baz $BAT/;

%EXPORT_TAGS

Ce module prend en charge les tags exactement comme le fait Exporter.

use Importer 'Some::Thing'  => ':DEFAULT';
use Importer 'Other::Thing' => ':some_tag';

Les tags peuvent être spécifiés de cette manière :

our %EXPORT_TAGS = (
    oos => [qw/foo boo zoo/],
    ees => [qw/fee bee zee/],
);

@EXPORT_FAIL

C'est utilisé exactement de la même manière que par Exporter.

Utilisez ceci pour lister les subs qui ne sont pas disponibles sur toutes les plateformes. Si quelqu'un essaie d'en importer une, Importer appellera votre « $from->export_fail(@items) » callback pour essayer de résoudre le problème. Voir Exporter pour la documentation de cette fonctionnalité.

our @EXPORT_FAIL = qw/maybe_bad/;

%EXPORT_ANON

C'est nouveau dans ce module, Exporter ne le prend pas en charge.

Cela vous permet d'exporter des symboles qui ne sont pas réellement dans la table de symboles de votre package. Les clés doivent être les noms des symboles, les valeurs sont les références pour les symboles.

our %EXPORT_ANON = (
    '&foo' => sub { 'foo' }
    '$foo' => \$foo,
    ...
);

%EXPORT_GEN

C'est nouveau dans ce module, Exporter ne le prend pas en charge.

Cela vous permet d'exporter des symboles qui sont générés lors de l'export. La clé doit être le nom d'un symbole. La valeur doit être une référence de code qui produit une référence qui sera exportée.

Lorsque les générateurs sont appelés, ils recevront 2 arguments, le package dans lequel le symbole est exporté, et le symbole importé (le nom peut ou non inclure le sigle pour les subs).

our %EXPORT_GEN = (
    '&foo' => sub {
        my $from_package = shift;
        my ($into_package, $symbol_name) = @_;
        ...
        return sub { ... };
    },
    ...
);

%EXPORT_MAGIC

C'est nouveau dans ce module. Exporter ne le prend pas en charge.

Cela vous permet de définir des actions personnalisées à exécuter APRÈS qu'un export a été injecté dans l'espace de noms du consommateur. C'est un bon endroit pour activer des hooks de parseur comme avec Devel::Declare. Ceux-ci NE seront PAS exécutés si un consommateur utilise un callback d'affectation personnalisé.

our %EXPORT_MAGIC = (
    foo => sub {
        my $from = shift;    # Devrait être le package qui fait l'export
        my %args = @_;
        my $into      = $args{into};         # Package dans lequel le symbole a été exporté
        my $orig_name = $args{orig_name};    # Nom original de l'export (dans l'exporteur)
        my $new_name  = $args{new_name};     # Nom sous lequel le symbole a été importé
        my $ref       = $args{ref};          # La référence vers le symbole
        ...; # ce que vous voulez, le retour est ignoré.
    },
);

UTILISATION AVEC D'AUTRES IMPLÉMENTATIONS D'EXPORTER

Si vous voulez que votre module fonctionne avec Importer, mais que vous utilisez autre chose qu'Exporter pour définir vos exports, vous pouvez le faire fonctionner en définissant la méthode « IMPORTER_MENU » dans votre package. De même, d'autres exporteurs peuvent être mis à jour pour prendre en charge Importer en plaçant cette sub dans votre package. IMPORTER_MENU() doit être défini dans votre package, pas dans une classe de base !

sub IMPORTER_MENU {
    my $class = shift;
    my ($into, $caller) = @_;
    return (
        export       => \@EXPORT,          # Exports par défaut
        export_ok    => \@EXPORT_OK,       # Autres exports autorisés
        export_tags  => \%EXPORT_TAGS,     # Définir les tags
        export_fail  => \@EXPORT_FAIL,     # Pour les subs qui peuvent ne pas toujours être disponibles
        export_anon  => \%EXPORT_ANON,     # Symboles anonymes à exporter
        export_magic => \%EXPORT_MAGIC,    # Magie à appliquer après qu'un symbole est exporté
        generate   => \&GENERATE,          # Sub pour générer des exports dynamiques
                                           # OU
        export_gen => \%EXPORT_GEN,        # Hachage de constructeurs, la clé est le nom
                                           # du symbole, la valeur est la sub qui génère
                                           # la référence du symbole.
    );
}
sub GENERATE {
    my ($symbol) = @_;
    ...
    return $ref;
}

Tous les exports doivent être listés dans soit @EXPORT ou @EXPORT_OK, ou être des clés dans %EXPORT_GEN ou %EXPORT_ANON pour être autorisés. 'export_tags', 'export_fail', 'export_anon', 'export_gen' et 'generate' sont facultatifs. Vous ne pouvez pas combiner 'generate' et 'export_gen'.

Note : Si votre sub GENERATE a besoin de $class, $into, ou $caller alors votre méthode IMPORTER_MENU() devra construire une sub anonyme qui les capture :

sub IMPORTER_MENU {
    my $class = shift;
    my ($into, $caller) = @_;
    return (
        ...
        generate => sub { $class->GENERATE($into, $caller, @_) },
    );
}

Interface OO

use Importer;
my $imp = Importer->new(from => 'Some::Exporter');
$imp->do_import('Destination::Package');
$imp->do_import('Another::Destination', @symbols);

Ou, peut-être plus utile :

my $imp = Importer->new(from => 'Carp');
my $croak = $imp->get_one('croak');
$croak->("This will croak");

CONSTRUCTION D'OBJET

$imp = Importer->new(from => 'Some::Exporter')
$imp = Importer->new(from => 'Some::Exporter', caller => [$package, $file, $line])
Voici comment vous créez une nouvelle instance d'Importer. « from => 'Some::Exporter' » est le seul argument requis. Vous pouvez également spécifier le « caller => [...] » tableau de référence, qui sera utilisé uniquement pour le rapport d'erreurs. Si vous ne spécifiez pas un appelant alors Importer tentera de trouver l'appelant dynamiquement à chaque fois qu'il en aura besoin (ce qui est lent et coûteux, mais nécessaire si vous avez l'intention de réutiliser l'objet.)

MÉTHODES OBJET

$imp->do_import($into)
$imp->do_import($into, @symboles)
Cela importera depuis le paquet "from" de l'objet vers le paquet $into. Vous pouvez fournir une liste de @symboles, ou la laisser vide pour utiliser les valeurs par défaut.
$imp->do_unimport()
$imp->do_unimport(@symboles)
Cela supprimera les symboles importés du paquet "from" de l'objet. Si vous spécifiez une liste de @symboles, seuls les symboles spécifiés seront supprimés, sinon tous les symboles importés en utilisant Importer seront supprimés.

Note : Veuillez être conscient de la différence entre do_import() et do_unimport(). Pour l'importation, 'from' est utilisé comme origine, dans la désimportation, il est utilisé comme cible. Cela signifie que vous ne pouvez pas réutiliser une instance pour importer puis désimporter.

($into, $versions, $exclude, $symboles, $set) = $imp->parse_args('Dest::Package')
($into, $versions, $exclude, $symboles, $set) = $imp->parse_args('Dest::Package', @symboles)
Cela analyse les arguments. Le premier argument doit être le paquet de destination. D'autres arguments peuvent être un mélange de noms de symboles, de balises, de motifs, de numéros de version et d'exclusions.
$caller_ref = $imp->get_caller()
Cela trouvera l'appelant. Ceci est principalement utilisé pour le signalement d'erreurs. Si l'objet a été construit avec un appelant, c'est ce qui est retourné, sinon il parcourra la pile à la recherche du premier appel qui n'est pas originaire d'un paquet qui ISA Importer.
$imp->carp($warning)
Avertit au niveau de l'appelant.
$imp->croak($exception)
Meurt au niveau de l'appelant.
$from_package = $imp->from()
Obtient le paquet "from" qui a été spécifié lors de la construction.
$file = $imp->from_file()
Obtient le nom de fichier du paquet "from".
$imp->load_from()
Cela chargera le paquet "from" s'il n'a pas déjà été chargé. Cela utilise une magie pour s'assurer que les erreurs dans le processus de chargement sont signalées à l'"appelant".
$menu_hr = $imp->menu($into)
Obtient le menu d'exportation construit à partir, ou fourni par, le paquet "from". Ceci est mis en cache après la première fois qu'il est appelé. Utilisez "$imp->reload_menu()" pour le rafraîchir.

La structure du menu ressemble à ceci :

$menu = {
    # chaque export valide a une clé dans le hashref de recherche, la valeur est toujours
    # 1, la clé inclut toujours le sigil
    lookup => {'&symbol_a' => 1, '$symbol_b' => 1, ...},
    # la plupart des exports sont listés ici, le nom du symbole avec sigil est la clé, la valeur est
    # une référence vers le symbole. Si un symbole est manquant, il peut être généré.
    exports => {'&symbol_a' => \&symbol_a, '$symbol_b' => \$symbol_b, ...},
    # Hashref de balises, le nom de la balise (sans le préfixe ':') est la clé, la valeur est un
    # arrayref de noms de symboles, les subs peuvent avoir un sigil, mais ne sont pas obligatoires.
    tags => { DEFAULT => [...], foo => [...], ... },
    # Magie à appliquer
    magic => { foo => sub { ... }, ... },
    # Ceci est un hashref tout comme 'lookup'. Les clés sont des symboles qui ne peuvent pas
    # toujours être disponibles. S'il n'y a pas de symboles dans cette catégorie,
    # la valeur de la clé 'fail' sera undef au lieu d'un hashref.
    fail => { '&iffy_symbol' => 1, '\&only_on_linux' => 1 },
    # OU fail => undef,
    # Si présent, cette sous-routine sait comment générer des références pour les
    # symboles listés dans 'lookup', mais manquants dans 'exports'. Les références
    # qu'elle retourne ne sont JAMAIS mises en cache.
    generate => sub { my $sym_name = shift; ...; return $symbol_ref },
};
$imp->reload_menu($into)
Cela rechargera le menu d'exportation à partir du paquet "from".
my $exports = $imp->get(@imports)
Cela retourne un hashref de "{ $name => $ref }" pour tous les imports spécifiés.
my @export_refs = $imp->get_list(@imports)
Cela retourne une liste de références pour chaque import spécifié. Seules les références d'exportation sont retournées, les noms ne le sont pas.
$export_ref = $imp->get_one($import)
Cela retourne une seule référence à un seul export. Si vous fournissez plusieurs imports, seul le DERNIER sera utilisé.

FONCTIONS

Celles-ci peuvent être importées :

use Importer 'Importer' => qw/import optimal_import/;
$bool = optimal_import($from, $into, \@caller, @imports)
Cette fonction tentera d'importer @imports du paquet $from vers le paquet $into. @caller doit contenir un nom de paquet, un nom de fichier et un numéro de ligne. Si cette fonction échoue, aucun export ne sera réellement effectué.

Si l'importation réussit, elle retournera vrai.

Si l'importation échoue, elle retournera faux et aucune modification de la table des symboles ne sera effectuée.

$class->import(@imports)
Si vous écrivez une classe destinée à être utilisée avec Importer, mais que vous avez également besoin de fournir une méthode d'importation héritée pour les consommateurs directs de votre classe, vous pouvez importer cette méthode import(). 
package My::Exporter;
# Ceci vous donnera 'import()' très similaire à 'use base "Exporter";'
use Importer 'Importer' => qw/import/;
...
