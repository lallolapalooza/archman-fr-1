IPC::Run::IO(3) Documentation Perl Contribuée par l'Utilisateur IPC::Run::IO(3)

NOM

IPC::Run::IO -- Canaux d'E/S pour IPC::Run.

SYNOPSIS

PAS ENCORE IMPLÉMENTÉ SOUS Win32 ! Win32 ne permet pas select() sur les descripteurs de fichiers normaux ; IPC::RUN::IO nécessite d'utiliser IPC::Run::Win32Helper pour cela.

use IPC::Run qw( io );
## Le sens de '>' et '<' est l'inverse de celui de perl open(),
## mais il est conforme à IPC::Run.
$io = io( "nom_fichier", '>',  \$reception );
$io = io( "nom_fichier", 'r',  \$reception );
## Ajouter à $reception :
$io = io( "nom_fichier", '>>', \$reception );
$io = io( "nom_fichier", 'ra', \$reception );
$io = io( "nom_fichier", '<',  \$envoi );
$io = io( "nom_fichier", 'w',  \$envoi );
$io = io( "nom_fichier", '<<', \$envoi );
$io = io( "nom_fichier", 'wa', \$envoi );
## Descripteurs / objets IO ouverts par l'appelant :
$io = io( \*DESC,   '<',  \$envoi );
$f = IO::Handle->new( ... ); # Toute sous-classe de IO::Handle
$io = io( $f, '<', \$envoi );
require IPC::Run::IO;
$io = IPC::Run::IO->new( ... );
## Ensuite, utilisez run(), harness(), ou start() :
run $io, ...;
## Vous pouvez, bien sûr, utiliser io() ou IPC::Run::IO->new() comme
## argument de run(), harness, ou start() :
run io( ... );

DESCRIPTION

Cette classe et ce module permettent de maîtriser les descripteurs de fichiers et les noms de fichiers pour les E/S lorsqu'ils sont utilisés avec IPC::Run, indépendamment de tout ce que fait IPC::Run (sauf que les erreurs et exceptions peuvent affecter toutes les choses qu'IPC::Run est en train de faire).

SOUS-CLASSEMENT

CHANGEMENT INCOMPATIBLE : en raison de la difficulté introduite par la suppression des pseudohashs de Perl, cette classe n'utilise *plus* le pragma fields.

nom_fichier
Récupère/définit le nom du fichier. Renvoie la valeur après le changement de nom, le cas échéant.
init
Effectue l'initialisation requise avant que cela puisse être exécuté. Cela inclut l'ouverture du fichier, si nécessaire, et l'effacement du scalaire de destination si nécessaire.
open
Si un nom de fichier a été passé, l'ouvre. Détermine si le descripteur est ouvert via fileno(). Lance une exception en cas d'erreur.
open_pipe
S'il s'agit d'un objet d'E/S de redirection, il ouvre le tube d'une manière indépendante de la plateforme.
close
Ferme le descripteur. Lance une exception en cas d'échec.
fileno
Renvoie le fileno du descripteur. Lance une exception en cas d'échec.
mode
Renvoie l'opérateur en termes de 'r', 'w', et 'a'. Il existe un état 'ra', contrairement à l'ouverture de Perl, qui indique que les données lues du descripteur ou du fichier seront ajoutées à la sortie si la sortie est un scalaire. Ceci n'a de sens que si la sortie est un scalaire ; cela n'a aucun effet si la sortie est une sous-routine.

Les opérateurs de redirection peuvent être un peu déroutants, voici donc un tableau de référence :

>      r      Lire depuis le descripteur vers le processus
<      w      Écrire depuis le processus vers le descripteur
>>     ra     Lire depuis le descripteur, l'ajoutant aux données existantes
              si la destination est un scalaire.
<<     wa     Écrire depuis le processus vers le descripteur, l'ajoutant aux données existantes
              si IPC::Run::IO a ouvert un fichier nommé.
op
Renvoie l'opération : '<', '>', '<<', '>>'. Voir "mode" si vous voulez les épeler 'r', 'w', etc.
binmode
Définit/récupère si ce tube est en mode binaire ou non. Aucun effet hors des systèmes d'exploitation Win32, bien sûr, et sous Win32, aucun effet une fois que le harness est start()ed.
dir
Renvoie le premier caractère de $self->op. C'est soit "<" soit ">".
