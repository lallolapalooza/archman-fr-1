NOM

IO::WrapTie - encapsuler des objets utilisables par tie() dans une interface IO::Handle

Ceci est actuellement du code Alpha, publié pour commentaires.
Merci de me faire part de vos retours !

SYNOPIS

Tout d'abord, vous aurez besoin de tie(), donc :

require 5.004;

Interface fonctionnelle (expérimental). Utilisez ceci avec n'importe quelle classe existante...

use IO::WrapTie;
use FooHandle;                  ### implémente l'interface TIEHANDLE
### Supposons que nous voulons un "FooHandle->new(&FOO_RDWR, 2)".
### Nous pouvons plutôt dire...
$FH = wraptie('FooHandle', &FOO_RDWR, 2);
### Maintenant nous pouvons utiliser...
print $FH "Salut, ";            ### syntaxe d'opérateur traditionnelle...
$FH->print("monde !\n");         ### ...et aussi la syntaxe OO !

Interface OO (préférée). Vous pouvez hériter de "Slave" dans le mixin IO::WrapTie pour obtenir un constructeur sympathique new_tie()...

#------------------------------
package FooHandle;                        ### une classe qui peut TIEHANDLE
use IO::WrapTie;
@ISA = qw(IO::WrapTie::Slave);            ### hérite de new_tie()
...
#------------------------------
package main;
$FH = FooHandle->new_tie(&FOO_RDWR, 2);   ### $FH est un IO::WrapTie::Master
print $FH "Salut, ";                      ### syntaxe d'opérateur traditionnelle
$FH->print("monde !\n");                   ### syntaxe OO

Voir IO::Scalar comme exemple. Il vous montre également comment créer des classes qui fonctionnent avec et sans 5.004.

DESCRIPTION

Supposons que vous ayez une classe "FooHandle", où...

  • "FooHandle" n'hérite pas de IO::Handle. C'est-à-dire qu'elle effectue des E/S similaires à celles des descripteurs de fichiers, mais vers autre chose qu'un descripteur de fichier sous-jacent. IO::Scalar (pour écrire dans une chaîne) et IO::Lines (pour écrire dans un tableau de lignes) en sont de bons exemples.
  • "FooHandle" implémente l'interface "TIEHANDLE" (voir perltie). C'est-à-dire qu'elle fournit les méthodes "TIEHANDLE", "GETC", "PRINT", "PRINTF", "READ" et "READLINE".
  • "FooHandle" implémente l'interface OO traditionnelle de FileHandle et IO::Handle. C'est-à-dire qu'elle contient des méthodes comme "getline", "read", "print", "seek", "tell", "eof", etc.

Normalement, les utilisateurs de votre classe auraient deux options :

  • Utiliser uniquement la syntaxe OO, et renoncer aux opérateurs d'E/S nommés comme "print".
  • Utiliser avec tie, et renoncer à le traiter comme un objet de première classe (c'est-à-dire que les méthodes spécifiques à la classe ne peuvent être invoquées que via l'objet sous-jacent via "tied"... donnant à l'objet une "double personnalité").

Mais maintenant, avec IO::WrapTie, vous pouvez dire :

$WT = wraptie('FooHandle', &FOO_RDWR, 2);
$WT->print("Salut, monde !\n");   ### syntaxe OO
print $WT "Oui !\n";             ### aussi la syntaxe d'opérateur nommée !
$WT->weird_stuff;               ### Autres méthodes !

Et si vous créez une classe comme "FooHandle", faites-la simplement hériter de "IO::WrapTie::Slave" et cette première ligne devient encore plus jolie :

$WT = FooHandle->new_tie(&FOO_RDWR, 2);

En résumé : maintenant, presque n'importe quelle classe peut ressembler et fonctionner exactement comme un IO::Handle et être utilisée à la fois avec la syntaxe d'E/S OO et non-OO.

COMMENT TOUT FONCTIONNE

Les structures de données

Considérez ce code d'exemple, utilisant les classes de cette distribution :

use IO::Scalar;
use IO::WrapTie;
$WT = wraptie('IO::Scalar',\$s);
print $WT "Salut, ";
$WT->print("monde !\n");

Dans ce code, la fonction "wraptie" crée une structure de données comme suit :

                      * $WT est une référence bénie vers un descripteur de fichier lié
          $WT           glob; ce glob est lié à l'objet "Slave".
           |          * Vous feriez toutes vos E/S directement avec $WT.
           |
           |
           |     ,---isa--> IO::WrapTie::Master >--isa--> IO::Handle
           V    /
    .-------------.
    |             |
    |             |   * Les opérateurs d'E/S Perl fonctionnent sur l'objet lié,
    |  "Master"   |     invoquant les méthodes C<TIEHANDLE>.
    |             |   * Les invocations de méthodes sont déléguées à l'esclave lié.
    |             |
    `-------------'
           |
tied(*$WT) |     .---isa--> IO::WrapTie::Slave
           V    /
    .-------------.
    |             |
    |   "Slave"   |   * Instance d'une classe de type FileHandle qui n'utilise
    |             |     pas réellement de descripteurs de fichiers, comme IO::Scalar.
    |  IO::Scalar |   * L'esclave peut être de n'importe quel type d'objet.
    |             |   * Doit implémenter l'interface C<TIEHANDLE>.
    `-------------'

NOTE : tout comme un IO::Handle est réellement une référence bénie vers un glob de descripteur de fichier *traditionnel*. De même, un "IO::WrapTie::Master" est réellement une référence bénie vers un glob de descripteur de fichier *qui a été lié à une certaine classe "esclave"*.

Comment fonctionne "wraptie"

1.
L'appel à la fonction "wraptie(CLASSE_ESCLAVE, ARGUMENTS_TIE...)" est transmis à IO::WrapTie::Master::new(). Notez que la classe "IO::WrapTie::Master" est une sous-classe de IO::Handle.
2.
La méthode "IO::WrapTie::Master->new" crée un nouvel objet IO::Handle, re-béni dans la classe "IO::WrapTie::Master". Cet objet est le *maître*, qui sera retourné par le constructeur. En même temps...
3.
La méthode "new" crée également l'*esclave* : c'est une instance de "CLASSE_ESCLAVE" qui est créée en liant l'IO::Handle du maître à "CLASSE_ESCLAVE" via "tie". Cet appel à "tie" crée l'esclave de la manière suivante :
4.
La classe "CLASSE_ESCLAVE" reçoit le message "TIEHANDLE" ; elle délègue généralement cela à "CLASSE_ESCLAVE->new(ARGUMENTS_TIE)", résultant en la création et le retour d'une nouvelle instance de "CLASSE_ESCLAVE".
5.
Une fois le maître et l'esclave créés, le maître est retourné à l'appelant.

Comment fonctionnent les opérateurs d'E/S (sur le maître)

Considérez l'utilisation d'un opérateur d'E/S sur le maître :

print $WT "Salut, monde !\n";

Comme le maître $WT est réellement une référence "bénie" vers un glob, les opérateurs d'E/S normaux de Perl comme "print" peuvent être utilisés dessus. Ils agiront simplement sur la partie symbole du glob.

Comme le glob est lié à l'esclave, la méthode "PRINT" de l'esclave (partie de l'interface "TIEHANDLE") sera automatiquement invoquée.

Si l'esclave est un IO::Scalar, cela signifie que "PRINT" dans IO::Scalar sera invoqué, et cette méthode délègue par hasard à la méthode "print" de la même classe. Donc le *vrai* travail est finalement effectué par "print" dans IO::Scalar.
