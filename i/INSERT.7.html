NOM

INSERT - créer de nouvelles lignes dans une table

SYNTAXE

[ WITH [ RECURSIVE ] requete_commune [, ...] ]
INSERT INTO nom_table [ AS alias ] [ ( nom_colonne [, ...] ) ]
    [ OVERRIDING { SYSTEM | USER } VALUE ]
    { DEFAULT VALUES | VALUES ( { expression | DEFAULT } [, ...] ) [, ...] | requete }
    [ ON CONFLICT [ cible_conflit ] action_conflit ]
    [ RETURNING [ WITH ( { OLD | NEW } AS alias_sortie [, ...] ) ]
                { * | expression_sortie [ [ AS ] nom_sortie ] } [, ...] ]
où cible_conflit peut être l'un des suivants :
    ( { nom_colonne_index | ( expression_index ) } [ COLLATE collation ] [ opclass ] [, ...] ) [ WHERE predicate_index ]
    ON CONSTRAINT nom_contrainte
et action_conflit est l'un des suivants :
    DO NOTHING
    DO UPDATE SET { nom_colonne = { expression | DEFAULT } |
                    ( nom_colonne [, ...] ) = [ ROW ] ( { expression | DEFAULT } [, ...] ) |
                    ( nom_colonne [, ...] ) = ( sous-requete )
                  } [, ...]
              [ WHERE condition ]

DESCRIPTION

INSERT insère de nouvelles lignes dans une table. On peut insérer une ou plusieurs lignes spécifiées par des expressions de valeur, ou zéro ou plusieurs lignes résultant d'une requête.

Les noms des colonnes cibles peuvent être listés dans n'importe quel ordre. Si aucune liste de noms de colonnes n'est fournie, la valeur par défaut est toutes les colonnes de la table dans leur ordre déclaré ; ou les N premiers noms de colonnes, s'il n'y a que N colonnes fournies par la clause VALUES ou la requête. Les valeurs fournies par la clause VALUES ou la requête sont associées à la liste explicite ou implicite des colonnes de gauche à droite.

Chaque colonne non présente dans la liste explicite ou implicite des colonnes sera remplie avec une valeur par défaut, soit sa valeur par défaut déclarée, soit NULL s'il n'y en a pas.

Si l'expression pour une colonne quelconque n'est pas du bon type de données, une conversion de type automatique sera tentée.

L'insertion dans des tables qui n'ont pas d'index uniques ne sera pas bloquée par une activité concurrente. Les tables avec des index uniques peuvent être bloquées si des sessions concurrentes effectuent des actions qui verrouillent ou modifient des lignes correspondant aux valeurs d'index uniques en cours d'insertion ; les détails sont couverts dans la Section 63.5. ON CONFLICT peut être utilisé pour spécifier une action alternative au lieu de lever une erreur de violation de contrainte unique ou de contrainte d'exclusion. (Voir la clause ON CONFLICT ci-dessous.)

La clause RETURNING optionnelle provoque l'exécution par INSERT du calcul et du retour de la ou des valeurs basées sur chaque ligne effectivement insérée (ou mise à jour, si une clause ON CONFLICT DO UPDATE a été utilisée). Ceci est principalement utile pour obtenir des valeurs fournies par défaut, comme un numéro de séquence SERIAL. Cependant, toute expression utilisant les colonnes de la table est autorisée. La syntaxe de la liste RETURNING est identique à celle de la liste de sortie de SELECT. Seules les lignes qui ont été insérées ou mises à jour avec succès seront retournées. Par exemple, si une ligne a été verrouillée mais pas mise à jour parce qu'une condition de clause ON CONFLICT DO UPDATE ... WHERE n'était pas satisfaite, la ligne ne sera pas retournée.

Vous devez avoir le privilège INSERT sur une table pour pouvoir y insérer. Si ON CONFLICT DO UPDATE est présent, le privilège UPDATE sur la table est également requis.

Si une liste de colonnes est spécifiée, vous n'avez besoin que du privilège INSERT sur les colonnes listées. De même, lorsque ON CONFLICT DO UPDATE est spécifié, vous n'avez besoin que du privilège UPDATE sur la ou les colonnes listées pour être mises à jour. Cependant, ON CONFLICT DO UPDATE requiert également le privilège SELECT sur toute colonne dont les valeurs sont lues dans les expressions ON CONFLICT DO UPDATE ou la condition.

L'utilisation de la clause RETURNING nécessite le privilège SELECT sur toutes les colonnes mentionnées dans RETURNING. Si vous utilisez la clause requête pour insérer des lignes à partir d'une requête, vous devez bien sûr avoir le privilège SELECT sur toute table ou colonne utilisée dans la requête.

PARAMÈTRES

Insertion

Cette section couvre les paramètres qui peuvent être utilisés lors de l'insertion de nouvelles lignes uniquement. Les paramètres utilisés *exclusivement* avec la clause ON CONFLICT sont décrits séparément.

requete_commune

La clause WITH permet de spécifier une ou plusieurs sous-requêtes qui peuvent être référencées par leur nom dans la requête INSERT. Voir la Section 7.8 et SELECT(7) pour plus de détails.

Il est possible que la requête (instruction SELECT) contienne également une clause WITH. Dans un tel cas, les deux ensembles de requete_commune peuvent être référencés dans la requête, mais le second a la priorité car il est imbriqué plus profondément.

nom_table

Le nom (éventuellement qualifié par un schéma) d'une table existante.

alias

Un nom substitut pour nom_table. Lorsqu'un alias est fourni, il masque complètement le nom réel de la table. Ceci est particulièrement utile lorsque ON CONFLICT DO UPDATE cible une table nommée excluded, car cela sera sinon interprété comme le nom de la table spéciale représentant la ligne proposée pour insertion.

nom_colonne

Le nom d'une colonne dans la table nommée par nom_table. Le nom de la colonne peut être qualifié par un nom de sous-champ ou un indice de tableau, si nécessaire. (L'insertion dans seulement certains champs d'une colonne composite laisse les autres champs à NULL.) Lors de la référence à une colonne avec ON CONFLICT DO UPDATE, n'incluez pas le nom de la table dans la spécification d'une colonne cible. Par exemple, INSERT INTO nom_table ... ON CONFLICT DO UPDATE SET nom_table.col = 1 est invalide (cela suit le comportement général de UPDATE).

OVERRIDING SYSTEM VALUE

Si cette clause est spécifiée, alors toute valeur fournie pour les colonnes d'identité remplacera les valeurs générées par séquence par défaut.

Pour une colonne d'identité définie comme GENERATED ALWAYS, il est une erreur d'insérer une valeur explicite (autre que DEFAULT) sans spécifier soit OVERRIDING SYSTEM VALUE, soit OVERRIDING USER VALUE. (Pour une colonne d'identité définie comme GENERATED BY DEFAULT, OVERRIDING SYSTEM VALUE est le comportement normal et sa spécification ne fait rien, mais PostgreSQL l'autorise en tant qu'extension.)

OVERRIDING USER VALUE

Si cette clause est spécifiée, alors toute valeur fournie pour les colonnes d'identité est ignorée et les valeurs générées par séquence par défaut sont appliquées.

Cette clause est utile, par exemple, lors de la copie de valeurs entre tables. L'écriture de INSERT INTO tbl2 OVERRIDING USER VALUE SELECT * FROM tbl1 copiera de tbl1 toutes les colonnes qui ne sont pas des colonnes d'identité dans tbl2, tandis que les valeurs pour les colonnes d'identité dans tbl2 seront générées par les séquences associées à tbl2.

DEFAULT VALUES

Toutes les colonnes seront remplies avec leurs valeurs par défaut, comme si DEFAULT était explicitement spécifié pour chaque colonne. (Une clause OVERRIDING n'est pas permise sous cette forme.)

expression

Une expression ou une valeur à assigner à la colonne correspondante.

DEFAULT

La colonne correspondante sera remplie avec sa valeur par défaut. Une colonne d'identité sera remplie avec une nouvelle valeur générée par la séquence associée. Pour une colonne générée, la spécification de ceci est permise mais spécifie simplement le comportement normal de calcul de la colonne à partir de son expression de génération.

requete

Une requête (instruction SELECT) qui fournit les lignes à insérer. Référez-vous à l'instruction SELECT(7) pour une description de la syntaxe.

alias_sortie

Un nom substitut optionnel pour les lignes OLD ou NEW dans la liste RETURNING.

Par défaut, les anciennes valeurs de la table cible peuvent être retournées en écrivant OLD.nom_colonne ou OLD.*, et les nouvelles valeurs peuvent être retournées en écrivant NEW.nom_colonne ou NEW.*. Lorsqu'un alias est fourni, ces noms sont masqués et les lignes anciennes ou nouvelles doivent être référencées en utilisant l'alias. Par exemple RETURNING WITH (OLD AS o, NEW AS n) o.*, n.*.

expression_sortie

Une expression à calculer et retourner par la commande INSERT après l'insertion ou la mise à jour de chaque ligne. L'expression peut utiliser tous les noms de colonnes de la table nommée par nom_table. Écrivez * pour retourner toutes les colonnes des lignes insérées ou mises à jour.

    VALUES (5, 'Gizmo Transglobal'), (6, 'Associated Computing, Inc')
    ON CONFLICT (did) DO UPDATE SET dname = EXCLUDED.dname
    RETURNING old.did AS old_did, old.dname AS old_dname,
              new.did AS new_did, new.dname AS new_dname;

Insérez un distributeur, ou ne faites rien pour les lignes proposées pour insertion lorsqu'une ligne existante et exclue (une ligne avec une ou plusieurs colonnes contraintes correspondantes après l'exécution des déclencheurs before row insert) existe. L'exemple suppose qu'un index unique a été défini, qui contraint les valeurs apparaissant dans la colonne did :

INSERT INTO distributors (did, dname) VALUES (7, 'Redline GmbH')
    ON CONFLICT (did) DO NOTHING;

Insérez ou mettez à jour de nouveaux distributeurs selon les besoins. L'exemple suppose qu'un index unique a été défini, qui contraint les valeurs apparaissant dans la colonne did. La clause WHERE est utilisée pour limiter les lignes effectivement mises à jour (toute ligne existante non mise à jour sera toujours verrouillée, cependant) :

-- Ne mettez pas à jour les distributeurs existants basés dans un certain code postal
INSERT INTO distributors AS d (did, dname) VALUES (8, 'Anvil Distribution')
    ON CONFLICT (did) DO UPDATE
    SET dname = EXCLUDED.dname || ' (formerly ' || d.dname || ')'
    WHERE d.zipcode <> '21201';
-- Nommez une contrainte directement dans l'instruction (utilise l'index associé
-- pour arbitrer la prise de l'action DO NOTHING)
INSERT INTO distributors (did, dname) VALUES (9, 'Antwerp Design')
    ON CONFLICT ON CONSTRAINT distributors_pkey DO NOTHING;

Insérez un nouveau distributeur si possible ; sinon, NE FAITES RIEN. L'exemple suppose qu'un index unique a été défini, qui contraint les valeurs apparaissant dans la colonne did sur un sous-ensemble de lignes où la colonne booléenne is_active est évaluée à vrai :

-- Cette instruction pourrait déduire un index unique partiel sur "did"
-- avec un prédicat "WHERE is_active", mais elle pourrait aussi
-- simplement utiliser une contrainte unique régulière sur "did"
INSERT INTO distributors (did, dname) VALUES (10, 'Conrad International')
    ON CONFLICT (did) WHERE is_active DO NOTHING;

COMPATIBILITÉ

INSERT est conforme à la norme SQL, à l'exception de la clause RETURNING qui est une extension PostgreSQL, ainsi que la capacité d'utiliser WITH avec INSERT, et la capacité de spécifier une action alternative avec ON CONFLICT. De plus, le cas où une liste de noms de colonnes est omise, mais que toutes les colonnes ne sont pas remplies à partir de la clause VALUES ou query, est interdit par la norme. Si vous préférez une instruction plus conforme à la norme SQL que ON CONFLICT, voir MERGE(7).

La norme SQL spécifie que OVERRIDING SYSTEM VALUE ne peut être spécifié que s'il existe une colonne d'identité générée toujours. PostgreSQL autorise la clause dans tous les cas et l'ignore si elle n'est pas applicable.

Les limitations possibles de la clause query sont documentées sous SELECT(7).
