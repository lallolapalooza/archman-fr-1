de code source courants

DESCRIPTIO

N

"Inline::Filters" fournit des filtres de code source courants aux modules de langage Inline. S

auf si vous êtes développeur de module Inline, v
ous pouvez simplement lire la section suivante.

Filtres pris en

charge

Cette section décrit chaque filtre dans Inline::

Filters.

Strip_PO

D

Supprime le POD intégré d'un bloc de code dans n'importe quel langage. Ceci est implémenté en tant qu'expression régulière

: 
$code =~ s/^=\w+[^\n]*\n\n(.*?)(^=cut\n\n|\Z)
//gsm;

Cela signifie que si vous avez un langage qui contient une syntaxe de type POD, il sera supprimé par ce filtre (c'est-à-dire n'utilisez pas ce filtre avec un tel langage). Ce filtre est utile pour faire compiler du code comme ceci

: 
use Inline C => <<'END', FILTERS => 'Strip_POD'
; =head1 add Returns the sum of two integers. =
cut int add(int x, int y) { return x + y; } END

Strip_Comment

s

Supprime les commentaires d'un bloc de code dans le langage que vous utilisez. Le supprimeur de commentaires est sûr pour les chaînes -- c'est-à-dire qu'il ne supprimera pas les commentaires intégrés dans les

chaînes.

Cette fonctionnalité est utile car les grammaires C et C++ ne peuvent pas gérer les commentaires à des points arbitraires dans le code source ; le faire gonflerait la grammaire. À la place, du code comme celui-ci devrait avoir ses commentaires supprimés avant l'analyse

: 
use Inline C => <<'END', FILTERS => 'Strip_Comments';
int md5_block(char *block,   /* the block to operate on */
              long length,   /* the number of bytes */
              char **result) /* the resulting 128-bit sum */
{
     /* some code here */
}
END

Strip_Comments est disponible pour les langages suivants

:

nts
Strip_CPP_Comme
nts
Strip_Python_Comme
nts
Strip_TCL_Comme
nts

Les filtres Python et Java ne sont disponibles que pour la commodité. Il y a peu de b

esoin pour eux, car Inline::Python et Inline::Java utilisent les compilateurs officiel
s du langage pour analyser le code, et ces compilateurs connaissent les commentaires.

Preproces

s

Maintenant disponible pour tous les langages. Utilise le préprocesseur C ($Config{cpprun}) pour prétraiter un bloc de code. C'est utile si vous voulez étendre les macros et le code conditionnel avant l'analyse. Par exemple

: 
use Inline CPP => <<'END', FILTERS => 'Preprocess';
class Foo
#ifdef FOO_INHERITS_BAR
   : public Bar
#endif
{
};
END

Le code montré ci-dessus ne s'analysera pas correctement sans le filtre Preprocess, car la grammaire Inline::CPP ne peut pas comprendre les directives du

préprocesseur.

Argument

CPPFLAGS

L'argument CPPFLAGS est également disponible, pour spécifier les directives du préprocesseur

C. 
use Inline C => <<'END' => CPPFLAGS => ' -DPREPROCESSOR_DEFINE' => FILTERS => 'Preprocess';
#ifdef PREPROCESSOR_DEFINE
int foo() { return 4321; }
#else
int foo() { return -1; }
#endif
END

Le code montré ci-dessus retournera 4321 lorsque foo() est

appelé.

Argument CLEAN_AFTER_BUIL

D

Par défaut, le filtre Preprocess supprime tous les fichiers Filters*.c qu'il crée. Si vous définissez le drapeau CLEAN_AFTER_BUILD à false, alors les fichiers "Filters*.c" ne seront pas supprimés ; c'est nécessaire lorsque vous utilisez "gdb" pour déboguer les programmes Inline::C et Inline::CPP qui utilisent le filtre

Preprocess.

Si vous ne définissez pas le drapeau CLEAN_AFTER_BUILD à false, vous obtiendrez probablement une erreur "No such file or directory" dans gdb

: 
use Inline C => <<'END' => FILTERS => 'Preprocess';
// your code here
END

$ gdb /usr/bin/perl (gdb) run ./my_script.pl arg0 arg1 ... Thread 1 "perl" received signal SIGSEGV, Segmentation fault. MyPackage::my_method (this=this@entry=0x1234567, my_arg=my_arg@entry=23)
at /.../_Inline/build/eval_XXX_YYYY/FiltersZZZZ.c:42 42 /.../_Inline/build/eval_XXX_YYYY/FiltersZZZZ.c: No such file or

directory.

Si vous définissez le drapeau CLEAN_AFTER_BUILD à false, vous devriez voir le code C ou C++ réellement fautif dans gdb

: 
use Inline C => <<'END' => CLEAN_AFTER_BUILD => 0 => FILTERS => 'Preprocess';
// your code here
END

$ gdb /usr/bin/perl (gdb) run ./my_script.pl arg0 arg1 ... Thread 1 "perl" received signal SIGSEGV, Segmentation fault. MyPackage::my_method (this=this@entry=0x1234567, my_arg=my_arg@entry=23)

DÉTAIL

S

Filtres

intégrés

Les filtres de code source intégrés sont implémentés en tant que référence bénie à un hash contenant deux éléments : 'filter' est le nom du filtre, et 'coderef' est une référence de code vers le filtre approprié. L'objet a une méthode filter(), qui devrait être appelée avec l'objet ILSM comme premier paramètre, et

le code source comme deuxième paramètre. Les
filtres retournent toujours le code filtré.

Filtres fournis par

l'utilisateur

Depuis Inline 0.42, vous pouvez fournir vos propres filtres à Inline en passant une référence de code à l'option FILTERS, comme ceci

: 
sub my_filter { };
use Inline C => DATA => FILTERS => [\&my_filter]
;

La sous-routine du filtre reçoit un argument : le code non filtré. Elle doit retourner le code filtré comme sa seule valeur de retour. Si quelque chose se passe mal et que vous devez informer l'utilisateur, faites simplement un

croak.

Note : dans certaines circonstances, vous devez mettre votre sous-routine de filtre au-dessus de l'instruction "use Inline". Quand c'est possible, Inline compile votre code au moment de la compilation, ce qui signifie que la sous-routine doit être définie. Si vous

lisez le code depuis le filehandle 'DATA', vous pouvez mettre le filtre n'impor
te où dans votre script, car Inline retarde la compilation jusqu'à l'exécution.

Application des

filtres

"Inline" fournit une méthode filter() qui applique les filtres demandés l'un après l'autre sur le code source. Tous les ILSM devraient enregistrer le résultat de $o->filter() et le considérer comme le code source. Si aucun filtre n'

a été demandé, cela retourne simp
lement le code source non filtré.
