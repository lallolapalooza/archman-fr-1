DESCRIPTIO

N

"Inline::C" est un module qui permet d'écrire des sous-routines Perl en C. Depuis la version 0.30, le module Inline prend en charge plusieurs langages de programmation et chaque langage a son propre module de support. Ce document décrit comment utiliser Inline avec le langage de programmation C. Il aborde également un peu les détails internes de Perl

C.

Si vous souhaitez commencer à travailler avec des exemples de p

rogrammation immédiatement, consultez Inline::C::Cookbook. P
our plus d'informations sur Inline en général, voir Inline.

UTILISATI

ON

Vous n'utilisez jamais directement "Inline::C". C'est simplement un module de support pour utiliser "Inline.pm" avec C. L'utilisation est donc toujours

: 
use Inline C => ...
;

o

u 
bind Inline C => ..
.
;

DÉFINITIONS DE

FONCTIONS

La grammaire Inline pour C reconnaît certaines définitions de fonctions (ou signatures) dans votre code C. Si une signature est reconnue par Inline, alors elle sera disponible dans l'espace Perl. C'est-à-dire qu'Inline générera le "collage" nécessaire pour appeler cette fonction comme si c'était une sous-routine Perl. Si la signature n'est pas reconnue, Inline l'ignorera simplement, sans aucune plainte. Elle ne sera pas disponible depuis l'espace Perl, bien qu'elle soit disponible depuis l'espace

C.

Inline recherche les définitions de fonctions de style ANSI/prototype. Elles doivent être de la forme

: 
type-de-retour nom-de-fonction ( paires-type-nom ) { ...
}

Les types les plus courants sont : "int", "long", "double", "char*", et "SV*". Mais vous pouvez utiliser n'importe quel type pour lequel Inline peut trouver un typemap. Inline utilise le fichier "typemap" distribué avec Perl par défaut. Vous pouvez spécifier plus de typemaps avec l'option de configuration "typemaps"

.

Un type de retour "void" peut également être utilisé. Voici des exemples de définitions de fonctions

valides. 
int Foo(double num, char* str) {
void Foo(double num, char* str) {
void Foo(SV*, ...) {
long Foo(int i, int j, ...) {
SV* Foo(void) { # L'argument 'void' est invalide avec l'analyseur ParseRecDescent.
                # Fonctionne uniquement avec l'analyseur ParseRegExp.
                # Voir la section sur `using` (ci-dessous).
SV* Foo() {  # Alternative à la spécification de l'argument 'void'. Est valide avec
             # les analyseurs ParseRecDescent et
ParseRegExp.

Les définitions suivantes ne seraient pas reconnues

: 
Foo(int i) {               # pas de type de retour
int Foo(float f) {         # pas de typemap (par défaut) pour float
int Foo(num, str) double num; char* str;
{

Notez qu'Inline ne recherche que les définitions de fonctions, pas les prototypes de fonctions. Les définitions sont la syntaxe précédant directement un corps de fonction. De plus, Inline ne scanne pas les fichiers externes, comme les en-têt

es. Seul le code passé à Inline est utilisé pour créer les liaisons ; bien q
ue d'autres bibliothèques puissent être liées et appelées depuis l'espace C.

DES SOUS-ROUTINES C

NOM

Inline::C - Méthode de création de modules Perl écrits en C

VERSION

0.82

DESCRIPTION

Ce module vous permet de créer des modules Perl écrits en C.

Vous pouvez ainsi implémenter des parties critiques de votre code en C pour des raisons de performance, tout en conservant la simplicité et la flexibilité de Perl pour le reste.

UTILISATION

Voici un exemple simple:

use Inline 'C';
my $result = add( 5, 7 );
print $result; # affiche 12
__END__
__C__
int add(int x, int y) {
  return x + y;
}

Comme vous pouvez le voir, vous utilisez le pragma "use Inline 'C';". Ensuite, vous écrivez votre code C directement dans le script Perl, délimité par __END__ et __C__.

Inline::C va compiler et lier votre code C, puis le rendre disponible en tant que fonctions Perl.

DÉFINITIONS DE FONCTIONS

Les définitions de vos fonctions C tomberont dans l'une des quatre catégories suivantes. Pour chaque catégorie, il existe des considérations spéciales.

"int Foo(int arg1, char* arg2, SV* arg3) {"
C'est le cas le plus simple. Vous avez un type de retour non "void" et une liste d'arguments de longueur fixe. Vous n'avez pas beaucoup à vous soucier. Toutes les conversions se feront automatiquement.
"void Foo(int arg1, char* arg2, SV* arg3) {"
Dans cette catégorie, vous avez un type de retour "void". Cela signifie que soit vous ne voulez rien retourner, soit vous voulez retourner une liste. Dans ce dernier cas, vous devrez pousser vous-même les valeurs sur la Pile. Il existe quelques macros Inline qui facilitent cela. Écrivez quelque chose comme ceci : 
int i, max; SV* my_sv[10];
Inline_Stack_Vars;
Inline_Stack_Reset;
for (i = 0; i < max; i++)
  Inline_Stack_Push(my_sv[i]);
Inline_Stack_Done;

Après avoir réinitialisé le pointeur de pile, ce code pousse une série de valeurs de retour. À la fin, il utilise "Inline_Stack_Done" pour marquer la fin de la pile de retour.

Si vous voulez vraiment ne rien retourner, n'utilisez pas les macros "Inline_Stack_". Si vous devez les utiliser, définissez "Inline_Stack_Void" à la fin de votre fonction.

"char* Foo(SV* arg1, ...) {"
Dans cette catégorie, vous avez un nombre d'arguments non fixe. Cela signifie que vous devrez dépiler vous-même les valeurs de la Pile. Faites-le comme ceci : 
int i;
Inline_Stack_Vars;
for (i = 0; i < Inline_Stack_Items; i++)
  handle_sv(Inline_Stack_Item(i));

Le type de retour de Inline_Stack_Item(i) est "SV*".

"void* Foo(SV* arg1, ...) {"
Dans cette catégorie, vous avez à la fois un type de retour "void" et un nombre d'arguments non fixe. Combinez simplement les techniques des catégories 3 et 4.

EXEMPLES

Voici quelques exemples. Chacun est un programme complet que vous pouvez essayer d'exécuter vous-même. Pour beaucoup plus d'exemples, voir Inline::C::Cookbook.

Exemple #1 - Salutations

Cet exemple prendra un argument de chaîne (un nom) et affichera un salut. La fonction est appelée avec une chaîne et avec un nombre. Dans le second cas, le nombre est forcé en une chaîne.

Notez que vous n'avez pas besoin d'"#include <stdio.h">. Le fichier d'en-tête "perl.h" qui est inclus par défaut, charge automatiquement les fichiers d'en-tête C standard pour vous.

use Inline 'C';
greet('Ingy');
greet(42);
__END__
__C__
void greet(char* name) {
  printf("Hello %s!\n", name);
}

Exemple #2 - et Salutations

Ceci est similaire au dernier exemple, sauf que le nom est passé en tant que "SV*" (pointeur vers une valeur scalaire) plutôt qu'une chaîne ("char*"). Cela signifie que nous devons convertir le "SV" en chaîne nous-mêmes. Ceci est accompli en utilisant la fonction "SvPVX" qui fait partie de l'API interne "Perl". Voir "perldocperlapi" pour plus d'informations.

Un problème est que "SvPVX" ne convertit pas automatiquement les chaînes en nombres, donc nous avons une petite surprise lorsque nous essayons de saluer 42. Le programme segfault, une occurrence courante lorsque l'on plonge dans les entrailles de Perl.

use Inline 'C';
greet('Ingy');
greet(42);
__END__
__C__
void greet(SV* sv_name) {
  printf("Hello %s!\n", SvPVX(sv_name));
}

Exemple #3 - Correction du problème

Nous pouvons corriger le problème de l'exemple #2 en utilisant la fonction "SvPV" à la place. Cette fonction convertira en chaîne le "SV" s'il ne contient pas de chaîne. "SvPV" retourne la longueur de la chaîne comme deuxième paramètre. Puisque nous ne nous soucions pas de la longueur, nous pouvons simplement y mettre "PL_na", qui est une variable spéciale conçue à cet effet.

use Inline 'C';
greet('Ingy');
greet(42);
__END__
__C__
void greet(SV* sv_name) {
  printf("Hello %s!\n", SvPV(sv_name, PL_na));
}

BOGUES ET DÉFICIENCES

Si vous utilisez des noms de fonctions C qui sont également utilisés en interne par Perl, vous obtiendrez une erreur de chargement au moment de l'exécution. Il n'y a actuellement aucune fonctionnalité pour empêcher cela ou pour vous avertir. Pour l'instant, une liste des symboles internes de Perl est incluse dans la distribution du module Inline sous le nom de fichier 'symbols.perl'. Évitez de les utiliser dans votre code.
