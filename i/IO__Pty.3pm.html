NOM

IO::Pty - Classe d'objet Pseudo TTY

VERSION

1.20

RÉSUMÉ

use IO::Pty;
$pty = new IO::Pty;
$slave  = $pty->slave;
foreach $val (1..10) {
    print $pty "$val\n";
    $_ = <$slave>;
    print "$_";
}
close($slave);

DESCRIPTION

"IO::Pty" fournit une interface permettant la création d'un pseudo tty.

"IO::Pty" hérite de "IO::Handle" et fournit donc toutes les méthodes définies par le paquet "IO::Handle" .

Veuillez noter que la création de pty dépend fortement du système. Si vous rencontrez des problèmes, consultez IO::Tty pour obtenir de l'aide.

CONSTRUCTEUR

new
Le "new" constructeur ne prend aucun argument et retourne un nouvel objet fichier qui est le côté maître du pseudo tty.

MÉTHODES

ttyname()
Retourne le nom du pseudo tty esclave. Sur les machines UNIX, il s'agit du chemin du périphérique. Utilisez ce nom uniquement à titre informatif ; pour obtenir un descripteur de fichier esclave, utilisez slave().
slave()
La "slave" méthode retourne le descripteur de fichier esclave du pty maître donné, en le réouvrant si nécessaire. Si IO::Stty est installé, vous pouvez ensuite appeler "$slave->stty()" pour modifier les paramètres du terminal.
close_slave()
Le descripteur de fichier esclave sera fermé et détruit. Cela est nécessaire dans le parent après un fork pour se débarrasser du descripteur de fichier ouvert, sinon le parent ne remarquera pas la sortie de l'enfant. Les appels ultérieurs à slave() retourneront un nouveau descripteur de fichier esclave ouvert.
make_slave_controlling_terminal()
Cela définira le descripteur de fichier esclave comme terminal de contrôle du processus courant, qui deviendra le chef de session ; cela ne doit donc être appelé que par un processus enfant après un fork(), par exemple dans le rappel de sync_exec() (voir Proc::SyncExec). Voir le script "try" (aussi "test.pl") pour un exemple de la manière correcte de lancer un sous-processus.
set_raw()
Définira le pty en mode brut. Notez qu'il s'agit d'une opération à sens unique ; vous avez besoin d'IO::Stty pour définir les paramètres du terminal à autre chose.

Sur certains systèmes, le pty maître n'est pas un tty. Cette méthode vérifie cela et retourne quand même le succès sur de tels systèmes. Notez que cette méthode doit être appelée sur l'esclave, et devrait probablement être appelée sur le maître, juste pour être sûr, c'est-à-dire

$pty->slave->set_raw();
$pty->set_raw();
clone_winsize_from(\*FH)
Récupère la taille du terminal depuis le descripteur de fichier FH (qui doit être un terminal) et la transfère au pty. Retourne vrai en cas de succès et undef en cas d'échec. Notez que cela doit être appelé sur le slave, c'est-à-dire 
$pty->slave->clone_winsize_from(\*STDIN);

Sur certains systèmes, le pty maître est aussi isatty. Je n'ai en fait aucune idée si le fait de définir les tailles de terminal là-bas est transmis à l'esclave, donc si cette méthode est appelée pour un maître qui n'est pas un tty, elle retourne silencieusement OK.

Voir le script "try" pour un exemple de code comment propager SIGWINCH.

get_winsize()
Retourne la taille du terminal, dans une liste de 4 éléments. 
($row, $col, $xpixel, $ypixel) = $tty->get_winsize()
set_winsize($row, $col, $xpixel, $ypixel)
Définit la taille du terminal. Si non spécifié, $xpixel et $ypixel sont définis à 0. Comme pour "clone_winsize_from", cela doit être appelé sur le slave.
