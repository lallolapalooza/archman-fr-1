NOM

Image::Info - Extraire des métadonnées des fichiers image

SYNOPHIS

use Image::Info qw(image_info dim);
my $info = image_info("image.jpg");
if (my $error = $info->{error}) {
    die "Impossible d'analyser les informations de l'image : $error\n";
}
my $color = $info->{color_type};

my $type = image_type("image.jpg");
if (my $error = $type->{error}) {
    die "Impossible de déterminer le type de fichier : $error\n";
}
die "Les fichiers gif ne sont pas autorisés !" if $type->{file_type} eq 'GIF';

my($w, $h) = dim($info);

DESCRIPTION

Ce module fournit des fonctions pour extraire divers types de métadonnées des fichiers image.

EXPORTATIONS

N'exporte rien par défaut, mais peut exporter les méthodes suivantes sur demande :

image_info
image_type
dim
html_dim
determine_file_type

MÉTHODES

Les fonctions suivantes sont fournies par le module "Image::Info" :

image_info( $fichier )
image_info( \$donnees_img )
image_info( $fichier, clé => valeur,... )
Cette fonction prend le nom d'un fichier ou d'un descripteur de fichier comme argument et renvoie un ou plusieurs hachages (en fait des références de hachage) décrivant les images dans le fichier. S'il n'y a qu'une seule image dans le fichier, un seul hachage est renvoyé. En contexte scalaire, seul le hachage de la première image est renvoyé.

En cas d'erreur, un hachage contenant la clé "error" sera renvoyé. La valeur correspondante sera un message d'erreur approprié.

Si une référence à un scalaire est passée comme argument à cette fonction, alors il est supposé que ce scalaire contient directement les données brutes de l'image.

La fonction image_info() accepte également des arguments optionnels de type clé/valeur qui peuvent influencer les informations retournées.

image_type( $fichier )
image_type( \$donnees_img )
Renvoie un hachage avec une seule clé, "file_type". La valeur sera le type du fichier. En cas d'erreur, définit les deux clés "error" et "Errno".

Cette fonction est une alternative beaucoup plus rapide à la fonction image_info pour les situations où vous avez **uniquement** besoin de trouver le type d'image.

Elle utilise uniquement la détection interne du type de fichier pour ce faire, et n'a donc pas besoin de charger de modules de pilote spécifiques au type d'image, ni d'accéder à l'intégralité du fichier. Elle n'a également besoin que d'accéder aux 11 premiers octets du fichier.

Pour maintenir un certain niveau de compatibilité avec image_info, image_type renvoie dans le même format, avec le même style de message d'erreur. C'est-à-dire qu'elle renvoie une référence HASH, avec la clé "$type->{error}" définie s'il y a eu une erreur.

En cas de succès, la référence HASH contiendra la seule clé "file_type", qui représente le type du fichier, exprimé sous forme de code de type utilisé pour les divers pilotes ('GIF', 'JPEG', 'TIFF', etc.).

S'il y a plusieurs images dans le fichier, elles seront ignorées, car cette fonction ne fournit que le type du fichier global, et non celui des diverses images qu'il contient. Cette fonction ne renverra pas plusieurs hachages si le fichier contient plusieurs images.

Bien sûr, dans tous les cas (ou dans pratiquement tous les cas), le type des images dans le fichier sera le même que celui du fichier lui-même.

dim( $hash_info )
Prend un hachage tel que retourné par image_info() et renvoie les dimensions ($width, $height) de l'image. En contexte scalaire renvoie les dimensions sous forme de chaîne de caractères.
html_dim( $hash_info )
Renvoie les dimensions sous forme de chaîne de caractères adaptée à l'intégration directe dans les balises <img> de HTML ou SVG. Par exemple : 
print "<img src="..." @{[html_dim($info)]}>\n";
determine_file_format( $donnees_fichier )
Détermine le format du fichier à partir des données de fichier fournies (un scalaire Perl normal contenant les premiers octets du fichier), et renvoie soit undef pour un format de fichier inconnu, soit une chaîne décrivant le format, comme "BMP" ou "JPEG".

Descriptions d'images

La fonction image_info() renvoie des métadonnées sur chaque image sous la forme d'une référence à un hachage. Les clés de hachage utilisées sont dans la plupart des cas basées sur les noms des éléments TIFF. Toutes les clés en minuscules sont obligatoires pour tous les formats de fichiers et seront toujours présentes sauf si une erreur s'est produite (auquel cas la clé "error" sera présente.) Les clés en casse mixte ne seront présentes que lorsque l'élément d'information correspondant est disponible dans l'image.

Les noms de clés suivants sont courants pour tout format d'image :

file_media_type
Il s'agit du type MIME approprié pour le format de fichier donné. La valeur correspondante est une chaîne comme : "image/png" ou "image/jpeg".
file_ext
C'est l'extension de nom de fichier suggérée pour un fichier du format de fichier donné. La valeur est une chaîne de 3 lettres en minuscules comme "png", "jpg".
width
C'est le nombre de pixels horizontalement dans l'image.
height
C'est le nombre de pixels verticalement dans l'image. (TIFF utilise le nom ImageLength pour ce champ.)
color_type
La valeur est une courte chaîne décrivant le type de valeurs que les pixels encodent. La valeur peut être l'une des suivantes : 
Gray
GrayA
RGB
RGBA
CMYK
YCbCr
CIELab

Ces noms peuvent également être préfixés par "Indexed-" si l'image est composée d'index dans une palette. Parmi ceux-ci, seul "Indexed-RGB" est susceptible d'apparaître.

C'est similaire au champ TIFF "PhotometricInterpretation", mais ce nom s'est avéré trop long, nous avons donc utilisé le terme inspiré de PNG à la place.

resolution
La valeur de ce champ indique normalement la taille physique de l'image à l'écran ou sur le papier. Lorsque le spécificateur d'unité est manquant, ce champ désigne la forme carrée des pixels dans l'image.

La syntaxe de ce champ est :

<res> <unité>
<xres> "/" <yres> <unité>
<xres> "/" <yres>

Les champs <res>, <xres> et <yres> sont des nombres. L'<unité> est une chaîne comme "dpi", "dpm" ou "dpcm" (indiquant "points par pouce/cm/mètre").

SamplesPerPixel
Ceci indique combien de canaux il y a dans l'image. Pour certains formats d'image, ce nombre peut être supérieur au nombre implicite du "color_type".
BitsPerSample
Ceci indique combien de bits sont utilisés pour encoder chacun des échantillons. La valeur est une référence à un tableau contenant des nombres. Le nombre d'éléments dans le tableau doit être le même que "SamplesPerPixel".
Comment
Commentaires textuels trouvés dans le fichier. La valeur est une référence à un tableau s'il y a plusieurs commentaires trouvés.
Int

Ce site n'est en aucun cas associé à Arch Linux ni affilié à ce projet. Le contenu est uniquement une traduction des pages de manuel d'Arch publiées sur man.archlinux.org.

erlace
Si l'image est entrelacée, alors ceci indique la méthode d'entrelacement utilisée.
Compression
Ceci indique quel algorithme de compression est utilisé.
Gamma
Un nombre.
LastModificationTime
Une chaîne de caractères de date ISO

Formats d'images supportés

Les formats de fichiers image suivants sont supportés :

AVIF
Supporte les noms de clés d'informations standard de base.
BMP
Ce module supporte le format Microsoft Device Independent Bitmap (BMP, DIB, RLE).

Pour plus d'informations, voir Image::Info::BMP.

GIF
GIF87a et GIF89a sont supportés et le numéro de version est trouvé sous la forme "GIF_Version" pour la première image. Les fichiers GIF peuvent contenir plusieurs images, et les informations de toutes les images seront retournées si image_info() est appelée dans un contexte de liste. L'extension Netscape-2.0 pour boucler les séquences d'animation est représentée par la clé "GIF_Loop" pour la première image. La valeur est soit "forever" (pour toujours) soit un nombre indiquant le nombre de boucles.
ICO
Ce module supporte le format Microsoft Windows Icon Resource (.ico).
JPEG
Pour les fichiers JPEG, nous extrayons des informations à partir des segments d'application "JFIF" et "Exif".

"Exif" est le format de fichier utilisé par la plupart des appareils photo numériques. Il encode des informations telles que l'horodatage, le modèle de l'appareil, la distance focale, le temps d'exposition, l'ouverture, l'utilisation du flash, la position GPS, etc.

La spécification "Exif" est disponible à l'adresse : http://www.exif.org/specifications.html.

L'élément "color_type" peut avoir les valeurs suivantes : "Gray", "YCbCr", et "CMYK". Notez que la détection de "RGB" et "YCCK" ne fonctionne pas actuellement, mais le fera, espérons-le, à l'avenir.

PNG
Les informations provenant des chunks IHDR, PLTE, gAMA, pHYs, tEXt, tIME sont extraites. La séquence des chunks est également donnée par la clé "PNG_Chunks".
PBM/PGM/PPM
Toutes les informations disponibles sont extraites.
SVG
Fournit une pléthore d'attributs et de métadonnées d'un graphique vectoriel SVG.
TIFF
La spécification "TIFF" est disponible à l'adresse : http://partners.adobe.com/public/developer/tiff/

La spécification EXIF est disponible à l'adresse : http://www.exif.org/specifications.html

WBMP
Les fichiers wbmp n'ont pas de signature magique, ils ne peuvent donc pas être utilisés avec les fonctions normales d'Image::Info. Voir Image::Info::WBMP pour plus d'informations.
WEBP
Les fichiers VP8 (avec perte), VP8L (sans perte) et VP8X (étendu) sont supportés. Définit la clé "Animation" à vrai si le fichier est une animation. Sinon, définit la clé "Compression" soit à "VP8" soit à "Lossless" (sans perte).
XBM
Voir Image::Info::XBM pour les détails.
XPM
Voir Image::Info::XPM pour les détails.

MISE EN GARDE

Bien que ce module soit adapté à l'analyse des informations de base des images, telles que le type d'image, les dimensions et la profondeur de couleur, il n'est probablement pas suffisant pour extraire des informations plus avancées comme les données EXIF. Si vous souhaitez une bibliothèque d'analyse EXIF à jour et testée, veuillez utiliser Image::ExifTool.
