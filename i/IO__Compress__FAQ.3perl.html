Comment recompresser avec une compression différente

?

C'est plus simple que vous ne le pensez si vous réalisez que tous les objets "IO::Compress::*" sont dérivés de "IO::File" et que tous les modules "IO::Uncompress::*" peuvent lire depuis un descripteur de fichier "IO::Fi

le".

Ainsi, par exemple, disons que vous avez un fichier compressé avec gzip que vous souhaitez recompresser avec bzip2. Voici tout ce qui est nécessaire pour effectuer la

recompression. 
use IO::Uncompress::Gunzip ':all';
use IO::Compress::Bzip2 ':all';
my $gzipFile = "somefile.gz";
my $bzipFile = "somefile.bz2";
my $gunzip = IO::Uncompress::Gunzip->new( $gzipFile )
    or die "Cannot gunzip $gzipFile: $GunzipError\n" ;
bzip2 $gunzip => $bzipFile
    or die "Cannot bzip2 to $bzipFile: $Bzip2Error\n"
;

Notez qu'il y a une limitation à cette technique. Certains formats de fichiers de compression stockent des informations sup

plémentaires avec les données compressées. Par exemple, gzip peut éventuellement stocker le nom de fichier original et Zip
stocke beaucoup d'informations sur le fichier original. Si le fichier compressé original contient l'une de ces informati
ons supplémentaires, elles ne seront pas transférées vers le nouveau fichier compressé en utilisant la technique ci-dessus.

Puis-je lire/écrire des fichiers Zip plus grands que 4 Gig

Oui, à la fois les modules "IO-Compress-Zip" et "IO-Uncompress-Unzip" prennent en charge la fonctionnalité zip appelée Zip64. Cela leur permet de lire/écrire des fichiers/buffers plus grands que 4

Si vous créez un fichier Zip en utilisant l'interface one-shot, et que l'un des fichiers d'entrée est supérieur à 4 Gig, un fichier zip conforme à zip64 sera

zip "really-large-file" => "my.

zip";

L'interface one-shot vous permet de forcer la création d'un fichier zip zip64 en incluant l' option "Zi

Gestion des fichiers gzip

concaténés

Si le programme gunzip rencontre un fichier contenant plusieurs fichiers gzip concaténés, il les décompressera automatiquement tous. L'exemple ci-dessous illustre ce

comportement 
$ echo abc | gzip -c >x.gz
$ echo def | gzip -c >>x.gz
$ gunzip -c x.gz
abc
def

Par défaut "IO::Uncompress::Gunzip" ne se comportera pas comme le programme gunzip. Il ne décompressera que le premier flux de données gzip du fichier, comme montré

ci-dessous 
$ perl -MIO::Uncompress::Gunzip=:all -e 'gunzip "x.gz" => \*STDOUT'
abc

Pour forcer "IO::Uncompress::Gunzip" à décompresser tous les flux de données gzip, incluez l'option "MultiStream", comme montré

ci-dessous 
$ perl -MIO::Uncompress::Gunzip
=:all -e 'gunzip "x.gz" => \*ST
DOUT, MultiStream => 1' abc def

Apache::GZip

revisité

Ci-dessous se trouve un module de compression Apache pour mod_perl, appelé "Apache::GZip", tiré de http://perl.apache.org/docs/tutorials/tips/mod_perl_tricks/mod_perl_tricks.html#On_the_Fly_Compressio

n 
package Apache::GZip;
#File: Apache::GZip.pm
use strict vars;
use Apache::Constants ':common';
use Compress::Zlib;
use IO::File;
use constant GZIP_MAGIC => 0x1f8b;
use constant OS_MAGIC => 0x03;
sub handler {
    my $r = shift;
    my ($fh,$gz);
    my $file = $r->filename;
    return DECLINED unless $fh=IO::File->new($file);
    $r->header_out('Content-Encoding'=>'gzip');
    $r->send_http_header;
    return OK if $r->header_only;
    tie *STDOUT,'Apache::GZip',$r;
    print($_) while <$fh>;
    untie *STDOUT;
    return OK;
}
sub TIEHANDLE {
    my($class,$r) = @_;
    # initialize a deflation stream
    my $d = deflateInit(-WindowBits=>-MAX_WBITS()) || return undef;
    # gzip header -- don't ask how I found out
    $r->print(pack("nccVcc",GZIP_MAGIC,Z_DEFLATED,0,time(),0,OS_MAGIC));
    return bless { r   => $r,
                   crc =>  crc32(undef),
                   d   => $d,
                   l   =>  0
                 },$class;
}
sub PRINT {
    my $self = shift;
    foreach (@_) {
      # deflate the data
      my $data = $self->{d}->deflate($_);
      $self->{r}->print($data);
      # keep track of its length and crc
      $self->{l} += length($_);
      $self->{crc} = crc32($_,$self->{crc});
    }
}
sub DESTROY {
   my $self = shift;
   # flush the output buffers
   my $data = $self->{d}->flush;
   $self->{r}->print($data);
   # print the CRC and the total length (uncompressed)
   $self->{r}->print(pack("LL",@{$self}{qw/crc l/}));
}
1;

Voici l'entrée de configuration Apache dont vous aurez besoin pour l'utiliser. Une fois configurée, tout ce qui se trouve dans le répertoire /compressed sera compressé automatiquement

. 
<Location /compressed>
   SetHandler  perl-script
   PerlHandler Apache::GZip
</Location>

Bien qu'à première vue il semble se passer beaucoup de choses dans "Apache::GZip", on pourrait résumer ce que fait le code comme suit -- lire le contenu du fichier dans "$r->filename", le compresser et écrire les données compressées sur la sortie standard. C'est

tout.

Ce code doit faire quelques détours pour y parvenir

car
1
.
La prise en charge de gzip dans "Compress::Zlib" version 1.x ne peut fonctionner qu'avec un descripteur de fichier réel du système de fichiers. Les descripteurs de fichier utilisés par les modules Apache ne sont pas associés au système de
fichiers.
2
.
Cela signifie que toute la prise en charge de gzip doit être faite à
la main - dans ce cas en créant un descripteur de fichier lié
(tied) pour gérer la création de l'en-tête et de la queue gzip.

"IO::Compress::Gzip" n'a pas cette limitation de descripteur de fichier (c'était l'une des raisons pour lesquelles il a été écrit à l'origine). Donc si "IO::Compress::Gzip" est utilisé à la place de "Compress::Zlib", tout le code du descripteur de fichier lié peut être supprimé. Voici le code

réécrit. 
package Apache::GZip;
use strict vars;
use Apache::Constants ':common';
use IO::Compress::Gzip;
use IO::File;
sub handler {
    my $r = shift;
    my ($fh,$gz);
    my $file = $r->filename;
    return DECLINED unless $fh=IO::File->new($file);
    $r->header_out('Content-Encoding'=>'gzip');
    $r->send_http_header;
    return OK if $r->header_only;
    my $gz = IO::Compress::Gzip->new( '-', Minimal => 1 )
        or return DECLINED ;
    print $gz $_ while <$fh>;
    return OK;
}

ou encore plus succinctement, comme ceci, en utilisant un gzip en une seule

exécution 
package Apache::GZip;
use strict vars;
use Apache::Constants ':common';
use IO::Compress::Gzip qw(gzip);
sub handler {
    my $r = shift;
    $r->header_out('Content-Encoding'=>'gzip');
    $r->send_http_header;
    return OK if $r->header_only;
    gzip $r->filename => '-', Minimal => 1
      or return DECLINED ;
    return OK;
}
1;

L'utilisation de "gzip" en une seule exécution ci-dessus lit simplement depuis "$r->filename" et écrit les données compressées sur la sortie

standard.

Notez l'utilisation de l'option "Minimal" dans le code ci-dessus. Lorsque vous utilisez gzip pour Content-Encoding, vous devriez toujours utiliser cette option. Dans l'exemple ci-dessus, elle empêchera que le nom de fichier so

it inclus dans l'en-tête gzip et rendra la taille d
u flux de données gzip légèrement plus petite.

Fichiers compressés et Net::

FTP

Le module "Net::FTP" fournit deux méthodes de bas niveau appelées "stor" et "retr" qui renvoient toutes deux des descripteurs de fichier. Ces descripteurs de fichier peuvent être utilisés avec les modules "IO::Compress/Uncompress" pour compresser ou décompresser des fichiers lus depuis ou écrits vers un serveur FTP à la volée, sans avoir à créer un fichier

temporaire.

Tout d'abord, voici du code qui utilise "retr" pour décompresser un fichier lorsqu'il est lu depuis le serveur

FTP. 
use Net::FTP;
use IO::Uncompress::Gunzip qw(:all);
my $ftp = Net::FTP->new( ... )
my $retr_fh = $ftp->retr($compressed_filename);
gunzip $retr_fh => $outFilename, AutoClose => 1
    or die "Cannot uncompress '$compressed_file': $GunzipError\n"
;

et ceci pour compresser un fichier lorsqu'il est écrit vers le serveur

use IO::Compress::Gzip qw(:all);

IO::Compress::FAQ - Questions fréquemment posées sur IO::Compress

DESCRIPTION

Cette FAQ contient des informations sur l'utilisation du module IO::Compress.

GENERAL

Comment obtenir la taille des données compressées ?

Utilisez l'option CompressedSize :

    use IO::Compress::Gzip;
    my $gzip = IO::Compress::Gzip->new( \$data );
    $gzip->write( $original_data );
    $gzip->close();
    my $compressed_size = $gzip->{CompressedSize};

Comment obtenir la taille des données décompressées ?

Utilisez l'option UncompressedSize :

    use IO::Compress::Gzip;
    my $gzip = IO::Compress::Gzip->new( \$data );
    $gzip->write( $original_data );
    $gzip->close();
    my $uncompressed_size = $gzip->{UncompressedSize};

ZIP

Utilisation de "InputLength" pour décompresser des données intégrées dans un fichier/buffer plus grand.

Un cas d'utilisation assez courant est celui où des données compressées sont intégrées dans un fichier/buffer plus grand et où vous souhaitez lire les deux.

À titre d'exemple, considérez la structure d'un fichier zip. Il s'agit d'un format de fichier bien défini qui mélange des sections de données compressées et non compressées dans un seul fichier.

Pour les besoins de cette discussion, vous pouvez considérer un fichier zip comme une séquence de flux de données compressées, chacun étant préfixé par un en-tête local non compressé. L'en-tête local contient des informations sur le flux de données compressées, y compris le nom du fichier compressé et, en particulier, la longueur du flux de données compressées.

Pour illustrer comment utiliser "InputLength", voici un script qui parcourt un fichier zip et affiche le nombre de lignes dans chaque fichier compressé (si vous avez l'intention d'écrire du code pour parcourir un fichier zip pour de vrai, voir "Walking through a zip file" dans IO::Uncompress::Unzip). De plus, bien que cet exemple utilise la compression basée sur zlib, la technique peut être utilisée par les autres modules "IO::Uncompress::*".

use strict;
use warnings;
use IO::File;
use IO::Uncompress::RawInflate qw(:all);
use constant ZIP_LOCAL_HDR_SIG  => 0x04034b50;
use constant ZIP_LOCAL_HDR_LENGTH => 30;
my $file = $ARGV[0] ;
my $fh = IO::File->new( "<$file" )
            or die "Cannot open '$file': $!\n";
while (1)
{
    my $sig;
    my $buffer;
    my $x ;
    ($x = $fh->read($buffer, ZIP_LOCAL_HDR_LENGTH)) == ZIP_LOCAL_HDR_LENGTH
        or die "Truncated file: $!\n";
    my $signature = unpack ("V", substr($buffer, 0, 4));
    last unless $signature == ZIP_LOCAL_HDR_SIG;
    # Read Local Header
    my $gpFlag             = unpack ("v", substr($buffer, 6, 2));
    my $compressedMethod   = unpack ("v", substr($buffer, 8, 2));
    my $compressedLength   = unpack ("V", substr($buffer, 18, 4));
    my $uncompressedLength = unpack ("V", substr($buffer, 22, 4));
    my $filename_length    = unpack ("v", substr($buffer, 26, 2));
    my $extra_length       = unpack ("v", substr($buffer, 28, 2));
    my $filename ;
    $fh->read($filename, $filename_length) == $filename_length
        or die "Truncated file\n";
    $fh->read($buffer, $extra_length) == $extra_length
        or die "Truncated file\n";
    if ($compressedMethod != 8 && $compressedMethod != 0)
    {
        warn "Skipping file '$filename' - not deflated $compressedMethod\n";
        $fh->read($buffer, $compressedLength) == $compressedLength
            or die "Truncated file\n";
        next;
    }
    if ($compressedMethod == 0 && $gpFlag & 8 == 8)
    {
        die "Streamed Stored not supported for '$filename'\n";
    }
    next if $compressedLength == 0;
    # Done reading the Local Header
    my $inf = IO::Uncompress::RawInflate->new( $fh,
                        Transparent => 1,
                        InputLength => $compressedLength )
      or die "Cannot uncompress $file [$filename]: $RawInflateError\n"  ;
    my $line_count = 0;
    while (<$inf>)
    {
        ++ $line_count;
    }
    print "$filename: $line_count\n";
}

La majorité du code ci-dessus concerne la lecture des données d'en-tête local zip. Le code sur lequel je veux me concentrer est en bas.

while (1) {
    # read local zip header data
    # get $filename
    # get $compressedLength
    my $inf = IO::Uncompress::RawInflate->new( $fh,
                        Transparent => 1,
                        InputLength => $compressedLength )
      or die "Cannot uncompress $file [$filename]: $RawInflateError\n"  ;
    my $line_count = 0;
    while (<$inf>)
    {
        ++ $line_count;
    }
    print "$filename: $line_count\n";
}

L'appel à "IO::Uncompress::RawInflate" crée un nouveau descripteur de fichier $inf qui peut être utilisé pour lire à partir du descripteur de fichier parent $fh, en le décompressant au fur et à mesure. L'utilisation de l'option "InputLength" garantira qu'au plus $compressedLength octets de données compressées seront lus à partir du descripteur de fichier $fh (La seule exception est pour un cas d'erreur comme un fichier tronqué ou un flux de données corrompu).

Cela signifie qu'une fois que RawInflate est terminé, $fh sera positionné juste après le flux de données compressées.

Considérez maintenant à quoi ressemble le code sans "InputLength"

while (1) {
    # read local zip header data
    # get $filename
    # get $compressedLength
    # read all the compressed data into $data
    read($fh, $data, $compressedLength);
    my $inf = IO::Uncompress::RawInflate->new( \$data,
                        Transparent => 1 )
      or die "Cannot uncompress $file [$filename]: $RawInflateError\n"  ;
    my $line_count = 0;
    while (<$inf>)
    {
        ++ $line_count;
    }
    print "$filename: $line_count\n";
}

La différence ici est l'ajout de la variable temporaire $data. Elle est utilisée pour stocker une copie des données compressées pendant qu'elles sont décompressées.

Si vous savez que $compressedLength n'est pas si grand, l'utilisation d'un stockage temporaire ne sera pas un problème. Mais si $compressedLength est très grand ou si vous écrivez une application que d'autres utiliseront, et donc vous n'avez aucune idée de la taille de $compressedLength, cela pourrait poser problème.

L'utilisation de "InputLength" évite l'utilisation de stockage temporaire et permet à l'application de gérer de grands flux de données compressées.

Un dernier point : évidemment, "InputLength" ne peut être utilisé que lorsque vous connaissez la longueur des données compressées à l'avance, comme ici avec un fichier zip.
