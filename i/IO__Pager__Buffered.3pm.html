NOM

IO::Pager::Buffered - Canalise la sortie différée vers PAGER si la destination est un TTY

SYNOPIS

use IO::Pager::Buffered;
{
  local $token = IO::Pager::Buffered::open local *STDOUT;
  print <<"  HEREDOC" ;
  ...
  Un tas de texte plus tard
  HEREDOC
}
{
  # Vous pouvez aussi utiliser des descripteurs de fichiers scalaires...
  my $token = IO::Pager::Buffered::open($FH) or warn($!);
  print $FH "Pas de globs ou de mots nus pour nous merci !\n" while 1;
}
{
  # ...ou une interface objet
  my $token = new IO::Pager::Buffered;
  $token->print("OO brillant...\n") while 1;
}

DESCRIPTION

Les sous-classes de IO::Pager sont conçues pour décider programmatique s'il faut ou non canaliser la sortie d'un descripteur de fichier vers un programme spécifié dans PAGER ; déterminé et défini par IO::Pager au moment de l'exécution s'il n'est pas encore défini.

Cette sous-classe met en tampon toute la sortie pour affichage jusqu'à ce que l'exécution revienne au scope parent ou qu'une vidange manuelle se produise. Si ce n'est pas ce que vous voulez, regardez une autre sous-classe comme IO::Pager::Unbuffered. Bien que probablement pas courant, cela peut être utile dans certains cas, comme la mise en tampon de toute la sortie vers STDOUT pendant que le processus se déroule afin que les avertissements sur STDERR soient plus visibles, puis l'affichage de la sortie moins urgente de STDOUT ensuite. Ou, alternativement, laisser la sortie vers STDOUT passer et différer les avertissements pour une consultation ultérieure.

MÉTHODES

Spécificités des méthodes spécifiques à la classe ci-dessous, les autres sont héritées de IO::Pager.

open( [DESCRIPTEUR DE FICHIER] )

Instancie un nouvel IO::Pager pour paginer le DESCRIPTEUR DE FICHIER si nécessaire. Assignez la valeur de retour à une variable lexicale. La sortie ne se produit pas tant que le descripteur de fichier n'est pas vidé ou fermé.

new( [DESCRIPTEUR DE FICHIER] )

Presque identique à open, sauf que vous obtiendrez un IO::Handle en retour s'il n'y a pas de TTY pour permettre une programmation agnostique d'IO::Pager.

close( DESCRIPTEUR DE FICHIER )

Vide le tampon vers le pagineur et ferme le descripteur de fichier en écriture. Normalement, lors de l'utilisation d'une variable lexicale ou locale pour conserver le jeton fourni par open, les appels explicites à close sont inutiles. Cependant, si vous utilisez IO::Pager::Buffered avec un STDOUT ou STDERR non localisé, vous fermez le descripteur de fichier pour afficher le contenu mis en tampon ou attendez le nettoyage global des variables indésirables à la fin du programme.

Alternativement, vous pourriez préférer utiliser un descripteur de fichier non-core avec IO::Pager, et appeler "select" dans perlfunc pour en faire la valeur par défaut pour la sortie.

tell( DESCRIPTEUR DE FICHIER )

Retourne la taille du tampon en octets.

flush( DESCRIPTEUR DE FICHIER )

Vide immédiatement le contenu du tampon.

Si le dernier print ne se terminait pas par un saut de ligne, le texte du saut de ligne précédent jusqu'à la fin du tampon sera vidé mais ne s'affichera probablement pas tant qu'un saut de ligne n'est pas imprimé et vidé.

AVERTISSEMENTS

Si vous mélangez des opérations mises en tampon et non mises en tampon, l'ordre de sortie n'est pas spécifié, et sera probablement différent pour un TTY par rapport à un fichier. Voir perlfunc.

$, est utilisé, voir perlvar.

Vous voudrez probablement faire quelque chose avec SIGPIPE, par exemple ;

eval {
  local $SIG{PIPE} = sub { die };
  local $STDOUT = IO::Pager::open(*STDOUT);
  while (1) {
    # Faire quelque chose
  }
}
# Faire autre chose
