NOM

Inline::C::Cookbook - Une corne d'abondance de recettes Inline C

DESCRIPTION

Il est beaucoup plus facile pour la plupart d'entre nous de cuisiner un repas à partir d'une recette, plutôt que de simplement jeter des ingrédients dans une casserole jusqu'à ce que quelque chose d'comestible se forme. Il en va de même pour la programmation. "Inline.pm" rend la programmation C pour Perl aussi facile que possible. Avoir un ensemble d'exemples faciles à comprendre, le rend encore plus simple.

Ce livre de cuisine est destiné à être un référentiel en constante expansion de petits exemples de code complets ; chacun montrant comment accomplir une tâche particulière avec Inline. Chaque exemple est suivi d'une courte discussion, expliquant en détail les caractéristiques particulières qui sont démontrées.

Beaucoup de ces recettes sont adaptées des discussions par e-mail que j'ai eues avec des utilisateurs d'Inline dans le monde entier. D'après mon expérience jusqu'à présent, Inline fournit une solution élégante à presque tous les problèmes impliquant Perl et C.

Bon appétit !

APÉRITIFS

Bonjour, monde

Problème

Il semble que la première chose que tout programmeur veuille faire lorsqu'il apprend une nouvelle technique de programmation est de l'utiliser pour saluer la Terre. Comment puis-je faire cela en utilisant Inline ?

Solution
use Inline C => <<'...';
void greet() {
  printf("Bonjour, monde\n");
}
...
greet;
Discussion
Rien de trop compliqué ici. Nous définissons une seule fonction C greet() qui affiche un message sur STDOUT. Une chose à noter est que puisque le code Inline vient avant l'appel de la fonction à "greet", nous pouvons l'appeler comme un mot nu (sans parenthèses).

Types de données

Problème
Comment passer différents types de données vers et depuis des fonctions Inline C ; comme des chaînes de caractères, des nombres et des entiers ?
Solution
# vowels.pl
use Inline 'C';
$filename = $ARGV[0];
die "Usage: perl vowels.pl filename\n" unless -f $filename;
$text = join '', <>;           # charger le fichier d'entrée
$vp = vowel_scan($text);       # appeler notre fonction
$vp = sprintf("%03.1f", $vp * 100);  # formater pour l'impression
print "Les lettres dans $filename sont $vp% de voyelles.\n";
__END__
__C__
/* Calculer le pourcentage de voyelles par rapport aux lettres */
double vowel_scan(char* str) {
  int letters = 0;
  int vowels = 0;
  int i = 0;
  char c;
  char normalize = 'a' ^ 'A';
  /* normalize force la casse inférieure en ASCII ; supérieure en EBCDIC */
  char A = normalize | 'a';
  char E = normalize | 'e';
  char I = normalize | 'i';
  char O = normalize | 'o';
  char U = normalize | 'u';
  char Z = normalize | 'z';
  while(c = str[i++]) {
    c |= normalize;
    if (c >= A && c <= Z) {
       letters++;
       if (c == A || c == E || c == I || c == O || c == U)
         vowels++;
    }
  }
  return letters ? ((double) vowels / letters) : 0.0;
}
Discussion
Ce script prend un nom de fichier depuis la ligne de commande et affiche le ratio de voyelles par rapport aux lettres dans ce fichier. "vowels.pl" utilise une fonction Inline C appelée "vowel_scan", qui prend une chaîne de caractères en argument, et retourne le pourcentage de voyelles sous forme de nombre à virgule flottante entre 0 et 1. Il gère les lettres majuscules et minuscules, et fonctionne avec l'ASCII et l'EBCDIC. Il est également assez rapide.

L'exécution de ce script produit :

> perl vowels.pl /usr/dict/words
Les lettres dans /usr/dict/words sont 37.5% de voyelles.

Il est très important de noter que les exemples de ce livre de cuisine utilisent "char *" pour signifier une chaîne de caractères. En interne, Perl dispose de divers mécanismes pour gérer les chaînes de caractères contenant des points de code supérieurs à 255, en utilisant Unicode. Cela signifie que traiter naïvement les chaînes de caractères comme "char *", un tableau de caractères 8 bits, peut entraîner des problèmes. Vous devez en être conscient et envisager d'utiliser une bibliothèque UTF-8 pour gérer les chaînes de caractères.

Listes d'arguments variables

Problème

Comment passer une liste d'arguments de taille variable à une fonction Inline C ?

Solution
greet(qw(Sarathy Jan Sparky Murray Mike));
use Inline C => <<'END_OF_C_CODE';
void greet(SV* name1, ...) {
  Inline_Stack_Vars;
  int i;
  for (i = 0; i < Inline_Stack_Items; i++)
    printf("Bonjour %s!\n", SvPV(Inline_Stack_Item(i), PL_na));
  Inline_Stack_Void;
}
END_OF_C_CODE
Discussion
Ce petit programme salue un groupe de personnes, comme mes collègues. Nous utilisons la syntaxe d'ellipse "C" : ""..."", car la liste peut être de n'importe quelle taille.

Comme il n'y a pas de types ou de noms associés à chaque argument, nous ne pouvons pas attendre de XS qu'il gère les conversions pour nous. Nous devrons les extraire de la Pile nous-mêmes. Heureusement, il existe deux fonctions (macros) qui rendent cette tâche très facile.

Premièrement, nous devons commencer notre fonction par une instruction ""Inline_Stack_Vars"". Cela définit quelques variables internes dont nous avons besoin pour accéder à la Pile. Maintenant, nous pouvons utiliser ""Inline_Stack_Items"", qui retourne un entier contenant le nombre d'arguments qui nous ont été passés par Perl.

NOTE : Il est important d'utiliser uniquement les macros ""Inline_Stack_"" lorsqu'il y a une ellipse ("...") dans la liste des arguments, ou que la fonction a un type de retour void.

Deuxièmement, nous utilisons la fonction Inline_Stack_Item(x) pour accéder à chaque argument où "0 <= x < items".

Valeurs de retour multiples

Problème
Comment retourner une liste de valeurs à partir d'une fonction C ?
Solution
print map {"$_\n"} get_localtime(time);
use Inline C => <<'END_OF_C_CODE';
#include <time.h>
void get_localtime(SV * utc) {
  const time_t utc_ = (time_t)SvIV(utc);
  struct tm *ltime = localtime(&utc_);
  Inline_Stack_Vars;
  Inline_Stack_Reset;
  Inline_Stack_Push(sv_2mortal(newSViv(ltime->tm_year)));
  Inline_Stack_Push(sv_2mortal(newSViv(ltime->tm_mon)));
  Inline_Stack_Push(sv_2mortal(newSViv(ltime->tm_mday)));
  Inline_Stack_Push(sv_2mortal(newSViv(ltime->tm_hour)));
  Inline_Stack_Push(sv_2mortal(newSViv(ltime->tm_min)));
  Inline_Stack_Push(sv_2mortal(newSViv(ltime->tm_sec)));
  Inline_Stack_Push(sv_2mortal(newSViv(ltime->tm_isdst)));
  Inline_Stack_Done;
}
END_OF_C_CODE
Discussion
Perl est un langage où il est courant de retourner une liste de valeurs à partir d'un appel de sous-routine au lieu d'une seule valeur. C n'est pas un tel langage. Afin d'accomplir cela en C, nous devons manipuler la pile d'appels Perl manuellement. Heureusement, Inline fournit des macros pour faciliter cela.

Cet exemple appelle la fonction système "localtime", et retourne chaque partie de la structure de temps ; un peu comme la fonction intégrée Perl localtime(). Sur chaque ajout à la pile, nous créons un nouvel entier Perl (SVIV) et le rendons mortel. L'appel sv_2mortal() assure que le compte de références est correctement défini. Sans cela, le programme fuirait de la mémoire.

NOTE : L'instruction "#include" n'est pas vraiment nécessaire, car Inline
inclut automatiquement les en-têtes Perl qui incluent presque tous
les appels système standards.

Voir aussi
Pour plus d'informations sur les macros de pile d'Inline, voir Inline::C.

Valeurs de retour multiples (Autre méthode)

Problème
Comment puis-je renvoyer plus d'une valeur sans utiliser la pile Perl ?
Solution
use Inline::Files;
use Inline 'C';
my ($foo, $bar);
change($foo, $bar);
print "\$foo = $foo\n";
print "\$bar = $bar\n";
__C__
int change(SV* var1, SV* var2) {
  sv_setpvn(var1, "Perl Rocks!", 11);
  sv_setpvn(var2, "Inline Rules!", 13);
  return 1;
}
Discussion
La plupart des interfaces de fonctions Perl retournent des valeurs sous forme de liste d'un ou plusieurs scalaires. Très peu, comme "chomp", modifient un scalaire d'entrée sur place. D'un autre côté, en C, vous faites cela assez souvent. Les valeurs sont passées par référence et modifiées sur place par la fonction appelée.

Il s'avère que nous pouvons également faire cela avec Inline. Le secret est d'utiliser un type '"SV*"' pour chaque argument qui doit être modifié. Cela garantit le passage par référence, car aucun typage n'est nécessaire.

La fonction peut alors utiliser l'API Perl5 pour opérer sur cet argument. Lorsque le contrôle retourne à Perl, l'argument conservera la valeur définie par la fonction C. Dans cet exemple, nous avons passé 2 scalaires vides et leur avons directement attribué des valeurs.

Prendre une référence de tableau en argument

Problème
Comment puis-je prendre une référence de tableau Perl comme argument dans ma fonction C ?
Solution
SV *sum(SV *array) {
    int total = 0;
    int numelts, i;
    if ((!SvROK(array))
        || (SvTYPE(SvRV(array)) != SVt_PVAV)
        || ((numelts = av_len((AV *)SvRV(array))) < 0)
    ) {
        return &PL_sv_undef;
    }
    for (i = 0; i <= numelts; i++) {
        total += SvIV(*av_fetch((AV *)SvRV(array), i, 0));
    }
    return newSViv(total);
}
Discussion
Cet exemple retourne "undef" s'il reçoit une référence non valide, une référence non-tableau, ou une référence à un tableau vide. Vous pouvez voir comment vous pourriez étendre cela pour prendre plus d'une référence de tableau.

Utilisation de la mémoire

Problème
Comment dois-je allouer des tampons dans mon code Inline C ?
Solution
print greeting('Ingy');
use Inline C => <<'END_OF_C_CODE';
SV* greeting(SV* sv_name) {
  return (newSVpvf("Hello %s!\n", SvPV(sv_name, PL_na)));
}
END_OF_C_CODE
Discussion
Dans cet exemple, nous allons retourner la salutation à l'appelant, plutôt que de l'imprimer. Cela semblerait très facile, sauf que nous devons allouer un petit tampon pour créer la salutation.

Je vous exhorte à éviter d'utiliser "malloc" pour votre propre tampon. Utilisez simplement la gestion de mémoire intégrée de Perl. En d'autres termes, créez simplement un nouveau scalaire chaîne Perl. La fonction "newSVpv" fait exactement cela. Et "newSVpvf" inclut la fonctionnalité "sprintf".

L'autre problème est de se débarrasser de ce nouveau scalaire. Comment le compte de références sera-t-il décrémenté après que nous ayons renvoyé le scalaire ? Perl fournit également une fonction appelée "sv_2mortal". Les variables mortelles meurent lorsque le contexte sort de la portée. En d'autres termes, Perl attendra que le nouveau scalaire soit renvoyé, puis décrémentera le compte de références pour vous, le rendant ainsi éligible à la collecte des ordures. Voir "perldoc perlguts".

Dans cet exemple, l'appel "sv_2mortal" est effectué en coulisses par XS, car nous avons déclaré le type de retour comme étant "SV*".

Pour voir le code XS généré, exécutez la commande ""perl -MInline=INFO,FORCE,NOCLEAN example004.pl"". Cela laissera le répertoire de construction intact et vous indiquera où le trouver.

Accès direct aux variables Perl

Problème
Puis-je écrire une fonction Inline C qui peut accéder directement à une variable Perl sans avoir à la passer en argument ?
Solution
use strict;
use warnings;
use Inline C => "DATA";
our $mesh_data = "MESH-POINTS 0.0 0.0 0.5 0.25 1.0 0.5 1.5 0.75";
CalcSurfaceHeights();
__DATA__
__C__
#define N_MP 4
void CalcSurfaceHeights() {
   double x[N_MP], y[N_MP], z;
   int    ix;
   char   *mesh_data = SvPV_nolen(get_sv("main::mesh_data", 0));
   sscanf(mesh_data, "MESH-POINTS %lf%lf%lf%lf%lf%lf%lf%lf",
                     x, y, x+1, y+1, x+2, y+2, x+3, y+3);
   for (ix=0; ix < N_MP; ix++) {
      z = 0.5*( sin(x[ix]) + sin(y[ix]) );
      printf("Surface-Height: %6.3f Mesh-Point: %6.2f, %6.2f\n",
             z, x[ix], y[ix]);
   }
}
Discussion
Il n'y a en réalité que deux points qui nécessitent une explication pour comprendre pourquoi le code ci-dessus fonctionne. Dans la section Perl, vous remarquerez la déclaration 
our $mesh_data = "...";

Pour que les variables Perl soient directement accessibles depuis les fonctions Inline::C, elles doivent être déclarées comme variables de paquet. Les variables lexicales, celles déclarées avec my, ne peuvent pas être accédées de cette manière.

Dans la section C du code de l'exemple, la ligne suivante est ce qui permet l'accès direct à la variable Perl ;

char *mesh_data = SvPV_nolen(get_sv("main::mesh_data", 0))

Ici, SvPV_nolen() retourne un pointeur vers la chaîne C contenue dans la variable scalaire. La variante "_nolen" ignore la longueur de la chaîne C. Par conséquent, la fonction ne prend qu'un seul argument, qui est le SV* de la variable scalaire.

Nous aurions pu utiliser la forme habituelle à deux arguments de SvPV() et, puisque la longueur de la chaîne ne nous importe pas, spécifier PL_na pour le deuxième argument. L'appel de fonction changerait alors ;

SvPV(get_sv("main::mesh_data", 0), PL_na)

La fonction get_sv() retourne le SV* d'une variable de paquet scalaire nommée. Elle prend une chaîne C, contenant le nom complètement qualifié de la variable, comme premier argument

```. Le deuxième argument contient des valeurs de drapeau liées

au type de données. Comme nous ne faisons que lire la variable scalaire, dans notre exemple, une valeur de 0 peut être utilisée.

Le problème avec l'exécution de code Inline depuis un script CGI est qu'Inline écrit dans une zone de construction sur votre disque chaque fois qu'il compile du code. La plupart des scripts CGI ne peuvent pas (et ne devraient pas pouvoir) créer un répertoire et y écrire.

Exécutez ensuite le script une fois à la main (depuis la ligne de commande). Cela fera précompiler le code C par Inline. De cette façon, le CGI n'aura besoin que d'un accès en lecture au répertoire de construction (pour charger la bibliothèque partagée depuis

celui-ci).

package Soldier;
use Inline C => <<'END';
/*
Allocate memory with Newx if it's
available - if it's an older perl
that doesn't have Newx then we
resort to using New.
*/
#ifndef Newx
#  define Newx(v,n,t) New(0,v,n,t)
#endif
typedef struct {
  char* name;
  char* rank;
  long  serial;
} Soldier;
SV* new(const char * classname, const char * name,
        const char * rank, long serial) {
  Soldier * soldier;
  SV      * obj;
  SV      * obj_ref;
  Newx(soldier, 1, Soldier);
  soldier->name = savepv(name);
  soldier->rank = savepv(rank);
  soldier->serial = serial;
  obj = newSViv((IV)soldier);
  obj_ref = newRV_noinc(obj);
  sv_bless(obj_ref, gv_stashpv(classname, GV_ADD));
  SvREADONLY_on(obj);
  return obj_ref;
}
char* get_name(SV* obj) {
  return ((Soldier*)SvIV(SvRV(obj)))->name;
}
char* get_rank(SV* obj) {
  return ((Soldier*)SvIV(SvRV(obj)))->rank;
}
long get_serial(SV* obj) {
  return ((Soldier*)SvIV(SvRV(obj)))->serial;
}
void DESTROY(SV* obj) {
  Soldier* soldier = (Soldier*)SvIV(SvRV(obj));
  Safefree(soldier->name);
  Safefree(soldier->rank);
  Safefree(soldier);
}
END

Damian Conway nous a donné d'innombrables façons d'implémenter la POO en Perl. Celle-ci, il n'y a peut-être pas

pensé.

La chose intéressante à propos de cet exemple est qu'il utilise Perl pour toutes les liaisons OO tout en utilisant C pour les attributs et les

méthodes.

Si vous examinez le code Perl, tout ressemble exactement à un exemple OO régulier. Il y a une méthode "new" et plusieurs méthodes d'accès. La familière 'syntaxe flèche' est utilisée pour les

invoquer.

Dans la définition de classe (la deuxième partie), l'instruction Perl "package" est utilisée pour nommer la classe d'objet ou l'espace de noms. Mais c'est là que les similitudes s'arrêtent, Inline prend le

relais.

L'idée est que nous appelons une sous-routine C appelée new() qui retourne un scalaire béni. Le scalaire contient un entier en lecture seule qui est un pointeur C vers une structure Soldier. C'est notre

objet.

La fonction new() doit allouer la mémoire pour la structure et ensuite y copier les valeurs initiales en utilisant savepv(). Cela alloue également plus de mémoire (dont nous devons garder la trace)

.

Les méthodes d'accès sont plutôt simples. Elles retournent la valeur actuelle de leur

attribut.

La dernière méthode DESTROY() est appelée automatiquement par Perl chaque fois qu'un objet sort de portée. C'est ici que nous pouvons libérer toute la mémoire utilisée par

l'objet.

C'est tout. C'est un exemple très simpliste. Il ne met pas en valeur de fonctionnalités OO avancées, mais c'est plutôt cool de voir à quel point l'implémentation peut être facile. L'appel Perl important est newSVrv() qui crée un scalaire

béni.
