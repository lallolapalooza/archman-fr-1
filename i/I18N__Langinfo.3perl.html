DESCRIPTIO

N

La fonction langinfo() interroge diverses informations de locale qui peuvent être utilisées pour localiser les sorties et les interfaces utilisateur. Elle utilise la locale sous-jacente courante, que la fonction soit appelée ou non à l'intérieur de la portée de "use locale". La fonction langinfo() requiert un argument numérique identifiant la constante de locale à interroger : si aucun argument n'est fourni, $_ est utilisé. Les constantes numériques appropriées à utiliser comme arguments sont exportables depuis I18N::

Langinfo.

L'exemple suivant importera la fonction langinfo() elle-même et trois constantes à utiliser comme arguments pour langinfo() : une constante pour le premier jour de la semaine en abrégé (la numérotation commence à dimanche = 1) et deux autres constantes pour les réponses affirmative et négative à une question binaire dans la locale

courante. 
use I18N::Langinfo qw(langinfo ABDAY_1 YESSTR NOSTR);
my ($abday_1, $yesstr, $nostr) =
    map { langinfo($_) } (ABDAY_1, YESSTR, NOSTR);
print "$abday_1? [$yesstr/$nostr]
";

"nl_langinfo"

Ce module était à l'origine simplement un wrapper pour la fonction libc "nl_langinfo", et ne fonctionnait pas sur les systèmes qui en étaient dépourvus, comme

Windows.

À partir de Perl 5.28, ce module fonctionne sur toutes les plateformes. Lorsque "nl_langinfo" n'est pas disponible, il utilise diverses méthodes pour construire ce que cette fonction, si elle était présente, renverrait. Mais il peut y avoir des anomalies potentielles. Avant Perl 5.28, les valeurs renvoyées sont peu

fiables pour les

constantes de locale "RADIXCHAR" et "THOUSEP"

.

À partir de 5.28, le changement de locale sur les compilations avec threads est pris en charge sur les systèmes qui offrent des fonctions de locale thread-safe. Cela inclut les systèmes POSIX 2008 et Windows à partir de Visual Studio 2005, et ce module fonctionnera correctement dans de telles situations. Cependant, sur les compilations avec threads sur Windows antérieures à Visual Studio 2015, récupérer les éléments "CRNCYSTR" et "THOUSEP" peut entraîner une condition de course avec un thread qui a été converti pour utiliser la locale globale. Il est assez rare qu'un thread ait

fait cela. Il serait possible de construire un contournement pour cela ; l
es correctifs sont bienvenus : voir "switch_to_global_locale" dans perlapi.
