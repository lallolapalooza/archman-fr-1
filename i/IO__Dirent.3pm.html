NOM

IO::Dirent - Accès aux structures dirent retournées par readdir

SYNTAXE

use IO::Dirent;
## Style "lecture complète"
opendir DIR, "/usr/local/foo";
my @entries = readdirent(DIR);
closedir DIR;
print $entries[0]->{name}, "\n";
print $entries[0]->{type}, "\n";
print $entries[0]->{inode}, "\n";
## Utilisation de l'énumérateur
opendir DIR, "/etc";
while( my $entry = nextdirent(DIR) ) {
  print $entry->{name} . "\n";
}
closedir DIR;

DESCRIPTION

readdirent retourne une liste de hachages. Chaque hachage contient le nom de l'entrée de répertoire, son inode pour le système de fichiers sur lequel il réside et son type (si disponible). Si le type de fichier ou l'inode ne sont pas disponibles, ils ne seront pas présents !

nextdirent retourne la prochaine entrée dirent sous forme de hachage, vous permettant d'itérer sur les entrées de répertoire une par une. Cela peut être utile dans des situations de faible mémoire ou lorsque vous avez des répertoires énormes.

IO::Dirent exporte les symboles suivants par défaut :

readdirent
nextdirent

Les balises suivantes peuvent être exportées dans votre espace de noms :

ALL

qui inclut readdirent, nextdirent et les symboles suivants :

DT_UNKNOWN
DT_FIFO
DT_CHR
DT_DIR
DT_BLK
DT_REG
DT_LNK
DT_SOCK
DT_WHT

Ces symboles peuvent être utilisés pour tester le type de fichier retourné par readdirent de la manière suivante :

for my $entry ( readdirent(DIR) ) {
    next unless $entry->{'type'} == DT_LNK;
    print $entry->{'name'} . " est un lien symbolique.\n";
}

Pour les plateformes qui n'implémentent pas le type de fichier dans leur structure dirent, readdirent retournera un hachage avec une seule clé/valeur 'name' et le nom du fichier (essentiellement la même chose que readdir). Ceci est susceptible de changer, si je peux implémenter certains des éléments à faire ci-dessous.

CAVEATS

Ceci a été écrit sur FreeBSD et OS X qui implémentent une structure dirent robuste (mais quelque peu non standard) et qui inclut une entrée de type de fichier. J'ai l'intention de rendre ce module plus portable et utile en effectuant un stat sur chaque entrée de répertoire pour trouver le type de fichier et le numéro d'inode lorsque dirent.h ne l'implémente pas autrement.

Les améliorations et les ports supplémentaires sont les bienvenus.

À FAIRE

  • Pour les plateformes qui n'implémentent pas une structure dirent avec type de fichier, effectuez un stat sur l'entrée et peuplez la structure de toute façon.
  • Faites du profilage mémoire (je ne suis pas sûr d'avoir des fuites ou non).
