DESCRIPTIO

N

Le paquet "IO::Select" implémente une approche orientée objet de l'appel de fonction "select" du système. Il permet à l'utilisateur de voir quels descripteurs d'E/S,

voir IO::Handle, sont prêts à être lus, é
crits ou ont une exception en attente.

MÉTHODE

S
add ( HANDLES
)
Ajoute la liste de descripteurs à l'objet "IO::Select". Ce sont ces valeurs qui seront retournées lorsqu'un événement se produit. "IO::Select" conserve ces valeurs dans un cache indexé par le "fileno" du descripteur ; ainsi, si plus d'un descripteur avec le même "fileno" est spécifié, seul le dernier est mis en cache.

Chaque descripteur peut être un objet "IO::Handle", un entier ou une référence de tableau dont le premier élément est un "IO::Handle"

ou un e
ntier.
remove ( HANDLES
)
Retire tous les descripteurs donnés de l'objet. Cette méthode fonctionne également par le "fileno" des descripteurs. Ainsi, il n'est pas nécessaire de passer exactement les descripteurs qui ont été ajoutés, mais seulement des descripteurs ayant un "fileno" équival
ent
exists ( HANDLE
)
Renvoie une valeur vraie (en fait, le descripteur lui-même) s'il est présent. Renvoie undef
sinon.
handl
es
Renvoie un tableau de tous les descripteurs
enregistrés.
can_read ( [ TIMEOUT ]
)
Renvoie un tableau de descripteurs prêts à être lus. "TIMEOUT" est le temps d'attente maximum avant de renvoyer une liste vide (avec $! inchangé), en secondes, éventuellement fractionnaire. Si "TIMEOUT" n'est pas donné et que des descripteurs sont enregistrés, l'appel se bloquera indéfiniment. En cas d'erreur, une liste vide est renvoyée, avec $! défini pour indiquer l'erreur. Pour distinguer un délai d'attente dépassé d'une erreur, définissez $! à zéro avant d'appeler cette méthode, et vérifiez-le après qu'une liste vide a été
renvoyée.
can_write ( [ TIMEOUT
] )
Identique à "can_read" mais vérifie les descripteurs vers lesquels on peut
écrire.
has_exception ( [ TIMEOUT
] )
Identique à "can_read" mais vérifie les descripteurs ayant une condition d'exception, par exemple des données hors bande en
attente.
count
()
Renvoie le nombre de descripteurs que l'objet vérifiera lorsque l'une des méthodes "can_" est appelée ou lorsque l'objet est passé à la méthode statique
"select".
bits
()
Renvoie la chaîne de bits utilisable comme argument pour l'appel select() du
noyau.
select ( READ, WRITE, EXCEPTION [, TIMEOUT
] )
"select" est une méthode statique, c'est-à-dire que vous l'appelez avec le nom du paquet comme "new". "READ", "WRITE" et "EXCEPTION" sont soit "undef", soit des objets "IO::Select". "TIMEOUT" est facultatif et a le même effet que pour l'appel select du noyau.

Si au moins un descripteur est prêt pour le type d'opération spécifié, le résultat sera un tableau de 3 éléments, chacun étant une référence à un tableau contenant les descripteurs prêts à être lus, écrits et ayant des exceptions respectivement. En cas de délai d'attente dépassé, une liste vide est renvoyée, avec $! inchangé. En cas d'erreur, une liste vide est renvoyée, avec $! défini pour indiquer l'erreur. Pour distinguer un délai d'attente dépassé d'une erreur, définissez $! à zéro avant d'appeler cette mé

thode, et vérifiez
-le après
qu'une liste vid
e a été renvoyée.

EXEMPL

E

Voici un court exemple montrant comment "IO::Select" pourrait être utilisé pour écrire un serveur qui communique avec plusieurs sockets tout en écoutant d'autres connexions sur un socket

d'écoute 
use IO::Select;
use IO::Socket;
my $lsn = IO::Socket::INET->new(Listen => 1, LocalPort => 8080);
my $sel = IO::Select->new( $lsn );
while(my @ready = $sel->can_read) {
    foreach my $fh (@ready) {
        if($fh == $lsn) {
            # Create a new socket
            my $new = $lsn->accept;
            $sel->add($new);
        }
        else {
            # Process socket
            # Maybe we have finished with the socket
            $sel->remove($fh);
            $fh->close;
        }
    }
}
