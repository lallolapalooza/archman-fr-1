DESCRIPTIO

N

IO::All combine tous les meilleurs modules d'entrée/sortie Perl en une seule interface orientée objet astucieuse pour simplifier considérablement vos idiomes d'entrée/sortie Perl quotidiens. Il exporte une seule fonction appelée "io", qui retourne un nouvel objet IO::All. Et cet objet peut tout faire

!

L'objet IO::All est un proxy pour IO::File, IO::Dir, IO::Socket, Tie::File, File::Spec, File::Path, File::MimeInfo et File::ReadBackwards ; ainsi que tous les modules DBM et MLDBM. Vous pouvez utiliser la plupart des méthodes trouvées dans ces classes et dans IO::Handle (qu'elles héritent). IO::All ajoute des dizaines d'autres méthodes idiomatiques utiles, y compris des fonctions de stat et de manipulation de

fichiers.

IO::All est extensible, et des modules comme IO::All::LWP et IO::All::Mailto ajoutent encore plus de fonctionnalités. De plus, chaque objet IO::All peut être lié à lui-même. Cela signifie que vous pouvez utiliser la plupart des fonctions intégrées d'entrée/sortie de Perl dessus : readline, "<>", getc, print, printf, syswrite, sysread,

close.

La magie distinctive d'IO::All est qu'il ouvrira (et fermera) automatiquement les fichiers, les répertoires, les sockets et autres choses d'entrée/sortie pour vous. Vous n'avez jamais besoin de spécifier le mode ("<", ">>", etc), puisqu'il est déterminé par le contexte d'utilisation. Cela signifie que vous pouvez remplacer ceci

: 
open STUFF, '<', './mystuff'
  or die "Can't open './mystuff' for input:\n$!";
local $/;
my $stuff = <STUFF>;
close
STUFF;

par ceci

: 
my $stuff < io '.
/mystuff';

Et c'est une bonne chose !

Il y a trois façons de créer un nouvel objet IO::All. La première est avec la fonction spéciale "io" qui appelle vraiment simplement "IO::All->new". La deuxième est en appelant "new" comme méthode de classe. La troisième est d'appeler "new" comme méthode d'instance d'objet. Dans ce dernier cas, les attributs du nouvel objet sont copiés depuis l'objet instance.

- Un handle de fichier
- Un nom de répertoire
- Un handle de répertoire
- Une référence de typeglob
- Une commande shell en pipe. ex '| ls -al'
- Un domaine/port de socket. ex 'perl.com:5678'
- '-' signifie STDIN ou STDOUT (selon l'utilisation)
- '=' signifie STDERR

NOTES OPÉRATIONNELLES

Re-bénediction
Chaque objet IO::All est re-béni en un objet IO::All::* dès que IO::All peut déterminer quel type d'objet il devrait être. Parfois, il est re-béni plus d'une fois : 
my $io = io('mydbm.db');
$io->dbm('DB_File');
$io->{foo} = 'bar';

Dans la première instruction, $io a une valeur de référence de 'IO::All::File', si "mydbm.db" existe. Dans la seconde instruction, l'objet est re-béni dans la classe 'IO::All::DBM'.

Ouverture automatique
Un objet IO::All sera automatiquement ouvert dès qu'il y aura suffisamment d'informations contextuelles pour connaître son type et le mode d'ouverture. Ceci se produit généralement lors de la première opération de lecture ou d'écriture, mais peut se produire plus tôt.
Mode automatique
Le mode d'ouverture d'un objet est déterminé de manière heuristique sauf s'il est explicitement spécifié.
Fermeture automatique
Pour l'entrée, les objets IO::All seront automatiquement fermés après la fin de fichier (EOF) ou la fin de données (EOD). Pour la sortie, l'objet se ferme lorsqu'il sort de sa portée.

Pour empêcher la fermeture des objets d'entrée à la fin de fichier, faites ceci :

$io->autoclose(0);
Ouverture et fermeture explicites
Vous pouvez toujours appeler explicitement "open" et "close" si vous avez besoin de ce niveau de contrôle. Pour vérifier si un objet est actuellement ouvert, utilisez la méthode "is_open".
Surcharge
Les opérations surchargées retournent l'objet cible, s'il en existe un.

Ceci définirait $xxx sur l'objet IO::All :

my $xxx = $contents > io('file.txt');

Alors que ceci définirait $xxx sur la chaîne de contenu :

my $xxx = $contents < io('file.txt');

STABILITÉ

L'objectif du projet IO::All est d'affiner continuellement le module pour qu'il soit aussi simple et cohérent que possible à utiliser. Par conséquent, dans les premières phases du projet, je n'hésiterai pas à rompre la compatibilité ascendante avec d'autres versions de IO::All si je peux trouver un moyen plus simple et plus clair de faire une chose particulière.

L'IO est une affaire délicate. Il y a certainement plus de travail à faire. D'un autre côté, ce module repose fortement sur des modules IO existants très stables ; il peut donc fonctionner assez bien.

Je suis sûr que vous trouverez de nombreuses « fonctionnalités » inattendues. Veuillez envoyer tous les problèmes, idées et suggestions à ingy@cpan.org.

Bugs connus et lacunes

Toutes les combinaisons possibles d'objets et de méthodes n'ont pas été testées. Il existe de nombreuses combinaisons. Tous les exemples ont été testés. Si vous trouvez un bug avec une combinaison particulière d'appels, faites-le moi savoir.

Si vous appelez une méthode qui n'a pas de sens pour un objet particulier, le résultat n'aura probablement pas de sens. Peu d'efforts sont faits pour vérifier une mauvaise utilisation.
