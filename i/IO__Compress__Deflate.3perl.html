DESCRIPTIO

N

Ce module fournit une interface Perl permettant d'écrire des données compressées dans des fichiers ou des buffers tel que défini dans la RFC

1950.

Pour lire des fichiers/buffers

RFC 1950, voir le module compagn
on IO::Uncompress::Inflate.

Interface

fonctionnelle

Une fonction de haut niveau, "deflate", est fournie pour effectuer une compression « en une passe » entre des buffers et/ou des fichiers. Pour un contrôle plus fin du processus de compression, voir la section « Interface OO »

. 
use IO::Compress::Deflate qw(deflate $DeflateError) ;
deflate $input_filename_or_reference => $output_filename_or_reference [,OPTS]
    or die "deflate failed: $DeflateError\n"
;

supérieur.

Paramètres

optionnels

Les paramètres optionnels pour la fonction en une passe "deflate" sont (pour la plupart) identiques à ceux utilisés avec l'interface OO définie dans la section « Options du constructeur ». Les exceptions sont listées

ci-dessous
"AutoClose =>
0|1"
Cette option s'applique à tout flux de données d'entrée ou de sortie passé à "deflate" qui sont des filehandles.

Si "AutoClose" est spécifié, et que la valeur est vraie, cela entraînera la fermeture de tous les filehandles d'entrée et/ou de sortie une fois que "deflate" aura

terminé.

Ce paramèt

re vaut 0 p
ar défaut.
"BinModeIn =>
0|1"
Cette option est désormais sans effet. Tous les fichiers seront lus en
binmode.
"Append =>
0|1"
Le comportement de cette
option dépend du type de f
lux de données de sortie.
  • Un buffer

    Si "Append" est activé, toutes les données compressées seront ajoutées à la fin du buffer de sortie.

    Sinon, le buffer de sortie sera vidé avant q
    • ue des données compressées ne soient écrites dedans.
  • Un nom de fichier

    Si "Append" est activé, le fichier sera ouvert en mode ajout. Sinon, le contenu du fichier,

    s'il y en a un, sera tronqué avant que des d
    • onnées compressées ne soient écrites dedans.
  • Un filehandle

    Si "Append" est activé, le filehandle sera positionné à la fin du fichier via un appel à "seek" avant que toute donnée compressée y soit écrite. Sinon, le pointeur de fichier ne sera pas déplacé.

Lorsque "Append" est spécifié et défini sur vrai, il *ajoutera* toutes les données compressées au flux de données de sortie.

Ainsi, lorsque la sortie est un fichier, une opération de recherche vers la fin sera effectuée avant d'écrire toute donnée compressée. Si la sortie est un nom de fichier, il sera ouvert en mode ajout. Si la sortie est un tampon, toutes les données compressées seront ajoutées au tampon existant.

Inversement, lorsque "Append" n'est pas spécifié, ou qu'il est présent et défini sur faux, il fonctionnera comme suit.

Lorsque la sortie est un nom de fichier, son contenu sera tronqué avant d'écrire toute donnée compressée. Si la sortie est un fichier, sa position ne sera pas modifiée. Si la sortie est un tampon, il sera vidé avant que toute donnée compressée ne soit sortie.

Par défaut à 0.

Exemples Oneshot

Voici quelques exemples qui montrent les capacités du module.

Streaming

Cet exemple très simple en ligne de commande démontre les capacités de streaming du module. Le code lit les données de STDIN, les compresse et écrit les données compressées dans STDOUT.

$ echo hello world | perl -MIO::Compress::Deflate=deflate -e 'deflate \*STDIN => \*STDOUT' >output.1950

Le nom de fichier spécial "-" peut être utilisé comme substitut pour "\*STDIN" et "\*STDOUT", donc ce qui précède peut être réécrit comme suit :

$ echo hello world | perl -MIO::Compress::Deflate=deflate -e 'deflate "-" => "-"' >output.1950

Compression d'un fichier depuis le système de fichiers

Pour lire le contenu du fichier "file1.txt" et écrire les données compressées dans le fichier "file1.txt.1950".

use strict ;
use warnings ;
use IO::Compress::Deflate qw(deflate $DeflateError) ;
my $input = "file1.txt";
deflate $input => "$input.1950"
    or die "deflate a échoué : $DeflateError\n";

Lecture depuis un fichier et écriture dans un tampon en mémoire

Pour lire à partir d'un fichier existant, $input, et écrire les données compressées dans un tampon, $buffer.

use strict ;
use warnings ;
use IO::Compress::Deflate qw(deflate $DeflateError) ;
use IO::File ;
my $input = IO::File->new( "<file1.txt" )
    or die "Impossible d'ouvrir 'file1.txt' : $!\n" ;
my $buffer ;
deflate $input => \$buffer
    or die "deflate a échoué : $DeflateError\n";

Compression de plusieurs fichiers

Pour compresser tous les fichiers du répertoire "/my/home" qui correspondent à "*.txt" et stocker les données compressées dans le même répertoire

use strict ;
use warnings ;
use IO::Compress::Deflate qw(deflate $DeflateError) ;
deflate '</my/home/*.txt>' => '<*.1950>'
    or die "deflate a échoué : $DeflateError\n";

et si vous voulez compresser chaque fichier un par un, ceci fera l'affaire :

use strict ;
use warnings ;
use IO::Compress::Deflate qw(deflate $DeflateError) ;
for my $input ( glob "/my/home/*.txt" )
{
    my $output = "$input.1950" ;
    deflate $input => $output
        or die "Erreur lors de la compression de '$input': $DeflateError\n";
}

Interface OO

Constructeur

Le format du constructeur pour "IO::Compress::Deflate" est montré ci-dessous

my $z = IO::Compress::Deflate->new( $output [,OPTS] )
    or die "IO::Compress::Deflate a échoué : $DeflateError\n";

Le constructeur prend un paramètre obligatoire, $output, défini ci-dessous, et zéro ou plusieurs "OPTS", définis dans "Options du constructeur".

Il renvoie un objet "IO::Compress::Deflate" en cas de succès et "undef" en cas d'échec. La variable $DeflateError contiendra un message d'erreur en cas d'échec.

Si vous utilisez Perl 5.005 ou une version ultérieure, l'objet, $z, renvoyé par IO::Compress::Deflate peut être utilisé exactement comme un fichier IO::File. Cela signifie que toutes les opérations normales de fichier de sortie peuvent être effectuées avec $z. Par exemple, pour écrire dans un fichier/tampon compressé, vous pouvez utiliser l'une ou l'autre de ces formes :

$z->print("hello world\n");
print $z "hello world\n";

Ci-dessous se trouve un exemple simple d'utilisation de l'interface OO pour créer un fichier de sortie "myfile.1950" et y écrire des données.

my $filename = "myfile.1950";
my $z = IO::Compress::Deflate->new($filename)
    or die "IO::Compress::Deflate a échoué : $DeflateError\n";
$z->print("abcde");
$z->close();

Voir les "Exemples" pour plus de détails.

Le paramètre obligatoire $output est utilisé pour contrôler la destination des données compressées. Ce paramètre peut prendre l'une des formes suivantes :

Un nom de fichier
Si le paramètre $output est un scalaire simple, il est supposé être un nom de fichier. Ce fichier sera ouvert en écriture et les données compressées y seront écrites.
Un fichier
Si le paramètre $output est un fichier, les données compressées y seront écrites. La chaîne '-' peut être utilisée comme alias pour la sortie standard.
Une référence scalaire
Si $output est une référence scalaire, les données compressées seront stockées dans $$output.

Si le paramètre $output est d'un autre type, "IO::Compress::Deflate"::new renverra undef.

Options du constructeur

"OPTS" est une combinaison de zéro ou plusieurs des options suivantes :

"AutoClose => 0|1"
Cette option n'est valide que lorsque le paramètre $output est un fichier. Si elle est spécifiée et que sa valeur est vraie, elle entraînera la fermeture du $output une fois que la méthode "close" aura été appelée ou que l'objet "IO::Compress::Deflate" sera détruit.

Ce paramètre est par défaut à 0.

"Append => 0|1"
Ouvre $output en mode ajout.

Le comportement de cette option dépend du type de $output.

  • Un Tampon

    Si $output est un tampon et que "Append" est activé, toutes les données compressées seront ajoutées à la fin de $output. Sinon, $output sera vidé avant que toute donnée ne y soit écrite.

  • Un Nom de Fichier

    Si $output est un nom de fichier et que "Append" est activé, le fichier sera ouvert en mode ajout. Sinon, le contenu du fichier, s'il y en a, sera tronqué avant que toute donnée compressée n'y soit écrite.

  • Un Fichier

    Si $output est un fichier, le pointeur de fichier sera positionné à la fin du fichier via un appel à "seek" avant que toute donnée compressée ne soit écrite. Sinon, le pointeur de fichier ne sera pas déplacé.

Ce paramètre est par défaut à 0.

"Merge => 0|1"
Cette option est utilisée pour compresser les données d'entrée et les ajouter à un flux de données compressées existant dans $output. Le résultat final est un seul flux de données compressées stocké dans $output.

Tenter d'utiliser cette option lorsque $output n'est pas un flux de données RFC 1950 est une erreur fatale.

Il existe un certain nombre d'autres limitations avec l'option "Merge" :

1.
Ce module doit avoir été compilé avec zlib 1.2.1 ou une version ultérieure pour fonctionner. Une erreur fatale sera levée si "Merge" est utilisé avec une version plus ancienne de zlib.
2.
Si $output est un fichier ou un fichier, il doit être navigable en position.

Ce paramètre est par défaut à 0.

-Niveau
Définit le niveau de compression utilisé par zlib. La valeur doit être soit un nombre compris entre 0 et 9 (0 signifie pas de compression et 9 est la compression maximale), soit l'une des constantes symboliques définies ci-dessous. 
Z_NO_COMPRESSION
Z_BEST_SPEED
Z_BEST_COMPRESSION
Z_DEFAULT_COMPRESSION

La valeur par défaut est Z_DEFAULT_COMPRESSION.

Notez que ces constantes ne sont pas importées par "IO::Compress::Deflate" par défaut.

use IO::Compress::Deflate qw(:strategy);
use IO::Compress::Deflate qw(:constants);
use IO::Compress::Deflate qw(:all);
-Stratégie
Définit la stratégie utilisée pour ajuster la compression. Utilisez l'une des constantes symboliques définies ci-dessous. 
Z_FILTERED
Z_HUFFMAN_ONLY
Z_RLE
Z_FIXED
Z_DEFAULT_STRATEGY

La valeur par défaut est Z_DEFAULT_STRATEGY.

"Strict => 0|1"
Ceci est une option réservée.
