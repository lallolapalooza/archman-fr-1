NOM

IO::Socket::SSL::PublicSuffix - fournir un accès à la liste de Mozilla des noms de domaine de premier niveau efficaces

SYNOPIS

   # utiliser la valeur par défaut intégrée
   use IO::Socket::SSL::PublicSuffix;
   $ps = IO::Socket::SSL::PublicSuffix->default;
   # charger à partir d'une chaîne
   $ps = IO::Socket::SSL::PublicSuffix->from_string("*.uk\n*");
   # charger à partir d'un fichier ou d'un descripteur de fichier
   $ps = IO::Socket::SSL::PublicSuffix->from_file($filename);
   $ps = IO::Socket::SSL::PublicSuffix->from_file(\*STDIN);
   # --- chaîne en entrée -> chaînes en sortie
   # $reste -> whatever.host
   # $tld  -> co.uk
   my ($rest,$tld) = $ps->public_suffix('whatever.host.co.uk');
   my $tld = $ps->public_suffix('whatever.host.co.uk');
   # $domaine_racine -> host.co.uk
   my $root_domain = $ps->public_suffix('whatever.host.co.uk', 1);
   # --- tableau en entrée -> tableau en sortie
   # $reste -> [qw(whatever host)]
   # $tld  -> [qw(co uk)]
   my ($rest,$tld) = $ps->public_suffix([qw(whatever host co uk)]);
----
   # Pour mettre à jour ce fichier avec la liste actuelle :
   perl -MIO::Socket::SSL::PublicSuffix -e 'IO::Socket::SSL::PublicSuffix::update_self_from_url()'

DESCRIPTION

Ce module utilise la liste des noms de domaine de premier niveau efficaces du projet Mozilla pour déterminer le domaine de premier niveau public d'un nom d'hôte donné.

Méthode

classe->default(%args)
Retourne un objet avec la valeur par défaut intégrée. "min_suffix" peut être spécifié dans %args pour indiquer le suffixe minimal, la valeur par défaut est 1.
classe->from_string(chaîne,%args)
Retourne un objet avec la configuration à partir d'une chaîne. Voir la méthode "default" pour %args.
classe->from_file( nom_de_fichier | descripteur_de_fichier, %args )
Retourne un objet avec la configuration à partir d'un fichier ou d'un descripteur de fichier. Voir la méthode "default" pour %args.
$self->public_suffix( $hôte|\@hôte, [ $ajout ] )
En contexte de tableau, la fonction retourne la partie non-tld et la partie tld du nom d'hôte donné, en contexte scalaire seulement la partie tld. Elle ajoute $ajout parties de la partie non-tld à la partie tld, par exemple avec "$ajout=1" elle retournera le domaine racine.

S'il n'y a pas eu de correspondance explicite avec la configuration du suffixe public, elle se rabattra sur un suffixe de longueur 1.

La fonction accepte une chaîne ou une référence de tableau (par exemple, un hôte divisé par "."). Dans le premier cas, elle retournera des chaînes, dans le second cas, des références de tableaux.

Les noms d'hôtes internationaux ou les étiquettes peuvent être en ASCII (forme IDNA commençant par "xn--") ou en unicode. Dans ce dernier cas, une bibliothèque de gestion IDNA doit être disponible. URI est préféré, mais Net::IDN:::Encode, Net::LibIDN sont toujours supportés.

($self|classe)->can_idn
Retourne vrai si le support IDN est disponible.

VOIR AUSSI

BUGS

Q: Pourquoi encore un module, nous avons déjà L<Domain::PublicSuffix> et
   L<Mozilla::PublicSuffix>.
R: Parce que les données de suffixe public changent plus souvent que ces modules,
   IO::Socket::SSL a besoin de cette liste et il est plus facile de la maintenir
   à jour ainsi.
