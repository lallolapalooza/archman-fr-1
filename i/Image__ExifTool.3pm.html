NOM

Image::ExifTool - Lire et écrire des méta-informations

SYNOPIS

use Image::ExifTool qw(:Public);
# ---- Usage procédural simple ----
# Obtenir un hash des noms/valeurs de balises de méta-informations d'une image
$info = ImageInfo('a.jpg');
# ---- Usage orienté objet ----
# Créer un nouvel objet Image::ExifTool
$exifTool = Image::ExifTool->new;
# Extraire les méta-informations d'une image
$exifTool->ExtractInfo($file, \%options);
# Obtenir la liste des balises dans l'ordre où elles ont été trouvées dans le fichier
@tagList = $exifTool->GetFoundTags('File');
# Obtenir la valeur d'une balise spécifiée
$value = $exifTool->GetValue($tag, $type);
# Obtenir une description de balise
$description = $exifTool->GetDescription($tag);
# Obtenir le nom du groupe associé à cette balise
$group = $exifTool->GetGroup($tag, $family);
# Définir une nouvelle valeur pour une balise
$exifTool->SetNewValue($tag, $newValue);
# Écrire les nouvelles méta-informations dans un fichier
$success = $exifTool->WriteInfo($srcfile, $dstfile);
# ... et de nombreuses autres méthodes utiles ...

CONFIGURATION

Les balises définies par l'utilisateur peuvent être ajoutées via le fichier de configuration ExifTool, ou en définissant le hash %Image::ExifTool::UserDefined avant d'appeler les méthodes ExifTool. Voir "ExifTool_config" dans la distribution ExifTool pour plus de détails.

Par défaut, ExifTool recherche un fichier de configuration nommé ".ExifTool_config", d'abord dans votre répertoire personnel, puis dans le répertoire du script d'application. Cependant, un répertoire différent peut être spécifié en définissant la variable d'environnement EXIFTOOL_HOME, ou un fichier différent peut être spécifié en définissant la variable "configFile" d'ExifTool avant d'utiliser Image::ExifTool. Par exemple :

BEGIN { $Image::ExifTool::configFile = '/Users/phil/myconfig.cfg' }
use Image::ExifTool;

La fonctionnalité de configuration peut également être désactivée en définissant "configFile" à une chaîne vide :

BEGIN { $Image::ExifTool::configFile = '' }
use Image::ExifTool;

EXPORTATIONS

N'exporte rien par défaut, mais "ImageInfo" et toutes les méthodes statiques peuvent être exportées avec la liste d'exportation ":Public".

METHODES

Toutes les fonctionnalités d'ExifTool sont accessibles via les méthodes de l'interface publique listées ci-dessous. Les autres méthodes et modules de Image::ExifTool ne doivent pas être accédés directement car leur interface peut changer dans les versions futures.

Aucune de ces méthodes ne devrait jamais mourir ou émettre des avertissements vers STDERR si elle est appelée avec les bons arguments (à l'exception de "SetNewValue" qui peut envoyer un message d'erreur à STDERR, mais seulement lorsqu'elle est appelée dans un contexte scalaire). Les messages d'erreur et d'avertissement qui surviennent pendant le traitement sont stockés dans les valeurs des balises Error et Warning, et sont accessibles via la méthode "GetValue" pour récupérer un seul message d'Erreur ou d'Avertissement, ou "GetInfo" pour récupérer un nombre quelconque d'entre eux.

Les méthodes ExifTool ne sont pas thread-safe.

new

Crée un nouvel objet ExifTool.

$exifTool = Image::ExifTool->new;

Un objet ExifTool peut être utilisé pour traiter plusieurs fichiers, donc la création de plusieurs objets ExifTool n'est généralement pas nécessaire.

Notez qu'ExifTool utilise AUTOLOAD pour charger les méthodes non-membres, donc toute classe utilisant Image::ExifTool comme classe de base doit définir une AUTOLOAD qui appelle Image::ExifTool::DoAutoLoad(). eg)

sub AUTOLOAD
{
    Image::ExifTool::DoAutoLoad($AUTOLOAD, @_);
}

ImageInfo

Lit un fichier image et renvoie les méta-informations. C'est la fonction en une étape pour récupérer les méta-informations d'une image. En interne, "ImageInfo" appelle "ExtractInfo" pour extraire les informations, "GetInfo" pour générer le hash d'informations, et "GetTagList" pour la liste des balises renvoyée.

# renvoie les méta-informations pour 2 balises seulement (procédural)
$info = ImageInfo($filename, $tag1, $tag2);
# renvoie les informations d'un fichier image ouvert (orienté objet)
$info = $exifTool->ImageInfo(\*FILE);
# renvoie les informations à partir de données d'image en mémoire pour les balises spécifiées
%options = (PrintConv => 0);
@tagList = qw(filename imagesize xmp:creator ex
if:* -ifd1:*); $info = ImageInfo(\$imageData, \@tagList, \%options); # extraire les informations d'une miniature intégrée $info = ImageInfo('image.jpg', 'thumbnailimage'); $thumbInfo = ImageInfo($$info{ThumbnailImage});

:
"ImageInfo" retourne une référence vers un hachage de paires clé/valeur de balises. Les clés de balises sont des identifiants -- essentiellement des noms de balises sensibles à la casse avec un numéro d'instance ajouté si plusieurs balises avec le même nom ont été extraites de l'image. Beaucoup de fonctions ExifTool nécessitent une clé de balise en argument. Utilisez "GetTagName [static]" pour obtenir le nom de balise pour une clé de balise donnée. Notez que la casse des noms de balises peut ne pas être la même que demandée. Voici un exemple simple pour imprimer les informations retournées par "ImageInfo" :

Les valeurs du hachage retourné sont généralement des scalaires simples, mais une référence de scalaire est utilisée pour indiquer des données binaires et une référence de tableau peut être utilisée pour indiquer une liste. WriteInfo

Écrit les méta-informations dans un fichier. Le fichier source spécifié est réécrit dans un fichier de destination de même type avec les nouvelles informations telles que spécifiées par les appels précédents à "SetNewValue". Les segments et/ou répertoires nécessaires sont créés dans le fichier de destination selon les besoins pour stocker les informations spécifiées. Peut être appelé plusieurs fois pour écrire les mêmes informations dans des fichiers supplémentaires sans avoir besoin d'appeler à nouveau "SetNewValue".

ExifTool met en file d'attente toutes les nouvelles valeurs qui sont assignées via des appels à "SetNewValue", puis les applique à un nombre quelconque de fichiers via un ou plusieurs appels à "WriteInfo". Ces valeurs mises en file d'attente peuvent être consultées via "GetNewValue", et sont complètement séparées des métadonnées extraites des fichiers via "ExtractInfo" ou "ImageInfo" et consultées via "GetInfo" ou "GetValue".

Pour être clair, il n'est PAS nécessaire d'appeler "ExtractInfo" ou "ImageInfo" avant "WriteInfo". "WriteInfo" ne modifie que les métadonnées spécifiées par les appels précédents à "SetNewValue".

# ajouter des informations à un fichier source, en écrivant la sortie dans un nouveau fichier
$exifTool->WriteInfo($srcfile, $dstfile);
# créer un fichier de données XMP à partir de zéro
$exifTool->WriteInfo(undef, $dstfile, 'XMP');
# écraser un fichier (vous avez bien des sauvegardes, n'est-ce pas ?)
$exifTool->WriteInfo($srcfile);
Entrées :
0) Référence à l'objet ExifTool

1) Nom du fichier source, référence de fichier, référence de scalaire, ou undef pour créer un fichier à partir de zéro. Une référence à un objet File::RandomAccess est également autorisée comme source, mais dans ce cas la destination n'est pas facultative.

2) [facultatif] Nom du fichier de destination, référence de fichier, référence de scalaire pour écrire en mémoire, ou undef pour écraser le fichier original. Peut être '-' pour écrire sur stdout.

3) [facultatif] Type du fichier de destination. Ignoré si une source est définie.

Valeur de retour :
1 si le fichier a été écrit correctement, 2 si le fichier a été écrit mais sans modifications, 0 en cas d'erreur d'écriture de fichier.

Si un code d'erreur est retourné, une balise Error est définie et GetValue('Error') peut être appelée pour obtenir la description de l'erreur. Une balise Warning peut être définie même si cette routine réussit. Appeler WriteInfo efface toutes les balises Error et Warning préexistantes.

$errorMessage = $exifTool->GetValue('Error');
$warningMessage = $exifTool->GetValue('Warning');
Notes :
Le nom du fichier source peut être indéfini pour créer un fichier à partir de zéro (actuellement seuls les fichiers XMP, MIE, ICC, VRD, DR4, EXV et EXIF peuvent être créés de cette manière -- voir "CanCreate" pour plus de détails). S'il est indéfini, le type du fichier de destination est requis sauf si le type peut être déterminé à partir de l'extension du nom du fichier de destination.

Si un nom de fichier de destination est donné, le fichier spécifié ne doit pas exister car un fichier de destination existant ne sera pas écrasé. Toutes les nouvelles valeurs pour FileName, Directory ou HardLink sont ignorées lorsqu'un nom de fichier de destination est spécifié.

Le nom du fichier de destination peut être indéfini pour écraser le fichier original (assurez-vous d'avoir des sauvegardes !). Dans ce cas, si un nom de fichier source est fourni, un fichier temporaire est créé et renommé pour remplacer le fichier source si aucune erreur ne s'est produite pendant l'écriture. Sinon, si une référence de fichier source ou une référence de scalaire est utilisée, l'image est d'abord écrite en mémoire puis copiée pour remplacer l'original s'il n'y a pas eu d'erreurs.

Sur les systèmes Mac OS, la resource fork du fichier est préservée si cette routine est appelée avec un nom de fichier source.

GetValue

Obtient la valeur d'une balise spécifiée. La valeur retournée est soit la valeur lisible par l'humain (PrintConv), la valeur convertie lisible par la machine (ValueConv), la valeur brute originale (Raw), ou la valeur rationnelle originale (Rational) pour les formats rationnels. Si le type de valeur n'est pas spécifié, la valeur PrintConv est retournée si l'option PrintConv est définie, sinon la valeur ValueConv est retournée. Les valeurs PrintConv sont les mêmes que les valeurs retournées par "ImageInfo" et "GetInfo" dans le hachage balise/valeur sauf si l'option PrintConv est désactivée.

Les balises qui représentent des listes de valeurs multiples (comme cela peut arriver avec 'Keywords' par exemple) sont traitées spécialement. En contexte scalaire, la valeur PrintConv retournée pour ces balises est soit une chaîne de valeurs ou une référence de liste (selon le paramètre de l'option ListJoin), et la valeur ValueConv est toujours une référence de liste. Mais en contexte liste, "GetValue" retourne toujours la liste elle-même.

Notez que "GetValue" nécessite une clé de balise sensible à la casse comme argument. Pour récupérer des informations de balise basées sur un nom de balise insensible à la casse (avec un spécificateur de groupe facultatif), utilisez "GetInfo" à la place.

# Exemple PrintConv
my $val = $exifTool->GetValue($tag);
if (ref $val eq 'SCALAR') {
    print "$tag = (valeur non imprimable)\n";
} else {
    print "$tag = $val\n";
}
# Exemples ValueConv
my $val = $exifTool->GetValue($tag, 'ValueConv');
if (ref $val eq 'ARRAY') {
    print "$tag est une liste de valeurs\n";
} elsif (ref $val eq 'SCALAR') {
    print "$tag représente des données binaires\n";
} else {
    print "$tag est un simple scalaire\n";
}
my @keywords = $exifTool->GetValue('Keywords', 'ValueConv');
Entrées :
0) Référence à l'objet ExifTool

1) Clé de balise, ou nom de balise sensible à la casse avec un ou plusieurs préfixes de groupe facultatifs

2) [facultatif] Type de valeur : 'PrintConv', 'ValueConv', 'Both', 'Raw', 'Bin' ou 'Rational'

Le type de valeur par défaut est 'PrintConv' si l'option PrintConv est définie, sinon le défaut est 'ValueConv'. Un type de valeur 'Both' retourne les valeurs ValueConv et PrintConv sous forme de liste. 'Raw' retourne la valeur brute décodée de la balise. 'Bin' retourne les données binaires originales pour les balises EXIF si l'option "SaveBin" était définie. 'Rational' retourne la valeur rationnelle brute sous forme de fraction de chaîne pour les types rationnels, ou undef pour les autres types.

Valeurs de retour :
La valeur de la balise spécifiée. Si la balise représente une liste de valeurs multiples et que l'option ListJoin est activée, alors PrintConv retourne une chaîne de valeurs, sinon une référence à la liste est retournée en contexte scalaire. La liste elle-même est retournée en contexte liste. (Sauf si des valeurs 'Both' sont demandées, auquel cas deux références de liste sont retournées, quel que soit le contexte.) Les valeurs peuvent aussi être des références de scalaire vers des données binaires, ou des références de hachage si l'option "Struct" est définie.

Note : Il est possible que "GetValue" retourne une valeur ValueConv ou PrintConv indéfinie (ou une liste vide en contexte liste) même si la balise existe, car il est possible que ces conversions produisent des valeurs indéfinies. Et la valeur Rational sera indéfinie pour toute balise non rationnelle. La valeur Raw devrait toujours exister si la balise existe.

SetNewValue

Définit la nouvelle valeur d'une balise. La routine peut être appelée plusieurs fois pour définir les valeurs de nombreuses balises avant d'utiliser "WriteInfo" pour écrire les nouvelles valeurs dans une image. Ces valeurs restent en attente d'écriture vers les fichiers suivants jusqu'à ce que "SetNewValue" soit appelé sans arguments pour réinitialiser les valeurs en

attente.

Pour les balises de type liste (comme Keywords), appelez soit répétitivement avec le même nom de balise pour chaque valeur, soit appelez avec une référence à la liste des

valeurs. 
# définir une nouvelle valeur pour une balise (les erreurs vont vers STDERR)
$succès = $exifTool->SetNewValue($balise, $valeur);
# définir une nouvelle valeur et capturer tout message d'erreur
($succès, $errStr) = $exifTool->SetNewValue($balise, $valeur);
# supprimer les informations pour la balise spécifiée si elle existe dans l'image
# (réinitialise aussi les options AddValue et DelValue pour cette balise)
$exifTool->SetNewValue($balise);
# réinitialiser toutes les valeurs des appels précédents à SetNewValue()
$exifTool->SetNewValue();
# supprimer un mot-clé spécifique
$exifTool->SetNewValue('Keywords', $mot, DelValue => 1);
# définir des mots-clés (une balise de type liste) avec deux nouvelles valeurs
$exifTool->SetNewValue(Keywords => 'mot1');
$exifTool->SetNewValue(Keywords => 'mot2');
# équivalent, mais définir les deux en un seul appel avec une référence de tableau
$exifTool->SetNewValue(Keywords => ['mot1','mot2']);
# ajouter un mot-clé sans remplacer les mots-clés existants dans le fichier
$exifTool->SetNewValue(Keywords => $mot, AddValue => 1);
# ajouter conditionnellement une balise si elle n'existait pas auparavant,
# ou la remplacer si elle avait une valeur spécifiée ("ancienne valeur")
$exifTool->SetNewValue(Description => '', DelValue => 1);
$exifTool->SetNewValue(Description => 'ancienne valeur', DelValue => 1);
$exifTool->SetNewValue(Description => 'nouvelle valeur');
# définir une balise dans un groupe spécifique
$exifTool->SetNewValue(Headline => $val, Group => 'XMP');
$exifTool->SetNewValue('XMP:Headline' => $val);  # (équivalent)
# décaler la date/heure originale de 2,5 heures en arrière
$exifTool->SetNewValue(DateTimeOriginal => '2:30', Shift => -1);
# écrire une balise seulement si elle avait une valeur spécifique
# (l'ordre des appels suivants n'est pas significatif)
$exifTool->SetNewValue(Title => $ancVal, DelValue => 1);
$exifTool->SetNewValue(Title => $nouvVal);
# écrire une balise par valeur numérique
$exifTool->SetNewValue(Orientation => 6, Type => 'ValueConv');
$exifTool->SetNewValue('Orientation#' => 6);  # (équivalent)
# supprimer tout sauf les balises EXIF
$exifTool->SetNewValue('*');  # tout supprimer...
$exifTool->SetNewValue('EXIF:*', undef, Replace => 2); # ...sauf EXIF
# écrire des informations structurées sous forme de référence HASH
$exifTool->SetNewValue('XMP:Flash' => {
    mode   => 'on',
    fired  => 'true',
    return => 'not'
});
# écrire des informations structurées sous forme de chaîne sérialisée
$exifTool->SetNewValue('XMP:Flash'=>'{mode=on,fired=true,return=not}')

ENCODAGES DE

CARACTÈRES

Certains formats de méta-informations permettent des jeux de caractères codés autres que l'ASCII simple. Lors de la lecture, la plupart des encodages connus sont convertis vers le jeu de caractères externe selon l'option "Charset", ou vers UTF-8 par défaut. Lors de l'écriture, les conversions inverses sont effectuées. Alternativement, les caractères spéciaux peuvent être convertis vers/depuis les entités de caractères HTML avec l'option HTML

"Escape".

Une distinction est faite entre le jeu de caractères externe visible via l'API ExifTool, et le caractère interne utilisé pour stocker le texte dans les métadonnées d'un fichier. Ces jeux de caractères peuvent être spécifiés séparément comme suit

:
Jeux de caractères externes
:
L'encodage pour les valeurs de balises passées aux/depuis les fonctions de l'API ExifTool est défini via l'option "Charset", qui est 'UTF8' par défaut.

L'encodage des noms de fichiers est spécifié via l' option "CharsetFileName". Par défaut, "CharsetFileName" n'est pas défini, et les noms de fichiers passés à ExifTool sont utilisés directement dans les appels aux routines d'entrée/sortie du système (qui s'attendent à des chaînes UTF-8 sur Mac/Linux, mais utilisent par défaut la page de code du système sur Windows). Dans ce mode sur Windows, un avertissement est émis si un nom de fichier contient des caractères spéciaux, mais cet avertissement peut être évité en définissant "CharsetFileName" à une chaîne vide. Définir "CharsetFileName" à toute autre valeur provoque la conversion des noms de fichier depuis l'encodage spécifié vers un encodage approprié pour le système. Sur Windows, cela a également pour effet d'activer la prise en charge des noms de fichiers Unicode via les routines d'entrée/sortie Windows à caractères larges si Win32API::File est

disponible.

Notez que le fait de définir l'option "WindowsWideFile" ou "WindowsLongPath" fait que "Char

setFileName" prend par défaut la valeur 'UTF8' sur Windows si elle n'est pas définie, et
"WindowsLongPath" est défini par défaut dans ExifTool 13.07 et versions ultérieures.
Jeux de caractères internes
:
Les encodages utilisés pour stocker les chaînes dans les différents formats de métadonnées. Ces
encodages peuvent être modifiés pour certains types de métadonnées via les options "CharsetEXI
F", "CharsetID3", "CharsetIPTC", "CharsetPhotoshop", "CharsetQuickTime" et "CharsetRIFF".

Les valeurs sont renvoyées sous forme de chaînes d'octets de caractères encodés. Les caractères larges de Perl ne sont pas utilisés. Par défaut, la plupart des chaînes renvoyées sont encodées en UTF-8. Pour celles-ci, Encode::decode_utf8() peut être utilisé pour convertir en une séquence de caractères logiques Perl. Notez que certains paramètres de la variable d'environnement PERL_UNICODE peuvent être incompatibles avec le traitement des caractères

d'ExifTool.

Des détails plus spécifiques sont donnés ci-dessous sur la manière dont le codage des caractères est géré pour les informations EXIF, IPTC, XMP, PNG, ID3, PDF, Photoshop, QuickTime, AIFF, MIE et Vorbis

:

EXI

F

La plupart des informations textuelles dans EXIF sont stockées au format ASCII (appelé "string" dans la documentation des noms de balises ExifTool). Par défaut, ExifTool ne convertit pas ces chaînes. Cependant, il n'est pas rare que des applications écrivent de l'UTF-8 ou d'autres encodages là où de l'ASCII est attendu. Pour gérer cela, ExifTool permet de spécifier l'encodage interne des chaînes EXIF avec "CharsetEXIF", ce qui provoque la conversion des valeurs de chaînes EXIF depuis le jeu de caractères spécifié lors de la lecture, et leur stockage avec ce jeu de caractères lors de l'écriture. (Le MWG recommande d'utiliser l'encodage UTF-8 pour les chaînes EXIF, et conformément à cela, le module MWG définit l'encodage interne par défaut des chaînes EXIF à UTF-8, mais notez que cela n'aura aucun effet à moins que l'encodage externe ne soit également défini à autre chose que la valeur par défaut UTF-8.

)

Quelques balises EXIF (UserComment, GPSProcessingMethod et GPSAreaInformation) prennent en charge un encodage de texte interne désigné, avec des valeurs stockées en ASCII, Unicode (UCS-2) ou JIS. Lors de la lecture de ces balises, ExifTool convertit Unicode et JIS vers le jeu de caractères externe spécifié par l' option "Charset", ou en UTF-8 par défaut. Le texte ASCII n'est pas converti. Lors de l'écriture, le texte est stocké en ASCII à moins que la chaîne ne contienne des caractères spéciaux, auquel cas il est converti depuis le jeu de caractères externe (UTF-8 par défaut) et stocké en Unicode. ExifTool écrit Unicode dans l'ordre d'octets EXIF natif par défaut, mais l'ordre des octets peut être spécifié en définissant la balise ExifUnicodeByteOrder (voir la documentation des balises supplémentaires)

.

Les balises "XP" EXIF (XPTitle, XPComment, etc) sont toujour

s stockées en Unicode little-endian (UCS-2), et sont lue
s et écrites en utilisant le jeu de caractères spécifié.

IPT

C

La valeur de la balise IPTC:CodedCharacterSet détermine comment les valeurs de chaîne IPTC internes sont interprétées. Si CodedCharacterSet existe et a une valeur de 'UTF8' (ou 'ESC % G'), alors les valeurs de chaîne sont supposées être stockées en UTF-8, sinon le codage Windows Latin1 (cp1252, 'Latin') est supposé par défaut, mais cela peut être changé avec l'option "CharsetIPTC". Lors de la lecture, ces chaînes sont converties vers le jeu de caractères spécifié par l'option "Charset". Lors de l'écriture, les conversions inverses sont effectuées. Aucune conversion n'est effectuée si les jeux de caractères interne (IPTC) et externe (ExifTool) sont identiques. Notez que le décalage de jeu de caractères ISO 2022 n'est pas pris en charge. À la place, un avertissement est émis et la chaîne n'est pas convertie si un code de décalage ISO 2022 est rencontré. Voir http://www.iptc.org/IIM/ pour la spécification IPTC

officielle.

ExifTool peut être utilisé pour convertir les valeurs IPTC vers un encodage interne différent. Pour ce faire, toutes les balises IPTC doivent être réécrites avec la valeur souhaitée de CodedCharacterSet. Par exemple, la commande suivante change l'encodage IPTC interne en UTF-8 (depuis Windows Latin1 sauf si CodedCharacterSet était déjà 'UTF8')

: 
exiftool -tagsfromfile @ -iptc:all -codedcharacterset=utf8 a.
jpg

ou de Windows Latin2 (cp1250) à UTF-8

: 
exiftool -tagsfromfile @ -iptc:all -codedcharacterset=utf8 \
-charset iptc=latin2 a.
jpg

et cette commande le change à nouveau de UTF-8 à Windows Latin1 (cp1252)

: 
exiftool -tagsfromfile @ -iptc:all -codedcharacterset= a.
jpg

ou à Windows Latin2

: 
exiftool -tagsfromfile @ -iptc:all -codedcharacterset= \
-charset iptc=latin2 a.
jpg

À moins que CodedCharacterSet ne soit 'UTF8', les applications n'ont pas de moyen fiable de déterminer l'encodage de caractères IPTC. Pour cette raison, il est recommandé que CodedCharacterSet soit défini sur 'UTF8' lors de la création de nouveaux

IPTC.

(Note : Ici, "IPTC" fait référence au format IPTC IIM p

lus ancien. Les spécifications IPTC Core et Extens
ion plus récentes utilisent en fait le format XMP.)
