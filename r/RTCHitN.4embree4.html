RTCHitN(3) Embree Ray Tracing Kernels 4 RTCHitN(3)

NOM

RTCHitN - paquet de collision de taille runtime

SYNTAXE

#include <embree4/rtcore.h>
struct HitN;
float& RTCHitN_Ng_x(RTCHitN* hit, unsigned int N, unsigned int i);
float& RTCHitN_Ng_y(RTCHitN* hit, unsigned int N, unsigned int i);
float& RTCHitN_Ng_z(RTCHitN* hit, unsigned int N, unsigned int i);
float& RTCHitN_u(RTCHitN* hit, unsigned int N, unsigned int i);
float& RTCHitN_v(RTCHitN* hit, unsigned int N, unsigned int i);
unsigned& RTCHitN_primID(RTCHitN* hit, unsigned int N, unsigned int i);
unsigned& RTCHitN_geomID(RTCHitN* hit, unsigned int N, unsigned int i);
unsigned& RTCHitN_instID(RTCHitN* hit, unsigned int N, unsigned int i, unsigned int level);

DESCRIPTION

Lorsque la taille du paquet de collision n'est pas connue au moment de la compilation (par exemple, lorsque Embree retourne un paquet de collision dans la fonction de rappel RTCFilterFuncN), Embree utilise le type RTCHitN pour les paquets de collision. Ces paquets de collision ne peuvent avoir que des tailles de 1, 4, 8 ou 16. Aucune autre taille de paquet ne sera utilisée.

Vous pouvez soit implémenter différents chemins de code spécifiques pour chacune de ces tailles de paquet possibles et caster le paquet de collision vers le type de paquet de collision approprié, soit implémenter un chemin de code général qui utilise les fonctions d'aide RTCHitN_XXX pour accéder aux composants du paquet de collision.

Ces fonctions d'aide prennent un pointeur vers le paquet de collision (argument hit), la taille du paquet (argument N), et retournent une référence à un composant (par exemple, le composant x de Ng) du i-ème coup du paquet (argument i).
