NAME

REVOKE - révoquer les privilèges d'accès

SYNOPSIS

REVOKE [ GRANT OPTION FOR ]
    { { SELECT | INSERT | UPDATE | DELETE | TRUNCATE | REFERENCES | TRIGGER | MAINTAIN }
    [, ...] | ALL [ PRIVILEGES ] }
    ON { [ TABLE ] table_name [, ...]
         | ALL TABLES IN SCHEMA schema_name [, ...] }
    FROM role_specification [, ...]
    [ GRANTED BY role_specification ]
    [ CASCADE | RESTRICT ]
REVOKE [ GRANT OPTION FOR ]
    { { SELECT | INSERT | UPDATE | REFERENCES } ( column_name [, ...] )
    [, ...] | ALL [ PRIVILEGES ] ( column_name [, ...] ) }
    ON [ TABLE ] table_name [, ...]
    FROM role_specification [, ...]
    [ GRANTED BY role_specification ]
    [ CASCADE | RESTRICT ]
REVOKE [ GRANT OPTION FOR ]
    { { USAGE | UPDATE } [, ...] | ALL [ PRIVILEGES ] }
    ON { SEQUENCE sequence_name [, ...]
         | ALL SEQUENCES IN SCHEMA schema_name [, ...] }
    FROM role_specification [, ...]
    [ GRANTED BY role_specification ]
    [ CASCADE | RESTRICT ]
REVOKE [ GRANT OPTION FOR ]
    { CREATE | CONNECT | TEMPORARY | TEMP } [, ...] | ALL [ PRIVILEGES ] }
    ON DATABASE database_name [, ...]
    FROM role_specification [, ...]
    [ GRANTED BY role_specification ]
    [ CASCADE | RESTRICT ]
REVOKE [ GRANT OPTION FOR ]
    { USAGE | ALL [ PRIVILEGES ] }
    ON DOMAIN domain_name [, ...]
    FROM role_specification [, ...]
    [ GRANTED BY role_specification ]
    [ CASCADE | RESTRICT ]
REVOKE [ GRANT OPTION FOR ]
    { USAGE | ALL [ PRIVILEGES ] }
    ON FOREIGN DATA WRAPPER fdw_name [, ...]
    FROM role_specification [, ...]
    [ GRANTED BY role_specification ]
    [ CASCADE | RESTRICT ]
REVOKE [ GRANT OPTION FOR ]
    { USAGE | ALL [ PRIVILEGES ] }
    ON FOREIGN SERVER server_name [, ...]
    FROM role_specification [, ...]
    [ GRANTED BY role_specification ]
    [ CASCADE | RESTRICT ]
REVOKE [ GRANT OPTION FOR ]
    { EXECUTE | ALL [ PRIVILEGES ] }
    ON { { FUNCTION | PROCEDURE | ROUTINE } function_name [ ( [ [ argmode ] [ arg_name ] arg_type [, ...] ] ) ] [, ...]
         | ALL { FUNCTIONS | PROCEDURES | ROUTINES } IN SCHEMA schema_name [, ...] }
    FROM role_specification [, ...]
    [ GRANTED BY role_specification ]
    [ CASCADE | RESTRICT ]
REVOKE [ GRANT OPTION FOR ]
    { USAGE | ALL [ PRIVILEGES ] }
    ON LANGUAGE lang_name [, ...]
    FROM role_specification [, ...]
    [ GRANTED BY role_specification ]
    [ CASCADE | RESTRICT ]
REVOKE [ GRANT OPTION FOR ]
    { { SELECT | UPDATE } [, ...] | ALL [ PRIVILEGES ] }
    ON LARGE OBJECT loid [, ...]
    FROM role_specification [, ...]
    [ GRANTED BY role_specification ]
    [ CASCADE | RESTRICT ]
REVOKE [ GRANT OPTION FOR ]
    { { SET | ALTER SYSTEM } [, ...] | ALL [ PRIVILEGES ] }
    ON PARAMETER configuration_parameter [, ...]
    FROM role_specification [, ...]
    [ GRANTED BY role_specification ]
    [ CASCADE | RESTRICT ]
REVOKE [ GRANT OPTION FOR ]
    { CREATE | USAGE } [, ...] | ALL [ PRIVILEGES ] }
    ON SCHEMA schema_name [, ...]
    FROM role_specification [, ...]
    [ GRANTED BY role_specification ]
    [ CASCADE | RESTRICT ]
REVOKE [ GRANT OPTION FOR ]
    { CREATE | ALL [ PRIVILEGES ] }
    ON TABLESPACE tablespace_name [, ...]
    FROM role_specification [, ...]
    [ GRANTED BY role_specification ]
    [ CASCADE | RESTRICT ]
REVOKE [ GRANT OPTION FOR ]
    { USAGE | ALL [ PRIVILEGES ] }
    ON TYPE type_name [, ...]
    FROM role_specification [, ...]
    [ GRANTED BY role_specification ]
    [ CASCADE | RESTRICT ]
REVOKE [ { ADMIN | INHERIT | SET } OPTION FOR ]
    role_name [, ...] FROM role_specification [, ...]
    [ GRANTED BY role_specification ]
    [ CASCADE | RESTRICT ]
where role_specification can be:
    [ GROUP ] role_name
  | PUBLIC
  | CURRENT_ROLE
  | CURRENT_USER
  | SESSION_USER

DESCRIPTION

La commande REVOKE révoque des privilèges précédemment accordés à un ou plusieurs rôles. Le terme PUBLIC fait référence au groupe implicite de tous les rôles.

Voir la description de la commande GRANT pour la signification des types de privilèges.

Note : Tout rôle aura la somme des privilèges qui lui sont directement accordés, les privilèges accordés à tout rôle dont il est membre, et les privilèges accordés à PUBLIC. Par conséquent, révoquer SELECT de PUBLIC ne signifie pas nécessairement que tous les rôles perdent SELECT sur l'objet : ceux qui ont le privilège accordé directement ou via un autre rôle continueront à l'avoir. De même, révoquer SELECT d'un utilisateur peut ne pas empêcher cet utilisateur d'utiliser SELECT si PUBLIC ou un autre rôle d'appartenance a les droits SELECT.

Si GRANT OPTION FOR est spécifié, seule l'option de prêt du privilège est révoquée, pas le privilège lui-même. Sinon, le privilège et l'option de prêt sont révoqués.

Si un utilisateur a un privilège avec une option de prêt et qu'il l'a accordé à d'autres utilisateurs, les privilèges que ces autres utilisateurs ont sont appelés privilèges dépendants. Si le privilège ou l'option de prêt détenu par le premier utilisateur est révoqué et que des privilèges dépendants existent, ceux-ci sont également révoqués si CASCADE est spécifié ; sinon, l'action de révocation échouera. Cette révocation récursive n'affecte que les privilèges qui ont été accordés via une chaîne d'utilisateurs qui peut être suivie jusqu'à l'utilisateur qui est le sujet de ce REVOKE. Par conséquent, les utilisateurs affectés peuvent effectivement conserver le privilège même s'il a été accordé via d'autres utilisateurs.

Lorsqu'on révoque des privilèges sur une table, les privilèges correspondants sur les colonnes (s'ils existent) sont automatiquement révoqués sur chaque colonne de la table, tout comme les privilèges sur les colonnes. D'un autre côté, si un rôle s'est vu accorder des privilèges sur une table, révoquer les mêmes privilèges sur des colonnes individuelles n'a aucun effet.

Lorsqu'on révoque l'appartenance à un rôle, GRANT OPTION est appelé ADMIN OPTION, mais le comportement est similaire. Bien que dans les versions antérieures à PostgreSQL 16, les privilèges dépendants n'étaient pas enregistrés pour les appartenances de rôle accordées, donc CASCADE n'affectait pas l'appartenance à un rôle. Ce n'est plus le cas. De plus, cette forme de commande n'autorise pas le terme GROUP dans role_specification.

Tout comme on peut retirer ADMIN OPTION d'un octroi existant, il est également possible de révoquer INHERIT OPTION ou SET OPTION. Ceci est équivalent à régler la valeur de l'option correspondante à FALSE.

NOTES

Un utilisateur ne peut révoquer que les privilèges qui lui ont été directement accordés. Si, par exemple, l'utilisateur A a accordé un privilège avec option de prêt à l'utilisateur B, et que l'utilisateur B l'a accordé à C, alors l'utilisateur A ne peut pas révoquer directement le privilège de C. Au lieu de cela, l'utilisateur A peut révoquer l'option de prêt de l'utilisateur B et utiliser l'option CASCADE pour révoquer le privilège de C. Pour un autre exemple, si A et B ont accordé le même privilège à C, A peut révoquer sa propre option de prêt, mais pas celle de B, donc C aura toujours le privilège.

Lorsqu'un utilisateur tente de révoquer des privilèges sur un objet et qu'il n'a pas de droits sur cet objet, la commande échouera immédiatement. Même si certains privilèges peuvent être disponibles, la commande sera exécutée, mais ne révoquera que les privilèges pour lesquels l'utilisateur détient des options de prêt. Les formes REVOKE ALL PRIVILEGES émettront un message d'avertissement si aucune option de prêt n'est détenue, tandis que les autres formes émettront un message d'avertissement si aucune option de prêt n'est détenue pour un privilège nommé spécifiquement dans la commande.

Si un superutilisateur choisit d'émettre une commande GRANT ou REVOKE, la commande s'exécutera comme si elle avait été émise par le propriétaire de l'objet affecté. (Mais les rôles n'ont pas de propriétaires, donc dans le cas d'un GRANT d'appartenance à un rôle, la commande s'exécutera comme si elle avait été émise par le superutilisateur bootstrap.) Puisque tous les privilèges proviennent finalement du propriétaire de l'objet (éventuellement indirectement via des chaînes d'options de prêt), il est possible pour un superutilisateur de révoquer tous les privilèges, mais cela peut nécessiter l'utilisation de CASCADE comme mentionné.

REVOKE peut également être exécuté par un rôle qui n'est pas le propriétaire de l'objet affecté, mais qui est membre du rôle propriétaire de l'objet ou qui est membre d'un rôle qui détient des privilèges avec GRANT OPTION sur l'objet. Dans ce cas, la commande s'exécutera comme si elle avait été émise par le rôle qui possède réellement l'objet ou qui détient les privilèges avec GRANT OPTION. Par exemple, si la table t1 appartient au rôle g1, dont le rôle u1 est membre, alors u1 peut révoquer les privilèges de t1.

NAME

REVOKE - supprimer des privilèges d'accès

SYNOPSIS

REVOKE [ GRANT OPTION FOR ] { { SELECT | INSERT | UPDATE | DELETE | TRUNCATE | REFERENCES | TRIGGER } [,...] | ALL [ PRIVILEGES ] }
    ON [ TABLE ] objet [, ...]
    FROM { groupe | PUBLIC } [, ...]
    [ CASCADE | RESTRICT ]

REVOKE
    { { CREATE | USAGE } [,...] | ALL [ PRIVILEGES ] }
    ON SCHEMA schema [, ...]
    FROM { groupe | PUBLIC } [, ...]
    [ CASCADE | RESTRICT ]

REVOKE
    { CREATE | ALL [ PRIVILEGES ] }
    ON DATABASE database [, ...]
    FROM { groupe | PUBLIC } [, ...]
    [ CASCADE | RESTRICT ]

REVOKE
    { USAGE | ALL [ PRIVILEGES ] }
    ON LANGUAGE langage [, ...]
    FROM { groupe | PUBLIC } [, ...]
    [ CASCADE | RESTRICT ]

REVOKE
    { TYPE | ALL [ PRIVILEGES ] }
    ON TYPE type [, ...]
    FROM { groupe | PUBLIC } [, ...]
    [ CASCADE | RESTRICT ]

REVOKE
    [ ADMIN ] { rôle | ALL }
    FROM membre_de_rôle [, ...]
    [ CASCADE | RESTRICT ]

DESCRIPTION

REVOKE supprime un ou plusieurs privilèges d'accès définis à partir d'un ou plusieurs rôles. Le rôle qui exécute la commande est celui qui accorde le privilège.

La syntaxe pour révoquer les privilèges sur les tables, schémas, bases de données, langages et types est la même que pour GRANT. Voir la page de manuel GRANT pour les descriptions des types de privilèges et des objets.

Il est également possible de révoquer l'adhésion à un rôle. Cela enlève l'adhésion au rôle spécifié pour les membres spécifiés. L'option ADMIN peut être utilisée pour révoquer le privilège d'accorder ou de révoquer l'adhésion à un rôle.

Si GRANT OPTION FOR est spécifié, seul le privilège d'accorder le privilège est révoqué, pas le privilège lui-même.

Si ALL PRIVILEGES est spécifié, cela signifie tous les privilèges applicables à l'objet en question.

Si CASCADE est spécifié, cela signifie que les privilèges qui ont été accordés par le rôle qui reçoit la révocation sont également révoqués. Si RESTRICT est spécifié, cela signifie que la révocation échouera si d'autres rôles ont hérité du privilège via ce rôle.

Si vous essayez de révoquer un privilège qui n'a pas été accordé, vous obtiendrez une erreur.

L'action de REVOKE est le contraire de GRANT.

NOTES

Si vous essayez de révoquer un privilège qui n'a pas été accordé, vous obtiendrez une erreur. Si vous souhaitez plutôt ignorer l'absence du privilège, utilisez GRANT ... WITH GRANT OPTION.

Si un rôle possède des privilèges indirectement via plusieurs chemins d'adhésion à des rôles, il est indéterminé quel rôle contenant sera utilisé pour exécuter la commande. Dans de tels cas, il est recommandé d'utiliser SET ROLE pour devenir le rôle spécifique que vous voulez utiliser pour effectuer la révocation. Ne pas le faire pourrait entraîner la révocation de privilèges autres que ceux que vous aviez l'intention de révoquer, ou ne rien révoquer du tout.

Voir la section 5.8 pour plus d'informations sur les types de privilèges spécifiques, ainsi que sur la manière d'inspecter les privilèges des objets.

EXAMPLES

Révoquer le privilège d'insertion pour le rôle public sur la table films :

REVOKE INSERT ON films FROM PUBLIC;

Révoquer tous les privilèges de l'utilisateur manuel sur la vue kinds :

REVOKE ALL PRIVILEGES ON kinds FROM manuel;

Notez que cela signifie en fait « révoquer tous les privilèges que j'ai accordés ».

Révoquer l'adhésion au rôle admins de l'utilisateur joe :

REVOKE admins FROM joe;

COMPATIBILITY

Les notes de compatibilité de la commande GRANT s'appliquent analogiquement à REVOKE. Le mot-clé RESTRICT ou CASCADE est requis conformément à la norme, mais PostgreSQL suppose RESTRICT par défaut.
