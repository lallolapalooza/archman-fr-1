NOM

Regexp::Common - Fournir des expressions régulières couramment demandées

SYNOPIS

# UTILISATION STANDARD 
use Regexp::Common;
while (<>) {
    /$RE{num}{real}/               and print q{un nombre};
    /$RE{quoted}/                  and print q{une chaîne entre guillemets ['"`]};
   m[$RE{delimited}{-delim=>'/'}]  and print q{une séquence /.../};
    /$RE{balanced}{-parens=>'()'}/ and print q{parenthèses équilibrées};
    /$RE{profanity}/               and print q{un mot #*@%-é};
}
# INTERFACE BASÉE SUR LES SOUS-ROUTINES
use Regexp::Common 'RE_ALL';
while (<>) {
    $_ =~ RE_num_real()              and print q{un nombre};
    $_ =~ RE_quoted()                and print q{une chaîne entre guillemets ['"`]};
    $_ =~ RE_delimited(-delim=>'/')  and print q{une séquence /.../};
    $_ =~ RE_balanced(-parens=>'()'} and print q{parenthèses équilibrées};
    $_ =~ RE_profanity()             and print q{un mot #*@%-é};
}
# MATCHING EN LIGNE...
if ( $RE{num}{int}->matches($text) ) {...}
# ...ET SUBSTITUTION
my $cropped = $RE{ws}{crop}->subs($uncropped);
# MOTIFS PERSONNALISÉS
use Regexp::Common 'pattern';
pattern name   => ['name', 'mine'],
        create => '(?i:J[.]?\s+A[.]?\s+Perl-Hacker)',
        ;
my $name_matcher = $RE{name}{mine};
pattern name    => [ 'lineof', '-char=_' ],
        create  => sub {
                       my $flags = shift;
                       my $char = quotemeta $flags->{-char};
                       return '(?:^$char+$)';
                   },
        match   => sub {
                       my ($self, $str) = @_;
                       return $str !~ /[^$self->{flags}{-char}]/;
                   },
        subs   => sub {
                       my ($self, $str, $replacement) = @_;
                       $_[1] =~ s/^$self->{flags}{-char}+$//g;
                  },
        ;
my $asterisks = $RE{lineof}{-char=>'*'};
# CHOISIR LES MOTIFS À CHARGER.
use Regexp::Common qw /comment number/;  # Motifs de commentaire et de nombre.
use Regexp::Common qw /no_defaults/;     # Ne charger aucun motif.
use Regexp::Common qw /!delimited/;      # Tous, sauf les motifs délimités.

DESCRIPTION

Par défaut, ce module exporte une seule table de hachage (%RE) qui stocke ou génère les expressions régulières couramment nécessaires (voir "Liste des motifs disponibles").

Il existe une interface alternative basée sur les sous-routines, décrite dans "Interface basée sur les sous-routines".

Syntaxe générale pour demander des motifs

Pour accéder à un motif particulier, %RE est traitée comme une table de hachage hiérarchique de tables de hachage (de tables de hachage...), chaque clé successive étant un identifiant. Par exemple, pour accéder au motif qui correspond aux nombres réels, vous spécifiez :

$RE{num}{real}

et pour accéder au motif qui correspond aux entiers :

$RE{num}{int}

Des couches plus profondes de la table de hachage sont utilisées pour spécifier des indicateurs : des arguments qui modifient le motif résultant d'une manière ou d'une autre. Les clés utilisées pour accéder à ces couches sont préfixées par un signe moins et peuvent avoir une valeur ; si une valeur est donnée, elle est utilisée via une clé multidimensionnelle. Par exemple, pour accéder au motif qui correspond aux nombres réels en base 2 avec des virgules incorporées séparant des groupes de trois chiffres (par exemple, 10,101,110.110101101) :

$RE{num}{real}{-base => 2}{-sep => ','}{-group => 3}

Grâce à la magie de Perl, ces couches d'indicateurs peuvent être spécifiées dans n'importe quel ordre (et même intercalées parmi les clés identifiantes), vous pourriez donc obtenir le même motif avec :

$RE{num}{real}{-sep => ','}{-group => 3}{-base => 2}

ou :

$RE{num}{-base => 2}{real}{-group => 3}{-sep => ','}

ou même :

$RE{-base => 2}{-group => 3}{-sep => ','}{num}{real}

etc.

Notez cependant que l'ordre relatif des clés identifiantes *est* significatif. C'est-à-dire :

$RE{list}{set}

ne serait pas identique à :

$RE{set}{list}

Syntaxe des indicateurs

Dans les versions antérieures à 2.113, les indicateurs pouvaient également être écrits sous la forme "{"-flag=valeur"}". Cela ne fonctionne plus, bien que "{"-flag$;valeur"}" fonctionne toujours. Cependant, "{-flag => 'valeur'}" est la syntaxe préférée.

Indicateurs universels

Normalement, les indicateurs sont spécifiques à un seul motif. Cependant, il existe deux indicateurs que tous les motifs peuvent spécifier.

"-keep"
Par défaut, les motifs fournis par %RE ne contiennent pas de parenthèses de capture. Cependant, si l'indicateur "-keep" est spécifié (il ne nécessite pas de valeur), alors toutes les sous-chaînes significatives que le motif correspondent sont capturées. Par exemple : 
if ($str =~ $RE{num}{real}{-keep}) {
        $number   = $1;
        $whole    = $3;
        $decimals = $5;
}

Une attention particulière est nécessaire si un motif "conservé" est interpolé dans une expression régulière plus grande, car la présence d'autres parenthèses de capture est susceptible de modifier les "variables de nombre" dans lesquelles les sous-chaînes significatives sont enregistrées.

Voir aussi "Ajout de nouvelles expressions régulières", qui décrit comment créer de nouveaux motifs avec des parenthèses "optionnelles" qui répondent à "-keep".

"-i"
Certains motifs ou sous-motifs ne correspondent qu'aux lettres minuscules ou majuscules. Si l'on souhaite effectuer une correspondance insensible à la casse, une option consiste à utiliser le modificateur d'expression régulière "/i", ou la séquence spéciale "(?i)". Mais si l'interface fonctionnelle est utilisée, on n'a pas cette option. Le commutateur "-i" résout ce problème ; en l'utilisant, le motif effectuera une correspondance insensible à la casse.

Interface OO et matching/substitution en ligne

Les motifs renvoyés par %RE sont des objets, donc au lieu d'écrire :

if ($str =~ /$RE{some}{pattern}/ ) {...}

vous pouvez écrire :

if ( $RE{some}{pattern}->matches($str) ) {...}

Pour la correspondance, cela ne semble pas présenter un grand avantage en dehors de la lisibilité (mais voir ci-dessous).

Pour les substitutions, cela présente d'autres avantages significatifs. Souvent, vous voulez effectuer une substitution sur une chaîne sans modifier l'original. La plupart des gens utilisent ceci :

$changed = $original;
$changed =~ s/$RE{some}{pattern}/$replacement/;

Les plus habiles utilisent :

($changed = $original) =~ s/$RE{some}{pattern}/$replacement/;

Regexp::Common vous permet d'écrire ceci :

$changed = $RE{some}{pattern}->subs($original=>$replacement);

Outre la réduction de l'angoisse de la précédence, cette approche a l'avantage supplémentaire que le comportement de substitution peut être optimisé à partir de l'expression régulière, et la chaîne de remplacement peut être fournie par défaut (voir "Ajout de nouvelles expressions régulières").

Par exemple, dans l'implémentation de cette substitution :

$cropped = $RE{ws}{crop}->subs($uncropped);

la chaîne vide par défaut est fournie automatiquement, et la substitution est optimisée pour utiliser :

$uncropped =~ s/^\s+//;
$uncropped =~ s/\s+$//;

plutôt que :

$uncropped =~ s/^\s+|\s+$//g;

Interface basée sur les sous-routines

L'interface basée sur les tables de hachage a été choisie car elle permet d'interpoler facilement les regex et parce qu'elle permet également de les "curry". Par exemple :

my $num = $RE{num}{int};
my $commad     = $num->{-sep=>','}{-group=>3};
my $duodecimal = $num->{-base=>12};

Cependant, l'utilisation de tables de hachage liées rend l'accès aux motifs de Regexp::Common plus lent qu'il ne pourrait l'être autrement. Dans les contextes où l'impatience l'emporte sur la paresse, Regexp::Common fournit une interface supplémentaire basée sur les sous-routines.

Pour chaque entrée (sous-entrée) dans la table de hachage %RE ("$RE{clé1}{clé2}{etc}"), il existe une sous-routine exportable correspondante : RE_clé1_clé2_etc(). Le nom de chaque sous-routine est la concaténation des clés séparées par des tirets bas.

Vous pouvez ajouter vos propres expressions régulières à la table de hachage %RE à l'exécution en utilisant la sous-routine exportable "pattern". Cette sous-routine attend une liste de paires clé-valeur spécifiant le comportement de l'expression régulière. Les différentes paires possibles sont :

"name => [ @list ]"
Un argument obligatoire spécifiant le nom de l'expression régulière, et tous les indicateurs qu'elle peut prendre, via une référence à une liste de chaînes de caractères. Par exemple : 
pattern name => [qw( line of -char )],
    # autres arguments ici
    ;

Ceci spécifie une entrée "$RE{line}{of}", qui peut prendre un indicateur "-char".

Les indicateurs peuvent également être spécifiés avec une valeur par défaut, qui est utilisée lorsque l'indicateur est spécifié sans valeur explicite (mais pas lorsque l'indicateur est omis). Par exemple :

pattern name => [qw( line of -char=_ )],
    # le caractère par défaut est '_'
    # autres arguments ici
    ;
"create => $sub_ref_or_string"
Un argument obligatoire spécifiant soit une chaîne qui sera retournée comme expression régulière : 
pattern name => [qw( line of underscores )],
    create => q/(?:^_+$)/
    ;

soit une référence à une sous-routine qui sera appelée pour créer l'expression régulière :

pattern name => [qw( line of -char=_ )],
    create => sub {
                        my ($self, $flags) = @_;
                        my $char = quotemeta $flags->{-char};
                        return '(?:^$char+$)';
                    },
    ;

Si la version sous-routine est utilisée, la sous-routine sera appelée avec trois arguments : une référence à l'objet d'expression régulière, une référence à une table de hachage contenant les indicateurs et leurs valeurs, et une référence à un tableau contenant les clés non-indicateurs.

Quels que soient les résultats de la sous-routine, ils seront convertis en une chaîne pour l'expression régulière.

Peu importe comment l'expression régulière est créée, elle sera immédiatement post-traitée pour inclure ou non des parenthèses de capture (selon la valeur de l'indicateur "-keep"). Pour spécifier des parenthèses de capture "facultatives" à l'intérieur de l'expression régulière associée à "create", utilisez la notation "(?k:...)". Toutes les parenthèses de cette catégorie seront converties en "(...)" lorsque l'indicateur "-keep" est spécifié, ou en "(?:...)" lorsqu'il est omis. C'est une convention de Regexp::Common que les parenthèses de capture les plus externes capturent toujours le motif complet, bien que cela ne soit pas appliqué.

"match => $sub_ref"
Un argument optionnel spécifiant une sous-routine qui sera appelée lorsque la méthode "$RE{...}->matches(...)" de cette expression régulière sera invoquée.

La sous-routine doit attendre deux arguments : une référence à l'objet d'expression régulière et la chaîne à comparer.

Elle doit retourner les mêmes types de valeurs qu'une expression régulière "m/.../".

pattern name => [qw( line of -char )],
    create => sub {...},
    match => sub {
                        my ($self, $str) = @_;
                        $str !~ /[^$self->{flags}{-char}]/;
                   },
    ;
"subs => $sub_ref"
Un argument optionnel spécifiant une sous-routine qui sera appelée lorsque la méthode "$RE{...}->subs(...)" de cette expression régulière sera invoquée.

La sous-routine doit attendre trois arguments : une référence à l'objet d'expression régulière, la chaîne à modifier et la valeur de remplacement. Le troisième argument peut être "undef", indiquant que le remplacement par défaut est nécessaire.

La sous-routine doit retourner les mêmes types de valeurs qu'une expression régulière "s/.../.../".

Par exemple :

pattern name => [ 'lineof', '-char=_' ],
    create => sub {...},
    subs => sub {
                     my ($self, $str, $ignore_replacement) = @_;
                     $_[1] =~ s/^$self->{flags}{-char}+$//g;
                   },
    ;

Note : une telle sous-routine devra presque toujours modifier $_[1] directement.

"version => $minimum_perl_version"
Si cet argument est spécifié, il indique la version minimale de Perl requise pour utiliser la nouvelle expression régulière. Les tentatives de l'utiliser avec des versions antérieures généreront un diagnostic grave.

Chargement de jeux de motifs spécifiques.

Par défaut, tous les jeux de motifs mentionnés ci-dessous sont disponibles. Cependant, il est possible d'indiquer quels jeux de motifs doivent être disponibles - les jeux souhaités sont indiqués comme arguments à l'instruction "use". Alternativement, il est également possible d'indiquer quels jeux de motifs ne doivent pas être disponibles - ces jeux sont indiqués comme arguments à l'instruction "use", mais précédés d'un point d'exclamation. L'argument no_defaults indique qu'aucun des motifs par défaut ne doit être disponible. Ceci est utile, par exemple, si vous ne souhaitez que la sous-routine pattern().

Exemples :

use Regexp::Common qw /comment number/;  # Motifs de commentaires et de nombres.
use Regexp::Common qw /no_defaults/;     # Ne charger aucun motif.
use Regexp::Common qw /!delimited/;      # Tous, sauf les motifs délimités.

Il est également possible de charger vos propres jeux de motifs. Si vous avez un module "Regexp::Common::my_patterns" qui fournit des motifs, vous pouvez le faire avec :

use Regexp::Common qw /my_patterns/;

Note : les motifs par défaut resteront disponibles, sauf si vous utilisez no_defaults ou si vous mentionnez explicitement l'un des jeux par défaut, les autres ne seront pas disponibles.

PAS UN BOGUE

•
Les différents patrons ne sont pas ancrés. C'est-à-dire qu'un patron comme "$RE {num} {int}" correspondra à "abc4def", car une sous-chaîne de l'échantillon correspond. C'est intentionnel, pas un bogue. Si vous voulez que le patron soit ancré, utilisez quelque chose comme : 
my $integer = $RE {num} {int};
$subj =~ /^$integer$/ and print "Ça correspond !\n";
