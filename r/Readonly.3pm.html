NOM

Readonly - Installation pour créer des scalaires, tableaux, hachages en lecture seule

Synopsis

use Readonly;
# Scalaire en lecture seule profonde
Readonly::Scalar    $sca => $valeur_initiale;
Readonly::Scalar my $sca => $valeur_initiale;
# Tableau en lecture seule profond
Readonly::Array    @arr => @valeurs;
Readonly::Array my @arr => @valeurs;
# Hachage en lecture seule profond
Readonly::Hash    %has => (clé => valeur, clé => valeur, ...);
Readonly::Hash my %has => (clé => valeur, clé => valeur, ...);
# ou:
Readonly::Hash    %has => {clé => valeur, clé => valeur, ...};
# Vous pouvez utiliser les variables en lecture seule comme des variables
# ordinaires :
print $sca;
$something = $sca + $arr[2];
next if $has{$some_key};
# Mais si vous essayez de modifier une valeur, votre programme mourra :
$sca = 7;
push @arr, 'sept';
delete $has{clé};
# Le message d'erreur est "Tentative de modification d'une valeur en lecture
# seule"
# Forme alternative (Perl 5.8 et plus récents)
Readonly    $sca => $valeur_initiale;
Readonly my $sca => $valeur_initiale;
Readonly    @arr => @valeurs;
Readonly my @arr => @valeurs;
Readonly    %has => (clé => valeur, clé => valeur, ...);
Readonly my %has => (clé => valeur, clé => valeur, ...);
Readonly my $sca; # undef implicite, valeur en lecture seule
# Forme alternative (pour Perl antérieur à la v5.8)
Readonly    \$sca => $valeur_initiale;
Readonly \my $sca => $valeur_initiale;
Readonly    \@arr => @valeurs;
Readonly \my @arr => @valeurs;
Readonly    \%has => (clé => valeur, clé => valeur, ...);
Readonly \my %has => (clé => valeur, clé => valeur, ...);

Description

Ceci est une installation pour créer des variables non modifiables. Ceci est utile pour les fichiers de configuration, les en-têtes, etc. Cela peut également être utile comme outil de développement et de débogage pour détecter les modifications apportées aux variables qui ne devraient pas être modifiées.

Profondeur de la variable

Readonly a la capacité de créer des variables en lecture seule profondes et peu profondes.

Si vous passez une $ref, un @array ou un %hash aux fonctions correspondantes ::Scalar(), ::Array() et ::Hash(), alors ces fonctions récursent sur la structure de données, marquant tout comme en lecture seule. L'ensemble de la structure est alors non modifiable. C'est normalement ce que vous voulez.

Si vous voulez que seul le niveau supérieur soit en lecture seule, utilisez les fonctions alternatives (et mal nommées) ::Scalar1(), ::Array1() et ::Hash1().

La forme simple Readonly() crée ce que l'auteur original appelle une variable en lecture seule "peu profonde", ce qui est génial si vous ne prévoyez pas de l'utiliser sur autre chose que des valeurs scalaires unidimensionnelles.

Readonly::Scalar() rend la variable en lecture seule "profondément", de sorte que l'extrait de code suivant plante comme prévu :

use Readonly;
Readonly::Scalar my $ref => { 1 => 'a' };
$ref->{1} = 'b';
$ref->{2} = 'b';

Alors que l'extrait de code suivant ne rend pas votre structure en lecture seule "profondément" :

use Readonly;
Readonly my $ref => { 1 => 'a' };
$ref->{1} = 'b';
$ref->{2} = 'b';

Le Passé

Les sections suivantes sont des versions mises à jour de la documentation des auteurs précédents.

Comparaison avec "use constant"

Perl fournit une installation pour créer des valeurs constantes, via le pragma constant. Il y a plusieurs problèmes avec ce pragma.

  • Les constantes créées n'ont pas de sigils de tête.
  • Ces constantes ne peuvent pas être interpolées dans les chaînes de caractères.
  • La syntaxe peut parfois être délicate. Par exemple : 
    use constant CARRAY => (2, 3, 5, 7, 11, 13);
$a_prime = CARRAY[2];        # faux !
$a_prime = (CARRAY)[2];      # juste -- DOIT utiliser des parenthèses
  • Il faut être très prudent dans les endroits où les mots nus sont autorisés.

    Par exemple :

    use constant SOME_KEY => 'clé';
%hash = (clé => 'valeur', autre_clé => 'autre_valeur');
$some_value = $hash{SOME_KEY};        # faux !
$some_value = $hash{+SOME_KEY};       # juste

    (qui pense à utiliser un plus unaire lors de l'utilisation d'un hachage pour scalariser la clé ?)

  • "use constant" fonctionne pour les scalaires et les tableaux, pas pour les hachages.
  • Ces constantes sont globales au paquet dans lequel elles sont déclarées ; ne peuvent pas être lexicalement délimitées.
  • Fonctionne uniquement au moment de la compilation.
  • Peut être remplacé : 
    use constant PI => 3.14159;
...
use constant PI => 2.71828;

    (cela génère un avertissement, cependant, si vous avez les avertissements activés).

  • Il est très difficile de créer et d'utiliser des structures profondes (structures de données complexes) avec "use constant".

Comparaison avec les constantes de typeglob

Une autre façon populaire de créer des scalaires en lecture seule est de modifier l'entrée de la table des symboles pour la variable en utilisant un typeglob :

*a = \'valeur';

Cela fonctionne bien, mais cela ne fonctionne que pour les variables globales (les variables "my" n'ont pas d'entrée de table des symboles). De plus, les constructions similaires suivantes ne fonctionnent pas :

*a = [1, 2, 3];      # Ne crée PAS un tableau en lecture seule
*a = { a => 'A'};    # Ne crée PAS un hachage en lecture seule

Avantages

Readonly.pm, en revanche, fonctionnera avec des variables globales et avec des variables lexicales ("my"). Il créera des scalaires, des tableaux ou des hachages, qui ressemblent et fonctionnent comme des variables Perl normales, en lecture/écriture. Vous pouvez les utiliser en contexte scalaire, en contexte de liste ; vous pouvez en prendre des références, les passer à des fonctions, n'importe quoi.

Readonly.pm fonctionne également bien avec les structures de données complexes, vous permettant d'étiqueter toute la structure comme non modifiable, ou juste le niveau supérieur.

De plus, les variables Readonly ne peuvent pas être réassignées. Le code suivant mourra :

Readonly::Scalar $pi => 3.14159;
...
Readonly::Scalar $pi => 2.71828;

Inconvénients

Readonly.pm imposait auparavant une pénalité de performance. C'était assez lent. Si lent que ? Exécutez le script "eg/benchmark.pl" qui accompagne Readonly. Sur mon système de test, "use constant" (const), les constantes de typeglob (tglob), les variables Perl normales lecture/écriture (normal/literal), et le nouveau Readonly (ro/ro_simple) ont toutes à peu près la même vitesse, les anciennes constantes Readonly.pm basées sur tie étaient environ 22 fois plus lentes.

Cependant, il y a un soulagement. Il existe un module compagnon disponible, Readonly::XS. Vous n'en aurez pas besoin si vous utilisez Perl 5.8.x ou une version ultérieure.

Je répète, vous n'avez pas besoin de Readonly::XS si votre environnement possède Perl 5.8.x ou une version ultérieure. Veuillez consulter la section intitulée Internals pour plus d'informations.

Fonctions

Readonly::Scalar $var => $valeur;
Crée un scalaire non modifiable, $var, et lui assigne une valeur $valeur. Par la suite, sa valeur ne peut pas être modifiée. Toute tentative de modification de la valeur provoquera la mort de votre programme.

Une valeur *doit* être fournie. Si vous souhaitez que la variable ait "undef" comme valeur, vous devez spécifier "undef".

Si $valeur est une référence vers un scalaire, un tableau ou un hachage, alors cette fonction marquera également le scalaire, le tableau ou le hachage qu'il pointe comme étant en lecture seule, et elle parcourra récursivement la structure, marquant l'ensemble comme étant en lecture seule. Généralement, c'est ce que vous voulez. Cependant, si vous voulez que seule $valeur soit marquée en lecture seule, utilisez "Scalar1".

Si $var est déjà une variable en lecture seule, le programme mourra avec une erreur concernant la réassignation de variables en lecture seule.

Readonly::Array @arr => (valeur, valeur, .

Clonage

Lorsque vous clonez en utilisant Storable ou Clone, vous remarquerez que la valeur reste en lecture seule, ce qui est correct. Si vous souhaitez cloner la valeur sans copier l'indicateur de lecture seule, utilisez la fonction "Clone" :

Readonly::Scalar my $scalar => {qw[this that]};
# $scalar->{'eh'} = 'foo'; # Modification d'une valeur en lecture seule
my $scalar_clone = Readonly::Clone $scalar;
$scalar_clone->{'eh'} = 'foo';
# $scalar_clone est maintenant {this => 'that', eh => 'foo'};

La nouvelle variable ($scalar_clone) est un clone modifiable de l'original ($scalar).

Exemples

Voici quelques exemples simples :

Scalaires

Une valeur scalaire en lecture seule ordinaire :

Readonly::Scalar $a => "A string value";

La valeur n'a pas nécessairement besoin d'être une valeur constante au moment de la compilation :

Readonly::Scalar $a => $computed_value;

Tableaux/Listes

Un tableau en lecture seule :

Readonly::Array @a => (1, 2, 3, 4);

Les parenthèses sont facultatives :

Readonly::Array @a => 1, 2, 3, 4;

Vous pouvez utiliser la syntaxe de découpage de Perl :

Readonly::Array @a => qw/1 2 3 4/;

Vous pouvez initialiser un tableau en lecture seule à partir d'une variable :

Readonly::Array @a => @computed_values;

Un tableau en lecture seule peut être vide :

Readonly::Array @a => ();
Readonly::Array @a;        # équivalent

Hashs

Utilisation typique :

Readonly::Hash %a => (key1 => 'value1', key2 => 'value2');

Un hash en lecture seule peut être initialisé à partir d'une variable :

Readonly::Hash %a => %computed_values;

Un hash en lecture seule peut être vide :

Readonly::Hash %a => ();
Readonly::Hash %a;        # équivalent

Si vous passez un nombre impair de valeurs, le programme s'arrêtera :

Readonly::Hash %a => (key1 => 'value1', "value2");
# S'arrête avec "May not store an odd number of values in a hash"

Exportations

Historiquement, ce module exportait le symbole "Readonly" dans l'espace de noms du programme appelant par défaut. Vous pouvez également importer les symboles suivants si vous préférez : "Scalar", "Scalar1", "Array", "Array1", "Hash", et "Hash1".

Internes

Certains utilisateurs ne comprennent tout simplement pas la relation entre ce module et le "Readonly" de Readonly::XS, j'ai donc ajouté cette section. Même s'ils ne le comprennent peut-être toujours pas, j'aime écrire comme ça...

Autrefois, la "magie" de Readonly était réalisée en "liant" (tie()) des variables aux paquets "Readonly::Scalar", "Readonly::Array" et "Readonly::Hash" (pas aux fonctions du même nom) et en agissant sur "WRITE", "READ", etc. Bien que cela ait bien fonctionné, c'était lent. Très lent. 20 à 30 fois plus lent que d'accéder directement aux variables ou d'utiliser l'un des modules liés aux constantes qui ont émergé après le lancement de Readonly en 2003.

Pour "résoudre" cela, Readonly::XS a été écrit. S'il était installé, Readonly::XS utilisait les méthodes internes "SvREADONLY" et "SvREADONLY_on" pour verrouiller des scalaires simples. En surface, tout était parfait, mais ce n'était pas le cas en coulisses. Dans les cas limites, le code se comportait très différemment si Readonly::XS était installé et n'était pas une dépendance requise dans la plupart des cas, ce qui rendait le débogage du code ultérieur très difficile.

Des années après le lancement de Readonly::XS, les méthodes internes privées ont été exposées et peuvent être utilisées en Perl pur. Des modules similaires ont été écrits en profitant de cette possibilité et un correctif a été créé pour Readonly. Il n'est plus nécessaire de construire et d'installer un autre module pour rendre Readonly utile dans les builds modernes de Perl.

  • Vous n'avez pas besoin d'installer Readonly::XS.
  • Vous devez cesser de mentionner Readonly::XS comme dépendance ou attendre qu'il soit installé.
  • Laisser la variable $Readonly::XSokay ne pas être utilisée dans le code ou les tests.

Exigences

Veuillez noter que les utilisateurs principaux de "Readonly" n'ont pas besoin d'installer le module complémentaire "Readonly::XS", qui est recommandé mais non obligatoire pour Perl 5.6.x et les versions antérieures. Vous ne devez pas le forcer dans un nouveau code et n'utilisez pas la variable de paquet $Readonly::XSokay dans le code ou les tests. Pour plus d'informations, voir "Internes" dans la section des nouveaux internes de "Readonly").

Il n'y a pas d'exigences non standard.

NOM

Lecture seule

Synopsis

Utilisez Readonly pour rendre une variable lecture seule.

Description

Le module Readonly fournit un moyen de rendre une variable lecture seule. Ceci est utile lorsque vous souhaitez garantir qu'une variable ne peut pas être modifiée après son affectation initiale.

Profondeur Variable

Le module Readonly vous permet de spécifier la profondeur d'une variable. Cela signifie que vous pouvez rendre une variable lecture seule au niveau de sa définition, ou au niveau de ses sous-variables.

Le Passé

Le module Readonly a été introduit pour la première fois en 2002. Il a été initialement développé pour Perl 5.8 et les versions ultérieures.

Comparaison avec les constantes typeglob

Le module Readonly fournit un moyen de rendre une variable lecture seule, similaire à l'utilisation des constantes typeglob. Cependant, Readonly offre plus de flexibilité en termes de spécification de la profondeur de la lecture seule.

Fonctions

Le module Readonly fournit les fonctions suivantes :

  • Readonly - Rend une variable lecture seule.
  • Readonly - Rend une variable lecture seule à une profondeur spécifique.
  • Readonly - Rend une variable lecture seule au niveau de ses sous-variables.

Clonage

Le module Readonly vous permet de cloner une variable lecture seule. Cela signifie que vous pouvez créer une nouvelle variable qui partage la propriété lecture seule de la variable d'origine.

Exemples

Voici quelques exemples d'utilisation du module Readonly :

# Exemple 1: Rendre une variable lecture seule
my $x = 5;
Readonly my $y => 10;

# Exemple 2: Rendre une variable lecture seule à une profondeur spécifique
Readonly my $z => 20, 30;

# Exemple 3: Cloner une variable lecture seule
my $w = $y;
Readonly my $v => $w;

Exports

Le module Readonly exporte les fonctions suivantes :

  • Readonly - Rend une variable lecture seule.
  • Readonly - Rend une variable lecture seule à une profondeur spécifique.
  • Readonly - Rend une variable lecture seule au niveau de ses sous-variables.

Internes

Le module Readonly utilise les mécanismes internes suivants :

  • Readonly - Garantit qu'une variable ne peut pas être modifiée après son affectation initiale.
  • Readonly - Permet la spécification de la profondeur de la lecture seule.
  • Readonly - Permet le clonage de variables lecture seule.

Prérequis

Le module Readonly nécessite les dépendances suivantes :

  • perl - L'interpréteur Perl.

Rapports de bugs

Pour tout rapport de bug ou problème rencontré avec le module Readonly, veuillez les signaler aux mainteneurs.
