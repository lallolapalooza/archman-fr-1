NOM

REASSIGN OWNED - changer la propriété des objets de base de données appartenant à un rôle de base de données

SYNTAXE

REASSIGN OWNED PAR { ancien_role | CURRENT_ROLE | CURRENT_USER | SESSION_USER } [, ...]
               À { nouveau_role | CURRENT_ROLE | CURRENT_USER | SESSION_USER }

DESCRIPTION

REASSIGN OWNED demande au système de changer la propriété des objets de base de données appartenant à l'un des anciens_rôles à nouveau_role.

PARAMETRES

ancien_role

Le nom d'un rôle. La propriété de tous les objets au sein de la base de données actuelle, et de tous les objets partagés (bases de données, tablespaces), appartenant à ce rôle sera réattribuée à nouveau_role.

nouveau_role

Le nom du rôle qui deviendra le nouveau propriétaire des objets concernés.

NOTES

REASSIGN OWNED est souvent utilisé pour préparer la suppression d'un ou plusieurs rôles. Comme REASSIGN OWNED n'affecte pas les objets dans d'autres bases de données, il est généralement nécessaire d'exécuter cette commande dans chaque base de données contenant des objets appartenant à un rôle qui doit être supprimé.

REASSIGN OWNED nécessite d'appartenir à la fois aux rôles source et au rôle cible.

La commande DROP OWNED est une alternative qui supprime simplement tous les objets de base de données appartenant à un ou plusieurs rôles.

La commande REASSIGN OWNED n'affecte aucun privilège accordé aux anciens_rôles sur des objets qui ne leur appartiennent pas. De même, elle n'affecte pas les privilèges par défaut créés avec ALTER DEFAULT PRIVILEGES. Utilisez DROP OWNED pour révoquer de tels privilèges.

Voir la section 21.4 pour plus de discussion.

COMPATIBILITE

La commande REASSIGN OWNED est une extension de PostgreSQL.

VOIR AUSSI

DROP OWNED (DROP_OWNED(7)), DROP ROLE (DROP_ROLE(7)), ALTER DATABASE (ALTER_DATABASE(7))
