RAND_GET0_PRIMARY(3ssl) OpenSSL RAND_GET0_PRIMARY(3ssl)

NOM

RAND_get0_primary, RAND_get0_public, RAND_get0_private, RAND_set0_public, RAND_set0_private - obtenir l'accès aux instances EVP_RAND_CTX globales

SYNOPSIS

#include <openssl/rand.h>
EVP_RAND_CTX *RAND_get0_primary(OSSL_LIB_CTX *ctx);
EVP_RAND_CTX *RAND_get0_public(OSSL_LIB_CTX *ctx);
EVP_RAND_CTX *RAND_get0_private(OSSL_LIB_CTX *ctx);
int RAND_set0_public(OSSL_LIB_CTX *ctx, EVP_RAND_CTX *rand);
int RAND_set0_private(OSSL_LIB_CTX *ctx, EVP_RAND_CTX *rand);

DESCRIPTION

L'implémentation par défaut de l'API RAND (RAND_OpenSSL()) utilise trois instances DRBG partagées qui sont accessibles via l'API RAND :

Les DRBG public et private sont des instances locales aux threads, utilisées respectivement par RAND_bytes() et RAND_priv_bytes(). Le DRBG primary est une instance globale, qui n'est pas destinée à être utilisée directement, mais elle est utilisée en interne pour réensemencer les deux autres instances.

Les trois fonctions get fournissent l'accès aux instances DRBG partagées.

Les deux fonctions set permettent de remplacer les instances DRBG public et private par un autre générateur de nombres aléatoires.

VALEURS DE RETOUR

RAND_get0_primary() renvoie un pointeur vers l'instance DRBG primary pour le OSSL_LIB_CTX ctx donné.

RAND_get0_public() renvoie un pointeur vers l'instance DRBG public pour le OSSL_LIB_CTX ctx donné.

RAND_get0_private() renvoie un pointeur vers l'instance DRBG private pour le OSSL_LIB_CTX ctx donné.

RAND_set0_public() et RAND_set0_private() renvoient 1 en cas de succès et 0 en cas d'erreur.

NOTES

L'accès à l'instance DRBG primary n'est pas sûr pour les threads. L'accès aux instances DRBG public et private est sûr, car elles sont locales aux threads. Notez cependant que les modifications apportées à ces deux instances ne s'appliquent qu'au thread courant.

Pour cette raison, il est recommandé de ne pas modifier les paramètres de ces trois instances directement. Au lieu de cela, une application devrait modifier les paramètres par défaut pour les nouvelles instances DRBG au moment de l'initialisation, avant de créer des threads supplémentaires.

Lors de l'initialisation, il est possible de modifier l'intervalle de réensemencement et l'intervalle temporel de réensemencement. Il est également possible d'échanger entièrement les callbacks de réensemencement.

Pour définir le type de DRBG qui sera instancié, utilisez l'appel RAND_set_DRBG_type(3) avant d'accéder à l'infrastructure de génération de nombres aléatoires.

Les deux fonctions set agissent sur le thread courant. Si vous souhaitez utiliser le même générateur de nombres aléatoires sur tous les threads, chaque thread doit appeler individuellement les fonctions set.

VOIR AUSSI

EVP_RAND(3), RAND_set_DRBG_type(3)

HISTORIQUE

RAND_set0_public() et RAND_set0_private() ont été ajoutés dans OpenSSL 3.1.

Les fonctions restantes ont été ajoutées dans OpenSSL 3.0.
