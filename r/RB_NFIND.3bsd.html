DESCRIPTION

Ces macros définissent des structures de données pour différents types d'arbres : arbres de splay et arbres rouge-noir.

Dans les définitions de macro, TYPE est le tag d'une structure définie par l'utilisateur qui doit contenir un champ nommé FIELD de type SPLAY_ENTRY ou RB_ENTRY. L'argument HEADNAME est le tag d'une structure définie par l'utilisateur qui doit être déclarée en utilisant les macros SPLAY_HEAD() ou RB_HEAD(). L'argument NAME doit être un nom de préfixe unique pour chaque arbre défini.

Les prototypes de fonctions sont déclarés avec SPLAY_PROTOTYPE, RB_PROTOTYPE ou RB_PROTOTYPE_STATIC. Les corps des fonctions sont générés avec SPLAY_GENERATE, RB_GENERATE ou RB_GENERATE_STATIC. Voir les exemples ci-dessous pour une explication plus détaillée de la façon dont ces macros sont utilisées.

ARBRE DE SPLAY

Un arbre de splay est une structure de données auto-organisatrice. Chaque opération sur l'arbre provoque un splay. Le splay déplace le nœud demandé vers la racine de l'arbre et rééquilibre partiellement l'arbre.

Cet avantage est que l'accès local aux nœuds demandés rend les requêtes plus rapides, car les nœuds demandés sont déplacés vers le haut de l'arbre. D'un autre côté, chaque requête provoque des écritures en mémoire.

Le Théorème d'Équilibrage limite le temps d'accès total pour m opérations et n insertions dans un arbre initialement vide à O((m + n)lg n). Le coût amorti pour une séquence de m accès à un arbre de splay est O(lg n).

Un arbre de splay est dirigé par une structure définie par la macro SPLAY_HEAD(). Un SPLAY_HEAD est déclaré comme suit :

SPLAY_HEAD(HEADNAME, TYPE) head;

où HEADNAME est le nom de la structure à définir et TYPE est le type des éléments à insérer dans l'arbre.

La macro SPLAY_ENTRY déclare une structure qui permet de connecter les éléments dans l'arbre.

Pour utiliser les fonctions qui manipulent la structure de l'arbre, leurs prototypes doivent être déclarés avec la macro SPLAY_PROTOTYPE, où NAME est un identifiant unique pour cet arbre particulier. L'argument TYPE est le type de la structure qui gère l'arbre. L'argument FIELD est le nom de l'élément défini par SPLAY_ENTRY.

Les corps des fonctions sont générés avec la macro SPLAY_GENERATE. Elle prend les mêmes arguments que la macro SPLAY_PROTOTYPE() mais ne doit être utilisée qu'une seule fois.

Enfin, l'argument CMP est le nom d'une fonction qui compare des nœuds d'arbre entre eux. La fonction prend deux arguments de type struct TYPE *. Si le premier argument est inférieur au second, la fonction renvoie une valeur inférieure à zéro. S'ils sont égaux, elle renvoie zéro. Sinon, elle doit renvoyer une valeur supérieure à zéro. La fonction de comparaison définit l'ordre des éléments de l'arbre.

La macro SPLAY_INIT initialise l'arbre référencé par head.

L'arbre de splay peut également être initialisé statiquement à l'aide de la macro SPLAY_INITIALIZER comme suit :

SPLAY_HEAD(HEADNAME, TYPE) head = SPLAY_INITIALIZER(&head);

La macro SPLAY_INSERT insère le nouvel élément elm dans l'arbre. En cas de succès, elle renvoie NULL. Si un élément ayant la même valeur existe déjà dans l'arbre, l'insertion est abandonnée et un pointeur vers cet élément existant est renvoyé.

La macro SPLAY_REMOVE supprime l'élément elm de l'arbre pointé par head. En cas de succès, un pointeur vers l'élément supprimé est renvoyé. NULL est renvoyé si elm n'est pas présent dans l'arbre.

La macro SPLAY_FIND peut être utilisée pour trouver un élément spécifique dans l'arbre.

struct TYPE find, *res;
find.key = 30;
res = SPLAY_FIND(NAME, &head, &find);

Les macros SPLAY_ROOT(), SPLAY_MIN(), SPLAY_MAX() et SPLAY_NEXT() peuvent être utilisées pour parcourir l'arbre :

for (np = SPLAY_MIN(NAME, &head); np != NULL; np = SPLAY_NEXT(NAME, &head, np))

Ou, pour plus de simplicité, la macro SPLAY_FOREACH peut être utilisée :

SPLAY_FOREACH(np, NAME, &head)

La macro SPLAY_EMPTY doit être utilisée pour vérifier si un arbre de splay est vide.

ARBRE ROUGE-NOIR

Un arbre rouge-noir est un arbre de recherche binaire avec la couleur des nœuds comme attribut supplémentaire. Il garantit un ensemble de conditions :

  1. Chaque chemin de recherche de la racine à une feuille contient le même nombre de nœuds noirs,
  2. Chaque nœud rouge (sauf la racine) a un parent noir,
  3. Chaque nœud feuille est noir.

Chaque opération sur un arbre rouge-noir est limitée à O(lg n). La hauteur maximale d'un arbre rouge-noir est de 2lg(n+1).

Un arbre rouge-noir est dirigé par une structure définie par la macro RB_HEAD. Un RB_HEAD est déclaré comme suit :

RB_HEAD(HEADNAME, TYPE) head;

où HEADNAME est le nom de la structure à définir et TYPE est le type des éléments à insérer dans l'arbre.

La macro RB_ENTRY déclare une structure qui permet de connecter les éléments dans l'arbre.

Pour utiliser les fonctions qui manipulent la structure de l'arbre, leurs prototypes doivent être déclarés avec les macros RB_PROTOTYPE() ou RB_PROTOTYPE_STATIC() où NAME est un identifiant unique pour cet arbre particulier. L'argument TYPE est le type de la structure qui gère l'arbre. L'argument FIELD est le nom de l'élément défini par RB_ENTRY.

Les corps des fonctions sont générés avec les macros RB_GENERATE() ou RB_GENERATE_STATIC(). Ces macros prennent les mêmes arguments que les macros RB_PROTOTYPE() et RB_PROTOTYPE().

utilisés uniquement une fois.

Enfin, l'argument CMP est le nom d'une fonction utilisée pour comparer les nœuds des arbres entre eux. La fonction prend deux arguments de type struct TYPE *. Si le premier argument est plus petit que le second, la fonction retourne une valeur inférieure à zéro. S'ils sont égaux, la fonction retourne zéro. Sinon, elle doit retourner une valeur supérieure à zéro. La fonction de comparaison définit l'ordre des éléments de l'arbre.

La macro RB_INIT() initialise l'arbre référencé par head.

L'arbre rouge-noir peut également être initialisé statiquement en utilisant la macro RB_INITIALIZER() comme suit :

RB_HEAD(NOM_ENTETE, TYPE) head = RB_INITIALIZER(&head);

La macro RB_INSERT() insère le nouvel élément elm dans l'arbre. En cas de succès, NULL est retourné. Si un élément correspondant existe déjà dans l'arbre, l'insertion est interrompue et un pointeur vers l'élément existant est retourné.

La macro RB_REMOVE() supprime l'élément elm de l'arbre pointé par head. RB_REMOVE() retourne elm.

Les macros RB_FIND() et RB_NFIND() peuvent être utilisées pour trouver un élément particulier dans l'arbre. RB_FIND() trouve le nœud avec la même clé que elm. RB_NFIND() trouve le premier nœud supérieur ou égal à la clé de recherche.

struct TYPE find, *res;
find.cle = 30;
res = RB_FIND(NOM, &head, &find);

Les macros RB_ROOT(), RB_MIN(), RB_MAX(), RB_NEXT(), et RB_PREV() peuvent être utilisées pour parcourir l'arbre :

for (np = RB_MIN(NOM, &head); np != NULL; np = RB_NEXT(NOM, &head, np))

Ou, pour plus de simplicité, on peut utiliser les macros RB_FOREACH() ou RB_FOREACH_REVERSE() :

RB_FOREACH(np, NOM, &head)

Les macros RB_FOREACH_SAFE() et RB_FOREACH_REVERSE_SAFE() parcourent l'arbre référencé par head dans un sens avant ou arrière respectivement, en assignant chaque élément à tour de rôle à np. Cependant, contrairement à leurs homologues non sécurisés, elles permettent à la fois la suppression de np ainsi que sa libération depuis la boucle en toute sécurité sans interférer avec le parcours.

La macro RB_EMPTY() doit être utilisée pour vérifier si un arbre rouge-noir est vide.

EXEMPLES

L'exemple suivant montre comment déclarer un arbre rouge-noir contenant des entiers. Les valeurs y sont insérées et le contenu de l'arbre est imprimé dans l'ordre. Enfin, la structure interne de l'arbre est imprimée.

#include <sys/tree.h>
#include <err.h>
#include <stdio.h>
#include <stdlib.h>

struct node {
	RB_ENTRY(node) entry;
	int i;
};

int	intcmp(struct node *, struct node *);
void	print_tree(struct node *);

int
intcmp(struct node *e1, struct node *e2)
{
	return (e1->i < e2->i ? -1 : e1->i > e2->i);
}

RB_HEAD(inttree, node) head = RB_INITIALIZER(&head);
RB_PROTOTYPE(inttree, node, entry, intcmp)
RB_GENERATE(inttree, node, entry, intcmp)

int testdata[] = {
	20, 16, 17, 13, 3, 6, 1, 8, 2, 4, 10, 19, 5, 9, 12, 15, 18,
	7, 11, 14
};

void
print_tree(struct node *n)
{
	struct node *left, *right;

	if (n == NULL) {
		printf("nil");
		return;
	}
	left = RB_LEFT(n, entry);
	right = RB_RIGHT(n, entry);
	if (left == NULL && right == NULL)
		printf("%d", n->i);
	else {
		printf("%d(", n->i);
		print_tree(left);
		printf(",");
		print_tree(right);
		printf(")");
	}
}

int
main(void)
{
	int i;
	struct node *n;

	for (i = 0; i < sizeof(testdata) / sizeof(testdata[0]); i++) {
		if ((n = malloc(sizeof(struct node))) == NULL)
			err(1, NULL);
		n->i = testdata[i];
		RB_INSERT(inttree, &head, n);
	}

	RB_FOREACH(n, inttree, &head) {
		printf("%d\n", n->i);
	}
	print_tree(RB_ROOT(&head));
	printf("\n");
	return (0);
}

HISTORIQUE

Les macros d'arbre sont apparues pour la première fois dans FreeBSD 4.6.

NOTES

Essayer de libérer un arbre de la manière suivante est une erreur courante :

SPLAY_FOREACH(var, NOM, &head) {
	SPLAY_REMOVE(NOM, &head, var);
	free(var);
}
free(head);

Étant donné que var est libéré, la macro FOREACH() fait référence à un pointeur qui a pu être réalloué. Un code correct nécessite une seconde variable.

for (var = SPLAY_MIN(NOM, &head); var != NULL; var = nxt) {
	nxt = SPLAY_NEXT(NOM, &head, var);
	SPLAY_REMOVE(NOM, &head, var);
	free(var);
}
