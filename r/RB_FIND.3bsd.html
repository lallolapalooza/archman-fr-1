DESCRIPTION

Ces macros définissent des structures de données pour différents types d'arbres : arbres auto-équilibrants (splay trees) et arbres rouge-noir.

Dans les définitions de macros, TYPE est le nom d'une structure définie par l'utilisateur qui doit contenir un champ nommé FIELD, de type SPLAY_ENTRY ou RB_ENTRY. L'argument HEADNAME est le nom d'une structure définie par l'utilisateur qui doit être déclarée en utilisant les macros SPLAY_HEAD() ou RB_HEAD(). L'argument NOM doit être un préfixe unique pour chaque arbre défini.

Les prototypes des fonctions sont déclarés avec SPLAY_PROTOTYPE, RB_PROTOTYPE, ou RB_PROTOTYPE_STATIC. Les corps des fonctions sont générés avec SPLAY_GENERATE, RB_GENERATE, ou RB_GENERATE_STATIC. Voir les exemples ci-dessous pour plus d'explications sur l'utilisation de ces macros.

ARbres AUTO-ÉQUILIBRANTS (SPLAY TREES)

Un arbre auto-équilibrant (splay tree) est une structure de données auto-organisée. Chaque opération sur l'arbre provoque un "splay". Le splay déplace le nœud demandé vers la racine de l'arbre et le rééquilibre partiellement.

Cela a pour avantage que la localité des requêtes accélère les recherches, car les nœuds demandés se déplacent vers le sommet de l'arbre. D'un autre côté, chaque consultation entraîne des écritures en mémoire.

Le Théorème d'Équilibrage borne le temps d'accès total pour m opérations et n insertions dans un arbre initialement vide comme O((m + n)lg n). Le coût amorti pour une séquence de m accès à un arbre auto-équilibrant est O(lg n).

Un arbre auto-équilibrant est dirigé par une structure définie par la macro SPLAY_HEAD(). Une structure SPLAY_HEAD est déclarée comme suit :

SPLAY_HEAD(NOM_TETE, TYPE) tete;

où NOM_TETE est le nom de la structure à définir, et struct TYPE est le type des éléments à insérer dans l'arbre.

La macro SPLAY_ENTRY() déclare une structure qui permet de connecter les éléments dans l'arbre.

Pour utiliser les fonctions qui manipulent la structure de l'arbre, leurs prototypes doivent être déclarés avec la macro SPLAY_PROTOTYPE(), où NOM est un identifiant unique pour cet arbre particulier. L'argument TYPE est le type de la structure gérée par l'arbre. L'argument FIELD est le nom de l'élément défini par SPLAY_ENTRY().

Les corps des fonctions sont générés avec la macro SPLAY_GENERATE(). Elle prend les mêmes arguments que la macro SPLAY_PROTOTYPE(), mais ne doit être utilisée qu'une seule fois.

Enfin, l'argument CMP est le nom d'une fonction utilisée pour comparer les nœuds de l'arbre entre eux. La fonction prend deux arguments de type struct TYPE *. Si le premier argument est plus petit que le second, la fonction renvoie une valeur inférieure à zéro. S'ils sont égaux, la fonction renvoie zéro. Sinon, elle doit renvoyer une valeur supérieure à zéro. La fonction de comparaison définit l'ordre des éléments de l'arbre.

La macro SPLAY_INIT() initialise l'arbre référencé par tete.

L'arbre auto-équilibrant peut également être initialisé statiquement en utilisant la macro SPLAY_INITIALIZER() comme suit :

SPLAY_HEAD(NOM_TETE, TYPE) tete = SPLAY_INITIALIZER(&tete);

La macro SPLAY_INSERT() insère le nouvel élément elm dans l'arbre. En cas de succès, NULL est retourné. Si un élément correspondant existe déjà dans l'arbre, l'insertion est interrompue et un pointeur vers l'élément existant est retourné.

La macro SPLAY_REMOVE() supprime l'élément elm de l'arbre pointé par tete. En cas de succès, un pointeur vers l'élément supprimé est retourné. NULL est retourné si elm n'est pas présent dans l'arbre.

La macro SPLAY_FIND() peut être utilisée pour trouver un élément particulier dans l'arbre.

struct TYPE recherche, *res;
recherche.cle = 30;
res = SPLAY_FIND(NOM, &tete, &recherche);

Les macros SPLAY_ROOT(), SPLAY_MIN(), SPLAY_MAX(), et SPLAY_NEXT() peuvent être utilisées pour parcourir l'arbre :

pour (np = SPLAY_MIN(NOM, &tete); np != NULL; np = SPLAY_NEXT(NOM, &tete, np))

Ou, pour plus de simplicité, on peut utiliser la macro SPLAY_FOREACH() :

SPLAY_FOREACH(np, NOM, &tete)

La macro SPLAY_EMPTY() doit être utilisée pour vérifier si un arbre auto-équilibrant est vide.

ARbres ROUGE-NOIR

Un arbre rouge-noir est un arbre binaire de recherche avec la couleur du nœud comme attribut supplémentaire. Il remplit un ensemble de conditions :

  1. chaque chemin de recherche de la racine à une feuille contient le même nombre de nœuds noirs,
  2. chaque nœud rouge (sauf la racine) a un parent noir,
  3. chaque nœud feuille est noir.

Chaque opération sur un arbre rouge-noir est bornée à O(lg n). La hauteur maximale d'un arbre rouge-noir est 2lg (n+1).

Un arbre rouge-noir est dirigé par une structure définie par la macro RB_HEAD(). Une structure RB_HEAD est déclarée comme suit :

RB_HEAD(NOM_TETE, TYPE) tete;

où NOM_TETE est le nom de la structure à définir, et struct TYPE est le type des éléments à insérer dans l'arbre.

La macro RB_ENTRY() déclare une structure qui permet de connecter les éléments dans l'arbre.

Pour utiliser les fonctions qui manipulent la structure de l'arbre, leurs prototypes doivent être déclarés avec les macros RB_PROTOTYPE() ou RB_PROTOTYPE_STATIC(), où NOM est un identifiant unique pour cet arbre particulier. L'argument TYPE est le type de la structure gérée par l'arbre. L'argument FIELD est le nom de l'élément défini par RB_ENTRY().

Les corps des fonctions sont générés avec les macros RB_GENERATE() ou RB_GENERATE_STATIC(). Ces macros prennent les mêmes arguments que les macros RB_PROTOTYPE() et RB_PROTOTY

NOM

RB_HEAD - Macros pour les arbres rouges-noirs et splay

BIBLIOTHÈQUE

sys/tree.h

SYNOPSIS

RB_HEAD(HEADNAME, TYPE) head = RB_INITIALIZER(&head);

DESCRIPTION

Ces macros fournissent des implémentations d'arbres rouges-noirs et de splay. Ils vous permettent de construire des structures de données en arbre efficaces sans avoir à implémenter les détails complexes de ces arbres. Les macros gèrent l'insertion, la suppression, la recherche et le parcours des éléments dans l'arbre.

EXEMPLES

L'exemple suivant montre comment déclarer un arbre rouge-noir qui stocke des entiers. Les valeurs sont insérées dedans et imprimées dans l'ordre. Enfin, la structure interne de l'arbre est imprimée.

RB_HEAD(HEADNAME, TYPE) head = RB_INITIALIZER(&head);
RB_PROTOTYPE(HEADNAME, TYPE, entry, intcmp);
RB_GENERATE(HEADNAME, TYPE, entry, intcmp);

int intcmp(struct TYPE *e1, struct TYPE *e2);
void print_tree(struct TYPE *);

int testdata[] = {
	20, 16, 17, 13, 3, 6, 1, 8, 2, 4, 10, 19, 5, 9, 12, 15, 18,
	7, 11, 14
};

void print_tree(struct TYPE *n);
int main(void);

int main(void)
{
	int i;
	struct TYPE *n;

	for (i = 0; i < sizeof(testdata) / sizeof(testdata[0]); i++) {
		if ((n = malloc(sizeof(struct TYPE))) == NULL)
			err(1, NULL);
		n->i = testdata[i];
		RB_INSERT(HEADNAME, &head, n);
	}

	RB_FOREACH(n, HEADNAME, &head) {
		printf("%d\n", n->i);
	}
	print_tree(RB_ROOT(&head));
	printf("\n");
	return (0);
}

HISTORIQUE

Les macros d'arbre ont été introduites dans FreeBSD 4.6.

NOTES

L'erreur courante suivante consiste à essayer de libérer un arbre de la manière suivante :

SPLAY_FOREACH(var, NAME, &head) {
	SPLAY_REMOVE(NAME, &head, var);
	free(var);
}
free(head);

Comme var est libéré, la macro FOREACH fait référence à un pointeur qui a pu être réalloué. Le code correct nécessite une variable supplémentaire.

for (var = SPLAY_MIN(NAME, &head); var != NULL; var = nxt) {
	nxt = SPLAY_NEXT(NAME, &head, var);
	SPLAY_REMOVE(NAME, &head, var);
	free(var);
}
