val create : ?runtime_begin:(int -> Runtime_events.Timestamp.t -> Runtime_events.runtime_phase -> unit) -> ?runtime_end:(int -> Runtime_events.Timestamp.t -> Runtime_events.runtime_phase -> unit) -> ?runtime_counter:(int -> Runtime_events.Timestamp.t -> Runtime_events.runtime_counter -> int -> unit) -> ?alloc:(int -> Runtime_events.Timestamp.t -> int array -> unit) -> ?lifecycle:(int -> Runtime_events.Timestamp.t -> Runtime_events.lifecycle -> int option -> unit) -> ?lost_events:(int -> int -> unit) -> unit -> t

Crée un Callback qui s'abonne éventuellement à un ou plusieurs événements d'exécution. Le premier entier fourni aux rappels est l'index du tampon circulaire. Chaque domaine possède un unique tampon circulaire pour la durée de son existence. Après la terminaison d'un domaine, un nouveau domaine peut prendre possession du tampon circulaire. Un rappel runtime_begin est appelé lorsque le runtime entre dans une nouvelle phase (par exemple, un runtime_begin avec EV_MINOR est appelé au début d'un GC mineur). Un rappel runtime_end est appelé lorsque le runtime quitte une certaine phase. Le rappel runtime_counter est appelé lorsqu'un compteur est émis par le runtime. Les rappels lifecycle sont appelés lorsque le tampon subit un changement de cycle de vie et qu'un consommateur peut avoir besoin de répondre. Les rappels alloc sont actuellement uniquement appelés sur le runtime instrumenté. Les rappels lost_events sont appelés si le code consommateur détecte que des événements non consommés ont été écrasés.

val add_user_event : 'a Runtime_events.Type.t -> (int -> Runtime_events.Timestamp.t -> 'a Runtime_events.User.t -> 'a -> unit) -> t -> t

add_user_event ty callback t étend t pour s'abonner en plus aux événements utilisateur de type ty. Lorsque un tel événement se produit, callback est appelé avec l'événement et la charge utile correspondants.
