DESCRIPTION

These macros define data structures for different kinds of trees: splay trees and red-black trees.

In the macro definitions, TYPE is the tag of a user-defined structure that must contain a field named FIELD of type SPLAY_ENTRY or RB_ENTRY. The argument HEADNAME is the tag of a user-defined structure that must be declared using the SPLAY_HEAD() or RB_HEAD() macros. The argument NAME has to be a unique prefix name for each tree defined.

Function prototypes are declared with SPLAY_PROTOTYPE, RB_PROTOTYPE or RB_PROTOTYPE_STATIC. Functions are generated with SPLAY_GENERATE, RB_GENERATE or RB_GENERATE_STATIC. Let's look at the examples below for a more detailed explanation of how these macros are used.

SPLAY TREES

A splay tree is a self-balancing data structure. Every operation on the tree causes a splay. The splay moves the requested node to the root of the tree and partially rebalances the tree.

This has the benefit that locality of requests leads to faster queries since requested nodes are moved to the top of the tree. On the other hand, every query causes writes to memory.

The Amortized Balance Theorem bounds the total access time for m operations and n insertions into an initially empty tree as O((m + n)lg n). The amortized cost of m accesses to a splay tree is O(lg n).

A splay tree is headed by a structure defined by the SPLAY_HEAD() macro. A SPLAY_HEAD structure is declared as follows:

SPLAY_HEAD(HEADNAME, TYPE) head;

where HEADNAME is the name of the structure to be defined, and TYPE is the type of the elements to be inserted into the tree.

The SPLAY_ENTRY macro declares a structure that allows elements to be linked in the tree.

To use the functions that manipulate the tree structure, their prototypes must be declared with the SPLAY_PROTOTYPE macro where NAME is a unique identifier for this particular tree. The TYPE argument is the type of the structure managing the tree. The FIELD argument is the name of the element defined by SPLAY_ENTRY).

The functions are generated with the SPLAY_GENERATE macro. It takes the same arguments as the SPLAY_PROTOTYPE macro but should be used only once.

Finally, the CMP argument is the name of a function that compares tree nodes with each other. The function takes two arguments of type struct TYPE *. If the first argument is less than the second, it returns a value less than zero. If they are equal, it returns zero. Otherwise, it must return a value greater than zero. The comparison function defines the order of elements in the tree.

The SPLAY_INIT macro initializes the tree referenced by head.

The splay tree can also be initialized statically using the SPLAY_INITIALIZER macro like this:

SPLAY_HEAD(HEADNAME, TYPE) head = SPLAY_INITIALIZER(&head);

The SPLAY_INSERT macro inserts the new element elm into the tree. If the insertion is successful, it returns NULL. If a matching element already exists in the tree, the insertion is aborted and a pointer to the existing element is returned.

The SPLAY_REMOVE macro removes the element elm from the tree pointed to by head. If the removal is successful, a pointer to the removed element is returned. If elm does not exist in the tree, NULL is returned.

The SPLAY_FIND macro can be used to find a specific element in the tree.

struct TYPE find, *res;
find.key = 30;
res = SPLAY_FIND(NAME, &head, &find);

The SPLAY_ROOT, SPLAY_MIN, SPLAY_MAX, and SPLAY_NEXT macros can be used to traverse the tree:

for (np = SPLAY_MIN(NAME, &head); np != NULL; np = SPLAY_NEXT(NAME, &head, np))

Or, for simplicity, the SPLAY_FOREACH macro can be used:

SPLAY_FOREACH(np, NAME, &head)

The SPLAY_EMPTY macro should be used to check if a splay tree is empty.

RED-BLACK TREES

A red-black tree is a binary search tree with node color as an additional property. It fulfills a number of conditions:

  1. Every path from the root to a leaf node contains the same number of black nodes.
  2. Every red node (except the root) has a black parent.
  3. Every leaf node is black.

Every operation on a red-black tree is bounded as O(lg n). The maximum height of a red-black tree is 2lg(n+1).

A red-black tree is headed by a structure defined by the RB_HEAD macro. An RB_HEAD structure is declared as follows:

RB_HEAD(HEADNAME, TYPE) head;

where HEADNAME is the name of the structure to be defined, and TYPE is the type of the elements to be inserted into the tree.

The RB_ENTRY macro declares a structure that allows elements to be linked in the tree.

To use the functions that manipulate the tree structure, their prototypes must be declared with the RB_PROTOTYPE or RB_PROTOTYPE_STATIC macros, where NAME is a unique identifier for this particular tree. The TYPE argument is the type of the structure managing the tree. The FIELD argument is the name of the element defined by RB_ENTRY).

The functions are generated with the RB_GENERATE or RB_GENERATE_STATIC macros, which take the same arguments as the RB_PROTOTYPE and RB_PROTOTYP

DESCRIPTION

These macros maintain a red-black tree. They are modeled after the same macros found in the NetBSD operating system.

A red-black tree is a binary search tree that uses node coloring to ensure that the tree remains approximately balanced, guaranteeing O(log n) performance for search, insertion, and deletion operations.

The macros require the user to define a structure for the tree nodes and to provide a comparison function. The tree structure itself is defined using RB_HEAD and related macros. The tree nodes must contain a field of type RB_ENTRY(TYPE), where TYPE is the name of the structure.

The RB_HEAD macro declares a structure that will serve as the root of the red-black tree. The first argument, HEADNAME, is the name to be given to the tree head structure. The second argument, TYPE, is the name of the structure that will be used for the tree nodes.

The RB_PROTOTYPE macro should be used in header files to declare the functions that RB_GENERATE will create. The first argument, HEADNAME, is the name of the tree head structure. The second argument, TYPE, is the name of the structure used for the nodes. The third argument, field, is the name of the RB_ENTRY field within the TYPE structure. The fourth argument, CMP, is the name of the comparison function.

The RB_GENERATE macro should be used in one source file to generate the actual tree functions. The arguments are the same as for RB_PROTOTYPE. Note that RB_PROTOTYPE and RB_GENERATE should be called with the same arguments. Both macros must be used only once.

Finally, the CMP argument is the name of a function used to compare trees' nodes with each other. The function takes two arguments of type struct TYPE *. If the first argument is smaller than the second, the function returns a value smaller than zero. If they are equal, the function returns zero. Otherwise, it should return a value greater than zero. The compare function defines the order of the tree elements.

The RB_INIT() macro initializes the tree referenced by head.

The red-black tree can also be initialized statically by using the RB_INITIALIZER() macro like this:

RB_HEAD(HEADNAME, TYPE) head = RB_INITIALIZER(&head);

The RB_INSERT() macro inserts the new element elm into the tree. Upon success, NULL is returned. If a matching element already exists in the tree, the insertion is aborted, and a pointer to the existing element is returned.

The RB_REMOVE() macro removes the element elm from the tree pointed by head. RB_REMOVE() returns elm.

The RB_FIND() and RB_NFIND() macros can be used to find a particular element in the tree. RB_FIND() finds the node with the same key as elm. RB_NFIND() finds the first node greater than or equal to the search key.

struct TYPE find, *res;
find.key = 30;
res = RB_FIND(NAME, &head, &find);

The RB_ROOT(), RB_MIN(), RB_MAX(), RB_NEXT(), and RB_PREV() macros can be used to traverse the tree:

for (np = RB_MIN(NAME, &head); np != NULL; np = RB_NEXT(NAME, &head, np))

Or, for simplicity, one can use the RB_FOREACH() or RB_FOREACH_REVERSE() macros:

RB_FOREACH(np, NAME, &head)

The macros RB_FOREACH_SAFE() and RB_FOREACH_REVERSE_SAFE() traverse the tree referenced by head in a forward or reverse direction respectively, assigning each element in turn to np. However, unlike their unsafe counterparts, they permit both the removal of np as well as freeing it from within the loop safely without interfering with the traversal.

The RB_EMPTY() macro should be used to check whether a red-black tree is empty.

EXAMPLES

The following example demonstrates how to declare a red-black tree holding integers. Values are inserted into it and the contents of the tree are printed in order. Lastly, the internal structure of the tree is printed.

#include <sys/tree.h>
#include <err.h>
#include <stdio.h>
#include <stdlib.h>

struct node {
	RB_ENTRY(node) entry;
	int i;
};

int	intcmp(struct node *, struct node *);
void	print_tree(struct node *);

int
intcmp(struct node *e1, struct node *e2)
{
	return (e1->i < e2->i ? -1 : e1->i > e2->i);
}

RB_HEAD(inttree, node) head = RB_INITIALIZER(&head);
RB_PROTOTYPE(inttree, node, entry, intcmp)
RB_GENERATE(inttree, node, entry, intcmp)

int testdata[] = {
	20, 16, 17, 13, 3, 6, 1, 8, 2, 4, 10, 19, 5, 9, 12, 15, 18,
	7, 11, 14
};

void
print_tree(struct node *n)
{
	struct node *left, *right;

	if (n == NULL) {
		printf("nil");
		return;
	}
	left = RB_LEFT(n, entry);
	right = RB_RIGHT(n, entry);
	if (left == NULL && right == NULL)
		printf("%d", n->i);
	else {
		printf("%d(", n->i);
		print_tree(left);
		printf(",");
		print_tree(right);
		printf(")");
	}
}

int
main(void)
{
	int i;
	struct node *n;

	for (i = 0; i < sizeof(testdata) / sizeof(testdata[0]); i++) {
		if ((n = malloc(sizeof(struct node))) == NULL)
			err(1, NULL);
		n->i = testdata[i];
		RB_INSERT(inttree, &head, n);
	}

	RB_FOREACH(n, inttree, &head) {
		printf("%d\n", n->i);
	}
	print_tree(RB_ROOT(&head));
	printf("\n");
	return (0);
}

NOTES

Trying to free a tree in the following way is a common error:

SPLAY_FOREACH(var, NAME, &head) {
	SPLAY_REMOVE(NAME, &head, var);
	free(var);
}
free(head);

Since var is free'd, the FOREACH() macro refers to a pointer that may have been reallocated already. Proper code needs a second variable.

for (var = SPLAY_MIN(NAME, &head); var != NULL; var = nxt) {
	nxt = SPLAY_NEXT(NAME, &head, var);
	SPLAY_REMOVE(NAME, &head, var);
	free(var);
}
