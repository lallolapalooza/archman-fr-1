RSA_check_key(3ssl)

Paquet: openssl

Licences: Apache-2.0

RSA_CHECK_KEY(3ssl) OpenSSL RSA_CHECK_KEY(3ssl)

NOM

RSA_CHECK_KEY_EX, RSA_CHECK_KEY - valider les clés RSA privées

SYNTAXE

#include <openssl/rsa.h>

Les fonctions suivantes ont été dépréciées depuis OpenSSL 3.0, et peuvent être entièrement masquées en définissant OPENSSL_API_COMPAT avec une valeur de version appropriée, voir openssl_user_macros(7) :

int RSA_check_key_ex(const RSA *rsa, BN_GENCB *cb);
int RSA_check_key(const RSA *rsa);

DESCRIPTION

Les deux fonctions décrites sur cette page sont dépréciées. Les applications devraient plutôt utiliser EVP_PKEY_public_check(3), EVP_PKEY_private_check(3) et EVP_PKEY_pairwise_check(3).

La fonction RSA_check_key_ex() valide les clés RSA. Elle vérifie que p et q sont bien premiers, et que n = p*q.

Elle ne fonctionne pas sur les clés publiques RSA dont seuls le module et l'exposant public sont renseignés. Elle vérifie également que d*e = 1 mod (p-1*q-1), et que dmp1, dmq1 et iqmp sont correctement définis ou sont NULL. Elle effectue des vérifications d'intégrité sur tout le matériel de clé RSA, de sorte que la structure RSA doit contenir toutes les données de clé privée également. Par conséquent, elle ne peut pas être utilisée avec un objet de clé RSA arbitraire, même s'il est sinon adapté aux opérations RSA régulières.

Le paramètre cb est une fonction de rappel qui sera appelée de la même manière que BN_is_prime_ex(3).

RSA_check_key() est équivalent à RSA_check_key_ex() avec un cb égal à NULL.

VALEURS DE RETOUR

RSA_check_key_ex() et RSA_check_key() renvoient 1 si rsa est une clé RSA valide, et 0 sinon. Elles renvoient -1 si une erreur se produit lors de la vérification de la clé.

Si la clé est invalide ou si une erreur s'est produite, le code d'erreur peut être obtenu en utilisant ERR_get_error(3).

NOTES

Contrairement à la plupart des autres fonctions RSA, cette fonction ne fonctionne pas de manière transparente avec aucune implémentation ENGINE sous-jacente car elle utilise directement les données de clé dans la structure RSA. Une implémentation ENGINE peut remplacer la façon dont les données de clé sont stockées et gérées, et peut même fournir un support pour les clés HSM - auquel cas la structure RSA peut ne contenir aucune donnée de clé du tout ! Si l'ENGINE en question n'est utilisé qu'à des fins d'accélération ou d'analyse, alors dans tous les cas les données de clé RSA sont complètes et intactes, mais cela ne peut pas être supposé dans le cas général.

BOGUES

Une méthode de vérification de la clé RSA utilisant des fonctions API RSA opaques pourrait nécessiter d'être examinée. Actuellement, RSA_check_key() utilise simplement les éléments de la structure RSA directement, en contournant la table RSA_METHOD (et en violant complètement l'encapsulation et l'orientation objet dans le processus). La meilleure solution consisterait probablement à introduire un gestionnaire "check_key()" dans la table des fonctions RSA_METHOD afin que les implémentations alternatives puissent également fournir leurs propres vérificateurs.

VOIR AUSSI

BN_is_prime_ex(3), ERR_get_error(3)

HISTORIQUE

Toutes ces fonctions ont été dépréciées dans OpenSSL 3.0.

RSA_check_key_ex() est apparue après OpenSSL 1.0.2.
