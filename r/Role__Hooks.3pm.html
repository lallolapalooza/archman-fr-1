Role::Hooks(3) Documentation Perl fournie par l'utilisateur Role::Hooks(3)

NOM

Role::Hooks - rappels de rôle

SYNOPSIS

package Local::Role {
  use Moo::Role;
  use Role::Hooks;

  Role::Hooks->after_apply(__PACKAGE__, sub {
    my ($role, $target) = @_;
    print "$role a été appliqué à $target.\n";
  });
}

package Local::Class {
  use Moo;
  with "Local::Role";   # imprime le message ci-dessus
}

DESCRIPTION

Ce module permet à un rôle d'exécuter un rappel lorsqu'il est appliqué à une classe ou à un autre rôle.

Compatibilité

Il devrait fonctionner avec Role::Tiny, Moo::Role, Moose::Role, Mouse::Role, Role::Basic et Mite. Tous les constructeurs de classe ne fonctionnent pas bien avec tous les constructeurs de rôle (par exemple, une classe Moose consommant un rôle Mouse). Mais lorsqu'ils fonctionnent ensemble, Role::Hooks devrait pouvoir exécuter les rappels.

(La seule combinaison que j'ai testée est Moo avec Moose).

D'autres implémentations de rôle (telles que Moos::Role, exact::role et OX::Role) ne sont que des wrappers autour d'un des constructeurs de rôle pris en charge, elles devraient donc fonctionner en grande partie.

Avec Role::Basic, le crochet "after_apply" est appelé un peu plus tôt que prévu ; après que le rôle a été complètement chargé et que ses méthodes ont été copiées dans le package cible, mais avant de gérer "requires" et avant de patcher la méthode "DOES" dans le package cible. Si vous utilisez Role::Basic, envisagez de passer à Role::Tiny.

Avec Mite, le crochet "before_apply" est appelé assez tard ; après que le rôle est complètement chargé et que les attributs et méthodes ont été copiés dans le package cible, après que "DOES" a été patché, mais avant que les modificateurs de méthode du rôle n'aient été appliqués au package cible.

Outre Role::Tiny/Moo::Role, un hashref d'arguments supplémentaires (choses comme "-excludes" et "-alias") peut être passé lors de la consommation d'un rôle. Bien que je décourage les gens d'utiliser ceux-ci en général, si vous avez besoin d'accéder à ces arguments dans le rappel, vous pouvez vérifier %Role::Hooks::ARGS.

Les rôles générés via Package::Variant devraient fonctionner ; voir t/20packagevariant.t pour une démonstration.

Méthodes

"before_apply"
Role::Hooks->before_apply($rolename, $callback);

Configure un rappel pour un rôle qui sera appelé avant que le rôle ne soit appliqué à un package cible. Le rappel recevra deux paramètres : le rôle appliqué et le package cible.

Le rôle appliqué peut ne pas être le même rôle que celui dans lequel le rappel a été défini !

package Local::Role1 {
  use Moo::Role;
  use Role::Hooks;
  Role::Hooks->before_apply(__PACKAGE__, sub {
    my ($role, $target) = @_;
    print "$role a été appliqué à $target.\n";
  });
}

package Local::Role2 {
  use Moo::Role;
  with "Local::Role1";
}

package Local::Class1 {
  use Moo::Role;
  with "Local::Role2";
}

Cela imprimera :

Local::Role1 a été appliqué à Local::Role2.
Local::Role2 a été appliqué à Local::Class1.

Si vous ne vous souciez que des applications directes de rôles (c'est-à-dire la première) :

Role::Hooks->before_apply(__PACKAGE__, sub {
  my ($role, $target) = @_;
  return if $role ne __PACKAGE__;
  print "$role a été appliqué à $target.\n";
});

Si vous ne vous souciez que des rôles appliqués à des classes (c'est-à-dire la seconde) :

Role::Hooks->before_apply(__PACKAGE__, sub {
  my ($role, $target) = @_;
  return if Role::Hooks->is_role($target);
  print "$role a été appliqué à $target.\n";
});
"after_apply"
Role::Hooks->after_apply($rolename, $callback);

Identique à "before_apply", mais appelé plus tard dans le processus d'application du rôle.

Notez que lorsque le rappel est appelé, même s'il est après que le rôle ait été appliqué à la cible, cela ne signifie pas que la cible a fini d'être construite. Par exemple, il peut y avoir des déclarations "has" après la déclaration "with", et celles-ci n'auront pas encore été évaluées.

Si vous voulez générer une erreur lorsque quelqu'un applique votre rôle à une cible inappropriée, il est probablement préférable de le faire dans "before_apply" si vous le pouvez.

"after_inflate"
Role::Hooks->after_inflate($pkg_name, $callback);

Même si cela fait partie de Role::Hooks, cela fonctionne aussi sur les classes. Mais cela ne fonctionne que sur les classes et les rôles construits avec Moo. Cela exécute votre rappel si votre classe ou rôle Moo est "gonflé" en une classe ou rôle Moose.

Si vous configurez un rappel pour un rôle, alors le rappel sera également appelé si les packages auxquels ce rôle a été appliqué sont gonflés.

"is_role"
Retournera vrai si le package donné semble être un rôle, faux sinon.

(En fait, renvoie une chaîne représentant quel constructeur de rôle le rôle semble utiliser -- "Role::Tiny", "Moose::Role", "Mouse::Role", "Role::Basic" ou "Mite::Role" ; les rôles construits avec Moo::Role sont détectés comme "Role::Tiny".)

ENVIRONNEMENT

La variable d'environnement "PERL_ROLE_HOOKS_DEBUG" peut être définie à vrai pour activer les messages de débogage.
