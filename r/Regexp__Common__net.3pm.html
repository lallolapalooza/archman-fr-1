NOM

Regexp::Common::net -- fournit des regex pour les adresses IPv4, IPv6 et MAC.

SYNOPSIS

use Regexp::Common qw /net/;
while (<>) {
    /$RE{net}{IPv4}/       and print "Adresse IP décimale pointée";
    /$RE{net}{IPv4}{hex}/  and print "Adresse IP hexadécimale pointée";
    /$RE{net}{IPv4}{oct}{-sep => ':'}/ and
                           print "Adresse IP octale séparée par des deux-points";
    /$RE{net}{IPv4}{bin}/  and print "Adresse IP binaire pointée";
    /$RE{net}{MAC}/        and print "Adresse MAC";
    /$RE{net}{MAC}{oct}{-sep => " "}/ and
                           print "Adresse MAC octale séparée par des espaces";
}

DESCRIPTION

Veuillez consulter le manuel de Regexp::Common pour une description générale du fonctionnement de cette interface.

N'utilisez pas ce module directement, mais chargez-le via Regexp::Common.

Ce module vous fournit des expressions régulières pour différents styles d'adresses IPv4, IPv6 et MAC (ou Ethernet).

"$RE{net}{IPv4}"

Retourne un modèle qui correspond à une adresse IP valide en « décimal pointé ». Notez que bien que 318.99.183.11 ne soit pas une adresse IP valide, elle correspond à "/$RE{net}{IPv4}/", mais c'est parce que 318.99.183.11 contient une adresse IP valide, à savoir 18.99.183.11. Pour éviter les correspondances indésirables, il faut ancrer la regexp : "/^$RE{net}{IPv4}$/".

Pour ce modèle et les quatre suivants, avec l'option "-keep" (Voir Regexp::Common) :

$1
capture la correspondance entière
$2
capture le premier composant de l'adresse
$3
capture le deuxième composant de l'adresse
$4
capture le troisième composant de l'adresse
$5
capture le dernier composant de l'adresse

"$RE{net}{IPv4}{dec}{-sep}"

Retourne un modèle qui correspond à une adresse IP valide en « décimal pointé ». Les zéros en tête sont autorisés, tant que chaque composant ne dépasse pas 3 chiffres.

Si "-sep=P" est spécifié, le modèle P est utilisé comme séparateur. Par défaut, P est "qr/[.]/".

"$RE{net}{IPv4}{strict}{-sep}"

Retourne un modèle qui correspond à une adresse IP valide en « décimal pointé », mais refuse les zéros en tête.

Si "-sep=P" est spécifié, le modèle P est utilisé comme séparateur. Par défaut, P est "qr/[.]/".

"$RE{net}{IPv4}{hex}{-sep}"

Retourne un modèle qui correspond à une adresse IP valide en « hexadécimal pointé », avec les lettres "A" à "F" en majuscules.

Si "-sep=P" est spécifié, le modèle P est utilisé comme séparateur. Par défaut, P est "qr/[.]/". "-sep=""" et "-sep=" "" sont des alternatives utiles.

"$RE{net}{IPv4}{oct}{-sep}"

Retourne un modèle qui correspond à une adresse IP valide en « octal pointé ».

Si "-sep=P" est spécifié, le modèle P est utilisé comme séparateur. Par défaut, P est "qr/[.]/".

"$RE{net}{IPv4}{bin}{-sep}"

Retourne un modèle qui correspond à une adresse IP valide en « binaire pointé ».

Si "-sep=P" est spécifié, le modèle P est utilisé comme séparateur. Par défaut, P est "qr/[.]/".

"$RE{net}{MAC}"

Retourne un modèle qui correspond à une adresse MAC ou Ethernet valide sous forme d'hexadécimaux séparés par des deux-points.

Pour ce modèle et les quatre suivants, avec l'option "-keep" (Voir Regexp::Common) :

Ce modèle, et les quatre suivants, ont également une méthode "subs", qui transformera une adresse MAC correspondante en un format dit canonique. Le format canonique signifie que chaque composant de l'adresse sera exactement constitué de deux hexadécimaux (avec un zéro en tête si nécessaire), et les composants seront séparés par un deux-points.

"$RE{net}{MAC}{dec}{-sep}"

Retourne un modèle qui correspond à une adresse MAC valide sous forme de décimaux séparés par des deux-points.

Si "-sep=P" est spécifié, le modèle P est utilisé comme séparateur. Par défaut, P est "qr/:/".

"$RE{net}{MAC}{hex}{-sep}"

Retourne un modèle qui correspond à une adresse MAC valide sous forme d'hexadécimaux séparés par des deux-points, avec les lettres "a" à "f" en minuscules.

Si "-sep=P" est spécifié, le modèle P est utilisé comme séparateur. Par défaut, P est "qr/:/".

"$RE{net}{MAC}{oct}{-sep}"

Retourne un modèle qui correspond à une adresse MAC valide sous forme d'octals séparés par des deux-points.

Si "-sep=P" est spécifié, le modèle P est utilisé comme séparateur. Par défaut, P est "qr/:/".

"$RE{net}{MAC}{bin}{-sep}"

Retourne un modèle qui correspond à une adresse MAC valide sous forme de nombres binaires séparés par des deux-points.

Si "-sep=P" est spécifié, le modèle P est utilisé comme séparateur. Par défaut, P est "qr/:/".

"$RE{net}{IPv6}{-sep_=> ':'}{-style_=> 'HeX'}"

Retourne un modèle qui correspond à une adresse IPv6.

Les options suivantes sont disponibles :

{-sep => P}
Permet de spécifier le motif P à utiliser comme séparateur. Par défaut, c'est "qr/:/".
{-style => S}
Permet de spécifier le style de l'adresse IPv6. Les styles supportés sont "HeX" (par défaut) et "short". Le style "HeX" correspond aux nombres hexadécimaux avec les lettres capitalisées, tandis que le style "short" permet l'utilisation des doubles deux-points pour raccourcir l'adresse (par exemple, ::1).

NOM

Regexp::Common::net - Expressions régulières pour les adresses IP, les noms de domaine, etc.

SYNOPSIS

  use Regexp::Common;
  # ...
  $string =~ /$RE{net}{IPv6}{-keep}/;
  # ...
  $string =~ /$RE{net}{domain}/;

DESCRIPTION

Ce module fournit des expressions régulières courantes pour les éléments réseau.

"$RE{net}{IPv6}"

Retourne un motif correspondant aux nombres IPv6. Une adresse IPv6 se compose de huit groupes de quatre chiffres hexadécimaux, séparés par des deux-points. Dans chaque groupe, les zéros non significatifs peuvent être omis. Deux groupes consécutifs ou plus composés uniquement de zéros peuvent être omis (y compris les deux-points qui les séparent), résultant en deux ensembles de groupes, séparés par un double deux-points. (Chacun des groupes peut être vide; "::" est une adresse valide, équivalente à "0000:0000:0000:0000:0000:0000:0000:0000"). Les nombres hexadécimaux peuvent être en majuscules ou minuscules.

Si l'option "-sep" est utilisée, son argument est un motif qui correspond au séparateur séparant les groupes. Ceci vaut par défaut ":". L'option "-style" est utilisée pour spécifier la casse des nombres hexadécimaux autorisés. Le style par défaut, 'HeX', indique que les lettres minuscules 'a' à 'f' et les lettres majuscules 'A' à 'F' seront correspondantes. Le style 'HEX' limite la correspondance aux lettres majuscules, et 'hex' correspond uniquement aux lettres minuscules.

Si "{-keep}" est utilisé, $1 à $9 seront définis. $1 sera défini avec l'adresse correspondante, tandis que $2 à $9 seront définis avec chaque groupe correspondant. Si un groupe est omis car il contient tous des zéros, sa variable correspondante sera la chaîne vide.

Exemple :

"2001:db8:85a3::8a2e:370:7334" =~ /$RE{net}{IPv6}{-keep}/;
print $2;    # '2001'
print $4;    # '85a3'
print $6;    # Chaîne vide
print $8;    # '370'

Perl 5.10 (ou ultérieur) est requis pour ce motif.

"$RE{net}{domain}"

Retourne un motif pour correspondre aux domaines (et hôtes) tels que définis dans la RFC 1035. Sous {-keep} seul le nom de domaine entier est retourné.

La RFC 1035 stipule qu'un seul espace peut également être un nom de domaine. Ainsi, le motif retourné par "$RE{net}{domain}" reconnaît un seul espace. Ce n'est pas toujours ce que les gens souhaitent. Si vous voulez reconnaître des noms de domaine, mais pas un espace, vous pouvez faire l'une des deux choses suivantes : soit utiliser

/(?! )$RE{net}{domain}/

soit utiliser l'option "{-nospace}" (sans argument).

La RFC 1035 n'autorise pas les noms d'hôtes ou de domaines à commencer par un chiffre ; cependant, cette restriction est assouplie dans la RFC 1101 ; cette RFC autorise les noms d'hôtes et de domaines à commencer par un chiffre, à condition que la première partie d'un domaine ne ressemble pas à une adresse IP. Si l'option "{-rfc1101}" est donnée (comme dans "$RE{net}{domain}{-rfc1101}"), nous ferons la correspondance en utilisant les règles assouplies.

RÉFÉRENCES

RFC 1035
Mockapetris, P.: DOMAIN NAMES - IMPLEMENTATION AND SPECIFICATION. Novembre 1987.
RFC 1101
Mockapetris, P.: DNS Encoding of Network Names and Other Types. Avril 1987.
