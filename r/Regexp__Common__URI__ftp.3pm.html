NOM

Regexp::Common::URI::ftp -- Renvoie un modèle pour les URI FTP.

SYNTAXE

use Regexp::Common qw /URI/;
while (<>) {
    /$RE{URI}{FTP}/       and  print "Contient un URI FTP.\n";
}

DESCRIPTION

$RE{URI}{FTP}{-type}{-password};

Renvoie une expression régulière pour les URI FTP. Note : Les URI FTP ne sont pas formellement définis. La RFC 1738 définit les URL FTP, mais des parties de cette RFC ont été obsolètes par la RFC 2396. Cependant, les différences entre la RFC 1738 et la RFC 2396 sont telles qu'elles ne s'appliquent pas directement aux URI FTP.

Il y a deux problèmes principaux :

Mots de passe.
La RFC 1738 autorisait un nom d'utilisateur optionnel et un mot de passe optionnel (séparés par un deux-points) dans l'URL FTP. Par conséquent, les deux-points n'étaient pas autorisés dans le nom d'utilisateur ni dans le mot de passe. La RFC 2396 déconseille fortement l'utilisation de mots de passe dans les URI. Elle autorise l'utilisation d'une userinfo à la place. Cette partie userinfo peut contenir des deux-points, et donc plusieurs deux-points. L'expression régulière renvoyée suit la spécification de la RFC 2396, sauf si l'option {-password} est donnée ; dans ce cas, l'expression régulière autorise un nom d'utilisateur et un mot de passe optionnels, séparés par un deux-points.
Le spécificateur ;type.
La RFC 1738 n'autorise pas les points-virgules dans les noms de chemins FTP, car le point-virgule est un caractère réservé pour les URI FTP. Le point-virgule est utilisé pour séparer le chemin du spécificateur d'option type. Cependant, dans la RFC 2396, les chemins sont composés de segments séparés par des barres obliques, et chaque segment est un groupe de paramètres séparés par des points-virgules. Une application directe de la RFC 2396 signifierait qu'un spécificateur type final ne pourrait pas être distingué du dernier segment du chemin ayant deux paramètres, le dernier commençant par type=. Par conséquent, nous avons choisi de ne pas autoriser de point-virgule dans la partie chemin d'un URI FTP.

De plus, la RFC 1738 autorise trois valeurs pour le spécificateur type, A, I et D (en majuscules ou minuscules). Cependant, le brouillon internet sur les URI FTP [DRAFT-FTP-URL] (qui a expiré en mai 1997) note le manque d'implémentation cohérente du paramètre D et supprime D de l'ensemble des valeurs possibles. Nous suivons cette pratique ; cependant, le comportement de la RFC 1738 peut être obtenu en utilisant le paramètre -type = "[ADIadi]".

Les URI FTP ont la syntaxe suivante :

"ftp:" "//" [ userinfo "@" ] host [ ":" port ]
            [ "/" path [ ";type=" value ]]

Lors de l'utilisation de {-password}, nous avons la syntaxe :

"ftp:" "//" [ user [ ":" password ] "@" ] host [ ":" port ]
            [ "/" path [ ";type=" value ]]

Sous "{-keep}", les éléments suivants sont renvoyés :

$1
L'URI complet.
$2
Le schéma.
$3
La userinfo, ou si {-password} est utilisée, le nom d'utilisateur.
$4
Si {-password} est utilisée, le mot de passe, sinon "undef".
$5
Le nom d'hôte ou l'adresse IP.
$6
Le numéro de port.
$7
Le chemin complet et la spécification de type, y compris la barre oblique initiale.
$8
Le chemin complet et la spécification de type, sans la barre oblique initiale.
$9
Le chemin complet, sans la spécification de type ni la barre oblique initiale.
$10
La valeur de la spécification de type.
