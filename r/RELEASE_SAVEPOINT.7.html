RELEASE SAVEPOINT(7) Documentation PostgreSQL 18.1 RELEASE SAVEPOINT(7)

NOM

RELEASE SAVEPOINT - libère un point de sauvegarde précédemment défini

SYNTAXE

RELEASE [ SAVEPOINT ] nom_point_sauvegarde

DESCRIPTION

RELEASE SAVEPOINT libère le point de sauvegarde nommé et tous les points de sauvegarde actifs qui ont été créés après le point de sauvegarde nommé, et libère leurs ressources. Toutes les modifications apportées depuis la création du point de sauvegarde qui n'ont pas déjà été annulées sont fusionnées dans la transaction ou le point de sauvegarde qui était actif lorsque le point de sauvegarde nommé a été créé. Les modifications apportées après RELEASE SAVEPOINT feront également partie de cette transaction ou de ce point de sauvegarde actif.

PARAMETRES

nom_point_sauvegarde

Le nom du point de sauvegarde à libérer.

NOTES

Spécifier un nom de point de sauvegarde qui n'a pas été défini précédemment est une erreur.

Il n'est pas possible de libérer un point de sauvegarde lorsque la transaction est dans un état abandonné ; pour ce faire, utilisez ROLLBACK TO SAVEPOINT (ROLLBACK_TO_SAVEPOINT(7)).

Si plusieurs points de sauvegarde portent le même nom, seul le plus récemment défini et non libéré est libéré. Des commandes répétées libéreront progressivement les points de sauvegarde plus anciens.

EXEMPLES

Pour établir puis libérer un point de sauvegarde :

BEGIN;
    INSERT INTO table1 VALUES (3);
    SAVEPOINT my_savepoint;
    INSERT INTO table1 VALUES (4);
    RELEASE SAVEPOINT my_savepoint;
COMMIT;

La transaction ci-dessus insérera à la fois 3 et 4.

Un exemple plus complexe avec plusieurs sous-transactions imbriquées :

BEGIN;
    INSERT INTO table1 VALUES (1);
    SAVEPOINT sp1;
    INSERT INTO table1 VALUES (2);
    SAVEPOINT sp2;
    INSERT INTO table1 VALUES (3);
    RELEASE SAVEPOINT sp2;
    INSERT INTO table1 VALUES (4))); -- génère une erreur

Dans cet exemple, l'application demande la libération du point de sauvegarde sp2, qui a inséré 3. Cela change le contexte de transaction de l'insertion à sp1. Lorsque l'instruction tentant d'insérer la valeur 4 génère une erreur, les insertions des valeurs 2 et 4 sont perdues car elles sont dans le même point de sauvegarde, maintenant annulé, et la valeur 3 est dans le même contexte de transaction. L'application ne peut maintenant choisir qu'une de ces deux commandes, car toutes les autres commandes seront ignorées :

ROLLBACK;
ROLLBACK TO SAVEPOINT sp1;

Choisir ROLLBACK annulera tout, y compris la valeur 1, tandis que ROLLBACK TO SAVEPOINT sp1 conservera la valeur 1 et permettra à la transaction de continuer.

COMPATIBILITE

Cette commande est conforme à la norme SQL. La norme spécifie que le mot-clé SAVEPOINT est obligatoire, mais PostgreSQL permet de l'omettre.

VOIR AUSSI
