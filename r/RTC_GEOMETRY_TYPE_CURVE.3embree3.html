DESCRIPTION

Les courbes avec des rayons par sommet sont supportées avec des bases linéaires, de Bézier cubique, de B-spline cubique et d'Hermite cubique. Ces géométries de courbe sont créées en passant les valeurs suivantes à la fonction rtcNewGeometry: RTC_GEOMETRY_TYPE_FLAT_LINEAR_CURVE, RTC_GEOMETRY_TYPE_FLAT_BEZIER_CURVE, RTC_GEOMETRY_TYPE_FLAT_BSPLINE_CURVE, RTC_GEOMETRY_TYPE_FLAT_HERMITE_CURVE, RTC_GEOMETRY_TYPE_FLAT_CATMULL_ROM_CURVE, RTC_GEOMETRY_TYPE_NORMAL_ORIENTED_FLAT_BEZIER_CURVE, RTC_GEOMETRY_TYPE_NORMAL_ORIENTED_FLAT_BSPLINE_CURVE, RTC_GEOMETRY_TYPE_NORMAL_ORIENTED_FLAT_HERMITE_CURVE, RTC_GEOMETRY_TYPE_NORMAL_ORIENTED_FLAT_CATMULL_ROM_CURVE, RTC_GEOMETRY_TYPE_CONE_LINEAR_CURVE, RTC_GEOMETRY_TYPE_ROUND_LINEAR_CURVE, RTC_GEOMETRY_TYPE_ROUND_BEZIER_CURVE, RTC_GEOMETRY_TYPE_ROUND_BSPLINE_CURVE, RTC_GEOMETRY_TYPE_ROUND_HERMITE_CURVE, ou RTC_GEOMETRY_TYPE_ROUND_CATMULL_ROM_CURVE. Les indices de la courbe peuvent être spécifiés via un tampon d'index (RTC_BUFFER_TYPE_INDEX) et les sommets de la courbe via un tampon de sommets (RTC_BUFFER_TYPE_VERTEX). Pour la base Hermite, il est nécessaire de spécifier en plus un tampon de tangente (RTC_BUFFER_TYPE_TANGENT), un tampon de normales orientées (RTC_BUFFER_TYPE_NORMAL) pour les courbes orientées par normale, et un tampon de dérivée normale (RTC_BUFFER_TYPE_NORMAL_DERIVATIVE) pour les courbes Hermite orientées par normale. Voir rtcSetGeometryBuffer et rtcSetSharedGeometryBuffer pour plus de détails sur la configuration des tampons.

Le tampon d'index contient un tableau d'indices 32 bits (format RTC_FORMAT_UINT), chacun pointant vers le premier sommet de contrôle dans le tampon de sommets, mais aussi vers la première tangente dans le tampon de tangentes, et vers la première normale dans le tampon de normales si ces tampons sont présents.

Le tampon de sommets stocke chaque sommet de contrôle sous forme de position et de rayon en virgule flottante simple précision au format (x, y, z, r) en mémoire (format RTC_FORMAT_FLOAT4). Le nombre de sommets est déduit de la taille de ce tampon. Les rayons peuvent être inférieurs à zéro, mais les rayons interpolés doivent toujours être supérieurs ou égaux à zéro. De même, le tampon de tangentes stocke la dérivée de chaque sommet de contrôle (au format (x, y, z, r) et RTC_FORMAT_FLOAT4) et le tampon de normales stocke une normale en virgule flottante simple précision par sommet de contrôle (au format (x, y, z) et RTC_FORMAT_FLOAT3).

Base linéaire

Pour la base linéaire, les indices pointent vers le premier de 2 points de contrôle consécutifs dans le tampon de sommets. Le premier point de contrôle est le début et le second point de contrôle est la fin de la ligne. Lors de la construction de mèches de cheveux dans cette base, le point final peut être partagé avec le début de la ligne suivante.

Pour la base linéaire, l'utilisateur peut éventuellement fournir un tampon de drapeaux de type RTC_BUFFER_TYPE_FLAGS contenant des octets indiquant si les segments voisins (RTC_CURVE_FLAG_NEIGHBOR_LEFT et RTC_CURVE_FLAG_NEIGHBOR_RIGHT) existent (voir [RTCCurveFlags]). Si ce tampon n'est pas défini, les bits gauche et droit sont calculés automatiquement en se basant sur le tampon d'index (le segment (id-1) +1 == segment (id) signifie que le segment gauche existe et le segment (id+1)-1 == segment (id) signifie que le segment droit existe).

Un segment voisin gauche est supposé se terminer au sommet de départ du segment actuel et commencer au sommet précédent du tampon de sommets. De même, le segment voisin droit est supposé commencer au sommet de fin du segment actuel et se terminer au sommet suivant du tampon de sommets.

Ce n'est que lorsque les bits gauche et droit sont correctement spécifiés que le segment actuel peut correctement servir les voisins gauche et droit, sinon la zone de contact pourrait ne pas être affichée correctement.

Base de Bézier cubique

Pour la base de Bézier cubique, les indices pointent vers le premier de 4 points de contrôle consécutifs dans le tampon de sommets. Ces points de contrôle utilisent la base de Bézier cubique, où le premier point de contrôle représente le point de départ de la courbe et le quatrième point de contrôle représente le point de fin de la courbe. La base de Bézier cubique est interpolante, de sorte que la courbe passe exactement par les premier et quatrième points de contrôle.

Base de B-spline cubique

Pour la base de B-spline cubique, les indices pointent vers le premier de 4 points de contrôle consécutifs dans le tampon de sommets. Ces points de contrôle forment un B-spline cubique (implicite avec un vecteur de nœuds équidistant). Cette base n'est pas interpolante, de sorte que la courbe ne passe généralement par aucun des points de contrôle. Un grand avantage de cette base est que 3 points de contrôle peuvent être partagés entre deux segments de courbe consécutifs continus, par exemple, les courbes (p0, p1, p2, p3) et (p1, p2, p3, p4) sont C1 continues. Cette caractéristique permet de construire des courbes multi-segments continues de manière efficace, tout en maintenant une consommation mémoire minimale.

Base d'Hermite

Pour la base d'Hermite cubique, les indices pointent vers le premier de 2 points consécutifs dans le tampon de sommets, et vers la première de 2 tangentes consécutives dans le tampon de tangentes. Ces deux points et deux tangentes forment une courbe d'Hermite cubique. Cette base est interpolante, de sorte qu'elle passe exactement par les premier et second points de contrôle, et la dérivée d'ordre un au début et à la fin coïncide exactement avec la valeur spécifiée dans le tampon de tangentes. En joignant deux segments de manière continue, le point final et la tangente du segment précédent peuvent être partagés. Différentes versions de splines de Catmull-Rom peuvent être construites facilement en utilisant la base d'Hermite, en calculant un tampon de tangentes approprié à partir des points de contrôle.

Base de Catmull-Rom

Pour la base de Catmull-Rom, les indices pointent vers le premier de 4 points de contrôle consécutifs dans le tampon de sommets. Cette base passe par p1 et p2 avec les tangentes (p2-p0)/2 et (p3-p1)/2.

Courbes plates

Le mode RTC_GEOMETRY_TYPE_FLAT_* est un mode rapide conçu pour le rendu de cheveux éloignés. Dans ce mode, la courbe est rendue comme une séquence connectée de stries pointant vers l'avant. Dans ce mode, la courbe est rendue comme une séquence de stries consécutives qui se dirigent vers l'avant.

RTC_GEOMETRY_TYPE_CURVE(4embree3)

NAME

RTC_GEOMETRY_TYPE_CURVE(4)

DESCRIPTION

Embree curves are a generalization of subdivision curves where each curve segment is tessellated into a set of Bezier quads.

The tessellation rate can be controlled per geometry. The number of quads to subdivide into can be specified through the rtcSetGeometryTessellationRate function. By default the tessellation rate is 4.

Normal Oriented Curves

The RTC_GEOMETRY_TYPE_NORMAL_ORIENTED_* mode is a mode designed to render blades of grass. In this mode a vertex spline has to get specified as for the previous modes, but additionally a normal spline is required. If the Hermite basis is used, the RTC_BUFFER_TYPE_NORMAL and RTC_BUFFER_TYPE_NORMAL_DERIVATIVE buffers have both to be set.

The curve is rendered as a flat band whose center approximately follows the provided vertex spline, whose half width approximately follows the provided radius spline, and whose normal orientation approximately follows the provided normal spline.

To intersect the normal oriented curve, we perform a newton-raphson style intersection of a ray with a tensor product surface of a linear basis (perpendicular to the curve) and cubic Bézier basis (along the curve). We use a guide curve and its derivatives to construct the control points of that surface. The guide curve is defined by a sweep surface defined by sweeping a line centered at the vertex spline location along the curve. At each parameter value the half width of the line matches the radius spline, and the direction matches the cross product of the normal from the normal spline and tangent of the vertex spline. Note that this construction does not work when the provided normals are parallel to the curve direction. For this reason the provided normals should best be kept as perpendicular to the curve direction as possible. We further assume second order derivatives of the center curve to be zero for this construction, as otherwise very large curvatures occurring in corner cases, can thicken the constructed curve significantly.

Round Curves

In the RTC_GEOMETRY_TYPE_ROUND_* round mode, a real geometric surface is rendered for the curve, which is more expensive but allows closeup views.

For the linear basis the round mode renders a cone that tangentially touches a start-sphere and end-sphere. The start sphere is rendered when no previous segments is indicated by the neighbor bits. The end sphere is always rendered but parts that lie inside the next segment are clipped away (if that next segment exists). This way a curve is closed on both ends and the interior will render properly as long as only neighboring segments penetrate into a segment. For this to work properly it is important that the flags buffer is properly populated with neighbor information.

For the cubic polynomial bases, the round mode renders a sweep surface by sweeping a varying radius circle tangential along the curve. As a limitation, the radius of the curve has to be smaller than the curvature radius of the curve at each location on the curve.

The intersection with the curve segment stores the parametric hit location along the curve segment as u-coordinate (range 0 to +1).

For flat curves, the v-coordinate is set to the normalized distance in the range -1 to +1. For normal oriented curves the v-coordinate is in the range 0 to 1. For the linear basis and in round mode the v-coordinate is set to zero.

In flat mode, the geometry normal Ng is set to the tangent of the curve at the hit location. In round mode and for normal oriented curves, the geometry normal Ng is set to the non-normalized geometric normal of the surface.

For multi-segment motion blur, the number of time steps must be first specified using the rtcSetGeometryTimeStepCount call. Then a vertex buffer for each time step can be set using different buffer slots, and all these buffers must have the same stride and size. For the Hermite basis also a tangent buffer has to be set for each time step and for normal oriented curves a normal buffer has to get specified for each time step.

Also see tutorials [Hair] and [Curves] for examples of how to create and use curve geometries.

EXIT STATUS

On failure NULL is returned and an error code is set that can be queried using rtcGetDeviceError.
