DESCRIPTION

Ces macros définissent des structures de données pour différents types d'arbres : arbres auto-réorganisateurs (splay trees) et arbres rouge-noir.

Dans les définitions de macros, TYPE est le nom d'étiquette d'une structure définie par l'utilisateur qui doit contenir un champ nommé FIELD, de type SPLAY_ENTRY ou RB_ENTRY. L'argument HEADNAME est le nom d'étiquette d'une structure définie par l'utilisateur qui doit être déclarée en utilisant les macros SPLAY_HEAD() ou RB_HEAD(). L'argument NOM doit être un préfixe unique pour chaque arbre défini.

Les prototypes des fonctions sont déclarés avec SPLAY_PROTOTYPE, RB_PROTOTYPE, ou RB_PROTOTYPE_STATIC. Les corps des fonctions sont générés avec SPLAY_GENERATE, RB_GENERATE, ou RB_GENERATE_STATIC. Voir les exemples ci-dessous pour plus d'explications sur la façon dont ces macros sont utilisées.

ARbres AUTO-RÉORGANISATEURS (SPLAY TREES)

Un arbre auto-réorganisateur est une structure de données auto-organisatrice. Chaque opération sur l'arbre provoque une réorganisation (splay). La réorganisation déplace le nœud demandé à la racine de l'arbre et le rééquilibre partiellement.

Cela présente l'avantage que la localité des requêtes entraîne des recherches plus rapides, car les nœuds demandés se déplacent vers le haut de l'arbre. D'un autre côté, chaque recherche entraîne des écritures en mémoire.

Le Théorème d'Équilibrage borne le temps d'accès total pour m opérations et n insertions sur un arbre initialement vide à O((m + n)lg n). Le coût amorti pour une séquence de m accès à un arbre auto-réorganisateur est O(lg n).

Un arbre auto-réorganisateur est dirigé par une structure définie par la macro SPLAY_HEAD(). Une structure SPLAY_HEAD est déclarée comme suit :

SPLAY_HEAD(NOM_TETE, TYPE) tete;

où NOM_TETE est le nom de la structure à définir, et struct TYPE est le type des éléments à insérer dans l'arbre.

La macro SPLAY_ENTRY() déclare une structure qui permet de connecter les éléments dans l'arbre.

Pour utiliser les fonctions qui manipulent la structure de l'arbre, leurs prototypes doivent être déclarés avec la macro SPLAY_PROTOTYPE(), où NOM est un identifiant unique pour cet arbre particulier. L'argument TYPE est le type de la structure gérée par l'arbre. L'argument FIELD est le nom de l'élément défini par SPLAY_ENTRY().

Les corps des fonctions sont générés avec la macro SPLAY_GENERATE(). Elle prend les mêmes arguments que la macro SPLAY_PROTOTYPE(), mais ne doit être utilisée qu'une seule fois.

Enfin, l'argument CMP est le nom d'une fonction utilisée pour comparer les nœuds de l'arbre entre eux. La fonction prend deux arguments de type struct TYPE *. Si le premier argument est plus petit que le second, la fonction retourne une valeur inférieure à zéro. S'ils sont égaux, la fonction retourne zéro. Sinon, elle doit retourner une valeur supérieure à zéro. La fonction de comparaison définit l'ordre des éléments de l'arbre.

La macro SPLAY_INIT() initialise l'arbre référencé par tete.

L'arbre auto-réorganisateur peut également être initialisé statiquement en utilisant la macro SPLAY_INITIALIZER() comme ceci :

SPLAY_HEAD(NOM_TETE, TYPE) tete = SPLAY_INITIALIZER(&tete);

La macro SPLAY_INSERT() insère le nouvel élément elm dans l'arbre. En cas de succès, NULL est retourné. Si un élément correspondant existe déjà dans l'arbre, l'insertion est interrompue et un pointeur vers l'élément existant est retourné.

La macro SPLAY_REMOVE() supprime l'élément elm de l'arbre pointé par tete. En cas de succès, un pointeur vers l'élément supprimé est retourné. NULL est retourné si elm n'est pas présent dans l'arbre.

La macro SPLAY_FIND() peut être utilisée pour trouver un élément particulier dans l'arbre.

struct TYPE recherche, *res;
recherche.cle = 30;
res = SPLAY_FIND(NOM, &tete, &recherche);

Les macros SPLAY_ROOT(), SPLAY_MIN(), SPLAY_MAX(), et SPLAY_NEXT() peuvent être utilisées pour parcourir l'arbre :

pour (np = SPLAY_MIN(NOM, &tete); np != NULL; np = SPLAY_NEXT(NOM, &tete, np))

Ou, pour plus de simplicité, on peut utiliser la macro SPLAY_FOREACH() :

SPLAY_FOREACH(np, NOM, &tete)

La macro SPLAY_EMPTY() doit être utilisée pour vérifier si un arbre auto-réorganisateur est vide.

ARbres ROUGE-NOIR

Un arbre rouge-noir est un arbre binaire de recherche avec la couleur du nœud comme attribut supplémentaire. Il respecte un ensemble de conditions :

  1. chaque chemin de recherche de la racine à une feuille est constitué du même nombre de nœuds noirs,
  2. chaque nœud rouge (sauf la racine) a un parent noir,
  3. chaque nœud feuille est noir.

Chaque opération sur un arbre rouge-noir est bornée à O(lg n). La hauteur maximale d'un arbre rouge-noir est de 2lg (n+1).

Un arbre rouge-noir est dirigé par une structure définie par la macro RB_HEAD(). Une structure RB_HEAD est déclarée comme suit :

RB_HEAD(NOM_TETE, TYPE) tete;

où NOM_TETE est le nom de la structure à définir, et struct TYPE est le type des éléments à insérer dans l'arbre.

La macro RB_ENTRY() déclare une structure qui permet de connecter les éléments dans l'arbre.

Pour utiliser les fonctions qui manipulent la structure de l'arbre, leurs prototypes doivent être déclarés avec les macros RB_PROTOTYPE() ou RB_PROTOTYPE_STATIC(), où NOM est un identifiant unique pour cet arbre particulier. L'argument TYPE est le type de la structure gérée par l'arbre. L'argument FIELD est le nom de l'élément défini par RB_ENTRY().

Les corps des fonctions sont générés avec les macros RB_GENERATE() ou RB_GENERATE_STATIC(). Ces macros prennent les mêmes arguments que les macros RB_PROTOTYPE() et RB_PROTOTYPE

NAME

RB_ROOT, RB_MIN, RB_MAX, RB_NEXT, RB_PREV, RB_FIND, RB_NFIND, RB_INSERT, RB_REMOVE, RB_INIT, RB_INITIALIZER, RB_FOREACH, RB_FOREACH_REVERSE, RB_FOREACH_SAFE, RB_FOREACH_REVERSE_SAFE, RB_EMPTY — macros for maintaining red-black trees

LIBRARY

libbsd libbsd

SYNOPSIS

In order to use the red-black tree implementation, you must define a struct rb_head in your application, and then include the <sys/tree.h> header file. The tree head must be initialized using the RB_INIT() macro or the RB_INITIALIZER() macro.

The macros are defined as follows:

RB_HEAD(name, type);
Declares a structure name which will hold the root of the tree. The tree will contain elements of structure type.
RB_PROTOTYPE(name, type, field, cmp);
Declares the functions needed to manipulate the tree. name is the name of the tree head structure, type is the structure type of the nodes in the tree, field is the name of the structure field which is of type struct rb_entry, and cmp is the name of the comparison function.
RB_GENERATE(name, type, field, cmp);
Generates the functions needed to manipulate the tree. name is the name of the tree head structure, type is the structure type of the nodes in the tree, field is the name of the structure field which is of type struct rb_entry, and cmp is the name of the comparison function.

The field argument must be declared in the node structure type as follows:

struct rb_entry field;

The cmp argument is the name of a function used to compare nodes. The function takes two arguments of type struct TYPE *. If the first argument is smaller than the second, the function returns a value smaller than zero. If they are equal, the function returns zero. Otherwise, it should return a value greater than zero. The comparison function defines the order of the tree elements.

DESCRIPTION

The red-black tree macros provide an implementation of a balanced tree data structure. The implementation is based on the algorithm described in the book “Sedgewick's Algorithms”.

The macros are defined in the <sys/tree.h> header file.

To declare a tree head, use the RB_HEAD() macro:

RB_HEAD(tree_name, node_type) head_name;

To declare the functions that manipulate the tree, use the RB_PROTOTYPE() macro:

RB_PROTOTYPE(tree_name, node_type, entry_field, compare_func);

To generate the functions that manipulate the tree, use the RB_GENERATE() macro:

RB_GENERATE(tree_name, node_type, entry_field, compare_func);

The entry_field argument is the name of the field in node_type that is of type struct rb_entry. The compare_func argument is the name of the comparison function.

The RB_INITIALIZER() macro can be used to initialize a tree head statically. It is the preferred way to initialize a tree head.

The RB_INIT() macro initializes the tree referenced by head.

The red-black tree can also be initialized statically by using the RB_INITIALIZER() macro like this:

RB_HEAD(HEADNAME, TYPE) head = RB_INITIALIZER(&head);

The RB_INSERT() macro inserts the new element elm into the tree. Upon success, NULL is returned. If a matching element already exists in the tree, the insertion is aborted, and a pointer to the existing element is returned.

The RB_REMOVE() macro removes the element elm from the tree pointed by head. RB_REMOVE() returns elm.

The RB_FIND() and RB_NFIND() macros can be used to find a particular element in the tree. RB_FIND() finds the node with the same key as elm. RB_NFIND() finds the first node greater than or equal to the search key.

struct TYPE find, *res;
find.key = 30;
res = RB_FIND(NAME, &head, &find);

The RB_ROOT(), RB_MIN(), RB_MAX(), RB_NEXT(), and RB_PREV() macros can be used to traverse the tree:

for (np = RB_MIN(NAME, &head); np != NULL; np = RB_NEXT(NAME, &head, np))

Or, for simplicity, one can use the RB_FOREACH() or RB_FOREACH_REVERSE() macros:

RB_FOREACH(np, NAME, &head)

The macros RB_FOREACH_SAFE() and RB_FOREACH_REVERSE_SAFE() traverse the tree referenced by head in a forward or reverse direction respectively, assigning each element in turn to np. However, unlike their unsafe counterparts, they permit both the removal of np as well as freeing it from within the loop safely without interfering with the traversal.

The RB_EMPTY() macro should be used to check whether a red-black tree is empty.

EXAMPLES

The following example demonstrates how to declare a red-black tree holding integers. Values are inserted into it and the contents of the tree are printed in order. Lastly, the internal structure of the tree is printed.

#include <sys/tree.h>
#include <err.h>
#include <stdio.h>
#include <stdlib.h>

struct node {
	RB_ENTRY(node) entry;
	int i;
};

int	intcmp(struct node *, struct node *);
void	print_tree(struct node *);

int
intcmp(struct node *e1, struct node *e2)
{
	return (e1->i < e2->i ? -1 : e1->i > e2->i);
}

RB_HEAD(inttree, node) head = RB_INITIALIZER(&head);
RB_PROTOTYPE(inttree, node, entry, intcmp)
RB_GENERATE(inttree, node, entry, intcmp)

int testdata[] = {
	20, 16, 17, 13, 3, 6, 1, 8, 2, 4, 10, 19, 5, 9, 12, 15, 18,
	7, 11, 14
};

void
print_tree(struct node *n)
{
	struct node *left, *right;

	if (n == NULL) {
		printf("nil");
		return;
	}
	left = RB_LEFT(n, entry);
	right = RB_RIGHT(n, entry);
	if (left == NULL && right == NULL)
		printf("%d", n->i);
	else {
		printf("%d(", n->i);
		print_tree(left);
		printf(",");
		print_tree(right);
		printf(")");
	}
}

int
main(void)
{
	int i;
	struct node *n;

	for (i = 0; i < sizeof(testdata) / sizeof(testdata[0]); i++) {
		if ((n = malloc(sizeof(struct node))) == NULL)
			err(1, NULL);
		n->i = testdata[i];
		RB_INSERT(inttree, &head, n);
	}

	RB_FOREACH(n, inttree, &head) {
		printf("%d\n", n->i);
	}
	print_tree(RB_ROOT(&head));
	printf("\n");
	return (0);
}

NOTES

Trying to free a tree in the following way is a common error:

SPLAY_FOREACH(var, NAME, &head) {
	SPLAY_REMOVE(NAME, &head, var);
	free(var);
}
free(head);

Since var is free'd, the FOREACH() macro refers to a pointer that may have been reallocated already. Proper code needs a second variable.

for (var = SPLAY_MIN(NAME, &head); var != NULL; var = nxt) {
	nxt = SPLAY_NEXT(NAME, &head, var);
	SPLAY_REMOVE(NAME, &head, var);
	free(var);
}
