DESCRIPTION

Ces macros définissent des structures de données pour différents types d'arbres : les arbres splay et les arbres rouge-noir.

Dans les définitions de macros, TYPE est le nom de type de la structure définie par l'utilisateur qui doit contenir un champ nommé FIELD de type SPLAY_ENTRY ou RB_ENTRY. L'argument HEADNAME est le nom de type de la structure définie par l'utilisateur qui doit être déclarée en utilisant les macros SPLAY_HEAD() ou RB_HEAD(). L'argument NAME doit être un nom de préfixe unique pour chaque arbre défini.

Les prototypes de fonctions sont déclarés avec SPLAY_PROTOTYPE, RB_PROTOTYPE ou RB_PROTOTYPE_STATIC. Les corps de fonctions sont générés avec SPLAY_GENERATE, RB_GENERATE ou RB_GENERATE_STATIC. Voir les exemples ci-dessous pour une explication plus détaillée de l'utilisation de ces macros.

ARbres SPLAY

Un arbre splay est une structure de données auto-organisatrice. Chaque opération sur l'arbre provoque un splay. Le splay déplace le nœud demandé vers la racine de l'arbre et rééquilibre partiellement l'arbre.

Cela a pour avantage que la localité des requêtes rend les accès plus rapides car les nœuds demandés sont déplacés vers le haut de l'arbre. D'un autre côté, chaque recherche entraîne des écritures en mémoire.

Le Théorème d'Équilibrage borne le temps d'accès total pour m opérations et n insertions dans un arbre initialement vide à O((m + n)lg n). Le coût amorti pour une séquence de m accès à un arbre splay est O(lg n).

Un arbre splay est en-tête par une structure définie par la macro SPLAY_HEAD(). Une structure SPLAY_HEAD est déclarée comme suit :

SPLAY_HEAD(HEADNAME, TYPE) head;

où HEADNAME est le nom de la structure à définir, et TYPE est le type des éléments à insérer dans l'arbre.

La macro SPLAY_ENTRY déclare une structure qui permet de relier les éléments dans l'arbre.

Pour utiliser les fonctions qui manipulent la structure de l'arbre, leurs prototypes doivent être déclarés avec la macro SPLAY_PROTOTYPE, où NAME est un identifiant unique pour cet arbre particulier. L'argument TYPE est le type de la structure qui gère l'arbre. L'argument FIELD est le nom de l'élément défini par SPLAY_ENTRY().

Les corps des fonctions sont générés avec la macro SPLAY_GENERATE. Les mêmes arguments que ceux de la macro SPLAY_PROTOTYPE() sont utilisés, mais ils ne doivent être utilisés qu'une seule fois.

Enfin, l'argument CMP est le nom d'une fonction qui compare les nœuds de l'arbre entre eux. La fonction prend deux arguments de type struct TYPE *. Si le premier argument est inférieur au second, elle renvoie une valeur inférieure à zéro. S'ils sont égaux, elle renvoie zéro. Sinon, elle renvoie une valeur supérieure à zéro. La fonction de comparaison définit l'ordre des éléments de l'arbre.

La macro SPLAY_INIT initialise l'arbre référencé par head.

L'arbre splay peut également être initialisé statiquement en utilisant la macro SPLAY_INITIALIZER comme suit :

SPLAY_HEAD(HEADNAME, TYPE) head = SPLAY_INITIALIZER(&head);

La macro SPLAY_INSERT insère le nouvel élément elm dans l'arbre. En cas de succès, elle renvoie NULL. Si un élément ayant la même valeur existe déjà dans l'arbre, l'insertion est abandonnée et un pointeur vers l'élément existant est renvoyé.

La macro SPLAY_REMOVE supprime l'élément elm de l'arbre pointé par head. En cas de succès, elle renvoie un pointeur vers l'élément supprimé. Si elm n'est pas présent dans l'arbre, elle renvoie NULL.

La macro SPLAY_FIND peut être utilisée pour trouver un élément spécifique dans l'arbre.

struct TYPE find, *res;
find.key = 30;
res = SPLAY_FIND(NAME, &head, &find);

Les macros SPLAY_ROOT(), SPLAY_MIN(), SPLAY_MAX() et SPLAY_NEXT() peuvent être utilisées pour parcourir l'arbre :

for (np = SPLAY_MIN(NAME, &head); np != NULL; np = SPLAY_NEXT(NAME, &head, np))

Ou, pour plus de simplicité, la macro SPLAY_FOREACH peut être utilisée :

SPLAY_FOREACH(np, NAME, &head)

La macro SPLAY_EMPTY doit être utilisée pour vérifier si un arbre splay est vide.

ARbres ROUGE-NOIR

Un arbre rouge-noir est un arbre de recherche binaire avec la couleur du nœud comme propriété supplémentaire. Il respecte un ensemble de conditions :

  1. Tout chemin de la racine à une feuille contient le même nombre de nœuds noirs.
  2. Tout nœud rouge (sauf la racine) a un parent noir.
  3. Toute feuille est noire.

Chaque opération sur un arbre rouge-noir est bornée à O(lg n). La hauteur maximale d'un arbre rouge-noir est 2lg(n+1).

Un arbre rouge-noir est en-tête par une structure définie par la macro RB_HEAD. Une structure RB_HEAD est déclarée comme suit :

RB_HEAD(HEADNAME, TYPE) head;

où HEADNAME est le nom de la structure à définir, et TYPE est le type des éléments à insérer dans l'arbre.

La macro RB_ENTRY déclare une structure qui permet de relier les éléments dans l'arbre.

Pour utiliser les fonctions qui manipulent la structure de l'arbre, leurs prototypes doivent être déclarés avec les macros RB_PROTOTYPE ou RB_PROTOTYPE_STATIC, où NAME est un identifiant unique pour cet arbre particulier. L'argument TYPE est le type de la structure qui gère l'arbre. L'argument FIELD est le nom de l'élément défini par RB_ENTRY().

Les corps des fonctions sont générés avec les macros RB_GENERATE ou RB_GENERATE_STATIC, qui prennent les mêmes arguments que les macros RB_PROTOTYPE() et RB_GENERATE().

HISTORIQUE

La macro d'arbre rouge-noir est apparue pour la première fois dans FreeBSD 4.6.

NOTES

Tenter de libérer un arbre de la manière suivante est une erreur courante :

SPLAY_FOREACH(var, NAME, &head) {
	SPLAY_REMOVE(NAME, &head, var);
	free(var);
}
free(head);

Comme `var` est libéré, la macro FOREACH() fait référence à un pointeur qui peut avoir été réalloué. Le code correct nécessite une variable supplémentaire.

for (var = SPLAY_MIN(NAME, &head); var != NULL; var = nxt) {
	nxt = SPLAY_NEXT(NAME, &head, var);
	SPLAY_REMOVE(NAME, &head, var);
	free(var);
}
