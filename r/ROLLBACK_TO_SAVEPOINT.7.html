ROLLBACK TO SAVEPOINT(7) Documentation PostgreSQL 18.1 ROLLBACK TO SAVEPOINT(7)

NOM

ROLLBACK TO SAVEPOINT - annuler jusqu'à un point de sauvegarde

SYNTAXE

ROLLBACK [ WORK | TRANSACTION ] TO [ SAVEPOINT ] nom_point_sauvegarde

DESCRIPTION

Annule toutes les commandes qui ont été exécutées après l'établissement du point de sauvegarde, puis démarre une nouvelle sous-transaction au même niveau de transaction. Le point de sauvegarde reste valide et peut être utilisé pour des annulations ultérieures, si nécessaire.

ROLLBACK TO SAVEPOINT détruit implicitement tous les points de sauvegarde qui ont été établis après le point de sauvegarde nommé.

PARAMETRES

nom_point_sauvegarde

Le point de sauvegarde jusqu'auquel annuler.

NOTES

Utilisez RELEASE SAVEPOINT pour détruire un point de sauvegarde sans annuler les effets des commandes exécutées après son établissement.

La spécification d'un nom de point de sauvegarde non établi est une erreur.

Les curseurs ont un comportement quelque peu non transactionnel par rapport aux points de sauvegarde. Tout curseur ouvert dans un point de sauvegarde sera fermé lorsque le point de sauvegarde sera annulé. Si un curseur précédemment ouvert est affecté par une commande FETCH ou MOVE dans un point de sauvegarde qui est ultérieurement annulé, le curseur reste à la position laissée par FETCH (c'est-à-dire que le mouvement du curseur causé par FETCH n'est pas annulé). La fermeture d'un curseur n'est pas non plus annulée par une annulation. Cependant, les autres effets secondaires causés par la requête du curseur (tels que les effets secondaires des fonctions volatiles appelées par la requête) sont annulés s'ils se produisent pendant un point de sauvegarde qui est ultérieurement annulé. Un curseur dont l'exécution provoque l'abandon d'une transaction est placé dans un état de non-exécution, de sorte que, bien que la transaction puisse être restaurée à l'aide de ROLLBACK TO SAVEPOINT, le curseur ne peut plus être utilisé.

EXEMPLES

Pour annuler les effets des commandes exécutées après l'établissement de mon_point_sauvegarde :

ROLLBACK TO SAVEPOINT mon_point_sauvegarde;

Les positions des curseurs ne sont pas affectées par l'annulation d'un point de sauvegarde :

BEGIN;
DECLARE foo CURSOR FOR SELECT 1 UNION SELECT 2;
SAVEPOINT foo;
FETCH 1 FROM foo;
 ?column?
----------
        1
ROLLBACK TO SAVEPOINT foo;
FETCH 1 FROM foo;
 ?column?
----------
        2
COMMIT;

COMPATIBILITE

La norme SQL spécifie que le mot-clé SAVEPOINT est obligatoire, mais PostgreSQL et Oracle permettent de l'omettre. SQL autorise seulement WORK, pas TRANSACTION, comme mot parasite après ROLLBACK. De plus, SQL a une clause optionnelle AND [ NO ] CHAIN qui n'est actuellement pas prise en charge par PostgreSQL. Sinon, cette commande est conforme à la norme SQL.
