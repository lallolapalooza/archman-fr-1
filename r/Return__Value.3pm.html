Return::Value(3) Documentation Perl fournie par l'utilisateur Return::Value(3)

NOM

Return::Value - (obsolète) valeurs de retour polymorphiques

VERSION

version 1.666005

SYNTAXE

Utilisé avec l'interface d'appel de fonction de base :

use Return::Value;

sub send_over_network {
    my ($net, $send) = @_:
    if ( $net->transport( $send ) ) {
        return success;
    } else {
        return failure "Impossible de transporter les informations.";
    }
}

my $result = $net->send_over_network(  "Data" );

# booléen
unless ( $result ) {
    # chaîne
    print $result;
}

Ou, construisez votre Return::Value sous forme d'objet :

sub build_up_return {
    my $return = failure;

    if ( ! foo() ) {
        $return->string("Impossible de faire foo !");
        return $return;
    }

    if ( ! bar() ) {
        $return->string("Impossible de faire bar");
        $return->prop(failures => \@bars);
        return $return;
    }

    # tout va bien si nous sommes arrivés ici.
    $return++;
    return $return; # succès !
}

DESCRIPTION

Les valeurs de retour polymorphiques sont une idée horrible, mais cette bibliothèque a été écrite sur la base de la notion qu'elles étaient utiles. Souvent, nous voulons juste savoir si quelque chose a fonctionné ou non. D'autres fois, nous aimerions connaître le texte de l'erreur. Encore d'autres fois, nous pourrions vouloir connaître le code d'erreur et les propriétés de l'erreur. Nous ne voulons pas gérer des objets ou des structures de données pour chaque valeur de retour, mais nous voulons vérifier les conditions d'erreur dans notre code, car c'est ce que font les bons programmeurs.

Lorsque les fonctions réussissent, elles peuvent retourner vrai, ou peut-être des données utiles. Dans la quête de fournir des valeurs de retour cohérentes, cela devient confus entre les erreurs complexes et informatives et les valeurs de retour réussies.

Ce module fournit ces fonctionnalités avec une API simpliste qui devrait vous donner ce que vous cherchez dans chaque contexte où une valeur de retour est utilisée.

Attributs

Toutes les valeurs de retour ont un ensemble d'attributs qui regroupent les informations retournées. Tous les attributs peuvent être accessibles ou modifiés via des méthodes du même nom, sauf indication contraire. Beaucoup peuvent également être accessibles via des opérations surchargées sur l'objet, comme indiqué ci-dessous.

type
Le type d'une valeur est soit "success" (succès), soit "failure" (échec) et reflète (évidemment) si la valeur retourne un succès ou un échec.
errno
L'attribut errno stocke le numéro d'erreur de la valeur de retour. Pour les résultats de type succès, il est par défaut indéfini. Pour les autres résultats, il vaut 1 par défaut.
string
L'attribut chaîne de la valeur est un simple message décrivant la valeur.
data
L'attribut data stocke une référence vers un hash ou un tableau, et peut être utilisé comme un moyen simple de retourner des données supplémentaires. Les données stockées dans l'attribut data peuvent être accessibles en déréférençant la valeur de retour elle-même. (Voir ci-dessous.)
prop
L'attribut le plus générique de tous, prop est un hashref qui peut être utilisé pour passer un nombre arbitraire de structures de données, tout comme l'attribut data. Contrairement à l'attribut data, cependant, ces structures doivent être récupérées via des appels de méthode.

NUTILISEZ PAS CETTE LIBRAIRIE

Return::Value était une mauvaise idée. Je suis désolé de l'avoir eue, désolé d'être allé jusqu'au bout, et désolé qu'elle ait été utilisée dans d'autres bibliothèques utiles. Heureusement, peu de choses l'utilisent. L'une d'entre elles est Email::Send, qui est également obsolète au profit de Email::Sender.

Il n'y a aucune raison de spécifier un nouveau module pour remplacer Return::Value. En général, les routines doivent retourner des valeurs de type uniforme ou lever des exceptions. Return::Value a essayé d'être un type uniforme pour toutes les routines, mais a tellement de comportements étranges qu'il finit par être déroutant et pas très "Perl-like".

Les objets qui sont faux sont juste une idée horrible dans presque toutes les circonstances, surtout quand l'objet a des propriétés utiles.

S'il vous plaît, n'utilisez pas cette bibliothèque. Vous le regretterez plus tard.

Une version de cette bibliothèque en juin 2009 promettait que les avertissements d'obsolescence commenceraient à être émis en juin 2010. Nous sommes maintenant en décembre 2012, et les avertissements sont maintenant émis. Ils peuvent être désactivés par les moyens clairement indiqués dans le code source.

FONCTIONS

L'interface fonctionnelle est fortement recommandée pour une utilisation au sein des fonctions qui utilisent "Return::Value" pour leurs valeurs de retour. Elle est simple et directe, et construit toute la valeur de retour en une seule instruction.

success
La fonction "success" retourne un "Return::Value" avec le type "success".

Des paramètres nommés supplémentaires peuvent être passés pour définir les attributs de l'objet retourné. Le premier paramètre, facultatif, est l'attribut chaîne et n'a pas besoin d'être nommé. Tous les autres paramètres doivent être passés par nom.

# cas le plus simple
return success;
failure
"failure" est identique à "success", mais retourne un objet avec le type "failure".

METHODES

L'API objet est utile dans le code qui capture les objets "Return::Value".

new
my $return = Return::Value->new(
    type   => 'failure',
    string => "VOUS AVEZ ÉCHOUÉ",
    prop   => {
        failed_objects => \@objects,
    },
);

Crée un nouvel objet "Return::Value". Les paramètres nommés peuvent être utilisés pour définir les attributs de l'objet.

bool
print "ça a marché" if $result->bool;

Retourne le résultat dans un contexte booléen : vrai pour le succès, faux pour l'échec.

prop
printf "%s: %s',
  $result->string, join ' ', @{$result->prop('strings')}
    unless $result->bool;

Retourne les propriétés de la valeur de retour. Accepte le nom d'une propriété retournée, ou retourne la référence du hash des propriétés si aucun nom n'est donné.

autres accesseurs d'attributs
Des accesseurs simples existent pour les autres attributs de l'objet : "type", "errno", "string", et "data".

Surcharge

Plusieurs opérateurs sont surchargés pour les objets "Return::Value". Ils sont listés ici.

Conversion en chaîne
print "$result\n";

Se convertit en l'attribut chaîne.

Booléen
print $result unless $result;

Retourne la représentation "bool".

Numérique
Retourne également la valeur "bool".
Déréférencement
Déréférencer la valeur comme un hash ou un tableau retournera la valeur de l'attribut data, s'il correspond à ce type, ou une référence vide sinon. Vous pouvez vérifier "ref $result->data" pour déterminer quel type de données (le cas échéant) a été passé.
