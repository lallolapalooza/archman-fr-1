NOM

Role::Tiny - Rôles : une tranche de taille portion nouvelle cuisine de Moose

SYNOPSIS

package Some::Role;
use Role::Tiny;
sub foo { ... }
sub bar { ... }
around baz => sub { ... };
1;

ailleurs

package Some::Class;
use Role::Tiny::With;
# bar est importé, mais pas foo
with 'Some::Role';
sub foo { ... }
# baz est enveloppé dans le modificateur around par Class::Method::Modifiers
sub baz { ... }
1;

Si vous vouliez également des attributs, regardez Moo::Role.

DESCRIPTION

"Role::Tiny" est un outil minimaliste de composition de rôles.

COMPOSITION DE RÔLES

La composition de rôles peut être considérée comme un héritage multiple beaucoup plus intelligent et significatif. Les bases de cette implémentation de rôles sont :

  • Si une méthode est déjà définie dans une classe, cette méthode ne sera pas composée à partir du rôle. Une méthode héritée par une classe est cependant remplacée par la méthode du rôle du même nom.
  • Si une méthode que le rôle "exige" d'être implémentée n'est pas implémentée, l'application du rôle échouera bruyamment.

Contrairement à Class::C3, où la dernière classe héritée "gagne", la composition de rôles est l'inverse, où la classe gagne. Si plusieurs rôles sont appliqués en un seul appel (une seule instruction with), alors si l'une de leurs méthodes fournies entre en conflit, une exception est levée à moins que la classe ne fournisse une méthode, car ce conflit indique un problème potentiel.

METHODES DE RÔLE

Toutes les subs créées après l'importation de Role::Tiny seront considérées comme des méthodes à composer. Par exemple :

package MyRole;
use List::Util qw(min);
sub mysub { }
use Role::Tiny;
use List::Util qw(max);
sub mymethod { }

Dans ce rôle, "max" et "mymethod" seront inclus lors de la composition de MyRole, et "min" et "mysub" ne le seront pas. Pour un contrôle supplémentaire, namespace::clean peut être utilisé pour exclure les subs indésirables des rôles.

SOUS PROGRAMMES IMPORTÉS

requires

requires qw(foo bar);

Déclare une liste de méthodes qui doivent être définies pour composer le rôle.

with

with 'Some::Role1';
with 'Some::Role1', 'Some::Role2';

Compose un autre rôle dans le rôle actuel (ou la classe via Role::Tiny::With).

Si vous avez des conflits et que vous voulez les résoudre en faveur de Some::Role1, vous pouvez écrire à la place :

with 'Some::Role1';
with 'Some::Role2';

Si vous avez des conflits et que vous voulez résoudre des conflits différents en faveur de différents rôles, veuillez refactoriser votre base de code.

before

before foo => sub { ... };

Voir "before method(s) => sub { ... };" dans Class::Method::Modifiers pour la documentation complète.

Notez que puisque vous n'êtes pas obligé d'utiliser des modificateurs de méthode, Class::Method::Modifiers est chargé paresseusement et nous ne le déclarons pas comme une dépendance. Si votre rôle Role::Tiny utilise des modificateurs, vous devez dépendre à la fois de Class::Method::Modifiers et de Role::Tiny.

around

around foo => sub { ... };

Voir "around method(s) => sub { ... };" dans Class::Method::Modifiers pour la documentation complète.

Notez que puisque vous n'êtes pas obligé d'utiliser des modificateurs de méthode, Class::Method::Modifiers est chargé paresseusement et nous ne le déclarons pas comme une dépendance. Si votre rôle Role::Tiny utilise des modificateurs, vous devez dépendre à la fois de Class::Method::Modifiers et de Role::Tiny.

after

after foo => sub { ... };

Voir "after method(s) => sub { ... };" dans Class::Method::Modifiers pour la documentation complète.

Notez que puisque vous n'êtes pas obligé d'utiliser des modificateurs de méthode, Class::Method::Modifiers est chargé paresseusement et nous ne le déclarons pas comme une dépendance. Si votre rôle Role::Tiny utilise des modificateurs, vous devez dépendre à la fois de Class::Method::Modifiers et de Role::Tiny.

Strict et Warnings

En plus d'importer des sous-programmes, l'utilisation de "Role::Tiny" applique strict et warnings à l'appelant.

SOUS PROGRAMMES

does_role

if (Role::Tiny::does_role($foo, 'Some::Role')) {
  ...
}

Retourne vrai si la classe a été composée avec le rôle.

Cette sous-routine est également installée comme ->does sur toute classe dans laquelle un Role::Tiny est composé, à moins que cette classe n'ait déjà une méthode ->does, donc

if ($foo->does('Some::Role')) {
  ...
}

fonctionnera pour les classes, mais pour tester un rôle, il faut utiliser directement ::does_role.

De plus, Role::Tiny remplacera la méthode standard Perl "DOES" pour votre classe. Cependant, si "n'importe quelle" classe dans la hiérarchie d'héritage de votre classe fournit "DOES", alors Role::Tiny ne la remplacera pas.

METHODES

make_role

Role::Tiny->make_role('Some::Role');

Transforme un paquet en rôle, mais n'exporte aucune subs dedans.

apply_roles_to_package

Role::Tiny->apply_roles_to_package(
  'Some::Package', 'Some::Role', 'Some::Other::Role'
);

Compose le rôle avec le paquet. Voir aussi Role::Tiny::With.

apply_roles_to_object

Role::Tiny->apply_roles_to_object($foo, qw(Some::Role1 Some::Role2));

Compose les rôles dans l'ordre directement dans l'objet. L'objet est reblessé dans la classe résultante. Notez que les méthodes de l'objet sont remplacées par celles du rôle portant le même nom.

create_class_with_roles

Role::Tiny->create_class_with_roles('Some::Base', qw(Some::Role1 Some::Role2));

Crée une nouvelle classe basée sur base, avec les rôles composés dedans dans l'ordre. La nouvelle classe est retournée.

is_role

Role::Tiny->is_role('Some::Role1')

Retourne vrai si le paquet donné est un rôle.

CAVEATS

  • Sur perl 5.8.8 et versions antérieures, l'application d'un rôle à un objet n'appliquera pas les surcharges du rôle aux autres copies de l'objet.
  • Sur perl 5.16 et versions antérieures, l'application d'un rôle à une classe n'appliquera pas les surcharges du rôle aux instances existantes de la classe.

VOIR AUSSI

Role::Tiny est le sous-ensemble sans attribut de Moo::Role ; Moo::Role est un sous-ensemble sans méta-protocole du roi des systèmes de rôles, Moose::Role.

Ovid's Role::Basic fournit des rôles de portée similaire, mais sans modificateurs de méthode, et avec des restrictions d'utilisation supplémentaires.
