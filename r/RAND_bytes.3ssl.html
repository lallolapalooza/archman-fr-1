RAND_bytes(3ssl)

Paquet: openssl

Licences: Apache-2.0

RAND_BYTES(3ssl) OpenSSL RAND_BYTES(3ssl)

NOM

RAND_bytes, RAND_priv_bytes, RAND_bytes_ex, RAND_priv_bytes_ex, RAND_pseudo_bytes, RAND_set1_random_provider - générer des données aléatoires

SYNTAXE

#include <openssl/rand.h>
int RAND_bytes(unsigned char *buf, int num);
int RAND_priv_bytes(unsigned char *buf, int num);
int RAND_bytes_ex(OSSL_LIB_CTX *ctx, unsigned char *buf, size_t num,
                  unsigned int strength);
int RAND_priv_bytes_ex(OSSL_LIB_CTX *ctx, unsigned char *buf, size_t num,
                       unsigned int strength);
int RAND_set1_random_provider(OSSL_LIB_CTX *ctx, OSSL_PROVIDER *p);

La fonction suivante a été dépréciée depuis OpenSSL 1.1.0, et peut être entièrement masquée en définissant OPENSSL_API_COMPAT avec une valeur de version appropriée, voir openssl_user_macros(7) :

int RAND_pseudo_bytes(unsigned char *buf, int num);

DESCRIPTION

RAND_bytes() génère num octets aléatoires en utilisant un générateur pseudo-aléatoire cryptographiquement sûr (CSPRNG) et les stocke dans buf. buf NE DOIT PAS être NULL.

RAND_priv_bytes() a la même sémantique que RAND_bytes(). Elle est destinée à être utilisée pour générer des valeurs qui doivent rester privées. Si la méthode RAND par défaut est utilisée, cette fonction utilise une instance PRNG "privée" séparée afin qu'une compromission de l'instance PRNG "publique" n'affecte pas le secret de ces valeurs privées, comme décrit dans RAND(7) et EVP_RAND(7).

RAND_bytes_ex() et RAND_priv_bytes_ex() sont les mêmes que RAND_bytes() et RAND_priv_bytes(), à l'exception qu'elles prennent toutes deux des paramètres supplémentaires strength et ctx. Les octets générés auront une force de sécurité d'au moins strength bits. Le DRBG utilisé pour l'opération est le DRBG public ou privé associé au ctx spécifié. Le paramètre peut être NULL, auquel cas le contexte de bibliothèque par défaut est utilisé (voir OSSL_LIB_CTX(3). Si la méthode RAND par défaut a été modifiée, pour des raisons de compatibilité, la méthode RAND sera utilisée par préférence et le DRBG du contexte de bibliothèque sera ignoré.

RAND_set1_random_provider() spécifie un fournisseur, prov, qui sera utilisé par le contexte de bibliothèque ctx pour tous les appels de génération ci-dessus au lieu des DRBG intégrés et de la source d'entropie. Passez NULL pour le fournisseur afin de désactiver la fonctionnalité du fournisseur aléatoire. Dans ce cas, les DRBG intégrés et la source d'entropie seront utilisés. Cet appel ne doit pas être considéré comme thread-safe.

NOTES

Par défaut, le CSPRNG d'OpenSSL prend en charge un niveau de sécurité de 256 bits, à condition qu'il ait pu s'amorcer à partir d'une source d'entropie de confiance. Sur toutes les plateformes majeures prises en charge par OpenSSL (y compris les plateformes de type Unix et Windows), OpenSSL est configuré pour amorcer automatiquement le CSPRNG lors de la première utilisation en utilisant le générateur aléatoire du système d'exploitation.

Si la source d'entropie échoue ou n'est pas disponible, le CSPRNG entrera dans un état d'erreur et refusera de générer des octets aléatoires. Pour cette raison, il est important de toujours vérifier la valeur de retour d'erreur de RAND_bytes() et RAND_priv_bytes() et de ne pas prendre le caractère aléatoire pour acquis.

Sur d'autres plateformes, il peut ne pas y avoir de source d'entropie de confiance disponible ou OpenSSL peut avoir été explicitement configuré pour utiliser d'autres sources d'entropie. Si vous avez des doutes sur la qualité de la source d'entropie, n'hésitez pas à demander à votre fournisseur de système d'exploitation ou à poser une question sur GitHub ou la liste de diffusion openssl-users.

VALEURS DE RETOUR

RAND_bytes() et RAND_priv_bytes() retournent 1 en cas de succès, -1 si non pris en charge par la méthode RAND actuelle, ou 0 en cas d'autre échec. Le code d'erreur peut être obtenu par ERR_get_error(3).

RAND_set1_random_provider() retourne 1 en cas de succès et 0 en cas d'échec.

VOIR AUSSI

HISTORIQUE

  • RAND_pseudo_bytes() a été déprécié dans OpenSSL 1.1.0 ; utilisez RAND_bytes() à la place.
  • La fonction RAND_priv_bytes() a été ajoutée dans OpenSSL 1.1.1.
  • Les fonctions RAND_bytes_ex() et RAND_priv_bytes_ex() ont été ajoutées dans OpenSSL 3.0
  • La fonction RAND_set1_random_provider() a été ajoutée dans OpenSSL 3.5
