NAME

RRDs - Accéder à RRDtool comme module partagé

SYNOPSIS

use RRDs;
RRDs::error
RRDs::last ...
RRDs::info ...
RRDs::create ...
RRDs::update ...
RRDs::updatev ...
RRDs::graph ...
RRDs::fetch ...
RRDs::tune ...
RRDs::times(start, end)
RRDs::dump ...
RRDs::restore ...
RRDs::flushcached ...
RRDs::register_fetch_cb ...
$RRDs::VERSION

DESCRIPTION

Séquence d'appel

Ce module accède directement à la fonctionnalité de RRDtool depuis Perl. Les arguments des fonctions mentionnées dans SYNOPSIS sont expliqués dans la documentation normale de RRDtool. L'appel à la ligne de commande

rrdtool update mydemo.rrd --template in:out N:12:13

devient

RRDs::update ("mydemo.rrd", "--template", "in:out", "N:12:13");

Notez que

--template=in:out

est également valide.

La fonction RRDs::times prend deux paramètres : un temps de "start" et un temps de "end". Ceux-ci doivent être spécifiés dans le format de spécification de temps de style AT par RRDtool. Voir la documentation de rrdfetch pour une explication détaillée de la façon de spécifier le temps.

Gestion des erreurs

Les fonctions RRDs::update n'arrêtent pas le programme, même si elles ne peuvent pas interpréter les arguments que vous leur avez passés.

La fonction RRDs::error doit être appelée pour obtenir le statut d'erreur après chaque appel de fonction. Si RRDs::error ne renvoie rien, alors la fonction précédente a terminé sa tâche avec succès.

use RRDs;
RRDs::update ("mydemo.rrd","N:12:13");
my $ERR=RRDs::error;
die "ERROR while updating mydemo.rrd: $ERR\n" if $ERR;

Valeurs de retour

Les fonctions RRDs::last, RRDs::graph, RRDs::info, RRDs::fetch et RRDs::times renvoient leurs résultats.

RRDs::last renvoie un seul ENTIER représentant le temps de la dernière mise à jour.

$lastupdate = RRDs::last ...

RRDs::graph renvoie un tableau avec la taille en largeur et hauteur de l'image créée et un pointeur vers un tableau avec les résultats des arguments PRINT.

($result_arr,$xsize,$ysize) = RRDs::graph ...
print "Image size: ${xsize}x${ysize}\n";
print "Averages: ", (join ", ", @$averages);

RRDs::info renvoie un pointeur vers une table de hachage. Les clés de la table de hachage représentent les noms des propriétés du RRD et les valeurs de la table de hachage sont les valeurs des propriétés.

$hash = RRDs::info "example.rrd";
foreach my $key (keys %$hash){
  print "$key = $$hash{$key}\n";
}

RRDs::graphv prend les mêmes paramètres que RRDs::graph mais renvoie un pointeur vers une table de hachage. La table de hachage renvoyée contient des méta-informations sur le graphique. Quelques exemples incluent sa taille et la position de la zone de graphique dans l'image. Lorsqu'elle est appelée avec '-' comme nom de fichier, le contenu du graphique est renvoyé dans la table de hachage sous la clé (key 'image').

RRDs::updatev renvoie également un pointeur vers une table de hachage. Les clés de la table de hachage sont des chaînes concaténées d'un temps, d'un index RRA et d'un nom de source de données pour chaque point de données consolidé (CDP) écrit sur disque en conséquence de l'appel actuel. Les valeurs de la table de hachage sont les valeurs des CDP.

RRDs::fetch est le plus complexe en termes de valeurs renvoyées. Il y a quatre valeurs. Deux entiers normaux, un pointeur vers un tableau et un pointeur vers un tableau de pointeurs.

my ($start,$step,$names,$data) = RRDs::fetch ... 
print "Start:       ", scalar localtime($start), " ($start)\n";
print "Step size:   $step seconds\n";
print "DS names:    ", join (", ", @$names)."\n";
print "Data points: ", $#$data + 1, "\n";
print "Data:\n";
for my $line (@$data) {
  print "  ", scalar localtime($start), " ($start) ";
  $start += $step;
  for my $val (@$line) {
    printf "%12.1f ", $val;
  }
  print "\n";
}

RRDs::xport expose la fonctionnalité de rrdxport et renvoie des données avec la structure suivante :

my ($start,$end,$step,$cols,$names,$data) = RRDs::xport ...

# $start : timestamp
# $end   : timestamp
# $step  : secondes
# $cols  : nombre de colonnes renvoyées
# $names : arrayref avec les noms des colonnes
# $data  : arrayref d'arrayrefs avec les données (premier indice est le temps, second est la colonne)

RRDs::times renvoie deux entiers qui sont le nombre de secondes depuis l'epoch (1970-01-01) pour les arguments "start" et "end" respectivement.

Voir le répertoire d'exemples pour plus de façons d'utiliser cette extension.

Fonction de rappel de récupération

Normalement, lorsque vous utilisez graph, xport ou fetch, les données que vous voyez seront obtenues à partir d'un fichier rrd réel. Certains utilisateurs qui apprécient le style de graphiques rrd exportent leurs données d'une base de données, puis les chargent dans un fichier rrd afin de pouvoir appeler rrdgraph dessus. En utilisant une fonction de rappel personnalisée, vous pouvez fournir votre propre code pour gérer les demandes de données de graph, xport et fetch.

Pour ce faire, vous devez d'abord écrire une fonction fetch en perl, puis enregistrer cette fonction à l'aide de RRDs::fetch_register_callback.

Enfin, vous pouvez utiliser le nom de chemin pseudo cb//[nom de fichier] pour indiquer à rrdtool d'utiliser votre routine de rappel au lieu de la méthode normale de récupération de données rrd pour organiser les données nécessaires.

La fonction de rappel doit ressembler à ceci :

sub fetch_callback {
    my $args_hash = shift;
    # {
    #  filename => 'cb//somefilename',
    #  cd => 'AVERAGE',
    #  start => 1401295291,   
    #  end => 1401295591,
    #  step => 300 }
    # faire quelque chose d'intelligent pour récupérer ces données
    return {
        start => $unix_timestamp,
        step => $step_width,
        data => {
            dsName1 => [ value1, value2, ... ],
            dsName2 => [ value1, value2, ... ],
            dsName3 => [ value1, value2, ... ],
        }
   };
}

NOTE

Si vous manipulez la variable TZ, vous devez également appeler la fonction POSIX tzset(3) pour initialiser tous les états internes de la bibliothèque dans le fuseau horaire de votre choix.

use POSIX qw(tzset);
$ENV{TZ} = 'CET';   
POSIX::tzset();
