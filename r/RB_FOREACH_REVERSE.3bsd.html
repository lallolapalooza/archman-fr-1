DESCRIPTION

These macros define data structures for different kinds of trees: splay trees and red-black trees.

In the macro definitions, TYPE is the name of a user-defined struct tag which must contain a field named FIELD of type SPLAY_ENTRY or RB_ENTRY. The argument HEADNAME is the name of a user-defined struct tag which must be declared using the SPLAY_HEAD() or RB_HEAD() macros. The argument NAME has to be a unique prefix for each tree defined.

Function declarations are done using SPLAY_PROTOTYPE, RB_PROTOTYPE or RB_PROTOTYPE_STATIC. Function bodies are generated using SPLAY_GENERATE, RB_GENERATE or RB_GENERATE_STATIC. Refer to the examples below for a more detailed explanation of how these macros are used.

SPLAY TREES

A splay tree is a self-balancing data structure. Each operation on the tree causes a splay. The splay moves the requested node to the root of the tree and partially rebalances it.

It has the benefit that request locality makes queries faster since requested nodes are moved to the top of the tree. On the other hand, every query causes writes to memory.

The Amortized Analysis theorem bounds the total access time for m operations and n insertions into an initially empty tree to O((m + n)lg n). The amortized cost of m accesses to a splay tree is O(lg n).

A splay tree is headed by a structure defined using the SPLAY_HEAD() macro. A SPLAY_HEAD structure is declared like this:

SPLAY_HEAD(HEADNAME, TYPE) head;

where HEADNAME is the name of the structure to define, and TYPE is the type of the elements inserted into the tree.

The SPLAY_ENTRY macro declares a structure that allows elements to be linked into the tree.

In order to use the functions that manipulate the tree structure, their prototypes must be declared using the SPLAY_PROTOTYPE macro, where NAME is a unique identifier for this particular tree. The argument TYPE is the type of the struct managing the tree. The argument FIELD is the name of the field defined by the SPLAY_ENTRY macro.

The bodies of the functions are generated using the SPLAY_GENERATE macro. It takes the same arguments as the SPLAY_PROTOTYPE() macro, but should be used only once.

Finally, the argument CMP is the name of a function that compares tree nodes against each other. The function takes two arguments of type struct TYPE *. If the first argument is less than the second, it returns a value less than zero. If they are equal, it returns zero. Otherwise, it must return a value greater than zero. The comparison function defines the ordering of the elements in the tree.

The SPLAY_INIT macro initializes the tree pointed to by head.

The splay tree can also be initialized statically using the SPLAY_INITIALIZER macro like this:

SPLAY_HEAD(HEADNAME, TYPE) head = SPLAY_INITIALIZER(&head);

The SPLAY_INSERT macro inserts the new element elm into the tree. On success, NULL is returned. If an element matching the key already exists in the tree, the insertion is aborted and a pointer to the existing element is returned.

The SPLAY_REMOVE macro removes the element elm from the tree pointed to by head. On success, a pointer to the removed element is returned. NULL is returned if elm is not present in the tree.

The SPLAY_FIND macro can be used to find a specific element in the tree.

struct TYPE find, *res;
find.key = 30;
res = SPLAY_FIND(NAME, &head, &find);

The SPLAY_ROOT, SPLAY_MIN, SPLAY_MAX, and SPLAY_NEXT macros can be used to iterate over the tree:

for (np = SPLAY_MIN(NAME, &head); np != NULL; np = SPLAY_NEXT(NAME, &head, np))

Or, for simplicity, the SPLAY_FOREACH macro can be used:

SPLAY_FOREACH(np, NAME, &head)

The SPLAY_EMPTY macro should be used to check if a splay tree is empty.

RED-BLACK TREES

A red-black tree is a binary search tree with the node color as an additional attribute. It satisfies a number of conditions:

  1. Every path from the root to a leaf node contains the same number of black nodes,
  2. Every red node (except the root) has a black parent,
  3. Every leaf node is black.

Each operation on a red-black tree is bounded to O(lg n). The maximum height of a red-black tree is 2lg(n+1).

A red-black tree is headed by a structure defined using the RB_HEAD macro. An RB_HEAD structure is declared like this:

RB_HEAD(HEADNAME, TYPE) head;

where HEADNAME is the name of the structure to define, and TYPE is the type of the elements inserted into the tree.

The RB_ENTRY macro declares a structure that allows elements to be linked into the tree.

In order to use the functions that manipulate the tree structure, their prototypes must be declared using the RB_PROTOTYPE or RB_PROTOTYPE_STATIC macros, where NAME is a unique identifier for this particular tree. The argument TYPE is the type of the struct managing the tree. The argument FIELD is the name of the field defined by the RB_ENTRY macro.

The bodies of the functions are generated using the RB_GENERATE or RB_GENERATE_STATIC macros. These macros take the same arguments as the RB_PROTOTYPE() and RB_GENERATE() macros.

SYNOPSIS

Inclure l'en-tête <sys/tree.h>.

Pour utiliser les arbres rouge-noir, vous devez d'abord définir votre structure de nœud. Elle doit contenir une macro RB_ENTRY (ou RB_GENERATE) dont le premier argument est le nom de la structure de nœud, et le second est le nom de membre de l'entrée d'arbre.

struct nodename {
	RB_ENTRY(nodename) fieldname;
	...
};

Vous devez ensuite déclarer une tête d'arbre à l'aide de RB_HEAD. Le premier argument est le nom de la tête d'arbre, et le second est le nom de la structure de nœud. La tête d'arbre doit être initialisée à l'aide de RB_INITIALIZER ou RB_INIT.

RB_HEAD(headname, nodename) head = RB_INITIALIZER(&head);

Après cela, vous devez définir les prototypes des fonctions à l'aide de RB_PROTOTYPE. Le premier argument est le nom de la tête d'arbre, le second est le nom de la structure de nœud, le troisième est le nom du champ de l'entrée d'arbre dans la structure de nœud, et le quatrième est le nom de la fonction de comparaison.

RB_PROTOTYPE(headname, nodename, fieldname, compar);

Enfin, vous devez générer les fonctions réelles à l'aide de RB_GENERATE. Les arguments sont les mêmes que pour RB_PROTOTYPE.

RB_GENERATE(headname, nodename, fieldname, compar);

Les appels de macros suivants sont alors disponibles.

DESCRIPTION

Ce manuel décrit les macros pour la manipulation des arbres rouge-noir définis dans <sys/tree.h>. Ces macros fournissent une implémentation générique d'arbres rouge-noir qui peuvent être utilisés pour stocker n'importe quel type de données. L'ordre des éléments dans l'arbre est déterminé par une fonction de comparaison fournie par l'utilisateur.

RÉFÉRENCES AUX MACROS

Les macros suivantes sont fournies pour la manipulation des arbres rouge-noir.

RB_HEAD
Déclare une structure de tête d'arbre rouge-noir. Elle prend deux arguments : le nom de la tête d'arbre et le nom du type de nœud.
RB_ENTRY
Déclare une entrée d'arbre rouge-noir à l'intérieur d'une structure de nœud. Elle prend deux arguments : le nom du type de nœud et le nom du champ pour l'entrée d'arbre.
RB_PROTOTYPE
Définit le prototype des fonctions d'arbre rouge-noir. Elle prend quatre arguments : le nom de la tête d'arbre, le nom du type de nœud, le nom du champ d'entrée d'arbre et le nom de la fonction de comparaison. Cette macro doit être appelée dans l'en-tête du programme.
RB_GENERATE
Génère les fonctions d'arbre rouge-noir. Elle prend quatre arguments : le nom de la tête d'arbre, le nom du type de nœud, le nom du champ d'entrée d'arbre et le nom de la fonction de comparaison. Cette macro doit être appelée une seule fois dans le fichier source.

Enfin, l'argument CMP est le nom d'une fonction utilisée pour comparer les nœuds des arbres entre eux. La fonction prend deux arguments de type struct TYPE *. Si le premier argument est plus petit que le second, la fonction retourne une valeur inférieure à zéro. S'ils sont égaux, la fonction retourne zéro. Sinon, elle doit retourner une valeur supérieure à zéro. La fonction de comparaison définit l'ordre des éléments de l'arbre.

RB_INIT
Initialise l'arbre référencé par head.
RB_INITIALIZER
L'arbre rouge-noir peut également être initialisé statiquement en utilisant la macro RB_INITIALIZER comme ceci :
RB_HEAD(HEADNAME, TYPE) head = RB_INITIALIZER(&head);
RB_INSERT
La macro RB_INSERT insère le nouvel élément elm dans l'arbre. En cas de succès, NULL est retourné. Si un élément correspondant existe déjà dans l'arbre, l'insertion est abandonnée et un pointeur vers l'élément existant est retourné.
RB_REMOVE
La macro RB_REMOVE supprime l'élément elm de l'arbre pointé par head. RB_REMOVE() retourne elm.
RB_FIND
Les macros RB_FIND() et RB_NFIND() peuvent être utilisées pour trouver un élément particulier dans l'arbre. RB_FIND() trouve le nœud avec la même clé que elm. RB_NFIND() trouve le premier nœud supérieur ou égal à la clé de recherche.
struct TYPE find, *res;
find.key = 30;
res = RB_FIND(NAME, &head, &find);
RB_ROOT
Les macros RB_ROOT(), RB_MIN(), RB_MAX(), RB_NEXT(), et RB_PREV() peuvent être utilisées pour parcourir l'arbre :
for (np = RB_MIN(NAME, &head); np != NULL; np = RB_NEXT(NAME, &head, np))
RB_FOREACH
Ou, pour plus de simplicité, on peut utiliser les macros RB_FOREACH() ou RB_FOREACH_REVERSE() :
RB_FOREACH(np, NAME, &head)
RB_FOREACH_SAFE
Les macros RB_FOREACH_SAFE() et RB_FOREACH_REVERSE_SAFE() parcourent l'arbre référencé par head dans un sens ou dans l'autre, en assignant chaque élément à tour de rôle à np. Cependant, contrairement à leurs homologues non sûrs, elles permettent à la fois la suppression de np et sa libération à l'intérieur de la boucle en toute sécurité sans interférer avec le parcours.
RB_EMPTY
La macro RB_EMPTY() doit être utilisée pour vérifier si un arbre rouge-noir est vide.

EXEMPLES

L'exemple suivant montre comment déclarer un arbre rouge-noir contenant des entiers. Des valeurs y sont insérées et le contenu de l'arbre est imprimé dans l'ordre. Enfin, la structure interne de l'arbre est imprimée.

#include <sys/tree.h>
#include <err.h>
#include <stdio.h>
#include <stdlib.h>

struct node {
	RB_ENTRY(node) entry;
	int i;
};

int	intcmp(struct node *, struct node *);
void	print_tree(struct node *);

int
intcmp(struct node *e1, struct node *e2)
{
	return (e1->i < e2->i ? -1 : e1->i > e2->i);
}

RB_HEAD(inttree, node) head = RB_INITIALIZER(&head);
RB_PROTOTYPE(inttree, node, entry, intcmp)
RB_GENERATE(inttree, node, entry, intcmp)

int testdata[] = {
	20, 16, 17, 13, 3, 6, 1, 8, 2, 4, 10, 19, 5, 9, 12, 15, 18,
	7, 11, 14
};

void
print_tree(struct node *n)
{
	struct node *left, *right;

	if (n == NULL) {
		printf("nil");
		return;
	}
	left = RB_LEFT(n, entry);
	right = RB_RIGHT(n, entry);
	if (left == NULL && right == NULL)
		printf("%d", n->i);
	else {
		printf("%d(", n->i);
		print_tree(left);
		printf(",");
		print_tree(right);
		printf(")");
	}
}

int
main(void)
{
	int i;
	struct node *n;

	for (i = 0; i < sizeof(testdata) / sizeof(testdata[0]); i++) {
		if ((n = malloc(sizeof(struct node))) == NULL)
			err(1, NULL);
		n->i = testdata[i];
		RB_INSERT(inttree, &head, n);
	}

	RB_FOREACH(n, inttree, &head) {
		printf("%d\n", n->i);
	}
	print_tree(RB_ROOT(&head));
	printf("\n");
	return (0);
}

HISTORIQUE

Les macros d'arbre sont apparues pour la première fois dans FreeBSD 4.6.

NOTES

Essayer de libérer un arbre de la manière suivante est une erreur courante :

SPLAY_FOREACH(var, NAME, &head) {
	SPLAY_REMOVE(NAME, &head, var);
	free(var);
}

Puisque var est libéré, la macro FOREACH() fait référence à un pointeur qui a peut-être déjà été réalloué. Un code correct nécessite une seconde variable.

for (var = SPLAY_MIN(NAME, &head); var != NULL; var = nxt) {
	nxt = SPLAY_NEXT(NAME, &head, var);
	SPLAY_REMOVE(NAME, &head, var);
	free(var);
}
