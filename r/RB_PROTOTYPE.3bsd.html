DESCRIPTION

Ces macros définissent des structures de données pour différents types d'arbres : arbres splay et arbres rouge-noir.

Dans les définitions de macros, TYPE est l'étiquette d'une structure définie par l'utilisateur qui doit contenir un champ nommé FIELD de type SPLAY_ENTRY ou RB_ENTRY. L'argument HEADNAME est l'étiquette d'une structure définie par l'utilisateur qui doit être déclarée à l'aide des macros SPLAY_HEAD() ou RB_HEAD(). L'argument NAME doit être un nom de préfixe unique pour chaque arbre défini.

Les prototypes de fonctions sont déclarés avec SPLAY_PROTOTYPE, RB_PROTOTYPE ou RB_PROTOTYPE_STATIC. Les corps des fonctions sont générés avec SPLAY_GENERATE, RB_GENERATE ou RB_GENERATE_STATIC. Voir les exemples ci-dessous pour une explication plus détaillée de l'utilisation de ces macros.

ARbres SPLAY

Un arbre splay est une structure de données auto-organisatrice. Chaque opération sur l'arbre provoque un splay. Le splay déplace le nœud demandé vers la racine de l'arbre et rééquilibre partiellement l'arbre.

Cela présente l'avantage que la localité des requêtes entraîne des requêtes plus rapides, car les nœuds demandés sont déplacés vers le haut de l'arbre. D'un autre côté, chaque requête entraîne des écritures en mémoire.

Le Théorème d'Équilibrage limite le temps d'accès total pour m opérations et n insertions dans un arbre initialement vide à O((m + n)lg n). Le coût amorti pour une séquence de m accès dans un arbre splay est O(lg n).

Un arbre splay est dirigé par une structure définie à l'aide de la macro SPLAY_HEAD(). Une structure SPLAY_HEAD est déclarée comme suit :

SPLAY_HEAD(HEADNAME, TYPE) head;

où HEADNAME est le nom de la structure à définir, et TYPE est le type des éléments à insérer dans l'arbre.

La macro SPLAY_ENTRY déclare une structure qui permet de relier les éléments dans l'arbre.

Pour utiliser les fonctions qui manipulent la structure de l'arbre, leurs prototypes doivent être déclarés avec la macro SPLAY_PROTOTYPE, où NAME est un identifiant unique pour cet arbre particulier. L'argument TYPE est le type de la structure qui gère l'arbre. L'argument FIELD est le nom de l'élément défini par SPLAY_ENTRY.

Les corps des fonctions sont générés avec la macro SPLAY_GENERATE. Elle prend les mêmes arguments que la macro SPLAY_PROTOTYPE() mais ne doit être utilisée qu'une seule fois.

Enfin, l'argument CMP est le nom d'une fonction utilisée pour comparer les nœuds de l'arbre à d'autres. La fonction prend deux arguments de type struct TYPE *. Si le premier argument est inférieur au second, elle renvoie une valeur inférieure à zéro. S'ils sont égaux, elle renvoie zéro. Sinon, elle renvoie une valeur supérieure à zéro. La fonction de comparaison définit l'ordre des éléments de l'arbre.

La macro SPLAY_INIT initialise l'arbre référencé par head.

L'arbre splay peut également être initialisé statiquement à l'aide de la macro SPLAY_INITIALIZER, comme indiqué :

SPLAY_HEAD(HEADNAME, TYPE) head = SPLAY_INITIALIZER(&head);

La macro SPLAY_INSERT insère le nouvel élément elm dans l'arbre. En cas de succès, elle renvoie NULL. Si un élément correspondant existe déjà dans l'arbre, l'insertion est abandonnée et un pointeur vers l'élément existant est renvoyé.

La macro SPLAY_REMOVE supprime l'élément elm de l'arbre pointé par head. En cas de succès, elle renvoie un pointeur vers l'élément supprimé. NULL est renvoyé si elm n'existe pas dans l'arbre.

La macro SPLAY_FIND peut être utilisée pour trouver un élément spécifique dans l'arbre.

struct TYPE find, *res;
find.key = 30;
res = SPLAY_FIND(NAME, &head, &find);

Les macros SPLAY_ROOT(), SPLAY_MIN(), SPLAY_MAX(), et SPLAY_NEXT() peuvent être utilisées pour parcourir l'arbre :

for (np = SPLAY_MIN(NAME, &head); np != NULL; np = SPLAY_NEXT(NAME, &head, np))

Ou, pour plus de simplicité, la macro SPLAY_FOREACH peut être utilisée :

SPLAY_FOREACH(np, NAME, &head)

La macro SPLAY_EMPTY doit être utilisée pour vérifier si un arbre splay est vide.

ARbres ROUGE-NOIR

Un arbre rouge-noir est un arbre de recherche binaire avec la couleur du nœud comme attribut supplémentaire. Il respecte un ensemble de conditions :

  1. Tout chemin de la racine à un nœud feuille contient le même nombre de nœuds noirs,
  2. Tout nœud rouge (sauf la racine) a un parent noir,
  3. Tout nœud feuille est noir.

Chaque opération sur un arbre rouge-noir est limitée à O(lg n). La hauteur maximale d'un arbre rouge-noir est de 2lg(n+1).

Un arbre rouge-noir est dirigé par une structure définie à l'aide de la macro RB_HEAD(). Une structure RB_HEAD est déclarée comme suit :

RB_HEAD(HEADNAME, TYPE) head;

où HEADNAME est le nom de la structure à définir, et TYPE est le type des éléments à insérer dans l'arbre.

La macro RB_ENTRY déclare une structure qui permet de relier les éléments dans l'arbre.

Pour utiliser les fonctions qui manipulent la structure de l'arbre, leurs prototypes doivent être déclarés avec les macros RB_PROTOTYPE() ou RB_PROTOTYPE_STATIC() où NAME est un identifiant unique pour cet arbre particulier. L'argument TYPE est le type de la structure qui gère l'arbre. L'argument FIELD est le nom de l'élément défini par RB_ENTRY.

Les corps des fonctions sont générés avec les macros RB_GENERATE() ou RB_GENERATE_STATIC() où celles-ci prennent les mêmes arguments que la macro RB_PROTOTYPE() et RB_GENERATE() et RB_GENERATE_STATIC().

SYNOPSIS

The following macros are available for manipulating tree data structures:

#include <sys/tree.h>

Red-black trees:

#define RB_HEAD(name, type) /* ... */
#define RB_INITIALIZER(head) /* ... */
#define RB_INIT(head) /* ... */
#define RB_INSERT(name, head, elm) /* ... */
#define RB_REMOVE(name, head, elm) /* ... */
#define RB_FIND(name, head, elm) /* ... */
#define RB_NFIND(name, head, elm) /* ... */
#define RB_ROOT(head) /* ... */
#define RB_MIN(name, head) /* ... */
#define RB_MAX(name, head) /* ... */
#define RB_NEXT(name, head, elm) /* ... */
#define RB_PREV(name, head, elm) /* ... */
#define RB_FOREACH(elm, name, head) /* ... */
#define RB_FOREACH_REVERSE(elm, name, head) /* ... */
#define RB_FOREACH_SAFE(elm, name, head, next) /* ... */
#define RB_FOREACH_REVERSE_SAFE(elm, name, head, next) /* ... */
#define RB_EMPTY(head) /* ... */
#define RB_PROTOTYPE(name, type, field, cmp) /* ... */
#define RB_GENERATE(name, type, field, cmp) /* ... */

DESCRIPTION

These macros implement red-black trees. Red-black trees are binary search trees with an additional field for each node which stores whether the node is red or black. Red-black trees are used to implement ordered sets and maps. They are designed to ensure that operations that take logarithmic time in the worst case (such as lookups, insertions and deletions) are efficient.

The macros use node structures derived from RB_ENTRY().

The RB_PROTOTYPE() macro declares the external tree head structure. It is to be placed in a header file. The RB_GENERATE() macro defines the tree head structure and the internal functions used to maintain the tree. It is to be placed in exactly one C file.

The name argument is the name of the tree. The type argument is the type of the structure that is stored in the tree. The field argument is the name of the RB_ENTRY() macro instance within the type structure. The cmp argument is the name of a function that compares nodes.

The RB_HEAD() macro declares the type of the tree head structure. The head argument is the name of the tree head structure.

The CMP argument is the name of a function used to compare trees' nodes with each other. The function takes two arguments of type struct TYPE *. If the first argument is smaller than the second, the function returns a value smaller than zero. If they are equal, the function returns zero. Otherwise, it should return a value greater than zero. The compare function defines the order of the tree elements.

The RB_INIT() macro initializes the tree referenced by head.

The red-black tree can also be initialized statically by using the RB_INITIALIZER() macro like this:

RB_HEAD(HEADNAME, TYPE) head = RB_INITIALIZER(&head);

The RB_INSERT() macro inserts the new element elm into the tree. Upon success, NULL is returned. If a matching element already exists in the tree, the insertion is aborted, and a pointer to the existing element is returned.

The RB_REMOVE() macro removes the element elm from the tree pointed by head. RB_REMOVE() returns elm.

The RB_FIND() and RB_NFIND() macros can be used to find a particular element in the tree. RB_FIND() finds the node with the same key as elm. RB_NFIND() finds the first node greater than or equal to the search key.

struct TYPE find, *res;
find.key = 30;
res = RB_FIND(NAME, &head, &find);

The RB_ROOT(), RB_MIN(), RB_MAX(), RB_NEXT(), and RB_PREV() macros can be used to traverse the tree:

for (np = RB_MIN(NAME, &head); np != NULL; np = RB_NEXT(NAME, &head, np))

Or, for simplicity, one can use the RB_FOREACH() or RB_FOREACH_REVERSE() macros:

RB_FOREACH(np, NAME, &head)

The macros RB_FOREACH_SAFE() and RB_FOREACH_REVERSE_SAFE() traverse the tree referenced by head in a forward or reverse direction respectively, assigning each element in turn to np. However, unlike their unsafe counterparts, they permit both the removal of np as well as freeing it from within the loop safely without interfering with the traversal.

The RB_EMPTY() macro should be used to check whether a red-black tree is empty.

EXAMPLES

The following example demonstrates how to declare a red-black tree holding integers. Values are inserted into it and the contents of the tree are printed in order. Lastly, the internal structure of the tree is printed.

#include <sys/tree.h>
#include <err.h>
#include <stdio.h>
#include <stdlib.h>

struct node {
	RB_ENTRY(node) entry;
	int i;
};

int	intcmp(struct node *, struct node *);
void	print_tree(struct node *);

int
intcmp(struct node *e1, struct node *e2)
{
	return (e1->i < e2->i ? -1 : e1->i > e2->i);
}

RB_HEAD(inttree, node) head = RB_INITIALIZER(&head);
RB_PROTOTYPE(inttree, node, entry, intcmp)
RB_GENERATE(inttree, node, entry, intcmp)

int testdata[] = {
	20, 16, 17, 13, 3, 6, 1, 8, 2, 4, 10, 19, 5, 9, 12, 15, 18,
	7, 11, 14
};

void
print_tree(struct node *n)
{
	struct node *left, *right;

	if (n == NULL) {
		printf("nil");
		return;
	}
	left = RB_LEFT(n, entry);
	right = RB_RIGHT(n, entry);
	if (left == NULL && right == NULL)
		printf("%d", n->i);
	else {
		printf("%d(", n->i);
		print_tree(left);
		printf(",");
		print_tree(right);
		printf(")");
	}
}

int
main(void)
{
	int i;
	struct node *n;

	for (i = 0; i < sizeof(testdata) / sizeof(testdata[0]); i++) {
		if ((n = malloc(sizeof(struct node))) == NULL)
			err(1, NULL);
		n->i = testdata[i];
		RB_INSERT(inttree, &head, n);
	}

	RB_FOREACH(n, inttree, &head) {
		printf("%d\n", n->i);
	}
	print_tree(RB_ROOT(&head));
	printf("\n");
	return (0);
}

NOTES

Trying to free a tree in the following way is a common error:

SPLAY_FOREACH(var, NAME, &head) {
	SPLAY_REMOVE(NAME, &head, var);
	free(var);
}
free(head);

Since var is free'd, the FOREACH() macro refers to a pointer that may have been reallocated already. Proper code needs a second variable.

for (var = SPLAY_MIN(NAME, &head); var != NULL; var = nxt) {
	nxt = SPLAY_NEXT(NAME, &head, var);
	SPLAY_REMOVE(NAME, &head, var);
	free(var);
}
