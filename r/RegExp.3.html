ARGUMENTS

Tcl_Interp *interp (in)
Interpréteur Tcl à utiliser pour le rapport d'erreurs. L'interpréteur peut être NULL si aucun rapport d'erreur n'est souhaité.
Tcl_Obj *textObj (in/out)
Fait référence à la valeur à partir de laquelle obtenir le texte à rechercher. La représentation interne de la valeur peut être convertie dans une forme pouvant être recherchée efficacement.
Tcl_Obj *patObj (in/out)
Fait référence à la valeur à partir de laquelle obtenir une expression régulière. L'expression régulière compilée est mise en cache dans la valeur.
const char *text (in)
Texte dans lequel rechercher une correspondance avec une expression régulière.
const char *pattern (in)
Chaîne sous forme de motif d'expression régulière.
Tcl_RegExp regexp (in)
Expression régulière compilée. Doit avoir été retournée précédemment par Tcl_GetRegExpFromObj ou Tcl_RegExpCompile.
const char *start (in)
Si text n'est qu'une portion d'une autre chaîne, cet argument identifie le début de la chaîne plus grande. S'il n'est pas identique à text, alors aucune correspondance “^” ne sera permise.
int index (in)
Spécifie quelle plage est désirée : 0 signifie la plage de la correspondance entière, 1 ou plus signifie la plage qui correspondait à une sous-expression entre parenthèses.
const char **startPtr (out)
L'adresse du premier caractère dans la plage est stockée ici, ou NULL s'il n'y a pas de telle plage.
const char **endPtr (out)
L'adresse du caractère juste après le dernier caractère dans la plage est stockée ici, ou NULL s'il n'y a pas de telle plage.
int cflags (in)
Combinaison OR des indicateurs de compilation TCL_REG_ADVANCED, TCL_REG_EXTENDED, TCL_REG_BASIC, TCL_REG_EXPANDED, TCL_REG_QUOTE, TCL_REG_NOCASE, TCL_REG_NEWLINE, TCL_REG_NLSTOP, TCL_REG_NLANCH, TCL_REG_NOSUB, et TCL_REG_CANMATCH. Voir ci-dessous pour plus d'informations.
int offset (in)
Le décalage de caractères dans le texte où la recherche doit commencer. La valeur du décalage n'a aucun impact sur les correspondances ^. Ce comportement est contrôlé par eflags.
int nmatches (in)
Le nombre de sous-expressions correspondantes qui doivent être mémorisées pour une utilisation ultérieure. Si cette valeur est 0, aucune information de correspondance de sous-expression ne sera calculée. Si la valeur est -1, toutes les sous-expressions correspondantes seront mémorisées. Toute autre valeur sera considérée comme le nombre maximum de sous-expressions à mémoriser.
int eflags (in)
Combinaison OR des indicateurs d'exécution TCL_REG_NOTBOL et TCL_REG_NOTEOL. Voir ci-dessous pour plus d'informations.
Tcl_RegExpInfo *infoPtr (out)
L'adresse de l'emplacement où les informations sur une correspondance précédente doivent être stockées par Tcl_RegExpGetInfo.

DESCRIPTION

Tcl_RegExpMatch détermine si son argument pattern correspond à regexp, où regexp est interprété comme une expression régulière selon les règles de la page de référence re_syntax. S'il y a une correspondance, Tcl_RegExpMatch retourne 1. S'il n'y a pas de correspondance, Tcl_RegExpMatch retourne 0. Si une erreur se produit pendant le processus de correspondance (par exemple, pattern n'est pas une expression régulière valide), Tcl_RegExpMatch retourne -1 et laisse un message d'erreur dans le résultat de l'interpréteur. Tcl_RegExpMatchObj est similaire à Tcl_RegExpMatch sauf qu'elle opère sur les valeurs Tcl textObj et patObj au lieu de chaînes UTF. Tcl_RegExpMatchObj est généralement plus efficace que Tcl_RegExpMatch, c'est donc l'interface préférée.

Tcl_RegExpCompile, Tcl_RegExpExec, et Tcl_RegExpRange fournissent un accès de plus bas niveau au moteur de correspondance d'expressions régulières. Tcl_RegExpCompile compile une chaîne d'expression régulière dans la forme interne utilisée pour une correspondance efficace. La valeur de retour est un jeton pour cette forme compilée, qui peut être utilisé dans des appels ultérieurs à Tcl_RegExpExec ou Tcl_RegExpRange. Si une erreur se produit lors de la compilation de l'expression régulière, Tcl_RegExpCompile retourne NULL et laisse un message d'erreur dans le résultat de l'interpréteur. Note : la valeur de retour de Tcl_RegExpCompile n'est valide que jusqu'au prochain appel à Tcl_RegExpCompile ; il n'est pas sûr de conserver ces valeurs pendant de longues périodes.

Tcl_RegExpExec exécute le moteur de correspondance d'expressions régulières. Il retourne 1 si text contient une plage de caractères qui correspond à regexp, 0 s'il n'y a pas de correspondance, et -1 si une erreur se produit. En cas d'erreur, Tcl_RegExpExec laisse un message d'erreur dans le résultat de l'interpréteur. Lors de la recherche d'une chaîne pour plusieurs correspondances d'un motif, il est important de distinguer le début de la chaîne d'origine et le début de la recherche actuelle. Par exemple, lors de la recherche de la deuxième occurrence d'une correspondance, l'argument text peut pointer vers le caractère juste après la première correspondance ; cependant, il est important que le moteur de correspondance sache que ce n'est pas le début de la chaîne entière, afin qu'il n'autorise pas les atomes “^” du motif à correspondre. L'argument start fournit cette information en pointant vers le début de la chaîne globale contenant text. Start sera inférieur ou égal à text ; s'il est inférieur à text, aucune correspondance ^ ne sera autorisée.

Tcl_RegExpRange peut être appelée après que Tcl_RegExpExec ait retourné ; elle fournit des informations détaillées sur quelles plages de la chaîne correspondent à quelles parties du motif. Tcl_RegExpRange retourne une paire de pointeurs dans *startPtr et *endPtr qui identifient une plage de caractères dans la chaîne source pour l'appel le plus récent à Tcl_RegExpExec. Index indique quelle de plusieurs plages est désirée : si index est 0, des informations sont retournées sur la plage globale de caractères qui a correspondu à l'ensemble du motif ; sinon, des informations sont retournées sur la plage de caractères qui a correspondu à la index-ième sous-expression entre parenthèses dans le motif. S'il n'y a pas de plage correspondant à index, NULL est stocké dans *startPtr et *endPtr.

Tcl_GetRegExpFromObj, Tcl_RegExpExecObj, et Tcl_RegExpGetInfo sont des interfaces de valeur qui fournissent le contrôle le plus direct de la bibliothèque d'expressions régulières de Henry Spencer. Pour les utilisateurs qui ont besoin de modifier directement les options de compilation et d'exécution, il est recommandé d'utiliser ces interfaces plutôt que d'appeler les fonctions internes de regexp. Ces interfaces gèrent les détails des traductions UTF vers Unicode ainsi que l'amélioration des performances grâce à la mise en cache dans les valeurs de motif et de chaîne.

Tcl_GetRegExpFromObj tente de retourner une expression régulière compilée à partir de patObj. Si la valeur ne contient pas déjà une expression régulière compilée, elle tentera d'en créer une à partir de la chaîne dans la valeur et de l'assigner à la représentation interne de patObj. La valeur de retour de cette fonction est de type Tcl_RegExp. La valeur de retour est un jeton pour cette forme compilée, qui peut être utilisé dans des appels ultérieurs à Tcl_RegExpExecObj ou Tcl_RegExpGetInfo. Si une erreur se produit lors de la compilation de l'expression régulière, Tcl_GetRegExpFromObj retourne NULL et laisse un message d'erreur dans le résultat de l'interpréteur. Le jeton d'expression régulière peut être utilisé tant que la représentation interne de patObj fait référence à la forme compilée. ARGUMENTS

TCL_REG_ADVANCED
Compile les expressions régulières avancées (« ARE »). Ce mode correspond à la syntaxe normale des expressions régulières acceptée par les commandes Tcl regexp et regsub.
TCL_REG_EXTENDED
Compile les expressions régulières étendues (« ERE »). Ce mode correspond à la syntaxe des expressions régulières reconnue par Tcl 8.0 et les versions antérieures.
TCL_REG_BASIC
Compile les expressions régulières de base (« BRE »). Ce mode correspond à la syntaxe des expressions régulières reconnue par les utilitaires Unix courants comme sed et grep. C'est le mode par défaut si aucun indicateur n'est spécifié.
TCL_REG_EXPANDED
Compile l'expression régulière (de base, étendue ou avancée) en utilisant une syntaxe étendue qui autorise les commentaires et les espaces. Ce mode ignore les espaces blancs non entourés de barre oblique inverse et non dans une expression entre crochets, ainsi que les commentaires de type # jusqu'à la fin de la ligne.
TCL_REG_QUOTE
Compile une chaîne littérale, tous les caractères étant traités comme des caractères ordinaires.
TCL_REG_NOCASE
Compile pour une correspondance ignorant la différence entre majuscules et minuscules.
TCL_REG_NEWLINE
Compile pour une correspondance sensible aux sauts de ligne. Par défaut, le saut de ligne est un caractère complètement ordinaire sans signification spéciale dans les expressions régulières ou les chaînes. Avec cet indicateur, les expressions entre crochets (« [^ ») et le caractère « . » ne correspondent jamais au saut de ligne, « ^ » correspond à une chaîne vide après tout saut de ligne en plus de sa fonction normale, et « $ » correspond à une chaîne vide avant tout saut de ligne en plus de sa fonction normale. REG_NEWLINE est l'opération OU bit-à-bit de REG_NLSTOP et REG_NLANCH.
TCL_REG_NLSTOP
Compile pour une correspondance partielle sensible aux sauts de ligne, avec le comportement des expressions entre crochets (« [^ ») et du caractère « . » affecté, mais pas le comportement de « ^ » et « $ ». Dans ce mode, les expressions entre crochets (« [^ ») et le caractère « . » ne correspondent jamais au saut de ligne.
TCL_REG_NLANCH
Compile pour une correspondance partielle inverse sensible aux sauts de ligne, avec le comportement de « ^ » et « $ » (les « ancres ») affecté, mais pas le comportement des expressions entre crochets (« [^ ») et du caractère « . ». Dans ce mode, « ^ » correspond à une chaîne vide après tout saut de ligne en plus de sa fonction normale, et « $ » correspond à une chaîne vide avant tout saut de ligne en plus de sa fonction normale.
TCL_REG_NOSUB
Compile pour une correspondance qui ne rapporte que le succès ou l'\x00E9;chec, pas ce qui a été correspondant. Cela réduit la charge de compilation et peut améliorer les performances. Les appels ultérieurs à Tcl_RegExpGetInfo ou Tcl_RegExpRange ne rapporteront aucune information sur la correspondance.
TCL_REG_CANMATCH
Compile pour une correspondance qui rapporte la possibilité de compléter une correspondance partielle compte tenu de texte supplémentaire (voir ci-dessous).

Un seul parmi TCL_REG_EXTENDED, TCL_REG_ADVANCED, TCL_REG_BASIC et TCL_REG_QUOTE peut êt;re spécifié.

Tcl_RegExpExecObj exécute le moteur de correspondance de motifs d'expressions régulières. Elle retourne 1 si objPtr contient une plage de caractères qui correspondent à regexp, 0 si aucune correspondance n'est trouvée, et -1 si une erreur se produit. En cas d'erreur, Tcl_RegExpExecObj laisse un message d'erreur dans le résultat de l'interpréteur. La valeur nmatches indique au moteur combien de sous-expressions sont d'intérêt;. Si nmatches est 0, alors aucune information sur les sous-expressions correspondantes n'est enregistrée, ce qui peut permettre au moteur de faire diverses optimisations. Si la valeur est -1, alors toutes les sous-expressions du motif sont mémorisées. Si la valeur est un entier positif, alors seul ce nombre de sous-expressions sera mémorisé. La correspondance commence à l'index de caractère Unicode spécifié par offset. Contrairement à Tcl_RegExpExec, le comportement des ancres n'est pas affecté par la valeur d'offset. Au lieu de cela, le comportement des ancres est explicitement contrôlé par l'argument eflags, qui est une opération OU bit-à-bit de zéro ou plusieurs des indicateurs suivants:

TCL_REG_NOTBOL
Le caractère de début ne sera pas traité comme le début d'une ligne ou le début de la chaîne, donc « ^ » ne correspondra pas là cet endroit. Notez que cet indicateur n'a aucun effet sur la correspondance de « \A ».
TCL_REG_NOTEOL
Le dernier caractère de la chaîne ne sera pas traité comme la fin d'une ligne ou la fin de la chaîne, donc « $ » ne correspondra pas à cet endroit. Notez que cet indicateur n'a aucun effet sur la correspondance de « \Z ».

Tcl_RegExpGetInfo récupère des informations sur la dernière correspondance effectuée avec une expression régulière donnée regexp. L'argument infoPtr contient un pointeur vers une structure définie comme suit :

typedef struct Tcl_RegExpInfo {
    int nsubs;
    Tcl_RegExpIndices *matches;
    long extendStart;
} Tcl_RegExpInfo;

Le champ nsubs contient un compte du nombre de sous-expressions entre parenthèses dans l'expression régulière. Si TCL_REG_NOSUB a été utilisé, alors cette valeur sera zéro. Le champ matches pointe vers un tableau de nsubs+1 valeurs qui indiquent les limites de chaque sous-expression correspondante. Le premier élément du tableau fait référence à la plage correspondant par l'expression régulière entière, et les éléments suivants font référence aux sous-expressions entre parenthèses dans l'ordre où elles apparaissent dans le motif. Chaque élément est une structure définie comme suit :

typedef struct Tcl_RegExpIndices {
    long start;
    long end;
} Tcl_RegExpIndices;

Les valeurs start et end sont des index de caractères Unicode par rapport à la position de décalage dans objPtr où la correspondance a commencé. L'index start identifie le premier caractère de la sous-expression correspondante. L'index end identifie le premier caractère après la sous-expression correspondante. Si la sous-expression a correspondant la chaîne vide, alors start et end seront égaux. Si la sous-expression n'a pas participé à la correspondance, alors start et end seront mis à -1.

Le champ extendStart dans Tcl_RegExpInfo n'est défini que si l'indicateur TCL_REG_CANMATCH a été utilisé. Il indique le premier caractère de la chaîne où une correspondance pourrait se produire. Si une correspondance a été trouvée, ce sera le début de la correspondance actuelle. Si aucune correspondance n'a été trouvée, il indiquera le point le plus précoce auquel une correspondance pourrait se produire si du texte supplémentaire est ajouté à la chaîne. Si aucune correspondance n'est possible même avec du texte supplémentaire, ce champ sera mis à -1.
