NOM

RAND - le générateur aléatoire OpenSSL

DESCRIPTION

Les nombres aléatoires sont un élément vital de la cryptographie ; ils sont nécessaires pour fournir de l'imprévisibilité pour des tâches telles que la génération de clés, la création de sels, et bien d'autres. Les générateurs basés sur logiciel doivent être initialisés avec de l'aléatoire externe avant de pouvoir être utilisés comme générateur de nombres pseudo-aléatoires cryptographiquement sécurisés (CSPRNG). La disponibilité de matériel courant avec des instructions spéciales et des systèmes d'exploitation modernes, qui peuvent utiliser des éléments tels que le jitter d'interruption et les temporisations des paquets réseau, peut être une source raisonnable de matériel d'initialisation.

OpenSSL est livré avec une implémentation par défaut de l'API RAND qui est basée sur le modèle du générateur de bits aléatoires déterministe (DRBG) tel que décrit dans [NIST SP 800-90A Rev. 1]. Le générateur aléatoire par défaut s'initialisera automatiquement lors de sa première utilisation et sera pleinement fonctionnel sans avoir à être explicitement initialisé ('seedé'). Il s'initialise et se réinitialise automatiquement en utilisant des sources aléatoires fiables fournies par le système d'exploitation.

En tant que développeur d'application normal, vous n'avez pas à vous soucier des détails, utilisez simplement RAND_bytes(3) pour obtenir des données aléatoires. Ceci dit, il y a une règle importante à respecter : vérifiez toujours la valeur de retour d'erreur de RAND_bytes(3) et ne prenez pas l'aléatoire pour acquis. Bien que l'initialisation (réinitialisation) soit automatique, elle peut échouer car aucune source aléatoire fiable n'est disponible ou les sources fiables échouent temporairement à fournir suffisamment de matériel d'initialisation aléatoire. Dans ce cas, le CSPRNG entre dans un état d'erreur et cesse de fournir une sortie, jusqu'à ce qu'il puisse se rétablir de l'erreur en se réinitialisant. Pour plus de détails sur la réinitialisation et la récupération d'erreurs, voir EVP_RAND(7).

Pour les valeurs qui doivent rester secrètes, vous pouvez utiliser RAND_priv_bytes(3) à la place. Cette méthode ne fournit pas de meilleure aléatoire ; elle utilise le même type de CSPRNG. L'intention derrière l'utilisation d'un CSPRNG dédié exclusivement aux valeurs privées est qu'aucune de ses sorties ne doit être visible par un attaquant (par exemple, utilisée comme valeur de sel), afin de révéler le moins d'informations possible sur son état interne, et qu'un compromis de l'instance CSPRNG « publique » n'affectera pas la confidentialité de ces valeurs privées.

Dans le cas rare où l'implémentation par défaut ne satisferait pas vos exigences spéciales, les internes RAND par défaut peuvent être remplacés par vos propres objets EVP_RAND(3).

Changer le générateur aléatoire par défaut ne devrait être nécessaire que dans des cas exceptionnels et n'est pas recommandé, à moins que vous n'ayez une connaissance approfondie des principes cryptographiques et que vous ne compreniez les implications de vos changements.

Enfin, il est possible pour un fournisseur de contourner la configuration RAND par défaut pour RAND_bytes(3) et les fonctions associées. Un fournisseur peut être spécifié comme la seule source d'aléatoire via la fonction RAND_set1_random_provider(3) ou via la configuration en utilisant l'option random_provider dans config(5). Une fois spécifié, le fournisseur désigné sera utilisé directement lors de l'appel à la famille de fonctions RAND_bytes(3).

CONFIGURATION PAR DÉFAUT

La méthode RAND par défaut d'OpenSSL est basée sur les classes de générateur de bits aléatoires déterministes (DRBG) EVP_RAND. Un DRBG est un certain type de générateur de nombres pseudo-aléatoires cryptographiquement sécurisés (CSPRNG), qui est décrit dans [NIST SP 800-90A Rev. 1].

VOIR AUSSI

RAND_bytes(3), RAND_priv_bytes(3), EVP_RAND(3), RAND_get0_primary(3), config(5), EVP_RAND(7), RAND_set1_random_provider(3).
