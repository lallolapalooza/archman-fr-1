RRDp(3pm)

Paquet: rrdtool

Licences: GPL-2.0-or-later

RRDp(3pm) Documentation Perl fournie par l'utilisateur RRDp(3pm)

NOM

RRDp - Attacher RRDtool depuis un script perl via un ensemble de pipes ;

SYNTAXE

use RRDp

RRDp::start chemin vers l'exécutable RRDtool

RRDp::cmd ligne de commande rrdtool

$réponse = RRD::read

$statut = RRD::end

$RRDp::user, $RRDp::sys, $RRDp::real, $RRDp::error_mode, $RRDp::error

DESCRIPTION

Avec ce module, vous pouvez communiquer en toute sécurité avec RRDtool.

Après chaque RRDp::cmd, vous devez émettre une commande RRDp::read pour obtenir la réponse de RRDtool à votre commande. La réponse est retournée sous forme de pointeur, afin d'accélérer les choses. Si la dernière commande n'a retourné aucune donnée, RRDp::read retournera une variable indéfinie.

Si vous importez les variables PERFORMANCE dans votre espace de noms, vous pouvez accéder aux mesures de performance internes de RRDtool.

use RRDp
Charge le module RRDp::pipe.
RRDp::start chemin vers l'exécutable RRDtool
démarre RRDtool. L'argument doit être le chemin vers l'exécutable RRDtool
RRDp::cmd ligne de commande rrdtool
transmet les commandes à RRDtool. Consultez la documentation RRDtool pour plus d'informations sur les commandes RRDtool.

Note : En raison de limitations de conception, RRDp::cmd ne prend pas en charge la commande "graph -" - utilisez plutôt "graphv -".

$réponse = RRDp::read
lit la réponse de RRDtool à votre commande. Notez que la variable $réponse ne contiendra qu'un pointeur vers les données retournées. La raison en est que RRDtool peut potentiellement retourner des quantités de données assez excessives et nous ne voulons pas copier cela en mémoire. Donc, lorsque vous souhaitez accéder au contenu de $réponse, vous devez utiliser $$réponse qui déréférence la variable.
$statut = RRDp::end
termine RRDtool et retourne le statut de RRDtool...
$RRDp::user, $RRDp::sys, $RRDp::real
ces variables contiendront les totaux du temps utilisateur, du temps système et du temps réel tels que vus par RRDtool. Le temps utilisateur est le temps pendant lequel RRDtool s'exécute, le temps système est le temps passé dans les appels système et le temps réel est le temps total pendant lequel RRDtool s'est exécuté.

La différence entre le temps utilisateur + système et le temps réel est le temps passé à attendre des choses comme le disque dur et de nouvelles entrées du script Perl.

$RRDp::error_mode et $RRDp::error
Si vous définissez la variable $RRDp::error_mode à la valeur 'catch' avant d'exécuter RRDp::read, un message d'erreur potentiel ne provoquera pas l'arrêt du programme mais sera retourné dans cette variable. Aucune erreur ne se produisant, la variable sera vide. 
$RRDp::error_mode = 'catch';
RRDp::cmd qw(info file.rrd);
print $RRDp::error if $RRDp::error;

EXEMPLE

use RRDp;
RRDp::start "/usr/local/bin/rrdtool";
RRDp::cmd   qw(create demo.rrd --step 100 
              DS:in:GAUGE:100:U:U
              RRA:AVERAGE:0.5:1:10);
$answer = RRDp::read;
print $$answer;
($temps_utilisateur,$temps_systeme,$temps_reel) =  ($RRDp::user,$RRDp::sys,$RRDp::real);

Pour plus d'informations sur l'utilisation de RRDtool, consultez les manpages.
