NOM

RSA_padding_add_PKCS1_type_1, RSA_padding_check_PKCS1_type_1, RSA_padding_add_PKCS1_type_2, RSA_padding_check_PKCS1_type_2, RSA_padding_add_PKCS1_OAEP, RSA_padding_check_PKCS1_OAEP, RSA_padding_add_PKCS1_OAEP_mgf1, RSA_padding_check_PKCS1_OAEP_mgf1, RSA_padding_add_none, RSA_padding_check_none - remplissage de chiffrement asymétrique

SYNTAXE

#include <openssl/rsa.h>

Les fonctions suivantes ont été dépréciées depuis OpenSSL 3.0, et peuvent être entièrement masquées en définissant OPENSSL_API_COMPAT avec une valeur de version appropriée, voir openssl_user_macros(7) :

                                 const unsigned char *f, int fl);
int RSA_padding_check_PKCS1_type_1(unsigned char *to, int tlen,
                                   const unsigned char *f, int fl, int rsa_len);
int RSA_padding_add_PKCS1_type_2(unsigned char *to, int tlen,
                                 const unsigned char *f, int fl);
int RSA_padding_check_PKCS1_type_2(unsigned char *to, int tlen,
                                   const unsigned char *f, int fl, int rsa_len);
int RSA_padding_add_PKCS1_OAEP(unsigned char *to, int tlen,
                               const unsigned char *f, int fl,
                               const unsigned char *p, int pl);
int RSA_padding_check_PKCS1_OAEP(unsigned char *to, int tlen,
                                 const unsigned char *f, int fl, int rsa_len,
                                 const unsigned char *p, int pl);
int RSA_padding_add_PKCS1_OAEP_mgf1(unsigned char *to, int tlen,
                                    const unsigned char *f, int fl,
                                    const unsigned char *p, int pl,
                                    const EVP_MD *md, const EVP_MD *mgf1md);
int RSA_padding_check_PKCS1_OAEP_mgf1(unsigned char *to, int tlen,
                                      const unsigned char *f, int fl, int rsa_len,
                                      const unsigned char *p, int pl,
                                      const EVP_MD *md, const EVP_MD *mgf1md);
int RSA_padding_add_none(unsigned char *to, int tlen,
                         const unsigned char *f, int fl);
int RSA_padding_check_none(unsigned char *to, int tlen,
                           const unsigned char *f, int fl, int rsa_len);

DESCRIPTION

Toutes les fonctions décrites sur cette page sont dépréciées. Les applications devraient plutôt utiliser les API PKEY d'EVP.

Les fonctions RSA_padding_xxx_xxx() sont appelées à partir des fonctions de chiffrement, déchiffrement, signature et vérification RSA. Normalement, elles ne devraient pas être appelées depuis les programmes applicatifs.

Cependant, elles peuvent également être appelées directement pour implémenter le remplissage pour d'autres chiffrements asymétriques. RSA_padding_add_PKCS1_OAEP() et RSA_padding_check_PKCS1_OAEP() peuvent être utilisées dans une application combinée avec RSA_NO_PADDING afin d'implémenter OAEP avec un paramètre d'encodage.

RSA_padding_add_xxx() encode fl octets à partir de f de manière à tenir dans tlen octets et stocke le résultat à to. Une erreur se produit si fl ne respecte pas les exigences de taille de la méthode d'encodage.

Les méthodes d'encodage suivantes sont implémentées :

PKCS1_type_1
EMSA-PKCS1-v1_5 de PKCS #1 v2.0 (type de bloc v1.5 de PKCS #1 type 1) ; utilisé pour les signatures
PKCS1_type_2
EME-PKCS1-v1_5 de PKCS #1 v2.0 (type de bloc v1.5 de PKCS #1 type 2)
PKCS1_OAEP
EME-OAEP de PKCS #1 v2.0
none
copier simplement les données

Le générateur de nombres aléatoires doit être amorcé avant d'appeler RSA_padding_add_xxx(). Si l'amorçage ou le réamorçage automatique du CSPRNG d'OpenSSL échoue en raison de circonstances externes (voir RAND(7)), l'opération échouera.

RSA_padding_check_xxx() vérifie que les fl octets situés à f contiennent un encodage valide pour une clé RSA de rsa_len octets dans la méthode d'encodage respective et stocke les données récupérées d'au plus tlen octets (pour RSA_NO_PADDING : de taille tlen) à to.

Pour RSA_padding_xxx_OAEP(), p pointe vers le paramètre d'encodage de longueur pl. p peut être NULL si pl est 0.

Pour RSA_padding_xxx_OAEP_mgf1(), md pointe vers le hachage md, si md est NULL cela signifie md=sha1, et mgf1md pointe vers le hachage mgf1, si mgf1md est NULL cela signifie mgf1md=md.

VALEURS DE RETOUR

Les fonctions RSA_padding_add_xxx() retournent 1 en cas de succès, 0 en cas d'erreur. Les fonctions RSA_padding_check_xxx() retournent la longueur des données récupérées, -1 en cas d'erreur. Les codes d'erreur peuvent être obtenus en appelant ERR_get_error(3).

AVERTISSEMENTS

Le résultat de RSA_padding_check_PKCS1_type_2() est exactement l'information qui est utilisée pour monter une attaque classique d'oracle de remplissage de Bleichenbacher. C'est une faiblesse inhérente à la conception du remplissage PKCS #1 v1.5. Préférez le remplissage PKCS1_OAEP. Si cela n'est pas possible, le résultat de RSA_padding_check_PKCS1_type_2() devrait être vérifié en temps constant s'il correspond à la longueur attendue du texte en clair et si des vérifications de cohérence spécifiques à l'application sur le texte en clair doivent être effectuées en temps constant. Si le texte en clair est rejeté, il faut garder secret quel contrôle a provoqué le rejet du message par l'application. Ne supprimez pas le remplissage zéro des données RSA brutes déchiffrées qui ont été calculées par RSA_private_decrypt() avec RSA_NO_PADDING, car cela créerait un petit canal secondaire de temporisation qui pourrait être utilisé pour monter une attaque de Bleichenbacher contre tout mode de remplissage, y compris PKCS1_OAEP.

Vous devriez préférer l'utilisation des API EVP PKEY pour le déchiffrement PKCS#1 v1.5 car elles implémentent les contournements nécessaires en interne.
