NOM

Razor::Errorhandler - Mécanisme de gestion des erreurs pour Razor.

SYNOPSIS

package Foo;
use Razor::Errorhandler;
@ISA = qw(Razor::Errorhandler);
sub alive { 
    ..
    ..
    return 
    $self->error ("Awake, awake! Ring the alarum bell. \
                   Murther and treason!", $dagger) 
        if $self->murdered($king);
}
package main; 
use Foo;
my $foo = new Foo;
$foo->alive($king) or print $foo->errstr(); 
# affiche "Awake, awake! ... "

DESCRIPTION

Razor::Errorhandler encapsule le mécanisme de gestion des erreurs utilisé par les modules de la suite Razor. Razor::Errorhandler n'a pas de constructeur et est destiné à être hérité. Les modules dérivés utilisent ses deux méthodes, error() et errstr(), pour communiquer les messages d'erreur à l'appelant.

Lorsqu'une méthode du module dérivé échoue, elle appelle $self->error() et retourne à l'appelant. Le message d'erreur passé à error() est mis à la disposition de l'appelant via l'accesseur errstr(). error() accepte également une liste de données sensibles qu'il efface (met à undef) avant de retourner.

L'appelant ne doit jamais appeler errstr() pour vérifier les erreurs. errstr() ne doit être appelé que lorsqu'une méthode indique (généralement par une valeur de retour undef) qu'une erreur s'est produite. En effet, errstr() n'est jamais écrasé et contiendra toujours une valeur après la survenue de la première erreur.

MÉTHODES

error($mesage, ($wipeme, $wipemetoo))
Le premier argument de error() est $message qui est placé dans $self->{errstr} et les arguments restants sont interprétés comme des variables contenant des données sensibles qui sont effacées de la mémoire. error() retourne toujours undef.
errstr()
errstr() est une méthode d'accesseur pour $self->{errstr}.
