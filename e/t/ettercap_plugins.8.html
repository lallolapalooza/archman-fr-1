N

Ettercap(8) prend en charge les modules chargeables à l'exécution. Ils sont appelés plugins et sont inclus dans l'archive tar des sources. Ils sont automatiquement compilés si votre système les prend en charge, sauf si vous spécifiez l'option -DENABLE_PLUGINS=OFF au script de configuration cmake.
Certains des anciens plugins d'ettercap (roper, banshee, etc.) n'ont pas été portés vers la nouvelle version. Cependant, vous pouvez obtenir les mêmes résultats en utilisant le nouveau moteur de filtrage.
Si vous utilisez le mode interactif, la plupart des plugins nécessitent de démarrer le "Start Sniff" avant de les

utiliser.
Pour obtenir la liste des plugins installés sur votre système, exécutez cette commande
:

ette

rcap
-P
list

op

précisément.

exemple

autoa
dd

Il ajoutera automatiquement de nouvelles victimes à l'attaque MITM par empoisonnement ARP lorsqu'elles apparaissent. Il recherche les requêtes ARP sur le LAN et, lorsqu'elles sont détectées, il ajoutera l'hôte à la liste des victimes s'il a été spécifié dans la cible (TARGET). L'hôte est ajouté lorsqu'une requête ARP est vue provenant de lui, car les hôtes qui communiquent

sont vivants
:)
chk_pois
on

Il effectue une vérification pour voir si le module d'empoisonnement ARP d'ettercap a réussi. Il envoie des paquets ICMP echo falsifiés à toutes les victimes de l'empoisonnement en se faisant passer pour chacune des autres cibles. Si nous pouvons intercepter une réponse ICMP avec notre adresse MAC comme destination, cela signifie que l'empoisonnement entre ces deux cibles est réussi. Il vérifie les deux sens de chaque communication. Ce plugin n'a de sens que là où l'empoisonnement a du sens. Le test échoue si vous ne spécifiez qu'une seule cible en mode silencieux. Vous ne pouvez pas exécuter ce plugin depuis la ligne de commande car le processus d'empoisonnement n'est pas encore démarré. Vous devez le lancer depuis le

menu
approprié.
dns_spo
of

Ce plugin intercepte les requêtes DNS et répond avec une réponse falsifiée. Vous pouvez choisir les adresses auxquelles le plugin doit répondre, ainsi que le temps d'expiration en secondes (TTL) en modifiant le fichier etter.dns. Le plugin intercepte les requêtes A, AAAA, PTR, MX, WINS, SRV et TXT. S'il s'agissait d'une requête A, le nom est recherché dans le fichier et l'adresse IP est renvoyée (vous pouvez utiliser des caractères génériques dans le nom).
La même chose s'applique s'il s'agissait d'une requête

AAAA.

Le TTL est un champ facultatif qui est spécifié comme dernière option dans une entrée du fichier etter.dns. Le TTL est spécifié en nombre de secondes de 0 à 2^31-1 (voir RFC 2181). Le TTL est spécifié par hôte. Si le TTL n'est pas spécifié pour un hôte particulier, la valeur par défaut est de 3600 secondes (1

heure).

S'il s'agissait d'une requête PTR, l'adresse IP est recherchée dans le fichier et le nom est renvoyé (sauf pour les noms contenant un caractère générique). Pour les requêtes PTR, les adresses IPv4 ou IPv6 sont prises en

charge.

Dans le cas d'une requête MX, une réponse spéciale est fabriquée. L'hôte est résolu avec un hôte factice 'mail.host' et l'enregistrement additionnel contient l'adresse IP de 'mail.host'. La première adresse correspondante est renvoyée, alors faites attention à l'ordre. L'adresse IP pour les requêtes MX peut être une adresse IPv4 ou

IPv6.

Si la requête était une requête WINS, le nom est recherché dans le fichier et l'adresse IP est

renvoyée.

Dans le cas d'une requête SRV, une réponse spéciale est fabriquée. L'hôte est résolu avec un hôte factice 'srv.host' et l'enregistrement additionnel contient l'adresse IP de 'srv.host'. L'adresse IP pour les requêtes SRV peut être une adresse IPv4 ou

IPv6.

Dans le cas d'une requête TXT, la chaîne définie est renvoyée. La chaîne doit être entre guillemets doubles. Les caractères génériques pour le nom demandé peuvent également être

utilisés.

Une réponse spéciale peut être falsifiée pour les requêtes A ou AAAA, si l'« adresse indéfinie » est spécifiée comme adresse IP dans le fichier. Alors le client reçoit une réponse qui arrête immédiatement le traitement de la résolution. De cette façon, on peut contrôler quelle famille d'adresses est utilisée pour accéder à un hôte double

pile.

Dans le cas d'une requête ANY, tous les résultats correspondants de type A, AAAA, MX et TXT sont renvoyés dans la réponse. Si l'« adresse indéfinie » pour les enregistrements A ou AAAA est définie, rien n'est renvoyé pour ces types, que le nom

corresponde ou
non.
mdns_spo
of

Ce plugin fait la même chose que le plugin dns_spoof décrit ci-dessus, sauf qu'il écoute les requêtes mDNS (Multicast DNS) sur le port UDP 5353. Pour choisir l'adresse à laquelle le plugin doit répondre, vous devez modifier un fichier différent appelé etter.mdns. En raison de la nature de mDNS, le plugin n'intercepte que les requêtes A, AAAA, PTR et

SRV.

La façon dont le plugin mdns_spoof interprète le fichier etter.mdns et les règles qui s'appliquent sont les mêmes qu'avec le plugin dns_spoof, bien que le plugin mdns_spoof ne prenne actuellement pas en charge un TTL personnalisé. Le TTL pour toutes les réponses mDNS falsifiées est de 3600

secondes (1 heure)
.
dos_atta
ck

Ce plugin lance une attaque d.o.s. contre une adresse IP victime. Il « scanne » d'abord la victime pour trouver les ports ouverts, puis commence à inonder ces ports avec des paquets SYN, en utilisant une adresse « fantôme » comme adresse IP source. Ensuite, il utilise des réponses ARP factices pour intercepter les paquets pour l' hôte fantôme. Lorsqu'il reçoit un SYN-ACK de la victime, il répond avec un paquet ACK créant une connexion ESTABLISHED. Vous devez utiliser une adresse IP libre dans votre sous-réseau pour créer l'hôte « fantôme » (vous pouvez utiliser find_ip à cette fin). Vous ne pouvez pas exécuter ce plugin en mode non offensif.
Ce plugin est basé sur l'attaque DoS originale Naptha (http://razor.bindview.com/publish/advisor

ies/adv_NAPTHA.html)

ettercap

gre_rel
ay

Ce plugin peut être utilisé pour renifler le trafic distant redirigé par GRE. L'idée de base est de créer un tunnel GRE qui envoie tout le trafic d'une interface de routeur vers la machine ettercap. Le plugin renverra les paquets GRE au routeur, après la "manipulation" par ettercap (vous pouvez utiliser des plugins "actifs" tels que smb_down, le déchiffrement ssh, les filtres, etc... sur le trafic redirigé). Il nécessite un hôte "factice" vers lequel le trafic doit être redirigé (pour éviter les réponses du noyau). L'IP "factice" sera le point de terminaison du tunnel. Le plugin gre_relay se fera passer pour l'hôte "factice". Pour trouver une adresse IP inutilisée pour l'hôte "factice", vous pouvez utiliser le plugin find_ip. Basé sur la technique Tunnelx originale par Anthony C. Zboralski (http://www.phrack.org/ar

Il sollicite des paquets d'empoisonnement après des requêtes ARP de diffusion (ou réponses) d'un hôte empoisonné. Par exemple : nous empoisonnons Groupe1 en nous faisant passer pour Hôte2. NAME

ettercap_plugins - plugin list for ettercap

DESCRIPTION

This page describes the plugins available with ettercap. These plugins are used for several purposes, mostly related to network security, sniffing, and man-in-the-middle attacks.

arp_spoof

This plugin is the most common plugin for ARP poisoning. It can be used to make packets sent by some host go through your machine. It can be used for sniffing or for mitm attacks.

example:

ettercap -Tq -i eth0 // -P arp_spoof

dhcp_spoof

This plugin can be used to spoof DHCP replies and give hosts on the network false IP addresses, or to make them use a malicious DHCP server.

example:

ettercap -Tq -i eth0 // -P dhcp_spoof

dns_spoof

This plugin allows you to spoof DNS answers. If a host requests the IP address for a domain name, this plugin can provide a false IP address.

example:

ettercap -Tq -i eth0 // -P dns_spoof

You will need to edit the filter file (etter.filter) to specify which domains you want to spoof.

ftpd_banner

This plugin replaces the FTP banner with a custom one. It is useful for social engineering purposes.

example:

ettercap -Tq -i eth0 // -P ftpd_banner

http_header

This plugin allows you to inject custom HTTP headers into HTTP connections. This can be used to redirect users to malicious websites or to perform other types of web-based attacks.

example:

ettercap -Tq -i eth0 // -P http_header

You will need to edit the filter file (etter.filter) to specify the headers you want to inject.

jail

This plugin attempts to jail FTP users into their home directories. It can be useful for restricting the access of FTP users.

example:

ettercap -Tq -i eth0 // -P jail

mms_spoof

This plugin spoofs MMS messages. It can be used to send malicious MMS messages to users, potentially leading to further attacks.

example:

ettercap -Tq -i eth0 // -P mms_spoof

mysql_fake_user

This plugin allows you to intercept and modify MySQL authentication attempts. It can be used to create fake user accounts or to steal existing credentials.

example:

ettercap -Tq -i eth0 // -P mysql_fake_user

nfs_user

This plugin deals with NFS user information. It can be used to spoof or manipulate NFS user lookups.

example:

ettercap -Tq -i eth0 // -P nfs_user

portredirect

This plugin redirects traffic from one port to another. It can be used to redirect traffic intended for a specific service to a different, potentially malicious, service running on your machine.

example:

ettercap -Tq -i eth0 // -P portredirect

You will need to edit the filter file (etter.filter) to specify the source and destination ports.

redir

This plugin is a generic packet redirection tool. It can be used to redirect packets to another host or port, which is useful for various man-in-the-middle attacks.

example:

ettercap -Tq -i eth0 // -P redir

smb_browse

This plugin intercepts and manipulates SMB browsing requests. It can be used to provide fake network shares or to redirect users to malicious SMB services.

example:

ettercap -Tq -i eth0 // -P smb_browse

This plugin hooks the smb dissector, so you have to keep it active. If you use it against a Windows client, it will probably result in a failure. Try it against a *nix smbclient :)

smb_down

It forces the client to not to use NTLM2 password exchange during smb authentication. This way, obtained hashes can be easily cracked by LC4. You have to be in the "middle" of the connection to successfully use it. It hooks the smb dissector, so you have to keep it active.

smurf_attack

The Smurf Attack is a DoS attack in which huge numbers of ICMP packets with the intended victim(s) IP(s) in target1 are sent to the hosts in target2. This causes all hosts on the target2 to reply to the ICMP request, causing significant traffic to the victim's computer(s).

example (192.168.0.5 is the victim):

ettercap -i eth1 -Tq /192.168.0.5/ // -P fraggle_attack

sslstrip

While performing the SSL mitm attack, ettercap substitutes the real ssl certificate with its own. The fake certificate is created on the fly and all the fields are filled according to the real cert presented by the server. Only the issuer is modified and signed with the private key contained in the 'etter.ssl.crt' file. If you want to use a different private key you have to regenerate this file. To regenerate the cert file use the following commands:

openssl genrsa -out etter.ssl.crt 1024
openssl req -new -key etter.ssl.crt -out tmp.csr
openssl x509 -req -days 1825 -in tmp.csr -signkey etter.ssl.crt -out tmp.new
cat tmp.new >> etter.ssl.crt
rm -f tmp.new tmp.csr

NOTE: SSL mitm is not available (for now) in bridged mode.

NOTE: You can use the --certificate/--private-key long options if you want to specify a different file rather than the etter.ssl.crt file.

stp_mangler

It sends spanning tree BPDUs pretending to be a switch with the highest priority. Once in the "root" of the spanning tree, ettercap can receive all the "unmanaged" network traffic.
It is useful only against a group of switches running STP.
If there is another switch with the highest priority, try to manually decrease your MAC address before running it.

example :

ettercap -TP stp_mangler
