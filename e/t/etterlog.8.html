etterlog - Analyseur de

journaux pour les fichie
rs de journal d'ettercap

SYNOPSI

S

etterlog [OPTIONS] FICHI

E
R

DESCRIPTIO

N

Etterlog est l'analyseur de journaux pour les fichiers de journal créés par ettercap. Il peut gérer les fichiers de journal compressés (créés avec -Lc) ou non compressés. Avec cet outil, vous pouvez manipuler les fichiers binaires comme vous le souhaitez et vous pouvez imprimer les données de différentes manières autant de fois que vous le voulez (contrairement à l'ancien système de journalisation qui était utilisé pour effectuer un vidage d'une seule manière statique).
Vous pourrez effectuer le vidage du trafic d'une seule connexion de votre choix, d' un seul ou de plusieurs hôtes, imprimer les données en hexadécimal, ASCII, binaire, etc..

.

ASTUCE : Tous les messages inutiles sont imprimés sur stderr, afin que vous puissiez enregistrer la sortie d'etterlog avec la commande suivante

:
etterlog [options] fichier_journal >
fichier_sortie

Ainsi, vous pouvez par exemple effectuer le vidage d'un fichier binaire à partir d'un

e connexion ftp si vous imprimez les données en mode binaire, sans en-têtes et
en sélectionnant uniquement le serveur ftp comme source de la communication.
OPTIONS
GÉNÉRALES
-a, --analy
ze
Analyse un fichier journal et affiche quelques statistiques
intéressantes.
-c, --connectio
ns
Analyse le fichier journal et imprime un tableau des connexions uniques (port vers port). Cette option ne peut être utilisée que sur les fichiers de journal LOG_PACKET. Sur les fichiers de journal LOG_INFO, elle est inutile.

ASTUCE : vous pouvez rechercher un hôte particulier en utilisant la commande

suivante :

etterlog -c fichier_journal.ecp | grep

10.0.
0.1
-f, --filter
<CIBLE>
Imprime uniquement les paquets provenant de la CIBLE ou destinés à la CIBLE. La spécification de la CIBLE est la même que dans ettercap.
La CIBLE est de la forme MAC/IPs/PORTs. Avec le support IPv6 activé, la CIBLE est de la forme MAC/IPs/IPv6/PORTs. L'omission d'une ou plusieurs de ses parties équivaut à les définir sur ANY. IPs et IPv6 seront traités comme une seule partie afin qu'ils ne soient définis sur ANY que si les deux, IPs et IPv6, sont omis. Cela aboutit à un résultat que la plupart des utilisateurs attendraient.

Si le type de journal est LOG_INFO, la cible est utilisée pour afficher les hôtes correspon

dant à la mac, à l'ip et ayant le(s) port(s) spécifié(s) ouvert(s). Par exemple, la cible //
80 n'affichera que les informations sur les hôtes avec un serveur web en cours d'exécution.
-r, --rever
se
Inverse la correspondance dans la sélection de la CIBLE. Cela signifie not(CIBLE). Tout sauf la CIBLE
sélectionnée.
-t, --proto
<PROTO>
Écoute uniquement les paquets PROTO (par défaut TCP + UDP). Cette option n'est utile qu'en mode « simple ». Si vous démarrez ettercap en mode interactif, à la fois TCP et UDP sont écoutés.
PROTO peut être "tcp", "udp" ou "all" pour les
deux.
-F, --filcon
<CONNEXION>
Imprime uniquement les paquets appartenant à cette CONNEXION.
La CONNEXION est de la forme PROTO:SOURCE:DEST. SOURCE et DEST sont de la forme IP:PORT.

exemple

:

etterlog -F TCP:10.0.0.23:3318:198.182.

196.56:
80

ce
Affiche uniquement les paquets envoyés par la source de la CONNEXION sélectionnée. Cette option n'a de sens qu'en conjonction avec l'option -F.

ASTUCE : si vous souhaitez enregistrer un fichier transféré dans une connexion HTTP ou FTP vous pouvez utiliser la commande

suivante :

etterlog -B -s -n -F TCP:10.0.0.1:20:10.0.0.2:35426 fichier_journal.ecp >

exemple.tar.

-n, --no-heade

N'imprime pas l'en-tête de chaque paquet. Cette option est utile si vous souhaitez enregistrer un fichier au format binaire (option -B). Sans les en-têtes, vous pouvez rediriger la sortie vers un fichier et vous obtiendrez le flux original.

-k, --col

S'il est utilisé en conjonction avec -F, il affiche la source et la destination de la connexion en utilisant différentes couleurs. S'il est utilisé avec un fichier LOG_INFO, il imprime les hôtes LAN en vert, les hôtes REMOTE en bleu et les GATEWAYS en

OPTIONS DE
RECHERCHE
-e, --regex
<REGEX>
Affiche uniquement les paquets correspondant à l'expression régulière <REGEX>.
Si cette option est utilisée sur un fichier de journal LOG_PACKET, l'expression régulière est exécutée sur la charge utile du paquet. Si le type est LOG_INFO, l'expression régulière est exécutée sur tous les champs du profil de l'hôte (OS, bannières, service et adaptateur ethernet).
REMARQUE : l'expression régulière est compilée avec le drapeau REG_ICASE (insensible à la casse)
.
-u, --user
<UTILISATEUR>
Affiche les informations sur cet utilisateur. La recherche est effectuée sur toutes les paires utilisateur/mot de passe collectées sur tous les
hôtes.
-p, --passwor
ds
Imprime uniquement les informations de compte collectées pour chaque hôte. Cela évite la sortie de profil énorme. Elle peut être utilisée en conjonction avec l'option -u pour filtrer les utilisateurs. Un astérisque '*' utilisé devant un compte représente une tentative de connexion
échouée.
-i, --show-clie
nt
Affiche l'adresse ip du client lors de l'affichage des utilisateurs et des mots de passe collectés. Cela peut être utile lorsque des ACL sont en
place.
-I, --client
<IP>
Affiche uniquement les mots de passe provenant d'une <IP> spécifique. Cela est utile pour voir tous les noms d'utilisateur et mots de passe d'un
client.
OPTIONS
D'ÉDITION
-C, --conc
at
Utilisez cette option pour concaténer deux (ou plus) fichiers en un seul fichier. C'est utile si vous avez collecté des fichiers de journal d'ettercap à partir de multiples sources et que vous souhaitez avoir un rapport unifié. Le fichier de sortie doit être spécifié avec l'option -o et les fichiers d'entrée sont listés en tant qu'arguments normaux.

exemple :
etterlog -C -o fic

hier_sortie entre
e1 entree2 entree3

<FICHIER>

concaténation.

Imprime uniquement les caractères « imprimables », les autres sont affichés comme des points

Convertir un texte EBCDIC en ASCII.
-H, --html
Supprimer toutes les balises HTML du texte. Une balise est toute chaîne entre '<' et '>'.

exemple:

-U, --utf8 <encodage>
Afficher les paquets au format UTF-8. Le paramètre <encodage> spécifie l'encodage à utiliser lors de la conversion. Utilisez la commande `iconv --list` pour obtenir une liste de tous les encodages pris en charge.
-Z, --zero
Afficher toujours la chaîne vide. C'est-à-dire, n'afficher que les informations d'en-tête et aucun contenu de paquet ne sera affiché.
-x, --xml
Afficher les informations sur l'hôte au format XML, de sorte que vous puissiez les analyser avec votre programme préféré.

Le DTD associé à la sortie XML se trouve dans share/etterlog.dtd

EXEMPLES

Voici quelques exemples d'utilisation d'etterlog.

etterlog -k -l dump.eci

Affiche des informations sur les hôtes locaux dans différentes couleurs.

etterlog -X dump.ecp

Affiche les paquets en mode HEX avec les en-têtes complets.

etterlog -c dump.ecp

Affiche la liste des connexions enregistrées dans le fichier.

etterlog -Akn -F TCP:10.0.0.1:13423:213.203.143.52:6666 dump.ecp

Affiche le trafic IRC effectué par 10.0.0.1 en mode ASCII, sans informations d'en-tête et en mode couleur.

etterlog -H -t tcp -f //80 dump.ecp

Enregistre tout le trafic HTTP et supprime les balises HTML.

etterlog -Z -r -f /10.0.0.2/22 dump.ecp

N'affiche que les en-têtes de toutes les connexions sauf SSH sur l'hôte 10.0.0.2

etterlog -A -e 'user' -f //110 dump.ecp

N'affiche que les paquets POP contenant le regexp 'user' (insensible à la casse).

etterlog -u root dump.eci

Affiche des informations sur tous les comptes de l'utilisateur 'root'.

etterlog -e Apache dump.eci

Affiche des informations sur tous les hôtes exécutant 'Apache'.

etterlog -e Linux dump.eci

Affiche des informations sur tous les hôtes avec le système d'exploitation 'Linux'.

etterlog -t tcp -f //110 dump.eci

Affiche des informations sur tous les hôtes ayant le port TCP 110 ouvert.

etterlog -t udp dump.eci

Affiche des informations sur tous les hôtes ayant au moins un port UDP ouvert.

etterlog -B -s -n -F TCP:10.0.0.1:20:10.0.0.2:35426 logfile.ecp > example.tar.gz

Enregistre sous forme binaire les données envoyées par 10.0.0.1 sur le port de données FTP. Comme les en-têtes sont omis, vous obtiendrez le fichier tel qu'il était.
