ETTERFILTER(8) Manuel de l'administrateur système ETTERFILTER(8)

NOM

etterfilter - Compilateur de filtres pour le moteur de filtrage de contenu d'ettercap

SYNTAXE

etterfilter [OPTIONS] FICHIER

DESCRIPTION

L'utilitaire etterfilter est utilisé pour compiler des fichiers sources de filtres en fichiers binaires de filtres qui peuvent être interprétés par l'interpréteur JIT du moteur de filtres ettercap. Vous devez compiler vos scripts de filtres afin de les utiliser dans ettercap. Toutes les erreurs de syntaxe/analyse seront vérifiées au moment de la compilation, vous aurez donc l'assurance de produire un filtre binaire correct pour ettercap.

OPTIONS GÉNÉRALES
-o, --output <FICHIER>
vous pouvez spécifier le fichier de sortie pour un fichier source de filtre. Par défaut, la sortie est filter.ef.
-t, --test <FICHIER>
vous pouvez analyser un fichier de filtre compilé avec cette option. etterfilter affichera sous forme lisible par l'homme toutes les instructions qu'il contient. C'est une sorte de "désassembleur" pour les fichiers de filtres binaires.
-d, --debug
affiche des messages de débogage pendant la compilation. Utilisez-le plus d'une fois pour augmenter le niveau de débogage ( etterfilter -ddd ... ).
-w, --suppress-warnings
Ne pas s'arrêter en cas d'avertissements. Avec cette option, le compilateur compilera le script même s'il contient des avertissements.
OPTIONS STANDARDES
-v, --version
Affiche la version et quitte.
-h, --help
affiche l'écran d'aide avec un bref résumé des options disponibles.
SYNTAXE DES SCRIPTS
Un script est un ensemble d'instructions. Il est exécuté séquentiellement et vous pouvez faire des branchements avec les instructions 'if'. Les instructions 'if' et 'if/else' sont les seules supportées. Aucune boucle n'est implémentée. La syntaxe est presque comme du code C, sauf que vous devez placer les blocs 'if' entre parenthèses graphiques '{' '}', même s'ils ne contiennent qu'une seule instruction.

NOTE : vous devez mettre un espace entre 'if' et '('. Vous ne devez pas mettre d'espace entre le nom de la fonction et le '('.

Exemple :
if (conditions) { }
func(args...);

Les conditions pour une instruction 'if' peuvent être soit des fonctions, soit des comparaisons. Deux conditions ou plus peuvent être liées ensemble avec des opérateurs logiques comme OU '||' et ET '&&'.

Exemple :
if (tcp.src == 21 && search(DATA.data, "ettercap")) {
}

Faites attention à la priorité des opérateurs. Vous ne pouvez pas utiliser de parenthèses pour grouper les conditions, alors soyez prudent quant à l'ordre. Un ET au début d'un bloc de conditions exclura tous les autres tests s'il est évalué comme faux. L'analyse se fait de gauche à droite, lorsqu'un opérateur est trouvé : s'il s'agit d'un ET et que la condition précédente est fausse, toute l'instruction est évaluée comme fausse ; s'il s'agit d'un OU, l'analyse continue même si la condition est fausse.

Exemple :
if (ip.proto == UDP || ip.proto == TCP && tcp.src == 80) {
}

if (ip.proto == TCP && tcp.src == 80 || ip.proto == UDP) {
}

La première condition correspondra à tout trafic UDP ou HTTP. La seconde est incorrecte, car si le paquet n'est pas TCP, tout le bloc de condition sera évalué comme faux. Si vous voulez créer des conditions complexes, le mieux est de les diviser en blocs 'if' imbriqués.

Étant donné qu'etterfilter prend en charge les deux familles d'adresses IP, vous devez faire attention si vous utilisez 'ip.proto' qui est spécifique à la famille d'adresses IPv4 ou à son équivalent IPv6 'ipv6.nh'. En particulier pour la correspondance de protocoles L4 en utilisant 'ip.proto' et/ou 'ipv6.nh', vous devez être prudent si vous agissez réellement sur le bon protocole. Ceci devrait être renforcé en utilisant l'identifiant de protocole L3 'eth.proto'.

Exemple :
if (eth.proto == IP && ip.proto == TCP && tcp.dst == 80 || tcp.src == 80) {
}

if (eth.proto == IP6 && ipv6.nh == TCP && tcp.dst == 80 || tcp.src == 80) {
}

if (tcp.dst == 80 || tcp.src == 80) {
}

Le premier exemple correspond correctement au trafic HTTP uniquement sur IPv4 tandis que le second correspondrait au trafic HTTP uniquement sur IPv6. Le troisième exemple correspond au trafic HTTP quelle que soit sa famille d'adresses IP.

Chaque instruction dans un bloc doit se terminer par un point-virgule ';'.

Les comparaisons sont implémentées avec l'opérateur '==' et peuvent être utilisées pour comparer des nombres, des chaînes de caractères ou des adresses IP. Une adresse IP DOIT être entourée de deux apostrophes (par exemple, '192.168.0.7' ou '2001:db8::2'). Vous pouvez également utiliser les opérateurs 'inférieur à' ('<'), 'supérieur à' ('>'), 'inférieur ou égal' ('<=') et 'supérieur ou égal' ('>=') . La partie gauche d'une comparaison doit être un décalage (voir plus loin)

Exemple :
if (DATA.data + 20 == "ettercap" && ip.ttl > 16) {
}

Les affectations sont implémentées avec l'opérateur '=' et la partie gauche peut être un décalage (voir plus loin). La partie droite peut être une chaîne de caractères, un entier ou une valeur hexadécimale.

Exemple :
ip.ttl = 0xff;
DATA.data + 7 = "ettercap NG";

Vous pouvez également utiliser les opérations 'inc' et 'dec' sur les champs du paquet. Les opérateurs utilisés sont '+=' et '-='. La partie droite peut être un entier ou une valeur hexadécimale.

Exemple :
ip.ttl += 5;

Plus d'exemples peuvent être trouvés dans le fichier etter.filter.examples.

DÉFINITION DU DÉCALAGE
Un décalage est identifié par un pointeur virtuel. En bref, un décalage est un pointeur vers le tampon du paquet. Le pointeur virtuel est un tuple <L, O, S>, où L est le niveau iso/osi, O est le décalage dans ce niveau et S est la taille du pointeur virtuel. Vous pouvez effectuer des opérations algébriques sur un pointeur virtuel et le résultat est toujours un décalage. Spécifier 'vp + n' résultera en un nouveau pointeur virtuel <L, O+n, S>. Et ceci est parfaitement légal, nous avons modifié le décalage interne de ce niveau.

Les pointeurs virtuels sont sous la forme 'nom.champ.sous_champ'. Par exemple, 'ip.ttl' est le pointeur virtuel pour le champ Time To Live dans l'en-tête IP d'un paquet. Il sera traduit par <L=3, O=9, S=1>. En effet, c'est le 9ème octet du niveau 3 et sa taille est de 1 octet. 'ip.ttl + 1' est identique à 'ip.proto' car le 10ème octet de l'en-tête IP est le protocole encapsulé dans le paquet IP. Notez que puisque etterfilter prend également en charge le traitement d'IPv6, ce qui précède ne s'applique qu'aux paquets IPv4, tandis que son homologue dans IPv6 serait 'ipv6.nh'.

La liste de tous les pointeurs virtuels supportés se trouve dans le fichier etterfilter.tbl. Vous pouvez ajouter vos propres pointeurs virtuels en ajoutant une nouvelle table ou en modifiant celles existantes. Référez-vous aux commentaires en début de fichier pour la syntaxe du fichier etterfilter.tbl.

FONCTIONS DES SCRIPTS
search(où, quoi)
cette fonction recherche la chaîne 'quoi' dans le tampon 'où'. Le tampon peut être DATA.data ou DECODED.data. Le premier est la charge utile au niveau DATA (au-dessus de TCP ou UDP) telle qu'elle est transmise sur le réseau, le second est la charge utile décodée/déchiffrée par les dissectors.
Ainsi, si vous voulez chercher dans une connexion SSH, il est préférable d'utiliser 'DECODED.data' car 'data' sera chiffré.
La chaîne 'quoi' peut être binaire. Vous devez l'échapper.

exemple :
search(DATA.data, "\x41\x42\x43")

regex(où, regex)
cette fonction retournera vrai si la 'regex' a correspondu au tampon 'où'. Les considérations concernant 'DECODED.data' et 'DATA.data' mentionnées pour la fonction 'search' sont les mêmes pour la fonction regex.

NOTE : regex ne peut être utilisé que contre un tampon de chaîne de caractères.

. )
cette fonction évaluera une expression régulière compatible perl. Vous pouvez faire correspondre à la fois DATA et DECODED, mais si votre expression modifie le buffer, il est logique de n'opérer que sur DATA. La fonction accepte 2 ou 3 paramètres selon l'opération que vous souhaitez effectuer. La forme à deux paramètres est utilisée uniquement pour faire correspondre un motif. La forme à trois paramètres signifie que vous voulez effectuer une substitution. Dans les deux cas, le deuxième paramètre est la chaîne de recherche.
Vous pouvez utiliser $n dans la chaîne de remplacement. Ces espaces réservés font référence aux groupes créés dans la chaîne de recherche. (par exemple, pcre_regex(DATA.data, "^var1=([:digit:]*)&var2=([:digit:]*)", "var1=$2&var2=$1") échangera la valeur de var1 et var2).
NOTE : le support de pcre est optionnel dans ettercap et ne sera activé que si vous avez libpcre installé. L' compilateur vous avertira si vous essayez de compiler un filtre qui contient des expressions pcre mais que vous n'avez pas libpcre. Utilisez l'option -w pour supprimer l'avertissement.

exemple :

$2")
