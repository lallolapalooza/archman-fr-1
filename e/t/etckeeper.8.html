NOM

etckeeper - stocker /etc dans un dépôt git, mercurial, bazaar ou darcs

SYNTAXE

etckeeper commande [-d répertoire]

DESCRIPTION

etckeeper gère le répertoire /etc en le stockant dans un dépôt git, mercurial, bazaar ou darcs. Par défaut, chaque commande opère sur /etc, mais un répertoire différent peut être spécifié pour opérer sur un clone du dépôt /etc situé ailleurs.

COMMANDES

init
Initialise et configure un dépôt git, mercurial, bazaar ou darcs (selon le paramètre VCS dans /etc/etckeeper/etckeeper.conf). Généralement, cela est exécuté dans /etc une seule fois au démarrage de l'utilisation d'etckeeper sur une machine. Peut également être utilisé pour initialiser un clone du dépôt /etc situé ailleurs.
commit [message]
Valide tous les changements dans /etc dans le dépôt. Un message de validation peut être spécifié. Vous pouvez également utiliser le VCS sous-jacent pour valider manuellement. (Notez qu'etckeeper commit remarquera si un utilisateur a utilisé sudo ou su pour devenir root, et enregistrera le nom d'utilisateur d'origine dans la validation.)
pre-commit
Est appelé comme un hook pre-commit. Il stocke les métadonnées et effectue des contrôles de cohérence.
pre-install
Est appelé par le hook DPkg::Pre-Install-Pkgs d'apt, ou par des hooks équivalents d'autres gestionnaires de paquets. Il permet de valider les changements non validés avant que les paquets ne soient installés, mis à niveau, etc.
post-install
Est appelé par le hook DPkg::Post-Invoke d'apt, ou par des hooks équivalents d'autres gestionnaires de paquets. Il valide les changements apportés par les paquets dans le dépôt. (Vous pouvez également appeler cela manuellement après avoir exécuté dpkg manuellement.)
unclean
Retourne vrai si le répertoire contient des changements non validés.
update-ignore [-a]
Met à jour le fichier d'ignorance du VCS. Le contenu extérieur à un bloc "géré par etckeeper" n'est pas modifié. Ceci est généralement exécuté lors de la mise à niveau vers une nouvelle version d'etckeeper. (Le commutateur -a ajoutera un bloc "géré par etckeeper" s'il n'est pas présent.)
vcs sous-commande [options ...]
Vous pouvez utiliser ceci pour exécuter toute sous-commande du VCS que etckeeper est configuré pour exécuter. Elle sera exécutée dans /etc. Par exemple, "etckeeper vcs diff" exécutera "git diff", etc.
uninit [-f]
Cette commande DETRUIT DES DONNÉES ! C'est l'inverse de la commande init, supprimant les informations du VCS et les informations de comptabilité propres à etckeeper du répertoire. À utiliser avec prudence. Un cas d'usage typique serait d'exécuter etckeeper uninit, puis de modifier etckeeper.conf pour utiliser un VCS différent, et ensuite d'exécuter etckeeper init. (Le commutateur -f peut être utilisé pour forcer la désinitialisation sans demander.)

FICHIERS

Le fichier de configuration est /etc/etckeeper/etckeeper.conf.

Le répertoire /etc/etckeeper contient également des répertoires contenant les programmes qui sont exécutés pour chacune des commandes ci-dessus.

VARIABLES D'ENVIRONNEMENT

ETCKEEPER_CONF_DIR chemin vers le répertoire de configuration au lieu du défaut /etc/etckeeper.
