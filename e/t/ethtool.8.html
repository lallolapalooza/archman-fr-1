DESCRIPTION

ethtool est utilisé pour interroger et contrôler les paramètres matériels et du pilote des périphériques réseau, en particulier pour les périphériques Ethernet filaires.

devname est le nom du périphérique réseau sur lequel ethtool doit opérer.

OPTIONS

ethtool avec un seul argument spécifiant le nom du périphérique affiche les paramètres actuels du périphérique spécifié.

-h --help
Affiche un bref message d'aide.
--version
Affiche le numéro de version d'ethtool.
--debug N
Active les messages de débogage. L'argument est interprété comme un masque :
0x01 Informations sur le parseur
0x02 Résumé des messages netlink
0x04 Vidage hexadécimal des messages netlink envoyés
0x08 Vidage hexadécimal des messages netlink reçus
0x10 Structure des messages netlink
--disable-netlink
N'utilise pas netlink et utilise l'interface ioctl si possible.
--json
Affiche les résultats au format JavaScript Object Notation (JSON). Seul un sous-ensemble d'options prend en charge cela. Celles qui ne le font pas continueront d'afficher du texte brut en présence de cette option.
-I --include-statistics
Inclut les statistiques liées à la commande dans la sortie. Cette option permet d'afficher les statistiques pertinentes du périphérique pour les commandes de récupération sélectionnées.
--phy N
Cible un PHY dans l'interface. L'indice du PHY peut être récupéré avec --show-phys. L'indice de PHY 0 cible le périphérique PHY directement attaché à la MAC Ethernet, le cas échéant. Les commandes suivantes peuvent accepter un indice de PHY :
--cable-test
--cable-test-tdr
--get-plca-cfg
--set-plca-cfg
--get-plca-status
--show-pse
--set-pse
-a --show-pause
Interroge le périphérique Ethernet spécifié pour obtenir des informations sur les paramètres de pause.
--src aggregate|emac|pmac
Si la couche MAC Merge est prise en charge, demande une source particulière de statistiques de périphérique (eMAC ou pMAC, ou leur agrégat). Valide uniquement si ethtool a été appelé avec l'argument -I --include-statistics.
-A --pause
Modifie les paramètres de pause du périphérique Ethernet spécifié.
autoneg on|off
Spécifie si la négociation automatique de pause doit être activée.
rx on|off
Spécifie si la pause RX doit être activée.
tx on|off
Spécifie si la pause TX doit être activée.
-c --show-coalesce
Interroge le périphérique réseau spécifié pour obtenir des informations sur la coalescence.
-C --coalesce
Modifie les paramètres de coalescence du périphérique réseau spécifié.
-g --show-ring
Interroge le périphérique réseau spécifié pour obtenir des informations sur les paramètres des anneaux rx/tx.
-G --set-ring
Modifie les paramètres des anneaux rx/tx du périphérique réseau spécifié.
rx N
Modifie le nombre d'entrées d'anneau pour l'anneau Rx.
rx-mini N
Modifie le nombre d'entrées d'anneau pour l'anneau Rx Mini.
rx-jumbo N
Modifie le nombre d'entrées d'anneau pour l'anneau Rx Jumbo.
tx N
Modifie le nombre d'entrées d'anneau pour l'anneau Tx.
rx-buf-len N
Modifie la taille d'un tampon dans l'anneau Rx.
tcp-data-split auto|on|off
Spécifie l'état de la division des données TCP.
hds-thresh N
Spécifie la valeur de seuil de la division des données TCP.
cqe-size N
Modifie la taille de l'événement de file d'attente de complétion.
tx-push on|off
Spécifie si la poussée TX doit être activée.
rx-push on|off
Spécifie si la poussée RX doit être activée.
tx-push-buf-len N
Spécifie le nombre maximum d'octets d'un paquet transmis qu'un pilote peut pousser directement vers le périphérique sous-jacent.
-i --driver
Interroge le périphérique réseau spécifié pour obtenir des informations sur le pilote associé.
-d --register-dump
Récupère et affiche un vidage des registres pour le périphérique réseau spécifié. Le format des registres est connu et décodé pour certains périphériques, d'autres sont affichés en hexadécimal. Lorsque raw est activé, ethtool déverse les données brutes des registres sur stdout. Si file est spécifié, il utilise le contenu du vidage précédent des registres bruts, plutôt que de lire à partir du périphérique.
-e --eeprom-dump
Récupère et affiche un vidage EEPROM pour le périphérique réseau spécifié. Lorsque raw est activé, il déverse les données brutes EEPROM sur stdout. Les paramètres length et offset permettent de vider certaines portions de l'EEPROM. Par défaut, l'ensemble de l'EEPROM est vidé.
raw on|off
offset N
length N
-E --change-eeprom
Si une valeur est spécifiée, modifie un octet EEPROM pour le périphérique réseau spécifié. offset et value spécifient quel octet et sa nouvelle valeur. Si value n'est pas spécifiée, stdin est lu et écrit dans l'EE
EEPROM
La longueur et les paramètres de décalage permettent d'écrire sur certaines parties de l'EEPROM. En raison de la nature persistante de l'écriture sur l'EEPROM, une clé magique spécifique à l'appareil doit être spécifiée pour éviter l'écriture accidentelle sur l'EEPROM.
-k --show-features --show-offload
Interroge le périphérique réseau spécifié pour connaître l'état de la mise hors charge des protocoles et d'autres fonctionnalités.
-K --features --offload
Modifie les paramètres de mise hors charge et d'autres fonctionnalités du périphérique réseau spécifié. Les noms de fonctionnalités suivants sont intégrés et d'autres peuvent être définis par le noyau.
rx on|off
Spécifie si la somme de contrôle RX doit être activée.
tx on|off
Spécifie si la somme de contrôle TX doit être activée.
sg on|off
Spécifie si le scatter-gather doit être activé.
tso on|off
Spécifie si la mise hors charge de la segmentation TCP doit être activée.
ufo on|off
Spécifie si la mise hors charge du fractionnement UDP doit être activée.
gso on|off
Spécifie si la mise hors charge de segmentation générique doit être activée.
gro on|off
Spécifie si la mise hors charge de réception générique doit être activée.
lro on|off
Spécifie si la mise hors charge de réception volumineuse doit être activée.
rxvlan on|off
Spécifie si l'accélération VLAN RX doit être activée.
txvlan on|off
Spécifie si l'accélération VLAN TX doit être activée.
ntuple on|off
Spécifie si les filtres et actions ntuple Rx doivent être activés.
rxhash on|off
Spécifie si la mise hors charge du hachage de réception doit être activée.
-p --identify
Déclenche une action spécifique à l'adaptateur destinée à permettre à un opérateur d'identifier facilement l'adaptateur visuellement. Généralement, cela implique le clignotement d'une ou plusieurs LED sur le port réseau spécifique.
[ N]
Durée d'exécution de phys-id, en secondes.
-P --show-permaddr
Interroge le périphérique réseau spécifié pour son adresse matérielle permanente.
-r --negotiate
Redémarre la négociation automatique sur le périphérique Ethernet spécifié, si la négociation automatique est activée.
-S --statistics
Interroge le périphérique réseau spécifié pour des statistiques standard (IEEE, IETF, etc.) ou spécifiques au NIC et au pilote. Les statistiques spécifiques au NIC et au pilote sont demandées lorsqu'aucun groupe de statistiques n'est spécifié.

Les statistiques spécifiques au NIC et au pilote, ainsi que les statistiques standard, sont indépendantes ; les périphériques peuvent implémenter l'une, les deux ou aucune. Il y a peu de points communs entre la dénomination des statistiques spécifiques au NIC et au pilote selon les fournisseurs.

--all-groups
--groups [eth-phy] [eth-mac] [eth-ctrl] [rmon]
Demande des groupes de statistiques standard du périphérique.
--src aggregate|emac|pmac
Si la couche de fusion MAC est prise en charge, demande une source particulière de statistiques du périphérique (eMAC ou pMAC, ou leur agrégat).
--phy-statistics
Interroge le périphérique réseau spécifié pour des statistiques spécifiques au PHY.
-t --test
Exécute l'autotest de l'adaptateur sur le périphérique réseau spécifié. Les modes de test possibles sont :
offline
Effectue l'ensemble complet des tests, pouvant interrompre le fonctionnement normal pendant les tests.
online
Effectue un ensemble limité de tests, sans interrompre le fonctionnement normal.
external_lb
Effectue l'ensemble complet des tests, comme pour offline, et en outre un test de boucle externe.
-s --change
Permet de modifier tout ou partie des paramètres du périphérique réseau spécifié. Toutes les options suivantes ne s'appliquent que si -s a été spécifié.
speed N
Définit la vitesse en Mb/s. ethtool avec uniquement le nom du périphérique comme argument vous montrera les vitesses prises en charge par le périphérique.
lanes N
Définit le nombre de voies.
duplex half|full
Définit le mode duplex partiel ou complet.
port tp|aui|bnc|mii
Sélectionne le port du périphérique.
master-slave preferred-master|preferred-slave|forced-master|forced-slave
Configure le rôle MAÎTRE/ESCLAVE du PHY. Lorsque le PHY est configuré comme MAÎTRE, la fonction PMA Transmit doit sourcer TX_TCLK à partir d'une source d'horloge locale. Lorsqu'il est configuré comme ESCLAVE, la fonction PMA Transmit doit sourcer TX_TCLK à partir de l'horloge récupérée du flux de données fourni par le MAÎTRE. Tous les périphériques ne prennent pas en charge cette option.
preferred-master Préférer le rôle MAÎTRE lors de la négociation automatique.
preferred-slave Préférer le rôle ESCLAVE lors de la négociation automatique.
forced-master Forcer le PHY en mode MAÎTRE. Peut être utilisé sans négociation automatique.
forced-slave Forcer le PHY en mode ESCLAVE. Peut être utilisé sans négociation automatique.
mdix auto|on|off
Sélectionne le mode MDI-X pour le port. Peut être utilisé pour remplacer la fonction de détection automatique de la plupart des adaptateurs. Un argument auto signifie détection automatique du statut MDI, on force le mode MDI-X (croisé), tandis que off signifie mode MDI (droit). Le pilote doit garantir que cette commande prend effet immédiatement, et si nécessaire, peut réinitialiser la liaison pour que le changement prenne effet.
autoneg on|off
Spécifie si la négociation automatique doit être activée. La négociation automatique est activée par défaut, mais certains périphériques réseau peuvent avoir des problèmes avec, vous pouvez donc la désactiver si nécessaire.

Effectue un test de câble et rapporte les données brutes du réflectomètre dans le domaine temporel (Time Domain Reflectometer). Une impulsion est envoyée le long d'une paire de câble et l'amplitude de la réflexion, pour une distance donnée, est rapportée. Une coupure dans le câble renvoie une grande réflexion. Un dommage mineur au câble renvoie une petite réflexion. Si le câble est en court-circuit, l'amplitude de la réflexion peut être négative. les distances à la granularité effectivement implémentée. C'est souvent 0,8 mètre. Les résultats doivent inclure la première et la dernière distance réelles arrondies ainsi que la taille du pas.

node-cnt N
Le paramètre node-cnt N (0 <= N <= 255) définit le nombre total de nœuds participants à PLCA. Ce paramètre doit être identique sur tous les nœuds du même segment. La valeur de ce paramètre est utilisée pour calculer le temps de battement de détection de porteur (PCS) pour le nœud actuel. Ce temps de battement PCS est calculé comme suit : PCS_BEAT = (32 + N) BT. La valeur par défaut est 2, ce qui correspond à un temps de battement PCS de 34 BT. Ce paramètre est uniquement pris en compte sur le nœud coordinateur (nod-id = 0). La définition de ce paramètre sur un nœud suiveur n'a aucun effet. Le paramètre node-cnt correspond à la clause 30.16.1.1.3 (aPLCANodeCount) de la norme IEEE 802.3cg-2019.
to-tmr N
Le paramètre du timer TO (Transmit Opportunity) définit la valeur du timer d'opportunité de transmission en temps de bits, et doit être réglé de manière identique sur tous les nœuds partageant le même média pour que PLCA fonctionne. La valeur par défaut de 32 est suffisante pour couvrir une liaison d'environ 50 mètres. Ce paramètre correspond à la clause 30.16.1.1.5 (aPLCATransmitOpportunityTimer) de la norme IEEE 802.3cg-2019.
burst-cnt N
Le paramètre burst-cnt [0 .. 255] indique le nombre supplémentaire de paquets que le nœud est autorisé à envoyer pendant une seule opportunité de transmission. Par défaut, cet attribut est de 0, ce qui signifie que le nœud peut envoyer un seul tram par TO. Lorsqu'il est supérieur à 0, le RS PLCA conserve le TO après toute transmission, attendant que le MAC envoie une nouvelle trame pendant jusqu'à burst-tmr BT. Cela ne peut se produire qu'un certain nombre de fois par cycle PLCA, jusqu'à la valeur de ce paramètre. Ensuite, le burst est terminé et le comptage normal des TO reprend. Ce paramètre correspond à la clause 30.16.1.1.6 (aPLCAMaxBurstCount) de la norme IEEE 802.3cg-2019.
burst-tmr N
Le paramètre burst-tmr [0 .. 255] définit combien de temps de bits le RS PLCA attend que le MAC initie une nouvelle transmission lorsque burst-cnt est supérieur à 0. Si le MAC ne parvient pas à envoyer une nouvelle trame dans ce délai, le burst se termine et le comptage des TO reprend. Sinon, la nouvelle trame est envoyée dans le cadre du burst actuel. Ce paramètre correspond à la clause 30.16.1.1.7 (aPLCABurstTimer) de la norme IEEE 802.3cg-2019. La valeur de burst-tmr doit être supérieure au temps d'écart inter-trames (IFG) du MAC (plus une marge) pour que le mode burst PLCA fonctionne comme prévu.
