NAME

etags

create tags file for Emacs

SYNOPSIS

etags [-a|--append] [-c|--cpp] [-e|--emacs] [-e|--emacs=emacs] [-f|--output=tagsfile] [-h|--help] [-l|--language=language] [-o|--old-filenames] [-R|--no-regex] [-r|--regex=regex] [-u|--update] [-v|--vgrind] [-x|--cxref] [-V|--version] [file ...]

DESCRIPTION

etags

génère un fichier de tags pour Emacs à partir des fichiers sources spécifiés.

Le fichier de tags résultant, par défaut nommé tags, contient une liste de mots et leurs emplacements dans les fichiers sources. Ceci permet à Emacs de sauter rapidement vers un symbole donné.

Par défaut, etags cherche à reconnaître le langage de chaque fichier source et à utiliser les règles appropriées pour extraire les tags. Il peut généralement reconnaître les langages à partir de leurs extensions de fichier (par exemple, C, C++, Java, Pascal, Scheme, etc.).

Plusieurs options permettent de modifier le comportement de etags, notamment la manière dont les tags sont reconnus et les langages pris en charge.

OPTIONS

-a, --append
Ajoute les tags aux fichiers spécifiés à la fin du fichier de tags existant, au lieu de le remplacer. Ne fonctionne qu'avec ctags et ne peut être utilisé qu'une seule fois.
-c, --cpp
Utilise des règles de reconnaissance des tags spécifiques au C++. Notamment, il reconnaît les classes, les structures, les unions, les énumérations, les définitions de membres et les macros prédéfinies (#define). Les fichiers C++ sont généralement reconnus sans cette option.
-e, --emacs
Génère un fichier de tags pour Emacs. C'est le comportement par défaut.
-e, --emacs=emacs
Utilise emacs comme programme pour générer le fichier de tags. Par défaut, il est supposé que le programme s'appelle etags.
-f FILE, --output=FILE
Utilise FILE comme nom pour le fichier de tags. Le nom par défaut est tags.
-l LANG, --language=LANG
Définit le langage des fichiers sources suivants à LANG. Les langages connus sont ceux répertoriés par etags --help. L'option --language=none désactive la reconnaissance automatique des langages.
-o, --old-filenames
Utilise les noms de fichiers tels qu'ils étaient avant la version 5.5 de GNU Emacs. Ceci est obsolète.
-r REGEX, --regex=REGEX
Ajoute une expression régulière pour l'extraction des tags. L'expression régulière REGEX est composée d'une expression régulière de balisage et, optionnellement, d'une expression régulière de capture, séparées par un caractère délimiteur. Le format général est /tagregexp/capture-group/modifiers.
L'expression régulière de balisage (tagregexp) est une expression régulière qui correspond à la ligne contenant le tag. Elle doit contenir une ou plusieurs expressions de capture pour identifier les parties du tag qui vous intéressent. Le premier groupe de capture identifie le nom du tag. Les groupes de capture suivants sont utilisés comme des informations supplémentaires pour le tag (par exemple, des paramètres de fonction).
L'expression régulière de capture (capture-group) est optionnelle. Si elle est fournie, elle est utilisée pour extraire une partie spécifique du tag identifié par le premier groupe de capture. Si elle n'est pas fournie, le groupe de capture entier est utilisé.
Les modifiers sont une séquence optionnelle de caractères parmi i, m, s.
Les expressions régulières sont ignorées si elles ne contiennent pas de nameregexp. La syntaxe des expressions régulières est la même que celle d'Emacs, à l'exception près que les échappements par antislash sont identiques à ceux de GNU grep (ce qui signifie, par exemple, que les groupes discrets ne sont pas pris en charge), et que [:ascii:], [:multibyte:], [:nonascii:], [:word:] et [:unibyte:] ne sont pas pris en charge. Les séquences d'échappement de caractères suivantes sont prises en charge : \a, \b, \d, \e, \f, \n, \r, \t, \v, qui représentent respectivement les caractères ASCII BEL, BS, DEL, ESC, FF, NL, CR, TAB, VT.
Les modifiers sont une séquence de 0 ou plusieurs caractères parmi i, qui signifie ignorer la casse lors de la correspondance ; m, qui signifie que le tagregexp sera mis en correspondance avec le contenu entier du fichier à la fois, plutôt que ligne par ligne, et que la séquence de correspondance peut correspondre à plusieurs lignes ; et s, qui implique m et signifie que le caractère point dans tagregexp correspond également au caractère de saut de ligne.
Le délimiteur, qui est / dans les exemples, peut être n'importe quel caractère différent de l'espace, de la tabulation, des accolades et de @. Si le caractère délimiteur est nécessaire à l'intérieur de l'expression régulière, il doit être échappé en le précédant de \.
Le préfixe optionnel {langage} signifie que le tag ne doit être créé que pour les fichiers du langage langage, et ignoré sinon. Ceci est particulièrement utile lors du stockage de nombreux expressions régulières prédéfinies dans un fichier.
Dans sa seconde forme, regexfile est le nom d'un fichier contenant un nombre d'arguments pour l'option --regex=, un par ligne. Les lignes commençant par un espace ou une tabulation sont considérées comme des commentaires, et sont ignorées.

Voici quelques exemples. Toutes les expressions régulières sont protégées pour éviter leur interprétation par le shell.

Baliser les macros DEFVAR dans les fichiers sources d'emacs :
--regex='/[ \t]*DEFVAR_[A-Z_ \t(]+"\([^"]+\)"/'

Baliser les fichiers VHDL (cet exemple est une seule longue ligne, coupée ici pour des raisons de mise en forme) :
--language=none --regex='/[ \t]*\(ARCHITECTURE\|\ CONFIGURATION\) +[^ ]* +OF/' --regex='/[ \t]*\ \(ATTRIBUTE\|ENTITY\|FUNCTION\|PACKAGE\( BODY\)?\ \|PROCEDURE\|PROCESS\|TYPE\)[ \t]+\([^ \t(]+\)/\3/'

Baliser les fichiers Tcl (ce dernier exemple montre l'utilisation d'un tagregexp) :
--lang=none --regex='/proc[ \t]+\([^ \t]+\)/\1/'

Une expression régulière peut être précédée de {lang}, la restreignant ainsi à la mise en correspondance des lignes des fichiers du langage spécifié. Utilisez etags --help pour obtenir la liste des langages reconnus. Cette fonctionnalité est particulièrement utile dans les fichiers d'expressions régulières. Un fichier d'expressions régulières contient une expression régulière par ligne. Les lignes vides, et celles commençant par un espace ou une tabulation sont ignorées. Les lignes commençant par @ font référence à des fichiers d'expressions régulières dont le nom suit le signe @. Les autres lignes sont considérées comme des expressions régulières similaires à celles qui suivent --regex.
Par exemple, la commande
etags --regex=@regex.file *.c
lit les expressions régulières contenues dans le fichier regex.file.

-R, --no-regex
Ne plus effectuer de correspondance d'expressions régulières sur les fichiers suivants. Peut être librement mélangé avec les noms de fichiers et l'option --regex.
-u, --update
Met à jour les entrées de tags pour les fichiers spécifiés en ligne de commande, laissant les entrées de tags pour les autres fichiers en place. Actuellement, ceci est implémenté en supprimant les entrées existantes pour les fichiers donnés, puis en réécrivant les nouvelles entrées à la fin du fichier de tags. Il est souvent plus rapide de reconstruire simplement l'intégralité du fichier de tags que d'utiliser cette option. Seul ctags accepte cette option.
-v, --vgrind
Au lieu de générer un fichier de tags, écrit un index (au format vgrind) sur la sortie standard. Seul ctags accepte cette option.
-x, --cxref
Au lieu de générer un fichier de tags, écrit une référence croisée (au format cxref) sur la sortie standard. Seul ctags accepte cette option.
-h, -H, --help
Affiche les informations d'utilisation. Suivi d'une ou plusieurs options --language=LANG affiche des informations détaillées sur la manière dont les tags sont créés pour LANG.
-V, --version
Affiche la version actuelle du programme (identique à la version d'Emacs avec laquelle etags est distribué).
