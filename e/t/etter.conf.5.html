ETTER.CONF(5) Manuel des formats de fichiers ETTER.CONF(5)

NOM

etter.conf - Fichier de configuration Ettercap

DESCRIPTION

etter.conf est le fichier de configuration qui détermine le comportement d'ettercap. Il est toujours chargé au démarrage et configure certains attributs utilisés à l'exécution.

Le fichier contient des entrées de la forme :

[section]
entrée = valeur
...

Chaque entrée définit une variable qui peut être personnalisée. Chaque valeur DOIT être un entier. Les sections sont utilisées uniquement pour regrouper certaines variables.

NOTE : Si vous omettez une variable dans le fichier de configuration, elle sera initialisée avec la valeur 0. Il est fortement déconseillé de ne pas initialiser des variables critiques telles que "arp_poison_delay" ou "connection_timeout".

Voici une liste des variables disponibles :

[privs]
ec_uid
Cette variable spécifie l'UID auquel les privilèges sont abaissés au démarrage. Une fois le socket au niveau de la liaison ouvert, les privilèges sont abaissés à un UID spécifique différent de root pour des raisons de sécurité. etter.conf est le seul fichier lu avec les privilèges root. Assurez-vous que l'UID spécifié a suffisamment de privilèges pour lire les autres fichiers (etter.*). Vous pouvez contourner cette variable en définissant la variable d'environnement EC_UID.
[mitm]
arp_storm_delay
La valeur représente les millisecondes à attendre entre deux paquets consécutifs lors du scan ARP initial. Vous pouvez incrémenter cette valeur pour être moins agressif au démarrage. Le scan aléatoire plus un délai élevé peuvent tromper certains types de détecteurs de scan ARP.
arp_poison_smart
Avec cette variable définie, seuls 3 messages ARP empoisonnés initiaux sont envoyés aux victimes. Ce statut empoisonné est maintenu par ettercap en répondant aux requêtes ARP des victimes qui souhaitent rafraîchir leur cache ARP. Cela rend l'empoisonnement ARP très discret, mais peut être peu fiable sur des médias partagés comme le WiFi.
arp_poison_warm_up
Lorsque le processus d'empoisonnement commence, le délai inter-paquets est faible pour les 5 premiers empoisonnements (pour être sûr que le processus d'empoisonnement a réussi). Après les 5 premiers empoisonnements, le délai est incrémenté (pour maintenir l'empoisonnement). Cette variable contrôle le délai pour les 5 premiers empoisonnements. La valeur est en secondes.
Le même délai est utilisé lorsque les victimes sont restaurées aux associations originales (RE-ARPing) lorsque ettercap est fermé.
arp_poison_delay
Cette variable contrôle le délai d'empoisonnement après les 5 premiers empoisonnements. La valeur est exprimée en secondes. Vous pouvez augmenter cette valeur (pour essayer de tromper l'IDS) jusqu'au timeout du cache ARP (qui dépend du système d'exploitation empoisonné).
arp_poison_icmp
Active l'envoi d'un message ICMP falsifié pour forcer les cibles à effectuer une requête arp. Cela créera une entrée dans le cache ARP, donc ettercap sera capable de gagner la condition de concurrence et d'empoisonner la cible. Utile contre les cibles qui n'acceptent pas les arp gratruits si l'entrée n'est pas dans le cache.
arp_poison_reply
Utilise les réponses ARP pour empoisonner les cibles. C'est l'attaque classique.
arp_poison_request
Utilise les requêtes ARP pour empoisonner les cibles. Utile contre les cibles qui mettent en cache même les valeurs de requêtes arp.
arp_poison_equal_mac
Définissez cette option à 0 si vous souhaitez ignorer l'empoisonnement de deux hôtes avec la même adresse mac. Cela peut se produire si une carte réseau a un ou plusieurs alias sur le même réseau.
dhcp_lease_time
C'est le temps de bail (en secondes) pour une assignation dhcp. Vous pouvez abaisser cette valeur pour permettre aux victimes de recevoir une réponse dhcp correcte après l'arrêt de votre attaque. L'utilisation de timeouts plus élevés peut sérieusement perturber votre réseau après la fin de l'attaque. D'un autre côté, certains clients préféreront un temps de bail plus élevé, vous devrez donc l'augmenter pour gagner la condition de concurrence contre le serveur réel.
port_steal_delay
C'est le temps de délai (en millisecondes) entre les paquets de vol pour la méthode mitm "port". Avec des délais faibles, vous pourrez intercepter plus de paquets, mais vous générerez plus de trafic. Vous devrez ajuster cette valeur pour trouver un bon équilibre entre le nombre de paquets interceptés, les paquets retransmis et les paquets perdus. Cette valeur dépend des canaux full/half duplex, des pilotes et adaptateurs réseau, de la configuration générale du réseau et du matériel.
port_steal_send_delay
C'est le temps de délai (en microsecondes) entre les paquets lorsque la méthode mitm "port" doit renvoyer les files de paquets. Comme mentionné pour port_steal_delay, vous devrez ajuster cette option à la valeur la plus basse acceptable.
ndp_poison_warm_up
Cette option fonctionne de manière similaire à l'option arp_poison_warm_up. Lorsque le processus d'empoisonnement commence, cette option contrôle le délai d'empoisonnement NDP pour les 5 premiers empoisonnements (pour être sûr que le processus d'empoisonnement a réussi). Après les 5 premiers empoisonnements, le délai est incrémenté (pour maintenir l'empoisonnement). Cette variable contrôle le délai pour les 5 premiers empoisonnements. La valeur doit être inférieure à ndp_poison_delay. La valeur est en secondes.
Le même délai est utilisé lorsque les victimes sont restaurées aux associations originales
lorsque ettercap est fermé.
ndp_poison_delay
Cette option est similaire à l'option arp_poison_delay. Elle contrôle le délai en secondes pour l'envoi des paquets NDP empoisonnés afin d'empoisonner le cache du voisin de la victime. Cette valeur peut être augmentée pour se cacher des IDS. Mais augmenter la valeur augmente également la probabilité d'échec des conditions de concurrence lors de la découverte du voisin et de manquer certains paquets.
ndp_poison_send_delay
Cette option contrôle le délai en microsecondes entre l'envoi des paquets NDP empoisonnés. Cette valeur peut être augmentée pour se cacher des IDS. Mais augmenter la valeur augmente également la probabilité d'échec des conditions de concurrence lors de la découverte du voisin et de manquer certains paquets.
ndp_poison_icmp
Active l'envoi d'un message ICMPv6 falsifié pour inciter les cibles à effectuer la découverte de voisins. Cela créera une entrée dans le cache des voisins de l'hôte, donc ettercap sera capable de gagner la condition de concurrence et d'empoisonner la cible. Utile contre les cibles qui n'acceptent pas les annonces de voisins si l'entrée n'est pas dans le cache.
ndp_poison_equal_mac
Définissez cette option à 0 si vous souhaitez ignorer l'empoisonnement NDP de deux hôtes avec la même adresse mac. Cela peut se produire si une carte réseau a un ou plusieurs alias sur le même réseau.
icmp6_probe_delay
Cette option définit le temps en secondes pendant lequel ettercap attend que les nœuds IPv6 actifs répondent aux sondes ICMP. Diminuer cette valeur pourrait entraîner la perte des réponses des nœuds IPv6 actifs, donc les manquer dans la liste des hôtes. Augmenter la valeur n'a généralement pas d'impact ; normalement, les nœuds peuvent gérer de répondre pendant le délai par défaut.

NOTE : Les options ndp et icmp6 ne sont disponibles que si ettercap a été compilé avec le support IPv6.

[connections]
connection_timeout
Chaque fois qu'une nouvelle connexion est découverte, ettercap alloue les structures nécessaires. Après un délai personnalisable, vous pouvez libérer ces structures pour maintenir une faible utilisation de la mémoire. Cette variable représente ce délai. La valeur est exprimée en secondes. Ce délai est également appliqué à la session
système de suivi (la machine à états du protocole pour les dissecteurs).
connection_i
dle
Le nombre de secondes à attendre avant qu'une connexion soit marquée comme
INACTIVE.
connection_buf
fer
Cette variable contrôle la taille du tampon lié à chaque connexion. Chaque paquet capturé est ajouté au tampon et lorsque le tampon est plein, les paquets les plus anciens sont supprimés pour faire de la place aux plus récents. Ce tampon est utile pour voir les données qui sont passées sur le câble avant que vous ne sélectionniez et consultiez une connexion spécifique. Plus cette valeur est élevée, plus la mémoire occupée par ettercap est importante. De plus, le tampon est dynamique, donc si vous définissez un tampon de 100 000 octets, il n'est pas alloué en une seule fois lors du premier paquet d'une connexion, mais il est rempli au fur et à mesure que les paquets
arrivent.
connect_time
out
Le délai d'attente en secondes lors de l'utilisation de l'appel système connect(). Augmentez-le si vous obtenez une erreur "Connection timeout". Cette option n'a rien à voir avec les connexions interceptées par ettercap. Il s'agit d'un délai d'attente pour les connexions établies par ettercap vers d'autres hôtes (par exemple lors de l'empreinte d'un hôte distant)
.
[stat
s]
sampling_ra
te
Ettercap conserve certaines statistiques sur le temps de traitement de la moitié basse (le sniffeur) et de la moitié haute (le décodeur de protocole). Ces statistiques sont calculées sur le temps de traitement moyen de sampling_rate paquets. Vous pouvez diminuer cette valeur pour obtenir une image plus précise du temps de traitement en temps réel, ou l'augmenter pour une image plus lisse. La moyenne totale ne changera pas, mais la pire valeur sera fortement influencée par cette
valeur.
[mis
c]
close_on_e
of
Lors de la lecture depuis un fichier de capture et de l'utilisation de l'interface console ou démon, cette variable est utilisée pour déterminer quelle action doit être effectuée à la fin de fichier. C'est une valeur booléenne. Si elle est définie à 1, ettercap se fermera de lui-même (utile dans les scripts). Sinon, la session continuera en attendant la saisie de
l'utilisateur.
store_profil
es
Ettercap collecte en mémoire un profil pour chaque hôte qu'il détecte. Les utilisateurs et les mots de passe y sont collectés. Si vous voulez exécuter ettercap en arrière-plan en journalisant tout le trafic, vous voudrez peut- être désactiver la collecte en mémoire pour économiser la mémoire du système. Définissez cette option à 0 (zéro) pour désactiver la collecte des profils. Une valeur de 1 activera la collecte pour tous les hôtes, 2 collectera uniquement les hôtes locaux et 3 uniquement les hôtes distants (un hôte est considéré comme distant s'il n'appartient pas au masque de réseau)
.
aggressive_dissect
ors
Certains dissecteurs (comme SSH et HTTPS) doivent modifier la charge utile des paquets afin de collecter les mots de passe et de mener une attaque de déchiffrement. Si vous voulez désactiver complètement les dissecteurs "dangereux", définissez cette valeur
à 0.
skip_forward
ed
Si vous définissez cette valeur à 0, vous intercepterez même les paquets transférés par ettercap ou par le noyau. Cela générera des paquets en double en conjonction avec la méthode MITM arp (par exemple). Cela pourrait être utile lors de l'exécution d'ettercap en mode non offensif sur un hôte avec plus d'une interface réseau (en attendant la fonctionnalité multi- interface.
..)
checksum_warn
ing
Si vous définissez la valeur à 0, les messages concernant les sommes de contrôle incorrectes ne seront pas affichés dans les fenêtres de messages utilisateur (ni journalisés dans un fichier avec -m).
Notez que cette option ne désactivera pas la vérification des paquets, mais empêchera seulement l'affichage du message (voir ci-dessous)
.
checksum_che
ck
Cette option est utilisée pour désactiver complètement la vérification de la somme de contrôle des paquets qu'ettercap reçoit. La vérification des paquets est effectuée pour éviter qu'ettercap ne soit détecté grâce à des paquets avec de mauvaises sommes de contrôle (voir Phrack 60.12). Si vous désactivez la vérification, vous pourrez intercepter même des paquets avec de mauvaises sommes de contrôle, mais vous serez détecté si quelqu'un vous cherche.
..
sniffing_at_star
tup
Si cette option est définie à 1, ettercap démarrera immédiatement le sniffing unifié ou en pont après la fin de la phase de configuration. Cette option aide à éviter le blocage du trafic lorsqu'une technique MITM a été démarrée mais qu'on a oublié de démarrer le sniffing. Par conséquent, cette option est définie à 1 par défaut.
Si ce comportement n'est pas souhaité, définissez-la à 0 pour contrôler manuellement l'état du sniffing unifié ou en pont après le démarrage d'ettercap. Cependant, le sniffing peut être arrêté et démarré à tout moment pendant l'exécution
d'ettercap.
geoip_support_ena
ble
Cette option contrôle si les informations GeoIP doivent être traitées pour les adresses IP, que ettercap ait été compilé avec le support GeoIP ou
non.
gtkui_prefer_dark_th
eme
Cette option tente d'imposer la variante sombre du thème appliqué. Cependant, cela n'a un effet que si le thème appliqué fournit une variante sombre. Normalement, l'environnement de bureau contrôle le thème des applications. Mais certains environnements de bureau légers ne prennent pas en charge une option de configuration pour les thèmes sombres même lorsque le thème fournit une variante sombre. Pour laisser le choix de la variante du thème à l'environnement de bureau, cette option est définie à 0 par défaut.
REMARQUE : Cette option n'est pertinente qu'en mode GTK et si ettercap a été compilé avec un support GTK3
complet.
[dissector
s]
protocol_na
me
Cette valeur représente le port auquel le dissecteur de protocole doit se lier. Une valeur de 0 désactivera le dissecteur. Le nom de la variable est le même que le nom du protocole. Vous pouvez spécifier un port non standard pour chaque dissecteur ainsi que plusieurs ports. La syntaxe pour la sélection multiports est la suivante : port1,port2,port3,...
REMARQUE : certains dissecteurs sont compilés conditionnellement. Cela signifie que, en fonction des bibliothèques trouvées sur votre système, certains dissecteurs seront activés et d'autres non. Par défaut, etter.conf contient tous les dissecteurs pris en charge. Si vous obtenez une erreur "FATAL: Dissector "xxx" does not exists (etter.conf line yy)", vous devez mettre en commentaire la ligne yy dans etter.
conf.
[curse
s]
col
or
Vous pouvez personnaliser les couleurs de l'interface curses.
Définissez simplement un champ à l'une des valeurs suivantes et regardez l'aspect de l'interface :)
Voici une liste de valeurs : 0 Noir, 1 Rouge, 2 Vert, 3 Jaune, 4 Bleu, 5 Magenta, 6 Cyan, 7
Blanc
[string
s]
utf8_encodi
ng
spécifie l'encodage à utiliser lors de l'affichage des paquets au format UTF-8. Utilisez la commande `iconv --list` pour obtenir une liste des encodages pris en
charge.
remote_brows
er
Cette commande est exécutée par le plugin remote_browser chaque fois
qu'il intercepte une bonne requête d'URL dans une connexion HTTP. La commande doit être capable de recevoir 2 paramètres :
%ho
st
la balise Host: dans l'en-tête HTTP. Utilisée pour créer la requête complète dans le
navigateur.
%u
rl
La page d
emandée d
ans la req
uête GET.
redir_command
_on
Vous devez fournir une commande (ou un script) valide pour activer la
redirection tcp au niveau du noyau afin de pouvoir utiliser la dissec
tion SSL. Votre script doit être capable de recevoir 5 paramètres :
%ifa
ce
L'interface réseau sur laquelle la règle doit être
définie
%sour
ce
L'IP source ou le réseau correspondant aux paquets à rediriger (la valeur par défaut est 0.0.0.0/0, ::/0 respectivement, ou n'importe
lequel)
%destinati
on
L'IP de destination ou le réseau correspondant aux paquets à rediriger (la valeur par défaut est 0.0.0.0/0, ::/0 respectivement, ou n'importe
lequel)
%po
rt
Le port source des paquets à rediriger (443 pour HTTPS, 993 pour imaps,
etc).
%rpo
rt
Le port lié en interneau auquel ettercap écoute les connexions. REMARQUE :
ce script est exécuté avec un execve(), vous ne pouvez donc pas utiliser d
e pipes ni de redirection de sortie comme si vous étiez dans un shell. No
us vous suggérons de créer un script si vous avez besoin de ces commandes.

REMARQUE : pour que cela fonctionne, vous devez définir ec_uid à un UID qui est autorisé à exécuter le redir_command ou fournir un programme

setuid.
redir_command_
off
Ce script est utilisé pour supprimer les règles de redirection appliquées par
'redir_command_on'. Vous devez noter que ce script est appelé à l'aide de atexi
t() et n'a donc pas de privilèges élevés. Vous devriez fournir un programme setuid ou définir ec_uid à 0 pour être sûr que le script est exécuté avec succès.
