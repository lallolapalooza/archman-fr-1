Email::MIME::ContentType(3) Documentation Perl contribuée par les utilisateurs Email::MIME::ContentType(3)

NOM

Email::MIME::ContentType - Analyser et construire un en-tête MIME Content-Type ou Content-Disposition

VERSION

version 1.028

SYNOPSIS

use Email::MIME::ContentType;
# Content-Type: text/plain; charset="us-ascii"; format=flowed
my $ct = 'text/plain; charset="us-ascii"; format=flowed';
my $data = parse_content_type($ct);
$data = {
  type       => "text",
  subtype    => "plain",
  attributes => {
    charset => "us-ascii",
    format  => "flowed"
  }
};
my $ct_new = build_content_type($data);
# text/plain; charset=us-ascii; format=flowed
# Content-Type: application/x-stuff;
#  title*0*=us-ascii'en'This%20is%20even%20more%20;
#  title*1*=%2A%2A%2Afun%2A%2A%2A%20;
#  title*2="isn't it!"
my $ct = q(application/x-stuff;
 title*0*=us-ascii'en'This%20is%20even%20more%20;
 title*1*=%2A%2A%2Afun%2A%2A%2A%20;
 title*2="isn't it!");
my $data = parse_content_type($ct);
$data = {
  type       => "application",
  subtype    => "x-stuff",
  attributes => {
    title => "This is even more ***fun*** isn't it!"
  }
};
# Content-Disposition: attachment; filename=genome.jpeg;
#   modification-date="Wed, 12 Feb 1997 16:29:51 -0500"
my $cd = q(attachment; filename=genome.jpeg;
  modification-date="Wed, 12 Feb 1997 16:29:51 -0500");
my $data = parse_content_disposition($cd);
$data = {
  type       => "attachment",
  attributes => {
    filename            => "genome.jpeg",
    "modification-date" => "Wed, 12 Feb 1997 16:29:51 -0500"
  }
};
my $cd_new = build_content_disposition($data);
# attachment; filename=genome.jpeg; modification-date="Wed, 12 Feb 1997 16:29:51 -0500"

FONCTIONS

parse_content_type

Cette routine est exportée par défaut.

Cette routine analyse les en-têtes de type de contenu des e-mails conformément à la section 5.1 de la RFC 2045 ainsi qu'à la RFC 2231 (jeu de caractères et continuations de paramètres). Elle retourne un hash comme ci-dessus, avec des entrées pour le "type", le "subtype", et un hash de "attributes".

Pour la rétrocompatibilité avec un malentendu vraiment regrettable de la RFC 2045 par les premiers implémenteurs de ce module, "discrete" et "composite" sont également présents dans le hashref retourné, avec les valeurs de "type" et "subtype" respectivement.

parse_content_disposition

Cette routine est exportée par défaut.

Cette routine analyse les en-têtes Content-Disposition des e-mails conformément aux RFC 2183 et 2231. Elle retourne un hash comme ci-dessus, avec des entrées pour le "type", et un hash de "attributes".

build_content_type

Cette routine est exportée par défaut.

Cette routine construit l'en-tête Content-Type des e-mails conformément aux RFC 2045 et 2231. Elle prend un hash comme ci-dessus, avec des entrées pour le "type", le "subtype", et éventuellement aussi un hash de "attributes". Elle retourne une chaîne représentant l'en-tête Content-Type. Les attributs non-ASCII sont encodés en UTF-8 conformément à la section Jeu de caractères de la RFC 2231. Un attribut qui a plus de 78 caractères ASCII est divisé en plusieurs attributs conformément aux continuations de paramètres de la RFC 2231.

Pour des raisons de compatibilité avec les clients qui ne supportent pas la RFC 2231, la chaîne de sortie contient aussi une version ASCII tronquée de tout attribut trop long ou non-ASCII. L'encodage en ASCII se fait via le module Text::Unidecode. Ce comportement peut causer de la confusion pour les implémentations MIME compatibles avec la 2231, et peut être désactivé en définissant $Email::MIME::ContentType::STRICT à vrai.

build_content_disposition

Cette routine est exportée par défaut.

Cette routine construit l'en-tête Content-Disposition des e-mails conformément aux RFC 2182 et 2231. Elle prend un hash comme ci-dessus, avec des entrées pour le "type", et éventuellement aussi un hash de "attributes". Elle retourne une chaîne représentant l'en-tête Content-Disposition. Les attributs non-ASCII ou trop longs sont traités de la même manière que dans la fonction build_content_type.

AVERTISSEMENTS

Ceci n'est pas un en-tête de type de contenu valide, selon les RFC 1521 et 2045 :

Content-Type: type/subtype;

Si un point-virgule apparaît, un paramètre doit suivre. "parse_content_type" émettra un avertissement si elle rencontre un en-tête de ce type, mais vous pouvez supprimer cela en définissant $Email::MIME::ContentType::STRICT_PARAMS à une valeur fausse. Veuillez envisager de localiser cette assignation !

La même chose s'applique pour "parse_content_disposition".
