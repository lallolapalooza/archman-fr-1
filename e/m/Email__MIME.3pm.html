NOM

Email::MIME - gestion facile des messages MIME

VERSION

version 1.954

SYNOPSIS

Attendez ! Avant de lire ceci, il se peut que vous ayez seulement besoin de Email::Stuffer, qui est un outil beaucoup plus facile à utiliser pour construire des courriels simples qui peuvent avoir des pièces jointes ou à la fois du texte brut et du HTML. Si cela ne vous convient pas, alors continuez absolument à lire.

use Email::MIME;
my $parsed = Email::MIME->new($message);
my @parts = $parsed->parts; # Ce seront aussi des objets Email::MIME.
my $decoded = $parsed->body;
my $non_decoded = $parsed->body_raw;
my $content_type = $parsed->content_type;

...ou...

use Email::MIME;
use IO::All;
# message multipart
my @parts = (
    Email::MIME->create(
        attributes => {
            filename     => "report.pdf",
            content_type => "application/pdf",
            encoding     => "quoted-printable",
            name         => "2004-financials.pdf",
        },
        body => io( "2004-financials.pdf" )->binary->all,
    ),
    Email::MIME->create(
        attributes => {
            content_type => "text/plain",
            disposition  => "attachment",
            charset      => "US-ASCII",
        },
        body_str => "Hello there!",
    ),
);
my $email = Email::MIME->create(
    header_str => [
        From => 'casey@geeknest.com',
        To => [ 'user1@host.com', 'Name <user2@host.com>' ],
        Cc => Email::Address::XS->new("Display Name \N{U+1F600}", 'user@example.com'),
    ],
    parts      => [ @parts ],
);
# imbrication des parties
$email->parts_set(
    [
      $email->parts,
      Email::MIME->create( parts => [ @parts ] ),
    ],
);
# modifications standard
$email->header_str_set( 'X-PoweredBy' => 'RT v3.0'      );
$email->header_str_set( To            => rcpts()        );
$email->header_str_set( Cc            => aux_rcpts()    );
$email->header_str_set( Bcc           => sekrit_rcpts() );
# plus avancé
$_->encoding_set( 'base64' ) for $email->parts;
# Création rapide d'un multipart
my $email = Email::MIME->create(
    header_str => [
        From => 'my@address',
        To   => 'your@address',
    ],
    parts => [
        q[This is part one],
        q[This is part two],
        q[These could be binary too],
    ],
);
print $email->as_string;

DESCRIPTION

Ceci est une extension du module Email::Simple, pour gérer les messages encodés en MIME. Elle prend un message sous forme de chaîne, le divise en ses parties constitutives, et vous permet d'accéder aux différentes parties du message. Les en-têtes sont décodés de l'encodage MIME.

VERSION DE PERL

Cette bibliothèque devrait fonctionner sur des versions de perl sorties il y a longtemps. Elle devrait fonctionner sur toute version de perl sortie au cours des cinq dernières années.

Bien qu'elle puisse fonctionner sur des versions plus anciennes de perl, aucune garantie n'est faite que la version minimale requise ne sera pas augmentée. La version peut être augmentée pour n'importe quelle raison, et il n'y a aucune promesse que des correctifs seront acceptés pour abaisser la version minimale de perl requise.

MÉTHODES

Veuillez consulter Email::Simple pour l'ensemble de base des méthodes. Cela ne prendra pas très longtemps. En plus de cela, vous avez :

create

my $single = Email::MIME->create(
  header_str => [ ... ],
  body_str   => '...',
  attributes => { ... },
);
my $multi = Email::MIME->create(
  header_str => [ ... ],
  parts      => [ ... ],
  attributes => { ... },
);

Cette méthode crée une nouvelle partie MIME. Le "header_str" paramètre est une liste de paires d'en-têtes à inclure dans le message. La valeur de chaque paire est censée être une chaîne de texte qui sera encodée en MIME selon les besoins. Alternativement, elle peut être un objet avec la "as_mime_string" méthode qui implémente la conversion de cet objet en chaîne encodée en MIME. Cette méthode d'objet est appelée avec deux paramètres d'entrée nommés : "charset" et "header_name_length". Elle devrait retourner la représentation encodée en MIME de l'objet. En date du 2017-07-25, le code pour les en-têtes-valeurs-sous-forme-d'objet est très récent, et pourrait encore changer.

Dans le cas où le nom de l'en-tête est enregistré dans le %Email::MIME::Header::header_to_class_map hash, alors la classe enregistrée est utilisée pour la conversion d'une chaîne Unicode en encodage MIME 8 bits. La valeur peut être soit une chaîne, soit une référence à un tableau de chaînes. L'objet est construit via la méthode "from_string" avec la valeur de la chaîne (ou les valeurs en cas de référence à un tableau) et converti en chaîne encodée en MIME via la "as_mime_string" méthode.

Un paramètre "header" similaire peut être fourni en plus de, ou à la place de, "header_str". Ses valeurs seront utilisées telles quelles.

"attributes" est un hash d'attributs MIME à assigner à la partie, et peut remplacer des portions de l'en-tête défini dans le "header" paramètre. Les clés du hash correspondent directement aux méthodes pour modifier un message. Les clés autorisées sont : content_type, charset, name, format, boundary, encoding, disposition, et filename. Elles seront mappées vers "$attr\_set" pour la modification du message.

Le "parts" paramètre est une référence à une liste contenant des objets "Email::MIME" . Les éléments de la "parts" liste peuvent aussi être une chaîne de données non-référence. Dans ce cas, un "Email::MIME" objet sera créé pour vous. Des vérifications simples détermineront si la partie est binaire ou non, et toutes les parties créées de cette manière sont encodées avec "base64", par précaution.

Si "body" est donné à la place de "parts", il spécifie le corps à utiliser pour un message MIME plat (sans sous-partie). On suppose que c'est une séquence d'octets.

Si "body_str" est donné à la place de "body" ou "parts", on suppose que c'est une chaîne de caractères à utiliser comme corps. Si vous fournissez un "body_str" paramètre, vous devez fournir les attributs "charset" et "encoding" .

content_type_set

$email->content_type_set( 'text/html' );

Change le type de contenu. Tous les attributs de l'en-tête "Content-Type" resteront intacts.

charset_set

name_set

format_set

boundary_set

$email->charset_set( 'UTF-8' );
$email->name_set( 'some_filename.txt' );
$email->format_set( 'flowed' );
$email->boundary_set( undef ); # supprime la frontière

Ces quatre méthodes modifient les attributs courants de "Content-Type" . S'ils sont définis à "undef", l'attribut est supprimé. Toutes les autres informations de l'en-tête "Content-Type" sont préservées lors de la modification d'un attribut.

encode_check

encode_check_set

$email->encode_check;
$email->encode_check_set(0);
$email->encode_check_set(Encode::FB_DEFAULT);

Récupère/définit le paramètre "encode_check" courant (par défaut : FB_CROAK"). C'est le paramètre passé à "decode" dans Encode et à "encode" dans Encode quand body_str(), body_str_set(), et an class="Li">create() sont appelées.

Avec le paramètre par défaut, Email::MIME peut planter si le jeu de caractères revendiqué d'un corps ne correspond pas à son contenu (par exemple - des données utf8 dans un message text/plain; charset=us-ascii).

Avec un "encode_check" de 0, les octets non reconnus seront à la place remplacés par le "REPLACEMENT CHARACTER" (U+0FFFD), et peuvent finir par être soit celui-ci, soit des points d'interrogation (?).

Voir "Handling Malformed Data" dans Encode pour plus d'informations.

encoding_set

$email->encoding_set( 'base64' );
$email->encoding_set( 'quoted-printable' );
$email->encoding_set( '8bit' );

Convertit le corps du message et modifie l'en-tête "Content-Transfer-Encoding" en utilisant cette méthode. Le corps de votre message, la sortie de la méthode body() , restera le même. Le corps brut, la sortie de la méthode body_raw() , sera modifié pour refléter le nouvel encodage.

body_set

$email->body_set( $unencoded_body_string );

Cette méthode encodera le nouveau corps que vous envoyez en utilisant l'encodage spécifié dans l'en-tête "Content-Transfer-Encoding" , puis définira le corps sur le nouveau corps encodé.

body_str_set

$email->body_str_set($unicode_str);

Cette méthode se comporte comme "body_set", mais suppose que la valeur donnée est une chaîne Unicode qui doit être encodée dans le jeu de caractères du message avant d'être définie.

Le jeu de caractères doit déjà être défini, soit manuellement (via l'argument "attributes" à "create" ou "charset_set"), soit à travers le "Content-Type" d'un message analysé. Si le jeu de caractères ne peut pas être déterminé, une exception est levée.

disposition_set

$email->disposition_set( 'attachment' );

Modifie le "Content-Disposition" d'un message. Tous les attributs de l'en-tête resteront intacts.

filename_set

$email->filename_set( 'boo.pdf' );

Définit l'attribut filename dans l'en-tête "Content-Disposition" . Toutes les autres informations de l'en-tête sont préservées lors de la définition de cet attribut.

parts_set

$email->parts_set( \@new_parts );

Remplace les parties d'un objet. Accepte une référence à une liste d'objets "Email::MIME" , représentant les nouvelles parties. Si ce message était à l'origine une partie unique, l'en-tête "Content-Type" sera changé en "multipart/mixed", et recevra un nouvel attribut boundary.

parts_add

$email->parts_add( \@more_parts );

Ajoute des parties MIME à la partie MIME actuelle. C'est une simple extension de "parts_set" pour nous faciliter la vie. Elle accepte une référence à un tableau de parties supplémentaires.

walk_parts

$email->walk_parts(sub {
    my ($part) = @_;
    return if $part->subparts; # multipart
    if ( $part->content_type =~ m[text/html]i ) {
        my $body = $part->body;
        $body =~ s/<link [^>]+>//; # simple filter example
        $part->body_set( $body );
    }
});

Parcourt toutes les parties MIME d'un message et applique un rappel à chacune. Accepte une référence à une fonction comme unique argument. La référence à la fonction recevra un seul argument, la partie MIME actuelle dans l'objet MIME de premier niveau. Toutes les modifications seront appliquées sur place.

header

Achtung! Méfiez-vous de cette méthode ! Dans Email::MIME, elle signifie la même chose que "header_str", mais sur un objet Email::Simple, elle signifie "header_raw". Sauf si vous savez toujours quel type d'objet vous avez, vous pourriez obtenir l'un des deux comportements significativement différents.

Essayez d'utiliser soit "header_str" ou "header_raw" selon le cas.

header_str_set

$email->header_str_set($header_name => @value_strings);

Cela se comporte comme "header_raw_set", mais attend des chaînes Unicode (caractères) comme valeurs à définir, plutôt que des chaînes d'octets pré-encodées. Elle les encodera en tant que mots encodés MIME s'ils contiennent des caractères de contrôle ou 8 bits.

Alternativement, les valeurs peuvent être des objets avec la méthode "as_mime_string" . Identique à la méthode "create".

header_str_pairs

my @pairs = $email->header_str_pairs;

Cette méthode se comporte comme "header_raw_pairs", retournant une liste de paires nom de champ/valeur, mais les valeurs ont été décodées en chaînes de caractères, lorsque c'est possible.

header_as_obj

my $first_obj = $email->header_as_obj($field);
my $nth_obj   = $email->header_as_obj($field, $index);
my @all_objs  = $email->header_as_obj($field);
my $nth_obj_of_class  = $email->header_as_obj($field, $index, $class);
my @all_objs_of_class = $email->header_as_obj($field, undef, $class);

Cette méthode retourne une représentation objet de la valeur de l'en-tête. Elle instancie un nouvel objet via la méthode "from_mime_string" de la classe spécifiée. L'argument d'entrée pour cette méthode de classe est la liste des valeurs brutes encodées MIME. Si l'argument classe n'est pas spécifié, le nom de la classe est pris dans le hachage %Email::MIME::Header::header_to_class_map via la clé field. Utilisez la méthode de classe "Email::MIME::Header->set_class_for_header($class, $field)" pour ajouter un nouveau mappage.

parts

Cela retourne une liste d'objets "Email::MIME" reflétant les parties du message. S'il s'agit d'un message à partie unique, vous obtenez l'objet original.

En contexte scalaire, cette méthode retourne le nombre de parties.

C'est une méthode stupide. Ne l'utilisez pas.

subparts

Cela retourne une liste d'objets "Email::MIME" reflétant les parties du message. S'il s'agit d'un message à partie unique, cette méthode retourne une liste vide.

En contexte scalaire, cette méthode retourne le nombre de sous-parties.

body

Cela décode et retourne le corps de l'objet en tant que chaîne d'octets. Pour les objets de premier niveau dans les messages multi-parties, il s'agit très probablement de quelque chose comme "This is a multi-part message in MIME format."

body_str

Cela décode à la fois la couche Content-Transfer-Encoding du corps (comme la méthode "body" ) ainsi que le jeu de caractères du corps (contrairement à la méthode "body" ), retournant une chaîne Unicode.

Si le jeu de caractères est connu, il est utilisé. S'il n'y a pas de jeu de caractères mais que le type de contenu est soit "text/plain" ou "text/html", us-ascii est supposé. Sinon, une exception est levée.

body_raw

Cela retourne le corps de l'objet, mais ne décode pas l'encodage de transfert.

decode_hook

Cette méthode est appelée avant la méthode "decode" de Email::MIME::Encodings, pour décoder le corps des messages non binaires (ou des messages binaires, si la méthode "force_decode_hook" retourne vrai). Par défaut, cette méthode ne fait rien, mais les sous-classes peuvent définir un comportement.

Cette méthode pourrait être utilisée pour implémenter le déchiffrement du contenu dans un courriel sécurisé, par exemple.

content_type

C'est un raccourci pour accéder à l'en-tête du type de contenu.

filename

Cela fournit le nom de fichier suggéré pour la pièce jointe. Normalement, il retournera le nom de fichier provenant des en-têtes, mais si "filename" reçoit un paramètre vrai, il générera un nom de fichier "stable" approprié si aucun n'est trouvé dans les en-têtes MIME.

invent_filename

my $filename = Email::MIME->invent_filename($content_type);

Cette routine est utilisée par "filename" pour générer des noms de fichiers pour les fichiers joints. Elle essaiera de choisir une extension raisonnable, en se rabattant sur dat.

debug_structure

my $description = $email->debug_structure;

Cette méthode retourne une chaîne qui décrit la structure de l'entité MIME. Par exemple :

+ multipart/alternative; boundary="=_NextPart_2"; charset="BIG-5"
  + text/plain
  + text/html

CONFIGURATION

La variable i">$Email::MIME::MAX_DEPTH est la profondeur maximale des parties qui seront traitées. Sa valeur par défaut est 10, déjà supérieure à ce qu'un courriel légitime est susceptible d'atteindre. Cette valeur peut augmenter au fil du temps à mesure que l'analyseur est amélioré.

La variable $Email::MIME::MAX_PARTS est le nombre maximal de parties qui seront traitées. Sa valeur par défaut est 100, déjà supérieur à ce qu'un courriel légitime est susceptible d'atteindre. Cette valeur peut augmenter au fil du temps à mesure que l'analyseur est amélioré ou à mesure que des recherches suggèrent que notre position de départ était erronée.

L'augmentation de l'une de ces variables risque une consommation de mémoire importante. Testez avant de modifier quoi que ce soit.
