NOM

Email::Send::Test - Capture les emails envoyés via Email::Send pour les tests

SYNTAXE

# Charger comme d'habitude
use Email::Send;
use Email::Send::Test;
# Toujours effacer le piège à emails avant chaque test pour éviter des
# résultats inattendus, et donc des résultats de test fallacieux.
Email::Send::Test->clear;
### COMMENCEZ VOTRE CODE À TESTER (exemple ci-dessous)
my $sender = Email::Send->new({ mailer => 'Test' });
$sender->send( $message );
### FIN DE VOTRE CODE À TESTER
# Vérifiez que le nombre et le type (et le contenu) des mails
# correspondent à ce que vous attendez.
my @emails = Email::Send::Test->emails;
is( scalar(@emails), 1, '1 email envoyé' );
isa_ok( $emails[0], 'Email::MIME' ); # Les sous-classes de Email::Simple passent

DESCRIPTION

Email::Send::Test est un pilote destiné à être utilisé dans les tests d'applications qui utilisent Email::Send pour envoyer des emails.

Pour pouvoir l'utiliser dans les tests, vous aurez besoin d'un mécanisme de configuration pour spécifier la méthode de livraison à utiliser, ou d'une autre manière pour que dans vos scripts de test vous puissiez forcer votre code à utiliser "Test" comme expéditeur, plutôt que "Sendmail" ou un autre expéditeur réel.

Comment ça marche

Email::Send::Test est un piège pour les emails. Lorsqu'un email est envoyé, il ajoute les emails à un tableau interne sans rien faire du tout avec eux, et retourne un succès à l'appelant.

Si votre application envoie un email, il y en aura un dans le piège. Si vous en envoyez 20, il y en aura 20, et ainsi de suite.

Un test typique consistera à exécuter du code qui devrait résulter en l'envoi d'un email, puis à vérifier dans le piège pour voir si le code a effectivement envoyé l'email.

Si vous le souhaitez, vous pouvez extraire les emails du piège et les examiner. Si vous vous souciez seulement que quelque chose ait été envoyé, vous pouvez simplement effacer le piège et passer à votre test suivant.

Le piège à emails

Le piège à emails est un simple tableau qui se remplit avec ce qui est envoyé.

Lorsque vous envoyez un email, il est poussé à la fin du tableau. Vous pouvez accéder directement au tableau si vous le souhaitez, ou utiliser les méthodes fournies.

MÉTHODES

envoyer $message

Comme pour tout autre expéditeur Email::Send, "send" prend le message à envoyer.

Cependant, dans notre cas, aucun argument n'a de valeur pour nous, et ils sont donc ignorés.

Il est à noter que nous ne faisons RIEN pour vérifier ou modifier l'email. Par exemple, si on nous passe "undef", il finit tel quel dans le piège. De cette manière, vous pouvez voir exactement ce qui a été envoyé sans aucun possible bidouillage de la part de l'expéditeur de test.

Bien sûr, cela n'empêche aucun bidouillage par Email::Send lui-même :)

Retourne toujours vrai.

emails

La méthode "emails" est la méthode préférée et recommandée pour accéder au piège à emails.

En contexte de liste, retourne le contenu du tableau du piège sous forme de liste.

En contexte scalaire, retourne le nombre d'éléments dans le piège.

effacer

La méthode "clear" réinitialise le piège, le vidant.

Il est recommandé d'effacer toujours le piège avant chaque test pour s'assurer que les emails existants sont supprimés et ne créent pas un résultat de test fallacieux.

Retourne toujours vrai.

livraisons

Cette méthode retourne une liste d'arrayrefs, un pour chaque appel à "send" qui a été effectué. Chaque arrayref est sous la forme :

[ $mailer, $email, \@rest ]

Le premier élément est l'invocant sur lequel "send" a été appelé. Le second est l'email qui a été passé à "send". Le troisième est le reste des arguments passés à "send".
