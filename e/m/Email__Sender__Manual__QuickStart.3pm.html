DÉMARRAGE

RAPIDE

Envoyons du courrier

!

Pas de chichi, envoyons juste du

courrier. 
use strict;
use Email::Sender::Simple qw(sendmail);
use Email::MIME;
# Vous pouvez créer un objet courriel de plusieurs façons. Choisissez-en une que vous aimez !
my $email = Email::MIME->create(...);
sendmail($email)
;

C'est tout. Votre message part sur Internet et tente d'être livré à "x.ample@exampl

e.com".

Dans l'exemple ci-dessus, $email pourrait être un objet Email::MIME, un MIME::Entity, une chaîne contenant un message courriel, ou l'un des plusieurs autres types d'entrée. Si "Email::Abstract" peut comprendre une valeur, elle peut être passée à Email::Sender::Simple. Email::Sender::Simple essaie de faire une bonne supposition sur la façon d'envoyer le message. Elle essaiera généralement d'utiliser le programme sendmail sur les systèmes de type unix et d'utiliser SMTP sur Windows. Vous pouvez spécifier un transport, si vous en avez besoin, mais normalement cela ne devrait pas poser de problème. (Voir « Choisir un transport » cependant, pour plus d'informations.

)

Remarquez également que nous avons importé et utilisé une routine "sendmail" dans l'exemple ci-dessus. C'est exactement la même chose que d'écrire

: 
Email::Sender::Simple->send($email)
;

...mais c'est beaucoup plus facile à taper. Vous pouvez utiliser l'une ou

l'autre.

informations sur

l'enveloppe

Nous n'avons pas eu à dire à Email::Sender::Simple où envoyer le message. Si vous ne spécifiez pas de destinataires, elle utilisera toutes les adresses courriel qu'elle peut trouver dans les en-têtes To et Cc par défaut. Elle utilisera Email::Address::XS pour analyser ces champs. De même, si aucun expéditeur n'est spécifié, elle utilisera la première adresse trouvée dans l'en-tête From

.

Dans la plupart des systèmes de transmission de courrier, cependant, les en-têtes ne sont pas nécessairement liés aux adresses utilisées comme expéditeur et destinataires. Par exemple, l'en-tête de votre message pourrait dire « From: mailing-list@example.com » tandis que votre client SMTP dit « MAIL FROM:<verp-1234@lists.example.com> ». C'est une fonctionnalité puissante, et elle est nécessaire pour de nombreuses applications de courrier. Pouvoir les définir distinctement est important, et Email::Sender::Simple vous permet de le faire

: 
sendmail($email, { to => [ $to_1, $to_2 ], from => $sender })
;

en cas

d'erreur

Lorsque le message est envoyé avec succès (au moins jusqu'à son prochain saut), "sendmail" renverra une valeur vraie -- spécifiquement, un objet Email::Sender::Success. Cet objet n'est que rarement très utile. Ce qui est plus utile, c'est ce qui se passe si le message ne peut pas être

envoyé.

S'il y a une erreur lors de l'envoi du message, une exception sera levée. Ce sera un objet appartenant à la classe Email::Sender::Failure. Cet objet aura un attribut "message" décrivant la nature de l'échec. Il existe plusieurs formes spécialisées d'échec, comme Email::Sender::Failure::Multi, qui est levée lorsque plus d'une erreur est rencontrée lors d'une tentative d'envoi. Vous n'avez pas besoin de les connaître pour utiliser Email::Sender::Simple, cependant. Tout ce que vous avez besoin de savoir, c'est que "sendmail" renvoie vrai en cas de succès et meurt en cas

d'échec.

Si vous préférez ne pas avoir à attraper des exceptions en cas d'échec d'envoi de courrier, vous pouvez utiliser la méthode "try_to_send", qui peut être importée comme "try_to_sendmail". Cette méthode renverra simplement faux en cas d'échec d'envoi de

courrier.

Par exemple

: 
Email::Sender::Simple->try_to_send($email, { ... });
use Email::Sender::Simple qw(try_to_sendmail);
try_to_sendmail($email, { ... })
;

Certains transports Email::Sender peuvent signaler un succès si certains, mais pas tous, les destinataires ont pu être a

tteints. Email::Sender::Simple fait de son mieux pour s'assurer que cela n'arrive jamais. Lorsque vous utilisez Ema
il::Sender::Simple, le courrier doit soit être envoyé, soit ne pas l'être. Un succès partiel ne devrait jamais survenir.

Choisir un

transport

passer votre propre

transport

Si Email::Sender::Simple ne choisit pas le transport que vous voulez, ou si vous avez des besoins plus spécifiques, vous pouvez spécifier un transport de plusieurs façons. La plus simple est de construire un objet transport et de le passer. Vous pouvez en apprendre plus sur les transports ailleurs. Pour l'instant, nous supposerons simplement que vous devez envoyer du courrier via SMTP sur un port inhabituel. Vous pouvez envoyer du courrier comme ceci

: 
my $transport = Email::Sender::Transport::SMTP->new({
  host => 'smtp.example.com',
  port => 2525,
});
sendmail($email, { transport => $transport })
;

Maintenant, au lieu de deviner quel transport utiliser, Email::Sender::Simple utilisera celui que vous avez fourni. Ce transport devra être spécifié pour chaque appel à "sendmail", vous pourriez donc vouloir examiner les autres options, qui

suivent.

spécifier le transport dans

l'environnement

Si vous avez un programme qui fait plusieurs appels à Email::Sender::Simple, et que vous devez exécuter ce programme avec un serveur de courrier différent, vous pouvez définir des variables d'environnement pour changer la valeur par défaut. Par exemple

: 
$ export EMAIL_SENDER_TRANSPORT=SMTP
$ export EMAIL_SENDER_TRANSPORT_host=smtp.example.com
$ export EMAIL_SENDER_TRANSPORT_port=2525
$ perl
your-program

Il est important de noter que si vous avez défini le transport par défaut en utilisant l'environnement, aucun argument "transport" ultérieur passé à "sendmail" ne sera respecté. Si vous définissez le transport par défaut via l'environnement, c'est tout. Tout utilisera ce transport. (Remarquez également que bien que nous ayons donné les arguments host et port en minuscules ci-dessus, la casse des arguments dans l'environnement est aplatie pour prendre en charge les systèmes où les variables d'environnement ont une casse fixe. Ainsi, "EMAIL_SENDER_TRANSPORT_PORT" fonctionnerait

aussi.

C'est un comportement extrêmement précieux, car il vous permet d'auditer chaque message qui serait envoyé par un programme en exécutant quelque chose comme ceci

: 
$ export EMAIL_SENDER_TRANSPORT=Maildir
$ perl
your-program

Dans cet exemple, tout message envoyé via Email::Sender::Simple serait livré à un maildir dans le répertoire

courant.

sous-classer pour changer le transport par

défaut

Si vous voulez utiliser une bibliothèque qui se comportera comme Email::Sender::Simple mais avec un transport par défaut différent, vous pouvez sous-classer Email::Sender::Simple et remplacer la méthode "build_defaul

t_trans
port".

Test

s

Email::Sender::Simple rend très, très facile de tester du code qui envoie du courrier. La façon la plus simple est de faire quelque chose comme ceci

: 
use Test::More;
BEGIN { $ENV{EMAIL_SENDER_TRANSPORT} = 'Test' }
use YourCode;
YourCode->run;
my @deliveries = Email::Sender::Simple->default_transport->
deliveries;

Vous avez maintenant un tableau contenant chaque livraison effectuée via Email::Sender::Simple, dans l'ordre. Parce que vous avez défini le transport via l'environnement, aucun autre code ne pourra forcer un transport

différent.

Lors du test de code qui se divise (fork), Email::Sender::Transport::SQLit

e peut être utilisé pour permettre à chaque processus enfant de livrer
vers une base de données de destination unique et facile à inspecter.

Hé, où est le support de Bcc

?

Une question fréquente est « Pourquoi Email::Sender::Simple ne respecte-t-elle pas automatiquement mon en-tête Bcc ? » Cela est souvent combiné avec « Voici un correctif pour le "corriger". » Ce n'est pas un bug ni un oubli. Bcc est ignoré intentionnellemently pour l'instant car simplement ajouter les adresses Bcc aux destinataires du message ne produirait pas le comportement habituellement

souhaité.

Par exemple, voici un ensemble d'en-têtes

: 
From: sender@example.com
To:   to_rcpt@example.com
Cc:   cc_rcpt@example.com
Bcc:  the_boss@example.
com

Dans ce cas, on s'attendrait à ce que le message soit livré à trois personnes : to_rcpt, cc_rcpt et the_boss. C'est pourquoi il est souvent suggéré que l'en-tête Bcc devrait être une source pour les destinataires de l'enveloppe. En fait, cependant, un message avec un en-tête Bcc devrait probablement être livré uniquement aux destinataires Bcc. Le « B » de Bcc signifie « blind » (aveugle). Les autres destinataires ne devraient pas voir qui a reçu une copie en Cci. Cela signifie que vous voulez envoyer deux messages : un à to_rcpt et cc_rcpt, sans en-tête Bcc présent ; et un autre à the_boss uniquement, avec l'en-tête Bcc. Si vous prenez simplement les adresses Bcc comme destinataires, tout le monde verra qui a reçu une copie en

Cci.

Email::Sender::Simple promet d'envoyer les messages de manière atomique. C'est-à-dire : il ne livrera pas à seulement certains des destinataires et pas à d'autres. Cela signifie qu'il ne peut pas détecter automatiquement l'en-tête Bcc et effectuer deux livraisons. Il y aurait une possibilité que la deuxième échoue après que la première a réussi, ce qui briserait la promesse d'un échec ou d'un succès

pur.

L'autre stratégie pour gérer les Bcc est de supprimer l'en-tête Bcc du message puis d'injecter le message avec une enveloppe incluant les adresses Bcc. Les informations d'enveloppe ne seront pas visibles aux destinataires finaux, donc c'est sûr. Malheureusement, cela nécessite de modifier le message, et Email::Sender::Simple ne devrait pas altérer l'objet email mutable qui lui est passé. Il n'y a pas de méthode « clone » sur Email::Abstract, donc il ne peut pas non plus simplement construire une copie et la modifier. Lorsqu'une telle méthode existera, la gestion des Bcc pourrait être

possible.

Exemple de gestion des

Bcc

Si vous voulez prendre en charge l'en-tête Bcc maintenant, c'est à vous de gérer la façon dont vous voulez transformer le courrier et injecter les copies (éventuellement) transformées dans votre flux de courrier sortant. Il n'est pas raisonnable de suggérer qu'Email::Sender::Simple fasse ce

travail.

Exemple 1 : Définir explicitement les destinataires de l'enveloppe pour les destinataires

Bcc

Créez l'email sans en-tête Bcc, envoyez-le explicitement aux utilisateurs Bcc, puis envoyez-le implicitement aux utilisateurs

To/Cc. 
my $message = create_email_mime_msg;  # <- whatever you do to get the message
$message->header_set('bcc');          # delete the Bcc header before sending
sendmail($message, { to => $rcpt });  # send to explicit Bcc address
sendmail($message);                   # and then send as
normal

Exemple 2 : Définir explicitement les destinataires de l'enveloppe pour tous les

destinataires

Vous pouvez faire un seul appel à « sendmail » en extrayant toutes les adresses des destinataires des en-têtes vous-même et en

spécifiant tous les destinataires de l'envelop
pe en une fois. Encore une fois, supprimez l'en
-tête Bcc avant que le message ne soit envoyé.
