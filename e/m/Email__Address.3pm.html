DESCRIPTIO

N

Cette classe implémente un analyseur RFC 2822 basé sur des expressions régulières qui localise les adresses courriel dans les chaînes de caractères et renvoie une liste d'objets "Email::Address" trouvés. Vous pouvez également construire les objets manuellement. Le but de ce logiciel est d'être correct, et très très

rapide.

La version 1.909 et les versions antérieures de ce module contenaient des vulnérabilités (CVE-2015-7686 https://cve.mitre.org/cgi-bin/cvename.cgi?name=CVE-2015-7686) et (CVE-2015-12558 https://cve.mitre.org/cgi-bin/cvename.cgi?name=CVE-2018-12558) qui permettaient à un courriel spécialement conçu de provoquer un déni de service. Les vulnérabilités signalées et quelques autres cas pathologiques (signifiant qu'ils ne devraient vraiment pas survenir dans un courriel normal) ont été corrigés dans la version 1.910 et les versions suivantes. Si vous utilisez la version 1.909 ou une version antérieure, vous devriez mettre à jour

!

Vous pourriez également passer à Email::Address::XS qui possède une API rétrocompatible. Pourquoi ne pas simplement utiliser celui-ci

?

ATTENTION ! Un courriel n'est pas facile (voire impossible) à analyser avec une expression régulière, du moins si vous utilisez un "perl" antérieur à 5.10.0. Fournir des expressions régulières à utiliser par d'autres programmes n'est pas une bonne idée, car cela rend difficile l'amélioration de l'analyseur sans casser la fonctionnalité « c'est une expression régulière ». L'utilisation de ces expressions régulières n'est pas encouragée, et des méthodes comme "Email::Address->is_addr_spec" devraient être fournies à

l'avenir.

Plusieurs expressions régulières utilisées dans ce paquet sont utiles pour d'autres. Par commodité, ces variables sont déclarées en tant que variables de paquet auxquelles vous pouvez accéder depuis votre

programme.

Ces expressions régulières sont conformes aux règles spécifiées dans la RFC

2822.

Méthodes de

my @addrs = Email::Address->parse(
  q[me@local, Casey <me@local>, "Casey" <me@local> (West)
] );

Cette méthode renvoie une liste d'objets "Email::Address" qu'elle trouve dans la chaîne d'entrée. Veuillez noter qu'elle renvoie une liste et s'attend à ce qu'elle puisse trouver plusieurs adresses. Le comportement en contexte scalaire est

indéfini.

La spécification d'une adresse courriel permet des commentaires imbriqués de façon infinie. C'est bien en théorie, mais un peu excessif. Par défaut, ce module permet un seul (1) niveau de commentaires imbriqués. Si vous pensez en avoir besoin de plus, modifiez la variable de paquet $Email::Address::COMMENT_NEST_LEVEL pour en permettre

plus. 
$Email::Address::COMMENT_NEST_LEVEL = 10; # Je suis
profond

La raison de cette limitation quasi-inexistante est simple :

l'efficacité.

Les longues chaînes d'espaces blancs peuvent poser problème pour l'analyse par ce module, un bogue qui n'a pas encore été correctement corrigé. Le comportement par défaut est maintenant de réduire plusieurs espaces à un seul espace, ce qui évite ce problème. Pour empêcher ce comportement, définissez $Email::Address::COLLAPSE_SPACES à zéro. Cette variable disparaîtra lorsque le bogue sera correctement

résolu.

Conformément à la RFC 822 et ses descendants, ce module exige que les

adresses courriel soient uniquement en ASCII. Tout contenu non-ASCII dans
les adresses analysées fera que l'analyseur ne renverra aucun résultat.
