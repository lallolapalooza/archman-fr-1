ELINKS.CONF(5) Fichier de configuration ELinks ELINKS.CONF(5)

NOM

elinks.conf - Fichier de configuration ELinks

SYNOPSIS

set        <option> = <valeur>
set_domain <domaine> <option> = <valeur>
unset      <option>
bind       "<keyboard_map>" "<touche>" = "<action>"
include    "<fichier>"

DESCRIPTION

Le fichier elinks.conf contient des informations de configuration pour ELinks. Il peut être utilisé pour configurer le comportement d'ELinks de nombreuses manières : comportement des protocoles, raccourcis clavier, couleurs utilisées pour le rendu et pour l'interface utilisateur.

Il est lu au démarrage et sauvegardé uniquement lorsqu'il est demandé. Toutes les options décrites dans ce document peuvent être configurées depuis ELinks. L'édition de elinks.conf n'est nécessaire que si vous souhaitez remplacer les valeurs de certaines options dans des domaines individuels (set_domain).

Notez que les options relatives aux MIME utilisées pour spécifier les gestionnaires de différents types MIME ne sont pas entièrement décrites dans ce document. La documentation pour ces options se trouve dans le chapitre MIME du manuel ELinks. Les raccourcis clavier peuvent également être spécifiés dans elinks.conf. Ceci est décrit dans elinkskeys(5).

SYNTAXE

La syntaxe du fichier de configuration est très simple. Le fichier elinks.conf est un fichier texte ASCII libre. Le fichier peut contenir des tabulations et des sauts de ligne supplémentaires pour la mise en forme. Les mots-clés du fichier sont sensibles à la casse. Les commentaires peuvent être placés n'importe où dans le fichier (sauf entre guillemets). Les commentaires commencent par le caractère # et se terminent à la fin de la ligne.

EXEMPLES

Quelques réglages d'exemple :

# Utiliser un résolveur DNS asynchrone ?
set connection.async_dns = 1
# Marge de texte horizontale.
set document.browse.margin_width = 3
# Codepage par défaut du document.
set document.codepage.assume = "ISO-8859-1"
# Gestionnaires de protocoles définis par l'utilisateur
set protocol.user.mailto.unix = "mutt %h -s \"%s\""

favoris (Bookmarks)

Options des favoris.

Format de fichier pour les favoris (affecte la lecture et la sauvegarde) :

config (Système de configuration)

Options de gestion de la configuration.

config.comments <num> (défaut: 3)

Quantité de commentaires écrits automatiquement dans le fichier de configuration :
•0 aucun commentaire n'est écrit
•1 seul le "blurb" (nom+type) est écrit
•2 seule la description est écrite
•3 commentaires complets sont écrits

config.indentation <num> (défaut: 2)

Largeur de décalage d'un niveau d'indentation dans le fichier de configuration. Zéro signifie qu'aucune indentation n'est effectuée lors de la sauvegarde de la configuration.

config.saving_style <num> (défaut: 3)

Détermine ce qui se passe lorsque vous demandez à ELinks de sauvegarder les options :
•0 seules les valeurs des options actuelles sont modifiées
•1 les valeurs des options actuelles sont modifiées et les options manquantes sont ajoutées à la fin du fichier
•2 le fichier de configuration est réécrit à partir de zéro
•3 les valeurs des options actuelles sont modifiées et les options modifiées pendant cette session ELinks sont ajoutées à la fin du fichier

config.i18n [0|1] (défaut: 0)

Si défini à 1, les commentaires dans le fichier de configuration seront traduits dans la langue utilisée par l'interface utilisateur. Notez que si vous avez une langue différente définie dans différents terminaux, la langue utilisée dans le fichier de configuration PEUT être la même que celle du terminal où vous avez sauvegardé le fichier, mais cela devrait généralement être considéré comme imprévisible.

config.saving_style_w [0|1] (défaut: 0)

Ceci est une option interne utilisée lors de l'affichage d'un avertissement concernant config.saving_style obsolète. Vous ne devriez pas y toucher.

config.show_template [0|1] (défaut: 0)

Afficher les options de modèle dans les arbres auto-créés dans le gestionnaire d'options et les sauvegarder dans le fichier de configuration.

Options du

document.cache.cache_redirects [0|1] (par défaut :

0)
Mettre en cache même les redirections envoyées par le serveur (généralement via HTTP par un code HTTP 302 et un en-tête Location). C'était le comportement original pendant un certain temps, mais cela cause des problés dans une situation très courante pour divers systèmes de connexion web – souvent, lors de l'accès à un emplacement donné, ils vous redirigeront vers une page de connexion s'ils ne reçoivent pas un cookie d'authentification, la page de connexion vous donne alors le cookie et vous redirige vers la page originale, mais vous avez déjà mis en cache la redirection vers la page de connexion ! Si cette option a la valeur 0, ce dysfonctionnement est corrigé, mais occasionnellement vous pouvez recevoir des requêtes superflues (selon la façon dont vous le prenez ;-) vers le serveur. Si cette option a la valeur 1, les utilisateurs expérimentés peuvent toujours contourner cela par une combinaison intelligente de l'utilisation du rechargement, des sauts dans l'historique de session et de l'appui sur ctrl+enter.

Notez que cette option est vérifiée lors de la récupération des informations depuis l

e cache, pas lors de l'enregistrement dans le cache – ainsi si vous l'activez, même les
redirections précédentes seront prises depuis le cache au lieu de demander au serveur.
