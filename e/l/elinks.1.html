ELINKS(1) Le navigateur texte Elinks ELINKS(1]]

NOM

elinks - navigateur WWW en mode caractère, alternative à lynx

SYNOPSISSE

elinks [OPTION]... [URL]...

DESCRIPTION

ELinks est un navigateur WWW en mode texte, prenant en charge les couleurs, le rendu des tableaux, le téléchargement en arrière-plan, une interface de configuration pilotée par menu, la navigation par onglets et un code compact.

Les cadres (frames) sont pris en charge. Vous pouvez associer différents formats de fichiers à des visualiseurs externes. mailto: et telnet: sont pris en charge via des clients externes.

ELinks peut gérer aussi bien les fichiers locaux que les URL distantes. Les protocoles distants principalement pris en charge sont HTTP, HTTPS (avec la prise en charge de SSL compilée) et FTP. Une prise en charge de protocoles supplémentaires existe pour BitTorrent finger, Gopher, SMB et NNTP.

La page d'accueil de ELinks se trouve à l'adresse http://elinks.cz/, où le manuel d'ELinks est également hébergé.

OPTIONS

La plupart des options peuvent être définies dans l'interface utilisateur ou le fichier de configuration, vous n'avez donc généralement pas à vous en préoccuper. Notez que cette liste est approximativement équivalente à la sortie obtenue en exécutant ELinks avec l'option --long-help.

-always-load-config [0|1] (par défaut : 0)

Charge la configuration également pour les instances esclaves. Plus lent, mais plus robuste.

-anonymous [0|1] (par défaut : 0)

Restreint ELinks pour qu'il puisse s'exécuter sur un compte anonyme. La navigation dans les fichiers locaux, les téléchargements et la modification des options seront désactivés. L'exécution des visualiseurs est autorisée, mais les entrées du tableau d'associations ne peuvent pas être ajoutées ou modifiées.

-auto-submit [0|1] (par défaut : 0)

Soumet automatiquement le premier formulaire des URL indiquées.

-base-session <num> (par défaut : 0)

Utilisé en interne lors de l'ouverture d'instances ELinks dans de nouvelles fenêtres. L'identifiant correspond à des informations qui seront utilisées lors de la création de la nouvelle instance. Vous ne devriez pas l'utiliser.

-bind-address <str> (par défaut : "")

Utilise une adresse IP locale spécifique

-bind-address-ipv6 <str> (par défaut : "")

Utilise une adresse IPv6 locale spécifique

-colors (alias pour document.colors.use_document_colors)

Valeurs possibles : 0, 1 ou 2.

-config-dir <str> (par défaut : "")

Chemin du répertoire dans lequel ELinks lira et écrira ses fichiers de configuration et d'état d'exécution au lieu de ~/.config/elinks. Si le chemin ne commence pas par un '/', il est considéré comme relatif à votre répertoire HOME .

-config-dump

Affiche sur stdout un fichier de configuration avec les options définies sur les valeurs par défaut intégrées.

-config-file <str> (par défaut : "elinks.conf")

Nom du fichier de configuration à partir duquel toutes les options de configuration seront lues et dans lequel elles seront écrites. Il devrait être relatif à config-dir.

-config-help

Affiche l'aide pour les options de configuration et quitte.

-default-mime-type (alias pour mime.default_type)

Le type MIME par défaut utilisé pour les documents de type inconnu.

-default-keys [0|1] (par défaut : 0)

Lorsqu'il est défini, toutes les associations de touches des fichiers de configuration seront ignorées. Cela force l'utilisation des associations de touches par défaut et réinitialisera celles définies par l'utilisateur lors de l'enregistrement.

-delete-timer-queue [0|1] (par défaut : 0)

Indique s'il faut supprimer la file d'attente des minuteurs sous Windows. Lorsque QuickJS est activé sur Win32, vous pouvez activer cette option pour désactiver les délais d'exécution de js.

-dump [0|1] (par défaut : 0)

Affiche sur stdout les versions texte brut formatées des URL indiquées.

-dump-charset (alias pour document.dump.codepage)

Page de code utilisée lors du formatage de la sortie de dump.

-dump-color-mode (alias pour document.dump.color_mode)

Mode couleur utilisé avec -dump.

-dump-width (alias pour document.dump.width)

Largeur de la sortie de dump.

-eval

Spécifie des directives de fichier de configuration sur la ligne de commande qui seront évaluées après que tous les fichiers de configuration ont été lus. Exemple d'utilisation : -eval 'set protocol.file.allow_special_files = 1'

-force-html

Fait qu'ELinks suppose que les documents de type inconnu sont du HTML. Utile lorsque vous utilisez ELinks comme visualiseur externe depuis des MUAs. Cela équivaut à -default-mime-type text/html.

-?, -h, -help

Affiche l'aide d'utilisation et quitte.

-localhost [0|1] (par défaut : 0)

Restreint ELinks à fonctionner hors ligne et à ne se connecter qu'aux serveurs dont l'adresse est locale (c.-à-d. 127.0.0.1). Aucune connexion à des serveurs distants ne sera autorisée.

-long-help

Affiche une aide d'utilisation détaillée et quitte.

-lookup

Recherche l'hôte spécifié et affiche toutes les adresses IP résolues par DNS.

-no-connect [0|1] (par défaut : 0)

Exécute ELinks comme une instance séparée au lieu de se connecter à une instance existante. Notez que normalement, aucun fichier d'état d'exécution (signets, historique, etc.) n'est écrit sur le disque lorsque cette option est utilisée. Voir aussi -touch-files.

-no-home [0|1] (par défaut : 0)

Désactive la création et l'utilisation de fichiers dans le répertoire de configuration de l'utilisateur (~/.config/elinks). Cela force l'utilisation des valeurs de configuration par défaut et désactive l'enregistrement des fichiers d'état d'exécution.

-no-libevent [0|1] (par défaut : 0)

Désactive libevent.

-no-numbering (alias pour document.dump.numbering)

Empêche l'affichage du numéro de lien dans la sortie de dump.

Notez que cela n'affecte réellement que -dump, rien d'autre.

-no-references (alias pour document.dump.references)

Empêche l'affichage des références (URI) des liens du document dans la sortie de dump.

Notez que cela n'affecte réellement que -dump, rien d'autre.

-remote

Contrôle une instance ELinks distante en lui passant des commandes. L'option prend un argument supplémentaire contenant la méthode qui doit être invoquée et tous les paramètres qui doivent lui être passés. Pour faciliter l'utilisation, l'argument de méthode supplémentaire peut être omis, auquel cas toute argument d'URL sera ouvert dans de nouveaux onglets de l'instance distante.

Voici la liste des méthodes prises en charge :

•ping(): recherche une instance distante
•openURL(): invite à saisir une URL dans l'onglet courant
•openURL(URL): ouvre l'URL dans l'onglet courant
•openURL(URL, new-tab): ouvre l'URL dans un nouvel onglet
•openURL(URL, new-window): ouvre l'URL dans une nouvelle fenêtre
•addBookmark(URL, title): ajoute l'URL aux signets avec le titre
•infoBox(text): affiche le texte dans une boîte de message
•reload(): recharge le document dans l'onglet courant
•search(string): recherche dans l'onglet courant
•xfeDoCommand(openBrowser): ouvre une nouvelle fenêtre

-session-ring <num> (par défaut : 0)

Identifiant de l'anneau de session auquel cette session ELinks devrait se connecter. ELinks fonctionne dans des anneaux de session, où toutes les instances d'ELinks sont interconnectées et partagent l'état (cache, signets, cookies, etc.). Par défaut, toutes les instances d'ELinks se connectent à l'anneau de session 0. Vous pouvez changer ce comportement avec ce commutateur et former autant d'anneaux de session que vous le souhaitez. Évidemment, si l'anneau de session avec ce numéro n'existe pas encore, il est créé et cette instance ELinks deviendra l'instance maîtresse (ce qui n'a généralement pas beaucoup d'importance pour vous en tant qu'utilisateur).

Notez que vous ne voulez généralement pas utiliser ceci à moins que vous ne soyez un développeur et que vous souhaitiez effectuer des tests - si vous voulez que chaque instance ELinks fonctionne de manière autonome, utilisez plutôt l'option de ligne de commande -no-connect. Notez également que normalement, aucun fichier d'état d'exécution n'est écrit sur le disque lorsque cette option est utilisée. Voir aussi -touch-files.>

-source [0|1] (par défaut : 0)

Affiche les URL données sous forme source sur stdout.

-terminfo [0|1] (par défaut : 0)

Lorsqu'il est activé, les fonctions ncurses terminfo seront utilisées au lieu des séquences codées en dur.

-test [0|1] (par défaut : 0)

Lorsqu'il est activé, aide à tester le js.

-touch-files [0|1] (par défaut : 0)

Lorsqu'il est activé, les fichiers d'état d'exécution (signets, historique, etc.) sont écrits sur disque, même lorsque -no-connect ou -session-ring est utilisé. L'option n'a aucun effet si elle n'est pas utilisée en conjonction avec l'une de ces options.

-verbose <num> (par défaut : 1)

Le niveau de verbosité contrôle les messages affichés au démarrage et pendant l'exécution :
•0 signifie n'afficher que les erreurs graves
•1 signifie afficher les erreurs graves et les avertissements
•2 signifie afficher tous les messages

-version

Affiche les informations de version d'ELinks et quitte.

Généré à l'aide de la sortie d'ELinks version 0.18.0.

VARIABLES D'ENVIRONNEMENT

COMSPEC, SHELL

Le shell utilisé pour Fichier -> Shell OS sur DOS/Windows et UNIX, respectivement.

EDITOR

Le programme à utiliser pour l'éditeur externe (lors de l'édition de zones de texte).

ELINKS_CONFDIR

Si défini, l'emplacement du répertoire contenant les fichiers de configuration. S'il n'est pas défini, voir ci-dessous.

XDG_CONFIG_HOME

L'emplacement du répertoire contenant les fichiers de configuration. S'il est défini, les fichiers de configuration se trouvent dans $XDG_CONFIG_HOME/elinks/. Sinon dans ~/.config/elinks/.

ELINKS_TWTERM, LINKS_TWTERM

La commande à exécuter lors de la sélection de Fichier -> Nouvelle fenêtre et si TWDISPLAY est défini (par défaut twterm -e).

ELINKS_XTERM, LINKS_XTERM

La commande à exécuter lors de la sélection de Fichier -> Nouvelle fenêtre et si DISPLAY est défini (par défaut xterm -e).

FTP_PROXY, HTTP_PROXY, HTTPS_PROXY

L'hôte par lequel faire transiter le trafic des différents protocoles.

NO_PROXY

Une liste d'URL séparées par des virgules qui ne doivent pas passer par le proxy.

HOME

Le chemin vers le répertoire personnel de l'utilisateur. Utilisé lors de l'expansion de ~/.

WWW_HOME

Emplacement de la page d'accueil (comme dans lynx(1)).

FICHIERS

Les fichiers de configuration contrôlés par ELinks se trouvent dans le répertoire de configuration de l'utilisateur, par défaut ~/.config/elinks/. En plus des fichiers listés ci-dessous, une feuille de style CSS définie par l'utilisateur peut être définie à l'aide de l'option document.css.stylesheet .

@sysconfdir@/elinks.conf

Fichier de configuration global au site.

~/.config/elinks/elinks.conf

Fichier de configuration par utilisateur, chargé après la configuration globale au site.

~/.config/elinks/bookmarks

Fichier de signets.

~/.config/elinks/cookies

Fichier de cookies.

~/.config/elinks/exmodehist

Fichier d'historique d'exmode.

~/.config/elinks/formhist

Fichier d'historique des formulaires.

~/.config/elinks/globhist

Fichier d'historique contenant les URL les plus récemment visitées.

~/.config/elinks/gotohist

Fichier d'historique de la boîte de dialogue GoTo URL.

~/.config/elinks/hooks.{js,lua,pl,py,rb,scm}

Hooks de scriptage du navigateur.

~/.config/elinks/searchhist

Fichier d'historique de recherche.

~/.config/elinks/socket

Socket interne ELinks pour la communication entre ses instances.

~/.mailcap, /etc/mailcap

Correspondances des types MIME aux gestionnaires externes.

~/.mime.types, /etc/mime.types

Correspondances des extensions de fichiers aux types MIME.

BOGUES

Veuillez signaler tout autre bogue que vous rencontrez soit à la liste de diffusion ELinks à <elinks-users@linuxfromscratch.org> ou, si vous préférez, les saisir dans le système de suivi des bogues http://bugzilla.elinks.cz/. Plus d'informations sur la façon de contacter les développeurs et d'obtenir de l'aide peuvent être trouvées sur la page de la communauté http://elinks.cz/community.html.
