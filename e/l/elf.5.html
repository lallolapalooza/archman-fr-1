Le fichier d'en-tête <elf.h> définit le format des fichiers binaires exécutables ELF. Parmi ces fichiers se trouvent les fichiers exécutables normaux, les fichiers objets relocalisables, les fichiers core et les objets

partagés.

Un fichier exécutable utilisant le format de fichier ELF se compose d'un en-tête ELF, suivi d'une table d'en-têtes de programme ou d'une table d'en-têtes de section, ou des deux. L'en-tête ELF se trouve toujours à l'offset zéro du fichier. Les offsets de la table d'en-têtes de programme et de la table d'en-têtes de section dans le fichier sont définis dans l'en-tête ELF. Les deux tables décrivent le reste des particularités du

fichier.

Ce fichier d'en-tête décrit les en-têtes mentionnés ci-dessus sous forme de structures C et inclut également des structures pour les sections dynamiques, les sections de relocalisation et les tables de

symboles.

En-tête de programme

(Phdr)

La table des en-têtes de programme d'un fichier exécutable ou d'un objet partagé est un tableau de structures, chacune décrivant un segment ou d'autres informations dont le système a besoin pour préparer le programme à l'exécution. Un fichier objet segment contient une ou plusieurs sections. Les en-têtes de programme n'ont de sens que pour les fichiers exécutables et les objets partagés. Un fichier spécifie sa propre taille d'en-tête de programme avec les éléments e_phentsize et e_phnum de l'en-tête ELF. L'en-tête de programme ELF est décrit par le type Elf32_Phdr ou Elf64_Phdr selon l'architecture

: 


typedef struct {
    uint32_t   p_type;
    Elf32_Off  p_offset;
    Elf32_Addr p_vaddr;
    Elf32_Addr p_paddr;
    uint32_t   p_filesz;
    uint32_t   p_memsz;
    uint32_t   p_flags;
    uint32_t   p_align;
}
Elf32_Phdr; 


typedef struct {
    uint32_t   p_type;
    uint32_t   p_flags;
    Elf64_Off  p_offset;
    Elf64_Addr p_vaddr;
    Elf64_Addr p_paddr;
    uint64_t   p_filesz;
    uint64_t   p_memsz;
    uint64_t   p_align;
}
Elf64_Phdr;

Table des en-têtes de section

(Shdr)

La table des en-têtes de section d'un fichier permet de localiser toutes les sections du fichier. La table des en-têtes de section est un tableau de structures Elf32_Shdr ou Elf64_Shdr. Le membre e_shoff de l'en-tête ELF donne le décalage en octets depuis le début du fichier jusqu'à la table des en-têtes de section. e_shnum contient le nombre d'entrées que contient la table des en-têtes de section. e_shentsize contient la taille en octets de chaque

entrée.

Un indice de table des en-têtes de section est un indice de tableau. Certains indices de table des en-têtes de section sont réservés : l'entrée initiale et les indices entre SHN_LORESERVE et SHN_HIRESERVE. L'entrée initiale est utilisée dans les extensions ELF pour e_phnum, e_shnum et e_shstrndx ; dans les autres cas, chaque champ de l'entrée initiale est mis à zéro. Un fichier objet n'a pas de sections pour ces indices spéciaux

:

Notes

(Nhdr)

Les notes ELF permettent d'ajouter des informations arbitraires pour que le système les utilise. Elles sont largement utilisées par les fichiers core (e_type de ET_CORE), mais de nombreux projets définissent leur propre ensemble d'extensions. Par exemple, la chaîne d'outils GNU utilise les notes ELF pour transmettre des informations du chargeur à la bibliothèque

C.

Les sections de notes contiennent une série de notes (voir les définitions de struct ci-dessous). Chaque note est suivie du champ name (dont la longueur est définie dans n_namesz) puis du champ descriptor (dont la longueur est définie dans n_descsz) et dont l'adresse de départ a une alignement de 4 octets. Aucun de ces champs n'est défini dans la structure de note en raison de leurs longueurs

arbitraires.

Un exemple d'analyse de deux notes consécutives devrait clarifier leur disposition en mémoire

: 


void *memory, *name, *desc;
Elf64_Nhdr *note, *next_note;
/* Le pointeur du tampon pointe vers le début de la section/segment.  */
note = memory;
/* Si le nom est défini, il suit la note.  */
name = note->n_namesz == 0 ? NULL : memory + sizeof(*note);
/* Si le descripteur est défini, il suit le nom
   (avec alignement).  */
desc = note->n_descsz == 0 ? NULL :
       memory + sizeof(*note) + ALIGN_UP(note->n_namesz, 4);
/* La note suivante suit les deux (avec alignement).  */
next_note = memory + sizeof(*note) +
                     ALIGN_UP(note->n_namesz, 4) +
                     ALIGN_UP(note->n_descsz, 4)
;

Gardez à l'esprit que l'interprétation de n_type dépend de l'espace de noms défini par le champ n_namesz.
