XSBuilder - Qu'est-ce que c'est ?

Son but est de générer automatiquement une interface Perl vers du code C

Résout le problème selon lequel l'interface Perl n'est pas toujours à jour avec l'interface C

Évite beaucoup de travail de copier-coller

Les changements systématiques ne doivent être effectués qu'une seule fois

Par exemple les changements dans la gestion de la mémoire des chaînes de caractères.

Fait partie du système de construction de mod_perl 2.0

La plupart du code a été développé par Doug MacEachern. De plus, j'ai

abstrait le code de mod_perl afin qu'il soit utilisable pour n'importe quel code C
ajouté de nouvelles fonctionnalités comme les rappels (callbacks) et la capacité d'analyser les commentaires
Remplacé C::Scan par un Parse::RecDescent pour être indépendant de la plateforme et du compilateur

Le but est de remplacer le code actuel de génération XS de mod_perl par XSBuilder

Inline versus XSBuilder

Inline : intégrer du code C dans Perl
XSBuilder : Créer une interface pour des bibliothèques/applications C existantes

XSBuilder - Que fait-il ?

Créer des fonctions/méthodes Perl pour chaque fonction C

La fonction peut être assignée à différents paquets, également automatiquement en inspectant le premier paramètre

Créer une classe Perl pour chaque structure C

Chaque élément de la structure devient une méthode Perl pour obtenir/définir sa valeur. L'objet peut être soit une référence scalaire (utilisée par mod_perl) ou une référence à un hash (utilisée par Embperl), ce qui permet de stocker des données supplémentaires par le code Perl dans ce hash.

Créer du code de liaison pour gérer les rappels (callbacks)

Il existe plusieurs types de rappels, tous ne sont pas implémentés pour le moment

Créer des constantes Perl

Bientôt disponible...

XSBuilder - Comment ça marche ?

Analyser les fichiers d'en-tête C

Extraire

Les fonctions, leurs arguments et types de retour
Les structures et leurs membres
Les constantes
Les rappels (callbacks)

et créer quatre tableaux qui contiennent les résultats

Créer le code XS

L'entrée est

Les tableaux sources
Les fichiers de correspondance (mapfiles) qui contiennent la correspondance de C vers Perl
Du code C et Perl supplémentaire qui peut être utilisé pour personnaliser l'interface

La sortie est

Les fichiers XS (un pour chaque classe générée)
Makefile.PL pour chaque classe
Les fichiers pm

Analyser la source

Créez votre propre classe ParseSource et surchargez les méthodes...

package Apache::DAV::ParseSource;
use strict;
use vars qw{@ISA $VERSION} ;
use ExtUtils::XSBuilder::ParseSource  ;
@ISA = ('ExtUtils::XSBuilder::ParseSource') ;
$VERSION = '0.01';
my $dav_dir = 'C:\perl\msrc\cvs\mod_dav' ;
my $ap_dir  = 'c:\programme\apache group\apache' ;
# ============================================================================
sub find_includes {
    my $self = shift;
    return $self->{includes} if $self->{includes};
    my @includes = ("$ap_dir/include/ap_alloc.h", "$dav_dir/mod_dav.h") ;
    return $self->{includes} = $self -> sort_includes (\@includes) ;
    }
# ============================================================================
sub package     { 'Apache::DAV' } 
# ============================================================================
sub preprocess {
    my $self     = shift ;
    $_[0] =~ s/(?:API_EXPORT)(?:_NONSTD)?\s*\(\s*(.*?)\s*\)/$1/g ;
}
1;

Créer les fichiers de correspondance

Les fichiers de correspondance sont utilisés pour indiquer à XSBuilder comment les types de données C, les structures et les arguments de fonctions doivent être convertis en équivalents Perl.

Créer votre propre classe WrapXS et redéfinir les méthodes

package Apache::DAV::WrapXS ;
use strict;
use vars qw{@ISA $VERSION} ;
use ExtUtils::XSBuilder::WrapXS ;
@ISA = ('ExtUtils::XSBuilder::WrapXS') ;
$VERSION = '0.01';
# ============================================================================
sub new_parsesource  { [ Apache::DAV::ParseSource->new ] }
# ============================================================================
sub my_xs_prefix  { 'davxs_' }
# ============================================================================
sub h_filename_prefix  { 'moddav_xs_' }
# ============================================================================
sub xs_includes {
    my $self = shift ;
    my $i = $self -> SUPER::xs_includes ;
    my @i = grep (!/ap_alloc/, @$i) ;
    return \@i ;
}

XSBuilder peut créer/mettre à jour les fichiers de correspondance initiaux pour vous

Nous avons maintenant quatre fichiers de correspondance

new_types.map
Contient la correspondance des types C vers les classes Perl
new_functions.map
Contient la correspondance des fonctions C vers les fonctions Perl. Peut être utilisé pour réordonner les arguments, indiquer à XSBuilder quels arguments sont en fait des valeurs de retour et dans quel paquetage Perl la fonction sera créée.
new_structures.map
Contient la correspondance des structures C vers les classes Perl et définit pour quels membres des méthodes d'accès doivent être créées. Vous pouvez également spécifier si vous voulez une "new" méthode pour la classe.
new_callbacks.map
Contient la correspondance des fonctions de rappel C vers les fonctions de rappel Perl. Peut être utilisé pour réordonner les arguments, indiquer à XSBuilder quels arguments sont en fait des valeurs de retour et dans quel paquetage Perl la fonction sera créée.

C'est une bonne idée de renommer le préfixe "new_" en quelque chose d'unique, ici nous utilisons "dav"

Chaque fois que vous relancez checkmaps, XSBuilder créera des fichiers new_* avec les éléments qui ne font pas déjà partie des autres fichiers de correspondance.

Le fichier de correspondance des fonctions définit la correspondance des arguments des fonctions C vers les arguments Perl

L'entrée suivante dans le fichier de correspondance indique à XSBuilder que la valeur de "res_p" doit être retournée
dav_get_resource           | | r, <res_p

La fonction C

int dav_get_resource(request_rec *r, dav_resource **res_p) ;

Comment l'appeler depuis Perl

# get a sub request of the actual document
$subr = $r -> lookup_uri($uri);
# get a mod_dav resource object
my ($err, $resource) =  $subr->get_resource;
Vous pouvez laisser XSBuilder insérer votre code personnalisé, pour l'interface
Si vous appelez "get_props" depuis Perl "glue_dav_get_props" sera appelée, ce qui peut ajuster les arguments et les types de retour si nécessaire. Le code réel pour "glue_dav_get_props" sera pris depuis un fichier d'inclusion séparé. 
dav_get_props      | glue_
dav_get_allprops   | glue_

xsinclude\Apache\DAV\PropResult\Apache__DAV__PropResults.h

dav_get_props_result * dav_glue_get_props(dav_propdb * db, dav_xml_doc *doc)
    {
    dav_get_props_result * result = (dav_get_props_result *)ap_palloc (db -> p, sizeof (dav_get_props_result)) ;
    *result = dav_get_props(db, doc) ;
    return result ;
    }
Les arguments peuvent être remplacés
MODULE=Apache::Array   PACKAGE=Apache::Array PREFIX=ap_
 ap_make_array      | ap_make_array(r->pool, nelts, elt_size) | request_rec *:r, nelts, elt_size

ap_make_array nécessite un pool comme premier paramètre, nous passons le request_rec depuis Perl et XSBuilder prendra le pool à partir du request_rec.

Makefile.PL

Nous devons créer un Makefile.PL de premier niveau

use ExtUtils::MakeMaker ();

my $apdir  = '/path/to/apache';
my $davdir = '/path/to/moddav';
%MMARGS = (
           'INC'    => "-I\"$davdir\" -I\"$apdir/include\" -I\"$apdir/os/unix\" -I\"$dir/xs\"  -I\"$dir/xsinclude\"",
           ) ;
open FH, ">xs/mmargs.pl" or die "Cannot open xs/mmargs.pl ($!)" ;
print FH Data::Dumper -> Dump ([\%MMARGS], ['MMARGS']) ;
close FH ;
ExtUtils::MakeMaker::WriteMakefile(
    'NAME'    => 'Apache::DAV',
    'VERSION' => '0.13',
    %MMARGS,
);

Comment ça continue...

Génération de la documentation

XSBuilder extrait déjà les commentaires source des fonctions et des structures. Il analyse également les commentaires doxygen, qui sont utilisés dans Apache 2.0. Lyle Brooks a commencé à créer automatiquement des fichiers POD à partir de ces informations.
