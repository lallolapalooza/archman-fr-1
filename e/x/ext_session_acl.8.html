NOM

ext_session_acl - Aide externe pour le suivi de session Squid.

Version 1.2

SYNOPIS

ext_session_acl [-t délai ] [-b base de données ] [-a]

DESCRIPTION

ext_session_acl maintient un concept de sessions en surveillant les requêtes et en mettant fin aux sessions expirées. Le délai d'expiration est basé soit sur l'utilisation inactive ( -t ) soit sur une période de temps fixe ( -T ). La première option est adaptée pour afficher les termes et conditions à un utilisateur ; la seconde est adaptée pour l'affichage de publicités ou d'autres notifications (les deux comme une page de démarrage - voir les exemples de configuration dans le wiki en ligne). L'aide de session peut également être utilisée pour forcer les utilisateurs à se ré-authentifier si %LOGIN et -a sont tous deux utilisés.

OPTIONS

-t délai
Délai d'expiration pour inactivité de toute session. La valeur par défaut si non spécifiée est de 3600 secondes.
-T délai
Délai d'expiration fixe pour toute session. Ceci mettra fin à la session après le délai, quelle que soit l'activité de l'utilisateur. Si utilisé avec le mode actif, cela mettra fin à la session de l'utilisateur après délai, après quoi une autre LOGIN sera requise. LOGOUT réinitialisera la session et le délai d'expiration.
-b chemin
Chemin vers la base de données persistante. Si un fichier est spécifié, ce fichier unique est utilisé comme base de données. Si un chemin est spécifié, un environnement de base de données Berkeley DB est créé dans le répertoire. L'avantage de cette dernière option est un meilleur support de base de données entre plusieurs instances de l'aide de session. L'utilisation de plusieurs instances de l'aide de session avec un seul fichier de base de données provoquera des problèmes de synchronisation entre les processus. Si cette option n'est pas spécifiée, les détails de la session seront conservés uniquement en mémoire et toutes les sessions seront réinitialisées chaque fois que Squid redémarrera ses aides (redémarrage de Squid ou rotation des journaux).
-a
Mode actif. Dans ce mode, les sessions sont démarrées en évaluant une acl avec l'argument LOGIN, ou terminées par l'argument LOGOUT. Sans ce drapeau, l'aide démarre automatiquement la session après la première requête.

CONFIGURATION

L'aide ext_session_acl est une aide concurrente ; par conséquent, l'option concurrency= doit être spécifiée dans la configuration.

Exemple de configuration de session passive utilisant le mode automatique par défaut

external_acl_type session ttl=300 negative_ttl=0 children=1 concurrency=200 %LOGIN /usr/local/squid/libexec/ext_session_acl
acl session external session
http_access deny !session
deny_info http://votre.serveur.example.com/bannerpage?url=%s session

Configurez ensuite http://votre.serveur.example.com/bannerpage pour afficher une page de démarrage de session, puis redirigez l'utilisateur vers l'URL demandée donnée dans le paramètre de requête url.
