NOM

execl, execlp, execle, execv, execvp, execvpe - exécuter un programme

BIBLIOTHÈQUE

Bibliothèque C standard (libc, -lc)

SYNOPSIS

#include <unistd.h>

int execl(const char *pathname, const char *arg0, ...);
int execlp(const char *file, const char *arg0, ...);
int execle(const char *pathname, const char *arg0, ..., char *const envp[]);
int execv(const char *pathname, char *const argv[]);
int execvp(const char *file, char *const argv[]);
int execvpe(const char *file, char *const argv[], char *const envp[]);

DESCRIPTION

Les fonctions exec*() remplacent le processus actuel par un nouveau processus. Le nouveau processus est initialisé avec l'ID du processus appelant, mais avec un PID différent.

exec*() ne peut pas être utilisée pour changer de noyau. Elle remplace le segment d'image du processus courant par une image nouvelle. La nouvelle image de processus est chargée à partir d'un fichier exécutable spécifié.

Les arguments des fonctions exec*() sont les suivants :

pathname
Spécifie le chemin du fichier exécutable à exécuter.
file
Spécifie le nom du fichier exécutable à exécuter. Si file ne contient aucune barre oblique ('/'), alors le fichier est recherché dans les répertoires spécifiés par la variable d'environnement PATH. Si file contient une barre oblique, elle est traitée comme un chemin absolu ou relatif.
arg0
Le premier argument passé au nouveau processus. Par convention, il s'agit du nom du fichier exécutable.
argv
Un tableau de chaînes de caractères qui constituent la liste des arguments passés au nouveau processus. Le dernier élément de ce tableau doit être un pointeur NULL.
envp
Un tableau de chaînes de caractères qui constituent la liste des variables d'environnement passées au nouveau processus. Chaque chaîne est au format "NOM=VALEUR". Le dernier élément de ce tableau doit être un pointeur NULL. Si ce paramètre est NULL, le nouveau processus hérite de la liste des variables d'environnement du processus appelant.

Les fonctions execl(), execlp() et execle() utilisent une liste d'arguments variable pour passer les arguments et l'environnement. La liste d'arguments doit être terminée par un pointeur NULL. Le premier argument arg0 est le nom du programme.

Les fonctions execv(), execvp() et execvpe utilisent un tableau d'arguments argv pour passer les arguments. Le dernier élément de argv doit être un pointeur NULL. Le premier élément de argv est le nom du programme.

Les fonctions se terminant par p (execlp(), execvp(), execvpe) recherchent le fichier exécutable dans les répertoires spécifiés par la variable d'environnement PATH si le nom du fichier ne contient pas de barre oblique.

La fonction execle() et execvpe permettent de spécifier un nouvel environnement pour le nouveau processus.

Si le nouveau processus est exécuté avec succès, le code de retour n'est jamais atteint. Si une erreur se produit, exec*() retourne -1 et la variable globale errno est définie en conséquence.

VALEUR DE RETOUR

En cas de succès, ces fonctions ne retournent jamais. En cas d'erreur, elles retournent -1 et errno est défini.

ERREURS

EACCES
Le fichier spécifié par pathname ou file n'est pas accessible en exécution, ou l'un des répertoires du chemin d'accès n'est pas accessible en recherche.
EFAULT
Un des pointeurs pathname, file, arg0, argv ou envp pointe en dehors de l'espace d'adressage accessible.
ELOOP
Trop de liens symboliques ont été rencontrés lors de la résolution de pathname ou file.
ENAMETOOLONG
La longueur de pathname ou file dépasse PATH_MAX.
ENOENT
Le fichier spécifié par pathname ou file n'existe pas, ou l'un des répertoires du chemin d'accès n'existe pas.
ENOTDIR
Un composant de pathname ou file n'est pas un répertoire.
ETXTBSY
Le fichier est un fichier texte occupé, et l'exécution est interdite.

Des erreurs supplémentaires peuvent survenir selon le type de fichier exécutable.

ATTRIBUTS

PORTABILITÉ

Les fonctions execl(), execv(), execle(), execve(), execlp(), execvp() sont définies par POSIX.1-2001. execvpe est une extension GNU.

CONFORMITÉ

Les fonctions execl(), execlp(), execle(), execv(), execvp() sont conformes à POSIX.1-2001.

execvpe est une extension GNU.

NOTES SUR LA TRANSMISSION DES DESCRIPTEURS DE FICHIER

Lorsqu'un processus est remplacé par un appel à l'une des fonctions exec*(), tous les descripteurs de fichiers ouverts par le processus appelant restent ouverts dans le nouveau processus, sauf s'ils ont été explicitement fermés avant l'appel à exec*(). Les descripteurs de fichiers marqués pour la fermeture (par exemple, avec fcntl(fd, F_SETFD, FD_CLOEXEC)) sont fermés avant l'exécution du nouveau programme.

BOGUES

Avant glibc 2.24, execl() et execle() utilisaient realloc(3) en interne et n'étaient par conséquent pas sûrs au niveau des signaux asynchrones, en violation des exigences de POSIX.1. Ce problème a été corrigé dans glibc 2.24.

Détails spécifiques à l'architecture

Sur sparc et sparc64, execv() est fournie comme appel système par le noyau (avec le prototype indiqué ci-dessus) pour la compatibilité avec SunOS. Cette fonction n'est *pas* utilisée par la fonction d'encapsulation execv() sur ces architectures.
