FBB::Exception(3bobcat) classe d'exception insérable FBB::Exception(3bobcat)

NOM

FBB::Exception - objets std::exception acceptant les insertions de flux

SYNTAXE

#include <bobcat/exception>
Option de liaison : -lbobcat

DESCRIPTION

Les objets FBB::Exception sont dérivés de std::exception, mais ils acceptent les insertions de flux. Leur utilisation prévue consiste à lancer un objet anonyme, dans lequel le texte du message std::exception::what a été inséré.

Les exceptions Exception sont lancées par plusieurs classes Bobcat. Ces classes sont Arg, ArgConfig, BigInt, Cgi, Cidr, ClientSocket, CmdFinderBase, ConfigFile, DateTime, DecryptBuf, DigestBuf, EncryptBuf, Fork, GetHostent, Glob, HMacBuf, Hostname, LocalClientSocket, LocalServerSocket, LocalSocketBase, Log, MailHeaders, Mbuf, Milter, Mstream, OFoldBuf, OneKey, Pattern, Pipe, Process, Redirector, Selector, ServerSocket, Signal, SocketBase, Stat, TempStream, User, Xpointer

ESPACE DE NOMS

FBB
Tous les constructeurs, membres, opérateurs et manipulateurs mentionnés dans cette page de manuel sont définis dans l'espace de noms FBB.

HERITE DE

std::exception

ENUMERATION

L'énumération Protection est utilisée par le membre protection décrit ci-dessous. L'énumération a deux valeurs :

o
ANY : un fichier existant peut avoir n'importe quel ensemble de bits de protection ;
o
EQUAL : un fichier existant doit avoir exactement l'ensemble de bits de protection spécifié lors de l'appel à Exception::protection.

CONSTRUCTEURS

o
Exception() :
Le constructeur par défaut (assigne 0 à FBB::g_errno, voir le constructeur suivant).
o
Exception(int errnoValue) :
Ce constructeur stocke la valeur errnoValue fournie dans une variable thread-local int FBB::g_errno. Avant Bobcat 4.04.00, errnoValue était uniquement stocké dans la variable globale ::errno (il l'est toujours), mais comme cette variable est également utilisée par de nombreuses autres fonctions, la valeur de errno peut avoir changé au moment où l'exception est interceptée. La variable thread_local int FBB::g_errno n'a pas cet inconvénient.
Lorsque g_errno doit être déclaré sans inclure bobcat/exception, faites : 
    namespace FBB
    {
        extern thread_local int g_errno;
    }

Les constructeurs de copie et de déplacement (ainsi que les opérateurs d'affectation) sont disponibles.

FONCTIONS MEMBRES

Tous les membres de std::exception sont disponibles, car FBB::Exception hérite de cette classe.

o
char const *what() const noexcept(true) override :
Retourne le texte qui a été inséré dans l'objet FBB::Exception.

OPERATEURS Surcharge

o
Exception &&operator<<(Exception &&in, Type const &t) :
Un gabarit de fonction implémentant l'opérateur d'insertion surchargé. Il peut être utilisé pour insérer des valeurs de n'importe quel type qui peut également être inséré dans un objet ostringstream.

MEMBRES STATIQUES

Les fonctions utilitaires suivantes peuvent être utilisées pour l'ouverture contrôlée d'objets de type flux, tels que les objets std::ofstream et std::ifstream. Ces objets de type flux doivent prendre en charge les membres open et close, similaires à ceux fournis par std::ifstream et std::ofstream.

Si le flux était déjà ouvert, il est d'abord fermé.

Si l'ouverture échoue, une exception FBB::Exception est lancée, contenant un court message indiquant que le flux nommé n'a pas pu être ouvert.

o
static StreamType factory<StreamType>(std::string const &name) :
Retourne un objet flux StreamType> ouvert, qui peut être utilisé pour construire par déplacement un objet StreamType. Par exemple, 
    auto out{ Exception::factory<ofstream>("/tmp/out") };
o
static StreamType factory<StreamType>(int errnoValue, std::string const &name) :
Retourne un objet flux StreamType> ouvert, qui peut être utilisé pour construire par déplacement un objet StreamType. Si la construction de l'objet flux échoue, alors l'exception FBB::Exception lancée assigne errnoValue à FBB::g_errno.
o
static StreamType factory<StreamType>(std::string const &name, std::ios::openmode mode) :
Retourne un objet flux StreamType> ouvert, créé en utilisant les indicateurs openmode mode, qui peut être utilisé pour construire par déplacement un objet StreamType.
o
static StreamType factory<StreamType>(int errnoValue, std::string const &name, std::ios::openmode mode) :
Retourne un objet flux StreamType> ouvert, créé en utilisant les indicateurs openmode mode, qui peut être utilisé pour construire par déplacement un objet StreamType. Si la construction de l'objet flux échoue, alors l'exception FBB::Exception lancée assigne errnoValue à FBB::g_errno.
o
static StreamType factory<StreamType>(std::string const &name, std::ios::openmode mode1, std::ios::openmode mode2) :
Retourne un objet flux StreamType> ouvert. Le flux est initialement ouvert en utilisant mode1. Si cela échoue, mode2 est utilisé. Si les deux méthodes d'ouverture du flux échouent, alors une exception Exception est lancée. Le flux retourné peut être utilisé pour construire par déplacement un objet StreamType. Ce membre peut être utilisé pour ouvrir un std::fstream qui peut ou non exister déjà pour la lecture et l'écriture. Par exemple, 
    auto out{ Exception::factory<fstream>("/tmp/out",
                ios::in | ios::out,
                ios::in | ios::out | ios::trunc) };
Si /tmp/out existe déjà, alors ios::in | ios::out devrait réussir. Sinon, il est créé vide pour la lecture et l'écriture, en utilisant ios::in | ios::out | ios::trunc.
o
static StreamType factory<StreamType>(int errnoValue, std::string const &name, std::ios::openmode mode1, std::ios::openmode mode2) :
Retourne un objet flux StreamType> ouvert. Le flux est initialement ouvert en utilisant mode1. Si cela échoue, mode2 est utilisé. Si les deux méthodes d'ouverture du flux échouent, alors une exception Exception est lancée, assignant errnoValue à FBB::g_errno.
o
static void open(int errnoValue, StreamType &stream, std::string const &name, std::ios::openmode mode) :
Ouvre l'objet flux, en utilisant son membre open, passant mode à open. Si l'ouverture du flux échoue, alors l'exception lancée FBB::Exception assigne errnoValue à FBB::g_errno.
o
static void open(StreamType &stream, std::string const &name) :
Ouvre l'objet flux, en utilisant son membre open par défaut.

o
static size_t protection(std::string const &path, size_t protect, Protection type = EQUAL):
Retourne les bits de protection (cf. open(2)) de path. Le protect paramètre est utilisé pour spécifier les bits de protection demandés. Cette valeur est généralement spécifiée sous forme octale. Si la valeur spécifiée dépasse 0777, une exception est lancée. Le troisième paramètre n'est utilisé qu'en combinaison avec des fichiers déjà existants. S'il est spécifié comme ANY , les bits de permission réels du fichier ne sont pas comparés avec protect; s'il est spécifié comme EQUAL , les bits de permission du fichier doivent être identiques à protect, ou une exception est lancée. Si path n'existe pas encore, un fichier path avec les permissions protect est créé. Ce membre retourne path's bits de permission.
Si path est créé par protection, alors l'ouverture d'un flux pour path ne change pas path's protection.

MANIPULATEUR

Le manipulateur suivant (qui n'est pas une partie de la FBB::Exception, classe, mais est défini dans le FBB espace de noms) peut être inséré dans l'objet FBB::Exception :

o
FBB::errnodescr:
Le texte descriptif associé à la valeur errno courante est inséré dans l'objet FBB::Exception (il peut aussi être utilisé pour insérer le texte descriptif dans un objet std::ostream ). Aucun texte n'est inséré si errno est égal à zéro. Ce manipulateur est sûr pour les threads (mais errno peut être modifié lorsque errno contient une valeur invalide).
