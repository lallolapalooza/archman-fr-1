DESCRIPTIO

N

Gère l'installation et la désinstallation des modules perl, des scripts, des pages de manuel, etc..

.

À la fois install() et uninstall() sont spécifiques à la manière dont ExtUtils::MakeMaker gère l'installation et la désinstallation des modules perl. Elles ne sont pas conçues comme des outils à usage

général.

Sur certains systèmes d'exploitation comme Win32, l'installation peut ne pas être possible avant qu'un redémarrage ait eu lieu. Cela peut avoir des conséquences variables : la suppression d'une ancienne DLL n'affecte pas les programmes utilisant la nouvelle, mais si une nouvelle DLL ne peut pas être installée correctement avant le redémarrage, alors tout ce qui en dépend doit attendre. La variable de

paquet 
$ExtUtils::Install::
MUST_REBOOT

est utilisée pour stocker cet

état.

Si cette variable est vraie, alors une telle opération a eu lieu et tout ce qui dépend de ce module ne peut pas continuer avant qu'un redémarrage ait eu

lieu.

Si cette valeur est définie mais fausse, alors

une telle opération a eu lieu, mais ne de
vrait pas affecter les opérations ultérieures.

Fonction

s

instal

l 
# formes obsolètes
install(\%from_to);
install(\%from_to, $verbose, $dry_run, $uninstall_shadows,
            $skip, $always_copy, \%result);
# forme recommandée depuis 1.47
install([
    from_to => \%from_to,
    verbose => 1,
    dry_run => 0,
    uninstall_shadows => 1,
    skip => undef,
    always_copy => 1,
    result => \%install_results,
])
;

Copie chaque arborescence de répertoires de %from_to vers sa valeur correspondante en préservant les horodatages et les

permissions.

Il y a deux clés avec une signification spéciale dans le hachage : "read" et "write". Celles-ci contiennent des fichiers packlist. Après que la copie soit terminée, install() écrira la liste des fichiers cibles dans $from_to{write}. Si $from_to{read} est fourni, le contenu de ce fichier sera fusionné dans le fichier écrit. Le fichier lu et le fichier écrit peuvent être identiques, mais sur AFS il est tout à fait probable que les gens installent vers un répertoire différent de celui où les fichiers apparaissent plus

tard.

Si $verbose est vrai, affichera chaque fichier supprimé. La valeur par défaut est faux. Cela correspond à "make install VERBINST=1". Des valeurs de $verbose allant jusqu'à 5 affichent de plus en plus de

diagnostics.

Si $dry_run est vrai, il affichera seulement ce qu'il allait faire sans le faire réellement. La valeur par défaut est

faux.

Si $uninstall_shadows est vrai, toutes les versions différentes à travers @INC seront désinstallées. Cela correspond à "make install

UNINST=1"

Depuis la version 1.37_02 install() supporte l'utilisation d'une liste de motifs pour filtrer les fichiers qui ne devraient pas être installés. Si $skip est omis ou indéfini, alors l'installation essaiera de lire la liste depuis INSTALL.SKIP dans le CWD. Ce fichier est une liste de expressions régulières et est juste comme le fichier MANIFEST.SKIP utilisé par ExtUtils::

Manifest.

Un INSTALL.SKIP de site par défaut peut être fourni en définissant la variable d'environnement EU_INSTALL_SITE_SKIPFILE, cela ne sera utilisé que quand il n'y a pas d'INSTALL.SKIP spécifique à la distribution. Si la variable d'environnement EU_INSTALL_IGNORE_SKIP est vraie, alors aucun filtrage de fichier d'installation ne sera

effectué.

Si $skip est indéfini, alors le fichier de saut sera auto-détecté et utilisé s'il est trouvé. Si $skip est une référence à un tableau, alors on suppose que le tableau contient la liste des motifs, si $skip est une valeur vraie non-référence, on suppose que c'est le nom de fichier contenant la liste des motifs, toute autre valeur de $skip est prise pour signifier qu'aucun filtrage d'installation ne devrait avoir

lieu.

Changements Depuis la Version 1.

47

Depuis la version 1.47, les ajouts suivants ont été faits à l'interface d'installation. Notez que le nouveau style d'argument et l'utilisation de le hachage %result sont

recommandés.

Le paramètre $always_copy qui, quand il est vrai, cause la mise à jour des fichiers indépendamment de leur modification, si il est défini mais faux, alors les copies ne sont faites que si les fichiers ont changé, si il est indéfini, alors la valeur de la variable d'environnement EU_INSTALL_ALWAYS_COPY est utilisée par

défaut.

Le hachage %result sera rempli avec les différentes clés/sous-hachages reflétant l'installation. Actuellement ces clés et leur structure sont

: 
install             => { $target    => $source },
install_fail        => { $target    => $source },
install_unchanged   => { $target    => $source },
install_filtered    => { $source    => $pattern },
uninstall           => { $uninstalled => $source },
uninstall_fail      => { $uninstalled => $source }
,

où $source est le chemin du fichier en cours d'installation. $target est l'endroit où il est installé, et $uninstalled est tout fichier fantôme qui est dans @INC ou $ENV{PERL5LIB} ou d'autres emplacements standard, et $pattern est le motif qui a causé qu'un fichier source soit ignoré. À l'avenir, plus de clés seront ajoutées, comme pour montrer les répertoires créés, cependant cela nécessite des changements dans d'autres modules et doit donc

attendre.

Ces clés seront remplies avant que des exceptions soient lancées s'il y a une

erreur.

Notez que toutes les mises à jour de %result sont additives, le hachage ne sera pas effacé avant utilisation, permettant ainsi l'agrégation facile des résultats d'état de nombreuses

installations.

NOUVEAU STYLE

D'ARGUMENT

S'il n'y a qu'un seul argument et que c'est une référence à un tableau, alors le tableau est supposé contenir une liste de paires clé-valeur spécifiant les options. Dans ce cas, l'option "from_to" est obligatoire. Ce style signifie que vous n'avez pas à fournir une liste cryptique d'arguments et pouvez utiliser une liste d'arguments auto-documentante plus facile à

comprendre.

C'est maintenant l'interface recommandée pour install

().

Appelle install() avec des arguments pour copier un module depuis blib/ vers l'emplacement d'installation de site par

défaut.

$fullext est le nom du module converti en répertoire (ex. Foo::Bar serait Foo/Bar). Si $fullext n'est pas spécifié, il essaiera de le lire depuis @ARGV

.

C'est principalement utile pour les scripts

d'installation.

rtoires site vs core vs vendor et la manière étrange dont le no

uninstal

l 
uninstall($packlist_file);
uninstall($packlist_file, $verbose, $dont_execute)
;

Supprime les fichiers listés dans un $packlist_file

.

Si $verbose est vrai, affichera chaque fichier supprimé. La valeur par défaut est

faux.

Si $dont_execute est vrai, il affichera seulement ce qu'il allait

faire sans le faire réellement.
La valeur par défaut est faux.

pm_to_bli

b 
pm_to_blib(\%from_to);
pm_to_blib(\%from_to, $autosplit_dir);
pm_to_blib(\%from_to, $autosplit_dir, $filter_cmd)
;

Copie chaque clé de %from_to vers sa valeur correspondante de manière efficace. Si un $autosplit_dir est fourni, tous les fichiers .pm seront autosplit dedans. Les répertoires de destination sont créés si

nécessaire.

$filter_cmd est une commande shell facultative à exécuter sur chaque fichier .pm avant la division et la copie. L'entrée est le contenu du module, la sortie le nouveau contenu du

module.

Vous pouvez définir la variable d'environnement PERL_INSTALL_ROOT, qui sera préfixée en tant que répertoire à chaque fichier (et répertoire)

installé.

Par défaut, une sortie verbeuse

est générée ; définir la var
iable d'environnement PERL_INSTA
LL_QUIET désactive cette sortie.
