NOM

ExtUtils::CBuilder - Compiler et lier du code C pour des modules Perl

SYNOPSIS

use ExtUtils::CBuilder;
my $b = ExtUtils::CBuilder->new(%options);
$obj_file = $b->compile(source => 'MyModule.c');
$lib_file = $b->link(objects => $obj_file);

DESCRIPTION

Ce module peut construire les parties C des modules Perl en invoquant les compilateurs et éditeurs de liens appropriés de manière multiplateforme. Il a été motivé par le projet "Module::Build" , mais peut être utile à d'autres fins également. Cependant, il n'est pas destiné à être une interface multiplateforme générale pour tous vos besoins de construction C. Cela aurait été un objectif beaucoup plus ambitieux !

MÉTHODES

new
Renvoie un nouvel objet "ExtUtils::CBuilder" . Un paramètre "config" vous permet de remplacer "Config.pm" pour toutes les opérations effectuées par l'objet, comme dans l'exemple suivant : 
# Utiliser un compilateur différent de celui indiqué par Config.pm
my $b = ExtUtils::CBuilder->new( config =>
                                 { ld => 'gcc' } );

Un paramètre "quiet" indique à "CBuilder" de ne pas imprimer ses commandes system() avant de les exécuter :

# Être plus silencieux que d'habitude
my $b = ExtUtils::CBuilder->new( quiet => 1 );
have_compiler
Renvoie vrai si le système actuel dispose d'un compilateur C et d'un éditeur de liens fonctionnels, faux sinon. Pour le déterminer, nous compilons et éditons réellement un exemple de bibliothèque C. L'exemple sera compilé dans le répertoire temporaire du système ou, si cela échoue pour une raison quelconque, dans le répertoire courant.
have_cplusplus
Tout comme have_compiler mais pour C++ au lieu de C.
compile
Compile un fichier source C et produit un fichier objet. Le nom du fichier objet est renvoyé. Le fichier source est spécifié dans un paramètre "source" , qui est requis ; les autres paramètres listés ci-dessous sont facultatifs.
"object_file"
Spécifie le nom du fichier de sortie à créer. Sinon, la méthode object_file() sera consultée, en lui passant le nom du fichier "source" .
"include_dirs"
Spécifie les répertoires supplémentaires dans lesquels rechercher des fichiers d'en-tête. Peut être donné sous forme de chaîne indiquant un seul répertoire, ou sous forme de référence de liste indiquant plusieurs répertoires.
"extra_compiler_flags"
Spécifie les arguments supplémentaires à passer au compilateur. Doit être donné sous forme de référence de liste contenant les arguments individuellement, ou si cela n'est pas possible, sous forme de chaîne contenant tous les arguments ensemble.
"C++"
Spécifie que le fichier source est un fichier source C++ et définit les drapeaux de compilation appropriés.

Le fonctionnement de cette méthode est également affecté par les entrées "archlibexp", "cccdlflags", "ccflags", "optimize", et "cc" dans "Config.pm".

link
Invoque l'éditeur de liens pour produire un fichier bibliothèque à partir de fichiers objets. En contexte scalaire, le nom du fichier bibliothèque est renvoyé. En contexte liste, le fichier bibliothèque et tous les fichiers temporaires créés sont renvoyés. Un paramètre requis "objects" contient le nom des fichiers objets à traiter, soit dans une chaîne (pour un fichier objet) ou une référence de liste (pour un ou plusieurs fichiers). Les paramètres suivants sont facultatifs :
lib_file
Spécifie le nom du fichier bibliothèque de sortie à créer. Sinon, la méthode lib_file() sera consultée, en lui passant le nom de la première entrée de "objects".
module_name
Spécifie le nom du module Perl qui sera créé par l'édition de liens. Sur les plateformes nécessitant une pré-édition de liens (Win32, OS/2, etc.), c'est un paramètre requis.
extra_linker_flags
Tout drapeau supplémentaire que vous souhaitez passer à l'éditeur de liens.

Sur les plateformes où need_prelink() renvoie vrai, prelink() sera appelé automatiquement.

Le fonctionnement de cette méthode est également affecté par les entrées "lddlflags", "shrpenv", et "ld" dans "Config.pm".

link_executable
Invoque l'éditeur de liens pour produire un fichier exécutable à partir de fichiers objets. En contexte scalaire, le nom du fichier exécutable est renvoyé. En contexte liste, le fichier exécutable et tous les fichiers temporaires créés sont renvoyés. Un paramètre requis "objects" contient le nom des fichiers objets à traiter, soit dans une chaîne (pour un fichier objet) ou une référence de liste (pour un ou plusieurs fichiers). Les paramètres facultatifs sont les mêmes que "link" à l'exception de
exe_file
Spécifie le nom du fichier exécutable de sortie à créer. Sinon, la méthode exe_file() sera consultée, en lui passant le nom de la première entrée de "objects".
object_file
my $object_file = $b->object_file($source_file);

Convertit le nom d'un fichier source C en le nom le plus naturel d'un fichier objet de sortie à en créer. Par exemple, sur Unix, le fichier source foo.c donnerait le fichier objet foo.o.

lib_file
my $lib_file = $b->lib_file($object_file);

Convertit le nom d'un fichier objet en le nom le plus naturel d'un fichier bibliothèque de sortie à en créer. Par exemple, sur Mac OS X le fichier objet foo.o donnerait le fichier bibliothèque foo.bundle.

exe_file
my $exe_file = $b->exe_file($object_file);

Convertit le nom d'un fichier objet en le nom le plus naturel d'un fichier exécutable à en créer. Par exemple, sur Mac OS X, le fichier objet foo.o donnerait le fichier exécutable foo, et sur Windows, cela donnerait foo.exe.

prelink
Sur certaines plateformes comme Win32, OS/2, VMS et AIX, il est nécessaire d'effectuer certaines actions avant d'invoquer l'éditeur de liens. Le module "ExtUtils::Mksymlists" fait cela, en écrivant des fichiers utilisés par l'éditeur de liens lors de la création de bibliothèques partagées pour les extensions dynamiques. Les noms de tous les fichiers écrits seront renvoyés sous forme de liste.

Plusieurs paramètres correspondent aux options ExtUtils::Mksymlists::Mksymlists() , comme suit :

 Mksymlists()   prelink()          type
-------------|-------------------|-------------------
 NAME        |  dl_name          | chaîne (requis)
 DLBASE      |  dl_base          | chaîne
 FILE        |  dl_file          | chaîne
 DL_VARS     |  dl_vars          | référence de tableau
 DL_FUNCS    |  dl_funcs         | référence de hachage
 FUNCLIST    |  dl_func_list     | référence de tableau
 IMPORTS     |  dl_imports       | référence de hachage
 VERSION     |  dl_version       | chaîne

Veuillez consulter la documentation pour "ExtUtils::Mksymlists"> pour les détails de ce que font ces paramètres.

need_prelink
Renvoie vrai sur les plateformes où prelink() doit être appelé lors de la liaison, et faux sinon.
extra_link_args_after_prelink
Renvoie la liste des arguments supplémentaires à donner à la commande de liaison ; les arguments sont les mêmes que pour prelink(), avec en plus une référence de tableau vers les résultats de prelink(); cette référence est indexée par la clé "prelink_res".

À FAIRE

Actuellement, cela n'a été testé que sur Unix et ne contient aucun du code spécifique à Windows du projet "Module::Build" . Je ferai cela ensuite.

HISTORIQUE

Ce module est issu du projet "Module::Build" , auquel ont contribué de nombreuses personnes. Notamment, Randy W. Sims a soumis beaucoup de code pour prendre en charge 3 compilateurs sur Windows et a aidé avec divers autres problèmes spécifiques à certaines plateformes. Ilya Zakharevich a apporté des correctifs pour OS/2 ; John E. Malmberg et Peter Prymmer ont fait de même pour VMS.

SUPPORT

ExtUtils::CBuilder est maintenu dans le cadre du cœur de Perl 5. Veuillez soumettre tout rapport de bogue via l'outil perlbug inclus avec Perl 5. Les rapports de bogues seront inclus dans le système de tickets de Perl 5 à l'adresse https://rt.perl.org.

Le code source de Perl 5 est disponible à l'adresse https://perl5.git.perl.org/perl.git et ExtUtils-CBuilder peut être trouvé dans le répertoire dist/ExtUtils-CBuilder du dépôt.
