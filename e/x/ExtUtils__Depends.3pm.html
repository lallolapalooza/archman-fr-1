ExtUtils::Depends - Construire facilement des extensions XS qui dépendent

d'autres extensions XS

SYN

OP
SIS

use ExtUtils::Depends; $package = new ExtUtils::Depends ('pkg::name', 'base::package') # définir les drapeaux et les bibliothèques pour compiler et lier le module $package->set_inc("-I/opt/blahblah"); $package->set_libs("-lmylib"); # ajouter un fichier .c et un fichier .xs à compiler $package->add_c('code.c'); $package->add_xs('module-code.xs'); # ajouter les typemaps à utiliser $package->add_typemaps("typemap"); # installer des fichiers de données et des en-têtes supplémentaires $package->install (qw/foo.h data.txt/); # enregistrer les informations $package->save_config('Files.pm'); WriteMakefile(

'NAME' => 'Mymodule', $package->get_makefile_vars() ); 
DESC
RIP
TION

Ce module tente de faciliter la construction d'extensions Perl qui utilisent des fonctions et des typemaps fournis par d'autres extensions Perl. Cela signifie qu'une extension Perl est traitée comme une bibliothèque partagée qui fournit également une interface C et XS en

plus de l'interface Perl.

Cela fonctionne tant que l'extension de base (ou « productrice ») est chargée avec

le

drapeau "RTLD_GLOBAL" (généralement fait avec une

fonction 
sub dl_load_flags
{0x01}

dans le fichier .pm principal) si vous devez utiliser des fonctions définies dans le module. Cette extension « productrice » devra également indiquer à ExtUtils::MakeMaker les fonctions spécifiques à exporter, avec des arguments à "WriteMakefile" comme

: 
FUNCLIST => [qw(nom_fonction)],
DL_FUNCS => { 'Extension::Nom' => [] }
,

Le schéma de fonctionnement de base consiste à collecter des informations sur un module dans l'instance, puis à stocker ces données dans la bibliothèque Perl où elles pourront être récupérées ultérieurement. L'objet peut également reformater ces informations en structures de données requises par la fonction WriteMakefile d'ExtUtils::

MakeMaker.

Pour savoir comment faire en sorte que votre module s'intègre dans ce schéma, voir « hashref = ExtUtils::Depends::load (name) »

.

Lors de la création d'un nouvel objet Depends, vous lui donnez un nom, qui est le nom du module que vous construisez. Vous pouvez également spécifier les noms des modules dont ce module dépend. Ces dépendances seront chargées automatiquement, et leurs typemaps, fichiers d'en-tête, etc. seront fusionnés avec les éléments de votre nouvel objet. Lorsque vous enregistrez les données de votre objet, la liste des dépendances est enregistrée avec lui, de sorte qu'un autre module dépendant du vôtre n'ait pas besoin de savoir exactement de quels modules le vôtre

dépend.

Par exemple

: 
Gtk2 dépend de Glib
Gnome2::Canvas dépend de Gtk2
ExtUtils::Depends->new ('Gnome2::Canvas', 'Gtk2');
   cette commande amène automatiquement tout ce qui est nécessaire
   pour Glib, puisque Gtk2 en
dépend.

Lorsque les informations de configuration sont enregistrées, elles incluent également une méthode de classe appelée "Inline", héritable par votre module. Cela vous permet de dire simplement en haut de votre module

: 
package Mymod;
use parent 'Mymod::Install::Files'; # pour hériter de la méthode
'Inline'

Et les utilisateurs de "Mymod" qui souhaitent écrire du code en ligne (avec Inline) pourront simplement écrire

: 
use Inline with =>
'Mymod';

Et tous les fichiers d'en-tête, définitions et bibliothèques nécessaires seront ajoutés pour

eux.

Le module "Mymod::Install::Files" implémentera également une méthode "deps", qui renverra une liste de tous les modules dont "Mymod" dépend - vous n'aurez normalement pas besoin de l'utiliser

: 
require Mymod::Install
::Files; @deps = Mymod:
:Install::Files->deps;
