ExtUtils::Typemaps(3perl) Guide de référence des programmeurs Perl ExtUtils::Typemaps(3perl)

NOM

ExtUtils::Typemaps - Lire/Modifier/Écrire des fichiers typemap Perl/XS

RÉSUMÉ

# lire/créer un fichier
my $typemap = ExtUtils::Typemaps->new(file => 'typemap');
# ou créer un typemap en mémoire
# $typemap = ExtUtils::Typemaps->new();
# ou créer un typemap en mémoire en analysant une chaîne
# $typemap = ExtUtils::Typemaps->new(string => $sometypemap);
# ajouter une correspondance
$typemap->add_typemap(ctype => 'NV', xstype => 'T_NV');
$typemap->add_inputmap(
   xstype => 'T_NV', code => '$var = ($type)SvNV($arg);'
);
$typemap->add_outputmap(
   xstype => 'T_NV', code => 'sv_setnv($arg, (NV)$var);'
);
$typemap->add_string(string => $typemapstring);
                                         # sera analysé et fusionné
# supprimer une correspondance (de même pour remove_typemap et remove_outputmap...)
$typemap->remove_inputmap(xstype => 'SomeType');
# enregistrer un typemap dans un fichier
$typemap->write(file => 'anotherfile.map');
# fusionner l'autre typemap dans celui-ci
$typemap->merge(typemap => $another_typemap);

DESCRIPTION

Ce module peut lire, modifier, créer et écrire des fichiers typemap Perl XS. Si vous ne savez pas ce qu'est un typemap, consultez les manuels perlxstut et perlxs.

Le module n'est pas entièrement sûr pour un aller-retour : par exemple, il supprime actuellement tous les commentaires. Cependant, l'ordre des entrées dans les cartes est préservé.

Nous vérifions les entrées en double dans le typemap, mais nous ne vérifions pas les entrées "TYPEMAP" manquantes pour les entrées "INPUTMAP" ou "OUTPUTMAP" car celles-ci peuvent être masquées dans un autre typemap.

MÉTHODES

new

Renvoie un nouvel objet typemap. Prend un paramètre optionnel "file" . S'il est défini, le fichier donné sera lu. Si le fichier n'existe pas, un typemap vide est renvoyé.

Alternativement, si le paramètre "string" est fourni, la chaîne fournie sera analysée à la place d'un fichier.

file

Obtient/définit le fichier vers lequel le typemap est écrit lorsque la méthode "write" est appelée.

add_typemap

Ajoute une entrée "TYPEMAP" au typemap.

Arguments nommés requis : le "ctype" (par ex. "ctype => 'double'") et le "xstype" (par ex. "xstype => 'T_NV'").

Arguments nommés optionnels : "replace => 1" force la suppression/remplacement des entrées "TYPEMAP" existantes de même "ctype". "skip => 1" déclenche une logique "premier arrivé, premier servi" par laquelle les nouvelles entrées qui entrent en conflit avec des entrées existantes sont silencieusement ignorées.

En alternative à l'utilisation des paramètres nommés, vous pouvez passer un objet "ExtUtils::Typemaps::Type" en premier argument, dont une copie sera ajoutée au typemap. Dans ce cas, seuls les paramètres nommés "replace" ou "skip" peuvent être utilisés après l'objet. Exemple :

$map->add_typemap($type_obj, replace => 1);

add_inputmap

Ajoute une entrée "INPUT" au typemap.

Arguments nommés requis : le "xstype" (par ex. "xstype => 'T_NV'") et le "code" à y associer pour l'entrée.

Arguments nommés optionnels : "replace => 1" force la suppression/remplacement des entrées "INPUT" existantes de même "xstype". "skip => 1" déclenche une logique "premier arrivé, premier servi" par laquelle les nouvelles entrées qui entrent en conflit avec des entrées existantes sont silencieusement ignorées.

En alternative à l'utilisation des paramètres nommés, vous pouvez passer un objet "ExtUtils::Typemaps::InputMap" en premier argument, dont une copie sera ajoutée au typemap. Dans ce cas, seuls les paramètres nommés "replace" ou "skip" peuvent être utilisés après l'objet. Exemple :

$map->add_inputmap($type_obj, replace => 1);

add_outputmap

Ajoute une entrée "OUTPUT" au typemap. Fonctionne exactement comme "add_inputmap".

add_string

Analyse une chaîne en tant que typemap et la fusionne dans l'objet typemap.

Argument nommé requis : "string" pour spécifier la chaîne à analyser.

remove_typemap

Supprime une entrée "TYPEMAP" du typemap.

Argument nommé requis : "ctype" pour spécifier l'entrée à supprimer du typemap.

Alternativement, vous pouvez passer un seul objet "ExtUtils::Typemaps::Type" .

remove_inputmap

Supprime une entrée "INPUT" du typemap.

Argument nommé requis : "xstype" pour spécifier l'entrée à supprimer du typemap.

Alternativement, vous pouvez passer un seul objet "ExtUtils::Typemaps::InputMap" .

remove_outputmap

Supprime une entrée "OUTPUT" du typemap.

Argument nommé requis : "xstype" pour spécifier l'entrée à supprimer du typemap.

Alternativement, vous pouvez passer un seul objet "ExtUtils::Typemaps::OutputMap" .

get_typemap

Récupère une entrée de la section TYPEMAP du typemap.

Arguments nommés obligatoires : le "ctype" de l'entrée.

Renvoie l'objet "ExtUtils::Typemaps::Type" pour l'entrée si elle est trouvée.

get_inputmap

Récupère une entrée de la section INPUT du typemap.

Arguments nommés obligatoires : le "xstype" de l'entrée ou le "ctype" du typemap qui peut être utilisé pour trouver le "xstype". À savoir, les morceaux de code suivants sont équivalents :

my $type = $typemap->get_typemap(ctype => $ctype)
my $input_map = $typemap->get_inputmap(xstype => $type->xstype);
my $input_map = $typemap->get_inputmap(ctype => $ctype);

Renvoie l'objet "ExtUtils::Typemaps::InputMap" pour l'entrée si elle est trouvée.

get_outputmap

Récupère une entrée de la section OUTPUT du typemap.

Arguments nommés obligatoires : le "xstype" de l'entrée ou le "ctype" du typemap qui peut être utilisé pour résoudre le "xstype". (Voir ci-dessus pour un exemple.)

Renvoie l'objet "ExtUtils::Typemaps::InputMap" pour l'entrée si elle est trouvée.d.

write

Écrit la typemap dans un fichier. Accepte éventuellement un "file" argument. Si fourni, la typemap sera écrite dans le fichier spécifié. Sinon, la typemap est écrite dans le nom de fichier actuellement stocké (voir "file" ci-dessus, cela par défaut au fichier à partir duquel elle a été lue le cas échéant).

as_string

Génère et retourne la forme chaîne de caractères de la typemap.

as_embedded_typemap

Génère et retourne la forme chaîne de caractères de la typemap avec le préfixe approprié autour d'elle pour une inclusion verbatim dans un fichier XS en tant que typemap intégrée. Cela retournera une chaîne comme

TYPEMAP: <<END_OF_TYPEMAP
... typemap ici (voir as_string) ...
END_OF_TYPEMAP

La méthode veille à ne pas utiliser un marqueur de fin de HERE-doc qui apparaît dans la chaîne de la typemap elle-même.

merge

Fusionne une typemap donnée dans l'objet. Notez qu'une opération de fusion échouée laisse l'objet dans un état incohérent, clonez-le donc si nécessaire.

Arguments nommés obligatoires : soit "typemap => $another_typemap_obj" ou "file => $path_to_typemap_file" mais pas les deux.

Arguments optionnels : "replace => 1" pour forcer le remplacement des entrées de typemap existantes sans avertissement ou "skip => 1" pour ignorer les entrées qui existent déjà dans la typemap.

is_empty

Retourne un booléen indiquant si cette typemap est entièrement vide.

list_mapped_ctypes

Retourne une liste des types C qui peuvent être mappés par cet objet typemap.

_get_typemap_hash

Retourne un hash associant les types C aux types XS :

{
  'char **' => 'T_PACKEDARRAY',
  'bool_t' => 'T_IV',
  'AV *' => 'T_AVREF',
  'InputStream' => 'T_IN',
  'double' => 'T_DOUBLE',
  # ...
}

C'est documenté parce que c'est utilisé par "ExtUtils::ParseXS", mais ce n'est pas destiné à un usage général. Peut être supprimé à tout moment.

_get_inputmap_hash

Retourne un hash associant les types XS (identifiants) au code INPUT correspondant :

{
  'T_CALLBACK' => '   $var = make_perl_cb_$type($arg)
',
  'T_OUT' => '    $var = IoOFP(sv_2io($arg))
',
  'T_REF_IV_PTR' => '   if (sv_isa($arg, \\"${ntype}\\")) {
  # ...
}

C'est documenté parce que c'est utilisé par "ExtUtils::ParseXS", mais ce n'est pas destiné à un usage général. Peut être supprimé à tout moment.

_get_outputmap_hash

Retourne un hash associant les types XS (identifiants) au code OUTPUT correspondant :

{
  'T_CALLBACK' => '   sv_setpvn($arg, $var.context.value().chp(),
              $var.context.value().size());
',
  'T_OUT' => '    {
          GV *gv = (GV *)sv_newmortal();
          gv_init_pvn(gv, gv_stashpvs("$Package",1),
                     "__ANONIO__",10,0);
          if ( do_open(gv, "+>&", 3, FALSE, 0, 0, $var) )
              sv_setsv(
                $arg,
                sv_bless(newRV((SV*)gv), gv_stashpv("$Package",1))
              );
          else
              $arg = &
       }
',
  # ...
}

C'est documenté parce que c'est utilisé par "ExtUtils::ParseXS", mais ce n'est pas destiné à un usage général. Peut être supprimé à tout moment.

_get_prototype_hash

Retourne un hash associant les types C de la typemap à leurs prototypes correspondants.

{
  'char **' => '$',
  'bool_t' => '$',
  'AV *' => '$',
  'InputStream' => '$',
  'double' => '$',
  # ...
}

C'est documenté parce que c'est utilisé par "ExtUtils::ParseXS", mais ce n'est pas destiné à un usage général. Peut être supprimé à tout moment.

clone

Crée et retourne un clone d'un objet typemaps complet.

Prend des paramètres nommés : Si "shallow" est vrai, le clone partagera les objets type/input/outputmap individuels réels, mais ne partagera pas leur stockage. À utiliser avec prudence. Sans "shallow", le clone sera entièrement indépendant.

tidy_type

Fonction pour (heuristiquement) canoniser un type C en termes d'espaces blancs. Fonctionne dans une certaine mesure avec les types C++. Par exemple,

$halfway_canonical_type = tidy_type('  int *  * const   *  ');

retourne 'int ** const *'.

Déplacé depuis "ExtUtils::ParseXS".
