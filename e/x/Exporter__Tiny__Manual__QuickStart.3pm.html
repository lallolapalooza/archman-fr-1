Exporter::Tiny::Manual::QuickStart(3) Documentation Perl fournie par l'utilisateur Exporter::Tiny::Manual::QuickStart(3)

NOM

Exporter::Tiny::Manual::QuickStart - le moyen le plus rapide de commencer avec Exporter::Tiny

SYNTAXE

package MyUtils;

use Exporter::Shiny qw( frobnicate );

sub frobnicate {
   ...;   # votre code ici
}

1;

Maintenant, les gens peuvent utiliser votre module comme ceci :

use MyUtils "frobnicate";

frobnicate(42);

Ou comme ceci :

use MyUtils "frobnicate" => { -as => "frob" };

frob(42);

DESCRIPTION

Voir la syntaxe. Oui, c'est aussi simple que ça.

Prochaines étapes

Exportations par défaut

Notez que le module dans la syntaxe n'exporte rien par défaut. Si les gens chargent "MyUtils" comme ceci :

use MyUtils;

Alors ils n'ont importé aucune fonction. Vous pouvez spécifier un ensemble par défaut de fonctions à exporter comme ceci :

package MyUtils;

use Exporter::Shiny qw( frobnicate );

our @EXPORT = qw( frobnicate );

sub frobnicate { ... }

1;

Ou, si vous voulez être une superstar du rock :

package MyUtils;

use Exporter::Shiny our @EXPORT = qw( frobnicate );

sub frobnicate { ... }

1;

Tags

Vous pouvez fournir des tags que les gens peuvent utiliser :

package MyUtils;

use Exporter::Shiny qw( frobnicate red green blue );

our %EXPORT_TAGS = (
   utils   => [qw/ frobnicate /],
   colours => [qw/ red green blue /],
);

sub frobnicate { ... }
sub red        { ... }
sub green      { ... }
sub blue       { ... }

1;

Et les gens peuvent maintenant importer vos fonctions comme ceci :

use MyUtils ":colours";

Ou ceci :

use MyUtils "-colours";

Ou profiter du fait que Perl quote magiquement les mots nus précédés d'un trait d'union :

use MyUtils -colours;

Deux tags sont automatiquement définis pour vous : "-default" (qui est juste le même que @EXPORT) et "-all" (qui est l'union de @EXPORT et @EXPORT_OK). Si vous ne les aimez pas, vous pouvez les remplacer :

our %EXPORT_TAGS = (
   default => \@some_other_stuff,
   all     => \@more_stuff,
);

Générateurs

L'exportation normale fonctionne en copiant une sous-routine de votre paquet dans le paquet de votre appelant. Mais il est parfois utile de générer une sous-routine *personnalisée* à insérer dans le paquet de votre appelant. C'est assez facile à faire.

package MyUtils;

use Exporter::Shiny qw( frobnicate );

sub _generate_frobnicate {
   my ( $me, $name, $args, $globals ) = @_;
   my $caller = $globals->{into};

   return sub {
       ...;  # votre code ici
   };
}

1;

Le paramètre $me ici est une chaîne contenant le nom du paquet dont on importe ; $caller est le paquet de destination ; $name est le nom de la sous-routine (dans ce cas, "frobnicate") ; et $args est un argument personnalisé pour cette fonction. (Par convention, $args est normalement un hashref.)

# Le hashref { foo => 42 } est $args ci-dessus.
#
use MyUtils "frobnicate" => { foo => 42 };

Éviter Exporter::Shiny

Exporter::Shiny est une petite couche autour d'Exporter::Tiny. Il devrait surtout faire ce que vous attendez, mais vous pourriez parfois préférer utiliser Exporter::Tiny directement.

L'exemple dans la syntaxe aurait pu être écrit comme ceci :

package MyUtils;

use parent "Exporter::Tiny";
our @EXPORT_OK = qw( frobnicate );

sub frobnicate {
   ...;   # votre code ici
}

1;

Ce qu'Exporter::Shiny fait principalement est de définir @EXPORT_OK pour vous et de configurer l'héritage de la classe de base (Exporter::Tiny).

Exporter::Shiny définit également $INC{'MyUtils.pm'} pour vous, ce qui fait généralement peu de différence, mais est utile dans certains cas limites.
