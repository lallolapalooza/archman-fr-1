EX(1) Commandes utilisateur EX(1)

NOM

ex, edit - éditeur de texte

SYNTAXE

ex [-c commande|+commande] [-r [nom_fichier]] [-s|-] [-t chaîne_tag] [-w taille] [-lLRvV] [fichier ...]

edit [-c commande|+commande] [-r [nom_fichier]] [-s|-] [-t chaîne_tag] [-w taille] [-lLRvV] [fichier ...]

DESCRIPTION

Ex est le point de départ d'une famille d'éditeurs : edit, ex et vi. Ex est un sur-ensemble de ed, avec comme extension la plus notable une facilité d'édition d'affichage. L'édition basée sur l'affichage sur terminaux CRT est au centre de vi.

Pour ceux qui n'ont pas utilisé ed, ou pour les utilisateurs occasionnels, l'éditeur edit peut être pratique. Il évite certaines des complexités de ex principalement utilisées par les programmeurs système et les personnes très familières avec ed.

Les options suivantes sont acceptées :

-c commande ou +commande
Exécute commande au début de l'édition.
-l
Démarre dans un mode spécial utile pour le langage de programmation Lisp.
-r [nom_fichier] ou -L
Lorsqu'aucun argument n'est fourni avec cette option, tous les fichiers à récupérer sont listés et l'éditeur se termine immédiatement. Si un nom_fichier est spécifié, le fichier temporaire correspondant est ouvert en mode récupération.
-R
Les fichiers sont ouverts en lecture seule lorsque cette option est donnée.
-s ou -
Mode script ; tout retour d'information pour l'édition interactive est désactivé. Les fichiers EXINIT et .exrc ne sont pas traités.
-t chaîne_tag
Lit le fichier tags, puis choisit le fichier et la position spécifiés par chaîne_tag pour l'édition.
-v
Démarre en mode visuel même s'il est appelé comme ex.
-V
Écho de l'entrée de commande sur la sortie d'erreur standard, sauf si elle provient d'un terminal.
-w taille
Spécifie la taille de la fenêtre d'édition pour le mode visuel.

Manipulation des fichiers

Ex édite normalement le contenu d'un seul fichier, dont le nom est enregistré dans le nom de fichier courant. Ex effectue toutes les actions d'édition dans un tampon (en réalité un fichier temporaire) dans lequel le texte du fichier est initialement lu. Les modifications apportées au tampon n'ont aucun effet sur le fichier en cours d'édition tant que le contenu du tampon n'est pas écrit sur le fichier avec une commande write. Après que le contenu du tampon ait été écrit, le contenu précédent du fichier écrit n'est plus accessible. Lorsqu'un fichier est édité, son nom devient le nom de fichier courant, et son contenu est lu dans le tampon.

Le fichier courant est presque toujours considéré comme édité. Cela signifie que le contenu du tampon est logiquement connecté au nom de fichier courant, de sorte qu'écrire le contenu du tampon courant sur ce fichier, même s'il existe, est une action raisonnable. Si le fichier courant n'est pas édité alors ex n'écrira normalement pas dessus s'il existe déjà.

Pour sauvegarder des blocs de texte lors de l'édition, et particulièrement lors de l'édition de plus d'un fichier, ex dispose d'un groupe de tampons nommés. Ceux-ci sont similaires au tampon normal, sauf qu'un nombre limité d'opérations leur est applicable. Les tampons ont les noms a à z.

Conditions exceptionnelles

Lorsque des erreurs surviennent, ex sonne (facultativement) la cloche du terminal et, de toute façon, affiche un diagnostic d'erreur. Si l'entrée principale provient d'un fichier, le traitement de l'éditeur s'arrête. Si un signal d'interruption est reçu, ex affiche “Interrupt” et revient à son niveau de commande. Si l'entrée principale est un fichier, alors ex se terminera lorsque cela se produira.

Si un signal de déconnexion est reçu et que le tampon a été modifié depuis sa dernière écriture, ou si le système plante, soit l'éditeur (dans le premier cas), soit le système (après redémarrage dans le second cas) tentera de préserver le tampon. La prochaine fois que l'utilisateur se connectera, il devrait pouvoir récupérer le travail qu'il était en train de faire, perdant au plus quelques lignes de modifications depuis le dernier point avant la déconnexion ou le crash de l'éditeur. Pour récupérer un fichier, on peut utiliser l'option -r. Si l'on éditait le fichier resume, alors il faut se déplacer dans le répertoire où l'on était lors du crash, en donnant la commande :

ex -r resume

Après avoir vérifié que le fichier récupéré est bien correct, on peut l'écrire pour remplacer le contenu précédent de ce fichier.

L'utilisateur recevra normalement un mail du système lui indiquant quand un fichier a été sauvegardé après un crash. La commande :

ex -r

affichera une liste des fichiers qui ont été sauvegardés pour l'utilisateur.

Modes d'édition

Ex a cinq modes distincts. Le mode principal est le mode commande. Les commandes sont saisies en mode commande lorsqu'un invite `:' est présent, et sont exécutées à chaque fois qu'une ligne complète est envoyée. En mode saisie de texte, ex collecte les lignes d'entrée et les place dans le fichier. Les commandes append, insert, et change utilisent le mode de saisie de texte. Aucun invite n'est affiché en mode saisie de texte. Ce mode est quitté en tapant un `.' seul au début d'une ligne, et le mode commande reprend.

Les trois derniers modes sont les modes open et visual, activés par les commandes du même nom, et, au sein des modes open et visual, le mode insertion de texte. Les modes open et visual permettent d'effectuer des opérations d'édition locales sur le texte du fichier. La commande open affiche une ligne à la fois sur n'importe quel terminal tandis que visual fonctionne sur les terminaux CRT avec des curseurs à positionnement aléatoire, utilisant l'écran comme une (unique) fenêtre pour les modifications d'édition de fichier. Ces modes sont décrits (uniquement) dans An Introduction to Display Editing with Vi.

Structure des commandes

La plupart des noms de commandes sont des mots anglais, et les préfixes initiaux des mots sont des abréviations acceptables. L'ambiguïté des abréviations est résolue en faveur des commandes les plus couramment utilisées.

La plupart des commandes acceptent des adresses de préfixe spécifiant les lignes du fichier sur lesquelles elles doivent avoir un effet. Les formes de ces adresses seront discutées ci-dessous. Un certain nombre de commandes peuvent également prendre un compteur final spécifiant le nombre de lignes à impliquer dans la commande. Ainsi la commande “10p” imprimera la dixième ligne dans le tampon tandis que “delete 5” supprimera cinq lignes du tampon, à partir de la ligne courante.

Certaines commandes prennent d'autres informations ou paramètres, ces informations étant toujours données après le nom de la commande.

Un certain nombre de commandes ont deux variantes distinctes. La forme variante de la commande est invoquée en plaçant un `!' immédiatement après le nom de la commande. Certaines des variantes par défaut peuvent être contrôlées par des options ; dans ce cas, le `!' sert à basculer la valeur par défaut.

Les caractères `#', `p' et `l' peuvent être placés après de nombreuses commandes (Un `p' ou `l' doit être précédé d'un espace ou d'une tabulation sauf dans le cas spécial unique `dp'). Dans ce cas, la commande abrégée par ces caractères est exécutée après l'achèvement de la commande. Puisque ex imprime normalement la nouvelle ligne courante après chaque modification, `p' est rarement nécessaire. Un nombre quelconque de caractères `+' ou `-' peut également être donné avec ces drapeaux. S'ils apparaissent, le décalage spécifié est appliqué à la valeur de la ligne courante avant l'exécution de la commande d'impression.

NAME

ex - text editor

SYNOPSIS

ex [-s] [-r] [-l] [-R] [-v] [-V] [-x] [-c line] [-t tag] [-w number] [file ...]

vi [options] [file ...]

DESCRIPTION

The ex editor is a modeless screen editor. It is the successor to the ed editor and the ancestor of the vi editor. Editing commands, starting with a colon (':') or none at all, operate on the lines of the text file currently being edited. The vi editor is invoked by running ex with the -v option, or by running vi directly.

When ex is invoked, it initializes itself and then processes the commands specified on the command line. If no command line arguments are given, the editor processes commands read from the standard input, or interactively if the standard input is a terminal. If file arguments are given, the editor processes commands read from the standard input and then begins an editing session on the first file argument. The editor considers the buffer to be modified if it is edited.

The initial value of the directory option is the current directory.

The editor prints the name of the file being edited and the size of the file, and then enters command mode. A summary of the file and its size is printed if ex is invoked with the -s (silent) option. A summary of the file and its size is printed if ex is invoked with the -s (silent) option.

The editor returns a non-zero exit status if the last operation failed. This occurs if the editor detects that the buffer has been modified since the last write command was issued, and no command line arguments were provided.

The following command line options are recognized:

-c line
Start editing at the specified line number. This is equivalent to typing the line number followed by the open command.
-l
Enable lisp mode. This is useful for editing Lisp programs.
-R
Read-only mode. This prevents accidental modifications to the file.
-r [file]
Recovery mode. If the system crashed, this option attempts to recover the file from an earlier saved state. If file is specified, it attempts to recover that specific file.
-s
Silent mode. Suppresses diagnostic messages and the summary report.
-t tag
Edit the file specified by tag. This is equivalent to typing the tag name followed by the edit command.
-V
Verbose mode. Prints the name of the editor being used and any messages generated during startup.
-v
Visual mode. This invokes the vi editor.
-x
Encryption mode. Prompts for a key to encrypt/decrypt the file.
-w number
Set the default write number for files. This is the number of characters that will be written to the file before the editor issues a warning.

If the buffer has been modified since the last write command, and no command line arguments were provided, the editor exits with a non-zero status. This is a safeguard against accidental loss of work.

More than one file may be specified. The editor processes each file in turn. If any file is not found, the editor issues a warning and proceeds to the next file.

COMMANDS

Commands are processed one per line, unless they are separated by `|'. The format of a command is:

address command [parameters] [flags]

An address selects a line in the file. If no address is given, the current line is assumed. If the command is capable of operating on a range of lines, and only one address is given, the command operates on a range of lines starting from the given address and ending at the address specified in the command's default range. If two addresses are given, they specify the start and end of the range.

The command is a single character, or a name which may be abbreviated. If the command character or name is omitted, it is assumed to be `p' (print).

Many commands accept an optional count or flags. These are described below.

Commands may be followed by comments. The comment character is the double quote: ". Any command line beginning with " is ignored. Comments beginning with " may also be placed at the ends of commands, except in cases where they could be confused as part of text (shell escapes and the substitute and map commands).

More than one command may be placed on a line by separating each pair of commands by a `|' character. However the global commands, comments, and the shell escape `!' must be the last command on a line, as they are not terminated by a `|'.

Command addressing

.
The current line. Most commands leave the current line as the last line which they affect. The default address for most commands is the current line, thus `.' is rarely used alone as an address.
n
The nth line in the editor's buffer, lines being numbered sequentially from 1.
$
The last line in the buffer.
%
An abbreviation for “1,$”, the entire buffer.
+n -n
An offset relative to the current buffer line. The forms `.+3' `+3' and `+++' are all equivalent; if the current line is line 100 they all address line 103.
/pat/ ?pat?
Scan forward and backward respectively for a line containing pat, a regular expression (as defined below). The scans normally wrap around the end of the buffer. If all that is desired is to print the next line containing pat, then the trailing / or ? may be omitted. If pat is omitted or explicitly empty, then the last regular expression specified is located. The forms \/ and \? scan using the last regular expression used in a scan; after a substitute // and ?? would scan using the substitute's regular expression.
´´ ´x
Before each non-relative motion of the current line `.', the previous current line is marked with a tag, subsequently referred to as `´´'. This makes it easy to refer or return to this previous context. Marks may also be established by the mark command, using single lower case letters x and the marked lines referred to as `´x'.

Addresses to commands consist of a series of addressing primitives, separated by `,' or `;'. Such address lists are evaluated left-to-right. When addresses are separated by `;' the current line `.' is set to the value of the previous addressing expression before the next address is interpreted. If more addresses are given than the command requires, then all but the last one or two are ignored. If the command takes two addresses, the first addressed line must precede the second in the buffer.

Null address specifications are permitted in a list of addresses, the default in this case is the current line `.'; thus `,100' is equivalent to `.,100'. It is an error to give a prefix address to a command which expects none.

Used to begin an editing session on a new file. The editor first checks to see if the buffer has been modified since the last write command was issued. If it has been, a warning is issued and the command is aborted. The command otherwise deletes the entire contents of the editor buffer, makes the named file the current file and prints the new filename. After insuring that this file is sensible (i.e., that it is not a binary file such as a directory, a block or character special file other than /dev/tty, a terminal, or a binary or executable file), the editor reads the file into its buffer.

If the read of the file completes without error, the number of lines and characters read is typed. Any null characters in the file are discarded. If none of these errors occurred, the file is considered edited. If the last line of the input file is missing the trailing newline character, it will be supplied and a complaint will be issued. Expressions régulières

Une expression régulière spécifie un ensemble de chaînes de caractères. Un membre de cet ensemble de chaînes est dit être correspondant par l'expression régulière. Ex se souvient de deux expressions régulières précédentes : l'expression régulière précédente utilisée dans une commande substitute et l'expression régulière précédente utilisée ailleurs (appelée expression régulière de balayage précédente.) L'expression régulière précédente peut toujours être référencée par une re nulle, par ex. `//' ou `??'.

Les constructions de base suivantes sont utilisées pour construire les expressions régulières en mode magic.

char
Un caractère ordinaire correspond à lui-même. Les caractères `^' au début d'une ligne, `$' à la fin d'une ligne, `*' comme n'importe quel caractère autre que le premier, `.', `\', `[', et `~' ne sont pas des caractères ordinaires et doivent être échappés (précédés) par `\' pour être traités comme tels.
^
Au début d'un motif, force la correspondance à réussir uniquement au début d'une ligne.
$
À la fin d'une expression régulière, force la correspondance à réussir uniquement à la fin de la ligne.
.
Correspond à n'importe quel caractère unique, à l'exception du caractère de nouvelle ligne.
\<
Force la correspondance à se produire uniquement au début d'une « variable » ou d'un « mot » ; c'est-à-dire, soit au début d'une ligne, soit juste avant une lettre, un chiffre ou un soulignement et après un caractère qui n'est pas l'un de ceux-ci.
\>
Similaire à `\<', mais correspondant à la fin d'une « variable » ou d'un « mot », c'est-à-dire soit la fin de la ligne, soit avant un caractère qui n'est ni une lettre, ni un chiffre, ni le caractère de soulignement.
[string]
Correspond à n'importe quel caractère (unique) de la classe définie par string. La plupart des caractères dans string se définissent eux-mêmes.
  Une paire de caractères séparés par `-' dans string définit l'ensemble des caractères qui s'ordonnent entre les limites inférieure et supérieure spécifiées, ainsi `[a-z]' en tant qu'expression régulière correspond à n'importe quelle lettre minuscule (ASCII) (unique).
  Si la séquence `[:class:]' apparaît dans string, où class est l'un de `alnum', `alpha', `blank', `cntrl', `digit', `graph', `lower'
', `print', `punct', `space', `upper', `xdigit', ou une classe de caractères spécifique à la locale, tous les caractères appartenant à la classe donnée sont appariés. Ainsi `[[:lower:]]' apparie toute lettre minuscule, possiblement incluant des caractères au-delà de la portée de ASCII.
Si le premier caractère de la chaîne est un `^' alors la construction apparie les caractères qu'elle n'apparierait pas autrement ; ainsi `[^a-z]' apparie tout sauf une lettre minuscule ASCII (et bien sûr un retour à la ligne).
Le backslash `\' est interprété comme caractère d'échappement. Pour placer un caractère `\' dans la chaîne, écrivez-le deux fois : `\\' ; pour placer n'importe lequel des caractères `^', `[', ou `-' dans la chaîne, échappez-les avec un `\' précédent.
Les caractères perdent également leur signification spéciale par leur position : `^' est un caractère ordinaire sauf s'il suit immédiatement le `[' initial, `]' est un caractère ordinaire s'il suit immédiatement le `[' initial (ou `^', s'il est présent), et `-' est un caractère ordinaire s'il est placé immédiatement après `[' ou `^', ou avant ']'.

La concaténation de deux expressions régulières apparie la plus à gauche puis la plus longue chaîne qui peut être divisée de telle sorte que la première pièce apparie la première expression régulière et la deuxième pièce apparie la

deuxième.

Une expression régulière peut être encadrée entre les séquences `\(' et `\)', qui apparie ce que l'expression encadrée

apparie.

L'une des expressions régulières (appariant un seul caractère) mentionnées ci-dessus ou une expression régulière entourée de `\(' et '\)' peut être suivie du caractère `*' pour former une expression régulière qui apparie un nombre quelconque d'occurrences adjacentes (y compris 0) des caractères appariés par l'expression régulière qu'elle

suit.

Une expression régulière d'un seul caractère ou une expression régulière entourée de `\(' et '\)' suivie de `\{m,n\}' apparie une séquence de m à n occurrences, incluses, de l'expression d'un seul caractère. Les valeurs de m et n doivent être non négatives et inférieures à 255. La forme `\{m\}' apparie exactement m occurrences, `\{m,\}' apparie au moins m

occurrences.

Le caractère `~' peut être utilisé dans une expression régulière, et apparie le texte qui a défini la partie de remplacement de la dernière commande subs

titute.

La séquence `\n' apparie le texte qui a été apparié par la n-ième sous-expression régulière encadrée entre

`\(' et `\)' précéde
mment dans l'expression.

Motifs de remplacement de

Substitute

Les métacaractères de base pour le motif de remplacement sont `&', `~', et `#' ; les deux premiers sont donnés comme `\&' et `\~' quand nomagic est défini. Chaque instance de `&' est remplacée par les caractères que l'expression régulière a appariés. Le métacaractère `~' représente, dans le motif de remplacement, le texte de définition du motif de remplacement précédent. Si le motif de remplacement entier est `#', le texte de définition du motif de remplacement précédent est

utilisé.

Les autres métaséquences possibles dans le motif de remplacement sont toujours introduites par le caractère d'échappement `\'. La séquence `\n' est remplacée par le texte apparié par la n-ième sous-expression régulière encadrée entre `\(' et `\)'. Quand des sous-expressions parentisées imbriquées sont présentes, n est déterminé en comptant les occurrences de `\(' depuis la gauche. Les séquences `\u' et `\l' font que le caractère suivant immédiatement dans la remplacement est converti en majuscule ou minuscule respectivement si ce caractère est une lettre. Les séquences `\U' et `\L' activent une telle conversion, soit jusqu'à ce que `\E' ou `\e' soit rencontré, soit jusqu'à l

a fin du motif
de remplacement.

Mark Horton a maintenu l'éditeur depuis la version 2.7, ajoutant des macros, le support de nombreux terminaux inhabituels, et d'autres fonctionnalités comme le mode d'abréviation de mots.

NOTES

Undo ne dégage jamais la condition de modification du tampon.

La commande z imprime un nombre de lignes logiques plutôt que physiques. Plus d'un écran de sortie peut en résulter si de longues lignes sont présentes.

Les erreurs d'entrée/sortie de fichier n'impriment pas de nom si l'option `-' de la ligne de commande est utilisée.

L'éditeur ne prévient pas si du texte est placé dans des tampons nommés et n'est pas utilisé avant de quitter l'éditeur.

Les caractères nuls (00) sont convertis en caractères 0200 lors de la lecture des fichiers d'entrée, et ne peuvent pas apparaître dans les fichiers résultants.

Les locales LC_COLLATE sont ignorées ; les symboles de tri `[.c.]' et les classes d'équivalence `[=c=]' dans les expressions entre crochets sont reconnus mais inutiles car `c' est restreint à un seul caractère et est le seul caractère correspondant ; les expressions de plage `[a-m]' sont toujours évaluées dans l'ordre des octets.
