NOM

exiftool - Lire et écrire des métainformations dans des fichiers

SYNOPSIS

Lecture

exiftool [OPTIONS] [-TAG...] [--TAG...] FILE...

Écriture

exiftool [OPTIONS] -TAG[+-^<]=[VALUE]... FILE...

Copie

exiftool [OPTIONS] -tagsFromFile SRCFILE [-[DSTTAG<]SRCTAG...] FILE...

Autre

exiftool [ -ver | -list[w|f|r|wf|g[NUM]|d|x|geo] ]

Pour des exemples spécifiques, voir les sections EXEMPLES ci-dessous.

Cette documentation est affichée si exiftool est exécuté sans fichier d'entrée FILE alors qu'un fichier est attendu.

DESCRIPTION

Une interface en ligne de commande pour Image::ExifTool, utilisée pour lire et écrire des métainformations dans divers types de fichiers. FILE est un ou plusieurs noms de fichiers source, noms de répertoires, ou "-" pour l'entrée standard. Les métadonnées sont lues depuis les fichiers sources et affichées sous une forme lisible sur la console (ou écrites dans des fichiers de sortie texte avec -w).

Pour écrire ou supprimer des métadonnées, les valeurs de balises sont assignées en utilisant -TAG=[VALUE], et/ou les options -geotag, -csv= ou -json= . Pour copier ou déplacer des métadonnées, la fonctionnalité -tagsFromFile est utilisée. Par défaut, les fichiers d'origine sont préservés avec "_original" ajouté à leurs noms -- assurez-vous de vérifier que les nouveaux fichiers sont OK avant d'effacer les originaux. Une fois en mode écriture, exiftool ignorera toute option spécifique à la lecture.

Remarque : Si FILE est un nom de répertoire, seuls les types de fichiers pris en charge dans le répertoire sont traités (en mode écriture, seuls les types inscriptibles sont traités). Cependant, les fichiers peuvent être spécifiés par nom, ou l'option -ext peut être utilisée pour forcer le traitement des fichiers avec n'importe quelle extension. Les fichiers cachés dans le répertoire sont également traités. L'ajout de l'option -r fait traiter les sous-répertoires de manière récursive, mais les sous-répertoires dont les noms commencent par "." sont ignorés sauf si -r. est utilisé.

OPTIONS

La casse n'est pas significative pour aucune option de ligne de commande (y compris les noms de balises et de groupes), sauf pour les options à un caractère lorsqu'une option en majuscule correspondante existe. De nombreuses options à un caractère ont des équivalents en nom long (affichés entre crochets), et certaines options ont des inverses qui sont invoquées avec un double tiret initial. Les options non reconnues sont interprétées comme des noms de balises (pour cette raison, plusieurs options à un caractère ne peuvent PAS être combinées en un seul argument). Contrairement à la pratique standard, les options peuvent apparaître après les noms de fichiers source sur la ligne de commande exiftool.

Option Détails

Opérations sur les tags

-TAG
Extraire les informations pour le tag spécifié (par ex. "-CreateDate"). Plusieurs tags peuvent être spécifiés dans une seule commande. Un nom de tag est le nom sous lequel une information est référencée. Voir Image::ExifTool::TagNames pour la documentation sur les noms de tags disponibles. Un nom de tag peut inclure des noms de groupes de tête séparés par des deux-points (par ex. "-EXIF:CreateDate", ou "-Doc1:XMP:Creator"), et chaque nom de groupe peut être préfixé par un chiffre pour spécifier le numéro de famille (par ex. "-1IPTC:City"). (Notez que les options API SavePath et SaveFormat doivent être utilisées pour que les groupes de familles 5 et 6 respectivement soient disponibles.) Utilisez l' -listg option pour lister les noms de groupes disponibles par famille.

Un nom de tag spécial "All" peut être utilisé pour indiquer toutes les métadonnées (c.-à-d. -All). C'est particulièrement utile lorsqu'un nom de groupe est spécifié pour extraire toutes les informations d'un groupe (mais attention, sauf si l' -a option est également utilisée, certains tags du groupe peuvent être supprimés par des tags du même nom dans d'autres groupes). Les caractères génériques "?" et "*" peuvent être utilisés dans un nom de tag pour correspondre respectivement à n'importe quel caractère unique et zéro ou plusieurs caractères. Ceux-ci ne peuvent pas être utilisés dans un nom de groupe, à l'exception où un nom de groupe de "*" (ou "All") peut être utilisé pour extraire toutes les instances d'un tag (comme si -a était utilisé). Notez que les arguments contenant des caractères génériques doivent être entre guillemets sur la ligne de commande de la plupart des systèmes pour empêcher le globbing du shell.

Un "#" peut être ajouté à la fin du nom de tag pour désactiver la conversion d'affichage pour un tag donné (voir l' -n option). Cela peut aussi être utilisé lors de l'écriture ou de la copie de tags.

Si aucun tag n'est spécifié, toutes les informations disponibles sont extraites (comme si "-All" avait été spécifié).

Note : Par défaut, ce sont les descriptions, et non les noms de tags, qui sont affichées lors de l'extraction des informations. Utilisez l' -s option pour voir les noms de tags à la place.

--TAG
Exclure le tag spécifié des informations extraites. Équivalent à l' -x option. Les noms de groupes et les caractères génériques sont autorisés comme décrit ci-dessus pour -TAG. Une fois exclu de la sortie, un tag ne peut pas être ré-inclus par une option ultérieure. Peut aussi être utilisé après une -tagsFromFile option pour exclure des tags d'être copiés (lors de la redirection vers un autre tag, c'est le tag source qui doit être exclu), ou pour exclure des groupes d'être supprimés lors de la suppression de toutes les informations (par ex. "-all= --exif:all" supprime tout sauf les informations EXIF). Mais notez que cela n'exclura pas les tags individuels d'une suppression de groupe (sauf si un groupe de famille 2 est spécifié, voir la note 4 ci-dessous). À la place, les tags individuels peuvent être récupérés en utilisant l' -tagsFromFile option (par ex. "-all= -tagsfromfile @ -artist").

Pour accélérer le traitement lors de la lecture de XMP, les exclusions dans les groupes XMP contournent aussi le traitement de la propriété XMP correspondante et de toute propriété qu'elle contient. Par exemple, "--xmp-crs:all" peut accélérer significativement le traitement dans les cas où un grand nombre de tags XMP-crs existent. Pour utiliser cette fonctionnalité pour contourner le traitement d'une propriété XMP spécifique, le nom de la propriété doit être utilisé à la place du nom de tag ExifTool (par ex. "--xmp-crs:dabs"). De plus, "XMP-all" peut être utilisé pour indiquer n'importe quel espace de noms XMP (par ex. "--xmp-all:dabs").

-TAG[+-^]=[VALUE]
Écrire une nouvelle valeur pour le tag spécifié (par ex. "-comment=wow"), ou supprimer le tag si aucune VALUE n'est donnée (par ex. "-comment="). "+=" et "-=" sont utilisés pour ajouter ou supprimer des entrées existantes d'une liste, ou pour décaler des valeurs de date/heure (voir Image::ExifTool::Shift.pl et les notes 6 et 7 ci-dessous pour plus de détails). "+=" peut aussi être utilisé pour incrémenter des valeurs numériques (ou décrémenter si VALUE est négative), et "-=" peut être utilisé pour supprimer ou remplacer conditionnellement un tag (voir "EXEMPLES D'ÉCRITURE" pour des exemples). "^=" est utilisé pour écrire une chaîne vide au lieu de supprimer le tag lorsque aucune VALUE n'est donnée, mais autrement il est équivalent à "=". (Notez que le caret doit être entre guillemets sur la ligne de commande Windows.)

TAG peut contenir un ou plusieurs noms de groupes de tête de familles 0, 1, 2 ou 7, préfixés par des numéros de famille optionnels, et séparés par des deux-points. Si aucun nom de groupe n'est spécifié, le tag est créé dans le groupe préféré, et mis à jour dans tout autre endroit où un tag du même nom existe déjà. Le groupe préféré dans les images JPEG et au format TIFF est le premier groupe de la liste suivante où TAG est valide : 1) EXIF, 2) IPTC, 3) XMP.

Les caractères génériques "*" et "?" peuvent être utilisés dans les noms de tags pour assigner la même valeur à plusieurs tags. Lorsqu'ils sont spécifiés avec des caractères génériques, les tags "Unsafe" ne sont pas écrits. Un nom de tag "All" est équivalent à "*" (sauf qu'il ne nécessite pas de guillemets, alors que les arguments avec des caractères génériques en nécessitent sur les systèmes avec globbing du shell), et est souvent utilisé lors de la suppression de toutes les métadonnées (c.-à-d. "-All=") ou d'un groupe entier (par ex. "-XMP-dc:All=", voir la note 4 ci-dessous). Notez que tous les groupes ne sont pas supprimables, et que le groupe "Adobe" de l'APP14 JPEG n'est pas supprimé par défaut avec "-All=" car cela pourrait affecter l'apparence de l'image. Cependant, les informations de l'espace colorimétrique sont supprimées, donc les couleurs peuvent être affectées (mais cela peut être évité en recopiant les tags définis par le raccourci ColorSpaceTags). Utilisez l' -listd option pour une liste complète des groupes supprimables, et voir la note 5 ci-dessous concernant les groupes "APP". De plus, dans une image, certains groupes peuvent être contenus dans d'autres, et ces groupes sont supprimés si le groupe contenant est supprimé :

Notes:


1) De nombreuses valeurs de balises peuvent être attribuées en une seule commande. Si deux affectations concernent la même balise, la dernière prend le dessus (sauf pour les balises de type liste, pour lesquelles les deux valeurs sont écrites).


2) En général, les balises MakerNotes sont considérées comme "Permanentes", et peuvent être modifiées mais pas créées ou supprimées individuellement. Cela évite de nombreux problèmes potentiels, y compris les problèmes de compatibilité inévitables avec les logiciels OEM qui peuvent être très inflexibles quant aux informations qu'ils s'attendent à trouver dans les notes du fabricant.


3) Les modifications apportées aux fichiers PDF par ExifTool sont réversibles (en supprimant la mise à jour avec "-PDF-update:all=") car les informations d'origine ne sont jamais réellement supprimées du fichier. Ainsi, ExifTool seul ne peut pas être utilisé pour modifier de manière sécurisée les métadonnées des fichiers PDF.


4) La spécification de "-GROUP:all=" supprime tout le groupe en bloc uniquement si un seul groupe de famille 0 ou 1 est spécifié. Sinon, toutes les balises supprimables dans le(s) groupe(s) spécifié(s) sont supprimées individuellement, et dans ce cas, il est possible d'exclure des balises individuelles d'une suppression de masse. Par exemple, "-time:all --Exif:Time:All" supprime toutes les balises Time supprimables, à l'exception de celles dans EXIF. Cette différence s'applique également si la famille 2 est spécifiée lors de la suppression de tous les groupes. Par exemple, "-2all:all=" supprime les balises individuellement, tandis que "-all:all=" supprime des blocs entiers.


5) Les noms de groupe "APP" ("APP0" à "APP15") sont utilisés pour supprimer les segments d'application JPEG qui ne sont pas associés à un autre groupe supprimable. Par exemple, la spécification de "-APP14:All=" ne supprimera PAS le segment "Adobe" APP14 car cela est accompli avec "-Adobe:All". Mais notez que ces segments APP sans nom ne peuvent pas être exclus avec "--APPxx:all" lors de la suppression de toutes les informations.


6) Lors du décalage d'une valeur, le décalage est appliqué à la valeur d'origine de la balise, remplaçant toutes les autres valeurs précédemment attribuées à la balise sur la même ligne de commande. Pour décaler une valeur de date/heure et la copier vers une autre balise dans la même opération, utilisez l'option -globalTimeShift.


7) L'opérateur "+=" ne peut pas être utilisé pour décaler une balise de date/heure de type Liste (par ex. XMP-dc:Date) car "+=" est utilisé pour ajouter des éléments à la liste. Utilisez plutôt l'option -globalTimeShift.


Fonctionnalité spéciale : les valeurs entières peuvent être spécifiées en hexadécimal avec un préfixe "0x", et les valeurs rationnelles simples peuvent être spécifiées sous forme de fractions.
-TAG<=DATFILE ou -TAG<=FMT
Définit la valeur d'une balise à partir du contenu du fichier DATFILE. Le nom du fichier peut également être donné par une chaîne FMT où %d, %f et %e représentent le répertoire, le nom de fichier et l'extension du FILE d'origine (voir l'option -w pour plus de détails). Notez que des guillemets sont requis autour de cet argument pour empêcher la redirection du shell car il contient un symbole "<". Si DATFILE/FMT n'est pas fourni, l'effet est le même que "-TAG=", et la balise est simplement supprimée. "+<=" ou "-<=" peuvent également être utilisés pour ajouter ou supprimer des entrées de liste spécifiques, ou pour décaler des valeurs de date/heure.
-tagsFromFile SRCFILE ou FMT
Copie les valeurs de balises de SRCFILE vers FILE. Les noms de balises sur la ligne de commande après cette option spécifient les balises à copier ou à exclure de la copie. Les caractères génériques sont autorisés dans ces noms de balises. Si aucune balise n'est spécifiée, alors toutes les balises possibles (voir note 1 ci-dessous) du fichier source sont copiées vers des balises de même nom dans l'emplacement préféré du fichier de sortie (équivalent à spécifier "-all"). Plus d'une option -tagsFromFile peut être utilisée pour copier des balises à partir de plusieurs fichiers.

Par défaut, cette option mettra à jour toutes les balises existantes et modifiables portant le même nom dans le FILE de sortie, mais créera de nouvelles balises uniquement dans leurs groupes préférés. Cela permet à certaines informations d'être automatiquement transférées vers le groupe approprié lors de la copie entre images de formats différents. Cependant, si un nom de groupe est spécifié pour une balise, alors l'information est écrite uniquement dans ce groupe (sauf redirection vers un autre groupe, voir ci-dessous). Si "All" est utilisé comme nom de groupe, alors la ou les balises spécifiées sont écrites dans le même groupe de famille 1 qu'elles avaient dans le fichier source (c'est-à-dire le même emplacement spécifique, comme ExifIFD ou XMP-dc). Par exemple, l'opération courante de copie de toutes les balises modifiables vers les mêmes emplacements spécifiques dans le FILE de sortie est réalisée en ajoutant "-all:all". Une famille différente peut être spécifiée en ajoutant un numéro de famille avant le nom du groupe (par ex., "-0all:all" conserve le même emplacement général, comme EXIF ou XMP).

SRCFILE peut être le même que FILE pour déplacer des informations à l'intérieur d'un seul fichier. Dans ce cas, "@" peut être utilisé pour représenter le fichier source (c'est-à-dire "-tagsFromFile @"), permettant ainsi d'utiliser cette fonctionnalité pour le traitement par lots de plusieurs fichiers. Les balises spécifiées sont alors copiées de chaque fichier tour à tour lorsqu'il est réécrit. Pour une utilisation avancée par lots, le nom du fichier source peut également être spécifié à l'aide d'une chaîne FMT dans laquelle %d, %f et %e représentent le répertoire, le nom de fichier et l'extension de FILE. (par ex., le FILE actuel serait représenté par "%d%f.%e", avec le même effet que "@"). Voir l'option -w pour des exemples de chaînes FMT.

Une puissante fonctionnalité de redirection permet de spécifier une balise de destination pour chaque balise copiée. Avec cette fonctionnalité, les informations peuvent être écrites dans une balise avec un nom ou un groupe différent. Ceci est fait en utilisant "'-DSTTAG<SRCTAG'" ou "'-SRCTAG>DSTTAG'" sur la ligne de commande après -tagsFromFile, et provoque la copie de la valeur de SRCTAG depuis SRCFILE vers DSTTAG dans FILE. N'a aucun effet sauf si SRCTAG existe dans SRCFILE. Notez que cet argument doit être mis entre guillemets pour éviter la redirection du shell, et qu'il n'y a pas de signe "=" comme lors de l'affectation de nouvelles valeurs. Les balises source et/ou destination peuvent être préfixées par un nom de groupe et/ou suffixées par "#". Les caractères génériques sont autorisés dans les noms de balises source et destination. Un nom de groupe et/ou de balise de destination de "All" ou "*" écrit dans le même groupe de famille 1 et/ou le même nom de balise que la source (mais la famille peut être spécifiée en ajoutant un nombre avant le nom du groupe, par ex., "0All" écrit dans le même groupe de famille 0 que la source). Si aucun groupe de destination n'est spécifié, l'information est écrite dans le groupe préféré. Les espaces autour de ">" ou "<" sont ignorés. Par commodité, "-tagsFromFile @" est supposé pour toutes les balises redirigées spécifiées sans option -tagsFromFile préalable. Les balises copiées peuvent également être ajoutées ou supprimées d'une liste avec des arguments de la forme "'-SRCTAG+<DSTTAG'" ou "'-SRCTAG-<DSTTAG'" (mais voir la Note 5 ci-dessous).

Une extension de la fonctionnalité de redirection permet d'utiliser des chaînes impliquant des noms de balises du côté droit du symbole "<" avec la syntaxe "'-DSTTAG<STR'", où les noms de balises dans STR sont préfixés par un symbole "$". Voir l'option -p et la section "Fonctionnalité de formatage avancé" pour plus de détails sur cette syntaxe. Les chaînes commençant par un signe "=" doivent insérer un seul espace après le "<" pour éviter toute confusion avec l'opérateur "<=" qui définit la valeur de la balise à partir du contenu d'un fichier. Un espace unique au début de la chaîne est supprimé s'il existe, mais tous les autres espaces dans la chaîne sont conservés. Voir la note 8 ci-dessous concernant l'utilisation de la fonctionnalité de redirection avec des balises de type liste, des raccourcis ou lors de l'utilisation de caractères génériques dans les noms de balises.

Voir "EXEMPLES DE COPIE" pour des exemples utilisant -tagsFromFile.

Notes:

1) Certaines balises (généralement celles qui peuvent affecter l'apparence de l'image) sont considérées comme "dangereuses" à écrire, et ne sont copiées que si elles sont spécifiées explicitement (c'est-à-dire sans caractères génériques). Voir la documentation des noms de balises pour plus de détails sur les balises "dangereuses".

2) Soyez conscient de la différence entre exclure une balise de la copie (--TAG) et supprimer une balise (-TAG=). Exclure une balise empêche sa copie vers l'image de destination, tandis que supprimer retire une balise préexistante de l'image.

3) Les informations des notes du fabricant sont copiées en bloc, elles ne sont donc pas affectées comme les autres informations par les affectations de balises ultérieures sur la ligne de commande, et les balises individuelles des notes du fabricant ne peuvent pas être exclues d'une copie de bloc. De plus, comme l'image d'aperçu référencée dans les notes du fabricant peut être assez volumineuse, elle n'est pas copiée et doit être transférée séparément si désiré.

4) L'ordre des opérations consiste à copier toutes les balises spécifiées au point de l'option -tagsFromFile dans la ligne de commande. Toute affectation de balise à droite de l'option -tagsFromFile est effectuée après la copie de toutes les balises. Par exemple, de nouvelles valeurs de balises sont définies dans l'ordre Un, Deux, Trois puis Quatre avec cette commande :

exiftool -One=1 -tagsFromFile
s.jpg -Two -Four=4 -Three d.jpg

Cela est significatif dans le cas où il existe un chevauchement entre les balises copiées et assignées, car les opérations ultérieures peuvent annuler les précédentes.

5) Le comportement normal des balises copiées diffère de celui des balises assignées pour les balises de type liste et les remplacements conditionnels, car chaque opération de copie sur une balise annule toutes les opérations précédentes. Bien que cela évite les éléments de liste en double lors de la copie de groupes de balises à partir d'un fichier contenant des informations redondantes, cela empêche également les valeurs de balises différentes d'être copiées dans la même liste lorsque c'est l'intention. Pour accumuler les valeurs de différentes opérations dans la même liste, ajoutez un "+" après le "-" initial de l'argument. Par exemple :

exiftool -tagsfromfile @ '-subject<make' '-+subject<model' ...

De même, "-+DSTTAG" doit être utilisé lors du remplacement conditionnel d'une balise pour empêcher l'annulation des conditions précédentes.

6) L'option -a (autoriser les balises en double) est toujours en vigueur lors de la copie de balises à partir de SRCFILE, mais la balise de la plus haute priorité est toujours copie en dernier, elle prend donc le dessus.

7) Les balises structurées sont copiées par défaut lors de la copie de balises. Voir l'option -struct pour plus de détails.

8) Avec la fonctionnalité de redirection, copier une balise directement (c'est-à-dire "'-DSTTAG<SRCTAG'") n'est pas la même chose que d'interpoler sa valeur à l'intérieur d'une chaîne (c'est-à-dire "'-DSTTAG<$SRCTAG'") pour les balises sources qui sont des balises de type liste, des balises raccourcies ou des noms de balises contenant des caractères génériques. Lors de la copie directe, les valeurs de chaque balise source correspondante sont copiées individuellement vers la balise de destination (comme s'il s'agissait de séparations distinctes). Cependant, lorsqu'elles sont interpolées dans une chaîne, les éléments de liste et les valeurs des balises raccourcies sont concaténés (avec un séparateur défini par l'option -sep ), et les caractères génériques ne sont pas autorisés. Une autre différence est qu'un avertissement mineur est généré si une balise n'existe pas lors de l'interpolation de sa valeur dans une chaîne (avec "$"), mais pas lors de la copie directe de la balise.

Enfin, le comportement est différent lorsqu'une balise de destination ou un groupe "All" est utilisé. Lors de la copie directe, un groupe de destination et/ou un nom de balise "All" écrit dans le même groupe de famille 1 et/ou le même nom de balise que la source. Mais lorsqu'il est interpolé dans une chaîne, l'identité des balises sources est perdue et la valeur est écrite dans tous les groupes/balises possibles. Par exemple, la forme chaîne doit être utilisée dans la commande suivante puisque l'intention est de définir la valeur de toutes les balises de date/heure existantes à partir de "CreateDate":

exiftool '-time:all<$createdate' -wm w FILE
-x TAG (-exclude)
Exclure la balise spécifiée. Il peut y avoir plusieurs options -x . Cela a le même effet que --TAG sur la ligne de commande. Voir la documentation de --TAG ci-dessus pour une description complète.

-args (-argFormat)
Afficher les informations sous la forme d'arguments exiftool, adapté à une utilisation avec l'option -@ lors de l'écriture. Peut être combiné avec l'option -G pour inclure les noms de groupes. Cette fonctionnalité peut être utilisée pour copier efficacement des balises entre des images, mais permet aux métadonnées d'être modifiées en éditant le fichier intermédiaire ("out.args" dans cet exemple) :

Par exemple, les balises FileName et Directory sont exclues dans l'exemple ci-dessus pour éviter de renommer et de déplacer le fichier de destination. Avec un double tiret en tête (--b ou --binary), les balises qui contiennent des données binaires sont supprimées de la sortie lors de la lecture.

-csv[[+]=CSVFILE]
Exporter les informations au format CSV, ou importer des informations si CSVFILE est spécifié. Lors de l'importation, le fichier CSV doit être exactement dans le même format que le fichier exporté. La première ligne du CSVFILE doit être les noms de balises ExifTool (avec des noms de groupes facultatifs) pour chaque colonne du fichier, et les valeurs doivent être séparées par des virgules. Une colonne spéciale "SourceFile" spécifie les fichiers associés à chaque ligne d'informations (et un SourceFile de "*" peut être utilisé pour définir des balises par défaut à importer pour tous les fichiers qui sont combinés avec uneny tags specified for the specific SourceFile processed). The -csvDelim option may be used to change the input/output field delimiter if something other than a comma is required.

The following examples demonstrate basic use of the -csv option:

# generate CSV file with common tags from all images in a directory
exiftool -common -csv dir > out.csv
# update metadata for all images in a directory from CSV file
exiftool -csv=a.csv dir

When importing, empty values are ignored unless the -f option is used and the API MissingTagValue is set to an empty string (in which case the tag is deleted). Also, FileName and Directory columns are ignored if they exist (ie. ExifTool will not attempt to write these tags with a CSV import), but all other columns are imported. To force a tag to be deleted, use the -f option and set the value to "-" in the CSV file (or to the MissingTagValue if this API option was used). Multiple databases may be imported in a single command.

Specific tags may be imported from the CSV database by adding -TAG options to the command, or excluded with --TAG, with exclusions taking priority. Group names and wildcards are allowed. If no tags are specified, then all except FileName and Directory are used. Tags are imported in the same order as the database entries.

When exporting a CSV file, the -g or -G option adds group names to the tag headings. If the -a option is used to allow duplicate tag names, the duplicate tags are only included in the CSV output if the column headings are unique. Adding the -G4 option ensures a unique column heading for each tag. The -b option may be added to output binary data, encoded in base64 if necessary (indicated by ASCII "base64:" as the first 7 bytes of the value). Values may also be encoded in base64 if the -charset option is used and the value contains invalid characters.

When exporting specific tags, the CSV columns are arranged in the same order as the specified tags provided the column headings exactly match the specified tag names, otherwise the columns are sorted in alphabetical order.

When importing from a CSV file, only files specified on the command line are processed. Any extra entries in the CSV file are ignored.

List-type tags are stored as simple strings in a CSV file, but the -sep option may be used to split them back into separate items when importing.

Special feature: -csv+=CSVFILE may be used to add items to existing lists. This affects only list-type tags. Also applies to the -j option.

Note that this and the -plot options are fundamentally different than all other output format options because they require information from all input files to be buffered in memory before the output is written. This may result in excessive memory usage when processing a very large number of files with a single command. Also, when used with -csv, the -w option changes to specify a complete file name with no filename formatting codes or append mode allowed, and -W may not be used. When processing a large number of files, it is recommended to either use the JSON (-j) or XML (-X) output format, or use -p to generate a fixed-column CSV file instead of using the -csv option.

-csvDelim STR
Set the delimiter for separating CSV entries for CSV file input/output via the -csv option. STR may contain "\t", "\n", "\r" and "\\" to represent TAB, LF, CR and '\' respectively. A double quote is not allowed in the delimiter. Default is ','.
-d FMT (-dateFormat)
Set the format for date/time tag values. The FMT string may contain formatting codes beginning with a percent character ("%") to represent the various components of a date/time value. ExifTool implements 3 format codes internally (see below), but other format codes are system dependent -- consult the "strftime" man page on your system for details. The default format is equivalent to "%Y:%m:%d %H:%M:%S". This option has no effect on date-only or time-only tags. Requires POSIX::strptime or Time::Piece for the inversion conversion when writing. Only one -d option may be used per command.

Additional format codes implemented internally by ExifTool:

1) %z represents the time zone in "+/-HHMM" format. Adding a colon (ie. %:z) adds a colon separator (eg. "-05:00"). If the date/time value doesn't contain a time zone then %z gives the system time zone for the specified date/time value.

2) %f represents fractional seconds, and supports an optional width to specify the number of digits after the decimal point (eg. %3f would give something like ".437"). Adding a minus sign drops the decimal point (eg. "%-3f" would give "437").

3) %s represents the number of seconds since 00:00 UTC Jan 1, 1970, taking into account the specified time zone (or system time zone if not specified).

Alternativement, une chaîne FMT peut être utilisée pour un meilleur contrôle sur le nom et le répertoire du fichier de sortie. Dans la chaîne de format, %d, %f et %e représentent le répertoire, le nom de fichier et l'extension du fichier source, et %c représente un numéro de copie qui est automatiquement incrémenté si le fichier existe déjà. %d inclut le '/' final si nécessaire, mais %e n'inclut pas le '.' initial. Par exemple :

-w dir/%f_%e.out  # écrit les fichiers dans "dir" sous le nom "FILE_EXT.out"

Les deux peuvent être utilisés (c.-à-d. -w+! ou -textOut+!) pour écraser les fichiers de sortie qui n'existaient pas avant l'exécution de la commande, et ajouter la sortie de plusieurs fichiers sources. Par exemple, pour écrire un fichier de sortie pour tous les fichiers sources dans chaque répertoire :

exiftool -filename -createdate -T -w+! %d/out.txt -r DIR

Les codes de format en majuscules %D, %F, %E et %C fournissent des alternatives légèrement différentes aux versions en minuscules. %D n'inclut pas le '/' final, %F est le nom de fichier complet incluant l'extension, %E inclut le '.' initial, et %C incrémente le compteur pour chaque fichier traité (voir ci-dessous).

1) Dans un fichier BAT Windows, le caractère "%" est représenté par "%%", donc un argument comme "%d%f.txt" est écrit comme "%%d%%f.txt".

2) Si l'argument pour -w ne contient pas de code de format valide (par ex. %f), alors il est interprété comme une extension de fichier, mais il y a trois façons différentes de créer un fichier de sortie unique à partir de plusieurs fichiers sources :

# 1. Redirection du shell
exiftool FILE1 FILE2 ... > out.txt
# 2. Avec l'option -w et un code de format de largeur nulle
exiftool -w+! %0fout.txt FILE1 FILE2 ...
# 3. Avec l'option -W (voir l'option -W ci-dessous)
exiftool -W+! out.txt FICHIER1 FICHIER2 ...

3) L'option -w change lorsqu'elle est utilisée avec un format de sortie multi-fichiers (-csv ou -plot). Avec ceux-ci, l'argument de -w est un nom de fichier complet sans codes de formatage, et la fonction d'ajout ne peut pas être utilisée.

Fonctionnalités avancées :

Une sous-chaîne du nom de fichier, du répertoire ou de l'extension d'origine peut être prise en spécifiant une largeur de champ immédiatement après le caractère '%'. Si la largeur est négative, la sous-chaîne est prise depuis la fin. La position de la sous-chaîne (caractères à ignorer au début ou à la fin de la chaîne) peut être donnée par une deuxième valeur optionnelle après un point décimal. Par exemple :

Nom de fichier d'entrée     Spécificateur de format    Nom de fichier de sortie
--------------------    -----------------------    ------------------------
Picture-123.jpg         %7f.txt                  Picture.txt
Picture-123.jpg         %-.4f.out                Picture.out
Picture-123.jpg         %7f.%-3f                 Picture.123
Picture-123a.jpg        Meta%-3.1f.txt             Meta123.txt

(Notez que les caractères spéciaux peuvent avoir une largeur supérieure à un.)

Pour %d et %D, les spécificateurs de largeur/position de champ peuvent être appliqués aux niveaux de répertoire au lieu de la position de sous-chaîne en utilisant un deux-points au lieu d'un point décimal dans le spécificateur de format. Par exemple :

Répertoire source     Format   Résultat       Notes
-----------------   ------   ----------   ------------------
pics/2012/02        %2:d     pics/2012/   prendre les 2 niveaux supérieurs
pics/2012/02        %-:1d    pics/2012/   remonter d'un niveau de répertoire
pics/2012/02        %:1d     2012/02/     ignorer le niveau supérieur
pics/2012/02        %1:1d    2012/        prendre 1 niveau après le supérieur
pics/2012/02        %-1:D    02           nom du dossier du bas
/Users/phil         %:2d     phil/        ignorer les 2 niveaux supérieurs

(Notez que le répertoire racine compte comme un niveau lorsqu'un chemin absolu est utilisé, comme dans le dernier exemple ci-dessus.)

Pour %c, ces modificateurs ont des effets différents. Si une largeur de champ est donnée, le numéro de copie est complété par des zéros jusqu'à la largeur spécifiée. Un '-' initial ajoute un tiret avant le numéro de copie, et un '+' ajoute un soulignement. Par défaut, le numéro de copie est omis pour le premier fichier du même nom, mais cela peut être changé en ajoutant un point décimal au modificateur. Par exemple :

-w A%-cZ.txt      # AZ.txt, A-1Z.txt, A-2Z.txt ...
-w B%5c.txt       # B.txt, B00001.txt, B00002.txt ...
-w C%.c.txt       # C0.txt, C1.txt, C2.txt ...
-w D%-.c.txt      # D-0.txt, D-1.txt, D-2.txt ...
-w E%-.4c.txt     # E-0000.txt, E-0001.txt, E-0002.txt ...
-w F%-.4nc.txt    # F-0001.txt, F-0002.txt, F-0003.txt ...
-w G%+c.txt       # G.txt, G_1.txt G_2.txt ...
-w H%-lc.txt      # H.txt, H-b.txt, H-c.txt ...
-w I.%.3uc.txt    # I.AAA.txt, I.AAB.txt, I.AAC.txt ...

Une fonctionnalité spéciale permet d'incrémenter le numéro de copie pour chaque fichier traité en utilisant %C (majuscule) au lieu de %c. Cela permet d'ajouter un numéro séquentiel aux noms de fichiers de sortie, même si les noms sont différents. Pour %C, un numéro de copie de zéro n'est pas omis comme c'est le cas avec %c. Un '-' initial fait réinitialiser le numéro au début de chaque nouveau répertoire (dans la structure de répertoires d'origine si les fichiers sont déplacés), et '+' n'a aucun effet. Le nombre avant le point décimal donne l'indice de départ, le nombre après le point décimal donne la largeur du champ. Pour préserver la synchronisation avec le numéro de fichier traité, par défaut le numéro de copie n'est pas incrémenté pour éviter les collisions de noms de fichiers, donc tout fichier existant du même nom provoquera une erreur. Cependant, l'utilisation d'un deux-points à la place d'un point décimal fait incrémenter le nombre pour éviter les collisions avec les fichiers existants.

Les exemples suivants montrent les noms de fichiers de sortie lorsqu'ils sont utilisés avec la commande "exiftool rose.jpg star.jpg jet.jpg ..." :

-w %C%f.txt       # 0rose.txt, 1star.txt, 2jet.txt
-w %f-%10C.txt    # rose-10.txt, star-11.txt, jet-12.txt
-w %.3C-%f.txt    # 000-rose.txt, 001-star.txt, 002-jet.txt
-w %57.4C%f.txt   # 0057rose.txt, 0058star.txt, 0059jet.txt

Tous les codes de format peuvent être modifiés par 'l' ou 'u' pour spécifier respectivement la casse inférieure ou supérieure (par exemple %le pour une extension de fichier en casse inférieure). Lorsqu'ils sont utilisés pour modifier %c ou %C, les nombres sont convertis dans une base alphabétique (voir l'exemple H ci-dessus). De plus, %c et %C peuvent être modifiés par 'n' pour compter en utilisant des nombres naturels commençant à 1, au lieu de 0 (voir l'exemple F ci-dessus).

Cette même syntaxe FMT est utilisée avec les options -o et -tagsFromFile, bien que %c et %C ne soient valides que pour les noms de fichiers de sortie.

-W[+|!] FMT (-tagOut)
Cette version améliorée de l'option -w permet de créer un fichier de sortie distinct pour chaque balise extraite. Voir la documentation de l'option -w ci-dessus pour les détails de la fonctionnalité de base. Sont énumérées ici les différences entre -W et -w :

1) Avec -W, un nouveau fichier de sortie est créé pour chaque balise extraite.

2) -W supporte quatre codes de format supplémentaires : %t, %g et %s représentent le nom de la balise, le nom du groupe et l'extension suggérée pour le fichier de sortie (basé sur le format des données), et %o représente la valeur de la balise OriginalRawFileName ou OriginalFileName du fichier d'entrée (y compris l'extension). Le code %g peut être suivi d'un seul chiffre pour spécifier le numéro de famille du groupe (par exemple %g1), sinon la famille 0 est supposée. Les spécificateurs de largeur/position/casse de sous-chaîne peuvent être utilisés avec ces codes de format de la même manière qu'avec %f et %e.

3) L'argument de -W est interprété comme un nom de fichier s'il ne contient aucun code de format. (Pour -w, ce serait une extension de fichier.) Ce changement permet de spécifier un nom de fichier simple, qui, combiné à la fonction d'ajout, fournit une méthode pour écrire les métadonnées de plusieurs fichiers sources dans un seul fichier de sortie sans avoir besoin de redirection shell. Par exemple, les paires de commandes suivantes donnent le même résultat :

# écraser le fichier texte existant
exiftool test.jpg > out.txt     # redirection shell
exiftool test.jpg -W+! out.txt  # option -W équivalente
# ajouter au fichier texte existant
exiftool test.jpg >> out.txt    # redirection shell
exiftool test.jpg -W+ out.txt   # option -W équivalente

4) L'ajout de l'option -v à -W envoie une liste des balises et des noms de fichiers de sortie à la console au lieu de donner un détail verbeux de tout le fichier. (Sauf si toutes les sorties sont ajoutées à un seul fichier pour chaque fichier source en utilisant -W+ avec un fichier de sortie FMT qui ne contient pas %t, %g, %s ou %o.)

5) Les éléments de liste individuels sont stockés dans des fichiers séparés lorsque -W est combiné avec -b, mais notez que pour que des fichiers séparés soient créés, %c ou %C doit être utilisé dans FMT pour donner des noms uniques aux fichiers.

-Wext EXT, --Wext EXT (-tagOutExt)
Cette option est utilisée pour spécifier le type de fichier(s) de sortie écrit(s) par l'option -W. Un fichier de sortie est écrit uniquement si l'extension suggérée correspond à EXT. Plusieurs options -Wext peuvent être utilisées pour écrire plus d'un type de fichier. Utilisez --Wext pour écrire tout sauf le(s) type(s) spécifié(s).
-X (-xmlFormat)
Utilise le formatage RDF/XML spécifique à ExifTool pour la sortie console. Implique l'option -a, donc les balises dupliquées sont extraites. Les options de formatage -b, -D, -H, -l, -s, -sep, -struct et -t peuvent être utilisées en combinaison avec -X pour affecter la sortie, mais notez que les options d'ID de balise (-D, -H et -t), de données binaires (-b) et de sortie structurée (-struct) ne sont pas efficaces pour la sortie courte (-s). Une autre restriction de -s est qu'une seule balise avec un groupe et un nom donnés peut apparaître dans la sortie. Notez que les options d'ID de balise (-D, -H et -t) produiront un RDF/XML non standard à moins que l'option -l ne soit également utilisée.

Par défaut, -X produit des balises aplaties, donc -struct doit être ajouté si nécessaire pour préserver les structures XMP. Les balises de type liste avec plusieurs valeurs sont formatées comme un Sac RDF, mais elles sont combinées en une seule chaîne lorsque -s ou -sep est utilisé. L'utilisation de -L change l'encodage XML de "UTF-8" à "windows-1252". D'autres réglages -charset changent l'encodage uniquement s'il existe un jeu de caractères XML standard correspondant. L'option -b provoque l'écriture des valeurs de données binaires, encodées en base64 si nécessaire. L'option -t ajoute des informations de table de balises à la sortie (voir -t pour les détails).

Note : Cette sortie N'EST PAS la même que XMP car elle utilise des noms de propriétés générés dynamiquement correspondant aux noms de balises ExifTool avec les noms de groupes ExifTool famille 1 comme espaces de noms, et non les propriétés et espaces de noms XMP standard. Pour écrire XMP à la place, utilisez l'option -o avec une extension XMP pour le fichier de sortie.

Contrôle du traitement

-a, --a (-duplicates, --duplicates)
Permet (-a) ou supprime (--a) l'extraction des noms de balises dupliqués. Par défaut, les balises dupliquées sont supprimées lors de la lecture sauf si les options -ee ou -X sont utilisées ou si l'option Duplicates est activée dans le fichier de configuration. Lors de l'écriture, cette option permet d'afficher plusieurs messages d'avertissement. Les balises dupliquées sont toujours extraites lors de la copie.
-e (--composite)
Extraire uniquement les balises existantes -- ne pas générer de balises composites.
-ee[NUM] (-extractEmbedded)
Extrait les informations des documents incorporés dans les fichiers EPS, des informations EPS incorporées et des images JPEG et Jpeg2000 dans les fichiers PDF, des images MPF incorporées dans les fichiers JPEG et MPO, des métadonnées en flux dans les vidéos AVCHD et de la resource fork des fichiers Mac OS. Implique l'option -a. Utilisez -g3 ou -G3 pour iden
tifier le document d'origine pour les informations extraites. Les documents imbriqués contenant des sous-documents sont indiqués par des tirets dans le nom de groupe famille 3. (ex. "Doc2-3" est le 3ème sous-document du 2ème document imbriqué.) Notez que cette option peut augmenter considérablement le temps de traitement, en particulier pour les fichiers PDF avec de nombreuses images imbriquées ou les vidéos avec des métadonnées de streaming.

Utilisée avec -ee, l'option -p est évaluée pour chaque document imbriqué comme s'il s'agissait d'un fichier d'entrée séparé. Cela permet, par exemple, la génération de journaux de trace GPS à partir de métadonnées horodatées dans les vidéos. Voir https://exiftool.org/geotag.html#Inverse pour des exemples.

Définir NUM sur 2 fait analyser le flux vidéo H264 dans les vidéos MP4 jusqu'à ce que le premier message Supplemental Enhancement Information (SEI) soit décodé, ou 3 pour analyser l'intégralité du flux H624 et décoder toutes les informations SEI. Pour les vidéos M2TS, une valeur de 3 fait analyser l'intégralité du fichier à la recherche de programmes non listés qui peuvent contenir des données GPS horodatées.

-ext[+] EXT, --ext EXT (-extension)
Traiter uniquement les fichiers avec (-ext) ou sans (--ext) une extension spécifiée. Il peut y avoir plusieurs options -ext et --ext . Un signe plus peut être ajouté (c.-à-d. -ext+) pour ajouter l'extension spécifiée aux fichiers normalement traités. EXT peut commencer par un point '.', qui est ignoré. La casse n'est pas significative. "*" peut être utilisé pour traiter les fichiers avec n'importe quelle extension (ou aucune), comme dans les trois derniers exemples : 
exiftool -ext JPG DIR             # traiter uniquement les fichiers JPG
exiftool --ext cr2 --ext dng DIR  # fichiers supportés sauf CR2/DNG
exiftool -ext+ txt DIR            # fichiers supportés plus TXT
exiftool -ext "*" DIR             # traiter tous les fichiers
exiftool -ext "*" --ext xml DIR   # traiter tous sauf les fichiers XML
exiftool -ext "*" --ext . DIR     # tous sauf ceux sans extension

L'utilisation de cette option présente deux principaux avantages par rapport à la spécification de "*.EXT" sur la ligne de commande : 1) Elle s'applique aux fichiers dans les sous-répertoires lorsqu'elle est combinée avec l'option -r . 2) L'option -ext est insensible à la casse, ce qui est utile lors du traitement de fichiers sur des systèmes de fichiers sensibles à la casse.

Notez que tous les fichiers spécifiés sur la ligne de commande seront traités quelle que soit leur extension, sauf si l'option -ext est utilisée.

-F[OFFSET] (-fixBase)
Corriger la base pour les décalages des notes du fabricant. Un problème courant avec certains éditeurs d'images est que les décalages dans les notes du fabricant ne sont pas correctement ajustés lorsque le fichier est modifié. Cela peut entraîner l'extraction de mauvaises valeurs pour certaines entrées des notes du fabricant lors de la lecture du fichier modifié. Cette option permet de spécifier un entier OFFSET pour ajuster le décalage de base des notes du fabricant. Si aucun OFFSET n'est donné, ExifTool fait sa meilleure estimation de la base correcte. Notez qu'exiftool corrigera automatiquement les décalages pour les images qui stockent les informations de décalage original (ex. modèles Canon plus récents). Les décalages sont corrigés de manière permanente si -F est utilisé lors de l'écriture de l'EXIF dans une image. ex.) 
exiftool -F -exif:resolutionunit=inches image.jpg
-fast[NUM]
Augmenter la vitesse d'extraction des informations. Avec -fast (ou -fast1), ExifTool ne parcourera pas la fin d'une image JPEG pour vérifier la présence d'un trailer AFCP ou PreviewImage, ni au-delà du premier commentaire dans les images GIF ou les données audio/vidéo dans les fichiers WAV/AVI pour rechercher des métadonnées supplémentaires. Ces gains de vitesse sont faibles lors de la lecture d'images directement depuis le disque, mais peuvent être substantiels si l'on transporte les images via une connexion réseau. Contourne également la validation CRC lors de l'écriture d'images PNG, ce qui peut être très lent. Pour des gains de vitesse plus substantiels, -fast2 fait également qu'exiftool évite d'extraire les informations EXIF MakerNote, et s'arrête au chunk IDAT des images PNG et à l'atome mdat des fichiers au format QuickTime (mais notez que certains fichiers peuvent stocker des métadonnées après cela). -fast3 évite d'extraire les métadonnées du fichier, et ne retourne que les tags System pseudo, mais lit toujours l'en-tête du fichier pour obtenir une estimation éclairée du FileType. -fast4 ne lit même pas l'en-tête du fichier, et ne retourne que les tags System et un FileType basé sur l'extension du fichier. -fast5 désactive également la génération des tags Composite (comme -e). N'a aucun effet lors de l'écriture.

Notez qu'un réglage -fast séparé peut être utilisé pour l'évaluation d'une condition -if , ou lors du tri des fichiers avec l'option -fileOrder . Voir les options -if et -fileOrder pour plus de détails.

-fileOrder[NUM] [-]TAG
Définir l'ordre de traitement des fichiers selon la valeur triée du tag spécifié TAG. Sans cette option, les fichiers sont traités dans l'ordre renvoyé par le système, généralement par nom de fichier, mais cela dépend du système de fichiers. Par exemple, pour traiter les fichiers par date : 
exiftool -fileOrder DateTimeOriginal DIR

Des options -fileOrder supplémentaires peuvent être ajoutées pour des clés de tri secondaires. Les nombres sont triés numériquement, et toutes les autres valeurs sont triées alphabétiquement. Les fichiers dépourvus du tag spécifié sont triés en dernier. L'ordre de tri peut être inversé en préfixant le nom du tag avec un "-" (ex. "-fileOrder -createdate"). La conversion d'affichage des valeurs triées est désactivée avec l'option -n , ou un "#" ajouté au nom du tag. Les autres options de formatage (ex. -d) n'ont aucun effet sur les valeurs triées. Notez que l'option -fileOrder peut entraîner une grande pénalité de performance car elle implique une passe de traitement initiale supplémentaire de tous les fichiers, mais cet impact peut être réduit en spécifiant un NUM pour définir efficacement le niveau -fast pour la passe initiale. Par exemple, -fileOrder4 peut être utilisé si TAG est un tag System pseudo. Si plusieurs options -fileOrder sont utilisées, l'extraction se fait au niveau -fast le plus bas. Notez que les fichiers sont triés à travers les limites de répertoires si plusieurs répertoires d'entrée sont spécifiés.

-i DIR (-ignore)
Ignorer le nom de répertoire spécifié. DIR peut être soit un nom de dossier individuel, soit un chemin complet, et est sensible à la casse. Si un chemin complet est spécifié, il doit correspondre exactement au tag Directory pour être ignoré. Utilisez plusieurs options -i pour ignorer plus d'un nom de répertoire. Une valeur spéciale DIR de "SYMLINKS" peut être spécifiée pour éviter de récurser dans les répertoires qui sont des liens symboliques lorsque l'option -r est utilisée (notez que cela ne fonctionne actuellement pas sous Windows). De même, une valeur de "HIDDEN" peut être utilisée pour ignorer les fichiers dont les noms commencent par un "." (c.-à-d. fichiers cachés sur les systèmes Unix) lors du balayage d'un répertoire.
-if[NUM] EXPR
Spécifier une condition à évaluer avant de traiter chaque FILE. EXPR est une expression logique de type Perl contenant des noms de tags préfixés par les symboles "$" . Elle est évaluée avec les tags de chaque FILE à tour de rôle, et le fichier n'est traité que si l'expression est vraie. Contrairement aux noms de variables Perl, les noms de tags ne sont pas sensibles à la casse et peuvent contenir un tiret. De plus, les noms de tags peuvent avoir des noms de groupe de tête séparés par des deux-points, et/ou un caractère "#" final pour désactiver la conversion d'affichage. L'expression $GROUP:all vaut 1 si un tag existe dans le "GROUP"spécifié, ou 0 sinon (voir la note 2 ci-dessous). Lorsque plusieurs options -if sont utilisées, toutes les conditions doivent être satisfaites pour traiter le fichier. Renvoie un code de sortie de 2 si tous les fichiers échouent à la condition. Voici quelques exemples : 
# extraire la vitesse d'obturation de toutes les images Canon dans un répertoire
exiftool -shutterspeed -if '$make eq "Canon"' dir
# ajouter une heure à toutes les images créées le ou après le 2 avril 2006
exiftool -alldates+=1 -if '$CreateDate ge "2006:04:02"' dir
# définir la valeur ISO EXIF si possible, sauf si elle est déjà définie
exiftool '-exif:iso<iso' -if 'not $exif:iso' dir
# trouver les images contenant un mot-clé spécifique (insensible à la casse)
exiftool -if '$keywords =~ /harvey/i' -filename dir

Ajouter NUM à l'option -if fait exécuter une passe de traitement séparée pour évaluer l' EXPR à un niveau -fast donné par NUM (voir la documentation de l'option -fast pour plus de détails). Sans NUM, une seule passe de traitement est effectuée au niveau spécifié par l'option -fast . Par exemple, l'utilisation de -if5 est possible si EXPR n'utilise que des tags System pseudo, et peut accélérer considérablement le traitement si suffisamment de fichiers échouent à la condition.

L'expression a accès à l'objet ExifTool courant via $self, et les fonctions spéciales suivantes sont disponibles pour permettre le court-circuitage du traitement du fichier. Les deux fonctions ont une valeur de retour de 1. La casse est significative pour les noms de fonctions.

End()    - terminer le traitement après ce fichier
EndDir() - terminer le traitement des fichiers dans le répertoire courant
           après ce fichier (non compatible avec -fileOrder)

Notes :

1) Les options -n et -b s'appliquent également aux tags utilisés dans EXPR.

2) L'option API RequestTags est automatiquement définie pour tous les tags utilisés dans la condition -if .

3) Les tags dans la chaîne sont interpolés de manière similaire à -p avant que l'expression ne soit évaluée. Dans cette interpolation, $/ est converti en un saut de ligne et $$ représente un seul symbole "$" . Ainsi, les variables Perl, si elles sont utilisées, nécessitent un double "$", et les expressions régulières se terminant par $/ doivent utiliser $$/ à la place.

4) La condition n'accède qu'aux tags du fichier en cours de traitement, sauf si l'option -fileNUM est utilisée pour lire un fichier alternatif et que le nom de groupe famille 8 correspondant est spécifié pour le tag. Voir les détails de l'option -fileNUM pour plus d'informations.

5) L'option -a (Doublons) est implicite lorsque -if est utilisé sans un NUMrapide, et les valeurs de les balises en double sont accessibles en spécifiant un nom de groupe dans l'expression (tel qu'un numéro d'instance de famille 4, ex. $Copy1:TAG, $Copy2:TAG, etc).

6) Un UserParam spécial "OK" est disponible pour tester la réussite de la commande précédente lorsque -execute a été utilisé, et peut être utilisé comme n'importe quelle autre balise dans la condition (c.-à-d. "$OK").

7) Les valeurs des balises non définies dans l'expression sont affectées par les options -f et -m sauf si l'option API UndefTags est également définie.

8) La condition échoue si une erreur Perl se produit. Cela peut se produire par exemple si une valeur non définie (ex. une balise manquante) est utilisée de manière inappropriée.

-m (-ignoreMinorErrors)
Ignorer les erreurs et avertissements mineurs. Cela permet d'écrire dans des fichiers avec des erreurs mineures et désactive certaines vérifications de validation qui pourraient entraîner des avertissements mineurs. Généralement, les erreurs/avertissements mineurs indiquent un problème qui ne devrait généralement pas entraîner de perte de métadonnées s'il est ignoré. Cependant, il existe des exceptions, ExifTool vous laisse donc le soin de prendre la décision finale. Les erreurs et avertissements mineurs sont indiqués par "[minor]" au début du message. Les avertissements qui affectent le traitement lorsqu'ils sont ignorés sont indiqués par "[Minor]" (avec un "M" majuscule). Notez que cela provoque le fait que les valeurs manquantes dans les chaînes -tagsFromFile, -p, -if et -fileNUM soient définies à une chaîne vide plutôt qu'à une valeur non définie (mais cela peut être évité pour -if en utilisant l'option API UndefTags).
-o OUTFILE ou FMT (-out)
Définir le nom du fichier ou du répertoire de sortie lors de l'écriture d'informations. Sans cette option, lorsque des balises "réelles" sont écrites, le fichier original est renommé en "FILE_original" et la sortie est écrite dans FILE. Lors de l'écriture uniquement des balises "pseudo" FileName et/ou Directory, -o provoque la copie du fichier au lieu de son déplacement, mais les répertoires spécifiés pour l'une ou l'autre de ces balises priment sur celui spécifié par l'option -o .

OUTFILE peut être "-" pour écrire sur stdout. Le nom du fichier de sortie peut également être spécifié en utilisant une chaîne FMT dans laquelle %d, %f et %e représentent le répertoire, le nom de fichier et l'extension de FILE. De plus, %c peut être utilisé pour ajouter un numéro de copie. Voir l'option -w pour des exemples de chaînes FMT .

Le fichier de sortie est considéré comme un nom de répertoire s'il existe déjà en tant que répertoire ou si le nom se termine par '/'. Les répertoires de sortie sont créés si nécessaire. Les fichiers existants ne seront pas écrasés. La combinaison de l'option -overwrite_original avec -o provoque l'effacement du fichier source original après que le fichier de sortie a été écrit avec succès.

Une caractéristique spéciale de cette option permet la création de certains types de fichiers à partir de zéro, ou avec les métadonnées d'un autre type de fichier. Les types de fichier suivants peuvent être créés en utilisant cette technique :

XMP, EXIF, EXV, MIE, ICC/ICM, VRD, DR4

Le type du fichier de sortie est déterminé par l'extension de OUTFILE (spécifié comme "-.EXT" lors de l'écriture sur stdout). Le fichier de sortie est ensuite créé à partir d'une combinaison des informations de FILE (comme si l'option -tagsFromFile était utilisée), et des valeurs de balises assignées sur la ligne de commande. Si aucun FILE n'est spécifié, le fichier de sortie peut être créé à partir de zéro en utilisant uniquement les balises assignées sur la ligne de commande.

-overwrite_original
Écraser le fichier FILE original (au lieu de le préserver en ajoutant "_original" au nom du fichier) lors de l'écriture d'informations dans une image. Attention : Cette option ne devrait être utilisée que si vous avez déjà des copies de sauvegarde séparées de vos fichiers image. L'écrasement est réalisé en renommant un fichier temporaire pour remplacer l'original. Cela supprime le fichier original et le remplace par la version éditée en une seule opération. Lorsqu'elle est combinée avec -o, cette option provoque la suppression du fichier original si le fichier de sortie a été écrit avec succès (c.-à-d. le fichier est déplacé au lieu d'être copié).
-overwrite_original_in_place
Similaire à -overwrite_original sauf qu'une étape supplémentaire est ajoutée pour permettre la préservation des attributs du fichier original. Par exemple, sur un Mac, cela provoque la préservation de la date de création du fichier original, du type, du créateur, de la couleur de l'étiquette, de l'icône, des étiquettes Finder, des autres attributs étendus et des liens physiques vers le fichier (mais notez que la resource fork de Mac OS est toujours préservée sauf si elle est spécifiquement supprimée avec "-rsrc:all="). Cela est réalisé en ouvrant le fichier original en mode mise à jour et en remplaçant ses données par une copie d'un fichier temporaire avant de supprimer le fichier temporaire. L'étape supplémentaire entraîne des performances plus lentes, l'option -overwrite_original devrait donc être utilisée à la place si ce n'est pas nécessaire.

Notez que cette option revient au comportement de l'option -overwrite_original lorsque les balises FileName et/ou Directory sont également écrites.

-P (-preserve)
Préserver la date/heure de modification du système de fichiers ("FileModifyDate") du fichier original lors de l'écriture. Notez que certains systèmes de fichiers stockent une date de création (c.-à-d. "FileCreateDate" sur les systèmes Windows et Mac ) qui n'est pas affectée par cette option. Cette date de création est préservée sur les systèmes Windows où Win32API::File et Win32::API sont disponibles quel que soit ce paramètre. Pour les autres systèmes, l'option -overwrite_original_in_place peut être utilisée si nécessaire pour préserver la date de création. L'option -P est remplacée par toute valeur écrite dans la balise FileModifyDate.
-password PASSWD
Spécifier le mot de passe pour permettre le traitement des documents PDF protégés par mot de passe. Si un mot de passe est requis mais non donné, un avertissement est émis et le document n'est pas traité. Cette option est ignorée si un mot de passe n'est pas requis.
-progress[NUM][:[TITLE]]
Afficher la progression lors du traitement des fichiers. Sans deux-points, l'option -progress ajoute un compteur de progression entre crochets après le nom de chaque fichier traité, donnant le numéro du fichier actuel et le nombre total de fichiers à traiter. Implique l'option -v0 , ce qui provoque l'affichage des noms des fichiers traités lors de l'écriture. Lorsqu'elle est combinée avec l'option -if , le compte total inclut tous les fichiers avant que la condition ne soit appliquée, mais les fichiers qui échouent à la condition n'auront pas leurs noms affichés. Si NUM est spécifié, la progression est affichée tous les NUM fichiers d'entrée.

S'il est suivi d'un deux-points (c.-à-d. -progress:), le titre de la fenêtre de la console est défini selon la chaîne TITLE spécifiée. Si aucun TITLE n'est donné, une chaîne TITLE par défaut de "ExifTool %p%%" est supposée. Dans la chaîne, %f représente le nom du fichier, %p est la progression en pourcentage, %r est la progression sous forme de ratio, %##b est une barre de progression de largeur "##" (où "##" est un entier spécifiant la largeur de la barre en caractères, ou 20 caractères par défaut si "##" est omis), et %% est un caractère %. Peut être combinée avec l'option normale -progress pour afficher également le compteur de progression dans les messages de la console. (Note : Pour que cette fonctionnalité fonctionne correctement sur Mac/Linux, stderr doit aller vers la console.)

-q (-quiet)
Traitement silencieux. Un -q supprime les messages d'information normaux, et un deuxième -q supprime également les avertissements. Les messages d'erreur ne peuvent pas être supprimés, bien que les erreurs mineures puissent être rétrogradées en avertissements avec l'option -m , qui peuvent alors être supprimées avec "-q -q".
-r[.] (-recurse)
Traiter récursivement les fichiers dans les sous-répertoires. N'a de sens que si FILE est un nom de répertoire. Les sous-répertoires dont les noms commencent par "." ne sont pas traités sauf si "." est ajouté au nom de l'option (c.-à-d. -r. ou -recurse.). Par défaut, exiftool suivra également les liens symboliques vers les répertoires si le système le prend en charge, mais cela peut être désactivé avec "-i SYMLINKS" (voir l'option -i pour plus de détails). Combinez cela avec les options -ext pour contrôler les types de fichiers traités.
-scanForXMP
Scanner tous les fichiers (même les formats non pris en charge) pour les informations XMP sauf s'ils ont déjà été trouvés. Lorsqu'elle est combinée avec l'option -fast , seuls les types de fichiers non pris en charge sont scannés. Attention : Le scan de fichiers volumineux peut prendre du temps.
-u (-unknown)
Extraire les valeurs des balises inconnues. Ajoutez un autre -u pour extraire également les informations inconnues des blocs de données binaires. Cette option s'applique aux balises avec des ID de balises numériques, et provoque la génération de noms de balises comme "Exif_0xc5d9" pour les informations inconnues. Elle n'a aucun effet sur les types d'informations qui ont des ID de balises lisibles par l'homme (tels que XMP), car les balises inconnues sont extraites automatiquement de ces formats.

Extraire les valeurs des balises inconnues ainsi que les informations inconnues de certains blocs de données binaires. C'est la même chose que deux options -u .

Définir le mode pour l'écriture/création de balises. MODE est une chaîne d'un ou plusieurs caractères de la liste ci-dessous. Le mode d'écriture par défaut est "wcg". 
w - Écrire les balises existantes
c - Créer de nouvelles balises
g - Créer de nouveaux Groupes si nécessaire

Le niveau du groupe est le niveau du Sous-Répertoire dans la structure des métadonnées. Pour XMP ou IPTC, c'est le bloc XMP/IPTC complet (le groupe de famille 0), mais pour EXIF, c'est l'IFD individuel (le groupe de famille 1).

-@ ARGFILE
Lit les arguments de la ligne de commande à partir du fichier spécifié. -stay_open FLAG
Si FLAG est 1 ou "True" (insensible à la casse), cela fait continuer à lire exiftool depuis le -@ ARGFILE même après avoir atteint la fin du fichier. Cette fonctionnalité permet aux applications appelantes de précharger exiftool, évitant ainsi la surcharge de chargement d'exiftool pour chaque commande. La procédure est la suivante :

1) Exécuter "exiftool -stay_open True -@ ARGFILE", où ARGFILE est le nom d'un fichier d'arguments existant (éventuellement vide) ou "-" pour acheminer les arguments depuis l'entrée standard.

2) Écrire les arguments de la ligne de commande d'exiftool dans ARGFILE, un argument par ligne (voir l'option -@ pour plus de détails).

3) Écrire "-execute\n" dans ARGFILE, où "\n" représente une séquence de nouvelle ligne. (Remarque : Vous devrez peut-être vider vos tampons d'écriture ici si vous utilisez une sortie tamponnée.) ExifTool exécutera alors la commande avec les arguments reçus jusqu'à ce point, enverra un message "{ready}" vers stdout lorsqu'il est terminé (sauf si l'option -q ou -T est utilisée), et continuera à essayer de lire les arguments pour la prochaine commande depuis ARGFILE. Pour faciliter la synchronisation commande/réponse, tout nombre ajouté à l'option -execute est renvoyé dans le message "{ready}". Par exemple, "-execute613" donne "{ready613}". Lorsque ce nombre est ajouté, -q ne supprime plus le message "{ready}". (Voir également les options -echo3 et -echo4 pour d'autres moyens de transmettre des signaux à votre application.)

4) Répéter les étapes 2 et 3 pour chaque commande.

5) Écrire "-stay_open\nFalse\n" (ou "-stay_open\n0\n") dans ARGFILE lorsque vous avez terminé. Cela fera qu'exiftool traitera tous les arguments restants de la ligne de commande puis quittera normalement.

True
-@

Cela fait que ARGFILE est fermé, et que NEWARGFILE est maintenu ouvert. (Sans le -stay_open ici, exiftool serait revenu à la lecture des arguments depuis ARGFILE après avoir atteint la fin de NEWARGFILE.)

Remarque : Lors de l'écriture d'arguments dans un fichier disque, il y a un délai allant jusqu'à 0,01 seconde après l'écriture de "-execute\n" avant qu'exiftool ne commence à traiter la commande. -userParam PARAM[[^]=[VAL]]
Définir un paramètre utilisateur. PARAM est un nom de paramètre utilisateur arbitraire. C'est une interface vers l'option UserParam de l'API (voir la documentation Image::ExifTool Options), et fournit une méthode pour accéder aux paramètres définis par l'utilisateur dans les arguments des options -if, -p et -fileNUM comme s'il s'agissait de n'importe quelle autre balise. Ajouter un signe dièse ("#") à PARAM (par ex. "-userParam MyTag#=yes") fait aussi que le paramètre est extrait comme une balise normale dans le groupe UserParam.
Comme pour l'option -api , la valeur du paramètre est définie à 1 si =VAL est omis, à undef si seulement VAL est omis avec "=", ou à une chaîne vide si VAL est omis avec "^=". 
exiftool -p '$test from $filename' -userparam test=Hello FILE

Fonctionnalité de mise en forme avancée

Une fonctionnalité de mise en forme avancée permet de modifier la valeur de n'importe quelle balise interpolée dans un argument -if, -p ou -fileNUM , ou une chaîne de redirection -tagsFromFile . Les noms de balises dans ces chaînes sont préfixés par un symbole "$" , et une expression Perl arbitraire peut être appliquée à la valeur de la balise en plaçant des accolades autour du nom de la balise et en insérant l'expression après le nom, séparées par un point-virgule (c.-à-d. "${TAG;EXPR}"). L'expression agit sur la valeur de la balise à travers la variable d'entrée par défaut ($_), et a accès à l'API complète d'ExifTool à travers l'objet ExifTool courant ($self) et la clé de balise ($tag). Elle peut contenir n'importe quel code Perl valide, y compris les opérations de traduction ("tr///") et de substitution ("s///"), mais notez que les accolades dans l'expression doivent être équilibrées. Si l'expression ne modifie pas $_ , la valeur originale de la balise est retournée. L'exemple ci-dessous imprime le Make de l'appareil photo avec les espaces traduits en soulignés, et les soulignés multiples consécutifs remplacés par un seul souligné :

exiftool -p '${make;tr/ /_/;s/__+/_/g}' image.jpg

Un "@" peut être ajouté après le nom de la balise pour faire agir l'expression sur des éléments de liste individuels pour les balises de type liste, simplifiant le traitement des listes. Définir $_ à undef pour supprimer un élément de la liste. Par exemple, la commande suivante retourne tous les sujets ne contenant pas la chaîne "xxx" :

exiftool -p '${subject@;$_=undef if /xxx/}' image.jpg

Une expression par défaut de "tr(/\\?*:|"<>\0)()d" est supposée si l'expression est vide (c.-à-d. "${TAG;}"). Cela supprime les caractères / \ ? * : | < > et null de la valeur imprimée. (Ces caractères sont illégaux dans les noms de fichiers Windows, donc cette fonctionnalité est utile si les valeurs de balises sont utilisées dans des noms de fichiers.)

Fonctions auxiliaires

Notez que les noms de fonctions sont sensibles à la casse.

"DateFmt"

Simplifie le reformatage des valeurs individuelles de date/heure. Cette fonction agit sur une valeur de date/heure formatée selon EXIF dans $_ et la formate selon la chaîne de format spécifiée (voir l'option -d ). Pour éviter d'essayer de reformater une valeur de date/heure déjà formatée, un "#" doit être ajouté au nom de la balise (comme dans l'exemple ci-dessous) si l'option -d est également utilisée. Par exemple :

exiftool -p '${createdate#;DateFmt("%Y-%m-%d_%H%M%S")}' a.jpg

"ShiftTime"

Décale une chaîne de date/heure formatée selon EXIF d'un montant spécifié. Commencez par un signe moins initial pour décaler vers le passé. Voir Image::ExifTool::Shift.pl pour des détails sur la syntaxe de décalage. Par exemple, pour décaler une valeur de date/heure d'un an en arrière :

exiftool -p '${createdate;ShiftTime("-1:0:0 0")}' a.jpg

"NoDups"

Supprime les éléments en double d'une liste avec un séparateur spécifié par l'option -sep . Cette fonction est la plus utile lors de la copie de balises de type liste. Par exemple, la commande suivante peut être utilisée pour supprimer les mots-clés en double :

exiftool -sep '##' '-keywords<${keywords;NoDups}' a.jpg

L'option -sep est nécessaire pour diviser la chaîne en éléments de liste individuels lors de l'écriture dans une balise de type liste.

Un argument d'option facultatif peut être défini à 1 pour faire que "NoDups" définisse $_ à undef s'il n'y avait pas de doublons, empêchant ainsi le fichier d'être réécrit inutilement :

exiftool -sep '##' '-keywords<${keywords;NoDups(1)}' a.jpg

ExifTool 12.64 ajoute une option API NoDups qui rend la fonction auxiliaire NoDups largement redondante, avec toute la fonctionnalité sauf la capacité d'éviter de réécrire le fichier s'il n'y a pas de doublons, mais avec l'avantage que les doublons peuvent être supprimés lors de l'accumulation d'éléments de liste à partir de plusieurs sources. Un équivalent aux commandes ci-dessus utilisant cette fonctionnalité serait :

exiftool -tagsfromfile @ -keywords -api nodups a.jpg

"SetTags"

Utilisé pour définir des balises dans les images extraites. Sans arguments, copie toutes les balises du fichier source vers l'image intégrée :

exiftool -p '${previewimage;SetTags}' -b a.arw > preview.jpg

Des arguments peuvent être ajoutés pour copier ou définir des balises spécifiques. Les arguments prennent exactement la même forme que ceux sur la ligne de commande lors de la copie ou de l'écriture de balises, mais sans le tiret initial. Par exemple :

exiftool -p '${previewimage;SetTags("comment=test","title<filename")}' ...

NOMS DE FICHIERS UNICODE SOUS WINDOWS

Sous Windows, les arguments de la ligne de commande sont spécifiés en utilisant la page de code actuelle et sont recodés automatiquement en page de code système. Ce recodage n'est pas fait pour les arguments dans les fichiers d'arguments ExifTool, donc par défaut les noms de fichiers dans les fichiers d'arguments utilisent la page de code système. Malheureusement, ces pages de code ne sont pas des jeux de caractères complets, donc tous les noms de fichiers ne peuvent pas être représentés.

ExifTool 9.79 et versions ultérieures permettent de spécifier l'encodage du nom de fichier avec "-charset filename=CHARSET", où "CHARSET" est le nom d'un jeu de caractères ExifTool valide, de préférence an class="Li">"UTF8" (voir l'option -charset pour la liste complète). Cela active l'utilisation des routines d'E/S large caractère de Windows, fournissant ainsi la prise en charge de la plupart des noms de fichiers Unicode (voir la note 4). Mais notez qu'il n'est pas trivial de passer des noms de fichiers correctement encodés en ligne de commande Windows (voir https://exiftool.org/faq.html#Q18 pour les détails), il est donc recommandé, si possible, de les placer dans un fichier d'arguments -@ encodé en UTF-8 et d'utiliser "-charset filename=utf8" .

Un avertissement est émis si un nom de fichier spécifié contient des caractères spéciaux et que le jeu de caractères du nom de fichier n'a pas été fourni. Cependant, l'avertissement peut être désactivé en définissant "-charset filename=""", et ExifTool peut toujours fonctionner correctement si la page de code du système correspond au jeu de caractères utilisé pour les noms de fichiers.

Lorsqu'un nom de répertoire est fourni, l'encodage du nom de fichier n'a pas besoin d'être spécifié (sauf si le nom du répertoire contient des caractères spéciaux), et ExifTool utilisera automatiquement les routines large caractère pour parcourir le répertoire.

Le jeu de caractères du nom de fichier s'applique aux arguments FILE ainsi qu'aux arguments de nom de fichier de -@, -geotag, -o, -p, -srcfile, -tagsFromFile, -csv=, -j= et -TAG<=. Cependant, il ne s'applique pas au nom de fichier de -config , qui utilise toujours le jeu de caractères du système. L'option "-charset filename=" doit précéder l'option -@ pour être efficace, mais l'ordre n'a pas d'importance pour les autres options.

Notes :

1) Les valeurs des balises FileName et Directory utilisent toujours le même encodage que les autres valeurs de balises, et sont converties vers/depuis le jeu de caractères du nom de fichier lors de l'écriture/lecture si spécifié.

2) La prise en charge de Unicode n'est pas encore implémentée pour les autres systèmes basés sur Windows comme Cygwin.

3) Voir « ÉCRITURE DE FICHIERS EN LECTURE SEULE » ci-dessous pour une note concernant l'édition de fichiers en lecture seule avec des noms Unicode.

4) Les noms de fichiers Unicode avec des paires de substitution (points de code au-dessus de U+FFFF) posent toujours problème.

ÉCRITURE DE FICHIERS EN LECTURE SEULE

En général, ExifTool peut être utilisé pour écrire des métadonnées dans des fichiers en lecture seule à condition que l'utilisateur ait la permission d'écriture dans le répertoire. Cependant, il y a trois cas où la permission d'écriture du fichier est également requise :

1) Lors de l'utilisation de l'option -overwrite_original_in_place .

2) Lors de l'écriture uniquement de balises System pseudo (ex. FileModifyDate).

3) Sur Windows, si le fichier a des caractères Unicode dans son nom, et a) l'option -overwrite_original est utilisée, ou b) la sauvegarde "_original" existe déjà.

Les fichiers cachés dans Windows se comportent comme des fichiers en lecture seule lors de la tentative d'écriture de vraies balises dans le fichier -- une erreur est générée lors de l'utilisation de -overwrite_original_in_place, sinon l'écriture devrait réussir et l'attribut caché sera supprimé. Mais l'option -if peut être utilisée pour éviter le traitement des fichiers cachés (à condition que Win32API::File soit disponible) :

exiftool -if "$fileattributes !~ /Hidden/" ...

EXEMPLES DE LECTURE

Note: Méfiez-vous lorsque vous copiez-collez ces exemples dans votre terminal ! Certains caractères tels que les guillemets simples et doubles et les tirets peuvent avoir été remplacés par des caractères similaires en apparence mais fonctionnellement différents par le formateur de texte utilisé pour afficher cette documentation. Notez également que dans le shell Windows cmd, il faut utiliser des guillemets doubles au lieu des guillemets simples utilisés dans les exemples.

"exiftool -a -u -g1 a.jpg"
Afficher toutes les méta-informations d'une image, y compris les balises en double et inconnues, triées par groupe (pour la famille 1). Pour des raisons de performance, cette commande peut ne pas extraire toutes les métadonnées disponibles. (Les métadonnées dans des documents intégrés, les métadonnées extraites par des utilitaires externes et les métadonnées nécessitant un temps de traitement excessif peuvent ne pas être extraites). Ajoutez "-ee3" et "-api RequestAll=3" à la commande pour extraire absolument tout ce qui est disponible.
"exiftool -common dir"
Afficher les méta-informations courantes pour toutes les images dans "dir". "-common" est une balise raccourci représentant les méta-informations EXIF courantes.
"exiftool -T -createdate -aperture -shutterspeed -iso dir > out.txt"
Lister les méta-informations spécifiées sous forme de colonnes délimitées par des tabulations pour toutes les images dans "dir" vers un fichier texte de sortie nommé "out.txt".
"exiftool -s -ImageSize -ExposureTime b.jpg"
Afficher les noms et valeurs des balises ImageSize et ExposureTime.
"exiftool -l -canon c.jpg d.jpg"
Afficher les informations Canon standard de deux fichiers image.
"exiftool -r -w .txt -common pictures"
Extraire récursivement les méta-informations courantes des fichiers dans le répertoire "pictures" , en écrivant la sortie texte dans des fichiers ".txt" portant les mêmes noms.
"exiftool -b -ThumbnailImage image.jpg > thumbnail.jpg"
Enregistrer l'image miniature de "image.jpg" dans un fichier appelé "thumbnail.jpg".
"exiftool -b -JpgFromRaw -w _JFR.JPG -ext NEF -r ."
Extraire récursivement l'image JPG de tous les fichiers Nikon NEF du répertoire courant, en ajoutant "_JFR.JPG" au nom des fichiers JPG de sortie.
"exiftool -a -b -W %d%f_%t%-c.%s -preview:all dir"
Extraire tous les types d'images d'aperçu (ThumbnailImage, PreviewImage, JpgFromRaw, etc.) des fichiers du répertoire "dir", en ajoutant le nom de la balise aux noms des fichiers d'image d'aperçu de sortie.
"exiftool -d '%r %a, %B %e, %Y' -DateTimeOriginal -S -s -ext jpg ."
Afficher la date/heure formatée pour tous les fichiers JPG du répertoire courant.
"exiftool -IFD1:XResolution -IFD1:YResolution image.jpg"
Extraire la résolution de l'image à partir des informations EXIF IFD1 (IFD de l'image miniature).
"exiftool '-*resolution*' image.jpg"
Extraire toutes les balises dont les noms contiennent le mot "Resolution" d'une image.
"exiftool -xmp:author:all -a image.jpg"
Extraire toutes les méta-informations XMP liées à l'auteur d'une image.
"exiftool -xmp -b a.jpg > out.xmp"
Extraire l'enregistrement de données XMP complet intact de "a.jpg" et l'écrire dans "out.xmp" en utilisant la balise spéciale "XMP" (voir les balises supplémentaires dans Image::ExifTool::TagNames).
"exiftool -p '$filename has date $dateTimeOriginal' -q -f dir"
Afficher une ligne de sortie contenant le nom du fichier et DateTimeOriginal pour chaque image dans le répertoire "dir".
"exiftool -ee3 -p '$gpslatitude, $gpslongitude, $gpstimestamp' a.m2ts"
Extraire toutes les positions GPS d'une vidéo AVCHD.
"exiftool -icc_profile -b -w icc image.jpg"
Enregistrer le profil ICC_Profile complet d'une image dans un fichier de sortie portant le même nom et une extension ".icc".
"exiftool -htmldump -w tmp/%f_%e.html t/images"
Générer des pages HTML à partir d'un dump hexadécimal des informations EXIF de toutes les images du répertoire "t/images" . Les fichiers HTML de sortie sont écrits dans le répertoire "tmp" (qui est créé s'il n'existait pas), avec des noms de la forme 'FILENAME_EXT.html'.
"exiftool -a -b -ee -embeddedimage -W Image_%.3g3.%s file.pdf"
Extraire les images JPG et JP2 intégrées d'un fichier PDF. Les images de sortie auront des noms de fichier comme "Image_#.jpg" ou "Image_#.jp2", où "#" est le numéro de document intégré ExifTool famille 3 pour l'image.

EXEMPLES D'ÉCRITURE

Notez que les guillemets sont nécessaires autour des arguments qui contiennent certains caractères spéciaux tels que ">", "<" ou n'importe quel espace blanc. Ces techniques de guillemetage dépendent du shell, mais les exemples ci-dessous fonctionneront pour la plupart des shells Unix. Cependant, avec le shell Windows cmd, il faut utiliser des guillemets doubles (ex. -Comment="Ceci est un nouveau commentaire").

"exiftool -tagsfromfile src.jpg -exif:all --subifd:all dst.jpg"
Écrire un nouveau commentaire dans une image JPG (remplace tout commentaire existant).
"exiftool -comment= -o newdir -ext jpg ."
Supprimer le commentaire de toutes les images JPG du répertoire courant, en écrivant les images modifiées dans un nouveau répertoire.
"exiftool -keywords=EXIF -keywords=editor dst.jpg"
Remplacer la liste de mots-clés existante par deux nouveaux mots-clés ("EXIF" et "editor").
"exiftool -Keywords+=word -o newfile.jpg src.jpg"
Copier une image source vers un nouveau fichier, et ajouter un mot-clé ("word") à la liste actuelle de mots-clés.
"exiftool -exposurecompensation+=-0.5 a.jpg"
Décrémenter la valeur d'ExposureCompensation de 0,5 EV. Notez que += avec une valeur négative est utilisé pour décrémenter car l'opérateur -= est utilisé pour la suppression conditionnelle (voir l'exemple suivant).
"exiftool -credit-=xxx dir"
Supprimer les informations Credit de tous les fichiers d'un répertoire où la valeur de Credit était "xxx".
"exiftool -xmp:description-de='k&hl' -E dst.jpg"
Écrire la langue alternative pour XMP:Description, en utilisant l'échappement de caractères HTML pour saisir les caractères spéciaux.
"exiftool -all= dst.jpg"
Supprimer toutes les méta-informations d'une image. Note : Vous ne devriez PAS faire cela pour les images RAW (sauf DNG) car les formats d'image RAW propriétaires contiennent souvent des informations dans les notes du fabricant qui sont nécessaires pour convertir l'image.
"exiftool -all= -comment='lonely' dst.jpg"
Supprimer toutes les méta-informations d'une image et ajouter un commentaire. (Notez que l'ordre est important : "-comment='lonely' -all=" supprimerait aussi le nouveau commentaire.)
"exiftool -all= --jfif:all dst.jpg"
Supprimer toutes les méta-informations sauf le groupe JFIF d'une image.
"exiftool -Photoshop:All= dst.jpg"
Supprimer les méta-informations Photoshop d'une image (notez que les informations Photoshop incluent aussiPTC).
"exiftool -r -XMP-crss:all= DIR"
Supprime récursivement toutes les informations XMP-crss des images d'un répertoire.
"exiftool '-ThumbnailImage<=thumb.jpg' dst.jpg"
Définit l'image miniature à partir du fichier spécifié (Note : Les guillemets sont nécessaires pour empêcher la redirection du shell).
"exiftool '-JpgFromRaw<=%d%f_JFR.JPG' -ext NEF -r ."
Écrit récursivement des images JPEG dont les noms de fichiers se terminent par "_JFR.JPG" dans la balise JpgFromRaw de fichiers de même nom avec l'extension ".NEF" dans le répertoire courant. (Ceci est l'inverse de la commande "-JpgFromRaw" de la section "EXEMPLES DE LECTURE" ci-dessus.)
"exiftool -DateTimeOriginal-='0:0:0 1:30:0' dir"
Ajuste la date/heure d'origine de toutes les images du répertoire "dir" en soustrayant une heure et 30 minutes. (Ceci est équivalent à "-DateTimeOriginal-=1.5". Voir Image::ExifTool::Shift.pl pour les détails.)
"exiftool -createdate+=3 -modifydate+=3 a.jpg b.jpg"
Ajoute 3 heures aux horodatages CreateDate et ModifyDate de deux images.
"exiftool -AllDates+=1:30 -if '$make eq "Canon"' dir"
Déplace les valeurs de DateTimeOriginal, CreateDate et ModifyDate d'une heure et 30 minutes en avant pour toutes les images Canon d'un répertoire. (La balise AllDates est fournie comme raccourci pour ces trois balises, permettant d'y accéder via une seule balise.)
"exiftool -xmp:city=Kingston image1.jpg image2.nef"
Écrit une balise dans le groupe XMP de deux images. (Sans le "xmp:", cette balise serait écrite dans le groupe IPTC puisque "City" existe dans les deux, et IPTC est préféré par défaut.)
"exiftool -LightSource-='Unknown (0)' dst.tiff"
Supprime la balise "LightSource" uniquement si elle est inconnue avec une valeur de 0.
"exiftool -whitebalance-=auto -WhiteBalance=tung dst.jpg"
Définit "WhiteBalance" sur "Tungsten" uniquement si c'était précédemment "Auto".
"exiftool -comment-= -comment='nouveau commentaire' a.jpg"
Écrit un nouveau commentaire uniquement si l'image n'en a pas déjà un.
"exiftool -o %d%f.xmp dir"
Crée des fichiers de données d'informations méta XMP pour toutes les images de "dir".
"exiftool -o test.xmp -owner=Phil -title='Fichier XMP'"
Crée un fichier de données XMP uniquement à partir des balises définies sur la ligne de commande.
"exiftool '-ICC_Profile<=%d%f.icc' image.jpg"
Écrit le profil ICC dans une image à partir d'un fichier ".icc" du même nom.
"exiftool -hierarchicalkeywords='{keyword=one,children={keyword=B}}'"
Écrit des informations XMP structurées. Voir https://exiftool.org/struct.html pour plus de détails.
"exiftool -trailer:all= image.jpg"
Supprime tout "trailer" trouvé après la fin de l'image (EOI) dans un fichier JPEG. Un certain nombre d'appareils photo numériques stockent une grande PreviewImage après l'EOI JPEG, et la taille du fichier peut être considérablement réduite en supprimant ce trailer. Voir la documentation des balises JPEG pour une liste des trailers JPEG reconnus.

EXEMPLES DE COPIE

Ces exemples démontrent la capacité de copier des valeurs de balises entre fichiers.

"exiftool -tagsFromFile src.cr2 dst.jpg"
Copie les valeurs de toutes les balises inscriptibles de "src.cr2" vers "dst.jpg", en écrivant les informations dans des balises de même nom dans les groupes préférés.
"exiftool -TagsFromFile src.jpg -all:all dst.jpg"
Copie les valeurs de toutes les balises inscriptibles de "src.jpg" vers "dst.jpg", en préservant les groupes de balises d'origine.
"exiftool -all= -tagsfromfile src.jpg -exif:all dst.jpg"
Efface toutes les informations méta du fichier "dst.jpg", puis copie les balises EXIF de "src.jpg".
"exiftool -exif:all= -tagsfromfile @ -all:all -unsafe bad.jpg"
Reconstruit toutes les informations méta EXIF à partir de zéro dans une image. Cette technique peut être utilisée dans les images JPEG pour réparer des informations EXIF corrompues qui ne pourraient pas autrement être écrites en raison d'erreurs. La balise "Unsafe" est un raccourci pour les balises EXIF non sécurisées dans les images JPEG qui ne sont normalement pas copiées. Voir la documentation des noms de balises pour plus de détails sur les balises non sécurisées.
"exiftool -Tagsfromfile a.jpg out.xmp"
Copie les informations méta de "a.jpg" vers un fichier de données XMP. Si le fichier de données XMP "out.xmp" existe déjà, il sera mis à jour avec les nouvelles informations. Sinon, le fichier de données XMP sera créé. Seuls les fichiers contenant uniquement des métadonnées peuvent être créés de cette manière (les fichiers contenant des images peuvent être modifiés mais pas créés). Voir "EXEMPLES D'ÉCRITURE" ci-dessus pour une autre technique de génération de fichiers XMP.
"exiftool -TagsFromFile a.jpg -XMP:All= -ThumbnailImage= -m b.jpg"
Copie toutes les informations méta de "a.jpg" vers "b.jpg", en supprimant toutes les informations XMP et l'image miniature de la destination.
"exiftool -TagsFromFile src.jpg -title -author=Phil dst.jpg"
Copie le titre d'une image à une autre et définit un nouveau nom d'auteur.
"exiftool -TagsFromFile a.jpg -ISO -TagsFromFile b.jpg -comment dst.jpg"
Copie l'ISO d'une image et le Commentaire d'une autre image vers une image de destination.
"exiftool -tagsfromfile src.jpg -exif:all --subifd:all dst.jpg"
Copie uniquement les informations EXIF d'une image à une autre, en excluant les balises SubIFD.
"exiftool '-FileModifyDate<DateTimeOriginal' dir"
Utilise la date d'origine des informations méta pour définir la date de modification du système de fichiers de la même image pour toutes les images d'un répertoire. (Notez que "-TagsFromFile @" est supposé si aucun autre -TagsFromFile n'est spécifié lors de la redirection d'informations comme dans cet exemple.)
"exiftool -TagsFromFile src.jpg '-xmp:all<all' dst.jpg"
Copie toutes les informations possibles de "src.jpg" et écrit au format XMP dans "dst.jpg".
"exiftool '-Description<${FileName;s/\.[^.]*$//}' dir"
Définit la Description de l'image à partir du nom du fichier après avoir supprimé l'extension. Cet exemple utilise la "fonction de formatage avancée" pour effectuer une opération de substitution afin de supprimer le dernier point et les caractères suivants du nom de fichier.
"exiftool -@ iptc2xmp.args -iptc:all= a.jpg"
Traduit les informations IPTC en XMP avec les conversions de noms de balises appropriées, et supprime les informations IPTC d'origine d'une image. Cet exemple utilise iptc2xmp.args, qui est un fichier inclus dans la distribution ExifTool qui contient les arguments nécessaires pour convertir les informations IPTC au format XMP. Sont également inclus dans la distribution xmp2iptc.args (qui effectue la conversion inverse) et quelques autres fichiers .args pour d'autres conversions entre EXIF, IPTC et XMP.
"exiftool -tagsfromfile %d%f.CR2 -r -ext JPG dir"
Réécrit récursivement toutes les images "JPG" dans "dir" avec les informations copiées des images "CR2" correspondantes dans les mêmes répertoires.
"exiftool '-keywords+<make' image.jpg"
Ajoute la marque de l'appareil photo à la liste des mots-clés.
"exiftool '-comment<ISO=$exif:iso Exposure=${shutterspeed}' dir"
Définit la balise Commentaire de toutes les images du répertoire "dir" à partir des valeurs des balises EXIF:ISO et ShutterSpeed. Le commentaire résultant sera sous la forme "ISO=100 Exposure=1/60".
"exiftool -TagsFromFile src.jpg -icc_profile dst.jpg"
Copie le profil ICC d'une image à une autre.
"exiftool -TagsFromFile src.jpg -all:all dst.mie"
Copie toutes les informations méta sous leur forme d'origine d'une image JPEG vers un fichier MIE. Le fichier MIE sera créé s'il n'existe pas. Cette technique peut être utilisée pour stocker les métadonnées d'une image afin qu'elles puissent être réinsérées dans l'image (avec la commande inverse) plus tard dans un flux de travail.
"exiftool -o dst.mie -all:all src.jpg"
Cette commande effectue exactement la même tâche que la commande ci-dessus, sauf que l'option -o n'écrira pas dans un fichier de sortie qui existe déjà.
"exiftool -b -jpgfromraw -w %d%f_%ue.jpg -execute -b -previewimage -w %d%f_%ue.jpg -execute -tagsfromfile @ -srcfile %d%f_%ue.jpg -overwrite_original -common_args --ext jpg DIR"

Ici, la ligne de commande est divisée en trois sections (séparées par des options -execute), et chacune est exécutée comme si c'était une commande séparée. L'option -common_args fait en sorte que les arguments "--ext jpg DIR" soient appliqués aux trois commandes, et l'option -srcfile permet à l'image JPG extraite d'être le fichier source pour la troisième commande (tandis que les fichiers RAW sont les fichiers source pour les deux autres commandes).

En écrivant les balises "FileName" et "Directory", les fichiers sont renommés et/ou déplacés vers de nouveaux répertoires. Ceci peut être particulièrement utile et puissant pour organiser les fichiers par date lorsqu'il est combiné avec l'option -d. De nouveaux répertoires sont créés si nécessaire, mais les fichiers existants ne seront pas écrasés. Les codes de format %d, %f et %e peuvent être utilisés dans le nouveau nom de fichier pour représenter le répertoire, le nom et l'extension du fichier d'origine, et %c peut être utilisé pour ajouter un numéro de copie si le fichier existe déjà (voir l'option -w pour les détails). ExifTool - Guide de l'utilisateur et exemples

NOM

exiftool - Lecteur et éditeur de métadonnées d'images et d'autres fichiers

SYNOPIS

exiftool [OPTIONS] FILE...
exiftool [OPTIONS] -[TAG]* FILE...
exiftool [OPTIONS] -TAG[+/-]=[VALUE] FILE...
exiftool [OPTIONS] -TAG[--]=[FILE] FILE...
exiftool -@ OPTFILE FILE...
exiftool -h | -help
exiftool -list
exiftool -ver

DESCRIPTION

ExifTool est un utilitaire de ligne de commande en Perl pour lire, écrire et éditer les métadonnées dans une large gamme de fichiers. Il prend en charge de nombreux formats de fichiers différents, y compris les formats d'images courants comme JPEG, TIFF, PNG et RAW, ainsi que les formats audio et vidéo. ExifTool peut également lire et écrire des métadonnées dans des fichiers bruts d'images.

Les métadonnées peuvent inclure des informations telles que la date et l'heure de création, les paramètres de l'appareil photo (ouverture, vitesse d'obturation, ISO), les informations GPS, les mots-clés, les titres, les descriptions, etc.

Ce guide fournit des exemples courants d'utilisation d'ExifTool pour diverses tâches.

OPTIONS

ExifTool propose une multitude d'options pour contrôler son comportement. Certaines options courantes incluent :

  • - : Lire depuis l'entrée standard (stdin)
  • -a : Afficher les balises en double
  • -c FMT : Spécifier le format pour les coordonnées GPS
  • -d FMT : Spécifier le format pour les dates
  • -debug[NUM] : Activer le débogage
  • -e : Extraire toutes les vignettes
  • -f : Activer le traitement des fichiers de sortie
  • -fast[NUM] : Optimiser la vitesse de lecture
  • -G : Afficher les numéros de groupe des balises
  • -h : Afficher l'aide
  • -if EXPR : N'écrire que si l'expression est vraie
  • -j : Sortie au format JSON
  • -k : Lire les métadonnées depuis un fichier
  • -l : Lire depuis un fichier
  • -m : Ignorer les erreurs de valeur
  • -n : Afficher les valeurs numériques brutes
  • -o OUTFILE : Spécifier le fichier de sortie
  • -p FMT : Formater la sortie
  • -q : Supprimer les messages d'avertissement
  • -r : Traiter les répertoires récursivement
  • -s : Afficher les noms courts des balises
  • -S : Afficher les noms courts des balises
  • -t : Afficher les valeurs séparées par des tabulations
  • -v[NUM] : Afficher les informations de débogage
  • -w OUTFILE : Écrire les métadonnées dans un fichier
  • -x TAG : Exclure une balise
  • -ver : Afficher la version

Pour une liste complète des options, consultez la documentation complète d'ExifTool.

NOMS DE FICHIER UNICODE WINDOWS

ExifTool prend en charge les noms de fichiers Unicode sur Windows. Pour utiliser des noms de fichiers Unicode, assurez-vous que votre console est configurée pour utiliser l'encodage UTF-8.

ÉCRITURE DE FICHIERS EN LECTURE SEULE

Par défaut, ExifTool ne modifie pas les fichiers en lecture seule. Pour forcer l'écriture sur un fichier en lecture seule, utilisez l'option -force.

EXEMPLES DE LECTURE

"exiftool a.jpg"
Afficher toutes les métadonnées d'un fichier JPEG.
"exiftool -a -G1 a.jpg"
Afficher toutes les métadonnées, y compris les balises en double, avec les numéros de groupe des balises.
"exiftool -comment -copyright=a.jpg"
Afficher uniquement les balises Commentaire et Copyright.
"exiftool -all= a.jpg"
Supprimer toutes les métadonnées d'un fichier.
"exiftool -comment= new comment a.jpg"
Modifier la balise Commentaire.
"exiftool -comment+= new comment a.jpg"
Ajouter un commentaire à la balise Commentaire existante.
"exiftool -comment-= new comment a.jpg"
Supprimer un commentaire de la balise Commentaire.
"exiftool -keywords=nature,hiking a.jpg"
Définir les mots-clés.
"exiftool -keywords+=landscape a.jpg"
Ajouter un mot-clé.
"exiftool -keywords-=nature a.jpg"
Supprimer un mot-clé.
"exiftool -createdate=2023:10:27 10:30:00 a.jpg"
Définir la date de création.
"exiftool -createdate+=1:0:0 a.jpg"
Ajouter 1 heure à la date de création.
"exiftool -shutter=1/100 a.jpg"
Définir la vitesse d'obturation.
"exiftool -exif:gpslatitude=40.7128 -exif:gpslongitude=-74.0060 a.jpg"
Définir les coordonnées GPS.
"exiftool -xmp:description='Ceci est une description' a.jpg"
Définir la description XMP.
"exiftool -thumbnailimage -b a.jpg > thumb.jpg"
Extraire la vignette dans un fichier séparé.
"exiftool -ext jpg -r ."
Parcourir récursivement les sous-répertoires et afficher les métadonnées des fichiers JPEG dans le répertoire courant.
"exiftool -ext jpg -r -json . > exif.json"
Parcourir récursivement les sous-répertoires et écrire les métadonnées des fichiers JPEG dans un fichier JSON.

EXEMPLES D'ÉCRITURE

"exiftool -comment='Ceci est un commentaire' image.jpg"
Ajouter un commentaire à un fichier image.
"exiftool -artist='Mon Nom' image.jpg"
Définir le nom de l'artiste.
"exiftool -iso=400 -aperture=f/5.6 -shutter=1/125 image.jpg"
Définir plusieurs paramètres de caméra.
"exiftool -gpslatitude=40.7128 -gpslongitude=-74.0060 -gpsaltitude=10 image.jpg"
Ajouter des informations de géolocalisation GPS.
"exiftool -keywords+=soleil -keywords+=plage image.jpg"
Ajouter plusieurs mots-clés.
"exiftool -createdate=2023:10:27 10:30:00 -createtime=10:30:00 image.jpg"
Définir la date et l'heure de création.
"exiftool -rating=5 image.jpg"
Définir la note.
"exiftool -usercomment='Un autre commentaire' image.jpg"
Ajouter un commentaire utilisateur.
"exiftool -all= image.jpg"
Supprimer toutes les métadonnées du fichier.
"exiftool -gps:all= image.jpg"
Supprimer toutes les métadonnées GPS.
"exiftool -xmp:description= image.jpg"
Supprimer la description XMP.
"exiftool -ext jpg -all= -createdate=2023:10:27 -comment='Traitement par lot' *.jpg"
Appliquer des modifications à tous les fichiers JPEG du répertoire courant.

EXEMPLES DE COPIE

Utilisez l'option -o pour copier des fichiers tout en appliquant des modifications aux métadonnées.

"exiftool -o new.jpg -comment='Nouveau commentaire' old.jpg"
Copier old.jpg vers new.jpg avec un commentaire modifié.
"exiftool -o . -tagsFromFile @ -all:all *.jpg"
Copier toutes les métadonnées de tous les fichiers JPEG dans le répertoire courant vers eux-mêmes (sans modification). Ceci est utile pour convertir les métadonnées dans le même format, par exemple pour s'assurer que les métadonnées sont valides pour le format de fichier.
"exiftool -o . '-Directory<DateTimeOriginal' -d %Y/%m/%d dir"
Copier tous les fichiers du répertoire dir dans une hiérarchie de répertoires basée sur l'année, le mois et le jour de DateTimeOriginal. eg) Cette commande copierait le fichier dir/image.jpg avec un DateTimeOriginal de 2005:10:12 16:05:56 vers 2005/10/12/image.jpg.
"exiftool -o . '-filename<%f_${model;}.%e' dir"
Copier tous les fichiers dans dir en ajoutant le nom du modèle de l'appareil photo au nom du fichier. Le point-virgule après le nom de la balise à l'intérieur des accolades supprime les caractères invalides dans les noms de fichiers Windows de la valeur de la balise (voir la "Fonction de formatage avancé" pour une explication).

EXEMPLES DE RENOMMAGE

Utilisez l'option -filename ou la syntaxe < avec -filename pour renommer les fichiers.

"exiftool -filename=new.jpg dir/old.jpg"
Renommer old.jpg en new.jpg dans le répertoire dir.
"exiftool -directory=%e dir"
Déplacer tous les fichiers du répertoire dir dans des répertoires nommés d'après les extensions de fichiers d'origine.
"exiftool '-Directory<DateTimeOriginal' -d %Y/%m/%d dir"
Déplacer tous les fichiers dans dir dans une hiérarchie de répertoires basée sur l'année, le mois et le jour de DateTimeOriginal. eg) Cette commande déplacerait le fichier dir/image.jpg avec un DateTimeOriginal de 2005:10:12 16:05:56 vers 2005/10/12/image.jpg.
"exiftool -o . '-Directory<DateTimeOriginal' -d %Y/%m/%d dir"
Même effet que ci-dessus, sauf que les fichiers sont copiés au lieu d'être déplacés.
"exiftool '-filename<%f_${model;}.%e' dir"
Renommer tous les fichiers dans dir en ajoutant le nom du modèle de l'appareil photo au nom du fichier. Le point-virgule après le nom de la balise à l'intérieur des accolades supprime les caractères invalides dans les noms de fichiers Windows de la valeur de la balise (voir la "Fonction de formatage avancé" pour une explication).
"exiftool '-FileName<CreateDate' -d %Y%m%d_%H%M%S%%-c.%%e dir"
Renommer toutes les images dans dir selon la date et l'heure CreateDate, en ajoutant un numéro de copie avec un '-' si le fichier existe déjà (%-c), et en préservant l'extension d'origine du fichier (%e). Notez le '%' supplémentaire nécessaire pour échapper les codes de nom de fichier (%c et %e) dans la chaîne de format de date.
"exiftool -r '-FileName<CreateDate' -d %Y-%m-%d/%H%M_%%f.%%e dir"
Le répertoire et le nom du fichier peuvent être modifiés ensemble via la balise FileName si le nouveau FileName contient un '/'. L'exemple ci-dessus renomme récursivement toutes les images d'un répertoire en ajoutant un horodatage CreateDate au début du nom du fichier, puis les déplace dans de nouveaux répertoires nommés par date.
"exiftool '-FileName<${CreateDate}_$filenumber.jpg' -d %Y%m%d -ext jpg ."
Définir le nom de fichier de toutes les images JPG dans le répertoire courant à partir des balises CreateDate et FileNumber, sous la forme "20060507_118-1861.jpg".

EXEMPLES DE GEOTAG

ExifTool implémente le géolocalisation à partir de fichiers journaux GPS via 3 balises spéciales : Geotag (qui, par commodité, est également implémentée comme une option exiftool), Geosync et Geotime. Les exemples ci-dessous mettent en évidence certaines fonctionnalités de géolocalisation. Voir https://exiftool.org/geotag.html pour une documentation supplémentaire. (Notez que le géolocalisation à partir de coordonnées GPS connues se fait en écrivant directement les balises GPS plutôt qu'en utilisant l'option -geotag.)

"exiftool -geotag track.log a.jpg"
Géolocaliser une image (a.jpg) à partir des informations de position dans un journal de suivi GPS (track.log). Comme la balise Geotime n'est pas spécifiée, la valeur de SubSecDateTimeOriginal (de préférence) ou DateTimeOriginal est utilisée pour la géolocalisation. L'heure système locale est supposée sauf si l'heure contient un fuseau horaire.
"exiftool -geotag track.log -geolocate=geotag a.jpg"
Géolocaliser une image et également écrire des informations de géolocalisation de la ville la plus proche (nom de la ville, état/province et pays). Lire ici pour plus de détails sur la fonctionnalité de géolocalisation : https://exiftool.org/geolocation.html#Write
"exiftool -geotag t.log -geotime='2009:04:02 13:41:12-05:00' a.jpg"
Géolocaliser une image avec la position GPS pour une heure spécifique.
"exiftool -geotag log.gpx '-xmp:geotime<createdate' dir"
Géolocaliser toutes les images du répertoire dir avec des balises XMP au lieu de balises EXIF, basé sur la date de création de l'image.
"exiftool -geotag a.log -geosync=-20 dir"
Géolocaliser les images du répertoire dir, en tenant compte des horodatages des images qui étaient 20 secondes en avance sur le GPS.
"exiftool -geotag a.log -geosync=1.jpg -geosync=2.jpg dir"
Géolocaliser les images en utilisant la synchronisation horaire de deux images précédemment géolocalisées (1.jpg et 2.jpg), en synchronisant les heures de l'image et du GPS à l'aide d'une correction de dérive temporelle linéaire.
"exiftool -geotag a.log '-geotime<${createdate}+01:00' dir"
Géolocaliser les images dans dir en utilisant CreateDate avec le fuseau horaire spécifié. Si CreateDate contenait déjà un fuseau horaire, alors le fuseau horaire spécifié sur la ligne de commande est ignoré.
"exiftool -geotag= a.jpg"
Supprimer les balises GPS qui peuvent avoir été ajoutées par la fonctionnalité de géolocalisation. Notez que cela ne supprime pas toutes les balises GPS - pour ce faire, utilisez plutôt "-gps:all=".
"exiftool -xmp:geotag= a.jpg"
Supprimer les balises GPS XMP qui ont été ajoutées par la fonctionnalité de géolocalisation.
"exiftool -xmp:geotag=track.log a.jpg"
Géolocaliser une image avec des balises XMP, en utilisant l'heure de SubSecDateTimeOriginal ou DateTimeOriginal.
"exiftool -geotag a.log -geotag b.log -r dir"
Combiner plusieurs journaux de suivi et géolocaliser un arbre de répertoires entier d'images.
"exiftool -geotag 'tracks/*.log' -r dir"
Lire tous les journaux de suivi du répertoire tracks.
"exiftool -p gpx.fmt dir > out.gpx"
Générer un journal de suivi GPX à partir de toutes les images du répertoire dir. Cet exemple utilise le fichier gpx.fmt inclus dans la distribution complète d'ExifTool et suppose que les images dans dir ont toutes été préalablement géolocalisées.

"cat a.jpg | exiftool -"
Extraire les informations de stdin.

Extraire les informations d'une vignette intégrée.

INTERRUPTION D'EXIFTOOL

Interrompre exiftool avec un CTRL-C ou SIGINT n'entraînera pas de fichiers partiellement écrits ou de fichiers temporaires restant sur le disque dur. L'application exiftool intercepte SIGINT et la reporte à la fin des processus critiques si nécessaire, puis effectue un nettoyage approprié avant de quitter.

STATUT DE SORTIE

L'application exiftool se termine avec un statut de 0 en cas de succès, ou 1 si une erreur s'est produite, ou 2 si tous les fichiers ont échoué à la condition -if (pour toutes les commandes si -execute a été utilisé).
