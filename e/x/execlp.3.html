DESCRIPTIO

N

La famille de fonctions exec() remplace l'image du processus actuel par une nouvelle image de processus. Les fonctions décrites dans cette page de manuel sont des couches placées au-dessus de execve(2). (Voir la page de manuel de execve(2) pour plus de détails sur le remplacement de l'image du processus actuel.

)

L'argument initial de ces fonctions est le nom d'un fichier à

exécuter.

Les fonctions peuvent être regroupées en fonction des lettres suivant le préfixe « exec »

.

l - execl(), execlp(),

execle()

Le const char *arg et les points de suspension suivants peuvent être considérés comme arg0, arg1, ..., argn. Ensemble, ils décrivent une liste d'un ou plusieurs pointeurs vers des chaînes terminées par un caractère nul qui représentent la liste d'arguments disponible pour le programme exécuté. Le premier argument, par convention, doit pointer vers le nom de fichier associé au fichier exécuté. La liste d'arguments doit être terminée par un pointeur nul et, puisqu'il s'agit de fonctions variadiques, ce pointeur doit être converti en (char *)

NULL.

Contrairement aux fonctions « l », les fonctions « v » (

ci-dessous) spécifient les arguments de la ligne de
commande du programme exécuté sous forme de vecteur.

v - execv(), execvp(),

execvpe()

L' char *const argv[] argument est un tableau de pointeurs vers des chaînes terminées par un caractère nul qui représentent la liste d'arguments disponible pour le nouveau programme. Le premier argument, par convention, doit pointer vers le nom de fichier associé au fichier exécuté. Le tableau de pointeurs doit être terminé p

ar un poi
nteur nul.

e - execle(),

execvpe()

L'environnement de la nouvelle image de processus est spécifié via l'argument envp. L' envp argument est un tableau de pointeurs vers des chaînes terminées par un caractère nul et doit être terminé par un pointeur

nul.

Toutes les autres fonctions exec() (qui n'incluent pas « e » dans le suffixe) prennent l'environnement de la nouvelle image de processus à partir de la variable externe environ du proc

essus a
ppelant.

p - execlp(), execvp(),

execvpe()

Ces fonctions reproduisent les actions du shell lors de la recherche d'un fichier exécutable si le nom de fichier spécifié ne contient pas de caractère slash (/). Le fichier est recherché dans la liste des chemins de répertoires séparés par des deux-points spécifiée dans la variable d'environnement PATH. Si cette variable n'est pas définie, la liste des chemins est par défaut une liste incluant les répertoires renvoyés par confstr(_CS_PATH) (qui renvoie généralement la valeur « /bin:/usr/bin ») et éventuellement aussi le répertoire de travail courant ; voir VERSIONS pour plus de

détails.

execvpe() recherche le programme en utilisant la valeur de PATH de l'environnement de l'appelant, et non à partir de envp

argument.

Si le nom de fichier spécifié inclut un caractère slash, alors PATH est ignoré et le fichier au chemin spécifié est

exécuté.

De plus, certaines erreurs sont traitées de manière

particulière.

Si les permissions sont refusées pour un fichier (la tentative execve(2) a échoué avec l'erreur EACCES), ces fonctions continueront la recherche dans le reste du chemin de recherche. Si aucun autre fichier n'est trouvé, elles retourneront avec errno défini à EACCES

.

Si l'en-tête d'un fichier n'est pas reconnu (la tentative execve(2) a échoué avec l'erreur ENOEXEC), ces fonctions exécuteront le shell (/bin/sh) avec le chemin du fichier comme premier argument. (Si cette tentative échoue, aucune recherche ultérieure n'est effectuée.

)

Toutes les autres fonctions exec() (qui n'incluent pas « p » dans le suffixe) pre

nnent comme premier argument un ch
emin (relatif ou absolu) qui
identifie le programme à exécuter.

VERSION

S

Le chemin de recherche par défaut (utilisé lorsque l'environnement ne contient pas la variable PATH) présente certaines variations selon les systèmes. Il inclut généralement /bin et /usr/bin (dans cet ordre) et peut également inclure le répertoire de travail courant. Sur certains autres systèmes, le répertoire de travail courant est inclus après /bin et /usr/bin, comme mesure anti-cheval de Troie. L'implémentation de glibc a longtemps suivi le défaut traditionnel où le répertoire de travail courant est inclus au début du chemin de recherche. Cependant, un refactoring de code lors du développement de glibc 2.24 a entraîné la suppression du répertoire de travail courant du chemin de recherche par défaut. Ce changement de comportement accidentel est considéré comme légèrement bénéfique et ne sera pas

annulé.

Le comportement de execlp() et execvp() lorsque des erreurs se produisent lors de la tentative d'exécution du fichier est une pratique historique, mais n'a pas traditionnellement été documentée et n'est pas spécifiée par la norme POSIX. BSD (et possiblement d'autres systèmes) effectuent une pause et une nouvelle tentative automatiques si ETXTBSY est rencontré. Linux le traite comme une erreur fatale et retourne

immédiatement.

Traditionnellement, les fonctions execlp() et execvp() ignoraient toutes les erreurs sauf celles décrites ci-dessus et ENOMEM et E2BIG, pour lesquelles elles retournaient. Elles retournent déso

rmais si une erreur autre que cel
les décrites ci-dessus se produit.
