DESCRIPTIO

N

L'appel système execveat() exécute le programme référencé par la combinaison de dirfd et path. Il fonctionne exactement de la même manière que execve(2), à l'exception des différences décrites dans cette page de

manuel.

Si path est relatif, il est alors interprété par rapport au répertoire référencé par le descripteur de fichier dirfd (plutôt que par rapport au répertoire de travail courant du processus appelant, comme c'est le cas pour execve(2) avec un chemin relatif)

.

Si path est relatif et dirfd est la valeur spéciale AT_FDCWD, alors path est interprété par rapport au répertoire de travail courant du processus appelant (comme pour execve(2))

.

Si path est absolu, alors dirfd est

ignoré.

Si path est une chaîne vide et que l'indicateur AT_EMPTY_PATH est spécifié, alors le descripteur de fichier dirfd spécifie le fichier à exécuter (c'est-à-dire que dirfd fait référence à un fichier exécutable, et non à un répertoire)

.

:

NOTE

S

En plus des raisons expliquées dans openat(2), l'appel système execveat() est également nécessaire pour permettre l'implémentation de fexecve(3) sur les systèmes qui n'ont pas le système de fichiers /proc

monté.

Lorsqu'on lui demande d'exécuter un fichier script, le argv[0] transmis à l'interprète du script est une chaîne de la forme /dev/fd/N ou /dev/fd/N/P, où N est le numéro du descripteur de fichier transmis via l'argument dirfd. Une chaîne de la première forme apparaît lorsque AT_EMPTY_PATH est utilisé. Une chaîne de la deuxième forme apparaît lorsque le script est spécifié à la fois via dirfd et path ; dans ce cas, P est la valeur donnée dans path

.

Pour les mêmes raisons que celles décrites dans fexecve(3), l'idiome naturel lors de l'utilisation de execveat() est de définir l'indicateur close-on-exec sur dirfd. (Mais v

oir ANOM
ALIES.)

ANOMALI

ES

L'erreur ENOENT décrite ci-dessus signifie qu'il n'est pas possible de définir l'indicateur close-on-exec sur le descripteur de fichier donné à un appel de la forme

: 


execveat(fd, "", argv, envp, AT_EMPTY_PATH)
;

Cependant, l'impossibilité de définir l'indicateur close-on-exec signifie qu'un descripteur de fichier faisant référence au script fuit vers le script lui-même. En plus de gaspiller un descripteur de fichier, cette fuite peut entraîner une épuisement des descripteurs de fichier dans des scénarios où les scripts emploient récursivement execve

at
().
