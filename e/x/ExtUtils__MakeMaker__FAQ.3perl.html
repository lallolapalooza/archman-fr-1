Comment garder mon $VERSION à jour sans le réinitialiser manuellement
?
Souvent, vous voulez définir manuellement le $VERSION dans la distribution du module principal car c'est la version que tout le monde voit sur CPAN et peut-être voulez-vous la personnaliser un peu. Mais pour tous les autres modules de votre dist, $VERSION n'est vraiment qu'une simple comptabilité et tout ce qui compte, c'est qu'il augmente chaque fois que le module est modifié. Le faire à la main est pénible et on l'oublie souvent.

La façon la plus simple de faire cela est probablement d'utiliser perl-reversion dans Perl::

Version : 
perl-reversion
-bump

Si votre système de contrôle de version supporte les numéros de révision (git ne le fait pas facilement), la façon la plus simple de le faire automatiquement est d'utiliser son numéro de révision (vous utilisez le contrôle de version, n'est-ce

pas ?).

Dans CVS, RCS et SVN, vous utilisez $Revision$ (voir la documentation de votre système de contrôle de version pour les détails). Chaque fois que le fichier est enregistré, le $Revision$ sera mis à jour, mettant à jour votre $VERSI

ON.

SVN utilise un entier simple pour $Revision$ vous pouvez donc l'adapter pour votre $VERSION comme

ceci : 
($VERSION) = q$Revision$ =~ /(\d+)
/;

Dans CVS et RCS, la version 1.9 est suivie de 1.10. Puisque CPAN compare les numéros de version numériquement, nous utilisons un sprintf() pour convertir 1.9 en 1.009 et 1.10 en 1.010 qui se comparent

correctement. 
$VERSION = sprintf "%d.%03d", q$Revision$ =~ /(\d+)\.(\d+)
/g;

Si des branches sont impliquées (c'est-à-dire $Revision: 1.5.3.4$), c'est un peu plus

compliqué. 
# doit être sur une seule ligne sinon MakeMaker sera confus.
$VERSION = do { my @r = (q$Revision$ =~ /\d+/g); sprintf "%d."."%03d" x $#r,
@r };

Dans SVN, $Revision$ devrait être le même pour chaque fichier du projet, ils auraient donc tous le même $VERSION. CVS et RCS ont un $Revision$ différent par fichier, chaque fichier aura donc un $VERSION différent. Les systèmes de contrôle de version distribués, comme SVK, peuvent avoir un $Revision$ différent selon qui extrait le fichier, ce qui entraîne un $VERSION différent sur chaque machine ! Enfin, certains systèmes de contrôle de ve

rsion distribués, comme darcs, n'ont pas
du tout de concept de numéro de révision.

Comment supprimer tout ce qui n'est pas dans mon MANIFES
T ?
Certaines personnes sont surprises que "make distclean" ne supprime pas tout ce qui n'est pas listé dans leur MANIFEST (créant ainsi une distribution propre) mais leur indique seulement ce qu'elles doivent supprimer. Cela est fait car c'est considéré comme trop dangereux. Pendant le développement de votre module, vous pourriez écrire un nouveau fichier, ne pas l'ajouter au MANIFEST, puis lancer un "distclean" et être triste car votre nouveau travail a été supprimé.

Si vous voulez vraiment faire cela, vous pouvez utiliser ExtUtils::Manifest::manifind() pour lire le MANIFEST et File::Find pour supprimer les fichiers. Mais vous devez faire attention. Voici un script pour faire cela. Utilisez à vos propres risques. Amusez-vous à vous faire des trous dans

le pied. 
#!/usr/bin/perl -w
use strict;
use File::Spec;
use File::Find;
use ExtUtils::Manifest qw(maniread);
my %manifest = map  {( $_ => 1 )}
               grep { File::Spec->canonpath($_) }
                    keys %{ maniread() };
if( !keys %manifest ) {
    print "No files found in MANIFEST.  Stopping.\n";
    exit;
}
find({
      wanted   => sub {
          my $path = File::Spec->canonpath($_);
          return unless -f $path;
          return if exists $manifest{ $path };
          print "unlink $path\n";
          unlink $path;
      },
      no_chdir => 1
     },
".
" );

Comment éviter les erreurs "object version X.XX does not match bootstrap parameter Y.
YY" ?
Le code XS est très sensible au numéro de version du module et se plaindra si le numéro de version dans votre module Perl ne correspond pas. Si vous changez le numéro de version de votre module sans relancer Makefile.PL, l'ancien numéro de version restera dans le Makefile, ce qui fera que le code XS sera compilé avec le mauvais numéro.

Pour éviter cela, vous pouvez forcer la reconstruction du Makefile chaque fois que vous changez le module contenant le numéro de version en ajoutant ceci à vos arguments de WriteMakefile()

depend => { '$(FIR
ST_MAKEFILE)' => '
$(VERSION_FROM)' }
