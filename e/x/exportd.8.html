NOM

nfsv4.exportd - Daemon de montage NFSv4

SYNTAXE

/usr/sbin/nfsv4.exportd [options]

DESCRIPTION

nfsv4.exportd est utilisé pour gérer les exportations NFSv4. Le serveur NFS (nfsd) maintient un cache d'informations d'authentification et d'autorisation qui est utilisé pour identifier la source de chaque requête, puis quelles permissions d'accès cette source a sur un système de fichiers local. Lorsque les informations requises ne sont pas trouvées dans le cache, le serveur envoie une requête à nfsv4.exportd pour compléter les informations manquantes. nfsv4.exportd utilise une table d'informations stockée dans /var/lib/nfs/etab et maintenue par exportfs(8), éventuellement basée sur le contenu de exports(5), pour répondre à chaque requête.

OPTIONS

-d kind ou --debug kind
Activer le débogage. Les types valides sont : all, auth, call, general et parse.
-l ou --log-auth
Activer la journalisation des réponses aux requêtes d'authentification et d'accès provenant de nfsd. Chaque réponse est ensuite mise en cache par le noyau pendant 30 minutes (ou tel que défini par --ttl ci-dessous), et sera rafraîchie après 15 minutes (la moitié du temps TTL) si le client concerné reste actif. Notez que -l est équivalent à -d auth et peut donc être activé dans /etc/nfs.conf avec "debug = auth" dans la section [exportd].
-i ou --cache-use-ipaddr
Normalement, chaque adresse IP client est comparée à chaque identifiant d'hôte (nom, joker, netgroup, etc.) trouvé dans /etc/exports et une identité combinée est formée à partir de tous les identifiants correspondants. Souvent, de nombreux clients correspondent à la même identité combinée, donc effectuer ce mappage réduit le nombre de détails d'accès distincts que le noyau doit stocker. Spécifier l'option -i supprime ce mappage de sorte que l'accès à chaque système de fichiers est demandé et mis en cache séparément pour chaque adresse IP client. Cela peut légèrement augmenter la charge de mise à jour du cache, mais peut rendre les messages de journalisation produits par l'option -l plus faciles à lire.
-T ou --ttl
Fournir une durée de vie (TTL) pour les informations mises en cache données au noyau. Le noyau demandera normalement une mise à jour si l'information est nécessaire après l'expiration de la moitié de ce temps. Augmenter le nombre fourni, exprimé en secondes, réduit le taux de requêtes de mise à jour du cache, ce qui est particulièrement perceptible lorsque ces requêtes sont journalisées avec -l. Cependant, l'augmentation signifie également que les changements dans les mappages nom d'hôte vers adresse peuvent prendre plus de temps à être remarqués. La TTL par défaut est de 1800 (30 minutes).
-F ou --foreground
Exécuter en avant-plan (ne pas démoniser)
-h ou --help
Afficher le message d'utilisation.
-t N ou --num-threads=N ou --num-threads N
Cette option spécifie le nombre de threads de travail que nfsv4.exports lance. Le défaut est de 1 thread, ce qui est probablement suffisant. Plus de threads sont généralement nécessaires uniquement pour les serveurs NFS qui doivent gérer des tempêtes de montage de centaines de montages NFS en quelques secondes, ou lorsque votre serveur DNS est lent ou peu fiable.
-g ou --manage-gids
Accepter les requêtes du noyau pour mapper les numéros d'identifiant d'utilisateur dans des listes de numéros d'identifiant de groupe pour le contrôle d'accès. Une requête NFS contiendra normalement (sauf lors de l'utilisation de Kerberos ou d'une autre authentification cryptographique) un identifiant d'utilisateur et une liste d'identifiants de groupe. En raison d'une limitation du protocole NFS, au plus 16 identifiants de groupe peuvent être listés. Si vous utilisez l'option -g, la liste des identifiants de groupe reçue du client sera remplacée par une liste d'identifiants de groupe déterminée par une recherche appropriée sur le serveur. Notez que l'identifiant de groupe 'primaire' n'est pas affecté, donc une commande newgroup sur le client sera toujours effective. Cette fonction nécessite un noyau Linux avec une version au moins 2.6.21.

FICHIER DE CONFIGURATION

Beaucoup d'options qui peuvent être définies sur la ligne de commande peuvent également être contrôlées par des valeurs définies dans les sections [exportd] ou, dans certains cas, [nfsd] du fichier de configuration /etc/nfs.conf. Les valeurs reconnues dans la section [exportd] incluent cache-use-ipaddr, ttl, manage-gids et debug, qui ont chacune le même effet que l'option du même nom.

FICHIERS

/etc/exports
fichier d'entrée pour exportfs, listant les exportations, les options d'exportation et les listes de contrôle d'accès.
