en tant qu'expression Tcl, et renvoie la valeur. Les opérateurs autorisés dans les expressions Tcl incluent un sous-ensemble des opérateurs autorisés dans les expressions C. Pour les opérateurs communs à Tcl et C, Tcl applique la même signification et la même priorité que les opérateurs C correspondants. Les expressions produisent presque toujours des résultats numériques (valeurs entières ou en virgule flottante). Par exemple, l'expression expr 8.2 + 6 évalue à 14.2. Des espaces peuvent être utilisés entre les opérandes et les opérateurs et les parenthèses (ou virgules) ; ils sont ignorés par les instructions de l'expression. Lorsque c'est possible, les opérandes sont interprétés comme des valeurs entières. Les valeurs entières peuvent être spécifiées en décimal (le cas normal), en binaire (si les deux premiers caractères de l'opérande sont 0b), en octal (si les deux premiers caractères de l'opérande sont 0o), ou en hexadécimal (si les deux premiers caractères de l'opérande sont 0x). Pour la compatibilité avec les versions plus anciennes de Tcl, une valeur entière octale est également indiquée simplement lorsque le premier caractère de l'opérande est 0, que le deuxième caractère soit [[30]] o ou non. Si un opérande n'a pas l'un des formats entiers donnés ci-dessus, alors il est traité comme un nombre en virgule flottante si cela est possible. Les nombres en virgule flottante peuvent être spécifiés dans l'un des formats courants utilisant les chiffres décimaux, le point décimal ., les caractères e ou E indiquant la notation e or scientifique, et les caractères de signe + ou -. Par exemple, tous les nombres suivants sont des nombres en virgule flottante valides : 2.1, 3., 6e4, 7.91e+16. Les chaînes Inf et NaN sont également reconnues comme valeurs en virgule flottante, en utilisant n'importe quelle casse pour chaque caractère. TYPES, DÉBORDEMENT ET

PRÉCISION

Tous les calculs internes impliquant des entiers sont effectués en faisant appel à la bibliothèque d'entiers à précision multiple LibTomMath selon les besoins afin que tous les calculs sur les entiers soient effectués exactement. Notez que dans les versions de Tcl antérieures à 8.5, les calculs sur les entiers étaient effectués avec l'un des types C long int ou Tcl_WideInt, ce qui causait une troncature implicite de la plage dans ces calculs où les valeurs dépassaient la plage de ces types. Tout code qui s'appuyait sur ces troncatures implicites devra ajouter explicitement des appels de fonctions int() ou wide() aux expressions aux points où une telle troncature doit avoir

lieu.

Tous les calculs internes impliquant des flottants sont effectués avec le type C double. Lors de la conversion d'une chaîne en flottant, un débordement d'exposant est détecté et résulte en la valeur double de Inf ou -Inf selon le cas. Le débordement et le débordement négatif des flottants sont détectés dans la mesure où le matériel le permet, ce qui est généralement assez

fiable.

La conversion entre les représentations internes pour les opérandes entiers, flottants et chaînes se fait automatiquement selon les besoins. Pour les calculs arithmétiques, les entiers sont utilisés jusqu'à ce qu'un nombre flottant soit introduit, après quoi les flottants sont utilisés. Par

exemple, 
expr {
5 /
4}

renvoie 1, tandis

que 
expr {5 / 4.0}
expr {5 / ( [string length "abcd"] + 0.0
)
}

renvoient tous deux 1.25. Les valeurs flottantes sont toujours renvoyées avec un «. » ou un «e » afin qu'elles ne ressemblent pas à des valeurs entières. Par

exemple, 
expr {20
.0/
5.0}

renvoie 4.0, pas 4

OPÉRATIONS SUR LES

CHAÎNES

Les valeurs de chaîne peuvent être utilisées comme opérandes des opérateurs de comparaison, bien que l'évaluateur d'expression essaie de faire des comparaisons en entier ou en flottant quand il le peut, c'est-à- dire quand tous les arguments de l'opérateur permettent des interprétations numériques, sauf dans le cas des opérateurs eq et ne . Si l'un des opérandes d'une comparaison est une chaîne et que l'autre a une valeur numérique, une représentation canonique de chaîne de la valeur numérique de l'opérande est générée pour la comparer avec l'opérande chaîne. La représentation canonique de chaîne pour les valeurs entières est un format de chaîne décimal. La représentation canonique de chaîne pour les valeurs flottantes est celle produite par le spécificateur de format %g de la commande format de Tcl. Par exemple, les

commandes 
expr {"0x03" > "2"}
expr {"0y"
> "0
x12"}

renvoient toutes deux 1. La première comparaison est faite avec une comparaison d'entiers, et la seconde avec une comparaison de chaînes. En raison de la tendance de Tcl à traiter les valeurs comme des nombres chaque fois que c'est possible, il n'est généralement pas une bonne idée d'utiliser des opérateurs comme == quand on veut vraiment une comparaison de chaînes et que les valeurs des opérandes peuvent être arbitraires ; il est préférable dans ces cas d'utiliser les opérateurs eq ou ne, ou la commande st

CONSIDÉRATIONS DE

PERFORMANCE

Entourez les expressions d'accolades pour la meilleure vitesse et les plus petites exigences de stockage. Cela permet au compilateur de code intermédiaire de Tcl de générer le meilleur

code.

Comme mentionné ci-dessus, les expressions sont substituées deux fois : une fois par l'analyseur Tcl et une fois par la commande expr. Par exemple, les

commandes 
set a 3
set b {$a + 2}
expr
$b
*4

renvoient 11, pas un multiple de 4. C'est parce que l'analyseur Tcl substituera d'abord «$a + 2 » pour la variable b, puis la commande expr évaluera l'expression «$a + 2*4 »

.

La plupart des expressions ne nécessitent pas un deuxième tour de substitutions. Soit elles sont entourées d'accolades, soit, si ce n'est pas le cas, leurs substitutions de variables et de commandes produisent des nombres ou des chaînes qui ne nécessitent elles-mêmes pas de substitutions. Cependant, parce que quelques expressions sans accolades nécessitent deux tours de substitutions, le compilateur de code intermédiaire doit émettre des instructions supplémentaires pour gérer cette situation. Le code le plus coûteux est requis pour les expressions sans accolades qui contiennent des substitutions de commandes. Ces expressions doivent être implémentées en générant du nouveau code chaque fois que l'expression est

exécutée.

S'il est nécessaire d'inclure une chaîne d'expression non constante dans le contexte plus large d'une expression autrement constante, la technique la plus efficace est de mettre la partie variable à l'intérieur d'un expr récursif, car cela permet au moins la compilation de la partie extérieure, bien que cela signifie que la partie variable doit elle-même être évaluée comme une expression séparée. Ainsi, dans cet exemple le résultat est 20 et l'expression extérieure bénéficie d'une compilation de code intermédiaire entièrement mise en

cache. 
set a 3
set b {$a + 2}
expr {[expr $
b] *
4}

Lorsque l'expression est sans accolades pour permettre la substitution d'une fonction ou d'un opérateur, envisagez d'utiliser directement les commandes documentées dans les pages de manuel mathfunc(n) ou mathop(n)

à la p
lace.

proc tcl::mathfunc::calc {x y} {

: 
# convert from ($radius,$angle)
set x [expr { $radius * cos($angle) }]

}
]

:
