ExtUtils::Typemaps::OutputMap(3perl) Guide de référence du programmeur Perl ExtUtils::Typemaps::OutputMap(3perl)

NOM

ExtUtils::Typemaps::OutputMap - Entrée dans la section OUTPUT d'une typemap

SYNOPSIS

use ExtUtils::Typemaps;
...
my $output = $typemap->get_output_map('T_NV');
my $code = $output->code();
$output->code("...");

DESCRIPTION

Se référer à ExtUtils::Typemaps pour plus de détails.

MÉTHODES

new

Nécessite les paramètres "xstype" et "code".

code

Retourne ou définit le code de mappage OUTPUT pour cette entrée.

xstype

Retourne le nom du type XS de la carte OUTPUT.

cleaned_code

Retourne une copie nettoyée du code pour lequel certaines transformations ont été appliquées pour le rendre plus conforme à l'ANSI.

targetable_legacy

Ne pas utiliser pour du nouveau code.

C'est la version originale de la méthode targetable(), dont le comportement a été figé pour des raisons de compatibilité ascendante. Elle est utilisée pour déterminer s'il faut émettre un "dXSTARG" précoce, qui sera dans la portée de la plupart des XSUB. La génération de code XSUB plus récente émet un "dXSTARG" dans une portée plus restreinte si aucun n'a déjà été émis. Certains codes XS supposent que "TARG" a été déclaré, donc continuer à le déclarer dans les mêmes conditions qu'auparavant. La méthode plus récente "targetable" peut être vraie dans des circonstances supplémentaires.

Si l'optimisation ne peut pas être appliquée, ceci retourne undef. Si elle peut être appliquée, cette méthode retourne une référence de hachage contenant les informations suivantes :

type:      N'importe quel caractère parmi i, u, n, p
with_size: Bool indiquant s'il s'agit de la variante sv_setpvn
what:      Le code qui s'évalue effectivement au scalaire de sortie
what_size: Si "with_size" est vrai, ceci contient la longueur de la chaîne (en tant que code,
           pas une constante, y compris une virgule initiale)

targetable

Méthode de classe.

Retourne un booléen indiquant si le fragment de code fourni est adapté pour utiliser TARG comme SV de destination plutôt qu'un nouveau mortel.

En principe, la plupart des choses le sont, à l'exception des expressions qui définiraient le SV à une valeur de référence. Cela peut provoquer la non-libération de la valeur référencée, car les targs ne sont pas libérés (du moins pendant la durée de leur CV). Donc, en pratique, nous le restreignons à une liste approuvée de formes sv_setfoo(), et seulement là où il n'y a pas de code supplémentaire après le sv_setfoo() (donc nous devons faire correspondre la parenthèse fermante, en autorisant les parenthèses imbriquées etc. à l'intérieur).
