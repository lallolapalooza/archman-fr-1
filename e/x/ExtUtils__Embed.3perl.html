ldopts
()
Affiche les arguments pour lier la bibliothèque Perl et les extensions à votre application.

Lorsqu'elle est invoquée comme `perl -MExtUtils::Embed -e ldopts --`, les options suivantes sont reconnues

:

-s

td

Affiche les arguments pour lier la bibliothèque Perl et toute extension liée avec le Perl

actuel.

-I <chemin1:

chemin2>

Chemin de recherche pour les archives ModuleName.a. Le chemin par défaut est @INC. Les archives de bibliothèque sont censées être trouvées comme /some/path/auto/ModuleName/ModuleName.a Par exemple, lors de la recherche de Socket.a relativement à un chemin de recherche, nous devrions trouver auto/Socket/Socket.

a

Lors de la recherche de "DBD::Oracle" relativement à un chemin de recherche, nous devrions trouver auto/DBD/Oracle/Oracle.

a

Gardez à l'esprit que vous pouvez toujours fournir /my/own/path/ModuleName.a comme argument de liaison

supplémentaire.

-- <liste d'arguments de

liaison>

Arguments de liaison supplémentaires à prendre en

compte.

Tout argument supplémentaire trouvé avant le -- token est attendu sous forme de noms de modules pour lesquels générer du

code.

Lorsqu'elle est invoquée avec des paramètres, les éléments suivants sont acceptés et facultatifs

"ldopts($std,[@modules],[@link_args],

$path)"

:

$std est booléen, équivalent à l'option -std

[@modules] est équivalent aux arguments supplémentaires trouvés avant le -- tok

[@link_args] est équivalent aux arguments trouvés après le -- tok

$path est équivalent à l'option -I

Cela affichera les arguments pour lier avec "libperl" et les extensions trouvées dans $Config{static_ext}. Cela inclut les bibliothèques trouvées dans $Config{libs} et la première bibliothèque ModuleName.a pour chaque extension trouvée en recherchant dans @INC ou le chemin spécifié par l'option -I. De plus, lorsque ModuleName.a est trouvé, des arguments de liaison supplémentaires sont récupérés depuis le fichier extralibs.ld dans le même
