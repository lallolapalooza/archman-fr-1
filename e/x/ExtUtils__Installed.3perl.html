DESCRIPTIO

N

ExtUtils::Installed fournit un moyen standard de découvrir quels fichiers de base et de modules ont été installés. Elle utilise les

informations stockées dans les fichiers .packlist créés lors de l'installation pour fournir ces informations. De plus, elle fournit d
es fonctionnalités pour classer les fichiers installés et extraire des informations de répertoire à partir des fichiers .packlist.

UTILISATI

ON

La fonction new() recherche tous les .packlists installés sur le système et stocke leur contenu. Les .packlists peuvent être interrogés avec les fonctions décrites ci-dessous. L'endroit où elle recherche par défaut est déterminé par les paramètres trouvés dans %Config::Config, et par la valeur d

e la variable d'env
ironnement PERL5LIB.

MÉTHODE

S

Sauf indication contraire, toutes les méthodes peuvent être appelées en tant que méthodes de classe ou en tant que méthodes d'objet. Si elles sont appelées en tant que méthodes de classe, l'objet « par défaut » sera utilisé et, si nécessaire, créé à l'aide du %Config et du @INC du processus courant. Voir l'option 'default' de new() pour plus de

détails.
new
()
Cette fonction accepte des paramètres nommés optionnels. Sans paramètres, elle recherche tous les .packlists installés sur le système en utilisant les informations de %Config::Config et les chemins de recherche de modules par défaut @INC. Les packlists sont lues à l'aide du module ExtUtils::Packlist.

Si le paramètre nommé "skip_cwd" est vrai, le répertoire courant "." sera retiré de @INC avant la recherche des .packlists. Cela empêche ExtUtils::Installed de trouver des modules installés dans d'autres interpréteurs Perl qui se trouvent par hasard sous le répertoire

courant.

Si le paramètre nommé "config_override" est spécifié, il doit être une référence vers un tableau associatif contenant toutes les informations habituellement trouvées dans %Config::Config. Par exemple, vous pouvez obtenir les informations de configuration d'une installation Perl distincte et les

passer. 
my $yoda_cfg  = get_fake_config('yoda');
my $yoda_inst =
           ExtUtils::Installed->new(config_override=>$yoda_cfg)
;

De même, le paramètre "inc_override" peut être une référence vers un tableau utilisé à la place des chemins de recherche de modules par défaut de @I

NC. 
use Config;
my @dirs = split(/\Q$Config{path_sep}\E/, $ENV{PERL5LIB});
my $p5libs = ExtUtils::Installed->new(inc_override=>
\@dirs);

Remarque : vous ne voudrez probablement pas utiliser ces options seules ; presque toujours, vous voudrez les définir toutes les deux

ensemble.

Le paramètre "extra_libs" peut être utilisé pour spécifier des chemins supplémentaires où rechercher les modules installés.

Par exemple 
my $installed =
         ExtUtils::Installed->new(extra_libs=>["/my/lib/path"]
);

Cela ne devrait être nécessaire que si /my/lib/path n'est pas dans

PERL5LIB.

Enfin, il y a l'option 'default' et les options associées 'default_get' et 'default_set'. Ces options contrôlent l'objet « par défaut » fourni par l'interface de classe aux méthodes. Définir "default_get" à vrai indique au constructeur de retourner l'objet par défaut s'il est défini. Définir "default_set" à vrai indique au constructeur de faire de l'objet par défaut l'objet construit. Définir l'option "default" revient à définir les deux à vrai. Cela est principalement ut

ilisé en interne et n'est probablement
pas intéressant pour un utilisateur réel.
modules
()
Cette fonction renvoie une liste des noms de tous les modules installés. Le « cœur » de Perl reçoit le nom spécial
'Perl'.
files
()
Cette fonction prend un paramètre obligatoire, le nom d'un module. Elle renvoie une liste de tous les noms de fichiers du paquet. Pour obtenir une liste des fichiers de base de Perl, utilisez le nom de module 'Perl'. Des paramètres supplémentaires sont autorisés. Le premier est l'une des chaînes "prog", "doc" ou "all", pour sélectionner soit les fichiers de programme, soit les fichiers de manuel, soit tous les fichiers. Les paramètres restants sont une liste de répertoires. Les noms de fichiers renvoyés seront limités à ceux situés sous les répertoires
spécifiés.
directories
()
Cette fonction prend un paramètre obligatoire, le nom d'un module. Elle renvoie une liste de tous les répertoires du paquet. Des paramètres supplémentaires sont autorisés. Le premier est l'une des chaînes "prog", "doc" ou "all", pour sélectionner soit les répertoires de programme, soit les répertoires de manuel, soit tous les répertoires. Les paramètres restants sont une liste de répertoires. Les répertoires renvoyés seront limités à ceux situés sous les répertoires spécifiés. Cette méthode ne renvoie que les répertoires terminaux contenant des fichiers du module
spécifié.
directory_tre
e()
Son fonctionnement est identique à celui de directories(), sauf qu'elle inclut tous les répertoires intermédiaires jusqu'aux répertoires
spécifiés.
validate
()
Cette fonction prend un paramètre obligatoire, le nom d'un module. Elle vérifie que tous les fichiers listés dans le .packlist du module existent réellement et renvoie une liste de tous les fichiers manquants. Si un second argument optionnel évalué à vrai est fourni, tous les fichiers manquants seront retirés du .
packlist
packlist
()
Cette fonction renvoie l'objet ExtUtils::Packlist pour le module
spécifié.
version
()
Cette fonction r
envoie le numéro
de version du
module spécifié.
