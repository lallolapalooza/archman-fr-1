DESCRIPTIO

N

Un serveur NFS maintient une table des systèmes de fichiers physiques locaux accessibles aux clients NFS. Chaque système de fichiers dans cette table est appelé un système de fichiers exporté, ou export, pour faire

court.

La commande exportfs maintient la table d'exports courante du serveur NFS. La table d'exports maîtresse est conservée dans un fichier nommé /var/lib/nfs/etab. Ce fichier est lu par rpc.mountd lorsqu'un client envoie une requête NFS

MOUNT.

Normalement, la table d'exports maîtresse est initialisée avec le contenu de /etc/exports et des fichiers sous /etc/exports.d en invoquant exportfs -a. Cependant, un administrateur système peut choisir d'ajouter ou de supprimer des exports sans modifier /etc/exports ou les fichiers sous /etc/exports.d en utilisant la commande exp

ortfs.

exportfs et son programme associé rpc.mountd fonctionnent dans l'un des deux modes suivants : un mode historique qui s'applique aux versions 2.4 et antérieures du noyau Linux, et un nouveau mode qui s'applique aux versions 2.6 et ultérieures, à condition que le système de fichiers virtuel nfsd ait été monté à /proc/fs/nfsd ou /proc/fs/nfs. Sur les noyaux 2.6, si ce système de fichiers n'est pas monté, le mode historique est

utilisé.

Dans le nouveau mode, exportfs ne donne aucune information au noyau, mais la fournit uniquement à rpc.mountd à travers le fichier /var/lib/nfs/etab. rpc.mountd gère ensuite les requêtes du noyau demandant des informations sur les exports, selon les

besoins.

Dans le mode historique, les exports qui identifient un hôte spécifique, plutôt qu'un sous-réseau ou un groupe réseau, sont insérés directement dans la table d'exports du noyau, en plus d'être écrits dans /var/lib/nfs/etab. De plus, les exports listés dans /var/lib/nfs/rmtab qui correspondent à une requête d'export non spécifique à un hôte provoqueront l'ajout d'une entrée d'export appropriée pour l'hôte donné dans rmtab à la table d

'exports
du noyau.

Exportation de

répertoires

Le premier synopsis montre comment invoquer exportfs lors de l'ajout de nouvelles entrées à la table d'exports. Lors de l'utilisation de exportfs -a, tous les exports listés dans /etc/exports et les fichiers sous /etc/exports.d sont ajoutés à /var/lib/nfs/etab. La table d'exports du noyau est également mise à jour selon les

besoins.

L'argument client:/chemin spécifie un répertoire local à exporter, ainsi que le ou les clients autorisés à y accéder. Voir exports(5) pour une description des options prises en charge et des formats de liste

d'accès.

Les adresses de présentation IPv6 contiennent des deux-points, qui sont déjà utilisés pour séparer les arguments de ligne de commande « hôte » et « chemin ». Lors de la spécification d'un client à l'aide d'une adresse IPv6 brute, enclosez l'adresse entre crochets. Pour les adresses de réseau IPv6, placez le préfixe juste après le crochet

fermant.

Pour exporter un répertoire au monde entier, spécifiez simplement :/chem

in.

Les options d'export pour une paire hôte/répertoire particulière proviennent de plusieurs sources. Les options d'export par défaut sont sync,ro,root_squash,wdelay. Celles-ci peuvent être remplacées par des entrées dans /etc/exports ou les fichiers sous /etc/expor

ts.d.

Un administrateur système peut remplacer les options de ces sources en utilisant l'option de ligne de commande -o sur exportfs. Cette option prend une liste d'options séparées par des virgules de la même manière que l'on les spécifierait dans /etc/exports. De cette façon, exportfs peut être utilisé pour modifier les

options d'export d'un
répertoire déjà exporté.

NFS.

Pour supprimer un export, spécifiez une paire client:/chemin. Cela supprime l'entrée spécifiée de /var/lib/nfs/etab et supprime l'entrée

correspondante du no
yau (le cas échéant).

NAME

exportfs ― manage NFS shared resources

SYNOPSIS

exportfs [ -arvu ] [ -t Directory ] [ Directory ... ]

exportfs [ -auv ] [ -t Directory ] [ Host:Directory ... ]

DESCRIPTION

The exportfs command is used to manage the NFS export list. The list of exported file systems is read from the file /etc/exports or from files in the directory /etc/exports.d/*.exports.

If exportfs is run without any options, it will print the current list of exported file systems.

OPTIONS

-a
Export or unexport all directories.
-r
Reexport all directories. It reads the /etc/exports file or files in /etc/exports.d/ and reexports the directories therein. This is useful for changing export options.
-u
Unexport the specified directories or all directories if -a is specified.
-v
Be verbose. Print what is being done.
-t Directory
This option specifies the directory in which the export table should be stored. The default is /var/lib/nfs/etab.

CONFIGURATION FILE

The NFS server configuration is specified by the file /etc/exports and files in the directory /etc/exports.d/. Each line specifies a single export and contains the directory name, followed by a comma-separated list of client addresses, followed by a comma-separated list of export options.

exportfs reads the export information and updates the NFS server's export table and notifies the NFS server rpc.mountd using the /var/lib/nfs/etab file.

DISCUSSION

When exportfs is run with options like -r or -a, it will read the configuration files and update the kernel's export table. It will also notify the rpc.mountd daemon, which is responsible for handling client mount requests. If rpc.mountd is not running, exportfs will start it.

EXAMPLES

To export the directory /usr/tmp to all clients:

# exportfs -a -i /usr/tmp

To export the directory /srv/data to a specific host thor:

# exportfs -i thor:/srv/data

To unexport the directory /usr/tmp:

# exportfs -u -i /usr/tmp

To unexport all directories:

# exportfs -ua

To reexport all directories defined in /etc/exports or under /etc/exports.d:

# exportfs -r

To export the /usr/tmp directory to IPv6 link-local clients:

# exportfs [fe80::]/64:/usr/tmp

USAGE NOTES

Exporting to IP networks or DNS and NIS domains does not enable clients from these groups to access NFS immediately. Rather, these sorts of exports are hints to rpc.mountd(8) to grant any mount requests from these clients. This is usually not a problem, because any existing mounts are preserved in rmtab across reboots.

When unexporting a network or domain entry, any current exports to members of this group will be checked against the remaining valid exports and if they themselves are no longer valid they will be removed.

FILES

/etc/exports
input file listing exports, export options, and access control lists
/etc/exports.d
directory where extra input files are stored. Note: only files that end with .exports are used.
/var/lib/nfs/etab
master table of exports
/var/lib/nfs/rmtab
table of clients accessing server's exports
