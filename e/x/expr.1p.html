L'opérateur de

correspondance

':' doit comparer la chaîne résultant de l'évaluation de expr1 avec le motif d'expression régulière résultant de l'évaluation de expr2. La syntaxe des expressions régulières doit être celle définie dans le volume Définitions de base de POSIX.1‐2017, Section 9.3, Expressions régulières de base, sauf que tous les motifs sont ancrés au début de la chaîne (c'est-à-dire que seules les séquences commençant à le premier caractère d'une chaîne sont appariés par l'expression rationnelle) et, par conséquent, il n'est pas spécifié si '^' est un caractère spécial dans ce contexte. Habituellement, l'opérateur de correspondance doit renvoyer une chaîne représentant le nombre de caractères appariés ('0' en cas d'échec). Alternativement, si le motif contient au moins une sous-expression d'expression rationnelle "[\(...\)]", la chaîne appariée par l'expression de référence arrière "\1" doit être renvoyée. APPLICATIONS

L'utilitaire expr a une syntaxe plutôt difficile

:
*
Beaucoup des opérateurs sont aussi des opérateurs de contrôle de shell ou des mots réservés, ils doivent donc être échappés sur la ligne de
commande.
*
Chaque partie de l'expression est composée d'arguments distincts, un usage libéral des caractères <blanc> est donc requis. Par exemple : lide lide 1+2 1 + 2 2" 1 + 2 (2 * 3) + \(

\)

Dans de nombreux cas, les fonctionnalités arithmétiques et de chaînes fournies dans le langage de commande du shell sont plus faciles à utiliser que leurs équivalents dans expr. Les scripts nouvellement écrits devraient éviter expr au profit des nouvelles fonctionnalités du shell ; voir Section 2.5, Paramètres et Variables et Section 2.6.4, Expansion arith

métique.

Après le traitement des arguments par le shell, expr n'est pas tenu de pouvoir faire la différence entre un opérateur et un opérande, sauf par la valeur. Si "$a" est '=', la commande

: 
expr
"$a"
= '='

ressemble à

: 
expr =
=
=

car les arguments sont passés à expr (et ils peuvent tous être pris comme l'opérateur '='). Ce qui suit fonctionne de manière fiable

: 
expr
"X$a"
= X=

Notez également que ce volume de POSIX.1‐2017 permet aux implémentations d'étendre les utilitaires. L'utilitaire expr permet aux arguments entiers d'être précédés d'un signe moins unaire. Cela signifie qu'un argument entier pourrait ressembler à une option. Par conséquent, l'application conforme doit employer la construction "--" de la Ligne directrice 10 du volume Définitions de base de POSIX.1‐2017, Section 12.2, Lignes directrices de syntaxe des utilitaires pour protéger ses opérandes s'il y a une chance que le premier opérande soit un entier négatif (ou toute chaîne avec un signe moins initial)

.

Pour tester l'égalité de chaînes, l'utilitaire test est préféré à expr, car il est généralement implémenté comme une commande interne du shell. Cependant, la fonctionnalité n'est pas tout à fait la même car les opérateurs expr = et != vérifient si les chaînes ont la même collation, alors que test vérifie si elles sont identiques. Par conséquent, ils peuvent produire des résultats différents dans les locales où la séquence de collation n'a pas un ordre total de tous les caractères (voir le volume Définitions de base de POSIX.1‐2017, Section 7.3.2, LC_COLLATE).

JUSTIFICATIO

N

Dans une proposition précoce, les ERE étaient utilisés dans la syntaxe de l'expression de correspondance. Cela a été changé en BRE pour éviter de casser les applications

historiques.

L'utilisation d'un <circonflexe> initial dans le BRE n'est pas spécifiée car de nombreuses implémentations historiques l'ont traité comme un caractère spécial, malgré leur documentation système. Par exemple

: 
expr foo : ^
foo expr
^foo : ^foo

renvoient respectivement 3 et 0 sur ces systèmes ; leur documentation impliquerait

l'inverse. Ainsi, la condition d'ancrage est laissée non spécifiée pour éviter de
casser les scripts historiques s'appuyant sur cette fonctionnalité non documentée.
