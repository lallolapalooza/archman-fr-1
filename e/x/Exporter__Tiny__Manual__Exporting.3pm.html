DESCRIPTIO

N

La configuration simple fonctionne de la même manière que Exporter ; héritez de Exporter::Tiny, et utilisez les @EXPORT, @EXPORT_OK, et %EXPORT_TAGS variables de paquet pour lister les sous-routines à

exporter.

Contrairement à Exporter, Exporter::Tiny effectue la plupart de ses tâches internes (y compris la résolution des noms de tags en noms de sous-routines, la résolution des noms de sous-routines en références de code, et l'installation des références de code dans le paquet cible) sous forme de appels de méthode, ce qui signifie que votre module (qui est une sous-classe de Exporter::Tiny) peut les redéfinir pour fournir un comportement

intéressant.

Tags

avancés

Vous pouvez définir des tags en utilisant d'autres tags

: 
use Exporter::Shiny qw(
   black white red green blue cyan magenta yellow
);

our %EXPORT_TAGS = (
   rgb        => [qw( red green blue )],
   cym        => [qw( cyan magenta yellow )],
   cymk       => [qw( black :cym )],
   monochrome => [qw( black white )],
   all        => [qw( :rgb :cymk :monochrome )],
)
;

AVERTISSEMENT : Si vous créez un cycle dans les tags, cela pourrait mettre Ex

porter::Tiny dans une boucle infinie en d
éveloppant les tags. Ne faites pas cela.

Plus sur les

générateurs

Exporter::Tiny a toujours permis de générer des sous-routines exportées (comme Sub::Exporter), mais jusqu'à la version 0.025, il n'avait pas d'API particulièrement agréable pour

cela.

Maintenant, c'est facile. Si vous voulez générer une sous-routine "foo" à exporter, listez-la dans @EXPORT ou @EXPORT_OK comme d'habitude, et donnez simplement à votre module exporteur une méthode de classe appelée "_generate_foo"

. 
push @EXPORT_OK, 'foo';

sub _generate_foo {
   my $class = shift;
   my ($name, $args, $globals) = @_;

   return sub {
      ...;
   }
}

Nous avons montré comment faire cela dans Exporter::Tiny::Manual::QuickStart, mais une chose que nous n'avons pas montrée est que $globals est transmis là-bas. Il s'agit du hachage d'options globales, comme décrit dans Exporter::Tiny::Manual::Importing. Il peut souvent être utile. En particulier, il vous indiquera dans quel paquet la sous-routine générée est destinée à être

installée.

Pour générer des symboles non-code, nommez vos générateurs comme ceci

: 
sub _generateScalar_Foo { ... }  # générer un symbole $Foo
sub _generateArray_Bar  { ... }  # générer un symbole @Bar
sub _generateHash_Baz   { ... }  # générer un symbole
%Baz

Vous pouvez aussi générer des tags

: 
my %constants;
BEGIN {
   %constants = (FOO => 1, BAR => 2);
}
use constant \%constants;

$EXPORT_TAGS{constants} = sub {
   my $class = shift;
   my ($name, $args, $globals) = @_;

   return keys(%constants);
}
;

Crochet

s

Parfois, en plus d'exporter des trucs, vous voulez faire un peu de configuration ou quelque chose comme

ça.

Vous pouvez définir quelques méthodes de classe dans votre paquet, et elles seront appelées au moment opportun

: 
package MyUtils;

...;

sub _exporter_validate_opts {
   my $class = shift;
   my ($globals) = @_;

   ...;   # faire des trucs ici

   $class->SUPER::_exporter_validate_opts(@_);
}

sub _exporter_validate_unimport_opts {
   my $class = shift;
   my ($globals) = @_;

   ...;   # faire des trucs ici

   $class->SUPER::_exporter_validate_unimport_opts(@_);
}

La variable $globals est ce fameux hachage d'options globales. En particulier, "$globals->{into}" est utile car il vous indique quel paquet vous a

importé.

Comme vous l'aurez peut-être deviné, ces méthodes étaient initialement destinées à

valider le hachage d'options globales, mais peuvent être utilisées pour effectuer n'i
mporte quelle tâche générale avant que le vrai travail d'exportation ne soit fait.

internes

Une différence importante entre Exporter et Exporter::Tiny est que ce dernier appelle toutes ses fonctions internes sous forme de méthodes de classe. Cela signifie que votre sous-classe peut les redéfinir pour modifier leur

comportement.

Cette méthode est appelée pour traduire un nom de sous-routine en un hachage de paires nom => référence de code pour l'exportation vers l'appelant. En général, ce serait juste un hachage avec une clé et une valeur, mais, par exemple, Type::Library redéfinit cette méthode pour que "+Foo" soit développé en : 
(
   Foo         => sub { $type },
   is_Foo      => sub { $type->check(@_) },
   to_Foo      => sub { $type->assert_coerce(@_) },
   assert_Foo  => sub { $type->assert_return(@_)
}, )

L'implémentation par défaut vérifie que le nom est autorisé à être exporté (en utilisant la méthode "_exporter_permitted_regexp"), obtient la référence de code en utilisant le générateur s'il y en a un (ou en appelant "can" sur votre exporteur sinon) et appelle "_exporter_fail" si elle est incapable de générer ou de récupérer une référence de

code.
