Exporter(3perl) Guide de référence des programmeurs Perl Exporter(3perl)

NOM

Exporter - Implémente la méthode d'importation par défaut pour les modules

RÉSUMÉ

Dans le module YourModule.pm:

package YourModule;
use Exporter 'import';
our @EXPORT_OK = qw(munge frobnicate);  # symboles à exporter sur demande

ou

package YourModule;
require Exporter;
our @ISA = qw(Exporter);  # hériter de toutes les méthodes de Exporter
our @EXPORT_OK = qw(munge frobnicate);  # symboles à exporter sur demande

ou

package YourModule;
use parent 'Exporter';  # hériter de toutes les méthodes de Exporter
our @EXPORT_OK = qw(munge frobnicate);  # symboles à exporter sur demande

Dans les autres fichiers qui souhaitent utiliser "YourModule":

use YourModule qw(frobnicate);      # importer les symboles listés
frobnicate ($left, $right)          # appelle YourModule::frobnicate

Consultez « Bonnes pratiques » pour quelques variantes que vous voudrez utiliser dans le code Perl moderne.

DESCRIPTION

Le module Exporter implémente une "import" méthode qui permet à un module d'exporter des fonctions et des variables dans les espaces de noms de ses utilisateurs. De nombreux modules utilisent Exporter plutôt que d'implémenter leur propre "import" méthode car Exporter fournit une interface hautement flexible, avec une implémentation optimisée pour le cas courant.

Perl appelle automatiquement la "import" méthode lors du traitement d'une "use" instruction pour un module. Les modules et "use" sont documentés dans perlfunc et perlmod. Comprendre le concept de modules et comment l'instruction "use" fonctionne est important pour comprendre Exporter.

Comment exporter

Les tableaux @EXPORT et @EXPORT_OK dans un module contiennent des listes de symboles qui vont être exportés par défaut dans l'espace de noms de l'utilisateur, ou qu'ils peuvent demander à exporter, respectivement. Les symboles peuvent représenter des fonctions, des scalaires, des tableaux, des hachages, ou des typeglobs. Les symboles doivent être donnés par leur nom complet, à l'exception que l'esperluette devant une fonction est facultative, par exemple.

our @EXPORT    = qw(afunc $scalar @array);   # afunc est une fonction
our @EXPORT_OK = qw(&bfunc %hash *typeglob); # préfixe explicite sur &bfunc

Si vous n'exportez que des noms de fonctions, il est recommandé d'omettre l'esperluette, car l'implémentation est plus rapide de cette façon.

Sélectionner ce qu'il faut exporter

Ne pas exporter de noms de méthodes !

Ne pas exporter quoi que ce soit d'autre par défaut sans bonne raison !

Les exports polluent l'espace de noms de l'utilisateur du module. Si vous devez exporter, essayez d'utiliser @EXPORT_OK de préférence à @EXPORT et évitez les noms de symboles courts ou courants pour réduire le risque de conflits de noms.

En général, tout ce qui n'est pas exporté reste accessible depuis l'extérieur du module en utilisant la syntaxe "YourModule::item_name" (ou "$blessed_ref->method"). Par convention, vous pouvez utiliser un soulignement initial sur les noms pour indiquer informellement qu'ils sont « internes » et non destinés à un usage public.

(Il est en fait possible d'obtenir des fonctions privées en disant :

my $subref = sub { ... };
$subref->(@args);            # L'appeler comme une fonction
$obj->$subref(@args);        # L'utiliser comme une méthode

Cependant, si vous les utilisez pour des méthodes, c'est à vous de trouver comment faire fonctionner l'héritage.)

En règle générale, si le module essaie d'être orienté objet alors n'exportez rien. S'il s'agit juste d'une collection de fonctions, alors @EXPORT_OK n'importe quoi, mais utilisez @EXPORT avec prudence. Pour les noms de fonctions et de méthodes utilisez des mots nus de préférence aux noms préfixés d'esperluettes pour les listes d'export.

D'autres lignes directrices pour la conception de modules peuvent être trouvées dans perlmod.

Comment importer

Dans les autres fichiers qui souhaitent utiliser votre module, il y a trois façons de base pour eux de charger votre module et d'importer ses symboles :

"use YourModule;"
Cela importe tous les symboles de @EXPORT de YourModule dans l'espace de noms de l'instruction "use"
"use YourModule ();"
Cela fait charger votre module par perl mais n'importe aucun symbole.
"use YourModule qw(...);"
Cela n'importe que les symboles listés par l'appelant dans leur espace de noms. Tous les symboles listés doivent être dans votre @EXPORT ou @EXPORT_OK, sinon une erreur se produit. Les fonctionnalités avancées d'export d'Exporter sont accessibles de cette façon, mais avec des entrées de liste qui sont syntaxiquement distinctes des noms de symboles.

À moins que vous ne souhaitiez utiliser ses fonctionnalités avancées, c'est probablement tout ce que vous avez besoin de savoir pour utiliser Exporter.

Fonctionnalités avancées

Listes d'importation spécialisées

Si l'une des entrées d'une liste d'importation commence par !, : ou /, alors la liste est traitée comme une série de spécifications qui ajoutent ou suppriment des noms de la liste des noms à importer. Elles sont traitées de gauche à droite. Les spécifications sont sous la forme :

[!]name         Ce nom seulement
[!]:DEFAULT     Tous les noms dans @EXPORT
[!]:tag         Tous les noms dans le tableau anonyme $EXPORT_TAGS{tag}
[!]/pattern/    Tous les noms dans @EXPORT et @EXPORT_OK qui correspondent

Un ! initial indique que les noms correspondants doivent être supprimés de la liste des noms à importer. Si la première spécification est une suppression, elle est traitée comme si elle était précédée de :DEFAULT. Si vous voulez juste importer des noms supplémentaires en plus de l'ensemble par défaut, vous devrez quand même inclure :DEFAULT explicitement.

par exemple, Module.pm définit :

our @EXPORT      = qw(A1 A2 A3 A4 A5);
our @EXPORT_OK   = qw(B1 B2 B3 B4 B5);
our %EXPORT_TAGS = (T1 => [qw(A1 A2 B1 B2)], T2 => [qw(A1 A2 B3 B4)]);

Notez que vous ne pouvez pas utiliser de tags dans @EXPORT ou @EXPORT_OK.

Les noms dans EXPORT_TAGS doivent aussi apparaître dans @EXPORT ou @EXPORT_OK.

Une application utilisant Module peut dire quelque chose comme :

use Module qw(:DEFAULT :T2 !B3 A3);

D'autres exemples incluent :

use Socket qw(!/^[AP]F_/ !SOMAXCONN !SOL_SOCKET);
use POSIX  qw(:errno_h :termios_h !TCSADRAIN !/^EXIT/);

Rappelez-vous que la plupart des motifs (utilisant //) devront être ancrés avec un ^ initial, par exemple, "/^EXIT/" plutôt que "/EXIT/".

Vous pouvez dire "BEGIN { $Exporter::Verbose=1 }" pour voir comment les spécifications sont traitées et ce qui est réellement importé dans les modules.

Exporter sans utiliser la méthode import d'Exporter

Exporter a une méthode spéciale, 'export_to_level', qui est utilisée dans les situations où vous ne pouvez pas appeler directement la méthode import d'Exporter. La méthode export_to_level ressemble à :

MyPackage->export_to_level(
    $where_to_export, $package, @what_to_export
);

où $where_to_export est un entier indiquant à quel niveau remonter dans la pile d'appels pour exporter vos symboles, et @what_to_export est un tableau indiquant quels symboles *exporter* (habituellement c'est @_). L'argument $package est actuellement inutilisé.

Par exemple, supposez que vous avez un module, A, qui a déjà une fonction import :

package A;
our @ISA = qw(Exporter);
our @EXPORT_OK = qw($b);
sub import
{
    $A::b = 1;     # pas une méthode d'importation très utile
}

et vous voulez exporter le symbole $A::b vers le module qui a appelé le package A. Puisque Exporter dépend de la méthode import pour fonctionner, par héritage, en l'état Exporter::import() ne sera jamais appelé. À la place, dites ce qui suit :

package A;
our @ISA = qw(Exporter);
our @EXPORT_OK = qw($b);
sub import
{
    $A::b = 1;
    A->export_to_level(1, @_);
}

Cela exportera les symboles un niveau « au-dessus » du paquetage actuel, c'est-à-dire vers le programme ou le module qui a utilisé le paquetage

A.

Note : soyez prudent et ne modifiez pas @_ du tout avant d'appeler export_to_level - sinon les personnes utilisa

s résultats très incompréhensibles !

Quoi ne pas exporter

On vous a déjà mis en garde dans "Sélectionner quoi exporter" de ne pas exporter :

  • les noms de méthodes (parce que vous n'en avez pas besoin et que cela ne fera probablement pas ce que vous voulez),
  • quoi que ce soit par défaut (parce que vous ne voulez pas surprendre vos utilisateurs... violemment)
  • quoi que ce soit dont vous n'avez pas besoin (parce que moins, c'est plus)

Il y a un élément de plus à ajouter à cette liste. Ne exportez pas de noms de variables. Tout simplement parce que "Exporter" vous le permet, cela ne signifie pas que vous devriez le faire.

@EXPORT_OK = qw($svar @avar %hvar); # NE PAS FAIRE !

Exporter des variables n'est pas une bonne idée. Elles peuvent changer en interne, provoquant d'horribles effets à distance qui sont trop difficiles à suivre et à corriger. Faites-moi confiance : cela n'en vaut pas la peine.

Pour fournir la capacité de définir/récupérer des paramètres au niveau de la classe, il est préférable de fournir des accesseurs sous forme de sous-routines ou de méthodes de classe à la place.
