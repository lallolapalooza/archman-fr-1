ExtUtils::InstallPaths(3) Documentation Perl contribuée par les utilisateurs ExtUtils::InstallPaths(3)

NOM

ExtUtils::InstallPaths - La logique des chemins d'installation de Build.PL rendue facile

VERSION

version 0.015

RÉSUMÉ

use ExtUtils::InstallPaths;
use ExtUtils::Install 'install';
GetOptions(\my %opt, 'install_base=s', 'install_path=s%', 'installdirs=s', 'destdir=s', 'prefix=s', 'uninst:1', 'verbose:1');
my $paths = ExtUtils::InstallPaths->new(%opt, dist_name => $dist_name);
install($paths->install_map, $opt{verbose}, 0, $opt{uninst});

DESCRIPTION

Ce module tente de rendre la résolution des chemins d'installation aussi simple que possible.

Lorsque vous souhaitez installer un module, il doit déterminer où installer les choses. La version résumée du fonctionnement est que les emplacements d'installation par défaut sont déterminés par ExtUtils::Config, et ils peuvent être individuellement remplacés en utilisant l'attribut "install_path" . Un attribut "install_base" vous permet de spécifier une racine d'installation alternative comme /home/foo et "prefix" fait quelque chose de similaire d'une manière plutôt différente (et plus compliquée). "destdir" vous permet de spécifier un répertoire d'installation temporaire comme /tmp/install au cas où vous voudriez créer des paquets installables groupés.

Les types suivants sont pris en charge par défaut.

  • lib

    Généralement des fichiers de modules pure Perl se terminant par .pm ou .pod.

  • arch

    Fichiers de modules "dépendants de l'architecture", généralement produits en compilant du code XS, Inline, ou similaire.

  • script

    Programmes écrits en Perl pur. Afin d'améliorer la réutilisation, vous voudrez peut-être les rendre aussi petits que possible - mettez le code dans des modules quand c'est possible.

  • bin

    Programmes exécutables "dépendants de l'architecture", c'est-à-dire du code C compilé ou quelque chose de ce genre. C'est assez rare de voir cela dans une distribution perl, mais cela arrive.

  • bindoc

    Documentation pour les éléments dans "script" et "bin". Généralement générée à partir du POD dans ces fichiers. Sous Unix, ce sont des pages manuelles appartenant à la catégorie 'man1'. Sauf si défini explicitement, cela n'est disponible que sur les plateformes prenant en charge les pages man.

  • libdoc

    Documentation pour les éléments dans "lib" et "arch". C'est généralement généré à partir du POD dans les fichiers .pm et .pod . Sous Unix, ce sont des pages manuelles appartenant à la catégorie 'man3'. Sauf si défini explicitement, cela n'est disponible que sur les plateformes prenant en charge les pages man.

  • binhtml

    C'est la même chose que "bindoc" ci-dessus, mais s'applique aux documents HTML. Sauf si défini explicitement, cela n'est disponible que lorsque perl a été configuré pour le faire.

  • libhtml

    C'est la même chose que "libdoc" ci-dessus, mais s'applique aux documents HTML. Sauf si défini explicitement, cela n'est disponible que lorsque perl a été configuré pour le faire.

ATTRIBUTS

installdirs

Les destinations par défaut pour ces éléments installables proviennent des entrées dans la configuration de votre système. Vous pouvez choisir parmi trois ensembles différents d'emplacements par défaut en définissant le paramètre "installdirs" comme suit :

                        'installdirs' défini à :
                 core          site                vendor
            utilise les valeurs par défaut suivantes d'ExtUtils::Config :
lib     => installprivlib  installsitelib      installvendorlib
arch    => installarchlib  installsitearch     installvendorarch
script  => installscript   installsitescript   installvendorscript
bin     => installbin      installsitebin      installvendorbin
bindoc  => installman1dir  installsiteman1dir  installvendorman1dir
libdoc  => installman3dir  installsiteman3dir  installvendorman3dir
binhtml => installhtml1dir installsitehtml1dir installvendorhtml1dir [*]
libhtml => installhtml3dir installsitehtml3dir installvendorhtml3dir [*]
* Sous certains OS (par ex. MSWin32), la destination pour les documents HTML est déterminée par l'entrée C<installhtmldir> de C<Config.pm>.

La valeur par défaut de "installdirs" est "site".

install_base

Vous pouvez aussi définir tout l'ensemble des chemins d'installation en fournissant le paramètre "install_base" pour pointer vers un répertoire sur votre système. Par exemple, si vous définissez "install_base" sur "/home/ken" sur un système Linux, vous installerez comme suit :

lib     => /home/ken/lib/perl5
arch    => /home/ken/lib/perl5/i386-linux
script  => /home/ken/bin
bin     => /home/ken/bin
bindoc  => /home/ken/man/man1
libdoc  => /home/ken/man/man3
binhtml => /home/ken/html
libhtml => /home/ken/html

prefix

Cela définit un préfixe, identique à l'option PREFIX d'ExtUtils::MakeMaker. Cela fait quelque chose de similaire à "install_base" d'une manière beaucoup plus compliquée.

config()

L'objet ExtUtils::Config utilisé pour cet objet.

verbose

Le niveau de verbosité d'ExtUtils::InstallPaths. La valeur par défaut est 0.

create_packlist

En combinaison avec "module_name" cela contrôle si une liste de paquet (packlist) sera ajoutée ; la valeur par défaut est 1.

dist_name

Le nom du module actuel.

module_name

Le nom du module principal du paquet. C'est requis pour la création de la liste de paquet, mais à l'avenir cela pourrait être remplacé par dist_name. La valeur par défaut est "dist_name =~ s/-/::/gr" si dist_name est défini.

destdir

Si vous voulez d'abord tout installer dans un répertoire temporaire (par exemple, si vous voulez créer une arborescence de répertoires à partir de laquelle un gestionnaire de paquets comme "rpm" ou "dpkg" pourrait créer un paquet), vous pouvez utiliser le paramètre "destdir" . Par ex. Définir "destdir" sur "/tmp/foo" installera effectivement vers "/tmp/foo/$sitelib", "/tmp/foo/$sitearch", et ainsi de suite, sauf qu'il utilisera "File::Spec" pour faire fonctionner correctement les chemins sur la plateforme sur laquelle vous installez.

MÉTHODES

new

Crée un nouvel objet ExtUtils::InstallPaths. Tous les attributs sont des arguments valides pour le constructeur, ainsi que ceci :

  • install_path

    Doit être une référence de hachage avec les types comme clés et la destination comme valeurs.

  • install_base_relpaths

    Doit être une référence de hachage avec les types comme clés et un chemin relatif à l'install_base comme valeur.

  • prefix_relpaths

    Doit être une référence de hachage avec n'importe lequel de ces trois clés : core, vendor, site. Chacune des valeurs doit être une référence de hachage avec les types comme clés et un chemin relatif au préfixe comme valeur. Vous voudrez probablement rendre ces trois références de hachage identiques.

  • original_prefix

    Doit être une référence de hachage avec les valeurs légales d'installdirs comme clés et les répertoires de préfixe comme valeurs.

  • install_sets

    Doit être une référence de hachage avec les valeurs légales d'installdirs comme clés, et les valeurs étant des références de hachage avec les types comme cléseys et les emplacements comme valeurs.

install_map()

Retourne une carte utilisable avec ExtUtils::Install. Dans la plupart des cas, c'est la seule méthode dont vous aurez besoin.

install_destination($type)

Retourne la destination d'un certain type.

install_types()

Retourne une liste de tous les types d'installation pris en charge dans la configuration actuelle.

is_default_installable($type)

Étant donné un type de fichier, retournera vrai si le type de fichier serait normalement installé lorsque ni install-base ni prefix n'ont été définis. C'est-à-dire qu'il ne sera vrai que si le chemin est défini à partir de l'objet de configuration ou défini explicitement par l'utilisateur via install_path.

install_path($type)

Obtient le chemin d'installation pour un certain type.

install_sets($installdirs, $type)

Obtient le chemin pour un certain $type avec un certain $installdirs.

install_base_relpaths($type, $relpath)

Obtient les chemins relatifs à utiliser avec install_base pour un certain type.

prefix_relative($installdirs, $type)

Obtient le chemin d'un certain $type et $installdirs relatif au préfixe.

prefix_relpaths($install_dirs, $type)

Obtient le chemin relatif par défaut à utiliser dans le cas où les chemins d'installation de la configuration ne peuvent pas être rendus relatifs au préfixe. Vous ne voulez pas utiliser ceci pour obtenir un chemin relatif quelconque, mais vous pouvez avoir besoin de l'utiliser pour le définir pour des types personnalisés.

original_prefix($installdirs)

Obtient le préfixe original pour un certain type de $installdirs.
