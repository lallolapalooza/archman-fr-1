SANS TRY::TINY "Exception::Class" fournit du sucre syntaxique pour attraper des exceptions de

manière 
sûre :
eval {...};
if ( my $e = Exception::Class->caught('My::Error') ) {
    cleanup();
    do_something_with_exception($e);
}

La méthode "caught" prend un nom de classe et renvoie un objet d'exception si la dernière exception levée est de la classe donnée, ou d'une sous-classe de cette classe. Si aucun argument n'est donné, elle renvoie simplement $@

.

Vous devriez toujours faire une copie de l'objet d'exception, plutôt que d'utiliser $@ directement. C'est nécessaire car si votre "cleanup" fonction utilise "eval", ou appelle quelque chose qui l'utilise, alors $@ est écrasé. Copier l'exception le préserve pour l'appel à "do_something_with_exception"

.

Les objets d'exception fournissent également une méthode caught, vous pouvez donc écrire

: 
if ( my $e = My::Error->caught ) {
    cleanup();
    do_something_with_exception($e);
}

Exceptions non

interceptables

En interne, la méthode caught appellera "isa" sur l'objet d'exception. Vous pourriez rendre une exception « non interceptable » en redéfinissant "isa" dans cette classe comme ceci

: 
package Exception::Uncatchable;
sub isa { shift->rethrow
}

RECOMMANDATION

D'UTILISATION

Si vous créez un système complexe qui lance de nombreux types d'exceptions différents, envisagez de mettre toutes les déclarations d'exceptions dans un seul endroit. Pour une application appelée Foo, vous pourriez créer un module "Foo::Exceptions" et l'utiliser dans tout votre code. Ce module pourrait simplement contenir le code pour faire "Exception::Class" effectuer sa création automatique de classes. Cela vous permet de voir plus facilement quelles exceptions vous avez et facilite leur

suivi.

Cela pourrait ressembler à quelque chose comme ceci

: 
package Foo::Bar::Exceptions;
use Exception::Class (
    Foo::Bar::Exception::Senses =>
        { description => 'sense-related exception' },
    Foo::Bar::Exception::Smell => {
        isa         => 'Foo::Bar::Exception::Senses',
        fields      => 'odor',
        description => 'stinky!'
    },
    Foo::Bar::Exception::Taste => {
        isa         => 'Foo::Bar::Exception::Senses',
        fields      => [ 'taste', 'bitterness' ],
        description => 'like, gag me with a spoon!'
    },
    ...
)
;

Vous voudrez peut-être créer un vrai module pour sous-classer Exception::Class::Base également, en particulier si vous voulez que vos exceptions aient plus de

méthodes.

Sous-classer Exception::Class::

Base

Dans le cadre de votre utilisation de "Exception::Class", vous pouvez créer votre propre classe d'exception de base qui sous-classe Exception::Class::Base. Vous pouvez sous-classer librement l'une des méthodes documentées ci-dessus. Par exemple, vous pourriez vouloir sous-classer "new" pour ajouter des informat

ions supplément
aires à vos obje
ts d'exception.

Fonctions Exception::

Class

La méthode "Exception::Class" offre une fonction, "Classes", qui n'est pas exportée. Cette méthode retourne une liste des classes qui ont été créées en appelant la méthode "import" de "Exception::Class". Notez qu'il s'agit de toutes les sous-classes qui ont été créées, elles peuvent donc inclure des sous-classes créées par des modules CPAN, etc. Notez également que si vous définissez simplement une sous-classe via la méthode Perl normale en définissant @ISA ou "use base", votre sous-

classe ne ser
a pas incluse.
