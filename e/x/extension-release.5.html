Le

d'os-release est une liste d'assignations de variables compatibles avec les scripts shell, séparées par des

retours

à la ligne. Il est possible d'inclure la configuration dans des scripts Bourne shell, cependant, au-delà des simples assignations de variables, aucune fonctionnalité shell n'est prise en charge (ce qui signifie que l'expansion de variables n'est explicitement pas prise en charge), permettant aux applications de lire le fichier sans implémenter un moteur d'exécution compatible shell. Les valeurs des assignations de variables doivent être entourées de guillemets doubles ou simples si elles contiennent des espaces, des points-virgules ou d'autres caractères spéciaux en dehors de A–Z, a–z, 0–9. (Les assignations qui ne contiennent pas ces caractères spéciaux peuvent aussi être entourées de guillemets, mais c'est facultatif.) Les caractères spéciaux du shell ("$", guillemets, antislash, accent grave) doivent être échappés avec des antislashes, en suivant le style du shell. Toutes les chaînes doivent être en encodage UTF-8, et les caractères non imprimables ne doivent pas être utilisés. La concaténation de plusieurs chaînes individuellement entourées de guillemets n'est pas prise en charge. Les lignes commençant par "#" sont traitées comme des commentaires. Les lignes vides sont autorisées et ignorées. Le fichier /etc/os-release a la

priorité

sur /usr/lib/os-release. Les applications doivent vérifier le premier, et utiliser exclusivement ses données s'il existe, et ne recourir à /usr/lib/os-release que si celui-ci est manquant. Les applications ne doivent pas combiner les données des deux fichiers. /usr/lib/os-release est l'emplacement recommandé pour stocker les informations de version du système d'exploitation dans le cadre des arborescences de fournisseurs. /etc/os-release doit être un lien symbolique relatif vers /usr/lib/os-release, pour assurer la compatibilité avec les applications qui ne regardent que dans /etc/. Un lien symbolique relatif au lieu d'un lien symbolique absolu est nécessaire pour éviter de casser le lien dans un environnement chroot ou initrd. os-release

des données qui sont définies par le fournisseur du système d'exploitation et ne devraient généralement pas être modifiées par l'administrateur

RELEASE_TYPE

=
Une chaîne en minuscules (sans espaces ni autres caractères en dehors de 0-9, a-z, ".", "_" et "-"), décrivant le type de version de cette version du système d'exploitation. Les valeurs connues sont les suivantes :
•"stable" est pour les versions normales du système, adaptées à une utilisation en production. Généralement, les versions stables deviennent en fin de vie peu après la sortie de la prochaine version stable majeure, bien que ce ne soit pas le cas si, par exemple, une distribution adopte un modèle de version continue et reste toujours prête pour la production. Les exemples incluent Fedora 40, Ubuntu 23.10, OpenSUSE Tumbleweed et Arch
Linux.
•"lts" est pour les versions de support à long terme du système, adaptées à une utilisation en production et supportées pendant une période prolongée. Généralement, les versions LTS continuent de recevoir du support même si des versions majeures plus récentes de la distribution sont disponibles. Les exemples incluent Ubuntu 24.04, Debian 12 Bookworm et RHEL 9.
4.
•"development" est pour les versions instables du système, inadaptées à une utilisation en production, telles que les versions alpha, bêta ou continues instables. Les exemples incluent Fedora Rawhide, Debian Testing, Fedora 40 Beta et GNOME OS
Nightly.
•"experiment" est pour les versions expérimentales du système, créées spécifiquement pour tester une fonctionnalité en cours de développement. Cela est destiné à être utilisé en combinaison avec EXPERIMENT=

HOME_URL=, DOCUMENTATION_URL=, SUPPORT_URL=, BUG_REPORT_URL=, PRIVACY_POLICY_URL

=
Liens vers des ressources sur Internet liées au système d'exploitation. HOME_URL= devrait référencer la page d'accueil du système d'exploitation, ou alternativement une page d'accueil de la version spécifique du système d'exploitation. DOCUMENTATION_URL= devrait référencer la page de documentation principale pour ce système d'exploitation. SUPPORT_URL= devrait référencer la page de support principale pour le système d'exploitation, s'il y en a une. Cela est principalement destiné aux systèmes d'exploitation pour lesquels les fournisseurs offrent du support. BUG_REPORT_URL= devrait référencer la page principale de signalement de bogues pour le système d'exploitation, s'il y en a une. Cela est principalement destiné aux systèmes d'exploitation qui reposent sur une assurance qualité communautaire. PRIVACY_POLICY_URL= devrait référencer la page principale de la politique de confidentialité pour le système d'exploitation, s'il y en a une. Ces paramètres sont facultatifs, et il est courant de ne fournir que certains d'entre eux. Ces URL sont destinées à être exposées dans les interfaces "À propos de ce système" derrière des liens avec des légendes telles que "À propos de ce système d'exploitation", "Obtenir du support", "Signaler un bogue" ou "Politique de confidentialité". Les valeurs devraient être au format RFC3986[5], et devraient être des URL "http:" ou "https:", et éventuellement "mailto:" ou "tel:". Une seule URL doit être listée dans chaque paramètre. Si plusieurs ressources doivent être référencées, il est recommandé de fournir une page de destination en ligne liant toutes les ressources disponibles.

Exemples : "HOME_URL="https://fedoraproject.org/"", "BUG_REPORT_URL="https://bugzilla

.redhat
.com/"".

=
La date à laquelle le support pour cette version du système d'exploitation se termine. Par exemple, "SUPPORT_END=2001-01-01" signifie que le système a été supporté jusqu'à la fin du dernier jour du millénaire

DEFAULT_HOSTNAME

=
Une chaîne spécifiant le nom d'hôte si hostname(5) n'est pas présent et qu'aucune autre source de configuration ne spécifie le nom d'hôte. Doit être soit une étiquette DNS unique (une chaîne composée de caractères ASCII 7 bits en minuscules, sans espaces ni points, limitée au format autorisé pour les étiquettes de noms de domaine DNS), soit une séquence de telles étiquettes séparées par des points qui forme un FQDN DNS valide. Le nom d'hôte doit faire au plus 64 caractères, ce qui est une limitation de Linux (DNS autorise des noms plus longs).

Si le caractère point d'interrogation "?" apparaît dans le nom d'hôte, il est automatiquement remplacé par un caractère hexadécimal dérivé du machine-id(5) lorsqu'il est appliqué, de manière sécurisée et déterministe par hachage cryptographique. Exemple : "foobar-????-????" s'expandra automatiquement en "foobar-92a9-061c" ou similaire, selon l'identifiant de la machine

locale.

Voir org.freedesktop.hostname1(5) pour une description de la manière dont systemd-hostnamed.service(8) détermine le nom d'hôte de

secours.

Prend une liste d'au moins une chaîne séparée par des espaces parmi "system", "initrd" et "portable". Ce champ n'est pris en charge que dans les fichiers extension-release.d/ et indique les environnements auxquels l'extension système s'applique : c'est-à-dire aux systèmes réguliers, aux initrds et exitrds, ou aux images de services portables. Si non spécifié, "SYSEXT_SCOPE=system portable" est implicite, c'est-à-dire que toute extension système sans ce champ s'applique aux systèmes réguliers et aux environnements de services portables, mais pas aux environnements initrd/exitrd.

PORTABLE_PREFIXES

=
Prend une liste d'au moins une chaîne de correspondance de préfixe valide pour la logique des Services portables[3]. Ce champ sert deux objectifs : il est informatif, identifiant les images de services portables comme telles (et permettant ainsi de les distinguer des autres images du système d'exploitation, telles que les images système amorçables). Il est également utilisé lorsqu'une image de service portable est attachée : le préfixe de service portable spécifié ou implicite est vérifié par rapport à la liste spécifiée ici, pour faire respecter les restrictions sur la manière dont les images peuvent être attachées à un système.

import ast
import re
import sys
def read_os_release():
    try:
        filename = '/etc/os-release'
        f = open(filename)
    except FileNotFoundError:
        filename = '/usr/lib/os-release'
        f = open(filename)
    for line_number, line in enumerate(f, start=1):
        line = line.rstrip()
        if not line or line.startswith('#'):
            continue
        m = re.match(r'([A-Z][A-Z_0-9]+)=(.*)', line)
        if m:
            name, val = m.groups()
            if val and val[0] in '"\'':
                val = ast.literal_eval(val)
            yield name, val
        else:
            print(f'{filename}:{line_number}: bad line {line!r}',
                  file=sys.stderr)
