DESCRIPTIO

N

L'interface extcap (capture externe) est une interface de plugin polyvalente qui permet à des binaires externes d'agir comme des interfaces de capture directement dans Wireshark. Elle est utilisée dans les scénarios où la source de la capture n'est pas un modèle de capture traditionnel (capture en direct depuis une interface, depuis un tube, depuis un fichier, etc.). L'exemple typique est la connexion de matériel exotique d'un certain type à l'application principale

Wireshark.

Sans extcap, une capture peut toujours être réalisée en écrivant directement dans un fichier de capture

: 
the-esoteric-binary --the-strange-f
lag --interface=stream1 --file dump
file.pcap & wireshark dumpfile.pcap

mais l'interface extcap permet d'établir et de configurer facilement une telle connexion à l'aide de l'interface graphique de

Wireshark.

Le sous-système extcap est composé de plusieurs binaires extcap qui sont automatiquement appelés par l'interface graphique à la suite. Dans les chapitres suivants, nous les appellerons « les extcaps »

.

Les extcaps peuvent être n'importe quel binaire ou script dans les répertoires extcap/wireshark ou extcap/stratoshark. Veuillez noter que les scripts doivent être exécutables sans préfixer un interprète de script avant

l'appel.

UTILISATEURS WINDOWS : En raison des restrictions, l'appel direct du script peut ne pas toujours fonctionner. Dans un tel cas, un fichier batch peut être fourni, qui exécute alors le script. Veuillez consulter doc/extcap_example.py pour plus

d'informations.

Lorsque Wireshark lance un extcap, il ajoute automatiquement son chemin d'installation (normalement C:\Program Files\Wireshark\) au chemin de recherche des DLL afin que les dépendances de la bibliothèque extcap puissent être trouvées (il n'est pas conçu pour être lancé manuellement). C'est fait exprès. Il n

e devrait y avoir que des programmes extcap (exécutables, scripts Python, ...) dans le dossier extcap po
ur réduire le temps de démarrage et éviter que Wireshark n'essaie d'exécuter d'autres types de fichiers.

CHAMP

TABLE

Le champ « table » est un peu différent, car ses valeurs peuvent avoir des options de configuration supplémentaires. Les valeurs peuvent soit être saisies manuellement par l'utilisateur, soit une liste de valeurs disponibles peut être fournie en utilisant la même API que « multicheck ». Contrairement à la plupart des API, la valeur est fournie en utilisant une API de type ligne de commande, séparée par des espaces au lieu de virgules. Par exemple, un attribut « myparam » configuré où l'utilisateur a sélectionné trois valeurs (1, 2 et 3) recevrait

: 
--mypa
ram "
1 2 3"

Si un « prefix » est configuré pour être « --p », il recevrait ce qui suit

: 
--myparam
"--p 1 --
p 2 --p 3"

Les valeurs sélectionnées dans un champ de tableau peuvent avoir des options de configuration spécifiques, si « configurable=true » pour le champ « multicheck ». Dans ce cas, l'extcap sera à nouveau appelé lorsque l'utilisateur appuie sur la roue de configuration qui correspond à une valeur dans le tableau, avec l'argument supplémentaire « --extcap-config-option-name <option_name> --extcap-config-option-value <option_value> » sans préfixe. Un programme extcap doit répondre avec un ensemble supplémentaire d'arguments, qui seront ouverts dans une fenêtre contextuelle. Une fois ceux-ci configurés, l'extcap pourrait recevoir ce qui suit, en supposant par exemple qu'un « param1 » supplémentaire est demandé quand la valeur est 1, et « param2 » quand la valeur est

2. 
--myparam "--p
1 --param1 1
--p 2 --para
m2 true --p 3"
