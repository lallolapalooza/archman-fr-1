EXEC(1P) Manuel du programmeur POSIX EXEC(1P)

PROLOG

Cette page de manuel fait partie du Manuel du programmeur POSIX. L'implémentation Linux de cette interface peut différer (consultez la page de manuel Linux correspondante pour les détails du comportement sous Linux), ou l'interface peut ne pas être implémentée sous Linux.

NOM

exec — exécute des commandes et ouvre, ferme ou copie des descripteurs de fichiers

SYNTAXE

exec [commande [argument...]]

DESCRIPTION

L'utilitaire exec ouvre, ferme et/ou copie des descripteurs de fichiers comme spécifié par toute redirection dans le cadre de la commande.

Si exec est spécifié sans commande ou arguments, et si des descripteurs de fichiers dont les numéros sont supérieurs à 2 sont ouverts avec des instructions de redirection associées, il est indéterminé si ces descripteurs de fichiers restent ouverts lorsque le shell invoque un autre utilitaire. Les scripts concernés par le fait que les shells enfants puissent abuser de descripteurs de fichiers ouverts peuvent toujours les fermer explicitement, comme montré dans l'un des exemples suivants.

Si exec est spécifié avec commande, il remplace le shell par commande sans créer de nouveau processus. Si des arguments sont spécifiés, ils sont transmis comme arguments à commande. La redirection affecte l'environnement d'exécution du shell actuel.

Aucune.

Voir la DESCRIPTION.

SORTIE STANDARD

Non utilisé.

ERREUR STANDARD

L'erreur standard est utilisée uniquement pour les messages de diagnostic.

FICHIERS DE SORTIE

Aucun.

DESCRIPTION ÉTENDUE

Aucune.

STATUT DE SORTIE

Si commande est spécifiée, exec ne doit pas retourner au shell ; au contraire, le statut de sortie du processus sera le statut de sortie du programme implémentant commande, qui a remplacé le shell. Si commande n'est pas trouvée, le statut de sortie sera 127. Si commande est trouvée, mais qu'il ne s'agit pas d'un utilitaire exécutable, le statut de sortie sera 126. Si une erreur de redirection se produit (voir Section 2.8.1, Conséquences des erreurs du shell), le shell se terminera avec une valeur comprise entre 1 et 125. Sinon, exec retournera un statut de sortie de zéro.

CONSÉQUENCES DES ERREURS

Par défaut.

Les sections suivantes sont informatives.

UTILISATION PAR LES APPLICATIONS

Aucune.

EXEMPLES

Ouvrir readfile comme descripteur de fichier 3 en lecture :

exec 3< readfile

Ouvrir writefile comme descripteur de fichier 4 en écriture :

exec 4> writefile

Faire de writefile une copie du descripteur de fichier 0 :

exec 5<&0

Fermer le descripteur de fichier 3 :

exec 3<&-

Afficher le fichier maggie en remplaçant le shell actuel par l'utilitaire cat :

exec cat maggie

RATIONALE

La plupart des implémentations historiques n'étaient pas conformes dans le sens où :

foo=bar exec cmd

ne passait pas foo à cmd.
