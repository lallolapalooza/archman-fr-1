exec(3) Manuel des fonctions de bibliothèque exec(3)

NOM

execl, execlp, execle, execv, execvp, execvpe - exécuter un fichier

BIBLIOTHÈQUE

Bibliothèque C standard (libc, -lc)

SYNTAXE

#include <unistd.h>
extern char **environ;
int execl(const char *path, const char *arg, ...
                /*, (char *) NULL */);
int execlp(const char *file, const char *arg, ...
                /*, (char *) NULL */);
int execle(const char *path, const char *arg, ...
                /*, (char *) NULL, char *const envp[] */);
int execv(const char *path, char *const argv[]);
int execvp(const char *file, char *const argv[]);
int execvpe(const char *file, char *const argv[], char *const envp[]);

DESCRIPTION

La famille de fonctions exec() remplace l'image du processus courant par une nouvelle image de processus. Les fonctions décrites dans ce manuel sont basées sur execve(2). (Voir le manuel de execve(2) pour plus de détails sur le remplacement de l'image du processus courant.)

Le premier argument de ces fonctions est le nom d'un fichier qui doit être exécuté.

Les fonctions peuvent être regroupées en fonction des lettres suivant le préfixe "exec".

l - execl(), execlp(), execle()

Le const char *arg et les points de suspension suivants peuvent être considérés comme arg0, arg1, ..., argn. Ensemble, ils décrivent une liste d'un ou plusieurs pointeurs vers des chaînes de caractères terminées par un caractère nul qui représentent la liste d'arguments disponible pour le programme exécuté. Le premier argument, par convention, doit pointer vers le nom de fichier associé au fichier en cours d'exécution. La liste des arguments doit être terminée par un pointeur nul, et, étant donné qu'il s'agit de fonctions variadiques, ce pointeur doit être casté en (char *) NULL.

Par contraste avec les fonctions 'l', les fonctions 'v' (ci-dessous) spécifient les arguments de la ligne de commande du programme exécuté sous forme de vecteur.

v - execv(), execvp(), execvpe()

L'argument char *const argv[] est un tableau de pointeurs vers des chaînes de caractères terminées par un caractère nul qui représentent la liste d'arguments disponible pour le nouveau programme. Le premier argument, par convention, doit pointer vers le nom de fichier associé au fichier en cours d'exécution. Le tableau de pointeurs doit être terminé par un pointeur nul.

e - execle(), execvpe()

L'environnement de la nouvelle image de processus est spécifié via l'argument envp. L'argument envp est un tableau de pointeurs vers des chaînes de caractères terminées par un caractère nul et doit être terminé par un pointeur nul.

Toutes les autres fonctions exec() (qui n'incluent pas 'e' dans le suffixe) prennent l'environnement de la nouvelle image de processus à partir de la variable externe environ du processus appelant.

p - execlp(), execvp(), execvpe()

Ces fonctions dupliquent les actions du shell lors de la recherche d'un fichier exécutable si le nom de fichier spécifié ne contient pas de caractère slash (/). Le fichier est recherché dans la liste de chemins de répertoires séparés par des deux-points spécifiée dans la variable d'environnement PATH. Si cette variable n'est pas définie, la liste des chemins est par défaut une liste incluant les répertoires retournés par confstr(_CS_PATH) (qui retourne généralement la valeur "/bin:/usr/bin") et éventuellement aussi le répertoire de travail courant ; voir VERSIONS pour plus de détails.

execvpe() recherche le programme en utilisant la valeur de PATH de l'environnement de l'appelant, et non à partir de l'argument envp.

Si le nom de fichier spécifié inclut un caractère slash, alors PATH est ignoré, et le fichier au chemin spécifié est exécuté.

De plus, certaines erreurs sont traitées spécialement.

Si la permission est refusée pour un fichier (la tentative de execve(2) a échoué avec l'erreur EACCES), ces fonctions continueront à rechercher dans le reste du chemin de recherche. Si aucun autre fichier n'est trouvé, cependant, elles retourneront avec errno défini à EACCES.

Si l'en-tête d'un fichier n'est pas reconnu (la tentative de execve(2) a échoué avec l'erreur ENOEXEC), ces fonctions exécuteront le shell (/bin/sh) avec le chemin du fichier comme premier argument. (Si cette tentative échoue, aucune recherche supplémentaire n'est effectuée.)

Toutes les autres fonctions exec() (qui n'incluent pas 'p' dans le suffixe) prennent comme premier argument un chemin (relatif ou absolu) qui identifie le programme à exécuter.

VALEUR DE RETOUR

Les fonctions exec() ne retournent que si une erreur s'est produite. La valeur de retour est -1, et errno est défini pour indiquer l'erreur.

ERREURS

Toutes ces fonctions peuvent échouer et définir errno pour chacune des erreurs spécifiées pour execve(2).

VERSIONS

Le chemin de recherche par défaut (utilisé lorsque l'environnement ne contient pas la variable PATH) montre quelques variations entre les systèmes. Il inclut généralement /bin et /usr/bin (dans cet ordre) et peut également inclure le répertoire de travail courant. Sur certains autres systèmes, le répertoire de travail courant est inclus après /bin et /usr/bin, comme mesure anti-cheval de Troie. L'implémentation glibc a longtemps suivi la convention par défaut où le répertoire de travail courant est inclus au début du chemin de recherche. Cependant, certains refactorings de code lors du développement de glibc 2.24 ont entraîné la suppression complète du répertoire de travail courant du chemin de recherche par défaut. Ce changement de comportement accidentel est considéré comme légèrement bénéfique et ne sera pas annulé.

Le comportement de execlp() et execvp() en cas d'erreurs lors de la tentative d'exécution du fichier est une pratique historique, mais n'a pas été traditionnellement documenté et n'est pas spécifié par la norme POSIX. BSD (et potentiellement d'autres systèmes) effectuent une mise en veille et une nouvelle tentative si ETXTBSY est rencontré. Linux le traite comme une erreur fatale et retourne immédiatement.

Traditionnellement, les fonctions execlp() et execvp() ignoraient toutes les erreurs sauf celles décrites ci-dessus et ENOMEM et E2BIG, sur lesquelles elles retournaient. Elles retournent maintenant si une erreur autre que celles décrites ci-dessus se produit.
