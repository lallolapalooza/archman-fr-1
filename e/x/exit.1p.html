EXIT(1P) Manuel du programmeur POSIX EXIT(1P)

PROLOGUE

Cette page man fait partie du Manuel du programmeur POSIX. L'implémentation Linux de cette interface peut différer (consultez la page man Linux correspondante pour les détails du comportement de Linux), ou l'interface peut ne pas être implémentée sur Linux.

NOM

exit — faire quitter le shell

SYNOPSIS

exit [n]

DESCRIPTION

L'utilitaire exit doit faire quitter le shell de son environnement d'exécution courant avec le code de sortie spécifié par l'entier décimal non signé n. Si l'environnement d'exécution courant est un environnement de sous-shell, le shell doit quitter l'environnement de sous-shell avec le code de sortie spécifié et continuer dans l'environnement à partir duquel cet environnement de sous-shell a été invoqué ; sinon, l'utilitaire shell doit se terminer avec le code de sortie spécifié. Si n est spécifié, mais que sa valeur n'est pas comprise entre 0 et 255 inclusivement, le code de sortie est indéfini.

Un piège sur EXIT doit être exécuté avant que le shell ne se termine, sauf lorsque l'utilitaire exit est invoqué dans ce piège lui-même, auquel cas le shell doit quitter immédiatement.

OPTIONS

Aucune.

OPÉRANDS

Voir la DESCRIPTION.

STDIN

Non utilisé.

FICHIERS D'ENTRÉE

Aucun.

VARIABLES D'ENVIRONNEMENT

Aucune.

ÉVÉNEMENTS ASYNCHRONES

Par défaut.

STDOUT

Non utilisé.

STDERR

L'erreur standard doit être utilisée uniquement pour les messages de diagnostic.

FICHIERS DE SORTIE

Aucun.

DESCRIPTION ÉTENDUE

Aucune.

CODE DE SORTIE

Le code de sortie doit être n, s'il est spécifié, sauf que le comportement est indéfini si n n'est pas un entier décimal non signé ou est supérieur à 255. Sinon, la valeur doit être la valeur de sortie de la dernière commande exécutée, ou zéro si aucune commande n'a été exécutée. Lorsque exit est exécuté dans une action de piège , la dernière commande est considérée comme étant celle qui a été exécutée immédiatement avant l'action de piège .

CONSÉQUENCES DES ERREURS

Par défaut.

Les sections suivantes sont informatives.

UTILISATION PAR LES APPLICATIONS

Aucune.

EXEMPLES

Quitter avec une valeur vraie :

exit 0

Quitter avec une valeur fausse :

exit 1

Propager la gestion des erreurs depuis un sous-shell :

(
    command1 || exit 1
    command2 || exit 1
    exec command3
) > outputfile || exit 1
echo "outputfile created successfully"

JUSTIFICATION

Comme expliqué dans d'autres sections, certaines valeurs de code de sortie ont été réservées à des usages spéciaux et ne doivent être utilisées par les applications que pour ces usages :

126
Un fichier à exécuter a été trouvé, mais ce n'était pas un utilitaire exécutable.
127
Un utilitaire à exécuter n'a pas été trouvé.
>128
Une commande a été interrompue par un signal.

Le comportement de exit lorsqu'un argument invalide ou une option inconnue est donné est indéfini, en raison des pratiques différentes dans les diverses implémentations historiques. Une valeur supérieure à 255 pourrait être tronquée par le shell, et être indisponible même pour un processus parent qui utilise waitid() pour obtenir la valeur de sortie complète. Il est recommandé que les implémentations qui détectent une erreur d'utilisation quelconque provoquent un code de sortie non nul (ou, si le shell est interactif et que l'erreur ne cause pas l'interruption du shell, stocker une valeur non nulle dans "$?"), mais même cela n'a pas été fait historiquement dans tous les shells.
