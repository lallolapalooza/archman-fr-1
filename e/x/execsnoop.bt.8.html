NOM

execsnoop.bt - Trace les nouveaux processus via les appels système exec(). Utilise bpftrace/eBPF.

SYNOPIS

execsnoop.bt

DESCRIPTION

Ceci trace les appels à exec() (execve()). C'est utile pour identifier les nouveaux processus créés via la séquence habituelle fork()->exec(). Notez que la valeur de retour n'est pas actuellement tracée, donc l'appel exec() peut avoir échoué.

Cet outil est utile pour déboguer les scripts shell, y compris le démarrage des applications. Il est également utile pour identifier un type de problème de performance : un flot de processus de courte durée, qui se terminent rapidement et ne sont pas facilement visibles dans top(1).

Étant donné que cela utilise BPF, seul l'utilisateur root peut utiliser cet outil.

EXIGENCES

CONFIG_BPF et bpftrace.

EXEMPLES

Tracer tous les nouveaux processus appelant execve() :
# execsnoop.bt

CHAMPS

HEURE
Heure de l'appel exec(), en millisecondes depuis le début du programme.
PID
Identifiant du processus
PPID
Identifiant du processus parent
ARGS
Nom du processus et arguments (16 mots maximum).

SURCHARGE

Ceci trace le point de trace execve() et affiche la sortie pour chaque événement. Étant donné que le taux de ces événements est généralement faible (< 100/s), la surcharge est également attendue comme négligeable. Si vous avez une application qui génère un grand nombre de nouveaux processus pour une raison quelconque (grand processus de compilation), cela pourrait causer une légère surcharge : testez et comprenez la surcharge avant utilisation.

SOURCE

Ceci provient de bpftrace.

https://github.com/bpftrace/bpftrace

Consultez également la distribution bpftrace pour un fichier _examples.txt compagnon contenant des exemples d'utilisation, de sortie et des commentaires pour cet outil.

Il s'agit d'une version bpftrace de l'outil bcc du même nom. L'outil bcc fournit plus de champs et d'options pour personnaliser la sortie.

https://github.com/iovisor/bcc
