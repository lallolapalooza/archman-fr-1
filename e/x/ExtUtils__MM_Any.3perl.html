DESCRIPTIO

N

POUR USAGE INTERNE UNIQUEMENT

!

ExtUtils::MM_Any est une superclasse pour l'ensemble de modules ExtUtils::MM_*. Elle contient des méthodes qui sont soit intrinsèquement multiplateformes, soit écrites de manière multiplateforme

.

Héritez d'ExtUtils::MM_Any et d'ExtUtils::MM_Unix. Ceci est une solution

temporaire.

CECI PEUT

ÊTRE TEM
PORAIRE !

S

sous-classes.

Méthodes auxiliaires multiplateforme

s

Ce sont des méthodes qui aident à écrire du code multiplateforme

.

os_flavor

Abstraite 
my @os_flavor = $mm->
os_flavor;

@os_flavor est le style de système d'exploitation de celui-ci, correspondant généralement au fichier MM_*.pm que nous

utilisons.

Le premier élément de @os_flavor est la famille principale (c'est-à-dire Unix, Windows, VMS, OS/2, etc.) et les autres sont des

sous-familles.

Quelques exemples

: 
Cygwin98       ('Unix',  'Cygwin', 'Cygwin9x')
Windows        ('Win32')
Win98          ('Win32', 'Win9x')
Linux          ('Unix',  'Linux')
MacOS X        ('Unix',  'Darwin', 'MacOS', 'MacOS X')
OS/2
('OS/2')

Ceci est utilisé pour écrire du code pour des styles de systèmes d'exploitation. Voir os_flavor_is() pour l'u

tilisation.

os_flavor_i

s 
my $is_this_flavor = $mm->os_flavor_is($this_flavor);
my $is_this_flavor = $mm->os_flavor_is(@one_of_these_flavors)
;

Vérifie si le système d'exploitation actuel est l'une des saveurs

données.

Ceci est utile pour du code comme

: 
if( $mm->os_flavor_is('Unix') ) {
    $out = `foo 2>&1`;
}
else {
    $out = `foo`;
}

can_ru

n 
use ExtUtils::MM;
my $runnable = MM->can_run($Config{make})
;

Si appelé dans un contexte scalaire, il renverra le chemin complet vers le binaire demandé s'il a été trouvé, ou "undef" s'il ne l'a pas

été.

Si appelé dans un contexte liste, il renverra une liste des chemins complets vers les instances du binaire trouvées dans "PATH", ou une liste vide s'il n'a pas été

trouvé.

Copié depuis IPC::Cmd, mais modifié en méthode (et la fonctionnalité $INSTANCES a été supprimée)

.

quote_de

p 
$text = $mm->quote_dep($text)
;

Méthode qui protège les constantes à valeur unique du Makefile (principalement les noms de fichiers), afin que make les traite toujours comme des valeurs uniques même si elles contiennent malheureusement des espaces. Si le programme make utilisé ne peut pas réaliser une telle protection et que le texte donné en aurait besoin, une exception est

levée.

split_comman

d 
my @cmds = $MM->split_command($cmd, @args)
;

La plupart des systèmes d'exploitation ont une longueur de commande maximale qu'ils peuvent exécuter à la fois. Les grands modules peuvent facilement générer des commandes bien au-delà de cette limite. Il est nécessaire de diviser les longues commandes en une série de commandes plus

courtes.

"split_command" renverra une série de @cmds, chacune traitant une partie des arguments. Collectivement, elles traiteront tous les arguments. Chaque ligne individuelle dans @cmds ne sera pas plus longue que $self->max_exec_len, en prenant soin de prendre en compte l'expansion des

macros.

$cmd devrait inclure tous les commutateurs et les arguments initiaux répétés. S'il contient des sauts de ligne, ils devraient déjà être

échappés.

Si aucun @args n'est donné, aucun @cmds ne sera

renvoyé.

Les paires d'arguments seront toujours préservées dans une seule commande, ceci est une heuristique pour des choses comme pm_to_blib et pod2man qui fonctionnent par paires d'arguments. Cela rend des choses comme celle-ci sûres

: 
$self->split_command($cmd, %pod2man)
;

stashmet

a 
my @recipelines = $MM->stashmeta($text, $file)
;

Génère un ensemble de @recipelines qui feront que le texte littéral $text se retrouve dans le fichier littéral $file lorsque la recette est exécutée. Appelez-le une fois, avec tout le texte que vous voulez dans $file. Les macros make ne seront pas développées, donc les emplacements seront fixés au moment de la configuration (configure-time), et non au moment de la construction (build-time)

.

ech

o 
my @commands = $MM->echo($text);
my @commands = $MM->echo($text, $file);
my @commands = $MM->echo($text, $file, \%opts)
;

Génère un ensemble de @commands qui impriment le $text dans un $file

.

Si $file n'est pas donné, la sortie va vers

STDOUT.

Si $opts{append} est vrai, le $file sera ajouté (append) plutôt qu'écrasé. Par défaut, c'est

écraser.

Si $opts{allow_variables} est vrai, les variables make de la forme "$(...)" ne seront pas échappées. Les autres "$" le seront. Par défaut, c'est échapper tous les "$"

.

Exemple d'utilisation

: 
my $make = join '', map "\t$_\n", $MM->echo($text, $file)
;

maketext_filte

r 
my $filter_make_text = $mm->maketext_filter($make_text)
;

Le texte du Makefile passe par cette méthode avant d'être écrit sur disque. Elle permet aux systèmes de faire des corrections de portabilité sur le

Makefile.

Par défaut, elle ne fait

rien.

Cette méthode est protégée et n'est pas destinée à être appelée en dehors de

MakeMaker.

cd

Abstraite 
my $subdir_cmd = $MM->cd($subdir, @cmds)
;

Cela générera un fragment de make qui exécute les @cmds dans le $dir donné. L'équivalent approximatif de cela, mais multiplateforme

. 
cd $subdir &&
$cmd

Actuellement, $dir ne peut descendre que d'un niveau. "foo" est bien. "foo/bar" ne l'est pas. "../foo" est hors de

question.

Le $subdir_cmd résultant n'a ni tabulation initiale ni saut de ligne final. Cela facilite son intégration dans une chaîne make. Par

exemple. 
    my $make = sprintf <<'CODE', $subdir_cmd;
foo :
    $(ECHO) what
    %s
    $(ECHO) mouche
CODE

oneliner

Abstraite 
my $oneliner = $MM->oneliner($perl_code);
my $oneliner = $MM->oneliner($perl_code, \@switches)
;

Cela générera une ligne de commande perl (one-liner) sûre pour la plateforme particulière sur laquelle vous êtes, basée sur le $perl_code donné et les @switches (un -e est supposé) adaptée à l'utilisation dans une cible make. Elle utilisera le guillemetage et les échappements shell

appropriés.

$(PERLRUN) sera utilisé comme

perl.

Toute nouvelle ligne dans $perl_code sera échappée. Les nouvelles lignes de début et de fin seront supprimées. Rend cet idiome beaucoup plus facile

: 
    my $code = $MM->oneliner(<<'CODE', [...switches...]);
some code here
another line here
CODE

L'utilisation pourrait ressembler à

: 
# an echo emulation
$oneliner = $MM->oneliner('print "Foo\n"');
$make = '$oneliner >
somefile';

Les signes dollar dans le $perl_code seront protégés de make en utilisant la méthode "quote_literal", sauf s'ils sont reconnus comme étant une variable make, "$(varname)", auquel cas ils seront laissés pour que make les développe. N'oubliez pas de mettre les macros make entre guillemets, sinon elles pourraient être utilisées comme mot simple. Par exemple

: 
# Assign the value of the $(VERSION_FROM) make macro to $vf.
$oneliner = $MM->oneliner('$vf = "$(VERSION_FROM)"')
;

C'est actuellement très simple, et cela pourrait être étendu à l'avenir pour inclure du code et des options plus

flexibles.

quote_literal

Abstrait 
my $safe_text = $MM->quote_literal($text);
my $safe_text = $MM->quote_literal($text, \%options)
;

Cela mettra entre guillemets $text pour qu'il soit interprété littéralement dans le

shell.

Par exemple, sur Unix, cela échapperait toutes les apostrophes dans $text et entourerait l'ensemble

d'apostrophes.

Si $options{allow_variables} est vrai, cela laissera les variables make '$(FOO)' intactes. Si faux, elles seront échappées comme n'importe quel autre "$". Par défaut, c'est

vrai.

init_DIRFILESEP

Résumé 
$MM->init_DIRFILESEP;
my $dirfilesep = $MM->{DIRFILESEP}
;

Initialise la macro DIRFILESEP qui est le séparateur entre le répertoire et le nom de fichier dans un chemin. Par exemple : / sur Unix, \ sur Win32 et rien sur

VMS.

Par exemple

: 
# au lieu de $(INST_ARCHAUTODIR)/extralibs.ld
$(INST_ARCHAUTODIR)$(DIRFILESEP)extralibs.
ld

C'est un peu un hack mais cela évite beaucoup de duplication de code entre les variantes

MM_*.

N'utilisez pas ceci comme séparateur entre répertoires. Certains systèmes d'exploitation utilisent des séparateurs différents entre sous-répertoires qu'entre répertoires et noms de fichiers (par exemple : VOLUME:[dir1.dir2]fichier sur VMS)

.
