DESCRIPTIO

N

La fonction ef_expand_file() fait partie de la bibliothèque tecla (voir la page man libtecla(3)). Elle développe un nom de fichier spécifié, en convertissant ~user/ et ~/ au début du nom de fichier en les répertoires personnels correspondants, en remplaçant $envvar par la valeur de la variable d'environnement correspondante, puis, s'il y a des caractères génériques, en les faisant correspondre avec les noms de fichiers existants. Les antislashs dans le nom de fichier d'entrée sont interprétés comme échappant les significations spéciales des caractères qui les suivent. Seuls les antislashs qui sont eux-mêmes précédés par des antislashs sont conservés dans le nom de fichier

développé.

En présence de caractères génériques, la liste renvoyée de noms de fichiers inclut uniquement les noms des fichiers existants qui correspondent aux caractères génériques. Sinon, le nom de fichier original est renvoyé après le développement des expressions tilde et dollar, et le résultat n'est pas vérifié par rapport aux fichiers existants. Cela imite le comportement de globbing de fichiers du shell unix tcsh

.

Les caractères génériques pris en charge et leurs significations sont

: 
  *        -  Correspond à toute séquence de zéro ou plusieurs caractères.
  ?        -  Correspond à n'importe quel caractère unique.
  [chars]  -  Correspond à n'importe quel caractère unique qui apparaît dans
              'chars'. Si 'chars' contient une expression de
              la forme a-b, alors n'importe quel caractère entre a et
              b, y compris a et b, correspond. Le caractère '-'
              perd sa signification spéciale en tant que
              spécificateur de plage lorsqu'il apparaît au début
              de la séquence de caractères. Le caractère ']'
              perd également sa signification en tant que
              terminateur de l'expression de plage s'il
              apparaît immédiatement après le '[' d'ouverture, au
             quel cas il est traité comme l'un des
              caractères de la plage. Si vous voulez à la fois '-'
              et ']' faire partie de la plage, le '-'
              devrait venir en premier et le ']' en second.
  [^chars] -  Identique à [chars] sauf qu'il correspond à n'importe quel
              caractère unique qui n'apparaît pas dans
'chars'.

Notez que les caractères génériques ne correspondent jamais au point initial dans les noms de fichiers qui commencent par '.'. Le '.' initial doit être explicitement spécifié dans le nom de fichier. Cela imite à nouveau le comportement de globbing de la plupart des shells unix, et sa justification est basée sur le fait que dans unix, les fichiers dont les noms commencent par '.' sont généralement des fichiers de configuration cachés, qui ne sont pas listés par défaut par la commande

ls.

Voici un exemple complet de la manière d'utiliser la fonction de développement de

fichiers. 
  #include <stdio.h>
  #include <libtecla.h>
  int main(int argc, char *argv[])
  {
    ExpandFile *ef;      /* L'objet ressource d'expansion */
    char *filename;      /* Le nom de fichier en cours de développement */
    FileExpansion *expn; /* Les résultats du développement */
    int i;
    ef = new_ExpandFile();
    if(!ef)
      return 1;
    for(arg = *(argv++); arg; arg = *(argv++)) {
      if((expn = ef_expand_file(ef, arg, -1)) == NULL) {
        fprintf(stderr, "Erreur lors du développement de %s (%s).\n", arg,
                         ef_last_error(ef));
      } else {
        printf("%s correspond aux fichiers suivants :\n", arg);
        for(i=0; i<expn->nfile; i++)
          printf(" %s\n", expn->files[i]);
      }
    }
    ef = del_ExpandFile(ef);
    return 0;
}

La fonction ef_expand_file() effectue le développement de noms de fichiers, comme documenté au début de cette section. Son premier argument est un objet ressource renvoyé par new_ExpandFile(). Un pointeur vers le début du nom de fichier à mettre en correspondance est passé via l'argument path. Cela doit être une chaîne normale terminée par NUL, mais sauf si une longueur de -1 est passée dans pathlen, seuls les premiers caractères pathlen seront utilisés dans le développement du nom de fichier. Si la longueur est spécifiée comme -1, toute la chaîne sera

développée.

La fonction renvoie un pointeur vers un conteneur dont le contenu est le résultat du développement. S'il n'y avait pas de caractères génériques dans le nom de fichier, le membre nfile sera 1, et le membre exists devrait être interrogé s'il est important de savoir si le fichier développé existe actuellement ou non. S'il y avait des caractères génériques, alors le tableau files[] contenu contiendra les noms des fichiers existants nfile qui correspondaient au nom de fichier avec caractères génériques, et le membre exists aura la valeur 1. Notez que le conteneur renvoyé appartient à l'objet ef spécifié, et son contenu changera à chaque appel, donc si vous devez conserver les résultats de plus d'un appel à ef_expand_file(), vous devriez soit faire une copie privée des résultats renvoyés, soit créer plusieurs objets ressource d'expansion de fichiers via plusieurs appels à new_ExpandF

ile().

En cas d'erreur, NULL est renvoyé, et une explication de l'erreur peut être obtenue en appelant ef_last_erro

r(ef).

  int ef_list_expansions(FileExpansion *result, FILE *fp,
                         int terminal_width)
;

La fonction ef_list_expansions() fournit un moyen pratique de lister les développements de noms de fichiers renvoyés par ef_expand_file(). Comme la commande unix ls, elle arrange les noms de fichiers en colonnes de largeur égale, chaque colonne ayant la largeur du fichier le plus grand. Le nombre de colonnes utilisées est ainsi déterminé par la longueur du nom de fichier le plus long et la largeur de terminal spécifiée. Attention, les noms de fichiers plus longs que la largeur de terminal spécifiée sont imprimés sans être tronqués, de sorte qu'une sortie plus longue que la largeur de terminal spécifiée peut survenir. La liste est écrite dans le flux stdio spécifié par l'argument fp

.

SÉCURITÉ DES

THREADS

Dans les programmes multi-threadés, vous devriez utiliser la version libtecla_r.a de la bibliothèque. Celle-ci utilise les fonctions réentrantes POSIX lorsqu'elles sont disponibles (d'où le suffixe _r), et désactive les fonctionnalités qui reposent sur des fonctions système non réentrantes. Actuellement, aucune fonctionnalité n'est désactivée dans ce

module.

En utilisant la version libtecla_r.a de la bibliothèque, il est sûr d'utiliser les fonctionnalités de ce module dans plusieurs threads, à condition que chaque thread utilise un objet ExpandFile alloué séparément. En d'autres termes, si deux threads veulent faire du développement de fichiers, ils devraient chacun appeler new_ExpandFile() pour allouer leurs pr

opres objets d'exp
ansion de fichiers.
