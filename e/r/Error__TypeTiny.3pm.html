NOM

Error::TypeTiny - exceptions pour Type::Tiny et ses amis

SYNOPSIS

use feature 'try';
use Data::Dumper;
use Types::Standard qw( Str );

try {
   Str->assert_valid( undef );
}
catch ( $exception ) {
   warn "Erreur rencontrée : $exception";
   warn Dumper( $exception->explain )
      if $exception->isa( "Error::TypeTiny::Assertion" );
}

STATUT

Ce module est couvert par la politique de stabilité de Type-Tiny.

DESCRIPTION

Lorsque Type::Tiny et ses modules associés rencontrent une erreur, ils déclenchent un objet exception. Ces objets exception héritent de Error::TypeTiny.

Constructeurs

new(%attributs)
Fonction constructeur de style Moose.
throw(%attributs)
Construit une exception et la passe à "die".

Remplit automatiquement "context" et "stack_trace" si approprié.

"throw_cb($callback, %attributs)"
Construit une exception et la passe à $callback qui doit être un coderef ; si undef, utilise "die".

Remplit automatiquement "context" et "stack_trace" si approprié.

Attributs

"message"
Le message d'erreur.
"context"
Hashref contenant le paquet, le fichier et la ligne qui ont généré l'erreur.
"stack_trace"
Une trace de pile plus complète. Cette fonctionnalité nécessite Devel::StackTrace ; utilisez la variable de paquet $StackTrace pour l'activer.

Méthodes

"to_string"
Retourne le message, suivi du contexte s'il est défini.

Fonctions

"Error::TypeTiny::croak($format, @args)"
Raccourci de style fonctionnel vers la méthode "throw". Prend une chaîne de format style "sprintf" et des arguments optionnels pour construire le "message".

Surcharge

•
La stringification est surchargée pour appeler "to_string".

Variables de paquet

%Carp::CarpInternal
Error::TypeTiny respecte cette variable de paquet de Carp. (%Error::TypeTiny::CarpInternal est un alias pour elle.)
$Error::TypeTiny::StackTrace
Booléen pour activer la génération de la trace de pile.
$Error::TypeTiny::LastError
Une référence au dernier objet exception déclenché.

ATTENTION

Bien que les objets Error::TypeTiny soient déclenchés pour les erreurs produites par Type::Tiny, cela ne signifie pas que chaque fois que vous utiliserez Type::Tiny, vous obtiendrez des Error::TypeTinys quand vous le voudrez.

Par exemple, si vous utilisez une contrainte de type Type::Tiny dans un attribut Moose, Moose n'appellera pas la méthode "assert_valid" de la contrainte (qui déclenche une exception). Au lieu de cela, il appellera "check" et "get_message" (qui ne le font pas), et utilisera "confess" un message d'erreur de son propre chef. (La variable de paquet $LastError pourrait vous sauver la mise.)
