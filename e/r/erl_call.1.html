NOM

erl_call - Appelle/démarre un nœud Erlang distribué

DESCRIPTION

erl_call permet de démarrer et/ou de communiquer avec un nœud Erlang distribué. Il est basé sur la bibliothèque Erl_Interface comme exemple d'application. Son objectif est d'utiliser un script shell Unix pour interagir avec un nœud Erlang distribué. Il effectue toutes les communications avec le serveur rex d'Erlang, en utilisant la facilité RPC standard d'Erlang. Il ne nécessite aucun logiciel spécial pour être exécuté sur le nœud Erlang cible.

L'utilisation principale est soit de démarrer un nœud Erlang distribué, soit d'effectuer un appel de fonction ordinaire. Cependant, il est également possible de transférer un module Erlang vers erl_call et de le faire compiler, ou de transférer une séquence d'expressions Erlang à évaluer (similaire au shell Erlang).

Les options, qui font lire stdin, peuvent être utilisées avec avantage, comme les scripts à partir de scripts shell (Unix). Une autre bonne utilisation de erl_call pourrait être à partir de scripts CGI-bin (HTTP).

erl_call <options>

Démarre/appelle Erlang.

Chaque indicateur d'option est décrit ci-dessous avec son nom, son type et sa signification.

-a [Mod [Fun [Args]]]]

( Optionnel.) Applique la fonction spécifiée et retourne le résultat. Mod doit être spécifié. Cependant, start et [] sont supposés pour Fun et Args non spécifiés, respectivement. Args doit être dans le même format que pour erlang:apply/3 dans ERTS, à l'exception qu'un sous-ensemble limité de tous les termes est autorisé. Les types de termes autorisés sont : liste (et sa représentation sous forme de chaîne, c'est-à-dire "exemple"), tuple, atome et nombre.

Notez que cet indicateur prend exactement un argument, de sorte que les guillemets peuvent être nécessaires pour regrouper Mod, Fun, et Args d'une manière dépendante du comportement de votre shell de commande.

-address [Hostname:]Port

(Un des indicateurs -n, -name, -sname ou -address est requis.) Hostname est le nom d'hôte de la machine qui exécute le nœud pair avec lequel erl_call communiquera. Le nom d'hôte par défaut est le nom d'hôte de la machine locale. Port est le numéro de port du nœud avec lequel erl_call communiquera. L'indicateur -address ne peut pas être combiné avec les indicateurs -n, -name, -sname ou -s.

L'indicateur -address est généralement utile lorsqu'on veut appeler un nœud qui s'exécute sur une machine sans instance epmd accessible.

-c Cookie

( Optionnel.) Utilisez cette option pour spécifier un cookie particulier. Si aucun cookie n'est spécifié, le fichier ~/.erlang.cookie est lu et son contenu est utilisé comme cookie. Le nœud Erlang auquel nous voulons communiquer doit avoir le même cookie.

-d

( Optionnel.) Mode de débogage. Cela provoque la sortie de toutes les entrées/sorties dans le fichier ~/.erl_call.out.NomDuNœud, où NomDuNœud est le nom du nœud Erlang en question.

-e

( Optionnel.) Lit une séquence d'expressions Erlang, séparées par des virgules (,) et terminées par un point (.), depuis stdin jusqu'à EOF (Control-D). Évalue les expressions et retourne le résultat de la dernière expression. Retourne {ok,Result} en cas de succès.

-fetch_stdout

( Optionnel.) Exécute le code, spécifié avec l'option -a ou -e, dans un nouveau processus dont le leader de groupe redirige toutes les sorties standard (stdout) pour qu'elles soient imprimées sur la sortie standard du processus erl_call. Cela signifie que les données stdout écrites pendant l'exécution du code appelé, par le code et par les processus descendants, seront redirigées (à condition que le leader de groupe n'ait pas été modifié par un appel à erlang:group_leader/2).

Les données imprimées sont encodées en UTF-8.

Cette option n'est pertinente que lorsqu'elle est combinée avec les options -a ou -e.

Voir la documentation du protocole d'E/S pour plus d'informations sur le concept de leader de groupe.

NOTE : Cette option ne fonctionne que lorsque erl_call interagit avec un nœud dont la version est supérieure ou égale à OTP-24.

-h NomCaché

( Optionnel.) Spécifie le nom du nœud caché que erl_call représente.

-m

( Optionnel.) Lit un module Erlang depuis stdin et le compile.

-n Nœud

(Un des indicateurs -n, -name, -sname ou -address est requis.) A la même signification que -name et peut toujours être utilisé pour des raisons de compatibilité descendante.

-name Nœud

(Un des indicateurs -n, -name, -sname ou -address est requis.) Nœud est le nom du nœud pair à démarrer ou avec lequel communiquer. Il est supposé que Nœud est démarré avec erl -name, ce qui signifie que des noms de nœuds longs entièrement qualifiés sont utilisés. Si l'option -s est spécifiée, un nœud Erlang sera (si nécessaire) démarré avec erl -name.

-no_result_term

( Optionnel.) N'imprime pas le terme de résultat. Cette option n'est pertinente qu'en conjonction avec les options -a et -e.

-q

( Optionnel.) Arrête le nœud Erlang spécifié par l'option -n. Cet indicateur remplace l'option -s.

-r

( Optionnel.) Génère un nom aléatoire pour le nœud caché que erl_call représente.

-R

( Optionnel.) Demande un nom aléatoire dynamique, du nœud caché que erl_call représente, auprès du nœud pair. Supporté depuis OTP 23. Préférez -R à -r lors de requêtes répétées vers le même nœud pair.

-s

( Optionnel.) Démarre un nœud Erlang distribué si nécessaire. Cela signifie que dans une séquence d'appels, où '-s' et '-n Nœud' sont constants, seul le premier appel démarre le nœud Erlang. Cela rend la communication restante très rapide. Cet indicateur n'est actuellement disponible que sur les plateformes de type Unix (Linux, Mac OS X, Solaris, etc.).

-sname Nœud

(Un des indicateurs -n, -name, -sname ou -address est requis.) Nœud est le nom du nœud pair à démarrer ou avec lequel communiquer. Il est supposé que Nœud est démarré avec erl -sname, ce qui signifie que des noms de nœuds courts sont utilisés. Si l'option -s est spécifiée, un nœud Erlang est démarré (si nécessaire) avec erl -sname.

-timeout Secondes

( Optionnel.) Avorte le processus erl_call après expiration du délai. Notez que cela n'avorte pas les commandes qui ont déjà été démarrées avec -a, -e ou similaire.

-v

( Optionnel.) Affiche beaucoup d'informations verbeuses. Ceci est seulement utile pour le développeur et le mainteneur de erl_call.

-x ScriptErlang

( Optionnel.) Spécifie un autre nom de script de démarrage Erlang à utiliser. S'il n'est pas spécifié, le script de démarrage standard erl est utilisé.

Exemples

Pour démarrer un nœud Erlang et appeler erlang:time/0:

erl_call -s -a 'erlang time' -n madonna
{18,27,34}

Pour terminer un nœud Erlang en appelant erlang:halt/0:

erl_call -s -a 'erlang halt' -n madonna

Pour appliquer avec de nombreux arguments :

erl_call -s -a 'lists seq [1,10]' -n madonna

Pour évaluer quelques expressions (l'entrée se termine par EOF (Control-D)) :

erl_call -s -e -n madonna
statistics(runtime),
X=1,
Y=2,
{_,T}=statistics(runtime),
{X+Y,T}.
^D
{ok,{3,0}}

Pour compiler un module et l'exécuter (encore une fois, l'entrée se termine par EOF (Control-D)) :

(Dans l'exemple, la sortie a été formatée après coup.)

erl_call -s -m -a procnames start -n madonna
-module(procnames).
-compile(export_all).
start() ->
        P = processes(),
        F = fun(X) -> {X,process_info(X,registered_name)} end,
        lists:map(F,[],P).
^D

Pour transférer la sortie standard sans afficher le résultat (encore une fois, l'entrée se termine par EOF (Contrôle-D)) :

erl_call -s -e -sname madonna -fetch_stdout -no_result_term
io:format("Number of schedulers: ~p~n", [erlang:system_info(schedulers)]),
io:format("Number of logical cores: ~p~n", [erlang:system_info(logical_processors_available)]).
^D
