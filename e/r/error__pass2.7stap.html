NOM

error::pass2 - erreurs de passe 2 de systemtap

DESCRIPTION

Les erreurs qui surviennent pendant la passe 2 (élaboration) peuvent avoir diverses causes. Les types courants incluent :

débogage manquant
Le script nécessite des informations de débogage pour résoudre un point de sonde, mais n'en a trouvé aucune. Voir error::dwarf(7stap) et warning::debuginfo(7stap) pour plus de détails.
classes de points de sonde indisponibles
Certains types de points de sonde ne sont disponibles que sur certaines versions du système, architectures et configurations. Par exemple, les sondes process.* de l'espace utilisateur peuvent nécessiter la capacité utrace ou uprobes dans le noyau pour cette architecture.
points de sonde indisponibles
Certains points de sonde peuvent être individuellement indisponibles même si leur classe est correcte. Par exemple, kprobe.function("foobar") peut échouer si la fonction foobar n'existe plus dans le noyau. Les données de débogage ou de symboles peuvent être absentes pour certains types de sondes .function ou .statement ; vérifiez la disponibilité des informations de débogage. Essayez le programme stap-prep pour télécharger les informations de débogage potentiellement requises. Utilisez un paramètre générique tel que stap -l 'kprobe.function("*foo*")' pour localiser les variantes existantes. Utilisez les suffixes de sondes ! ou ? pour indiquer des alternatives optionnelles / préférées, afin que les parties fonctionnelles d'un script puissent continuer.
fautes de frappe
Il peut y avoir une faute de frappe dans le nom du point de sonde ("sycsall" vs "syscall"). Les sondes génériques peuvent ne trouver aucune correspondance dans les tapsets. Revérifiez les noms à l'aide de stap -l PROBEPOINT. Une autre erreur courante est d'utiliser l'opérateur . au lieu du bon -> lors du déréférencement des sous-champs ou des pointeurs de variables de contexte : $foo->bar->baz même si en C on dirait foo->bar.baz.
variables de contexte indisponibles
Les scripts Systemtap souhaitent souvent faire référence à des variables du contexte des programmes sondés en utilisant la notation $variable. Ces variables ne sont pas toujours disponibles, en fonction des versions du compilateur, des indicateurs de débogage/optimisation utilisés, de l'architecture, etc. Utilisez stap -L PROBEPOINT pour lister les variables de contexte disponibles pour des sondes données. Utilisez l'expression @defined() pour tester la résolution d'une expression de variable de contexte. Envisagez d'utiliser l'option stap --skip-badvars pour remplacer silencieusement les expressions de variables de contexte problématiques par zéro. Expérimentez avec l'option stap --prologue-searching.
incohérences du cache du module
Occasionnellement, le cache du module systemtap ($HOME/.systemtap/cache) peut contenir des informations obsolètes provenant d'une configuration/version antérieure du système et produire des résultats erronés lorsque systemtap tente de le réutiliser. Retenter avec stap --poison-cache ... force la génération de nouvelles informations. Note : cela ne devrait pas arriver et représente probablement un bug dans systemtap. Veuillez le signaler.

RECUEIL D'INFORMATIONS COMPLÉMENTAIRES

Augmenter la verbosité de la passe 2 avec une option telle que --vp 02 peut aider à identifier le problème.
