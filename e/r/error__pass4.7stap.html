NOM

error::pass4 - erreurs de la passe 4 de systemtap

DESCRIPTION

Les erreurs qui surviennent pendant la passe 4 (compilation) n'ont généralement que quelques causes :

changements de version du noyau ou de l'OS
L'exécution de systemtap et les fragments C embarqués dans la bibliothèque tapset sont conçus pour être portables sur une large gamme de versions d'OS. Cependant, des incompatibilités peuvent survenir lorsque certains changements d'OS se produisent, tels que des modifications du noyau qui changent des fonctions, des types ou des macros référencés par systemtap. Les builds upstream (git://sourceware.org/git/systemtap.git) de systemtap sont souvent rapidement mis à jour pour inclure les corrections pertinentes, alors essayez d'obtenir ou de créer une version mise à jour. Reformulé : compilez systemtap depuis git pour une utilisation avec des noyaux très récents. Si le problème persiste, signalez le problème aux développeurs de systemtap.
code C embarqué défectueux
Le code C embarqué dans vos propres scripts en mode guru ne peut pas être vérifié par systemtap, et est transmis tel quel au compilateur. Des erreurs dans de tels extraits de code peuvent être trouvées lors de l'invocation du compilateur de la passe 4, bien qu'elles puissent être difficiles à identifier par les messages d'erreur du compilateur.
code C embarqué incompatible
Les normes d'interface entre le code généré par systemtap et le code C embarqué changent occasionnellement. Par exemple, avant la version 1.8, les arguments étaient passés en utilisant les macros THIS->foo et THIS->__retvalue mais à partir de la version 1.8, en utilisant STAP_ARG_foo et STAP_RETVALUE. Adaptez votre code C embarqué aux normes actuelles, ou utilisez l'option stap --compatible=VERSION pour que systemtap utilise une version différente.
bugs et mystères du compilateur
Des messages tels que « erreur interne du compilateur » suggèrent des problèmes de compilateur. Ceux-ci devraient être signalés aux développeurs du compilateur sous la forme d'un fichier .i prétraité, plus la ligne de commande du compilateur. Pour rassembler les informations pertinentes, exécutez 
stap -k --vp 0003 -p4 ....

Systemtap signalera le répertoire temporaire enregistré et la ligne de commande du compilateur qu'il a tenté. Allez dans le répertoire pour trouver le fichier principal généré stap_NNNNN_src.c. Forcez le compilateur à produire un fichier prétraité avec :

make -C /lib/modules/`uname -r`/build M=`pwd` stap_NNNNN_src.i

(notez le suffixe .i), et la ligne de commande du compilateur devrait se trouver dans le fichier .stap_NNNNN_src.i.cmd.
