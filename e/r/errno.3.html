errno(3) Manuel des fonctions de bibliothèque errno(3)

NOM

errno — numéro de la dernière erreur

BIBLIOTHÈQUE

Bibliothèque C standard (libc, -lc)

SYNTAXE

#include <errno.h>

DESCRIPTION

Le fichier d'en-tête <errno.h> définit la variable entière errno, qui est définie par les appels système et certaines fonctions de bibliothèque en cas d'erreur pour indiquer ce qui s'est mal passé.

errno

La valeur dans errno n'est significative que lorsque la valeur de retour de l'appel a indiqué une erreur (c'est-à-dire -1 pour la plupart des appels système ; -1 ou NULL pour la plupart des fonctions de bibliothèque) ; une fonction qui réussit est autorisée à modifier errno. La valeur de errno n'est jamais mise à zéro par un appel système ou une fonction de bibliothèque.

Pour certains appels système et fonctions de bibliothèque (par exemple, getpriority(2)), -1 est un retour valide en cas de succès. Dans de tels cas, un retour réussi peut être distingué d'un retour d'erreur en mettant errno à zéro avant l'appel, puis, si l'appel retourne un statut indiquant qu'une erreur peut s'être produite, en vérifiant si errno a une valeur non nulle.

errno est défini par la norme C ISO comme étant une valeur modifiable de type int, et ne doit pas être explicitement déclarée ; errno peut être une macro. errno est propre à chaque thread ; le modifier dans un thread n'affecte pas sa valeur dans les autres threads.

Numéros et noms d'erreur

Les numéros d'erreur valides sont tous des nombres positifs. Le fichier d'en-tête <errno.h> définit des noms symboliques pour chacun des numéros d'erreur possibles qui peuvent apparaître dans errno.

Tous les noms d'erreur spécifiés par POSIX.1 doivent avoir des valeurs distinctes, à l'exception de EAGAIN et EWOULDBLOCK, qui peuvent avoir la même valeur. Sur Linux, ces deux ont la même valeur sur toutes les architectures.

Les numéros d'erreur qui correspondent à chaque nom symbolique varient d'un système UNIX à l'autre, et même d'une architecture à l'autre sur Linux. Par conséquent, les valeurs numériques ne sont pas incluses dans la liste des noms d'erreur ci-dessous. Les fonctions perror(3) et strerror(3) peuvent être utilisées pour convertir ces noms en messages d'erreur textuels correspondants.

Sur un système Linux donné, on peut obtenir une liste de tous les noms d'erreur symboliques et des numéros d'erreur correspondants en utilisant la commande errno(1) (qui fait partie du paquet moreutils) :


$ errno -l;
EPERM 1 Operation not permitted
ENOENT 2 No such file or directory
ESRCH 3 No such process
EINTR 4 Interrupted system call
EIO 5 Input/output error
...

La commande errno(1) peut également être utilisée pour rechercher des numéros et des noms d'erreur individuels, et pour rechercher des erreurs à l'aide de chaînes de caractères de la description d'erreur, comme dans les exemples suivants :


$ errno 2;
ENOENT 2 No such file or directory
$ errno ESRCH;
ESRCH 3 No such process
$ errno -s permission;
EACCES 13 Permission denied

POSIX.1-2001
Le nom est défini par POSIX.1-2001, et est défini dans les versions ultérieures de POSIX.1, sauf indication contraire.
POSIX.1-2008
Le nom est défini dans POSIX.1-2008, mais n'était pas présent dans les normes POSIX.1 antérieures.
C99
Le nom est défini par C99.

NOTES

Une erreur courante est de faire


if (somecall() == -1) {
    printf("somecall() failed\n");
    if (errno == ...) { ...; }
}

où errno n'a plus forcément la valeur qu'il avait lors du retour de somecall() (c'est-à-dire qu'il a pu être modifié par le printf(3)). Si la valeur de errno doit être conservée à travers un appel de bibliothèque, elle doit être sauvegardée :


if (somecall() == -1) {
    int errsv = errno;
    printf("somecall() failed\n");
    if (errsv == ...) { ...; }
}

Notez que les API de threads POSIX ne définissent pas errno en cas d'erreur. À la place, en cas d'échec, elles renvoient un numéro d'erreur comme résultat de la fonction. Ces numéros d'erreur ont les mêmes significations que les numéros d'erreur renvoyés dans errno par d'autres API.

Sur certains systèmes anciens, <errno.h> n'était pas présent ou ne déclarait pas errno, de sorte qu'il était nécessaire de déclarer errno manuellement (c'est-à-dire, extern int errno). Ne faites pas cela. Cela a cessé d'être nécessaire depuis longtemps, et cela causera des problèmes avec les versions modernes de la bibliothèque C.
