ERR_new(3ssl)

Paquet: openssl

Licences: Apache-2.0

ERR_NEW(3ssl) OpenSSL ERR_NEW(3ssl)

NOM

ERR_new, ERR_set_debug, ERR_set_error, ERR_vset_error - Blocs de construction pour l'enregistrement des erreurs

SYNTAXE

#include <openssl/err.h>
void ERR_new(void);
void ERR_set_debug(const char *file, int line, const char *func);
void ERR_set_error(int lib, int reason, const char *fmt, ...);
void ERR_vset_error(int lib, int reason, const char *fmt, va_list args);

DESCRIPTION

Les fonctions décrites ici ne sont généralement pas utilisées directement, mais plutôt via des macros telles que ERR_raise(3). Elles peuvent toujours être utiles à ceux qui souhaitent créer leurs propres macros.

ERR_new() alloue un nouvel emplacement dans la file d'attente d'erreurs du thread.

ERR_set_debug() définit les informations de débogage relatives à l'erreur actuelle dans la file d'attente d'erreurs du thread. Les valeurs pouvant être fournies sont le nom du fichier file, la ligne dans le fichier line et le nom de la fonction func où l'erreur s'est produite. Les noms doivent être constants, cette fonction ne fait que sauvegarder les pointeurs, pas copier les chaînes.

ERR_set_error() définit les informations d'erreur, qui sont le numéro de la bibliothèque lib et le code de raison reason, ainsi que des données supplémentaires sous forme de chaîne de format fmt et d'un nombre arbitraire d'arguments. Les données supplémentaires sont traitées avec BIO_snprintf(3) pour former la chaîne de données supplémentaire, qui est allouée et stockée dans l'enregistrement d'erreur.

ERR_vset_error() fonctionne comme ERR_set_error(), mais prend un argument va_list au lieu d'un nombre variable d'arguments.

VALEURS DE RETOUR

ERR_new, ERR_set_debug, ERR_set_error et ERR_vset_error ne retournent aucune valeur.

NOTES

Le numéro de bibliothèque est unique à chaque unité qui enregistre des erreurs. OpenSSL dispose d'un certain nombre de numéros pré-alloués pour ses propres usages, mais d'autres peuvent allouer leur propre numéro de bibliothèque dynamiquement avec ERR_get_next_error_library(3).

Les codes de raison sont uniques au sein de chaque bibliothèque et peuvent avoir un ensemble associé de chaînes décrivant brièvement la raison. Pour les numéros de bibliothèque alloués dynamiquement, les chaînes de raison sont enregistrées avec ERR_load_strings(3).

Les auteurs de fournisseurs reçoivent des versions de base de ces fonctions, voir provider-base(7).
