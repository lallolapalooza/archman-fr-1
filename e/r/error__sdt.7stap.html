NOM

error::sdt - échecs des marqueurs <sys/sdt.h>

DESCRIPTION

Les sondes <sys/sdt.h> de Systemtap sont modélisées d'après l'API USDT de DTrace, mais sont implémentées différemment. Elles ne laissent qu'une instruction NOP dans le segment de texte du programme utilisateur et ajoutent une note ELF au binaire avec des métadonnées. Ces métadonnées décrivent le nom et les paramètres du marqueur. Ce codage est conçu pour être analysable par plusieurs outils (pas seulement systemtap : GDB, le débogueur GNU, contient également un support). Ceci permet aux outils de trouver les paramètres et leurs types, où qu'ils se trouvent, même sans informations de débogage DWARF.

La raison pour laquelle trouver les paramètres est délicat est que les marqueurs STAP_PROBE / DTRACE_PROBE stockent une expression en langage assembleur pour chaque opérande, suite à l'utilisation de directives d'assembleur en ligne de GCC. Le compilateur reçoit une chaîne de contrainte d'opérande GCC large ("nor") pour les opérandes, ce qui fonctionne généralement bien. Habituellement, cela n'oblige pas le compilateur à charger les paramètres dans ou hors des registres, ce qui ralentirait un programme instrumenté. Cependant, certains sites d'instrumentation avec certains paramètres ne fonctionnent pas bien avec la contrainte "nor" par défaut.

non résoluble en temps d'exécution
GCC peut émettre des chaînes qu'un assembleur pourrait résoudre (du contexte de la compilation du programme original), mais qu'un outil d'exécution ne peut pas. Par exemple, la chaîne d'opérande peut faire référence à une étiquette d'un symbole local qui n'est pas du tout émise dans le fichier objet ELF, ne laissant aucune trace pour le temps d'exécution. La référence à de tels paramètres dans systemtap peut entraîner des erreurs "SDT asm not understood".
expression trop compliquée
GCC peut synthétiser des modes d'adressage assembleur très compliqués à partir de types de données C / expressions de pointeur complexes. systemtap ou gdb peuvent ne pas être en mesure d'analyser certaines expressions valides mais compliquées. La référence à de tels paramètres dans systemtap peut entraîner des erreurs "SDT asm not understood".
contrainte trop restrictive
GCC pourrait ne pas être capable de compiler le programme original avec la contrainte "nor" par défaut en raison d'un manque de registres ou d'autres raisons. Une erreur de compilation GCC telle que "asm operand has impossible constraints" peut en résulter.

Il existe deux solutions générales à cette famille de problèmes.

modifier les contraintes
Lors de la compilation du programme instrumenté original, définissez la macro STAP_SDT_ARG_CONSTRAINT sur différentes chaînes de contraintes. Voir le manuel GCC sur les différentes options. Par exemple, sur de nombreuses architectures machine, "r" force les opérandes dans les registres, et "g" laisse les opérandes essentiellement sans contrainte.
revenir aux informations de débogage
Tant que le programme instrumenté compile, il peut être acceptable de continuer à utiliser <sys/sdt.h> mais d'éviter d'extraire quelques paramètres individuels. Dans le pire des cas, désactivez les macros <sys/sdt.h> entièrement pour éviter l'instrumentation compilée. Si les informations de débogage DWARF ont été générées et préservées, un script systemtap pourrait faire référence aux variables de contexte source sous-jacentes au lieu des paramètres positionnels STAP_PROBE.
