error(n) Commandes intégrées Tcl error(n)

NOM

error - Générer une erreur

SYNOPIS

error message ?info? ?code?

DESCRIPTION

Renvoie un code TCL_ERROR, ce qui provoque le déroulement de l'interprétation de la commande. Message est une chaîne qui est renvoyée à l'application pour indiquer ce qui s'est mal passé.

L'option de retour -errorinfo d'un interpréteur est utilisée pour accumuler une trace de pile de ce qui était en cours lorsque s'est produite une erreur ; au fur et à mesure que les commandes imbriquées se déroulent, l'interpréteur Tcl ajoute des informations à l'option de retour -errorinfo. Si l'argument info est présent, il est utilisé pour initialiser l'option de retour -errorinfo et la première partie des informations de déroulement ne sera pas ajoutée par l'interpréteur Tcl. Autrement dit, la commande contenant la commande error n'apparaîtra pas dans la trace de pile ; à sa place se trouvera info. Historiquement, cette fonctionnalité était surtout utile en conjonction avec la commande catch : si une erreur interceptée ne peut pas être gérée avec succès, info peut être utilisée pour renvoyer une trace de pile reflétant le point d'origine de l'erreur :

catch {...} errMsg
set savedInfo $::errorInfo
...
error $errMsg $savedInfo

Lorsque vous travaillez avec Tcl 8.5 ou une version ultérieure, le code suivant doit être utilisé à la place :

catch {...} errMsg options
...
return -options $options $errMsg

Si l'argument code est présent, alors sa valeur est stockée dans l'option de retour -errorcode. L'option de retour -errorcode est destinée à contenir une description lisible par machine de l'erreur dans les cas où de telles informations sont disponibles ; voir la page de manuel de return pour des informations sur le format approprié pour la valeur de cette option.

EXEMPLE

Générer une erreur si une opération mathématique de base échoue :

if {1+2 != 3} {
    error "quelque chose ne va pas du tout avec l'addition"
}
