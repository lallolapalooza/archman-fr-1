ERR_put_error(3ssl)

Paquet: openssl

Licences: Apache-2.0

ERR_PUT_ERROR(3ssl) OpenSSL ERR_PUT_ERROR(3ssl)

NOM

ERR_raise, ERR_raise_data, ERR_put_error, ERR_add_error_data, ERR_add_error_vdata, ERR_add_error_txt, ERR_add_error_mem_bio - enregistrer une erreur

SYNOPSIS

#include <openssl/err.h>
void ERR_raise(int lib, int reason);
void ERR_raise_data(int lib, int reason, const char *fmt, ...);
void ERR_add_error_data(int num, ...);
void ERR_add_error_vdata(int num, va_list arg);
void ERR_add_error_txt(const char *sep, const char *txt);
void ERR_add_error_mem_bio(const char *sep, BIO *bio);

La fonction suivante est dépréciée depuis OpenSSL 3.0 et peut être entièrement masquée en définissant OPENSSL_API_COMPAT avec une valeur de version appropriée, voir openssl_user_macros(7):

void ERR_put_error(int lib, int func, int reason, const char *file, int line);

DESCRIPTION

ERR_raise() ajoute une nouvelle erreur à la file d'erreurs du thread. L'erreur s'est produite dans la bibliothèque lib pour la raison donnée par le code reason . De plus, le nom du fichier, la ligne et le nom de la fonction où l'erreur s'est produite sont enregistrés avec l'enregistrement d'erreur.

ERR_raise_data() fait la même chose que ERR_raise(), mais permet également à l'appelant de spécifier des informations supplémentaires sous forme de chaîne de format fmt et d'un nombre arbitraire de valeurs, qui sont traitées avec BIO_snprintf(3).

ERR_put_error() ajoute un code d'erreur à la file d'erreurs du thread. Il signale que l'erreur de code de raison reason s'est produite dans la fonction func de la bibliothèque lib, à la ligne line du fichier file. Cette fonction est généralement appelée par une macro.

ERR_add_error_data() associe la concaténation de ses num arguments de chaîne comme données supplémentaires au code d'erreur ajouté en dernier. ERR_add_error_vdata() est similaire sauf que l'argument est une va_list. Des appels multiples à ces fonctions s'ajoutent au sommet actuel de la file d'erreurs. La longueur totale des données de chaîne par erreur est limitée à 4096 caractères.

ERR_add_error_txt() ajoute la chaîne de texte donnée comme données supplémentaires à la dernière entrée de la file d'erreurs, après avoir inséré la chaîne de séparation optionnelle si elle n'est pas NULL et si l'entrée d'erreur supérieure n'a pas encore de données supplémentaires. Si le séparateur est à la fin du texte, il n'est pas ajouté aux données. L' sep argument peut être par exemple "\n" pour insérer un saut de ligne si nécessaire. Si les données associées deviendraient plus longues que 4096 caractères (ce qui est la limite donnée ci-dessus), elles sont réparties sur suffisamment de nouvelles copies de la dernière entrée de la file d'erreurs.

ERR_add_error_mem_bio() est identique à ERR_add_error_txt() sauf que la chaîne de texte est prise à partir du BIO mémoire donné. Elle ajoute '\0' au contenu du BIO s'il n'est pas déjà terminé par NUL.

ERR_load_strings(3) peut être utilisé pour enregistrer des chaînes d'erreur afin que l'application puisse générer des messages d'erreur lisibles pour l'humain à partir du code d'erreur.

Rapport d'erreurs

Rapports de la bibliothèque OpenSSL

Chaque sous-bibliothèque OpenSSL a un code de bibliothèque ERR_LIB_XXX et a son propre ensemble de codes de raison XXX_R_.... Ceux-ci sont tous deux transmis en combinaison à ERR_raise() et ERR_raise_data(), et la combinaison produit finalement le texte d'erreur correct pour l'erreur signalée.

Toutes ces macros et les valeurs qu'elles ont sont spécifiques aux bibliothèques d'OpenSSL. Les codes de raison d'OpenSSL sont normalement constitués de descriptions textuelles d'erreurs. Par exemple, la fonction ssl3_read_bytes() signale un « échec de handshake » comme suit :

ERR_raise(ERR_LIB_SSL, SSL_R_SSL_HANDSHAKE_FAILURE);

Il y a deux exceptions :

ERR_LIB_SYS
Ce « code de bibliothèque » indique qu'une erreur système est signalée. Dans ce cas, le code de raison donné à ERR_raise() et ERR_raise_data() doit être errno(3). 
ERR_raise(ERR_LIB_SYS, errno);
ERR_R_XXX
Cet ensemble de codes d'erreur est considéré comme global et peut être utilisé en combinaison avec n'importe quel code de sous-bibliothèque. 
ERR_raise(ERR_LIB_RSA, ERR_R_PASSED_INVALID_ARGUMENT);

Autres logiciels

Les autres logiciels qui souhaiteraient utiliser le système de rapport d'erreurs d'OpenSSL, tels que les moteurs ou les applications, doivent normalement obtenir leurs propres numéros.

  • Pour obtenir un « code de bibliothèque », appelez ERR_get_next_error_library(3); cela donne au code appelant un numéro dynamique, utilisable pendant la durée du processus.
  • Les codes de raison pour chaque « bibliothèque » de ce type sont déterminés ou générés par les auteurs de ce code. Ils doivent être des nombres dans la plage de 1 à 524287 (en d'autres termes, ils doivent être des entiers non signés de 18 bits non nuls).

Les exceptions mentionnées dans « Rapports de la bibliothèque OpenSSL » ci-dessus sont valables pour les autres logiciels, c'est-à-dire qu'ils peuvent utiliser ERR_LIB_SYS pour signaler des erreurs système :

ERR_raise(ERR_LIB_SYS, errno);

... et ils peuvent utiliser les macros ERR_R_XXX avec leur propre « code de bibliothèque ».

int app_lib_code = ERR_get_next_error_library();
/* ... */
ERR_raise(app_lib_code, ERR_R_PASSED_INVALID_ARGUMENT);

VALEURS RETOURNÉES

ERR_raise(), ERR_raise_data(), ERR_put_error(), ERR_add_error_data(), ERR_add_error_vdata() ERR_add_error_txt(), et ERR_add_error_mem_bio() ne retournent aucune valeur.

NOTES

ERR_raise(), ERR_raise() et ERR_put_error() sont implémentées comme des macros.

VOIR AUSSI

ERR_load_strings(3), ERR_get_next_error_library(3)

HISTORIQUE

ERR_raise, ERR_raise_data, ERR_add_error_txt() et ERR_add_error_mem_bio() ont été ajoutés dans OpenSSL 3.0.
