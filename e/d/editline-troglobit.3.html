DESCRIPTIO

N

editline est une bibliothèque qui fournit une interface d'édition de ligne avec historique. Elle est destinée à être fonctionnellement équivalente à la bibliothèque readline fournie par la Free Software Foundation, mais beaucoup plus petite. L'essentiel de cette page de manuel décrit l'interface utilisateur de base. D'autres API, à la fois natives et pour la compatibilité readline, sont également disponibles. Voir le fichier d'en-tête editline.h pour plus de

détails.

La fonction readline() affiche le invite donné sur stdout, attend la saisie de l'utilisateur sur stdin, puis retourne une ligne de texte avec le retour à la ligne final supprimé. Les données sont retournées dans un tampon alloué avec malloc(3), l'espace doit donc être libéré avec free(3) lorsque le programme appelant en a terminé

l'utilisation.

Chaque ligne retournée est automatiquement enregistrée dans la liste d'historique interne, sauf si elle est identique à la ligne précédente. Ceci est configurable si vous compilez editline à partir des sources, c'est-à-dire si vous préférez appeler add_history()

manuellement.

Les fonctions read_history() et write_history() peuvent être utilisées pour charger et enregistrer l'historique de votre application. Remarque : ces API ne font aucune expansion de tilde ni de variable d'environnement pour le nom de fichier

donné.

Interface

utilisateur

Un programme utilisant cette bibliothèque fournit à ses utilisateurs une interface d'édition simple de type emacs. Une ligne peut être éditée avant d'être envoyée au programme appelant en tapant soit des caractères de contrôle, soit des séquences d'échappement. Un caractère de contrôle, représenté par un accent circonflexe suivi d'une lettre, est tapé en maintenant la touche contrôle enfoncée tout en tapant la lettre. Par exemple, ^A est un contrôle-A. Une séquence d'échappement est saisie en appuyant sur la touche d'échappement suivie d'un ou plusieurs caractères. La touche d'échappement est abrégée ESC. Contrairement aux touches de contrôle, la casse est importante dans les séquences d'échappement ; ESC F n'est pas la même chose que ESC

f.

Une commande d'édition peut être tapée n'importe où sur la ligne, pas seulement au début. De même, un retour à la ligne peut être tapé n'importe où sur la ligne, pas seulement à la

fin.

La plupart des commandes d'édition peuvent recevoir un nombre de répétition, n, où n est un nombre. Pour saisir un nombre de répétition, tapez la touche d'échappement, le nombre, puis la commande à exécuter. Par exemple, ESC 4 ^f avance de quatre caractères. Si une commande peut recevoir un nombre de répétition, le texte [n] est indiqué à la fin de sa

description.

La bibliothèque editline possède une petite fonctionnalité de macros. Si vous tapez la touche d'échappement suivie d'une lettre majuscule, C, alors le contenu de la variable d'environnement $C est lu comme si vous l'aviez tapé au clavier. Par exemple, si la variable $L contient ce qui suit

:
^A^Kecho '^V^[[H^V^[[2J'^
M

Alors taper ESC L déplacera au début de la ligne, supprimera la ligne entière, entrera la commande echo nécessaire pour effacer le terminal (si votre terminal est de type VT-100), et renverra la ligne au

shell.

La bibliothèque editline effectue également la complétion de noms de fichiers. Supposons que le répertoire racine contienne les fichiers suivants

:
bin
vmunix
core vmunix.
old

Si vous tapez rm /v puis la touche de tabulation, editline complétera alors autant que possible le nom en ajoutant munix. Comme le nom n'est pas unique, elle émettra alors un bip. Si vous tapez la touche d'échappement et un point d'interrogation, elle affichera les deux choix. Si vous tapez ensuite un point et une tabulation, la bibliothèque complétera le nom de fichier pour vous

:
rm /v[TAB] munix .[TAB] ol
d

AUTEUR

S

La bibliothèque editline originale a été publiée sur le groupe de discussion comp.sources.unix par Simmule R. Turner et Rich Salz en 1992. Elle existe désormais en plusieurs forks : Debian, Minix, Heimdal, Festival speech tools, Mozilla, Google Gadgets for Linux, et bien d'autres encore. La page de manuel originale a été réalisée par David W.

Sanderson.

Cette version était initialement basée sur les sources de Minix 2, mais a depuis évolué pour inclure les correctifs de tous les forks pertinents. Elle est actuellement maintenue par Joachim Nilsson sur GitHub, ⟨http://github.com/troglobit/editlin
