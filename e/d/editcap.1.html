NOM

editcap - Édite et/ou traduit le format des fichiers de capture

SYNTAXE

DESCRIPTION

Editcap est un programme qui lit tout ou partie des paquets capturés depuis le fichier_entree, les convertit éventuellement de différentes manières et écrit les paquets résultants dans le fichier_sortie (ou fichiers de sortie).

Par défaut, il lit tous les paquets du fichier_entree et les écrit dans le fichier_sortie au format de fichier pcapng. Utilisez '-' pour fichier_entree ou fichier_sortie pour lire depuis l'entrée standard ou écrire vers la sortie standard, respectivement.

Les options -A et -B vous permettent de limiter la plage horaire des paquets lus depuis le fichier_entree.

Une liste facultative de numéros de paquets peut être spécifiée sur la ligne de commande ; les numéros de paquets individuels séparés par des espaces et/ou des plages de numéros de paquets peuvent être spécifiés sous la forme début-fin, faisant référence à tous les paquets de début à fin. Par défaut, les paquets sélectionnés avec ces numéros ne seront pas écrits dans le fichier de capture. Si l'option -r est spécifiée, la sélection entière des paquets est inversée ; dans ce cas, seuls les paquets sélectionnés seront écrits dans le fichier de capture.

Editcap peut également être utilisé pour supprimer les paquets dupliqués. Plusieurs options différentes (-d, -D et -w) sont utilisées pour contrôler la fenêtre de paquets ou la fenêtre de temps relative utilisée pour la comparaison des doublons.

Editcap peut être utilisé pour assigner des chaînes de commentaires à des numéros de trames.

Editcap est capable de détecter, lire et écrire les mêmes fichiers de capture que ceux pris en charge par Wireshark. Le fichier d'entrée n'a pas besoin d'une extension de nom de fichier spécifique ; le format du fichier et une compression gzip, zstd ou lz4 facultative seront automatiquement détectés. Près du début de la section DESCRIPTION de wireshark(1) ou https://www.wireshark.org/docs/man-pages/wireshark.html se trouve une description détaillée de la manière dont Wireshark gère cela, ce qui est la même manière dont Editcap gère cela.

Editcap peut écrire le fichier dans plusieurs formats de sortie. L'option -F peut être utilisée pour spécifier le format dans lequel écrire le fichier de capture ; editcap -F fournit une liste des formats de sortie disponibles. Editcap peut également compresser le fichier de sortie. L'option --compress peut spécifier le type de compression. Si cette option n'est pas donnée, alors la méthode de compression souhaitée, le cas échéant, est déduite de l'extension du fichier_sortie ; par exemple, si le nom du fichier de sortie a l'extension .gz, alors le format gzip est utilisé.

Editcap peut également être utilisé pour extraire les secrets de déchiffrement intégrés des formats de fichiers comme pcapng qui les contiennent, au lieu d'écrire un fichier de capture.

OPTIONS

-a <numéro de trame:commentaire>

Pour le numéro de trame spécifié, assigne la chaîne de commentaire donnée. Peut être répété pour plusieurs trames. Seule la dernière chaîne de commentaire pour chaque numéro de trame unique spécifié dans la ligne de commande sera enregistrée. Les guillemets doivent être utilisés avec les chaînes de commentaires qui incluent des espaces.

Par défaut, l'option -a remplacera tous les commentaires de paquet pour le numéro de trame donné. Ajoutez l'option --preserve-packet-comment à la ligne de commande pour conserver tous les commentaires de paquet préexistants.

-A <heure de début>

Lit uniquement les paquets dont l'horodatage est égal ou postérieur à <heure de début>. L'heure peut être donnée soit au format ISO 8601, soit au format horodatage Unix epoch.

Le format ISO 8601 est soit

AAAA-MM-JJ HH:MM:SS[.nnnnnnnnn][Z|±hh:mm]

soit

AAAA-MM-JJTHH:MM:SS[.nnnnnnnnn][Z|±hh:mm]

Les secondes fractionnaires sont facultatives, tout comme le décalage horaire par rapport à l'UTC (auquel cas l'heure locale est supposée).

Le format Unix epoch est en secondes depuis l'epoch Unix et nanosecondes, avec soit un point, soit une virgule séparant les secondes et les nanosecondes. Les nanosecondes sont facultatives. L'epoch Unix est le 1970-01-01 00:00:00 UTC, donc ce format n'est pas l'heure locale.

-B <heure de fin>

Lit uniquement les paquets dont l'horodatage est antérieur à <heure de fin>. L'heure peut être donnée soit au format ISO 8601, soit au format horodatage Unix epoch.

Le format ISO 8601 est soit

AAAA-MM-JJ HH:MM:SS[.nnnnnnnnn][Z|±hh:mm]

soit

AAAA-MM-JJTHH:MM:SS[.nnnnnnnnn][Z|±hh:mm]

Les secondes fractionnaires sont facultatives, tout comme le décalage horaire par rapport à l'UTC (auquel cas l'heure locale est supposée).

Le format Unix epoch est en secondes depuis l'epoch Unix et nanosecondes, avec soit un point, soit une virgule séparant les secondes et les nanosecondes. Les nanosecondes sont facultatives. L'epoch Unix est le 1970-01-01 00:00:00 UTC, donc ce format n'est pas l'heure locale.

-c <paquets par fichier>

Divise la sortie des paquets en différents fichiers basés sur des décomptes de paquets uniformes avec un maximum de <paquets par fichier> chacun.

Chaque fichier de sortie sera créé avec un infix _nnnnn[_AAAAmmjjHHMMSS] inséré avant l'extension du fichier (qui peut être nulle) de fichier_sortie. L'infix se compose du numéro ordinal du fichier de sortie, commençant par 00000, suivi de l'horodatage de son premier paquet. L'horodatage est omis si le fichier d'entrée ne contient pas d'informations d'horodatage.

Après que le nombre spécifié de paquets a été écrit dans le fichier de sortie, le fichier de sortie suivant est ouvert. Par défaut, un seul fichier de sortie est utilisé. Cette option entre en conflit avec -i.

-C [décalage:]<longueur de coupe>

Définit la longueur de coupe à utiliser lors de l'écriture des données des paquets. Chaque paquet est coupé par <longueur de coupe> octets de données. Les valeurs positives coupent au début du paquet tandis que les valeurs négatives coupent à la fin du paquet.

Si un décalage facultatif précède la <longueur de coupe>, alors les octets coupés seront décalés à partir de cette valeur. Les décalages positifs sont à partir du début du paquet, tandis que les décalages négatifs sont à partir de la fin du paquet.

Ceci est utile pour couper les en-têtes lors de la décapsulation d'une capture entière, la suppression des en-têtes de tunnel, ou dans le cas rare où la conversion entre deux formats de fichiers laisse des octets aléatoires à la fin de chaque paquet. Une autre utilisation est la suppression des balises VLAN.


Note

Cette option peut être utilisée plus d'une fois, vous permettant effectivement de couper
octets à partir de deux

{ "p": "différentes zones d'un paquet en un seul passage à condition que vous spécifiez au moins une longueur de découpage comme valeur positive et au moins une comme valeur négative. Toutes les longueurs de découpage positives sont additionnées, de même que toutes les longueurs de découpage négatives.

-d

\n
\n

Tente de supprimer les paquets dupliqués. La longueur et le hachage MD5 du paquet actuel sont comparés aux quatre (4) paquets précédents. Si une correspondance est trouvée, le paquet actuel est ignoré. Cette option est équivalente à l'utilisation de l'option -D 5.

\n
\n

-D <fenêtre de doublons>

\n
\n

Tente de supprimer les paquets dupliqués. La longueur et le hachage MD5 du paquet actuel sont comparés aux <fenêtre de doublons> - 1 paquets précédents. Si une correspondance est trouvée, le paquet actuel est ignoré.

\n

L'utilisation de l'option -D 0 combinée à l'option -V est utile car le numéro de paquet, la longueur et le hachage MD5 de chaque paquet seront imprimés sur la sortie d'erreur standard. Cette sortie verbeuse (en particulier les chaînes de hachage MD5) peut être utile dans les scripts pour identifier les paquets dupliqués entre les fichiers de trace.

\n

La <fenêtre de doublons> est spécifiée comme une valeur entière comprise entre 0 et 1 000 000 (inclus).

\n
\n
\nNote\n

La spécification de grandes valeurs de <fenêtre de doublons> avec de grands fichiers de trace peut entraîner des temps de traitement très longs pour editcap.

\n

-E <probabilité d'erreur>

\n
\n

Définit la probabilité que les octets du fichier de sortie soient modifiés de manière aléatoire. Editcap utilise cette probabilité (comprise entre 0,0 et 1,0 inclus) pour appliquer des erreurs à chaque octet de données du fichier. Par exemple, une probabilité de 0,02 signifie que chaque octet a une chance de 2 % d'avoir une erreur.

\n

Cette option est destinée à être utilisée pour le fuzz-testing des disséqueurs de protocoles.

\n

-F <format de fichier>

\n
\n

Définit le format de fichier de sortie. Editcap peut écrire le fichier dans plusieurs formats, editcap -F fournit une liste des formats de sortie disponibles. Le format par défaut est pcapng.

-i <secondes par fichier>

\n
\n

Divise la sortie des paquets en différents fichiers basés sur des intervalles de temps uniformes, avec un intervalle maximum de <secondes par fichier> chacun. Les valeurs à virgule flottante (par exemple, 0,5) sont autorisées.

\n

Chaque fichier de sortie sera créé avec un infixe _nnnnn[_YYYYmmddHHMMSS] inséré avant l'extension de fichier (qui peut être vide) de outfile. L'infixe se compose du numéro ordinal du fichier de sortie, commençant par 00000, suivi de l'horodatage de son premier paquet. L'horodatage est omis si le fichier d'entrée ne contient pas d'informations d'horodatage.

\n

Une fois les paquets de l'intervalle de temps spécifié écrits dans le fichier de sortie, le fichier de sortie suivant est ouvert. Par défaut, un seul fichier de sortie est utilisé. Cette option entre en conflit avec -c.

-I <octets à ignorer>

\n
\n

Ignore le nombre d'octets spécifié au début de la trame lors du calcul du hachage MD5, à moins que la trame ne soit trop courte, auquel cas la trame entière est utilisée. Utile pour supprimer les paquets dupliqués capturés sur plusieurs routeurs (adresses MAC différentes par exemple) par exemple -I 26 dans le cas d'Ether/IP ignorera l'en-tête Ether (14) et IP (20 - 4 (IP source) - 4 (IP destination)). La valeur par défaut est 0.

\n

-L

\n
\n

Ajuste la longueur d'origine de la trame en conséquence lors de la découpe et/ou de la capture (en plus de la longueur capturée, qui est toujours ajustée, que -L soit spécifié ou non). Voir aussi -C <longueur de découpage> et -s <longueur de capture>.

\n
\n

-o <décalage de changement>

\n
\n

Lorsqu'il est utilisé conjointement avec -E, ignore certains octets du début du paquet pour qu'ils ne soient pas modifiés. De cette façon, certains en-têtes ne sont pas modifiés, et le fuzzer se concentre sur une partie plus petite du paquet. En gardant une partie du paquet fixe, le même disséqueur est déclenché, ce qui rend le fuzzing plus précis.

-s <longueur de capture>

\n
\n

Définit la longueur de capture à utiliser lors de l'écriture des données. Si le drapeau -s est utilisé pour spécifier une longueur de capture, les paquets du fichier d'entrée dont les données capturées dépassent la longueur de capture spécifiée n'auront que la quantité de données spécifiée par la longueur de capture écrite dans le fichier de sortie.

\n

Cela peut être utile si le programme qui doit lire le fichier de sortie ne peut pas gérer les paquets de plus de certaine taille (par exemple, les versions de snoop dans Solaris 2.5.1 et Solaris 2.6 semblent rejeter les paquets Ethernet de plus de la MTU Ethernet standard, ce qui les rend incapables de gérer les captures Gigabit Ethernet si des paquets jumbo ont été utilisés).

--seed <graine>

\n
\n

Lorsqu'il est utilisé conjointement avec -E, définit la graine du générateur de nombres pseudo-aléatoires. Ceci est utile pour recréer une séquence d'erreurs particulière.

\n
\n

--skip-radiotap-header

\n
\n

Ignore l'en-tête radiotap de chaque trame lors de la vérification des doublons de paquets. Ceci est utile lors du traitement d'une capture créée en combinant les sorties de plusieurs périphériques de capture sur le même canal à proximité les uns des autres.

\n
\n

-S <ajustement temporel strict>

\n
\n

Ajuste le temps des paquets sélectionnés pour assurer un ordre chronologique strict.

\n

La valeur <ajustement temporel strict> représente des secondes relatives spécifiées comme secondes[.secondes fractionnaires].

\n

Lorsque le fichier de capture est traité, le temps absolu de chaque paquet est éventuellement ajusté pour être égal ou supérieur à l'horodatage absolu du paquet précédent, en fonction de la valeur de <ajustement temporel strict>.

\n

Si la valeur <ajustement temporel strict> est de 0 ou supérieure (par exemple, 0,000001), alors seuls les paquets dont l'horodatage est inférieur à celui du paquet précédent seront ajustés. La valeur de l'horodatage ajusté sera égale à la valeur de l'horodatage du paquet précédent plus la valeur de <ajustement temporel strict>. Une valeur de <ajustement temporel strict> de 0 ajustera le nombre minimum de valeurs d'horodatage nécessaires pour garantir que le fichier de capture résultant est dans un ordre chronologique strict.

\n

Si la valeur <ajustement temporel strict> est spécifiée comme une valeur négative, alors les valeurs d'horodatage de tous les paquets seront ajustées pour être égales à la valeur de l'horodatage du paquet précédent plus la valeur absolue de <ajustement temporel strict>. Une valeur de <ajustement temporel strict> de -0 entraînera que tous les paquets auront la valeur d'horodatage du premier paquet.

\n

Cette fonctionnalité est utile lorsque le fichier de trace contient un paquet occasionnel avec une durée delta négative par rapport au paquet précédent.

\n
\n

-t <ajustement temporel>

\n
\n

Définit l'ajustement temporel à utiliser sur les paquets sélectionnés. Si le drapeau -t est utilisé pour spécifier un ajustement temporel, l'ajustement spécifié sera appliqué à tous les paquets sélectionnés dans le fichier de capture. L'ajustement est spécifié comme secondes[.secondes fractionnaires]. Par exemple, -t 3600 avance l'horodatage des paquets sélectionnés d'une heure tandis que -t -0,5 réduit l'horodatage des paquets sélectionnés d'une demi-seconde.

\n

Cette fonctionnalité est utile lors de la synchronisation de dumps collectés sur différentes machines où la différence de temps entre les deux machines est connue ou peut être estimée.

\n
\n

-T <type d'encapsulation>

\n
\n

Définit le type d'encapsulation des paquets du fichier de capture de sortie. Si le drapeau -T est utilisé pour spécifier un type d'encapsulation, le type d'encapsulation du fichier de capture de sortie sera forcé au type spécifié. editcap -T fournit une liste des types disponibles. Le type par défaut est celui qui convient au type d'encapsulation du fichier de capture d'entrée.

\n

Remarque : cela force simplement le type d'encapsulation du fichier de sortie au type spécifié ; les en-têtes de paquets des paquets ne seront pas traduits du type d'encapsulation du fichier de capture d'entrée au type d'encapsulation spécifié (par exemple, il ne traduira pas une capture Ethernet en une capture FDDI si une capture Ethernet est lue et que '-T fddi' est spécifié). Si vous avez besoin de supprimer/ajouter des en-têtes d'un paquet, vous aurez besoin de od(1)/text2pcap(1).

La <fenêtre temporelle des doublons> est spécifiée comme secondes[.secondes fractionnaires].

--log-level

<level>
Définit le niveau de journalisation actif. Les niveaux pris en charge, du plus bas au plus élevé, sont "noisy", "debug", "info", "message", "warning", "critical" et "error". Les messages de chaque niveau et supérieur seront imprimés, par exemple "warning" imprime les messages "warning", "critical" et "error", et "noisy" imprime tous les messages. Les niveaux ne sont pas sensibles à la
casse.

--log-fatal

<level>
Interrompt le programme si des messages sont journalisés au niveau spécifié ou supérieur. Par exemple, "warning" interrompt sur tout message "warning", "critical" ou
"error".

--log-domains

<list>
N'imprime que les messages pour les domaines de journalisation spécifiés, par ex. "GUI,Epan,sshdump". La liste des domaines doit être séparée par des virgules. Peut être niée avec "!" comme premier caractère (inverse la correspondance)
.

--log-debug

<list>
Force les domaines spécifiés à journaliser au niveau "debug". La liste des domaines doit être séparée par des virgules. Peut être niée avec "!" comme premier caractère (inverse la correspondance)
.

--log-noisy

<list>
Force les domaines spécifiés à journaliser au niveau "noisy". La liste des domaines doit être séparée par des virgules. Peut être niée avec "!" comme premier caractère (inverse la correspondance)
.

--log-fatal-domains

<list>
Interrompt le programme si des messages sont journalisés pour les domaines de journalisation spécifiés. La liste des domaines doit être séparée par des
virgules.

--log-file

<path>
