ED(1P) Manuel du programmeur POSIX ED(1P)

PROLOGUE

Cette page de manuel fait partie du Manuel du programmeur POSIX. L'implémentation Linux de cette interface peut différer (consultez la page de manuel Linux correspondante pour les détails du comportement de Linux), ou l'interface peut ne pas être implémentée sur Linux.

NOM

ed — éditeur de texte

SYNOPSIS

ed [-p chaîne] [-s] [fichier]

DESCRIPTION

L'utilitaire ed est un éditeur de texte orienté ligne qui utilise deux modes : le mode commande et le mode saisie. En mode commande, les caractères saisis sont interprétés comme des commandes, et en mode saisie, ils sont interprétés comme du texte. Voir la section DESCRIPTION ÉTENDUE.

Si un opérande est '-', les résultats ne sont pas spécifiés.

OPTIONS

L'utilitaire ed doit être conforme au volume Définitions de Base de POSIX.1-2017, Section 12.2, Conventions de syntaxe des utilitaires, à l'exception de l'utilisation non spécifiée de '-'.

Les options suivantes doivent être prises en charge :

-p chaîne
Utilise chaîne comme chaîne d'invite lorsque le mode commande est actif. Par défaut, il n'y a pas de chaîne d'invite.
-s
Supprime l'écriture des comptes d'octets par les commandes e, E, r et w, ainsi que l'invite '!' après une commande !commande.

OPÉRANDES

L'opérande suivant doit être pris en charge :

fichier
Si l'argument fichier est fourni, ed simule une commande e sur le fichier nommé par le chemin fichier, avant d'accepter les commandes depuis l'entrée standard.

ENTRÉE STANDARD

L'entrée standard doit être un fichier texte composé de commandes, comme décrit dans la section DESCRIPTION ÉTENDUE.

FICHIERS D'ENTRÉE

Les fichiers d'entrée doivent être des fichiers texte.

VARIABLES D'ENVIRONNEMENT

Les variables d'environnement suivantes doivent affecter l'exécution de ed :

HOME
Détermine le chemin d'accès au répertoire personnel de l'utilisateur.
LANG
Fournit une valeur par défaut pour les variables d'internationalisation qui sont non définies ou vides. (Voir le volume Définitions de Base de POSIX.1-2017, Section 8.2, Variables d'internationalisation pour la priorité des variables d'internationalisation utilisées pour déterminer les valeurs des catégories de localisation.)
LC_ALL
Si défini à une chaîne de caractères non vide, remplace les valeurs de toutes les autres variables d'internationalisation.
LC_COLLATE

Détermine la localisation pour le comportement des plages, des classes d'équivalence et des éléments de tri multi-caractères dans les expressions régulières.
LC_CTYPE
Détermine la localisation pour l'interprétation des séquences d'octets de données textuelles en caractères (par exemple, caractères mono-octet par opposition à multi-octets dans les arguments et les fichiers d'entrée) et le comportement des classes de caractères dans les expressions régulières.
LC_MESSAGES

Détermine la localisation qui doit être utilisée pour affecter le format et le contenu des messages de diagnostic écrits sur la sortie standard d'erreur et des messages informatifs écrits sur la sortie standard.
NLSPATH
Détermine l'emplacement des catalogues de messages pour le traitement de LC_MESSAGES.

ÉVÉNEMENTS ASYNCHRONES

L'utilitaire ed doit prendre l'action standard pour tous les signaux (voir la section ÉVÉNEMENTS ASYNCHRONES dans Section 1.4, Défauts de description des utilitaires) à l'exception des suivants :

SIGINT
L'utilitaire ed doit interrompre son activité en cours, écrire la chaîne "?\n" sur la sortie standard, et retourner au mode commande (voir la section DESCRIPTION ÉTENDUE).
SIGHUP
Si le tampon n'est pas vide et a été modifié depuis la dernière écriture, l'utilitaire ed doit tenter d'écrire une copie du tampon dans un fichier. D'abord, le fichier nommé ed.hup dans le répertoire courant sera utilisé ; si cela échoue, le fichier nommé ed.hup dans le répertoire spécifié par la variable d'environnement HOME sera utilisé. Dans tous les cas, l'utilitaire ed doit se terminer sans écrire le fichier sur le chemin mémorisé actuellement et sans retourner au mode commande.
SIGQUIT
L'utilitaire ed doit ignorer cet événement.

SORTIE STANDARD

Diverses commandes d'édition et la fonction d'invite (voir -p) écrivent sur la sortie standard, comme décrit dans la section DESCRIPTION ÉTENDUE.

SORTIE STANDARD D'ERREUR

La sortie standard d'erreur ne doit être utilisée que pour les messages de diagnostic.

FICHIERS DE SORTIE

Les fichiers de sortie doivent être des fichiers texte dont les formats dépendent des commandes d'édition fournies.

DESCRIPTION ÉTENDUE

L'utilitaire ed opère sur une copie du fichier qu'il édite ; les modifications apportées à la copie n'ont aucun effet sur le fichier jusqu'à ce qu'une commande w (write, écrire) soit donnée. La copie du texte est appelée le tampon.

Les commandes de ed ont une structure simple et régulière : zéro, une ou deux adresses suivies d'une commande d'un seul caractère, éventuellement suivie de paramètres pour cette commande. Ces adresses spécifient une ou plusieurs lignes dans le tampon. Chaque commande nécessitant des adresses a des adresses par défaut, de sorte que les adresses peuvent souvent être omises. Si l'option -p est spécifiée, la chaîne d'invite est écrite sur la sortie standard avant chaque commande lue.

En général, une seule commande peut apparaître sur une ligne. Certaines commandes permettent la saisie de texte. Ce texte est placé à l'endroit approprié dans le tampon. Pendant que ed accepte du texte, on dit qu'il est en mode saisie. Dans ce mode, aucune commande n'est reconnue ; toute saisie est simplement collectée. Le mode saisie est terminé en saisissant une ligne composée de deux caractères : un <point> ('.') suivi d'un <newline>. Cette ligne n'est pas considérée comme faisant partie du texte saisi.

Expressions Régulières dans ed

L'utilitaire ed prend en charge les expressions régulières de base, telles que décrites dans le volume Définitions de Base de POSIX.1-2017, Section 9.3, Expressions Régulières de Base. Comme les expressions régulières dans ed sont toujours comparées à des lignes uniques (à l'exclusion des caractères <newline> de terminaison), jamais à une section de texte plus large, il n'y a aucun moyen pour une expression régulière de correspondre à un <newline>.

Une RE nulle est équivalente à la dernière RE rencontrée.

Les expressions régulières sont utilisées dans les adresses pour spécifier des lignes, et dans certaines commandes (par exemple, la commande de substitution s) pour spécifier des parties d'une ligne à substituer.

    Certaines des différences entre les

L' option -s a été ajoutée pour permettre la fonctionnalité de l'
    option - supprimée d'une manière compatible avec les
    Lignes directrices de syntaxe des 
utilitaires.

Dans les propositions initiales, il y avait une limite, {ED_FILE_MAX}, qui
    décrivait les limitations historiques de certaines utilitaires ed dans leur
    traitement des fichiers volumineux ; certaines d'entre elles ont eu des problèmes avec des fichiers plus grands
    que 100000 octets. C'est cette limitation qui a motivé en grande partie le désir
    d'inclure une commande split dans ce volume de POSIX.1‐2017.
    Étant donné que cette limite a été supprimée, ce volume de POSIX.1‐2017 exige
    que les implémentations documentent les limites de taille de fichier imposées par ed dans
    le document de conformité. La limite {ED_LINE_MAX} a également été supprimée ;
    par conséquent, la limite globale {LINE_MAX} est utilisée pour les lignes d'entrée et de 
sortie.

La manière dont la commande l écrit les caractères non imprimables
    a été modifiée pour éviter la méthode historique de surimpression de retour arrière.
    Sur les terminaux d'affichage vidéo, la surimpression est ambiguë car la plupart
    des terminaux remplacent simplement les caractères surimprimés, ce qui rend le format l
    inutile pour son objectif visé de comprendre sans ambiguïté le
    contenu de la ligne. Les <backslash>-échappements historiques étaient également
    ambigus. (La chaîne "a\0011" pouvait représenter une ligne
    contenant ces six caractères ou une ligne contenant les trois caractères
    'a', un octet avec une valeur binaire de 1, et un 1.) Dans le format
    requis ici, un <backslash> apparaissant dans la ligne est écrit comme
    "\\" afin que la sortie soit véritablement non ambiguë. La méthode de
    marquage des fins de lignes a été adoptée à partir de l'éditeur ex et est
    requise pour toute ligne se terminant par des caractères <space> ; le '$' est
    placé sur toutes les lignes afin qu'un vrai '$' à la fin d'une ligne ne puisse pas être
    mal 
interprété.

Les versions antérieures de cette norme permettaient des implémentations avec
    des octets autres que huit bits, mais cela a été modifié dans cette 
version.

La description de la manière dont un NUL est écrit a été supprimée. Le caractère
    NUL ne peut pas se trouver dans des fichiers texte, et ce volume de POSIX.1‐2017
    ne devrait pas dicter de comportement en cas d'entrée indéfinie ou 
erronée.

Contrairement à certaines des autres utilitaires d'édition, les noms de fichiers acceptés par les commandes E, e, R et r ne sont pas
  des 
motifs.

Les propositions initiales indiquaient que l' option -p ne fonctionnait que lorsque
    l'entrée standard était associée à un périphérique terminal. Cela a été modifié
    pour se conformer aux implémentations historiques, permettant ainsi aux applications de
    s'interposer entre un utilisateur et l' utilitair
e ed.

La forme de la commande de substitution utilisant le suffixe n
    était limitée dans certaines documentations historiques (où cela était décrit
    incorrectement comme « backreferencing »). Cette limite a été omise car
    il n'y a aucune raison pour qu'un éditeur traitant des lignes de longueur {LINE_MAX} ait
    cette restriction. La commande s/x/X/2047 devrait pouvoir
    substituer la 2047e occurrence de 'x' sur une 
ligne.

L'utilisation des commandes d'impression avec des suffixes d'impression (comme
    pn, lp, etc.) a été rendue indéfinie car les systèmes basés sur BSD
    le permettent, alors que System V ne le permet 
pas.

Certains systèmes basés sur BSD se terminent immédiatement à la réception de
    la fin de fichier si toutes les lignes du fichier ont été supprimées. Puisque ce
    volume de POSIX.1‐2017 fait référence à la commande q dans ce
    cas, un tel comportement n'est pas 
autorisé.

Certaines implémentations historiques renvoyaient un statut de sortie zéro même si
    des erreurs de commande s'étaient produites ; cela n'est pas autorisé par ce volume de
    POSIX.
1‐2017.

Certaines implémentations historiques contenaient un bogue permettant à un
    unique <period> d'être saisi en mode d'entrée sous la forme <backslash>
    <period> <newline>. Cela n'est pas autorisé par ed car
    il n'y a aucune description d'échappement de l'un des caractères en mode d'entrée ;
    les caractères <backslash> sont entrés dans le tampon exactement comme tapés.
    La méthode typique pour saisir un unique <period> a été de le faire
    précéder d'un autre caractère puis d'utiliser la commande de substitution pour supprimer ce
    
caractère.

Il est difficile, sous certains modes de certains pilotes de terminaux de systèmes d'exploitation historiques, de distinguer une condition de fin de fichier
    d'une déconnexion de terminal. POSIX.1‐2008 n'exige pas
    des implémentations qu'elles distinguent les deux situations, ce qui permet
    aux implémentations historiques de l' utilitaire ed sur des plateformes historiques
    de se conformer. Les implémentations sont encouragées à distinguer les deux,
    si possible, et à prendre des mesures appropriées en cas de déconnexion de 
terminal.

Historiquement, ed acceptait une adresse zéro pour les commandes a
    et r afin d'insérer du texte au début du tampon d'édition.
    Lorsque le tampon était vide, la commande .= renvoyait zéro.
    POSIX.1‐2008 exige la conformité à la pratique 
historique.

Pour la cohérence avec les commandes a et r et pour une meilleure
    fonctionnalité utilisateur, les commandes i et c doivent également accepter une

Un nombre quelconque d'adresses peut être fourni aux commandes prenant
    des adresses ; par exemple, "1,2,3,4,5p" imprime les lignes 4 et 5,
    car deux est le plus grand nombre valide d'adresses accepté par la

    permet aux utilisateurs de créer des commandes basées sur des motifs ordonnés dans le
    fichier. Par exemple, la commande "3;/foo/;+2p" affichera
    la première ligne après la ligne 3 contenant le motif foo, plus les
    deux lignes suivantes. Notez que l'adresse "3;" doit toujours être
    évaluée avant d'être écartée, car l'origine de recherche pour la
    commande "/foo/" en 
dépend.
