NOM

edtx2dtx - Convertir .edtx en .dtx

SYNOPSIS

edtx2dtx nom_fichier.edtx > nom_fichier.dtx

DESCRIPTION

Cet utilitaire encapsule les blocs de code par une paire (commentée et correctement indentée) de \begin{macrocode} et \end{macrocode}. Un bloc de code est toute séquence de lignes non introduite par un seul caractère de commentaire (éventuellement indenté) (%) ; c'est-à-dire que les lignes non commentées et les lignes introduites par plusieurs caractères de commentaire sont considérées comme du code, et les lignes de documentation peuvent être indentées.

La partie du fichier qui doit être traitée doit être marquée par une paire \begin{macrocode} et \end{macrocode}. Autrement dit, tout ce qui précède \begin{macrocode} est considéré comme un en-tête et n'est pas modifié, et tout ce qui suit \end{macrocode} est considéré comme un pied de page et n'est pas modifié. En fait, un nombre quelconque de paires \begin{macrocode} — \end{macrocode} est autorisé. (Le système permet de conserver le pilote tel quel, et facilite également le collage d'un fichier .dtx dans un .edtx, car l'utilisation de cet utilitaire sur un .dtx ne modifie pas le fichier.)

En outre, l'utilitaire remplace la première occurrence de <nom_fichier>.edtx dans l'en-tête, suivie d'une note optionnelle entre parenthèses, par <nom_fichier>.dtx, plus la note sur la façon dont le fichier a été généré.

OPTIONS

-c, --comment
Le caractère de commentaire d'entrée ; par défaut, c'est %. (Tous les caractères de commentaire d'entrée dans l'en-tête et le pied de page seront remplacés par le caractère de commentaire de sortie, qui est toujours %.)

-b, --begin-macrocode regex

-e, --end-macrocode regex
Utilisez ces options pour modifier les marqueurs d'entrée par défaut \begin{macrocode} et \end{macrocode}. (Les marqueurs de sortie sont toujours \begin{macrocode} et \end{macrocode}.) Les marqueurs doivent être donnés sous forme d'expressions régulières correspondant à la ligne entière. Les marqueurs d'entrée ne sont pas conservés dans le fichier, c'est-à-dire qu'ils sont remplacés par les marqueurs de sortie.

-B, --Begin-macrocode regex

-E, --End-macrocode regex
Comme -b et -e, mais les marqueurs d'entrée sont conservés en sortie.
-s, --strip-empty
Si cette option est donnée, les lignes vides ne sont pas incluses dans la sortie.
-h, --help
Afficher l'aide et quitter.
-V, --version
Afficher le numéro de version et quitter.

EXEMPLES

Si input.edtx est semblable à un fichier dtx, mais sans \begin{macrocode} et \end{macrocode} autour de chaque bloc de code :

edtx2dtx input.edtx > output.dtx

Memoize utilise l'invocation ci-dessous pour produire un .dtx à partir du code documenté de Python de memoize-extract.py. La valeur de -c adapte edtx2dtx aux commentaires Python. -B marque tout ce qui précède la déclaration du numéro de version comme en-tête, et conserve la déclaration du numéro de version en sortie. De même, -E indique que le traitement doit s'arrêter à la rencontre des variables locales d'Emacs (qui sont conservées, inchangées, en sortie).

edtx2dtx -s -c '#' -B '^__version__' -E '^# Local Variables:' $< \
