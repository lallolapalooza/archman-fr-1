SYNOPSI

S

edid-decode

DESCRIPTIO

N

edid-decode décode les données de description du moniteur EDID dans un format lisible par l'humain. Si [in] n'est pas donné, ou si [in] est '-', l'EDID sera lu depuis l'entrée standard. Si [out] est donné, alors l'EDID lu depuis [in] est écrit vers [out] ou vers la sortie standard si [out] est '-'. Par défaut, la sortie est écrite sous forme de dump hexadécimal lors de l'écriture vers la sortie standard ou un EDID brut si écrit vers un

fichier.

Si [out] est donné, alors edid-decode ne fait que la conversion, il sautera l'étape de

décodage.

Les fichiers d'entrée peuvent être des binaires bruts ou du texte ASCII. L'entrée ASCII est scannée à la recherche de dumps hexadécimaux ; des heuristiques sont incluses pour rechercher des dumps hexadécimaux dans la sortie de edid-decode(1) (tant que le dump hexadécimal initial était inclus), la sortie des propriétés de xrandr(1) et les formats de fichier journal de Xorg(1), sinon les données sont traitées comme un dump hexadécimal brut. Les blocs EDID des moniteurs connectés peuvent être trouvés dans /sys/class/drm/*/edid sur les systèmes Linux modernes prenant en charge le modesetting du

noyau.

Tous les timings sont affichés dans un format court, par exemple

:


VIC 16 : 1920x1080 60.000 Hz 16:9 67.500 kHz 148.500 MHz (natif)
VIC 5 : 1920x1080i 60.000 Hz 16:9 33.750 kHz 74.250 MHz
VIC 39 : 1920x1080i 50.000 Hz 16:9 31.250 kHz 72.000

MHz

Chaque format commence par un préfixe de type de timing, la résolution, un indicateur entrelacé optionnel ('i'), la fréquence d'images (fréquence de champ pour les formats entrelacés), le rapport d'aspect de l'image, la fréquence horizontale, la fréquence d'horloge de pixel et éventuellement des drapeaux supplémentaires entre

parenthèses.

Notez que pour les formats entrelacés, la hauteur d'image est donnée, et non la hauteur de champ. Ainsi, chaque champ dans un format 1920x1080i a 540

lignes.

Les timings détaillés ont d'autres 2-3 lignes de données

:


VIC 16 : 1920x1080 60.000 Hz 16:9 67.500 kHz 148.500 MHz (natif)
Hfront 88 Hsync 44 Hback 148 Hpol P
Vfront 4 Vsync 5 Vback 36 Vpol P
VIC 5 : 1920x1080i 60.000 Hz 16:9 33.750 kHz 74.250 MHz
Hfront 88 Hsync 44 Hback 148 Hpol P
Vfront 2 Vsync 5 Vback 15 Vpol P Vfront +0.5 Champ impair
Vfront 2 Vsync 5 Vback 15 Vpol P Vback +0.5 Champ pair
VIC 39 : 1920x1080i 50.000 Hz 16:9 31.250 kHz 72.000 MHz
Hfront 32 Hsync 168 Hback 184 Hpol P
Vfront 23 Vsync 5 Vback 57 Vpol N Les deux

champs

Celles-ci décrivent les valeurs de front porch, sync, back porch et polarité de synchronisation horizontales et verticales. Pour les formats entrelacés, il y a deux lignes pour les informations verticales : une pour le champ impair (aka champ 1) et une pour le champ pair (aka champ 2). Le front porch vertical du champ impair est en fait 2.5 (d'où le 'Vfront +0.5' à la fin de la ligne), et le back porch du champ pair est en fait 15.5 (d'où le 'Vback +0.5' à la fin de la ligne)

.

Il existe un format entrelacé spécial 'VIC 39' où les deux champs ont les mêmes timings verticaux, dans ce cas cela est marqué avec 'Les deux

champs'.

n]
[,alt][,hblank=<hblank>][,vblank=<vblank>][,early-vsync]
Calcule les timings CVT pour le format donné.

<largeur> est la largeur en pixels, <hauteur> est la hauteur de l'image (pas du champ !) en lignes.
<ips> est le nombre d'images par seconde pour les timings progressifs et le nombre de champs par seconde pour les timings entrelacés.
<rb> peut être 0 (pas de blanking réduit, par défaut), ou 1-3 pour la version avec blanking réduit.
Si entrelacé est spécifié, alors il s'agit d'un format entrelacé.
Si overscan est spécifié, alors il s'agit d'un format avec overscan. C'est-à-dire, les marges sont requises.
Si alt est spécifié et <rb>=2, alors signale les timings optimisés pour la vidéo : 1000 / 1001 * <ips>.
Si alt est spécifié et <rb>=3, alors le blanking horizontal est de 160 au lieu de 80 pixels.
Si hblank est spécifié et <rb>=3, alors le blanking horizontal est de <hblank> pixels (de 80 à 200 et divisible par 8), remplaçant alt.
Si vblank est spécifié et <rb>=3, alors la durée du blanking vertical est de <vblank> microsecondes (460 minimum, les valeurs > 705 pourraient ne pas être prises en charge par toutes les sources compatibles avec les timings RBv3).
Si early-vsync est spécifié et <rb>=3, alors sélectionne un

timing avec
vsync anticipé.

Calcule les timings GTF pour le format donné.

<largeur> est la largeur en pixels, <hauteur> est la hauteur de l'image (pas du champ !) en lignes.
<ips> est le nombre d'images par seconde pour les timings progressifs et le nombre de champs par seconde pour les timings entrelacés.
<freqhor> est la fréquence horizontale en kHz.
<horlogepix> est la fréquence de l'horloge des pixels en MHz. Un seul parmi fps, horfreq ou pixclk doit être spécifié.
Si entrelacé est spécifié, alors il s'agit d'un format entrelacé.
Si overscan est spécifié, alors il s'agit d'un format avec overscan. C'est-à-dire, les marges sont requises.
Si secondary est spécifié, alors le GTF secondaire est utilisé pour le blanking réduit, où <c>, <m>, <k> et <j> sont les paramètres de la courbe secondaire. NOTE

S

Tous les champs ne sont pas décodés, ou complètement décodés. edid-decode tente de valider ses entrées par rapport aux normes pertinentes, mais ses conclusions n'ont pas été revérifiées par les organismes de normalisation concernés, elles peuvent donc ê

tre erronées. Ne vous fiez pas au format de sortie, car il changera probablement dans les futur
es versions de l'outil à mesure que des champs et des extensions supplémentaires seront ajoutés.
