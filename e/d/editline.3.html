DESCRIPTION

La bibliothèque editline fournit des fonctions génériques d'édition de ligne, d'historique et de tokenisation, similaires à celles trouvées dans sh(1).

Ces fonctions sont disponibles dans la bibliothèque libedit (qui nécessite la bibliothèque libtermcap ). Les programmes doivent être liés avec -ledit -ltermcap.

La bibliothèque editline respecte la locale LC_CTYPE définie par le programme applicatif et n'utilise jamais setlocale(3) pour changer la locale.

FONCTIONS D'ÉDITION DE LIGNE

Les fonctions d'édition de ligne utilisent une structure de données commune, EditLine, qui est créée par el_init() ou el_init_fd() et libérée par el_end().

Les fonctions pour caractères larges se comportent de la même manière que leurs homologues étroits.

Les fonctions suivantes sont disponibles :

el_init()
Initialise l'éditeur de ligne et renvoie une structure de données à utiliser par toutes les autres fonctions d'édition de ligne, ou NULL en cas d'échec. prog est le nom du programme appelant, utilisé lors de la lecture du fichier editrc(5) pour déterminer les paramètres à utiliser. fin, fout et ferr sont les flux d'entrée, de sortie et d'erreur (respectivement) à utiliser. Dans cette documentation, les références à « the tty » (le terminal) désignent en réalité cette combinaison de flux d'entrée/sortie.
el_init_fd()
Comme el_init() mais permet de spécifier des descripteurs de fichier pour les flux stdio(3) correspondants, au cas où ceux-ci auraient été créés avec funopen(3).
el_end()
Nettoie et termine avec e, supposé avoir été créé avec el_init() ou el_init_fd().
el_reset()
Réinitialise le terminal et l'analyseur. Cela devrait être appelé après une erreur qui aurait pu perturber l'état du terminal.
el_gets()
Lit une ligne depuis le terminal. count est modifié pour contenir le nombre de caractères lus. Renvoie la ligne lue en cas de succès, ou NULL si aucun caractère n'a été lu ou si une erreur s'est produite. Si une erreur s'est produite, count est défini à -1 et errno contient le code d'erreur qui l'a causée. La valeur de retour peut ne pas rester valide entre les appels à el_gets() et doit être copiée si les données doivent être conservées.
el_wgetc()
Lit un caractère large depuis le terminal, en respectant la locale actuelle, ou depuis la file d'entrée décrite dans editline(7) si celle-ci n'est pas vide, et le stocke dans wc. Si un caractère invalide ou incomplet est trouvé, il est ignoré, errno est défini à EILSEQ, et le caractère suivant est lu et stocké dans wc. Renvoie 1 si un caractère valide a été lu, 0 en fin de fichier, ou -1 en cas d'échec de read(2) . Dans ce dernier cas, errno est défini pour indiquer l'erreur.
el_getc()
Lit un caractère large comme décrit pour el_wgetc() et renvoie 0 en fin de fichier ou -1 en cas d'échec. Si le caractère large peut être représenté comme un caractère d'un seul octet, convertissez-le avec wctob(3), stockez le résultat dans ch, et renvoyez 1 ; sinon, définissez errno à ERANGE et renvoyez -1. Dans la locale C ou POSIX, cela lit simplement un octet, mais pour toute autre locale, y compris UTF-8, cela est rarement utile.
el_wpush()
Remet la chaîne de caractères larges wcs sur la file d'entrée décrite dans editline(7). Si la file déborde, par exemple à cause d'une macro récursive, ou si une erreur se produit, par exemple parce que wcs est NULL ou que l'allocation de mémoire échoue, la fonction émet un bip pour l'utilisateur, mais ne signale pas le problème à l'appelant.
el_push()
Utilise la locale actuelle pour convertir la chaîne multioctets mbs en une chaîne de caractères larges, et passe le résultat à el_wpush().
el_parse()
Analyse le tableau argv (qui fait argc éléments de taille) pour exécuter les commandes intégrées editline . Si la commande est préfixée par « prog » : alors el_parse() n'exécutera la commande que si « prog » correspond à l'argument prog fourni à el_init(). La valeur de retour est -1 si la commande est inconnue, 0 s'il n'y a pas eu d'erreur ou si « prog » ne correspond pas, ou 1 si la commande a renvoyé une erreur. Consultez editrc(5) pour plus d'informations.
el_set()
Définit les paramètres editline . op détermine quel paramètre définir, et chaque opération a sa propre liste de paramètres. Renvoie 0 en cas de succès, -1 en cas d'échec.

Les valeurs suivantes pour op sont prises en charge, avec la liste d'arguments requise :

EL_PROMPT, char *(*f)(EditLine *)
Définit la fonction d'affichage de l'invite comme f, qui doit renvoyer une chaîne contenant l'invite.
EL_PROMPT_ESC, char *(*f)(EditLine *), char c
Comme EL_PROMPT, mais l'argument c indique le caractère de début/fin d'invite littérale.

Si un caractère littéral de début/fin est trouvé dans l'invite, le caractère lui-même n'est pas imprimé, mais les caractères qui le suivent sont imprimés directement sur le terminal sans affecter l'état de la ligne courante. Un second caractère littéral de début/fin ultérieur met fin à ce comportement. Ceci est typiquement utilisé pour intégrer des séquences d'échappement littérales qui changent la couleur/le style du terminal dans l'invite. Notez que le caractère d'échappement littéral ne peut pas être le dernier caractère de l'invite, car la séquence d'échappement est attachée au caractère suivant dans l'invite. 0 le désactive.

EL_REFRESH
Réaffiche la ligne courante sur la ligne du terminal suivante.
EL_RPROMPT, char *(*f)(EditLine *)
Définit la fonction d'affichage de l'invite de droite comme f, qui doit renvoyer une chaîne contenant l'invite.
EL_RPROMPT_ESC, char *(*f)(EditLine *), char c
Définit la fonction d'affichage de l'invite de droite mais avec un caractère d'échappement littéral.
EL_TERMINAL, const char *type
Définit le type de terminal du tty à type, ou à TERM si type est NULL.
EL_EDITOR, const char *mode
Définit le mode d'édition à mode, qui doit être l'un des suivants : « emacs » ou « vi ».
EL_SIGNAL, int flag
Si flag est non nul, editline installera son propre gestionnaire de signaux pour les signaux suivants lors de la lecture des entrées de commande : SIGCONT, SIGHUP, SIGINT, SIGQUIT, SIGSTOP, SIGTERM, SIGTSTPet SIGWINCH. Sinon, les gestionnaires de signaux actuels seront utilisés.
EL_BIND, const char *, ..., NULL
Exécute la commande intégrée bind . Consultez editrc(5) pour plus d'informations.
EL_ECHOTC, const char *, ..., NULL
Exécute la commande intégrée echotc . Consultez editrc(5) pour plus d'informations.
EL_SETTC, const char *, ..., NULL
Exécute la commande intégrée settc . Consultez editrc(5) pour plus d'informations.
EL_SETTY, const char *, ..., NULL
Exécute la commande intégrée setty . Consultez editrc(5) pour plus d'informations.
EL_TELLTC, const char *, ..., NULL
Exécute la commande intégrée telltc . Consultez editrc(5) pour plus d'informations.
EL_ADDFN, const char *name, const char *help, unsigned char (*func)(EditLine *e, int ch)
Ajoute une fonction définie par l'utilisateur, func(), appelée name qui est invoquée lorsqu'une touche liée à name est entrée. help est une description de name. Au moment de l'invocation, ch est la touche qui a déclenché l'invocation. La valeur de retour de func() doit être l'une des suivantes :
CC_NORM
Ajoute un caractère normal.
CC_NEWLINE
Fin de ligne entrée.
CC_EOF
EOF entré.
CC_ARGHACK
S'attend à une entrée de commande supplémentaire en tant qu'arguments, ne rien faire visuellement.
CC_REFRESH
Rafraîchit l'affichage.
CC_REFRESH_BEEP
Rafraîchit l'affichage et émet un bip.
CC_CURSOR
Le curseur s'est déplacé, mettre à jour et exécuter CC_REFRESH.
CC_REDISPLAY
Redessine toute la ligne d'entrée. C'est utile si une liaison de touche produit des informations supplémentaires.
CC_ERROR
Une erreur s'est produite. Émet un bip et vide le tty.
CC_FATAL
Erreur fatale, réinitialise le tty à un état connu.
EL_HIST, History *(*func)(History *, int op, ...), const char *ptr
Définit quelle fonction d'historique utiliser, qui est généralement history(). ptr doit être la valeur retournée par history_init().
EL_EDITMODE, int flag
Si flag est non nul, l'édition est activée (par défaut). Notez qu'il ne s'agit que d'une indication et que cela n'affecte pas le fonctionnement de editline. Actuellement, il incombe à l'appelant de vérifier cela (en utilisant el_get()) pour déterminer si l'édition doit être activée ou non.
EL_UNBUFFERED, int flag
Si flag est zéro, le mode non tamponné est désactivé (par défaut). En mode non tamponné, el_gets() retournera immédiatement après le traitement d'un seul caractère.
EL_SAFEREAD, int flag
Si l'argument flag est non nul, editline tentera de se remettre d'erreurs de lecture, en ignorant la première erreur d'interruption et en essayant de réinitialiser le descripteur de fichier d'entrée pour réinitialiser l'E/S non bloquante. C'est désactivé par défaut, et n'est souhaitable que lorsque editline est utilisé dans des applications de type shell.
EL_GETCFN, el_rfunc_t f
Lors de la lecture d'un caractère, utiliser la fonction
int f(EditLine *e, wchar_t *wc);
qui stocke le caractère dans wc et retourne 1 en cas de succès, 0 en cas de fin de fichier, ou -1 en cas d'erreur d'E/S ou d'encodage. Les fonctions qui l'utilisent en interne incluent el_wgets(), el_wgetc(), el_gets(), et el_getc(). Initialement, une fonction intégrée est installée, et il est déconseillé de la remplacer car l'écriture d'une telle fonction est très sujette aux erreurs. La fonction intégrée peut être restaurée à tout moment en passant la valeur spéciale EL_BUILTIN_GETCFN au lieu d'un pointeur de fonction.
EL_CLIENTDATA, void *data
Enregistre data pour être associé à cette structure EditLine. Il peut être récupéré avec l'appel correspondant el_get().
EL_SETFP, int fd, FILE *fp
Définit le pointeur de fichier courant de editline pour « entrée » fd = 0, « sortie » fd = 1, ou « erreur » fd = 2 à partir de fp.
el_get()
Récupère les paramètres editline . op détermine quel paramètre récupérer dans result. Retourne 0 en cas de succès, -1 sinon.

Les valeurs suivantes pour op sont prises en charge, avec le type réel de result:

EL_PROMPT, char *(*f)(EditLine *), char *c
Définit f comme un pointeur vers la fonction qui affiche l'invite. Si c n'est pas NULL, le définir comme le caractère de début/fin d'invite littérale.
EL_RPROMPT, char *(*f)(EditLine *), char *c
Définit f comme un pointeur vers la fonction qui affiche l'invite. Si c n'est pas NULL, le définir comme le caractère de début/fin d'invite littérale.
EL_EDITOR, const char **n
Définit le nom de l'éditeur dans n, qui sera l'un des suivants : « emacs » ou « vi ».
EL_GETTC, const char *name, void *value
Si name est une capacité termcap(5) valide, définir value à la valeur courante de cette capacité.
EL_SIGNAL, int *s
Définit s à non-zéro si editline a installé des gestionnaires de signaux privés (voir el_get() ci-dessus).
EL_EDITMODE, int *c
Définit c à non-zéro si l'édition est activée.
EL_GETCFN, el_rfunc_t *f
Définit f comme pointeur vers la fonction qui lit les caractères, ou vers EL_BUILTIN_GETCFN si la fonction intégrée est utilisée.
EL_CLIENTDATA, void **data
Définit data comme les données client précédemment enregistrées, définies par un appel à el_set().
EL_UNBUFFERED, int *c
Définit c à non-zéro si le mode non tamponné est activé.
EL_SAFEREAD, int *c
Définit c à non-zéro si la lecture sécurisée est activée.
EL_GETFP, int fd, FILE **fp
Définit fp comme le pointeur de fichier courant d' editline pour « entrée » fd = 0, « sortie » fd = 1, ou « erreur » fd = 2.
el_source()
Initialise editline en lisant le contenu du fichier. el_parse() est appelé pour chaque ligne du fichier. Si fichier est NULL, essaie $EDITRC et si cette variable n'est pas définie, $HOME/.editrc. Voir editrc(5) pour plus de détails sur le format du fichier. el_source() renvoie 0 en cas de succès et -1 en cas d'erreur.
el_resize()
Doit être appelé si la taille du terminal change. Si EL_SIGNAL a été défini avec el_set(), cela est fait automatiquement. Sinon, c'est à l'application d'appeler el_resize() aux moments appropriés.
el_cursor()
Déplace le curseur vers la droite (si positif) ou vers la gauche (si négatif) de count caractères. Renvoie le décalage résultant du curseur depuis le début de la ligne.
el_line()
Renvoie les informations d'édition de la ligne courante dans une structure LineInfo , définie comme suit : 
typedef struct lineinfo {
    const char *buffer;    /* adresse du tampon */
    const char *cursor;    /* adresse du curseur */
    const char *lastchar;  /* adresse du dernier caractère */
} LineInfo;

buffer n'est pas terminé par NUL. Cette fonction peut être appelée après el_gets() pour obtenir la structure LineInfo correspondant à la ligne renvoyée par cette fonction, et depuis des fonctions définies par l'utilisateur ajoutées avec EL_ADDFN.

el_insertstr()
Insère str dans la ligne à la position du curseur. Renvoie -1 si str est vide ou ne peut pas tenir, et 0 sinon.
el_deletestr()
Supprime count caractères avant le curseur.

FONCTIONS DE LISTE D'HISTORIQUE

Les fonctions d'historique utilisent une structure de données commune, History, qui est créée par history_init() et libérée par history_end().

Les fonctions suivantes sont disponibles :

history_init()
Initialise la liste d'historique et renvoie une structure de données à utiliser par toutes les autres fonctions de liste d'historique, ou NULL en cas d'échec.
history_end()
Nettoie et termine avec h, supposé avoir été créé avec history_init().
history()
Effectue l'opération op sur la liste d'historique, avec les arguments optionnels requis par l'opération. ev est modifié en conséquence par l'opération. Les valeurs suivantes pour op sont supportées, avec la liste d'arguments requise :
H_SETSIZE, int size
Définit la taille de l'historique à size éléments.
H_GETSIZE
Renvoie le nombre d'événements actuellement dans l'historique.
H_END
Nettoie et termine avec h, supposé être créé avec history_init().
H_CLEAR
Efface l'historique.
H_FUNC, void *ptr, history_gfun_t first, history_gfun_t next, history_gfun_t last, history_gfun_t prev, history_gfun_t curr, history_sfun_t set, history_vfun_t clear, history_efun_t enter, history_efun_t add
Définit les fonctions pour effectuer diverses opérations d'historique. ptr est l'argument donné à une fonction lorsqu'elle est invoquée.
H_FIRST
Renvoie le premier élément de l'historique.
H_LAST
Renvoie le dernier élément de l'historique.
H_PREV
Renvoie l'élément précédent de l'historique. Il est plus récent que l'actuel.
H_NEXT
Renvoie l'élément suivant de l'historique. Il est plus ancien que l'actuel.
H_CURR
Renvoie l'élément courant de l'historique.
H_SET, int position
Définit le curseur pour qu'il pointe vers l'élément demandé.
H_ADD, const char *str
Ajoute str à l'élément courant de l'historique, ou effectue l'opération H_ENTER avec l'argument str s'il n'y a pas d'élément courant.
H_APPEND, const char *str
Ajoute str au dernier nouvel élément de l'historique.
H_ENTER, const char *str
Ajoute str comme nouvel élément à l'historique et, si nécessaire, supprime l'entrée la plus ancienne pour maintenir la liste à la taille créée. Si H_SETUNIQUE a été appelé avec un argument non nul, l'élément ne sera pas ajouté à l'historique si son contenu correspond à celui de l'élément courant de l'historique. Si l'élément est ajouté, history() renvoie 1 ; s'il est ignoré comme doublon, renvoie 0. Enfin, history() renvoie -1 si une erreur est survenue.
H_PREV_STR, const char *str
Renvoie l'événement précédent le plus proche qui commence par str.
H_NEXT_STR, const char *str
Renvoie l'événement suivant le plus proche qui commence par str.
H_PREV_EVENT, int e
Renvoie l'événement précédent numéroté e.
H_NEXT_EVENT, int e
Renvoie l'événement suivant numéroté e.
H_LOAD, const char *file
Charge la liste d'historique stockée dans fichier.
H_SAVE, const char *file
Enregistre la liste d'historique vers fichier.
H_SAVE_FP, FILE *fp
Enregistrer la liste d'historique dans le pointeur FILE ouvert fp.
H_NSAVE_FP, size_t n, FILE *fp
Enregistrer les n dernières entrées d'historique dans le pointeur FILE ouvert fp.
H_SETUNIQUE, int unique
Définir le drapeau indiquant que les chaînes d'événements identiques adjacentes ne doivent pas être ajoutées à l'historique.
H_GETUNIQUE
Récupérer le réglage actuel indiquant si les éléments identiques adjacents doivent être ajoutés à l'historique.
H_DEL, int e
Supprimer l'événement numéroté e. Cette fonction est fournie uniquement pour la compatibilité avec readline . L'appelant est responsable du free de la chaîne dans le HistEventretourné.

history() renvoie >= 0 si l'opération op réussit. Sinon, -1 est renvoyé et ev est mis à jour pour contenir plus de détails sur l'erreur.

FONCTIONS DE TOKENISATION

Les fonctions de tokenisation utilisent une structure de données commune, Tokenizer, qui est créée par tok_init() et libérée par tok_end().

Les fonctions suivantes sont disponibles :

tok_init()
Initialiser le tokenizer et renvoyer une structure de données à utiliser par toutes les autres fonctions de tokenisation. IFS contient les séparateurs de champs d'entrée (Input Field Separators), qui par défaut sont ⟨espace⟩, ⟨tabulation⟩ et ⟨nouvelle ligne⟩ si NULL.
tok_end()
Nettoyer et terminer avec t, supposé avoir été créé avec tok_init().
tok_reset()
Réinitialiser l'état du tokenizer. À utiliser après qu'une ligne a été tokenisée avec succès par tok_line() ou tok_str() et avant qu'une nouvelle ligne soit tokenisée.
tok_line()
Tokeniser li. En cas de succès, modifier : argv pour contenir les mots, argc pour contenir le nombre de mots, cursorc (si non NULL) pour contenir l'index du mot contenant le curseur, et cursoro (si non NULL) pour contenir le décalage dans argv[cursorc] du curseur.

Renvoie 0 en cas de succès, -1 pour une erreur interne, 1 pour une guillemet simple non appariée, 2 pour une guillemet double non appariée, et 3 pour une ⟨nouvelle ligne⟩ protégée par une barre oblique inverse. Un code de sortie positif indique qu'une autre ligne doit être lue et que la tokenisation doit être tentée à nouveau.

tok_str()
Une forme plus simple de tok_line() ; str est une chaîne terminée par NUL à tokeniser.

VOIR AUSSI

HISTORIQUE

La bibliothèque editline est apparue pour la première fois dans 4.4BSD. CC_REDISPLAY est apparu dans NetBSD 1.3. CC_REFRESH_BEEP, EL_EDITMODE et l'émulation readline sont apparus dans NetBSD 1.4. EL_RPROMPT est apparu dans NetBSD 1.5.

AUTEURS

La bibliothèque editline a été écrite par Christos Zoulas. Luke Mewburn a écrit ce manuel et implémenté CC_REDISPLAY, CC_REFRESH_BEEP, EL_EDITMODEet EL_RPROMPT. Jaromir Dolecek a implémenté l'émulation readline. Johny Mattsson a implémenté la prise en charge des caractères larges.

BUGS

Actuellement, il est de la responsabilité de l'appelant de vérifier le résultat de l'opération EL_EDITMODE de el_get() (après un el_source() ou un el_parse()) pour déterminer si editline doit être utilisé pour la saisie suivante. C'est-à-dire que EL_EDITMODE est purement une indication du résultat de la commande editrc(5) edit la plus récente.
