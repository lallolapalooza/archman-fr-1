eza_colors — personnalisation d

es couleurs des fichiers et de
l'interface utilisateur de eza

SYNOPSI

S

La variable d'environnement EZA_COLORS peut être utilisée pour personnaliser les couleurs que eza utilise pour mettre en évidence les noms de fichiers, les métadonnées des fichiers et les parties de l'interface

utilisateur.

Vous pouvez utiliser le programme dircolors pour générer un script qui définit la variable à partir d'un fichier d'entrée, ou si vous n'avez pas d'objection à éditer de longues chaînes de texte, vous pouvez simplement la taper directement. Ces variables ont la structure suivante

:
•
Une liste de paires clé-valeur séparées par `=', telles que `*.txt=3
2'.
•
Plusieurs codes de formatage ANSI sont séparés par `;', tels que `*.txt=32;1;
4'.
•
Enfin, plusieurs paires sont séparées par `:', telles que `*.txt=32:*
.mp3=1
;35'.

La partie clé de la paire peut être soit un code de deux lettres, soit un motif de fichier (glob), et tout ce qui n'est pas un code valide sera traité comme un motif, y compris les clés qui ont par hasard deux lettres de

long.

Pour la rétrocompatibilité la variable d'environnement EXA_COLORS est vérifiée si EZA_COLORS n'est

pas
définie.

De nombreux terminaux traiteront le texte en gras comme une couleur différente, ou fourniront au moins cette

option.

eza fournit son propre ensemble intégré de correspondances d'extensions de fichiers qui couvre une large gamme d'extensions de fichiers courantes, y compris les documents, les archives, les médias et les fichiers temporaires. Toute correspondance dans les variables d'environnement remplacera cet ensemble par défaut : exécuter eza avec LS_COLORS="*.zip=32" rendra les fichiers zip verts mais laissera les couleurs des autres fichiers compressés

inchangées.

Vous pouvez également désactiver entièrement cet ensemble intégré en incluant une entrée reset au début de EZA_COLORS. Ainsi, définir EZA_COLORS="reset:*.txt=31" ne mettra en évidence que les fichiers texte ; définir EZA_COLORS="reset" ne m

ettra rien
en évidence.
