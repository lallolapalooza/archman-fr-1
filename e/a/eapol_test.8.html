NOM

eapol_test - Test de client EAP pair et RADIUS

SYNTAXE

eapol_test [ -nWS ] [ -cfichier de configuration ] [ -aadresse IP du serveur ] [ -Aadresse IP du client ] [ -pport UDP ] [ -ssecret partagé ] [ -rréauthentifications ] [ -tdélai ] [ -Cinformations de connexion ] [ -Madresse MAC ] [ -ofichier ] [ -Nspécification d'attribut ]

eapol_test scard

eapol_test sim [ PIN ] [ nombre de triplets ]

APERÇU

eapol_test est un programme qui relie la même implémentation de pair EAP que celle utilisée par wpa_supplicant et le code client d'authentification RADIUS de hostapd. De plus, il contient un code de connexion minimal pour combiner ces deux composants de manière similaire aux machines d'état d'authentification IEEE 802.1X/EAPOL. En d'autres termes, il intègre l'authentificateur IEEE 802.1X (normalement, un point d'accès) et le supplicant IEEE 802.1X (normalement, un client sans fil) pour générer un programme unique qui peut être utilisé pour tester les méthodes EAP sans avoir à configurer un point d'accès et un client sans fil.

Les principales utilisations d'eapol_test sont les tests d'interopérabilité des méthodes EAP avec des serveurs RADIUS et les tests de développement pour de nouvelles méthodes EAP. Il peut être facilement utilisé pour automatiser les tests EAP pour l'interopérabilité et la régression, car le programme peut être exécuté à partir de scripts shell sans nécessiter de composants de test supplémentaires à part un serveur RADIUS. Par exemple, les tests EAP automatisés décrits dans eap_testing.txt sont implémentés avec eapol_test. De même, eapol_test pourrait être utilisé pour implémenter une suite de tests de régression automatisés pour un serveur d'authentification RADIUS.

Par exemple :

eapol_test -ctest.conf -a127.0.0.1 -p1812 -ssecret -r1

tente de compléter l'authentification EAP basée sur la configuration réseau de test.conf contre le serveur RADIUS fonctionnant sur l'hôte local. Une réauthentification est déclenchée pour tester la réauthentification rapide. Le fichier de configuration utilise le même format pour les blocs réseau que wpa_supplicant.

ARGUMENTS DE COMMANDE

-c chemin du fichier de configuration
Une configuration à utiliser. La configuration doit utiliser le même format pour les blocs réseau que wpa_supplicant.
-a adresse du serveur
Adresse IP du serveur d'authentification. La valeur par défaut est '127.0.0.1'.
-A adresse du client
Adresse IP du client. La valeur par défaut est de sélectionner une adresse automatiquement.
-p port du serveur
Port UDP du serveur d'authentification. La valeur par défaut est '1812'.
-s secret du serveur
Secret partagé avec le serveur d'authentification. La valeur par défaut est 'radius'.
-r nombre
Nombre de réauthentifications.
-t délai
Délai en secondes. La valeur par défaut est 30.
-C informations
Informations de connexion RADIUS. La valeur par défaut est
-M adresse MAC
Adresse MAC du client (Calling-Station-Id). La valeur par défaut est '02:00:00:00:00:01'.
-o fichier
Emplacement pour écrire le certificat du serveur.
-N spécification d'attribut
Envoyer un attribut arbitraire spécifié par id_attribut:syntaxe:valeur, ou id_attribut seul. id_attribut doit être l'ID numérique de l'attribut, et syntaxe doit être l'un des suivants : 's' (chaîne). Lorsque id_attribut est donné seul, NULL est utilisé comme valeur d'attribut. Plusieurs attributs peuvent être spécifiés en utilisant l'option plusieurs fois.
-n
Indique qu'aucune clé MPPE n'est attendue.
-W
Attend un moniteur d'interface de contrôle avant de commencer.
-S
Enregistre la configuration après authentification.
