EVP_SignInit(3ssl)

Paquet: openssl

Licences: Apache-2.0

EVP_SIGNINIT(3ssl) OpenSSL EVP_SIGNINIT(3ssl)

NOM

EVP_SignInit, EVP_SignInit_ex, EVP_SignUpdate, EVP_SignFinal_ex, EVP_SignFinal - Fonctions de signature EVP

SYNTAXIS

#include <openssl/evp.h>
int EVP_SignInit_ex(EVP_MD_CTX *ctx, const EVP_MD *type, ENGINE *impl);
int EVP_SignUpdate(EVP_MD_CTX *ctx, const void *d, unsigned int cnt);
int EVP_SignFinal_ex(EVP_MD_CTX *ctx, unsigned char *md, unsigned int *s,
                     EVP_PKEY *pkey, OSSL_LIB_CTX *libctx, const char *propq);
int EVP_SignFinal(EVP_MD_CTX *ctx, unsigned char *sig, unsigned int *s,
                  EVP_PKEY *pkey);
void EVP_SignInit(EVP_MD_CTX *ctx, const EVP_MD *type);

DESCRIPTION

Les routines de signature EVP sont une interface de haut niveau pour les signatures numériques.

EVP_SignInit_ex() configure le contexte de signature ctx pour utiliser le digest type du ENGINE impl. ctx doit être créé avec EVP_MD_CTX_new() avant d'appeler cette fonction.

EVP_SignUpdate() hache cnt octets de données à l'adresse d dans le contexte de signature ctx. Cette fonction peut être appelée plusieurs fois sur le même ctx pour inclure des données supplémentaires.

EVP_SignFinal_ex() signe les données dans ctx en utilisant la clé privée pkey et place la signature dans sig. Le contexte de librairie libctx et la requête de propriété propq sont utilisés lors de la création d'un contexte à utiliser avec la clé pkey. sig doit avoir une taille d'au moins EVP_PKEY_get_size(pkey) octets. s est un paramètre de sortie, et n'est pas utilisé comme paramètre d'entrée. Le nombre d'octets de données écrits (c'est-à-dire la longueur de la signature) sera écrit dans l'entier à s, au plus EVP_PKEY_get_size(pkey) octets seront écrits.

EVP_SignFinal() est similaire à EVP_SignFinal_ex() mais utilise les valeurs par défaut NULL pour le contexte de librairie libctx et la requête de propriété propq.

EVP_SignInit() initialise un contexte de signature ctx pour utiliser l'implémentation par défaut du digest type.

VALEURS DE RETOUR

EVP_SignInit_ex(), EVP_SignUpdate(), EVP_SignFinal_ex() et EVP_SignFinal() retournent 1 en cas de succès et 0 en cas d'échec.

Les codes d'erreur peuvent être obtenus par ERR_get_error(3).

NOTES

L'interface EVP pour les signatures numériques devrait presque toujours être utilisée de préférence aux interfaces de bas niveau. Cela permet au code de devenir transparent à l'algorithme utilisé et beaucoup plus flexible.

Lors de la signature avec certains types de clés privées, le générateur de nombres aléatoires doit être amorcé. Si l'amorçage ou le réamorçage automatique du CSPRNG OpenSSL échoue en raison de circonstances externes (voir RAND(7)), l'opération échouera.

L'appel à EVP_SignFinal() finalise en interne une copie du contexte de digest. Cela signifie que les appels à EVP_SignUpdate() et EVP_SignFinal() peuvent être appelés ultérieurement pour d'autres données à digérer et signer. Les applications peuvent désactiver ce comportement en définissant le drapeau de contexte EVP_MD_CTX_FLAG_FINALISE via EVP_MD_CTX_set_flags(3).

Comme seule une copie du contexte de digest est jamais finalisée, le contexte doit être libéré après utilisation en appelant EVP_MD_CTX_free(), sinon une fuite de mémoire se produira.

Notez que tous les fournisseurs ne prennent pas en charge la continuation. Si le fournisseur sélectionné ne permet pas de dupliquer les contextes, EVP_SignFinal() finalisera le contexte de digest et toute tentative de traitement de données supplémentaires via EVP_SignUpdate() entraînera une erreur.

BOGUES

Les versions antérieures de cette documentation indiquaient à tort que les appels à EVP_SignUpdate() ne pouvaient pas être effectués après avoir appelé EVP_SignFinal().

Comme la clé privée est passée dans l'appel à EVP_SignFinal(), toute erreur relative à la clé privée (par exemple, une combinaison clé et digest inappropriée) ne sera indiquée qu'après que potentiellement de grandes quantités de données aient été traitées via EVP_SignUpdate().

Il n'est pas possible de modifier les paramètres de signature à l'aide de ces fonctions.

Les deux bogues précédents sont corrigés dans les fonctions plus récentes EVP_DigestSign*().
