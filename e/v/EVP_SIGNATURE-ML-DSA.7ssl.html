EVP_SIGNATURE-ML-DSA(7ssl)

EVP_SIGNATURE-ML-DSA(7ssl) OpenSSL EVP_SIGNATURE-ML-DSA(7ssl)

NOM

EVP_SIGNATURE-ML-DSA, EVP_SIGNATURE-ML-DSA-44, EVP_SIGNATURE-ML-DSA-65, EVP_SIGNATURE-ML-DSA-87, - Prise en charge de ML-DSA par EVP_SIGNATURE

DESCRIPTION

Les implémentations EVP_PKEY ML-DSA-44, ML-DSA-65 et ML-DSA-87 prennent en charge la génération de clés, ainsi que la signature et la vérification en une seule passe (one-shot) à l'aide des schémas de signature ML-DSA décrits dans FIPS 204 https://csrc.nist.gov/pubs/fips/204/final.

Les différents noms d'algorithmes correspondent aux ensembles de paramètres définis dans FIPS 204 https://csrc.nist.gov/pubs/fips/204/final Section 4 Tableau 1. (Les signatures varient en taille de ~2,5K à ~4,5K selon le type choisi). Il existe 3 catégories de sécurité différentes, également selon le type.

EVP_SIGNATURE_fetch(3) peut être utilisé pour récupérer explicitement l'un des 3 algorithmes, qui peuvent ensuite être utilisés avec EVP_PKEY_sign_message_init(3), EVP_PKEY_sign(3), EVP_PKEY_verify_message_init(3)et EVP_PKEY_verify(3) pour effectuer une signature de message ou une vérification de signature en une seule passe.

Le processus de signature normal (appelé Pure ML-DSA Signature Generation) encode le message en interne comme 0x00 || len(ctx) || ctx || message, où ctx est une valeur optionnelle de taille 0x00..0xFF. Ce processus est défini dans FIPS 204 https://csrc.nist.gov/pubs/fips/204/final Algorithme 2 étape 10 et Algorithme 3 étape 5. OpenSSL permet également de ne pas encoder le message, ce qui est requis pour les tests. OpenSSL ne prend pas en charge la génération de signature Pre Hash ML-DSA, mais cela peut être fait par l'utilisateur en effectuant l'encodage Pre hash en externe puis en choisissant l'option de ne pas encoder le message.

Paramètres de signature ML-DSA

Le paramètre suivant peut être utilisé pour la signature et la vérification. Il peut être défini en passant un tableau OSSL_PARAM à EVP_PKEY_sign_message_init(3) ou EVP_PKEY_verify_message_init(3)

"context-string" (OSSL_SIGNATURE_PARAM_CONTEXT_STRING) <octet string>
Une chaîne d'octets d'une longueur maximale de 255. Par défaut, il s'agit de la chaîne vide.

Les paramètres suivants peuvent être utilisés lors de la signature : ils peuvent être définis en passant un tableau OSSL_PARAM à EVP_PKEY_sign_init_ex2(3).

"message-encoding" (OSSL_SIGNATURE_PARAM_MESSAGE_ENCODING) <integer>
La valeur par défaut de 1 utilise la « Pure ML-DSA Signature Generation » comme décrit ci-dessus. La définir à 0 n'encode pas le message, ce qui est utilisé pour les tests. Les étapes d'encodage du message sont définies dans FIPS 204 https://csrc.nist.gov/pubs/fips/204/final Algorithme 2 étape 10 et Algorithme 3 étape 5.
"test-entropy" (OSSL_SIGNATURE_PARAM_TEST_ENTROPY) <octet string>
Utilisé pour les tests afin de passer une valeur aléatoire déterministe optionnelle par message. Si défini, la taille doit être de 32 octets.
"deterministic" (OSSL_SIGNATURE_PARAM_DETERMINISTIC) <integer>
La valeur par défaut de 0 fait que l'aléatoire par message est généré aléatoirement à l'aide d'un DRBG. Le définir à 1 fait que l'aléatoire par message est défini à 32 octets de zéros. Cette valeur est ignorée si "test-entropy" est défini.
"mu" (OSSL_SIGNATURE_PARAM_MU) <integer>
La valeur par défaut de 0 fait que les opérations de signature et de vérification traitent un message brut. Le définir à 1 fait que ces opérations supposent que l'entrée est la valeur "mu" de FIPS 204 https://csrc.nist.gov/pubs/fips/204/final Algorithme 7 étape 6 et Algorithme 8 étape 7.

Notez que les étapes d'encodage du message de FIPS 204 https://csrc.nist.gov/pubs/fips/204/final Algorithme 2 étape 10 et Algorithme 3 étape 5 sont omises lorsque ce paramètre est à 1.

Voir EVP_PKEY-ML-DSA(7) pour des informations relatives aux clés ML-DSA .

NOTES

Pour des raisons de rétrocompatibilité, EVP_DigestSignInit_ex(), EVP_DigestSign(), EVP_DigestVerifyInit_ex() et EVP_DigestVerify() peuvent également être utilisés, mais le digest passé dans mdname doit être NULL.

EXEMPLES

Pour signer un message à l'aide d'une structure EVP_PKEY ML-DSA :

void do_sign(EVP_PKEY *key, unsigned char *msg, size_t msg_len)
{
    size_t sig_len;
    unsigned char *sig = NULL;
    const OSSL_PARAM params[] = {
        OSSL_PARAM_octet_string("context-string", (unsigned char *)"A context string", 16),
        OSSL_PARAM_END
    };
    EVP_PKEY_CTX *sctx = EVP_PKEY_CTX_new_from_pkey(NULL, pkey, NULL);
    EVP_SIGNATURE *sig_alg = EVP_SIGNATURE_fetch(NULL, "ML-DSA-65", NULL);
    EVP_PKEY_sign_message_init(sctx, sig_alg, params);
    /* Calculate the required size for the signature by passing a NULL buffer. */
    EVP_PKEY_sign(sctx, NULL, &sig_len, msg, msg_len);
    sig = OPENSSL_zalloc(sig_len);
    EVP_PKEY_sign(sctx, sig, &sig_len, msg, msg_len);
    ...
    OPENSSL_free(sig);
    EVP_SIGNATURE_free(sig_alg);
    EVP_PKEY_CTX_free(sctx);
}
