EVENTLOGADM(8) Outils d'administration système EVENTLOGADM(8)

NOM

eventlogadm - insérer des enregistrements dans le magasin de journaux d'événements Samba

SYNTAXE

eventlogadm [-s] [-d] [-h] -o addsource EVENTLOG NOMSOURCE FICHIERMSG

eventlogadm [-s] [-d] [-h] -o write EVENTLOG

eventlogadm [-s] [-d] [-h] -o dump EVENTLOG NUMEROENREGISTREMENT

DESCRIPTION

Cet outil fait partie de la suite samba(1).

eventlogadm est un filtre qui accepte des enregistrements de journal d'événements formatés sur l'entrée standard et les écrit dans le magasin de journaux d'événements Samba. Les clients Windows peuvent ensuite manipuler ces enregistrements à l'aide des outils d'administration habituels.

OPTIONS

-s NOMFICHIER

L'option -s demande à eventlogadm de charger le fichier de configuration donné sous le nom NOMFICHIER au lieu de celui par défaut utilisé par Samba.

-d

L'option -d demande à eventlogadm d'émettre des informations de débogage.

-o addsource EVENTLOG NOMSOURCE FICHIERMSG

L'option -o addsource crée une nouvelle source de journal d'événements.

-o write EVENTLOG

L'option -o write lit les enregistrements du journal d'événements depuis l'entrée standard et les écrit dans le magasin de journaux d'événements Samba nommé par EVENTLOG.

-o dump EVENTLOG NUMEROENREGISTREMENT

L'option -o dump lit les enregistrements du journal d'événements depuis une tdb EVENTLOG et les affiche sur la sortie standard.

-h

Affiche les informations d'utilisation.

FORMAT ENREGISTREMENT EVENTLOG

Pour l'opération d'écriture, eventlogadm s'attend à pouvoir lire des enregistrements structurés depuis l'entrée standard. Ces enregistrements sont une séquence de lignes, avec la clé et les données de l'enregistrement séparées par un caractère deux-points. Les enregistrements sont séparés par au moins une ou plusieurs lignes vides.

Les champs de l'enregistrement du journal d'événements sont :

•LEN - Ce champ doit être 0, car eventlogadm calculera cette valeur.
•RS1 - Ceci doit être la valeur 1699505740.
•RCN - Ce champ doit être 0.
•TMG - L'heure à laquelle l'enregistrement du journal d'événements a été généré ; le format est le nombre de secondes depuis le 1er janvier 1970, 00:00:00 UTC.
•TMW - L'heure à laquelle l'enregistrement du journal d'événements a été écrit ; le format est le nombre de secondes depuis le 1er janvier 1970, 00:00:00 UTC.
•EID - L'ID du journal d'événements.
•ETP - Le type d'événement -- l'un des éléments suivants : "INFO", "ERROR", "WARNING", "AUDIT SUCCESS" ou "AUDIT FAILURE".
•ECT - La catégorie d'événement ; cela dépend du fichier de messages. Il est principalement utilisé comme moyen de filtrage dans le visualiseur de journaux d'événements.
•RS2 - Ce champ doit être 0.
•CRN - Ce champ doit être 0.
•USL - Ce champ doit être 0.
•SRC - Ce champ contient le nom de la source associé au journal d'événements. Si un fichier de messages est utilisé avec un journal d'événements, il y aura une entrée de registre associant ce nom de source à un DLL de fichier de messages.
•SRN - Le nom de la machine sur laquelle le journal d'événements a été généré. C'est typiquement le nom d'hôte.
•STR - Le texte associé au journal d'événements. Il peut y avoir plus d'une chaîne dans un enregistrement.
•DAT - Ce champ doit être laissé vide.

EXEMPLES

Un exemple du format d'enregistrement accepté par eventlogadm :

LEN: 0
RS1: 1699505740
RCN: 0
TMG: 1128631322
TMW: 1128631322
EID: 1000
ETP: INFO
ECT: 0
RS2: 0
CRN: 0
USL: 0
SRC: cron
SRN: dmlinux
STR: (root) CMD ( rm -f /var/spool/cron/lastrun/cron.hourly)
DAT:

Configurer une source de journal d'événements, en spécifiant un fichier de messages DLL :

eventlogadm -o addsource Application MyApplication | \\
    	%SystemRoot%/system32/MyApplication.dll

Filtrer des messages du journal système dans un journal d'événements :

tail -f /var/log/messages | \\
	my_program_to_parse_into_eventlog_records | \\
      	eventlogadm SystemLogEvents
