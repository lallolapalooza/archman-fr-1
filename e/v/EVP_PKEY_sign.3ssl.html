EVP_PKEY_sign(3ssl)

Paquet: openssl

Licences: Apache-2.0

EVP_PKEY_SIGN(3ssl) OpenSSL EVP_PKEY_SIGN(3ssl)

NOM

EVP_PKEY_sign_init, EVP_PKEY_sign_init_ex, EVP_PKEY_sign_init_ex2, EVP_PKEY_sign, EVP_PKEY_sign_message_init, EVP_PKEY_sign_message_update, EVP_PKEY_sign_message_final - signer à l'aide d'un algorithme de clé publique

SYNOPSIS

#include <openssl/evp.h>
int EVP_PKEY_sign_init(EVP_PKEY_CTX *ctx);
int EVP_PKEY_sign_init_ex(EVP_PKEY_CTX *ctx, const OSSL_PARAM params[]);
int EVP_PKEY_sign_init_ex2(EVP_PKEY_CTX *ctx, EVP_SIGNATURE *algo,
                           const OSSL_PARAM params[]);
int EVP_PKEY_sign_message_init(EVP_PKEY_CTX *ctx, EVP_SIGNATURE *algo,
                               const OSSL_PARAM params[]);
int EVP_PKEY_sign_message_update(EVP_PKEY_CTX *ctx,
                                 unsigned char *in, size_t inlen);
int EVP_PKEY_sign_message_final(EVP_PKEY_CTX *ctx, unsigned char *sig,
                                size_t *siglen, size_t sigsize);
int EVP_PKEY_sign(EVP_PKEY_CTX *ctx,
                  unsigned char *sig, size_t *siglen,
                  const unsigned char *tbs, size_t tbslen);

DESCRIPTION

EVP_PKEY_sign_init() initialise un contexte d'algorithme de clé publique ctx pour la signature à l'aide de l'algorithme donné lors de la création du contexte avec EVP_PKEY_CTX_new(3) ou ses variantes. L'algorithme est utilisé pour récupérer implicitement une méthode EVP_SIGNATURE , voir « Implicit fetch » dans provider(7) pour plus d'informations sur les récupérations implicites.

EVP_PKEY_sign_init_ex() est identique à EVP_PKEY_sign_init() mais définit en plus les paramètres passés params sur le contexte avant de retourner.

EVP_PKEY_sign_init_ex2() initialise un contexte d'algorithme de clé publique ctx pour signer un résumé de message pré-calculé à l'aide de l'algorithme donné par algo et de la clé donnée via EVP_PKEY_CTX_new(3) ou EVP_PKEY_CTX_new_from_pkey(3). Un contexte ctx sans clé préchargée ne peut pas être utilisé avec cette fonction. Cette fonction fournit presque les mêmes fonctionnalités que EVP_PKEY_sign_init_ex(), mais est destinée uniquement à être utilisée avec un résumé de message pré-calculé, et permet de prédéterminer les conditions exactes pour ce résumé de message, si un algorithme de signature composite (tel que RSA-SHA256) a été récupéré. Après un appel à cette fonction, la définition de paramètres modifiant l'implémentation du résumé ou le padding n'est généralement pas prise en charge.

EVP_PKEY_sign_message_init() initialise un contexte d'algorithme de clé publique ctx pour signer un message de taille illimitée à l'aide de l'algorithme donné par algo et de la clé donnée via EVP_PKEY_CTX_new(3) ou EVP_PKEY_CTX_new_from_pkey(3). Le passage du message est pris en charge à la fois de manière一次性 (one-shot) via EVP_PKEY_sign(), et par la combinaison de EVP_PKEY_sign_message_update() et EVP_PKEY_sign_message_final(). Cette fonction permet d'utiliser des algorithmes capables de traiter des entrées de longueur arbitraire, tels que ED25519, RSA-SHA256 et similaires.

EVP_PKEY_sign_message_update() ajoute inlen octets de in aux données à traiter pour la signature. La spécification et l'implémentation de l'algorithme de signature déterminent comment les octets d'entrée sont traités et s'il existe une limite sur la taille totale de l'entrée. Voir « NOTES » ci-dessous pour une explication plus détaillée.

EVP_PKEY_sign_message_final() signe les données traitées et place les données dans sig, et le nombre d'octets de signature dans *siglen, si le nombre d'octets ne dépasse pas la taille donnée par sigsize. sig peut être NULL, et dans ce cas, seul *siglen est mis à jour avec le nombre d'octets de signature.

EVP_PKEY_sign() est une fonction一次性 (one-shot) qui peut être utilisée avec toutes les fonctions d'initialisation ci-dessus. Lorsque l'initialisation a été faite avec EVP_PKEY_sign_init(), EVP_PKEY_sign_init_ex() ou EVP_PKEY_sign_init_ex2(), les données spécifiées par tbs et tbslen sont signées après un padding approprié. Lorsque l'initialisation a été faite avec EVP_PKEY_sign_message_init(), les données spécifiées par tbs et tbslen sont résumées par l'algorithme de résumé de message implicite, et le résultat est signé après un padding approprié. Si sig est NULL, alors la taille maximale du tampon de sortie est écrite dans le paramètre siglen . Si sig n'est pas NULL, alors avant l'appel, le paramètre siglen doit contenir la longueur du tampon sig , et si l'appel réussit, la signature est écrite dans sig et la quantité de données écrite dans siglen.

NOTES

Général

Certaines implémentations de signature accumulent uniquement les données d'entrée et ne font aucun traitement supplémentaire avant de les signer (elles s'attendent à ce que l'entrée soit un résumé), tandis que d'autres compressent les données, généralement en produisant internement un résumé, et signent le résultat. Certaines prennent en charge les deux modes de fonctionnement à la fois. On attend de l'appelant qu'il sache comment l'algorithme choisi est censé se comporter et sous quelles conditions.

Par exemple, on peut s'attendre à ce qu'une implémentation RSA n'attende qu'un résumé de message en entrée, tandis qu'on peut s'attendre à ce qu'ED25519 traite l'entrée avec une fonction de hachage, c'est-à-dire produise le résumé de message en interne, et tandis qu'on peut s'attendre à ce que RSA-SHA256 gère l'un ou l'autre mode de fonctionnement, selon que l'opération a été initialisée avec EVP_PKEY_sign_init_ex2() ou avec EVP_PKEY_sign_message_init().

De même, une implémentation RSA s'attend généralement à ce que des détails supplémentaires soient définis, comme l'algorithme de résumé de message avec lequel l'entrée doit être résumée, ainsi que le mode de padding (voir EVP_PKEY_CTX_set_signature_md(3) et EVP_PKEY_CTX_set_rsa_padding(3) et d'autres similaires), tandis qu'une implémentation RSA-SHA256 a généralement ces détails prédéfinis et immuables.

Les fonctions décrites ici ne peuvent pas être utilisées pour combiner des algorithmes distincts. En particulier, ni EVP_PKEY_CTX_set_signature_md(3) ni le paramètre OSSL_PARAM OSSL_PARAM « digest » (OSSL_SIGNATURE_PARAM_DIGEST) ne peuvent être utilisés pour combiner un algorithme de signature avec un algorithme de hachage pour traiter l'entrée. En d'autres termes, il n'est pas possible de spécifier un ctx préchargé avec une clé RSA, ou un algo qui a récupéré « RSA » et d'essayer de spécifier SHA256 séparément pour obtenir les fonctionnalités de RSA-SHA256. Si vous souhaitez combiner des algorithmes de cette manière, veuillez utiliser EVP_DigestSignInit(3) et les fonctions associées.

Effectuer plusieurs signatures

Lorsqu'il est initialisé avec EVP_PKEY_sign_init_ex() ou EVP_PKEY_sign_init_ex2(), EVP_PKEY_sign() peut être appelé plus d'une fois sur le même contexte pour effectuer plusieurs opérations一次性 (one-shot) avec les mêmes paramètres.

Lorsqu'il est initialisé avec EVP_PKEY_sign_message_init(), il n'est pas possible d'appeler EVP_PKEY_sign() plusieurs fois.

VALEURS RETOURNÉES

Toutes les fonctions retournent 1 en cas de succès et 0 ou une valeur négative en cas d'échec.

En particulier, EVP_PKEY_sign_init() et ses autres variantes peuvent retourner -2 pour indiquer que l'opération n'est pas prise en charge par l'algorithme de clé publique.

EXEMPLES

RSA avec padding PKCS#1 pour SHA256

Signer des données à l'aide de RSA avec padding PKCS#1 et un résumé SHA256 en entrée :

#include <openssl/evp.h>
#include <openssl/rsa.h>
EVP_PKEY_CTX *ctx;
/* md est un résumé SHA-256 dans cet exemple. */
unsigned char *md, *sig;
size_t mdlen = 32, siglen;
EVP_PKEY *signing_key;
/*
 * NB : suppose que signing_key et md sont configurés avant la
 * prochaine étape. signing_key doit être une clé privée RSA et md doit
 * pointer vers le résumé SHA-256 à signer.
 */
ctx = EVP_PKEY_CTX_new(signing_key, NULL /* pas de moteur */);
if (ctx == NULL)
    /* Une erreur s'est produite */
if (EVP_PKEY_sign_init(ctx) <= 0)
    /* Erreur */
if (EVP_PKEY_CTX_set_rsa_padding(ctx, RSA_PKCS1_PADDING) <= 0)
    /* Erreur */
if (EVP_PKEY_CTX_set_signature_md(ctx, EVP_sha256()) <= 0)
    /* Erreur */
/* Déterminer la longueur du tampon */
if (EVP_PKEY_sign(ctx, NULL, &siglen, md, mdlen) <= 0)
    /* Erreur */
sig = OPENSSL_malloc(siglen);
if (sig == NULL)
    /* échec de malloc */
if (EVP_PKEY_sign(ctx, sig, &siglen, md, mdlen) <= 0)
    /* Erreur */
/* La signature est siglen octets écrits dans le tampon sig */

RSA-SHA256 avec un digest pré-calculé

Signer un digest avec RSA-SHA256 en utilisant les fonctions one-shot. À noter que RSA-SHA256 est supposé être une implémentation de "sha256WithRSAEncryption", pour lequel le padding est prédéterminé à être RSA_PKCS1_PADDING, et le digest d'entrée est supposé avoir été calculé avec SHA256.

#include <openssl/evp.h>
#include <openssl/rsa.h>
EVP_PKEY_CTX *ctx;
/* md est un digest SHA-256 dans cet exemple. */
unsigned char *md, *sig;
size_t mdlen = 32, siglen;
EVP_PKEY *signing_key;
/*
 * NB : suppose que signing_key et md sont configurés avant la
 * prochaine étape. signing_key doit être une clé privée RSA et md doit
 * pointer vers le digest SHA-256 à signer.
 */
ctx = EVP_PKEY_CTX_new(signing_key, NULL /* pas de moteur */);
alg = EVP_SIGNATURE_fetch(NULL, "RSA-SHA256", NULL);
if (ctx == NULL)
    /* Une erreur est survenue */
if (EVP_PKEY_sign_init_ex2(ctx, alg, NULL) <= 0)
    /* Erreur */
/* Déterminer la longueur du tampon */
if (EVP_PKEY_sign(ctx, NULL, &siglen, md, mdlen) <= 0)
    /* Erreur */
sig = OPENSSL_malloc(siglen);
if (sig == NULL)
    /* échec de malloc */
if (EVP_PKEY_sign(ctx, sig, &siglen, md, mdlen) <= 0)
    /* Erreur */
/* La signature est siglen octets écrits dans le tampon sig */

RSA-SHA256, one-shot

Signer un document avec RSA-SHA256 en utilisant les fonctions one-shot. À noter que RSA-SHA256 est supposé être une implémentation de "sha256WithRSAEncryption", pour lequel le padding est prédéterminé à être RSA_PKCS1_PADDING.

#include <openssl/evp.h>
#include <openssl/rsa.h>
EVP_PKEY_CTX *ctx;
/* in est l'entrée dans cet exemple. */
unsigned char *in, *sig;
/* inlen est la longueur de l'entrée dans cet exemple. */
size_t inlen, siglen;
EVP_PKEY *signing_key;
EVP_SIGNATURE *alg;
/*
 * NB : suppose que signing_key, in et inlen sont configurés avant
 * la prochaine étape. signing_key doit être une clé privée RSA,
 * in doit pointer vers les données à digérer et signer, et
 * inlen doit être la taille des données en octets.
 */
ctx = EVP_PKEY_CTX_new(signing_key, NULL /* pas de moteur */);
alg = EVP_SIGNATURE_fetch(NULL, "RSA-SHA256", NULL);
if (ctx == NULL || alg == NULL)
    /* Une erreur est survenue */
if (EVP_PKEY_sign_message_init(ctx, alg, NULL) <= 0)
    /* Erreur */
/* Déterminer la longueur du tampon sig */
if (EVP_PKEY_sign(ctx, NULL, &siglen, in, inlen) <= 0)
    /* Erreur */
sig = OPENSSL_malloc(siglen);
if (sig == NULL)
    /* échec de malloc */
if (EVP_PKEY_sign(ctx, sig, &siglen, in, inlen) <= 0)
    /* Erreur */
/* La signature est siglen octets écrits dans le tampon sig */

RSA-SHA256, en utilisant update et final

C'est la même chose que l'exemple précédent, mais en permettant une fonctionnalité de type flux.

#include <openssl/evp.h>
#include <openssl/rsa.h>
EVP_PKEY_CTX *ctx;
/* in est l'entrée dans cet exemple. */
unsigned char *in, *sig;
/* inlen est la longueur de l'entrée dans cet exemple. */
size_t inlen, siglen;
EVP_PKEY *signing_key;
EVP_SIGNATURE *alg;
/*
 * NB : suppose que signing_key, in et inlen sont configurés avant
 * la prochaine étape. signing_key doit être une clé privée RSA,
 * in doit pointer vers les données à digérer et signer, et
 * inlen doit être la taille des données en octets.
 */
ctx = EVP_PKEY_CTX_new(signing_key, NULL /* pas de moteur */);
alg = EVP_SIGNATURE_fetch(NULL, "RSA-SHA256", NULL);
if (ctx == NULL || alg == NULL)
    /* Une erreur est survenue */
if (EVP_PKEY_sign_message_init(ctx, alg, NULL) <= 0)
    /* Erreur */
while (inlen > 0) {
    if (EVP_PKEY_sign_message_update(ctx, in, inlen)) <= 0)
        /* Erreur */
    if (inlen > 256) {
        inlen -= 256;
        in += 256;
    } else {
        inlen = 0;
    }
}
/* Déterminer la longueur du tampon sig */
if (EVP_PKEY_sign_message_final(ctx, NULL, &siglen) <= 0)
    /* Erreur */
sig = OPENSSL_malloc(siglen);
if (sig == NULL)
    /* échec de malloc */
if (EVP_PKEY_sign_message_final(ctx, sig, &siglen) <= 0)
    /* Erreur */
/* La signature est siglen octets écrits dans le tampon sig */

HISTORIQUE

Les fonctions EVP_PKEY_sign_init() et EVP_PKEY_sign() ont été ajoutées dans OpenSSL 1.0.0.

La fonction EVP_PKEY_sign_init_ex() a été ajoutée dans OpenSSL 3.0.

Les fonctions EVP_PKEY_sign_init_ex2(), EVP_PKEY_sign_message_init(), EVP_PKEY_sign_message_update() et EVP_PKEY_sign_message_final() ont été ajoutées dans OpenSSL 3.4.
