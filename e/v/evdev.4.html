DESCRIPTIO

N

evdev est un pilote d'entrée pour Xorg destiné aux périphériques d'événements génériques de Linux. Il prend donc en charge tous les périphériques d'entrée connus du noyau, y compris la plupart des souris, claviers, tablettes et écrans tactils. evdev est le pilote par défaut sur les principales distributions

Linux.

Le pilote evdev peut servir à la fois de périphérique d'entrée pointeur et de clavier. Plusieurs périphériques d'entrée sont pris en charge par plusieurs instances de ce pilote, avec une section InputDevice dans votre xorg.conf pour chaque périphérique d'entrée qui utilisera ce

pilote.

Il est recommandé que les périphériques evdev soient configurés via la directive InputClass (voir xorg.conf(5)) plutôt que par une configuration manuelle pour chaque périphéri

que. Les périphériques configurés dans xorg.conf(5) ne
sont pas compatibles avec le branchement à chaud.

CONFIGURATION

Veuillez vous référer à xorg.conf(5) pour les détails généraux de configuration et pour les options qui peuvent être utilisées avec tous les pilotes d'entrée. Cette section ne couvre que les détails de configuration spécifiques à ce

pilote.

Les options de pilote suivantes sont prises en charge

:
Option "ButtonMapping" "string
"
Définit la correspondance des boutons pour ce périphérique. La correspondance est une liste de correspondances de boutons séparées par des espaces qui correspondent dans l'ordre aux boutons physiques du périphérique (c'est-à-dire que le premier nombre est la correspondance pour le bouton 1, etc.). La correspondance par défaut est "1 2 3 ... 32". Une correspondance de 0 désactive le bouton. Plusieurs boutons peuvent avoir la même correspondance. Par exemple, une souris gauchère avec la molette de défilement désactivée utiliserait une correspondance de "3 2 1 0 0". Les correspondances invalides sont ignorées et la correspondance par défaut est utilisée. Les boutons non spécifiés dans la correspondance de l'utilisateur utilisent la correspondance par
défaut.
Option "Device" "string
"
Spécifie le périphérique via lequel le périphérique peut être accessible. Cela sera généralement de la forme "/dev/input/eventX", où X est un entier. La correspondance entre le nœud de périphérique et le matériel dépend du système. Propriété : "Device Node" (lecture seule)
.
Option "DragLockButtons" "L1 B2 L3 B4
"
Définit les "boutons de verrouillage de glissement" qui simulent l'appui maintenu sur un bouton, de sorte que les personnes ayant une faible dextérité n'aient pas à maintenir un bouton enfoncé en même temps qu'elles déplacent le curseur de la souris. Les numéros de boutons apparaissent par paires, avec le numéro du bouton de verrouillage en premier, suivi du numéro du bouton qui est la cible du bouton de verrouillage. Propriété : "Evdev Drag Lock
Buttons".
Option "DragLockButtons" "M1
"
Définit un "bouton maître de verrouillage de glissement" qui agit comme une "touche Méta" indiquant que le prochain bouton pressé doit être "verrouillé pour le glissement". Propriété : "Evdev Drag Lock
Buttons".
Option "Emulate3Buttons" "boolean
"
Active/désactive l'émulation du troisième bouton (du milieu) de la souris pour les souris qui n'ont que deux boutons physiques. Le troisième bouton est émulé en pressant les deux boutons simultanément. Par défaut : désactivé. Propriété : "Evdev Middle Button
Emulation".
Option "Emulate3Timeout" "integer
"
Définit le délai d'attente (en millisecondes) que le pilote attend avant de décider si deux boutons ont été pressés "simultanément" lorsque l'émulation à 3 boutons est activée. Par défaut : 50. Propriété : "Evdev Middle Button
Timeout".
Option "Emulate3Button" "integer
"
Spécifie le numéro du bouton physique à émettre si l'émulation du bouton du milieu est déclenchée. Par défaut : 2. Propriété : "Evdev Middle Button
Button".
Option "EmulateWheel" "boolean
"
Active/désactive l'émulation de la "molette". L'émulation de la molette signifie l'émulation des événements d'appui/relâchement de bouton lorsque la souris est déplacée pendant qu'un bouton réel spécifique est enfoncé. Les événements de bouton de molette (généralement les boutons 4 et 5) sont généralement utilisés pour le défilement. L'émulation de la molette est utile pour obtenir un comportement semblable à une molette avec des trackballs. Elle peut aussi être utile pour les souris avec 4 boutons ou plus mais sans molette. Voir la description des options EmulateWheelButton, EmulateWheelInertia, EmulateWheelTimeout, XAxisMapping, et YAxisMapping. Par défaut : désactivé. Propriété "Evdev Wheel
Emulation".
Option "EmulateWheelButton" "integer
"
Spécifie le bouton qui doit être maintenu enfoncé pour activer le mode d'émulation de la molette. Tant que ce bouton est enfoncé, le mouvement du pointeur en X et/ou Y générera des événements d'appui/relâchement de bouton comme spécifié pour les paramètres XAxisMapping et YAxisMapping. Si le bouton est 0 et que EmulateWheel est activé, tout mouvement du périphérique est converti en événements de molette. Par défaut : 4. Propriété : "Evdev Wheel Emulation
Button".
Option "EmulateWheelInertia" "integer
"
Spécifie la distance (en pixels) que le pointeur doit parcourir pour générer
des événements d'appui/relâchement de bouton en mode d'émulation de la
molette. Par défaut : 10. Propriété : "Evdev Wheel Emulation Inertia".
Cette valeur doit être définie pour tout périphérique qui ne ressemble pas à une souris standard. Plus précisément, sur les périphériques absolus tels que les tablettes, la valeur doit être définie à une fraction raisonnable du mouvement attendu pour éviter des événements de défilement
excessifs.
AVERTISSEMENT : le nom "inertia" est un abus de langage. Cette option définit la distance requise pour générer un événement de défilement similaire aux options VertScrollDelta et HorizScrollDelta. Elle n'active pas l'inertie au sens physique, le déf
ilement s'arrête immédiatement une foi
s que le mouvement s'est arrêté.
Option "EmulateWheelTimeout" "integer
"
Spécifie le temps en millisecondes pendant lequel le EmulateWheelButton doit être enfoncé avant que l'émulation de la molette ne démarre. Si le EmulateWheelButton est relâché avant ce délai d'attente, l'événement d'appui/relâchement original du bouton est envoyé. Par défaut : 200. Propriété : "Evdev Wheel Emulation
Timeout".
Option "EmulateThirdButton" "boolean
"
Active l'émulation du troisième bouton. L'émulation du troisième bouton émet un événement de bouton droit (par défaut) en pressant et maintenant le premier bouton. Le premier bouton doit être maintenu enfoncé pendant le délai d'attente configuré et ne doit pas bouger plus que le seuil configuré pour que l'émulation s'active. Sinon, l'événement du premier bouton est transmis normalement. Par défaut : désactivé. Propriété : "Evdev Third Button
Emulation".
Option "EmulateThirdButtonTimeout" "integer
"
Spécifie le délai d'attente en millisecondes entre l'appui initial du bouton et la génération de l'événement de bouton émulé. Par défaut : 1000. Propriété : "Evdev Third Button Emulation
Timeout".
Option "EmulateThirdButtonButton" "integer&qu

Options

Option "EmulateThirdButton" "boolean"
If enabled, the middle button emulation is triggered when the first and third buttons are pressed simultaneously. Default: disabled.
Option "EmulateThirdButtonTimeout" "integer"
Specifies the timeout in milliseconds before the third button emulation is triggered. Default: 20. Property: "Evdev Middle Button Timeout".
Option "EmulateThirdButtonButton" "integer"
Specifies the physical button number to be emitted if third button emulation is triggered. Default: 3. Property: "Evdev Third Button Button".
Option "EmulateThirdButtonMoveThreshold" "integer"
Specifies the maximum move fuzz in device coordinates for third button emulation. If the device moves by more than this threshold before the third button emulation is triggered, the emulation is cancelled and a first button event is generated as normal. Default: 20. Property: "Evdev Third Button Emulation Threshold".
Option "GrabDevice" "boolean"
Force a grab on the event device. Doing so will ensure that no other driver can initialise the same device and it will also stop the device from sending events to /dev/kbd or /dev/input/mice. Events from this device will not be sent to virtual devices (e.g. rfkill or the Macintosh mouse button emulation). Default: disabled.
Option "InvertX" "Bool"
Option "InvertY" "Bool"
Invert the given axis. Default: off. Property: "Evdev Axis Inversion".
Option "IgnoreRelativeAxes" "Bool"
Option "IgnoreAbsoluteAxes" "Bool"
Ignore the specified type of axis. Default: unset. The X server cannot deal with devices that have both relative and absolute axes. Evdev tries to guess which axes to ignore given the device type and disables absolute axes for mice and relative axes for tablets, touchscreens and touchpad. These options allow to forcibly disable an axis type. Mouse wheel axes are exempt and will work even if relative axes are ignored. No property, this configuration must be set in the configuration.
If either option is set to False, the driver will not ignore the specified axes regardless of the presence of other axes. This may trigger buggy behavior and events from this axis are always forwarded. Users are discouraged from setting this option.
Option "Calibration" "min-x max-x min-y max-y"
Calibrates the X and Y axes for devices that need to scale to a different coordinate system than reported to the X server. This feature is required for devices that need to scale to a different coordinate system than originally reported by the kernel (e.g. touchscreens). The scaling to the custom coordinate system is done in-driver and the X server is unaware of the transformation. Property: "Evdev Axis Calibration".
Option "Mode" "Relative"|"Absolute"
Sets the mode of the device if device has absolute axes. The default value for touchpads is relative, for other absolute. This option has no effect on devices without absolute axes.
Option "SwapAxes" "Bool"
Swap x/y axes. Default: off. Property: "Evdev Axes Swap".
Option "XAxisMapping" "N1 N2"
Specifies which buttons are mapped to motion in the X direction in wheel emulation mode. Button number N1 is mapped to the negative X axis motion and button number N2 is mapped to the positive X axis motion. Default: no mapping. Property: "Evdev Wheel Emulation Axes".
Option "YAxisMapping" "N1 N2"
Specifies which buttons are mapped to motion in the Y direction in wheel emulation mode. Button number N1 is mapped to the negative Y axis motion and button number N2 is mapped to the positive Y axis motion. Default: "4 5". Property: "Evdev Wheel Emulation Axes".
Option "TypeName" "type""
Specify the X Input 1.x type (see XListInputDevices(3)). There is rarely a need to use this option, evdev will guess the device type based on the device's capabilities. This option is provided for devices that need quirks.
Option "VertScrollDelta" "integer"
The amount of motion considered one unit of scrolling vertically. Default: "1". Property: "Evdev Scrolling Distance".
Option "HorizScrollDelta" "integer"
The amount of motion considered one unit of scrolling horizontally. Default: "1". Property: "Evdev Scrolling Distance".
Option "DialDelta" "integer"
The amount of motion considered one unit of turning the dial. Default: "1". Property: "Evdev Scrolling Distance".
Option "Resolution" "integer"
Sets the resolution of the device in dots per inch. The resolution is used to scale relative motion events from mouse devices to 1000 DPI resolution. This can be used to make high resolution mice less sensitive without turning off acceleration. If set to 0 no scaling will be performed. Default: "0".

PROPRIÉTÉS PRISES EN CHARGE

Les propriétés suivantes sont fournies par le pilote evdev.

Evdev Axis Calibration
4 valeurs 32 bits, ordre min-x, max-x, min-y, max-y ou 0 valeurs pour désactiver l'étalonnage de l'axe dans le pilote.
Evdev Axis Inversion
2 valeurs booléennes (8 bits, 0 ou 1), ordre X, Y. 1 inverse l'axe.
Evdev Axes Swap
1 valeur booléenne (8 bits, 0 ou 1). 1 échange les axes x/y.
Evdev Drag Lock Buttons
8 bits. Soit 1 valeur, soit des paires de valeurs. Plage de valeurs 0-32, 0 désactive une valeur.
Evdev Middle Button Emulation
1 valeur booléenne (8 bits, 0 ou 1).
Evdev Middle Button Timeout
1 valeur positive 16 bits.
Evdev Middle Button Button
1 valeur 8 bits, plage autorisée 0-32, 0 désactive le bouton.
Evdev Wheel Emulation
1 valeur booléenne (8 bits, 0 ou 1).
Evdev Wheel Emulation Axes
4 valeurs 8 bits, ordre X haut, X bas, Y haut, Y bas. 0 désactive une valeur.
Evdev Wheel Emulation Button
1 valeur 8 bits, plage autorisée 0-32, 0 désactive le bouton.
Evdev Wheel Emulation Inertia
1 valeur positive 16 bits.
Evdev Wheel Emulation Timeout
1 valeur positive 16 bits.
Evdev Scrolling Distance
3 valeurs 32 bits : vertical, horizontal et molette.
