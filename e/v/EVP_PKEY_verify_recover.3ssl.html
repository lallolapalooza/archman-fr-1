EVP_PKEY_verify_recover(3ssl)

Paquet: openssl

Licences: Apache-2.0

EVP_PKEY_VERIFY_RECOVER(3ssl) OpenSSL EVP_PKEY_VERIFY_RECOVER(3ssl)

NOM

EVP_PKEY_verify_recover_init, EVP_PKEY_verify_recover_init_ex, EVP_PKEY_verify_recover_init_ex2, EVP_PKEY_verify_recover - récupérer la signature à l'aide d'un algorithme de clé publique

SYNOPSIS

#include <openssl/evp.h>
int EVP_PKEY_verify_recover_init(EVP_PKEY_CTX *ctx);
int EVP_PKEY_verify_recover_init_ex(EVP_PKEY_CTX *ctx,
                                    const OSSL_PARAM params[]);
int EVP_PKEY_verify_recover_init_ex2(EVP_PKEY_CTX *ctx, EVP_SIGNATURE *algo,
                                     const OSSL_PARAM params[]);
int EVP_PKEY_verify_recover(EVP_PKEY_CTX *ctx,
                            unsigned char *rout, size_t *routlen,
                            const unsigned char *sig, size_t siglen);

DESCRIPTION

EVP_PKEY_verify_recover_init() initialise un contexte d'algorithme de clé publique ctx pour la signature à l'aide de l'algorithme donné lors de la création du contexte avec EVP_PKEY_CTX_new(3) ou des variantes de celui-ci. L'algorithme est utilisé pour récupérer une méthode EVP_SIGNATURE implicitement, voir "Fetch implicite" dans provider(7) pour plus d'informations sur les fetches implicites.

EVP_PKEY_verify_recover_init_ex() est identique à EVP_PKEY_verify_recover_init() mais définit en plus les paramètres transmis params sur le contexte avant de retourner.

EVP_PKEY_verify_recover_init_ex2() est identique à EVP_PKEY_verify_recover_init_ex(), mais fonctionne avec une méthode EVP_SIGNATURE explicitement récupérée algo. Un contexte ctx sans clé pré-chargée ne peut pas être utilisé avec cette fonction. Selon l'algorithme récupéré, certains détails concernant le traitement de l'entrée de EVP_PKEY_verify() peuvent être prédéterminés, et dans ce cas, ces détails ne peuvent normalement pas être modifiés. Voir "NOTES" ci-dessous pour une explication plus approfondie.

La fonction EVP_PKEY_verify_recover() récupère les données signées à l'aide de ctx. La signature est spécifiée à l'aide des paramètres sig et siglen. Si rout est NULL, alors la taille maximale du tampon de sortie est écrite dans le paramètre routlen. Si rout n'est pas NULL, alors avant l'appel, le paramètre routlen doit contenir la longueur du tampon rout. Si l'appel réussit, les données récupérées sont écrites dans rout et la quantité de données écrite est dans routlen.

NOTES

Normalement, une application ne s'intéresse qu'à savoir si une opération de vérification de signature est réussie dans les cas où la fonction EVP_verify() doit être utilisée.

Parfois, cependant, il est utile d'obtenir les données initialement signées à l'aide d'une opération de signature. Seuls certains algorithmes de clé publique peuvent récupérer une signature de cette manière (par exemple, RSA en mode de remplissage PKCS).

Après l'appel à EVP_PKEY_verify_recover_init(), des opérations de contrôle spécifiques à l'algorithme peuvent être effectuées pour définir les paramètres appropriés pour l'opération.

Après l'appel à EVP_PKEY_verify_recover_init_ex2(), des opérations de contrôle spécifiques à l'algorithme peuvent ne pas être nécessaires si l'algorithme choisi implique que ces contrôles sont prédéfinis (et immuables).

La fonction EVP_PKEY_verify_recover() peut être appelée plusieurs fois sur le même contexte si plusieurs opérations sont effectuées avec les mêmes paramètres.

VALEUR DE RETOUR

EVP_PKEY_verify_recover_init() et EVP_PKEY_verify_recover() retournent 1 en cas de succès et 0 ou une valeur négative en cas d'échec. En particulier, une valeur de retour de -2 indique que l'opération n'est pas prise en charge par l'algorithme de clé publique.

EXEMPLES

Récupérer le digest initialement signé à l'aide du digest PKCS#1 et SHA256 :

#include <openssl/evp.h>
#include <openssl/rsa.h>
EVP_PKEY_CTX *ctx;
unsigned char *rout, *sig;
size_t routlen, siglen;
EVP_PKEY *verify_key;
/*
 * NB : suppose que verify_key, sig et siglen sont déjà configurés
 * et que verify_key est une clé publique RSA
 */
ctx = EVP_PKEY_CTX_new(verify_key, NULL /* pas de moteur */);
if (!ctx)
    /* Une erreur s'est produite */
if (EVP_PKEY_verify_recover_init(ctx) <= 0)
    /* Erreur */
if (EVP_PKEY_CTX_set_rsa_padding(ctx, RSA_PKCS1_PADDING) <= 0)
    /* Erreur */
if (EVP_PKEY_CTX_set_signature_md(ctx, EVP_sha256()) <= 0)
    /* Erreur */
/* Déterminer la longueur du tampon */
if (EVP_PKEY_verify_recover(ctx, NULL, &routlen, sig, siglen) <= 0)
    /* Erreur */
rout = OPENSSL_malloc(routlen);
if (!rout)
    /* Échec de malloc */
if (EVP_PKEY_verify_recover(ctx, rout, &routlen, sig, siglen) <= 0)
    /* Erreur */
/* Les données récupérées font routlen octets et sont écrites dans le tampon rout */

HISTORIQUE

Les fonctions EVP_PKEY_verify_recover_init() et EVP_PKEY_verify_recover() ont été ajoutées dans OpenSSL 1.0.0.

La fonction EVP_PKEY_verify_recover_init_ex() a été ajoutée dans OpenSSL 3.0.
