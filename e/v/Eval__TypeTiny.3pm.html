DESCRIPTIO

N

Ce module est utilisé par Type::Tiny pour compiler des références de sous-programmes à partir de chaînes de code Perl, et des références de hachages de variables à

fermer.

Fonction

s

Par défaut, ce module exporte une fonction, qui fonctionne de manière très similaire à la fonction du même nom de Eval::Closure

:
"eval_closure(source => $source, environment => \%env, %opt)
"

D'autres fonctions peuvent être importées sur demande

:
"set_subname( $fully_qualified_name, $coderef
)"
Fonctionne comme la fonction du même nom de Sub::Util, mais reviendra à ne rien faire si ni Sub::Util ni Sub::Name ne sont disponibles. Refusera également lâchement de définir le nom d'une référence de sous-programme une deuxième fois si elle en a déjà
un.
"type_to_coderef( $type, %options
)"
Transforme un objet Type::Tiny en référence de sous-programme, adaptée pour être installée dans une table de symboles afin de créer une fonction comme "ArrayRef" ou "Int". (Devrait en fait fonctionner pour n'importe quel objet qui fournit les méthodes "is_parameterizable", "parameterize", et "qualified_name", comme Type::Coercion.)

$options{post_method} peut être une chaîne Perl indiquant une méthode à appeler sur la contrainte de type avant de la retourner. Par exemple '->moose_t

ype'.

$options{description} peut être une description de la référence de sous-programme qui peut être affichée dans les traces de pile,

etc.

La référence de sous-programme sera nommée en utilisant "set_subname" sauf si $options{anonymous} est

vrai.

Si $type est undef, alors on suppose que la contrainte de type n'a pas encore été définie mais le sera plus tard, mais vous voulez toujours une fonction maintenant. $options{type_library} et $options{type_name} seront utilisées p

our trouver la
contrainte de
type lorsque la fon
ction sera appelée.

Constante

s

Les constantes suivantes peuvent être exportées, mais ne le sont pas par

défaut.
"HAS_LEXICAL_SU
BS"
Booléen indiquant si Eval::TypeTiny prend en charge les sous-programmes lexicaux. (Cette fonctionnalité nécessite Perl 5.
18.)
"ALIAS_IMPLEMENTATI
ON"
Renvoie une chaîne indiquant quelle implémentation de "alias => 1" est utilisée. Eval::TypeTiny choisira automatiquement la meilleure implémentation. Cette constante peut être comparée aux constantes "IMPLEMENTATION_
*".
"IMPLEMENTATION_NATI
VE"
Si "ALIAS_IMPLEMENTATION eq IMPLEMENTATION_NATIVE" alors Eval::TypeTiny utilise actuellement la fonctionnalité d'alias native de Perl 5.22. Cela nécessite Perl 5.
22.
"IMPLEMENTATION_DEVEL_LEXALI
AS"
Si "ALIAS_IMPLEMENTATION eq IMPLEMENTATION_DEVEL_LEXALIAS" alors Eval::TypeTiny utilise actuellement Devel::LexAlias pour fournir des
alias.
"IMPLEMENTATION_PADWALK
ER"
Si "ALIAS_IMPLEMENTATION eq IMPLEMENTATION_PADWALKER" alors Eval::TypeTiny utilise actuellement PadWalker pour fournir des
alias.
"IMPLEMENTATION_T
IE"
Si "ALIAS_IMPLEMENTATION eq IMPLEMENTATION_TIE" alors Eval::TypeTiny utilise l'implémentation de secours des alias en utilisant "tie". C'est l'implémentation la plus lente, et elle peut causer des problèmes dans certains cas limites, comme essayer d'aliaser des variables déjà liées (tie), mais c'est la seule façon d'implémenter "alias => 1" sans une version récente de Perl ou l'un des deux modules optionnels mentionnés
ci-dessus.
"NICE_PROTOTYP
ES"
Si c'est vrai, alors type_to_coderef donnera aux contraintes de type paramétrables le prototype légèrement plus élégant "(;$)" au lieu du défaut "(;@)". Cela permet des constructions comme : 
ArrayRef[Int] |
HashRef[Int]

... po

ur « f
onctio
nner s
implem
ent ».

ENVIRONNEMENT

D'ÉVALUATION

L'évaluation est effectuée en présence de strict, mais en l'absence de warnings. (C'est différent d'Eval::Closure qui active les warnings pour les fermetures compilées.

)

Le pragma feature n'est pas actif dans l'environnement d'évaluation, donc ce qui suit ne fonctionnera pas

: 
use feature qw(say);
use Eval::TypeTiny qw(eval_closure);

my $say_all = eval_closure(
   source => 'sub { say for @_ }',
);
$say_all->("Hello", "World")
;

Le pragma feature ne se « transmet » pas dans l'eval de chaîne. Il est bien sûr possible d'importer des pragmas dans la chaîne évaluée en tant que partie de la chaîne elle-même

: 
use Eval::TypeTiny qw(eval_closure);

my $say_all =
eval_closure( source => 'sub { use feature qw(sa
y); say for @_ }', ); $say_all->("Hello", "World");
