ÉVÉNEMENTS VIRTUELS

PRÉDÉFINIS

Tk définit les événements virtuels suivants à des fins de notification

:
<<AltUnderlined>
>
Cet événement est envoyé à un widget pour le notifier que la lettre qu'il a soulignée (comme indicateur d'accélérateur) avec l'option -underline a été pressée en combinaison avec la touche Alt. La réponse habituelle à cela est soit de donner le focus au widget (ou à un widget connexe), soit d'invoquer le
widget.
<<Invoke>
>
Cet événement peut être envoyé à certains widgets (par exemple button, listbox, menu) comme alternative à <space>
.
<<ListboxSelect>
>
Cet événement est envoyé à une listbox lorsque l'ensemble des éléments sélectionnés dans la listbox est mis à
jour.
<<MenuSelect>
>
Cet événement est envoyé à un menu lorsque l'élément actuellement sélectionné dans le menu change. Il est destiné à être utilisé avec des systèmes d'aide
contextuelle.
<<Modified>
>
Cet événement est envoyé à un widget text lorsque le contenu du widget est
modifié.
<<Selection>
>
Cet événement est envoyé à un widget text lorsque la sélection dans le widget est
modifiée.
<<ThemeChanged>
>
Cet événement est envoyé à tous les widgets lorsque le thème ttk a changé. Les widgets ttk écoutent cet événement et se redessinent lorsqu'il se déclenche. Les widgets hérités ignorent cet
événement.
<<TkWorldChanged>
>
Cet événement est envoyé à tous les widgets lorsqu'une police est modifiée, par exemple par l'utilisation de [font configure]. Le champ user_data (%d) aura la valeur "FontChanged". Pour d'autres changements au niveau du système, cet événement sera envoyé à tous les widgets, et le champ user_data indiquera la cause du changement. NOTE : tous les widgets tk et ttk gèrent déjà cet événement en
interne.
<<TraverseIn>
>
Cet événement est envoyé à un widget lorsque le focus entre dans le widget à la suite d'une action utilisateur de type « tab vers le widget
».
<<TraverseOut>
>
Cet événement est envoyé à un widget lorsque le focus quitte le widget à la suite d'une action utilisateur de type « tab vers le widget
».
<<UndoStack>
>
Cet événement est envoyé à un widget text lorsque sa pile d'annulation ou sa pile de rétablissement devient vide ou non
vide.
<<WidgetViewSync>
>
Cet événement est envoyé à un widget text lorsque ses données internes deviennent obsolètes, et à nouveau
lorsque ces données internes sont de nouveau synchronisées avec la vue du widget. Le champ detail (la
substitution %d) est soit true (lorsque le widget est synchronisé), soit false (lorsqu'il ne l'est pas).

ASSOCIATION DES TOUCHES AUX ÉVÉNEMENTS

VIRTUELS

Pour qu'une association d'événement virtuel se déclenche, deux choses doivent se produire. Premièrement, l'événement virtuel doit être défini avec la commande event add . Deuxièmement, une association doit être créée pour l'événement virtuel avec la commande bind. Considérez les définitions suivantes d'événements virtuels

: 
event add <<Paste>> <Control-y>
event add <<Paste>> <Button-2>
event add <<Save>> <Control-X><Control-S>
event add <<Save>> <Shift-F12>
if {[tk windowingsystem] eq "aqua"} {
    event add <<Save>> <Command-s>
}

Dans la commande bind, un événement virtuel peut être associé comme n'importe quel autre type d'événement intégré comme suit

: 
bind Entry <<Pas
te>> {%W insert
[selection get]}

Les doubles chevrons sont utilisés pour spécifier qu'un événement virtuel est associé. Si l'utilisateur tape Control-y ou appuie sur le bouton 2, ou si un événement virtuel <<Paste>> est synthétisé avec event generate, alors l'association <<Paste>> sera

invoquée.

Si une association virtuelle a exactement la même séquence qu'une association physique séparée, alors l'association physique prendra le dessus. Considérez l'exemple suivant

: 
event add <<Paste>> <Control-y> <Meta-Control-y>
bind Entry <
Control-y> {puts Control-y} bin
d Entry <<Paste>> {puts Paste}

Lorsque l'utilisateur tape Control-y, l'association <Control-y> sera invoquée, car un événement physique est considéré comme plus spécifique qu'un événement virtuel, toutes choses égales par ailleurs. Cependant, lorsque l'utilisateur tape Meta-Control-y, l'association <<Paste>> sera invoquée, car le modificateur Meta dans le motif physique associé à l'association virtuelle est plus spécifique que la séquence <Control-y> pour l'événement

physique.

Des associations sur un événement virtuel peuvent être créées avant que l'événement virtuel n'existe. En effet, l'événement virtuel n'a jamais réellement besoin d'être défini, par exemple, sur les plateformes où l'événement virtuel spécifique serait sans sens ou

ingénérable.

Lorsqu'une définition d'événement virtuel change à l'exécution, toutes les fenêtres répondront immédiatement à la nouvelle définition. En partant de l'exemple précédent, si le code suivant est exécuté

: 
bind Entry <Control-y> {}
event add <<Pa
ste>> <
Key-F6>

le comportement changera de deux manières. Premièrement, l'association <<Paste>> masquée émergera. Taper Control-y n'invoquera plus l'association <Control-y>, mais invoquera à la place l'événement virtuel <<Paste>>. Deuxièmement, appuyer sur la touche F6 invoquera désormais aussi l'association <<Pas

te>
>.

DÉPLACEMENT DU POINTEUR DE LA

SOURIS

Parfois, il est utile de pouvoir vraiment déplacer le pointeur de la souris. Par exemple, si vous avez un logiciel capable de démontrer directement à l'utilisateur comment utiliser le programme. Pour ce faire, vous devez « warper » la souris en utilisant event generate, comme ceci

: 
for {set xy 0} {$xy < 200} {incr xy} {
    event generate . <Motion> -x $xy -y
$xy -warp 1 upd
ate after 50 }

Notez qu'il est généralement considéré comme mauvais style de déplacer le poin

teur de la souris pour l'utilisateur car cela lui retire le contrôle. Par
conséquent, cette technique doit être utilisée avec prudence. Notez égale
ment qu'elle n'est pas garantie de fonctionner sur toutes les plateformes.
