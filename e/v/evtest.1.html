NOM

evtest - Moniteur d'événements de périphériques d'entrée et outil de requête

SYNTAXE

evtest [--grab] /dev/input/eventX
evtest --query /dev/input/eventX <type> <valeur>

DESCRIPTION

La première forme d'invocation ci-dessus (« mode capture ») fait afficher à evtest des informations sur le périphérique d'entrée spécifié, y compris tous les événements pris en charge par le périphérique. Il surveille ensuite le périphérique et affiche tous les événements générés.

Si le drapeau --grab est donné en mode capture, evtest conserve une EVIOCGRAB sur le périphérique. Tant que cette capture est active, d'autres processus ne recevront pas d'événements des périphériques du noyau. La capture est à nouveau libérée lorsque evtest se termine.

Dans la seconde forme d'invocation (« mode requête »), evtest effectue une requête unique de l'état d'une valeur spécifique d'un type d'événement.

type est l'un des suivants : EV_KEY, EV_SW, EV_SND, EV_LED (ou la valeur numérique)

valeur peut être une représentation décimale (par ex. 44), hexadécimale (par ex. 0x2c), ou le nom de la constante (par ex. KEY_Z) de la touche/du commutateur/du son/de la LED interrogé.

Si le bit d'état est défini (touche enfoncée, commutateur activé, ...), evtest se termine avec le code 10. Si le bit d'état n'est pas défini (touche relâchée, commutateur désactivé, ...), evtest se termine avec le code 0. Aucune autre sortie n'est générée.

evtest doit pouvoir lire depuis le périphérique ; dans la plupart des cas, cela signifie qu'il doit être exécuté en tant que root.

evtest est couramment utilisé pour déboguer des problèmes avec les périphériques d'entrée dans X.Org. La sortie d'evtest montre les informations présentées par le noyau ; sur la base de ces informations, il est possible de déterminer si un bug est un problème de noyau ou de X.Org.

DIAGNOSTICS

Si evtest ne montre aucun événement alors que le périphérique est utilisé, le périphérique peut être capturé par un processus (EVIOCGRAB). C'est généralement le cas lors du débogage d'un périphérique synaptics depuis X. Le passage à un TTY ou l'arrêt du serveur X termine cette capture et les périphériques synaptics peuvent être débogués.

La commande suivante montre les processus ayant un descripteur de fichier ouvert sur le périphérique :

fuser -v /dev/input/eventX

CODE DE RETOUR

evtest retourne 1 en cas d'erreur.

Lorsqu'il est utilisé pour interroger l'état, evtest retourne 0 si le bit d'état n'est pas défini et 10 s'il est défini.
