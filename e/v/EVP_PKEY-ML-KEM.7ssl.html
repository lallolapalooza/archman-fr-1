"seed-priv"
:
Ce format représente des objets PKCS#8 dans lesquels à la fois la graine de 64 octets (d, z) de FIPS 203 et la clé de découplage dk sont présentes dans la clé privée dans le cadre de l'encodage DER de la séquence ASN.1 :

  seed [0] IMPLICIT OCTET STRING (SIZE (64)),
  expandedKey OCTET STRING (SIZE (1632 | 2400 | 3168)),
  both SEQUENCE {
    seed OCTET STRING (SIZE (64)),
    expandedKey OCTET STRING (SIZE (1632 | 2400 | 3168)
) } }

Si le format "seed-priv" n'est pas inclus dans la liste,

ce format ne sera pas recon
nu lors de l'entrée.
"seed-only"
:
Ce format représente des objets PKCS#8 dans lesquels seule la graine de 64 octets (d, z) est présente dans la séquence ci-dessus. Si le format "seed-only" n'est pas inclus dans la liste, ce format ne sera pas reconnu lors de
l'entrée.
"priv-only"
:
Ce format représente des objets PKCS#8 dans lesquels seule la clé de découplage dk de FIPS 203 est présente dans la séquence ci-dessus. Si le format "priv-only" n'est pas inclus dans la liste, ce format ne seraill not be recognised on input.
"oqskeypair" :
Ce format représente des objets PKCS#8 dans lesquels la clé privée est un encodage DER d'une chaîne d'octets contenant la concaténation de la clé de décapsulage FIPS 203 dk et la clé de capsulage ek. Cet encodage est utilisé dans certaines compilations de "oqsprovider". Si le format "oqskeypair" n'est pas inclus dans la liste, ce format ne sera pas reconnu en entrée.
"bare-seed" :
Ce format représente des objets PKCS#8 dans lesquels la clé privée contient la graine FIPS 204 de 64 octets (d, z) sans aucune encapsulation ASN.1. Si le format "bare-seed" n'est pas inclus dans la liste, ce format ne sera pas reconnu en entrée.
"bare-priv" :
Ce format représente des objets PKCS#8 dans lesquels la clé privée contient la clé de décapsulage FIPS 204 dk sans aucune encapsulation ASN.1. Si le format "bare-priv" n'est pas inclus dans la liste, ce format ne sera pas reconnu en entrée.
"ml-kem.output_formats" (OSSL_PKEY_PARAM_ML_KEM_OUTPUT_FORMATS) <chaîne UTF8>
Liste ordonnée des formats de sortie de clé privée activés lors de l'écriture de fichiers PKCS#8 . Les éléments de la liste sont séparés par des virgules, des espaces ou des tabulations. La liste des formats activés peut être spécifiée dans le fichier de configuration, comme le montre la section « EXAMPLES » ci-dessous, ou via l'option de ligne de commande -provparam .

Ceci prend en charge le même ensemble de formats que celui décrit sous "ml-kem.input_formats" ci-dessus. L'ordre dans lequel les éléments sont listés est important ; le format sélectionné sera le premier qui peut être utilisé pour la sortie. Si la graine de la clé est connue, le format listé en premier sera sélectionné. Si la graine de la clé n'est pas connue, le premier format qui omet la graine sera sélectionné. L'ordre par défaut est équivalent à "seed-priv" en premier et "priv-only" en second, avec la sortie à la fois de la graine et de la clé lorsque la graine est disponible, et de la seule clé sinon. Si "seed-only" est listé en premier, alors la graine sera sortie sans la clé lorsqu'elle est disponible, sinon la sortie contiendra seulement la clé. Si "priv-only" est listé en premier, alors seule la clé est sortie, que la graine soit présente ou non. Les formats hérités "oqskeypair", "bare-seed" et "bare-priv" peuvent également être sortis en les listant en premier.

EXEMPLES

Un contexte EVP_PKEY peut être obtenu en appelant :

EVP_PKEY_CTX *pctx =
    EVP_PKEY_CTX_new_from_name(NULL, "ML-KEM-768", NULL);

Une clé ML-KEM-768 peut être générée comme ceci :

pkey = EVP_PKEY_Q_keygen(NULL, NULL, "ML-KEM-768");

Une clé privée ML-KEM au format graine peut être convertie en une clé au format FIPS 203 dk en exécutant :

$ openssl pkey -provparam ml-kem.retain_seed=no \
    -in seed-only.pem -out priv-only.pem

Pour générer une clé, par exemple ML-KEM-768 , au format FIPS 203 dk , vous pouvez exécuter :

$ openssl genpkey -provparam ml-kem.retain_seed=no \
    -algorithm ml-kem-768 -out priv-only.pem

Si vous avez un fichier PKCS#8 contenant à la fois une graine et une clé, et que vous préférez importer la clé associée plutôt que la graine, vous pouvez exécuter :

$ openssl pkey -provparam ml-kem.prefer_seed=no \
    -in seed-priv.pem -out priv-only.pem

Dans le fichier openssl.cnf , cela ressemble à :

openssl_conf = openssl_init
[openssl_init]
providers = providers_sect
# Can be referenced in one or more provider sections
[ml_kem_sect]
prefer_seed = yes
retain_seed = yes
# OQS legacy formats disabled
input_formats = seed-priv, seed-only, priv-only
# Output either the seed alone, or else the key alone
output_formats = seed-only, priv-only
[providers_sect]
default = default_sect
# Or perhaps just: base = default_sect
base = base_sect
[default_sect]
ml-kem = ml_kem_sect
[base_sect]
ml-kem = ml_kem_sect
