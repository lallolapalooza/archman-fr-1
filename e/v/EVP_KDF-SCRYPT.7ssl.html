NOM

EVP_KDF-SCRYPT - L'implémentation EVP_KDF de scrypt

DESCRIPTION

Support pour le calcul de la fonction de dérivation de clé basée sur un mot de passe scrypt via l'API EVP_KDF.

L'algorithme EVP_KDF-SCRYPT implémente la fonction de dérivation de clé basée sur un mot de passe scrypt, telle que décrite dans la RFC 7914. Elle est gourmande en mémoire dans le sens où elle nécessite délibérément une quantité significative de RAM pour un calcul efficace. L'intention est de rendre le craquage de mots de passe sur des systèmes ne disposant pas d'une grande quantité de mémoire vive (comme les GPU ou les ASIC) infaisable sur le plan informatique.

scrypt fournit trois facteurs de travail qui peuvent être personnalisés : N, r et p. N, qui doit être une puissance de deux positive, est le facteur de travail général et fait évoluer le temps CPU de manière approximativement linéaire. r est la taille du bloc de la fonction de hachage utilisée en interne et p est le facteur de parallélisation. r et p doivent être supérieurs à zéro. La quantité de RAM que scrypt nécessite pour son calcul est approximativement de (128 * N * r * p) octets.

Dans le papier original de Colin Percival (« Stronger Key Derivation via Sequential Memory-Hard Functions », 2009), les valeurs suggérées qui donnent un temps de calcul inférieur à 5 secondes sur un processeur Intel Core 2 Duo à 2,5 GHz sont N = 2^20 = 1048576, r = 8, p = 1. Par conséquent, la quantité de mémoire requise pour ce calcul est d'environ 1 Gio. Sur un processeur plus récent (Intel i7-5930K à 3,5 GHz), ce calcul prend environ 3 secondes. Lorsque N, r ou p ne sont pas spécifiés, ils prennent par défaut les valeurs 1048576, 8 et 1, respectivement. La quantité maximale de RAM qui peut être utilisée par scrypt est par défaut de 1025 Mio.

Identité

"SCRYPT" est le nom de cette implémentation ; il peut être utilisé avec la fonction EVP_KDF_fetch().

Paramètres supportés

Les paramètres supportés sont :

"pass" (OSSL_KDF_PARAM_PASSWORD) <chaîne d'octets>
"salt" (OSSL_KDF_PARAM_SALT) <chaîne d'octets>
Ces paramètres fonctionnent comme décrit dans "PARAMETERS" dans EVP_KDF(3).
"n" (OSSL_KDF_PARAM_SCRYPT_N) <entier non signé>
"r" (OSSL_KDF_PARAM_SCRYPT_R) <entier non signé>
"p" (OSSL_KDF_PARAM_SCRYPT_P) <entier non signé>
"maxmem_bytes" (OSSL_KDF_PARAM_SCRYPT_MAXMEM) <entier non signé>
Ces paramètres configurent les facteurs de travail scrypt N, r, maxmem et p. N et maxmem_bytes sont des paramètres de type uint64_t. r et p sont des paramètres de type uint32_t.
"properties" (OSSL_KDF_PARAM_PROPERTIES) <chaîne UTF8>
Ceci peut être utilisé pour définir la chaîne de requête de propriétés lors de la récupération du digest fixe en interne. NULL est utilisé si cette valeur n'est pas définie.

NOTES

Un contexte pour scrypt peut être obtenu en appelant :

EVP_KDF *kdf = EVP_KDF_fetch(NULL, "SCRYPT", NULL);
EVP_KDF_CTX *kctx = EVP_KDF_CTX_new(kdf);

La longueur de sortie de la dérivation de clé scrypt est spécifiée via le paramètre "keylen" de la fonction EVP_KDF_derive(3).

EXEMPLES

Cet exemple dérive un vecteur de test de 64 octets en utilisant scrypt avec le mot de passe "password", le sel "NaCl" et N = 1024, r = 8, p = 16.

EVP_KDF *kdf;
EVP_KDF_CTX *kctx;
unsigned char out[64];
OSSL_PARAM params[6], *p = params;
kdf = EVP_KDF_fetch(NULL, "SCRYPT", NULL);
kctx = EVP_KDF_CTX_new(kdf);
EVP_KDF_free(kdf);
*p++ = OSSL_PARAM_construct_octet_string(OSSL_KDF_PARAM_PASSWORD,
                                         "password", (size_t)8);
*p++ = OSSL_PARAM_construct_octet_string(OSSL_KDF_PARAM_SALT,
                                         "NaCl", (size_t)4);
*p++ = OSSL_PARAM_construct_uint64(OSSL_KDF_PARAM_SCRYPT_N, (uint64_t)1024);
*p++ = OSSL_PARAM_construct_uint32(OSSL_KDF_PARAM_SCRYPT_R, (uint32_t)8);
*p++ = OSSL_PARAM_construct_uint32(OSSL_KDF_PARAM_SCRYPT_P, (uint32_t)16);
*p = OSSL_PARAM_construct_end();
if (EVP_KDF_derive(kctx, out, sizeof(out), params) <= 0) {
    error("EVP_KDF_derive");
}
{
    const unsigned char expected[sizeof(out)] = {
        0xfd, 0xba, 0xbe, 0x1c, 0x9d, 0x34, 0x72, 0x00,
        0x78, 0x56, 0xe7, 0x19, 0x0d, 0x01, 0xe9, 0xfe,
        0x7c, 0x6a, 0xd7, 0xcb, 0xc8, 0x23, 0x78, 0x30,
        0xe7, 0x73, 0x76, 0x63, 0x4b, 0x37, 0x31, 0x62,
        0x2e, 0xaf, 0x30, 0xd9, 0x2e, 0x22, 0xa3, 0x88,
        0x6f, 0xf1, 0x09, 0x27, 0x9d, 0x98, 0x30, 0xda,
        0xc7, 0x27, 0xaf, 0xb9, 0x4a, 0x83, 0xee, 0x6d,
        0x83, 0x60, 0xcb, 0xdf, 0xa2, 0xcc, 0x06, 0x40
    };
    assert(!memcmp(out, expected, sizeof(out)));
}
EVP_KDF_CTX_free(kctx);
