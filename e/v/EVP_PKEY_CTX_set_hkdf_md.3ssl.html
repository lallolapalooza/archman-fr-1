DESCRIPTIO

N

L'algorithme EVP_PKEY_HKDF implémente la fonction de dérivation de clé HKDF. HKDF suit le paradigme « extract-then-expand », où la KDF se compose logiquement de deux modules. La première étape prend le matériel de chiffrement d'entrée et « extrait » de celui-ci une clé aléatoire pseudo K de longueur fixe. La deuxième étape « développe » la clé K en plusieurs clés aléatoires pseudo supplémentaires (la sortie de la KDF)

.

EVP_PKEY_CTX_set_hkdf_mode() définit le mode pour l'opération HKDF. Il existe trois modes actuellement définis

:
EVP_PKEY_HKDEF_MODE_EXTRACT_AND_EXP
AND
C'est le mode par défaut. Appeler EVP_PKEY_derive(3) sur un EVP_PKEY_CTX configuré pour HKDF effectuera une opération d'extraction suivie d'une opération de développement en une seule fois. La clé dérivée retournée sera le résultat après l'opération de développement. La clé aléatoire pseudo intermédiaire de longueur fixe K n'est pas retournée.

Dans ce mode, les valeurs de digest, de clé, de sel e

t d'info doivent être définies avant qu'une c

NLY

Les valeurs de digest, de clé et de sel doi

COMMANDES DE

CHAÎNE

HKDF prend également en charge les opérations de contrôle basées sur des chaînes via EVP_PKEY_CTX_ctrl_str(3). Le paramètre de type « md » utilise la valeur fournie comme nom de l'algorithme de digest à utiliser. Le paramètre de type « mode » utilise les valeurs « EXTRACT_AND_EXPAND », « EXTRACT_ONLY » et « EXPAND_ONLY » pour déterminer le mode à utiliser. Les paramètres de type « salt », « key » et « info » utilisent le paramètre value fourni comme graine, clé ou valeur d'info. Les noms « hexsalt », « hexkey » et « hexinfo » sont similai

res, sauf qu'ils prennent une chaîne hexa
décimale qui est convertie en binaire.

REMARQUE

S

Un contexte pour HKDF peut être obtenu en appelant

: 
EVP_PKEY_CTX *pctx = EVP_PKEY_CTX_new_id(EVP_PKEY_HKDF, NULL)
;

La longueur totale du tampon d'info ne peut pas dépasser 2048 octets : cela devrait être largement suffisant pour toute utilisation normale de

HKDF.

La longueur de sortie d'une opération de développement HKDF est spécifiée via le paramètre length de la fonction EVP_PKEY_derive(3). Étant donné que la longueur de sortie HKDF est variable, passer un tampon NULL comme moyen d'obtenir la longueur requise n'a pas de sens avec HKDF dans un mode quelconque qui effectue une opération de développement. À la place, l'appelant doit allouer un tampon de la longueur désirée et passer ce tampon à EVP_PKEY_derive(3) avec (un pointeur initialisé à) la longueur désirée. Passer un tampon NULL pour obtenir la longueur est autorisé lors de l'utilisation de EVP_PKEY_HKDEF_MODE_EXTRACT_ONLY

.

Des versions optimisées de

HKDF peuvent être implém
entées dans un ENGINE.

RETOUR

Toutes ces fonctions retournent 1 en cas de succès et 0 ou une valeur néga

tive en cas d'échec. En particulier, une valeur de retour de -2 indique q
ue l'opération n'est pas prise en charge par l'algorithme de clé publique.

EXEMPLE

S

Cet exemple dérive 10 octets en utilisant SHA-256 avec la clé secrète « secret », la valeur de sel « salt » et la valeur d'info « label »

:

unsigned char out[10];
size_t outlen = sizeof(out);
pctx = EVP_PKEY_CTX_new_id(EVP_PKEY_HKDF, NULL);
if (EVP_PKEY_derive_init(pctx) <= 0)
    /* Error */
if (EVP_PKEY_CTX_set_hkdf_md(pctx, EVP_sha256()) <= 0) /* Error */ if (EVP_PKEY_CTX_set1_hkdf_salt(pctx, "salt", 4) <= 0) /* Error */ if (EVP_PKEY_CTX_set1_hkdf_key(
pctx, "secret", 6) <= 0) /* Error */ if (EVP_PKEY_CTX_add1_hkdf_info(pctx, "label", 5) <= 0) /* Error */ if (EVP_PKEY_derive(pctx, out, &outlen) <= 0) /* Error */
