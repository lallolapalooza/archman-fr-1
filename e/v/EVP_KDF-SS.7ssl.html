DESCRIPTIO

N

L'algorithme EVP_KDF-SS implémente la fonction de dérivation de clé Single Step (SSKDF). SSKDF dérive une clé à partir d'entrées telles qu'une clé secrète partagée (générée lors de l'exécution d'un schéma d'établissement de clé) et de fixedinfo. SSKDF est également informellement appelée 'Concat

KDF'.

La sortie est considérée comme du matériel de

clé.

Fonction

auxiliaire

L'implémentation utilise une fonction auxiliaire H sélectionnable, qui peut être l'une des suivantes

:
H(x) = hash(x,
digest=md)
H(x) = HMAC_hash(x, key=salt,
digest=md)
H(x) = KMACxxx(x, key=salt, custom="KDF",
outlen=mac_size)

Les implémentations HMAC et KMAC définissent toutes de

ux la clé à l'aide de la valeur 'salt'. Le hash et le
HMAC nécessitent également que le digest soit défini.

Identit

é

"SSKDF" est le nom de cette implémentation ; elle peut être utilisée avec la fonction EVP_KDF_

fetc
h().

charge

Ce paramètre définit le secret partagé utilisé pour la dérivation de

Le fournisseur FIPS d'OpenSSL prend également en charge les paramètres suivants

"fips-indicator" (OSSL_KDF_PARAM_FIPS_APPROVED_INDICATOR)
<entier>
Un accesseur qui renvoie 1 si l'opération est approuvée par FIPS, ou 0 sinon. Cela peut être utilisé après l'appel à EVP_KDF_derive. Il renvoie 0 si "key-check" est défini à 0 et que la vérification

<entier>

l'erreur et définira l'indicateur approuvé
"fips-indicator" à 0. Cette option rompt l
a conformité FIPS si elle fait que l'indic

NOTE

S

Un contexte pour SSKDF peut être obtenu en appelant

: 
EVP_KDF *kdf = EVP_KDF_fetch(NULL, "SSKDF", NULL);
EVP_KDF_CTX *kctx = EVP_KDF_CTX_new(kdf)
;

La longueur de sortie d'un SSKDF est spécifiée via le paramètre keylen de la fonction EVP_KDF_d

erive
(3).

EXEMPLE

S

Cet exemple dérive 10 octets en utilisant H(x) = SHA-256, avec la clé secrète "secret" et la valeur fixedinfo "label"

: 
EVP_KDF *kdf;
EVP_KDF_CTX *kctx;
unsigned char out[10];
OSSL_PARAM params[4], *p = params;
kdf = EVP_KDF_fetch(NULL, "SSKDF", NULL);
kctx = EVP_KDF_CTX_new(kdf);
EVP_KDF_free(kdf);
*p++ = OSSL_PARAM_construct_utf8_string(OSSL_KDF_PARAM_DIGEST,
                                        SN_sha256, strlen(SN_sha256));
*p++ = OSSL_PARAM_construct_octet_string(OSSL_KDF_PARAM_KEY,
                                         "secret", (size_t)6);
*p++ = OSSL_PARAM_construct_octet_string(OSSL_KDF_PARAM_INFO,
                                         "label", (size_t)5);
*p = OSSL_PARAM_construct_end();
if (EVP_KDF_derive(kctx, out, sizeof(out), params) <= 0) {
    error("EVP_KDF_derive");
}
EVP_KDF_CTX_free(kctx)
;

Cet exemple dérive 10 octets en utilisant H(x) = HMAC(SHA-256), avec la clé secrète "secret", la valeur fixedinfo "label" et le salt "salt"

:

                                        SN_hmac, strlen(SN_hmac));
*p++ = OSSL_PARAM_construct_utf8_string(OSSL_KDF_PARAM_DIGEST,
                                        SN_sha256, strlen(SN_sha256));
*p++ = OSSL_PARAM_construct_octet_string(OSSL_KDF_PARAM_SECRET,
                                         "secret", (size_t)6);
*p++ = OSSL_PARAM_construct_octet_string(OSSL_KDF_PARAM_INFO,
                                         "label", (size_t)5);
*p++ = OSSL_PARAM_construct_octet_string(OSSL_KDF_PARAM_SALT,
                                         "salt", (size_t)4);
*p = OSSL_PARAM_construct_end();

    error("EVP_KDF_derive");
}
EVP_KDF_CTX_free(kctx)
;
