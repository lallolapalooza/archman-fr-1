DESCRIPTIO

N

L'évaluation de chaîne est souvent utilisée pour la génération de code dynamique. Par exemple, "Moose" l'utilise abondamment pour générer des versions en ligne des accesseurs et des constructeurs, ce qui accélère le code à l'exécution de manière significative. L'évaluation de chaîne n'est cependant pas sans problèmes - il est difficile de contrôler la portée dans laquelle elle est utilisée (ce qui détermine quelles variables sont dans la portée à l'intérieur de l'évaluation), et il est facile de manquer les erreurs de compilation, car l'évaluation les attrape et les place dans $@ à la

place.

Ce module tente de résoudre ces problèmes. Il fournit une fonction "eval_closure", qui évalue une chaîne dans un environnement propre, à part une liste fixe de variables spécifiées. Les erreurs de compilation sont relancées

automatiquement
.

FONCTION

S

eval_closure(%args

)

Cette fonction fournit la fonctionnalité principale de ce module. Elle est exportée par défaut. Elle prend un hash de paramètres, dont les clés suivantes sont valides

:
sour
ce
La chaîne à évaluer. Elle doit se terminer en renvoyant une référence de code. Elle peut accéder à toute variable déclarée dans le paramètre "environment" (et uniquement ces variables). Elle peut être soit une chaîne, soit une référence de tableau de lignes (qui seront jointes avec des sauts de ligne pour produire la chaîne)
.
environme
nt
L'environnement à fournir à l'évaluation. Cela doit être une référence de hash, associant des noms de variables (y compris les sigles) à des références du type approprié. Par exemple, une valeur valide pour environment serait "{ '@foo' => [] }" (ce qui permettrait à la fonction générée d'utiliser un tableau nommé @foo). Généralement, cela est utilisé pour permettre à la fonction générée d'accéder à des variables définies extérieurement (vous passeriez donc une référence à une variable qui existe déjà).

En perl 5.18 et supérieur, le hash d'environnement peut contenir des variables avec un sigle "&". Cela créera une sous-routine lexicale dans le code évalué (voir "The 'lexical_subs' feature" dans feature). Utiliser un sigle "&" sur des versions de perl antérieures à la disponib

ilité des sous-routine
s lexicales lèvera une erreur.
ali
as
Si défini à vrai, la référence de code renvoyée capture les variables référencées dans la référence de hash d'environnement. (Cette fonctionnalité nécessite Devel::LexAlias.) Si défini à faux, la référence de code capture une copie superficielle des variables.

Si cet argument est omis, Eval::Closure suppos

era actuellement faux, mais cette hypot
hèse pourrait changer dans une version future.
descripti
on
Cela vous permet de fournir un peu plus d'informations dans les backtraces. Normalement, lorsqu'une fonction générée via l'évaluation de chaîne est appelée, cette trame de pile apparaît sous la forme "(eval n)", où 'n' est un identifiant séquentiel pour chaque évaluation de chaîne qui s'est produite jusqu'à présent dans le programme. Passer un paramètre "description" permet de remplacer cela par quelque chose de plus utile (par exemple, Moose remplace la description des accesseurs par quelque chose comme "accessor foo at MyClass.pm, line 123")
.
li
ne
Cela permet de remplacer le numéro de ligne particulier qui apparaît dans les backtraces, tout comme l'option "description". La valeur par défaut est
1.

or

a échoué à compiler, et préfixe avec un texte e
xplicatif. Définir cette option à vrai supprime
ce comportement afin que vous n'obteniez que l'erreur
de compilation que Perl a réellement signalée.
