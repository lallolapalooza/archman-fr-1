EVP_SEALINIT(3ssl) OpenSSL EVP_SEALINIT(3ssl)

NOM

EVP_SealInit, EVP_SealUpdate, EVP_SealFinal - Chiffrement d'enveloppe EVP

SYNTAXE

#include <openssl/evp.h>
int EVP_SealInit(EVP_CIPHER_CTX *ctx, const EVP_CIPHER *type,
                 unsigned char **ek, int *ekl, unsigned char *iv,
                 EVP_PKEY **pubk, int npubk);
int EVP_SealUpdate(EVP_CIPHER_CTX *ctx, unsigned char *out,
                   int *outl, unsigned char *in, int inl);
int EVP_SealFinal(EVP_CIPHER_CTX *ctx, unsigned char *out, int *outl);

DESCRIPTION

Les routines d'enveloppe EVP sont une interface de haut niveau pour le chiffrement d'enveloppe. Elles génèrent une clé et un IV aléatoires (si nécessaire) puis les "enveloppent" en utilisant le chiffrement à clé publique. Les données peuvent ensuite être chiffrées en utilisant cette clé.

EVP_SealInit() initialise un contexte de chiffrement ctx pour le chiffrement avec le chiffrement type en utilisant une clé secrète et un IV aléatoires. type est normalement fourni par une fonction telle que EVP_aes_256_cbc(). La clé secrète est chiffrée en utilisant une ou plusieurs clés publiques, cela permet aux mêmes données chiffrées d'être déchiffrées en utilisant l'une des clés privées correspondantes. ek est un tableau de tampons où la clé secrète chiffrée par clé publique sera écrite, chaque tampon doit contenir suffisamment de place pour la clé chiffrée correspondante : c'est-à-dire que ek[i] doit avoir de la place pour EVP_PKEY_get_size(pubk[i]) octets. La taille réelle de chaque clé secrète chiffrée est écrite dans le tableau ekl. pubk est un tableau de npubk clés publiques.

Le paramètre iv est un tampon où l'IV généré est écrit. Il doit contenir suffisamment de place pour l'IV du chiffrement correspondant, tel que déterminé par (par exemple) EVP_CIPHER_get_iv_length(type).

Si le chiffrement ne nécessite pas d'IV, le paramètre iv est ignoré et peut être NULL.

EVP_SealUpdate() et EVP_SealFinal() ont exactement les mêmes propriétés que les routines EVP_EncryptUpdate() et EVP_EncryptFinal(), comme documenté dans la page de manuel EVP_EncryptInit(3).

VALEURS DE RETOUR

EVP_SealInit() retourne 0 en cas d'erreur ou npubk en cas de succès.

EVP_SealUpdate() et EVP_SealFinal() retournent 1 en cas de succès et 0 en cas d'échec.

NOTES

Comme une clé secrète aléatoire est générée, le générateur de nombres aléatoires doit être amorcé lorsque EVP_SealInit() est appelé. Si l'amorçage automatique ou le réamorçage du CSPRNG OpenSSL échoue en raison de circonstances externes (voir RAND(7)), l'opération échouera.

La clé publique doit être RSA car c'est le seul algorithme de clé publique OpenSSL qui prend en charge le transport de clés.

Le chiffrement d'enveloppe est la méthode habituelle d'utilisation du chiffrement à clé publique sur de grandes quantités de données, car le chiffrement à clé publique est lent mais le chiffrement symétrique est rapide. Ainsi, le chiffrement symétrique est utilisé pour le chiffrement de masse et la petite clé symétrique aléatoire utilisée est transférée à l'aide du chiffrement à clé publique.

Il est possible d'appeler EVP_SealInit() deux fois de la même manière que EVP_EncryptInit(). Le premier appel doit avoir npubk défini à 0 et (après avoir défini les paramètres de chiffrement) il doit être appelé à nouveau avec type défini à NULL.
