EVP_VerifyInit(3ssl)

Paquet: openssl

Licences: Apache-2.0

EVP_VERIFYINIT(3ssl) OpenSSL EVP_VERIFYINIT(3ssl)

NOM

EVP_VerifyInit_ex, EVP_VerifyInit, EVP_VerifyUpdate, EVP_VerifyFinal_ex, EVP_VerifyFinal - Fonctions de vérification de signature EVP

SYNTAXIS

#include <openssl/evp.h>
int EVP_VerifyInit_ex(EVP_MD_CTX *ctx, const EVP_MD *type, ENGINE *impl);
int EVP_VerifyUpdate(EVP_MD_CTX *ctx, const void *d, unsigned int cnt);
int EVP_VerifyFinal_ex(EVP_MD_CTX *ctx, const unsigned char *sigbuf,
                       unsigned int siglen, EVP_PKEY *pkey,
                       OSSL_LIB_CTX *libctx, const char *propq);
int EVP_VerifyFinal(EVP_MD_CTX *ctx, unsigned char *sigbuf, unsigned int siglen,
                    EVP_PKEY *pkey);
int EVP_VerifyInit(EVP_MD_CTX *ctx, const EVP_MD *type);

DESCRIPTION

Les routines de vérification de signature EVP sont une interface de haut niveau pour les signatures numériques.

EVP_VerifyInit_ex() configure le contexte de vérification ctx pour utiliser le digest type du ENGINE impl. ctx doit être créé en appelant EVP_MD_CTX_new() avant d'appeler cette fonction.

EVP_VerifyUpdate() calcule le hash de cnt octets de données situés à d dans le contexte de vérification ctx. Cette fonction peut être appelée plusieurs fois sur le même ctx pour inclure des données supplémentaires.

EVP_VerifyFinal_ex() vérifie les données dans ctx en utilisant la clé publique pkey et siglen octets dans sigbuf. Le contexte de bibliothèque libctx et la requête de propriété propq sont utilisés lors de la création d'un contexte à utiliser avec la clé pkey.

EVP_VerifyFinal() est similaire à EVP_VerifyFinal_ex() mais utilise les valeurs par défaut de NULL pour le contexte de bibliothèque libctx et la requête de propriété propq.

EVP_VerifyInit() initialise le contexte de vérification ctx pour utiliser l'implémentation par défaut du digest type.

VALEURS DE RETOUR

EVP_VerifyInit_ex() et EVP_VerifyUpdate() renvoient 1 en cas de succès et 0 en cas d'échec.

EVP_VerifyFinal_ex() et EVP_VerifyFinal() renvoient 1 pour une signature correcte, 0 en cas d'échec et une valeur négative si une autre erreur s'est produite.

Les codes d'erreur peuvent être obtenus via ERR_get_error(3).

NOTES

L'interface EVP pour les signatures numériques devrait presque toujours être préférée aux interfaces de bas niveau. En effet, le code devient alors transparent à l'algorithme utilisé et beaucoup plus flexible.

L'appel à EVP_VerifyFinal() finalise intérieurement une copie du contexte de digest. Cela signifie que des appels à EVP_VerifyUpdate() et EVP_VerifyFinal() peuvent être faits ultérieurement pour calculer le digest et vérifier des données supplémentaires. Les applications peuvent désactiver ce comportement en définissant le drapeau de contexte EVP_MD_CTX_FLAG_FINALISE via EVP_MD_CTX_set_flags(3).

Comme seule une copie du contexte de digest est jamais finalisée, le contexte doit être nettoyé après utilisation en appelant EVP_MD_CTX_free(), sinon une fuite de mémoire se produira.

Notez que tous les fournisseurs ne prennent pas en charge la continuation, au cas où le fournisseur sélectionné ne permettrait pas de dupliquer les contextes, EVP_VerifyFinal() finalisera le contexte de digest et tenter de traiter des données supplémentaires via EVP_VerifyUpdate() entraînera une erreur.

BOGUES

Les versions précédentes de cette documentation indiquaient à tort que les appels à EVP_VerifyUpdate() ne pouvaient pas être effectués après avoir appelé EVP_VerifyFinal().

Comme la clé publique est passée dans l'appel à EVP_SignFinal(), toute erreur relative à la clé privée (par exemple, une combinaison clé-digest inappropriée) ne sera indiquée qu'après que des quantités potentiellement importantes de données aient été traitées via EVP_SignUpdate().

Il n'est pas possible de modifier les paramètres de signature à l'aide de ces fonctions.

Les deux bogues précédents sont corrigés dans la nouvelle fonction EVP_DigestVerify*().
