EVP_PKEY_encapsulate(3ssl)

Paquet: openssl

Licences: Apache-2.0

EVP_PKEY_ENCAPSULATE(3ssl) OpenSSL EVP_PKEY_ENCAPSULATE(3ssl)

NOM

EVP_PKEY_encapsulate_init, EVP_PKEY_auth_encapsulate_init, EVP_PKEY_encapsulate - Encapsulation de clé à l'aide d'un algorithme KEM avec une clé publique

SYNOPSIS

#include <openssl/evp.h>
int EVP_PKEY_encapsulate_init(EVP_PKEY_CTX *ctx, const OSSL_PARAM params[]);
int EVP_PKEY_auth_encapsulate_init(EVP_PKEY_CTX *ctx, EVP_PKEY *authpriv,
                                  const OSSL_PARAM params[]);
int EVP_PKEY_encapsulate(EVP_PKEY_CTX *ctx,
                         unsigned char *wrappedkey, size_t *wrappedkeylen,
                         unsigned char *genkey, size_t *genkeylen);

DESCRIPTION

La fonction EVP_PKEY_encapsulate_init() initialise un contexte d'algorithme à clé publique ctx pour une opération d'encapsulation, puis définit les params sur le contexte de la même manière que l'appel à EVP_PKEY_CTX_set_params(3). Notez que ctx est généralement produit à l'aide de EVP_PKEY_CTX_new_from_pkey(3), en spécifiant la clé publique à utiliser.

La fonction EVP_PKEY_auth_encapsulate_init() est similaire à EVP_PKEY_encapsulate_init() mais passe également une clé privée d'authentification authpriv utilisée pendant l'encapsulation.

La fonction EVP_PKEY_encapsulate() effectue une opération d'encapsulation à clé publique en utilisant ctx. Le secret partagé écrit dans genkey peut être utilisé comme entrée pour la dérivation de clés, généralement pour divers algorithmes symétriques. Sa taille est écrite dans genkeylen, qui doit être initialisé à la taille du tampon fourni.

Le texte chiffré écrit dans wrappedkey est une forme encapsulée, qui n'est censée être utilisable que par le détenteur de la clé privée correspondant à la clé publique associée à ctx. Ce texte chiffré est ensuite communiqué au détenteur de la clé privée, qui peut utiliser EVP_PKEY_decapsulate(3) pour récupérer en toute sécurité le même secret partagé.

Si wrappedkey est NULL, la taille maximale du tampon de sortie est écrite dans le paramètre *wrappedkeylen sauf si wrappedkeylen est NULL, et la taille maximale du tampon de clé générée est écrite dans *genkeylen sauf si genkeylen est NULL.

Si wrappedkey n'est pas NULL et que l'appel réussit, le secret partagé généré est écrit dans genkey et sa taille est écrite dans *genkeylen (qui doit être non-NULL). Le texte chiffré encapsulé est écrit dans wrappedkey et sa taille est écrite dans *wrappedkeylen (doit également être non-NULL). La valeur pointée par wrappedlen contient initialement la taille du tampon unwrapped afin que sa taille puisse être validée par l'appel, garantissant qu'elle est suffisamment grande pour contenir le résultat écrit dans wrapped.

En l'absence de connaissances détaillées préalables sur le fonctionnement interne de l'algorithme KEM spécifique, les appelants NE DOIVENT PAS supposer que le secret partagé et le texte chiffré retournés sont nécessairement de la longueur maximale possible. Les longueurs retournées via *wrappedkeylen et *genkeylen DOIVENT être utilisées pour déterminer les longueurs réelles des sorties.

NOTES

Après l'appel à EVP_PKEY_encapsulate_init(), les paramètres spécifiques à l'algorithme pour l'opération peuvent être définis ou modifiés à l'aide de EVP_PKEY_CTX_set_params(3).

VALEURS DE RETOUR

EVP_PKEY_encapsulate_init(), EVP_PKEY_auth_encapsulate_init() et EVP_PKEY_encapsulate() retournent 1 en cas de succès et 0 ou une valeur négative en cas d'échec. En particulier, une valeur de retour de -2 indique que l'opération n'est pas prise en charge par l'algorithme à clé publique.

EXEMPLES

Encapsuler une clé RSASVE (pour les clés RSA).

#include <openssl/evp.h>
/*
 * NB: suppose que rsa_pub_key est une clé publique d'une autre partie.
 */
EVP_PKEY_CTX *ctx = NULL;
size_t secretlen = 0, outlen = 0;
unsigned char *out = NULL, *secret = NULL;
ctx = EVP_PKEY_CTX_new_from_pkey(libctx, rsa_pub_key, NULL);
if (ctx == NULL)
    /* Erreur */
if (EVP_PKEY_encapsulate_init(ctx, NULL) <= 0)
    /* Erreur */
/* Définir le mode - seul 'RSASVE' est actuellement pris en charge */
 if (EVP_PKEY_CTX_set_kem_op(ctx, "RSASVE") <= 0)
    /* Erreur */
/* Déterminer la longueur du tampon */
if (EVP_PKEY_encapsulate(ctx, NULL, &outlen, NULL, &secretlen) <= 0)
    /* Erreur */
out = OPENSSL_malloc(outlen);
secret = OPENSSL_malloc(secretlen);
if (out == NULL || secret == NULL)
    /* échec de malloc */
/*
 * Le 'secret' généré peut être utilisé comme matériau de clé.
 * Le 'out' encapsulé peut être envoyé à une autre partie qui peut
 * le décapsuler avec sa clé privée pour récupérer le 'secret'.
 */
if (EVP_PKEY_encapsulate(ctx, out, &outlen, secret, &secretlen) <= 0)
    /* Erreur */

HISTORIQUE

Les fonctions EVP_PKEY_encapsulate_init() et EVP_PKEY_encapsulate() ont été ajoutées dans OpenSSL 3.0. La fonction EVP_PKEY_auth_encapsulate_init() a été ajoutée dans OpenSSL 3.2.

La prise en charge de ML-KEM a été ajoutée dans OpenSSL 3.5.
