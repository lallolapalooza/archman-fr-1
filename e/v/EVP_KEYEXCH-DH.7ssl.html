NOM

EVP_KEYEXCH-DH - Support de l'algorithme d'échange de clés DH

DESCRIPTION

Support de l'échange de clés pour les types de clés DH et DHX.

Veuillez noter que bien que les deux types de clés supportent les mêmes opérations d'échange de clés, ils ne peuvent pas être utilisés ensemble dans un seul échange de clés. Il n'est pas possible d'utiliser une clé privée de type DH dans un échange de clés avec la clé publique de type DHX et vice versa.

PARAMÈTRES DE CHANGE DE CLÉS DH ET DHX

"pad" (OSSL_EXCHANGE_PARAM_PAD) <entier non signé>
Définit le mode de remplissage pour le contexte d'échange de clés associé. Définir une valeur de 1 active le remplissage. Définir une valeur de 0 désactive le remplissage. Si le remplissage est désactivé, le secret partagé dérivé peut être plus petit que la taille maximale possible du secret. Si le remplissage est activé, les premiers octets du secret partagé dérivé seront remplis de zéros si nécessaire pour que le secret partagé ait la même taille que la taille maximale possible du secret. Le paramètre de mode de remplissage est ignoré (et le remplissage est implicitement activé) lorsque le type de KDF est défini sur "X942KDF-ASN1" (OSSL_KDF_NAME_X942KDF_ASN1).
"kdf-type" (OSSL_EXCHANGE_PARAM_KDF_TYPE) <chaîne UTF8>
"kdf-digest" (OSSL_EXCHANGE_PARAM_KDF_DIGEST) <chaîne UTF8>
"kdf-digest-props" (OSSL_EXCHANGE_PARAM_KDF_DIGEST_PROPS) <chaîne UTF8>
"kdf-outlen" (OSSL_EXCHANGE_PARAM_KDF_OUTLEN) <entier non signé>
"kdf-ukm" (OSSL_EXCHANGE_PARAM_KDF_UKM) <chaîne d'octets>
"fips-indicator" (OSSL_EXCHANGE_PARAM_FIPS_APPROVED_INDICATOR) <entier>
"key-check" (OSSL_EXCHANGE_PARAM_FIPS_KEY_CHECK) <entier>
"digest-check" (OSSL_EXCHANGE_PARAM_FIPS_DIGEST_CHECK) <entier>
Voir "Paramètres communs d'échange de clés" dans provider-keyexch(7).
"cekalg" (OSSL_KDF_PARAM_CEK_ALG) <pointeur vers une chaîne d'octets>
Voir "Paramètres KDF" dans provider-kdf(7).

EXEMPLES

Les exemples supposent qu'un hôte et un pair génèrent tous deux des clés en utilisant le même groupe nommé (ou les mêmes paramètres de domaine). Voir "Exemples" dans EVP_PKEY-DH(7). L'hôte et le pair s'échangent leurs clés publiques.

Pour convertir la paire de clés générée par le pair en clé publique au format DER afin de la transférer à l'hôte :

EVP_PKEY *peer_key; /* Il est supposé que cela contient la clé générée par le pair */
unsigned char *peer_pub_der = NULL;
int peer_pub_der_len;
peer_pub_der_len = i2d_PUBKEY(peer_key, &peer_pub_der);
...
OPENSSL_free(peer_pub_der);

Pour convertir la clé publique reçue du pair à partir du format DER sur l'hôte :

const unsigned char *pd = peer_pub_der;
EVP_PKEY *peer_pub_key = d2i_PUBKEY(NULL, &pd, peer_pub_der_len);
...
EVP_PKEY_free(peer_pub_key);

Pour dériver un secret partagé sur l'hôte en utilisant la clé de l'hôte et la clé publique du pair :

/* Il est supposé que host_key et peer_pub_key sont configurés */
void derive_secret(EVP_KEY *host_key, EVP_PKEY *peer_pub_key)
{
    unsigned int pad = 1;
    OSSL_PARAM params[2];
    unsigned char *secret = NULL;
    size_t secret_len = 0;
    EVP_PKEY_CTX *dctx = EVP_PKEY_CTX_new_from_pkey(NULL, host_key, NULL);
    EVP_PKEY_derive_init(dctx);
    /* Définir éventuellement le remplissage */
    params[0] = OSSL_PARAM_construct_uint(OSSL_EXCHANGE_PARAM_PAD, &pad);
    params[1] = OSSL_PARAM_construct_end();
    EVP_PKEY_CTX_set_params(dctx, params);
    EVP_PKEY_derive_set_peer(dctx, peer_pub_key);
    /* Obtenir la taille en passant NULL comme tampon */
    EVP_PKEY_derive(dctx, NULL, &secret_len);
    secret = OPENSSL_zalloc(secret_len);
    EVP_PKEY_derive(dctx, secret, &secret_len);
    ...
    OPENSSL_clear_free(secret, secret_len);
    EVP_PKEY_CTX_free(dctx);
}

Un code très similaire peut être utilisé par le pair pour dériver le même secret partagé en utilisant la clé publique de l'hôte et la paire de clés générée par le pair.
