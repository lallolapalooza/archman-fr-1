Fonctions d'information

EVP_RAND_get_strength() renvoie la force de sécurité du RAND ctx.

EVP_RAND_get_state() renvoie l'état actuel du RAND ctx. Les états définis par les GNA d'OpenSSL sont :

  • EVP_RAND_STATE_UNINITIALISED : ce GNA est actuellement non initialisé. L'appel d'instanciation le changera à l'état prêt.
  • EVP_RAND_STATE_READY : ce GNA est actuellement prêt à générer des sorties.
  • EVP_RAND_STATE_ERROR : ce GNA est dans un état d'erreur.

EVP_RAND_is_a() renvoie 1 si rand est une implémentation d'un algorithme identifiable avec name, sinon 0.

EVP_RAND_get0_provider() renvoie le fournisseur qui détient l'implémentation du randdonné.

EVP_RAND_do_all_provided() parcourt tous les RAND implémentés par tous les fournisseurs activés dans le contexte de bibliothèque donné libctx, et pour chaque implémentation, appelle la fonction donnée fn avec la méthode d'implémentation et le arg donné comme argument.

EVP_RAND_get0_name() renvoie le nom canonique de rand.

EVP_RAND_names_do_all() parcourt tous les noms de rand, et appelle fn avec chaque nom et data.

EVP_RAND_get0_description() renvoie une description du rand, destinée à l'affichage et à la consommation humaine. La description est à la discrétion de l'implémentation du rand.

EVP_RAND_verify_zeroization() confirme si l'état interne du DRBG est actuellement mis à zéro. Ceci est utilisé par le fournisseur FIPS pour prendre en charge les auto-tests obligatoires.

PARAMÈTRES

Les noms de paramètres standard sont :

"state" (OSSL_RAND_PARAM_STATE) <entier>
Renvoie l'état du générateur de nombres aléatoires.
"strength" (OSSL_RAND_PARAM_STRENGTH) <entier non signé>
Renvoie la force en bits du générateur de nombres aléatoires.
"fips-indicator" (OSSL_RAND_PARAM_FIPS_APPROVED_INDICATOR) <entier>
Un accesseur qui renvoie 1 si l'opération est approuvée par FIPS, ou 0 sinon. Cette option est utilisée par le fournisseur FIPS d'OpenSSL et n'est pas prise en charge par toutes les sources EVP_RAND.

Pour les rands qui sont également des générateurs aléatoires de bits déterministes (DRBG), ces paramètres supplémentaires sont reconnus. Tous les paramètres ne sont pas pertinents pour, ou ne sont pas compris par tous les rands DRBG :

"reseed_requests" (OSSL_DRBG_PARAM_RESEED_REQUESTS) <entier non signé>
Lit ou définit le nombre de requêtes de génération avant le réensemencement du RAND ctx associé.
"reseed_time_interval" (OSSL_DRBG_PARAM_RESEED_TIME_INTERVAL) <entier>
Lit ou définit le nombre de secondes écoulées avant le réensemencement du RAND ctx associé.
"max_request" (OSSL_RAND_PARAM_MAX_REQUEST) <entier non signé>
Spécifie le nombre maximum d'octets qui peuvent être générés dans un seul appel à OSSL_FUNC_rand_generate.
"min_entropylen" (OSSL_DRBG_PARAM_MIN_ENTROPYLEN) <entier non signé>
"max_entropylen" (OSSL_DRBG_PARAM_MAX_ENTROPYLEN) <entier non signé>
Spécifie le nombre minimum et maximum d'octets de matériel aléatoire qui peuvent être utilisés pour semer le DRBG.
"min_noncelen" (OSSL_DRBG_PARAM_MIN_NONCELEN) <entier non signé>
"max_noncelen" (OSSL_DRBG_PARAM_MAX_NONCELEN) <entier non signé>
Spécifie le nombre minimum et maximum d'octets de nonce qui peuvent être utilisés pour semer le DRBG.
"max_perslen" (OSSL_DRBG_PARAM_MAX_PERSLEN) <entier non signé>
"max_adinlen" (OSSL_DRBG_PARAM_MAX_ADINLEN) <entier non signé>
Spécifie le nombre minimum et maximum d'octets de chaîne de personnalisation qui peuvent être utilisés avec le DRBG.
"reseed_counter" (OSSL_DRBG_PARAM_RESEED_COUNTER) <entier non signé>
Spécifie le nombre de fois où le DRBG a été semé ou réensemencé.
"properties" (OSSL_RAND_PARAM_PROPERTIES) <chaîne UTF8>
"mac" (OSSL_RAND_PARAM_MAC) <chaîne UTF8>
"digest" (OSSL_RAND_PARAM_DIGEST) <chaîne UTF8>
"cipher" (OSSL_RAND_PARAM_CIPHER) <chaîne UTF8>
Pour les implémentations RAND qui utilisent un MAC, digest ou chiffrement de calcul sous-jacent, ces paramètres définissent quel algorithme doit être utilisé.

La valeur est toujours le nom de l'algorithme visé, ou les propriétés dans le cas de OSSL_RAND_PARAM_PROPERTIES.

REMARQUES

L'utilisation d'une valeur non nulle pour l'argument prediction_resistance de EVP_RAND_instantiate(), EVP_RAND_generate() ou EVP_RAND_reseed() devrait être utilisée avec parcimonie. Dans la configuration par défaut, cela causera le réensemencement de tous les DRBG publics et privés à la prochaine utilisation. Puisque, par défaut, les DRBG publics et privés sont alloués par thread, cela peut entraîner une surcharge importante pour les applications fortement multi-threadées. Pour les cas d'utilisation normaux, les seuils par défaut "reseed_requests" et "reseed_time_interval" assurent une résistance aux prédictions suffisante dans le temps et vous pouvez réduire ces valeurs si vous pensez qu'elles sont trop élevées. Demander explicitement la résistance aux prédictions est destiné à des cas d'utilisation plus spécialisés comme la génération de secrets à long terme.

Un EVP_RAND_CTX doit avoir le verrouillage activé s'il agit comme le parent de plus d'un enfant et que les enfants peuvent être accédés simultanément. Cela doit être fait en appelant explicitement EVP_RAND_enable_locking().

Le cycle de vie du RAND est décrit dans life_cycle-rand(7). Dans le futur, les transitions décrites là-bas seront imposées. Quand cela sera fait, cela ne sera pas considéré comme un changement incompatible avec l'API.

VALEURS RENVOYÉES

EVP_RAND_fetch() renvoie un pointeur vers un EVP_RANDnouvellement récupéré, ou NULL si l'allocation a échoué.

EVP_RAND_get0_provider() renvoie un pointeur vers le fournisseur pour le RAND, ou NULL en cas d'erreur.

EVP_RAND_CTX_get0_rand() renvoie un pointeur vers le EVP_RAND associé au contexte.

EVP_RAND_get0_name() renvoie le nom de l'algorithme de génération de nombres aléatoires.

EVP_RAND_up_ref() renvoie 1 en cas de succès, 0 en cas d'erreur.

EVP_RAND_names_do_all() renvoie 1 si le rappel a été appelé pour tous les noms. Une valeur de retour de 0 signifie que le rappel n'a pas été appelé pour aucun nom.

EVP_RAND_CTX_new() renvoie soit la structure EVP_RAND_CTX nouvellement allouée, soit NULL si une erreur est survenue.

EVP_RAND_CTX_free() ne renvoie pas de valeur.

EVP_RAND_CTX_up_ref() renvoie 1 en cas de succès, 0 en cas d'erreur.

EVP_RAND_nonce() renvoie 1 en cas de succès, 0 en cas d'erreur.

EVP_RAND_get_strength() renvoie la force du générateur de nombres aléatoires en bits.

EVP_RAND_gettable_params(), EVP_RAND_gettable_ctx_params() et EVP_RAND_settable_ctx_params() renvoient un tableau de OSSL_PARAMs.

EVP_RAND_verify_zeroization() renvoie 1 si l'état interne du DRBG est actuellement mis à zéro, et 0 sinon.

Les fonctions restantes renvoient 1 pour le succès et 0 ou une valeur négative pour l'échec.
