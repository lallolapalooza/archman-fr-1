NOM

EVP_PKEY-ML-DSA, EVP_KEYMGMT-ML-DSA, EVP_PKEY-ML-DSA-44, EVP_PKEY-ML-DSA-65, EVP_PKEY-ML-DSA-87 - Type de clé EVP_PKEY ML-DSA et prise en charge de l'algorithme

DESCRIPTION

ML-DSA implémente les algorithmes ML-DSA-44, ML-DSA-65 et ML-DSA-87. Les types de clés EVP_PKEY_ML_DSA_44, EVP_PKEY_ML_DSA_65 et EVP_PKEY_ML_DSA_87 sont implémentés dans les fournisseurs par défaut et FIPS d'OpenSSL. Ces implémentations prennent en charge la clé associée, contenant la clé publique pub et la clé privée priv.

Chacun des différents types de clés a une catégorie de sécurité associée. Cette valeur est l'une de 2, 3 ou 5 pour les types de clés ML-DSA-44, ML-DSA-65 et ML-DSA-87 respectivement, qui correspondent à des forces de sécurité de 128, 192 et 256 respectivement.

Paramètres de génération de clés

"seed" (OSSL_PKEY_PARAM_ML_DSA_SEED) <chaîne d'octets>
La graine peut être utilisée pour générer les composants de la clé privée et publique de manière déterministe. La longueur de la valeur fournie doit être de 32 octets. Lorsque cette valeur n'est pas fournie, la graine est générée aléatoirement à l'aide d'un DRBG.

Les clés générées conservent par défaut la graine utilisée. La graine est également conservée par défaut lorsque les clés sont chargées à partir de fichiers PKCS#8 au format graine. Lorsqu'elle est disponible, le paramètre de graine est également utilisé lors de l'export et de l'import de clés, les clés étant (par défaut) régénérées à partir de la graine même si elle est également fournie lors de l'import. Voir « Paramètres de configuration du fournisseur » ci-dessous pour les contrôles associés. Lorsque la graine est conservée, elle est également disponible en tant que paramètre

lisible , et la sortie de la clé privée vers les fichiers PKCS#8 inclura par défaut la graine. Lorsque la graine n'était pas initialement connue, ou n'a pas été conservée, les fichiers de clé privée PKCS#8 ne contiendront que la clé privée au format « sk » de FIPS 204 .

"properties" (OSSL_PKEY_PARAM_PROPERTIES) <chaîne UTF8>
Définit les propriétés à utiliser lors de la récupération des implémentations d'algorithmes utilisées pour les opérations de hachage ML-DSA.

Utilisez EVP_PKEY_CTX_set_params(3) après avoir appelé EVP_PKEY_keygen_init(3).

Paramètres ML-DSA courants

En plus des paramètres courants que tous les types de clés doivent prendre en charge (voir « Common Information Parameters » dans provider-keymgmt(7), l'implémentation de ces types de clés prend en charge les paramètres listés ci-dessous. Ceux-ci sont lisibles à l'aide de EVP_PKEY_get_octet_string_param(3) ou EVP_PKEY_get_params(3). Ils peuvent être initialisés via EVP_PKEY_fromdata(3), et sont retournés par EVP_PKEY_todata(3) avec une sélectionappropriée. Une fois qu'une clé publique ou privée est configurée, elle ne peut plus être modifiée, et aucun autre composant de clé ne peut être ajouté.

"pub" (OSSL_PKEY_PARAM_PUB_KEY) <chaîne d'octets>
La valeur de la clé publique encodée de taille 1312, 1952 ou 2592 octets selon le type de clé respectif ML-DSA-44, ML-DSA-65 ou ML-DSA-87.
"priv" (OSSL_PKEY_PARAM_PRIV_KEY) <chaîne d'octets>
La valeur de la clé privée encodée de taille 2560, 4032 ou 4896 octets selon le type de clé respectif ML-DSA-44, ML-DSA-65 ou ML-DSA-87.

Paramètres de configuration du fournisseur

Voir la description de l'option -provparam dans openssl(1) pour savoir comment définir les paramètres de configuration du fournisseur dans les outils en ligne de commande. Voir OSSL_PROVIDER_add_conf_parameter(3) pour savoir comment définir les options de configuration du fournisseur par programmation.

"ml-dsa.retain_seed" (OSSL_PKEY_PARAM_ML_DSA_RETAIN_SEED) <chaîne UTF8>
Lorsqu'il est défini sur une chaîne représentant une valeur booléenne fausse (voir OSSL_PROVIDER_conf_get_bool(3)), la graine ne sera pas conservée après la génération de clé ou l'import de clé à partir d'une valeur de graine. Si la clé résultante est ensuite écrite dans un objet PKCS#8, elle ne contiendra que la clé « sk » de FIPS 204.
"ml-dsa.prefer_seed" (OSSL_PKEY_PARAM_ML_DSA_PREFER_SEED) <chaîne UTF8>
Lors du décodage des objets PKCS#8 contenant à la fois une graine et la clé privée « sk » de FIPS 204, la graine est par défaut utilisée pour régénérer la clé, et la clé privée associée est ignorée. Lorsque ce paramètre de configuration est défini sur une chaîne représentant une valeur booléenne fausse (voir OSSL_PROVIDER_conf_get_bool(3)), la graine est ignorée (ni utilisée pour régénérer la clé, ni conservée), et la clé associée est utilisée à la place.
"ml-dsa.input_formats" (OSSL_PKEY_PARAM_ML_DSA_INPUT_FORMATS) <chaîne UTF8>
Liste des formats d'entrée de clé privée activés lors de l'analyse des objets PKCS#8. Les éléments de la liste sont séparés par des virgules, des espaces ou des tabulations. La liste des formats activés peut être spécifiée dans le fichier de configuration, comme vu dans la section « EXEMPLES » ci-dessous, ou via l'option en ligne de commande -provparam (voir aussi OSSL_PROVIDER_add_conf_parameter(3)).

Les valeurs spécifiées en ligne de commande remplacent tous les paramètres du fichier de configuration. Par défaut, tous les formats pris en charge sont activés. Les formats pris en charge sont :

"seed-priv" :
Ce format représente des objets PKCS#8 dans lesquels à la fois la graine ξ de 32 octets de FIPS 204 et la clé secrète sk sont présentes dans la clé privée dans le cadre de l'encodage DER de la séquence ASN.1 : 
ML-DSA-PrivateKey ::= CHOICE {
  seed [0] IMPLICIT OCTET STRING (SIZE (32)),
  expandedKey OCTET STRING (SIZE (2560 | 4032 | 4896)),
  both SEQUENCE {
    seed OCTET STRING (SIZE (32)),
    expandedKey OCTET STRING (SIZE (2560 | 4032 | 4896)) } }

Si le format "seed-priv" n'est pas inclus dans la liste, ce format ne sera pas reconnu à l'entrée.

"seed-only" :
Ce format représente des objets PKCS#8 dans lesquels seule la graine ξ de 32 octets de FIPS 204 est présente dans la séquence ci-dessus. Si le format "seed-only" n'est pas inclus dans la liste, ce format ne sera pas reconnu à l'entrée.
"priv-only" :
Ce format représente des objets PKCS#8 dans lesquels seule la clé privée sk de FIPS 204 est présente dans la séquence ci-dessus. Si le format "priv-only" n'est pas inclus dans la liste, ce format ne sera pas reconnu à l'entrée.
"oqskeypair" :
Ce format représente des objets PKCS#8 dans lesquels la clé privée est un encodage DER d'une chaîne d'octets contenant la concaténation de la clé privée sk et de la clé publique pkde FIPS 204. Cet encodage est utilisé dans certaines compilations de "oqsprovider". Si le format "oqskeypair" n'est pas inclus dans la liste, ce format ne sera pas reconnu à l'entrée.
"bare-seed" :
Ce format représente des objets PKCS#8 dans lesquels la clé privée contient la graine ξ de 32 octets de FIPS 204 sans aucune encapsulation ASN.1. Si le format "bare-seed" n'est pas inclus dans la liste, ce format ne sera pas reconnu à l'entrée.
"bare-priv" :
Ce format représente des objets PKCS#8 dans lesquels la clé privée contient la clé secrète sk de FIPS 204 sans aucune encapsulation ASN.1. Si le format "bare-priv" n'est pas inclus dans la liste, ce format ne sera pas reconnu à l'entrée.
"ml-dsa.output_formats" (OSSL_PKEY_PARAM_ML_DSA_OUTPUT_FORMATS) <chaîne UTF8>
Liste ordonnée des formats de sortie de clé privée activés lors de l'écriture des fichiers PKCS#8 . Les éléments de la liste sont séparés par des virgules, des espaces ou des tabulations. La liste des formats activés peut être dans le fichier de configuration, comme vu dans la section « EXAMPLES » ci-dessous, ou via l' -provparam d'option de ligne de commande.

Cela prend en charge le même ensemble de formats que décrit sous « ml-dsa.input_formats » ci-dessus. L' ordre dans lequel les éléments sont listés est important, le format sélectionné sera le premier qui peut être produit. Si la graine de la clé est connue, le premier format listé sera sélectionné. Si la graine de la clé n'est pas connue, le premier format qui omet la graine sera sélectionné. L' ordre par défaut est équivalent à « seed-priv » en premier et « priv-only » en second, avec à la fois la graine et la clé produites lorsque la graine est disponible, et seulement la clé sinon. Si « seed-only » est listé en premier, alors la graine sera produite sans la clé lorsqu'elle est disponible, sinon la sortie aura juste la clé. Si « priv-only » est listé en premier, alors seule la clé est produite que la graine soit présente ou non. Les formats hérités « oqskeypair », « bare-seed » et « bare-priv » peuvent également être produits, en les listant en premier.

CONFORME À

FIPS 204

EXEMPLES

Un EVP_PKEY contexte peut être obtenu en appelant :

EVP_PKEY_CTX *pctx =
    EVP_PKEY_CTX_new_from_name(NULL, "ML-DSA-44", NULL);

Une ML-DSA-44 clé peut être générée comme ceci :

pkey = EVP_PKEY_Q_keygen(NULL, NULL, "ML-DSA-44");

Les composants de la paire de clés peuvent être extraits d'une clé en appelant :

/* Tailles suffisantes pour ML-DSA-87 */
uint8_t pub[2592], priv[4896], seed[32]:
size_t priv_len, pub_len, seed_len;
EVP_PKEY_get_octet_string_param(pkey, OSSL_PKEY_PARAM_ML_DSA_SEED,
                                seed, sizeof(seed), &seed_len);
EVP_PKEY_get_octet_string_param(pkey, OSSL_PKEY_PARAM_PRIV_KEY,
                                priv, sizeof(priv), &priv_len);
EVP_PKEY_get_octet_string_param(pkey, OSSL_PKEY_PARAM_PUB_KEY,
                                pub, sizeof(pub), &pub_len));

Une ML-DSA clé privée au format graine peut être convertie en une clé au format sk FIPS 204 en exécutant :

$ openssl pkey -provparam ml-dsa.retain_seed=no \
    -in seed-only.pem -out priv-only.pem

Pour générer une clé, par exemple une ML-DSA-65 , au format sk FIPS 204, vous pouvez exécuter :

$ openssl genpkey -provparam ml-dsa.retain_seed=no \
    -algorithm ml-dsa-65 -out priv-only.pem

Si vous avez un fichier PKCS#8 contenant à la fois une graine et une clé, et que vous préférez importer la clé associée plutôt que la graine, vous pouvez exécuter :

$ openssl pkey -provparam ml-dsa.prefer_seed=no \
    -in seed-priv.pem -out priv-only.pem

Dans le openssl.cnf fichier, cela ressemble à :

openssl_conf = openssl_init
[openssl_init]
providers = providers_sect
# Peut être référencé dans une ou plusieurs sections de fournisseur
[ml_dsa_sect]
prefer_seed = yes
retain_seed = yes
# Formats hérités OQS désactivés
input_formats = seed-priv, seed-only, priv-only
# Produit soit la seule graine, soit la seule clé
output_formats = seed-only, priv-only
[providers_sect]
default = default_sect
# Ou peut-être juste : base = default_sect
base = base_sect
[default_sect]
ml-dsa = ml_dsa_sect
[base_sect]
ml-dsa = ml_dsa_sect
