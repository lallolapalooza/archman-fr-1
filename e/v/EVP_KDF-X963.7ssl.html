NOM

EVP_KDF-X963 - L'implémentation EVP_KDF X9.63-2001

DESCRIPTION

L'algorithme EVP_KDF-X963 implémente la fonction de dérivation de clé (X963KDF). X963KDF est utilisée par la syntaxe de message cryptographique (CMS) pour l'accord de clé EC, afin de dériver une clé à l'aide d'entrées telles qu'une clé secrète partagée et des informations partagées.

La sortie est considérée comme du matériel de chiffrement.

Identité

"X963KDF" est le nom de cette implémentation ; il peut être utilisé avec la fonction EVP_KDF_fetch().

Paramètres pris en charge

Les paramètres pris en charge sont :

"properties" (OSSL_KDF_PARAM_PROPERTIES) <chaîne UTF8>
"digest" (OSSL_KDF_PARAM_DIGEST) <chaîne UTF8>
Ces paramètres fonctionnent comme décrit dans "PARAMÈTRES" de EVP_KDF(3).
"key" (OSSL_KDF_PARAM_KEY) <chaîne d'octets>
Le secret partagé utilisé pour la dérivation de clé. Ce paramètre définit le secret.
"info" (OSSL_KDF_PARAM_INFO) <chaîne d'octets>
Ce paramètre spécifie une valeur optionnelle pour les informations partagées.

Le fournisseur FIPS d'OpenSSL prend également en charge les paramètres suivants :

"fips-indicator" (OSSL_KDF_PARAM_FIPS_APPROVED_INDICATOR) <entier>
Un accesseur qui renvoie 1 si l'opération est approuvée par FIPS, ou 0 sinon. Ceci peut être utilisé après avoir appelé EVP_KDF_derive. Il renvoie 0 si un paramètre lié à "***-check" est défini sur 0 et que la vérification échoue.
"digest-check" (OSSL_KDF_PARAM_FIPS_DIGEST_CHECK) <entier>
La valeur par défaut de 1 provoque une erreur lors de EVP_KDF_CTX_set_params() si le digest utilisé n'est pas approuvé. Définir cela sur zéro ignorera l'erreur et définira "fips-indicator" approuvé sur 0. Cette option enfreint la conformité FIPS si elle amène "fips-indicator" approuvé à renvoyer 0.

Selon ANSI X9.63-2001, les algorithmes de digest approuvés sont les suivants : SHA2-224, SHA2-256, SHA2-384, SHA2-512, SHA2-512/224, SHA2-512/256, SHA3-224, SHA3-256, SHA3-384, SHA3-512.

"key-check" (OSSL_KDF_PARAM_FIPS_KEY_CHECK) <entier>
La valeur par défaut de 1 provoque une erreur lors de EVP_KDF_CTX_set_params() si la longueur de la clé de dérivation utilisée (OSSL_KDF_PARAM_KEY) est inférieure à 112 bits. Définir cela sur zéro ignorera l'erreur et définira "fips-indicator" approuvé sur 0. Cette option enfreint la conformité FIPS si elle amène "fips-indicator" approuvé à renvoyer 0.

NOTES

X963KDF est très similaire à SSKDF qui utilise un digest comme fonction auxiliaire. X963KDF ajoute le compteur au secret, tandis que SSKDF prépone le compteur.

Un contexte pour X963KDF peut être obtenu en appelant :

EVP_KDF *kdf = EVP_KDF_fetch(NULL, "X963KDF", NULL);
EVP_KDF_CTX *kctx = EVP_KDF_CTX_new(kdf);

La longueur de sortie d'un X963KDF est spécifiée via le paramètre keylen à la fonction EVP_KDF_derive(3).

EXEMPLES

Cet exemple dérive 10 octets, avec la clé secrète "secret" et la valeur d'informations partagées "label" :

EVP_KDF *kdf;
EVP_KDF_CTX *kctx;
unsigned char out[10];
OSSL_PARAM params[4], *p = params;
kdf = EVP_KDF_fetch(NULL, "X963KDF", NULL);
kctx = EVP_KDF_CTX_new(kdf);
EVP_KDF_free(kdf);
*p++ = OSSL_PARAM_construct_utf8_string(OSSL_KDF_PARAM_DIGEST,
                                        SN_sha256, strlen(SN_sha256));
*p++ = OSSL_PARAM_construct_octet_string(OSSL_KDF_PARAM_SECRET,
                                         "secret", (size_t)6);
*p++ = OSSL_PARAM_construct_octet_string(OSSL_KDF_PARAM_INFO,
                                         "label", (size_t)5);
*p = OSSL_PARAM_construct_end();
if (EVP_KDF_derive(kctx, out, sizeof(out), params) <= 0) {
    error("EVP_KDF_derive");
}
EVP_KDF_CTX_free(kctx);
