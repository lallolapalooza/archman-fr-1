NOM

EVP_KDF-TLS1_PRF - L'implémentation EVP_KDF TLS1_PRF

DESCRIPTION

Support pour le calcul du PRF TLS1 via l'API EVP_KDF.

L'algorithme EVP_KDF-TLS1_PRF implémente le PRF utilisé par les versions TLS jusqu'à et y compris TLS 1.2.

La sortie est considérée comme du matériel de dérivation de clé.

Identité

"TLS1-PRF" est le nom de cette implémentation ; il peut être utilisé avec la fonction EVP_KDF_fetch().

Paramètres pris en charge

Les paramètres pris en charge sont :

"properties" (OSSL_KDF_PARAM_PROPERTIES) <chaîne UTF8>
"digest" (OSSL_KDF_PARAM_DIGEST) <chaîne UTF8>
Ces paramètres fonctionnent comme décrit dans "PARAMÈTRES" de EVP_KDF(3).

Le paramètre OSSL_KDF_PARAM_DIGEST est utilisé pour définir le résumé de message associé au PRF TLS. EVP_md5_sha1() est traité comme un cas spécial qui utilise l'algorithme PRF utilisant à la fois MD5 et SHA1 comme utilisé dans TLS 1.0 et 1.1.

"secret" (OSSL_KDF_PARAM_SECRET) <chaîne d'octets>
Ce paramètre définit la valeur secrète du PRF TLS. Toute valeur secrète existante est remplacée.
"seed" (OSSL_KDF_PARAM_SEED) <chaîne d'octets>
Ce paramètre définit la graine de contexte. La longueur de la graine de contexte ne peut pas dépasser 1024 octets ; cela devrait être plus que suffisant pour toute utilisation normale du PRF TLS.

Le fournisseur FIPS d'OpenSSL prend également en charge les paramètres suivants :

"fips-indicator" (OSSL_KDF_PARAM_FIPS_APPROVED_INDICATOR) <entier>
Un accesseur qui renvoie 1 si l'opération est approuvée FIPS, ou 0 sinon. Cela peut être utilisé après avoir appelé EVP_KDF_derive. Il renvoie 0 si un paramètre lié à "***-check" est défini sur 0 et que la vérification échoue.
"ems_check" (OSSL_KDF_PARAM_FIPS_EMS_CHECK) <entier>
La valeur par défaut de 1 provoque une erreur lors de EVP_KDF_derive() si "master secret" est utilisé au lieu de "extended master secret". Définir cela sur zéro ignorera l'erreur et définira "fips-indicator" approuvé sur 0. Cette option enfreint la conformité FIPS si elle provoque le retour de 0 par "fips-indicator" approuvé.
"digest-check" (OSSL_KDF_PARAM_FIPS_DIGEST_CHECK) <entier>
La valeur par défaut de 1 provoque une erreur lors de EVP_KDF_CTX_set_params() si le digest utilisé n'est pas approuvé. Définir cela sur zéro ignorera l'erreur et définira "fips-indicator" approuvé sur 0. Cette option enfreint la conformité FIPS si elle provoque le retour de 0 par "fips-indicator" approuvé.

Selon SP 800-135r1, les algorithmes de digest approuvés sont les suivants : SHA2-256, SHA2-384, SHA2-512.

"key-check" (OSSL_KDF_PARAM_FIPS_KEY_CHECK) <entier>
La valeur par défaut de 1 provoque une erreur lors de EVP_KDF_CTX_set_params() si la longueur de la clé de dérivation utilisée (OSSL_KDF_PARAM_SECRET) est inférieure à 112 bits. Définir cela sur zéro ignorera l'erreur et définira "fips-indicator" approuvé sur 0. Cette option enfreint la conformité FIPS si elle provoque le retour de 0 par "fips-indicator" approuvé.

NOTES

Un contexte pour le PRF TLS peut être obtenu en appelant :

EVP_KDF *kdf = EVP_KDF_fetch(NULL, "TLS1-PRF", NULL);
EVP_KDF_CTX *kctx = EVP_KDF_CTX_new(kdf);

Le digest, la valeur secrète et la graine doivent être définis avant qu'une clé ne soit dérivée, sinon une erreur se produira.

La longueur de sortie du PRF est spécifiée par le paramètre keylen de la fonction EVP_KDF_derive().

EXEMPLES

Cet exemple dérive 10 octets en utilisant SHA-256 avec la clé secrète "secret" et la valeur de graine "seed" :

EVP_KDF *kdf;
EVP_KDF_CTX *kctx;
unsigned char out[10];
OSSL_PARAM params[4], *p = params;
kdf = EVP_KDF_fetch(NULL, "TLS1-PRF", NULL);
kctx = EVP_KDF_CTX_new(kdf);
EVP_KDF_free(kdf);
*p++ = OSSL_PARAM_construct_utf8_string(OSSL_KDF_PARAM_DIGEST,
                                        SN_sha256, strlen(SN_sha256));
*p++ = OSSL_PARAM_construct_octet_string(OSSL_KDF_PARAM_SECRET,
                                         "secret", (size_t)6);
*p++ = OSSL_PARAM_construct_octet_string(OSSL_KDF_PARAM_SEED,
                                         "seed", (size_t)4);
*p = OSSL_PARAM_construct_end();
if (EVP_KDF_derive(kctx, out, sizeof(out), params) <= 0) {
    error("EVP_KDF_derive");
}
EVP_KDF_CTX_free(kctx);
