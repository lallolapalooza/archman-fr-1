EVP_PKEY_CTX_new(3ssl)

Paquet: openssl

Licences: Apache-2.0

EVP_PKEY_CTX_NEW(3ssl) OpenSSL EVP_PKEY_CTX_NEW(3ssl)

NOM

EVP_PKEY_CTX_new, EVP_PKEY_CTX_new_id, EVP_PKEY_CTX_new_from_name, EVP_PKEY_CTX_new_from_pkey, EVP_PKEY_CTX_dup, EVP_PKEY_CTX_free, EVP_PKEY_CTX_is_a - fonctions de contexte d'algorithme de clé publique

SYNOPSIS

#include <openssl/evp.h>
EVP_PKEY_CTX *EVP_PKEY_CTX_new(EVP_PKEY *pkey, ENGINE *e);
EVP_PKEY_CTX *EVP_PKEY_CTX_new_id(int id, ENGINE *e);
EVP_PKEY_CTX *EVP_PKEY_CTX_new_from_name(OSSL_LIB_CTX *libctx,
                                         const char *name,
                                         const char *propquery);
EVP_PKEY_CTX *EVP_PKEY_CTX_new_from_pkey(OSSL_LIB_CTX *libctx,
                                         EVP_PKEY *pkey,
                                         const char *propquery);
EVP_PKEY_CTX *EVP_PKEY_CTX_dup(const EVP_PKEY_CTX *ctx);
void EVP_PKEY_CTX_free(EVP_PKEY_CTX *ctx);
int EVP_PKEY_CTX_is_a(EVP_PKEY_CTX *ctx, const char *keytype);

DESCRIPTION

La fonction EVP_PKEY_CTX_new() alloue un contexte d'algorithme de clé publique en utilisant le type de clé pkey et le ENGINE e.

La fonction EVP_PKEY_CTX_new_id() alloue un contexte d'algorithme de clé publique en utilisant le type de clé spécifié par id et le ENGINE e.

La fonction EVP_PKEY_CTX_new_from_name() alloue un contexte d'algorithme de clé publique en utilisant le contexte de bibliothèque libctx (voir OSSL_LIB_CTX(3)), le type de clé spécifié par name et la requête de propriété propquery. Aucun des arguments n'est dupliqué, ils doivent donc rester inchangés pendant la durée de vie du EVP_PKEY_CTX retourné ou de l'une de ses duplicatas. Lisez la suite à propos des noms possibles dans « NOTES » ci-dessous.

La fonction EVP_PKEY_CTX_new_from_pkey() alloue un contexte d'algorithme de clé publique en utilisant le contexte de bibliothèque libctx (voir OSSL_LIB_CTX(3)) et l'algorithme spécifié par pkey et la requête de propriété propquery. Aucun des arguments n'est dupliqué, ils doivent donc rester inchangés pendant la durée de vie du EVP_PKEY_CTX retourné ou de l'une de ses duplicatas.

EVP_PKEY_CTX_new_id() et EVP_PKEY_CTX_new_from_name() sont normalement utilisés lorsqu'aucune structure EVP_PKEY n'est associée aux opérations, par exemple lors de la génération de paramètres ou de la génération de clés pour certains algorithmes.

EVP_PKEY_CTX_dup() duplique le contexte ctx. Cela n'est pas pris en charge pour une opération de génération de clés. Il est cependant possible de dupliquer un contexte fraîchement créé via l'une des fonctions « new » ci-dessus, à condition que EVP_PKEY_keygen_init(3) n'ait pas encore été appelé sur le contexte source, puis d'utiliser la copie pour la génération de clés.

EVP_PKEY_CTX_free() libère le contexte ctx. Si ctx est NULL, rien n'est fait.

EVP_PKEY_is_a() vérifie si le type de clé associé à ctx est keytype.

NOTES

À propos de EVP_PKEY_CTX

La structure EVP_PKEY_CTX est un contexte d'algorithme de clé publique opaque utilisé par l'API de clé publique de haut niveau d'OpenSSL. Les contextes NE DOIVENT PAS être partagés entre threads : il n'est pas permis d'utiliser le même contexte simultanément dans deux threads.

À propos des types de clés

Nous mentionnons « type de clé » dans ce manuel, ce qui est la même chose que « algorithme » dans la plupart des cas, permettant d'utiliser les deux termes de manière interchangeable. Il existe des algorithmes où le type de clé et l' algorithme des opérations utilisant les clés ne sont pas les mêmes, comme les clés EC utilisées pour les opérations ECDSA et ECDH.

Les types de clés sont donnés de deux manières différentes :

NID hérité ou type EVP_PKEY
C'est le id utilisé avec EVP_PKEY_CTX_new_id().

Ce sont EVP_PKEY_RSA, EVP_PKEY_RSA_PSS, EVP_PKEY_DSA, EVP_PKEY_DH, EVP_PKEY_EC, EVP_PKEY_SM2, EVP_PKEY_X25519, EVP_PKEY_X448, et sont utilisés par les méthodes héritées.

Chaînes de noms
C'est le name utilisé avec EVP_PKEY_CTX_new_from_name().

Ce sont des noms comme « RSA », « DSA », et ce qui est disponible dépend des fournisseurs actuellement accessibles.

Les fournisseurs OpenSSL offrent un ensemble de types de clés disponibles de cette manière, veuillez consulter OSSL_PROVIDER-FIPS(7) et OSSL_PROVIDER-default(7) ainsi que la documentation associée pour plus d'informations.

VALEURS RETOURNÉES

EVP_PKEY_CTX_new(), EVP_PKEY_CTX_new_id() et EVP_PKEY_CTX_dup() retournent soit la structure EVP_PKEY_CTX nouvellement allouée, soit NULL si une erreur s'est produite.

EVP_PKEY_CTX_free() ne retourne pas de valeur.

EVP_PKEY_CTX_is_a() retourne 1 pour vrai et 0 pour faux.

VOIR AUSSI

HISTORIQUE

Les fonctions EVP_PKEY_CTX_new(), EVP_PKEY_CTX_new_id(), EVP_PKEY_CTX_dup() et EVP_PKEY_CTX_free() ont été ajoutées dans OpenSSL 1.0.0.

Les fonctions EVP_PKEY_CTX_new_from_name() et EVP_PKEY_CTX_new_from_pkey() ont été ajoutées dans OpenSSL 3.0.
