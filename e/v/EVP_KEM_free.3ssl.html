NOM

EVP_KEM_fetch, EVP_KEM_free, EVP_KEM_up_ref, EVP_KEM_get0_name, EVP_KEM_is_a, EVP_KEM_get0_provider, EVP_KEM_do_all_provided, EVP_KEM_names_do_all, EVP_KEM_get0_description, EVP_KEM_gettable_ctx_params, EVP_KEM_settable_ctx_params - Fonctions pour gérer les objets d'algorithme EVP_KEM

SYNTAXIS

#include <openssl/evp.h>
EVP_KEM *EVP_KEM_fetch(OSSL_LIB_CTX *ctx, const char *algorithm,
                       const char *properties);
void EVP_KEM_free(EVP_KEM *kem);
int EVP_KEM_up_ref(EVP_KEM *kem);
const char *EVP_KEM_get0_name(const EVP_KEM *kem);
int EVP_KEM_is_a(const EVP_KEM *kem, const char *name);
OSSL_PROVIDER *EVP_KEM_get0_provider(const EVP_KEM *kem);
void EVP_KEM_do_all_provided(OSSL_LIB_CTX *libctx,
                             void (*fn)(EVP_KEM *kem, void *arg), void *arg);
int EVP_KEM_names_do_all(const EVP_KEM *kem,
                         void (*fn)(const char *name, void *data), void *data);
const char *EVP_KEM_get0_description(const EVP_KEM *kem);
const OSSL_PARAM *EVP_KEM_gettable_ctx_params(const EVP_KEM *kem);
const OSSL_PARAM *EVP_KEM_settable_ctx_params(const EVP_KEM *kem);

DESCRIPTION

EVP_KEM_fetch() récupère l'implémentation pour l'algorithm donné à partir de n'importe quel fournisseur l'offrant, selon les critères donnés par les propriétés et dans le cadre du contexte de bibliothèque donné ctx (voir OSSL_LIB_CTX(3)). L'algorithme sera celui qui offre des fonctions pour effectuer des tâches asymétriques liées aux KEM, telles que l'encapsulation et la décapsulation de clés. Voir "ALGORITHM FETCHING" dans crypto(7) pour plus d'informations.

La valeur retournée doit éventuellement être libérée avec EVP_KEM_free().

EVP_KEM_free() décrémente le compteur de références pour la structure EVP_KEM. Typiquement, cette structure aura été obtenue par un appel précédent à EVP_KEM_fetch(). Si le compteur de références tombe à 0, la structure est libérée. Si l'argument est NULL, rien n'est fait.

EVP_KEM_up_ref() incrémente le compteur de références pour une structure EVP_KEM.

EVP_KEM_is_a() renvoie 1 si kem est une implémentation d'un algorithme identifiable par name, sinon 0.

EVP_KEM_get0_provider() renvoie le fournisseur à partir duquel kem a été récupéré.

EVP_KEM_do_all_provided() parcourt tous les EVP_KEM implémentés par tous les fournisseurs activés dans le contexte de bibliothèque donné libctx, et pour chacune des implémentations, appelle la fonction donnée fn avec la méthode d'implémentation et arg donné comme argument.

EVP_KEM_get0_name() renvoie le nom de l'algorithme à partir de l'implémentation fournie pour le kem donné. Notez que le kem peut avoir plusieurs synonymes associés. Dans ce cas, le premier nom de la définition de l'algorithme est retourné. La propriété de la chaîne retournée est conservée par l'objet kem et ne doit pas être libérée par l'appelant.

EVP_KEM_names_do_all() parcourt tous les noms pour kem, et appelle fn avec chaque nom et data.

EVP_KEM_get0_description() renvoie une description du kem, destinée à l'affichage et à la consommation humaine. La description est à la discrétion de l'implémentation du kem.

EVP_KEM_gettable_ctx_params() et EVP_KEM_settable_ctx_params() renvoient un tableau constant OSSL_PARAM(3) qui décrit les noms et types des paramètres de clé qui peuvent être récupérés ou définis par un algorithme d'encapsulation de clé à l'aide de EVP_PKEY_CTX_get_params(3) et EVP_PKEY_CTX_set_params(3).

VALEURS DE RETOUR

EVP_KEM_fetch() renvoie un pointeur vers un EVP_KEM en cas de succès, ou NULL en cas d'échec.

EVP_KEM_up_ref() renvoie 1 en cas de succès, ou 0 sinon.

EVP_KEM_names_do_all() renvoie 1 si la fonction de rappel a été appelée pour tous les noms. Une valeur de retour de 0 signifie que la fonction de rappel n'a été appelée pour aucun nom.

EVP_KEM_gettable_ctx_params() et EVP_KEM_settable_ctx_params() renvoient un tableau constant OSSL_PARAM(3) ou NULL en cas d'erreur.

VOIR AUSSI

"ALGORITHM FETCHING" dans crypto(7), OSSL_PROVIDER(3)

HISTORIQUE
