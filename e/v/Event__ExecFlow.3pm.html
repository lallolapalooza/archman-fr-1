NOM

Event::ExecFlow - API de haut niveau pour le contrôle de flux d'exécution basé sur les événements

NOTE

Cette version a très peu de documentation pour le moment. Si vous êtes intéressé par les détails, veuillez contacter l'auteur.

RÉSUMÉ

Event::ExecFlow fournit une API de haut niveau pour définir des contrôles de flux complexes avec exécution asynchrone de programmes externes.

SYNOPSIS

use Event::ExecFlow;
my $job = Event::ExecFlow::Job::Group->new (
  jobs => [
    Event::ExecFlow::Job::Command->new (
      name            => "transcode",
      title           => "Transcodage du titre DVD en OGG",
      command         => "transcode -i /dev/dvd ...",
      fetch_output    => 1,
      progress_max    => 4711, # nombre d'images
      progress_parser => sub {
        my ($job, $buffer) = @_;
        $job->set_progress_cnt($1) if $buffer =~ /\[\d+-(\d+)\]/;
        #-- ou simplement écrire ceci :
        #--   progress_parser => qr/\[\d+-(\d+)\]/,
      },
    ),
    Event::ExecFlow::Job::Code->new (
      name          => "checks",
      title         => "Effectuer quelques vérifications",
      depends_on    => [ "transcode" ],
      code          => sub {
        my ($job) = @_;
        my $transcode = $job->get_group->get_job_by_name("transcode");
        if ( $transcode->get_output !~ /.../ ) {
          $job->set_error_message("La vérification XY a échoué");
        }
        #-- cela pourrait être fait plus facilement comme un post_callback ajouté au
        #-- job "transcode" ci-dessus, mais c'est néanmoins un bon
        #-- exemple pour le type de job 'Code' et montre comment les jobs peuvent
        #-- interférer les uns avec les autres.
      },
    ),
    Event::ExecFlow::Job::Command->new (
      title         => "Multiplexage du fichier OGG",
      depends_on    => [ "checks" ],
      command       => "ogmmerge ...",
      no_progress   => 1,
    ),
  ],
);
#-- cela hérite de Event::ExecFlow::Frontend
my $frontend = Video::DVDRip::GUI::ExecFlow->new(...);
$frontend->start_job($job);

DESCRIPTION

Event::ExecFlow offre une API de haut niveau pour déclarer des tâches, qui exécutent principalement des commandes externes, analysent leur sortie pour obtenir des informations de progression ou d'autres statuts, déclenchent des actions lorsque la commande est terminée, etc. Ces tâches peuvent être chaînées de manière récursive pour accomplir des tâches plutôt complexes composées de nombreuses tâches.

De plus, il définit une API extensible pour la communication avec l'application frontend, qui peut être écrite en utilisant Gtk2, Tk ou Qt, ou être un simple programme console texte.

Dans le cas de Gtk2, un widget personnalisé pour afficher un plan de tâches Event::ExecFlow, y compris les mises à jour de progression, est fourni avec le package Gtk2::Ex::FormFactory.

EXIGENCES

Event::ExecFlow nécessite les modules Perl suivants :

AnyEvent           >= 0.04
Locale::TextDomain
Test::More

INSTALLATION

perl Makefile.PL
make test
make install
