EVP_PKEY-SM2(7ssl) OpenSSL EVP_PKEY-SM2(7ssl)

NOM

EVP_PKEY-SM2, EVP_KEYMGMT-SM2, SM2 - Prise en charge du type de clé EVP_PKEY pour les algorithmes de signature et de chiffrement SM2 chinois

DESCRIPTION

L'algorithme SM2 a été défini pour la première fois par la norme nationale chinoise GM/T 0003-2012 et a ensuite été normalisé par l'ISO sous la norme ISO/IEC 14888. SM2 est en fait un algorithme basé sur les courbes elliptiques. L'implémentation actuelle dans OpenSSL prend en charge les schémas de signature et de chiffrement via l'interface EVP.

Lors de l'utilisation de l'algorithme de signature SM2, il nécessite un identifiant distinctif pour former le préfixe du message qui est haché avant que le vrai message ne soit haché.

Paramètres SM2 communs

SM2 utilise les paramètres définis dans les "Paramètres EC communs" de EVP_PKEY-EC(7). Les paramètres suivants sont différents :

"cofactor" (OSSL_PKEY_PARAM_EC_COFACTOR) <entier non signé>
Ce paramètre est ignoré pour SM2.
(OSSL_PKEY_PARAM_DEFAULT_DIGEST) <chaîne UTF8>
Accesseur qui retourne le nom du digest par défaut. (Retourne actuellement "SM3" à partir d'OpenSSL 3.0).

NOTES

Les signatures SM2 peuvent être générées en utilisant la série d'API 'DigestSign', par exemple, EVP_DigestSignInit(), EVP_DigestSignUpdate() et EVP_DigestSignFinal(). Il en va de même pour le processus de vérification en appelant la série d'API 'DigestVerify'. Notez que l'algorithme SM2 nécessite la présence de la clé publique pour les signatures, de sorte que l'option OSSL_PKEY_PARAM_PUB_KEY doit être définie sur toute clé utilisée dans la génération de signature.

Avant de calculer une signature SM2, un EVP_PKEY_CTX doit être créé, et un ID SM2 doit lui être attribué, comme suit :

EVP_PKEY_CTX_set1_id(pctx, id, id_len);

Avant d'appeler les fonctions EVP_DigestSignInit() ou EVP_DigestVerifyInit(), ce EVP_PKEY_CTX doit être attribué au EVP_MD_CTX, comme suit :

EVP_MD_CTX_set_pkey_ctx(mctx, pctx);

Il n'est normalement pas nécessaire de passer un paramètre pctx à EVP_DigestSignInit() ou EVP_DigestVerifyInit() dans un tel scénario.

SM2 peut être testé avec l'application openssl-speed(1) depuis la version 3.0. Actuellement, le seul nom d'algorithme valide est sm2.

Depuis la version 3.0, les clés SM2 peuvent être générées et chargées uniquement lorsque les paramètres du domaine spécifient la courbe elliptique SM2.

EXEMPLES

Cet exemple démontre la séquence d'appel pour utiliser un EVP_PKEY pour vérifier un message avec l'algorithme de signature SM2 et l'algorithme de hachage SM3 :

#include <openssl/evp.h>
/* obtenir un EVP_PKEY par quelque méthode que ce soit... */
mctx = EVP_MD_CTX_new();
pctx = EVP_PKEY_CTX_new(pkey, NULL);
EVP_PKEY_CTX_set1_id(pctx, id, id_len);
EVP_MD_CTX_set_pkey_ctx(mctx, pctx);
EVP_DigestVerifyInit(mctx, NULL, EVP_sm3(), NULL, pkey);
EVP_DigestVerifyUpdate(mctx, msg, msg_len);
EVP_DigestVerifyFinal(mctx, sig, sig_len)
