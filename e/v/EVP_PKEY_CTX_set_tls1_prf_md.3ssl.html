EVP_PKEY_CTX_set_tls1_prf_md(3ssl)

Paquet: openssl

Licences: Apache-2.0

EVP_PKEY_CTX_SET_TLS1_PRF_MD(3ssl) OpenSSL EVP_PKEY_CTX_SET_TLS1_PRF_MD(3ssl)

NOM

EVP_PKEY_CTX_set_tls1_prf_md, EVP_PKEY_CTX_set1_tls1_prf_secret, EVP_PKEY_CTX_add1_tls1_prf_seed - Algorithme de dérivation de clé PRF TLS

SYNTAXE

#include <openssl/kdf.h>
int EVP_PKEY_CTX_set_tls1_prf_md(EVP_PKEY_CTX *pctx, const EVP_MD *md);
int EVP_PKEY_CTX_set1_tls1_prf_secret(EVP_PKEY_CTX *pctx,
                                      unsigned char *sec, int seclen);
int EVP_PKEY_CTX_add1_tls1_prf_seed(EVP_PKEY_CTX *pctx,
                                    unsigned char *seed, int seedlen);

DESCRIPTION

L'algorithme EVP_PKEY_TLS1_PRF implémente la fonction de dérivation de clé PRF pour TLS. Il n'a pas de clé privée associée et implémente uniquement la dérivation de clé en utilisant EVP_PKEY_derive(3).

EVP_PKEY_set_tls1_prf_md() définit le résumé de message associé au PRF TLS. EVP_md5_sha1() est traité comme un cas spécial qui utilise l'algorithme PRF utilisant à la fois MD5 et SHA1 comme utilisé dans TLS 1.0 et 1.1.

EVP_PKEY_CTX_set_tls1_prf_secret() définit la valeur secrète du PRF TLS à seclen octets du tampon sec. Toute valeur secrète existante est remplacée et toute graine est réinitialisée.

EVP_PKEY_CTX_add1_tls1_prf_seed() définit la graine à seedlen octets de seed. Si une graine est déjà définie, elle est ajoutée à la valeur existante.

COMMANDES STRING

Le PRF TLS prend également en charge les opérations de contrôle basées sur des chaînes en utilisant EVP_PKEY_CTX_ctrl_str(3). Le paramètre type "md" utilise la valeur fournie comme nom de l'algorithme de résumé à utiliser. Les paramètres type "secret" et "seed" utilisent le paramètre value fourni comme valeur secrète ou graine. Les noms "hexsecret" et "hexseed" sont similaires sauf qu'ils acceptent une chaîne hexadécimale qui est convertie en binaire.

NOTES

Un contexte pour le PRF TLS peut être obtenu en appelant :

EVP_PKEY_CTX *pctx = EVP_PKEY_CTX_new_id(EVP_PKEY_TLS1_PRF, NULL);

Le résumé, la valeur secrète et la graine doivent être définis avant qu'une clé ne soit dérivée, sinon une erreur se produira.

La longueur totale de toutes les graines ne peut pas dépasser 1024 octets : cela devrait être plus que suffisant pour toute utilisation normale du PRF TLS.

La longueur de sortie du PRF est spécifiée par le paramètre de longueur dans la fonction EVP_PKEY_derive(). Étant donné que la longueur de sortie est variable, définir le tampon sur NULL n'a pas de sens pour le PRF TLS.

Des versions optimisées du PRF TLS peuvent être implémentées dans un ENGINE.

VALEURS DE RETOUR

Toutes ces fonctions retournent 1 en cas de succès et 0 ou une valeur négative en cas d'échec. En particulier, une valeur de retour de -2 indique que l'opération n'est pas prise en charge par l'algorithme de clé publique.

EXEMPLES

Cet exemple dérive 10 octets en utilisant SHA-256 avec la clé secrète "secret" et la valeur de graine "seed" :

EVP_PKEY_CTX *pctx;
unsigned char out[10];
size_t outlen = sizeof(out);
pctx = EVP_PKEY_CTX_new_id(EVP_PKEY_TLS1_PRF, NULL);
if (EVP_PKEY_derive_init(pctx) <= 0)
    /* Erreur */
if (EVP_PKEY_CTX_set_tls1_prf_md(pctx, EVP_sha256()) <= 0)
    /* Erreur */
if (EVP_PKEY_CTX_set1_tls1_prf_secret(pctx, "secret", 6) <= 0)
    /* Erreur */
if (EVP_PKEY_CTX_add1_tls1_prf_seed(pctx, "seed", 4) <= 0)
    /* Erreur */
if (EVP_PKEY_derive(pctx, out, &outlen) <= 0)
    /* Erreur */
