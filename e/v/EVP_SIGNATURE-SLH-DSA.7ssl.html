EVP_SIGNATURE-SLH-DSA(7ssl) OpenSSL EVP_SIGNATURE-SLH-DSA(7ssl)

NOM

EVP_SIGNATURE-SLH-DSA, EVP_SIGNATURE-SLH-DSA-SHA2-128s, EVP_SIGNATURE-SLH-DSA-SHA2-128f, EVP_SIGNATURE-SLH-DSA-SHA2-192s, EVP_SIGNATURE-SLH-DSA-SHA2-192f, EVP_SIGNATURE-SLH-DSA-SHA2-256s, EVP_SIGNATURE-SLH-DSA-SHA2-256f, EVP_SIGNATURE-SLH-DSA-SHAKE-128s, EVP_SIGNATURE-SLH-DSA-SHAKE-128f, EVP_SIGNATURE-SLH-DSA-SHAKE-192s, EVP_SIGNATURE-SLH-DSA-SHAKE-192f, EVP_SIGNATURE-SLH-DSA-SHAKE-256s, EVP_SIGNATURE-SLH-DSA-SHAKE-256f - Support EVP_PKEY SLH-DSA

DESCRIPTION

Les implémentations EVP_PKEY SLH-DSA-SHA2-128s, EVP_PKEY-SLH-DSA-SHA2-128f, SLH-DSA-SHA2-192s, EVP_PKEY-SLH-DSA-SHA2-192f, SLH-DSA-SHA2-256s, EVP_PKEY-SLH-DSA-SHA2-256f, SLH-DSA-SHAKE-128s, EVP_PKEY-SLH-DSA-SHAKE-128f, SLH-DSA-SHAKE-192s, EVP_PKEY-SLH-DSA-SHAKE-192f, SLH-DSA-SHAKE-256s et EVP_PKEY-SLH-DSA-SHAKE-256f supportent la génération de clés, la signature et la vérification en une seule opération en utilisant les schémas de signature SLH-DSA décrits dans FIPS 205.

Les différents noms d'algorithmes correspondent aux jeux de paramètres définis dans la Section 11, Tableau 2 de FIPS 205. Les types "s" ont des tailles de signature plus petites, et les variantes "f" sont plus rapides (les signatures vont d'environ 8 Ko à 50 Ko selon le type choisi). Il existe 3 catégories de sécurité différentes, dépendant également du type.

EVP_SIGNATURE_fetch(3) peut être utilisé pour récupérer explicitement l'un des 12 algorithmes qui peuvent ensuite être utilisés avec EVP_PKEY_sign_message_init(3), EVP_PKEY_sign(3), EVP_PKEY_verify_message_init(3), et EVP_PKEY_verify(3) pour effectuer des opérations de signature ou de vérification de message en une seule opération.

Le processus de signature normal (appelé Génération de Signature Pure SLH-DSA) encode le message en interne comme 0x00 || len(ctx) || ctx || message. où ctx est une valeur optionnelle de taille 0x00..0xFF. OpenSSL permet également au message de ne pas être encodé, ce qui est requis pour les tests. OpenSSL ne supporte pas la Génération de Signature SLH-DSA Pré-Hachée, mais cela peut être fait par l'utilisateur en effectuant un encodage pré-haché externe puis en choisissant l'option de ne pas encoder le message.

Paramètres de signature SLH-DSA

Le paramètre "context-string", décrit ci-dessous, peut être utilisé pour la signature et la vérification. Il peut être défini en passant un tableau OSSL_PARAM à EVP_PKEY_sign_init_ex2(3) ou EVP_PKEY_verify_init_ex2(3).

"context-string" (OSSL_SIGNATURE_PARAM_CONTEXT_STRING) <chaîne d'octets>
Une chaîne d'octets d'une longueur maximale de 255. Par défaut, c'est une chaîne vide.

Les paramètres suivants peuvent être utilisés lors de la signature : ils peuvent être définis en passant un tableau OSSL_PARAM à EVP_PKEY_sign_init_ex2(3).

"message-encoding" (OSSL_SIGNATURE_PARAM_MESSAGE_ENCODING) <entier>
La valeur par défaut de 1 utilise la 'Génération de Signature Pure SLH-DSA' telle que décrite ci-dessus. La régler à 0 n'encode pas le message, ce qui est utilisé pour les tests, mais peut également être utilisé pour la 'Génération de Signature SLH-DSA Pré-Hachée'.
"test-entropy" (OSSL_SIGNATURE_PARAM_TEST_ENTROPY <chaîne d'octets>
Utilisé pour les tests afin de passer une valeur aléatoire optionnelle.
"deterministic" (OSSL_SIGNATURE_PARAM_DETERMINISTIC) <entier>
La valeur par défaut de 0 génère une valeur aléatoire (en utilisant un DRBG) qui est utilisée lors du traitement du message. La définir à 1 utilise à la place la graine de la clé privée. Cette valeur est ignorée si "test-entropy" est défini.

Voir EVP_PKEY-SLH-DSA(7) pour des informations relatives aux clés SLH-DSA.

NOTES

Pour des raisons de compatibilité ascendante, EVP_DigestSignInit_ex(3), EVP_DigestSign(3), EVP_DigestVerifyInit_ex(3) et EVP_DigestVerify(3) peuvent également être utilisés, mais le digest passé dans mdname doit être NULL.

EXEMPLES

Pour signer un message en utilisant une structure EVP_PKEY SLH-DSA :

void do_sign(EVP_PKEY *key, unsigned char *msg, size_t msg_len)
{
    size_t sig_len;
    unsigned char *sig = NULL;
    const OSSL_PARAM params[] = {
        OSSL_PARAM_octet_string("context-string", (unsigned char *)"A context string", 33),
        OSSL_PARAM_END
    };
    EVP_PKEY_CTX *sctx = EVP_PKEY_CTX_new_from_pkey(NULL, pkey, NULL);
    EVP_SIGNATURE *sig_alg = EVP_SIGNATURE_fetch(NULL, "SLH-DSA-SHA2-128s", NULL);
    EVP_PKEY_sign_message_init(sctx, sig_alg, params);
    /* Calculer la taille requise pour la signature en passant un tampon NULL. */
    EVP_PKEY_sign(sctx, NULL, &sig_len, msg, msg_len);
    sig = OPENSSL_zalloc(sig_len);
    EVP_PKEY_sign(sctx, sig, &sig_len, msg, msg_len);
    ...
    OPENSSL_free(sig);
    EVP_SIGNATURE_free(sig_alg);
    EVP_PKEY_CTX_free(sctx);
}
