Le type de clé EC est implémenté dans le fournisseur par défaut

d'OpenSSL.

Paramètres EC

courants

La manière normale de spécifier les paramètres de domaine pour une courbe EC est via le nom de courbe « group ». Pour les courbes sans nom de courbe, des paramètres explicites peuvent être utilisés qui spécifient « field-type », « p », « a », « b », « generator » et « order ». Les paramètres explicites sont pris en charge pour des raisons de rétrocompatibilité, mais ils ne sont pas conformes à plusieurs normes (y compris RFC5915) qui n'autorisent que les courbes

nommées.

Les types suivants de génération de clé / récupération / import / export sont disponibles pour l'algorithme EC intégré

:
« group » (OSSL_PKEY_PARAM_GROUP_NAME) <chaîne
UTF8>
Le nom de la
courbe.
« field-type » (OSSL_PKEY_PARAM_EC_FIELD_TYPE) <chaîne
UTF8>
La valeur doit être soit « prime-field » soit « characteristic-two-field », qui correspondent au corps premier Fp et au corps binaire
F2^m.
« p » (OSSL_PKEY_PARAM_EC_P) <entier non
signé>
Pour une courbe sur Fp p est le nombre premier du corps. Pour une courbe sur F2^m p représente le polynôme irréductible - chaque bit représente un terme du polynôme. Par conséquent, il y aura soit trois soit cinq bits à 1 selon que le polynôme est un trinôme ou un
pentanôme.
« a » (OSSL_PKEY_PARAM_EC_A) <entier non
signé>
« b » (OSSL_PKEY_PARAM_EC_B) <entier non
signé>
« seed » (OSSL_PKEY_PARAM_EC_SEED) <chaîne
d'octets>
a et b représentent les coefficients de la courbe. Pour Fp : y^2 mod p = x^3 + ax + b mod p OU Pour F2^m : y^2 + xy = x^3 + ax^2 + b

seed est une valeur optionnelle qui est à des fins d'information uniquement. Elle représente la graine du nombre aléatoire utilisée pour générer le coefficient b à partir d'un

nombre al
éatoire.
« generator » (OSSL_PKEY_PARAM_EC_GENERATOR) <chaîne
d'octets>
« order » (OSSL_PKEY_PARAM_EC_ORDER) <entier non
signé>
« cofactor » (OSSL_PKEY_PARAM_EC_COFACTOR) <entier non
signé>
Le générateur est un point bien défini sur la courbe choisi pour les opérations cryptographiques. L'encodage est conforme à la Sec. 2.3.3 de la norme SECG SEC 1 (« Elliptic Curve Cryptography »). Voir EC_POINT_oct2point(). Les entiers utilisés pour les multiplications de points seront entre 0 et order - 1. cofactor est une valeur optionnelle. order multiplié par le cofactor donne le nombre de points sur la
courbe.
« decoded-from-explicit » (OSSL_PKEY_PARAM_EC_DECODED_FROM_EXPLICIT_PARAMS)
<entier>
Obtient un indicateur indiquant si la clé ou les paramètres ont été décodés à partir de paramètres de courbe explicites. Défini à 1 si c'est le cas ou 0 si une courbe nommée a été
utilisée.
« use-cofactor-flag » (OSSL_PKEY_PARAM_USE_COFACTOR_ECDH)
<entier>
Active Cofactor DH (ECC CDH) si cette valeur est 1, sinon il utilise le DH EC normal si la valeur est zéro. La variante cofactor multiplie le secret partagé par le cofactor de la courbe EC (notez que pour certaines courbes le cofactor est 1).

Voir aussi EVP_KEYEXCH-ECDH(7) pour le paramètre OSSL_EXCHANGE_PARAM_EC_ECDH_COFACTOR_MODE

associé qui peut être
défini par opération.
« encoding » (OSSL_PKEY_PARAM_EC_ENCODING) <chaîne
UTF8>
Définit le format utilisé pour la sérialisation des paramètres du groupe EC. Les valeurs valides sont « explicit » ou « named_curve ». La valeur par défaut est « named_curve
».
« point-format » (OSSL_PKEY_PARAM_EC_POINT_CONVERSION_FORMAT) <chaîne
UTF8>
Définit ou récupère le point_conversion_form pour la clé. Pour une description des point_conversion_forms, veuillez consulter EC_POINT_new(3). Les valeurs valides sont « uncompressed » ou « compressed ». La valeur par défaut est « uncompressed
».
« group-check » (OSSL_PKEY_PARAM_EC_GROUP_CHECK_TYPE) <chaîne
UTF8>
Définit ou récupère le type de vérification du groupe effectué lorsque EVP_PKEY_param_check() est appelé. Les valeurs valides sont « default », « named » et « named-nist ». Le type « named » vérifie que les paramètres de domaine correspondent aux paramètres de courbe intégrés, « named-nist » est similaire mais vérifie aussi que la courbe nommée est une courbe nist. Le type « default » effectue la validation des paramètres de domaine pour le fournisseur par défaut d'OpenSSL, mais est équivalent à « named-nist » pour le fournisseur FIPS
d'OpenSSL.
« include-public » (OSSL_PKEY_PARAM_EC_INCLUDE_PUBLIC)
<entier>
Définir cette valeur à 0 indique que la clé publique ne doit pas être incluse lors de l'encodage de la clé privée. La valeur par défaut de 1 inclura la clé
publique.
« pub » (OSSL_PKEY_PARAM_PUB_KEY) <chaîne
d'octets>
La valeur de la clé publique au format de point EC encodé conforme à la Sec. 2.3.3 et 2.3.4 de la norme SECG SEC 1 (« Elliptic Curve Cryptography »). Ce paramètre est utilisé lors de l'importation ou de l'exportation de la valeur de la clé publique avec les fonctions EVP_PKEY_fromdata() et EVP_PKEY_todata().

Notez en particulier que le choix du format de compression de point utilisé pour encoder la valeur exportée via EVP_PKEY_todata() dépend de l'implémentation du fournisseur sous-jacent. Avant OpenSSL 3.0.8, l'implémentation des fournisseurs inclus avec OpenSSL choisissait toujours un encodage au format compressé, inconditionnellement. Depuis OpenSSL 3.0.8, l'implémentation a été modifiée pour respecter le paramètre OSSL_PKEY_PARAM_EC_POINT_CONVERSION_FORMAT, s'il est déf

ini, ou pour utiliser par déf
aut le format non compressé.
« priv » (OSSL_PKEY_PARAM_PRIV_KEY) <entier non
signé>
La valeur de la clé
privée.
« encoded-pub-key » (OSSL_PKEY_PARAM_ENCODED_PUBLIC_KEY) <chaîne
d'octets>
Utilisé pour récupérer et définir l'encodage d'une clé publique EC. La clé publique doit être un point conforme à la Sec. 2.3.4 de la norme SECG SEC 1 (« Elliptic Curve Cryptography
»).
« qx » (OSSL_PKEY_PARAM_EC_PUB_X) <entier non
signé>
Utilisé pour récupérer la composante X de la clé publique
EC.
« qy » (OSSL_PKEY_PARAM_EC_PUB_Y) <entier non
signé>
Utilisé pour récupérer la composante Y de la clé publique
EC.
« default-digest » (OSSL_PKEY_PARAM_DEFAULT_DIGEST) <chaîne
UTF8>
Accesseur qui retourne le nom du hachage par défaut. (Actuellement retourne « SHA256 » depuis OpenSSL 3.
0).
« dhkem-ikm » (OSSL_PKEY_PARAM_DHKEM_IKM) <chaîne
d'octets>
DHKEM nécessite la génération d'une paire de clés à l'aide d'un matériel de clé d'entrée (graine). Utilisez ceci pour spécifier le matériel de clé utilis
é pour la génération de la clé privée. Cette valeur ne doit pas être réutilisée à d'autres fins. Elle ne peut être utilisée que pour les courbes « P-256
», « P-384 » et « P-521 » et doit avoir une longueur d'au moins la taille de la clé privée encodée (c'est-à-dire 32, 48 et 66 pour les courbes listées).

Les types suivants de récupération sont également disponibles pour l'algorithme EC intégré

« basis-type » (OSSL_PKEY_PARAM_EC_CHAR2_TYPE) <chaîne
UTF8>
Prend en charge les valeurs « tpBasis » pour un trinôme ou « ppBasis » pour un pentanôme. Ce champ n'est utilisé que pour un corps binaire
F2^m.
« m » (OSSL_PKEY_PARAM_EC_CHAR2_M)
<entier>
« tp » (OSSL_PKEY_PARAM_EC_CHAR2_TP_BASIS)
<entier>
« k1 » (OSSL_PKEY_PARAM_EC_CHAR2_PP_K1)
<entier>
« k2 » (OSSL_PKEY_PARAM_EC_CHAR2_PP_K2)
<entier>
« k3 » (OSSL_PKEY_PARAM_EC_CHAR2_PP_K3)
<entier>
Ces champs ne sont utilisés que pour un corps binaire F2^m. m est le degré du corps binaire.

tp est le bit central d'un trinôme, donc sa valeur doit être dans la plage m > tp

> 0.

k1, k2 et k3 sont utilisés pour obtenir les bits centraux d'un pentanôme tel que m > k3 > k2 >

k1 >
0

Validation des clés

EC

Pour les clés EC, EVP_PKEY_param_check(3) se comporte de la manière suivante : Pour le fournisseur par défaut d'OpenSSL, il utilise soit EC_GROUP_check(3) soit EC_GROUP_check_named_curve(3) selon le drapeau EC_FLAG_CHECK_NAMED_GROUP. Le fournisseur FIPS d'OpenSSL utilise EC_GROUP_check_named_curve(3) afin de se conformer à SP800-56Ar3 Assurances of Domain-Parame

ter Validity.

Pour les clés EC, EVP_PKEY_param_check_quick(3) est équivalent à EVP_PKEY_param_c

heck(3).

Pour les clés EC, EVP_PKEY_public_check(3) et EVP_PKEY_public_check_quick(3) se conforment à SP800-56Ar3 ECC Full Public-Key Validation et ECC Partial Public-Key Validation

respectivement.

Pour les clés EC, EVP_PKEY_private_check(3) et EVP_PKEY_pairwise_check(3) se conforment à SP800-56Ar3 Private key validity et Owner Assurance of Pair-

wise Consist
ency res
pectivement.

EXEMPLE

S

Un contexte EVP_PKEY peut être obtenu en appelant

: 
EVP_PKEY_CTX *pctx =
    EVP_PKEY_CTX_new_from_name(NULL, "EC", NULL)
;

Une clé EVP_PKEY ECDSA ou ECDH peut être générée avec un groupe nommé "P-256" en appelant

: 
pkey = EVP_EC_gen("P-256")
;

ou comme ceci

: 
EVP_PKEY *key = NULL;
OSSL_PARAM params[2];
EVP_PKEY_CTX *gctx =
    EVP_PKEY_CTX_new_from_name(NULL, "EC", NULL);
EVP_PKEY_keygen_init(gctx);
params[0] = OSSL_PARAM_construct_utf8_string(OSSL_PKEY_PARAM_GROUP_NAME,
                                             "P-256", 0);
params[1] = OSSL_PARAM_construct_end();
EVP_PKEY_CTX_set_params(gctx, params);
EVP_PKEY_generate(gctx, &key);
EVP_PKEY_print_private(bio_out, key, 0, NULL);
...
EVP_PKEY_free(key);
EVP_PKEY_CTX_free(gctx)
;

Une clé EVP_PKEY EC CDH (Diffie-Hellman avec cofacteur) peut être générée avec un groupe nommé "K-571" en appelant

: 
int use_cdh = 1;
EVP_PKEY *key = NULL;
OSSL_PARAM params[3];
EVP_PKEY_CTX *gctx =
    EVP_PKEY_CTX_new_from_name(NULL, "EC", NULL);
EVP_PKEY_keygen_init(gctx);
params[0] = OSSL_PARAM_construct_utf8_string(OSSL_PKEY_PARAM_GROUP_NAME,
"K-571", 0); /* * Cette courbe a un cofacteur qui n'est pas 1 - donc le réglage du mode CDH * change le comportement. Pour beaucoup de courbes, le cofacteur est 1 - donc * régler cela n'a aucun effet. */ params[1] = OSSL_PARAM_construct_int(OSSL_PKEY_PARAM_US
E_COFACTOR_ECDH, &use_cdh); params[2] = OSSL_PARAM_construct_end(); EVP_PKEY_CTX_set_params(gctx, params); EVP_PKEY_generate(gctx, &key); EVP_PKEY_print_private(bio_out, key, 0, NULL); ... EVP_PKEY_free(key); EVP_PKEY_CTX_free(gctx);
