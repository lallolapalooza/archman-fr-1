EVP_PKEY_decapsulate(3ssl)

Paquet: openssl

Licences: Apache-2.0

EVP_PKEY_DECAPSULATE(3ssl) OpenSSL EVP_PKEY_DECAPSULATE(3ssl)

NOM

EVP_PKEY_decapsulate_init, EVP_PKEY_auth_decapsulate_init, EVP_PKEY_decapsulate - Décapsulation de clé à l'aide d'un algorithme KEM avec une clé privée

SYNOPSIS

#include <openssl/evp.h>
int EVP_PKEY_decapsulate_init(EVP_PKEY_CTX *ctx, const OSSL_PARAM params[]);
int EVP_PKEY_auth_decapsulate_init(EVP_PKEY_CTX *ctx, EVP_PKEY *authpub,
                                  const OSSL_PARAM params[]);
int EVP_PKEY_decapsulate(EVP_PKEY_CTX *ctx,
                         unsigned char *unwrapped, size_t *unwrappedlen,
                         const unsigned char *wrapped, size_t wrappedlen);

DESCRIPTION

La fonction EVP_PKEY_decapsulate_init() initialise un contexte de clé privée pour une opération de décapsulation et applique ensuite les params au contexte de la même manière que l'appel à EVP_PKEY_CTX_set_params(3). Notez que ctx est généralement obtenu en utilisant EVP_PKEY_CTX_new_from_pkey(3), en spécifiant la clé privée à utiliser.

La fonction EVP_PKEY_auth_decapsulate_init() est similaire à EVP_PKEY_decapsulate_init() mais transmet également une clé publique d'authentification authpub utilisée lors de la décapsulation.

La fonction EVP_PKEY_decapsulate() effectue une opération de décapsulation de clé privée à l'aide de ctx. Les données à décapsuler sont spécifiées à l'aide des paramètres wrapped et wrappedlen (qui doivent tous deux être non NULL).

Le paramètre wrapped est un argument de sortie, vers lequel le secret partagé décapsulé est écrit. Le secret partagé peut ne pas correspondre à la valeur de l'homologue même lorsque la décapsulation renvoie succès. Au lieu de cela, le secret partagé doit être utilisé pour dériver une clé qui est utilisée pour authentifier les données reçues ultérieurement de l'homologue. Si unwrapped est NULL, la taille du tampon du secret partagé de sortie est écrite dans *unwrappedlen et aucune décapsulation n'est effectuée. Cela permet de déterminer la taille du tampon requise à l'exécution.

Notez que la valeur pointée par unwrappedlen (qui ne doit PAS être **NULL**) doit être initialisée à la longueur de unwrapped, de sorte que l'appel puisse valider qu'elle est de taille suffisante pour contenir le résultat de l'opération.

En l'absence de connaissance interne détaillée de l'algorithme KEM spécifique, les appelants NE DEVRAIENT PAS supposer que le secret partagé renvoyé est nécessairement de longueur maximale possible. La longueur renvoyée via *unwrappedlen DEVRAIT être utilisée pour déterminer la longueur réelle de la sortie.

NOTES

Après l'appel à EVP_PKEY_decapsulate_init(), les paramètres spécifiques à l'algorithme pour l'opération peuvent être définis ou modifiés en utilisant EVP_PKEY_CTX_set_params(3).

VALEURS DE RETOUR

EVP_PKEY_decapsulate_init(), EVP_PKEY_auth_decapsulate_init() et EVP_PKEY_decapsulate() renvoient 1 en cas de succès et 0 ou une valeur négative en cas d'échec. En particulier, une valeur de retour de -2 indique que l'opération n'est pas prise en charge par l'algorithme de clé privée.

EXEMPLES

Décapsuler des données en utilisant RSA :

#include <openssl/evp.h>
/*
 * NB : suppose que rsa_priv_key est une clé privée RSA,
 * et que in, inlen sont déjà configurés pour contenir les données encapsulées.
 */
EVP_PKEY_CTX *ctx = NULL;
size_t secretlen = 0;
unsigned char *secret = NULL;;
ctx = EVP_PKEY_CTX_new_from_pkey(libctx, rsa_priv_key, NULL);
if (ctx == NULL)
    /* Erreur */
if (EVP_PKEY_decapsulate_init(ctx, NULL) <= 0)
    /* Erreur */
/* Définir le mode - seul 'RSASVE' est actuellement supporté */
if (EVP_PKEY_CTX_set_kem_op(ctx, "RSASVE") <= 0)
    /* Erreur */
/* Déterminer la longueur du tampon */
if (EVP_PKEY_decapsulate(ctx, NULL, &secretlen, in, inlen) <= 0)
    /* Erreur */
secret = OPENSSL_malloc(secretlen);
if (secret == NULL)
    /* Échec de malloc */
/* Les données secrètes décapsulées ont une longueur de secretlen octets */
if (EVP_PKEY_decapsulate(ctx, secret, &secretlen, in, inlen) <= 0)
    /* Erreur */

VOIR AUSSI

EVP_PKEY_CTX_new_from_pkey(3), EVP_PKEY_encapsulate(3), EVP_KEM-RSA(7), EVP_KEM-X25519(7), EVP_KEM-EC(7), EVP_KEM-ML-KEM-512(7), EVP_KEM-ML-KEM-768(7), EVP_KEM-ML-KEM-1024(7)

HISTORIQUE

Les fonctions EVP_PKEY_decapsulate_init() et EVP_PKEY_decapsulate() ont été ajoutées dans OpenSSL 3.0.

La fonction EVP_PKEY_auth_decapsulate_init() a été ajoutée dans OpenSSL 3.2.

Le support pour ML-KEM a été ajouté dans OpenSSL 3.5.
