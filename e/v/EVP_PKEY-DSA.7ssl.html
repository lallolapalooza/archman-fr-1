NOM

EVP_PKEY-DSA, EVP_KEY MGMT-DSA - Type de clé EVP_PKEY DSA et prise en charge de l'algorithme

DESCRIPTION

Pour DSA, la norme FIPS 186-4 spécifie que les valeurs utilisées pour la génération des paramètres FFC sont également requises pour la validation des paramètres. Cela signifie que les valeurs optionnelles des paramètres de domaine FFC pour le seed, le pcounter et le gindex peuvent devoir être stockées à des fins de validation. Pour DSA, ces champs ne sont pas stockés dans les données ASN1, ils doivent donc être stockés extérieurement si la validation est requise.

Dans le cadre de FIPS 140-3, DSA n'est plus approuvé par FIPS pour la génération de clés et la validation de signatures, mais est toujours autorisé pour la vérification de signatures.

Paramètres DSA

Le type de clé DSA prend en charge les paramètres FFC (voir "Paramètres FFC" dans EVP_PKEY-FFC(7)).

Il prend également en charge les paramètres suivants :

"sign-check" (OSSL_PKEY_PARAM_FIPS_SIGN_CHECK) <entier>
"fips-indicator" (OSSL_PKEY_PARAM_FIPS_APPROVED_INDICATOR) <entier>
Voir "Paramètres d'informations communs" dans provider-keymgmt(7) pour plus d'informations.

Paramètres de génération de clés DSA

Le type de clé DSA prend en charge les paramètres de génération de clés FFC (voir "Paramètres de génération de clés FFC" dans EVP_PKEY-FFC(7)

Les restrictions suivantes s'appliquent au champ "pbits" :

Pour "fips186_4", cela doit être 2048 ou 3072. Pour "fips186_2", cela doit être 1024. Pour "group", cela peut être 2048, 3072, 4096, 6144 ou 8192.

Validation de clés DSA

Pour les clés DSA, EVP_PKEY_param_check(3) se comporte comme suit : Le fournisseur FIPS d'OpenSSL est conforme aux règles de la norme FIPS186-4 pour la validation des paramètres FFC. Par souci de compatibilité ascendante, le fournisseur par défaut d'OpenSSL utilise une vérification beaucoup plus simple (voir ci-dessous) pour la validation des paramètres, à moins que le paramètre seed ne soit défini.

Pour les clés DSA, EVP_PKEY_param_check_quick(3) se comporte comme suit : Une vérification simple de L et N et de g partiel est effectuée. Le fournisseur par défaut prend également en charge la validation des clés héritées "fips186_2".

Pour les clés DSA, EVP_PKEY_public_check(3), EVP_PKEY_private_check(3) et EVP_PKEY_pairwise_check(3), les fournisseurs par défaut et FIPS d'OpenSSL sont conformes aux règles de SP800-56Ar3 pour les tests publics, privés et par paires respectivement.

EXEMPLES

Un contexte EVP_PKEY peut être obtenu en appelant :

EVP_PKEY_CTX *pctx = EVP_PKEY_CTX_new_from_name(NULL, "DSA", NULL);

Les paramètres de domaine DSA peuvent être générés en appelant :

unsigned int pbits = 2048;
unsigned int qbits = 256;
int gindex = 1;
OSSL_PARAM params[5];
EVP_PKEY *param_key = NULL;
EVP_PKEY_CTX *pctx = NULL;
pctx = EVP_PKEY_CTX_new_from_name(NULL, "DSA", NULL);
EVP_PKEY_paramgen_init(pctx);
params[0] = OSSL_PARAM_construct_uint("pbits", &pbits);
params[1] = OSSL_PARAM_construct_uint("qbits", &qbits);
params[2] = OSSL_PARAM_construct_int("gindex", &gindex);
params[3] = OSSL_PARAM_construct_utf8_string("digest", "SHA384", 0);
params[4] = OSSL_PARAM_construct_end();
EVP_PKEY_CTX_set_params(pctx, params);
EVP_PKEY_generate(pctx, &param_key);
EVP_PKEY_CTX_free(pctx);
EVP_PKEY_print_params(bio_out, param_key, 0, NULL);

Une clé DSA peut être générée en utilisant les paramètres de domaine en appelant :

EVP_PKEY *key = NULL;
EVP_PKEY_CTX *gctx = NULL;
gctx = EVP_PKEY_CTX_new_from_pkey(NULL, param_key, NULL);
EVP_PKEY_keygen_init(gctx);
EVP_PKEY_generate(gctx, &key);
EVP_PKEY_CTX_free(gctx);
EVP_PKEY_print_private(bio_out, key, 0, NULL);

CONFORME À

Les sections suivantes de FIPS186-4 :

A.1.1.2 Génération de nombres premiers probables p et q à l'aide d'une fonction de hachage approuvée.
A.2.3 Génération du générateur canonique g.
A.2.1 Génération non vérifiable du générateur g.

HISTORIQUE
