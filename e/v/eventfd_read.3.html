eventfd(2) Manuel des appels système eventfd(2)

NOM

eventfd - créer un descripteur de fichier pour la notification d'événements

BIBLIOTHÈQUE

Bibliothèque C standard (libc, -lc)

SYNTAXE

#include <sys/eventfd.h>
int eventfd(unsigned int initval, int flags);

DESCRIPTION

eventfd() crée un « objet eventfd » qui peut être utilisé comme mécanisme d'attente/notification d'événements par les applications en espace utilisateur, et par le noyau pour notifier les applications en espace utilisateur d'événements. L'objet contient un compteur entier non signé de 64 bits (uint64_t) maintenu par le noyau. Ce compteur est initialisé avec la valeur spécifiée dans l'argument initval.

En valeur de retour, eventfd() renvoie un nouveau descripteur de fichier qui peut être utilisé pour faire référence à l'objet eventfd.

Les valeurs suivantes peuvent être combinées par un OU bit à bit dans flags pour modifier le comportement de eventfd :

EFD_CLOEXEC (depuis Linux 2.6.27)
Définit le drapeau close-on-exec (FD_CLOEXEC) sur le nouveau descripteur de fichier. Voir la description du drapeau O_CLOEXEC dans open(2) pour les raisons pour lesquelles cela peut être utile.
EFD_NONBLOCK (depuis Linux 2.6.27)
Définit le drapeau d'état de fichier O_NONBLOCK sur la description de fichier ouverte (voir open(2)) référencée par le nouveau descripteur de fichier. L'utilisation de ce drapeau évite des appels supplémentaires à fcntl(2) pour obtenir le même résultat.
EFD_SEMAPHORE (depuis Linux 2.6.30)
Fournit des sémantiques de type sémaphore pour les lectures à partir du nouveau descripteur de fichier. Voir ci-dessous.

Jusqu'à Linux 2.6.26, l'argument flags est inutilisé et doit être spécifié comme zéro.

Les opérations suivantes peuvent être effectuées sur le descripteur de fichier renvoyé par eventfd :

read(2)
Chaque appel réussi à read(2) renvoie un entier de 8 octets. Un appel à read(2) échoue avec l'erreur EINVAL si la taille du tampon fourni est inférieure à 8 octets.
La valeur renvoyée par read(2) est dans l'ordre des octets natif (host byte order) — c'est-à-dire, l'ordre natif des octets pour les entiers sur la machine hôte.
Les sémantiques de read(2) dépendent de si le compteur eventfd a actuellement une valeur non nulle et si le drapeau EFD_SEMAPHORE a été spécifié lors de la création du descripteur de fichier eventfd :
•
Si EFD_SEMAPHORE n'a pas été spécifié et que le compteur eventfd a une valeur non nulle, alors un appel à read(2) renvoie 8 octets contenant cette valeur, et la valeur du compteur est remise à zéro.
•
Si EFD_SEMAPHORE a été spécifié et que le compteur eventfd a une valeur non nulle, alors un appel à read(2) renvoie 8 octets contenant la valeur 1, et la valeur du compteur est décrémentée de 1.
•
Si le compteur eventfd est nul au moment de l'appel à read(2), alors l'appel soit bloque jusqu'à ce que le compteur devienne non nul (à ce moment-là, read(2) se déroule comme décrit ci-dessus) soit échoue avec l'erreur EAGAIN si le descripteur de fichier a été rendu non bloquant.
write(2)
Un appel à write(2) ajoute la valeur entière de 8 octets fournie dans son tampon au compteur. La valeur maximale qui peut être stockée dans le compteur est la plus grande valeur entière non signée de 64 bits moins 1 (c'est-à-dire, 0xfffffffffffffffe). Si l'addition faisait dépasser la valeur du compteur au maximum, alors write(2) soit bloque jusqu'à ce qu'un read(2) soit effectué sur le descripteur de fichier, soit échoue avec l'erreur EAGAIN si le descripteur de fichier a été rendu non bloquant.
Un appel à write(2) échoue avec l'erreur EINVAL si la taille du tampon fourni est inférieure à 8 octets, ou si une tentative est faite pour écrire la valeur 0xffffffffffffffff.
poll(2)
select(2)
(et similaires)
Le descripteur de fichier renvoyé prend en charge poll(2) (et analogiquement epoll(7)) et select(2), comme suit :
•
Le descripteur de fichier est lisible (l'argument readfds de select(2) ; le drapeau POLLIN de poll(2)) si le compteur a une valeur supérieure à 0.
•
Le descripteur de fichier est écrivable (l'argument writefds de select(2) ; le drapeau POLLOUT de poll(2)) s'il est possible d'écrire une valeur d'au moins « 1 » sans bloquer.
•
Si un débordement de la valeur du compteur a été détecté, alors select(2) indique le descripteur de fichier comme étant à la fois lisible et écrivable, et poll(2) renvoie un événement POLLERR. Comme indiqué ci-dessus, write(2) ne peut jamais déborder le compteur. Cependant, un débordement peut survenir si 2^64 « signaux eventfd » ont été effectués par le sous-système KAIO (théoriquement possible, mais pratiquement peu probable). Si un débordement s'est produit, alors read(2) renverra cette valeur maximale de uint64_t (c'est-à-dire, 0xffffffffffffffff).
Le descripteur de fichier eventfd prend également en charge les autres API de multiplexage de descripteurs de fichiers : pselect(2) et ppoll(2).
close(2)
Lorsque le descripteur de fichier n'est plus requis, il doit être fermé. Lorsque tous les descripteurs de fichiers associés au même objet eventfd ont été fermés, les ressources de l'objet sont libérées par le noyau.

Une copie du descripteur de fichier créé par eventfd() est héritée par l'enfant produit par fork(2). Le descripteur de fichier dupliqué est associé au même objet eventfd. Les descripteurs de fichiers créés par eventfd() sont conservés lors de execve(2), à moins que le drapeau close-on-exec n'ait été défini.

VALEUR DE RETOUR

En cas de succès, eventfd() renvoie un nouveau descripteur de fichier eventfd. En cas d'erreur, -1 est renvoyé et errno est définie pour indiquer l'erreur.

ERREURS

EINVAL
Une valeur non prise en charge a été spécifiée dans flags.
EMFILE
La limite par processus du nombre de descripteurs de fichiers ouverts a été atteinte.
ENFILE
La limite globale du système sur le nombre total de fichiers ouverts a été atteinte.
ENODEV
Impossible de monter l'anneau anonyme (interne) de l'appareil.
ENOMEM
Il n'y avait pas assez de mémoire pour créer un nouveau descripteur de fichier eventfd.

ATTRIBUTS

Pour une explication des termes utilisés dans cette section, voir attributes(7).

Interface Attribut Valeur
eventfd () Sécurité des threads MT-Safe
VERSIONS

Différences entre la bibliothèque C et le noyau

Il existe deux appels système Linux sous-jacents : eventfd() et le plus récent eventfd2(). Le premier appel système n'implémente pas d' flags argument. Le second appel système implémente les valeurs de flags décrites ci-dessus. La fonction wrapper de glibc utilisera eventfd2() lorsqu'il est disponible.

Fonctionnalités supplémentaires de glibc

La bibliothèque C GNU définit un type supplémentaire et deux fonctions qui tentent d'abstraire certains des détails de la lecture et de l'écriture sur un descripteur de fichier eventfd :


typedef uint64_t eventfd_t;
int eventfd_read(int fd, eventfd_t *value);
int eventfd_write(int fd, eventfd_t value);

Les fonctions effectuent les opérations de lecture et d'écriture sur un descripteur de fichier eventfd, retournant 0 si le nombre correct d'octets a été transféré, ou -1 sinon.

STANDARDS

Linux, GNU.

HISTORIQUE

eventfd()
Linux 2.6.22, glibc 2.8.
eventfd2()
Linux 2.6.27 (voir VERSIONS). Depuis glibc 2.9, le wrapper eventfd() utilisera l'appel système eventfd2(), s'il est pris en charge par le noyau.

NOTES

Les applications peuvent utiliser un descripteur de fichier eventfd à la place d'un tube (voir pipe(2)) dans tous les cas où un tube est utilisé simplement pour signaler des événements. La surcharge du noyau d'un descripteur de fichier eventfd est bien moindre que celle d'un tube, et un seul descripteur de fichier est requis (contre les deux requis pour un tube).

Lorsqu'il est utilisé dans le noyau, un descripteur de fichier eventfd peut fournir un pont du noyau vers l'espace utilisateur, permettant, par exemple, des fonctionnalités comme KAIO (AIO du noyau) de signaler à un descripteur de fichier qu'une opération est terminée.

Un point clé concernant un descripteur de fichier eventfd est qu'il peut être surveillé comme n'importe quel autre descripteur de fichier en utilisant select(2), poll(2), ou epoll(7). Cela signifie qu'une application peut surveiller simultanément la disponibilité des fichiers « traditionnels » et la disponibilité d'autres mécanismes du noyau qui prennent en charge l'interface eventfd. (Sans l'interface eventfd(), ces mécanismes ne pourraient pas être multiplexés via select(2), poll(2), ou epoll(7).)

La valeur actuelle d'un compteur eventfd peut être consultée via l'entrée correspondant au descripteur de fichier dans le répertoire /proc/pid/fdinfo du processus. Voir proc(5) pour plus de détails.

EXEMPLES

Le programme suivant crée un descripteur de fichier eventfd puis se duplique (fork) pour créer un processus enfant. Pendant que le parent dort brièvement, l'enfant écrit chacun des entiers fournis dans les arguments de la ligne de commande du programme dans le descripteur de fichier eventfd. Lorsque le parent a fini de dormir, il lit depuis le descripteur de fichier eventfd.

La session shell suivante montre un exemple d'exécution du programme :


$ ./a.out 1 2 4 7 14
Child writing 1 to efd
Child writing 2 to efd
Child writing 4 to efd
Child writing 7 to efd
Child writing 14 to efd
Child completed write loop
Parent about to read
Parent read 28 (0x1c) from efd

Source du programme

#include <err.h>
#include <inttypes.h>
#include <stdio.h>
#include <stdlib.h>
#include <sys/eventfd.h>
#include <sys/types.h>
#include <unistd.h>
int
main(int argc, char *argv[])
{
    int       efd;
    uint64_t  u;
    ssize_t   s;
    if (argc < 2) {
        fprintf(stderr, "Usage: %s <num>...\n", argv[0]);
        exit(EXIT_FAILURE);
    }
    efd = eventfd(0, 0);
    if (efd == -1)
        err(EXIT_FAILURE, "eventfd");
    switch (fork()) {
    case 0:
        for (size_t j = 1; j < argc; j++) {
            printf("Child writing %s to efd\n", argv[j]);
            u = strtoull(argv[j], NULL, 0);
                    /* strtoull() allows various bases */
            s = write(efd, &u, sizeof(uint64_t));
            if (s != sizeof(uint64_t))
                err(EXIT_FAILURE, "write");
        }
        printf("Child completed write loop\n");
        exit(EXIT_SUCCESS);
    default:
        sleep(2);
        printf("Parent about to read\n");
        s = read(efd, &u, sizeof(uint64_t));
        if (s != sizeof(uint64_t))
            err(EXIT_FAILURE, "read");
        printf("Parent read %"PRIu64" (%#"PRIx64") from efd\n", u, u);
        exit(EXIT_SUCCESS);
    case -1:
        err(EXIT_FAILURE, "fork");
    }
}
