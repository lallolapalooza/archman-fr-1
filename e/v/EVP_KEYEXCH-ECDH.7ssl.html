NOM

EVP_KEYEXCH-ECDH - Prise en charge de l'algorithme d'échange de clés ECDH

DESCRIPTION

Prise en charge de l'échange de clés pour le type de clé ECDH.

paramètres d'échange de clés ECDH

"ecdh-cofactor-mode" (OSSL_EXCHANGE_PARAM_EC_ECDH_COFACTOR_MODE) <entier>
Définit ou obtient le mode de fonctionnement ECDH pour le contexte d'échange de clés associé.

Dans le contexte d'un échange de clés Diffie-Hellman sur courbe elliptique, ce paramètre peut être utilisé pour choisir entre les variantes de l'algorithme d'échange de clés Diffie-Hellman (DH) simple ou Diffie-Hellman par cofacteur (CDH).

Lors de la définition, la valeur doit être 1, 0 ou -1, forçant respectivement le mode cofacteur activé, désactivé, ou le réinitialisant à la valeur par défaut pour la clé privée associée au contexte d'échange de clés donné.

Lors de l'obtention, la valeur doit être 1 ou 0, indiquant respectivement si le mode cofacteur est activé ou désactivé.

Voir également provider-keymgmt(7) pour le paramètre connexe OSSL_PKEY_PARAM_USE_COFACTOR_ECDH qui peut être défini par clé.

"kdf-type" (OSSL_EXCHANGE_PARAM_KDF_TYPE) <chaîne UTF8>
"kdf-digest" (OSSL_EXCHANGE_PARAM_KDF_DIGEST) <chaîne UTF8>
"kdf-digest-props" (OSSL_EXCHANGE_PARAM_KDF_DIGEST_PROPS) <chaîne UTF8>
"kdf-outlen" (OSSL_EXCHANGE_PARAM_KDF_OUTLEN) <entier non signé>
"kdf-ukm" (OSSL_EXCHANGE_PARAM_KDF_UKM) <chaîne d'octets>

Le fournisseur FIPS d'OpenSSL prend également en charge les paramètres suivants :

"fips-indicator" (OSSL_EXCHANGE_PARAM_FIPS_APPROVED_INDICATOR) <entier>
"key-check" (OSSL_EXCHANGE_PARAM_FIPS_KEY_CHECK) <entier>
"digest-check" (OSSL_EXCHANGE_PARAM_FIPS_DIGEST_CHECK) <entier>
Voir "Paramètres communs d'échange de clés" dans provider-keyexch(7).
"ecdh-cofactor-check" (OSSL_EXCHANGE_PARAM_FIPS_ECDH_COFACTOR_CHECK) <entier>
Si requis, ce paramètre doit être défini avant OSSL_FUNC_keyexch_derive(). La valeur par défaut de 1 provoque une erreur lors de OSSL_FUNC_keyexch_derive si la courbe EC a un cofacteur qui n'est pas 1, et que le cofacteur n'est pas utilisé. Le définir à 0 ignorera l'erreur et définira le "fips-indicator" approuvé à 0. Cette option enfreint la conformité FIPS si elle provoque le retour de 0 du "fips-indicator" approuvé.

EXEMPLES

Les exemples d'accord de clés se trouvent dans demos/keyexch.

Les clés pour l'hôte et le pair doivent être générées comme montré dans "Exemples" dans EVP_PKEY-EC(7) en utilisant le même nom de courbe.

Le code pour générer un secret partagé dans le cas normal est identique à "Exemples" dans EVP_KEYEXCH-DH(7).

Pour dériver un secret partagé sur l'hôte en utilisant la clé de l'hôte et la clé publique du pair, mais en utilisant également X963KDF avec un matériau de clé utilisateur :

/* Il est supposé que host_key, peer_pub_key et ukm sont configurés */
void derive_secret(EVP_PKEY *host_key, EVP_PKEY *peer_key,
                   unsigned char *ukm, size_t ukm_len)
{
    unsigned char secret[64];
    size_t out_len = sizeof(secret);
    size_t secret_len = out_len;
    unsigned int pad = 1;
    OSSL_PARAM params[6];
    EVP_PKEY_CTX *dctx = EVP_PKEY_CTX_new_from_pkey(NULL, host_key, NULL);
    EVP_PKEY_derive_init(dctx);
    params[0] = OSSL_PARAM_construct_uint(OSSL_EXCHANGE_PARAM_PAD, &pad);
    params[1] = OSSL_PARAM_construct_utf8_string(OSSL_EXCHANGE_PARAM_KDF_TYPE,
                                                 "X963KDF", 0);
    params[2] = OSSL_PARAM_construct_utf8_string(OSSL_EXCHANGE_PARAM_KDF_DIGEST,
                                                 "SHA1", 0);
    params[3] = OSSL_PARAM_construct_size_t(OSSL_EXCHANGE_PARAM_KDF_OUTLEN,
                                            &out_len);
    params[4] = OSSL_PARAM_construct_octet_string(OSSL_EXCHANGE_PARAM_KDF_UKM,
                                                  ukm, ukm_len);
    params[5] = OSSL_PARAM_construct_end();
    EVP_PKEY_CTX_set_params(dctx, params);
    EVP_PKEY_derive_set_peer(dctx, peer_pub_key);
    EVP_PKEY_derive(dctx, secret, &secret_len);
    ...
    OPENSSL_clear_free(secret, secret_len);
    EVP_PKEY_CTX_free(dctx);
}
