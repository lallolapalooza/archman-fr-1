TSS2_RC Esys_ContextLoad (ESYS_CONTEXT * esysContext, const TPMS_CONTEXT * context, ESYS_TR * loadedHandle)

Appel unique pour TPM2_ContextLoad

Cette fonction invoque la commande TPM2_ContextLoad en variante à appel unique. Cela signifie que la fonction bloquera jusqu'à ce que la réponse du TPM soit disponible. Tous les paramètres d'entrée sont constants. La mémoire pour les paramètres de sortie non simples est allouée par l'implémentation de la fonction.

Paramètres

esysContext Le ESYS_CONTEXT.
context Le blob de contexte.
loadedHandle Handle ESYS_TR de la ressource ESYS pour TPMI_DH_CONTEXT.

Valeurs de retour

TSS2_RC_SUCCESS si l'appel de fonction a réussi.
TSS2_ESYS_RC_BAD_REFERENCE si esysContext ou les pointeurs d'entrée requis ou les références de handle de sortie requis sont NULL.
TSS2_ESYS_RC_BAD_CONTEXT si une corruption d'esysContext est détectée.
TSS2_ESYS_RC_MEMORY si l'ESAPI ne peut pas allouer suffisamment de mémoire pour les opérations internes ou les paramètres de retour.
TSS2_ESYS_RC_BAD_SEQUENCE si le contexte a déjà une opération asynchrone en attente.
TSS2_ESYS_RC_INSUFFICIENT_RESPONSE si la réponse du TPM ne contient pas au moins la balise, la longueur de la réponse et le code de réponse.
TSS2_ESYS_RC_MALFORMED_RESPONSE si la réponse du TPM est corrompue.
TSS2_ESYS_RC_RSP_AUTH_FAILED si le HMAC de réponse du TPM n'a pas été vérifié.
TSS2_RCs produits par les couches inférieures de la pile logicielle peuvent être retournés à l'appelant sans modification, sauf s'ils sont gérés en interne.

TSS2_RC Esys_ContextLoad_Async (ESYS_CONTEXT * esysContext, const TPMS_CONTEXT * context)

Fonction asynchrone pour TPM2_ContextLoad

Cette fonction invoque la commande TPM2_ContextLoad en variante asynchrone. Cela signifie que la fonction retournera dès que la commande aura été envoyée vers le bas de la pile vers le TPM. Tous les paramètres d'entrée sont constants. Pour récupérer la réponse du TPM, appelez Esys_ContextLoad_Finish.

Paramètres

esysContext Le ESYS_CONTEXT.
context Le blob de contexte.

Valeurs de retour

ESYS_RC_SUCCESS si l'appel de fonction a réussi.
TSS2_ESYS_RC_BAD_REFERENCE si esysContext ou les pointeurs d'entrée requis ou les références de handle de sortie requis sont NULL.
TSS2_ESYS_RC_BAD_CONTEXT si une corruption d'esysContext est détectée.
TSS2_ESYS_RC_MEMORY si l'ESAPI ne peut pas allouer suffisamment de mémoire pour les opérations internes ou les paramètres de retour.
TSS2_RCs produits par les couches inférieures de la pile logicielle peuvent être retournés à l'appelant sans modification, sauf s'ils sont gérés en interne.

TSS2_RC Esys_ContextLoad_Finish (ESYS_CONTEXT * esysContext, ESYS_TR * loadedHandle)

Fonction de fin asynchrone pour TPM2_ContextLoad

Cette fonction retourne les résultats d'une commande TPM2_ContextLoad invoquée via Esys_ContextLoad_Finish. Tous les paramètres de sortie non simples sont alloués par l'implémentation de la fonction. NULL peut être passé pour chaque paramètre de sortie si la valeur n'est pas requise.

Paramètres

esysContext Le ESYS_CONTEXT.
loadedHandle Handle ESYS_TR de la ressource ESYS pour TPMI_DH_CONTEXT.

Valeurs de retour

TSS2_RC_SUCCESS en cas de succès
ESYS_RC_SUCCESS si l'appel de fonction a réussi.
TSS2_ESYS_RC_BAD_REFERENCE si esysContext ou les pointeurs d'entrée requis ou les références de handle de sortie requis sont NULL.
TSS2_ESYS_RC_BAD_CONTEXT si une corruption d'esysContext est détectée.
TSS2_ESYS_RC_MEMORY si l'ESAPI ne peut pas allouer suffisamment de mémoire pour les opérations internes ou les paramètres de retour.
TSS2_ESYS_RC_BAD_SEQUENCE si le contexte a déjà une opération asynchrone en attente.
TSS2_ESYS_RC_TRY_AGAIN si le compteur de délai d'attente expire avant la réception de la réponse du TPM.
TSS2_ESYS_RC_INSUFFICIENT_RESPONSE si la réponse du TPM ne contient pas au moins la balise, la longueur de la réponse et le code de réponse.
TSS2_ESYS_RC_RSP_AUTH_FAILED si le HMAC de réponse du TPM n'a pas été vérifié.
TSS2_ESYS_RC_MALFORMED_RESPONSE si la réponse du TPM est corrompue.
TSS2_RCs produits par les couches inférieures de la pile logicielle peuvent être retournés à l'appelant sans modification, sauf s'ils sont gérés en interne.
