DESCRIPTIO

N

esh (embedded shell) est un moteur de gabarits pour évaluer des commandes shell intégrées dans des gabarits arbitraires. C'est comme ERB (Embedded RuBy) pour le shell, destiné à être utilisé pour le gabarit de fichiers de configuration. Contrairement à ERB, il prend en charge l'inclusion d'un gabarit ESH dans un autre (depuis la version 0.2.0)

.

esh convertit le gabarit fichier, ou stdin si fichier vaut « - », en une séquence de commandes shell. Les commandes situées entre les balises <% et %> sont transmises telles quelles, tout le reste est échappé et préfixé par la commande printf. Ces commandes sont finalement évaluées à l'aide du shell (sauf si -d est

spéci
fié).

SYNTAXE DU

GABARIT

ESH a deux balises pour le code shell, une balise pour l'inclusion, des commentaires et un moyen d'échapper les délimiteurs de

balises.

<% commandes

%>
Exécute les commandes et remplace cette balise par sa sortie sur stdout
.

<%= valeurs

%>
Exécute printf '%s ' avec les valeurs comme arguments et remplace cette balise par la sortie (sans espace blanc final). Les valeurs ne sont ni quotées ni échappées, de sorte que toutes les substitutions shell sont
appliquées.

<%+ nomdefichier

%>
Lit et convertit le gabarit ESH à partir du nomdefichier et le place à l'endroit de cette balise. Les inclusions sont traitées récursivement, mais la profondeur est limitée par ESH_MAX_DEPTH.

Si le nomdefichier est relatif, il est résolu par rapport au répertoire du fichier gabarit dans lequel se trouve cette balise. Si le gabarit est lu depuis stdin, les inclusions de premier niveau sont résolues par rapport au répertoire de travail courant. Veuillez noter que les inclusions sont traitées pendant la conversion, et non pendant la phase d'évaluation, de sorte que le nomdefichier ne peut pas être une expression ou une variable

!

Contrairement aux autres, cette balise

doit être fermée sur la même ligne,
sinon c'est une erreur de syntaxe.

<%# commentaire

%>
Supprimé de la sortie
finale.

-%

>
Peut être utilisé à la place de %>. Il supprime le saut de ligne suivant s'il est utilisé en fin de ligne, sinon il n'a aucun effet de
suppression.

<%

%
Un littéral <% lorsqu'il est utilisé en dehors des balises
ci-dessus.

%%

>
Un littéral %> lorsqu'il est utilisé à l'intérieur des balises
ci-dessus.

Les balises d'ouverture et de fermeture ne peuvent pas être sur la même

ligne.

Le texte en dehors d'une balise devient du texte littéral, mais il est soumis au code shell balisé qui l'entoure. Par exemple, un texte entouré par une instruction if balisée n'apparaît dans la sort

ie que si la con
dition est vraie.

EXEMPLE

S

nginx.conf.

esh 
http {
    access_log <%= $logs_dir/access.log %> main;
    resolver <%= $(sed -En 's/^nameserver ([^#]+)/\1/p' /etc/resolv.conf) %>;
    <% if nginx -V 2>&1 | grep -q lua-nginx-module; then -%>
    lua_package_path '<%= $(pkg-config --variable=INSTALL_LMOD lua) %>/?.lua';
    <% fi -%>
    <%+ ./http-common.esh %>
    <%# Le reste de la configuration est omis %>
}

Pour générer le fichier de configuration résultant, exécutez

: 
esh -o nginx.conf nginx.conf.esh logs_dir=/var/log/ng
