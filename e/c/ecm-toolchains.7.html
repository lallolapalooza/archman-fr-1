ECM-TOOLCHAINS(7) Modules CMake Supplémentaires ECM-TOOLCHAINS(7)

NOM

ecm-toolchains - Référence des chaînes d'outils ECM

INTRODUCTION

Les modules CMake Supplémentaires (ECM) fournissent quelques modules de chaînes d'outils. Contrairement aux modules normaux, ceux-ci ne sont pas inclus directement dans les projets, mais spécifiés avec la variable cache CMAKE_TOOLCHAIN_FILE en ligne de commande.

TOUS LES MODULES

AndroidToolchain

Permet la compilation facile de projets cmake sur Android.

En utilisant cette chaîne d'outils Android, les projets seront configurés pour compiler le projet spécifié ciblant une plateforme Android, en fonction de ses entrées. De plus, si désiré, un APK peut être directement généré en utilisant l'outil androiddeployqt https://doc.qt.io/qt-5/deployment-android.html.

CMake upstream dispose maintenant d'un support Android. Ce module nous fournira toujours quelques fonctionnalités utiles offrant l'intégration d'androiddeployqt et des formats d'exécutables adéquats pour nos applications Android.

Étant donné que nous utilisons le support Android de CMake, toute information de la documentation de CMake reste valide : https://cmake.org/cmake/help/v3.7/manual/cmake-toolchains.7.html#cross-compiling-for-android

Note :

Ce module requiert CMake 3.18.

Depuis 1.7.0.

Utilisation

Pour utiliser ce fichier, vous devez définir CMAKE_TOOLCHAIN_FILE pour pointer vers Android.cmake en ligne de commande :

cmake -DCMAKE_TOOLCHAIN_FILE=/usr/share/ECM/toolchain/Android.cmake

Vous devrez également fournir les emplacements du NDK et du SDK Android. Cela peut être fait en ligne de commande ou via des variables d'environnement ; dans les deux cas, les noms des variables sont :

CMAKE_ANDROID_NDK
Le chemin racine du NDK.
ANDROID_SDK_ROOT
Le chemin racine du SDK.

Des options supplémentaires sont spécifiées comme variables cache (par exemple, en ligne de commande) :

ANDROID_ABI
L'ABI à utiliser. Voir les répertoires sources/cxx-stl/gnu-libstdc++/*/libs dans le NDK. Par défaut : armeabi-v7a.
ANDROID_SDK_COMPILE_API
Le niveau API de la plateforme à utiliser pour la compilation. Peut être différent de la cible du NDK. Par défaut : la version installée la plus récente (par exemple, android-30).
ANDROID_SDK_BUILD_TOOLS_REVISION
La version des outils de build à utiliser. Par défaut : la version installée la plus récente (par exemple, 30.0.2).
ANDROID_EXTRA_LIBS
La liste des chemins complets vers les bibliothèques à inclure dans l'APK résultant, séparés par des “;” (Qt 5 uniquement).

Pour intégrer d'autres bibliothèques qui ne font pas partie de la chaîne d'outils Android, comme Qt5, et qui sont installées dans un préfixe séparé sur le système hôte, les préfixes d'installation de ces bibliothèques seraient passés comme racines alternatives sous forme de liste via ECM_ADDITIONAL_FIND_ROOT_PATH. Depuis 5.30.0.

Par exemple, pour intégrer un Qt5 pour Android présent dans ~/Qt/5.14.2/android/ et d'autres bibliothèques installées dans le préfixe /opt/android/foo, vous utiliseriez :

cmake \
  -DCMAKE_TOOLCHAIN_FILE=/usr/share/ECM/toolchain/Android.cmake \
  -DECM_ADDITIONAL_FIND_ROOT_PATH="~/Qt/5.14.2/android/;/opt/android/foo"

Si votre projet utilise find_package() pour localiser les outils de build sur le système hôte, assurez-vous de passer CMAKE_FIND_ROOT_PATH_BOTH ou NO_CMAKE_FIND_ROOT_PATH comme argument dans l'appel. Voir la documentation de find_package() pour plus de détails.

Déploiement des applications Qt 5

Après avoir compilé l'application, vous devrez générer un APK qui pourra être déployé sur un appareil Android. Ce module intègre le support d'androiddeployqt pour aider à cela pour les projets basés sur Qt. Pour l'activer, définissez la variable QTANDROID_EXPORTED_TARGET aux cibles que vous souhaitez exporter en tant qu'APK (dans une liste séparée par des ;-), ainsi que ANDROID_APK_DIR vers un répertoire contenant des informations de base. Cela créera une cible create-apk-<target> qui générera le fichier APK. Voir la documentation de Qt sur Android pour le déploiement https://doc.qt.io/qt-5/deployment-android.html pour plus d'informations.

Par exemple, vous pourriez faire :

cmake \
  -DCMAKE_TOOLCHAIN_FILE=/usr/share/ECM/toolchain/Android.cmake \
  -DQTANDROID_EXPORTED_TARGET=myapp \
  -DANDROID_APK_DIR=myapp-apk
make
make create-apk-myapp

Vous pouvez spécifier le répertoire de sortie de l'APK en définissant ANDROID_APK_OUTPUT_DIR. Sinon, l'APK se trouvera dans myapp_build_apk/ dans le répertoire de build.

La cible create-apk-myapp pourra accepter un paramètre ARGS avec des arguments supplémentaires pour androiddeployqt. Par exemple, on peut utiliser :

make create-apk-myapp ARGS="--install"

Pour installer l'apk afin de tester. Pour générer un apk signé, on peut le faire avec la syntaxe suivante :

make create-apk-myapp ARGS="--sign ~/my.keystore alias_name"

Si nécessaire pour votre application de définir le répertoire de l'APK depuis le script cmake, vous pouvez également définir le répertoire comme propriété ANDROID_APK_DIR de la cible create-apk-myapp.

Consultez la documentation Android sur la création d'un keystore à utiliser.

Options avancées

Les options d'empaquetage suivantes sont principalement intéressantes pour l'automatisation ou l'intégration avec des pipelines CI/CD :

ANDROID_APK_OUTPUT_DIR
Spécifie un dossier où les fichiers APK générés doivent être placés.
ANDROID_FASTLANE_METADATA_OUTPUT_DIR
Spécifie un dossier où les métadonnées générées pour le magasin F-Droid doivent être placées.
ANDROIDDEPLOYQT_EXTRA_ARGS
Permet de passer des arguments supplémentaires à androiddeployqt. C'est une alternative à l'argument ARGS= pour make et, contrairement à celui-ci, fonctionne avec tous les générateurs CMake.
