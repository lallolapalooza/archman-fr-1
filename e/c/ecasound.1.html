NOM

ecasound - éditeur d'échantillons, enregistreur multipiste, processeur d'effets, etc.

SYNTAXE

ecasound [ options_générales ] { [ configuration_chaîne ] [ configuration_effet ] [ configuration_entrée ] [ configuration_sortie ] }

DESCRIPTION

Ecasound est un ensemble de logiciels conçus pour le traitement audio multipiste. Il peut être utilisé pour des tâches simples comme la lecture audio, l'enregistrement et la conversion de formats, ainsi que pour le traitement d'effets multipistes, le mixage, l'enregistrement et le recyclage de signaux. Ecasound prend en charge une large gamme d'entrées, de sorties audio et d'algorithmes d'effets. Les effets et les objets audio peuvent être combinés de diverses manières, et leurs paramètres peuvent être contrôlés par des objets opérateurs tels que des oscillateurs et des MIDI-CC. Une interface utilisateur en mode console polyvalente est incluse dans le paquet.

OPTIONS

Remarque ! Toutes les options sauf celles mentionnées dans options ecasound et Options globales, peuvent être utilisées dans les fichiers de configuration de chaîne ecasound (.ecs).

OPTIONS ECASOUND

Ces options sont analysées et gérées par le binaire frontend d'ecasound et ne sont pas passées à la bibliothèque backend. Cela signifie que ces options peuvent ne pas fonctionner dans d'autres applications qui utilisent les bibliothèques ecasound pour leurs fonctionnalités.
-c
Démarre ecasound en mode interactif. En mode interactif, vous pouvez contrôler ecasound avec des commandes simples ("start", "stop", "pause", etc.). Voir ecasound-iam.
-C
Désactive le mode interactif d'ecasound (voir "-c" et "-K").
-D
Affiche toutes les informations de débogage sur stderr (sortie non mise en mémoire tampon, sortie brute sans ncurses).
-s[:]fichier_configuration_chaîne
Crée une nouvelle configuration de chaîne à partir du fichier 'fichier_configuration_chaîne' et l'ajoute à la session actuelle. Les fichiers de configuration de chaîne ont couramment une extension de nom de fichier '.ecs'. Une configuration de chaîne peut contenir des entrées, des sorties, des chaînes, des effets, des contrôleurs - c'est-à-dire des objets d'une configuration spécifique d'éléments de traitement audio. Une session, en revanche, est une collection d'une ou plusieurs configurations de chaîne. Une seule des configurations de chaîne peut être connectée (c'est-à-dire qu'elle peut être exécutée/traitée). Mais il est possible d'avoir une autre configuration de chaîne sélectionnée (c'est-à-dire qu'elle peut être configurée) pendant qu'une autre est connectée (c'est-à-dire en cours d'exécution).
-E "commande1 [[arguments] ; commande2 arguments ; ... ; commandeN]"
Exécute un ensemble de commandes du mode interactif Ecasound (EIAM) au lancement. Ces commandes sont exécutées immédiatement après le démarrage d'ecasound. Si la ligne de commande contient suffisamment d'options pour créer une configuration de chaîne valide qui sera exécutée, les commandes de lancement sont exécutées après l'analyse des autres options de la ligne de commande, mais avant le démarrage du moteur de traitement. Notez que cette commande est une fonctionnalité du binaire frontend d'ecasound et n'est pas prise en charge par le backend de la bibliothèque. Cela signifie que d'autres clients peuvent ne pas prendre en charge l'option '-E', et que les commandes de lancement ne sont pas enregistrées dans le cadre de la configuration de chaîne ou de l'état de la session.
--server
Active le mode dit NetECI, dans lequel ecasound peut être contrôlé à distance via une connexion socket. Lorsqu'il est activé, les clients peuvent se connecter à la session ecasound en cours d'exécution et utiliser les commandes du mode interactif pour contrôler et observer le traitement ecasound.
Le protocole NetECI est défini dans le guide du programmeur d'Ecasound.
Un exemple de client utilisant cette fonctionnalité est ecamonitor(1). Cet utilitaire est inclus dans le paquet de distribution Ecasound (nécessite un environnement Python fonctionnel).
Attention ! Si la machine exécutant ecasound est connectée à un réseau public, assurez-vous de bloquer le port d'ecasound dans votre pare-feu ! Comme aucun contrôle d'accès n'est implémenté pour les connexions entrantes, n'importe qui peut sinon se connecter, contrôler et observer vos sessions ecasound. Cette option remplace '--daemon' (obsolète en 2.6.0).
--server-tcp-port=NNN
Définit le port TCP utilisé par le mode daemon. Par défaut, ecasound utilise le numéro de port 2868. Cette option remplace '--daemon-port' (obsolète en 2.6.0).
--no-server
Désactive le mode daemon d'ecasound. C'est le comportement par défaut. Cette option remplace '--nodaemon' (obsolète en 2.6.0).
--osc-udp-port=NNN
Active le support d'Open Sound Control (OSC). Ecasound écoutera les messages OSC entrants sur le port UDP NNN. L'interface OSC d'Ecasound est documentée ici : http://ecasound.git.sourceforge.net/git/gitweb.cgi?p=ecasound/ecasound;a=blob;f=Documentation/ecasound_osc_interface.txt;hb=HEAD
Notez que le support OSC est encore expérimental et que l'interface pourrait changer dans les futures versions d'Ecasound.
Cette option a été ajoutée à ecasound 2.7.0.
--keep-running,-K
Ne pas quitter lorsque le traitement est terminé/arrêté. N'affecte que le mode de fonctionnement non interactif (voir -c/-C). Option ajoutée à ecasound 2.4.2.
--help,-h
Affiche cette aide.
--version
Affiche les informations de version.
OPTIONS GLOBALES
-d, -dd, -ddd
Augmente la quantité de messages de débogage affichés. -d ajoute un peu de verbosité, tandis que -ddd produit une sortie très détaillée.
-d:niveau_debug
Définit le masque du niveau de débogage sur 'niveau_debug'. Il s'agit d'une valeur masquée par bits avec les classes suivantes : erreurs (1), info (2), sous-systèmes (4), noms de modules (8), objets utilisateur (16), objets système 32, fonctions (64), continu (128) et valeurs de retour eiam (256). La valeur par défaut est 271 (1+2+4+8+256). Voir la documentation du code source pour la classe ECA_LOGGER pour des informations plus détaillées.
-R[:]chemin/vers/fichier
Utilise le fichier de ressources ecasound (voir la page de manuel ecasoundrc) 'chemin/vers/fichier' comme seule source de valeur de ressource. Spécifier cette option désactivera la politique normale de consultation des fichiers de ressources globaux et utilisateur (s'ils existent).
-q
Mode silencieux, aucune sortie. Identique à -d:0.
OPTIONS GÉNÉRALES DE CONFIGURATION DE CHAÎNE
-a:nom_chaîne1, nom_chaîne2, ...
Sélectionne les chaînes de signaux actives. Toutes les entrées et sorties suivant cette option '-a' sont assignées aux chaînes sélectionnées (jusqu'à ce qu'une nouvelle option -a soit spécifiée). Lors de l'ajout d'effets, de contrôleurs et d'autres opérateurs de chaîne, une seule chaîne peut être sélectionnée à la fois. Si aucune option -a n'a été donnée, la chaîne 'default' est utilisée à la place lors de l'ajout d'objets. Le nom de chaîne 'all' est également réservé. Il provoquera la sélection de toutes les chaînes existantes. En donnant plusieurs options -a, vous pouvez contrôler à quelles chaînes les effets, entrées et sorties sont assignés. Regardez la section EXEMPLES pour plus d'informations sur l'utilisation de cette option.
-n:nom
Définit le nom de la configuration de chaîne à 'nom'. Si non spécifié, il prend par défaut "command-line-setup" ou le nom du fichier à partir duquel la configuration de chaîne a été chargée. Les espaces ne sont pas autorisés.
-x
Tronque les sorties. Tous les objets de sortie sont ouverts en mode écrasement. Tous les fichiers existants seront tronqués.
-X
Ouvre les sorties pour mise à jour. Ecasound ouvre toutes les sorties - si le format cible le permet - en mode lecture/écriture.
-z:fonctionnalité
Active la 'fonctionnalité'. La plupart des fonctionnalités peuvent être désactivées en utilisant la notation -z:nofonctionnalité. '-z:db,dbsize' active le double buffering pour les objets audio qui le prennent en charge (dbsize=0 pour défaut, sinon taille du tampon en images d'échantillons). '-z:nodb' désactive le double buffering. '-z:intbuf' et '-z:nointbuf' contrôlent si un tampon interne supplémentaire est activé.
autorisé pour les périphériques temps réel. La désactivation peut réduire les temps de latence dans certaines situations. Avec '-z:xruns', le traitement s'arrête si un sous/sur-dépassement se produit. '-z:multitrack' et 'z:nomultitrack' peuvent être utilisés pour forcer ecasound à activer ou désactiver le mode multipiste. Dans de rares cas, vous pourriez vouloir spécifier explicitement le décalage d'enregistrement avec '-z:multitrack,offset-in-samples'. Le décalage est la quantité d'échantillons ignorés lors de l'enregistrement à partir d'entrées temps réel. '-z:psr' active le mode precise-sample-rates pour les périphériques OSS. '-z:mixmode,sum' active le mode de mixage où les canaux sont mélangés en sommant tous les canaux. La valeur par défaut est '-z:mixmode,avg', dans lequel les canaux sont mélangés par moyenne. La sélection du mode de mixage a été ajoutée pour la première fois à ecasound 2.4.0. Voir la page man ecasoundrc.
OPTIONS DE MISE EN TAMPON ET DE PERFORMANCE DE LA CHAÎNE
-B:buffering_mode
Sélectionne le mode de mise en tampon par défaut. Le mode est l'un des suivants : 'auto' (par défaut), 'nonrt', 'rt', 'rtlowlatency'.
-b:buffer_size
Définit la taille du tampon du moteur de traitement en échantillons. La taille doit être une puissance de 2, et elle est indépendante du nombre de canaux (par exemple, -b:1024 à 48kHz se traduira par une longueur de tampon de 21.333ms, que l'entrée soit mono, stéréo ou 5.1).
C'est une option importante car elle définit la longueur d'une itération du moteur de traitement et affecte ecasound de nombreuses façons. Si elle n'est pas explicitement spécifiée, ecasound essaiera de choisir une valeur optimale en fonction du mode de mise en tampon actuel (voir l'option -B). Pour le traitement en temps réel, vous pouvez essayer de la définir aussi bas que possible pour réduire le délai de traitement. Certaines machines peuvent gérer des valeurs de tampon aussi basses que 64 et 128. Dans certaines circonstances (par exemple, lors de l'utilisation d'enveloppes d'oscillateur), des tailles de tampon faibles rendront les enveloppes plus fluides. Lors du traitement hors temps réel (toutes les entrées et sorties sont des fichiers normaux), des valeurs plus élevées peuvent aider à éviter les dépassements de tampon, réduire l'utilisation du CPU et/ou améliorer les performances.
Notez que lorsque des entrées/sorties JACK sont utilisées, le réglage de la taille du tampon est ignoré et défini sur la taille de période/tampon rapportée par le serveur JACK (par exemple, l'option '-p' de jackd). Il n'est pas possible de désactiver ce comportement.
Si elle n'est pas explicitement spécifiée, la taille de tampon par défaut est choisie en fonction du mode de mise en tampon actuel (voir -B).
-r:sched_priority
Utilise la politique d'ordonnancement temps réel (SCHED_FIFO). Ceci est impossible si ecasound n'a pas les privilèges root. Attention ! Ceci offre de meilleures performances, mais peut provoquer des blocages complets si quelque chose tourne mal. La 'sched_priority' peut être omise (0=omis). Si elle est donnée, c'est la priorité statique du thread ecasound le plus prioritaire. Les autres threads ecasound s'exécutent avec une priorité 'sched_priority-1...n'. La valeur '-1' peut être utilisée pour désactiver le mode de priorité accrue.
-z:feature
Les fonctionnalités pertinentes sont -z:db,xxx (-z:nodb) et -z:intbuf (-z:nointbuf). Voir la section Options générales de la chaîne pour plus de détails.
CONTRÔLE DU TRAITEMENT
-t:seconds
Définit la durée du traitement en secondes (n'a pas besoin d'être une valeur entière). Si la durée du traitement n'est pas définie, le moteur s'arrête lorsque toutes les entrées sont terminées. Cette option est équivalente à la commande EIAM 'cs-set-length'. Une valeur spéciale de '-1' définira la longueur de la chaîne en fonction de l'objet d'entrée le plus long.
-tl
Active la boucle. Lorsque le traitement est terminé, le moteur recommencera depuis le début. Cette option est équivalente à la commande EIAM 'cs-loop'.
CONFIGURATION DES ENTRÉES/SORTIES

Voir le guide de l'utilisateur ecasound pour une documentation plus détaillée.

-G:mgrtype,optstring
Définit les options pour le type de gestionnaire d'objets audio 'mgrtype'. Pour les options disponibles, voir "NOTES SPÉCIFIQUES AUX TYPES D'OBJETS" ci-dessous.
-f:sample_format,channel,sample-rate,interleaving
Définit les paramètres du flux audio pour les objets audio suivants. Pour définir des paramètres différents pour différents objets audio, plusieurs options '-f' doivent être spécifiées (notez l'ordre, les options '-f' doivent précéder les objets audio pour avoir un effet). Voir la documentation des options '-i' et '-o'.
Lorsqu'un objet audio est ouvert (par exemple, un fichier ou un périphérique audio est ouvert, ou une connexion est établie à un serveur audio), les paramètres du flux audio sont transmis à l'objet. Il convient de noter que tous les objets audio ne permettent pas de définir tous les paramètres. Par exemple, lors de l'ouverture de fichiers audio existants, de nombreux formats de fichiers ont un en-tête décrivant les paramètres audio du fichier. Dans ces cas, l'en-tête du fichier audio remplace les paramètres transmis avec l'option '-f'. De même, lors de la création d'entrées et de sorties JACK, le serveur JACK impose le taux d'échantillonnage et le format d'échantillon.
Si aucune option '-f' n'est spécifiée, ou si certains des champs d'arguments sont laissés vides (par exemple, '-f:,2,44100'), ecasound utilisera les valeurs par défaut. Ces valeurs par défaut sont définies dans le fichier de configuration ecasoundrc. Voir la page de manuel ecasoundrc(5).
Notez qu'ecasound ouvre les fichiers de sortie par défaut en mode mise à jour. Sauf si l'option '-x' (écraser les sorties) est donnée, les paramètres audio d'un fichier audio existant ont la priorité sur les paramètres définis avec '-f'.
Le format d'échantillon est donné sous forme de chaîne formatée. La première lettre est soit "u", "s", et "f" (non signé, signé, virgule flottante). Le nombre suivant spécifie la taille de l'échantillon en bits. Si l'échantillon est little endian, "_le" est ajouté à la fin. De même, s'il est big endian, "_be" est ajouté. Si l'endianness n'est pas spécifié, l'ordre des octets de l'hôte est utilisé. Les formats actuellement pris en charge sont "u8" (équivalent à "8"), "s16_le" (équivalent à "16"), "s16_be", "s24_le", "s24_be", "s32_le", "s32_be", "f32_le" et "f32_be". Une chaîne vide "" choisit le format d'échantillon par défaut du système.
Le 4ème paramètre définit la disposition des canaux. Les options disponibles sont 'i' (interleaved) et 'n' (non-interleaved). Avec le réglage non-interleaved, ecasound traitera les échantillons canal par canal, et la taille de bloc est définie avec '-b'. Le réglage par défaut est 'i'.
-y:seconds
Définit la position de départ de la dernière entrée/sortie spécifiée. Si vous avez besoin d'un contrôle plus flexible sur les objets audio, vous devriez utiliser le format .ewf.
-i[:]input-file-or-device[,params]
Spécifie une nouvelle source d'entrée qui est connectée à toutes les chaînes sélectionnées (les chaînes sont sélectionnées avec '-a:...'). Connecter plusieurs entrées à la même chaîne n'est pas possible, mais une entrée peut être connectée à plusieurs chaînes. L'entrée peut être un fichier, un périphérique ou un autre objet audio (voir ci-dessous). Si l'entrée est un fichier, son type est déterminé par l'extension du nom de fichier. Si le nom de l'objet contient des virgules, le nom doit être entouré de guillemets inversés pour éviter de confondre l'analyseur. Les formats actuellement pris en charge sont les fichiers RIFF WAVE (.wav), les pistes de CD audio (.cdr), les fichiers EWF d'ecasound (.ewf), les données audio BRUTES (.raw) et les fichiers audio MPEG (.mp2,.mp3). D'autres formats audio sont pris en charge via les bibliothèques libaudiofile et libsndfile (voir la documentation ci-dessous). MikMod est également pris en charge (.xm, .mod, .s3m, .it, etc.). Les fichiers MIDI (.mid) sont pris en charge à l'aide de Timidity++. De même, Ogg Vorbis (.ogg) peut être lu, et écrit si les outils ogg123 et vorbize sont installés ; les fichiers FLAC (.flac) avec les outils en ligne de commande flac ou en utilisant libsndfile ; et les fichiers AAC (.aac/.m4a/.mp4) avec les outils faad2/faac. Les périphériques temps réel pris en charge sont les périphériques audio OSS (/dev/dsp*), les périphériques audio et de bouclage ALSA, et le sous-système audio JACK. Si aucune entrée n'est spécifiée, le premier argument de ligne de commande non-optionnel (ne commençant pas par '-') est considéré comme une entrée.
-o[:]output-file-or-device[,params]
Fonctionne de la même manière que l'option -i. Si aucune sortie n'est spécifiée, le périphérique de sortie par défaut est utilisé (voir ~/.ecasoundrc). Si le nom de l'objet contient des virgules, le nom doit être entouré de guillemets inversés pour éviter de confondre l'analyseur. Notez que de nombreux types d'objets ne prennent pas en charge la sortie (par exemple, MikMod, MIDI et bien d'autres).
NOTES SPÉCIFIQUES AUX TYPES D'OBJETS
Périphériques ALSA - 'alsa'
Lors de l'utilisation de pilotes ALSA, au lieu d'un nom de fichier de périphérique, vous devez utiliser la syntaxe d'option suivante : -i[:]alsa,pcm_device_name.
Accès direct hw et plugin ALSA - 'alsahw', 'alsaplugin'
Il est également possible d'utiliser une combinaison spécifique de carte et de périphérique en utilisant la notation suivante : -i[:]alsahw,card_number,device_number,subdevice_number. Une autre option est la couche de plugin PCM d'ALSA. Elle fonctionne comme les périphériques PCM ALSA normaux, mais avec des conversions automatiques du nombre de canaux et du format d'échantillon. La syntaxe de l'option est -i[:]alsaplugin,card_number,device_number,subdevice_number.
Entrée/sortie aRts - 'arts'
Si activé lors de la compilation, ecasound prend en charge l'entrée et la sortie audio à l'aide du serveur audio aRts. La syntaxe de l'option est -i:arts, -o:arts.
Séquençage de fichiers audio - 'audioloop', 'select', 'playat'
Ecasound fournit un ensemble de types d'objets audio spéciaux qui peuvent être utilisés pour le séquençage temporel des fichiers audio - c'est-à-dire la boucle, la lecture d'une partie sélectionnée d'un fichier, la lecture d'un fichier à une heure spécifique, et d'autres opérations similaires.
La boucle est possible avec -i:audioloop,file.ext,params. Le nom du fichier (ou tout autre type d'objet compris par Ecasound) donné comme deuxième paramètre est joué en boucle continue, revenant au début à la fin du fichier. LADSPA
-el:plugin_unique_name,param-1,...,
param-N
Ecasound prend en charge les plugins d’effets LADSPA (Linux Audio Developer’s Simple Plugin API). Les paramètres 1..N sont définis comme valeurs des ports de contrôle du
plugin.
Si le plugin a plus d’un port d’entrée et/ou de sortie audio, une seule instance de plugin est créée, et les canaux de la chaîne sont alimentés vers la même instance de plugin. Si le plugin a au plus une entrée et au plus une sortie audio, une instance de plugin distincte est créée pour chaque canal de la chaîne ecasound (par exemple, pour un canal audio stéréo, deux plugins LADSPA du même type sont créés, un par canal)
.
Les plugins sont situés dans des fichiers de bibliothèque partagée (.so). Ecasound recherche les plugins dans @prefix@/lib/ladspa (par exemple "/usr/local/lib/ladspa"), les répertoires listés dans la variable d’environnement LADSPA_PATH. Le chemin de recherche des plugins peut être configuré aussi via ecasoundrc, voir la page de manuel ecasoundrc(5). Un fichier de bibliothèque partagée peut contenir plusieurs objets plugin, mais chaque plugin a un nom de plugin unique. Ce nom est utilisé pour sélectionner les
plugins.
Voir le site web de la liste de diffusion LAD pour plus d’informations sur LADSPA. D’autres sites utiles sont la page d’accueil LADSPA et la documentation
LADSPA.

SIGNAU

X

Lorsque ecasound reçoit l'un des signaux POSIX SIGINT (ctrl-c), SIGHUP, SIGTERM ou SIGQUIT, la procédure de nettoyage et de sortie normale est initiée. Ici, une sortie normale signifie que, par exemple, les en-têtes de fichiers sont mis à jour avant la fermeture, les processus auxiliaires sont terminés de manière normale, et ainsi de

suite.

Si, pendant le nettoyage décrit ci-dessus, ecasound reçoit un autre signal (du même ensemble de signaux POSIX), ecasound sautera la procédure de nettoyage normale et se terminera immédiatement. Toutes les tâches de nettoyage restantes seront ignorées. Selon l'état d'exécution et la configuration, cette sortie forcée peut avoir certains effets de bord. Ecasound retournera le code de sortie ’4’ si le nettoyage normal a été

ignoré.

Un traitement spécial est appliqué au signal SIGINT (ctrl-c). Si un signal SIGINT est reçu pendant la procédure de nettoyage, ecasound ign

orera le signal une fois et émettra un avis sur ’stderr’ indiquant que le nettoyage est déjà en cours. Les signaux SIGINT ultérieurs ne b
énéficieront plus d'un traitement spécial, et le processus se terminera au contraire immédiatement (et possiblement sans nettoyage approprié).
