NOM

eCryptfs - un système de fichiers cryptographique de niveau entreprise pour linux

SYNOPSIS

mount -t ecryptfs [RÉP_SRC] [RÉP_DST] -o [OPTIONS]

DESCRIPTION

eCryptfs est un système de fichiers cryptographique empilé de niveau entreprise, conforme à POSIX, pour Linux. Il est dérivé de Cryptfs d'Erez Zadok, implémenté à travers le cadre FiST pour la génération de systèmes de fichiers empilés. eCryptfs étend Cryptfs pour fournir des fonctionnalités avancées de gestion des clés et de politiques. eCryptfs stocke les métadonnées cryptographiques dans l'en-tête de chaque fichier écrit, de sorte que les fichiers chiffrés peuvent être copiés entre hôts ; le fichier sera déchiffrable avec la bonne clé, et il n'est pas nécessaire de conserver des informations supplémentaires en dehors de ce qui se trouve déjà dans le fichier chiffré lui-même. Considérez eCryptfs comme une sorte de « gnupgfs ».

OPTIONS

OPTIONS DU NOYAU

Paramètres qui s'appliquent au module du noyau eCryptfs.

ecryptfs_sig=(sig_fekek)
Spécifie la signature du jeton d'authentification pour l'ensemble du montage. Le jeton d'authentification doit être dans le trousseau de clés du noyau avant que le montage ne soit effectué. ecryptfs-manager ou l'assistant de montage eCryptfs peuvent être utilisés pour construire le jeton d'authentification et l'ajouter au trousseau de clés avant le montage.
ecryptfs_fnek_sig=(sig_fnek)
Spécifie la signature du jeton d'authentification pour l'ensemble du montage utilisé pour le chiffrement des noms de fichiers. L'authentification doit être dans le trousseau de clés du noyau avant le montage.
ecryptfs_cipher=(chiffre)
Spécifie le chiffrement symétrique à utiliser par fichier.
ecryptfs_key_bytes=(octets_clé)
Spécifie la taille de la clé à utiliser avec le chiffrement sélectionné. Si le chiffrement n'a qu'une seule taille de clé, la taille de la clé n'a pas besoin d'être spécifiée.
ecryptfs_passthrough
Permet la lecture et l'écriture de fichiers non eCryptfs depuis l'intérieur d'un montage eCryptfs. Cette option est désactivée par défaut.
no_sig_cache
Ne pas vérifier la signature de la clé de montage par rapport aux valeurs du fichier ~/.ecryptfs/sig-cache.txt de l'utilisateur. Cela est utile pour des choses comme des scripts de configuration non interactifs, afin que l'assistant de montage ne s'arrête pas et n'interroge pas l'utilisateur si la signature de la clé n'est pas dans le cache.
ecryptfs_encrypted_view
Cette option fournit un format de fichier chiffré unifié des fichiers eCryptfs dans le point de montage inférieur. Actuellement, elle n'est utile que si le point de montage inférieur contient des fichiers avec les métadonnées stockées dans l'attribut étendu. Lors de la lecture d'un fichier dans le point de montage supérieur, la version chiffrée du fichier sera présentée avec les métadonnées dans l'en-tête du fichier au lieu de l'attribut étendu (xattr). Les fichiers ne peuvent pas être ouverts en écriture lorsque cette option est activée.
ecryptfs_xattr
Stocker les métadonnées dans l'attribut étendu des fichiers inférieurs plutôt que dans la région d'en-tête des fichiers inférieurs.
verbose
Journaliser les informations d'ecryptfs dans /var/log/messages. N'exécutez pas eCryptfs en mode verbeux à moins que vous ne le fassiez dans le seul but du développement, car des valeurs secrètes seront écrites dans le journal système dans ce cas.
OPTIONS DE L'ASSISTANT DE MONTAGE

Paramètres qui s'appliquent à l'assistant de montage eCryptfs.

key=(type_clé):[OPTIONS DU MODULE DE CLÉ]
Spécifie le type de clé à utiliser lors du montage d'eCryptfs.
ecryptfs_enable_filename_crypto=(y/n)
Spécifie si le chiffrement des noms de fichiers doit être activé. Sinon, l'assistant de montage n'interrogera pas l'utilisateur sur la signature de la clé de chiffrement des noms de fichiers (par défaut).
verbosity=0/1
Si verbosity=1, l'assistant de montage vous demandera les valeurs manquantes (par défaut). Sinon, si verbosity=0, il ne demandera pas les valeurs manquantes et échouera si des valeurs requises sont omises.
OPTIONS DU MODULE DE CLÉ

Les paramètres qui s'appliquent à des modules de clés individuels ont l'alias du module de clé comme préfixe du nom du paramètre. Les modules de clés sont modulables, et les modules de clés disponibles sur un système donné dépendent de ce qui se trouve installé dans /usr/lib*/ecryptfs/.

passphrase_passwd=(phrase_secrète)
Le mot de passe réel est la phrase secrète. Puisque le mot de passe est visible par les utilitaires (comme ps sous Unix), cette forme ne devrait être utilisée que là où la sécurité n'est pas importante.
passphrase_passwd_file=(nom_fichier)
Le mot de passe doit être spécifié dans un fichier avec passphrase_passwd_file=(phrase_secrète). Il est fortement recommandé que le fichier soit stocké sur un support sécurisé tel qu'une clé USB personnelle.
passphrase_passwd_fd=(descripteur de fichier)
Le mot de passe est spécifié à travers le descripteur de fichier spécifié.
passphrase_salt=(valeur hex)
Le sel doit être spécifié sous forme de valeur hexadécimale à 16 chiffres.
openssl_keyfile=(nom_fichier)
Le nom de fichier doit être le nom d'un fichier contenant une clé SSL RSA.
openssl_passwd_file=(nom_fichier)
Le mot de passe doit être spécifié dans un fichier avec openssl_passwd=(mot-de-passe-openssl). Il est fortement recommandé que le fichier soit stocké sur un support sécurisé tel qu'une clé USB personnelle.
openssl_passwd_fd=(descripteur de fichier)
Le mot de passe est spécifié à travers le descripteur de fichier spécifié.
openssl_passwd=(mot_de_passe)
Le mot de passe peut être spécifié sur la ligne de commande. Puisque le mot de passe est visible dans la liste des processus, il est fortement recommandé d'utiliser cette option uniquement à des fins de test.

EXEMPLE

La commande suivante montera eCryptfs en superposition sur /secret avec une phrase secrète contenue dans un fichier stocké sur un support sécurisé monté sur /mnt/usb/.

mount -t ecryptfs -o key=passphrase:passphrase_passwd_file=/mnt/usb/file.txt /secret /secret

Où file.txt contient le contenu "passphrase_passwd=[phrase_secrète]".

NOTES

N'exécutez pas eCryptfs en mode verbeux à moins que vous ne le fassiez pour le seul but du développement, car des valeurs secrètes seront écrites dans le journal système dans ce cas. Assurez-vous que votre montage eCryptfs couvre tous les endroits où vos applications peuvent écrire des données sensibles. De plus, utilisez dm-crypt pour chiffrer votre espace d'échange avec une clé aléatoire au démarrage, ou consultez ecryptfs-setup-swap(1).

Les phrases secrètes ont une longueur maximale de 64 caractères.aractères.

BOGUES

Veuillez signaler les bogues sur le système de suivi des bogues d'eCryptfs sur Launchpad.net : https://bugs.launchpad.net/ecryptfs/+filebug.

Pour les bogues du noyau, veuillez suivre la procédure détaillée dans Documentation/oops-tracing.txt pour nous aider à comprendre ce qui se passe.
