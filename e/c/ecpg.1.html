NOM

ecpg - préprocesseur C SQL embarqué

SYNOPIS

ecpg [option...] fichier...

DESCRIPTION

ecpg est le préprocesseur SQL embarqué pour les programmes C. Il convertit les programmes C avec des instructions SQL embarquées en code C normal en remplaçant les invocations SQL par des appels de fonctions spéciaux. Les fichiers de sortie peuvent ensuite être traités avec n'importe quelle chaîne d'outils de compilation C.

ecpg convertira chaque fichier d'entrée donné sur la ligne de commande en fichier de sortie C correspondant. Si un nom de fichier d'entrée n'a aucune extension, .pgc est supposé. L'extension du fichier sera remplacée par .c pour construire le nom du fichier de sortie. Mais le nom du fichier de sortie peut être remplacé en utilisant l'option -o.

Si un nom de fichier d'entrée est juste -, ecpg lit le programme depuis l'entrée standard (et écrit sur la sortie standard, sauf si cela est remplacé avec -o).

Cette page de référence ne décrit pas le langage SQL embarqué. Voir le Chapitre 34 pour plus d'informations sur ce sujet.

OPTIONS

ecpg accepte les arguments de ligne de commande suivants :

-c

Génère automatiquement certains codes C à partir du code SQL. Actuellement, cela fonctionne pour EXEC SQL TYPE.

-C mode

Définit un mode de compatibilité. mode peut être INFORMIX, INFORMIX_SE, ou ORACLE.

-D symbole[=valeur]

Définit un symbole de préprocesseur, de manière équivalente à la directive EXEC SQL DEFINE. Si aucune valeur n'est spécifiée, le symbole est défini avec la valeur 1.

-h

Traite les fichiers d'en-tête. Lorsque cette option est spécifiée, l'extension du fichier de sortie devient .h et non .c, et l'extension par défaut du fichier d'entrée est .pgh et non .pgc. De plus, l'option -c est forcée.

-i

Traite également les fichiers d'inclusion système.

-I répertoire

Spécifie un chemin d'inclusion supplémentaire, utilisé pour trouver les fichiers inclus via EXEC SQL INCLUDE. Les valeurs par défaut sont . (répertoire courant), /usr/local/include, le répertoire d'inclusion PostgreSQL qui est défini lors de la compilation (par défaut : /usr/local/pgsql/include), et /usr/include, dans cet ordre.

-o nomfichier

Spécifie que ecpg doit écrire toutes ses sorties dans le nomfichier donné. Écrire -o - pour envoyer toutes les sorties à la sortie standard.

-r option

Sélectionne le comportement d'exécution. Option peut être l'un des éléments suivants :

no_indicator

N'utilise pas d'indicateurs mais utilise des valeurs spéciales pour représenter les valeurs nulles. Historiquement, certaines bases de données ont utilisé cette approche.

prepare

Prépare toutes les instructions avant de les utiliser. Libecpg conservera un cache des instructions préparées et réutilisera une instruction si elle est exécutée à nouveau. Si le cache est plein, libecpg libérera l'instruction la moins utilisée.

questionmarks

Autorise le point d'interrogation comme espace réservé pour des raisons de compatibilité. C'était le comportement par défaut il y a longtemps.

-t

Active l'autocommit des transactions. Dans ce mode, chaque commande SQL est automatiquement validée sauf si elle se trouve à l'intérieur d'un bloc de transaction explicite. Dans le mode par défaut, les commandes ne sont validées que lorsque EXEC SQL COMMIT est émis.

-v

Affiche des informations supplémentaires, y compris la version et le chemin d'inclusion.

--version

Affiche la version d'ecpg et quitte.

-?
--help

Affiche l'aide sur les arguments de la ligne de commande d'ecpg et quitte.

NOTES

Lors de la compilation des fichiers de code C pré-traités, le compilateur doit pouvoir trouver les fichiers d'en-tête ECPG dans le répertoire d'inclusion de PostgreSQL. Par conséquent, vous devrez peut-être utiliser l'option -I lors de l'invocation du compilateur (par exemple, -I/usr/local/pgsql/include).

Les programmes utilisant du code C avec SQL embarqué doivent être liés à la bibliothèque libecpg, par exemple en utilisant les options de l'éditeur de liens -L/usr/local/pgsql/lib -lecpg.

La valeur de l'un de ces répertoires appropriée à l'installation peut être obtenue en utilisant pg_config(1).

EXEMPLES

Si vous avez un fichier source C avec SQL embarqué nommé prog1.pgc, vous pouvez créer un programme exécutable en utilisant la séquence de commandes suivante :

ecpg prog1.pgc
cc -I/usr/local/pgsql/include -c prog1.c
cc -o prog1 prog1.o -L/usr/local/pgsql/lib -lecpg
