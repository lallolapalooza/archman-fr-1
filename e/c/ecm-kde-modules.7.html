KDEFrameworkCompilerSetting

s

Définit des drapeaux de compilation et de liaison plus stricts pour les modules KDE

Frameworks.

Avertissement

:
N'utilisez pas ce module pour des logiciels qui ne font pa
s partie de KDE-Frameworks. Aucune garantie de rétrocom
patibilité n'est donnée dans les versions plus récentes.

Le module KDECompilerSettings <#kde-module:KDECompilerSettings> est inclus et, en plus, diverses définitions qui affectent les bibliothèques Qt sont définies pour imposer certaines

conventions.

Par exemple, des constructions comme QString("foo") sont interdites, obligeant plutôt à l'utilisation de QLatin1String ou QStringLiteral, et certains mots-clés définis par Qt comme signals et slots ne seront pas

définis.

Note

Il est recommandé d'inclure ce module avec le drapeau

Cette variable ne doit PAS être définie depuis des fichiers CMakeLists.txt, mais est destinée à être définie manuellement lors de la configuration d'un projet qui utilise KDEInstallDirs (p. ex. par les packagers)

.

Si KDE_INSTALL_DIRS_NO_DEPRECATED est défini à TRUE avant d'inclure ce module, les variables obsolètes (listées entre crochets ci-dessus) ne sont pas

définies.

De plus, pour chaque variable KDE_INSTALL_*, une variable CMAKE_INSTALL_* équivalente est définie. Si KDE_INSTALL_DIRS_NO_DEPRECATED est défini à TRUE, seules les variables définies par le module GNUInstallDirs (fourni avec CMake) sont définies. Si KDE_INSTALL_DIRS_NO_CMAKE_VARIABLES est défini à TRUE, aucune variable avec un préfixe CMAKE_ ne sera définie par ce module (à l'exception de CMAKE_INSTALL_DEFAULT_COMPONENT_NAME - voir ci-dessous)

.

Les variables KDE_INSTALL_<dir> (ou leurs équivalents CMAKE_INSTALL_<dir> ou obsolètes) peuvent être passées aux options DESTINATION des commandes install() pour le type de fichier correspondant. Elles sont définies dans le cache CMake, et ainsi les valeurs par défaut ci-dessus peuvent être surchargées par les

utilisateurs.

Notez que si la variable KDE_INSTALL_<dir>, CMAKE_INSTALL_<dir> ou sa forme obsolète est définie avant include(KDEInstallDirs), elle ne sera pas écrasée par KDEInstallDirs. C'est utile si vous voulez, par exemple, utiliser les définitions de variables en ligne de commande de CMake pour définir des valeurs personnalisées. Il y a cependant quelques autres implications dont vous devez être conscient : GNUInstallDirs définit les variables CMAKE_INSTALL_<dir>, donc KDEInstallDirs ne les écrasera pas s'il est inclus plus tard. Dans la plupart des cas, ce n'est pas voulu et si vous devez inclure GNUInstallDirs, vous devriez toujours le faire après avoir inclus KDEInstallDirs

.

Si vous définissez des valeurs personnalisées pour KDE_INSTALL_<dir> ou CMAKE_INSTALL_<dir> comme décrit ci-dessus, les deux formes de la variable seront toujours affectées. L'effet de passer plusieurs formes de la même variable, p. ex. en ligne de commande (comme KDE_INSTALL_BINDIR et CMAKE_INSTALL_BINDIR) est indéfini et doit être

évité.
