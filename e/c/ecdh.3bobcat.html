DESCRIPTIO

N

La classe FBB::ECDH calcule des clés partagées (secrets partagés) en appliquant des clés elliptiques à l'algorithme de Diffie-Hellman (1976). L'algorithme de Diffie-Hellman utilise des informations publiques et privées, fournissant une infrastructure de clé publique (PKI). L'information publique se compose d'une spécification de courbe elliptique et d'une clé publique, qui peuvent être échangées sur des supports non

sécurisés.

L'algorithme de Diffie-Hellman est couramment utilisé pour calculer une clé partagée qui est ensuite utilisée pour chiffrer les informations envoyées entre deux

parties.

Une partie, appelée ici dans cette page man initiateur, spécifie à la construction une courbe elliptique, construit une clé publique et une clé privée, et écrit la clé publique sous forme hexadécimale big-endian, suivie du nom de la courbe elliptique utilisée, dans un fichier. La clé privée de l'initiateur est écrite séparément dans un fichier, car la clé privée est nécessaire pour calculer la clé partagée. Un chiffrement peut être utilisé lors de l'écriture de la clé privée dans le

fichier.

Ensuite, l'initiateur transmet le fichier contenant la clé publique de l'initiateur et le nom de la courbe elliptique utilisée à l'autre partie, appelée ici dans cette page man pair

.

Le pair, ayant reçu le fichier de l'initiateur (clé publique), construit un objet FBB::ECDH. Le constructeur ECDH du pair calcule la clé publique et la clé privée du pair, écrit la clé publique du pair dans un fichier, et construit la clé partagée. Une fois l'objet ECDH du pair construit, le pair peut écrire la clé partagée dans un fichier. La clé privée du pair peut également être écrite dans un fichier, mais cela est facultatif, car la clé privée du pair n'est pas nécessaire pour les calculs ultérieurs. Un chiffrement peut également être utilisé lors de l'écriture de la clé privée du pair dans le

fichier.

Le fichier contenant la clé publique du pair est ensuite envoyé à l'initiateur. L'initiateur construit un objet ECDH en spécifiant les noms de la courbe elliptique utilisée, du fichier contenant la clé privée de l'initiateur, et du nom du fichier contenant la clé publique du pair. Une fois cet objet ECDH construit, le pair peut écrire la clé partagée dans un

fichier.

Les clés partagées de l'initiateur et du pair sont identiques et peuvent être utilisées pour le chiffrement symétrique des informations sensibles partagées entre l'initiateur et le

pair.

Des FBB::Exceptions sont levées si les constructeurs ECDH ou les membres ne peuvent pas accomplir leurs

tâches.

Secret parfait à l'avance et Diffie Hellman

éphémère

L'initiateur et le pair peuvent décider de ne pas sauvegarder leurs informations privées une fois qu'ils ont construit leurs clés partagées, résultant en Secret parfait à l'avance et Diffie Hellman éphémère. Ici, cette procédure est appliquée comme suit

:
o
L'initiateur et le pair ont convenu et échangé de manière sécurisée un secret commun de longue durée, qui peut être utilisé en combinaison avec, par exemple, des méthodes de chiffrement
symétrique.
o
En appliquant la procédure décrite dans la section précédente, les clés privées ne sont pas sauvegardées dans des fichiers, et le processus construisant l'objet ECDH de l'initiateur ne peut pas se terminer, mais doit rester actif jusqu'à ce que la clé publique du pair ait été reçue. Une fois que le processus de l'initiateur a construit la clé publique, cette clé est chiffrée à l'aide du secret commun, puis envoyée au pair. Alternativement, la clé privée de l'initiateur peut être temporairement stockée en mémoire partagée ou temporairement stockée chiffrée dans un
fichier.
o
Le pair, ayant reçu la clé publique de l'initiateur, construit le secret partagé, chiffre la clé publique du pair, et envoie la clé publique chiffrée à
l'initiateur.
o
L'initiateur, à la réception de la clé publique du pair, calcule la clé partagée, soit en continuant le processus de construction temporairement suspendu, soit en récupérant la clé partagée depuis la mémoire ou un fichier, supprimant le stockage (mémoire ou fichier) par la
suite.
o
Puisque les clés privées et les clés publiques ne sont pas stockées ou conservées dans des fichiers, les clés partagées ne peuvent pas être reconstruites, tandis qu'une attaque Man-In-The-Middle est empêchée en n'échangeant que des informations publiques
chiffrées.
o
La clé partagée peut maintenant
être utilisée pour chiffrer une
session de communication

Chiffrement de documents à l'aide de Diffie

Hellman

Comme pour la PKI en général, la méthode d'échange de clés Diffie Hellman n'est normalement pas utilisée pour chiffrer des documents. Au lieu de cela, elle est utilisée pour obtenir une clé qui est utilisée pour des méthodes de chiffrement symétrique comme 3DES ou CBC. Ces méthodes de chiffrement symétrique sont disponibles à travers, par exemple, les classes ISymCryptStream et OSymCryptStrea

m de
Bobcat.

Lancez le programme avec l'un des arguments suivants

o

itiateur séparé. 
#include "main.ih"
int main(int argc, char **argv)
try
{
    if (argc == 1)
    {
        usage(path{ argv[0] }.filename().string());
        return 0;
    }
    if ("curves"s == argv[1])           // show supported ECDH curves.
        cout << ECDH{};
    else if ("init"s == argv[1])        // initiator key construction
    {
                                        // write the file containing
                                        // the curve + public key
        ECDH ecdh{ ECDH::Initiator, "secp384r1", "init.pub" };
                                        // save the initiator’s 
                                       // private key
        ecdh.privKey("init.sec", "use your passphrase");
            // not using encryption:
            // auto initSec = Exception::factory<ofstream>("init.sec");
            // initSec << ecdh.privKey() << ’\n’;
    }
    else if ("priv"s == argv[1])        // initiator key construction
    {
                                        // write the file containing
                                        // the curve + public key
        ECDH ecdh{ ECDH::Initiator, "secp384r1", "init.pub" };
        cout << "wait for the peer’s public key. "
                "Press Enter to continue... ";
        cin.ignore(100, ’\n’);
                                                    // written to file
        auto initShared = Exception::factory<ofstream>("init.shared");
        initShared << ecdh.sharedKey("peer.pub") << ’\n’;  
    }
    else if ("peer"s == argv[1])        // peer’s key construction
    {                                   
                                        // write the peer’s public key
        ECDH ecdh{ ECDH::Peer, "init.pub", "peer.pub" }; 
                                        // save the peer’s private
                                        // key (although not needed)
        auto out = Exception::factory<ofstream>("peer.sec");
        out << ecdh.privKey() << ’\n’;
        out = Exception::factory<ofstream>("peer.shared");
        out << ecdh.sharedKey() << ’\n’;
    }
    else if ("shared"s == argv[1])      // the initiator’s shared key
    {                                   // construction
        ECDH ecdh{ "secp384r1", "peer.pub", "init.sec", 
                                            "use your passphrase" };
        auto initShared = Exception::factory<ofstream>("init.shared");
        initShared << ecdh.sharedKey() << ’\n’;     // written to file
    }
    else 
    {
        usage(path{ argv[0] }.filename().string());
        return 1;
    }
}
catch (exception const &exc)
{
    cerr << "Error: " << exc.what() << ’\n’;
    return 1;
}
catch (...)                     // and handle an unexpected exception
{
    cerr << "unexpected exception\n";
    return 1;
}
