EBFC(1) Manuel des commandes générales EBFC(1)

NOM

ebfc - Compilateur Brainfuck pour ELF

SYNOPSIS

ebfc [OPTIONS] FICHIERSRC

DESCRIPTION

ebfc est un compilateur pour le langage de programmation Brainfuck, créant des fichiers ELF 64 bits ciblant l'architecture Intel x86-64.

ebfc peut créer des exécutables autonomes, des bibliothèques partagées ou des fichiers objet. Les fichiers objet peuvent eux-mêmes être ciblés pour un exécutable autonome, une bibliothèque partagée ou un module dans un programme plus grand.

OPTIONS DE CIBLE DE COMPILATION

Les options suivantes contrôlent le type de fichier source qui est créé. On suppose ici que le nom du fichier source est foo.b.

-x
Compile le code source en un fichier exécutable autonome, nommé foo.
-l
Compile le code source en un fichier de bibliothèque partagée, nommé libfoo.so. Le programme sera exporté en tant que fonction nommée foo().
-c
Compile le code source en une fonction, nommée foo(), dans un fichier objet, nommé foo.o. Le fichier objet sera ciblé pour un module dans un exécutable.
-xc
Compile le code source en un fichier objet, nommé foo.o, qui peut ensuite être lié en tant qu'exécutable autonome.
-lc
Compile le code source en une fonction, nommée foo(), dans un fichier objet, nommé foo.o, qui peut ensuite être lié en tant que bibliothèque partagée.

Si l'argument FICHIERSRC ne possède pas de suffixe .b ou .bf , alors le nom de fichier complet sera utilisé lors de la création du nom du fichier cible et de la fonction. (Dans le cas de -x, le nom du fichier cible sera a.out à la place.)

AUTRES OPTIONS

-a, --arg
Compile la fonction pour qu'elle prenne un argument, à savoir un pointeur vers le tableau d'octets. Par défaut, ebfc compilera son code en une fonction qui ne prend aucun argument, qui utilisera un tableau d'octets interne. Lorsque cette option est utilisée, il n'y a pas de différence dans le fichier objet créé par -c et -lc. (Cette option n'est pas applicable à un exécutable autonome.)
-f, --function=FONCTION
Utilise FONCTION comme nom de la fonction contenant le programme compilé. Si cet argument est omis, le nom de la fonction sera pris depuis le nom du fichier source, comme décrit dans la section précédente.
-i, --input=FICHIER
Utilise FICHIER comme nom du fichier source à placer dans le fichier cible. Cette option ne remplace pas l'argument FICHIERSRC ; elle change simplement le nom stocké dans le fichier objet. (Cette option n'a pas de sens si la cible n'est pas un fichier objet, ou si l'option --strip est utilisée.)
-o, --output=FICHIER
Utilise FICHIER comme nom de fichier cible. Si cette option est omise, le nom de fichier de sortie sera généré à partir du nom du fichier source, comme décrit dans la section précédente.
-s, --strip
Supprime l'inclusion de données inutiles dans le fichier cible. Par défaut, ebfc inclut une section .comment et inclut un symbole dans la table des symboles pour le nom du fichier source. Ces éléments seront supprimés de la sortie lorsque cette option est utilisée. De plus, si la sortie est un exécutable autonome, cette option supprimera l'inclusion de la table des en-têtes de section.
-z, --compressed
Lit le fichier source au format Brainfuck compressé (voir ci-dessous).
--help
Affiche l'aide et quitte.
--version
Affiche le numéro de version et quitte.

LIAISON

Lors de l'appel d'un programme Brainfuck compilé depuis un programme C, le prototype C de la fonction doit avoir la forme :


extern void foo(void);

ou, si l'option --arg est spécifiée :


extern void foo(char *buffer);

Dans ce dernier cas, le tampon pointé par le paramètre de la fonction sera utilisé comme état initial du tampon Brainfuck lorsque la fonction est invoquée, et contiendra à son retour l'état final du tampon.

LE LANGAGE DE PROGRAMMATION BRAINFUCK

Un programme Brainfuck a un pointeur d'octets implicite, appelé « le pointeur », qui peut se déplacer librement dans un tableau d'octets, initialement tous à zéro. Le pointeur lui-même est initialisé pour pointer vers le début de ce tableau. (La taille du tableau n'est pas contrainte par le langage, mais est généralement de 30000 octets ou plus. ebfc donne aux programmes un tableau de 32768 octets.)

Le langage de programmation Brainfuck se compose de huit commandes, chacune représentée par un seul caractère.

>
Incrémente le pointeur.
<
Décrémente le pointeur.
+
Incrémente l'octet au pointeur.
-
Décrémente l'octet au pointeur.
.
Affiche l'octet au pointeur.
,
Lit un octet et le stocke dans l'octet au pointeur.
[
Saute vers le ] correspondant si l'octet au pointeur est zéro.
]
Saute vers le [correspondant.

Tout autre caractère dans le code source est traité comme un commentaire ou un espace blanc, et ignoré.

La sémantique des commandes Brainfuck peut aussi être exprimée succinctement en termes de C, comme suit (en supposant que p a été préalablement défini comme un char*) :

>
devient ++p;
<
devient --p;
+
devient ++*p;
-
devient --*p;
.
devient putchar(*p);
,
devient *p = getchar();
[
devient while (*p) {
]
devient }

Comme en C, le comportement du programme généré est indéfini si le pointeur est déplacé hors du tableau d'octets.

BRAINFUCK COMPRESSÉ

Il existe un format compressé pour stocker et transmettre les programmes Brainfuck, que ebfc peut lire nativement en utilisant l'option --compressed .

Dans le Brainfuck compressé, les huit commandes sont encodées en trois bits comme suit :

+
000
-
001
<
010
>
011
[
100
]
101
,
110
.
111

Chaque octet dans un fichier Brainfuck compressé contient une ou plusieurs commandes. Les deux bits de poids fort sélectionnent entre une des quatre lectures possibles des six bits de poids faible, comme suit :

Encodage Bits
Traduction
singleton 00 abc abc
abc
paire 00 abc def
abc suivi de def
triplet 10 ab cd ef
0ab puis 0cd puis 0ef
répétition 01 abc def
def répété 2 + abc fois (2-9)
0ef répété 2 + abcd fois (2-17)

ERREURS

Le compilateur émettra un message d'erreur et la compilation échouera si le programme contient des commandes de bracket non appariées, ou si le niveau d'imbrication des brackets dépasse la capacité maximale du compilateur (qui est fixée arbitrairement à 256).
