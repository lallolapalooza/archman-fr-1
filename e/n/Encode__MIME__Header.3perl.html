NOM

Encode::MIME::Header -- Encodage MIME pour un corps d'en-tête d'e-mail non structuré

SYNTAXE

use Encode qw(encode decode);
my $mime_str = encode("MIME-Header", "Échantillon:Texte \N{U+263A}");
# $mime_str est "=?UTF-8?B?RcSvY2hhbnRpbG9uOlRleHRlIOK4oA==?="
my $mime_q_str = encode("MIME-Q", "Échantillon:Texte \N{U+263A}");
# $mime_q_str est "=?UTF-8?Q?Q=C3=A9chantillon=3ATexte_=E2=98=BA?="
my $str = decode("MIME-Header",
    "=?ISO-8859-1?B?SWYgeW91IGNhbiByZWFkIHRoaXMgeW8=?=\r\n " .
    "=?ISO-8859-2?B?dSB1bmRlcnN0YW5kIHRoZSBleGFtcGxlLg==?="
);
# $str est "If you can read this you understand the example."
use Encode qw(decode :fallbacks);
use Encode::MIME::Header;
local $Encode::MIME::Header::STRICT_DECODE = 1;
my $strict_string = decode("MIME-Header", $mime_string, FB_CROAK);
# utiliser le décodage strict et planter en cas d'erreur

RÉSUMÉ

Ce module implémente l'encodage MIME RFC 2047 https://tools.ietf.org/html/rfc2047 pour un corps de champ d'en-tête d'e-mail non structuré. Il peut également être utilisé pour le jeton 'text' RFC 822 https://tools.ietf.org/html/rfc822. Cependant, il ne peut pas être utilisé directement pour l'ensemble de l'en-tête avec le nom de champ ni pour les champs d'en-tête structurés tels que De, À, Cc, Message-Id, etc. Il existe 3 noms d'encodage pris en charge par ce module : "MIME-Header", "MIME-B" et "MIME-Q".

DESCRIPTION

La méthode de décodage prend un corps de champ non structuré d'en-tête d'e-mail (ou un jeton 'text' RFC 822 https://tools.ietf.org/html/rfc822) comme entrée et décode chaque mot encodé MIME de la chaîne d'entrée en une séquence d'octets conformément à RFC 2047 https://tools.ietf.org/html/rfc2047 et RFC 2231 https://tools.ietf.org/html/rfc2231. Ensuite, chaque séquence d'octets avec le jeu de caractères MIME correspondant est décodée avec le module Encode et enfin, une chaîne de sortie est retournée. Les parties textuelles de la chaîne d'entrée qui ne contiennent pas de mot encodé MIME restent inchangées dans la chaîne de sortie. Les sauts de ligne repliés entre deux mots encodés MIME consécutifs sont supprimés, les autres sont conservés dans la chaîne de sortie. "MIME-B" peut décoder la variante Base64, "MIME-Q" peut décoder la variante Quoted-Printable et "MIME-Header" peut décoder les deux. Si le module Encode ne prend pas en charge le jeu de caractères MIME particulier ou la variante choisie, une action basée sur les indicateurs CHECK est effectuée (par défaut, le mot encodé MIME n'est pas décodé).

La méthode d'encodage prend une chaîne scalaire en entrée et utilise un encodeur UTF-8 strict pour l'encoder en octets UTF-8. Ensuite, une séquence d'octets UTF-8 est encodée en mots encodés MIME ("MIME-Header" et "MIME-B" utilisent une variante Base64 tandis que "MIME-Q" utilise une variante Quoted-Printable) où chaque mot encodé MIME est limité à 75 caractères. Les mots encodés MIME sont séparés par des "CRLF SPACE" et joints en une seule chaîne de sortie. La chaîne de sortie convient au corps de champ non structuré de l'en-tête de l'e-mail.

Les deux méthodes d'encodage et de décodage propagent les indicateurs CHECK lors de l'encodage et du décodage du jeu de caractères MIME.

BOGUES

Les versions antérieures à 2.22 (incluses dans Encode 2.83) avaient un décodeur et un encodeur défectueux. L'encodeur MIME insérait de manière notoire des espaces supplémentaires ou supprimait des espaces blancs entre des mots encodés MIME consécutifs, ce qui entraînait la production d'en-têtes MIME invalides par ce module. Le décodeur MIME avait tendance à supprimer des espaces blancs, à interpréter incorrectement des données ou à tenter de décoder des mots encodés MIME Base64 comme Quoted-Printable. Ces problèmes ont été corrigés dans la version 2.22. Il est fortement recommandé de ne pas utiliser de version antérieure à 2.22 !

Les versions antérieures à 2.24 (incluses dans Encode 2.87) ignoraient les indicateurs CHECK. L'encodeur MIME utilisait un encodeur non strict pour les chaînes Unicode d'entrée, ce qui pouvait entraîner des séquences UTF-8 invalides. Le décodeur MIME utilisait également un décodeur non strict et appelait en outre la méthode de décodage avec un indicateur "Encode::FB_PERLQQ" (ainsi les indicateurs CHECK spécifiés par l'utilisateur étaient ignorés). De plus, il plantait automatiquement lorsqu'un mot encodé MIME contenait un encodage inconnu. Depuis la version 2.24, ce module utilise un encodeur et un décodeur UTF-8 stricts. Et les indicateurs CHECK sont correctement propagés.

Depuis la version 2.22 (incluse dans Encode 2.83), l'encodeur MIME devrait être entièrement conforme aux RFC 2047 https://tools.ietf.org/html/rfc2047 et RFC 2231 https://tools.ietf.org/html/rfc2231. En raison des bogues susmentionnés dans les versions précédentes de l'encodeur MIME, il existe un mode compatible moins strict pour le décodeur MIME qui est utilisé par défaut. Il devrait être capable de décoder les mots encodés MIME codés par les versions antérieures à 2.22 de ce module. Cependant, notez que ce n'est pas correct selon la RFC 2047 https://tools.ietf.org/html/rfc2047.

En mode non strict par défaut, le décodeur MIME tente de décoder chaque sous-chaîne qui ressemble à un mot encodé MIME. Par conséquent, les mots encodés MIME n'ont pas besoin d'être séparés par des espaces blancs. Pour forcer un mode strict correct, définissez la variable $Encode::MIME::Header::STRICT_DECODE sur 1, par exemple en la localisant :

use Encode::MIME::Header;
local $Encode::MIME::Header::STRICT_DECODE = 1;
