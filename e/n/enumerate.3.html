Description

détaillée

Interface abstraite pour fournir la prise en charge des archives définies par

l'utilisateur.

Avertisseme

nt
Ceci est du matériel avancé et pointu. Vous n'en avez pas besoin à moins de savoir réellement ce que vous faites. La plupart des applications n'auront pas besoin de
ceci.

Historiquement, PhysicsFS fournissait un moyen de monter divers formats de fichiers d'archives et des répertoires physiques dans le système de fichiers natif. Cependant, les applications étaient limitées aux formats de fichiers fournis par la bibliothèque. Cette interface permet à une application de fournir ses propres types de fichiers

d'archives.

Conceptuellement, un PHYSFS_Archiver fournit des entrées de répertoire, tandis que PHYSFS_Io fournit des flux de données pour ces entrées de répertoire. L'utilisation la plus évidente de PHYSFS_Archiver est de fournir la prise en charge d'un type de fichier d'archive qui n'est pas fourni directement par PhysicsFS : peut-être un format propriétaire que seule votre application doit

comprendre.

En interne, toute la prise en charge intégrée des archives utilise cette interface, donc les meilleurs exemples pour construire un PHYSFS_Archiver sont le code source de PhysicsFS

lui-même.

Un archiver est ajouté au système avec PHYSFS_registerArchiver(), et sera ensuite automatiquement disponible pour utilisation avec PHYSFS_mount() ; si une archive donnée peut être gérée par votre archiver, le contrôle lui sera donné selon les

besoins.

Ces méthodes traitent des descripteurs de répertoire. Vous avez une instance de votre archiver, et elle génère un descripteur unique et opaque pour chaque archive ouverte dans sa méthode openArchive(). Puisque la durée de vie d'un Archiver (et non d'une archive) est généralement la durée de vie entière du processus, et qu'il est supposé être un singleton, nous ne fournissons aucune donnée d'instance pour l'archiver lui-même ; l'application peut simplement utiliser des variables statiques si

nécessaire.

Les liens symboliques doivent toujours être suivis (sauf dans stat()) ; PhysicsFS utilisera la méthode stat() pour vérifier la présence de liens symboliques et décider de continuer à appeler les autres méthodes en fonction de

cela.

Les archivers, lorsque c'est nécessaire, doivent définir l'état d'erreur de PhysicsFS avec PHYSFS_setErrorCode() avant de retourner. PhysicsFS transmettra ces erreurs à l'application intactes dans la plupart des

cas.

Sécurité des threads : Les implémentations de PHYSFS_Archiver ne sont pas garanties thread-safe en elles-mêmes. PhysicsFS fournit la sécurité des threads lorsqu'il appelle un archiver donné à l'intérieur de la bibliothèque, mais il ne promet pas que l'utilisation du même PHYSFS_File depuis deux threads à la fois est thread-safe ; en conséquence, votre PHYSFS_Archiver peut supposer que le verrouillage est géré pour vous tant que le PHYSFS_Io que vous retournez depuis PHYSFS_open* ne change aucun de vos états d'Archiver, car le PHYSFS_Io ne sera pas protégé aussi

agressivement.

void(* PHYSFS_Archiver::closeArchive) (void

*opaque)

Détruit une archive précédemment ouverte. Ferme cette archive et libère toute la mémoire associée, y compris le PHYSFS_Io original et (opaque) lui-même, si applicable. L'implémentation peut suppos

er qu'elle ne sera pas appelée s'il reste
des fichiers ouverts depuis cette archive.

PHYSFS_EnumerateCallbackResult(* PHYSFS_Archiver::enumerate) (void *opaque, const char *dirname, PHYSFS_EnumerateCallback cb, const char *origdir, void

*callbackdata)

Liste tous les fichiers dans (dirname). Chaque fichier est passé à (cb), où une copie est faite si approprié, afin que vous puissiez le libérer au retour du rappel. (dirname) est en notation indépendante de la plateforme. Si vous rencontrez une erreur, appelez PHYSFS_SetErrorCode() avec le code qui semble approprié et retournez PHYSFS_ENUM_ERROR. Si le rappel retourne PHYSFS_ENUM_ERROR, veuillez appeler PHYSFS_SetErrorCode(PHYSFS_ERR_APP_CALLBACK) puis retourner PHYSFS_ENUM_ERROR également. N'appelez pas le rappel à nouveau dans aucune circonstance. Si le rappel retourne PHYSFS_ENUM_STOP, arrêtez l'énumération et retournez PHYSFS_ENUM_STOP également. N'appelez pas le rappel à nouveau dans aucune circonstance. Ne définissez pas de code d'erreur dans ce cas. Les rappels ne sont censés retourner qu'une valeur de PHYSFS_EnumerateCallbackResult. Tout autre résultat a un comportement indéfini. Tant que le rappel a retourné PHYSFS_ENUM_OK et que vous n'avez rencontré aucune erreur de votre côté, continuez l'énumération jusqu'à ce que vous ayez terminé, puis retournez PHYSFS_ENUM_OK sans définir de code

d'erreur.

void *(* PHYSFS_Archiver::openArchive) (PHYSFS_Io *io, const char *name, int forWrite, int

*claimed)

Ouvre une archive fournie par (io). C'est ici que les ressources sont allouées et que les données sont analysées lors du montage d'une archive. (name) est un nom de fichier associé à (io), mais ne correspond pas nécessairement à quoi que ce soit, et encore moins à un vrai nom de fichier. Ce nom éventuellement sans signification est en notation dépendante de la plateforme. (forWrite) est non-zéro si ceci doit être utilisé pour le répertoire d'écriture, et zéro si ceci doit être utilisé pour un élément du chemin de recherche. (claimed) devrait être défini à 1 si c'est définitivement une archive que votre implémentation d'archiver peut gérer, même si elle échoue. Nous l'utilisons pour décider si nous devons arrêter d'essayer d'autres archivers si vous échouez à l'ouvrir. Par exemple : l'archiver .zip définira ceci à 1 pour quelque chose qui a une signature de fichier .zip, même s'il a échoué parce que le fichier était aussi tronqué. Pas de sens à essayer d'autres archivers ici, nous avons déjà essayé de le gérer avec l'implémentation appropriée !. Retourne NULL en cas d'échec et définit (claimed) de manière appropriée. Si aucun archiver n'a ouvert l'archive ou n'a défini (claimed), PHYSFS_mount() signalera PHYSFS_ERR_UNSUPPORTED. Sinon, il signalera l'erreur de l'archiver qui a réclamé les données via (cla

imed). Retourne non-NULL en cas de succès. Le pointeur retourné
sera passé comme paramètre "opaque" pour les appels ultérieurs.
