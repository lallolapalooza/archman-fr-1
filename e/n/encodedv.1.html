ENCODE(1) Manuel des commandes générales ENCODE(1)

NOM

encodedv - encode une série d'images dans un flux vidéo numérique

SYNTAXE

encodedv [ options ] modèle_vidéo [ entrée_audio ]

DESCRIPTION

encodedv prend une série d'images au format PPM/PGM/vidéo et, facultativement, un flux audio, et les compile en un flux vidéo encodé en DV. modèle spécifie où se trouvent les données d'entrée et peut être soit - pour l'entrée standard, soit un modèle de style printf prenant un argument numérique qui est remplacé par le numéro de l'image actuelle. Comme image%03d.ppm, qui est développé en image000.ppm, image001.ppm, etc.

--version
affiche le numéro de version de encodedv.
-s, --start-frame=compte
commence l'encodage à l'image numéro compte (par défaut 0).
-e, --end-frame=compte
termine l'encodage à l'image numéro compte (par défaut illimité).
-l, --wrong-interlace
inverse les lignes pour compenser un mauvais entrelacement dans les données d'entrée. Arrivé avec les données générées par mpeg2dec.
-p, --vlc-passes
passes de distribution de code VLC (1-3) des valeurs plus grandes = meilleure qualité mais pas nécessairement un encodage plus lent ! Par défaut pour une meilleure qualité = 3.
-v, --verbose
affiche les statistiques / informations d'état de l'encodeur
-i, --input=nom-filtre
Choisir le filtre d'entrée : [>ppm<, pgm, video] Le filtre ppm ne prend en charge que les fichiers ppm rgb bruts. Le format de fichier pgm est celui généré par mpeg2dec du projet livid. ( http://linuxvideo.org ) Ceci signifie : données Y suivies de données U et V qui sont mises à l'échelle par 2 et placées côte à côte. Cette option est par défaut PPM. Quelques points à garder à l'esprit :

1) Si vous voulez streamer des images vidéo (en utilisant video_pattern = "-") vous devez vous assurer qu'il n'y a pas de données parasites à la fin des images. Ceci est ignoré par la plupart des programmes de manipulation d'images !

2) Si vous faites partie des pauvres personnes avec une carte PCI défectueuse en maître de bus, ayez une sauvegarde à portée de main si vous voulez utiliser la prise en charge vidéo. Certaines versions des chipsets de cartes VIA bloquent votre machine et même votre disque dur. Comme encodedv utilise une capture en pleine résolution, il est plus susceptible de déclencher ces bugs que d'autres programmes. Si vous avez une carte VIA, vous voudrez certainement passer à Linux 2.4.3 ou supérieur.

3) Les images encodées doivent avoir la bonne résolution. Si ce n'est pas le cas, vous pourriez vouloir essayer ppmqscale. Le format vidéo utilisé est choisi par la résolution de l'image. Utilisez 720x576 pour PAL et 720x480 pour NTSC.

4) Si vous voulez accélérer un peu les choses et que vous générez les images d'entrée automatiquement, vous pourriez vouloir essayer les pgm au lieu des ppm car ils sont encodés un peu plus rapidement. Mais gardez à l'esprit que ce format pgm n'est optimal que pour PAL, car NTSC moyenne les valeurs U et V différemment.

-a, --audio-input=nom-filtre
Choisir le filtre d'entrée audio : [>aucun<, wav, dsp]
-o, --output=nom-filtre
Choisir le filtre de sortie : [>brut<]
-q, --static-qno=no-table
Tables qno statiques pour la quantification sur 2 passes VLC. Pour un encodage turbo (mais quelque peu avec perte) essayez -q [1,2] -p [2,3]. Il n'y a que deux tables qno statiques enregistrées actuellement :

1 : pour des images DV nettes

2 : pour un signal de télévision par satellite quelque peu bruyant

Si vous voulez en ajouter d'autres, allez-y ;-)

-f, --fps=numéro-fps
Définir les images par seconde (par défaut : utiliser toutes les images)
-d, --force-dct=mode-dct
Forcer le mode dct (88 ou 248) pour toute l'image

Options d'aide

-?, --help
Afficher le message d'aide.
--usage
Afficher un bref message d'utilisation.
