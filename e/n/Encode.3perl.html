DESCRIPTIO

N

Le module "Encode" fournit l'interface entre les chaînes de caractères Perl et le reste du système. Les chaînes de caractères Perl sont des séquences de caractères

.

Le répertoire de caractères que Perl peut représenter est un ensemble superset de ceux définis par le Consortium Unicode. Sur la plupart des plateformes, les valeurs ordinales d'un caractère telles que retournées par ord(S) sont le codepoint Unicode de ce caractère. Les exceptions sont les plateformes où l'encodage hérité est une variante d'EBCDIC plutôt qu'un superset d'ASCII ; voir

perlebcdic.

Au cours de l'histoire récente, les données sont déplacées sur un ordinateur par morceaux de 8 bits, souvent appelés « octets » mais aussi connus sous le nom d'« octets » dans les documents de normes. Perl est largement utilisé pour manipuler de nombreux types de données : non seulement des chaînes de caractères représentant des langages humains ou informatiques, mais aussi des données « binaires », étant la représentation machine de nombres, de pixels dans une image, ou à peu près n'importe

quoi.

Lorsque Perl traite des « données binaires », le programmeur veut que Perl traite des « séquences d'octets ». Ce n'est pas un problème pour Perl : parce qu'un octet a 256 valeurs possibles, il s'adapte facilement au « caractère logique » beaucoup plus grand de

Perl.

Ce document explique principalement le comment. perlunitut et perlunifaq expliquent le pourquo

i.

UTF-8 vs. utf8 vs.

UTF8 
....Nous considérons maintenant les chaînes non pas comme des séquences d'octets, mais comme des séquences de nombres dans la plage 0 .. 2**32-1 (ou dans le cas des ordinateurs 64 bits, 0 .. 2**64-1) -- Programming Perl, 3rd
ed.

C'est historiquement la notion de UTF-8 de Perl, car c'est ainsi que le UTF-8 a d'abord été conçu par Ken Thompson lorsqu'il l'a inventé. Cependant, grâce aux révisions ultérieures des normes applicables, le UTF-8 officiel est maintenant plutôt plus strict que cela. Par exemple, sa plage est beaucoup plus étroite (0 .. 0x10_FFFF pour couvrir seulement 21 bits au lieu de 32 ou 64 bits) et certaines séquences ne sont pas autorisées, comme celles utilisées dans les paires de substitution (surrogate pairs), les 31 points de code non caractères 0xFDD0 .. 0xFDEF, les deux derniers points de code dans n'importe quel plan (0xXX_FFFE et 0xXX_FFFF), toutes les encodages non les plus courts,

etc.

L'ancien comportement par défaut où Perl utilisait toujours une interprétation lâche du UTF-8 a maintenant été annulé

Retenez bien ceci : à partir de Perl 5.8.7, "UTF-8" signifie UTF-8 dans son sens actuel, qui est conservateur, strict et soucieux de la sécurité, alors que "utf8" signifie UTF-8 dans son ancien sens, qui était libéral, lâche et permissif. La version 2.10 ou ultérieure de "Encode" comprend donc cette distinction subtile mais extrêmement importante entre "UTF-8" et "utf8"

. 
encode("utf8",  "\x{FFFF_FFFF}", 1); # ok
encode("UTF-8", "\x{FFFF_FFFF}", 1); # provoque une erreur
fatale

Cette distinction est également importante pour le décodage. Dans ce qui suit, $s stocke le caractère U+200000, qui dépasse la plage autorisée par UTF-8. $s stocke donc un point de code Unicode invalide

: 
$s = decode("utf8", "\xf8\x88\x80\x80\x80")
;

"UTF-8", en revanche, va soit forcer la conversion de l'entrée en quelque chose de valide

: 
$s = decode("UTF-8", "\xf8\x88\x80\x80\x80"); #
U+FFFD

.. soit provoquer une erreur fatale

: 
decode("UTF-8", "\xf8\x88\x80\x80\x80", FB_CROAK|LEAVE_SRC)
;

Dans le module "Encode", "UTF-8" est en fait un nom canonique pour "utf-8-strict". Ce trait d'union entre le "UTF" et le "8" est crucial ; sans lui, "Encode" devient "libéral" et (peut-être trop-)permissif

: 
find_encoding("UTF-8")->name # est 'utf-8-strict'
find_encoding("utf-8")->name # idem. les noms ne sont pas sensibles à la casse
find_encoding("utf_8")->name # idem. "_" est traité comme "-"
find_encoding("UTF8")->name  # est
'utf8'.

Le drapeau interne UTF8 de Perl s'appelle "UTF8", sans

trait d'union. Il indique si une chaîne est encodée
en interne en "utf8", également sans trait d'union.
