UTILISATION DANS LES

APPLICATIONS

Les utilitaires command, env, nice, nohup, time et xargs ont été spécifiés pour utiliser le code de sortie 127 en cas d'erreur afin que les applications puissent distinguer « échec de la recherche d'un utilitaire » de « l'utilitaire invoqué s'est terminé avec une indication d'erreur ». La valeur 127 a été choisie car elle n'est pas couramment utilisée pour d'autres significations ; la plupart des utilitaires utilisent de petites valeurs pour « les conditions d'erreur normales » et les valeurs supérieures à 128 peuvent être confondues avec la terminaison due à la réception d'un signal. La valeur 126 a été choisie de manière similaire pour indiquer que l'utilitaire a pu être trouvé, mais pas invoqué. Certains scripts produisent des messages d'erreur significatifs différenciant les cas 126 et 127. La distinction entre les codes de sortie 126 et 127 est basée sur la pratique de KornShell qui utilise 127 lorsque toutes les tentatives de exec de l'utilitaire échouent avec [ENOENT], et utilise 126 lorsque toute tentative de exec de l'utilitaire échoue pour toute autre

raison.

Les implémentations historiques de l'utilitaire env utilisent les fonctions execvp() ou execlp() définies dans le volume des interfaces système de POSIX.1‐2017 pour invoquer l'utilitaire spécifié ; cela offre de meilleures performances et évite aux utilisateurs d'avoir à échapper les

caractères ayant une signification spéciale pour le shell. Par conséquent, les fonctions de shel
l, les intégrés spéciaux et les intégrés qui ne sont fournis que par le shell ne sont pas trouvés.

S

La commande suivante

: 
env -i PATH=/mybin:"$
PATH" $(getconf V7_E
NV) mygrep xyz myfile

invoque la commande mygrep avec une nouvelle valeur PATH comme seule entrée dans son environnement, en dehors de toute variable requise par l'implémentation pour la conformité. Dans ce cas, PATH est utilisé pour localiser mygrep, qui est censé se trouver dans /myb

i
n.

env fait avec l'entrée standard, la sortie standard, l'erreur standard, les fichiers d'entrée et les fichiers de sortie. Si une utilitaire est exécutée, elle n'est pas contrainte par la spécification de l'entrée et de la sortie par env

.

L'option -i a été ajoutée pour permettre la fonctionnalité de l'option retirée - d'une manière compatible avec les Directives de syntaxe des utilitaires. Il est possible de créer un environnement non conforme en utilisant l'option -i, car elle peut supprimer des variables d'environnement requises par l'implémentation pour la conformité.
