NOM

encode_keychange - produire la chaîne KeyChange pour SNMPv3

SYNTAXE

encode_keychange -t md5|sha1 [OPTIONS]

DESCRIPTION

encode_keychange produit une chaîne KeyChange en utilisant les anciens et nouveaux mots de passe tels que décrits dans la section 5 du RFC 2274 "User-based Security Model (USM) for version 3 of the Simple Network Management Protocol (SNMPv3)". L'option -t est obligatoire et spécifie le type de transformation de hachage à utiliser.

La transformation est utilisée pour convertir le mot de passe en clé maître pour un utilisateur donné (Ku), convertir la clé maître en clé localisée (Kul), et pour hacher l'ancien Kul avec les bits aléatoires.

Les mots de passe sont obtenus en examinant un certain nombre de sources jusqu'à succès (dans l'ordre indiqué) :

options de ligne de commande (voir les options -N et -O ci-dessous) ;
le fichier $HOME/.snmp/passphrase.ek qui ne devrait contenir que deux lignes avec l'ancien et le nouveau mot de passe ;
l'entrée standard -ou- l'entrée utilisateur depuis le terminal.

OPTIONS

-E [0x]<engineID> EngineID utilisé pour la génération de Kul.
<engineID> est interprété comme une chaîne hexadécimale lorsqu'il est précédé de 0x, sinon il est traité comme une chaîne de texte. Si aucun <engineID> n'est spécifié, il est construit à partir de la première adresse IP de la machine locale.
-f
Forcer la lecture des mots de passe depuis l'entrée standard.
-h
Afficher le message d'aide.
-N "<nouveau_mot_de_passe>"
Mot de passe utilisé pour générer le nouveau Ku.
-O "<ancien_mot_de_passe>"
Mot de passe utilisé pour générer l'ancien Ku.
-P
Désactiver la demande de mots de passe lors de la récupération de données depuis l'entrée standard.
-v
Être verbeux.
-V
Afficher les mots de passe sur le terminal.

VOIR AUSSI

La méthode de clé localisée est définie dans le RFC 2274, sections 2.6 et A.2, et documentée à l'origine dans

U. Blumenthal, N. C. Hien, B. Wijnen, "Key Derivation for Network Management Applications", IEEE Network Magazine, numéro avril/mai, 1997.
