NOM

Encode::GSM0338 -- Encodage ETSI GSM 03.38

SYNTAXE

use Encode qw/encode decode/;
$gsm0338 = encode("gsm0338", $unicode); # charge Encode::GSM0338 implicitement
$unicode = decode("gsm0338", $gsm0338); # idem

DESCRIPTION

GSM0338 est pour les téléphones portables GSM. Bien qu'il partage des alphanumériques avec ASCII, les plages de caractères de contrôle et d'autres parties sont mappées très différemment, principalement pour stocker des caractères grecs. Il existe également des séquences d'échappement (commençant par 0x1B) pour couvrir par exemple le signe Euro.

Ceci était autrefois géré par Encode::Bytes mais en raison de toutes ces spécifications inhabituelles, Encode 2.20 a déplacé le support vers ce module.

Ce module n'implémente que l'*alphabet par défaut GSM 7 bits* et *la table d'extension de l'alphabet par défaut GSM 7 bits* conformément à la norme 3GPP TS 23.038 version 16. Par conséquent, le *National Language Single Shift* et le *National Language Locking Shift* ne sont ni implémentés ni supportés.

Septets

Ce module fonctionne avec des octets (comme tout autre module Encode) et non avec des septets packés (contrairement à d'autres normes GSM). Par conséquent, pour traiter des SMS binaires ou des parties de la charge utile TPDU GSM (3GPP TS 23.040), il est nécessaire de faire la conversion entre octets et septets packés. À cette fin, les fonctions "pack" et "unpack" de Perl peuvent être utiles :

$bytes = substr(pack('(b*)*', unpack '(A7)*', unpack 'b*', $septets), 0, $num_of_septets);
$unicode = decode('GSM0338', $bytes);
$bytes = encode('GSM0338', $unicode);
$septets = pack 'b*', join '', map { substr $_, 0, 7 } unpack '(A8)*', unpack 'b*', $bytes;
$num_of_septets = length $bytes;

Veuillez noter que pour un décodage correct des septets packés, il est nécessaire de connaître le nombre de septets packés dans le tampon binaire, car le tampon binaire est toujours rempli avec des bits de zéros et 7 bits de zéros représentent le caractère "@". Le nombre de septets est également stocké dans la charge utile TPDU lorsqu'on traite avec 3GPP TS 23.040.

BOGUES

Les versions 2.7 et antérieures d'Encode::GSM0338 (partie d'Encode 3.06) géraient incorrectement les octets zéro (caractère "@"). Ceci a été corrigé dans Encode::GSM0338 version 2.8 (partie d'Encode 3.07).
