Encodage

Noms

Les noms d'encodage ne sont pas sensibles à la casse. Les espaces dans les noms sont ignorés. De plus, un encodage peut avoir des alias. Chaque encodage a un nom « canonique ». Le nom « canonique » est choisi parmi les noms de l'encodage en prenant le premier de la séquence suivante (avec quelques exceptions)

.
  • Le nom utilisé par la communauté Perl. Cela inclut 'utf8' et 'ascii'. Contrairement aux alias, les noms canoniques atteignent directement la méthode, de sorte que des mots fréquemment utilisés comme 'utf8' n'ont pas besoin de rechercher
    • d'alias.
  • Le nom MIME tel que défini dans les RFC de l'IETF. Cela inclut tous les « iso-
    • ».
  • Le nom dans le registre
    • IANA.
  • Le nom utilisé p
    • ar l'organisation
qui l'a défini.

Dans le cas où les noms canoniques de jure diffèrent de ceux du module Encode, ils sont toujours aliasés si cela devait être implémenté. Vous pouvez donc savoir en toute sécurité si un encodage donné est implémenté ou non simplement en passant le nom

canonique.

En raison de tous les problèmes d'alias, et parc

e que dans le cas général les encodages ont un
état, « Encode » utilise un objet d'encodage en
interne une fois qu'une opération est en cours.

Encodages pris en

charge

À partir de Perl 5.8.0, au moins les encodages suivants sont reconnus. Notez que sauf indication contraire, ils sont tous insensibles à la casse (via un alias) et toutes les occurrences d'espaces sont remplacées par '-'. En d'autres termes, « ISO 8859 1 » et « iso-8859-1 » sont

identiques.

Les encodages sont catégorisés et implémentés dans plusieurs modules différents, mais vous n'avez pas besoin de « use Encode::XX » pour les rendre disponibles dans la plupart des cas. Encode.pm chargera automatiquement ces modules à la

demande.

i une

description de la façon dont nous faisons comprendre nos caractères aux ordinateurs.

D'abord,
  • nous commençons par quels caractères inclure. Nous appelons cette collection de caractères répertoire de caractères
    • .
  • Ensuite, nous devons attribuer à chaque caractère un identifiant unique afin que votre ordinateur puisse faire la différence entre 'a' et 'A'. Ce répertoire de caractères numérotés est maintenant un jeu de carac
    • tères.
  • Si votre ordinateur peut étendre le jeu de caractères sans traitement supplémentaire, vous pouvez l'utiliser directement. C'est ce qu'on appelle un jeu de caractères codé (CCS) ou un encodage de caractères brut. ASCII est utilisé de cette manière dans la plupart des
    • cas.
  • Mais dans de nombreux cas, en particulier pour les encodages CJK multi-octets, vous devez ajuster un peu plus. Votre connexion réseau peut ne pas accepter de données avec le bit de poids fort (MSB) défini, et votre ordinateur peut ne pas être capable de déterminer si un octet donné est un caractère entier ou seulement la moitié de celui-ci. Vous devez donc encoder le jeu de caractères pour l'utiliser.

    Un schéma d'encodage de caractères (CES) détermine comment encoder un jeu de caractères donné, ou un ensemble de plusieurs jeux de caractères. ISO-2022 7 bits est un exemple de CES. Vous basculez entre les jeux de caractères via des séquences d'échappe

    men
    • t
.

Techniquement, ou mathématiquement parlant, un jeu de caractères encodé dans un tel CES qui fait correspondre caractère par caractère peut former un CCS. EUC est un tel exemple. Le CES d'EUC est le suivant

:
  • Mapper ASCII sans
    • modification.
  • Mapper un tel jeu de caractères qui se compose de 94 ou 96 puissance de N membres en ajoutant 0x80 à chaque
    • octet.
  • Vous pouvez également utiliser 0x8e et 0x8f pour indiquer que l
    • a séquence de caractères suivante appartient à un autre jeu de
caractères. À chaque octet suivant est ajoutée la valeur 0x80.

En examinant attentivement la séquence d'octets encodée, vous pouvez constater que la séquence d'octets correspond à un nombre unique. En ce sens, EUC est un CCS généré par un CES ci-dessus à partir d'au plus quatre CCS (compliqué ?). UTF-8 tombe dans cette catégorie. Voir « UTF-8 » dans perlUnicode pour découvrir comment UTF-8 mappe Unicode vers une séquence

d'octets.

Vous avez peut-être aussi compris pourquoi ISO-2022 7 bits ne peut pas constituer un CCS. Si vous regardez une séquence d'octets \x21\x21, vous ne pouvez pas dire s'il s'agit de deux ! ou d'IDEOGRAPHIC SPACE. EUC mappe le second vers \xA1\xA1, vous n'avez donc aucun problème pour différencier « !! » et «
