ENDHOSTENT(3P) Manuel du programmeur POSIX ENDHOSTENT(3P)

PROLOGUE

Cette page de manuel fait partie du Manuel du programmeur POSIX. L'implémentation Linux de cette interface peut différer (consultez la page de manuel Linux correspondante pour les détails du comportement sous Linux), ou l'interface peut ne pas être implémentée sous Linux.

NOM

endhostent, gethostent, sethostent — fonctions de la base de données des hôtes réseau

SYNTAXE

#include <netdb.h>
void endhostent(void);
struct hostent *gethostent(void);
void sethostent(int stayopen);

DESCRIPTION

Ces fonctions récupèrent des informations sur les hôtes. Ces informations sont considérées comme stockées dans une base de données accessible séquentiellement ou aléatoirement. L'implémentation de cette base de données n'est pas spécifiée.

Note :
Dans de nombreux cas, cette base de données est implémentée par le système Domain Name System (DNS), tel que documenté dans les RFC 1034, 1035 et 1886.

La fonction sethostent() ouvre une connexion à la base de données et définit l'entrée suivante à récupérer comme la première entrée de la base de données. Si l'argument stayopen est non nul, la connexion ne sera pas fermée par un appel à gethostent(), et l'implémentation peut maintenir un descripteur de fichier ouvert.

La fonction gethostent() lit l'entrée suivante dans la base de données, ouvrant et fermant une connexion à la base de données si nécessaire.

Les entrées sont retournées dans des structures hostent.

La fonction endhostent() ferme la connexion à la base de données, libérant tout descripteur de fichier ouvert.

Ces fonctions ne sont pas nécessairement thread-safe.

VALEUR RENVOYÉE

En cas de succès, la fonction gethostent() renvoie un pointeur vers une structure hostent si l'entrée demandée a été trouvée, et un pointeur nul si la fin de la base de données a été atteinte ou si l'entrée demandée n'a pas été trouvée.

L'application ne doit pas modifier la structure vers laquelle pointe la valeur renvoyée, ni les zones de stockage pointées par les pointeurs au sein de la structure. Le pointeur renvoyé, et les pointeurs au sein de la structure, peuvent être invalidés ou la structure ou les zones de stockage peuvent être écrasées par un appel ultérieur à gethostent(). Le pointeur renvoyé, et les pointeurs au sein de la structure, peuvent également être invalidés si le thread appelant est terminé.

ERREURS

Aucune erreur n'est définie pour endhostent(), gethostent() et sethostent().
