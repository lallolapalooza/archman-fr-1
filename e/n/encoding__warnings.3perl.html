encoding::warnings(3perl) Guide de référence du programmeur Perl encoding::warnings(3perl)

NOM

encoding::warnings - Avertir des conversions implicites d'encodage

VERSION

Ce document décrit la version 0.13 de encoding::warnings, publiée le 20 juin 2016.

NOTICE

À partir de Perl 5.26.0, ce module n'a plus d'effet. La fonctionnalité interne de Perl qui était utilisée pour implémenter ce module a été supprimée. Ces dernières années, beaucoup de travaux ont été réalisés sur le cœur de Perl pour éliminer les divergences dans le traitement des chaînes de caractères mises à niveau (upgraded) par rapport à celles déclassées (downgraded). De plus, le pragma "encoding", qui causait de nombreux problèmes, n'est plus pris en charge. Par conséquent, les avertissements produits par ce module ne sont plus nécessaires.

Ainsi, si vous chargez ce module sur Perl 5.26.0, vous recevrez un avertissement indiquant que le module n'est plus pris en charge ; et le module ne fera rien par la suite.

SYNOPSIS

use encoding::warnings; # ou 'FATAL' pour lever des exceptions fatales
utf8::encode($a = chr(20000));  # une chaîne d'octets (octets bruts)
$b = chr(20000);                # une chaîne unicode (caractères larges)
# "Octets implicitement mis à niveau en caractères larges sous iso-8859-1"
$c = $a . $b;

DESCRIPTION

Vue d'ensemble du problème

Par défaut, il existe une asymétrie fondamentale dans le modèle unicode de Perl : la mise à niveau implicite des chaînes d'octets vers des chaînes unicode suppose qu'elles ont été encodées en ISO 8859-1 (Latin-1), mais les chaînes unicode sont déclassées avec un encodage UTF-8. Cela se produit car les 256 premiers points de code Unicode correspondent à Latin-1.

Cependant, cette mise à niveau silencieuse peut facilement causer des problèmes si vous mélangez des chaînes unicode avec des données non-Latin1, c'est-à-dire des chaînes d'octets encodées en UTF-8 ou dans d'autres encodages. L'erreur ne se manifestera qu'au moment où la chaîne combinée sera écrite en sortie, auquel cas il serait impossible de savoir où la mise à niveau silencieuse s'est produite.

Détection du problème

Ce module simplifie le processus de diagnostic de tels problèmes. Il suffit d'ajouter cette ligne en haut de votre programme principal :

use encoding::warnings;

Après cela, la mise à niveau implicite des octets de haut niveau déclenchera un avertissement. Par ex. : "Octets implicitement mis à niveau en caractères larges sous iso-8859-1 à - ligne 7".

Cependant, les chaînes composées uniquement de points de code ASCII (0x00..0x7F) ne déclencheront *pas* cet avertissement.

Vous pouvez également rendre les avertissements fatals en important ce module comme suit :

use encoding::warnings 'FATAL';

Résolution du problème

La plupart du temps, cet avertissement se produit lorsqu'une chaîne d'octets est concaténée avec une chaîne unicode. Il existe plusieurs façons de le résoudre :

  • Mettre à niveau les deux côtés en chaînes unicode

    Si votre programme n'a pas besoin de compatibilité avec Perl 5.6 et versions antérieures, l'approche recommandée est d'appliquer les disciplines d'E/S appropriées, afin que toutes les données de votre programme deviennent des chaînes unicode. Voir encoding, open et "binmode" dans perlfunc pour plus de détails.

  • Déclasser les deux côtés en chaînes d'octets

    L'autre méthode fonctionne aussi, surtout si vous êtes sûr que toutes vos données sont sous le même encodage, ou si la compatibilité avec les anciennes versions de Perl est souhaitée.

    Vous pouvez déclasser les chaînes avec "Encode::encode" et "utf8::encode". Voir Encode et utf8 pour les détails.

  • Spécifier l'encodage pour la mise à niveau implicite des chaînes d'octets

    Si vous êtes certain que toutes les chaînes d'octets seront dans un encodage spécifique comme UTF-8, et que vous n'avez pas besoin de prendre en charge les anciennes versions de Perl, utilisez le pragma "encoding" :

    use encoding 'utf8';

    De même, cela supprimera les avertissements de ce module et conservera le comportement par défaut :

    use encoding 'iso-8859-1';

    Cependant, notez que "use encoding" avait en fait trois effets distincts :

  • Couches PerlIO pour STDIN et STDOUT

    Ceci est similaire à ce que fait le pragma open.

  • Conversions littérales

    Cela transforme toutes les chaînes littérales de votre programme en chaînes unicode (équivalent à un "use utf8"), en les décodant à l'aide de l'encodage spécifié.

  • Mise à niveau implicite pour les chaînes d'octets

    Cela supprimera les avertissements de ce module, comme indiqué ci-dessus.

Comme les conversions littérales fonctionnent également sur les chaînes vides, cela peut surprendre certaines personnes :

use encoding 'big5';
my $byte_string = pack("C*", 0xA4, 0x40);
print length $a;    # 2 ici.
$a .= "";           # concaténation avec une chaîne unicode...
print length $a;    # 1 ici !

Autrement dit, n'utilisez pas "use encoding" sauf si vous êtes certain que le programme ne traitera aucune donnée binaire brute de 8 bits.

Cependant, la variante "Filter => 1" de "use encoding" n'affectera pas la mise à niveau implicite des chaînes d'octets, et est donc incapable de supprimer les avertissements de ce module. Voir encoding pour plus de détails.

CAVEATS

Pour Perl 5.9.4 ou versions ultérieures, l'effet de ce module est lexical.

Pour les versions de Perl antérieures à 5.9.4, ce module affecte l'ensemble du script, au lieu d'agir à l'intérieur de son bloc lexical.
