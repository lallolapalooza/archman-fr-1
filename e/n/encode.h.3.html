BrotliEncoderOperationop, size_t * available_in, const uint8_t ** next_in, size_t * available_out, uint8_t ** next_out, size_t * total_out) Compresse le flux d'entrée vers le flux de sortie. Les valeurs

*available_in

et *available_out doivent spécifier le nombre d'octets adressables à *next_in et *next_out respectivement. Quand *available_out vaut 0, next_out peut être NULL.

Après chaque appel, *available_in sera décrémenté du nombre d'octets d'entrée consommés, et le pointeur *next_in sera incrémenté de ce montant. De même, *available_out sera décrémenté du nombre d'octets de sortie écrits, et le pointeur *next_out sera incrémenté de ce montant.

total_out, s'il n'est pas un pointeur nul, sera défini au nombre d'octets compressés depuis la dernière initialisation d'état.

Le flux de travail interne se compose de 3 tâches :

1.
(facultatif) copier les données d'entrée dans le tampon interne
2.
compresser réellement les données et (facultativement) les stocker dans le tampon interne
3.
(facultatif) copier les octets compressés du tampon interne vers le flux de sortie

Lorsque les 3 tâches ne peuvent plus avancer ou qu'une erreur se produit, cette méthode renvoie le flux de contrôle à l'appelant.

op est utilisé pour effectuer un flush, terminer le flux ou injecter un bloc de métadonnées. Voir BrotliEncoderOperation pour plus d'informations.

Le flush du flux signifie forcer l'encodage de toute l'entrée passée à l'encodeur et compléter le bloc de sortie actuel, afin qu'il puisse être entièrement décodé par le décodeur de flux. Pour effectuer un flush, définissez op sur BROTLI_OPERATION_FLUSH. Dans certaines circonstances (par exemple, manque de capacité du flux de sortie), cette opération nécessitera plusieurs appels à BrotliEncoderCompressStream. La méthode doit être rappelée jusqu'à ce que le flux d'entrée soit épuisé et que l'encodeur n'ait plus de sortie (voir BrotliEncoderHasMoreOutput) après que la méthode ait été appelée.

La fin du flux signifie l'encodage de toute l'entrée passée à l'encodeur et l'ajout de marques 'finales' spécifiques, afin que le décodeur de flux puisse déterminer que le flux est complet. Pour effectuer la fin, définissez op sur BROTLI_OPERATION_FINISH. Dans certaines circonstances (par exemple, manque de capacité du flux de sortie), cette opération nécessitera plusieurs appels à BrotliEncoderCompressStream. La méthode doit être rappelée jusqu'à ce que le flux d'entrée soit épuisé et que l'encodeur n'ait plus de sortie (voir BrotliEncoderHasMoreOutput) après que la méthode ait été appelée.

Avertissement :

Lors du flush et de la fin, op ne doit pas changer tant que l'opération n'est pas terminée ; le flux d'entrée ne doit pas être échangé, réduit ou étendu non plus.

Paramètres :

state instance de l'encodeur
op opération demandée
available_in in : quantité d'entrée disponible ;
out : quantité d'entrée inutilisée
next_in pointeur vers l'octet d'entrée suivant
available_out in : longueur du tampon de sortie ;
out : taille restante du tampon de sortie
next_out curseur du tampon de sortie compressé ; peut être NULL si available_out vaut 0
total_out nombre d'octets produits jusqu'à présent ; peut être NULL

Renvoie :

BROTLI_FALSE s'il y a eu une erreur

const uint8_t* BrotliEncoderTakeOutput (BrotliEncoderState * state, size_t * size)

Acquiert un pointeur vers le tampon de sortie interne. Cette méthode est utilisée pour rendre les liaisons de langage plus faciles et plus efficaces :

1.
pousser les données vers BrotliEncoderCompressStream, jusqu'à ce que BrotliEncoderHasMoreOutput renvoie BROTLI_TRUE
2.
utiliser BrotliEncoderTakeOutput pour lire les octets et les copier vers l'entité spécifique au langage

Cela peut également être utile s'il existe un flux de sortie capable de consommer toutes les données fournies (par exemple, lorsque les données sont sauvegardées dans le système de fichiers).

Attention :

Après chaque appel à BrotliEncoderTakeOutput *size octets de sortie sont considérés comme consommés pour tous les appels consécutifs aux méthodes de l'instance ; le pointeur renvoyé devient également invalide.

Remarque :

La sortie de l'encodeur n'est pas garantie d'être contiguë. Cela signifie qu'après l'appel à BrotliEncoderTakeOutputsans restriction de taille, l'appel immédiatement suivant à BrotliEncoderTakeOutput peut renvoyer plus de données.

Paramètres :

state instance de l'encodeur
size in : nombre d'octets que l'appelant est prêt à prendre, 0 si toute quantité peut être gérée ;
out : quantité de données pointées par le pointeur renvoyé et considérée comme consommée ;
la valeur out n'est jamais supérieure à la valeur in, sauf si elle vaut 0

Renvoie :

pointeur vers les données de sortie
