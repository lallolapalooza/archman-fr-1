ensemble(n)

Paquet: tcl

Licences: TCL

ensemble(n) [incr Tcl] ensemble(n)

NOM

itcl::ensemble - créer ou modifier une commande composite

SYNOPSIS

itcl::ensemble nomEns ?commande arg arg...?

ou

ensemble nomEns {
    part nomPartie args corps
    ...
    ensemble nomPartie {
        part nomSousPartie args corps
        part nomSousPartie args corps
    ...
    }
}

DESCRIPTION

La commande ensemble est utilisée pour créer ou modifier une commande composite. Voir la section QU'EST-CE QU'UN ENSEMBLE ? ci-dessous pour un bref aperçu des ensembles.

Si la commande ensemble trouve un ensemble existant appelé nomEns, elle met à jour cet ensemble. Sinon, elle crée un ensemble appelé nomEns. Si nomEns est un nom simple comme « foo », alors une commande d'ensemble nommée « foo » est ajoutée au contexte d'espace de noms actuel. Si une commande nommée « foo » existe déjà dans ce contexte, elle est supprimée. Si nomEns contient des qualificateurs d'espace de noms comme « a::b::foo », alors le chemin de l'espace de noms est résolu, et la commande d'ensemble est ajoutée à ce contexte d'espace de noms. Les espaces de noms parents comme « a » et « b » sont créés automatiquement, si nécessaire.

Si nomEns contient des espaces comme « a::b::foo bar baz », alors les mots supplémentaires comme « bar » et « baz » sont traités comme des sous-ensembles. Les sous-ensembles ne sont que des parties au sein d'un ensemble ; ils n'ont pas de commande Tcl associée. Un ensemble comme « foo » peut avoir un sous-ensemble appelé « foo bar », qui à son tour peut avoir un sous-ensemble appelé « foo bar baz ». Dans ce cas, le sous-ensemble « foo bar » doit être créé avant le sous-ensemble « foo bar baz » qui s'y trouve.

S'il y a des arguments suivant nomEns, ils sont traités comme des commandes et exécutés pour mettre à jour l'ensemble. Les commandes suivantes sont reconnues dans ce contexte : part et ensemble.

La commande part définit une nouvelle partie pour l'ensemble. Sa syntaxe est identique à celle de la commande proc habituelle, mais elle définit une partie au sein d'un ensemble, au lieu d'une commande Tcl. Si une partie appelée nomPartie existe déjà au sein de l'ensemble, la commande part renvoie une erreur.

La commande ensemble peut être imbriquée dans une autre commande ensemble pour définir un sous-ensemble.

QU'EST-CE QU'UN ENSEMBLE ?

La commande « info » habituelle est une commande composite : le nom de commande info doit être suivi d'une sous-commande comme body ou globals. Nous désignerons une commande comme info comme un ensemble, et les sous-commandes comme body ou globals comme ses parties.

Les ensembles peuvent être imbriqués. Par exemple, la commande info contient un ensemble info namespace. Cet ensemble a des parties comme info namespace all et info namespace children.

Avec les ensembles, les commandes composites peuvent être créées et étendues de manière automatique. N'importe quel paquet peut trouver un ensemble existant et y ajouter de nouvelles parties. Ainsi, les auteurs d'extensions peuvent ajouter leurs propres parties, par exemple, à la commande info.

Le système d'ensembles gère tous les noms de parties et garde une trace des abréviations uniques. Normalement, vous pouvez abréger info complete en info comp. Mais si une extension ajoute la partie info complexity, l'abréviation minimale pour info complete devient info complet.

Le système d'ensembles automatise non seulement la construction des commandes composites, mais aussi la gestion des erreurs. Si vous invoquez une commande d'ensemble sans spécifier de nom de partie, vous obtenez un message d'erreur généré automatiquement qui résume les informations d'utilisation. Par exemple, lorsque la commande info est invoquée sans aucun argument, elle produit le message d'erreur suivant :

mauvais # args : devrait être l'un des suivants...
  info args nomProc
  info body nomProc
  info cmdcount
  info commands ?pattern?
  info complete commande
  info context
  info default nomProc arg nomVar
  info exists nomVar
  info globals ?pattern?
  info level ?nombre?
  info library
  info locals ?pattern?
  info namespace option ?arg arg ...?
  info patchlevel
  info procs ?pattern?
  info protection ?-command? ?-variable? nom
  info script
  info tclversion
  info vars ?pattern?
  info which ?-command? ?-variable? ?-namespace? nom

Vous pouvez également personnaliser la façon dont un ensemble répond aux erreurs. Lorsqu'un ensemble rencontre un nom de partie non spécifié ou ambigu, il recherche une partie appelée @error. Si elle existe, elle est utilisée pour gérer l'erreur. Cette partie recevra tous les arguments de la ligne de commande à partir du nom de partie fautif. Elle peut trouver un autre moyen de résoudre la commande ou générer son propre message d'erreur.

EXEMPLE

Nous pourrions utiliser un ensemble pour nettoyer la syntaxe des différentes commandes « wait » dans Tcl/Tk. Au lieu d'utiliser une série de commandes étranges comme celles-ci :

vwait x
tkwait visibility .top
tkwait window .

nous pourrions utiliser des commandes avec une syntaxe uniforme, comme celle-ci :

wait variable x
wait visibility .top
wait window .

Le paquet Tcl pourrait définir l'ensemble suivant :

itcl::ensemble wait part variable {nom} {
    uplevel vwait $nom
}

Le paquet Tk pourrait ajouter quelques options à cet ensemble, avec une commande comme celle-ci :

itcl::ensemble wait {
    part visibility {nom} {
        tkwait visibility $nom
    }
    part window {nom} {
        tkwait window $nom
    }
}

D'autres extensions pourraient également ajouter leurs propres parties à la commande wait.
