DESCRIPTIO

N

env_parallel est une fonction de shell qui exporte l'environnement courant vers GNU parallel

.

Si la fonction de shell n'est pas chargée, un script factice sera exécuté à la place qui explique comment installer la

fonction.

env_parallel est 100 ms plus lent au démarrage que GNU parallel pur, et prend jusqu'à 30 % de plus pour démarrer une tâche (typiquement 15 ms). En raison du problème de l'espace d'environnement (voir ci-dessous), il est recommandé de ne transférer que l'environnement dont vous avez

besoin.

Pour vous aider à le faire, vous pouvez marquer les noms qui ne doivent pas être transférés. Cela peut être fait avec

soit

--session ou --record-env. # Enregistrer l'environnement "propre" (cela ne doit être fait qu'une seule fois) env_parallel --record-env # Éditer optionnellement ~/.parallel/ignored_vars (nécessaire seulement une fois) # Définir ce que vous voulez utiliser myfunc() { myalias et les fonctions $myvar fonctionnent. $1.; } alias myalias='echo Aliases' myvar='et les variables' # Utiliser --env _ pour ne transférer que les noms qui ne sont pas dans l'environnement "vide" env_parallel

--env _ -S localhost myfunc ::: Hooray 
Ou
:

# Faire --record-env dans $PARALLEL_IGNORED_NAMES env_parallel --session # Définir ce que vous voulez utiliser myfunc() { myalias et les fonctions $myvar fonctionnent. $1.; } alias myalias='echo Aliases' myvar='et les variables' # env_parallel n'exportera pas les noms dans $PARALLEL_IGNORED_NAMES

env_parallel -S localhost myfunc ::: Hooray # Optionnellement env_parallel --end-session

Espace
d'environnement

Par

défaut

env_parallel exportera toutes les variables d'environnement, les tableaux, les alias, les fonctions et les options de shell (voir les détails pour les shells individuels ci-dessous). Mais cela ne fonctionne que si la taille de l'environnement courant est inférieure à la longueur maximale d'une commande et inférieure à la moitié du maximum si l'exécution est distante. Par exemple, la taille max de la commande de Bash est de 128 Ko,

donc

env_parallel échouera si ' set | wc -c' est plus grand que 128 Ko. Techniquement, la limite est dansexecve(1) que IPC::open3 utilise. Les fonctions de complétion de Bash sont connues pour occuper bien plus de 128 Ko d'espace d'environnement et sont la raison principale qui

cause

l'échec de env_parallel

.

À la place, vous pouvez utiliser --env pour spécifier quelles variables, tableaux, alias et fonctions export

er, car cela n'exportera que ceux avec
le nom donné. Ou suivez l'utilisatio
n recommandée montrée dans DESCRIPTION.

OPTION

S

Identiques à GNU parallel en plus de celles-ci

:
--end-sessi
on
Annule la dernière --sessi
on
--record-e
nv
Enregistre tous les noms actuellement définis pour être ignorés à chaque fois que env_parallel est exécuté à
l'avenir.
--sessi
on
Ignore tous les noms actuellement définis. Les alias, variables, tableaux et fonctions actuellement définis ne seront pas transférés.

Mais les noms définis après avoir exécuté parallel --session seront trans

férés.

Cela n'est valide que dans le shell en cours d'exécution, et peut être annulé avec parallel --end-

session.

Vous pouvez exécuter plusieurs --session imbriqués les uns dans

les autres : 
env_parallel --session
var=not
# var est transféré
env_parallel -S
localhost 'echo var est $var' ::: ignored env_parallel --session
# var n'est pas transféré env_parallel -Slocalhost 'echo var est $
var' ::: ignored env_parallel --end-session # var est de nouveau
transféré env_parallel -Slocalhost 'echo var est $var' ::: ignored

BOGUE

S

En raison d'un bogue dans Bash, les alias contenant des sauts de ligne doivent

être suivis par un saut de ligne dans la commande. Certains systèmes ne so
nt pas affectés par ce bogue, mais afficheront un avertissement quand même.

cs

h

env_parallel pour csh casse $PARALLEL, donc n'utilisez pas $PARALLEL.

csh

Installation

Mettez ceci dans $HOME/.cshrc:

source `which env_parallel.csh`

Par exemple, en faisant:

echo 'source `which env_parallel.csh`' >> $HOME/.cshrc

Utilisation prise en charge

--env est pris en charge pour exporter uniquement la variable, l'alias ou le tableau avec le nom donné. Plusieurs --env peuvent être donnés.

alias
alias myecho 'echo aliases'
env_parallel myecho ::: work
env_parallel -S server myecho ::: work
env_parallel --env myecho myecho ::: work
env_parallel --env myecho -S server myecho ::: work
fonctions
Non pris en charge par csh.
variables
set myvar=variables
env_parallel echo '$myvar' ::: work
env_parallel -S server echo '$myvar' ::: work
env_parallel --env myvar echo '$myvar' ::: work
env_parallel --env myvar -S server echo '$myvar' ::: work
tableaux sans caractères spéciaux
set myarray=(arrays work, too)
env_parallel -k echo \$'{myarray[{}]}' ::: 1 2 3
env_parallel -k -S server echo \$'{myarray[{}]}' ::: 1 2 3
env_parallel -k --env myarray echo \$'{myarray[{}]}' ::: 1 2 3
env_parallel -k --env myarray -S server \
  echo \$'{myarray[{}]}' ::: 1 2 3

    env_parallel(1)

    Exécute des commandes en parallèle et définit des variables d'environnement pour chaque exécution.

    SYNOPSIS

    env_parallel [OPTION]... COMMANDE [ARG...]

    env_parallel [OPTION]... COMMANDE : ARG...

    env_parallel [OPTION]... COMMANDE ::: ARG...

    DESCRIPTION

    env_parallel exécute des commandes en parallèle. Il est similaire à GNU Parallel, mais il est destiné à des cas d'utilisation plus simples où vous souhaitez simplement exécuter une commande pour chaque ligne d'une entrée standard, et où vous souhaitez définir des variables d'environnement pour chaque exécution.

    Les arguments de ligne de commande sont lus à partir de l'entrée standard, un par ligne. Pour chaque ligne, la COMMANDE est exécutée avec les arguments donnés, et la ligne est passée à la commande comme argument supplémentaire (généralement comme dernier argument). Des variables d'environnement peuvent être définies pour chaque exécution en utilisant l'option -e.

    OPTIONS

    -j, --jobs=N
    Exécute jusqu'à N jobs en parallèle. La valeur par défaut est le nombre de cœurs CPU.
    -k, --keep-order
    Garde l'ordre de la sortie tel qu'il est entré.
    -e, --env=NOM=VALEUR
    Définit la variable d'environnement NOM à VALEUR pour chaque exécution de la commande.
    -E, --env-file=FICHIER
    Lit les variables d'environnement à partir du FICHIER. Le fichier doit être au format NOM=VALEUR, une variable par ligne.
    -p, --pipe
    Utilise un pipe pour passer les arguments de la commande à l'entrée standard de la commande.
    -P, --pipe-mode=MODE
    Définit le mode du pipe. Les modes possibles sont line (par défaut), byte, chunk.
    -s, --silent
    Ne pas afficher la sortie des commandes.
    -v, --verbose
    Afficher les commandes exécutées.
    -h, --help
    Afficher ce message d'aide et quitter.
    -V, --version
    Afficher les informations de version et quitter.

    SUPPORTED SHELLS

    env_parallel est implémenté en shell script et devrait fonctionner sur la plupart des shells POSIX.

    EXIT STATUS

    Retourne 0 si toutes les commandes se sont terminées avec succès, sinon retourne le code de sortie du premier échec.
