ENDUTXENT(3P) Manuel du programmeur POSIX ENDUTXENT(3P)

PROLOGUE

Cette page manuelle fait partie du Manuel du programmeur POSIX. L'implémentation Linux de cette interface peut différer (consultez la page manuelle Linux correspondante pour plus de détails sur le comportement de Linux), ou l'interface peut ne pas être implémentée sur Linux.

NOM

endutxent, getutxent, getutxid, getutxline, pututxline, setutxent — fonctions de la base de données de comptabilité des utilisateurs

SYNOPSIS

#include <utmpx.h>
void endutxent(void);
struct utmpx *getutxent(void);
struct utmpx *getutxid(const struct utmpx *id);
struct utmpx *getutxline(const struct utmpx *line);
struct utmpx *pututxline(const struct utmpx *utmpx);
void setutxent(void);

DESCRIPTION

Ces fonctions fournissent un accès à la base de données de comptabilité des utilisateurs.

La fonction getutxent() lit l'entrée suivante de la base de données de comptabilité des utilisateurs. Si la base de données n'est pas déjà ouverte, elle l'ouvre. Si elle atteint la fin de la base de données, elle échoue.

La fonction getutxid() recherche vers l'avant à partir du point courant dans la base de données. Si la valeur ut_type de la structure utmpx pointée par id est BOOT_TIME, OLD_TIME ou NEW_TIME, elle s'arrête lorsqu'elle trouve une entrée dont la valeur ut_type correspond. Si la valeur ut_type est INIT_PROCESS, LOGIN_PROCESS, USER_PROCESS ou DEAD_PROCESS, elle s'arrête lorsqu'elle trouve une entrée dont le type est l'un de ces quatre et dont le membre ut_id correspond au membre ut_id de la structure utmpx pointée par id. Si la fin de la base de données est atteinte sans correspondance, getutxid() échoue.

La fonction getutxline() recherche vers l'avant à partir du point courant dans la base de données jusqu'à ce qu'elle trouve une entrée de type LOGIN_PROCESS ou USER_PROCESS qui a également une valeur ut_line correspondant à celle de la structure utmpx pointée par line. Si la fin de la base de données est atteinte sans correspondance, getutxline() échoue.

La fonction getutxid() ou getutxline() peut mettre en cache des données. Pour cette raison, afin d'utiliser getutxline() pour rechercher plusieurs occurrences, l'application doit mettre à zéro les données statiques après chaque succès, sinon getutxline() peut retourner un pointeur vers la même structure utmpx .

Il existe une exception à la règle concernant la remise à zéro de la structure avant des lectures ultérieures. La lecture implicite effectuée par pututxline() (si elle constate qu'elle n'est pas déjà à la bonne place dans la base de données de comptabilité des utilisateurs) ne doit pas modifier la structure statique retournée par getutxent(), getutxid(), ou getutxline(), si l'application a modifié cette structure et a passé le pointeur à pututxline().

Pour toutes les entrées correspondant à une requête, le membre ut_type indique le type de l'entrée. Les autres membres de l'entrée doivent contenir des données significatives basées sur la valeur du membre ut_type comme suit :

Membre ut_type Autres membres avec des données significatives
EMPTY Aucun autre
BOOT_TIME ut_tv
OLD_TIME ut_tv
NEW_TIME ut_tv
USER_PROCESS ut_id, ut_user (nom de connexion de l'utilisateur), ut_line, ut_pid, ut_tv
INIT_PROCESS ut_id, ut_pid, ut_tv
LOGIN_PROCESS ut_id, ut_user (nom du processus de connexion défini par l'implémentation), ut_line, ut_pid, ut_tv
DEAD_PROCESS ut_id, ut_pid, ut_tv

Une implémentation qui fournit des contrôles de sécurité étendus peut imposer des restrictions définies par l'implémentation sur l'accès à la base de données de comptabilité des utilisateurs. En particulier, le système peut nier l'existence de certaines ou de toutes les entrées de la base de données de comptabilité des utilisateurs associées à des utilisateurs autres que l'appelant.

Si le processus dispose des privilèges appropriés, la fonction pututxline() doit écrire la structure dans la base de données de comptabilité des utilisateurs. Elle doit rechercher un enregistrement comme par getutxid() qui satisfait la requête. Si cette recherche réussit, l'entrée est remplacée. Sinon, une nouvelle entrée est créée à la fin de la base de données de comptabilité des utilisateurs.

La fonction endutxent() doit fermer la base de données de comptabilité des utilisateurs.

La fonction setutxent() doit réinitialiser la lecture au début de la base de données. Cela doit être fait avant chaque recherche d'une nouvelle entrée si l'on souhaite examiner l'ensemble de la base de données.

Ces fonctions n'ont pas besoin d'être sûres pour les threads.

VALEUR RENVOYÉE

À l'issue d'une exécution réussie, getutxent(), getutxid(), et getutxline() doivent retourner un pointeur vers une structure utmpx contenant une copie de l'entrée demandée dans la base de données de comptabilité des utilisateurs. Sinon, un pointeur nul doit être retourné.

La valeur retournée peut pointer vers une zone statique qui est écrasée par un appel ultérieur à getutxid() ou getutxline().

À l'issue d'une exécution réussie, pututxline() doit retourner un pointeur vers une structure utmpx contenant une copie de l'entrée ajoutée à la base de données de comptabilité des utilisateurs. Sinon, un pointeur nul doit être retourné.

Les fonctions endutxent() et setutxent() ne doivent retourner aucune valeur.

ERREURS

Aucune erreur n'est définie pour les fonctions endutxent(), getutxent(), getutxid(), getutxline(), et setutxent().
