ENC2XS(1perl) Guide de référence des programmeurs Perl ENC2XS(1perl)

NOM

enc2xs -- Générateur de modules Perl Encode

SYNTAXE

enc2xs -[options]
enc2xs -M ModName mapfiles...
enc2xs -C

DESCRIPTION

enc2xs construit une extension Perl à utiliser par Encode, soit à partir de fichiers de mappage de caractères Unicode (.ucm), soit à partir de fichiers d'encodage Tcl (.enc). En plus d'être utilisé en interne pendant le processus de construction du module Encode, vous pouvez utiliser enc2xs pour ajouter votre propre encodage à Perl. Aucune connaissance de XS n'est nécessaire.

Guide rapide

Si vous voulez en savoir le moins possible sur Perl mais que vous avez besoin d'ajouter un nouvel encodage, lisez simplement ce chapitre et oubliez le reste.

0.
Ayez un fichier .ucm prêt. Vous pouvez le récupérer quelque part, l'écrire vous-même à partir de zéro, ou en prendre un dans la distribution Encode et le personnaliser. Pour le format UCM, voir le chapitre suivant. Dans l'exemple ci-dessous, j'appellerai mon encodage théorique myascii, défini dans my.ucm. "$" est une invite de shell. 
$ ls -F
my.ucm
1.
Exécutez une commande comme suit ; 
$ enc2xs -M My my.ucm
generating Makefile.PL
generating My.pm
generating README
generating Changes

Regardez maintenant votre répertoire courant. Il devrait ressembler à ceci.

$ ls -F
Makefile.PL   My.pm         my.ucm        t/

Les fichiers suivants ont été créés.

Makefile.PL - Script MakeMaker
My.pm       - Sous-module Encode
t/My.t      - Fichier de test
1.1.
Si vous souhaitez que les fichiers *.ucm soient installés avec les modules, procédez comme suit ; 
$ mkdir Encode
$ mv *.ucm Encode
$ enc2xs -M My Encode/*ucm
2.
Modifiez les fichiers générés. Vous n'êtes pas obligé de le faire si vous n'avez pas le temps ET aucune intention de le donner à quelqu'un d'autre. Mais c'est une bonne idée d'éditer le pod et d'ajouter plus de tests.
3.
Émettez maintenant une commande que tous les Perl Mongers adorent : 
$ perl Makefile.PL
Writing Makefile for Encode::My
4.
Maintenant, tout ce que vous avez à faire est de faire. 
$ make
cp My.pm blib/lib/Encode/My.pm
/usr/local/bin/perl /usr/local/bin/enc2xs -Q -O \
  -o encode_t.c -f encode_t.fnm
Reading myascii (myascii)
Writing compiled form
128 bytes in string tables
384 bytes (75%) saved spotting duplicates
1 bytes (0.775%) saved using substrings
....
chmod 644 blib/arch/auto/Encode/My/My.bs
$

Le temps nécessaire varie en fonction de la vitesse de votre machine et de la taille de votre encodage. À moins que vous ne travailliez sur quelque chose de grand comme euc-tw, cela ne prendra pas trop de temps.

5.
Vous pouvez déjà faire "make install", mais vous devriez tester d'abord. 
$ make test
PERL_DL_NONLAZY=1 /usr/local/bin/perl -Iblib/arch -Iblib/lib \
  -e 'use Test::Harness  qw(&runtests $verbose); \
  $verbose=0; runtests @ARGV;' t/*.t
t/My....ok
All tests successful.
Files=1, Tests=2,  0 wallclock secs
 ( 0.09 cusr + 0.01 csys = 0.09 CPU)
6.
Si vous êtes satisfait du résultat des tests, faites simplement "make install"
7.
Si vous souhaitez ajouter votre encodage à la liste de chargement à la demande d'Encode (afin de ne pas avoir à taper "use Encode::YourEncoding"), exécutez 
enc2xs -C

pour mettre à jour Encode::ConfigLocal, un module qui contrôle les paramètres locaux. Après cela, "use Encode;" suffira à charger vos encodages à la demande.

La carte de caractères Unicode

Encode utilise le format UCM (Unicode Character Map) pour les mappages de caractères source. Ce format est utilisé par le package ICU d'IBM et a été adopté par Nick Ing-Simmons pour être utilisé avec le module Encode. Comme UCM est plus flexible que le mappage d'encodage de Tcl et beaucoup plus convivial, c'est le format recommandé pour Encode maintenant.

Un fichier UCM ressemble à ceci.

#
# Commentaires
#
<code_set_name> "US-ascii" # Obligatoire
<code_set_alias> "ascii"   # Optionnel
<mb_cur_min> 1             # Obligatoire; généralement 1
<mb_cur_max> 1             # Max. # d'octets/caractère
<subchar> \x3F             # Caractère de substitution
#
CHARMAP
<U0000> \x00 |0 # <control>
<U0001> \x01 |0 # <control>
<U0002> \x02 |0 # <control>
....
<U007C> \x7C |0 # BARRE VERTICALE
<U007D> \x7D |0 # ACCCOLADE DROITE
<U007E> \x7E |0 # TILDE
<U007F> \x7F |0 # <control>
END CHARMAP
  • Tout ce qui suit "#" est traité comme un commentaire.
  • La section d'en-tête se poursuit jusqu'à une ligne contenant le mot CHARMAP. Cette section a une forme de <mot-clé> valeur, une paire par ligne. Les chaînes utilisées comme valeurs doivent être mises entre guillemets. Les mots nus sont traités comme des nombres. \xXX représente un octet.

    La plupart des mots-clés sont explicites. subchar signifie caractère de substitution, pas sous-caractère. Lorsque vous décodez une séquence Unicode vers cet encodage mais qu'aucun caractère correspondant n'est trouvé, la séquence d'octets définie ici sera utilisée. Pour la plupart des cas, la valeur ici est \x3F ; en ASCII, c'est un point d'interrogation.

  • CHARMAP démarre la section de mappage de caractères. Chaque ligne a la forme suivante : 
    <UXXXX> \xXX.. |0 # commentaire
  ^     ^      ^
  |     |      +- Indicateur de repli
  |     +-------- Séquence d'octets encodée
  +-------------- Identifiant de caractère Unicode en hexadécimal

    Le format est approximativement le même que celui d'une section d'en-tête, sauf pour l'indicateur de repli : | suivi de 0..3. La signification des valeurs possibles est la suivante :

|0
Sûr pour l'aller-retour. Un caractère décodé en Unicode se ré-encode dans la même séquence d'octets. La plupart des caractères ont cet indicateur.
|1
Repli pour unicode -> encodage. Lorsqu'il est vu, enc2xs ajoute ce caractère uniquement pour la carte d'encodage.
|2
Ignorer le mappage de caractère de substitution s'il n'y a pas de point de code.
|3
Repli pour encodage -> unicode. Lorsqu'il est vu, enc2xs ajoute ce caractère uniquement pour la carte de décodage.
•
Et enfin, END OF CHARMAP termine la section.

Lorsque vous créez manuellement un fichier UCM, vous devriez copier ascii.ucm ou un encodage existant qui est proche du vôtre, plutôt que d'écrire le vôtre à partir de zéro.

Lorsque vous le faites, assurez-vous de laisser au moins U0000 à U0020 tels quels, sauf si votre environnement est EBCDIC.

AVERTISSEMENT : toutes les fonctionnalités d'UCM ne sont pas implémentées. Par exemple, icu:state n'est pas utilisé. Pour cette raison, vous devez écrire un module Perl si vous souhaitez prendre en charge les encodages algorithmiques, notamment la série ISO-2022. Ces modules incluent Encode::JP::2022_JP, Encode::KR::2022_KR et Encode::TW::HZ.

Gérer les mappages dupliqués

Lorsque vous créez un mappage, vous DEVEZ rendre vos mappages sûrs pour l'aller-retour. C'est-à-dire, encode('votre-encodage', decode('votre-encodage', $data)) eq $data s'applique à tous les caractères marqués comme "|0". Voici comment vous assurer :

  • Triez votre mappage par ordre Unicode.
  • Lorsque vous avez une entrée dupliquée, marquez l'une ou l'autre avec '|1' ou '|3'.
  • Et assurez-vous que l'entrée '|1' ou '|3' SUIT l'entrée '|0'.

Voici un exemple de big5-eten.

<U2550> \xF9\xF9 |0
<U2550> \xA2\xA4 |3

Interne, la carte Encodage -> Unicode et la carte Unicode -> Encodage ressemblent à ceci ;

E vers U               U vers E
--------------------------------------
\xF9\xF9 => U2550    U2550 => \xF9\xF9
\xA2\xA4 => U2550

C'est donc sûr pour l'aller-retour pour \xF9\xF9. Mais si la ligne ci-dessus est inversée, voici ce qui se passe.

E vers U               U vers E
--------------------------------------
\xA2\xA4 => U2550    U2550 => \xF9\xF9
( \xF9\xF9 => U2550 est maintenant écrasé !)

Le package Encode est livré avec ucmlint, un utilitaire brut mais suffisant pour vérifier l'intégrité d'un fichier UCM. Vérifiez sous le répertoire Encode/bin pour cela.

En cas de doute, vous pouvez utiliser ucmsort, encore un autre utilitaire sous le répertoire Encode/bin.
