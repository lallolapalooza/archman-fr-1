ENDPROTOENT(3P) Manuel du programmeur POSIX ENDPROTOENT(3P)

PROLOGUE

Cette page de manuel fait partie du Manuel du programmeur POSIX. L'implémentation Linux de cette interface peut différer (consulter la page de manuel Linux correspondante pour les détails du comportement de Linux), ou l'interface peut ne pas être implémentée sous Linux.

NOM

endprotoent, getprotobyname, getprotobynumber, getprotoent, setprotoent — fonctions de base de données des protocoles réseau

SYNTAXE

#include <netdb.h>
void endprotoent(void);
struct protoent *getprotobyname(const char *name);
struct protoent *getprotobynumber(int proto);
struct protoent *getprotoent(void);
void setprotoent(int stayopen);

DESCRIPTION

Ces fonctions permettent de récupérer des informations sur les protocoles. Ces informations sont considérées comme stockées dans une base de données accessible séquentiellement ou aléatoirement. L'implémentation de cette base de données n'est pas spécifiée.

La fonction setprotoent() ouvre une connexion à la base de données et positionne l'entrée suivante sur la première entrée. Si l'argument stayopen est différent de zéro, la connexion à la base de données des protocoles réseau ne sera pas fermée après chaque appel à getprotoent() (directement ou indirectement via l'une des autres fonctions getproto*()), et l'implémentation peut maintenir un descripteur de fichier ouvert pour la base de données.

La fonction getprotobyname() recherche dans la base de données à partir du début et trouve la première entrée pour laquelle le nom de protocole spécifié par name correspond au membre p_name, ouvrant et fermant une connexion à la base de données si nécessaire.

La fonction getprotobynumber() recherche dans la base de données à partir du début et trouve la première entrée pour laquelle le numéro de protocole spécifié par proto correspond au membre p_proto, ouvrant et fermant une connexion à la base de données si nécessaire.

La fonction getprotoent() lit l'entrée suivante de la base de données, ouvrant et fermant une connexion à la base de données si nécessaire.

Les fonctions getprotobyname(), getprotobynumber() et getprotoent() retournent chacune un pointeur vers une structure protoent, dont les membres contiennent les champs d'une entrée dans la base de données des protocoles réseau.

La fonction endprotoent() ferme la connexion à la base de données, libérant tout descripteur de fichier ouvert.

Ces fonctions ne sont pas nécessairement thread-safe.

VALEUR DE RETOUR

En cas de succès, getprotobyname(), getprotobynumber() et getprotoent() retournent un pointeur vers une structure protoent si l'entrée demandée a été trouvée, et un pointeur nul si la fin de la base de données a été atteinte ou si l'entrée demandée n'a pas été trouvée. Sinon, un pointeur nul est retourné.

L'application ne doit pas modifier la structure vers laquelle pointe la valeur de retour, ni les zones de mémoire pointées par les pointeurs dans la structure. Le pointeur retourné, ainsi que les pointeurs dans la structure, peuvent être invalidés ou la structure ou les zones de mémoire peuvent être écrasés par un appel ultérieur à getprotobyname(), getprotobynumber() ou getprotoent(). Le pointeur retourné, ainsi que les pointeurs dans la structure, peuvent également être invalidés si le thread appelant est terminé.
