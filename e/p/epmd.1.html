Ce démon agit comme un serveur de noms sur tous les hôtes impliqués dans des calculs Erlang distribués. Lorsqu'un nœud Erlang démarre, le nœud a un nom et obtient une adresse du noyau du système d'exploitation de l'hôte. Le nom et l'adresse sont envoyés au démon epmd en cours d'exécution sur l'hôte local. Dans un environnement TCP/IP, l'adresse se compose de l'adresse IP et d'un numéro de port. Le nom de nœud est un atome de la forme Name@Node. Le rôle du démon epmd est de garder une trace de quel nom de nœud écoute sur quelle adresse. Par conséquent, epmd mappe les noms de nœuds symboliques aux adresses des

machines.

Le démon epmd TCP/IP ne garde trace que de la partie Name (première) d'un nom de nœud Erlang. La partie Host (ce qui se trouve après le @) est implicite dans le nom du nœud où le démon epmd a été contacté, tout comme l'adresse IP à laquelle le nœud Erlang peut être atteint. Des services de noms TCP cohérents et corrects sont donc nécessaires au bon fonctionnement d'un réseau

Erlang.

NOTE : Sur Windows, le nombre maximal de nœuds autorisés dans une instance epmd est de 60. Cela est dû à des limitations de l'implémentation actuelle. Si vous avez besoin de plus de nœuds, vous devriez envisager d'utiliser une implémentation d'epmd basée sur Erlang telle que Erlang

EPMD.

Démarrage du démon de mappage de

ports
Le démon est démarré automatiquement par la commande erl(1) si le nœud doit être distribué et qu'aucune instance en cours d'exécution n'est présente. S'il est lancé automatiquement, des variables d'environnement doivent être utilisées pour modifier le comportement du démon ; voir la section Variables d'environnement.

Si l'argument -daemon n'est pas spécifié, epmd s'exécute comme un programme normal avec le terminal de contrôle du shell à partir duquel il est démarré. Normalement, il doit être exécuté comme un

démon.

régulières.

-debug

-relaxed_command_chec

k
Démarre le programme epmd avec une vérification des commandes détendue (principalement pour des raisons de compatibilité ascendante). Cela affecte ce qui suit :
•Avec une vérification des commandes détendue, le démon epmd peut être tué depuis l'hôte local avec, par exemple, la commande epmd -kill même si des nœuds actifs sont enregistrés. Normalement, seuls les démons avec une base de données de nœuds vide peuvent être tués avec epmd -k

Cela est dû au fait qu'elle peut causer une situation étrange où deux nœuds du même nom peuvent être actifs en même temps. Un nœud se désenregistre lui-même en fermant simplement la connexion à epmd, c'est pourquoi la commande stop n'était destinée qu'à être utilisée dans des situations de débogage.
