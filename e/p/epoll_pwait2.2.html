DESCRIPTIO

N

L'appel système epoll_wait() attend des événements sur l'instance epoll(7) désignée par le descripteur de fichier epfd. Le tampon pointé par events est utilisé pour renvoyer des informations provenant de la liste prête concernant les descripteurs de fichier de la liste d'intérêt qui ont des événements disponibles. Jusqu'à n sont renvoyés par epoll_wait(). L'argument n doit être supérieur à

zéro.

L'argument timeout spécifie le nombre de millisecondes pendant lesquelles epoll_wait() sera bloqué. Le temps est mesuré par rapport à l'horloge CLOCK_MONOTONIC

.

Un appel à epoll_wait() sera bloqué jusqu'à ce que l'une des conditions suivantes soit remplie

:
•
un descripteur de fichier délivre un événement
;
•
l'appel est interrompu par un gestionnaire de signal ;
ou
•
le délai
d'attent
e expire.

Notez que l'intervalle d'attente sera arrondi à la granularité de l'horloge système, et les retards d'ordonnancement du noyau signifient que l'intervalle de blocage peut être dépassé d'un petit montant. Spécifier un timeout de -1 fait que epoll_wait() se bloque indéfiniment, tandis que spécifier un timeout égal à zéro fait que epoll_wait() renvoie immédiatement, même si aucun événement n'est

disponible.

La structure struct epoll_event est décrite dans epoll_event(3

type).

Le champ data de chaque structure epoll_event renvoyée contient les mêmes données que celles spécifiées lors du dernier appel à epoll_ctl(2) (EPOLL_CTL_ADD, EPOLL_CTL_MOD) pour le descripteur de fichier ouvert

correspondant.

Le champ events est un masque de bits qui indique les événements survenus pour la description de fichier ouverte correspondante. Voir epoll_ctl(2) pour la liste des bits qui peuvent apparaître dans ce

masque.

epoll_pwait(

)

La relation entre epoll_wait() et epoll_pwait() est analogue à la relation entre select(2) et pselect(2) : comme pselect(2), epoll_pwait() permet à une application d'attendre en toute sécurité qu'un descripteur de fichier devienne prêt ou qu'un signal soit

capté.

L'appel epoll_pwait() suivant

: 


ready = epoll_pwait(epfd, &events, n, timeout, &sigmask)
;

est équivalent à l'exécution atomique des appels suivants

: 


sigset_t origmask;
pthread_sigmask(SIG_SETMASK, &sigmask, &origmask);
ready = epoll_wait(epfd, &events, n, timeout);
pthread_sigmask(SIG_SETMASK, &origmask, NULL)
;

L'argument sigmask peut être spécifié comme NULL, auquel cas epoll_pwait() est équivalent à epoll_

wait
().

epoll_pwait2(

)

L'appel système epoll_pwait2() est équivalent à epoll_pwait() sauf pour l'argument timeout. Il prend un argument de type timespec pour pouvoir spécifier un délai d'attente avec une résolution en nanosecondes. Cet argument fonctionne de la même manière que dans pselect(2) et ppoll(2). Si timeout est NULL, alors epoll_pwait2() peut

se bl
oquer ind
éfiniment.

indiquer
l'erreur.

NOTE

S

Pendant qu'un fil d'exécution est bloqué dans un appel à epoll_wait(), il est possible qu'un autre fil d'exécution ajoute un descripteur de fichier à l'instance epoll sur laquelle on attend. Si le nouveau descripteur de fichier devient prêt, il provoquera le déblocage de l'appel epoll_wai

t().

Si plus de n descripteurs de fichier sont prêts lorsque epoll_wait() est appelé, alors les appels successifs à epoll_wait() parcourront en rotation l'ensemble des descripteurs de fichier prêts. Ce comportement aide à éviter les scénarios de famine, où un processus ne remarque pas que des descripteurs de fichier supplémentaires sont prêts parce qu'il se concentre sur un ensemble de descripteurs de fichier déjà connus comme étant

prêts.

Notez qu'il est possible d'appeler epoll_wait() sur une instance epoll dont la liste d'intérêt est actuellement vide (ou dont la liste d'intérêt devient vide parce que des descripteurs de fichier sont fermés ou retirés de la liste d'intérêt dans un autre fil d'exécution). L'appel sera bloqué jusqu'à ce qu'un descripteur de fichier soit ajouté plus tard à la liste d'intérêt (dans un autre fil d'exécution) et que ce descripteur de fichier devienne

prêt.
