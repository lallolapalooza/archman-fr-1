Éphémères et tables de hachage faibles.

Les éphémères et les tables de hachage faibles sont utiles lorsque l'on souhaite mettre en cache ou mémoriser le calcul d'une fonction, tant que les arguments et la fonction sont utilisés, sans créer de fuites de mémoire en conservant continuellement les anciens résultats de calcul qui ne sont plus utiles car un argument ou la fonction est libéré. Une implémentation utilisant Hashtbl.t n'est pas adaptée car toutes les associations conserveraient les arguments et le résultat en mémoire.

Les éphémères peuvent également être utilisés pour « ajouter » un champ à une valeur OCaml boîte quelconque : vous pouvez attacher des informations à une valeur créée par une bibliothèque externe sans fuites de mémoire.

Les éphémères contiennent certaines clés et une ou aucune donnée. Ce sont tous des valeurs OCaml boîte. Les clés d'un éphémère ont le même comportement que les pointeurs faibles selon le collecteur de garbage. En fait, les pointeurs faibles d'OCaml sont implémentés comme des éphémères sans données.

Les clés et les données d'un éphémère sont dites pleines si elles pointent vers une valeur, ou vides si la valeur n'a jamais été définie, a été annulée, ou a été effacée par le GC. Dans la fonction qui accède aux clés ou aux données, ces deux états sont représentés par le type option.

Les données sont considérées vivantes par le collecteur de garbage si toutes les clés pleines sont vivantes et si l'éphémère est vivant. Lorsqu'une des clés n'est plus considérée comme vivante par le GC, les données sont vidées de l'éphémère. Les données pourraient être vivantes pour une autre raison et dans ce cas, le GC ne les libérera pas, mais l'éphémère ne contiendra plus les données.

Les éphémères compliquent la notion de vivacité des valeurs, car elle n'est plus une équivalence avec l'accessibilité depuis la valeur racine par des pointeurs usuels (ni faibles ni éphémères). Avec les éphémères, la notion de vivacité est construite par le moindre point fixe de : Une valeur est vivante si :

-c'est une valeur racine

-elle est accessible depuis une valeur vivante par des pointeurs usuels

-c'est la donnée d'un éphémère vivant avec toutes ses clés pleines vivantes

Remarques :

-Tous les types définis dans ce module ne peuvent pas être marshalisés en utilisant output_value ou les fonctions du module Marshal.

Les éphémères sont définis d'une manière agnostique au langage dans cet article : B. Hayes, Ephemerons: A New Finalization Mechanism, OOPSLA'97

Depuis 4.03

Alert unsynchronized_access. Les accès non synchronisés aux tables de hachage faibles sont une erreur de programmation.

Accès non synchronisés

Les accès non synchronisés à une table de hachage faible peuvent conduire à un état de table de hachage faible invalide. Ainsi, les accès concurrents à une table de hachage faible doivent être synchronisés (par exemple avec un Mutex.t ).

module type S = sig end

La signature de sortie des foncteurs Ephemeron.K1.Make et Ephemeron.K2.Make . Ces tables de hachage sont faibles dans les clés. Si toutes les clés d'une liaison sont vivantes, la liaison est conservée, mais si l'une des clés de la liaison est morte, la liaison est supprimée.

module type SeededS = sig end

La signature de sortie des foncteurs Ephemeron.K1.MakeSeeded et Ephemeron.K2.MakeSeeded .

module K1 : sig end

Éphémères avec une clé.

module K2 : sig end

Éphémères avec deux clés.

module Kn : sig end

Éphémères avec un nombre arbitraire de clés du même type.
