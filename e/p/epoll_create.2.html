epoll_create(2) Manuel des appels système epoll_create(2)

NOM

epoll_create, epoll_create1 - ouvrir un descripteur de fichier epoll

BIBLIOTHÈQUE

Bibliothèque C standard (libc, -lc)

SYNTAXE

#include <sys/epoll.h>
int epoll_create(int size);
int epoll_create1(int flags);

DESCRIPTION

epoll_create() crée une nouvelle instance epoll(7). Depuis Linux 2.6.8, l'argument size est ignoré, mais doit être supérieur à zéro ; voir HISTORIQUE.

epoll_create() renvoie un descripteur de fichier faisant référence à la nouvelle instance epoll. Ce descripteur de fichier est utilisé pour tous les appels ultérieurs à l'interface epoll. Lorsqu'il n'est plus requis, le descripteur de fichier renvoyé par epoll_create() doit être fermé en utilisant close(2). Lorsque tous les descripteurs de fichier faisant référence à une instance epoll ont été fermés, le noyau détruit l'instance et libère les ressources associées pour réutilisation.

epoll_create1()

Si flags est 0, alors, hormis le fait que l'argument obsolète size est supprimé, epoll_create1() est identique à epoll_create(). La valeur suivante peut être incluse dans flags pour obtenir un comportement différent :

EPOLL_CLOEXEC
Définit le drapeau close-on-exec (FD_CLOEXEC) sur le nouveau descripteur de fichier. Voir la description du drapeau O_CLOEXEC dans open(2) pour les raisons pour lesquelles cela peut être utile.

VALEUR DE RETOUR

En cas de succès, ces appels système renvoient un descripteur de fichier (un entier non négatif). En cas d'erreur, -1 est renvoyé, et errno est défini pour indiquer l'erreur.

ERREURS

EINVAL
size n'est pas positif.
EINVAL
(epoll_create1()) Valeur invalide spécifiée dans flags.
EMFILE
La limite par processus sur le nombre de descripteurs de fichier ouverts a été atteinte.
ENFILE
La limite à l'échelle du système sur le nombre total de fichiers ouverts a été atteinte.
ENOMEM
Il n'y avait pas assez de mémoire pour créer l'objet noyau.

NORMES

Linux.

HISTORIQUE

epoll_create()
Linux 2.6, glibc 2.3.2.
epoll_create1()
Linux 2.6.27, glibc 2.9.

Dans l'implémentation initiale de epoll_create(), l'argument size informait le noyau du nombre de descripteurs de fichier que l'appelant s'attendait à ajouter à l'instance epoll. Le noyau utilisait cette information comme un indice pour la quantité d'espace à allouer initialement dans les structures de données internes décrivant les événements. (Si nécessaire, le noyau allouerait plus d'espace si l'utilisation par l'appelant dépassait l'indice fourni dans size.) De nos jours, cet indice n'est plus nécessaire (le noyau redimensionne dynamiquement les structures de données requises sans avoir besoin d'indice), mais size doit toujours être supérieur à zéro, afin d'assurer la compatibilité ascendante lorsque de nouvelles applications epoll sont exécutées sur des noyaux plus anciens.

Avant Linux 2.6.29, un paramètre du noyau /proc/sys/fs/epoll/max_user_instances limitait les epolls actifs pour chaque ID utilisateur réel, et provoquait l'échec de epoll_create() avec EMFILE en cas de dépassement.

VOIR AUSSI

close(2), epoll_ctl(2), epoll_wait(2), ioctl_eventpoll(2), epoll(7)
