epoll_wait(2) Manuel des appels système epoll_wait(2)

NOM

epoll_wait, epoll_pwait, epoll_pwait2 - attendre un événement d'E/S sur un descripteur de fichier epoll

BIBLIOTHÈQUE

Bibliothèque C standard (libc, -lc)

SYNOPSIS

#include <sys/epoll.h>
int epoll_wait(int n;
               int epfd, struct epoll_event events[n], int n,
               int timeout);
int epoll_pwait(int n;
               int epfd, struct epoll_event events[n], int n,
               int timeout,
               const sigset_t *_Nullable sigmask);
int epoll_pwait2(int n;
               int epfd, struct epoll_event events[n], int n,
               const struct timespec *_Nullable timeout,
               const sigset_t *_Nullable sigmask);

DESCRIPTION

L'appel système epoll_wait() attend des événements sur l'instance epoll(7) référencée par le descripteur de fichier epfd. Le tampon pointé par events est utilisé pour retourner des informations de la liste des prêts sur les descripteurs de fichiers dans la liste d'intérêt qui ont des événements disponibles. Jusqu'à n sont retournés par epoll_wait(). L'argument n doit être supérieur à zéro.

L'argument timeout spécifie le nombre de millisecondes pendant lesquelles epoll_wait() bloquera. Le temps est mesuré par rapport à l'horloge CLOCK_MONOTONIC.

Un appel à epoll_wait() bloquera jusqu'à ce que soit :

•
un descripteur de fichier délivre un événement ;
•
l'appel soit interrompu par un gestionnaire de signaux ; ou
•
le délai d'attente expire.

Notez que l'intervalle timeout sera arrondi à la granularité de l'horloge système, et que les délais de planification du noyau signifient que l'intervalle de blocage peut dépasser légèrement. Spécifier un timeout de -1 fait que epoll_wait() bloque indéfiniment, tandis que spécifier un timeout égal à zéro fait que epoll_wait() retourne immédiatement, même si aucun événement n'est disponible.

La structure struct epoll_event est décrite dans epoll_event(3type).

Le champ data de chaque structure epoll_event retournée contient les mêmes données que celles spécifiées lors du dernier appel à epoll_ctl(2) (EPOLL_CTL_ADD, EPOLL_CTL_MOD) pour le descripteur de fichier ouvert correspondant.

Le champ events est un masque de bits qui indique les événements survenus pour la description de fichier ouverte correspondante. Voir epoll_ctl(2) pour une liste des bits qui peuvent apparaître dans ce masque.

epoll_pwait()

La relation entre epoll_wait() et epoll_pwait() est analogue à la relation entre select(2) et pselect(2) : comme pselect(2), epoll_pwait() permet à une application d'attendre en toute sécurité soit qu'un descripteur de fichier devienne prêt, soit qu'un signal soit intercepté.

L'appel epoll_pwait() suivant :


ready = epoll_pwait(epfd, &events, n, timeout, &sigmask);

est équivalent à l'exécution *atomique* des appels suivants :


sigset_t origmask;
pthread_sigmask(SIG_SETMASK, &sigmask, &origmask);
ready = epoll_wait(epfd, &events, n, timeout);
pthread_sigmask(SIG_SETMASK, &origmask, NULL);

L'argument sigmask peut être spécifié comme NULL, auquel cas epoll_pwait() est équivalent à epoll_wait().

epoll_pwait2()

L'appel système epoll_pwait2() est équivalent à epoll_pwait() à l'exception de l'argument timeout. Il prend un argument de type timespec pour pouvoir spécifier une résolution de délai d'attente en nanosecondes. Cet argument fonctionne de la même manière que dans pselect(2) et ppoll(2). Si timeout est NULL, alors epoll_pwait2() peut bloquer indéfiniment.

VALEUR DE RETOUR

En cas de succès, epoll_wait() retourne le nombre de descripteurs de fichiers prêts pour l'opération d'E/S demandée, ou zéro si aucun descripteur de fichier n'est devenu prêt pendant les timeout millisecondes demandées. En cas d'échec, epoll_wait() retourne -1 et errno est défini pour indiquer l'erreur.

ERREURS

EBADF
epfd n'est pas un descripteur de fichier valide.
EFAULT
La zone mémoire pointée par events n'est pas accessible avec des permissions d'écriture.
EINTR
L'appel a été interrompu par un gestionnaire de signaux avant que (1) l'un des événements demandés ne se produise ou (2) le timeout n'expire ; voir signal(7).
EINVAL
epfd n'est pas un descripteur de fichier epoll, ou n est inférieur ou égal à zéro.

NORMES

Linux.

NOTES

Tandis qu'un thread est bloqué dans un appel à epoll_wait(), il est possible qu'un autre thread ajoute un descripteur de fichier à l'instance epoll attendue. Si le nouveau descripteur de fichier devient prêt, cela provoquera le déblocage de l'appel epoll_wait().

Si plus de n descripteurs de fichiers sont prêts lorsque epoll_wait() est appelé, alors les appels successifs à epoll_wait() parcourront circulairement l'ensemble des descripteurs de fichiers prêts. Ce comportement aide à éviter les scénarios de famine, où un processus ne parvient pas à remarquer que des descripteurs de fichiers supplémentaires sont prêts parce qu'il se concentre sur un ensemble de descripteurs de fichiers déjà connus comme étant prêts.

Notez qu'il est possible d'appeler epoll_wait() sur une instance epoll dont la liste d'intérêt est actuellement vide (ou dont la liste d'intérêt devient vide parce que des descripteurs de fichiers sont fermés ou retirés de la liste d'intérêt dans un autre thread). L'appel bloquera jusqu'à ce qu'un descripteur de fichier soit ultérieurement ajouté à la liste d'intérêt (dans un autre thread) et que ce descripteur de fichier devienne prêt.

Différences bibliothèque C/noyau

Les appels système bruts epoll_pwait() et epoll_pwait2() ont un sixième argument, size_t sigsetsize, qui spécifie la taille en octets de l'argument sigmask. La fonction wrapper glibc epoll_pwait() spécifie cet argument comme une valeur fixe (égale à sizeof(sigset_t)).

BOGUES

Avant Linux 2.6.37, une valeur de timeout supérieure à approximativement LONG_MAX / HZ millisecondes est traitée comme -1 (c'est-à-dire, l'infini). Ainsi, par exemple, sur un système où sizeof(long) est 4 et la valeur HZ du noyau est 1000, cela signifie que les délais d'attente supérieurs à 35,79 minutes sont traités comme l'infini.
